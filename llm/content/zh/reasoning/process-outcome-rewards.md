上一章用一个验证器在采样出的解答之间做选择。要造一个验证器——或者用强化学习训练一个模型——我们必须决定*奖励什么*。最简单的选择是结果：最终答案对，解答就好。但数学老师批改的是演算过程，而不仅是答案，其两条理由对语言模型同样成立。对的答案可能来自错的推理，奖励它就教错了。而一条二十步、第七步就失败的长解答，包含六个好的步骤和一个可指认的错误；结果标签只说"错"。

本章比较**结果监督**（outcome supervision）与**过程监督**（process supervision）。定义结果奖励模型与过程奖励模型，证明用标准损失训练时各自学到什么，并给出两项主要的实证比较：Uesato 等（2022）在小学数学上的比较，以及 Lightman 等（2023）的比较——后者的 PRM800K 人类步标注数据集成了这一领域的参照点。随后介绍如 Math-Shepherd 那样用蒙特卡洛 rollout 估计的自动过程标签，并确切说明这类标签测的是什么——最终成功的概率，这与一步是否正确不是一回事。最后谈奖励破解与过度优化，包括 best-of-$n$ 选择把分布从基座模型推走多远的精确公式，以及 DeepSeek-R1 报告给出的、完全不使用学习式奖励的理由。奖励模型的一般理论与偏好的 Bradley–Terry 模型，见[[post-training/reward-models]]。

## 两类标签 {#sec-labels}

把一个解答写成步骤序列 $y = (s_1,\dots,s_T)$——通常是以换行分隔的行或段落——以最终答案 $a(y)$ 收尾。对有已知参考答案 $a^*$ 的题，**结果**为 $o(y) = \mathbf 1[a(y) = a^*]$，可自动检查。**过程**标签给每一步一个判定 $c_t\in\{0, 1\}$（有时带第三个中性值）：给定前面的步骤，第 $t$ 步是否正确、且有所推进？

::: definition 结果奖励模型与过程奖励模型 {#def-orm-prm}
**结果奖励模型**（outcome reward model，ORM）$r_\phi(x, y)\in[0,1]$ 的训练目标是预测问题 $x$ 的完整解答 $y$ 的结果 $o(y)$。**过程奖励模型**（process reward model，PRM）$r_\phi(x, s_{\le t})\in[0,1]$ 的训练目标是：给定问题与前 $t$ 步，预测第 $t$ 步的标签 $c_t$。PRM 的步分数要**聚合**成解答分数，最常见的是乘积 $\prod_t r_\phi(x, s_{\le t})$ 或最小值 $\min_t r_\phi(x, s_{\le t})$，有时用最后一步的分数。
:::

两者通常都是带一个小输出头、输出一个概率的语言模型，用二元交叉熵训练。Cobbe 等（2021）训练他们的 GSM8K 验证器——一个 ORM——在解答的*每一个词元*处预测结果，而不只在末尾，并发现这比只在末尾预测一次更有效。下一个命题说明这样的模型学到什么。

::: proposition 在前缀上训练的结果模型学到价值函数 {#prop-orm-value}
设解答从策略 $\pi$ 采样，并让一个 ORM 用交叉熵损失从每个前缀 $y_{\le t}$ 预测结果 $o(y)$：

$$
\mathcal L(\phi) = -\E_{x,\;y\sim\pi(\cdot\mid x)}\sum_t\Big[o(y)\log r_\phi(x, y_{\le t}) + \big(1 - o(y)\big)\log\big(1 - r_\phi(x, y_{\le t})\big)\Big].
$$

若模型类能表示 $(x, y_{\le t})$ 的任意函数，则最小化器为 $r^*(x, y_{\le t}) = \Prob_\pi\big(o(y) = 1\mid x, y_{\le t}\big)$，即策略从这个前缀继续、最终写到正确答案的概率。
:::

::: proof
损失是对前缀求和；把各项按输入 $h = (x, y_{\le t})$ 的取值分组。固定 $h$，期望贡献是 $-\big[\bar o\log r + (1-\bar o)\log(1-r)\big]$ 乘以 $h$ 的概率，其中 $r = r_\phi(h)$，而 $\bar o = \Prob_\pi(o = 1\mid h)$ 是对 $h$ 的续写取期望的结果。作为 $r\in(0,1)$ 的函数，其导数为 $-\bar o/r + (1-\bar o)/(1-r)$，只在 $r = \bar o$ 处为零，且函数是凸的，所以 $r = \bar o$ 使其最小。由于每个 $h$ 可以独立设定，$r^*(h) = \bar o(h)$。
:::

用强化学习的语言（[[post-training/rl-for-language-models]]），$r^*$ 是在末尾以 $o$ 为奖励时，部分解答在策略 $\pi$ 下的**价值** $V^\pi$。这对搜索（[[reasoning/search]]）有用，但注意它*不是*什么：它不是对已有步骤是否正确的判定。一道难题的正确前缀，若 $\pi$ 往往有头无尾，价值就低；一个错误前缀，只要 $\pi$ 有时仍碰得到正确答案，价值就为正。过程标签问的是另一个问题。

::: example 答案对，推理错 {#ex-false-positive}
某个生成器用 $8$ 步解题。一条解答完全正确的概率为 $0.5$；当某一步出错时，最终答案仍有 $0.15$ 的概率是对的（错误相互抵消、蒙对、抄来的数）。有正确最终答案的解答中，有多大比例含有错误的一步？若 best-of-$n$ 使用一个完美的 ORM——它在答案正确的解答中均匀挑选——它多久会返回这样一条解答？
::: solution
$\Prob(\text{答案正确}) = 0.5 + 0.5\cdot0.15 = 0.575$，且 $\Prob(\text{有错步}\mid\text{答案正确}) = 0.075/0.575 = 0.130$。完美的 ORM 分不出二者，所以只要它交回一条答案正确的解答，就有 $13\%$ 的时候该解答的推理是有毛病的。完美的 PRM 会把它们拒掉。在只检查答案的基准上，两种验证器得分相同；对阅读演算过程的用户，或对模仿被选解答的训练过程而言，二者不同。
:::
:::

## 实证比较 {#sec-evidence}

### Uesato 等（2022） {#sec-uesato}

Uesato 等在 DeepMind 在 GSM8K 上比较了基于结果与基于过程的方法——用于监督微调、用于重排序的奖励模型、以及强化学习。过程标签来自人类标注员，他们标记采样解答中第一个错误的步骤。他们测量两个量：**最终答案错误率**与**轨迹错误**（trace error）——最终答案正确、却含有推理错误的解答所占的比例。

他们的主要发现是：基于结果与基于过程的监督给出*相近*的最终答案错误率，但低的轨迹错误需要基于过程的反馈，或一个模仿它的奖励模型。他们最好的系统把最终答案错误率从此前最佳的 $16.8\%$ 降到 $12.7\%$，把轨迹错误从 $14.0\%$ 降到 $3.4\%$。还有一项更微妙的发现：只用结果标签训练的奖励模型，与人类*过程*标签的一致程度，反而高于与它所训练的结果标签的一致程度——这与[[#prop-orm-value]]相容，因为一个好的价值函数会在第一个致命错误处骤降。

### Lightman 等（2023）：《Let's verify step by step》 {#sec-lightman}

Lightman 等在 OpenAI 把比较扩展到更难的竞赛题数据集 MATH 上。一个基于 GPT-4 的生成器经微调后每行写一步，产出的解答由人类标注员逐步评为*正面*、*负面*或*中性*。

::: definition PRM800K {#def-prm800k}
**PRM800K** 是 Lightman 等（2023）发布的数据集，含约 $800{,}000$ 条步级人类标签，覆盖 $12{,}000$ 道 MATH 题的约 $75{,}000$ 条模型生成解答。送标的解答由**主动学习**挑选：优先选择*令人信服的错误解答*——当前 PRM 给它高分、答案却错的解答。
:::

他们的 PRM 以*每一步*都正确的概率为解答打分，由每步概率的乘积算出。ORM 则在均匀采样解答的最终答案正确性上训练。在 MATH 测试集的 $500$ 题留出子集（后来常称 MATH-500）上，以每题最多 $N = 1860$ 个样本的 best-of-$N$ 评估：PRM 为 $78.2\%$ 的题选出了正确解答，ORM 为 $72.4\%$，多数投票为 $69.6\%$。PRM 与 ORM 的差距随 $N$ *增大*：候选越多，拒掉令人信服的错误解答就越要紧。PRM 的优势在一个小型分布外集合（近期 STEM 考试题）上仍然保持。主动学习把过程标签的数据效率提高了约 $2.6$ 倍。

作者还做了受控的小规模实验，让一个大 PRM 扮演人类标注员，以在相同标注成本下比较监督方式。那里的过程监督同样优于结果监督。他们论证过程监督还有一项**对齐**上的好处：它直接奖励人类认可的思维链，而不是通往答案的任何路径。

::: proposition 乘积聚合与最小值聚合 {#prop-aggregate}
设 PRM 的步分数为 $r_1,\dots,r_T\in[0,1]$。(a) 若 $r_t$ 是在第 $1,\dots,t-1$ 步都正确的条件下、第 $t$ 步正确的条件概率，则 $\prod_t r_t$ 是每一步都正确的概率。(b) $\prod_t r_t\le\min_t r_t$，仅当其余分数全为 $1$ 时取等。(c) 若每一步的分数都是 $r < 1$，乘积为 $r^T$，随步数 $T$ 递减；而最小值对任何 $T$ 都是 $r$。
:::

::: proof
(a) 由概率的链式法则，$\Prob(c_1 = \dots = c_T = 1) = \prod_t\Prob(c_t = 1\mid c_1 = \dots = c_{t-1} = 1) = \prod_t r_t$。(b) 每个因子不超过 $1$，所以乘积不超过任何一个因子，特别是不超过最小者；只有其余全为 $1$ 时才等于最小者。(c) 显然。
:::

::: example 两种聚合意见相左 {#ex-aggregate}
解答 A 有 $4$ 步，PRM 给每步打 $0.95$。解答 B 用 $12$ 步更细致地解同一道题，每步打 $0.98$。乘积聚合偏爱哪一个？最小值聚合偏爱哪一个？
::: solution
乘积：A 得 $0.95^4 = 0.8145$，B 得 $0.98^{12} = 0.7847$，所以乘积偏爱更简洁的 A，尽管 A 的每一步都更不确定。最小值：A 得 $0.95$，B 得 $0.98$，最小值偏爱 B。若分数是校准好的条件概率，[[#prop-aggregate]] 的 (a) 说乘积才是正确的量——B 确实稍微更可能在哪里藏着错误，因为它犯错的地方多了三倍。反之，若 PRM 的分数校准很差、每一步都被征一道小"税"，乘积就会系统性地偏爱短解答。
:::
:::

(c) 是一个实际问题。乘积聚合即使每一步都没问题也会惩罚长解答，所以对着它优化的策略会学着写更少、更长的步骤；最小值聚合不会，但它除最弱的一步外无视一切。两者都不是任何场合下的正确答案，已发表的系统两种都在用。

## 自动过程标签 {#sec-auto}

人类步标签昂贵：PRM800K 需要专家标注员阅读几十万步竞赛数学。一个更便宜的主意利用[[#prop-orm-value]]：从前缀*rollout 出*补全并检查其答案，来估计每个前缀的价值。

::: algorithm 蒙特卡洛步标签（Math-Shepherd） {#alg-mc-labels}
**输入：**带参考答案 $a^*$ 的问题 $x$，解答步骤 $s_1,\dots,s_T$，补全策略 $\pi$，rollout 数 $N$。
1. 对 $t = 1,\dots,T$：采样 $N$ 个补全 $y^{(1)},\dots,y^{(N)}\sim\pi(\cdot\mid x, s_{\le t})$，记 $k_t$ 为最终答案等于 $a^*$ 的个数。
2. **软标签：**$\hat v_t = k_t/N$。**硬标签：**$\hat c_t = \mathbf 1[k_t > 0]$。
3. 用 $(x, s_{\le t}, \hat c_t)$ 或 $(x, s_{\le t}, \hat v_t)$ 以交叉熵训练一个 PRM。
:::

Wang 等（2024）以 **Math-Shepherd** 之名提出了这一流程。他们用自动标签训练 PRM，用它们做 best-of-$n$ 选择、并作为 PPO 强化学习的步级奖励，报告在约 $70$ 亿参数的开放模型上 GSM8K 与 MATH 都有提升——Mistral-7B 经逐步 PPO 从 GSM8K 的 $77.9\%$ 提高到 $84.1\%$、MATH 的 $28.6\%$ 提高到 $33.0\%$，再配合基于 PRM 的选择还有进一步上升。后来的工作让标注更便宜：OmegaPRM（Luo 等，2024）用对前缀位置的二分查找来定位第一个错误，因为估计的价值倾向于在第一个错误处下降。

::: proposition 蒙特卡洛标签估计的是什么 {#prop-mc}
在[[#alg-mc-labels]]中，设 $v_t = \Prob_\pi(a(y) = a^*\mid x, s_{\le t})$ 为前缀 $t$ 在补全策略下的价值。则软标签对价值无偏，$\E\hat v_t = v_t$ 且 $\Var\hat v_t = v_t(1-v_t)/N$；硬标签以概率 $1 - (1 - v_t)^N$ 取 $1$。
:::

::: proof
$N$ 个补全相互独立，每个以概率 $v_t$ 到达 $a^*$，所以 $k_t\sim\Bin(N, v_t)$。于是 $\E[k_t/N] = v_t$，$\Var(k_t/N) = v_t(1-v_t)/N$，且 $\Prob(k_t > 0) = 1 - \Prob(k_t = 0) = 1 - (1-v_t)^N$。
:::

于是标签从补全策略继承两种偏差。一道难题的**正确**一步可能被标坏，因为补全策略很少能把题做完（$v_t$ 小）；一个**错误**的步骤可能被标好，因为补全策略有时能挽回、或侥幸到达正确答案（$v_t > 0$）。用硬标签且 rollout 很多时，第二种效应会*更糟*：只要 $v_t > 0$，就有 $1 - (1-v_t)^N\to1$。

::: example 硬标签与侥幸答对 {#ex-hard-label}
某一步出错之后，补全策略仍以 $0.15$ 的概率到达参考答案（靠运气或悄悄纠正了错误）。$N = 8$ 次 rollout 时，硬标签多久会把错误步骤标成好？$N = 32$ 时呢？
::: solution
由[[#prop-mc]]，$1 - 0.85^8 = 1 - 0.2725 = 0.728$；$N = 32$ 时，$1 - 0.85^{32} = 0.9944$。rollout 很多时，硬标签测的是"这个前缀还能不能补全正确"——在答案可以蒙的场合（例如选择题、小整数答案），这几乎等于"任何一步"。软标签退化得温和：$\hat v_t$ 平均为 $0.15$，低于正确前缀的价值，所以一个阈值或排序仍能把它们分开。Qwen 团队的 Zhang 等（2025）报告，用蒙特卡洛标签训练的 PRM 在指认错误步骤上，不如用强模型评审的标签或人类标签训练的那些可靠；而只看 best-of-$n$ 评估会把这一点掩盖起来，因为它奖励的是最终答案的正确。
:::
:::

PRM 究竟多会定位错误，由 ProcessBench（Zheng 等，2024）一类基准直接测量：它要求在竞赛数学解答中给出最早错误步骤的序号。其作者报告，已有的开放 PRM 在这件事上常常不如被提示逐步批评解答的通用模型——这提醒我们，"PRM"说的是训练目标，不是保证。

::: warning 过程奖励不是正确性的神谕
PRM 是有自身错误与盲点的学出来的模型：它要么在某个生成器解答的人类标签上训练，要么在把"正确"与"可补全"混为一谈的蒙特卡洛价值上训练。两个推论：写步骤的策略一变，它的分数就会漂移（训练分布是另一个策略的步骤）；而对着它优化的策略总会找到它误判的步骤。要把 PRM 分数当作待验证的证词：留一批人工检查过的解答来验证它，并同时追踪轨迹错误与最终答案准确率。
:::

## 使用奖励：选择、搜索与训练 {#sec-uses}

奖励模型可以用在三种场合，按施加于它的压力递增排列。

1. **选择。** best-of-$n$ 或验证器加权投票（[[reasoning/self-consistency#def-bon]]）。策略是固定的；奖励只在其样本之间做选择。
2. **搜索。** PRM 给部分解答打分，搜索过程于是可以扩展有前景的前缀、并在糟糕的前缀写完之前弃掉它们（[[reasoning/search]]）。只有 PRM——或[[#prop-orm-value]]意义下的价值模型——做得到；只对完整解答打分的 ORM 不行。
3. **训练。** 奖励驱动强化学习。结果奖励是**稀疏的**：长序列末尾的一个数，学习者要从中倒推出哪些词元要紧。过程奖励是**稠密的**：每一步都有信号，原则上缓解了信用分配（[[reasoning/verifiable-rewards]] 展开的是结果奖励的情形）。

策略对着学出来的奖励优化得越狠，就越会利用奖励的错误。小 $n$ 的选择是温和的；数千步的强化学习不是。

::: definition 奖励破解 {#def-hacking}
**奖励破解**（reward hacking）指代理奖励 $r_\phi$ 因某些行为而升高，而真正意图的目标 $r^\star$ 却不升反降——例如 PRM 给出高分，只因为解答措辞自信、把某个正确步骤重复了许多遍、或把推理拆成许多平凡正确的碎步。
:::

一个选择程序会把输出的分布改变多少？对 best-of-$n$ 有精确答案，Gao 等（2023）用它把 best-of-$n$ 与强化学习放到同一尺度上比较。

::: theorem best-of-$n$ 的散度 {#thm-bon-kl}
设 $\pi$ 为基座策略，奖励 $r$ 在 $\pi$ 下的分布连续（无并列）。设 $\pi_n$ 为从 $\pi$ 独立抽 $n$ 个样本、按 $r$ 取最优者所得的分布。则

$$
\mathrm{KL}(\pi_n\,\Vert\,\pi) = \ln n - \frac{n-1}{n}.
$$ {#eq-bon-kl}
:::

::: proof
设 $F$ 为 $y\sim\pi$ 下 $r(y)$ 的分布函数，$U = F(r(y))$ 为样本奖励的分位数。$\pi$ 之下 $U$ 在 $[0,1]$ 上均匀分布，因为 $F$ 连续。$\pi_n$ 之下 $U$ 是 $n$ 个独立均匀变量之最大值，密度为 $g(u) = n u^{n-1}$。给定 $U = u$，$y$ 的条件分布在两个策略下相同：best-of-$n$ 只按奖励挑选，所以在给定奖励的输出之中，它照 $\pi$ 的样子挑。由相对熵的链式法则，$(U, y)$ 联合律的散度等于 $U$ 的边缘律的散度加上条件律散度的期望，而后者为 $0$，于是

$$
\mathrm{KL}(\pi_n\Vert\pi) = \int_0^1 n u^{n-1}\ln\big(n u^{n-1}\big)\,du = \ln n + n(n-1)\int_0^1 u^{n-1}\ln u\,du.
$$

分部积分得 $\int_0^1u^{n-1}\ln u\,du = \big[\tfrac{u^n}{n}\ln u\big]_0^1 - \int_0^1\tfrac{u^{n-1}}{n}du = -\tfrac1{n^2}$，故 $\mathrm{KL} = \ln n - (n-1)/n$。
:::

::: example 在 KL 预算下的 best-of-$n$ {#ex-kl-budget}
一次强化学习运行被允许离开初始策略 $3$ nat。哪个 best-of-$n$ 走出去的距离大致相同？
::: solution
解 $\ln n - (n-1)/n = 3$。由于 $(n-1)/n\approx1$，$n\approx e^4\approx55$；验算 $n = 53$ 得 $2.989$，$n = 54$ 得 $3.008$。所以 best-of-$54$ 恰在同一散度处。Gao 等用这一对应把 best-of-$n$ 与强化学习画在同一根横轴上，发现两种方法沿形状不同的"金标"奖励——散度曲线行进。best-of-$n$ 每次查询在推理时花 $n$ 个样本；强化学习则是一次性的训练开销。
:::
:::

对会出并列的离散输出，该公式是一个上界（Beirami 等，2024）。它只按对数增长：best-of-$16$ 离基座策略 $1.83$ nat，best-of-$256$ 是 $4.55$。Gao 等训练了一个"金标"（gold）奖励模型来代替人类判断，又在其标签上训练较小的"代理"（proxy）奖励模型，然后用 best-of-$n$ 和强化学习对着代理优化。随与初始策略的散度增大，金标奖励先升后降，且代理奖励模型越大，峰值出现的位置越靠后。他们把金标奖励拟合为 $d(\alpha - \beta d)$（best-of-$n$ 的情形，$d = \sqrt{\mathrm{KL}}$）——一个经验拟合，不是定律，但把过度优化总结得颇为传神。

::: widget plot

x: 1, 1000

caption: 用 Gao 等（2023）拟合的函数形式演示 best-of-$n$ 下的过度优化：真实（"金标"）奖励为 $d(\alpha - \beta d)$，其中 $d = \sqrt{\mathrm{KL}}$，而 $\mathrm{KL} = \ln n - (n-1)/n$ 来自[[#thm-bon-kl]]（此处 $\alpha = 1$；两个系数是为展示编造的）。横轴是 $n$。代理奖励随 $n$ 一路上升；真实奖励达到峰值后回落。$b$ 越小——在 Gao 等的实验中即奖励模型越大——峰值越靠右。

### DeepSeek-R1 为何不用 PRM {#sec-r1-prm}

DeepSeek-R1 报告（DeepSeek-AI，2025）只用基于规则的奖励——答案检查与格式检查——训练其推理模型，并在"没有成功的尝试"一节说明了原因。报告说，过程奖励模型面临三个障碍：一般推理中难以定义细粒度的"步骤"；难以判定一个中间步骤是否正确，因为自动标注不可靠、人工标注无法扩展；而一旦引入基于模型的 PRM，奖励破解随之而来，重训奖励模型又增加成本与复杂性。报告的结论是：PRM 在重排序与引导搜索上仍有用处，但在其大规模强化学习的设定下，与额外计算量相比其优势有限。这是单个团队在单个配方上的经验报告，不是普适结论，且截至 2026 年 PRM 仍是活跃的研究方向；但它解释了下一章为何以*可验证的结果*奖励为中心。

::: quiz
一个 ORM 在策略 $\pi$ 生成的、按最终答案正确性标注的解答上，用每个前缀处的交叉熵训练。哪些说法正确？（多选。）
- [x] 它在前缀处的理想预测，是 $\pi$ 把该前缀补全正确的概率。
- [ ] 它在前缀处的理想预测，是该前缀不含错误的概率。
- [x] 若日后用训练改变了策略，ORM 的预测可能不再是新策略的价值。
- [ ] 用这个 ORM 做 best-of-$n$，保证随 $n$ 增大而改进。
::: solution
由[[#prop-orm-value]]，最小化器是*生成训练数据的那个策略*之下的价值，不是前缀的正确性；因此它依赖于那个策略。用任何不完美的打分做 best-of-$n$，都可能在大 $n$ 处回落（[[reasoning/self-consistency#sec-verifier]]）。
:::
:::

## 数值实验室 {#sec-code}

清单模拟一个生成器：解答有 $8$ 步，每步正确率随题在 $0.80$ 到 $0.98$ 之间；一旦某步出错，其余步骤也全错，但最终答案仍有 $0.15$ 的概率正确。它比较两种 best-of-$16$ 选择：ORM（隔着一层高斯噪声看最终答案）与 PRM（每一步隔着*同一个*噪声、取最小值），然后计算蒙特卡洛步标签与 best-of-$n$ 的 KL 散度。

```python
import math, random
rng = random.Random(2)
S, LUCKY = 8, 0.15            # 每道解答的步数；P(某步出错时答案仍正确)

def solve(q, prefix=()):
    """从一串步骤正误标记组成的前缀继续解答；返回 (steps, answer_ok)。"""
    steps = list(prefix)
    while len(steps) < S:
        steps.append(all(steps) and rng.random() < q)   # 出错之后的步骤也记为错
    ok = all(steps) or rng.random() < LUCKY
    return steps, ok

def orm(steps, ok):           # 结果验证器：最终答案隔着一层噪声
    return ok + rng.gauss(0, 0.6)
def prm(steps, ok):           # 过程验证器：每步隔着同一噪声；取最小值
    return min(s + rng.gauss(0, 0.6) for s in steps)

# 1. Best-of-16 选择：最终答案准确率，以及正确答案中的轨迹错误
for name, score in [("ORM", orm), ("PRM", prm)]:
    acc = trace_err = 0
    problems = 3000
    for _ in range(problems):
        q = rng.uniform(0.80, 0.98)
        cands = [solve(q) for _ in range(16)]
        steps, ok = max(cands, key=lambda c: score(*c))
        acc += ok
        trace_err += ok and not all(steps)
    print(f"{name}: answer accuracy {acc / problems:.3f}, "
          f"right answer with a wrong step {trace_err / max(acc, 1):.3f} of correct answers")

# 2. 蒙特卡洛步标签（Math-Shepherd 风格）：每个前缀 rollout N 个补全
q, N = 0.9, 8
print("\nprefix              true value   soft label   hard label")
for prefix in [(True,), (True,) * 4, (True, False), (True,) * 4 + (False,)]:
    v = q**(S - len(prefix)) + (1 - q**(S - len(prefix))) * LUCKY if all(prefix) else LUCKY
    wins = sum(solve(q, prefix)[1] for _ in range(N))
    tag = "".join("+" if s else "-" for s in prefix)
    print(f"{tag:18s}  {v:10.3f}   {wins / N:10.3f}   {int(wins > 0):10d}")
hard_fp = 1 - (1 - LUCKY)**N
print(f"P(hard label says 'good' after a wrong step) = 1 - (1 - {LUCKY})^{N} = {hard_fp:.3f}")

# 3. best-of-n 相对基座策略的 KL 散度
for n in [2, 4, 16, 64, 256]:
    print(f"best-of-{n:<3d}  KL = ln n - (n-1)/n = {math.log(n) - (n - 1) / n:.3f} nats")
```

```text

PRM: answer accuracy 0.928, right answer with a wrong step 0.015 of correct answers

prefix              true value   soft label   hard label
+                        0.557        0.750            1
++++                     0.708        0.875            1
+-                       0.150        0.125            1
++++-                    0.150        0.125            1

```

面对同等噪声的观察，两个验证器的最终答案准确率相近（这里 ORM 略高：它看的是一个带噪声的数，而 PRM 要在八个带噪声的数中取最小值，更噪），但 ORM 选出的正确答案里有 $19\%$ 含错误步骤，PRM 只有 $1.5\%$——正是 Uesato 等报告的模式。蒙特卡洛标签显出了[[#prop-mc]]的两种偏差：软标签是对含噪价值（$8$ 次 rollout 的标准误差约 $0.17$）的估计，正确的一步前缀价值只有 $0.56$，而每个硬标签都是 $1$——包括错误步骤之后的那些。

::: history
训练验证器来给解答排序可追溯到 Cobbe 等（2021），其 GSM8K 验证器就是在每个词元处训练的结果模型。Uesato 等（2022）在 GSM8K 上比较了过程反馈与结果反馈，并引入轨迹错误这一指标。Lightman 等于 2023 年 5 月贴出《Let's verify step by step》（ICLR 2024），附 PRM800K。Gao、Schulman 与 Hilton（2023）用合成的金标奖励度量奖励模型的过度优化。Wang 等（Math-Shepherd，2023；ACL 2024）用蒙特卡洛 rollout 自动产出过程标签，Luo 等（2024）用二分查找为其提速（OmegaPRM）。DeepSeek-R1 报告（2025 年 1 月）解释了放弃学习式过程奖励的决定，而 ProcessBench（Zheng 等，2024）与 Qwen 团队对 PRM 训练的研究（Zhang 等，2025）则考察了 PRM 找错误的真实水平。
:::

::: summary
- **ORM** 预测最终答案是否正确；在策略解答的每个前缀上用交叉熵训练时，它学到的是*该策略*的**价值** $\Prob_\pi(\text{正确}\mid\text{前缀})$，而不是前缀的正确性。
- **PRM** 预测每一步的正确性；步分数以乘积（每一步都正确的概率，会惩罚长度）或最小值聚合。
- Uesato 等（2022）发现结果监督与过程监督的最终答案错误率相近，但过程反馈下的**轨迹错误**低得多；Lightman 等（2023）用 **PRM800K** 人类标签，在 MATH-500 上得到基于 PRM 的 best-of-$1860$ 选择 $78.2\%$，ORM $72.4\%$，多数投票 $69.6\%$。
- **蒙特卡洛标签**（Math-Shepherd）用 rollout 估计前缀价值：软标签对价值无偏；硬标签以概率 $1 - (1-v)^N$ 取 $1$，在有侥幸补全时把错误步骤标成好。
- 对着学出来的奖励优化会招来**奖励破解**；best-of-$n$ 把分布从基座策略移动 $\ln n - (n-1)/n$ nat，真实奖励随散度增长先升后降。DeepSeek-R1 因这些原因在大规模强化学习中避开了学习式奖励。
:::

::: exercise 蒙特卡洛标签的成本 {level=2 check="24000"}
用[[#alg-mc-labels]]给一条 $10$ 步解答打标签，要对每个前缀做 $N = 8$ 次 rollout，而一次 rollout 平均生成 $300$ 个词元。给一条解答打标签要生成多少词元？并评论一下给 $100{,}000$ 条解答打标签的成本。
::: solution
$10\cdot8\cdot300 = 24{,}000$ 个词元。$100{,}000$ 条解答就是 $2.4\times10^9$ 个生成词元——比人工标注便宜得多，但仍是一笔可观的推理任务；用二分查找定位第一个错误（OmegaPRM）能把需要 rollout 的前缀数从 $T$ 降到约 $\log_2T$。

::: exercise best-of-$n$ 的散度 {level=2 check="1.835"}
按[[#thm-bon-kl]]计算 best-of-$16$ 相对基座策略的 KL 散度，精确到三位小数。要让散度超过 $5$ nat，$n$ 至少要多大？
::: solution
$\ln16 - 15/16 = 2.7726 - 0.9375 = 1.835$。要得到 $5$ nat，需要 $\ln n - (n-1)/n > 5$，即 $\ln n > 5 + (n-1)/n\approx 6$，得 $n\approx e^6\approx403$；验算，$n = 403$ 给出 $5.9989 - 0.9975 = 5.0014$，而 $n = 402$ 给出 $4.999$，所以 $n = 403$。散度随 $n$ 增长如此之慢，以至于与强化学习相比，best-of-$n$ 是一种温和的优化——后者可以离开起点远得多。
:::
:::

::: exercise 用哪种聚合？ {level=2}
一个策略对着 PRM 用强化学习训练。描述它可能如何利用 (a) 乘积聚合与 (b) 最小值聚合，并为每种利用方式提出一个能察觉它的检查。
::: solution
(a) 只要分数低于 $1$，乘积就随步数递减（[[#prop-aggregate]]），所以策略可以靠写更少、更长的步骤来提高奖励——把若干运算合并成一行、或跳过解释——哪怕这会让错误更难被看出。察觉办法：在训练中追踪每道解答的步数与平均步长，并人工检查轨迹错误。(b) 最小值除最弱一步外无视一切，所以策略可以往解答里塞进许多简单、 显得有把握而正确的步骤而不付代价，或把一个有风险的运算拆开，让 PRM 只看到无害的碎片。察觉办法：追踪解答长度与重复，并随着训练推进，测试 PRM 在策略生成的解答中定位注入错误的能力。两种情形下，都应保留一个由人工或精确检查判定的留出集，盯住"代理奖励上升而真实准确率停滞"。
:::
:::

::: exercise 无法完成的前缀 {level=2}
对一道难题，一个正确的第一步在补全策略下价值 $v_1 = 0.05$；而对同一道题，一个恰好得出容易（但错误）子问题的错误第一步，却以 $0.10$ 的概率通向参考答案，因为参考答案是常被蒙中的小整数。哪个前缀的软标签期望更高？这对一个在这种标签上训练、并用于搜索的 PRM 意味着什么？
::: solution
由[[#prop-mc]]，软标签的期望分别为 $0.05$ 与 $0.10$：错误的步骤得分更高。在这种标签上训练的 PRM 会学着偏爱它，而由该 PRM 引导的搜索（[[reasoning/search]]）会先扩展错误的分支。蒙特卡洛标签测的是*特定策略*的可完成性，而对难题，它可能由蒙答案主导；对策包括选用答案难以蒙中的题、把软标签与人类或模型评审的标签结合、以及估计一步带来的价值*变化*而非其绝对水平。
:::
:::

::: exercise 作为价值函数的 ORM {level=3}
(a) 推广[[#prop-orm-value]]：若 ORM 不用交叉熵、而用平方误差 $(r_\phi - o)^2$ 训练，最小化器是什么？(b) 证明真实价值满足 $V(s_{\le t}) = \E_\pi\big[V(s_{\le t+1})\mid s_{\le t}\big]$，并解释这条"一致性"条件如何能在没有任何标签的情况下检查一个训练好的 PRM 或价值模型。
::: solution
(a) 对固定输入 $h$，期望损失为 $\E[(r - o)^2\mid h] = (r - \bar o)^2 + \Var(o\mid h)$，在 $r = \bar o(h)$ 处最小：同一个条件期望。任何恰当评分规则的 最小化器都是条件概率。

(b) 由塔性质，$V(s_{\le t}) = \Prob(o = 1\mid s_{\le t}) = \E\big[\Prob(o = 1\mid s_{\le t+1})\mid s_{\le t}\big] = \E[V(s_{\le t+1})\mid s_{\le t}]$，期望取自从 $\pi$ 抽取的下一步。要检查一个训练好的模型：从每个前缀抽许多下一步、给它们打分，再拿平均分与前缀自己的分数比较：出入很大，就说明该模型不是 $\pi$ 的一个一致的价值函数。这正是时序差分学习所强制的同一类贝尔曼（Bellman）型条件。
:::
:::

::: exercise 用二分查找第一个错误 {level=3}
假设一条解答的前缀价值 $v_t$ 在第一个错误之前较高（高于 $0.5$）、之后较低，并且一次用足够多 rollout 的蒙特卡洛估计能判出一个前缀位于 $0.5$ 的哪一侧。写一个纯 Python 函数，用 $O(\log T)$ 次估计找到第一个错误，并用模拟的补全策略测试它。
::: solution
```python
import random
rng = random.Random(3)

def estimate(prefix_ok, N=32):
    """前缀的蒙特卡洛价值：尚未出错为 0.8，出错之后为 0.1。"""
    v = 0.8 if prefix_ok else 0.1
    return sum(rng.random() < v for _ in range(N)) / N

def first_error(steps_ok):
    lo, hi = 0, len(steps_ok)                 # 不变式：长度 lo 的前缀完好，长度 hi 的前缀已坏
    if estimate(all(steps_ok)) > 0.5:
        return None, 1                        # 未发现错误
    calls = 1
    while hi - lo > 1:
        mid = (lo + hi) // 2
        calls += 1
        if estimate(all(steps_ok[:mid])) > 0.5:
            lo = mid
        else:
            hi = mid
    return hi, calls                          # 第一个错误步骤的序号（从 1 开始）

steps = [True] * 13 + [False] * 7             # 第一个错误在 20 步中的第 14 步
print(first_error(steps))
```

```text
(14, 6)
```

六次估计（整条解答一次，对 $20$ 个位置二分五次），而不是 $20$ 次。单调性假设正是 OmegaPRM 依赖的东西；当补全策略常常能从错误中恢复时它就失效了，那即[[#prop-mc]]之后讨论的偏差。
:::
:::
