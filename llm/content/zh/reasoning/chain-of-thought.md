语言模型逐词元地产出答案，而每个词元都来自一次穿过固定层数网络的前向传播。问模型“$17\times 24 - 39$ 是多少？”并要求立刻给出答案，整段计算就必须发生在写出那三个数字的前向传播内部。若让它先写出“$17\times24 = 408$，而 $408 - 39 = 369$”，计算的每个部分就都有自己的词元、自己的前向传播，以及一份供后面的词元阅读的书面记录。这第二种行为——在答案之前先写出中间步骤——就叫**思维链**（chain of thought，CoT）。它是本课程一切的起点。

本章讲述思维链的发现及其主要变体：训练进小模型的草稿本、面向大模型的少样本与零样本提示、由简入繁（least-to-most）提示一类的分解方法，以及模型编写代码、解释器负责执行的程序辅助推理。随后我们要问*为什么*中间词元有帮助。答案的一部分可以被证明：一个固定深度的 Transformer 若在作答前写出 $m$ 个词元，就能执行串行步数为原来 $m+1$ 倍的计算，而已发表的定理表明，在标准复杂性假设下，这使某些单次前向不可解的问题变得可解。答案的其他部分则依赖实验，且仍有争议。本章最后给出从*提示*模型推理到*训练*模型进行长推理的过渡，课程其余部分将沿此展开。基本的提示技巧见[[prompting-rag/prompt-design#sec-cot]]；这里要深入得多。

## 草稿本与思维链 {#sec-origins}

模型应当展示演算过程这一想法早于大语言模型。Ling 等（2017）收集了附有书面**推理依据**的应用代数题（AQuA 数据集），并训练了一个序列到序列模型先生成推理依据、再生成答案。Nye 等（2021）训练 Transformer 把中间结果写到一个**草稿本**上——长加法里的部分和，或 Python 程序执行时逐行写出的变量取值——然后再写出最终输出。在位数超过训练中见过的长度的加法以及程序执行任务上，用草稿本训练的模型远比直接输出答案的模型准确。Cobbe 等（2021）发布了 GSM8K——$8{,}500$ 道小学数学应用题，其参考解答用自然语言一步一步写出——并在这些解答上训练模型。

这些方法都需要带中间步骤的训练数据。Wei 等（2022）表明，足够大的预训练模型并不需要：提示中的几个示例——每个由问题、写明的推理链和答案组成——就足以让模型对新问题产出这样的链。

::: definition 思维链 {#def-cot}
对输入 $x$ 的**思维链**是模型在 $x$ 之后、最终答案 $y$ 之前生成的一串词元 $z = (z_1,\dots,z_m)$，其中包含解法的中间步骤。模型从

$$
p_\theta(z, y\mid x) = p_\theta(z\mid x)\,p_\theta(y\mid x, z),
$$ {#eq-cot-factor}

中采样，答案从输出的末尾提取（例如 "The answer is" 之后的文本）。**少样本思维链**在 $x$ 之前放置 $k$ 个示例 $(x_i, z_i, y_i)$；**零样本思维链**只加一条诸如 *Let's think step by step* 的指令；**推理模型**则经过训练自己产出 $z$，通常写在一对特殊分隔符之间。
:::

[[#eq-cot-factor]] 这个分解式不过是把概率的链式法则用到输出上：思维链是模型生成内容的一部分，而不是一套单独的机制。这一观察在本课程中将两次派上用场。在[[reasoning/self-consistency]]里，我们会对 $z$ *求边际*，把推理当作潜变量；在[[reasoning/faithfulness-limits]]里，我们要问 $z$ 是否真的反映了产生 $y$ 的那次计算。

### Wei 等人的发现 {#sec-wei}

Wei 等在算术（GSM8K、SVAMP、AQuA 等）、常识（CommonsenseQA、StrategyQA）与符号任务（拼接单词的末字母、跟踪一枚硬币在若干人翻动之后是否仍正面朝上）上评测了少样本思维链。三点发现定义了这个领域。

1. **多步问题上的巨大增益。** 在 $5400$ 亿参数的 PaLM 模型上，GSM8K 准确率从标准少样本提示（问题、答案）的 $17.9\%$ 升到八条思维链示例下的 $56.9\%$。
2. **对规模的依赖。** 增益只出现在他们测试过的最大模型上（约 $1000$ 亿参数及以上）；对小模型，思维链提示给出流利但错误的推理，准确率常常*低于*直接作答。作者把思维链描述为规模的一种*涌现*能力——后来的工作对这一说法作了限定，因为它取决于度量方式与模型的训练方式（[[pretraining/in-training-evaluation]]）。
3. **链的内容很重要。** 把链换成只有方程、换成相同数量的圆点、或把推理放在答案*之后*的消融实验，几乎恢复不了多少增益。中间步骤必须写在答案之前、用自然语言写成。

示例都很短——多数算术任务只有八条手写的解答——而且同样八条在若干数据集上都有效，这也是结果如此惊人的部分原因。

::: example 一条少样本思维链提示 {#ex-fewshot}
为问题 *A shop sells pens in packs of $12$. Mia buys $7$ packs and gives away $30$ pens. How many does she have left?* 写一个带一条示例的思维链提示。设约 $1.3$ 个词元对应一个英文单词、$1$ 个数字对应 $1$ 个词元，数一数有无思维链时模型分别必须生成多少个词元。
::: solution
一个带一条示例的提示：

> Q: Tom has 3 boxes of 8 eggs. He uses 5 eggs. How many are left?
> A: Tom has 3 × 8 = 24 eggs. After using 5 he has 24 − 5 = 19. The answer is 19.
>
> Q: A shop sells pens in packs of 12. Mia buys 7 packs and gives away 30 pens. How many does she have left?
> A:

期望的续写是 *Mia has 7 × 12 = 84 pens. After giving away 30 she has 84 − 30 = 54. The answer is 54.* 这约是 $16$ 个单词和 $6$ 个数字，合起来约 $16\cdot1.3 + 6\approx27$ 个词元；而直接作答 "54" 只有 $1$ 个词元。思维链在这里把输出乘了约 $27$ 倍，在难题上乘得更多——推理模型常常写出数千个词元。这些词元每一个都要花一次前向传播——这是思维链代价的一面，我们在[[#sec-cost]]与[[reasoning/test-time-scaling]]中再谈。
:::
:::

## 零样本思维链 {#sec-zeroshot}

Kojima 等（2022）去掉了示例。他们的**零样本思维链**提示分两个阶段。第一阶段是*推理提取*：在问题后接 "A: Let's think step by step."，让模型写出链。第二阶段是*答案提取*：把问题、触发语、生成的链以及一个依格式而定的短语（如 "Therefore, the answer (arabic numerals) is"）一并回喂，把模型的简短续写解析为答案。用一条指令跟随的 GPT-3 模型（text-davinci-002），MultiArith 基准上的准确率从 $17.7\%$ 升到 $78.7\%$，GSM8K 上从 $10.4\%$ 升到 $40.7\%$。示例良好的少样本思维链仍然更好，但仅凭触发语就恢复了大部分增益。Kojima 等比较了许多触发短语；有指令性的（"Let's think step by step"、"First,"）有帮助，误导性的或无关的则没有。

两阶段设计揭示了一个到 2026 年仍然成立的实践要点：答案必须被*提取*出来，而提取就是一个误差来源。以 "so the answer is probably 54, or perhaps 56" 收尾的链必须先归约为一个值，才能被评分、投票（[[reasoning/self-consistency]]）或给予奖励（[[reasoning/verifiable-rewards]]）。因此推理基准会固定答案格式（一个放进 \boxed{} 框中的数字、一个选项字母）与解析器。

::: warning "Let's think step by step" 并非普遍的提升
思维链最有帮助的是含若干相互依赖步骤的问题——算术应用题、符号操作、逻辑。Sprague 等（2024）分析了一百多篇论文，并在二十个数据集上做了自己的评测，发现思维链提示的增益集中在数学与符号推理上；在多数其他任务上增益很小，而在 MMLU 一类的知识问答上，大部分收益来自含方程的问题。思维链也可能有害：在某些知觉性或直觉性的判断上，写出推理反而降低准确率；在简单问题上它只是徒增成本。对已经训练过推理的模型，显式的思维链指令通常改变不大。先在你的任务上测试，而不是凭习惯加上它。
:::

## 为什么中间词元有帮助 {#sec-why}

给出的解释有三种，它们彼此互补而非互斥。

- **更多计算。** 每个生成的词元都是一次新的前向传播，其结果被写在任何后续传播都能读到的地方。思维链因此买到了单次前向传播所不具备的*串行*计算。这部分可以被严格化（[[#prop-depth]] 与 [[#sec-expressivity]]）。
- **分解为熟悉的步骤。** 一个难题变成一串容易的问题，每一个都长得像模型见过无数次的文本。Prystawski、Li 与 Goodman（2023）给出了形式化版本：当训练数据由共同出现的变量的局部簇构成时，模型能够经由中间变量逐步搭桥，估计两个从不同时出现的变量之间的关系，而推理恰好在那种设定下起作用。
- **以好的轨迹为条件。** 在预训练数据中，一道难题“正确解答在前、答案在后”远比“直接跟一个正确答案”常见。先写出解答，会把模型移到其分布中答案正确的那一部分。

### 串行深度 {#sec-depth}

考虑一个 $L$ 层的仅解码器 Transformer（[[transformers/transformer-block]]）。在位置 $t$，第 $\ell$ 层通过注意力读取位置 $1,\dots,t$ 的第 $(\ell-1)$ 层状态。信息沿层*向上*、沿位置*向前*流动，但第 $\ell$ 层的状态永远无法馈入更低层的状态——除了通过输出：位置 $t$ 的顶层产生一个词元，而该词元就是位置 $t+1$ 的输入，计算在那里从第 $1$ 层重新开始。

::: proposition 思维链把串行深度相乘 {#prop-depth}
在一个 $L$ 层的仅解码器 Transformer 中，输入长度为 $n$，先生成 $m$ 个思维链词元、再生成一个答案词元。把一条*串行路径*定义为一系列层的应用，其中每一次都把前一次的输出当作输入。终止于答案词元的最长串行路径长度为 $L(m+1)$。没有思维链（$m = 0$）时，无论输入多长，它都只有 $L$。
:::

::: proof
设提示占据位置 $1,\dots,n$，思维链占据位置 $n+1,\dots,n+m$；位置 $t$ 的顶层产生位置 $t+1$ 处的词元，因此答案词元由位置 $n+m$ 处的顶层产生。串行路径使用两类边：从 $(s,\ell-1)$ 到 $(t,\ell)$（$s\le t$，经由注意力或残差流）的边，使层数加一；以及经由一个*生成的*词元从 $(t, L)$ 到 $(t+1, 1)$ 的边——这只在 $t+1\in\{n+1,\dots,n+m\}$ 时可能——提示词元是给定的，不是算出来的。两条词元边之间，路径至多爬升 $L$ 次层应用。一条路径上至多有 $m$ 条词元边，因而至多有 $m+1$ 次爬升，总共至多 $L(m+1)$ 次层应用。上界可由这样一条路径达到：在位置 $n$ 爬满整个层栈，经由它送出的词元到达位置 $n+1$，在那里再爬满层栈，如此直到位置 $n+m$。当 $m = 0$ 时没有词元边，上界为 $L$。
:::

这条命题说的是*依赖结构*，不是模型真正如何用掉这些额外的深度。但它解释了一个基本局限：对直接提问的答案可用的串行层应用次数由架构固定，而一个计算的长度——一盘棋的步数、一次乘法的位数——随输入增长。加宽、加头或加长输入，增加的是并行计算，不是串行步骤。

::: example 推理模型的串行深度 {#ex-depth}
一个模型有 $L = 64$ 层。它可以直接回答一个问题，或在 $5{,}000$ 个词元的思维链之后回答。两种情形下最长串行路径各有多长？提示之后一共做了多少次前向传播？
::: solution
直接回答：$L = 64$ 次串行层应用，答案词元一次前向传播。带思维链：$64\cdot5{,}001 = 320{,}064$ 次串行层应用、$5{,}001$ 次前向传播。思维链没有让任何单次传播变深；它让传播的*复合*变深，而词元是其间唯一的通道。这条通道很窄——一个词元，对 $10^5$ 大小的词表约 $17$ 比特——这就是思维链必须把后面步骤所需的状态写下来的原因。
:::
:::

### 表达能力结果 {#sec-expressivity}

理论计算机科学用电路复杂性类把“固定的串行深度”严格化。$\mathsf{TC}^0$ 是可由常深度、多项式规模、带阈值（多数）门的布尔电路族解决的问题类；$\mathsf{NC}^1$ 允许对数深度、有界扇入的门。已知 $\mathsf{TC}^0\subseteq\mathsf{NC}^1$，且人们广泛相信——但未证明——这一包含是严格的。

::: theorem 有思维链与无思维链的 Transformer（已发表结果，非正式陈述） {#thm-expressivity}
1. （Merrill 与 Sabharwal，2023。）层数为常数、数值精度为 $O(\log n)$ 比特的 Transformer，在长度 $n$ 的输入上可被一致的 $\mathsf{TC}^0$ 电路模拟。因此，若 $\mathsf{TC}^0\ne\mathsf{NC}^1$，这样的 Transformer 靠一次前向无法解 $\mathsf{NC}^1$-完全问题，例如求五个元素的置换序列的复合（Barrington，1989）。
2. （Feng 等，2023。）在同一假设下，直接输出答案的常深度对数精度 Transformer 无法求算术表达式的值或解线性方程组，除非其规模随输入长度超多项式增长；而*常数*规模的 Transformer 通过生成长度为多项式的思维链却能解决这些任务。
3. （Merrill 与 Sabharwal，2024。）允许 Transformer 生成 $t(n)$ 个中间词元，其能力随 $t$ 增长：对数个步骤只把它扩展到略超 $\mathsf{TC}^0$；线性多个步骤使它能识别每一个正则语言（于是能跟踪任何有限自动机的状态）；多项式多个步骤（加上一个温和的架构假设）使它恰好能识别所有多项式时间可解的问题。
4. （Li 等，2024。）借助 $T$ 步思维链，常数精度位数的常深度 Transformer 能计算任何由规模为 $T$ 的布尔电路可计算的函数。
:::

我们不在这里证明这些定理；证明在引用的论文里。它们确立了什么、没有确立什么，应当谨慎地说清。它们是关于**表达能力**的结果——*是否存在*一组权重能计算该函数——建立在关于精度与注意力的理想化假设之上。它们并不说梯度下降会找到那些权重，不说训练出的模型会像那些构造一样使用思维链，也不说自然语言推理具有那些形式问题的结构。它们还依赖未证明的猜测 $\mathsf{TC}^0\ne\mathsf{NC}^1$。在这些限制之内，它们对“中间词元是能增加能力，还是只是让能力显形？”给出了干净的答复：能增加能力，因为它们增加了串行步骤。

在合成任务上，实验与这幅图景一致。直接训练来跟踪置换序列或有限自动机状态的模型往往学到在更长输入上失效的捷径（Liu 等，2023），而训练来写出中间状态的模型泛化得更远。下面的例子让这一想法变得具体。

::: example 猜球游戏 {#ex-shell}
球开始时在五个杯子中的 $0$ 号杯下；一列 $n$ 次移动，每次交换两个杯子。最后球在哪个杯子下？写出移动序列 $(3,4), (0,2), (4,3), (3,2), (3,2), (4,1)$ 的草稿本轨迹，并解释为什么这个任务是[[#thm-expressivity]]的一个自然测试。
::: solution
跟踪持球的杯子。从 $0$ 出发。$(3,4)$ 没碰到 $0$ 号杯：仍是 $0$。$(0,2)$ 把它移到 $2$。$(4,3)$：仍是 $2$。$(3,2)$：到 $3$。$(3,2)$：回到 $2$。$(4,1)$：仍是 $2$。草稿本轨迹是 $0, 2, 2, 3, 2, 2$，答案是 $2$ 号杯。

每一步只需要上一个状态和一次移动，因此一条在每次移动后写出状态的思维链把 $n$ 步的复合变成 $n$ 个简单步骤。直接作答则要求在一次前向中复合 $n$ 个五元素置换；跟踪球能区分恒等置换与五轮换，所以这正是[[#thm-expressivity]]第 1 条中的 $\mathsf{NC}^1$-完全问题，除非 $\mathsf{TC}^0 = \mathsf{NC}^1$，常深度 Transformer 无法在一次前向中对所有 $n$ 解决它。
:::
:::

### 误差会累积 {#sec-compound}

串行计算有一个代价：每一步都可能出错。若链的每一步独立地以概率 $q$ 正确，则 $s$ 步的链完全正确的概率为 $q^s$。即使 $q = 0.99$，一百步也只有 $0.99^{100}\approx0.37$。错误未必致命——后面的步骤可能察觉并修好前面的疏漏，而用强化学习训练的推理模型会明显地做这样的事（[[reasoning/verifiable-rewards]]）——但小数率误差的累积，正是长链需要检查、采样与验证的基本原因，后续各章将逐步展开。

::: widget plot
f: q^x; 1/5 + (4/5)*(1 - 5*(1 - q)/4)^x
x: 0, 200
y: 0, 1
sliders: q=0.98:0.9:0.999:0.001
labels: all $s$ steps correct, $q^s$; final answer correct (shell game, $5$ cups)
caption: 一条 $s$ 步链在每步正确概率为 $q$ 时完全正确的概率（$q^s$），以及当出错的一步把球放到一个随机的错误杯子下时、五杯猜球游戏最终答案正确的概率（在一道习题中推导）。后来的错误也能纠正先前的错误，所以答案比链本身更容易正确，但两者都朝各自的下限衰减——链是 $0$，答案是猜测率 $1/5$。把 $q$ 从 $0.98$ 移到 $0.999$，看看长推理需要多高的单步可靠性。
:::

## 分解 {#sec-decomposition}

思维链自己决定步骤。另一些方法则把分解显式化。

**由简入繁提示**（least-to-most prompting；Zhou 等，2023）分两个阶段。先让模型把问题分解成一列更简单的子问题；然后按序逐个求解，每个解答都追加到给下一步的提示里。在把“jump around left twice”一类指令翻译成动作序列的 SCAN 基准上（其测试划分要求比训练更长的复合），用 $14$ 条示例的由简入繁提示在一个代码训练的 GPT-3 模型上达到了约 $99\%$ 的准确率，而思维链提示只有约 $16\%$。增益来自**由易到难的泛化**：示例展示的是如何归约问题，而归约适用于比所展示的任何问题都更长的问题。

**Self-ask**（Press 等，2023）让模型在最终答案之前自己提出并回答明确的后续问题（"Follow up: iPhone 发布时，美国总统是谁？"），这同时为调用搜索引擎提供了自然的时机。Press 等把**组合性差距**定义为：模型两个单跳子问题都答对、却在两跳问题上答错的比例；他们发现这一差距不随模型变大而缩小，而让模型显式提出子问题会使它变窄。

::: algorithm 由简入繁提示 {#alg-ltm}
**输入：**问题 $x$；带示例的分解提示 $P_d$ 与求解提示 $P_s$。
1. 生成子问题 $(u_1,\dots,u_k)\sim p_\theta(\cdot\mid P_d, x)$，按从最简单到原问题排序（$u_k = x$）。
2. 令上下文 $C\leftarrow (P_s, x)$。
3. 对 $i = 1,\dots,k$：生成答案 $v_i\sim p_\theta(\cdot\mid C, u_i)$，并把 $(u_i, v_i)$ 追加到 $C$。
4. 返回 $v_k$。
:::

::: example 分解一道应用题 {#ex-ltm}
*Elsa 有 $5$ 个苹果。Anna 比 Elsa 多 $2$ 个苹果。两人一共有多少个苹果？*给出它的由简入繁分解及求解。
::: solution
分解：$u_1$ = “Anna 有几个苹果？”，$u_2$ = “两人一共有多少个苹果？”。求解：$v_1$ = “Anna 有 $5 + 2 = 7$ 个。”然后 $(u_1, v_1)$ 已在上下文中，$v_2$ = “两人共有 $5 + 7 = 12$ 个。”答案是 $12$。分解步骤完成了规划；每个求解步骤都是一次输入已经写明的单一运算——正是[[#prop-depth]]指出的固定深度模型能从中受益的结构。
:::
:::

## 外包计算：程序辅助推理 {#sec-pal}

语言模型会犯任何计算器都不会犯的算术错误。**程序辅助语言模型**（PAL；Gao 等，2023）与密切相关的**思维程序**（program of thoughts；Chen 等，2022）把解答的两部分分开：模型以程序形式写出推理，解释器负责执行。模型的思维链变成一段代码，其中的变量命名问题的各个量；答案就是程序打印出的东西。Gao 等报告，在 GSM8K 上，配代码模型的 PAL 比一个大得多的通用模型的思维链提示高约 $15$ 个百分点，而在数字更大的基准变体（GSM-Hard）上优势更大——那里模型的心算失灵，解释器的却不会。

::: example 一个程序辅助的解答 {#ex-pal}
为下题写出 PAL 风格的解答：*一列火车 09:40 出发，以 $93$ km/h 行驶 $372$ km，然后等待 $25$ 分钟，再以 $72$ km/h 行驶 $108$ km。它何时到达？*
::: solution
```python
leave = 9 * 60 + 40                 # 零点后的分钟数
leg1 = 372 / 93 * 60                # 240.0 分钟
wait = 25
leg2 = 108 / 72 * 60                # 90.0 分钟
arrive = leave + leg1 + wait + leg2 # 935.0
print(f"{int(arrive // 60):02d}:{int(arrive % 60):02d}")   # 15:35
```

模型的职责是把问题*翻译*成代码——有哪些量、它们如何组合——算术则交给解释器。若模型写错了公式，程序就跟着错，所以 PAL 消除的是计算错误，不是推理错误。同样的分工在[[agents]]中作为工具调用重现，也出现在对答案的自动检验中——正是后者使数学与代码上的强化学习成为可能（[[reasoning/verifiable-rewards]]）。
:::
:::

::: quiz
一个 $L = 48$ 层的模型被要求复合一列 $500$ 个置换。哪些说法是正确的？（多选。）
- [x] 直接作答时，到答案的最长串行路径长度为 $48$，与输入长度无关。
- [x] 在每个置换之后写出中间状态，可得到长度至多 $48\cdot501$ 的串行路径。
- [ ] 一段包含所有置换的足够长的提示能增加串行深度，因为注意力会读取它的全部内容。
- [ ] 表达能力定理证明，训练出的模型将学会用思维链跟踪状态。
::: solution
由[[#prop-depth]]，无思维链时串行深度为 $L$，带 $m$ 个生成词元时为 $L(m+1)$，故前两条正确。更长的提示增加的是并行计算（每层更多位置），不是串行步骤，因为输入词元是给定的而非算出的。表达能力结果（[[#thm-expressivity]]）只说存在合适的权重，不说训练能找到它们。
:::
:::

## 一个数值算例 {#sec-code}

下面的清单把五杯猜球游戏模拟成一个固定深度网络的玩具模型：一次前向传播至多可靠地施加 $h = 4$ 次移动，再多就只能猜，且每次传播以概率 $\varepsilon = 0.02$ 出错。思维链则在每 $h$ 次移动之后写出球的位置。这是对[[#prop-depth]]的演示，不是真实 Transformer 的模型。

```python
import random
rng = random.Random(0)

# 猜球游戏：球开始时在五只杯子中的 0 号杯下；每次移动交换两只杯子。
def moves(n):
    return [tuple(rng.sample(range(5), 2)) for _ in range(n)]

def trace(ms, start=0):
    """思维链会写下的草稿本：每次移动后球所在的杯子。"""
    pos, out = start, []
    for a, b in ms:
        pos = b if pos == a else a if pos == b else pos
        out.append(pos)
    return out

ms = moves(6)
print("moves:", ms)
print("scratchpad:", trace(ms))

# 固定深度网络的玩具模型：一次前向传播至多可靠地施加 h 次移动；
# 超出就只能猜（1/5）。每次传播以概率 eps 出错。
def direct(ms, h, eps):
    if len(ms) > h:
        return rng.randrange(5)
    true = trace(ms)[-1]
    return true if rng.random() > eps else rng.choice([c for c in range(5) if c != true])

def with_cot(ms, h, eps):
    pos = 0
    for i in range(0, len(ms), h):                 # 每 h 次移动写出一个词元
        chunk = ms[i:i + h]
        true = trace(chunk, pos)[-1]
        pos = true if rng.random() > eps else rng.choice([c for c in range(5) if c != true])
    return pos

h, eps, trials = 4, 0.02, 20000
print(" moves  direct  with CoT  CoT tokens  (1-eps)^tokens")
for n in [2, 4, 8, 16, 32, 64]:
    d = c = 0
    for _ in range(trials):
        ms = moves(n); ans = trace(ms)[-1]
        d += direct(ms, h, eps) == ans
        c += with_cot(ms, h, eps) == ans
    k = -(-n // h)
    print(f"{n:5d}  {d/trials:6.3f}  {c/trials:8.3f}  {k:10d}  {(1-eps)**k:14.3f}")
```

```text
moves: [(3, 4), (0, 2), (4, 3), (3, 2), (3, 2), (4, 1)]
scratchpad: [0, 2, 2, 3, 2, 2]
 moves  direct  with CoT  CoT tokens  (1-eps)^tokens
    2   0.978     0.980           1           0.980
    4   0.979     0.980           1           0.980
    8   0.200     0.960           2           0.960
   16   0.202     0.923           4           0.922
   32   0.200     0.855           8           0.851
   64   0.203     0.731          16           0.724
```

开头几行复现了[[#ex-shell]]。在深度预算之内，直接作答与思维链同样好；超出预算，它立刻掉到猜测率 $0.2$。思维链仍在工作，但缓慢衰减，因为它写出的每个状态（共 $\lceil n/h\rceil$ 个）都是一次新的出错机会；它的准确率略*高于* $(1-\varepsilon)^k$，因为出错的一步偶尔会把球放回正确的位置。后面有一道习题推导出精确曲线。

## 从提示到训练出的推理 {#sec-trained}

思维链*提示*是要求一个为其他目的训练的模型产出推理。自 2022 年起，推理越来越多地被*训练进模型*。

- **带推理依据的指令微调。** Chung 等（2022）发现，不含思维链数据的指令微调配比会损害模型的思维链能力，于是在 Flan 数据集中纳入九个思维链数据集以保住它（[[post-training/instruction-tuning]]）。
- **自我启动。** STaR（Zelikman 等，2022）采样推理依据，保留其中得到正确答案的那些，在其上微调，并反复进行——这是一种带可检验奖励的强化学习，[[reasoning/verifiable-rewards]]将详细分析。
- **推理模型。** 自 2024 年 9 月起，多家开发者发布了用大规模强化学习训练的模型，它们学会在作答前写出长长的思维链。OpenAI 的 o1 公告报告性能随更多强化学习算力与更多思考时间而提升，但未公开方法；DeepSeek-R1 报告（DeepSeek-AI，2025）详细描述了开放的配方并发布了权重。这类模型把推理写在分隔符之间（例如 `<think>` 与 `</think>`），有些部署只向用户展示其摘要。

对推理模型而言，本章各方法的角色发生了变化。显式的思维链指令几乎不再增添什么，因为模型本来就在推理；思维的少样本示例甚至可能有害——DeepSeek-R1 报告为其模型记录了这一点。沿用下来的是分析：思维链为什么有帮助（[[#prop-depth]]）、为什么昂贵（[[#sec-cost]]）、误差为什么会累积（[[#sec-compound]]）、答案为什么必须被提取和检验。

## 推理的代价 {#sec-cost}

思维链的每个词元都是一个输出词元：它占用一次前向传播、往 KV缓存里增加一个条目，并被 API 提供方按输出词元价格计费。下面三个量随之而来。

::: proposition 思维链的成本 {#prop-cost}
对一个有 $N$ 个参数的模型，在 $n$ 个词元的提示之后生成 $m$ 个思维链词元和 $a$ 个答案词元，忽略注意力项：

- 生成计算量约为 $2N(m + a)$ FLOPs（每个词元每个参数两个 FLOP，[[scaling]]）；
- 在解码速度为每秒 $v$ 个词元时，增加的延迟为 $m/v$ 秒；
- 在每个输出词元价格 $c_{\text{out}}$ 下，增加的成本为 $m\,c_{\text{out}}$。

KV缓存随 $n + m$ 线性增长，对其做注意力的计算量为每词元正比于 $n + m$，当 $m$ 达到数万词元时这一点不容忽略。
:::

::: proof
稠密模型生成单个词元的一次前向传播，要把该词元的激活与每个权重矩阵各乘一次，即每参数一次乘法和一次加法；$m+a$ 个生成词元需要 $m+a$ 次传播。延迟与成本两条分别是解码速度与每词元价格的定义。
:::

::: example 思考的价格 {#ex-cost}
某服务每天回答 $10^6$ 个问题。直接作答需要 $30$ 个输出词元；用推理模型则是 $2{,}000$ 个思考词元加 $30$ 个。输出词元每百万个 $\$10$，解码速度为每秒 $60$ 个词元。比较每日成本与每题延迟。
::: solution
直接作答：$30\times10^6$ 个词元，每天 $\$300$；延迟 $30/60 = 0.5$ 秒。带推理：$2{,}030\times10^6$ 个词元，每天 $\$20{,}300$，每题 $2{,}030/60\approx34$ 秒。思维链把成本和延迟都乘了约 $68$ 倍。这是否值当，取决于它在这类负载上换来多少准确率——[[reasoning/test-time-scaling]]将从数量上研究这一权衡，[[inference]]则从推理服务一侧研究。
:::
:::

::: history
Ling 等（2017）为代数题生成了推理依据；Nye 等（2021）训练模型使用草稿本；Cobbe 等（2021）发布了带自然语言解答的 GSM8K。2022 年 1 月，Wei 等贴出了《Chain-of-thought prompting elicits reasoning in large language models》（NeurIPS 2022）；同年 5 月，Kojima 等展示了零样本触发语 *Let's think step by step*（NeurIPS 2022）。自洽性（Wang 等，2022）、由简入繁提示（Zhou 等，2022）、程序辅助模型（Gao 等，2022；Chen 等，2022）与 self-ask（Press 等，2022）在随后的几个月内相继问世；多数在 2023 年的会议上发表。STaR（Zelikman 等，2022）在模型自己成功的推理依据上训练。把思维链视为额外计算的理论分析出现在 2023 与 2024 年（Feng 等；Merrill 与 Sabharwal；Li 等）。OpenAI 的 o1（2024 年 9 月）与 DeepSeek-R1（2025 年 1 月）使又长又经过训练的推理成为解难题的默认方式。
:::

::: summary
- **思维链**是输入与答案之间的生成文本 $z$，$p_\theta(z,y\mid x) = p_\theta(z\mid x)p_\theta(y\mid x,z)$；可以用示例（少样本）、指令（零样本）或训练获得它。
- Wei 等（2022）把 PaLM 540B 在 GSM8K 上从 $17.9\%$ 提到 $56.9\%$；增益依赖模型规模，也依赖推理写在答案之前。Kojima 等（2022）仅凭 *Let's think step by step* 就得到大部分增益。
- 生成 $m$ 个词元把 $L$ 层 Transformer 的**串行深度**从 $L$ 提升到 $L(m+1)$；表达能力定理表明，若 $\mathsf{TC}^0\ne\mathsf{NC}^1$，思维链能让 Transformer 解决单次前向无法解决的问题——那是关于权重所能计算的结果，不是训练所能找到的。
- 分解（由简入繁、self-ask）把步骤显式化并支持由易到难的泛化；**程序辅助**推理把算术交给解释器。
- 误差会累积：$s$ 个可靠性为 $q$ 的步骤给出 $q^s$，由此引出采样、验证与检查。
- 思维链的每个词元约花费 $2N$ FLOPs、一个解码步骤和一个输出词元的价格；推理模型会写出成千上万个这样的词元。
:::

::: solution
$400\times10{,}000 = 4\times10^6$ 个词元，而 $4\times10^6\times\$10/10^6 = \$40$。

::: exercise 重试验证过的步骤 {level=2 check="22.22"}
假设一道 $20$ 步解答的每一步都能被精确检查（例如由解释器），失败的步骤会被重新生成直到通过。对某一步的每次尝试以概率 $0.9$ 成功，相互独立。步骤尝试总次数的期望是多少？给出两位小数。
::: solution
一步的尝试次数服从成功概率 $0.9$ 的几何分布，均值为 $1/0.9$。由期望的线性性，总数为 $20/0.9 = 22.22$。对照不检查的链正确的概率 $0.9^{20}\approx0.12$：检查把指数式衰减变成了线性开销，这正是过程奖励（[[reasoning/process-outcome-rewards]]）与步骤级搜索（[[reasoning/search]]）的动机。
:::
:::

::: exercise 少样本还是零样本？ {level=2}
你必须用一个默认不推理的通用指令微调模型解决 $5{,}000$ 条关于发票算术的客户问题。描述一个实验，在直接作答、零样本思维链与少样本思维链之间做选择，包括你测量什么、以及如何提取答案。
::: solution
取一个几百条代表性问题的带标签样本（与用于撰写示例的问题相互留出）。固定答案格式——例如 "Final answer: <amount>"——并写一个按该格式提取最后一个金额的解析器，无法解析的输出计为错。运行三种提示（固定解码设置，例如贪心），测量准确率、解析失败率、平均输出词元数与延迟。由于用的是同一批问题，用配对检验比较准确率（如[[prompting-rag/prompt-design#sec-testing]]）。选择准确率与最佳者无显著差异之中最便宜的一种；若少样本胜出，再换一组示例检验其优势并非特定于该组示例。
:::

::: exercise 一个分解 {level=2}
给出下题的由简入繁分解（[[#alg-ltm]]）：*一个水箱容量 $240$ 升。从空箱开始，以每分钟 $12$ 升的速度注水，同时以每分钟 $4$ 升的速度排水。多少分钟后水位达到四分之三？*并求解。
::: solution
子问题：$u_1$ “净注水速率是多少？”$u_2$ “四分之三容量是多少升？”$u_3$ “需要多少分钟？”答案：$v_1$ $12 - 4 = 8$ 升每分钟；$v_2$ $0.75\times240 = 180$ 升；$v_3$ $180/8 = 22.5$ 分钟。每个答案只用到问题与先前的答案。
:::

::: exercise 猜球游戏的精确曲线 {level=3 check="0.7336"}
在清单的玩具模型中，思维链写出 $k$ 个状态。给定前一状态正确，每个写出的状态以概率 $1-\varepsilon$ 正确；出错时，它是四个非正确下一位置的杯子中均匀随机的一只。证明最终答案正确的概率为

$$
P_k = \tfrac15 + \tfrac45\big(1 - \tfrac54\varepsilon\big)^k,
$$

并对 $k = 16$、$\varepsilon = 0.02$ 求值到四位小数。与模拟结果比较。
::: solution
设 $P_j$ 为第 $j$ 个写出状态正确的概率，$P_0 = 1$。前一状态正确（概率 $P_{j-1}$）时，下一状态以 $1-\varepsilon$ 正确。前一状态错误时，作用其上的那步得到某个不同于正确位置的杯子（移动是双射）；以概率 $1-\varepsilon$ 写出的是那个错误杯子，以概率 $\varepsilon$ 写出除它以外均匀随机的一只杯子，而这恰为正确杯子的概率是 $1/4$。于是

$$
P_j = (1-\varepsilon)P_{j-1} + \tfrac{\varepsilon}{4}(1 - P_{j-1}) = \tfrac{\varepsilon}{4} + \big(1 - \tfrac54\varepsilon\big)P_{j-1}.
$$

不动点是 $P^* = \frac{\varepsilon/4}{5\varepsilon/4} = \frac15$，且 $P_j - \frac15 = (1-\frac54\varepsilon)(P_{j-1} - \frac15)$，所以 $P_k = \frac15 + \frac45(1-\frac54\varepsilon)^k$。$k = 16$、$\varepsilon = 0.02$ 时：$0.975^{16} = 0.6670$，且 $P_{16} = 0.2 + 0.8\cdot0.6670 = 0.7336$。模拟在 $20{,}000$ 次试验下给出 $0.731$，在其约 $0.003$ 的标准误差之内。
:::

::: exercise 有无草稿本的奇偶校验 {level=3}
$n$ 个比特的奇偶校验在有奇数个 $1$ 时为 $1$。(a) 写出一个奇偶校验的思维链，使每个生成的词元只需一个简单运算。(b) 奇偶校验*属于* $\mathsf{TC}^0$（阈值电路能计数），所以[[#thm-expressivity]]并不禁止单次前向的解法。然而已知训练出的 Transformer 很难在长输入上直接学会奇偶校验。解释这与定理为何不矛盾，并说明它对表达能力与可学习性之间的鸿沟提示了什么。
::: solution
(a) 写出运行奇偶校验：读完比特 $b_i$ 后，发出 $s_i = s_{i-1}\oplus b_i$，$s_0 = 0$；答案是 $s_n$。每个词元只需要两个比特的异或——上一个发出的状态与下一个输入比特，后者注意力可按位置取到。

(b) 定理关心的是权重是否存在；单次前向的奇偶校验网络存在，但要求精心调校的权重（例如精确计数 $1$ 的个数的注意力，以及对计数奇偶性的陡峭阈值），而损失面几乎没有指向它的梯度信号：改动任何一个输入比特都会翻转输出，因此输入的任何低阶统计量都与标签无关。有了草稿本，每个目标词元只依赖两个输入，易于学习。表达能力是一种能力的必要条件而非充分条件：梯度下降能从数据中找到什么是一个独立的问题；即使在表达能力上不需要思维链之处，它也能帮助*可学习性*。
:::
:::

::: exercise 加法的草稿本 {level=3}
写一个纯 Python 函数：输入是两个非负整数的字符串形式，输出它们之和的草稿本，风格与 Nye 等相同——从右起每个数位一行，写明两个数字、进来的进位、写下的数字与出去的进位，最后写出和。对 $5678 + 9876$ 运行它。
::: solution
```python
def scratchpad_add(a, b):
    a, b = a[::-1], b[::-1]
    carry, digits, lines = 0, [], []
    for i in range(max(len(a), len(b))):
        x = int(a[i]) if i < len(a) else 0
        y = int(b[i]) if i < len(b) else 0
        s = x + y + carry
        lines.append(f"pos {i}: {x} + {y} + carry {carry} = {s} -> write {s % 10}, carry {s // 10}")
        digits.append(str(s % 10)); carry = s // 10
    if carry:
        digits.append(str(carry)); lines.append(f"final carry {carry}")
    lines.append("answer " + "".join(reversed(digits)))
    return "\n".join(lines)

print(scratchpad_add("5678", "9876"))
```

```text
pos 0: 8 + 6 + carry 0 = 14 -> write 4, carry 1
pos 1: 7 + 7 + carry 1 = 15 -> write 5, carry 1
pos 2: 6 + 8 + carry 1 = 15 -> write 5, carry 1
pos 3: 5 + 9 + carry 1 = 15 -> write 5, carry 1
final carry 1
answer 15554
```

每一行只依赖两个输入数字与上一个进位，因此在这样的轨迹上训练的模型只需学习一个单位数字的运算，而不是一次跨越所有数位的长程依赖。
:::
