前几章讲并行时，一次只讲一种方案。前沿规模的训练运行则要把它们同时全部用上：在数以万计的加速器上跑几个星期甚至几个月，并且要在硬件每隔几小时就出一次故障的情况下持续取得进展。到了这个规模，问题就不再只是算术与显存，而是设备如何连线、各个并行维度如何铺在这套连线上、硬件峰值实际有多少变成了训练、以及一次运行能多快发现故障、丢弃丢失的工作并恢复。本章把这些零件装配起来：训练集群的构造；对一个约 $4000$ 亿参数的模型，从显存到吞吐完整推演一套布局；利用率的度量；以及已发表的大规模训练报告所记录的可靠性工程——故障率、检查点间隔与恢复。

这里的数字建立在前面各章之上：FLOPs 与显存见[[scaling/flops-memory]]，设备与链路数字见[[scaling/accelerators]]，分片见[[scaling/data-parallelism]]，张量、流水线与上下文方案见[[scaling/model-parallelism]]。同样的主题也从训练配方的角度在[[pretraining/training-loop]]与[[pretraining/training-stability]]中简述过；这类运行的能耗与环境代价见[[llm-society/environmental-cost]]。

## 训练集群的构造 {#sec-cluster}

按 2022 至 2025 年的公开报告所述，一个大语言模型训练集群由几种重复的单元装配而成。

- **服务器**（节点）：通常每节点 $8$ 块加速器，内部以高带宽互连相连（NVIDIA GPU 用 NVLink 与 NVSwitch，AMD 用 Infinity Fabric），并配有 CPU、主机内存与本地存储。较新的机架级系统（截至 2026 年）把高速互连扩展到数十块加速器。
- **横向扩展网络**：通常每块加速器配一个网络接口，2023–2024 年的系统为 $400$ Gb/s，跑在 InfiniBand 或支持 RDMA 的以太网（RoCE）上，组织方式是每台服务器的第 $k$ 块加速器各接自己的一组交换机——一种**轨道优化**（rail-optimised）拓扑——其上再叠多层胖树。TPU pod 则用光路交换机把芯片直接连成环面（[[scaling/accelerators]]）。
- **存储**：一个并行文件系统或对象存储，存放训练数据与检查点，速度要能在几分钟内吞下一个 TB 量级的检查点。
- **控制软件**：调度器、健康检查，以及训练框架自带的监控。

Meta 的 Llama 3 报告（2024）是最详尽的公开描述之一：其最大模型在多达 $16{,}384$ 块 H100 GPU 上训练，每服务器八块，走每 GPU $400$ Gb/s 的 RoCE 网络、三层拓扑，布局选择使通信最重的并行留在服务器内部。报告还指出，数千块 GPU 同步计算与同步通信的交替使数据中心的用电功率波动数十兆瓦，给电网带来约束——这提醒我们，在这个规模上，机房本身就是系统的一部分。

## 一套完整的布局 {#sec-layout}

各并行维度——张量（$t$）、上下文（$c$）、流水线（$p$）与数据（$d$）——相乘等于设备数 $n = t\cdot c\cdot p\cdot d$。标准启发式按通信强度与链路速度的匹配来排序：

1. **张量并行置于最内层**，在一台服务器之内（$t\le8$）：它每个块都要对激活做一次全规约。
2. **上下文并行其次**，仅当序列长到需要它时。
3. **流水线并行跨服务器**：相邻阶段之间点到点传输激活，能容忍较慢的链路。
4. **数据并行置于最外层**，按需分片（ZeRO 或 FSDP）：每步一次梯度规约，可与反向传播重叠。

::: definition 布局 {#def-layout}
一个训练作业在 $n$ 块设备上的**布局**，是把每台设备指派到 $t\times c\times p\times d$ 网格中的坐标 $(i_t, i_c, i_p, i_d)$，再配上微批次大小、每副本的微批次数 $m$、流水线调度、分片阶段与重计算策略的选择。除一个坐标外其余坐标都相同的设备构成该维度的一个**组**，该维度的集体通信在组内进行。
:::

::: example 给一个 4050 亿参数的模型做布局 {#ex-layout}
Llama 3 报告给出了其最大模型的形状——$L = 126$ 层、宽 $h = 16{,}384$、$128$ 个查询头与 $8$ 个键值头、前馈宽 $53{,}248$、词表 $128{,}256$、$N\approx4.05\times10^{11}$ 个参数——以及在 $16{,}384$ 块 GPU 上以序列长 $s = 8192$ 预训练时的布局：$t = 8$、$c = 1$、$p = 16$、$d = 128$，每个数据并行副本每步 $16$ 条序列（每个全局批次约 $1600$ 万词元）。请核对这套布局的算术：设备数、每 GPU 的模型状态（设数据并行组上做 ZeRO-1）、按 Megatron 记账在选择性重计算与完整重计算下的激活显存，以及流水线气泡。
::: solution
*设备：* $8\cdot1\cdot16\cdot128 = 16{,}384$。*批次：* $128\cdot16 = 2048$ 条序列 $\times8192 = 1680$ 万词元。

*模型状态。*每块 GPU 持有 $N/(tp) = 4.05\times10^{11}/128 = 3.16\times10^9$ 个参数：bf16 权重 $6.3$ GB、bf16 梯度 $6.3$ GB。其 fp32 主权重与 Adam 矩（每参数 $12$ 字节，$38$ GB）分片到 $d = 128$：$0.30$ GB。合计约 $13$ GB。

*激活。*在张量并行、序列并行与选择性重计算下，一层每个单序列微批次存 $34sbh/t = 34\cdot8192\cdot16{,}384/8 = 570$ MB（[[scaling/flops-memory#thm-activations]]）。一个阶段约持 $126/16\approx8$ 层，而 1F1B 下第一个阶段最多持有 $p = 16$ 个微批次：$8\cdot16\cdot0.57 = 72$ GB。加上 $13$ GB 的状态就超过 $80$ GB，所以按这套记账，仅靠选择性重计算此配置放不下。完整重计算只存分片后的块输入，每层每微批次 $2sbh/t = 34$ MB，$8\cdot16\cdot34\text{ MB} = 4.3$ GB，外加正在重计算的那一层的工作激活。（不带 dropout、带融合注意力的真实实现存的比 Megatron 常数少，重计算也可以只用于部分层；要点在于重计算策略正是由这套算术选定的。）

*气泡。*若 $m = 16$ 个微批次、$p = 16$ 个阶段，朴素 1F1B 调度会空闲 $15/31 = 48\%$ 的时间。$v = 8$ 个虚拟阶段（每段一层）的交错调度给出 $15/(128 + 15) = 10.5\%$（[[scaling/model-parallelism#prop-interleaved]]）。Llama 3 报告描述了对交错调度的修改，正是在这种批次约束下工作。
:::
:::

这个例子展示了布局设计的逻辑。全局批次受优化（临界批次大小）封顶，从而给 $m\cdot d$ 封了顶；每设备的模型状态与激活给 $t\cdot p$ 的最小值封了底；链路层级给 $t$ 封了顶；而气泡则推动大 $m$ 或交错。四者同时留有余地的情况很少见。

## 利用率 {#sec-mfu}

::: definition 模型 FLOPs 利用率与硬件 FLOPs 利用率 {#def-mfu}
对一次以 $\tau$ 词元/秒的速率在 $n$ 块峰值吞吐为 $F$ 的设备上运行的训练，**模型 FLOPs 利用率**（MFU）为

$$
\text{MFU} = \frac{c_{\text{tok}}\,\tau}{nF},
$$ {#eq-mfu}

其中 $c_{\text{tok}}$ 是模型在数学上完成一个训练步每个词元所需的 FLOPs 数——取 $6N$，若计入注意力项则为 $6N$ 加 $6Lsh$（含因果折半）。**硬件 FLOPs 利用率**（HFU）在分子中计入实际执行的全部 FLOPs，包括重计算。Chowdhery et al.（2022）引入 MFU，正是为了比较实现时不奖励冗余工作。
:::

::: example 该布局的 MFU {#ex-mfu}
对[[#ex-layout]]的布局，Llama 3 报告给出每 GPU 约 $400$ TFLOP/s 的吞吐与约 $41\%$ 的 MFU（按 NVIDIA 的 H100 SXM 规格，bf16 峰值 $989$ TFLOP/s）。请重建 MFU，并算出隐含的词元/秒与每步时间。
::: solution
$400/989 = 40.4\%$，考虑到吞吐的舍入，与报告的 $41\%$ 一致。每词元模型 FLOPs，含因果注意力项：$6N + 6Lsh = 2.43\times10^{12} + 6\cdot126\cdot8192\cdot16{,}384 = 2.43\times10^{12} + 1.0\times10^{11} = 2.53\times10^{12}$。集群模型 FLOP/s：$16{,}384\cdot4\times10^{14} = 6.55\times10^{18}$。词元/秒：$6.55\times10^{18}/2.53\times10^{12} = 2.59\times10^6$。一步 $1680$ 万词元花 $6.5$ 秒。报告给出的总预算约 $3.8\times10^{25}$ FLOPs（与 $6N\cdot15.6\times10^{12}$ 词元 $= 3.79\times10^{25}$ 吻合），在这一吞吐下、无任何中断，需要 $5.8\times10^6$ 秒，即 $67$ 天。
:::
:::

其余的 $59\%$ 去哪了？主要的损失，每一笔都能用前面各章的工具估算：流水线气泡（此例约 $10\%$）；没能藏到计算背后的通信（张量并行的全规约、步末的数据并行梯度规约）；受显存带宽支配的运算——归一化、逐元素函数、注意力中不是矩阵乘的那部分（[[scaling/accelerators]]）；重计算（费时间，但不计入 MFU）；流水线各阶段的负载不均；以及矩阵形状不能完美分块、核函数运行低于峰值。已发表的稠密模型在大集群上的 MFU 大体在 $35$–$55\%$ 区间（PaLM，$6144$ 块 TPU v4 芯片上 $46\%$，2022；Megatron-LM 的万亿参数配置，$3072$ 块 A100 上达峰值的 $52\%$，2021；Llama 3，视配置 $38$–$43\%$，2024）。混合专家模型报告的 MFU 通常更低，因为 all-to-all 通信更多、每专家的矩阵乘更小。

MFU 度量的是作业运行期间的吞吐。还有第二个数字，度量墙上时间里究竟有多大比例作业在运行。

::: definition 有效训练时间 {#def-goodput}
一次训练的**有效训练时间**（或 **goodput** 比例）是墙上时间中花在“被保留下来的进展”上的比例——排除故障损失（上一个检查点之后的工作）、重启、阻塞训练的检查点保存与停顿所占的时间。一次运行的端到端效率是 MFU 与有效训练时间之积。
:::

## 故障 {#sec-failures}

单块加速器、单台服务器或单根线缆很少出故障。一个数万设备的集群则无时无处不在出故障。

::: proposition 集群的故障率 {#prop-cluster-mtbf}
若一个作业依赖 $n$ 个部件，各部件故障相互独立，且部件 $i$ 的故障时间服从均值为 $M_i$ 的指数分布，则作业首次故障的时间服从指数分布，均值为

$$
M_{\text{job}} = \Big(\sum_{i=1}^{n}\frac{1}{M_i}\Big)^{-1},
$$

部件全同时等于 $M_1/n$。需要全部 $n$ 个部件都健在的作业，其故障频率是单个部件的 $n$ 倍。
:::

::: proof
作业一直运行到第一个部件故障，即 $T = \min_iT_i$。对速率 $\lambda_i = 1/M_i$ 的独立指数变量 $T_i$，$\Prob(T > t) = \prod_i\Prob(T_i > t) = \prod_ie^{-\lambda_it} = e^{-(\sum_i\lambda_i)t}$，故 $T$ 服从速率 $\sum_i\lambda_i$ 的指数分布，均值为 $1/\sum_i\lambda_i$。各 $M_i = M_1$ 相等时即为 $M_1/n$。
:::

指数模型是简化——真实故障在时间上成簇，在崭新的（“婴儿期夭折”）与老旧硬件上更频繁，并共享成因，如同一台交换机或同一路供电——但它抓住了规模效应的本质。已发表的记录与它相符。

- **OPT-175B**（Zhang et al., 2022）由 Meta 在 $992$ 块 A100 GPU（80 GB）上训练了约两个月。作者报告了至少 $35$ 次手动重启、以及因硬件故障轮换过百台以上主机，并公布了团队对这次运行逐日的**日志簿**——损失尖峰、学习率改动、节点故障与重启——一份关于大规模训练真实过程的难得坦率的公开记录。
- **PaLM**（Chowdhery et al., 2022）报告其 $5400$ 亿参数模型的训练中出现了约 $20$ 次损失尖峰，尽管已有梯度裁剪；处置办法是回滚到尖峰前约 $100$ 步的检查点，并跳过大约 $200$–$500$ 个批次的数据。
- **Llama 3**（2024）在多达 $16{,}384$ 块 GPU 上预训练的 $54$ 天快照中报告了 $466$ 次作业中断：$47$ 次计划内（维护与配置）与 $419$ 次意外，其中约 $78\%$ 归因于已确认或疑似的硬件问题，最大的单类是 GPU 与 GPU 显存故障。即便如此，团队报告有效训练时间超过 $90\%$，靠的是检测与恢复的自动化。

::: example 解读 Llama 3 的数字 {#ex-llama-failures}
由 $16{,}384$ 块 GPU 上 $54$ 天内的 $419$ 次意外中断，估计作业的平均无故障时间、隐含的每 GPU 平均无故障时间（把所有故障都算到 GPU 头上）、以及一天不出现意外中断的概率。
::: solution
$M_{\text{job}} = 54\cdot24/419 = 3.09$ 小时。每 GPU，由[[#prop-cluster-mtbf]]，$M_1 = nM_{\text{job}} = 16{,}384\cdot3.09 = 5.1\times10^4$ 小时，约 $5.8$ 年——每块 GPU 都极其可靠，作业却不是。$24$ 小时不坏的概率是 $e^{-24/3.09} = 4.3\times10^{-4}$：实际上，运行的每一天都有若干次中断。集群规模翻倍会把 $M_{\text{job}}$ 减半到约 $1.5$ 小时。
:::
:::

除了干脆的崩溃，大规模训练还面临不会主动示警的故障。**慢节点**（stragglers）——一块慢 GPU、一条被限速的链路、一个拥塞的交换机——会把每个同步的步拖到它们的速度；发现它们需要逐秩计时。集体通信中的**挂死**——一个秩不再参与、其余干等——必须靠超时抓住。还有**静默数据损坏**——硬件不报错却算出错误结果——已被 Meta（Dixit et al., 2021）与 Google（Hochschild et al., 2021）在机群规模上记录在案；在训练中它可能表现为原因不明的损失尖峰或发散，对策是冗余计算校验、比对各副本、以及退役可疑硬件。

## 检查点 {#sec-checkpoints}

对抗故障的通用手段是**检查点**：把精确恢复所需的一切都存一份——fp32 主权重、优化器矩、步数计数、学习率调度状态、随机数生成器状态与数据流中的位置。对[[#ex-layout]]那个 $4050$ 亿参数的模型，按模型状态每参数 $16$ 字节计，一个检查点约 $6.5$ TB。

多久存一次？每次保存花工作时间；每次故障丢掉上次保存之后的工作。经典答案出自 Young（1974），Daly（2006）作了改进。

::: theorem 最优检查点间隔 {#thm-young}
设一次保存阻塞训练 $\delta$ 时间，故障按平均无故障时间 $M$ 的泊松过程到来，每次故障损失上一个已完成检查点之后的工作、外加重启时间 $R$。每隔训练时间 $\tau$ 存一次检查点，则到 $\tau/M$ 与 $\delta/M$ 的一阶，期望损失的时间比例为

$$
f(\tau) = \frac{\delta}{\tau} + \frac{\tau}{2M} + \frac{R}{M},
$$ {#eq-young}

在

$$
\tau^\ast = \sqrt{2\delta M},\qquad f(\tau^\ast) = \sqrt{\frac{2\delta}{M}} + \frac{R}{M}.
$$ {#eq-young-opt}
:::

::: proof
*保存。*每段 $\tau$ 的训练，保存额外花 $\delta$，比例为 $\delta/\tau$（一阶意义下，$\delta/(\tau + \delta)\approx\delta/\tau$）。

*损失的工作。*故障等可能地落在一段内的任何位置，故平均毁掉半段的工作，$\tau/2$（一阶意义下——忽略了保存与重启期间的故障，其相对大小为 $\delta/M$ 与 $R/M$）。每次故障还花 $R$。故障按单位时间 $1/M$ 的速率到来，故单位时间的期望损失为 $(\tau/2 + R)/M$。

*最优点。*$f'(\tau) = -\delta/\tau^2 + 1/(2M)$ 在 $\tau^\ast = \sqrt{2\delta M}$ 处为零，且 $f''(\tau) = 2\delta/\tau^3 > 0$，故为最小值。代入得 $\delta/\tau^\ast = \sqrt{\delta/(2M)}$、$\tau^\ast/(2M) = \sqrt{\delta/(2M)}$——最优点处两项相等——于是 $f(\tau^\ast) = 2\sqrt{\delta/(2M)} + R/M = \sqrt{2\delta/M} + R/M$。
:::

这个结果有两个特征值得记住。重启时间 $R$ 加上一项常数损失，但不改变最优间隔。而在最优点，花在保存上的时间等于期望损失的工作：两者相差悬殊，就说明间隔选错了。Daly（2006）给出了更高阶的估计，当 $\delta < 2M$ 时

$$
\tau^\ast_{\text{Daly}} = \sqrt{2\delta M}\left[1 + \frac13\sqrt{\frac{\delta}{2M}} + \frac19\,\frac{\delta}{2M}\right] - \delta,
$$

在 $\delta$ 与 $M$ 相比不小的情形下更精确。下面的程序把两个估计与精确期望、以及与一次为期一个月的运行的蒙特卡洛模拟放在一起比较，取 Llama 3 的故障率（$M = 3$ 小时）、阻塞保存 $\delta = 5$ 分钟、重启 $R = 10$ 分钟。对每段都必须无故障跑满 $\tau + \delta$ 的情形，单位工作所需墙上时间的精确期望是 $(M + R)(e^{(\tau + \delta)/M} - 1)/\tau$，推导见[[#exr-overhead]]。

```python
import math, random

def simulate(work, tau, delta, mtbf, restart, rng):
    """Wall-clock time to finish `work` hours of training, checkpointing (blocking,
    `delta` hours) after every `tau` hours of progress; failures arrive as a Poisson
    process with mean `mtbf`; after a failure, `restart` hours are lost and training
    resumes from the last checkpoint."""
    t, done = 0.0, 0.0
    next_fail = rng.expovariate(1 / mtbf)
    while done < work:
        seg = min(tau, work - done)
        need = seg + (delta if done + seg < work else 0.0)   # 末段之后不再保存
        if t + need <= next_fail:                            # 该段与保存顺利完成
            t += need; done += seg
        else:                                                # 故障：丢掉该段
            t = next_fail + restart
            next_fail = t + rng.expovariate(1 / mtbf)
    return t

def expected_overhead(tau, delta, mtbf, restart):
    """Exact expected wall time per hour of work: a segment needs tau + delta hours
    without failure; each failed attempt costs the time to failure plus the restart."""
    return (mtbf + restart) * (math.exp((tau + delta) / mtbf) - 1) / tau

M, delta, R = 3.0, 5 / 60, 10 / 60          # 单位：小时——集群 MTBF、保存时间、重启时间
young = math.sqrt(2 * delta * M)
r = delta / (2 * M)
daly = math.sqrt(2 * delta * M) * (1 + math.sqrt(r) / 3 + r / 9) - delta
best = min((expected_overhead(t / 1000, delta, M, R), t / 1000) for t in range(10, 5000))
print(f"Young tau* = {young * 60:.1f} min   Daly tau* = {daly * 60:.1f} min   "
      f"exact optimum = {best[1] * 60:.1f} min")

rng = random.Random(0)
work = 24 * 30                                # 30 天的有效训练
print(" tau (min)  simulated overhead  exact expectation  first-order sqrt model")
for tau_min in (10, 20, 30, 43, 60, 120):
    tau = tau_min / 60
    sims = [simulate(work, tau, delta, M, R, rng) / work - 1 for _ in range(20)]
    exact = expected_overhead(tau, delta, M, R) - 1
    first = delta / tau + tau / (2 * M) + R / M
    print(f"{tau_min:9d}  {sum(sims) / len(sims):18.3f}  {exact:17.3f}  {first:22.3f}")
```

       10               0.651              0.651                   0.583

以打印的精度看，Daly 估计与精确最优一致；Young 的长 $8\%$，代价几乎可以忽略，因为开销曲线在最小值附近平坦（$30$、$43$、$60$ 分钟处的开销相差不出 $3$ 个百分点）。模拟在其抽样噪声内与精确期望一致。一阶模型在这些参数下低估了开销，因为 $\delta/M$ 与 $R/M$ 并不小。而开销本身——即便取最优间隔也损失约 $35\%$ 的运行时间——说明在这种故障率下，五分钟一次的阻塞保存是不可持续的。这正是大规模训练必须做工程的定量理由：

- **异步检查点**：把状态从加速器拷到主机内存（几秒钟），训练继续的同时在后台写入存储——于是 $\delta$ 是拷贝时间而不是写盘时间。
- **内存与对等检查点**：把最近的检查点存在其他服务器的主机内存里，恢复时就不必读远程存储（Wang et al., 2023，面向分布式训练的 *Gemini*）。
- **分片检查点**：每个秩只并行写自己那一片，写带宽随集群一起扩展。
- **快速检测与重启**：健康检查、集体通信超时、热备服务器与作业自动重启，把 $R$ 从几小时压到几分钟。

::: example 异步保存 {#ex-async}
设 $M = 3.09$ 小时，异步保存把阻塞成本从 $\delta = 5$ 分钟降到 $\delta = 1$ 分钟。Young 的最优间隔与一阶损失（忽略重启时间）各是多少？一个 $6.5$ TB 的检查点要在一个间隔内后台写完，需要多大的聚合写带宽？
::: solution
$\delta = 1/60$ 小时：$\tau^\ast = \sqrt{2\cdot0.0167\cdot3.09} = 0.32$ 小时 $= 19$ 分钟，且 $f = \sqrt{2\cdot0.0167/3.09} = 10.4\%$，而 $\delta = 5$ 分钟时是 $23\%$。要在 $19$ 分钟内写完 $6.5$ TB，需要 $6.5\times10^{12}/1140\approx5.7$ GB/s 的聚合带宽——摊到 $2048$ 台服务器上不过每台 $2.8$ MB/s——所以分片并行写入让频繁检查点变得可行。剩下的损失主要来自丢掉的工作与重启时间，所以下一个目标是恢复速度。
:::
:::

::: warning 可靠性不会免费随规模而来
人们容易这样规划一次运行：“$C$ FLOPs，$n$ 块设备，MFU $U$，耗时 $C/(nFU)$ 秒。”在大 $n$ 处，这漏掉了随 $n$ 增长的那一项：故障以 $n$ 倍的频率到来（[[#prop-cluster-mtbf]]），而最优损失 $\sqrt{2\delta/M} + R/M$ 按 $\sqrt n$ 与 $n$ 增长。不同时改进检查点与重启时间就翻倍集群，亏在故障上的可能比赚到的吞吐还多。规划时要同时使用有效训练时间与 MFU，并且两者都要测量。
:::

## 监控与决策 {#sec-monitoring}

大规模训练处于不间断的监视之下，其日志簿与报告显示的核心信号大体相同（评估的一面见[[pretraining/in-training-evaluation]]）：

- **训练损失**及其**尖峰**；裁剪**之前**的**梯度范数**，其增大往往先于尖峰出现；**学习率**与**损失缩放**（fp16 时）。
- 以词元/秒计的**吞吐**与**MFU**，逐步、逐秩记录，以捕捉慢节点与性能回退。
- **硬件遥测**：内存错误、温度、链路误码计数器，以及各秩步时的分布。
- **数值健康**：最大的激活与注意力 logits、跳过步的比例、权重范数与输出 logits 的范数（[[pretraining/training-stability]]）。

出现损失尖峰或发散时，标准的应对按代价递增排列为：观察等待（许多尖峰自己恢复）；回滚到较早的检查点并跳过尖峰附近的数据批次（PaLM 的做法）；回滚并调低学习率；或者修改配方。OPT 的日志簿在一次运行中就记录了多次这样的干预。每次重启或回滚都花掉数小时的集群时间，这些是一个团队能做出的最昂贵的决定之列；把例行决策自动化，是达到高有效训练时间的一部分。

::: quiz
一次训练在 $8192$ 块设备上 MFU 为 $45\%$、有效训练时间为 $85\%$。集群翻倍到 $16{,}384$ 块设备，MFU 降到 $42\%$。哪些说法正确？
- [x] 翻倍前的端到端效率约为 $38\%$。
- [x] 若不改动检查点与恢复，作业的平均无故障时间减半。
- [ ] 墙上时间必然减半。
- [x] 除非保存与重启变快，有效训练时间很可能下降。
::: solution
$0.45\cdot0.85 = 0.38$。故障随设备数增长（[[#prop-cluster-mtbf]]）。吞吐只升 $2\cdot42/45 = 1.87$ 倍而非 $2$ 倍，且故障更频繁使有效训练时间再降，所以加速不到 $1.87$。
:::
:::

::: history
长计算的检查点—重启问题在超级计算机上由 Young（1974）分析、Daly（2006）改进，远早于神经网络需要它。大规模模型训练报告在 2021–2022 年变得详细：Narayanan et al.（2021）描述了 Megatron-LM 在 $3072$ 块 GPU 上的三维并行；Chowdhery et al.（2022）随 PaLM 引入 MFU，PaLM 在两个 TPU v4 pod 上训练；Zhang et al.（2022）发布了 OPT-175B 日志簿；BigScience 研讨会（2022）公开训练了 $1760$ 亿参数的 BLOOM 并发表了工程笔记；Smith et al.（2022）描述了 Megatron-Turing NLG 530B。Llama 3 报告（2024）记录了一次 $16{,}384$ 块 GPU 运行的故障统计、有效训练时间与功率行为。Dixit et al.（2021）与 Hochschild et al.（2021）记录了机群规模的静默数据损坏。Wang et al.（2023）提出用内存检查点实现快速恢复。
:::

::: summary
- 集群由装着约 $8$ 块加速器、内部高速互连的**服务器**搭建，再以**横向扩展网络**（InfiniBand 或 RoCE，轨道优化胖树）相连；TPU 则用带光开关的环面。
- **布局**把设备指派到 $t\times c\times p\times d$ 网格：张量并行在服务器内，流水线跨服务器，数据并行在最外层；全局批次、每设备显存、链路速度与气泡共同约束它。
- **MFU** $= c_{\text{tok}}\tau/(nF)$ 只数必需的 FLOPs；大型稠密运行的报告值在 $35$–$55\%$。**有效训练时间**把故障、保存与重启计入；效率是两者之积。
- 依赖 $n$ 个部件的作业，故障频率是单个部件的 $n$ 倍：$M_{\text{job}} = M_1/n$。Llama 3 在 $16{,}384$ 块 GPU 上约每 $3$ 小时遇一次意外中断。
- 最优检查点间隔为 $\tau^\ast = \sqrt{2\delta M}$（Young；Daly 的改进约减去 $\delta$），损失比例 $\sqrt{2\delta/M} + R/M$；最优点处保存时间等于期望损失的工作。
- 大规模训练依赖**异步、分片与内存检查点**、**快速检测与重启**，以及对损失、梯度范数、吞吐与硬件健康的持续**监控**。
:::

::: exercise 集群 MTBF {level=1 check="2"}
$25{,}000$ 块设备每块的平均无故障时间为 $50{,}000$ 小时。在独立性假设下，作业的平均无故障时间是多少小时？
::: solution
$50{,}000/25{,}000 = 2$ 小时。

::: exercise Young 间隔 {level=1 check="21.91"}
一次阻塞保存花 $\delta = 2$ 分钟，集群平均无故障时间 $M = 120$ 分钟。Young 的最优间隔是多少分钟？保留两位小数。
::: solution
$\sqrt{2\cdot2\cdot120} = \sqrt{480} = 21.91$ 分钟；一阶损失为 $\sqrt{2\cdot2/120} = 18\%$，另加重启时间。
:::
:::

::: exercise 由吞吐求 MFU {level=2 check="0.415"}
一个 $700$ 亿参数的稠密模型在 $2048$ 块设备上以 $2.0\times10^6$ 词元/秒训练，每块峰值 $989$ TFLOP/s。按每词元 $6N$ 次 FLOPs，它的 MFU 是多少？保留三位小数。
::: solution
$6\cdot7\times10^{10}\cdot2\times10^6 = 8.4\times10^{17}$ FLOP/s，除以 $2048\cdot9.89\times10^{14} = 2.025\times10^{18}$：MFU $= 0.415$。
:::
:::

::: exercise Daly 的修正 {level=2 check="20.6"}
$\delta = 2$ 分钟、$M = 120$ 分钟时，计算 Daly 的最优间隔估计，保留一位小数，并与 Young 比较。
::: solution
$\delta/(2M) = 1/120 = 0.00833$，$\sqrt{0.00833} = 0.0913$。$\tau^\ast = 21.909\cdot(1 + 0.0304 + 0.00093) - 2 = 21.909\cdot1.0313 - 2 = 22.60 - 2 = 20.6$ 分钟，比 Young 的 $21.9$ 短约 $1.3$ 分钟；损失时间的差别可以忽略。
:::
:::

::: exercise 无故障的一天 {level=2 check="0.0498"}
作业的平均无故障时间为 $8$ 小时。它连续运行 $24$ 小时不出故障的概率是多少？保留三位有效数字。
::: solution
$e^{-24/8} = e^{-3} = 0.0498$。
:::

::: exercise 检查点带宽 {level=2 check="108"}
一个 $4050$ 亿参数的模型按每参数 $16$ 字节存检查点，须在 $60$ 秒内写入存储。需要多大的聚合带宽，以 GB/s 计？
::: solution
$16\cdot4.05\times10^{11} = 6.48\times10^{12}$ 字节；$6.48\times10^{12}/60 = 1.08\times10^{11}$ 字节/秒 $= 108$ GB/s。
:::
:::

::: exercise 故障损失随规模增长 {level=2}
在[[#eq-young-opt]]下取 $M = M_1/n$，说明最优损失比例如何随 $n$ 增长。一次 $4096$ 块设备上的运行在最优点，检查点与损失的工作占 $5\%$、重启占 $2\%$。每设备可靠性、保存时间与重启时间不变时，$16{,}384$ 块设备上这两笔损失各是多少？
::: solution
$f^\ast = \sqrt{2\delta n/M_1} + Rn/M_1$：第一项按 $\sqrt n$ 增长，第二项按线性增长。$n$ 变为四倍，第一项翻倍（$5\%\to10\%$），第二项变为四倍（$2\%\to8\%$）：合计 $18\%$ 而非 $7\%$——而且这只对小损失精确的一阶公式，已经开始显得乐观了。重启时间这件原本不起眼的事，在规模上成了头号隐忧。
:::
:::

::: exercise 批次受限下的布局 {level=3}
一个 $1.4\times10^{11}$ 参数的稠密模型要在 $8192$ 块 80 GB 设备上训练，序列长 $8192$，全局批次至多 $1024$ 条序列。张量并行限于 $t = 8$（一台服务器之内）。模型状态为每参数 $16$ 字节，其中 $12$ 字节的优化器状态在数据并行组上分片（ZeRO-1）。求 bf16 权重与梯度每设备不超过 $20$ GB 的最小流水线度 $p$（取 2 的幂），并对该 $p$ 计算 $d$、每副本的微批次数（每微批次一条序列）与 1F1B 气泡。交错会有帮助吗？还能改什么？
::: solution
每设备权重与梯度：$4N/(tp) = 5.6\times10^{11}/(8p)$ 字节 $= 70/p$ GB；$70/p\le20$ 要求 $p\ge3.5$，故 $p = 4$（$17.5$ GB）。于是 $d = 8192/(8\cdot4) = 256$，$m = 1024/256 = 4$ 个微批次每副本——气泡 $3/(4 + 3) = 43\%$。交错成 $v$ 段给出 $3/(4v + 3)$：$v = 8$ 把它压到 $8.6\%$，代价是多得多的点到点传输。其他选择：减少数据并行副本（少用设备，或加大 $t\cdot p$ 以提高 $m$）；用上下文并行在不增大批次的情况下给每个副本更多设备；或者用 ZeRO-3/FSDP 在数据并行组上分片权重与梯度，那么更小的 $p$（甚至 $p = 1$）就够用，拿流水线气泡换参数 all-gather。
:::
:::

::: exercise 精确的期望开销 {#exr-overhead level=3}
一段工作需要无故障地运行 $a = \tau + \delta$ 小时；故障按速率 $1/M$ 到来；每次故障损失本次尝试已经过的时间、外加一次重启 $R$（期间不发生任何故障），之后重试该段。证明完成一段的期望墙上时间为 $(M + R)(e^{a/M} - 1)$，并证明其按单位工作展开的一阶形式重现[[#eq-young]]。
::: solution
设单次尝试成功的概率为 $q = e^{-a/M}$；失败的尝试次数 $K$ 服从几何分布，$\E[K] = (1 - q)/q$。一次失败尝试的持续时间为条件于 $X < a$ 的 $X$，$\E[X\mid X < a] = \big(\int_0^axe^{-x/M}dx/M\big)/(1 - q) = M - aq/(1 - q)$，另加 $R$。于是 $\E[T] = a + \E[K]\,(M - aq/(1 - q) + R) = a + \frac{1-q}{q}(M + R) - a = (M + R)\frac{1 - q}{q} = (M + R)(e^{a/M} - 1)$。展开：$e^{a/M} - 1 = a/M + a^2/(2M^2) + \dots$，故在 $a/M$ 与 $R/M$ 的一阶下 $\E[T]\approx(M + R)\big(a/M + a^2/(2M^2)\big)\approx a + a^2/(2M) + Ra/M$。按单位工作 $\tau$ 计，取 $a = \tau + \delta$：$\E[T]/\tau - 1\approx\delta/\tau + \tau/(2M) + R/M$ 加上 $\delta/M$ 量级的项，即[[#eq-young]]。
:::
:::
