上一章数清了一个训练步的工作量：每词元约$6N$次浮点运算，外加权重、优化器状态与激活值的显存。本章问这些工作能做多快。答案很少是“和标称峰值一样快”。加速器做乘法远快于从主存取数，所以一个运算究竟跑在算术单元的速度上、还是跑在内存的速度上，取决于它每搬运一字节做多少次运算。正是这一个比值——**算术强度**——加上由它搭建的**屋顶线模型**，解释了为什么矩阵乘法能逼近峰值而归一化层步履蹒跚，为什么一次生成一个词元会让大部分硬件空转，以及 FlashAttention 这类融合核为何重要。

我们先描述加速器由什么构成，以及决定其行为表现的存储层次；然后导出屋顶线界并把它用在 Transformer 的各个运算上；接着讲解脉动阵列——矩阵单元背后的硬件结构；最后概览各代设备与把它们连起来的互连，所引数字注明日期、取自厂商公布的规格书。屋顶线与算术强度在[[transformers/attention-complexity]]中已就注意力引入过；这里把它们推广到整个模型、整台机器。

## 吞吐机器 {#sec-throughput}

中央处理器（CPU）为**延迟**而设计：它尽可能快地运行少数几个线程的复杂分支代码，配大容量缓存、分支预测和乱序执行。而深度学习加速器为**吞吐量**而设计：它对数百万个数重复同一条简单运算，并把晶体管花在算术单元而不是控制逻辑上。主流设计有两种。

**图形处理器**（GPU）在数据中心形态下由许多**流式多处理器**（SM）组成——NVIDIA A100 上有$108$个，H100 SXM 上有$132$个——每个包含标量与向量算术单元、能在单条指令中乘一小块矩阵的专用**张量核心**（tensor core）、一个大寄存器堆，以及一片快速的片上暂存（共享内存）。数千个线程分组为$32$个一束、以锁步执行的线程束（warp），在一部分线程束等数据时于束间切换，以此掩盖内存延迟。AMD 的数据中心 GPU 是大体相同的结构（带矩阵核心的计算单元）。

**张量处理器**（TPU）由 Google 设计，围绕少数几个大型**矩阵乘法单元**（MXU）构建——近几代是$128\times128$个乘加单元的脉动阵列——外加向量与标量单元以及片上向量内存。它运行由 XLA 编译器提前编译好的代码，由编译器显式地调度数据搬运，而不是依赖上千个线程。

细节各不相同，但两者的组织都围绕同样的事实：矩阵乘法是主导运算；专用单元以降低的精度、极高的速率执行它；而难的是让这些单元持续吃到数据。

## 存储层次 {#sec-hierarchy}

::: definition 存储层次 {#def-hierarchy}
加速器的**存储层次**是算术单元与系统其余部分之间的一串存储层级，按小、快、近到大、慢、远排列：寄存器；片上 SRAM（共享内存或 L1 缓存，GPU 上还有 L2 缓存；TPU 上是向量内存）；**高带宽内存**（HBM），与处理器封装在一起、堆叠在旁的 DRAM；主机 DRAM，经 PCIe 或类似链路访问；以及存储。每一层由其**容量**和**相对上一层的带宽**刻画。
:::

为具体起见，NVIDIA H100 SXM（2022年发布）按 NVIDIA 公布的数据，每个 SM 有$256$ KB 寄存器与$256$ KB 合并的 L1 缓存加共享内存、$50$ MB L2 缓存、以及$80$ GB 提供$3.35$ TB/s 带宽的 HBM3。片上 SRAM 带宽比 HBM 高一个数量级，但容量只有 HBM 的约千分之一。主机内存经由 PCIe Gen5 访问，16通道链路每方向约$64$ GB/s——比 HBM 慢五十倍。

实际后果是：训练中用到的每个张量都住在 HBM 里，每个运算都必须把操作数从 HBM 搬进片上内存、计算、再写回结果。若一个运算每搬入一字节只做了很少的算术，算术单元就得干等。

## 屋顶线模型 {#sec-roofline}

::: definition 算术强度与屋顶线 {#def-roofline}
一次计算的**算术强度**$I$是它执行的 FLOPs 数除以它在 HBM 与芯片之间搬运的字节数。峰值吞吐为$\pi$ FLOP/s、内存带宽为$\beta$字节/秒的设备执行它的速率至多为

$$
R(I) = \min(\pi,\ \beta I)\ \text{FLOP/s}.
$$ {#eq-roofline}

**脊点**$I^\ast = \pi/\beta$把受带宽限制的**访存受限**计算（$I < I^\ast$）与**计算受限**的计算（$I > I^\ast$）分开。
:::

这个界由两条事实而来：算术不可能快过$\pi$；而搬运$M$字节的计算至少要$M/\beta$秒，期间执行$IM$个 FLOPs。真实的内核会落在屋顶之下——延迟、访存与计算重叠得不完美、片上瓶颈都要分一杯羹——但写得好的内核能接近屋顶，而屋顶线会告诉该优化哪种资源。在双对数图上，它是一条斜线（访存受限）在脊点与一条水平线（计算受限）相交。

脊点随每一代上升，因为算术吞吐的增长快于内存带宽：从 A100 的每字节约$153$个 FLOPs 升到 H100 的约$295$个。越来越多曾经计算受限的运算如今成了访存受限。

::: proposition 矩阵乘积的算术强度 {#prop-intensity-matmul}
把一个$m\times k$矩阵与一个$k\times n$矩阵相乘，两个操作数各读一次、结果写一次、每元素$p$字节，其算术强度为

$$
I = \frac{2mkn}{p\,(mk + kn + mn)}。
$$

方阵（$m = k = n$）在16位格式（$p = 2$）下，$I = n/3$。对$b$个词元施加线性层（$m = b$、$k = n = d$）且$b\ll d$时，16位下$I\approx b$。
:::

::: proof
由[[scaling/flops-memory#prop-matmul]]，FLOPs 为$2mkn$；搬运的字节数是两个输入与输出元素总数乘以$p$。取$m = k = n$、$p = 2$：$2n^3/(2\cdot3n^2) = n/3$。取$m = b$、$k = n = d$：$2bd^2/(2(bd + d^2 + bd)) = bd/(d + 2b)$，当$b\ll d$时趋于$b$。
:::

于是矩阵乘积的强度随其最小维度增长。大型方阵乘积是深深计算受限的；而有一个维度很小的乘积——比如解码批次中的词元数——则是访存受限的，因为每个权重从 HBM 取来只用了$b$次。

::: example 矩阵乘法与逐元素运算对比 {#ex-roofline}
在 H100 SXM（$\pi = 989$ TFLOP/s 稠密 bf16，$\beta = 3.35$ TB/s）上，估算(a)两个$4096\times4096$ bf16 矩阵相乘，以及(b)对一个$4096\times4096$ bf16 矩阵逐元素施加 GeLU（按每元素约$10$个 FLOPs 计）的时间。
::: solution
(a) FLOPs $2\cdot4096^3 = 1.37\times10^{11}$；字节$3\cdot4096^2\cdot2 = 1.0\times10^8$；$I = 1365$ FLOPs/字节，远在脊点$295$之上，计算受限：至少$1.37\times10^{11}/9.89\times10^{14} = 0.14$毫秒。(b) 字节：以2字节读写$4096^2$个元素，共$6.7\times10^7$字节；FLOPs $1.7\times10^8$；$I = 2.5$ FLOPs/字节，远在脊点之下，访存受限：至少$6.7\times10^7/3.35\times10^{12} = 0.020$毫秒。GeLU 做的算术只有矩阵乘法的$0.12\%$，花的时间却占其$14\%$——而它这一类的运算（归一化、残差加法、激活、softmax）正是 Transformer 层达不到峰值的原因。
:::
:::

**融合**是主要的补救手段。若在前一个矩阵乘积的输出还留在片上内存时、在乘积的**收尾段**（epilogue）里就对它施加 GeLU，就几乎不花分文：不多跑一趟 HBM。编译器（XLA、TorchInductor）与手写内核把逐元素运算链融合起来，FlashAttention 则融合整个注意力，把打分矩阵留在 SRAM 里（[[transformers/attention-complexity]]）。融合减少搬运的字节；它不减少 FLOPs。

::: example 解码为何访存受限 {#ex-decode}
一个700亿参数的模型以 bf16 存放（权重$140$ GB），以$b$条序列的批次生成文本。每个解码步把每个权重矩阵乘上一个$b\times d$的激活。在每设备聚合带宽$3.35$ TB/s 的硬件上估算每步时间（设权重分到这样两块设备上，合起来$6.7$ TB/s、合计峰值$1.98$ PFLOP/s），分别取$b = 1$与$b = 256$，忽略 KV缓存。
::: solution
每步必须读全部$140$ GB 权重：无论$b$多少都至少$140/6700 = 21$毫秒。算术量为$2Nb$个 FLOPs：$b = 1$时$1.4\times10^{11}$个，峰值下只需$0.07$毫秒——设备只有$0.3\%$的时间在计算。$b = 256$时$3.6\times10^{13}$个，峰值下$18$毫秒——已与内存时间相当。由[[#prop-intensity-matmul]]，强度约为每字节$b$个 FLOPs，而脊点是$295$：批次不到几百时，解码访存受限，延迟不变而吞吐量几乎随批次线性增长。这就是推理服务系统拼命攒请求成批的原因，也是每步同样必须读取的 KV缓存如此要紧的原因（[[scaling/flops-memory#prop-kv]]）。
:::
:::

矩阵单元何以达到如此高的吞吐？关键在于**单元内部的数据复用**：在$n\times n$的乘积中每个输入元素被用$n$次，设计得当的单元只取它一次，让它在单元间接力传递，而不是取$n$次。

::: definition 脉动阵列 {#def-systolic}
**脉动阵列**（systolic array；Kung 与 Leiserson，1978）是一张由相同处理单元（PE）组成的网格，每个单元只与邻居相连，数据按规律节律在其中流动：每个时钟周期，每个 PE 从邻居取输入、执行一次运算、再把数据传下去。在计算$C = AB$的**输出驻留**$s\times s$阵列中，PE $(i, j)$累加$c_{ij}$；$A$的第$i$行元素从第$i$行左端进入，每周期右移一个 PE；$B$的第$j$列元素从第$j$列顶端进入，逐行下移。TPU 使用的**权重驻留**阵列则把一个操作数的一整块预载入各 PE，让另一个操作数穿流而过。
:::

为了让乘积在正确的时刻抵达正确的 PE，输入要做**错位**：$A$的第$i$行晚$i$个周期进入，$B$的第$j$列晚$j$个周期进入。

::: theorem 输出驻留脉动阵列的时序 {#thm-systolic}
按错位调度——$a_{il}$在第$i + l$周期进入第$i$行、$b_{lj}$在第$l + j$周期进入第$j$列（下标均从$0$起）——PE $(i, j)$恰在第$i + j + l$周期同时收到$a_{il}$与$b_{lj}$。因此计算一个$s\times k$与$k\times s$矩阵的乘积需要$k + 2s - 2$个周期，其间阵列完成$s^2k$次乘加，利用率为

$$
\frac{k}{k + 2s - 2}。
$$

$A$与$B$的每个元素都只从阵列外读入一次，却被使用$s$次。
:::

::: proof
元素$a_{il}$在第$i + l$周期进入 PE $(i, 0)$，每周期右移一个 PE，所以第$i + l + j$周期它在 PE $(i, j)$。元素$b_{lj}$在第$l + j$周期进入 PE $(0, j)$，每周期下移一个 PE，所以第$l + j + i$周期它在 PE $(i, j)$。两者恰好相遇，PE $(i, j)$在第$i + j + l$周期把$a_{il}b_{lj}$加到自己的累加器上。固定$(i, j)$，$l$从$0$跑到$k - 1$得到互不相同的周期，所以每个 PE 每周期至多做一次乘加，最终恰有$\sum_l a_{il}b_{lj} = c_{ij}$。最早的操作在第$0$周期（PE $(0,0)$，$l = 0$），最晚在第$(s - 1) + (s - 1) + (k - 1)$周期（PE $(s-1, s-1)$，$l = k - 1$），所以整个计算历时$k + 2s - 2$个周期。$s^2$个 PE 每个做$k$次运算、共$s^2k$次，占可用槽位$s^2(k + 2s - 2)$。每个$a_{il}$被第$i$行的$s$个 PE 使用、每个$b_{lj}$被第$j$列的$s$个 PE 使用，而它们都只在边界被读入过一次。
:::

当$k\gg s$时利用率趋于$1$：流水线的填充与排空（$2s - 2$个周期）被摊到很长的内维上。而所需的外设带宽只有每周期$2s$个元素，对应$s^2$次乘加——阵列自身的数据复用正是它跑赢内存的本钱。下面的程序逐周期模拟一个输出驻留阵列，同时检验结果与计时。

```python
import random

def systolic_matmul(A, B):
    """Output-stationary s x s systolic array computing C = A B (A: s x k, B: k x s).
    Row i of A enters from the left delayed by i cycles; column j of B enters from
    the top delayed by j cycles. Each cycle every cell multiplies the pair it holds,
    adds the product to its accumulator, and passes a right and b down."""
    s, k = len(A), len(A[0])
    acc = [[0] * s for _ in range(s)]
    a_reg = [[None] * s for _ in range(s)]          # 本周期 (i, j) 格持有的值
    b_reg = [[None] * s for _ in range(s)]
    cycle, macs, busy_last = 0, 0, 0
    while True:
        # 移位：a 向右，b 向下（从远端往回遍历）
        for i in range(s):
            for j in reversed(range(s)):
                a_reg[i][j] = a_reg[i][j - 1] if j > 0 else (
                    A[i][cycle - i] if 0 <= cycle - i < k else None)
        for j in range(s):
            for i in reversed(range(s)):
                b_reg[i][j] = b_reg[i - 1][j] if i > 0 else (
                    B[cycle - j][j] if 0 <= cycle - j < k else None)
        busy = 0
        for i in range(s):
            for j in range(s):
                if a_reg[i][j] is not None and b_reg[i][j] is not None:
                    acc[i][j] += a_reg[i][j] * b_reg[i][j]
                    busy += 1
        macs += busy
        cycle += 1
        if busy:
            busy_last = cycle
        elif cycle > k + 2 * s:
            break
    return acc, busy_last, macs

random.seed(0)
for s, k in ((4, 4), (4, 64), (16, 16), (16, 1024)):
    A = [[random.randint(-9, 9) for _ in range(k)] for _ in range(s)]
    B = [[random.randint(-9, 9) for _ in range(s)] for _ in range(k)]
    C, cycles, macs = systolic_matmul(A, B)
    ref = [[sum(A[i][l] * B[l][j] for l in range(k)) for j in range(s)] for i in range(s)]
    print(f"s={s:2d} k={k:4d}  correct={C == ref}  cycles={cycles}  k+2s-2={k + 2*s - 2}"
          f"  MACs={macs}  utilisation={macs / (cycles * s * s):.3f}")
```

```text
s= 4 k=   4  correct=True  cycles=10  k+2s-2=10  MACs=64  utilisation=0.400
s= 4 k=  64  correct=True  cycles=70  k+2s-2=70  MACs=1024  utilisation=0.914
s=16 k=  16  correct=True  cycles=46  k+2s-2=46  MACs=4096  utilisation=0.348
s=16 k=1024  correct=True  cycles=1054  k+2s-2=1054  MACs=262144  utilisation=0.972
```

初代 TPU（Jouppi 等，2017）有一块$256\times256$个8位乘加单元的权重驻留阵列，主频$700$ MHz：$65{,}536\cdot2\cdot7\times10^8 = 9.2\times10^{13}$次运算每秒，即公布的$92$ TOPS。后来的 TPU 每个核心在 bf16 下使用若干块$128\times128$阵列。GPU 的张量核心是小得多的矩阵单元——每个在单条指令里乘一小块——在所有 SM 上复制铺开，单块大阵列靠体积获得的复用改由共享内存与寄存器实现。两者只有在矩阵足够大、能让每个单元都忙碌、且各维度都是分块尺寸的整数倍时才能达到峰值；一个维度取$4097$而不是$4096$，就可能要多做整整一块的无用计算。

::: warning 峰值 FLOP/s 不是性能指标
规格书标注的峰值吞吐属于最有利情形：最低支持精度下的稠密矩阵乘法、最高主频，有时还算上结构化稀疏（对每四个值里有两个零的矩阵，标称数字会因此翻倍）。任何真实的训练运行都达不到它。一次运行能达到稠密 bf16 峰值的$40\%$就干得很漂亮了（[[scaling/large-runs]]）。比较设备时要把可比的放在一起——稠密对稠密、同一精度——还要看内存带宽与容量，对许多工作负载、尤其是推理，它们比峰值算术更重要。
:::

各代之间可见三个趋势，且预计将延续。峰值算术增长最快，低精度尤甚：H100 的 bf16 速率在 fp8 下翻倍，更新的器件又添了6位与4位格式（[[scaling/mixed-precision]]）。内存带宽增长较慢，所以脊点维持高位或继续抬升。每设备内存容量增长可观，这对推理、以及减少训练所需模型并行的程度，最为要紧。

::: example 新一代硬件带来什么 {#ex-generations}
用下表比较 A100 与 H100 在(a)一个算术强度$I = 1000$ FLOPs/字节、计算受限的矩阵乘法，以及(b)一个强度$I = 50$的访存受限内核上能达到的吞吐。
::: solution
(a) 都高于各自脊点，各以峰值运行：H100 快$989/312 = 3.2$倍。(b) 都在脊点以下：A100 $2.04\cdot50 = 102$ TFLOP/s，H100 $3.35\cdot50 = 168$ TFLOP/s，只快$1.64$倍——正是带宽之比。新硬件给一个工作负载带来的加速，取决于它在屋顶线上的位置：以大型矩阵乘法为主的训练大约拿到峰值之比，小批次推理大约拿到带宽之比。
:::
:::

单块设备从来不是故事的全部：限制大型训练运行的通常是系统——能连多少块设备，连得多快。

## 互连 {#sec-interconnects}

::: definition 延迟–带宽模型 {#def-alpha-beta}
经一条链路发送$M$字节的消息大约需要

$$
t(M) = \alpha + \frac{M}{\beta_{\text{link}}},
$$ {#eq-alpha-beta}

其中$\alpha$是**延迟**（每条消息的固定开销，从服务器内的几微秒到跨网络的几十微秒），$\beta_{\text{link}}$是链路的**带宽**。小消息受延迟支配，大消息受带宽支配；转折点在$M = \alpha\beta_{\text{link}}$。
:::

加速器在三个层级互连，每一级大约比上一级慢一个数量级。

- **服务器内部**，通常为$8$块设备，经专用高带宽互连结构：NVIDIA 的 NVLink 加 NVSwitch 让每台 H100 与服务器内任意其他 GPU 之间获得$900$ GB/s 的双向总带宽（每方向$450$ GB/s）；AMD 的 Infinity Fabric 连接一台服务器里的 MI300X。更新的系统（截至2026年）正把这类互连结构扩展到跨机架的数十台设备。
- **服务器之间**，经交换网络：InfiniBand 或带 RDMA 的以太网（RoCE），2023–2024年的集群通常每块加速器配一个$400$ Gb/s（$50$ GB/s）的网络接口，组织成多级胖树（fat-tree）或“轨道优化”（rail-optimised）拓扑——每台服务器的第$k$块设备都接到同一组叶交换机。
- **TPU Pod** 采用另一种设计：芯片经芯片间互连链路直接与邻居相连，构成**环面**（torus）——TPU v4 是$4096$块芯片的三维环面，并用**光路交换机**重新配置拓扑、绕开故障部件（Jouppi 等，2023）。

各层级之间的速率比塑造了接下来三章的一切。H100 的 HBM 提供$3.35$ TB/s；NVLink 每方向$450$ GB/s；网络接口$50$ GB/s。因此通信密集的并行（张量并行，每层都要交换激活）被留在服务器内部，通信轻的并行（数据并行，每步交换一次梯度、还能与计算重叠）才跨过网络。

::: example 搬运一次梯度 {#ex-interconnect}
一个70亿参数的模型有$14$ GB 的 bf16 梯度。把它们完整发送一次，(a)经服务器内两块 GPU 之间$450$ GB/s 的 NVLink，(b)服务器之间$50$ GB/s，(c)GPU 到主机经 PCIe Gen5 的$64$ GB/s，各要多久？$\alpha$取可忽略。
::: solution
(a) $14/450 = 31$毫秒。(b) $14/50 = 0.28$秒。(c) $14/64 = 0.22$秒。这个模型在单块设备上一个训练步大约一两秒；链路速度差九倍，决定的正是这次交换能否藏到计算背后。[[scaling/data-parallelism]]的全规约算法每设备搬运约两倍梯度大小的数据，与设备数量无关。
:::
:::

::: quiz
一个内核在$\pi = 10^{15}$ FLOP/s、$\beta = 2\times10^{12}$字节/秒的设备上执行$10^{10}$个 FLOPs、搬运$10^9$字节。哪些说法正确？
- [x] 它的算术强度是每字节$10$个 FLOPs。
- [x] 它访存受限，至少需要$0.5$毫秒。
- [ ] 把设备峰值 FLOP/s 翻倍能把它的运行时间减半。
- [x] 把它与下一个运算融合、让输出不必写回 HBM，能给它提速。
::: solution
$I = 10^{10}/10^9 = 10$，远低于脊点$\pi/\beta = 500$，所以访存受限、至少需要$10^9/(2\times10^{12}) = 0.5$毫秒（光算术只要$0.01$毫秒）。对访存受限的内核，更多的峰值算术没有用；更少的搬运才有用。
:::
:::

::: history
脉动阵列由 H. T. Kung 与 Charles Leiserson 于1978年为矩阵乘法这类规律计算提出。GPU 随 NVIDIA 的 CUDA（2007）成为通用处理器，而 Krizhevsky、Sutskever 与 Hinton 的 AlexNet（2012）用两块消费级 GPU 训练成功，使它成了深度学习的引擎。NVIDIA 在 V100（2017）引入张量核心；Google 在 Jouppi 等（2017）中描述了初代 TPU——一块带$256\times256$脉动阵列的推理芯片——后续各代加上 bf16 训练和由环面互连连成数千芯片的 Pod，并在 TPU v4 引入光路交换（Jouppi 等，2023）。屋顶线模型由 Williams、Waterman 与 Patterson（2009）为多核 CPU 提出，如今已是分析加速器内核的标准语言。Dao 等（2022）以 FlashAttention 表明：重新组织注意力以减少内存流量——而不是减少 FLOPs——能带来大幅加速——这是直接从屋顶线得出的论证。
:::

::: summary
- 加速器是吞吐机器：大量算术单元、专用的**矩阵单元**（张量核心、MXU），以及从寄存器与 SRAM 到 HBM、主机内存与存储的**存储层次**。
- **屋顶线**把吞吐限制在$\min(\pi, \beta I)$；强度低于脊点$\pi/\beta$（近年设备约每字节$150$–$300$个 FLOPs）的计算**访存受限**。
- 大型矩阵乘法的强度为$n/3$（方阵、16位），计算受限；逐元素运算、归一化和小批次解码（$I\approx b$）访存受限。**融合**消除 HBM 往返。
- **脉动阵列**让每个输入复用$s$次；$s\times s$输出驻留阵列计算$s\times k$乘$k\times s$的积需要$k + 2s - 2$个周期。
- 规格书上的峰值只是稠密低位宽矩阵运算的上界；比较要把可比的放在一起，并看带宽与容量。
- 互连从 HBM 到服务器内链路（NVLink、ICI）再到网络，大致逐级降低一个数量级；并行策略要按这个层次来映射。
:::

## 习题

::: exercise 脊点 {level=1 check="295"}
用 H100 SXM 的公布数字（稠密 bf16 $989$ TFLOP/s、$3.35$ TB/s），计算以每字节 FLOPs 计的脊点，取整。
::: solution
$9.89\times10^{14}/3.35\times10^{12} = 295$ FLOPs/字节。
:::
:::

::: exercise 方阵的算术强度 {level=1 check="2048"}
使 bf16 的$n\times n$乘$n\times n$乘积的算术强度至少达到每字节$682.67$个 FLOPs 的最小方阵尺寸$n$是多少？
::: solution
$I = n/3\ge682.67$给出$n\ge2048$。
:::
:::

::: exercise 脉动阵列的利用率 {level=1 check="0.8"}
一个$128\times128$输出驻留脉动阵列计算内维$k = 1016$的乘积。它的乘加槽有多大比例被用上？
::: solution
$k/(k + 2s - 2) = 1016/(1016 + 254) = 1016/1270 = 0.8$。
:::
:::

::: exercise 一个访存受限的内核 {level=2 check="0.24"}
一次残差加法读入两个形状$8\times4096\times4096$的 bf16 张量、写出一个。在$3.35$ TB/s 的设备上，最短时间是多少毫秒？保留两位有效数字。
::: solution
字节：$3\cdot8\cdot4096^2\cdot2 = 8.05\times10^8$；时间$8.05\times10^8/3.35\times10^{12} = 2.4\times10^{-4}$秒 $= 0.24$毫秒。它只做$1.3\times10^8$个 FLOPs，峰值下本需$0.14\,\mu$s：设备几乎全部时间都在等内存。
:::
:::

::: exercise 小批次下的线性层 {level=2 check="0.2134"}
一个$8192\times8192$的 bf16 权重矩阵施加到$b = 64$个词元上。用[[#prop-intensity-matmul]]与 H100 的数字，这个乘积至多能达到峰值的多大比例？保留四位小数。
::: solution
$I = bd/(d + 2b) = 64\cdot8192/(8192 + 128) = 63.015$ FLOPs/字节。可达比例$3.35\times10^{12}\cdot63.015/9.89\times10^{14} = 0.2134$，约为峰值的五分之一。
:::
:::

::: exercise 延迟还是带宽？ {level=2 check="250000"}
一条链路延迟$\alpha = 5\,\mu$s、带宽$50$ GB/s。消息多大（字节）时延迟与传输时间各占一半？通信库为什么要把许多个小梯度张量打包成更大的消息？
::: solution
$M = \alpha\beta_{\text{link}} = 5\times10^{-6}\cdot5\times10^{10} = 2.5\times10^5$字节（$250$ KB）。远小于此的消息由延迟支配；一个模型有几百个彼此独立的参数张量，逐个发送要把$\alpha$付上几百次，所以把它们拼接成几十兆字节的桶。
:::
:::

::: exercise 解码吞吐量 {level=2}
一个80亿参数的 bf16 模型在单块$3.35$ TB/s、$989$ TFLOP/s 的设备上提供服务。忽略 KV缓存，估算批次为$1$、$64$、$512$条序列时每解码步的最短时间与最大每秒词元数。批次多大时算术开始成为限制？
::: solution
权重：$16$ GB，每步读一次：至少$16/3350 = 4.8$毫秒。每步算术量：$2\cdot8\times10^9\cdot b$个 FLOPs，峰值下耗时$0.016b$毫秒。$b = 1$：$4.8$毫秒，$210$词元/秒。$b = 64$：算术$1.0$毫秒$<4.8$毫秒，仍是$4.8$毫秒，$13{,}400$词元/秒。$b = 512$：算术$8.3$毫秒$>4.8$毫秒，约$8.3$毫秒、$62{,}000$词元/秒。转折点在$0.016b = 4.8$、$b\approx295$——正是脊点，与[[#prop-intensity-matmul]]的预言一致。实践中 KV缓存会增添随批次与上下文增长的内存流量，使转折点移动。
:::
:::

::: exercise 初代 TPU 的峰值 {level=2 check="9.175e13"}
验证一个$256\times256$个8位乘加单元的脉动阵列在$700$ MHz 下的峰值吞吐，每次乘加计两次运算。保留四位有效数字。
::: solution
$256^2\cdot2\cdot7\times10^8 = 65{,}536\cdot1.4\times10^9 = 9.175\times10^{13}$次运算每秒，即公布的$92$ TOPS。
:::
:::

::: exercise 分块与波次 {level=3}
一台有$132$个 SM 的 GPU 计算一个乘积，输出被切成$128\times256$的分块，每个 SM 一次算一块。对$4096\times4096$的输出，共有多少分块、需要多少个$132$块一“波”？最后一波有多大比例空转，整体效率损失多少？对$4224\times4096$重复一遍并评论。
::: solution
$4096/128 = 32$乘$4096/256 = 16$：$512$个分块。$512/132 = 3.88$，故需$4$波，最后一波只有$512 - 396 = 116$块、$16$个 SM 空转（该波的$12\%$）。效率：$512/(4\cdot132) = 97.0\%$。$4224\times4096$：$33\cdot16 = 528$块，恰为$4\cdot132$，四波全满，$100\%$。大$3\%$的矩阵在同一时间内跑完。这种**波次量化**，加上分块量化（维度不能被分块尺寸整除），正是模型维度取$64$或$128$的整数倍、以及吞吐量随规模非单调变化的原因。
:::
:::

::: exercise 整个层的屋顶线 {level=3}
一个宽度$d = 4096$、$d_{\text{ff}} = 4d$的 Transformer 块以 bf16 处理$B\cdot n = 8192$个词元，估算它在 H100 上矩阵乘法与访存受限运算各自的时间（忽略注意力打分；设访存受限的那些运算——两个归一化、激活函数、两次残差加法——每个都对$Bn\times d$的激活读写一次，激活函数作用在$Bn\times4d$的张量上）。哪个占主导？把逐元素运算融合进相邻的乘积能省下什么？
::: solution
矩阵乘法：$24\cdot8192\cdot4096^2 = 3.30\times10^{12}$个 FLOPs，计算受限（最小维度$4096$，强度达几千）：至少$3.3\times10^{12}/9.89\times10^{14} = 3.3$毫秒。访存受限运算：每个$Bn\times d$的读写搬$2\cdot8192\cdot4096\cdot2 = 134$ MB；四个这样的（$2$个归一化、$2$次残差加法）加一个作用在$4d$上的（$537$ MB）：$1.07$ GB，至少$0.32$毫秒。所以算术占主导，但访存受限部分添了约$10\%$；把它们融合进相邻乘积的收尾段与起始段后，这些往返大部分消失。宽度更小、或逐元素运算更多（dropout、偏置、旋转位置编码）时，访存受限的份额会增大。
:::
:::
