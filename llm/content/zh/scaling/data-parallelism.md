在大量加速器上训练最简单的方式，是给每台设备一份完整的模型副本、每个批次给它们切到互不相同的一片。每台设备在自己那片上计算梯度；梯度在各设备间取平均；每台设备都施加同样的更新，副本因此始终保持一致。这就是**数据并行**（data parallelism），也是几乎每个大型训练任务的最外层。它简单，因为模型本身没有任何改变；它能扩展，因为昂贵的部分——前向与反向传播——可以被完美地切分；而它的代价有两条，正是本章要细究的：每一步为平均梯度付出的通信，以及每块设备上保存一份完整训练状态的显存。

我们先弄清数据并行训练为什么计算的与单设备训练完全相同，然后定义并行训练赖以搭建的集合通信操作，推导**环全规约**（ring all-reduce）的代价并用一个模拟加以验证。接着看通信与计算如何重叠，以及大批次给数据并行带来的限制。本章后半消除显存冗余：**ZeRO** 把优化器状态、梯度和参数分片到各数据并行设备上，而**全分片数据并行**（fully sharded data parallelism，FSDP）是它在 PyTorch 中的实现。显存记账见[[scaling/flops-memory]]，链路速率见[[scaling/accelerators]]；[[pretraining/training-loop]]还在预训练运行的背景下简要介绍过同样的想法。

## 同步数据并行 {#sec-sync}

::: definition 数据并行 {#def-dp}
在 $p$ 台设备上的**同步数据并行**中，每台设备 $r$ 持有参数 $\theta$ 的一份副本，并在每一步收到全局批次 $\mathcal{B} = \mathcal{B}_1\cup\dots\cup\mathcal{B}_p$ 的一个互不相交的**分片** $\mathcal{B}_r$。它计算局部梯度 $\mathbf{g}_r = \nabla_\theta\frac{1}{\lvert\mathcal{B}_r\rvert}\sum_{x\in\mathcal{B}_r}\ell(x;\theta)$；各设备经由一次集合通信算出平均 $\bar{\mathbf{g}} = \frac1p\sum_r\mathbf{g}_r$，并各自用 $\bar{\mathbf{g}}$ 施加同样的优化器更新。
:::

::: proposition 与单设备训练的等价性 {#prop-dp-equivalence}
若各分片大小相等，$\lvert\mathcal{B}_r\rvert = \lvert\mathcal{B}\rvert/p$，则平均后的梯度等于整个批次上平均损失的梯度，$\bar{\mathbf{g}} = \nabla_\theta\frac{1}{\lvert\mathcal{B}\rvert}\sum_{x\in\mathcal{B}}\ell(x;\theta)$。于是，若所有副本从相同的参数与优化器状态出发并使用同一个确定性优化器，它们将始终保持一致，训练轨迹就是批次为 $\mathcal{B}$ 的单设备训练（至多相差浮点舍入）。
:::

::: proof
当 $\lvert\mathcal{B}_r\rvert = n$、$\lvert\mathcal{B}\rvert = pn$ 时，由梯度的线性性，$\frac1p\sum_r\nabla\frac1n\sum_{x\in\mathcal{B}_r}\ell = \nabla\frac{1}{pn}\sum_{x\in\mathcal{B}}\ell$。随后每个副本都对相同的量（参数、优化器状态、$\bar{\mathbf{g}}$）施加同一个函数，故对步数归纳即知各副本保持相等。浮点加法不满足结合律，以不同次序归约可能在最后几位上有所不同；若归约次序确定，结果是可复现的。
:::

实践中有两点要紧。若各分片的*词元*数不等——把不同长度的序列装进包里、或用掩码屏蔽填充词元时很常见——朴素的平均会给词元不等的权重；补救办法是把损失求和、再除以全局词元总数，而全局词元总数与梯度一起通信。另外，计算依赖批次统计量的层（批归一化，在语言模型中很少用）在每设备批次很小时表现会不同。

数据并行与**梯度累积**（[[neural-networks/training-practice]]）可以组合：每台设备在平均步骤之前顺序处理 $A$ 个微批次并把它们的梯度累加起来，于是全局批次为 $b_{\text{micro}}\cdot A\cdot p$ 条序列，通信每 $A$ 个微批次才发生一次。

## 集合通信操作 {#sec-collectives}

::: definition 集合通信 {#def-collectives}
设 $p$ 台设备各持有一个 $M$ 字节的缓冲区，缓冲区均分为 $p$ 个分块。训练中用到的集合通信操作有：

- **全规约**（all-reduce）：每台设备最终得到全部 $p$ 个缓冲区的按元素和（或平均）；
- **规约-分散**（reduce-scatter）：设备 $r$ 最终得到各设备第 $r$ 个分块之和（每设备 $M/p$ 字节）；
- **全收集**（all-gather）：每台设备起初各持有一个 $M/p$ 字节的分块，最终每台设备得到全部 $p$ 个分块；
- **广播**（broadcast）与**规约**（reduce）：把一台设备的缓冲区复制给所有设备，或把所有设备的求和汇总到一台；
- **全对全**（all-to-all）：设备 $r$ 把自己的第 $s$ 块发给设备 $s$，对每一对都如此——相当于把分块转置。

一次全规约等价于一次规约-分散再接一次全收集。
:::

NCCL（NVIDIA）、RCCL（AMD）、Gloo 和 MPI 等库实现了这些操作，并按拓扑和消息大小挑选算法。最朴素而正确的全规约——把所有东西发给一台设备、求和、再发回去——要让那台设备发送和接收 $(p - 1)M$ 字节，形成一个随 $p$ 增长的瓶颈。环形算法让每设备的流量与 $p$ 无关。

::: algorithm 环全规约 {#alg-ring}
把 $p$ 台设备排成一个环，设备 $r$ 发送到 $r + 1 \bmod p$。把每个缓冲区分成 $0,\dots,p-1$ 号分块。
1. **规约-分散**，步 $t = 0,\dots,p-2$：设备 $r$ 把自己当前持有的第 $(r - t)\bmod p$ 块发给设备 $r + 1$，后者把它加到自己的这一块上。
2. $p - 1$ 步之后，设备 $r$ 持有第 $(r + 1)\bmod p$ 块的完整和。
3. **全收集**，步 $t = 0,\dots,p-2$：设备 $r$ 把第 $(r + 1 - t)\bmod p$ 块——它持有一份完整的——发给设备 $r + 1$，后者用自己的副本把它覆写。
4. 再过 $p - 1$ 步，每台设备都持有每个完整的分块。
:::

::: theorem 环全规约的代价 {#thm-ring}
在[[#alg-ring]]中，每台设备各发送和接收

$$
2\,\frac{p-1}{p}\,M\ \text{字节},
$$ {#eq-ring}

共 $2(p - 1)$ 步。在每条消息延迟 $\alpha$、链路带宽 $\beta$ 的延迟–带宽模型（[[scaling/accelerators#def-alpha-beta]]）下，时间为

$$
T_{\text{ring}} = 2(p - 1)\,\alpha + 2\,\frac{p-1}{p}\,\frac{M}{\beta}.
$$ {#eq-ring-time}
:::

::: proof
**正确性。**在规约-分散阶段考察第 $c$ 块。步 $t = 0$，设备 $c$ 把自己第 $c$ 块的副本发给设备 $c + 1$，后者加上自己的；第 $t$ 步，设备 $c + t$ 把第 $(c + t - t) = c$ 块——此时已装有设备 $c,\dots,c + t$ 贡献之和——发给设备 $c + t + 1$，后者加上自己的。第 $p - 2$ 步之后，设备 $c + p - 1\equiv c - 1$ 持有了全部 $p$ 台设备的和；等价地说，设备 $r$ 持有完整的第 $r + 1$ 块。在全收集阶段，第 $r + 1$ 块从设备 $r$ 出发沿环行进，每步一跳，$p - 1$ 步后到达其余全部 $p - 1$ 台设备。

**代价。**在 $2(p - 1)$ 步的每一步，每台设备恰好发送一个 $M/p$ 字节的分块并接收一个，于是每台设备各发送和接收 $2(p - 1)M/p$ 字节。所有设备同时在互不重叠的链路上发送，故一步耗时 $\alpha + (M/p)/\beta$，总时间即[[#eq-ring-time]]。
:::

当 $p$ 增大时，带宽项趋于 $2M/\beta$——**两倍缓冲区大小，与设备数量无关**——数据并行因此能扩展到数千台设备。这基本上也是最省的：全收集中每台设备必须接收它没有的 $(p-1)M/p$ 字节，而 Patarasuk 与 Yuan（2009）证明了在此模型下 $2(p-1)M/p$ 是全规约每设备流量的下界。弱点是延迟项 $2(p - 1)\alpha$，随 $p$ 线性增长。基于树的算法和**递归折半倍增**（recursive halving and doubling）算法只需 $O(\log p)$ 步，对是 $2$ 的幂的 $p$ 带宽代价相同；通信库按消息大小在算法之间切换，大型集群则采用**分层**方案——在每台服务器内部经其高速链路做规约、跨服务器做全规约、再在每台服务器内部做广播——以贴合拓扑。

下面的程序逐元素地模拟环形算法，对照精确和检验结果，并统计每台设备发送的元素数。

```python
import random

def ring_all_reduce(bufs):
    """Sum p equal-length vectors with the ring algorithm. Each device's buffer is cut
    into p chunks; p-1 reduce-scatter steps, then p-1 all-gather steps. In every step
    device i sends one chunk to device (i+1) mod p. Returns results and bytes sent."""
    p, M = len(bufs), len(bufs[0])
    bounds = [(c * M // p, (c + 1) * M // p) for c in range(p)]
    data = [list(b) for b in bufs]
    sent = [0] * p                                    # 每台设备发送的元素数
    for step in range(p - 1):                         # 规约-分散
        msgs = []
        for i in range(p):
            c = (i - step) % p                        # 本步设备 i 转发的分块
            lo, hi = bounds[c]
            msgs.append(((i + 1) % p, c, data[i][lo:hi]))
            sent[i] += hi - lo
        for dst, c, chunk in msgs:                    # 接收方加进自己的副本
            lo, hi = bounds[c]
            for k, v in enumerate(chunk):
                data[dst][lo + k] += v
    # 此时设备 i 持有第 (i + 1) mod p 块的完整和
    for step in range(p - 1):                         # 全收集
        msgs = []
        for i in range(p):
            c = (i + 1 - step) % p
            lo, hi = bounds[c]
            msgs.append(((i + 1) % p, c, data[i][lo:hi]))
            sent[i] += hi - lo
        for dst, c, chunk in msgs:                    # 接收方覆写
            lo, hi = bounds[c]
            data[dst][lo:hi] = chunk
    return data, sent

random.seed(0)
M = 1200                                              # 每个缓冲区的元素数
for p in (2, 4, 8, 16):
    bufs = [[random.randint(-100, 100) for _ in range(M)] for _ in range(p)]
    exact = [sum(col) for col in zip(*bufs)]
    out, sent = ring_all_reduce(bufs)
    ok = all(o == exact for o in out)
    print(f"p={p:2d}  correct={ok}  sent per device={sent[0]} elements"
          f"  = {sent[0] / M:.4f} M   formula 2(p-1)/p = {2 * (p - 1) / p:.4f}"
          f"   naive (gather to one, broadcast): root sends {(p - 1) * M}")
```

p= 4  correct=True  sent per device=1800 elements  = 1.5000 M   formula 2(p-1)/p = 1.5000   naive (gather to one, broadcast): root sends 3600

## 通信重叠 {#sec-overlap}

一步的全规约不必等整个反向传播结束。梯度按层逆序逐个就绪，最后几层梯度的全规约可以在较早各层仍在反向求导时先行运行。PyTorch 的 DistributedDataParallel（Li et al., 2020）把参数按使用的逆序分组成**桶**（bucket，默认约 $25$ MB），某个桶的全部梯度一就绪就发起它的全规约。分桶把每条消息的延迟 $\alpha$ 摊到许多个小的参数张量上；逆序则让通信尽早开始。

::: proposition 通信何时被藏住 {#prop-overlap}
设反向传播耗时 $T_b$ 且以均匀速率产生梯度，全部梯度单独做全规约耗时 $T_c$，且通信与计算并行进行、彼此不受拖累。则这一步的通信至多在反向传播结束后 $\max(0, T_c - T_b) + T_c/n_b$ 处完成，其中 $n_b$ 为均等的桶数。
:::

::: proof
第 $k$ 个桶（共 $n_b$ 个）在时刻 $kT_b/n_b$ 就绪，其全规约耗时 $T_c/n_b$；各桶按序通信。若 $T_c\le T_b$，通信跟得上产生，每个桶在就绪后 $T_c/n_b$ 内完成，最后一个桶在 $T_b + T_c/n_b$ 处完成。若 $T_c > T_b$，链路自第一个桶就绪的时刻 $T_b/n_b$ 起始终忙碌，最后一个桶在 $T_b/n_b + T_c$ 处完成；减去 $T_b$ 得 $T_c - T_b + T_b/n_b\le T_c - T_b + T_c/n_b$。
:::

所以当 $T_c\le T_b$ 时——粗略地说，当梯度的全规约用时不超过反向传播——除最后一只桶外，通信是免费的。有了梯度累积，$A$ 个微批次的反向传播都可用来藏住一次全规约。实践中重叠并不完美，因为通信内核会与计算争抢内存带宽与片上资源，但这个条件给出的量级是对的。

::: example 全规约藏住了吗？ {#ex-overlap}
[[#ex-allreduce]]中的模型每设备每步处理 $8$ 条 $4096$ 词元的序列，设备峰值 $10^{15}$ FLOP/s，MFU 为 $40\%$。$64$ 台设备上的全规约能藏到反向传播背后吗？
::: solution
每设备词元数：$32{,}768$。计算量：$6\cdot7\times10^9\cdot32{,}768 = 1.38\times10^{15}$ FLOPs，以 $4\times10^{14}$ FLOP/s 计需 $3.4$ 秒，其中反向传播约占三分之二，即 $2.3$ 秒。全规约耗时 $0.55$ 秒，远小于 $2.3$ 秒，可以藏住。若每设备只有一条序列，反向传播只有 $0.29$ 秒，通信就会反客为主——数据并行需要每设备每步有足够的活儿。
:::
:::

## 数据并行能走多远？ {#sec-limits}

在每设备批次不变的情况下增加数据并行设备，会增大全局批次。在一定程度内，批次更大就能按比例少跑若干步；超过**临界批次大小**（critical batch size，McCandlish et al., 2018）之后——它随训练推进、损失下降而增长——每步多喂词元换来的步数缩减越来越少，多余的设备便是在浪费计算（[[pretraining/training-loop]]）。超参数也必须随批次改变：对 SGD，Goyal et al.（2017）让学习率随批次线性放大并加上预热；对 Adam 类优化器，平方根法则更接近基于随机微分方程的理论所提示的（Malladi et al., 2022），而逐层自适应方法（LARS，You et al., 2017；LAMB，You et al., 2020）正是为把批次推得更大而设计的。已发表的语言模型训练任务使用几百万到几千万量级词元的全局批次。

第二个限制是显存。每个副本都持有完整训练状态，按[[scaling/flops-memory#prop-bytes]]即 $16N$ 字节：若训练状态在单块设备上放不下，光靠数据并行就无法训练；而放得下的模型，也要白白浪费 $p$ 倍显存。本章剩下的部分就是要去掉这份浪费。

## ZeRO：给训练状态分片 {#sec-zero}

朴素数据并行的训练状态是冗余的：$p$ 台设备保存着参数、梯度和优化器状态各 $p$ 份一模一样的副本。Rajbhandari、Rasley、Ruwase 与 He（2020）注意到每台设备只需*更新* $\theta$ 的 $1/p$，并提出**零冗余优化器**（Zero Redundancy Optimizer，ZeRO），分三个阶段消除冗余。

::: definition ZeRO 的阶段 {#def-zero}
设参数共 $\Psi$ 个，数据并行设备 $p$ 台，每台设备 $r$ 负责 $\theta$ 中 $\Psi/p$ 个参数的分片 $\theta^{(r)}$：

- **阶段 1**（$P_{os}$）：每台设备只为自己分片保存优化器状态（fp32 主权重与矩）。反向传播后梯度做**规约-分散**，设备 $r$ 收到自己分片的平均梯度；更新自己的分片；更新后的 16 位参数做**全收集**。
- **阶段 2**（$P_{os+g}$）：同阶段 1，且每台设备还只为自己分片保存梯度，别的梯度一旦归约完即丢弃。
- **阶段 3**（$P_{os+g+p}$）：同阶段 2，且每台设备还只为自己分片保存 16 位参数。每层前向与反向计算之前，先把该层的完整参数全收集过来，用完即释放。
:::

::: theorem ZeRO 的显存与通信 {#thm-zero}
采用混合精度的 Adam——16 位参数 $2\Psi$ 字节、16 位梯度 $2\Psi$ 字节、优化器状态 $K\Psi$ 字节且 $K = 12$——每设备的模型状态为

| | 每设备字节数 | 每设备每步通信量 |
|---|---|---|
| 数据并行 | $(2 + 2 + K)\Psi$ | $2\Psi\cdot\frac{p-1}{p}\cdot2$ |
| 阶段 1 | $(2 + 2)\Psi + K\Psi/p$ | 同上 |
| 阶段 2 | $2\Psi + (2 + K)\Psi/p$ | 同上 |
| 阶段 3 | $(2 + 2 + K)\Psi/p$ | $1.5\times$ |

其中通信量按 16 位梯度与参数、环形集合通信计算。
:::

::: proof
**显存。**每个阶段把未分片的项完整保留、分片的项只留 $1/p$：阶段 1 分片优化器状态的 $K\Psi$；阶段 2 再分片梯度的 $2\Psi$；阶段 3 再分片参数的 $2\Psi$。

**通信。**朴素数据并行对 $2\Psi$ 字节梯度做全规约，由[[#thm-ring]]每设备花费 $2\cdot\frac{p-1}{p}\cdot2\Psi$ 字节——即一次规约-分散和一次全收集，各 $\frac{p-1}{p}\cdot2\Psi$。阶段 1 与 2 做的恰是这两半，只是拆在两个时刻：梯度的规约-分散（每台设备得到自己平均分好的一份）与分片更新之后的参数全收集。总量不变。阶段 3 必须在每层前向收集一次参数、反向之前再收集一次（其间已被释放），并对梯度做规约-分散：三次 $\frac{p-1}{p}\cdot2\Psi$，即数据并行通信量的 $1.5$ 倍。
:::

::: example ZeRO 论文中的算例 {#ex-zero}
Rajbhandari et al. 用 $\Psi = 75$ 亿参数、$p = 64$ 演示各阶段。计算每个阶段每设备的模型状态。
::: solution
数据并行：$16\cdot7.5 = 120$ GB。阶段 1：$4\cdot7.5 + 12\cdot7.5/64 = 30 + 1.41 = 31.4$ GB。阶段 2：$2\cdot7.5 + 14\cdot7.5/64 = 15 + 1.64 = 16.6$ GB。阶段 3：$120/64 = 1.9$ GB。仅阶段 1 就在通信分文未加的情况下把显存削减近四倍；阶段 3 以 $1.5$ 倍通信为代价，把需要 $120$ GB 的模型搬上只有几 GB 富余的设备。
:::
:::

::: widget plot

x: 1, 256

sliders: s=7.5:1:70:0.5

caption: 由[[#thm-zero]]得出的每设备模型状态（GB）随数据并行设备数 $p$ 的变化，参数规模为 $s$ 十亿。阶段 1 与 2 无论加多少设备都各自停在 $4s$ 与 $2s$ GB——那是未分片的 16 位参数（与梯度）；只有阶段 3 按 $16s/p$ 持续下降。实际显存略高：激活值、临时缓冲区以及阶段 3 收集来的层还要另算。
:::

阶段 3 还有一笔表中未列的显存开销：任一时刻，设备都持有正在计算的那一层（若**预取**，还加上下一层）的完整参数，反向传播期间还有它们的梯度。对 $L$ 个等宽层的模型，这约是 $2\cdot(2\Psi/L)$ 字节的已收集 16 位参数，对深模型来说很小。各阶段的通信都能与计算重叠：阶段 3 中，第 $\ell + 1$ 层参数的全收集在第 $\ell$ 层计算时发出。

后续工作把 ZeRO 朝几个方向扩展：**ZeRO-Offload**（Ren et al., 2021）把优化器状态与更新计算挪到 CPU 内存；**ZeRO-Infinity**（Rajbhandari et al., 2021）再添 NVMe 存储，用带宽换容量；**ZeRO++**（Wang et al., 2023）通过量化要收集的权重与梯度、并在每台服务器内保留一份参数次级副本，削减阶段 3 的通信。

## 全分片数据并行 {#sec-fsdp}

PyTorch 的**全分片数据并行**（Fully Sharded Data Parallel，FSDP；Zhao et al., 2023）把 ZeRO 阶段 3 的方案实现为框架原语。模型被划分为**单元**——通常每个单元一个 Transformer 块——每个单元的参数被展平后分片到数据并行组上。前向传播时，一个单元的各分片恰在它运行之前全收集、运行之后即释放（也可选择保留到反向传播，用显存换掉一次全收集）；反向传播时再次收集、算出梯度，然后对梯度做规约-分散，使每台设备只保留自己分片的平均梯度，由它的优化器更新。后来的重新设计（常称 FSDP2，2024）不再展平单元，而是把每个参数沿第一维单独分片，与张量并行组合起来更容易。

::: example FSDP 下的峰值显存 {#ex-fsdp}
一个 $700$ 亿参数、$80$ 个等宽块的模型用 FSDP 在 $p = 512$ 台设备上训练，每个块一个单元，并预取一个单元。估算反向传播峰值时每设备的模型状态显存。
::: solution
分片状态：$16\cdot7\times10^{10}/512 = 2.19$ GB。一个单元含 $7\times10^{10}/80 = 8.75\times10^8$ 个参数，16 位下 $1.75$ GB。反向传播时，一台设备持有当前单元与预取的下一单元收集来的参数（$3.5$ GB），以及当前单元在规约-分散之前的完整 16 位梯度（$1.75$ GB）。峰值约 $2.19 + 3.5 + 1.75 = 7.4$ GB，其中分片状态尚不足三分之一。单元更小能压低峰值，但集合通信次数更多、更小，延迟要多付。
:::
:::

::: definition 混合分片 {#def-hsdp}
**混合分片数据并行**（hybrid sharded data parallelism，HSDP）把 $p$ 台设备划成 $p/g$ 个 $g$ 台一组（例如一台服务器里的 $g = 8$ 台设备）。训练状态在每组内部像 ZeRO-3 那样分片，跨组复制；梯度先在组内规约-分散，再逐分片跨组全规约。
:::

混合分片把频繁且怕延迟的全收集限制在服务器内部的高速链路上，只把一次分片梯度的全规约（每设备 $2\Psi/g$ 字节）送过较慢的网络，代价是每设备显存为 $16\Psi/g$ 而非 $16\Psi/p$。对分片后能装进一台服务器总显存的模型，它是天然的选择。

::: warning 分片状态不分片激活值
ZeRO 与 FSDP 把模型状态除以 $p$，但每台设备仍在自己的微批次上运行整个模型，并完整保存该微批次的激活值。序列很长或模型很大时，激活值——按[[scaling/flops-memory]]的记账每层 $sbh(34 + 5as/h)$ 字节——仍可能超出设备显存。缓解办法是激活重计算、更小的微批次，或用张量、序列与流水线并行把计算本身也切到各设备上（[[scaling/model-parallelism]]）。另外，分片也不减少给定微批次下每设备的 FLOPs。
:::

::: quiz
一个团队把模型从朴素数据并行迁到 ZeRO 阶段 2，设备仍是 $64$ 台。哪些说法正确？
- [x] 每设备优化器状态显存降为 $1/64$。
- [ ] 每步通信量减少。
- [x] 参数仍在每台设备上复制。
- [ ] 全局批次大小必须除以 $64$。
::: solution
阶段 2 分片优化器状态与梯度，二者降为 $1/64$（即 $1/p$），而 16 位参数仍然复制。通信量维持数据并行的水平（一次规约-分散加一次全收集取代一次全规约）。批次毫无变化。
:::
:::

## 超越同步平均 {#sec-local}

同步数据并行的每一步都以一次全局全规约收尾，这要求所有设备之间有高速网络。当设备分散在多个数据中心或由慢速链路相连时，通信更稀疏的方法就有了吸引力。**局部 SGD**（local SGD）让每个副本先在自己的数据上走几步优化器步，再平均参数。**DiLoCo**（Douillard et al., 2023）在若干副本上各自用内层 AdamW 跑数百步，再对它们参数增量的平均施加一步外层 Nesterov 动量，在其实验中报告以少几百倍的通信取得了与完全同步训练相当的语言模型质量。这类方法仍是活跃的研究方向（截至 2026 年），已发表的最大规模运行仍是同步的。

::: history
带参数服务器的数据并行训练——工作进程把梯度推给中央服务器、再拉回参数——早期大规模深度学习就在用（Dean et al., 2012，DistBelief）；Hogwild!（Recht et al., 2011）等异步变体容忍过期梯度。环全规约源自高性能计算（Patarasuk and Yuan, 2009），经百度（2017）与 Horovod（Sergeev and Del Balso, 2018）在深度学习界推广；NVIDIA 的 NCCL 库使它成为 GPU 上的默认。Goyal et al.（2017）用大批次同步 SGD 一小时训完 ImageNet 上的 ResNet-50。Li et al.（2020）描述了 PyTorch DDP 的分桶与重叠。Rajbhandari et al.（2020）在 DeepSpeed 中引入 ZeRO，并用它训练了 $170$ 亿参数的 Turing-NLG；Zhao et al.（2023）描述了 PyTorch FSDP，使分片训练在 DeepSpeed 之外成为标准做法。
:::

::: summary
- **同步数据并行**把每个批次分给 $p$ 个副本并对梯度取平均；分片等大时，它等价于在整体上做单设备训练。
- **全规约**是规约-分散加全收集；**环形算法**每设备发送 $2(p-1)M/p$ 字节、共 $2(p-1)$ 步，几乎与 $p$ 无关，延迟为 $2(p-1)\alpha$。
- **分桶**与**重叠**在全规约用时不超过反向传播时把通信藏起来；每设备需要足够的活儿。
- 数据并行受**临界批次大小**与每副本 $16N$ 字节的**显存冗余**限制。
- **ZeRO** 分片优化器状态（阶段 1：$4\Psi + 12\Psi/p$）、梯度（阶段 2：$2\Psi + 14\Psi/p$）与参数（阶段 3：$16\Psi/p$）；阶段 1–2 通信量与数据并行相同，阶段 3 为 $1.5\times$。
- **FSDP** 以单元为单位、带预取地实现阶段 3；**混合分片**在服务器内分片、跨服务器复制。激活值不分片。
:::

## 习题

::: exercise 环形流量 {level=1 check="1.875"}
$p = 16$ 台设备的环全规约中，每台设备发送缓冲区大小的多少倍？
::: solution
$2(p-1)/p = 30/16 = 1.875$。
:::
:::

::: exercise 全局批次 {level=1 check="1024"}
某次运行用 $2$ 条序列的微批次、$8$ 步累积、$64$ 个数据并行副本。全局批次共多少条序列？
::: solution
$2\cdot8\cdot64 = 1024$。
:::
:::

::: exercise ZeRO-1 显存 {level=1 check="51.172"}
$\Psi = 1.25\times10^{10}$ 个参数、$p = 128$ 时，ZeRO 阶段 1 下每设备持有模型状态多少 GB？保留三位小数。
::: solution
$4\Psi + 12\Psi/p = 4\cdot12.5 + 12\cdot12.5/128 = 50 + 1.171875 = 51.172$ GB，而未分片时要 $200$ GB。未分片的 16 位参数与梯度如今反客为主。
:::
:::

::: exercise 延迟还是带宽 {level=2 check="800"}
环全规约的缓冲区 $M = 1$ GB，链路 $\beta = 50$ GB/s，$\alpha = 25\,\mu$s。[[#eq-ring-time]]中的延迟项在设备数 $p$ 为多大时等于带宽项？
::: solution
$2(p - 1)\alpha = 2\frac{p-1}{p}\frac{M}{\beta}$；两边约去 $2(p - 1)$ 得 $p = M/(\alpha\beta) = 10^9/(25\times10^{-6}\cdot5\times10^{10}) = 800$。超过约 $800$ 台设备，平环花在延迟上的时间就超过搬数据本身，这正是大集群采用分层或树形算法的原因之一。
:::
:::

::: exercise ZeRO-3 通信 {level=2 check="41.34"}
$\Psi = 7\times10^9$ 个参数、梯度与参数均为 16 位，$p = 64$ 的 ZeRO 阶段 3 下每设备每步发送多少 GB？保留两位小数。
::: solution
三次环形集合通信，每次 $2\Psi = 14$ GB，每次每设备花费 $\frac{p-1}{p}\cdot14 = 13.78$ GB：$3\cdot13.78 = 41.34$ GB，而一次全规约只需 $27.56$ GB。
:::
:::

::: exercise 不等的分片 {level=2}
两台设备处理的分片分别含 $1000$ 与 $3000$ 个目标词元，各自计算自己*平均*词元损失的梯度。证明简单平均这两个梯度并不给出全部 $4000$ 个词元上平均损失的梯度，并给出正确的组合方式。
::: solution
记 $S_1, S_2$ 为损失之和。两台设备算出 $\nabla S_1/1000$ 与 $\nabla S_2/3000$；它们的平均是 $\nabla S_1/2000 + \nabla S_2/6000$，把第一台设备的词元看得比第二台的重三倍。平均损失的梯度是 $\nabla(S_1 + S_2)/4000$；正确的做法是让每台设备算 $\nabla S_r$（或 $\nabla S_r$ 除以一个公共常数），用全规约求和，再除以全局词元总数 $4000$——它本身也用全规约求得。
:::
:::

::: exercise 混合分片 {level=2 check="14"}
一个 $70$ 亿参数的模型以混合分片在 $256$ 台设备上训练，每组 $g = 8$ 台。每设备持有模型状态多少 GB？若在全部 $256$ 台上完全分片能省下多少显存？
::: solution
HSDP 下 $16\Psi/g = 16\cdot7/8 = 14$ GB 每设备；完全分片只需 $112/256 = 0.44$ GB，每设备省 $13.6$ GB，但每次参数全收集都要跨网络。
:::
:::

::: exercise 藏住通信 {level=2}
用[[#prop-overlap]]，反向传播 $T_b = 1.2$ 秒、全规约 $T_c = 0.9$ 秒，分成 $n_b = 30$ 个桶。通信在反向传播结束后多久完成？若 $T_c = 1.8$ 秒呢？
::: solution
$T_c\le T_b$：延迟至多 $T_c/n_b = 0.03$ 秒。$T_c = 1.8$ 秒时：$T_c - T_b + T_b/n_b = 0.6 + 0.04 = 0.64$ 秒，即每步约 $0.64$ 秒的暴露通信——补救之道是让每设备干更多活（更大的微批次或更多累积）、少传字节（更低精度的梯度）或换更快的链路。
:::
:::

::: exercise 树形全规约 {level=3}
**二叉树**全规约把缓冲区沿 $p = 2^k$ 台设备的二叉树向根节点求和（每个内部节点接收两个缓冲区、相加、向上发一个），再把结果沿树广播回去。假设每台设备一次能发送并接收一个 $M$ 字节的消息，数出步数以及最忙设备发送与接收的字节数。与环形比较，并解释树形算法为什么要**流水化**——把 $M$ 分成多块。
::: solution
归约沿树走 $k = \log_2p$ 层，广播再走 $k$ 层：$2\log_2p$ 步，每步搬运整个缓冲区，若节点先后接收两个孩子的缓冲区，时间为 $2\log_2p\,(\alpha + M/\beta)$（或再多一个常数因子）。内部节点接收 $2M$ 并向上发送 $M$，随后接收 $M$ 并向下发送 $2M$：收发各约 $3M$，与 $p$ 无关但大于环形的 $2M$；而且——更要紧的——每一层都要等整个缓冲区，带宽项被乘以 $\log_2p$。把 $M$ 分成 $c$ 块后，不同层可以并发处理不同的块，时间大约成为 $(2\log_2p + c)(\alpha + M/(c\beta))$：$c\gg\log_2p$ 时带宽项趋于 $M/\beta$ 的常数倍，延迟保持对数量级。NCCL 因此使用流水化的双二叉树。
:::
:::

::: exercise 挑选 ZeRO 阶段 {level=3}
一个 $300$ 亿参数的模型在 $128$ 台各 $80$ GB 的设备上训练。选择性重计算下激活值占每设备 $25$ GB，另留 $10$ GB 给缓冲区。哪些 ZeRO 阶段放得下？就你选的阶段，链路 $50$ GB/s、完全重叠不了时，一个 $10$ 秒的步中有多大比例花在发送数据上？
::: solution
模型状态可用：$80 - 25 - 10 = 45$ GB。朴素 DP：$480$ GB，不行。阶段 1：$4\cdot30 + 12\cdot30/128 = 120 + 2.8 = 122.8$ GB，不行。阶段 2：$60 + 14\cdot30/128 = 63.3$ GB，不行。阶段 3：$480/128 = 3.75$ GB，可以（再为收集来的层留几 GB）。通信：每设备每步 $3\cdot\frac{127}{128}\cdot60$ GB $= 178.6$ GB，$50$ GB/s 下 $3.6$ 秒，不重叠即占一步的 $36\%$。让全收集与计算重叠、改用混合分片（阶段 3 在 $16$ 台一组内做只需 $480/16 = 30$ GB，放得下）都能压低暴露的开销；与服务器内部的张量并行结合是另一个标准选项（[[scaling/model-parallelism]]）。
:::
:::
