Transformer 把它的全部参数都用在每一个词元上：词 *the* 与一行 Python 代码或一个汉语成语穿过的是同一套前馈权重。**混合专家**（mixture of experts，MoE）切断了这种绑定。它把一个块中的前馈网络换成许多备选网络——**专家**——再配一个小型**路由器**，把每个词元只发送给其中少数几个专家。于是模型拥有大网络的参数量，而每个词元只花费小网络的计算量。例如，Mixtral 8×7B 存有约 $470$ 亿参数，但每个词元只使用约 $130$ 亿；DeepSeek-V3 存有 $6710$ 亿，每个词元使用 $370$ 亿。

这种条件计算并非免费：所有专家都必须存放在内存中；词元必须在设备之间搬运才能到达自己的专家；而听之任之的路由器会把大多数词元送给少数几个“受宠”的专家，其余专家什么也学不到。本章定义 MoE 层，计算它的参数量与 FLOPs，并解释使它可训练的负载均衡损失与容量限制。

## 稀疏专家层 {#sec-layer}

MoE 层取代部分或全部 Transformer 块中的前馈网络；注意力部分保持不变。

::: definition 带 top-$k$ 路由的混合专家层 {#def-moe}
设 $E_1, \dots, E_N$ 为 $N$ 个专家网络 $\R^d\to\R^d$（通常是 [[transformers/transformer-block#def-ffn]] 那种前馈网络），$W_r\in\R^{d\times N}$ 为路由器的权重。对一个表示为 $\mathbf{x}$ 的词元，设 $\mathbf{z} = \mathbf{x}W_r$ 为它的路由 logits，$\mathcal{T}\subset\{1, \dots, N\}$ 为其最大的 $k$ 个 logits 的下标。则 **MoE 层**输出

$$
\operatorname{MoE}(\mathbf{x}) = \sum_{i\in\mathcal{T}} g_i(\mathbf{x})\,E_i(\mathbf{x}), \qquad g_i(\mathbf{x}) = \frac{e^{z_i}}{\sum_{j\in\mathcal{T}}e^{z_j}},
$$

即门权重是只在被选中的专家上取的 softmax。只有被选中的 $k$ 个专家会被求值。
:::

各变体的差别只在细节：有的模型在全部 $N$ 个 logits 上取 softmax，再保留最大的 $k$ 个值而不重新归一化；有的模型另加一个或多个**共享专家**，所有词元在路由到的专家之外都使用它们。但本质特征是相同的——一个学出来的、依赖词元的选择，挑出少数几个专家，再对它们的输出作加权和。

路由器和其余部分一样由梯度下降训练，梯度经由门权重 $g_i$ 传入：一个专家若帮助减小了某个词元的损失，下次遇到相似的词元时它分到的 logit 就更大。*选择*哪些专家来求值这件事是离散的、没有梯度，但分给被选中专家的权重有。

::: example 为一个词元路由 {#ex-router}
某层有 $N = 4$ 个专家和 top-$2$ 路由。某个词元的路由 logits 为 $\mathbf{z} = (2.0, 1.0, 0.5, -1.0)$，被选中的专家沿某一个坐标的输出为 $E_1(\mathbf{x}) = 1$、$E_2(\mathbf{x}) = 3$。计算门权重与输出。若不在重新归一化的情况下、改为在全部四个 logits 上取 softmax 再取前两个，权重会是多少？
::: solution
最大的两个 logits 是 $z_1 = 2$ 与 $z_2 = 1$，故 $\mathcal{T} = \{1, 2\}$，

$$
g_1 = \frac{e^2}{e^2 + e^1} = \frac{1}{1 + e^{-1}} = 0.731, \qquad g_2 = 0.269.
$$

输出为 $0.731\cdot1 + 0.269\cdot3 = 1.538$。专家 $3$ 和 $4$ 根本不被求值。在全部四个 logits 上取 softmax 得 $(0.610, 0.224, 0.136, 0.030)$；不重新归一化而保留前两个，权重为 $0.610$ 与 $0.224$，和为 $0.834$，于是输出会被分给未选中专家的那些权重压低。像 Mixtral 那样重新归一化，能保持输出与单个稠密网络处于同一尺度。
:::
:::

:::

## 参数与计算 {#sec-count}

MoE 的吸引力在于参数与计算彼此脱钩。

::: proposition 激活的参数量 {#prop-active}
在一个前馈网络全部换成 MoE 层的模型中，每层有 $N$ 个专家、每个专家 $P_e$ 个参数、采用 top-$k$ 路由，则每层存放的专家参数为 $NP_e$，而每个词元实际用到的专家参数为 $kP_e$。每个词元的前向 FLOPs 取决于 $k$，与 $N$ 无关。
:::

::: proof
所有 $N$ 个专家都必须存放，因为任何词元都可能被路由到其中任何一个。给定词元恰好由 $k$ 个专家处理，每个专家约花费 $2P_e$ FLOPs（每个权重两个），加上路由器的 $2dN$，后者很小。固定 $k$ 而增大 $N$，增加的是存放的参数量，而不是每个词元的 FLOPs（路由器除外）。
:::

::: example 数一数 Mixtral 8×7B {#ex-mixtral}
Mixtral 8×7B 有 $L = 32$ 层，$d = 4096$，注意力有 $32$ 个查询头和 $8$ 个维数为 $128$ 的键值头；每一层都有 $8$ 个 $d_{\text{ff}} = 14{,}336$ 的 SwiGLU 专家，采用 top-$2$ 路由；词表含 $32{,}000$ 个词元，输入与输出嵌入分开。计算它的总参数量与激活参数量。
::: solution
每层：注意力 $2\cdot4096^2 + 2\cdot4096\cdot1024 = 41{,}943{,}040$；每个专家 $3\cdot4096\cdot14{,}336 = 176{,}160{,}768$，八个专家共 $1{,}409{,}286{,}144$；路由器 $4096\cdot8 = 32{,}768$；两个 RMSNorm 增益 $8192$。每层合计 $1{,}451{,}270{,}144$，$32$ 层共 $46{,}440{,}644{,}608$。再加上嵌入 $2\cdot32{,}000\cdot4096 = 262{,}144{,}000$ 和末尾的归一化 $4096$，得 $46{,}702{,}792{,}704$——即 Mixtral 论文的“47B”。

每个词元的激活量：与上面相同，只是每层用两个专家而不是八个：$32\cdot(41{,}943{,}040 + 2\cdot176{,}160{,}768 + 32{,}768 + 8192) + 262{,}144{,}000 + 4096 = 12{,}879{,}925{,}248$，即“13B”。每个词元只经过模型约 $28\%$ 的参数。
:::
:::

::: warning “8×7B”不是 560 亿
Mixtral 8×7B 这个名字听起来像是把一个 $70$ 亿参数的模型复制八份、共 $560$ 亿参数。被复制的只有前馈网络：注意力、嵌入和归一化由所有专家共享，这正是总数只有 $467$ 亿的原因。同样，说一个 MoE 模型“激活参数 $13$B”，并不表示它能装进一个 13B 稠密模型的内存——全部 $47$B 都必须加载，因为任何词元都可能用到任何专家。MoE 省下的是每个词元的计算量，不是内存。
:::

于是在每个词元计算量相同的前提下，MoE 模型的参数量可以是稠密模型的许多倍。实验上，这些参数买来了质量：Switch Transformer 在预训练中只用其稠密 T5 基线的几分之一的时间就达到了后者的质量；Mixtral 在作者报告的大部分基准上追平或超过了 Llama 2 70B，而激活参数量只有其约五分之一。代价转移到了别处——内存、通信，以及训练的难度。

## 负载均衡 {#sec-balance}

刚初始化的路由器有一种自我强化的失效模式：早期恰好多分到词元的专家改进得更快，这就使路由器更偏爱它们，直到最后少数几个专家处理几乎所有词元、其余专家被白白浪费。两种机制对此加以遏制。

第一种是一个奖励均衡路由的辅助损失。

::: definition 负载均衡损失 {#def-aux-loss}
设一批 $B$ 个词元被路由到 $N$ 个专家，$f_i$ 为派给专家 $i$ 的词元比例（对 top-$k$ 路由，是全部 $kB$ 次分配中的比例），$P_i$ 为路由器在整批上对专家 $i$ 的平均概率，$P_i = \frac1B\sum_{\text{词元}}\operatorname{softmax}(\mathbf{z})_i$。Switch Transformer 的**负载均衡损失**为

$$
\mathcal{L}_{\text{aux}} = \alpha\,N\sum_{i=1}^{N} f_i\,P_i,
$$

以 $\alpha = 0.01$ 这样的小权重加到语言建模损失上。
:::

比例 $f_i$ 来自离散选择，没有梯度；这个损失通过概率 $P_i$ 训练路由器，压低那些已经分到很多词元的专家的概率。为什么是这个形式？

::: proposition 均衡使损失最小 {#prop-balance}
若派给各专家的比例等于平均概率，即对所有 $i$ 有 $f_i = P_i$，则 $\mathcal{L}_{\text{aux}} = \alpha N\sum_if_i^2\ge\alpha$，等号成立当且仅当路由是均匀的，即对所有 $i$ 有 $f_i = 1/N$。
:::

::: proof
当 $f_i = P_i$ 时，损失为 $\alpha N\sum_if_i^2$。由柯西-施瓦茨（Cauchy–Schwarz）不等式，$1 = \big(\sum_i f_i\cdot1\big)^2\le\big(\sum_if_i^2\big)\big(\sum_i1^2\big) = N\sum_if_i^2$，故 $N\sum_if_i^2\ge1$；等号成立当且仅当 $(f_1, \dots, f_N)$ 与 $(1, \dots, 1)$ 成正比，即每个 $f_i = 1/N$。
:::

::: widget plot
f: 2*(x^2 + (1 - x)^2)
x: 0, 1
y: 0.9, 2.1
points: 0.5, 1
caption: 两个专家的负载均衡损失（取 $\alpha = 1$）：比例为 $x$ 的词元去往专家 1，它的平均路由概率也是 $x$。均分时损失最小，为 $1$；一个专家独占所有词元时损失升至 $2$。
:::

::: example 一个辅助损失 {#ex-aux}
一批词元被路由到 $N = 4$ 个专家，派给比例为 $\mathbf{f} = (0.4, 0.3, 0.2, 0.1)$，平均路由概率为 $\mathbf{P} = (0.35, 0.3, 0.2, 0.15)$。计算 $\mathcal{L}_{\text{aux}}/\alpha$，并与均衡路由比较。
::: solution
$\sum_if_iP_i = 0.14 + 0.09 + 0.04 + 0.015 = 0.285$，故 $\mathcal{L}_{\text{aux}}/\alpha = 4\cdot0.285 = 1.14$。均衡路由给出 $4\cdot4\cdot\tfrac14\cdot\tfrac14 = 1$。对 $P_1$ 的梯度正比于 $f_1 = 0.4$，是四个中最大的，所以这个损失会促使路由器最大幅度地压低专家 1 的概率。
:::
:::

第二种机制是硬性限制：在并行硬件上，每个专家每批处理固定大小的词元缓冲区。

::: definition 专家容量 {#def-capacity}
设每批有 $B$ 个词元、$N$ 个专家、top-$k$ 路由和**容量因子** $c\ge1$，则每个专家每批至多接受

$$
C = c\cdot\frac{kB}{N}
$$

次词元分配。超出容量的分配会被**丢弃**：词元跳过该专家，原样经由残差连接继续向前。
:::

容量因子取略大于 $1$ 的数（Switch Transformer 用 $1$ 到 $1.25$）为不均衡留出了余地；丢弃词元虽然浪费，却使每个专家的工作量——从而每步的时长——有界。

::: example 容量与被丢弃的词元 {#ex-capacity}
某层有 $N = 8$ 个专家、top-$2$ 路由，处理的批次为 $B = 4096$ 个词元，容量因子 $c = 1.25$。每个专家的容量是多少？若某个专家收到 $1500$ 次分配，有多少被丢弃？
::: solution
$C = 1.25\cdot2\cdot4096/8 = 1280$。收到 $1500$ 次分配的专家处理其中 $1280$ 次，丢弃 $220$ 次；那些词元只能得到它另一个专家（加上残差流）的输出。若完全均衡，每个专家分到 $1024$ 次分配，远未触及容量。
:::
:::

较新的模型对这两种机制都做了改进。ST-MoE（Zoph et al., 2022）增加了**路由 z 损失**，惩罚过大的路由 logits，

$$
\mathcal{L}_z = \frac1B\sum_{\text{词元}}\Big(\log\sum_{j=1}^{N}e^{z_j}\Big)^2,
$$

权重取小值即可；把 logits 保持在小范围内，可使路由器的 softmax 避开低精度下舍入误差变大的区域，显著改善训练稳定性。**专家选择**（expert-choice）路由（Zhou et al., 2022）把选择反过来：由每个专家去挑自己最想要的词元，从构造上就均衡了负载。DeepSeek-V3（2024）几乎不依赖辅助损失来均衡其 $256$ 个细粒度专家：给每个专家的 logit 加一个偏置，专家闲置时抬高、超载时压低；这个偏置只影响选中哪些专家，不影响门权重。

::: quiz
关于一个训练好的、含 $8$ 个专家、top-$2$ 路由的 MoE 模型，下列说法哪些正确？（多选）
- [x] 推理期间八个专家都必须留在内存中
- [x] 它的专家层中每个词元的 FLOPs，约等于一个前馈参数量相当于两个专家的稠密模型
- [ ] 每个专家都专攻一个人类可辨认的主题，比如数学或生物
- [ ] 把专家数量翻倍，每个词元的 FLOPs 也翻倍
::: solution
任何词元都可能被路由到任何专家，所以所有专家都必须存放；每个词元的计算量取决于 $k = 2$ 而非 $N$（[[#prop-active]]），因此把 $N$ 翻倍只增加参数和路由器的开销，不增加专家的 FLOPs。对训练好的模型（包括 Mixtral 论文）的分析发现，路由往往遵循表面特征——句法、词元类型、位置——而不是干净的主题；专家从设计上就不是供人类阅读的专科医生。
:::
:::

那么专家究竟学到了什么？Mixtral 作者在对路由的分析中没有发现按学科划分专家的明显迹象——生物、哲学和数学文本使用的基本上是同一批专家——但发现了清楚的句法模式：Python 里的 *self* 和代码中的缩进被持续地送往特定专家，相邻的词元也常常被路由到相同的地方。专门化确实出现了，但划分的方式服务于模型，而不是图书管理员。

## 系统与权衡 {#sec-systems}

大型 MoE 模型用**专家并行**（[[scaling/model-parallelism]]）训练：不同的专家住在不同的设备上，每个 MoE 层执行一次*全对全*（all-to-all）交换，把每个词元的表示送到持有其专家的设备、再把结果取回。这种稠密模型没有的通信常常是瓶颈，并随 $k$ 和 $d$ 增长。推理则有镜像一般的问题：尽管每个词元只用到少数专家，所有专家都必须常驻内存，所以 MoE 模型的推理服务非常耗内存，而且批次必须足够大，才能让每个专家都有活干。

MoE 层放在哪里本身就是设计选择。GShard 和 Switch Transformer 每隔一个前馈网络换一个 MoE 层；Mixtral 全部替换；DeepSeek-V3 把前三个层保持为稠密，因为那里的词元表示还接近原始嵌入。推理时路由逐词元而变，所以一批 $B$ 个词元在每层会触及至多 $\min(N, kB)$ 个不同的专家。批次很小时，许多专家的权重从内存中读出却只处理一两个词元——正是 [[transformers/attention-complexity#def-roofline]] 所说的内存受限区——因此 MoE 模型在同时服务大量请求时最划算；在 GPU 内存有限的机器上，闲置的专家常被放到较慢的内存中，需要时再调入。

有两个设计趋势格外显眼。**细粒度专家**把每个专家拆成若干更小的专家，并把每个词元按相同比例路由给其中更多的专家：FLOPs 不变，而可能的专家组合数目暴增；DeepSeekMoE（Dai et al., 2024）把这一点与所有词元都使用的**共享专家**结合，用来存放无需被路由专家重复的公共知识。另一个是随着模型变大，激活参数的比例不断下降：DeepSeek-V3 在 $6710$ 亿参数中激活 $370$ 亿，约 $5.5\%$，而 Mixtral 是 $28\%$。

::: history
Jacobs、Jordan、Nowlan 与 Hinton（1991）提出了局部专家的自适应混合：由一个门控网络学会把每个输入指派给几个网络之一；Jordan 与 Jacobs（1994）把它做成了层级结构。Shazeer et al.（2017）以*稀疏门控*混合专家层让这一思想在大规模上复活：在循环层之间用带噪的 top-$k$ 门控，训练出参数多达 $1370$ 亿的语言模型。GShard（Lepikhin et al., 2020）把 top-$2$ 专家带入 Transformer，做出一个 $6000$ 亿参数的翻译模型；Switch Transformer（Fedus、Zoph 与 Shazeer，2021）把路由简化为单个专家，突破了万亿参数。GLaM（Du et al., 2021）与 ST-MoE（Zoph et al., 2022）改善了质量与稳定性，Zhou et al.（2022）提出了专家选择路由。Mixtral 8×7B（Jiang et al., 2024）让强大的开放 MoE 模型广为可得；DeepSeekMoE（Dai et al., 2024）与 DeepSeek-V3（2024）发展了细粒度专家、共享专家和无辅助损失的偏置均衡。
:::

::: summary
- MoE 层把前馈网络换成 $N$ 个专家和一个路由器；每个词元由其最看好的 $k$ 个专家处理，权重是这些专家 logits 上的 softmax。
- 存放的参数量随 $N$ 增长，每个词元的 FLOPs 随 $k$ 增长：Mixtral 8×7B 存放 $46.7$B 参数，每词元使用 $12.9$B。
- 若无干预，路由会塌缩到少数专家身上。在均匀路由下取最小值的负载均衡损失 $\alpha N\sum_if_iP_i$，加上带词元丢弃的每专家容量 $C = ckB/N$，使负载保持均衡、步时有界。
- 改进包括路由 z 损失、专家选择路由、细粒度与共享专家，以及无需辅助损失的偏置均衡。
- MoE 用内存和通信换计算：所有专家都必须存放，专家并行还要求设备之间的全对全交换。
:::

## 习题

::: exercise 存放的与使用的 {level=1 check="1/4"}
一个 MoE 层有 $8$ 个等大的专家和 top-$2$ 路由。每个词元用到该层专家参数的多少比例？
::: solution
$k/N = 2/8 = 1/4$。（就 Mixtral 整体而言，把注意力和嵌入也算进去，这个比例约为 $28\%$。）
:::
:::

::: exercise 两道门 {level=1 check="exp(1)/(exp(1)+1)"}
某个词元最大的两个路由 logits 为 $1.5$ 和 $0.5$。按 top-$2$ 路由和 [[#def-moe]] 的重新归一化 softmax，第一个专家分到的权重是多少？
::: solution
$e^{1.5}/(e^{1.5} + e^{0.5}) = 1/(1 + e^{-1}) = e/(e + 1)\approx0.731$。重要的只是两个 logits 之差。
:::

::: exercise 一个容量 {level=1 check="1280"}

::: exercise 均衡时的取值 {level=1 check="1"}
当 $N = 16$ 个专家各分到恰好 $1/16$ 的分配、平均路由概率也是 $1/16$ 时，$\mathcal{L}_{\text{aux}}/\alpha$ 是多少？

::: exercise 证明均衡 {level=2}
不用柯西-施瓦茨不等式而直接证明：当 $\sum_if_i = 1$ 时 $\sum_{i=1}^Nf_i^2 - \frac1N = \sum_{i=1}^N\big(f_i - \frac1N\big)^2$，以此完善 [[#prop-balance]] 的证明。这个恒等式对损失随不均衡程度的增长说明了什么？
::: solution
$\sum_i(f_i - \tfrac1N)^2 = \sum_if_i^2 - \tfrac2N\sum_if_i + N\cdot\tfrac1{N^2} = \sum_if_i^2 - \tfrac2N + \tfrac1N = \sum_if_i^2 - \tfrac1N$。于是 $\mathcal{L}_{\text{aux}}/\alpha = N\sum_if_i^2 = 1 + N\sum_i(f_i - \tfrac1N)^2$：损失超出最小值的部分，是路由分布到均匀分布的平方距离的 $N$ 倍，所以小的不均衡代价很小，大的不均衡代价很大。
:::
:::

::: exercise 梯度看到了什么 {level=2}
在 $\mathcal{L}_{\text{aux}} = \alpha N\sum_if_iP_i$ 中，比例 $f_i$ 是离散选择的计数。解释为什么梯度不会流过 $f_i$；计算 $\partial\mathcal{L}_{\text{aux}}/\partial P_i$，并描述这会如何改变一个超载专家的路由 logits。
::: solution
$f_i$ 的得出方式是数一数有多少词元在 top-$k$ 操作中选中了专家 $i$；logits 的微小改动不会改变计数（或者以跳跃的方式改变），所以它的导数几乎处处为零，并被视作常数。于是 $\partial\mathcal{L}_{\text{aux}}/\partial P_i = \alpha Nf_i$。梯度下降按 $f_i$ 的比例压低 $P_i$：被最严重超载的专家得到压低其概率的最强推力，而经由 softmax，这会压低它在批内词元上的 logits，使它下次更不容易被选中。
:::
:::

::: exercise 通信开销 {level=3 check="32768"}
在专家并行下，每个词元的 $d$ 维表示被送到持有其 $k$ 个专家的设备，再把 $k$ 个结果送回来。设 $d = 4096$、$k = 2$、bfloat16，最坏情形（每个专家都在别的设备上）下，每个词元每层有多少字节要穿过网络？对 $10^6$ 个词元、$32$ 层的批次，每次前向传播合多少 TB？
::: solution
送出：$k\cdot d\cdot2 = 16{,}384$ 字节；送回：同样多；合计每词元每层 $32{,}768$ 字节。$10^6$ 个词元、$32$ 层：$32{,}768\cdot10^6\cdot32\approx1.05\times10^{12}$ 字节，即每次前向传播约 $1$ TB，反向传播还要多约一倍。这就是 MoE 训练需要高速互连的原因，也是系统尽力安排专家位置、让大部分流量留在单个节点内的原因。
:::
:::

::: exercise 代码中的路由层 {level=3}
在 PyTorch 中实现一个含 $N = 4$ 个小 SiLU 专家、top-$2$ 路由的 MoE 层：对每个专家，收集路由到它的词元、把这些词元作为一个批次运行该专家一次，再把加权输出散射回原来的位置。用一个慢速循环对照检验：对每个词元，在其两个专家上求 $g_i(\mathbf{x})E_i(\mathbf{x})$ 的和。
::: solution
```python
import torch, torch.nn as nn

torch.manual_seed(0)
B, d, N, k, hidden = 5, 8, 4, 2, 16
x = torch.randn(B, d)                                   # (B, d)：五个词元
W_r = torch.randn(d, N)                                 # 路由器权重
experts = [nn.Sequential(nn.Linear(d, hidden), nn.SiLU(), nn.Linear(hidden, d)) for _ in range(N)]

top, idx = (x @ W_r).topk(k, dim=-1)                    # (B, k) logits 与专家下标
g = top.softmax(dim=-1)                                 # (B, k) 重新归一化的门
y = torch.zeros_like(x)
for e in range(N):                                      # 每个专家一次批量调用
    rows, slot = (idx == e).nonzero(as_tuple=True)      # 路由到专家 e 的词元，以及所在的槽
    if len(rows):
        y[rows] += g[rows, slot, None] * experts[e](x[rows])

slow = torch.stack([sum(g[b, s] * experts[int(idx[b, s])](x[b]) for s in range(k)) for b in range(B)])
print(torch.allclose(y, slow, atol=1e-6))               # True
```

批量化版本正是真实实现的做法（再加上容量限制，以及跨设备时的全对全通信）：每个专家面对自己词元的一个稠密批次，矩阵乘得以保持高效。
:::

::: exercise 细粒度专家 {level=3 check="488526937079580"}
某层有 $8$ 个专家、top-$2$ 路由。把每个专家拆成 $8$ 个更小的专家（每个只有原来八分之一大），并把每个词元路由到拆出的 $64$ 个专家中的 $16$ 个，参数量和每词元 FLOPs 都不变。拆分前后，一个词元各能选多少种不同的专家组合？更多的组合为什么可能有帮助？
::: solution
拆分前：$\binom82 = 28$ 种组合。拆分后：$\binom{64}{16} = 488{,}526{,}937{,}079{,}580$，约 $4.9\times10^{14}$。每个专家的参数量与激活比例不变（$16$ 个八分之一大小的专家等于 $2$ 个完整大小的），但路由器如今能为每个词元拼出远为具体的混合，于是知识可以更细地分到各专家、重复更少。这正是 DeepSeekMoE 细粒度专家的动机——它还配了共享专家，使公共知识不必在每个组合中复制。
:::
