训练一个大语言模型，数以万计的加速器要连续运转数周乃至数月；而把它提供给数百万用户使用，则让其中更多的加速器无限期运转。所有这些计算都靠电力驱动，产生需要排走的热量（往往要用水），并用到制造过程本身有碳足迹的硬件。对这些成本的估计，从触目惊心到不以为然都有，有时对同一个系统两种说法并存，因为它们依赖的假设很少被说出口。

本章讲授如何作出这类估计、如何读懂它们。我们先由浮点运算次数推导一次训练的能量消耗，再经硬件效率、利用率与数据中心的开销折算，然后通过电网的碳强度把能量换算成排放。我们比较训练与推理（inference），讨论水与隐含排放，并回顾已发表的估计——Strubell、Ganesh 与 McCallum（2019）、Patterson 等（2021）、Luccioni、Viguier 与 Ligozat（2023）——连同它们的日期、区间与争议。最后讨论能效的趋势，以及"能效提高是否减少总消耗"的争论。

这个领域的数字随硬件、模型与普及程度迅速变化，商用系统的许多输入并不公开。下文每一个数字都注有日期，请把它们当作数量级，并在引用任何估计之前先检查其假设。

## 从 FLOPs 到焦耳 {#sec-energy}

一次训练的计算量可近似为 $C\approx6ND$ 次浮点运算：参数规模为 $N$ 的稠密 Transformer 在 $D$ 个词元上训练——前向每词元约 $2N$，反向 $4N$（[[scaling/flops-memory]]）。硬件不会以峰值速率运行：实际达到的比例称为**模型 FLOPs 利用率**（model FLOPs utilisation，MFU），大规模训练通常在 $30\%$–$50\%$（[[scaling/large-runs]]）。

::: definition 电能使用效率 {#def-pue}
数据中心的**电能使用效率**（power usage effectiveness）为

$$
\text{PUE} = \frac{\text{全设施总能耗}}{\text{输送给IT设备的能量}}\ \ge1.
$$

超出 $1$ 的部分花在制冷、供电变换与照明上。大型现代设施报告的年均值约为 $1.1$–$1.2$；行业调查所报的全球平均值约为 $1.5$–$1.6$（截至2020年代中期）。
:::

::: proposition 一次训练的能量 {#prop-energy}
设某次训练执行 $C$ FLOPs，所用加速器峰值吞吐为 $F$（FLOP/s）、利用率 $u$，每台平均功率 $P$（W；如需，可含其分摊的主机与网络功耗），所在设施的电能使用效率为 $\text{PUE}$。则加速器时间为 $C/(uF)$ 秒，全设施能耗为

$$
E = \frac{C}{u\,F}\cdot P\cdot\text{PUE} = \frac{C}{u\,\eta}\cdot\text{PUE},\qquad \eta = \frac{F}{P}\ \ (\text{峰值 FLOP/焦耳}).
$$ {#eq-energy}
:::

::: proof
每台加速器每秒执行 $uF$ 个有效 FLOPs，故加速器·秒总数为 $C/(uF)$，与有多少台加速器分摊工作无关（更多的加速器缩短墙上时钟时间，但不减少总量）。每台加速器·秒在 IT 层消耗 $P$ 焦耳，而全设施消耗 IT 能耗的 $\text{PUE}$ 倍。记 $\eta = F/P$ 即得第二种形式。
:::

有两点简化值得注意。加速器未满负荷时功率低于额定值，所以用热设计功耗（TDP）作 $P$ 往往高估；但主机处理器、内存、网络与存储也在耗电，失败或重跑的训练、超参数搜索与小型实验也消耗算力——例如 Meta 报告，其 AI 算力容量大部分用于实验与推理而非最终训练（Wu et al., 2022）。因此"最终一次训练"的估计只是开发一个模型成本的下界。

::: definition 碳强度；基于位置与基于市场的核算 {#def-carbon}
电力的**碳强度** $I$ 指每单位发电量排放的温室气体质量，单位 $\text{kgCO}_2\text{e}/\text{kWh}$（二氧化碳当量，其他气体按其增温潜势折算）。运行排放即 $E\cdot I$。**基于位置**（location-based）的核算使用耗电所在地电网的平均强度；**基于市场**（market-based）的核算使用消费者通过购电协议或可再生能源证书所合约购买的电力的强度，对购买了足额绿电的公司可以接近于零。
:::

电网碳强度相差超过一个数量级：水电或核电为主的电网（挪威、魁北克、法国）通常低于 $0.06\ \text{kg/kWh}$，煤电为主的电网则超过 $0.6$；随太阳能与风电出力变化，强度逐小时也在变。同一次训练，基于位置与基于市场的数字可以天差地别，因此"零排放"的报告或一个大数字，都必须连同其核算方法一起读。基于市场的主张是否对应真实的减排，存在争论：支持者说长期购电协议为新增可再生能源提供了资金；批评者说按年匹配的证书并不能保证在用电的小时与地点用上清洁电力——这促使一些公司转向按小时（"24/7"）匹配。

::: example 一次700亿参数的训练 {#ex-training}
估计训练一个 $700$ 亿参数（$7\times10^{10}$）的稠密模型、在 $15$ 万亿词元上训练的能量与排放：加速器稠密 BF16 峰值 $989$ TFLOP/s、额定功率 $700$ W（NVIDIA H100 SXM 的数字），利用率 $40\%$、$\text{PUE} = 1.1$，电网强度 $0.4\ \text{kg/kWh}$。
::: solution
$C = 6\cdot7\times10^{10}\cdot1.5\times10^{13} = 6.3\times10^{24}$ FLOPs。加速器·秒 $= 6.3\times10^{24}/(0.4\cdot9.89\times10^{14}) = 1.59\times10^{10}$ s $= 4.42\times10^6$ 加速器·小时。IT 能量 $= 4.42\times10^6\ \text{h}\cdot0.7\ \text{kW} = 3.10\times10^6$ kWh；全设施能量 $= 1.1\times$ 该值 $= 3.41\times10^6$ kWh $\approx3.4$ GWh。排放 $= 3.41\times10^6\cdot0.4 = 1.36\times10^6$ kg $\approx1{,}360$ tCO$_2$e。

作为对照，Meta 的 Llama 3 70B 模型卡（2024）报告训练用逾 $15$ 万亿词元，$640$ 万 H100 GPU 小时、基于位置的排放 $1{,}900$ tCO$_2$e（基于市场为零，因为 Meta 以绿电采购匹配了用电）。报告的小时数比我们的估计高约 $45\%$，与更低的平均利用率或一次干净训练之外的额外工作相吻合；排放则在同一量级。$3.4$ GWh 大约相当于数百户美国家庭一年的用电量。
:::
:::

下面的清单复现了这一估计，并显示它对两个最不确定的输入有多敏感。

```python
def training_footprint(n_params, n_tokens, peak_flops, chip_watts, util, pue, grid_kg_per_kwh):
    """Energy (MWh) and emissions (tCO2e) of a training run, from first principles."""
    flops = 6 * n_params * n_tokens                     # 前向 + 反向
    chip_seconds = flops / (peak_flops * util)          # 加速器·秒
    chip_hours = chip_seconds / 3600
    it_kwh = chip_hours * chip_watts / 1000             # 加速器耗掉的电能
    facility_kwh = it_kwh * pue                         # 制冷、供电变换……
    return {"FLOPs": flops, "chip-hours": chip_hours, "MWh": facility_kwh / 1000,
            "tCO2e": facility_kwh * grid_kg_per_kwh / 1000}

# 一个 700 亿参数的模型在 15 万亿词元上训练，H100 级加速器
# （稠密 BF16 峰值 989 TFLOP/s，700 W），利用率 40 %，PUE 1.1
base = dict(n_params=70e9, n_tokens=15e12, peak_flops=989e12, chip_watts=700, util=0.4, pue=1.1)
r = training_footprint(**base, grid_kg_per_kwh=0.4)
print(f"FLOPs {r['FLOPs']:.2e}  chip-hours {r['chip-hours']/1e6:.2f} M  energy {r['MWh']:,.0f} MWh")

print("emissions (tCO2e) by grid intensity and utilisation:")
print("            " + "".join(f"util {u:.2f}  " for u in (0.3, 0.4, 0.5)))
for grid in (0.03, 0.2, 0.4, 0.7):
    row = [training_footprint(**{**base, "util": u}, grid_kg_per_kwh=grid)["tCO2e"] for u in (0.3, 0.4, 0.5)]
    print(f"{grid:4.2f} kg/kWh " + "".join(f"{t:10,.0f}  " for t in row))

# 推理：多少查询用掉与训练相当的能量？
for wh_per_query in (0.3, 3.0):
    q = r["MWh"] * 1e6 / wh_per_query
    print(f"{wh_per_query} Wh/query: training energy = {q:.2e} queries"
          f" = {q / 1e9:.1f} days at a billion queries a day")
```

```text
emissions (tCO2e) by grid intensity and utilisation:
            util 0.30  util 0.40  util 0.50  
0.03 kg/kWh        136         102          82  
0.20 kg/kWh        908         681         545  
0.40 kg/kWh      1,817       1,362       1,090

0.3 Wh/query: training energy = 1.14e+10 queries = 11.4 days at a billion queries a day

```

在一个合理的取值范围内，利用率使答案变动约 $1.7$ 倍；电网则使它变动 $23$ 倍。在哪里训练远比训练得多高效重要，这正是 Patterson 等（2021）强调选址与数据中心选择的原因。

## 已发表的估计及其度量对象 {#sec-published}

**Strubell、Ganesh 与 McCallum（2019）**通过测量短时训练期间的功率、再按报告的时长外推，估计了若干 NLP 模型训练的能耗与排放，采用美国平均 PUE 与电网强度。其最广为人知的数字——用神经架构搜索开发一个 Transformer 约 $284$ 吨 CO$_2$e（$626{,}155$ 磅），相当于五辆美国普通汽车连同燃料在内的整个寿命期排放——被广泛报道。但那指的是充分的架构搜索，而非训练单个模型；按其估计，后者排放要低得多。Patterson 等（2021）认为，该搜索估计因硬件、数据中心与搜索过程等假设，大幅高估了谷歌实际所做搜索的排放；而 Strubell 等更根本的主张——研究方法的代价也应当报告——已被广泛接受。

**Patterson 等（2021）**来自谷歌，依据实际硬件、利用率与数据中心的信息，估计了若干大型模型训练的能耗与排放。其中：T5 约 $86$ MWh、$47$ tCO$_2$e；GPT-3（训练细节由 OpenAI 提供，在微软数据中心进行）约 $1{,}287$ MWh、$552$ tCO$_2$e。他们主张，模型架构（例如稀疏混合专家）、处理器、数据中心与选址的选择合起来，可使排放相对不利的选择降低 $100$–$1{,}000$ 倍。

**Luccioni、Viguier 与 Ligozat（2023）**对 BLOOM——一个 2022 年在法国公共超算上训练的 $1760$ 亿参数开放模型——做了生命周期估计。训练耗电约 $433$ MWh；由于法国电网强度低（约 $0.057\ \text{kg/kWh}$），动态功耗对应约 $25$ tCO$_2$e。加上基础设施的待机功耗、以及对硬件制造隐含排放的估计，总计约 $50$ tCO$_2$e——也就是说设备制造与待机耗电共约占足迹的一半，而随着电网脱碳，这一份额还会增大。

::: warning "训练一个模型的排放相当于五辆汽车"不是普遍事实
那个比较出自2019年一项针对一次架构搜索、按美国平均条件假定的估计，且已有争议。已发表模型的训练排放从几吨到几千吨不等，取决于规模、硬件、选址与核算方法。同样，"AI 的碳足迹可以忽略"则无视了规模化的推理、数据中心用电的增长、隐含排放与水。引用估计时要连同它的系统、日期、边界（只含训练？开发？推理？）与方法（基于位置还是基于市场）一起引用。
:::

## 推理与训练 {#sec-inference}

模型只训练一次，使用却有许多次。对广泛部署的模型，其整个生命周期内推理的能耗可以超过训练。Patterson 等（2022）报告，机器学习占谷歌2019–2021年总能耗的 $10\%$–$15\%$，其中约五分之三是推理、五分之二是训练。Wu 等（2022）报告，Meta 的 AI 基础设施容量在实验、训练与推理之间大致按 $10:20:70$ 分配。

每次查询的能耗更难确定，已发表数字相差一个数量级。被广泛引用的每次聊天机器人查询约 $3$ Wh 的估计（de Vries，2023；国际能源署在2024年引用）建立在2023年初硬件与服务器数量的假设上。其后对更高效推理服务的估计更低：Epoch AI 的分析（2025）估计对前沿聊天模型的一次典型查询约 $0.3$ Wh；谷歌在2025年8月报告，其 Gemini 应用一次文本提示的中位数约 $0.24$ Wh，已含待机容量与数据中心开销。长输出、长上下文、大量生成词元的推理（reasoning）模型、以及图像或视频生成，耗电要多得多。Luccioni、Jernite 与 Strubell（2024）在标准任务上测量了 $88$ 个模型，发现生成类任务的能耗远高于分类或信息抽取，图像生成居首；同一任务上，通用模型比专用模型更耗电。

::: example 推理何时超过训练？ {#ex-breakeven}
以[[#ex-training]]那次 $3{,}400$ MWh 的训练为例：每次 $0.3$ Wh 的查询，多少次才与训练能耗相当？若该模型每天服务 $1$ 亿次查询，累计推理能耗多少天后追平训练能耗？
::: solution
$3.4\times10^9\ \text{Wh}/0.3\ \text{Wh} = 1.13\times10^{10}$ 次查询。按每天 $10^8$ 次，为 $113$ 天。部署一年，推理约用去训练能耗的三倍；若每次查询 $3$ Wh，追平只需 $11$ 天。这个比值取决于部署的规模与推理服务的效率（[[inference/batching-serving]]），这正是每次查询的数字重要的原因。
:::
:::

::: example 单个用户的足迹与总量 {#ex-per-user}
某用户每天发 $20$ 次文本查询、持续一年，每次 $0.3$ Wh，电网强度 $0.4$ kg/kWh。全年能耗与排放是多少？如果把其中十分之一的查询改用一个生成词元数为二十倍（从而一阶近似下能耗为二十倍）的推理模型，数字如何变化？若某个服务有 $5$ 亿这样的用户，又如何？
::: solution
基线：$20\cdot365\cdot0.3 = 2{,}190$ Wh $= 2.19$ kWh/年，排放 $0.88$ kg CO$_2$e——相当于用 $1$ kW 的电水壶烧两个多小时。含推理模型：每天 $18\cdot0.3 + 2\cdot6 = 17.4$ Wh，是原来的三倍：每年 $6.35$ kWh、$2.5$ kg。对 $5\times10^8$ 个用户，基线为每年 $1.1$ TWh，含推理模型的构成为 $3.2$ TWh。就个人总能耗而言，人均数字很小——这正是"个人 AI 使用只是个人足迹一小部分"论点的依据；而总量与一个小国的年用电量相当——这正是"它对电网有影响"论点的依据。两句话都对，回答的是不同的问题。
:::
:::

## 数据中心、水与硬件 {#sec-wider}

**电力需求。**国际能源署《能源与 AI》（*Energy and AI*）报告（2025年4月）估计，2024 年数据中心用电约 $415$ TWh，约占全球用电量的 $1.5\%$；基准情景下到 2030 年约 $945$ TWh，AI 是增长的主要驱动，各情景之间不确定性很大。在美国，劳伦斯伯克利国家实验室的报告（2024年12月）估计 2023 年数据中心占全国用电的 $4.4\%$，2028 年将达 $6.7\%$–$12\%$。局部影响可以比全球占比所显示的更大：数据中心是聚集的，在有些地区其用电占比既大又增得快，牵动电网投资、电价，以及为满足新增负荷动用化石能源发电。多家大型科技公司报告，尽管购买了绿电，2023–24 年总排放仍在上升——例如谷歌的2024年环境报告给出温室气体排放较 2019 年增加 $48\%$，主要归因于数据中心用电与供应链排放。

**水。**数据中心在站内耗水——主要是冷却塔中的蒸发——也在站外耗水：其用电的发电过程要用水（比如火电厂）。

::: definition 水使用效率 {#def-wue}
数据中心的**站内水使用效率**（water usage effectiveness）是每单位 IT 能耗为制冷所消耗的水量，单位 L/kWh。电力的**站外水强度**是每 kWh 发电量在发电过程中消耗的水量，单位 L/kWh。IT 能耗为 $E_{\text{IT}}$ 的一次计算的水足迹近似为 $E_{\text{IT}}\cdot\text{WUE}_{\text{on}} + E_{\text{IT}}\cdot\text{PUE}\cdot\text{WI}_{\text{off}}$。
:::

Li、Yang、Islam 与 Ren（2023）估计，在微软美国数据中心训练 GPT-3 的站内淡水消耗可达约 $700{,}000$ 升；与模型进行约 $10$–$50$ 次回复的一次对话，耗水约在半升级的量级，视其运行在何时何地而定。耗水量随气候与制冷设计差异极大（风冷耗水少但耗电多；蒸发制冷正相反），并在水资源紧张之处影响最大。谷歌2025年公布的每次提示数字中约含 $0.26$ mL 水。

::: example 一份水足迹 {#ex-water}
对[[#ex-training]]那次训练（IT 能耗 $3.10$ GWh，PUE $1.1$），在站内 WUE $0.5$ L/kWh、站外水强度 $3$ L/kWh 下估计其水足迹。并与一座采用风冷（站内 WUE $0.05$ L/kWh）、但 PUE $1.3$ 的设施比较。
::: solution
蒸发冷却：$3.10\times10^6\cdot0.5 + 3.10\times10^6\cdot1.1\cdot3 = 1.55\times10^6 + 1.02\times10^7 = 1.18\times10^7$ L，约 $1{,}200$ 万升。风冷：$3.10\times10^6\cdot0.05 + 3.10\times10^6\cdot1.3\cdot3 = 1.55\times10^5 + 1.21\times10^7 = 1.22\times10^7$ L。总水量相近，但风冷设施把大部分搬到了站外（且多耗 $18\%$ 的电）。孰优孰劣取决于所在地当地的水资源压力与电网碳强度——这是水与碳之间实实在在的取舍。
:::
:::

**隐含排放。**制造加速器、服务器与建筑，在任何计算开始之前就已排放温室气体。BLOOM 研究把约 $11$ tCO$_2$e 归给训练所用设备的制造，约占其总排放的五分之一。随着更清洁的电网压低运行排放，隐含排放的占比变大，硬件的使用寿命与利用率就成为重要抓手。材料开采与电子垃圾是另外的环境隐忧（Crawford，2021）。

## 能效及其极限 {#sec-efficiency}

若干趋势正在降低单位有效功的能耗。十年来，加速器能效（每焦耳 FLOPs）大致每代提高一个数量级；更低精度的运算（[[scaling/mixed-precision]]、[[inference/quantisation]]）成倍提高吞吐量。算法效率——更好的架构、数据与训练配方——降低了达到给定能力所需的计算量。由大模型蒸馏出的小模型（[[post-training/distillation]]）、每个词元只激活一部分参数的混合专家（[[transformers/mixture-of-experts]]），以及批处理、投机解码等推理服务优化，降低了每个词元的推理成本。

能效提高是否减少总消耗则另有争论。**回弹效应**（rebound effect，或称杰文斯悖论，源自 Jevons 在 1865 年的观察：更高效的蒸汽机反而增加了煤炭总消耗）认为，更便宜的计算会刺激需求——更多用户、更大模型、更长输出、长篇思考的推理模型——多到足以推高总用量。另一方则主张：任何服务的需求终将饱和；此前能效提升已使数据中心能耗长期大体持平（Masanet 等，2020 估计，2010–2018 年全球数据中心能耗仅增长约 $6\%$，而计算负载增长了数倍）；且把 AI 用于能源系统、材料与物流所减少的排放可能远超 AI 自身新增——这一主张原则上可信但难以核实，国际能源署亦指出这一点。两种效应都真实存在；其净结果是一个经验问题，截至 2026 年尚无定论。

**透明度。**开发者对训练能耗与排放的披露并不一致，推理能耗则几乎不披露；方法（基于位置还是基于市场、计入了哪些开销）也各不相同。改进的提议包括：在模型文档中标准化地报告能耗与硬件；对模型在标准任务上给出能效评级（如 2025 年的 AI Energy Score 倡议）；以及法律要求：欧盟《人工智能法》要求通用人工智能模型提供者记录其模型已知或估计的能耗（[[llm-society/governance-regulation]]）。

::: quiz
两个团队分别报告在相同硬件上训练相同规模模型的排放。A 团队报 $2{,}000$ tCO$_2$e；B 团队报 $0$。哪种解释最可能？
- [ ] B 团队的模型没有用电。
- [x] A 团队在高化石能源电网采用基于位置的核算，B 团队采用基于市场的核算、配有覆盖用电的绿电合同。
- [ ] B 团队只训练了一步。
- [ ] 排放与电网无关。
::: solution
同样的用电量，基于位置的核算可以报出大数字，基于市场的核算配合覆盖用电的合同则可报零。两者都是标准方法；报告应当写明所用方法，最好同时给出以 MWh 计的能量，让读者自行套用强度。
:::
:::

::: history
对计算能耗的关注早于 AI：Koomey 及其合作者自2000年代起记录数据中心的用电，The Green Grid 联盟于2007年定义了 PUE。在机器学习领域，Strubell、Ganesh 与 McCallum（2019）把能耗列入 NLP 研究的议程；Schwartz 等（2020）呼吁在准确率之外同时报告能效的"绿色 AI"（Green AI）；Henderson 等（2020）与 Lacoste 等（2019）发布了测量与估计排放的工具；Bender 等（2021）把环境成本列为模型不断增大的风险之一。Patterson 等（2021；2022）根据运行数据估计大型模型的排放，并主张排放将会见顶回落；Luccioni、Viguier 与 Ligozat（2023）对 BLOOM 做了生命周期评估；Li 等（2023）唤起对水的关注。2024 年起，AI 数据中心的扩张及其用电成为能源政策中的突出议题，国际能源署于2025年发布了其首份能源与 AI 专题报告。
:::

::: summary
- 训练能耗 $\approx C/(u\,\eta)\cdot\text{PUE}$，其中 $C\approx6ND$ FLOPs、利用率 $u$（典型 $0.3$–$0.5$）、硬件能效 $\eta$（峰值 FLOP/焦耳）、数据中心开销 $\text{PUE}$（$1.1$–$1.6$）。
- 排放 $=$ 能量 $\times$ 电网碳强度，随地点相差二十多倍；基于位置与基于市场的核算可以完全不同。
- 最终一次训练的估计是下界：实验、失败任务与推理还要另加。$70$B 模型、$15$T 词元需几 GWh，即视电网而定约 $100$–$2{,}000$ tCO$_2$e。
- 已发表的估计（Strubell 等，2019；Patterson 等，2021；Luccioni 等，2023）在边界与方法上各不相同；"五辆汽车"指的是架构搜索，且已有争议。
- 对广泛使用的模型，推理可在数月内超过训练；文本单次查询的能耗估计从约 $0.2$ 到 $3$ Wh 不等，取决于系统与时间。
- 水（站内制冷与站外发电）与隐含排放很重要，在局部地区和电网脱碳之后尤其如此。
- 能效提升很快；总消耗是否下降取决于需求的回弹，尚无定论；要弄清楚，需要更充分的披露。
:::

## 习题

::: exercise 训练 FLOPs {level=1 check="1.2e24"}
按 $C = 6ND$，训练一个 $100$ 亿参数的稠密模型、$20$ 万亿词元，需要多少 FLOPs？
::: solution
$6\cdot10^{10}\cdot2\times10^{13} = 1.2\times10^{24}$ FLOPs。
:::
:::

::: exercise 加速器·小时 {level=1 check="9.26e5"}
用峰值 $10^{15}$ FLOP/s、利用率 $36\%$ 的加速器完成 $1.2\times10^{24}$ FLOPs，需要多少加速器·小时？保留三位有效数字。
::: solution
$1.2\times10^{24}/(0.36\times10^{15}) = 3.33\times10^9$ s $= 3.33\times10^9/3600 = 9.26\times10^5$ 小时。
:::
:::

::: exercise 能量与排放 {level=1 check="200"}
某次训练在强度 $0.4$ kg CO$_2$e/kWh 的电网上用去 $500$ MWh 全设施能量。其基于位置的排放是多少吨？
::: solution
$5\times10^5\ \text{kWh}\cdot0.4 = 2\times10^5$ kg $= 200$ t。
:::
:::

::: exercise PUE 的作用 {level=2 check="27"}
同一电网下，把一次训练从 PUE $1.5$ 的设施移到 PUE $1.1$ 的设施，能耗降低百分之多少？四舍五入到整数。
::: solution
$(1.5 - 1.1)/1.5 = 0.267$，约 $27\%$。
:::
:::

::: exercise 与推理打平 {level=2 check="40"}
某模型训练用去 $1{,}200$ MWh，每天服务 $1000$ 万次查询、每次 $3$ Wh。累计推理能耗多少天后与训练能耗相等？
::: solution
每日推理能耗：$10^7\cdot3\ \text{Wh} = 3\times10^7$ Wh $= 30$ MWh。$1200/30 = 40$ 天。
:::
:::

::: exercise 读模型卡 {level=2}
某模型卡报告："H100-80GB（TDP $700$ W）上 $210$ 万 GPU 小时；估计排放基于位置 $590$ tCO$_2$e；基于市场 $0$"。(a) 这对应 GPU 层面多少能量？(b) 若忽略 PUE，该基于位置的数字隐含什么电网强度？(c) 完整的足迹还缺什么？
::: solution
(a) $2.1\times10^6\ \text{h}\cdot0.7\ \text{kW} = 1.47\times10^6$ kWh $= 1{,}470$ MWh（若 GPU 实际功率低于 TDP，这是上界）。(b) $590{,}000/1.47\times10^6 = 0.40$ kg/kWh。(c) 数据中心开销（PUE）、主机与网络功耗、实验与失败训练、模型整个生命周期内的推理、水、以及硬件的隐含排放。
:::
:::

::: exercise 碳感知调度 {level=2 check="0.25"}
一个 $10$ MWh 的微调任务，可以在 $24$ 小时内以平均电网强度 $0.4$ kg/kWh 匀速运行，也可以安排进日照最强的 $8$ 个小时——其间强度为 $0.1$ kg/kWh——但需三倍功率。假设总能量相同，调度后的排放是原来的多少？
::: solution
原方案：$10{,}000\cdot0.4 = 4{,}000$ kg。调度后：$10{,}000\cdot0.1 = 1{,}000$ kg。比例 $0.25$。实际上，三倍功率意味着这几小时需要三倍硬件，会抬高隐含排放与成本；碳感知调度最适合可延迟、且所用硬件本会空闲的任务。
:::
:::

::: exercise 一份完整的估计 {level=3}
在写明假设的前提下，估计一个每天 $2$ 亿次查询、平均每次输出 $500$ 词元的聊天助手全年的能耗与基于位置的排放。设推理成本为加速器层面每输出词元 $2\times10^{-4}$ Wh（含批处理效率）、主机与网络开销 $30\%$、PUE $1.15$、电网强度 $0.3$ kg/kWh。与[[#ex-training]]的训练比较，并说出你最没把握的假设。
::: solution
加速器层面每次查询：$500\cdot2\times10^{-4} = 0.1$ Wh；含开销 $0.13$ Wh；再含 PUE $0.1495$ Wh。每日：$2\times10^8\cdot0.1495 = 2.99\times10^7$ Wh $= 29.9$ MWh。全年：$10{,}900$ MWh $\approx10.9$ GWh。排放：$1.09\times10^7\ \text{kWh}\cdot0.3 = 3{,}270$ t。这约为每年[[#ex-training]]训练能耗（$3.4$ GWh）的三倍。最没把握的输入是每词元能耗，它取决于模型规模、硬件、批次大小、上下文长度与推理服务容量的利用率，不同系统之间相差一个数量级以上；已发表的每次查询数字（$0.24$–$3$ Wh）区间覆盖了我们的 $0.15$ Wh。
:::
:::

::: exercise 回弹 {level=3}
某服务每次查询的能耗在两年里因效率改进降为原来的 $1/4$，而查询数增长到 $6$ 倍、平均输出长度增长到 $1.5$ 倍（每次查询能耗与输出长度成正比）。(a) 推理总能耗变为原来的多少倍？(b) 若输出长度不变，需求的价格弹性（成本每变动百分之一引起的数量变动百分比，假设恒定）取何值时，效率增益恰好被更多查询抵销？(c) 讨论什么样的证据能区分"回弹"与"需求的独立增长"。
::: solution
(a) 每次查询能耗变为 $1.5/4 = 0.375$；总量变为 $0.375\cdot6 = 2.25$：能效翻两番，推理总能耗反而翻番有余。(b) 每次查询成本降为 $1/4$；要令总能耗不变，查询量须升四倍。设恒定弹性 $\varepsilon$，则 $Q\propto\text{cost}^{-\varepsilon}$，故 $4 = 4^{\varepsilon}$、$\varepsilon = 1$：单位弹性的需求恰好抵销能效提升；更有弹性的需求则会产生反效果。(c) 回弹指需求上升是*因为*成本下降。可用来识别的证据包括并非由需求驱动的价格变化（例如提供方在不同时点的降价，或效率改进先在某些地区上线形成的自然实验）及其对使用量的影响；而源于新能力或新用户采用的需求增长，即使成本不变也会发生。要把两者分开，需要数据，而提供方很少公布。
:::
:::
