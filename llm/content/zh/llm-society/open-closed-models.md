实验室训练完一个语言模型后，就面临一个已成为 AI 政策领域争论最激烈的问题之一的选择：谁能获得访问权，获得的是什么？它可以把模型完全留在内部；可以通过聊天产品或编程接口（API）提供它而不公开权重；也可以发布权重，让任何人下载、运行、研究和修改。它还可以发布训练所用的代码与数据。每一个选择都会对研究、竞争、安全、隐私、成本和权力分配产生影响，而不同开发者的选择差异极大——从只能通过 API 使用的模型，到权重、代码和训练数据全部公开的模型都有。

本章先把术语讲精确，因为“开放”一词所指差别很大：开放权重不是开源，而可下载模型所附的许可从宽松到严格限制不等。接着，我们列出支持与反对发布权重的主要论点——按各自主张者给出的最强形式——以及相关证据。一个简单的决策模型说明为什么发布权重不可逆如此要紧，以及分阶段发布能换来什么。本章以中间选项和政策现状（截至 2026 年）收尾。它不偏袒任何一方：分歧是真实的，既涉及经验上的不确定性，也涉及不同的价值观；合理的立场取决于所讨论模型的能力。

## 可以发布什么 {#sec-components}

一个训练好的模型不是单件产物。一次发布可以包含下列任何内容：

- **权重**：训练得到的参数，配合推理代码就能让任何人按自己的硬件运行模型。
- **推理代码与架构**：足以加载并运行权重。
- **训练代码**：训练模型所用的代码、配置与超参数。
- **训练数据**，或其详细信息：来源、过滤、混合比例（[[pretraining/training-data]]、[[pretraining/data-mixtures]]）。
- **中间检查点**：让研究者能够研究能力在训练过程中如何涌现。
- **文档与评估**：模型卡、安全评估、已知局限。

访问权也可以按不同方式给予，Solaiman（2023）把这些方式排成一条梯度。

::: definition 发布梯度（Solaiman, 2023） {#def-gradient}
生成式模型可以沿着一条访问梯度发布：(1) **完全闭源**（仅内部使用）；(2) **渐进或分阶段**发布（访问随时间放宽）；(3) **托管**访问（产品界面）；(4) **云端或 API** 访问（程序化查询，也可通过提供方做微调）；(5) **可下载**权重；(6) **完全开放**（权重、代码与数据）。沿梯度移动会增强外部人士研究、修改和使用模型的能力，同时削弱开发者监测、限制或撤回访问的能力。
:::

### 开放权重与开源

在软件领域，“开源”有一个由开源促进会（Open Source Initiative，OSI）维护的精确含义：以某种许可分发、授予出于任何目的使用、研究、修改和再分发之自由、并可获得源代码的软件。对模型而言，源代码的对应物并不显然——权重是“二进制”，而数据和训练代码才是“源码”吗？——许多被称作开放的模型只发布权重，而且是在限制用途的许可之下。

::: definition 开放权重模型与开源 AI {#def-open}
**开放权重**模型指训练得到的参数可在某种许可下公开下载的模型。OSI 的**开源 AI 定义**（Open Source AI Definition，版本 1.0，2024 年 10 月）要求：AI 系统必须按授予使用、研究、修改和共享其四项自由的条款提供，且发布须包含 (a) **数据信息**：关于训练数据的足够详细的信息，使有经验的从业者能够构建实质等价的系统；(b) 用于训练和运行该系统的完整**代码**；(c) **参数**（权重），且以 OSI 批准的条款提供。
:::

这一定义受到两面夹击。一些人主张应要求发布训练数据本身，因为“数据信息”无法让人复现或完全审计一个模型；OSI 回应说，大量训练数据依法无法再分发（因为版权或隐私），而且若作此要求，会把医学等领域排除在外。另一些人则主张，要求训练代码与数据信息立下的门槛是多数“开放”模型达不到的。事实上，按此定义，多数流行的开放权重模型都不是开源 AI；只有较少一批发布——例如 EleutherAI 的 Pythia、Allen 人工智能研究所（Allen Institute for AI）的 OLMo 系列模型以及 LLM360 项目——同时发布权重、代码、数据和检查点。

### 许可

许可决定用户对已发布的权重能做什么。大体而言（截至 2026 年）：

- **宽松的开源许可**（Apache 2.0、MIT）允许包括商用在内的任何用途，须署名。若干著名模型家族以这类许可发布——例如 Mistral 的 7B 模型（2023）、阿里巴巴 Qwen 系列的多个尺寸、以及 DeepSeek-R1（MIT，2025 年 1 月）。
- **定制社区许可**允许广泛使用但附加条件：例如 Meta 的 Llama 许可要求月活跃用户超过 $7$ 亿的服务须另行取得 Meta 的许可，规定可接受使用政策，并要求署名。Google 的 Gemma 条款同样附有限制用途的政策。
- **负责任 AI 许可**（RAIL，例如 BLOOM 所用的 BigScience OpenRAIL-M 许可）授予广泛权利，但禁止特定的有害用途，并要求下游许可沿用同样的限制。

使用限制在 OSI 的意义上不是开源，因为开源的定义禁止对领域的歧视。其辩护者认为，这类限制确立了规范，并为对付恶劣的滥用提供了法律追索；批评者则认为，它们对作恶者无从执行，给正当用户造成法律上的不确定性，还让企业得以白占开放的名声而不付出其实质。White 等（2024）的**模型开放度框架**（Model Openness Framework）按发布了哪些组件、各以何种许可发布为发布评级，以取代“开放/闭源”的二元标签，代之以信息量更大的分类。

::: warning “开放”模型并非同等开放，“闭源”模型也并非同等闭源
一个权重可下载、但数据未披露且许可严格的模型，与一个权重、代码、数据和检查点都以 Apache 2.0 发布的模型，都被称作“开放”。API 模型可能允许微调、暴露对数概率并设有研究者访问计划，也可能这些全都没有。“开放对闭源”的争论常常各说各话，因为双方心里想的是梯度上的不同点位。要说清楚发布了什么、以什么条款发布。
:::

## 权重使什么成为可能 {#sec-weights}

拥有权重在三个与这场争论攸关的方面改变了用户能做的事。

**随处运行模型。**模型可以在自己的硬件上运行，不必把数据发给提供方，也不受提供方的监测与使用政策约束。主要约束是内存（[[inference/quantisation]]）。

::: example 运行开放权重模型的硬件 {#ex-memory}
一个 $700$ 亿参数模型的权重，在 $16$ 比特、$8$ 比特和 $4$ 比特精度下各需要多少内存？其中哪些放得进一台有 $80$ GB 内存的加速器，或者两张各有 $24$ GB 的消费级显卡？
::: solution
$70\times10^9$ 个参数 $\times$ $2$、$1$、$0.5$ 字节，得 $140$ GB、$70$ GB 和 $35$ GB。$16$ 比特下模型至少需要两台 $80$ GB 加速器；$8$ 比特下一台放得下（但几乎不给 KV 缓存留余地，[[inference/kv-cache]]）；$4$ 比特下两张 $24$ GB 的消费级显卡放得下，或一台统一内存足够大的工作站也行。量化会一定程度降低质量，但它意味着这种规模的模型可以由个人和小组织在任何提供方之外运行。
:::
:::

::: example 自建部署还是 API？ {#ex-hosting}
一家医院想每月为 $30$ 亿词元的临床笔记做摘要，而在没有数据处理协议的情况下不得把它们发给外部提供方。方案 A：用 API，按（假设的）每百万词元 US\$0.60 计费。方案 B：在两台租来的加速器上运行一个开放权重模型，每台每加速器小时 US\$2.50，全天候运行，在所用批大小下每台以每秒 $1{,}500$ 词元的速度服务。方案 B 的容量够吗？按月成本两者相比如何（按 30 天计）？
::: solution
容量：$2\cdot1500\cdot3600\cdot24\cdot30 = 7.78\times10^9$ 词元/月，足够 $3\times10^9$。成本 A：$3000\cdot0.60 = $ US\$1,800。成本 B：$2\cdot2.50\cdot720 = $ US\$3,600，另加工程与维护。在这一体量下 API 更便宜；B 的成本约为其两倍，但把数据留在内部、模型固定不变。若每月 $80$ 亿词元，API 要花 US\$4,800，而两台加速器刚好满负荷。真实的决策取决于价格（变化很快）、利用率、质量差异与法律要求；要点是开放权重改变了选项集合，而不是某一方永远更便宜。
:::
:::

**修改模型。**权重可以被微调——把模型专门化到某种语言或领域、去掉拒答、或增加能力。参数高效方法让这件事很便宜。

::: example 修改模型的成本 {#ex-lora}
一个秩为 $r = 16$ 的低秩适配（LoRA）适配器，加在某个 $700$ 亿参数模型 $80$ 层中每一层的四个注意力投影矩阵（每个 $8192\times8192$）上（[[post-training/parameter-efficient-tuning]]）。它有多少可训练参数？占模型的多大比例？
::: solution
每个矩阵添上 $B\in\R^{8192\times16}$ 与 $A\in\R^{16\times8192}$：$2\cdot8192\cdot16 = 262{,}144$ 个参数。$80$ 层各四个矩阵：$4\cdot80\cdot262{,}144 = 8.39\times10^7$，约 $8{,}400$ 万，即 $700$ 亿的 $0.12\%$。在几千个样本上微调这么多个参数，在配置不高的硬件上只需几个小时。Lermen、Rogers-Smith 与 Ladish（2023）报告说，用不到 US\$200 的算力做 LoRA 微调，就去掉了 Llama 2-Chat 70B 的大部分安全拒答。
:::
:::

安全训练能从开放权重上被廉价地剥掉——这是整场争论的中心事实。这并非开放权重独有：Qi 等（2023）表明，通过提供方的微调 API 在少至 $10$ 个有害样本（花费不到 US\$0.20）上微调 GPT-3.5 Turbo，也能大体去除其安全行为——甚至良性的微调也会使其退化。区别在于：API 提供方可以筛查微调数据、监测使用并撤销访问，而下载后的模型无法召回。

**研究模型。**有了权重，研究者就能检视激活、做可解释性分析（[[interpretability]]）、度量对训练数据的记忆、在白盒攻击下测试鲁棒性，并复现或变换训练。已发表的语言模型研究——关于可解释性、记忆（[[llm-society/privacy-memorisation]]）、训练动态与评估——大量依赖开放权重模型，尤其是那些连同数据与检查点一起完全开放的模型。

## 诸种论点 {#sec-arguments}

Kapoor、Bommasani 等（2024）提出，开放基础模型的风险应按其**边际**效应来评判，这一框架现在被双方广泛采用。

::: definition 边际风险 {#def-marginal}
发布模型权重的**边际风险**，指某种滥用的期望危害相对于不发布权重之基线的增量，其中要考虑 (a) 威胁行为者利用现有工具——其他模型、搜索引擎、已发表的文献——本已能够做什么，以及 (b) 已经存在或将会调整的防御。只有当模型相对该基线提供了**提升（uplift）**，且造成该危害的瓶颈恰是模型所能供给的东西时，发布对该危害才构成高边际风险。
:::

### 主张发布权重

- **研究与监督。**独立研究者只有拿到模型才能研究、审计和复现模型。安全研究本身——可解释性、鲁棒性、评估——需要从权重中受益，而许多关于风险的发现（包括安全微调多么容易被撤销）正来自开放模型。数据与训练的透明度也支撑问责。
- **开放带来安全。**在软件领域，公开代码通常被认为能改善安全，因为它让更多人能够发现并修补缺陷；主张者认为模型亦然，并说把权重封闭会制造虚假的安全感，因为闭源模型可以经由 API 被越狱（[[safety-alignment/robustness-jailbreaks]]），其权重也可能被盗。
- **竞争与集中。**如果最强模型只能从少数几家大公司获得，这些公司就获得了对一种通用技术之访问权的支配——对价格、对允许的用途、对模型中嵌入的价值都是如此。开放权重让初创公司、大学、政府和非营利组织不必依赖它们也能搞建设。
- **隐私、定制与主权。**组织可以在自己的基础设施上运行模型，不必把敏感数据交给第三方；可以把模型适配到自己的语言和领域；并可在提供方变更条款或撤下模型之后继续使用。语言得不到充分服务的国家与社区可以自己微调模型。
- **对多数危害边际风险低。**就垃圾信息、虚假信息、骚扰等诸多关切而言，能力强的开放模型早已存在，瓶颈在于分发而非内容（见 [[llm-society/misinformation]]），因此再发布一个几乎没有边际风险。至于更严重的危害，主张者说尚无有意义提升的证据，应对应针对瓶颈（获取材料、实验室技能），而不是针对信息。

### 主张不发布权重（或分阶段发布）

- **不可逆性。**权重一旦发布就无法收回；若日后发现危险能力——通过新的引出技术、微调或与工具结合——将束手无策。API 则可以打补丁、收紧或关停。
- **保障措施无从执行。**使用政策、拒答训练、滥用监测与客户身份核查，全都依赖开发者控制访问。有了开放权重，安全训练可以被廉价去除（[[#ex-lora]]），恶意使用对开发者完全不可见。
- **严重滥用。**就最强模型而言，令人担忧的是它们可能给图谋大规模伤人者——例如在生物学或网络攻击方面——带来实质性的提升，而其下行后果是灾难性的，一次滥用就可能抵过众多收益。2024–25 年的证据是混合的：一项 RAND 红队研究（Mouton、Lucas 与 Guest，2024）发现，借助与不借助所测试的语言模型拟出的生物攻击计划，在可行性上没有统计显著差异；而开发者对后续模型自己的评估则报告相关知识与排障任务上的表现不断提高，某些模型还配有预防性保障。持这一观点者主张，决定应取决于对每个模型的能力评估，而不是某条一般原则（[[evaluation/capability-evaluations]]、[[safety-alignment/safety-frameworks]]）。
- **前沿的安全。**若最强模型的权重被发布，其极其昂贵的训练成果也就一并交给了竞争对手和国家；有人认为这对国家安全和投资安全的激励都有影响。Nevo 等（2024，RAND）分析了防止权重被不同能力层次的行动者窃取所需的安全措施——这一论点只适用于未发布的权重。
- **支撑开发。**通过 API 的商业访问为训练后续模型和安全研究提供资金；有人视之为闭源发布的正当理由，批评者则指出这也是商业利益，可能左右关于风险的论调。

### 动机混杂与证据

双方的论辩都出自利害关系方：发布开放权重的公司可能因把对手的产品商品化、吸引开发者而得利；保持权重封闭的公司则是在保护自己的收入；而任一立场的倡导者也可能本于原则持该立场。关于关键经验问题的证据——开放模型对严重危害的提升有多大、开放模型落后闭源前沿有多远、开放发布在多大程度上同时加速有益与有害的应用——既有限又在变化。Epoch AI 的分析（2024）估计，最好的开放权重模型在基准表现和训练算力上落后最好的闭源模型大约一年，起伏不小，且在个别时段有差距缩小的迹象（截至 2024–25 年）。美国国家电信和信息管理局（NTIA）关于权重广泛可得的双用途基础模型的报告（2024 年 7 月）认定，当时的证据并不支持限制开放权重，并建议政府建设监测风险、并在风险上升时采取行动的能力。

## 不确定之下的发布决策 {#sec-decision}

一个简单的模型使不可逆性论点变得精确，并展示了它的限度。设开发者尚不知道一个模型是否具有危险能力，并认为其概率为 $p$。发布权重每期产生收益 $B$，共 $T$ 期；若模型危险，发布还将带来每期期望危害 $D$，且无法阻止。或者，开发者可以先提供一期的 API 访问，获取收益的 $\beta < 1$ 这一部分，同时通过监测防止危害，并在期末知道模型是否危险；若模型安全就发布权重，否则继续只用 API（收益 $\beta B$，无危害）。

::: proposition 分阶段发布何时更优 {#prop-staged}
在此模型中，立即开放与分阶段的期望值分别为

$$
V_{\text{open}} = TB - pTD, \qquad V_{\text{staged}} = \beta B + (T - 1)\bigl[(1 - p)B + p\beta B\bigr].
$$

若 $TD > (T - 1)(1 - \beta)B$，则分阶段发布更优当且仅当

$$
p > p^{*} = \frac{(1 - \beta)B}{TD - (T - 1)(1 - \beta)B}.
$$ {#eq-pstar}
:::

::: proof
相减，

$$
\begin{aligned}
V_{\text{staged}} - V_{\text{open}} &= \beta B + (T - 1)B - (T - 1)pB(1 - \beta) - TB + pTD \\
&= -(1 - \beta)B + p\bigl[TD - (T - 1)(1 - \beta)B\bigr].
\end{aligned}
$$

由假设方括号为正，故当且仅当 $p$ 超过 [[#eq-pstar]] 时差为正。
:::

分阶段的成本是第一期中放弃的收益 $(1-\beta)B$；它的价值在于避免不可逆危害的期权。取 $B = 1$、$D = 3$、$T = 10$、$\beta = 0.6$，$p^* = 0.4/(30 - 3.6) = 0.015$：只要模型危险的概率超过 $1.5\%$，分阶段发布就是划算的。

```python
def open_now(p, B, D, T):
    """Release weights at once: benefit B per period for T periods; if the model
    turns out dangerous (probability p), a harm D per period that cannot be recalled."""
    return T * B - p * T * D

def staged(p, B, D, T, beta):
    """API only for one period (a share beta of the benefit, no harm, and the
    danger is learned); then open the weights only if the model is safe."""
    return beta * B + (T - 1) * ((1 - p) * B + p * beta * B)

B, D, T, beta = 1.0, 3.0, 10, 0.6
print(" p     open now   staged   better")
for p in (0.0, 0.02, 0.05, 0.1, 0.2, 0.4):
    o, s = open_now(p, B, D, T), staged(p, B, D, T, beta)
    print(f"{p:4.2f}  {o:8.2f}  {s:8.2f}   {'staged' if s > o else 'open'}")
p_star = (1 - beta) / ((T - 1) * beta + T * D - (T - 1))   # 两者相等之处
print(f"break-even p = {p_star:.4f}")
```

:::

这个模型是一幅漫画，而它的假设恰是真正分歧所在。它假设：一期的 API 访问就能揭示模型是否危险（能力评估并不完美，能力也可能在日后被引出）；API 能阻止一切危害（API 会被越狱，权重会被盗）；$\beta$ 是已知的（开放权重的许多价值——研究、隐私、竞争——无法经由 API 兑现，因此对某些用户 $\beta$ 可能很小）；它还忽略了其他开发者反正可能发布类似的模型，而这会降低边际危害 $D$。开放发布的主张者倾向于相信 $p$ 和边际 $D$ 很小、且重要用途的 $\beta$ 很低；就最强模型而言，闭源发布的主张者则认为 $D$ 可能是灾难性的，而评估只能缓慢地压低 $p$。

::: example 带厚尾的不确定危害 {#ex-tail}
在上面的模型中取 $B = 1$、$T = 10$、$\beta = 0.6$，设危险时的危害以 $0.99$ 的概率为 $D = 1$，以 $0.01$ 的概率为 $D = 1000$，于是 $\E D = 10.99$。用 $\E D$ 计算 $p^*$，并与 $D = 1$ 确定时比较。
::: solution
$D = 1$ 时：$p^* = 0.4/(10 - 3.6) = 0.0625$。$\E D = 10.99$ 时：$p^* = 0.4/(109.9 - 3.6) = 0.00376$。灾难性危害的很小概率把阈值压低到约十七分之一。期望值推理依赖于本身极不确定的尾部估计，这正是为什么关于最强模型是否开放发布的争论，常常落在如何对低概率、高严重性的结果进行推理上，而不是落在中心估计上。
:::
:::

## 中间选项与政策 {#sec-intermediate}

这个选择并非二元。介于闭源与完全开放之间的选项包括：

- **分阶段发布**：OpenAI 2019 年对 GPT-2 的做法：在九个月里逐步发布越来越大的版本，同时研究滥用，最终发布了完整模型。
- **结构化访问**（Shevlane, 2022）：受控的接口，让经审核的研究者获得更深的访问——微调、内部激活、对数概率——而不发布权重。
- **门控下载**：同意条款并表明身份后才能获得权重，一些模型托管平台即是如此。
- **开放较小模型**同时把最强模型留在手里——数个开发者采取了这一策略。
- **能力阈值**：开发者公布的前沿安全框架承诺在发布前进行评估，并在达到规定的能力阈值时采取保障措施——可以包括不发布权重。

政策大多避免了对开放权重的直接限制（截至 2026 年）。欧盟《人工智能法》豁免以自由开源许可发布的通用 AI 模型提供者的部分文档义务，但版权政策与训练内容摘要不在豁免之列，模型被认定构成系统性风险时也不豁免（[[llm-society/governance-regulation]]）；该法对“自由与开源”的定义排除了以某些方式营利的模型。在美国，NTIA 的 2024 年报告建议监测而非限制，此后的联邦政策声明（2025 年）表达了对开放模型的支持。中国开发者在 2024–25 年发布了多个领先的开放权重模型。数个法域曾讨论对最强模型要求许可或发布前审查的提案，那将影响开放发布。

::: quiz
一位开发者主张：“我们的模型权重应当发布，因为已有能力相近的模型是开放的。”这一论证使用了哪种框架？其主要局限是什么？
- [ ] 它使用了发布梯度；其局限在于 API 更开放。
- [x] 它论证边际风险低；其局限在于每一次发布仍可能增加能力、微调选项或触达范围，而且这一论证反复使用，可以为一步一步地发布越来越强的模型辩护。
- [ ] 它表明该模型在 OSI 定义下属于开源。
- [ ] 它证明了该模型没有危险能力。
::: solution
“类似的模型已经存在”是一个边际风险论证（相对基线的提升很小）。它常常正确而重要，但边际风险推理还必须计入能力的逐次增长和许多小步骤的累积效应；它对许可未置一词，也无言及模型在绝对意义上是否危险。
:::
:::

::: history
开放发布长期以来是机器学习研究的常态：模型、代码与基准随论文发表已沿用多年，早期的预训练语言模型如 BERT（2018）都是开放发布的。OpenAI 对 GPT-2（2019）以滥用担忧为由的分阶段发布开启了现代争论；GPT-3（2020）只通过 API 提供。EleutherAI 发布 GPT-J 与 GPT-NeoX（2021–22）和 Pythia 套件（2023），为研究者提供开放的替代选择；BigScience 以负责任 AI 许可发布 BLOOM（2022）；Meta 的 LLaMA 权重（2023 年 2 月）发给研究者后很快泄露，而 Llama 2（2023 年 7 月）以社区许可发布、允许商用，此后众多开发者发布了一批开放权重模型家族。Solaiman（2023）描述了发布梯度，Shevlane（2022）提出结构化访问，Kapoor、Bommasani 等（2024）提出边际风险框架。OSI 于 2024 年 10 月发布其开源 AI 定义 1.0，NTIA 于 2024 年 7 月发布关于广泛可得模型权重的报告。
:::

::: summary
- 一次发布可以包含权重、代码、数据信息、检查点与文档；访问沿一条梯度从闭源延伸到完全开放。
- 开放权重不是开源：OSI 的 2024 年定义还要求训练代码与足够详细的数据信息，且以授予四项自由的条款提供；许可从宽松到限制用途不等。
- 权重让任何人可以私下运行模型（$70$B 模型在 $4$ 比特下只占 $35$ GB）、廉价修改模型（约 $0.1\%$ 参数的 LoRA 适配器就能去掉安全训练）、并研究模型——这是大量研究的基础。
- 发布之利：研究与监督、开放带来安全、竞争与减少集中、隐私与主权，以及对多数危害边际风险低。
- 发布之弊（或主张分阶段）：不可逆性、无法执行的保障、最强模型对严重滥用的潜在提升、前沿的安全、支撑开发；关于提升的证据混合且仍在变化。
- 一个简单的期权模型表明：当危险概率超过 $p^*$ 时，分阶段发布值得其放弃的收益；这一阈值对尾部危害、以及 API 能交付多大比例的收益都极为敏感。
- 中间选项包括分阶段发布、结构化访问、门控下载与能力阈值；政策大多选择监测而非限制（截至 2026 年）。
:::

## 习题

::: exercise 低精度下的显存 {level=1 check="4"}
一个 $80$ 亿参数模型的权重，按每参数 $4$ 比特需要多少吉字节（忽略开销）？
::: solution
$8\times10^9\cdot0.5$ 字节 $= 4\times10^9$ 字节 $= 4$ GB。
:::

::: exercise LoRA 参数 {level=1 check="4194304"}
一个秩为 $8$ 的 LoRA 适配器加在 $32$ 层上，每层有 $2$ 个 $4096\times4096$ 的被适配矩阵。它增加多少可训练参数？
::: solution
每个矩阵 $2\cdot4096\cdot8 = 65{,}536$；共有 $32\cdot2 = 64$ 个被适配矩阵，故总计 $64\cdot65{,}536 = 4{,}194{,}304$ 个参数。
:::
:::

::: exercise 为发布方式归类 {level=1}
把下列各情形放到[[#def-gradient]]的发布梯度上，并判断其是否满足 OSI 开源 AI 定义：(a) 权重可下载，但许可禁止超过一定规模的公司使用，且没有训练代码；(b) 权重、训练代码、数据来源与过滤的完整说明，以 Apache 2.0 发布；(c) 一个没有 API 的聊天产品。
::: solution
(a) 可下载级；不是 OSI 开源（有使用限制，没有训练代码或数据信息）。(b) 可下载/完全开放级；只要数据信息足以让有经验的从业者构建实质等价的系统，就满足定义。(c) 托管级；闭源。
:::
:::

::: exercise 盈亏平衡概率 {level=2 check="0.0625"}
在[[#prop-staged]]中取 $B = 1$、$D = 1$、$T = 10$、$\beta = 0.6$。计算 $p^*$。
::: solution
$p^* = 0.4/(10 - 9\cdot0.4) = 0.4/6.4 = 0.0625$。
:::
:::

::: exercise 当 API 交付很少收益时 {level=2 check="0.035"}
设 $B = 1$、$D = 3$、$T = 10$，并设 API 只能交付收益的 $\beta = 0.2$（因为主要用途需要本地部署）。把 $p^*$ 计算到小数点后三位，并与 $\beta = 0.6$ 的情形比较。
::: solution
$p^* = 0.8/(30 - 9\cdot0.8) = 0.8/22.8 = 0.035$，比 $\beta = 0.6$ 时得到的 $0.015$ 大一倍有余。API 能交付的收益越少，分阶段发布就越昂贵，能够正当化它的危险概率就必须越高。
:::
:::

::: exercise 实践中的边际风险 {level=2}
就下列每种危害，讨论发布一个比现有最佳开放模型略强的模型之权重的边际风险：(a) 生成垃圾邮件；(b) 制作未经同意的私密影像（对图像模型而言）；(c) 协助新手实施一场精密的网络攻击。分别指出每种情形的瓶颈。
::: solution
(a) 边际风险低：能生成垃圾的模型早已存在；瓶颈在于绕过垃圾邮件过滤器的投递。(b) 对图像模型而言可观：不设防的开放模型已被广泛用于生成此类影像，托管服务上的保障是主要防线；瓶颈是获得一个不设防的生成器，而开放权重恰好供给（Kapoor 等把这列为开放发布有明确边际风险证据的危害）。(c) 不确定，取决于能力：瓶颈是操作技能与获得目标的机会；一个略好的模型是否带来实质提升，取决于对该模型的评估，而且防守方也从同一能力中获益。细致的回答应在每种情形中区分证据与猜测。
:::
:::

::: exercise 厚尾 {level=3}
在[[#ex-tail]]中，设灾难性结果的概率本身也不确定：开发者认为它以 $0.5$ 的概率为 $0.01$，以 $0.5$ 的概率为 $0.0001$。计算 $\E D$ 与 $p^*$。然后讨论用这样的估计以期望值决定发布问题的两条反对意见。
::: solution
灾难性结果的混合概率为 $0.5\cdot0.01 + 0.5\cdot0.0001 = 0.00505$，故 $\E D = 0.99495\cdot1 + 0.00505\cdot1000 = 6.04$。于是 $p^* = 0.4/(60.4 - 3.6) = 0.0070$。反对意见：(1) 输入是主观的、实际上无法检验，结论可以随尾部概率的选择而被操纵——这正是一些人偏爱由评估检验的明确能力阈值的原因；(2) 期望值把灾难的很小概率与确定的小危害视为等价，而许多决策者对不可逆的灾难是风险规避的（由此催生预防性进路）；另一些人则主张，对推测性风险采取预防会放弃巨大而确定的收益，本身也是一种有代价的选择。两者既是技术问题，同样是价值判断。
:::
:::

::: exercise 一条发布政策 {level=3}
为一家有意在合适场合开放发布权重的假想开发者起草一段话的发布政策。写明什么触发不发布的决定、开展哪些评估、权重之外同时发布什么、以及该政策如何回应双方论点。
::: solution
好的回答应当：对低于既定能力阈值的模型，默认承诺以宽松许可发布权重、代码与数据信息；在具体风险领域定义阈值（例如在经专家验证的生物与网络任务上评估出的提升），由内部与外部评估者在发布前评估，包括在去除保障措施的微调之后评估（因为发布后必会发生这样的事）；声明高于阈值时改用分阶段或结构化访问，公布评估结果与理由，并随证据与防御的变化重新决策；每次发布都随附模型卡、评估数据与已知局限；并为研究者对未发布模型提供结构化访问。它以开放为默认，回应了开放一方；又把不可逆性与微调置于评估的中心，回应了闭源一方。合理的政策在阈值设在何处、以及给竞争与研究访问多大权重上互不相同。
:::
:::
