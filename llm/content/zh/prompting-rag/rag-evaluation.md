检索增强系统有许多活动的部件——分块、嵌入、建索引、检索、重排序、构造提示、生成——改动其中任何一个，都可能以寥寥几个示例看不出来的方式让回答变好或变坏。新的嵌入模型可能对大多数问题检回更好的段落，却丢掉某个常见查询真正需要的那一段；新的提示可能让回答更流畅、却更不忠实。没有测量，RAG 系统就只能靠轶闻来调参。

本章来建立这些测量。先从检索器讲起——可以用信息检索的经典指标来评测它：$k$ 处召回率与精确率、平均倒数排名、归一化折损累计增益——既手算也用代码计算；然后评测回答：有短参考答案时用精确匹配与词元重合，没有时用忠实度与相关性。后者如今大量交由充当评审的语言模型完成，因此本章也讨论它们的偏差，以及如何对照人工标签验证它们，最后以区分真实改进与噪声所需的统计收尾。评测搜索的一般理论见计算机科学图谱（[评测搜索](/learn/cs/lesson.php?c=information-retrieval&l=evaluation)）；本章专注于语言模型检索所特有的部分。

## 分别评测各个部件 {#sec-principle}

第一条法则是结构性的。回答出错，可能因为正确的段落没有被检回，可能因为检回了但排名太低没能进入提示，也可能因为生成器忽视或误读了它。这些失败需要不同的修复，所以要分别测量。

::: definition 部件评测与端到端评测 {#def-levels}
对一个在一组查询上评测的 RAG 系统，**检索评测**把每个查询返回的有序块与相关性判定相对照；**生成评测**在给定块的前提下评估每个回答——它是否受这些块支持、是否切题；**端到端评测**则不问回答如何产生，直接把最终回答与参考答案或用户需求相比较。
:::

因此，评测集对每个查询需要以下几样中的若干项：**相关块**（或文档），可能时带分级相关性；**参考答案**；以及评测时记录下来的**实际传给生成器的上下文**。这样建起来的集合称为**测试集**（test collections）。公开的那些——Natural Questions（Kwiatkowski 等人，2019）、零样本检索基准 BEIR（Thakur 等人，2021）、包含出处的 KILT（Petroni 等人，2021）知识密集型任务——适合用来比较方法；但决定一次部署的评测要从系统自己的用户与文档构建：几百条真实查询、认真判定，往往胜过任何排行榜。

相关性判定昂贵，没有人能为每个查询判定集合中的每个文档。TREC 评测让**合并标注**（pooling）成为标准做法：只判定若干系统前列结果的并集，其余未判定的一律视为不相关。于是这个池偏向于构成它的系统：一个找到了无人判定的相关文档的新系统会被惩罚；更换检索器时，也要把新系统那些未判定的前列结果补上判定。

## 检索指标 {#sec-retrieval-metrics}

设某查询的相关块集合为 $\mathrm{Rel}$，$\lvert\mathrm{Rel}\rvert = R$，检索器返回一个有序列表 $d_1, d_2, \dots$。

::: definition 召回率、精确率与倒数排名 {#def-recall}
在截断点 $k$ 处，

$$
\operatorname{recall@}k = \frac{\lvert\{d_1, \dots, d_k\}\cap\mathrm{Rel}\rvert}{R}, \qquad \operatorname{precision@}k = \frac{\lvert\{d_1, \dots, d_k\}\cap\mathrm{Rel}\rvert}{k}.
$$

**命中率**@$k$ 在至少有一个相关块位于前 $k$ 时为 $1$，否则为 $0$。**倒数排名**为 $1/r$，其中 $r$ 是第一个相关块的排名（若没有则为 $0$）；**平均倒数排名**（MRR）是它在查询上的平均值。每个指标都对评测集的查询取平均。
:::

对 RAG 而言，最重要的单一检索指标是**在传给生成器的块数处取 recall@$k$**：前 $k$ 名之外的相关块永远到不了模型那里。precision@$k$ 也重要，因为无关块会分散生成器的注意力（[[prompting-rag/prompt-design#sec-position]]）。MRR 奖励把*某个*相关结果放在第一位，适合答案唯一的问题。

::: example 单个查询的指标 {#ex-recall}
某查询有三个相关块。检索器前五名依次为：不相关、相关、不相关、相关、不相关，第三个相关块排在第 $9$ 位。计算 recall@5、precision@5、命中率@1 和倒数排名。若另外两个查询的第一个相关块分别排在 $1$ 和 $4$，三个查询的 MRR 是多少？
::: solution
前五名中有两个相关块：recall@5 $= 2/3 = 0.667$，precision@5 $= 2/5 = 0.4$。第一名不相关，故命中率@1 $= 0$。第一个相关块排第 $2$：倒数排名 $1/2$。MRR $= (1/2 + 1 + 1/4)/3 = 0.583$。若生成器只收到五个块，这个查询有三分之一的相关材料到不了它那里。
:::
:::

召回率与精确率把前 $k$ 名当作集合。**折损累计增益**（discounted cumulative gain）则利用顺序与分级相关性：相关性高的块价值更大，排名越低的块价值越小（Järvelin 与 Kekäläinen，2002）。

::: definition 归一化折损累计增益 {#def-ndcg}
设 $g_i\ge0$ 为排名第 $i$ 的块的增益——常见取法是对分级相关性 $\mathrm{rel}_i\in\{0, 1, 2, 3\}$ 取 $g_i = 2^{\mathrm{rel}_i} - 1$，或取 $g_i = \mathrm{rel}_i$。则

$$
\operatorname{DCG@}k = \sum_{i=1}^{k}\frac{g_i}{\log_2(i + 1)}, \qquad \operatorname{nDCG@}k = \frac{\operatorname{DCG@}k}{\operatorname{IDCG@}k},
$$ {#eq-ndcg}

其中 $\operatorname{IDCG@}k$ 是**理想**排序的 DCG，即把所有判定过的块按增益从大到小排列。
:::

::: proposition nDCG 落在 $[0, 1]$ 内 {#prop-ndcg}
在固定增益多重集的所有排列中，按增益从大到小排序使 DCG@$k$ 最大。因此 $0\le\operatorname{nDCG@}k\le1$，且当且仅当前 $k$ 名的增益逐位与理想排序一样大时，才取到上界 $1$。
:::

::: proof
折减因子 $w_i = 1/\log_2(i + 1)$ 关于 $i$ 严格递减。若某个排序在 $i < j$ 处有 $g_i < g_j$，交换两者使 DCG 改变 $(w_i - w_j)(g_j - g_i) > 0$，即增大。从任一排序出发，反复交换这样的逆序对即可到达有序排列（每次交换都减少逆序对的数目），途中 DCG 只增不减；故有序排列是最大值。理想排序对所有判定过的块排序，包括未被检回的块，所以它的前 $k$ 名增益逐位支配任何检回列表的增益，$\operatorname{DCG@}k\le\operatorname{IDCG@}k$。所有项都非负，故 $\operatorname{nDCG@}k\ge0$。
:::

::: example 手算 nDCG {#ex-ndcg}
某查询前五名的分级相关性为 $2, 0, 3, 1, 0$，其余块均不相关。以增益 $2^{\mathrm{rel}} - 1$ 计算 nDCG@5。
::: solution
增益为 $3, 0, 7, 1, 0$，折减因子为 $1, 0.631, 0.5, 0.431, 0.387$。DCG $= 3 + 0 + 3.5 + 0.431 + 0 = 6.931$。理想的相关性顺序是 $3, 2, 1, 0, 0$，增益为 $7, 3, 1$：IDCG $= 7 + 3\cdot0.631 + 1\cdot0.5 = 9.393$。故 nDCG@5 $= 6.931/9.393 = 0.738$。把最相关的块从第一名放到第三名，损失了四分之一的分数；若用线性增益（$g = \mathrm{rel}$），同一排序得 $3.931/4.762 = 0.825$，所以务必说明你所用的增益。
:::
:::

::: widget plot
f: 1/(log(x + 1)/log(2)); 1/x
x: 1, 20
y: 0, 1.05
labels: DCG discount $1/\log_2(i + 1)$; reciprocal rank $1/i$
points: 1,1; 2,0.631; 3,0.5
caption: 在 DCG 与倒数排名下，排名第 $i$ 的相关结果值多少。倒数排名衰减很陡——排名第 $2$ 的相关结果只值第 $1$ 名的一半——而且只数第一个相关结果。DCG 折减因子降得慢（第 $2$ 名 $0.63$，第 $3$ 名 $0.5$，第 $10$ 名 $0.29$），并且把全部相关结果都计入，这契合由生成器读取多个块的 RAG。
:::

下面的清单在 $40$ 个查询上模拟两个检索器——每个查询在 $200$ 篇文档中有三篇相关——计算三个指标，并用配对自助法估计 MRR 差的置信区间。

```python
import math, random
rng = random.Random(11)
Q, D, R = 40, 200, 3                     # 查询数、每查询文档数、每查询相关文档数

def run(mu):                             # 模拟检索器：相关文档的得分均值高 mu
    out = []
    for q in range(Q):
        scores = [(rng.gauss(mu if d < R else 0, 1), d) for d in range(D)]   # 文档 0..R-1 相关
        out.append([d for _, d in sorted(scores, reverse=True)])
    return out

def recall_at(rank, k): return sum(d < R for d in rank[:k]) / R
def rr(rank): return next((1 / (i + 1) for i, d in enumerate(rank) if d < R), 0.0)
def ndcg_at(rank, k):
    dcg = sum(1 / math.log2(i + 2) for i, d in enumerate(rank[:k]) if d < R)
    idcg = sum(1 / math.log2(i + 2) for i in range(min(R, k)))
    return dcg / idcg

A, B = run(2.0), run(2.5)
for name, runs in (("A", A), ("B", B)):
    print(f"{name}: recall@10 {sum(recall_at(r, 10) for r in runs)/Q:.3f}  "
          f"MRR {sum(map(rr, runs))/Q:.3f}  nDCG@10 {sum(ndcg_at(r, 10) for r in runs)/Q:.3f}")

diff = [rr(b) - rr(a) for a, b in zip(A, B)]          # 逐查询的配对差
boots = sorted(sum(diff[rng.randrange(Q)] for _ in range(Q)) / Q for _ in range(2000))
print(f"MRR difference B - A {sum(diff)/Q:+.3f}, 95% bootstrap interval "
      f"[{boots[49]:+.3f}, {boots[1949]:+.3f}]")
```

```text
A: recall@10 0.575  MRR 0.636  nDCG@10 0.493
B: recall@10 0.808  MRR 0.788  nDCG@10 0.708
MRR difference B - A +0.153, 95% bootstrap interval [+0.023, +0.281]
```

检索器 B 在三个指标上都更好，且 MRR 差的配对区间不含零——但在只有 $40$ 个查询的情况下，尽管 B 的模拟优势相当大，也只是勉强不含。区间宽度约 $0.26$，它诚实地说明了 $40$ 个查询能让你知道多少。配对很重要：两个检索器面对同样的查询，而重采样查询时把两者的结果绑在一起（[[prompting-rag/prompt-design#sec-testing]] 对提示使用的是同一思想）。

## 有参考答案时的回答指标 {#sec-reference}

当问题有简短的参考答案——人名、数字、日期——回答可以对照它们自动打分。SQuAD（Rajpurkar 等人，2016）的抽取式问答传统定义了两种标准度量。

::: definition 精确匹配与词元 F1 {#def-em-f1}
把预测答案与参考答案归一化：转小写，去掉标点与冠词 *a*、*an*、*the*，再切分成词元。若词元序列完全相同，**精确匹配**（EM）为 $1$，否则为 $0$。**词元 F1** 是精确率（预测词元出现在参考答案中的比例，按重数计）与召回率（参考词元出现在预测中的比例）的调和平均。有多个参考答案时取其最大值。
:::

::: example EM 与 F1 {#ex-f1}
参考答案为 *Eiffel Tower*。给预测 *The Eiffel Tower.*、*the Eiffel Tower in Paris* 和 *Tower of London* 打分。
::: solution
归一化后的参考答案为 (*eiffel*, *tower*)。*The Eiffel Tower.* 变为 (*eiffel*, *tower*)：EM $1$，F1 $1$。*the Eiffel Tower in Paris* 变为 (*eiffel*, *tower*, *in*, *paris*)：EM $0$；精确率 $2/4$，召回率 $2/2$，F1 $= 2\cdot0.5\cdot1/1.5 = 0.667$。*Tower of London* 变为 (*tower*, *of*, *london*)：精确率 $1/3$，召回率 $1/2$，F1 $= 0.4$——一个只是与参考答案共享了一个词的错误答案拿到了部分分数。
:::
:::

对于完整句子形式的生成式回答（"The tower in question is the Eiffel Tower, completed in 1889"），EM 过于苛刻，而 F1 奖励的是词面重合而非正确。因此生成式评测往往检查参考答案是否*出现*在回答中，或让模型判断回答与参考是否一致——这就引出了评审。

## 没有参考答案时的回答指标 {#sec-faithfulness}

许多 RAG 问题没有简短的参考答案：*替我摘要一下我们为外包人员制定的差旅政策。* 仍有两种性质可以对照检索到的上下文与问题进行评估。

::: definition 忠实度与回答相关性 {#def-faithfulness}
把一个回答拆成原子**论断** $c_1, \dots, c_m$。它的**忠实度**（有据度，groundedness）是论断中被传给生成器的上下文支持——蕴含——的比例：

$$
\operatorname{faithfulness} = \frac{\lvert\{j : \text{上下文}\models c_j\}\rvert}{m}.
$$

它的**回答相关性**是它回应用所提问题的程度，与对错无关。对上下文也可以按同样的精神打分：**上下文精确率**，即检回块中与问题相关的比例；**上下文召回率**，即参考答案的论断中受检回块支持的比例。
:::

这些定义遵循 RAGAS（Es 等人，2024）这类框架——它把每一步（提取论断、蕴含检查、相关性）都用大模型提示来实现——以及度量长生成事实精确率的 FActScore（Min 等人，2023）（[[prompting-rag/hallucination#sec-measuring]]）。忠实度是幻觉在生成侧的对应物：一个不忠实的论断就是相对于上下文的一个内在或外在幻觉（[[prompting-rag/hallucination#def-intrinsic]]）。

::: example 一个回答的忠实度 {#ex-faithfulness}
一个关于远程办公的回答作出五条论断：(1) 员工每周可在家办公两天；(2) 更多天数需要书面批准；(3) 批准人是直属经理；(4) 批准通常要花一周；(5) 办公室上午 8 点开门。上下文支持 (1)、(2)、(3) 和 (5)。计算忠实度，并评论论断 (5)。
::: solution
五条论断中有四条受支持：忠实度 $4/5 = 0.8$。论断 (4) 是外在幻觉。论断 (5) 忠实，但与远程办公的问题无关，这拉低的是回答相关性而非忠实度——两个指标是有意分开的，一个系统完全可能在一项上拿满分、在另一项上很差。
:::
:::

注意忠实度*不*测量什么：上下文本身是否正确、完整。建立在过时政策上的忠实回答仍然是错的，所以上下文召回率与端到端的正确性也要测量。

## 以语言模型为评审 {#sec-judges}

提取论断、蕴含与相关性都可以由人来判定，但人既慢又贵。用一个强语言模型当评审——**大模型评审**（LLM-as-a-judge）——能让评测便宜到每次改动都跑得起。Zheng 等人（2023）发现，强模型对聊天机器人回答的成对偏好与人类专家的判定在 $80\%$ 以上的场合一致，差不多就是专家彼此一致的比例，并记录了系统性偏差。[[evaluation/model-judges]] 一般性地讨论评审；对 RAG 最要紧的是以下几点。

- **位置偏差**：成对比较中，评审偏向排在前面（或后面）的回答。两种顺序都要评测，只采纳判定一致的，或取平均。
- **冗长偏差**：更长的回答更受偏爱，即使内容毫无增加。要控制长度，或让评审在简短的正确答案上接受指令并接受检验。
- **自我偏好**：评审可能偏爱自家模型系列产出的输出。尽可能用不同系列的评审，并加以验证。
- **对无支持的论断过于宽容**：评审可能接受一个在现实中为真、却不受上下文支持的论断。要明确询问*给定上下文*是否支持，一次一个论断，并要求评审引用支持的原文。
- **漂移**：外部提供商提供的评审可能随时更换而不予通知；能锁定版本就锁定，评审更换后重新验证。

评审是一种测量仪器，而仪器必须对照标准来校准。人工标注几百条样本，让评审在同一批上运行，并测量超出随机水平的一致性。

::: definition Cohen's kappa 系数 {#def-kappa}
两名评定者按类别给同样的 $n$ 个条目标注。令 $p_o$ 为二人一致的条目占比，$p_e = \sum_c p_c^{(1)}p_c^{(2)}$ 为随机情况下预期的一致占比，其中 $p_c^{(r)}$ 为评定者 $r$ 标成类别 $c$ 的条目占比。**Cohen's kappa** 为

$$
\kappa = \frac{p_o - p_e}{1 - p_e},
$$

完全一致时为 $1$，一致性不优于随机时为 $0$。
:::

::: example 验证一个忠实度评审 {#ex-kappa}
在 $100$ 个回答上，一个评审与一位人类专家各有 $60$ 次同判"忠实"、$20$ 次同判"不忠实"；评审判忠实而人类判不忠心有 $15$ 次，相反情形 $5$ 次。计算一致率与 kappa。分歧的模式说明了什么？
::: solution
$p_o = 80/100 = 0.8$。评审有 $75\%$ 的时候判忠实，人类是 $65\%$，故 $p_e = 0.75\cdot0.65 + 0.25\cdot0.35 = 0.4875 + 0.0875 = 0.575$，$\kappa = (0.8 - 0.575)/(1 - 0.575) = 0.529$，属中等一致。分歧是偏斜的：$20$ 次分歧中有 $15$ 次是评审放行、人类判错的回答。评审过于宽容，其忠实度分数高估了真相。收紧它的提示（逐论断核查并附引文）后重新测量；或者像预测增强推断（prediction-powered inference）这类统计方法那样，用人工标注的样本来修正评审的汇总分数（Saad-Falcon 等人，2024 把该方法用于 RAG 评测）。
:::
:::

::: warning 指标可以被优化到脱离它所测量的东西
一旦某个指标——比如大模型评审的忠实度分数——被用来选择提示、块长与模型，系统就会连同指标的怪癖一起被优化，而不只是它想要的东西。为讨好宽容评审而调的生成器，学会写评审会放行的回答；为词元 F1 而调的，学会简短。要保留一个从不用于调优的人工标注集，定期重新检查与它的一致性，并且要读失败的例子，而不是只看平均值。
:::

- [ ] recall@5 不是有效的检索指标。
- [ ] 新的嵌入模型一定更差。
- [x] 生成器可能没有用上额外检回的相关块——例如由于它们在提示中的位置、相互冲突的块，或者它答错的那些题本来就不是检索有改善的那批。
- [ ] 端到端指标永远比检索指标噪声大，什么结论也得不出。
::: solution
检索改善了，瓶颈现在可能在生成。去看检索有改善的那些问题：它们的回答变了吗？如果正确的块现在在场而回答仍然错，就检查位置、干扰块和指令。检查两个数字的不确定度也有价值，但"什么结论也得不出"不是第一步。
:::
:::

## 需要多少个查询？ {#sec-statistics}

上面的每个指标都是查询上的平均，都有抽样误差。一个比例——命中率、被评审判为正确的回答占比——在 $n$ 个独立查询上测得时，标准误为 $\sqrt{p(1 - p)/n}$，$95\%$ 区间大约是 $\pm1.96$ 个标准误（更好的是 [[ml-fundamentals/evaluation-metrics#def-wilson]] 的 Wilson 区间）。

::: example 区间的宽度 {#ex-interval}
在 $200$ 个问题上做的端到端评测发现 $70\%$ 的回答正确。近似的 $95\%$ 区间是什么？要把区间宽度减半需要多少个问题？
::: solution
$1.96\sqrt{0.7\cdot0.3/200} = 1.96\cdot0.0324 = 0.064$：约 $70\% \pm 6.4$ 个百分点。宽度按 $1/\sqrt n$ 下降，所以减半需要四倍的问题数，即 $800$ 个。在 $200$ 个问题上测出的三个点的变化远在噪声之内，除非比较是配对的（同样的问题、两个系统）并用配对检验分析——配对能消去问题之间的变异。
:::
:::

::: widget plot
f: 1.96*sqrt(p*(1 - p)/x)
x: 20, 2000
y: 0, 0.25
sliders: p=0.7:0.05:0.95:0.05
labels: half-width of a $95\%$ interval for a proportion
points: 200,0.0635; 800,0.0318
caption: 在 $n$ 个独立查询上测得正确率 $p$ 时，$95\%$ 置信区间的近似半宽 $1.96\sqrt{p(1 - p)/n}$。$p = 0.7$ 时，$200$ 个查询给出 $\pm6.4$ 个百分点，$800$ 个给出 $\pm3.2$，如 [[#ex-interval]]。曲线趋于平缓：区间每再减半一次就要四倍的数据，所以能直接压低方差的配对设计，比蛮力堆数据更值钱。
:::

还有三条警示。查询很少是独立的——许多查询可能是少数几种信息需求的换个说法——所以有效样本量小于计数。在同一集合上比较多个指标和许多变体会招致虚假发现；要在留出的查询上确认胜出者。而且系统对不同种类查询的表现不同：要按类别报告结果（简短事实型、多跳、无法回答、按产品或语言），因为平均值可能掩盖一个大幅退步的类别。

::: history
对检索的系统评测始于 1960 年代 Cleverdon 的 Cranfield 实验，它引入了由文档、查询与相关性判定组成的测试集，以及召回率与精确率的度量。由 NIST 自 1992 年主办的文本检索会议（TREC）用合并标注与共享任务把这一方法规模化，自 1999 年起包括问答。Voorhees（1999）在 TREC 问答中使用了平均倒数排名，Järvelin 与 Kekäläinen（2002）为分级相关性引入了累计增益度量。Rajpurkar 等人（2016）为 SQuAD 定义了精确匹配与词元 F1；Natural Questions（2019）、BEIR（2021）与 KILT（2021）成为神经检索与知识密集型任务的标准基准。随着回答变为生成式，评测转向忠实度与归因（Rashkin 等人，2023；Min 等人，2023）、大模型评审（Zheng 等人，2023），以及 RAGAS（Es 等人，2024）与 ARES（Saad-Falcon 等人，2024）这类 RAG 专用框架。
:::

::: summary
- 分别评测检索、生成与端到端回答；每种失败各有对策。
- 在传给生成器的块数处取 recall@$k$ 是关键的检索指标；precision@$k$、命中率、MRR 与 nDCG 补全全貌。nDCG 使用分级增益与对数折减，且因有序增益使 DCG 最大而落在 $[0, 1]$ 内。
- 有短参考答案时，精确匹配与词元 F1 可以为回答打分，但对生成式文本两者都很粗糙。
- 没有参考答案时，忠实度（受上下文支持的论断比例）与回答相关性评估生成；上下文精确率与召回率评估生成器拿到的东西。
- 大模型评审让评测便宜，但存在位置、冗长与自我偏好偏差，且可能宽容；要用 Cohen's kappa 这类扣除随机的度量对照人工标签验证它们。
- 每个指标都有按 $1/\sqrt n$ 收缩的抽样误差；用配对方法在同一批查询上比较系统，按类别报告，并保留一个留出的人工标注集。
:::

## 习题

::: exercise 五处召回率 {level=1 check="0.4"}
某查询有五个相关块，其中两个出现在检索器的前五名里。recall@5 是多少？precision@5 是多少？
::: solution
recall@5 $= 2/5 = 0.4$，precision@5 $= 2/5 = 0.4$ 也相同（$R = k = 5$ 的巧合）。
:::
:::

::: exercise 平均倒数排名 {level=1 check="0.4583"}
四个查询中，第一个相关块分别排在 $1$、$3$、$2$，而最后一个查询的列表里没有任何相关块。保留四位小数计算 MRR。
::: solution
$(1 + 1/3 + 1/2 + 0)/4 = 1.8333/4 = 0.4583$。
:::
:::

::: exercise 手算 nDCG {level=2 check="0.661"}
前四名块的相关性为 $0, 3, 1, 2$，其余块均不相关。以增益 $2^{\mathrm{rel}} - 1$ 计算 nDCG@4，保留三位小数。
::: solution
增益 $0, 7, 1, 3$；折减因子 $1, 0.631, 0.5, 0.431$。DCG $= 0 + 4.417 + 0.5 + 1.292 = 6.209$。理想相关性 $3, 2, 1, 0$，增益 $7, 3, 1, 0$：IDCG $= 7 + 1.893 + 0.5 = 9.393$。nDCG@4 $= 6.209/9.393 = 0.661$。
:::
:::

::: exercise 词元 F1 {level=1 check="0.4"}
参考答案为 *Eiffel Tower*，预测为 *Tower of London*。归一化后计算词元 F1，并解释这个分数为何有误导性。
::: solution
预测词元 (*tower*, *of*, *london*)，参考词元 (*eiffel*, *tower*)：公共词元一个，精确率 $1/3$，召回率 $1/2$，F1 $= 2\cdot\frac13\cdot\frac12/(\frac13 + \frac12) = 0.4$。回答完全错了，却因与参考答案共享一个词而拿到 $40\%$ 的分数；F1 度量的是重合，不是正确。
:::
:::

::: exercise 某一标签占主导时的 kappa {level=2 check="0.377"}
在 $100$ 个回答上，评审与人类各有 $70$ 次同判"忠实"、$10$ 次同判"不忠实"；评审单独判忠实 $12$ 次，人类单独判忠实 $8$ 次。保留三位小数计算 $p_o$ 与 kappa，并与 [[#ex-kappa]] 比较。
::: solution
$p_o = 0.8$，与之前相同。评审有 $82\%$ 的时候判忠实，人类是 $78\%$，故 $p_e = 0.82\cdot0.78 + 0.18\cdot0.22 = 0.6396 + 0.0396 = 0.6792$，$\kappa = (0.8 - 0.6792)/(1 - 0.6792) = 0.377$。原始一致率与 [[#ex-kappa]] 相同，但因为两名评定者都说"忠实"的次数太多，这份一致中有很大部分是随机预期就有的；kappa 更低。在标签不均衡时，原始一致率会美化评审的表现。
:::
:::

::: exercise 忠实度 {level=1 check="0.75"}
一个回答包含八条原子论断，其中六条受检索到的上下文支持。它的忠实度是多少？若这六条受支持的论断中有两条没有回应问题，受影响的另一个指标是哪个？
::: solution
$6/8 = 0.75$。受支持但离题的论断不会拉低忠实度；它们拉低回答相关性。
:::
:::

::: exercise 调换评审的顺序 {level=2}
一个成对评审在 $200$ 个问题上比较系统 A 与 B 的回答，总是把 A 放在前面，A 有 $62\%$ 的时候胜出。把 B 放在前面重跑，A 的胜率变为 $48\%$。关于评审和关于两个系统，你能得出什么结论？这个比较应当如何报告？
::: solution
顺序影响判定：在同一批题对上，把 A 从第一位移到第二位，其胜率下降了 $14$ 个百分点，所以评审存在偏向第一个回答的位置偏差。对两种顺序取平均，A 的胜率约为 $55\%$，比任何一次运行显示的都弱；更好的做法是只统计评审在两种顺序下都偏好同一系统的问题，把不一致的视为平局。报告一致判定的比例、一致问题上带置信区间的胜率，以及不一致判定的比例——最后这个数字衡量对这个系统对而言评审有多可信。
:::
:::

::: exercise 有序排列使 DCG 最大 {level=2}
证明：对任意递减的正权重 $w_1 > w_2 > \dots > w_k$ 与增益 $g_1, \dots, g_k\ge0$，交换一对相邻的逆序（$g_i < g_{i+1}$）会增大 $\sum_iw_ig_i$，并推出排序所需的交换次数等于逆序对的数目。为什么这一论证也说明把相关块放在第一位使 MRR 最大？
::: solution
交换位置 $i$ 与 $i + 1$ 使总和改变 $w_ig_{i+1} + w_{i+1}g_i - w_ig_i - w_{i+1}g_{i+1} = (w_i - w_{i+1})(g_{i+1} - g_i) > 0$。每次交换一对相邻逆序恰好消除一个逆序对（$i < j$ 且 $g_i < g_j$）而不会制造新的，所以冒泡排序恰好以逆序对数那么多次交换到达有序排列，且每次交换都增大总和。对 MRR 而言，倒数排名只取决于第一个相关块的位置 $1/r$，在 $r = 1$ 处最大；它是权重为 $1/i$、且只有第一个相关条目计数的"DCG"的特例。
:::
:::

::: exercise 用代码实现 EM 与 F1 {level=3}
用纯 Python 实现 SQuAD 风格的归一化、精确匹配与词元 F1，在多个参考答案上取最大值，并对 *The Eiffel Tower.*、*the Eiffel Tower in Paris*、*Tower of London* 和 *Louvre* 以参考答案 *Eiffel Tower* 与 *the Eiffel Tower* 测试。
::: solution
```python
import re, string
from collections import Counter
def normalise(s):                       # SQuAD 风格：转小写，去标点与冠词
    s = "".join(ch for ch in s.lower() if ch not in string.punctuation)
    return re.sub(r"\b(a|an|the)\b", " ", s).split()
def exact_match(pred, gold): return float(normalise(pred) == normalise(gold))
def f1(pred, gold):
    p, g = normalise(pred), normalise(gold)
    common = sum((Counter(p) & Counter(g)).values())
    if common == 0: return 0.0
    prec, rec = common / len(p), common / len(g)
    return 2 * prec * rec / (prec + rec)
def best(pred, golds, metric): return max(metric(pred, g) for g in golds)

golds = ["Eiffel Tower", "the Eiffel Tower"]
for pred in ["The Eiffel Tower.", "the Eiffel Tower in Paris", "Tower of London", "Louvre"]:
    print(f"{pred!r:30s} EM {best(pred, golds, exact_match):.0f}  F1 {best(pred, golds, f1):.3f}")
```

```text
'The Eiffel Tower.'            EM 1  F1 1.000
'the Eiffel Tower in Paris'    EM 0  F1 0.667
'Tower of London'              EM 0  F1 0.400
'Louvre'                       EM 0  F1 0.000
```

结果与 [[#ex-f1]] 一致。`Counter` 的交集能正确计算重复词元（两边都出现两次的词元计两次），而归一化使两个参考答案等价。
:::
:::

::: exercise 构建评测集 {level=3}
公司工程文档 RAG 助手上线前，请你来评测它。描述你如何构建评测集（问题来源、标注、规模），为每个部件报告哪些指标，如何验证所用的大模型评审，以及如何判断一项提议的改动是改进。
::: solution
问题：从支持工单、聊天记录和搜索日志中抽样真实问题（匿名化），加上工程师为重要文档亲自写的问题，并有意纳入多跳问题、关于近期变更的问题和无法回答的问题；把同义改写去重为信息需求。标注：每个问题的相关块（从多个检索器前列结果构成的池中标注，带分级相关性）、参考答案，以及可回答性标记。规模：按 [[#sec-statistics]] 的区间宽度指导，每个重要类别几百个问题；划分为用于调优的开发集和留出的测试集。指标：在生成器的 $k$ 处的检索 recall@$k$、MRR 与 nDCG@10；在记录的上下文上测生成的忠实度与回答相关性；对照参考答案的端到端正确率，以及无法回答的问题上的拒答率；全部按类别报告。评审：对每个被评审的指标人工标注几百条，测量 kappa 与分歧的方向，修改评审提示直到一致性足够，评审模型更换后重新验证。决策：在同一批问题上用配对自助区间或 McNemar 检验比较系统，要求在留出集上有改进，检查没有类别退步超出其噪声，并在发布前读一批发生变化的回答。
:::
