提示是一种用自然语言写成的程序，写给一个行为没有人能完全规定的解释器执行。像任何程序一样，它由分工不同的部分组成——一条指令、上下文、示例、输入、对输出的描述——也像程序一样，它可以被测试、被度量、被改进。但与程序不同的是，在人类读者看来无关紧要的小改动（用冒号而不是换行、两个段落的先后顺序）可能大幅改变它的输出，而且对一个模型有帮助的改动可能伤害另一个模型。

本章把提示设计当作一门工程。它给提示的各个组成部分、以及指令微调模型接收提示所用的对话格式命名，收集有扎实证据支撑的技术——清晰的指令、精选的示例、思维链与自洽性——以及决定信息该放在哪里的位置效应。然后说明如何像对待任何其他实验那样、以统计上的审慎来比较提示，并以提示注入收尾：为什么别人提供的文本可能充当指令，以及系统如何防范它。

## 提示的结构 {#sec-anatomy}

::: definition 提示的组成 {#def-components}
**提示**是模型在生成之前所条件化的完整词元序列。它的组成部分（顺序任意，每个都可省略）有：

- **指令**：做什么、为谁做、带哪些约束；
- **上下文**：模型需要但并不掌握的材料——文档、数据、对话的状态；
- **示例**：输入–输出示例（[[prompting-rag/in-context-learning#def-kshot]]）；
- **输入**：要处理的这一个具体例子；
- **输出规格**：答案的格式、长度、语言或模式（[[prompting-rag/structured-output]]）。

**提示模板**是带有槽位的提示，例如 `{document}` 与 `{question}`，在每次调用时以程序方式填入。
:::

指令微调模型（[[post-training/instruction-tuning]]）是在**对话**而不是纯文本上训练的。一段对话是一个消息列表，每条消息有一个**角色**——常见的有 *system*（应用开发者的常驻指令）、*user*（使用者的发言）与 *assistant*（模型的发言），智能体系统里还有用于工具结果的其他角色（[[agents/function-calling]]）。在模型看到它之前，这个列表由**聊天模板**渲染成一条词元序列，用特殊词元标出每条消息从哪里开始、到哪里结束，例如

```text
<|start|>system
You are a careful assistant for a library catalogue.<|end|>
<|start|>user
Find books on medieval bridges.<|end|>
<|start|>assistant
```

其中 `<|start|>` 与 `<|end|>` 代表各模型特定的特殊词元。模型生成助手的那条消息，完成后发出结束词元。有两点对设计要紧。第一，角色是*在训练中学到的惯例*，不是强制执行机制：系统消息只拥有后训练赋予它的影响力，仅此而已。第二，模板不匹配——用模型没有在其上训练过的格式渲染消息——会悄无声息地拉低输出质量，因此永远使用随模型一起发布的模板。

::: example 词元花在了哪里 {#ex-tokens}
某个客服应用发送一条 $600$ 词元的系统消息、$4$ 个各约 $150$ 词元的示例、一篇检索到的 $1200$ 词元的文档和一个 $50$ 词元的用户问题，并允许 $400$ 个输出词元。用户问题占输入的多大比例？如果该应用每天处理 $200{,}000$ 个请求，固定系统消息与示例每天消耗多少输入词元？
::: solution
输入：$600 + 600 + 1200 + 50 = 2450$ 个词元，其中问题占 $50/2450 = 2.0\%$。固定部分每个请求 $1200$ 个词元，即每天 $1200\cdot200{,}000 = 2.4\times10^8$ 个词元。固定的前缀正是提示缓存发挥作用的地方（[[inference/kv-cache]]）：如果模型为共享前缀算出的键与值能被复用，这份代价就远不必每次支付。这套算术也说明了为什么把过长的系统消息改短值得测试。
:::
:::

## 指令 {#sec-instructions}

提示的多数失败是规格说明的失败：模型做了件合理的事，却并非书写者想要的。补救的办法，就是对人类同事管用的那几条。

- **说要做什么，而不只是要避免什么。**"回答不超过三句话"比"别啰嗦"更容易遵循。
- **给出目的和受众。**"为一个将要决定是否通读整份报告的读者作摘要"比"作摘要"更能约束内容。
- **用清晰的分隔符把指令与数据分开**——标题、`<document> … </document>` 这样的标签，或围栏块——并用数据的标签来指称数据。
- **明确写出输出格式**，格式不常见时附上一个示例，并说明边缘情况该怎么办（"如果文档不包含答案，回复 `NOT FOUND`"）。
- **每条要求只说一次，说在一个地方。**散布在长提示里的矛盾指令，被如何化解是不可预测的。

::: example 重写一条含糊的指令 {#ex-rewrite}
某个应用这样提问：*Look at this review and tell me about it.*（看看这条评论，跟我说说它。）把它改写成输出可以自动检查的形式。
::: solution
一个可测试的版本：

```text
Classify the customer review between <review> tags.
Reply with exactly one word: positive, negative or mixed.
"mixed" means the review contains both clear praise and clear complaints.
<review>{review}</review>
```

它点明了任务、标签集合和最不显然那个标签的含义，给数据加了分隔，并固定了一种格式，测试可以拿它与参考标签比对。原来的写法，回答一段摘要、一个情绪标签，或一篇对评论文风的批评，都算答得合理。
:::
:::

指令微调之后，示例仍然有用，主要用于格式，以及那些难以描述、却容易示范的任务。[[prompting-rag/in-context-learning#sec-what-matters]] 的证据在此适用：示例的格式和标签覆盖至少和它们的标签一样重要，挑选与输入相似的示例会有帮助。

## 思维链 {#sec-cot}

有些问题需要中间步骤。Transformer 用固定的层数计算每个词元；若要求它立即给出答案，对一个多步问题它就只有那一份固定的计算深度。若要求它先把步骤写出来，每一步都成为下一步的上下文的一部分，模型就能按推理所需付出任意多次前向计算。

::: definition 思维链提示 {#def-cot}
**思维链提示（chain-of-thought, CoT）**在最终答案之前引出一串中间推理步骤，做法可以是给出输出中包含完整推理过程的示例（**少样本 CoT**），也可以是一条要求推理的指令（**零样本 CoT**）。最终答案从生成文本的末尾抽取。
:::

Wei 等人（2022）引入了少样本 CoT。在小学数学应用题基准 GSM8K 上，$5400$ 亿参数的 PaLM 模型用标准少样本提示解出 $17.9\%$ 的题目，用思维链示例则解出 $56.9\%$；增益只在他们测试的最大模型上很大，小模型有时反而更差。Kojima 等人（2022）发现，仅仅追加一句 *Let's think step by step*（让我们一步步想），就把某个指令跟随模型在 GSM8K 上的零样本准确率从 $10.4\%$ 提到 $40.7\%$。理论工作支持这一计算观点：Feng 等人（2023）以及 Merrill 与 Sabharwal（2024）证明，在他们的形式化假设下，生成中间步骤的 Transformer 能解决固定深度的 Transformer 直接作答所不能解决的一类问题。

这些数字旁边要放上两个提醒。写出的推理并不保证就是答案的原因：Turpin 等人（2023）把少样本提示做了偏移，使正确选项永远是 *(A)*，模型的解释便替有偏的答案寻找理由，却只字不提那个偏移。而到 2026 年，许多模型经过训练会在回答前进行长篇推理，显式的 CoT 提示对它们往往增添不多。[[reasoning/chain-of-thought]] 讲述推理模型，[[reasoning/faithfulness-limits]] 讲述忠实性问题。

::: example 思考的代价 {#ex-cot-cost}
某个模型直接回答一个问题需要 $20$ 个词元，用思维链则需要 $350$ 个词元。输出词元是一个一个生成的，在该部署下的速度是每秒 $50$ 个词元。延迟和输出词元费用如何变化？
::: solution
生成的延迟从 $20/50 = 0.4$ 秒升到 $350/50 = 7$ 秒，输出词元数变为 $17.5$ 倍。这值不值得取决于任务：对算术应用题，上面提到的准确率差距很大；对检索一条事实，CoT 通常只添成本不见收益。在你的任务上把两者都测一测。
:::
:::

## 自洽性 {#sec-self-consistency}

思维链产生一条推理路径。在正温度下采样多条路径（[[inference/decoding-sampling]]），再取出现最频繁的最终答案，效果更好。Wang 等人（2023）把这一想法称为**自洽性**：不同的正确路径往往到达同一个答案，而错误四散分布。

::: definition 自洽性 {#def-self-consistency}
对同一个提示独立地从模型采样 $n$ 个输出，从每个输出中提取最终答案 $a_j$，返回**相对多数**（得票最多）的答案 $\hat a = \arg\max_a\ \lvert\{j : a_j = a\}\rvert$，平票时随机打破。
:::

投票什么时候有用？只有当正确答案是**概率最大**的单个答案时才有用，这一条件弱于要求它的概率超过一半。

::: proposition 相对多数投票收敛到众数 {#prop-plurality}
设单个样本的提取答案在有限的答案集合上服从分布 $\pi$，其唯一众数为 $a^* = \arg\max_a\pi(a)$，$n$ 个样本相互独立。则自洽性返回 $a^*$ 的概率当 $n\to\infty$ 时趋于 $1$。若 $\pi(a^*)$ 不是最大的概率，则该概率趋于 $0$。
:::

::: proof
用 $\hat\pi_n(a)$ 表示答案为 $a$ 的样本所占的比例。由大数定律，对有限个答案中的每一个，$\hat\pi_n(a)\to\pi(a)$ 几乎必然成立。设 $\delta = \pi(a^*) - \max_{a\ne a^*}\pi(a) > 0$。一旦每个 $\hat\pi_n(a)$ 都落在 $\pi(a)$ 的 $\delta/2$ 范围之内——对一切充分大的 $n$ 这几乎必然发生——就有 $\hat\pi_n(a^*) > \pi(a^*) - \delta/2\ge\pi(a) + \delta/2 > \hat\pi_n(a)$ 对每个 $a\ne a^*$ 成立，于是投票返回 $a^*$。反之若存在 $a\ne a^*$ 使 $\pi(a) > \pi(a^*)$，同样的论证表明最终 $\hat\pi_n(a) > \hat\pi_n(a^*)$，于是投票以趋于 $0$ 的概率返回 $a^*$。
:::

结果只有两种（对或错）时，速率是显式的。若每个样本以概率 $p > 1/2$ 正确，正确样本数 $X$ 服从二项分布，Hoeffding 不等式对"至多一半正确"这一事件给出概率上界：

$$
\Prob\big(X\le n/2\big)\le\exp\!\big(-2n(p - \tfrac12)^2\big).
$$ {#eq-hoeffding}

::: example 五个样本 {#ex-vote}
每条采样的推理路径以概率 $0.6$ 独立地到达正确答案，每条错误路径都给出某个错误答案。$5$ 个样本的多数正确的概率是多少？[[#eq-hoeffding]] 保证了什么？
::: solution
至少 $3$ 个样本正确时，多数才正确：

$$
\textstyle\sum_{k=3}^{5}\binom5k0.6^k0.4^{5-k} = 0.3456 + 0.2592 + 0.07776 = 0.68256.
$$

于是投票把准确率从 $0.6$ 提到 $0.683$。Hoeffding 界给出的错误概率至多为 $e^{-2\cdot5\cdot0.01} = 0.905$，在 $n = 5$ 时成立却毫无用处；它要到 $n$ 很大时才有信息量（$n = 101$ 时至多 $e^{-2.02} = 0.13$）。实际中错误答案往往彼此互不相同，所以相对多数正确的次数比多数计算显示的还要多。
:::
:::

::: widget distribution
dist: binomial
params: n=5, p=0.6
a: 3
b: 5
caption: $n$ 条相互独立的推理路径中正确路径的条数，每条正确的概率为 $p$。阴影柱是 $5$ 个样本中正确 $3$ 到 $5$ 条的情形，即多数投票答对的情形：$p = 0.6$ 时概率为 $0.683$，如 [[#ex-vote]]。增大 $n$（保持阴影范围在 $n/2$ 以上），概率趋向 $1$；把 $p$ 调到 $0.5$ 以下，投票反而更糟。
:::

::: example 一个势均力敌的对手 {#ex-competitor}
某模型的采样答案正确的概率为 $0.4$；某个特定的错误答案概率为 $0.35$，其余错误答案合计 $0.25$。第二个模型的答案正确概率为 $0.4$，三个不同的错误答案各概率 $0.2$。精确枚举给出相对多数投票正确的概率：

| 样本数 $n$ | $1$ | $3$ | $5$ | $11$ | $25$ | $51$ |
|---|---|---|---|---|---|---|
| 势均力敌 $(0.4, 0.35, 0.25)$ | $0.400$ | $0.422$ | $0.443$ | $0.493$ | $0.563$ | $0.636$ |
| 错误四散 $(0.4, 0.2, 0.2, 0.2)$ | $0.400$ | $0.448$ | $0.509$ | $0.635$ | $0.799$ | $0.928$ |

解释其中的差别。
::: solution
两个模型的正确答案都是唯一众数，因此由 [[#prop-plurality]] 二者都收敛到 $1$。速率取决于众数与次优答案之间的差距 $\delta$：第一个模型是 $0.05$，第二个是 $0.2$。对手势均力敌时，需要很多样本，投票才能可靠地区分两个领先的答案；错误四散时，少量样本就够。Wang 等人报告的增益在他们的基准上几十个样本之后便趋于饱和——这与真实误差分布介于两种情形之间、以及同一模型的样本相互正相关（[[#prop-plurality]] 的独立性假设忽略了这一点）都相吻合。
:::
:::

Wang 等人发现，在他们的主要设定下，自洽性把思维链在 GSM8K 上的准确率比单条路径的贪心解码提高了 $17.9$ 个百分点。代价是 $n$ 倍的生成量；它要求答案可以判等（一个数、一个选项字母）；对自由书写的回答，还需要判断两个答案是否同义的手段——这个问题在 [[prompting-rag/hallucination]] 中重新出现。

::: quiz
自洽性采样 $n$ 条推理路径并取相对多数答案。哪种情形下，不断增大 $n$ 最终会让答案**比单个样本更差**？
- [ ] 正确答案概率为 $0.4$，错误答案摊得很薄。
- [x] 正确答案概率为 $0.4$，某个特定错误答案概率为 $0.45$。
- [ ] 正确答案概率为 $0.6$。
- [ ] 样本在很高的温度下生成。
::: solution
由 [[#prop-plurality]]，投票收敛到概率最大的答案。若某个单个错误答案比正确答案概率还大，投票就收敛到它，准确率从 $0.4$ 跌向 $0$。错误答案摊得薄并无害，因为正确答案仍是众数。
:::
:::

## 信息放在哪里：位置效应 {#sec-position}

长提示提出了短提示没有的问题：模型是否均匀地使用它的整个上下文？Liu 等人（2024）用多文档问答检验这一点：一个问题，$10$ 到 $30$ 段检索来的段落，其中恰好一段包含答案，而该段落的位置不断变化。相关段落出现在最前或最后时准确率最高，出现在中间时最低——一条 **U 形**曲线，他们称之为**迷失在中间**（lost in the middle）。在某些设定下，模型拿到 $20$ 段材料而答案在中间时，表现得比完全不给材料的同一模型还差。这一效应在他们 2023 年测试的每个模型中都出现了，包括为长上下文设计的模型，也出现在一个合成任务里——从键值对列表中按键取回对应的值。

此后模型在简单的长上下文检索上已有进步，"大海捞针"式的合成测试如今已例行通过；但截至 2026 年，在评测中，那些要求利用、组合或推理长上下文里分散信息的任务，仍随长度和位置退化（[[inference/long-context]]）。实用规则是：

- 把指令放在开头，上下文很长时，在紧接输入之前重述关键要求；
- 把最相关的文档放在上下文块的首尾，而不是中间（[[prompting-rag/retrieval-augmented-generation]] 把这一点用于重排序后的段落）；
- 宁可要更短、更相关的上下文，也不要一段答案不知埋在何处的长上下文。

::: warning 更多上下文并不免费
把一切可能相关的东西都粘进长上下文窗口、让模型自己去整理，是很有诱惑力的。无关材料并不中性：它消耗词元和延迟，可能干扰模型（Shi 等人 2023 年表明，往算术题里加入无关句子会显著降低准确率），而且放在中间的相关段落被用得更少。检索与筛选是提示设计的一部分。
:::

## 作为实验学科的提示工程 {#sec-testing}

Sclar 等人（2024）只改变少样本提示的**排版格式**——分隔符、大小写、字段间的空格，这些不改变含义的选择——发现同一个开放模型在同一个任务上的准确率差距可达 $76$ 个百分点，而且最好的格式在不同模型之间各不相同。教训是：提示的质量是一个经验量：你无法从提示本身读出它，必须在数据上测量它。

::: algorithm 迭代改进提示 {#alg-prompt-loop}
1. **先定义任务和指标**——与标签精确匹配、模式检查、评分细则得分——再动笔写提示。
2. **搭建评测集**，收集带参考输出的代表性输入，包括难的与罕见的例子；留出一部分，迭代期间不看它。
3. **写一个基线提示**并评测；读失败的样本，而不只是看分数。
4. **每次只改一处**——一条指令、一个示例、顺序、格式——在同一批题目上重新评测。
5. **用配对检验比较**，只有改进大于噪声时才保留改动。
6. 重复；最后，在留出集上确认，并且每当模型改变就重跑评测。
:::

因为两个提示是在**同一批**题目上评测的，这个比较是配对的，合适的检验只看二者答案不一致的题目：McNemar 检验（[[ml-fundamentals/evaluation-metrics#prop-mcnemar]]）。

::: example 新提示更好吗？ {#ex-mcnemar}
在 $200$ 道测试题上，提示 A 答对 $142$ 题（$71\%$），提示 B 答对 $152$ 题（$76\%$）。B 在 A 答错的题里对了 $35$ 题，A 在 B 答错的题里对了 $25$ 题。在 $5\%$ 水平下 B 显著更好吗？
::: solution
不一致计数为 $b = 25$、$c = 35$（且必有 $152 - 142 = 35 - 25$）。McNemar 统计量为 $(b - c)^2/(b + c) = 100/60 = 1.67 < 3.84$，所以差异不显著：在 $60$ 道题改变了结果的情况下，$200$ 道题上五个百分点的提升落在噪声之内。要可靠地检出这么小的差别，你需要更多题目，或者一种把更少结果改向错误方向的提示改动。
:::
:::

带采样的生成带来第二个噪声源——同一个提示在同一道题上可能给出不同输出——所以就在你部署所用的温度下评测，或每题采样多个输出。自动方法针对这样的指标在提示空间里搜索：Zhou 等人（2023）让模型提出候选指令并打分，Yang 等人（2024）把模型当作提示的优化器、利用提示的历史得分，DSPy（Khattab et al., 2024）等框架则针对指标调优指令与示例，把一串模型调用编译成流水线。它们都像任何优化器一样会对评测集过拟合，这就是 [[#alg-prompt-loop]] 的第 6 步要留出数据的原因。

## 提示注入 {#sec-injection}

语言模型接收的是一串词元。当应用把不可信的文本放进这串词元——要摘要的网页、要分诊的邮件、为问题检索的文档、某个工具的输出——这段文本就可能包含指令，而模型没有可靠的办法知道这些指令出自与开发者或用户不同的主体。

::: definition 提示注入 {#def-injection}
**提示注入**是用进入模型应用上下文的文本来操纵该应用：模型把这些文本当作指令来解释，从而覆盖或颠覆开发者或用户的指令。攻击者就是向应用打字的用户时，注入是**直接的**；当指令被植入应用日后替他人处理的内容中时，注入是**间接的**（Greshake et al., 2023）。
:::

这个名字由 Simon Willison 在 2022 年提出，致敬 SQL 注入，而这个类比恰好说明了问题为何难。SQL 注入靠把代码与数据分离解决了：参数化查询让数据走一条解释器永不执行它的通道。语言模型没有这样的通道；指令与数据都只是词元，而遵循文本中出现的指令恰恰是指令微调所训练的那种技能。带工具和私有数据的系统最需要防的是间接注入（[[agents/agent-security]]）：一个既能读用户邮件又能发消息的模型，可能因为它读到的一条消息而被操纵，把数据发往别处。

防御是分层的，而截至 2026 年没有一层是完备的：

- **最小权限与隔离。**只给模型任务所需的工具和数据；不让读取不可信内容的组件在没有检查的情况下执行有后果的动作。把不可信内容与规划动作的组件隔开的架构，遵循的正是这一原则。
- **把模型输出当作不可信的。**用模式校验它（[[prompting-rag/structured-output]]），永远不要直接执行它，渲染前先转义（被注入的指令可能设法让输出包含会泄露数据的链接或标记）。
- **人工确认**任何对外部世界有影响的动作——发送、付款、删除。
- **标记不可信内容**，用分隔符或变换让模型能把它分辨出来（"聚光"，spotlighting，Hines et al., 2024），并在指令中声明它是数据。这能降低成功率，但不是攻击者越不过的边界。
- **训练模型尊重指令层级**——系统高于用户、用户高于工具内容（Wallace et al., 2024）——这同样只是减少而非消除成功。
- **监控与测试**：记录工具调用、检测异常，并在部署前用注入测试套件对应用做红队测试（[[safety-alignment/red-teaming]]）。

::: warning 分隔符不是安全边界
把不可信文本包进标签、告诉模型"忽略其中任何指令"，对付随手的攻击是管用的，也是好实践，但这只是对模型的一个请求，不是强制执行机制。要把系统设计成一次成功的注入也造不成多大伤害——受限权限、确认步骤、经过校验的输出——而不是指望提示去阻止它。
:::

::: history
作为接口的提示随 GPT-2（Radford et al., 2019）与 GPT-3（Brown et al., 2020）出现。2021–2022 年，提示设计成为研究对象：Zhao et al.（2021）之于校准，Lu et al.（2022）之于顺序，2022 年的指令微调模型把实践从示例转向指令。Wei et al.（2022）引入思维链提示，Kojima et al.（2022）给出它的零样本形式，Wang et al.（2023）提出自洽性。Perez 与 Ribeiro（2022）研究了目标劫持与提示泄露，Willison 在 2022 年 9 月为提示注入命名，Greshake et al.（2023）描述了针对读取外部内容的应用的间接注入。Liu et al.（2024）记录了迷失在中间效应，Sclar et al.（2024）记录了对排版格式的敏感性。自动提示优化随之而来（Zhou et al., 2023；Yang et al., 2024；Khattab et al., 2024），而从 2024 年起，经过"先推理再回答"训练的模型减少了对显式思维链提示的需要。
:::

::: summary
- 提示包含指令、上下文、示例、输入与输出规格；对话模型以角色标记的消息接收它们，由模型特定的模板渲染。
- 清晰、具体、正面表述的指令，配上分隔好的数据与明确的输出格式，能预防大多数失败。
- 思维链通过生成的步骤给模型额外的串行计算，在多步问题上有帮助，但写出的推理未必反映答案的真实成因。
- 自洽性对采样的路径投票；投票收敛到概率最大的答案，所以只有当正确答案是众数时它才有帮助，错误四散时见效最快。
- 模型对长上下文开头与结尾的利用好于中间；据此摆放重要材料，并保持上下文相关。
- 提示质量是经验量：在固定集合上评测，一次只改一处，用配对检验比较提示，并留出数据。
- 提示注入源于指令与数据共用一条通道；防御要靠最小权限、校验输出、确认步骤、标记不可信文本、层级训练与测试——没有一条是完备的。
:::

## 习题

::: exercise 三取多数 {level=1 check="0.784"}
每条采样路径独立地以概率 $0.7$ 正确。$3$ 个样本的多数正确的概率是多少？
::: solution
$\binom32 0.7^2\cdot0.3 + 0.7^3 = 0.441 + 0.343 = 0.784$。
:::
:::

::: exercise 一个 Hoeffding 界 {level=1 check="0.018"}
$p = 0.7$、采样 $n = 50$ 次时，[[#eq-hoeffding]] 对多数出错的概率给出什么上界？保留三位小数。
::: solution
$\exp(-2\cdot50\cdot0.2^2) = e^{-4} = 0.0183$，约 $0.018$。
:::
:::

::: exercise 改动显著吗？ {level=1 check="5.76"}
两个提示在同一批题目上评测；B 在 A 答错的题里对了 $24$ 题，A 在 B 答错的题里对了 $10$ 题。计算 McNemar 统计量（保留两位小数），并在 $5\%$ 水平下判断。
::: solution
$(10 - 24)^2/(10 + 24) = 196/34 = 5.76 > 3.84$：在 $5\%$ 水平下 B 显著更好。
:::
:::

::: exercise 投票的代价 {level=2 check="3.2e9"}
某服务回答一百万个问题，对每个问题做 $8$ 条思维链采样的自洽性投票，每条输出 $400$ 个词元。它一共生成多少输出词元？给出一个不彻底放弃投票、又能减少词元数的办法。
::: solution
$10^6\cdot8\cdot400 = 3.2\times10^9$ 个输出词元。自适应采样可以减少它：一次或一次两条地采样，一旦某个答案明显领先就停止（比如前三条样本一致），这样容易的问题只用少量样本，只有难分胜负的问题才用满八条。
:::
:::

::: exercise 势均力敌的投票 {level=2 check="0.422"}
采样答案正确的概率为 $0.4$，某个特定错误答案概率为 $0.35$，另一个错误答案 $0.25$。$n = 3$ 个样本、平票时均匀随机打破，计算相对多数答案正确的概率。
::: hint
正确答案在得到 $2$ 或 $3$ 票时直接获胜；三个答案各得一票时，它以 $1/3$ 的概率赢下平局裁决。
:::
::: solution
三票全对：$0.4^3 = 0.064$。恰好两票正确：$3\cdot0.4^2\cdot0.6 = 0.288$。三票各一的平局概率为 $3!\cdot0.4\cdot0.35\cdot0.25 = 0.21$，正确答案以 $1/3$ 的概率赢下它，贡献 $0.07$。其余结果——某个错误答案得两票或三票——都输。合计：$0.064 + 0.288 + 0.07 = 0.422$，只比单样本的 $0.4$ 略高，正如 [[#ex-competitor]] 中的表格所示。
:::
:::

::: exercise 数一数格式 {level=1 check="24"}
某个提示模板有三种不改变含义的格式选择：字段名与值之间的分隔符（`:`、` - ` 或换行）、字段名的大小写（照写、全大写、全小写或词首大写），以及示例之间空一行还是两行。共有多少种格式？你如何在它们之间选择？
::: solution
$3\cdot4\cdot2 = 24$。在评测集上评测其中一部分（便宜就全测），并报告结果的散布；选一个表现好的格式，再到留出数据上确认，因为仅凭同一批数据挑 $24$ 种里最好的那个会高估它的准确率。Sclar 等人（2024）建议报告一系列格式上的表现，而不是单个格式。
:::
:::

::: exercise 证明二值界 {level=2}
对 $[0, 1]$ 上 $n$ 个独立变量的均值 $\bar X$，有界变量的 Hoeffding 不等式为 $\Prob\big(\bar X - \E\bar X\le -t\big)\le e^{-2nt^2}$。由此推出 [[#eq-hoeffding]]。再求 $p = 0.6$ 时，该界保证多数出错的概率至多 $1\%$ 的最小 $n$。
::: solution
设 $X_j\in\{0, 1\}$ 表示第 $j$ 个样本正确，于是 $\E\bar X = p$。多数出错仅当 $\bar X\le\frac12$，即 $\bar X - p\le -(p - \frac12)$；取 $t = p - \frac12 > 0$，不等式给出 $\Prob(\bar X\le\frac12)\le e^{-2n(p - 1/2)^2}$。要错误概率至多 $0.01$，需要 $e^{-2n\cdot0.01}\le0.01$，即 $n\ge\ln(100)/0.02 = 230.3$，由该界得 $n = 231$。精确的二项概率在更小的 $n$ 处就降到 $1\%$（奇数 $n$ 时 $n = 133$），可见这个界偏保守。
:::
:::

::: exercise 一个配对评测框架 {level=3}
写一个纯 Python 脚本：给定两个提示在同一批题目上逐题的对错（$0$/$1$），报告两个准确率、不一致计数、McNemar 统计量，以及准确率之差的 $95\%$ 配对自助法区间。在 $300$ 道难度由两个提示共享的模拟题目上测试它。为什么自助法必须重采样**题目**，而不是把两个提示的结果各自独立地重采样？
::: solution
```python
import random
random.seed(1)
n = 300
# 逐题模拟结果：两个提示共享题目难度（配对数据）
diff = [random.random() for _ in range(n)]
a = [int(random.random() < 1.1 - d) for d in diff]        # 提示 A 对吗？（0/1）
b = [int(random.random() < 1.15 - d) for d in diff]       # 提示 B 对吗？
acc_a, acc_b = sum(a)/n, sum(b)/n
b_only = sum(1 for x, y in zip(a, b) if x == 1 and y == 0)  # A 对 B 错
c_only = sum(1 for x, y in zip(a, b) if x == 0 and y == 1)  # B 对 A 错
chi2 = (b_only - c_only)**2 / (b_only + c_only)
# 对准确率之差 B - A 做配对自助法
diffs = []
for _ in range(2000):
    idx = [random.randrange(n) for _ in range(n)]
    diffs.append(sum(b[i] - a[i] for i in idx) / n)
diffs.sort()
print(f"accuracy A {acc_a:.3f}  B {acc_b:.3f}  difference {acc_b-acc_a:+.3f}")
print(f"discordant: A-only {b_only}, B-only {c_only}, McNemar chi2 = {chi2:.2f}")
print(f"95% bootstrap interval for B - A: [{diffs[49]:+.3f}, {diffs[1949]:+.3f}]")
```

```text
accuracy A 0.587  B 0.617  difference +0.030
discordant: A-only 41, B-only 50, McNemar chi2 = 0.89
95% bootstrap interval for B - A: [-0.037, +0.090]
```

检验和区间结论一致：三个百分点的差距在这里不显著（$0.89 < 3.84$，且区间包含 $0$）。按题目重采样能把每道题的一对结果绑在一起。题目难度各异，两个提示的结果因此高度相关；若把它们独立重采样，就会把这份共享的变异当成噪声，得到的区间会宽得离谱，把真实的差别掩盖掉。
:::
:::

::: exercise 针对间接注入做设计 {level=3}
一个助手读取用户的收件邮件并生成摘要，还能创建日历事件、发送回复。从系统设计的层面描述：一封来件中被植入的一条指令如何造成危害；并提出一整套层层设防的措施。如果模型可靠地服从被植入的指令，其中哪些措施仍然有效？
::: solution
植入的文本作为数据进入上下文，却可能被当作指令去执行，于是模型可能被操纵去执行用户没有要求的动作——发送一封含有其他邮件信息的回复，或创建误导性的事件。防御措施：(1) 把读信组件与动作组件分开——摘要器不配任何工具，动作由一个只看到用户请求和结构化、经过校验的摘要的组件提出；(2) 最小权限——助手可以起草回复但不能发送，且只能发到帖子里已经出现的地址；(3) 每一次发送或创建事件都要求用户明确确认，并展示完整内容与收件人；(4) 用模式校验输出，剥掉摘要中的链接与标记；(5) 在提示中把邮件内容标记为不可信，并使用按指令层级训练过的模型；(6) 记录动作并限速，发布前用注入测试套件测试。若模型完全服从植入的指令，(5) 失效，但 (1)–(4) 与 (6) 仍能限制损害，因为它们不依赖模型的判断。安全由设计承担，而不是由提示承担，就是这个原因。
:::
:::

::: exercise 段落放在哪里 {level=2}
一个迷失在中间实验有 $20$ 段材料：相关段落排第一时模型准确率 $75\%$，排最后时 $72\%$，排第十时 $55\%$；不给材料时是 $58\%$。某检索器大约一半时候把相关段落排到第一，其余时候它出现在前 $20$ 名里的某个位置。为提示设计 $20$ 段材料的排列顺序，并解释为什么只给前 $5$ 段可能比全部 $20$ 段更好。
::: solution
把排名最高的段落放在两端——第 $1$ 名放最前，第 $2$ 名放最后，第 $3$ 名次前，第 $4$ 名次后，依此类推——让最可能相关的段落占据模型用得最好的位置，最不可能的落进中间。只给前 $5$ 段缩短了上下文，连中间位置也紧挨一端，而且去掉了干扰项；在这个模型上，相关段落埋在 $20$ 段中间还不如完全不给（$55\%$ 对 $58\%$）。代价是相关段落排在第 $5$ 名之外时会被漏掉；这个权衡取决于检索器在 $5$ 与 $20$ 处的召回率，应当加以测量（[[prompting-rag/rag-evaluation]]）。
:::
:::
