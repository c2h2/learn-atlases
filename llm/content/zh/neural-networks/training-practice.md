前面的几章给出了训练一次运行的全部材料：一个网络、一个损失、由反向传播得到的梯度、带调度的优化器、让信号保持合适尺度的初始化与归一化，以及正则化方法。本章讲的是把它们装配起来、让训练跑起来——以及跑不起来时找出原因。下面许多内容更像手艺而非理论，但这门手艺建立在能够确切说清的事实上：第零步的损失应该是多少，对微批取平均会对梯度做什么，一个 bfloat16 数有多少个比特、这对权重更新意味着什么，以及为什么同一个随机种子的两次运行结果仍可能不同。

重点在于及早发现问题的习惯。一次悄悄做着错误事情的训练是最昂贵的一类 bug：它可能要几天才暴露，而它的症状——损失略偏高——看起来像建模问题。Karpathy（2019）在那份广为流传的清单里说得直白：神经网络训练是“静默失败”的。对策是每个阶段都拿一个你能预测的数字去检验，从小的做起，一次只改一处。

## 数据流水线 {#sec-data}

训练数据要经过一条**流水线**（pipeline）：从存储读出、解码（图像、音频、文本）、变换（分词、裁剪、增强、标准化）、洗牌、组批，再拷贝到加速器上。流水线的三个性质关系到正确性。

- **切分。**训练、验证、测试数据必须在拟合任何东西之前分开，包括标准化所用的统计量和分词器的词表（[[ml-fundamentals/generalisation#def-splits]]）。跨切分的近似重复——同一张图缩放一遍、同一篇文档被抓取两次——会把测试信息泄漏进训练并虚高结果；大型语料库为此要做去重，同时也为了减少记忆。
- **洗牌。**SGD 的分析假设批次是随机样本。按顺序存放的数据（先是全猫、再是全狗；先是一个网站、再是下一个）必须洗牌，至少近似地洗，否则每个批次都有偏，损失曲线会显出周期性结构。数据大到无法在内存中洗牌时，用一个**洗牌缓冲区**（shuffle buffer）装下一段样例的窗口并从中采样，它只混合存放位置相近的样例——所以文件本身也要打乱。
- **标准化。**输入应有可比的尺度，通常按特征或通道化为零均值、单位方差，统计量在训练集上计算。对线性模型，损失的条件数——从而梯度下降的速度（[[math-for-ml/optimisation#sec-quadratic]]）——直接取决于特征的尺度；归一化层降低了深度网络对这一点的敏感度，但并没有消除它。

吞吐量同样要紧：加速器一旦等数据，本章别的一切都帮不上忙。加载器以并行的工作进程运行，并在处理当前批的同时**预取**后面的批；一个有用的最初测量，是把模型换成空操作后测出的每步耗时。

## 序列组批 {#sec-batching}

序列——句子、文档、音频片段——长短不一，而一个批次是矩形张量。标准的补救办法是用一个哑词元把每个序列**填充**（pad）到批内最长者，并传入一个标记哪些位置是真实的**掩码**（mask）。掩码有两个用途：在注意力里阻止真实词元注意填充（[[transformers/self-attention]]），在损失里把填充位置从平均中剔除。

::: example 填充的代价 {#ex-padding}
一批含四个序列，长度分别为$100$、$250$、$500$与$1{,}000$个词元，填充到$1{,}000$。有多大比例的计算花在填充上？减少它的方式有哪两种？
::: solution
这一批共有$4\cdot1{,}000 = 4{,}000$个位置，其中$100 + 250 + 500 + 1{,}000 = 1{,}850$个是真实的：$1 - 1{,}850/4{,}000 = 53.75\%$的位置是填充；而对代价随长度平方增长的注意力，浪费还要大。**分桶**（bucketing）把长度相近的序列分到同一批，每个只填一点点。**打包**（packing）把若干序列用一个文档结束词元隔开，拼接成若干定长行，完全不留填充；语言模型预训练通常打包，并可选地用注意力掩码阻止词元跨文档边界互相注意。
:::
:::

### 梯度累积 {#sec-accumulation}

当优化器本该看到的批次放不下内存时，把它拆成$k$个**微批**（micro-batch），逐个跑前向与反向、让梯度累加（在 PyTorch 里，`.backward()`会累加进`.grad`；[[neural-networks/automatic-differentiation#sec-systems]]），最后让优化器走一步。做对了这恰好等于大批量的梯度，但“对”字有一处微妙。

::: proposition 累积逐词元平均 {#prop-accumulation}
设一个含$N = \sum_{i=1}^kn_i$个词元的批被拆成含$n_i$个词元的各个微批，其逐词元平均损失为$\mathcal{L}_i = \frac1{n_i}\sum_{t\in\text{微批 }i}\ell_t$。整批逐词元平均$\mathcal{L} = \frac1N\sum_t\ell_t$的梯度为

$$
\nabla\mathcal{L} = \sum_{i=1}^k\frac{n_i}{N}\nabla\mathcal{L}_i,
$$

只有当所有$n_i$相等时，它才对一切损失都等于朴素的平均$\frac1k\sum_i\nabla\mathcal{L}_i$。
:::

::: proof
$\mathcal{L} = \frac1N\sum_i\sum_{t\in i}\ell_t = \frac1N\sum_in_i\mathcal{L}_i$，而梯度是线性的。若每个$n_i = N/k$，权$n_i/N$就都是$1/k$。否则取满足$\nabla\mathcal{L}_1\ne\nabla\mathcal{L}_2$的损失，两种加权便不同。
:::

长度不一的填充或打包序列，各微批的真实词元数*确实*不同，对它们的均值再取平均会高估短微批中词元的权重。改法是每个微批内把词元损失求和，最后再除以整批的词元总数$N$。广泛使用的训练库里发现并修复过正是这种 bug——这也是要在小模型上拿单个大批次来检验累积的一个理由。

::: example 有偏的累积 {#ex-accumulation}
两个微批的真实词元数为$100$与$900$，平均损失为$2.0$与$3.0$。正确的整批损失是多少？朴素平均报告什么？
::: solution
正确：$(100\cdot2.0 + 900\cdot3.0)/1{,}000 = 2.9$。朴素：$(2.0 + 3.0)/2 = 2.5$。朴素的梯度让第一个微批的$100$个词元中每一个的权重是第二个微批中词元的九倍——系统性地偏向短序列里恰好装着的东西。
:::
:::

## 混合精度 {#sec-precision}

加速器用16位浮点计算比32位快得多，16位数还把激活的内存与带宽减半。**混合精度**训练把大部分算术放在16位格式里做，而把需要精度的部分留在32位。

::: definition 训练中用到的浮点格式 {#def-formats}
一个有$e$个指数位、$m$个显式尾数（小数）位的二进制浮点格式表示规格化数$\pm(1.f_1f_2\dots f_m)_2\times2^E$；它的**机器 epsilon** $2^{-m}$是$1$与下一个可表示数之间的间隔。在用的格式：

| 格式 | 符号 / 指数 / 尾数位 | 最大有限值 | 最小规格化数 | epsilon $2^{-m}$ |
|---|---|---|---|---|
| float32（FP32） | $1/8/23$ | $3.4\times10^{38}$ | $1.2\times10^{-38}$ | $1.2\times10^{-7}$ |
| float16（FP16） | $1/5/10$ | $65{,}504$ | $6.1\times10^{-5}$ | $9.8\times10^{-4}$ |
| bfloat16（BF16） | $1/8/7$ | $3.4\times10^{38}$ | $1.2\times10^{-38}$ | $7.8\times10^{-3}$ |

Float16 另外还有小至$6.0\times10^{-8}$的非规格化数。
:::

Float16 精度更高但范围窄：超过约$65{,}504$的激活上溢为无穷，约低于$10^{-7}$的梯度下溢为零。Bfloat16（“brain floating point”，出自 Google Brain）保留了 float32 的指数，因此拥有 float32 的范围，代价是只剩$8$位精度（算上隐含的最高位$1$）。下图给出一个有效位$4$位的玩具格式，在一个每个可表示数都看得见的尺度上展示同样的结构。

::: widget floatline
p: 4
emin: -2
emax: 2
value: 1.3
caption: 有效位为$4$位的玩具二进制浮点格式的全部可表示数。间隔在每个$2$的幂处加倍，所以相对精度恒定，而绝对间隔不断拉大。Bfloat16 的有效位为$8$位：在$1$与$2$之间相邻数相差$1/128$，在$256$与$512$之间相差$2$。
:::

bfloat16 的精度正是权重要保留为 float32 的原因。优化器一步通常只把权重改动$10^{-3}$到$10^{-5}$的相对量——低于 bfloat16 的 epsilon。

::: proposition 不足半个 ulp 的更新会丢失 {#prop-swamping}
设$w > 0$可用 epsilon 为$2^{-m}$的浮点格式表示，且$2^E\le w < 2^{E+1}$，于是略高于$w$的可表示数的间隔为$u = 2^{E-m}$（一个**ulp**）。若$0 < \Delta < u/2$，则按就近舍入，$w + \Delta$舍回$w$。特别地，小于半个 ulp 的反复更新永远改不动存储的权重，不论更新多少次。
:::

::: proof
离$w + \Delta$最近的可表示数是$w$与$w + u$（因为$w + \Delta < w + u/2 < 2^{E+1}$把我们留在同一个二进制指数区间内，那里间隔为$u$）。它到$w$的距离是$\Delta < u/2$，到$w + u$的距离是$u - \Delta > u/2$，故舍入到$w$。每重复一次都从$w$重新开始、又舍回$w$。
:::

bfloat16 中$w = 1$时$u = 2^{-7} = 0.0078$，所以任何小于$0.0039$的更新都会丢失。因此混合精度训练保留一份 float32 的权重**主副本**，把更新加在它上面，再把它转成16位去做前向与反向；优化器状态也保存在 float32 里。

**损失缩放。**float16 下小梯度会下溢。Micikevicius et al.（2018）在反向传播之前把损失乘上一个缩放因子$S$（例如$2^{16}$）；由线性性，每个梯度都乘以$S$，被抬进 float16 的范围，再在更新之前于 float32 中除以$S$。**动态损失缩放**从一个大的$S$开始，梯度一出现溢出（无穷或 NaN）就把它减半——并跳过该步——而在连续若干步无溢出后翻倍。bfloat16 的范围就是 float32 的范围，不需要损失缩放，这是它成为大模型训练默认格式的主要原因（Kalamkar et al., 2019）。截至2026年，一些大规模训练还会在矩阵乘法的部分运算中使用8位浮点格式（E4M3 与 E5M2；Micikevicius et al., 2022），配以按张量或按块的缩放因子。

::: example 会溢出的 softmax {#ex-overflow}
一个 float16 的注意力层或输出层直接对 logits $\mathbf{z} = (12, 3, -1)$ 取指数来计算$\operatorname{softmax}(\mathbf{z})$。会发生什么？实现如何避免？
::: solution
$e^{12} = 162{,}755$超过了 float16 的最大值$65{,}504$（其对数为$11.09$），于是它变成无穷，和也是无穷，第一个分量得到$\infty/\infty = $ NaN——此后 NaN 传播进之后的每一次计算、每一个梯度。先减去最大值，$\operatorname{softmax}(\mathbf{z}) = \operatorname{softmax}(\mathbf{z} - 12)$，是对$(0, -9, -13)$取指数，全都不超过$1$，安全地给出$(0.99987, 0.00012, 0.0000023)$。即使输入是16位，程序库也在内部用 float32 计算 softmax 与 log-sum-exp。任何超过约$11$的 logit 都足以让朴素的 float16 softmax 上溢。
:::
:::

::: example 每个参数的内存 {#ex-memory}
估计一个$7\times10^9$参数的模型以混合精度训练所需的内存：bfloat16 权重与梯度、float32 主权重、float32 Adam 矩。激活另外计。
::: solution
每个参数：$2$字节（bfloat16 权重）$+ 2$（bfloat16 梯度）$+ 4$（float32 主权重）$+ 4 + 4$（Adam 的两个矩）$= 16$字节。对$7\times10^9$个参数：$1.12\times10^{11}$字节 $= 112$ GB——还没存任何一个激活，就已超过一块加速器通常的容量。这套每参数$16$字节的记账正是 Rajbhandari et al.（2020）所用的，他们的 ZeRO 方法把这些缓冲分片到各数据并行设备上，使每块设备只持有一部分（系统层面见[[inference]]与[[scaling]]）。
:::
:::

## 调试一次训练运行 {#sec-debugging}

### 预测最初的损失 {#sec-first-loss}

最有用的一项检验不花分文：在第一步之前算出损失，与一个未训练模型应得的值比较。

::: proposition 初始化时的损失 {#prop-initial-loss}
若一个$K$类 softmax 分类器输出的 logits $z_1, \dots, z_K$相互独立、均值为$0$、方差$\sigma^2$很小，且与标签无关，则它的期望交叉熵为

$$
\E\,\mathcal{L}\approx\ln K + \frac{\sigma^2}2\Big(1 - \frac1K\Big),
$$

当所有 logits 相等时恰为$\ln K$。
:::

::: proof
损失为$\operatorname{lse}(\mathbf{z}) - z_y$，其中$\operatorname{lse}(\mathbf{z}) = \ln\sum_ke^{z_k}$。若所有 logits 都等于$c$，它为$\ln(Ke^c) - c = \ln K$。一般地，把$\operatorname{lse}$在$\mathbf{0}$处二阶展开：它在该点的梯度是$\mathbf{1}/K$，黑塞矩阵是$\frac1KI - \frac1{K^2}\mathbf{1}\mathbf{1}^\top$（[[ml-fundamentals/logistic-regression#prop-softmax-grad]]），于是$\operatorname{lse}(\mathbf{z})\approx\ln K + \bar z + \frac1{2K}\sum_k(z_k - \bar z)^2$，其中$\bar z$为 logits 的均值。取期望，$\E\bar z = 0$，$\E z_y = 0$，$\E\sum_k(z_k - \bar z)^2 = (K - 1)\sigma^2$，即得公式。
:::

所以一个$10$类分类器应当从$\ln10 = 2.303$附近开始，二分类从$0.693$附近，一个词表为$50{,}257$的语言模型从$10.82$附近。最初的损失高得多，意味着 logits 太大——输出层的初始化太大，或输入没有标准化——头几百步会白白花在把它们压小上（“曲棍球杆式损失曲线”）。低得多通常意味着有 bug：标签泄漏进了输入，或者损失对错误的轴取了平均。若类别不平衡，理想的起点是类频率的熵，把输出偏置初始化为对数频率即可达到。

### 一串检验 {#sec-checks}

::: algorithm 启动一次新的训练运行 {#alg-bringup}
1. **检查数据。**在整条流水线之后、完全按模型看到的样子查看解码出的样例及其标签，包括增强与分词。
2. **核对最初的损失**，对照[[#prop-initial-loss]]；并在一个小模型上数值检查梯度（[[neural-networks/backpropagation#sec-gradcheck]]）。
3. **在单个批次上过拟合。**关掉正则化，用单个小批次训练；训练损失应降到几乎为零。若降不下去，就是模型、损失或优化器坏了——再多的数据也修不好。
4. **找学习率。**在对数刻度的学习率网格上跑几次短训练（或跑一次学习率指数增长的过程，即 Smith（2017）的“范围测试”），在损失停止改善或发散之点稍偏低的位置取值。
5. **逐步放大**：更多数据、更大模型、打开正则化、更长的调度——一次只改一处，并留一个可对照的基线。
6. **全程监控**训练与验证损失、学习率、全局梯度范数，以及每层的一些激活与权重统计量。
:::

下面的清单把第2、4步用在[[neural-networks/backpropagation#sec-code]]的圆盘与圆环问题上，网络是$2$-$16$-$2$的 tanh 网络、全批量梯度下降，然后对最佳学习率换五个种子重跑。

```python
import math, random

def make_rings(n, rng):                       # 类别 0：半径 1 的圆盘；类别 1：1.3-2 的圆环
    data = []
    for i in range(n):
        t = i % 2
        r = rng.uniform(0, 1) if t == 0 else rng.uniform(1.3, 2)
        a = rng.uniform(0, 2 * math.pi)
        data.append(((r * math.cos(a), r * math.sin(a)), t))
    return data

def train(lr, steps, seed, data, hidden=16):
    """Full-batch gradient descent on a 2-16-2 tanh MLP; returns the loss curve."""
    rng = random.Random(seed)
    W1 = [[rng.gauss(0, 1 / math.sqrt(2)) for _ in range(2)] for _ in range(hidden)]
    b1 = [0.0] * hidden
    W2 = [[rng.gauss(0, 1 / math.sqrt(hidden)) for _ in range(hidden)] for _ in range(2)]
    b2 = [0.0, 0.0]
    curve = []
    for step in range(steps):
        gW1 = [[0.0, 0.0] for _ in range(hidden)]; gb1 = [0.0] * hidden
        gW2 = [[0.0] * hidden for _ in range(2)]; gb2 = [0.0, 0.0]
        loss = 0.0
        for (x0, x1), y in data:
            h = [math.tanh(W1[j][0] * x0 + W1[j][1] * x1 + b1[j]) for j in range(hidden)]
            z = [sum(W2[k][j] * h[j] for j in range(hidden)) + b2[k] for k in range(2)]
            m = max(z); e = [math.exp(v - m) for v in z]; s = sum(e)
            loss += m + math.log(s) - z[y]
            dz = [e[k] / s - (k == y) for k in range(2)]
            for k in range(2):
                gb2[k] += dz[k]
                for j in range(hidden):
                    gW2[k][j] += dz[k] * h[j]
            for j in range(hidden):
                da = (dz[0] * W2[0][j] + dz[1] * W2[1][j]) * (1 - h[j] ** 2)
                gb1[j] += da; gW1[j][0] += da * x0; gW1[j][1] += da * x1
        n = len(data)
        curve.append(loss / n)
        if not math.isfinite(loss):
            break
        for j in range(hidden):
            b1[j] -= lr * gb1[j] / n
            for i in range(2):
                W1[j][i] -= lr * gW1[j][i] / n
        for k in range(2):
            b2[k] -= lr * gb2[k] / n
            for j in range(hidden):
                W2[k][j] -= lr * gW2[k][j] / n
    return curve

data = make_rings(200, random.Random(0))
print("learning-rate sweep, 300 full-batch steps (loss at steps 1 / 30 / 100 / 300):")
for lr in [0.01, 0.1, 1.0, 3.0, 10.0, 30.0]:
    c = train(lr, 300, seed=1, data=data)
    pts = [c[i] if i < len(c) else float("nan") for i in (0, 29, 99, 299)]
    print(f"  lr {lr:5.2f}: " + "  ".join(f"{v:7.4f}" for v in pts))
print("same lr 1.0, five seeds (loss at step 300):",
      " ".join(f"{train(1.0, 300, seed=s, data=data)[-1]:.4f}" for s in range(5)))
```

最初的损失是$0.6932$，与[[#prop-initial-loss]]预言的$\ln2 = 0.6931$吻合。在跨度达$3{,}000$倍的学习率之间，结果从几乎不动（$0.01$）到出色（$10$）再到坏掉（$30$：损失跳到$6.2$，网络最后卡死在$0.45$，多半是 tanh 单元饱和了）。可用的范围横跨两个数量级，而最佳值恰在不稳定边缘之下——学习率扫描的典型情形，也是它们要在对数刻度上做的原因。同一学习率下不同种子的最终损失从$0.017$到$0.024$：仅初始化就带来$40\%$的散布，这就是单次运行不能证明一个设置胜过另一个的原因。

### 解读损失曲线 {#sec-curves}

| 症状 | 可能的原因 |
|---|---|
| 损失为 NaN 或无穷 | 学习率过高；float16 上溢；手写的损失里有$\log0$或除以零；输入数值有问题 |
| 损失从一开始就平直 | 学习率太低；梯度到不了参数（计算图脱离、层被冻结、优化器的参数列表不对）；单元坏死或饱和 |
| 损失先降后持续上升 | 学习率对后期阶段太高；缺少衰减；不稳定性在累积 |
| 验证损失升而训练损失降 | 过拟合：需要更多数据、增强、正则化或早停 |
| 验证损失*低于*训练损失 | dropout 或增强只在训练时开启；或验证数据比训练数据更容易（或从其中泄漏） |
| 突发的孤立尖峰 | 某个异常的批次、高曲率区域里的一次大更新、注意力 logits 增长；Adam 的 $\beta_2$ 或 $\epsilon$ 太小 |
| 损失呈周期性模式 | 数据没有洗牌；轮次边界；反复出现的坏数据分片 |

**损失尖峰**是大型 Transformer 运行的典型问题。文献中报道的缓解措施包括梯度裁剪（[[neural-networks/optimisers#def-clipping]]）、更低的学习率、用 QK-归一化给注意力 logits 设界（[[transformers/transformer-block]]），以及操作性办法：PaLM 团队（Chowdhery et al., 2022）发现尖峰并非单个坏例所能致后，改为从尖峰前约$100$步的检查点重启、并跳过大约$200$到$500$个批次。**全局梯度范数**是最灵敏的早期预警：它常常在损失之前先上升。

::: warning 静默失败
最糟糕的 bug 不会崩溃。下面一些曾让真实项目损失数周：标签与输入各自打乱（模型只学会了类频率、别的什么都没学，损失就停在标签的熵上）；每个工作进程都复用同一个数据加载种子，于是每次“随机”增强都被一模一样地施加好几遍；验证时处于训练模式、dropout 开着；学习率调度按轮次定义、却按批推进，学习率几乎立刻归零；在对原始 logits 求损失的函数之前先套了一个`softmax`，于是 softmax 被施加了两次；以及在不带掩码的填充批次上计算评估指标。每一个都能产出一个训得起来的模型，只是差一些。在每个阶段和一个预测数字比对、和一个简单基线比对，就是防御。
:::

::: quiz
一个$1{,}000$类的图像分类器开始训练时损失为$45$。最可能的解释是什么？
- [ ] 学习率太低
- [ ] 模型对这个任务太小
- [x] 初始化时输出的 logits 太大，例如最后一层的权重或输入尺度不当
- [ ] 没有问题；最初的损失大是正常的
::: solution
由[[#prop-initial-loss]]，一个未训练的$1{,}000$类模型应从$\ln1000 = 6.91$附近开始。损失为$45$意味着网络在自信地犯错：有些 logits 比正确的大出几十个单位。常见原因是输出层初始化的尺度太大，或输入没有归一化（像素取在$0$–$255$而不是标准化过）。学习率与模型大小在第一步之前不可能影响损失。
:::
:::

## 可复现性 {#sec-reproducibility}

一个无法复现的结果无法调试、无法比较、无法信任。可复现性有两层：**重跑**——同样的代码在同样的硬件上应给出同样的数字；**复制**——用新的随机性重做应得到同样的结论。

**种子。**每一个随机性来源都需要种子：Python 与 NumPy 的生成器、框架的（在每块设备上）、数据加载器洗牌的、以及每个工作进程增强的。只设一个全局种子往往会漏掉其中一些。

**并行算术中的非确定性。**即使固定了所有种子，许多 GPU 核函数也不是确定性的，因为它们用原子操作累加求和、求和次序取决于线程调度，而浮点加法不满足结合律：float32 下$(10^8 + 1) - 10^8 = 0$而$(10^8 - 10^8) + 1 = 1$，因为 float32 在$10^8$附近的间隔是$8$（由[[#prop-swamping]]）。框架提供确定性模式（PyTorch 里是`torch.use_deterministic_algorithms(True)`），但要牺牲一些速度。分布式训练还增添别的来源：跨设备归约的次序，以及设备数目变化时批次划分方式的不同。

下面的清单演示本章的几个数值要点：bfloat16 与 float16 的舍入、不足半个 ulp 而丢失的更新、值依赖于求和次序的 float32 和，以及和$\ln K$对照的最初损失。

```python
import math, random, struct

# 1. 用 struct 模拟到 bfloat16 与 float16 的舍入（就近向偶数舍入）
def to_bf16(x):
    b = struct.unpack("<I", struct.pack("<f", x))[0]          # float32 位模式
    b = (b + 0x7FFF + ((b >> 16) & 1)) & 0xFFFF0000           # 保留 8 位指数 + 7 位尾数
    return struct.unpack("<f", struct.pack("<I", b))[0]
def to_fp16(x):
    try:
        return struct.unpack("<e", struct.pack("<e", x))[0]   # IEEE 半精度
    except OverflowError:
        return math.inf

print("value      bf16        fp16")
for v in [1.0 + 1e-3, 3.14159265, 1e-8, 70000.0]:
    print(f"{v:<10.8g} {to_bf16(v):<11.8g} {to_fp16(v):.8g}")

# 2. 低精度下小更新消失：往 1.0 连加一千次 1e-3
w_bf16, w_fp32 = 1.0, 1.0
for _ in range(1000):
    w_bf16 = to_bf16(w_bf16 + 1e-3)
    w_fp32 = struct.unpack("<f", struct.pack("<f", w_fp32 + 1e-3))[0]
print(f"1 + 1000 * 1e-3:  bf16 weights {w_bf16},  fp32 weights {w_fp32:.6f}")

# 3. 浮点加法不满足结合律：求和的次序会改变结果
rng = random.Random(0)
xs = [rng.gauss(0, 1) * 10 ** rng.randint(-3, 3) for _ in range(10000)]
def f32_sum(values):
    s = 0.0
    for v in values:
        s = struct.unpack("<f", struct.pack("<f", s + v))[0]  # 以 float32 累加
    return s
a, b = f32_sum(xs), f32_sum(sorted(xs))
print(f"float32 sum in two orders: {a:.6f} vs {b:.6f}  (exact {math.fsum(xs):.6f})")

# 4. 初始化时的损失：logits 为小随机数的 K 类 softmax
for K in [10, 1000, 50257]:
    losses = []
    for _ in range(200):
        z = [rng.gauss(0, 0.02) for _ in range(K)]
        m = max(z); lse = m + math.log(sum(math.exp(v - m) for v in z))
        losses.append(lse - z[0])
    print(f"K = {K:6d}: mean initial loss {sum(losses) / len(losses):.4f}   ln K = {math.log(K):.4f}")
```

```text
value      bf16        fp16
1.001      1           1.0009766
3.1415927  3.140625    3.140625
1e-08      1.0011718e-08 0
70000      70144       inf
1 + 1000 * 1e-3:  bf16 weights 1.0,  fp32 weights 2.000047
float32 sum in two orders: -48778.687500 vs -48778.699219  (exact -48778.617850)
K =     10: mean initial loss 2.3031   ln K = 2.3026
K =   1000: mean initial loss 6.9098   ln K = 6.9078
K =  50257: mean initial loss 10.8231   ln K = 10.8249
```

Bfloat16 分不清$1.001$与$1$，却保住了$10^{-8}$与$70{,}000$（在它的$8$位精度之内），而这两个数 float16 分别冲刷为零与上溢。一千次$10^{-3}$的更新让 bfloat16 权重停在恰好$1$——每一次都低于$0.0078$这个 ulp 的一半，正如[[#prop-swamping]]所说——而 float32 主副本到达$2.000047$（本身也略有偏差，来自 float32 的舍入）。同样$10{,}000$个数以两种次序在 float32 中求和，第五位有效数字就已不同，而且都不等于精确和。最初的损失与[[#prop-initial-loss]]在抽样噪声内一致。

**记录一切。**只有当运行的完整配置都被记录下来，它才是可复现的：代码版本（提交哈希）、全部超参数、数据版本与预处理、库与驱动版本、硬件、种子。**检查点**不仅应保存权重，还应保存优化器状态、学习率调度器、随机数生成器状态和数据流中的位置，这样恢复的运行才能恰好从停下的地方继续；用崭新的优化器矩恢复、或重开数据次序，是重启后损失尖峰的常见来源。

**跨种子的方差。**最后，复制结果需要知道：在与所测改动毫无关系的因素下，结果会波动多少。报告多个种子上的均值与散布，把小于种子间散布的差值当作噪声。上面学习率实验的五个种子在玩具问题上最终损失相差$40\%$；已发表的比较在更多种子、且给基线同等调参力度的重跑之下，差距一再缩水甚至消失。

::: history
训练的许多实践经验长期靠非正式途径口口相传。Yann LeCun、Léon Bottou、Genevieve Orr 与 Klaus-Robert Müller 的《Efficient BackProp》（1998）整理了关于输入标准化、初始化与学习率的建议；Léon Bottou 的《Stochastic gradient descent tricks》与 Yoshua Bengio 的《Practical recommendations for gradient-based training of deep architectures》（均为2012年）把它更新到深度学习时代。Leslie Smith 的学习率范围测试（2017）与 Andrej Karpathy 的《A recipe for training neural networks》（2019）成了从业者的标准参考。带损失缩放的混合精度训练由 Paulius Micikevicius 与合作者们描述（2018）；为 Google 的 TPU 引入的 bfloat16 由 Dhiraj Kalamkar 与合作者们针对深度学习训练做了分析（2019）。Samyam Rajbhandari 与合作们的 ZeRO（2020）处理了数据并行训练中优化器状态的内存问题，PaLM（2022）这类大规模运行的报告则记录了处理损失尖峰等操作性实践。
:::

::: summary
- **流水线**必须让各切分互不相通（包括预处理统计量）、正确洗牌、标准化输入，并让加速器吃饱。
- 变长序列要**填充并加掩码**，或分桶、**打包**；损失必须只对真实词元取平均。只有按词元数加权各微批的损失，**梯度累积**才等于大批量训练。
- **混合精度**用 bfloat16（float32 的范围、$8$位精度）或 float16（范围窄，需要**损失缩放**）计算，并保留 float32 主权重，因为不足半个 ulp 的更新会丢失；配 Adam 时约每参数$16$字节。
- **靠预测来调试**：$K$类模型的最初损失约为$\ln K$；在单个批次上过拟合；在对数刻度上扫描学习率；监控损失、梯度范数与激活统计量；会读损失曲线的症状。
- **可复现性**需要每一个种子、尽可能用确定性核函数（浮点加法不满足结合律）、完整的配置与检查点，以及跨多个种子报告结果。
:::

## 习题

::: exercise 一个预期的最初损失 {level=1 check="ln(100)"}
一个$100$类的分类器初始化得使 logits 几乎为零。它在训练前应报告多少损失？
::: solution
由[[#prop-initial-loss]]，$\ln100\approx4.605$纳特。
:::

::: exercise 填充的浪费 {level=1 check="1-(30+60+90+120)/(4*120)"}
长度$30$、$60$、$90$、$120$的四个序列被填充到$120$。有多大比例的位置是填充？
::: solution
真实词元：$480$个位置中$300$个，所以填充比例为$1 - 300/480 = 0.375$。
:::
:::

::: exercise 每个参数的字节数 {level=1 check="16*1.3e10"}
用[[#ex-memory]]的记账法，一个$13\times10^9$参数的模型的权重、梯度与 Adam 状态要占多少字节？
::: solution
$16\cdot1.3\times10^{10} = 2.08\times10^{11}$字节，约$208$ GB。
:::
:::

::: exercise bfloat16 的 ulp {level=2 check="2^(-7)*256"}
bfloat16 在$256$与$512$之间的间隔是多少？能改变$300$这个权重的最小更新是多少？填入间隔。
::: solution
尾数$m = 7$位时，$[2^E, 2^{E+1})$内的间隔是$2^{E-7}$；$E = 8$时为$2^{1} = 2$，即$2^{-7}\cdot256$。由[[#prop-swamping]]，小于其一半（即$1$）的更新会丢失（恰为$1$的更新是平局，按向偶数舍入解决）。所以 bfloat16 下任何小于$1$的更新都改不动$300$这个权重——相对变化$0.33\%$。
:::
:::

::: exercise 正确的累积 {level=2 check="(50*1.5+150*2.5+300*2)/500"}
三个微批的真实词元数为$50$、$150$、$300$，平均损失为$1.5$、$2.5$、$2.0$。整批损失是多少？朴素平均给出什么？填入整批损失。
::: solution
正确：$(50\cdot1.5 + 150\cdot2.5 + 300\cdot2.0)/500 = (75 + 375 + 600)/500 = 2.1$。朴素：$(1.5 + 2.5 + 2.0)/3 = 2.0$。
:::
:::

::: exercise 损失缩放 {level=2}
某个梯度分量为$3\times10^{-9}$。证明它在 float16 中下溢为零，而用$S = 2^{16}$做损失缩放后能被表示。若最大梯度分量为$0.5$，溢出对$S$加什么约束？
::: solution
Float16 的最小正值（非规格化）为$2^{-24}\approx6.0\times10^{-8}$；$3\times10^{-9}$不到它的一半，舍入为$0$。乘以$2^{16} = 65{,}536$后变为$1.97\times10^{-4}$，高于最小规格化数$6.1\times10^{-5}$，于是能以完整精度表示，在 float32 中除以$S$即可恢复。最大缩放分量必须保持在$65{,}504$以下：$0.5\,S < 65{,}504$，故$S < 131{,}008$，在$2$的幂中即$S\le2^{16}$。动态损失缩放通过在溢出时退让自动找到这条边界。
:::
:::

::: exercise 类别不平衡 {level=2 check="-(0.9*ln(0.9)+0.1*ln(0.1))"}
一个二分类问题中$90\%$的样例是负类。logits 为零的模型从多少损失起步？完全不看输入能达到的最好损失是多少？应如何初始化输出偏置才能从那里起步？填入最好的与输入无关的损失。
::: solution
零 logits 给出$p = \frac12$、损失$\ln2 = 0.693$。最好的与输入无关的预测是类频率，损失等于其熵，$-(0.9\ln0.9 + 0.1\ln0.1) = 0.325$。把输出偏置设为对数几率$\ln(0.1/0.9) = -2.197$（对正类用单个 logit）就让模型从那里起步，训练便不必把步数花在学习类频率上。
:::
:::

::: exercise 非结合性 {level=2}
在 float32（epsilon $2^{-23}$）中计算$(2^{24} + 1) - 2^{24}$与$(2^{24} - 2^{24}) + 1$。解释为什么一百万个 float32 数的并行求和会逐次运行而变化，以及为什么 bfloat16 矩阵乘法仍以 float32 累加为标准做法。
::: solution
$2^{24}$附近 float32 的间隔是$2^{24-23} = 2$，所以$2^{24} + 1$落在$2^{24}$与$2^{24} + 2$之间的平局，按向偶数有效位舍入取$2^{24}$；第一个表达式给出$0$，第二个给出$1$。并行归约以依赖调度的次序相加部分和，每种次序舍入不同，结果就可能在最后几位逐次运行而异；在训练过程中，这样的差异会被优化的混沌动力学放大，许多步之后各次运行出现可测的分歧。以 float32 累加乘积，可把长度为$n$的点积的舍入误差控制在相对$n\cdot2^{-24}$左右，而非$n\cdot2^{-8}$——$n$达几千时后者无法接受；所以硬件用 bfloat16 相乘、以 float32 累加。
:::
:::

::: exercise 可恢复的数据次序 {level=3}
一个训练任务在一轮共$100{,}000$步中于第$40{,}000$步被抢占，从一个只含权重与优化器状态、不含数据加载器状态的检查点恢复；加载器按自己的种子重新洗牌，从头开始这一轮。会出什么问题？数据次序应如何做成可恢复的？
::: solution
恢复后的运行会重走这一轮已经看过的$40{,}000$个批次（若洗牌相同），或已见与未见样例的随机混合（若不同），于是有些样例在本轮结束前被看两遍、有些一遍也没看；大规模下这会把训练偏向被重复的数据，可能表现为训练损失下凹、验证损失微升。更糟的是，若每次重启都换一种洗牌，看过的样例集合就失控了。改法是让数据次序成为（种子、轮次、步数）的确定性函数——例如由种子与轮次算出一个排列、以步数为下标索引——并把步数计数器（以及洗牌缓冲区的状态）存进检查点，使恢复时恰好跳过已消费的批次。
:::
:::

::: exercise 需要多少种子？ {level=3 check="2*0.003/sqrt(5)*sqrt(2)"}
两个配置各用$n = 5$个种子运行。最终准确率的种子间标准差两者都是$0.003$。两个均值之差大约要多大，才能超过其差的两倍标准误？若用$n = 20$个种子，答案如何变化？
::: solution
每个均值的标准误为$0.003/\sqrt5$，两个独立均值之差的标准误为$\sqrt2\cdot0.003/\sqrt5 = 0.0019$。两倍标准误是$2\sqrt2\cdot0.003/\sqrt5\approx0.0038$，所以低于约$0.4$个百分点的差与种子噪声无法区分。$20$个种子时阈值减半到约$0.0019$。许多已发表的改进就是这个量级，这就是结果应连同种子方差一起报告的原因（也是[[evaluation]]的评估方法重要的原因）。
:::
:::
