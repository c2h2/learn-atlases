一旦一个模型能作为智能体行动，就没有什么能阻止几个模型协同工作：一个智能体负责规划与分派，其他智能体并行搜索；一个「程序员」写代码，一个「审查者」批评它；三个实例各自独立回答同一个问题，再阅读彼此的答案、争论着趋于一致。这样的**多智能体系统**无论在实践上还是概念上都有吸引力。每个智能体都有自己的上下文窗口，因此一个团队能容纳的材料远多于单个智能体；相互独立的智能体可以并行工作；而分开的角色配上分开的指令，比一个庞大的提示更易于规定、测试和替换。它们同样很容易建得很糟——智能体们滔滔不绝地互相交谈、重复彼此的工作、在每一次交接处丢失信息，最后对错误的答案自信地达成一致。

本章采取一种有用的看法：多智能体系统是一个设计选择，其代价可以计算，其好处必须证明。我们从多智能体系统的经典理论（Wooldridge，2009）讲起，然后描述实践中最主要的三种模式——编排者–执行者、角色分解与辩论——并给出解释它们各自何时有效的分析：针对独立智能体的孔多塞陪审团定理、破坏这一定理的误差相关，以及不同拓扑下的通信代价。接着我们回顾证据，包括模型实例之间的辩论（Du 等，2023）、作为对齐方案的辩论（Irving 等，2018），以及关于多智能体系统为何失败的研究；最后讨论什么时候该用多个智能体、什么时候不该。正文配有一个普通 Python 模拟，计算有无共享误差时的多数投票准确率，以及通信的词元代价。

## 智能体之间 {#sec-mas}

多智能体系统在语言模型出现之前很久就是人工智能的一个领域，研究自主的软件智能体如何协调、谈判与竞争（Wooldridge，2009）。它的核心区分可以原样搬过来：**合作型**系统，其中的智能体共享由同一个设计者设定的同一个目标；以及**自利型**系统，其中的智能体代表不同的当事方——买方与卖方、相互竞争的公司——必须用博弈论来分析。到目前为止建成的语言模型多智能体系统几乎都是合作型的：一个开发者、一个目标、若干模型实例。为不同的人行动、与对方的智能体相互谈判的智能体，是一个正在兴起也更难的情形，也正是关于机制与协议的经典理论最有用武之地之处。

::: definition 多智能体系统 {#def-mas}
一个（语言模型的）**多智能体系统**由以下部分构成：智能体 $1, \dots, n$，每个都是一个智能体循环（[[agents/agent-loops#def-loop]]），有自己的系统提示（它的**角色**）、工具集、上下文，还可能有自己的模型；一个**通信拓扑**，即一个有向图，其边 $i\to j$ 表示智能体 $i$ 的消息会进入智能体 $j$ 的上下文；以及一个**协议**，规定智能体何时运行、消息包含什么，以及系统的最终输出如何产生。除了消息之外什么都不共享的智能体拥有**分离的上下文**；到达智能体 $j$ 的信息，恰好就是它的入边所携带的东西。
:::

最后这句话是整个题目的要害。分离的上下文既是主要的好处——每个智能体的上下文都保持短小、聚焦——也是主要的隐患：每条消息都是对发送者所知内容的一次压缩，而发送者漏掉的东西，接收者永远无从知道。单个智能体只有一个上下文，绝不会同自己沟通失误。

经典文献还提供了在现代系统中反复重现的协议。**契约网协议**（contract net protocol，Smith，1980）用公告与投标来分配任务：管理者发布任务，承标者按自身能力出价，管理者授予合同——这实质上就是编排者–执行者模式的早期版本，其中的执行者自己判断是否适合某项任务。**黑板架构**让智能体通过共享的工作区而不是直接的消息来通信，与今天的智能体共享文件或任务板如出一辙。

## 三种模式 {#sec-patterns}

### 编排者与执行者

::: definition 编排者–执行者 {#def-orchestrator}
在**编排者–执行者**模式中，一个主导智能体（编排者）接收任务，把它分解（[[agents/planning]]）为子任务，并启动若干执行者智能体，每个都带一份说明其子任务、预期输出和各种约束的任务书。执行者各自独立、常常并行地运行，各在自己的上下文里、使用自己的工具，返回一个浓缩后的结果。编排者整合这些结果，还可能再启动更多执行者，直到产出最终输出。其拓扑是一个星形：执行者只与编排者通信。
:::

这种模式适合宽而不深的任务：从多个来源调研一个问题、审阅许多文件、对同一个问题尝试几种进路。每个执行者可以读入几万词元再返回几百词元，于是编排者的上下文里装的是结论而不是原材料——这是 [[agents/memory-context]] 所述上下文管理的一种形式，只不过「摘要器」成了一个个完整的智能体。Anthropic 对其多智能体研究系统的描述（2025）是一份有教益的厂商报告：报告称，在该公司的内部研究评估中，带并行执行者的编排者大幅胜过单个智能体，而消耗的比普通对话多出许多倍的词元——按他们的说法约十五倍——并且在某个浏览基准上，性能差异的大部分可以由所用词元数来解释。这份报告的两半都要紧。更多的智能体买来了更多的总上下文和更多的并行搜索，这对广度优先的任务是实实在在的好处；而其中大部分好处是用算力买来的，因此公平的对照是把同样的词元预算交给单个智能体（[[#sec-evidence]]）。

::: example 编排式搜索的延迟 {#ex-latency-team}
一个研究任务需要 $75$ 个使用工具的阅读步骤，可以分成 $5$ 个相互独立的部分，每部分 $15$ 步。每一步耗时 $6$ 秒。编排者规划与写任务书需要 $2$ 步，汇总各份报告需要 $3$ 步。比较一个智能体包办一切与编排团队所需的墙钟时间，并算出加速比。
::: solution
单个智能体：$75\cdot6 = 450$ 秒。团队：规划 $2\cdot6 = 12$ 秒，然后五个执行者并行，$15\cdot6 = 90$ 秒，再汇总 $3\cdot6 = 18$ 秒，合计 $120$ 秒。加速比为 $450/120 = 3.75$，尽管执行者有 $5$ 个却不到 $5$ 倍，因为编排者的步骤是顺序进行的——这与阿姆达尔定律结构相同。若各部分不均衡，最慢的执行者决定节奏（[[agents/function-calling#prop-rounds]]）。
:::
:::

写任务书是编排者最难的工作。告诉执行者「调研热泵市场」，它会交回点什么；告诉它哪些国家、哪些年份、什么格式、避开哪些来源、其他执行者负责什么，它才会交回可用的东西。任务书没写清楚，结果就是重复劳动、执行者之间的空档，以及形式互不兼容的成果。

### 角色分解

第二种模式给智能体分配模仿人类团队的固定**角色**，把它们接成一条流水线或一个小图。ChatDev（Qian 等，2024）与 MetaGPT（Hong 等，2024）把软件开发组织成一家虚拟公司——产品经理、架构师、程序员、测试员——在角色之间传递结构化的制品（需求、设计、代码、测试报告）；MetaGPT 特别强调标准作业程序，让每一次交接都有规定的格式。更简单的双角色设计很常见：**生成者–审查者**（generator–critic）配对，一个智能体起草，另一个对照标准评审，反复进行直到审查者认可或预算用尽（这就是 [[agents/agent-loops#sec-agent]] 的评估者–优化器工作流）。

角色的帮助有两方面，两者很容易混淆。分开的提示使行为专门化——被指示去找毛病的一个评审，比被要求「检查自己的工作」的生成者更始终如一地寻找毛病。而分离的上下文让审查者以新鲜的眼光看问题，不受产生这份草稿的推理的污染。这两者都不需要不同的*模型*；同一个模型换两套提示就能兼得。

### 辩论与投票

第三种模式让多个智能体做*同一*个问题，再把答案合起来。最简单的合并办法是投票。

::: proposition 独立智能体的多数投票（孔多塞） {#prop-condorcet}
设 $n$ 为奇数，$n$ 个智能体各自独立地以概率 $p$ 答对一道二元问题。多数答案正确的概率为
$$
M_n(p) = \sum_{k = (n+1)/2}^{n}\binom{n}{k}p^k(1 - p)^{n - k}.
$$ {#eq-majority}
若 $p > \frac12$，则 $M_n(p)\ge1 - \exp\!\big(-2n(p - \tfrac12)^2\big)$，于是 $n\to\infty$ 时 $M_n(p)\to1$；若 $p < \frac12$，则 $M_n(p)\to0$。
:::

::: proof
正确智能体的个数 $K$ 服从 $\Bin(n, p)$，而当 $K\ge(n + 1)/2$ 时多数正确，这就给出了 [[#eq-majority]]。多数出错仅当 $K\le n/2$，即 $K/n - p\le-(p - \frac12)$。由 $[0, 1]$ 上 $n$ 个独立变量的均值的 Hoeffding 不等式，对 $t > 0$ 有 $\Prob(K/n - p\le-t)\le e^{-2nt^2}$；取 $t = p - \frac12$ 即得所求界。对 $p < \frac12$，把同一论证用于错误答案——错误答案这时构成期望中的多数。
:::

这就是**孔多塞陪审团定理**（Condorcet，1785），它是集成方法的数学论据，也是自洽性（[[reasoning/self-consistency]]）有效的缘故。但它的假设也恰恰是多智能体系统达不到它的地方。建立在同一个模型上、给定同一个提示的智能体，会因为同样的原因在同一批输入上出错；它们的误差是相关的，而相关为数量所能带来的好处设置了上限。

::: proposition 带共因误差的投票 {#prop-correlated}
设以概率 $\rho$，全部 $n$ 个智能体给出同一个答案，该答案以概率 $p$ 正确（一次共享的失败或成功，比如问题在所有智能体身上引发了同一个误解）；否则它们像 [[#prop-condorcet]] 中那样独立作答。则多数答案正确的概率为
$$
\rho\,p + (1 - \rho)\,M_n(p)\ \xrightarrow[n\to\infty]{}\ 1 - \rho\,(1 - p)\qquad (p > \tfrac12).
$$ {#eq-correlated}
:::

::: proof
按共享模式是否发生作条件。以概率 $\rho$ 所有答案一致，此时多数正确的概率为 $p$；以概率 $1 - \rho$ 智能体相互独立，此时多数正确的概率为 $M_n(p)$。全概率公式给出该表达式，而 $M_n(p)\to1$ 给出极限 $\rho p + 1 - \rho = 1 - \rho(1 - p)$。
:::

::: widget distribution
dist: binomial
params: n=5, p=0.7
a: 3
b: 5
caption: $n$ 个相互独立的智能体中答案正确的个数，每个智能体以概率 $p$ 答对。阴影区域（五个中至少三个）是多数正确的概率：$M_5(0.7) = 0.837$（[[#prop-condorcet]]）。增大 $n$（让 $a$ 保持为多数），可看到概率趋近 $1$；把 $p$ 调到 $\frac12$ 以下，多数就可靠地错。这个模型假设独立性，而共享同一个模型和同一个提示的智能体恰恰违反独立性（[[#prop-correlated]]）。
:::

::: example 测量共因概率 {#ex-rho}
某个模型的一个实例在某个基准上答对 $81\%$；五个实例的多数投票答对 $83\%$。在 [[#prop-correlated]] 的模型下，估计 $\rho$，并预测二十五个实例的多数投票的准确率。
::: solution
若投票者相互独立，应有 $M_5(0.81) = 0.949$。解方程 $0.83 = 0.81\rho + 0.949(1 - \rho)$ 得 $\rho = (0.949 - 0.83)/(0.949 - 0.81) = 0.857$。二十五个实例时，$M_{25}(0.81)\approx1$，于是预测为 $0.81\cdot0.857 + 1\cdot0.143 = 0.837$——比五个好不了多少。这个模型很粗糙（真实的相关并非全有或全无），但结论是稳健的：当五个投票者带来的收益已经很小时，更多投票者带来的收益只会更小。
:::
:::

**辩论**比投票更进一步：让智能体彼此看见、彼此回应。Du 等（2023）让同一个模型的若干实例回答一个问题，然后让每个实例看到其他实例的答案并更新自己的答案，如此进行若干轮，最终答案由多数投票产生。他们报告，与包括自我反思在内的单模型基线相比，算术与小学数学题上的准确率提高了，人物传记中的事实准确性也更好。智能体互相纠错的设想很吸引人，但要紧的对照必须在算力相等之下：$n$ 个智能体进行 $R$ 轮共产生 $nR$ 个答案，而干脆独立采样 $nR$ 个答案再投票就是一个很强的基线。做过这一对照的研究（例如 Smit 等，2024）发现，在相当的预算下，多智能体辩论并不能可靠地胜过自洽性与其他集成策略，其结果还对若干超参数——如轮数、以及在多大程度上鼓励智能体达成一致——很敏感。交换答案还可能*增大*相关：一个自信的错误答案可以说服其余智能体，把彼此独立的错误变成一个共同的错误。

辩论在对齐研究中另有一层含义。Irving、Christiano 与 Amodei（2018）提出了**通过辩论实现 AI 安全**（AI safety via debate）：两个高能力的智能体就一个问题的正反两面辩论，由人类裁判裁定哪一方更真实、更有帮助；若以获胜为目标来训练，每个智能体都会受到激励去揭发对方的错误与欺骗，于是一个自己回答不了问题的裁判，仍然可以裁判这场辩论。他们以复杂性理论中的交互式证明作类比论证：在最优博弈之下，辩论能让一个能力有限的裁判裁定远超其自身能力的问题。这是一个关于训练与监督的方案（[[safety-alignment/scalable-oversight]]），结构是零和的、对抗性的，不应与 Du 等的合作式答案交换混为一谈；关于它在语言模型上的实证检验，安全课程中有讨论。

::: example 辩论划算吗？ {#ex-debate}
三个智能体各以概率 $0.7$ 答对一道题。(a) 若它们相互独立，多数投票的准确率是多少？(b) 若以概率 $0.4$ 它们共享一个共因回应呢？(c) 一轮两回合的辩论的花费相当于 $6$ 个独立样本；同样花费下，$7$ 个独立样本（多出一个用来打破平局）的多数投票能达到多少准确率？
::: solution
(a) $M_3(0.7) = 0.7^3 + 3\cdot0.7^2\cdot0.3 = 0.343 + 0.441 = 0.784$。(b) $0.4\cdot0.7 + 0.6\cdot0.784 = 0.28 + 0.4704 = 0.750$。(c) $M_7(0.7) = \sum_{k=4}^{7}\binom7k0.7^k0.3^{7-k} = 0.2269 + 0.3177 + 0.2471 + 0.0824 = 0.874$。三个智能体的辩论要达到大约 $87\%$，才能赢过对独立样本投票这个更便宜的方案——而若样本共享共因误差，这两个数都会因同一个机制而低于上述数值。
:::
:::

### 投票与通信的模拟

下面的清单检验 [[#eq-majority]] 及其 Hoeffding 界，模拟共因概率 $\rho = 0.5$ 的投票，并数一数两种拓扑下每轮通信读入的词元。

```python
import random
from math import comb, exp

def majority_exact(n, p):
    """n 个相互独立的投票者中严格多数正确的概率，n 为奇数。"""
    return sum(comb(n, k) * p**k * (1 - p)**(n - k) for k in range(n // 2 + 1, n + 1))

def majority_sim(rng, n, p, rho, trials=100_000):
    """以概率 rho 所有智能体共享同一次抽取（一个共因误差源）；
    否则它们独立作答。每次抽取以概率 p 正确。"""
    wins = 0
    for _ in range(trials):
        if rng.random() < rho:
            wins += rng.random() < p
        else:
            wins += sum(rng.random() < p for _ in range(n)) > n // 2
    return wins / trials

rng = random.Random(42)
p = 0.7
for n in (1, 3, 5, 9, 15):
    hoeff = 1 - exp(-2 * n * (p - 0.5) ** 2)
    print(f"n={n:2d} exact {majority_exact(n, p):.4f}  Hoeffding bound {hoeff:.4f}  "
          f"sim rho=0 {majority_sim(rng, n, p, 0.0):.4f}  rho=0.5 {majority_sim(rng, n, p, 0.5):.4f}")

# 每轮通信读入的词元：消息长 L 个词元，n 个智能体。
L = 500
print("n  broadcast  orchestrator")
for n in (2, 4, 8, 16):
    broadcast = n * (n - 1) * L          # 每个智能体都要读其他所有智能体的消息
    star = 2 * (n - 1) * L               # 编排者读 n-1 份报告；每个执行者读 1 份任务书
    print(f"{n:2d} {broadcast:9d} {star:12d}")
```

```text
n= 3 exact 0.7840  Hoeffding bound 0.2134  sim rho=0 0.7847  rho=0.5 0.7430
n= 5 exact 0.8369  Hoeffding bound 0.3297  sim rho=0 0.8360  rho=0.5 0.7682
n= 9 exact 0.9012  Hoeffding bound 0.5132  sim rho=0 0.9032  rho=0.5 0.8026
n=15 exact 0.9500  Hoeffding bound 0.6988  sim rho=0 0.9506  rho=0.5 0.8239

```

独立的智能体严格沿着精确曲线走；Hoeffding 界成立，但对小的 $n$ 很松。当共因一半时间发生时，十五个智能体只达到 $0.82$，已经接近 [[#eq-correlated]] 的上限 $1 - 0.5\cdot0.3 = 0.85$：超过寥寥几个之后，再多买不来什么。词元的计数则显示了智能体之「多」的另一重代价。

## 通信的代价 {#sec-communication}

::: proposition 两种拓扑下每轮的词元数 {#prop-topology}
在 $n$ 个智能体的一轮通信中，设每条消息长 $L$ 个词元。若每个智能体都向其余所有智能体广播（完全图），智能体们总共读入 $n(n - 1)L$ 个词元。在一个由一个编排者和 $n - 1$ 个执行者构成的星形中，编排者向每个执行者发一份任务书、每个执行者交回一份报告，智能体们总共读入 $2(n - 1)L$ 个词元。若每条消息一旦读过就留在各读者的上下文里、直至其余各轮结束，那么在 $R$ 轮里，智能体读入的输入总量在两种拓扑下都按 $R^2$ 增长。
:::

::: proof
完全图中，$n$ 条消息中的每一条都被 $n - 1$ 个智能体读到。星形中，$n - 1$ 份任务书各被一个执行者读到，$n - 1$ 份报告都被编排者读到，共 $2(n - 1)$ 次读入。若消息不断累积，第 $r$ 轮中每个读者的上下文就含有第 $1, \dots, r$ 轮的消息，于是第 $r$ 轮读入的词元数与 $r$ 成正比，$R$ 轮的总量正比于 $\sum_{r=1}^{R}r = R(R + 1)/2$。
:::

::: widget plot

x: 2, 20
y: 0, 200
sliders: L=500:100:2000:50
labels: 完全图 $n(n-1)L$; 编排者星形 $2(n-1)L$

caption: 一轮通信中读入的词元数（以千计）随智能体数 $n$ 的变化，消息长 $L$ 个词元（[[#prop-topology]]）。广播按二次增长，星形按线性增长；$16$ 个智能体、每条消息 $500$ 词元时，两者相差八倍。标注的点是清单中算出的值。通信的二次增长是辩论只用少量智能体、少量轮数，而大系统采用层级结构的原因之一。
:::

词元只是看得见的代价。每条消息都是一次有损摘要，于是信息随每一跳不断衰减；互相等待的智能体增加延迟；而相互作用的智能体越多，它们对任务状态产生分歧的方式也越多。Cemri 等（2025）分析了若干开源多智能体框架在编码与推理任务上的执行轨迹，把它们的失败归入三大类：**规格与系统设计**问题（智能体不服从自己的角色或任务、步骤重复、丢失对话历史、不知道终止条件）、**智能体之间的错位**（隐瞒信息、无视其他智能体的输入、推理与行动不一致、从任务上脱轨）与**任务检验**（过早终止、对结果缺少检验或检验出错）。其中许多都是单个智能体不可能有的通信失败。

::: example 一个研究团队的代价 {#ex-team}
一个编排者启动 $5$ 个执行者。每个执行者在 $15$ 步里读入 $60{,}000$ 词元的材料（其上下文从 $3{,}000$ 起、每步增长 $4{,}000$），交回一份 $1{,}000$ 词元的报告。编排者自己的上下文为 $8{,}000$ 词元，另加各份报告。估算输入词元总数，并与这样一个智能体比较：它在同一个上下文里自己完成全部阅读，使用观察清除、让每个阅读步只留下 $800$ 词元的笔记。
::: solution
每个执行者：$15\cdot3{,}000 + 4{,}000\cdot\frac{14\cdot15}{2} = 45{,}000 + 420{,}000 = 465{,}000$ 词元；五个执行者 $2{,}325{,}000$。编排者：设约 $3$ 次调用，每次约 $8{,}000 + 5{,}000 = 13{,}000$ 词元，共 $39{,}000$。合计约 $236$ 万。单个智能体要走 $75$ 步；有了清除，其上下文从 $8{,}000$ 起每步增长 $800$，于是读入 $75\cdot8{,}000 + 800\cdot\frac{74\cdot75}{2} = 600{,}000 + 2{,}220{,}000 = 282$ 万词元，结束时上下文接近 $67{,}000$ 词元。两者总数相近；差别在别处。团队大约只需一个执行者的时间（$15$ 个顺序步骤而不是 $75$ 个），并且每个上下文都保持短小；单个智能体则能同时看到全部材料，并把没有任何一个执行者曾同时看到的各处发现联系起来。
:::
:::

## 更多智能体何时有帮助，何时有害 {#sec-evidence}

截至 2026 年，证据并不齐整：许多论文报告了特定多智能体设计的收益，但很少有把它们与单智能体在同等预算下比较的，整个领域也尚未形成共识。有三个规律的支持算得上比较充分。

- **广度优先、可并行的任务获益。**当任务能分成许多各自需要大量阅读的独立部分——搜索许多来源、审阅许多文件——带分离上下文的并行执行者既缩短延迟，又让每个上下文保持聚焦。这类场景报告出的收益很大，上面的厂商报告就是一例，尽管词元代价往往高得多。
- **集成的帮助程度取决于误差的独立程度。**同一个模型各实例之间的投票与辩论表现得像自洽性，其好处受相关误差的限制（[[#prop-correlated]]）；多样性——不同的模型、不同的提示、不同的信息来源——才是让额外智能体变得值钱的东西。
- **紧耦合的任务受害。**当每个部分都依赖在其他部分中做出的决定——写一段前后一致的代码、执行一段长的顺序流程——把作业分给带分离上下文的智能体会成倍放大交接损失和相互冲突的决定。正因如此，构建代码智能体的实践者主张：一个上下文管理得当的单智能体——也许只为孤立的只读调查动用子智能体——比一队平起平坐、共同修改同一份代码的智能体更可靠。

实践规则由此而来：先从一个智能体开始；为可并行、可分离、读得多的子任务加执行者；当独立评审有价值时，加一个在分离上下文里的审查者；只在成员足够多样时使用投票；并把每个多智能体设计与拿到同等总预算的单智能体作比较。

::: warning 一致不是证据
几个智能体达成一致时，人们很容易把这种一致当作确认。但若它们共享模型、共享提示、读同样的来源，它们的一致更接近一个意见被说了好几遍；而若它们已经读过彼此的答案，那可能只是一个智能体的意见被其余智能体采纳了。独立性必须靠设计创造出来——不同的模型或提示、分开的信息来源、先作答再看别人的——而最终答案能对照世界检验时，仍然要检验。
:::

::: application 智能体之间的协议
由不同各方建造的智能体需要一种共同语言来互相分派任务，正如工具曾经需要的那样（[[agents/function-calling#sec-protocols]]）。2025 年 4 月 Google 宣布了 **Agent2Agent**（A2A）协议，其后捐给了 Linux 基金会：智能体在其中发布自己能力的描述、接受任务、交换消息与制品，并为长时间运行的任务报告状态。与工具协议一样，它标准化的是接口而非行为，并提出经典自利型多智能体文献的那些问题：一个智能体代表谁行事、它可以向对方的智能体披露什么，以及智能体之间的承诺如何核验。
:::

::: quiz
一个团队建了一个系统：同一个模型的五个实例用同一个提示回答医疗编码问题，然后进行多数投票。准确率从单个实例的 $81\%$ 升到 $83\%$。什么解释了这么小的增益？什么改动最可能有帮助？
- [ ] 五个太少了；五十个实例时准确率会接近 $100\%$。
- [x] 各实例的误差高度相关；应让成员多样化（不同的模型或提示，或各自检索不同的证据），或加入一道独立的检查。
- [ ] 多数投票是错误的规则；系统应采用最长的那个答案。
- [ ] 各实例应辩论更多轮，直到全部达成一致。
::: solution
若成员独立、$p = 0.81$，五个投票者本应达到约 $0.95$（[[#prop-condorcet]]）；$0.83$ 说明共因误差严重，这靠更多副本解决不了（[[#prop-correlated]]）。只有多样性直接对准相关性。辩论更多轮往往增加一致，而不是独立。
:::
:::

::: history
多智能体系统在 1980 年代随分布式问题求解成为人工智能的一个领域：Smith 的契约网协议（1980）、Hearsay-II 这样的黑板系统，以及后来 1990 年代的信念–愿望–意图架构与智能体通信语言（KQML、FIPA-ACL），后来汇集于 Wooldridge 的教科书（2002；第 2 版 2009）。孔多塞的陪审团定理早在 1785 年就已提出。Irving、Christiano 与 Amodei 在 2018 年提出了通过辩论实现 AI 安全。到了语言模型时代，Park 等（2023）模拟了一个生成式智能体社区；Li 等（CAMEL，2023）研究成对角色扮演智能体；Du 等（2023）与 Liang 等（2023）提出用多智能体辩论改进推理与事实性；Qian 等（ChatDev）与 Hong 等（MetaGPT）把软件开发组织成角色化的团队（2023 年，2024 年发表）；而 AutoGen（Wu 等，2023）这类构建对话式多智能体应用的框架得到广泛使用。Smit 等（2024）在同等预算下把辩论策略与集成加以比较，Anthropic 在 2025 年描述了他的编排者–执行者研究系统，Cemri 等（2025）编目了多智能体的失败模式，Google 则于 2025 年 4 月宣布了 Agent2Agent 协议。
:::

::: summary
- 多智能体系统是若干带分离上下文的智能体循环，由通信拓扑与协议连接起来；每条消息都是对发送者所知内容的一次有损摘要。
- 编排者–执行者（星形）适合宽而可分的任务：并行的执行者带着聚焦的上下文返回浓缩的结果；任务书是最要紧的接口。
- 角色分解使行为专门化，并给审查者新鲜的上下文；它并不要求使用不同的模型。
- $n$ 个准确率为 $p > \frac12$ 的独立智能体的多数投票收敛到确定性（孔多塞），误差不超过 $e^{-2n(p - 1/2)^2}$；共因概率 $\rho$ 把准确率封顶在 $1 - \rho(1 - p)$。
- 实例之间的辩论（Du 等，2023）改进了某些任务，但在同等算力下不能可靠地胜过集成；作为对齐方案的辩论（Irving 等，2018）则是一种对抗性的监督方案，是另一回事。
- 人人广播的通信每轮花 $n(n - 1)L$ 词元，星形花 $2(n - 1)L$；交接还会丢失信息，并制造智能体之间的故障。
- 默认用一个智能体；为可并行的读得多的子任务加执行者，为独立评审加审查者，为投票配备多样的成员；并在同等预算下与单智能体比较。
:::

## 习题

::: exercise 三个投票者 {level=1 check="0.784"}
三个相互独立的智能体各以概率 $0.7$ 正确。多数正确的概率是多少？
::: solution
$0.7^3 + 3\cdot0.7^2\cdot0.3 = 0.343 + 0.441 = 0.784$。
:::
:::

::: exercise 广播的代价 {level=1 check="28000"}
八个智能体在一轮中各向其余所有智能体广播一条 $500$ 词元的消息。总共读入多少词元？
::: solution
$8\cdot7\cdot500 = 28{,}000$ 词元（[[#prop-topology]]）。
:::
:::

::: exercise 相关时的极限 {level=1 check="0.88"}
各智能体以概率 $0.8$ 正确，并以概率 $0.6$ 共享一个共因答案。随着智能体数增多，多数投票的准确率趋于多少？
::: solution
$1 - \rho(1 - p) = 1 - 0.6\cdot0.2 = 0.88$（[[#prop-correlated]]）。
:::
:::

::: exercise 五个投票者 {level=2 check="0.8369"}
精确计算 $M_5(0.7)$，保留四位小数，并与 Hoeffding 下界比较。
::: solution
$\binom53 0.7^3 0.3^2 + \binom54 0.7^4 0.3 + 0.7^5 = 10\cdot0.343\cdot0.09 + 5\cdot0.2401\cdot0.3 + 0.16807 = 0.3087 + 0.36015 + 0.16807 = 0.83692$，即 $0.8369$。下界为 $1 - e^{-2\cdot5\cdot0.04} = 1 - e^{-0.4} = 0.330$：成立，但在小的 $n$ 处离精确值很远。
:::
:::

::: exercise 多少个投票者？ {level=2 check="58"}
用 [[#prop-condorcet]] 的 Hoeffding 界：要让多数出错的概率至多为 $0.01$，需要多少个 $p = 0.7$ 的独立智能体？（向上取整；精确的需求要小得多。）
::: solution
需要 $e^{-2n\cdot0.04}\le0.01$，即 $n\ge\ln100/0.08 = 4.605/0.08 = 57.6$，故 $n = 58$（取奇数 $n = 59$ 可避免平局）。精确计算远不需要这么多：$M_{21}(0.7) = 0.974$，$M_{31}(0.7) = 0.990$，约 $31$ 个智能体就够——而这只在它们相互独立时成立。
:::
:::

::: exercise 辩论轮数与上下文 {level=2}
在 $n$ 个智能体、$R$ 轮的辩论中，第 $r\ge2$ 轮里每个智能体都要读其他 $n - 1$ 个智能体此前各轮的全部答案，每个 $L$ 个词元，另加一段固定的 $c$ 词元提示。推导输入词元总数，并对 $n = 3$、$R = 3$、$L = 400$、$c = 1{,}000$ 求值。
::: solution
第 $r$ 轮中，每个智能体读入 $c + (r - 1)(n - 1)L$ 词元（第 $1$ 轮只读 $c$）。总量为 $\sum_{r=1}^{R}n\,(c + (r - 1)(n - 1)L) = nRc + n(n - 1)L\frac{R(R - 1)}{2}$。代入数字：$3\cdot3\cdot1{,}000 + 3\cdot2\cdot400\cdot3 = 9{,}000 + 7{,}200 = 16{,}200$ 词元。若智能体还能看到自己此前的答案，再加 $nL\frac{R(R - 1)}{2} = 3{,}600$。费用对 $n$ 与 $R$ 都是二次的，而为投票取九个独立样本只需读 $9{,}000$。
:::
:::

::: exercise 能力不等的孔多塞 {level=3}
三个智能体的准确率各为 $0.9$、$0.6$ 与 $0.6$，相互独立。计算多数投票的准确率，并与直接听最好的智能体的比较。准确率满足什么条件时，三人多数能胜过其中最好的成员？
::: solution
至少两个正确时多数正确：$P = p_1p_2 + p_1p_3 + p_2p_3 - 2p_1p_2p_3 = 0.54 + 0.54 + 0.36 - 2\cdot0.324 = 1.44 - 0.648 = 0.792$，还不如最好智能体的 $0.9$。一般地，多数与智能体 $1$ 的裁决只在两种格局下不同：智能体 $1$ 错而另外两个都对（多数正确），以及智能体 $1$ 对而另外两个都错（多数错误）。因此多数胜过智能体 $1$ 当且仅当 $(1 - p_1)\,p_2p_3 > p_1(1 - p_2)(1 - p_3)$。代入 $0.9, 0.6, 0.6$：$0.9\cdot0.16 = 0.144$ 对 $0.1\cdot0.36 = 0.036$，多数输。以 $\log\frac{p_i}{1 - p_i}$ 为权的加权投票，对各成员独立且准确率已知时是最优的（Nitzan 与 Paroush，1982 的经典结果）；这里权重为 $2.20$、$0.41$、$0.41$，最好的智能体的票永远说了算，得到 $0.9$。
:::
:::

::: exercise 设计一个评审团队 {level=3}
设计一个多智能体系统，评审一个改动了 $40$ 个文件的 pull request，检查缺陷、安全问题与代码风格。写明有哪些智能体、它们的上下文与工具、拓扑、任务书，以及结果如何合并；然后说明你会如何检验它是否胜过单个智能体。
::: solution
**编排者**：读差异摘要与项目的惯例，把文件按模块分成约五个内聚的单元，为每个单元写一份任务书：涉及哪些文件、这次改动的目的、要找什么，以及输出格式（一份发现清单，每条含文件、行号、严重程度、证据与建议的修复）。**执行者**：每个单元一个，工具只读（查看文件、检索仓库、在沙箱里运行测试与代码检查器），各在自己的上下文里；它们只返回发现。**专职者**：一名安全评审，能看整个差异，但只配安全相关的上下文，因为安全问题常跨模块。**汇总**：编排者对发现去重，通过向执行者索要证据来裁决冲突，并按严重程度排序；还可另设一名审查者，以全新的上下文对照代码复核每条高严重度的发现，剔除误报。拓扑是星形加一名审查者。**检验**：收集一批带有已知缺陷（人为植入或历史遗留）的过往 pull request，让团队与单个智能体在相同的总词元预算下运行，比较发现的召回率与精确率，并在任务集与重复运行上给出置信区间（[[agents/agent-security#sec-evaluation]]）；同时测量延迟与成本，并读两者意见相左处的轨迹，看团队的分离上下文是否漏掉了跨模块的缺陷。
:::
:::
