大多数软件是为人写的，不是为程序写的。订一张火车票、报一笔差旅、在管理控制台里改一个设置、从一个老桌面应用导出一份报表：这类任务往往没有任何能被智能体当作工具调用的接口，只有按钮、表单和菜单。一个能像人一样操作**浏览器**乃至整台**计算机**的智能体——看屏幕、移动指针、点击、输入——原则上就能做其中任何一件，而且不必等谁先去做集成。正是这种通用性，让浏览与计算机操作智能体吸引了如此多的投入；也正是它，让这件事如此之难：智能体必须感知一屏为人眼设计的画面，通过一套为人手设计的接口行动，还要在那些会变、加载慢、弹窗不断的网站上重复几十步。

本章把网页与计算机控制当作一个观察空间与动作空间都不寻常的智能体问题来对待。我们先正式定义环境，再比较智能体看页面的三种方式——原始标记、无障碍树、屏幕截图——以及常常在它们之间起决定作用的词元算术；随后分析**定位**（grounding）：从「点击 Checkout 按钮」到一对像素坐标的那一步，并给出一个指向误差的小模型。一段用普通 Python 写成的清单通过无障碍树驱动一家玩具商店，并用模拟检验这个指向模型。后半部分沿着历史，从 WebGPT（Nakano 等，2021）讲到为这个领域立标准的几个基准——网站方面的 WebArena（Zhou 等，2024）与完整操作系统方面的 OSWorld（Xie 等，2024）——再讲到 2024 年起基于屏幕截图的计算机操作模型，最后说明为什么这类智能体需要比其他任何智能体都更严格的防护。

## 环境 {#sec-environment}

浏览器或桌面就是 [[agents/agent-loops#def-agent]] 意义下的一个环境，其中有两个要紧的特点。智能体永远看不到完整状态——服务器里的数据库、页面里的脚本、首屏以下的内容——只能看到它一部分的渲染结果。而且动作是低层级的：一个有意义的操作（「买便宜的那个水壶」）要花掉许多次点击和按键。

::: definition 计算机操作环境 {#def-gui-env}
**计算机操作环境**是一个部分可观测的决策过程：带有隐藏状态 $s_t$（这台机器、各个应用与任何远端服务器）、一个由 $s_t$ 产生 $o_t$ 的**观察函数**、以及一个由界面操作构成的**动作空间** $\mathcal{A}$。常见的观察类型有页面的**标记**（HTML）、**无障碍树**（暴露给辅助技术的那套结构：每个元素的角色、名称、状态与位置）和**屏幕截图**（屏幕的像素图），可单独使用也可组合。常见的动作空间有：
- **坐标动作**：在 $(x, y)$ 处移动或点击、拖拽、按一定幅度滚动、输入一段字符串、按下一个键或组合键；
- **元素动作**：点击、输入或选中当前观察中标识符为 $i$ 的元素；
- **导航动作**（浏览器）：打开一个 URL、后退、切换标签页；
- **控制动作**：等待、重新截屏、结束、或询问用户。
:::

元素动作要求观察为元素命名——标记和无障碍树做得到，截图做不到；坐标动作则对任何看得见的东西都管用，包括画布、远程桌面和没有任何无障碍信息的应用。许多智能体把它们混着用：用截图来理解，用无障碍树或带标签的叠加层来瞄准，拿坐标作后备。

### 智能体看到什么

三种观察类型在规模上、以及在各自让什么变得容易上，差别极大。

::: example 同一页面的三种视图 {#ex-views}
某个商品页的 HTML 有 $420$ kB，按大约每词元 $3.8$ 个字符算是约 $110{,}000$ 个词元，其中大部分是脚本、样式和跟踪标记。它的无障碍树列出 $180$ 个元素，每个约 $25$ 个词元。一张截图是 $1280\times800$ 像素，而模型的图像编码器每 $28\times28$ 像素块产出一个词元。比较三者的词元开销；若每一步都保留自己的观察，一个 $128{,}000$ 词元的窗口装得下多少步？
::: solution
HTML：$110{,}000$ 个词元——一页几乎塞满整个窗口。无障碍树：$180\cdot25 = 4{,}500$ 个词元。截图：$(1280/28)(800/28) = 45.7\cdot28.6\approx1{,}306$ 个词元。给指令与输出预留 $8{,}000$ 个词元后，窗口装得下一次 HTML 观察、约 $26$ 份无障碍树、或约 $92$ 张截图。实践中，智能体只完整保留最近的一两条观察、清掉更早的（[[agents/memory-context#ex-clearing]]），于是即使在长任务上无障碍树也用得起；原始标记则几乎总是先被清洗或整个换掉。
:::
:::

**无障碍树**由浏览器或操作系统根据页面结构、以及网页开发者为读屏软件添加的标注生成。在它完整的地方，它就是能拿到的最好观察：紧凑、结构化，带有明确的角色（「按钮」「文本框」「链接」）和名称，还带着可供智能体操作的稳定标识符。它的弱点在于，好坏全看页面的无障碍标注——没有标签的图标、画在画布上的自定义控件、做得很糟的表单，会以无名元素或干脆缺失的面目出现——而且它省掉了一个人无时无刻不在使用的视觉信息（布局、颜色、图像）。

**屏幕截图**是通用的观察：凡是人看得见的东西，在任何应用里智能体都看得见。它需要一个视觉-语言模型（[[multimodal/vision-language-models]]），并把难度挪到了**定位**上：知道该点**哪里**。一个流行的中间路线是 **set-of-mark 提示**（set-of-mark prompting；Yang 等，2023）：程序在截图的可交互元素上画出带编号的方框，模型于是可以说「点 14 号」而不必自己报出坐标。Zheng 等（2024）在真实网站上对一个视觉-语言模型智能体做评测，发现选对动作比把它定位到正确的元素更容易，后者仍是错误的主要来源。

### 用普通 Python 写成的玩具商店

下面的清单实现了一家五页的商店：它的观察是一棵带元素标识符的无障碍树，另有一个充当模型替身的脚本化策略，把树当作文本读取、按标识符行动。它会搜索、比较*按树中原样呈现*的两个价格、把便宜的水壶放进购物车，并在需要确认的结账处停下。清单的后半部分是坐标点击的模型，其推导见 [[#prop-pointing]]。

```python
import math, random

# --- 一家玩具网店，渲染成一棵无障碍树 ---------------------------------------
PAGES = {
    "home":    [("link", "Search"), ("link", "Account")],
    "search":  [("textbox", "Query"), ("button", "Go")],
    "results": [("link", "Kettle 1.7 L - 34.00"), ("link", "Kettle 1.0 L - 29.50"),
                ("button", "Next page")],
    "product": [("text", "Kettle 1.0 L, 29.50"), ("button", "Add to basket"),
                ("link", "Basket")],
    "basket":  [("text", "1 item, total 29.50"), ("button", "Checkout")],
}
LINKS = {("home", "Search"): "search", ("search", "Go"): "results",
         ("results", "Kettle 1.0 L - 29.50"): "product", ("product", "Basket"): "basket"}

class Shop:
    def __init__(self):
        self.page, self.query, self.basket = "home", "", 0
    def observe(self):
        """无障碍树：[id] 角色 "名称" —— 标识符就是智能体据以行动的东西。"""
        return "\n".join(f'[{i}] {role} "{name}"' for i, (role, name) in enumerate(PAGES[self.page]))
    def act(self, action, eid=None, text=None):
        role, name = PAGES[self.page][eid]
        if action == "type" and role == "textbox":
            self.query = text
        elif action == "click" and name == "Add to basket":
            self.basket += 1
        elif action == "click" and (self.page, name) in LINKS:
            self.page = LINKS[(self.page, name)]
        elif action == "click" and name == "Checkout":
            return "STOP: checkout needs the user's confirmation"
        return "ok"

def policy(obs, mem):
    """模型的脚本化替身：读树的文本，选出元素标识符。"""
    rows = [line.split(" ", 2) for line in obs.splitlines()]
    def find(word):
        return next(int(r[0][1:-1]) for r in rows if word in r[2])
    if '"Search"' in obs:
        return "click", find("Search"), None
    if '"Query"' in obs:
        if not mem.get("typed"):
            mem["typed"] = True
            return "type", find("Query"), "kettle"
        return "click", find("Go"), None
    if "Kettle 1.7" in obs:                                   # 比较树中呈现的价格
        prices = {int(r[0][1:-1]): float(r[2].rsplit(" ", 1)[1].strip('"'))
                  for r in rows if "Kettle" in r[2]}
        return "click", min(prices, key=prices.get), None
    if "Add to basket" in obs and not mem.get("added"):
        mem["added"] = True
        return "click", find("Add to basket"), None
    if '"Basket"' in obs:
        return "click", find("Basket"), None
    return "click", find("Checkout"), None

env, mem = Shop(), {}
for step in range(1, 10):
    page, obs = env.page, env.observe()
    action, eid, text = policy(obs, mem)
    result = env.act(action, eid, text)
    print(f"{step} {page:8s} {action:5s} [{eid}] {PAGES[page][eid][1]!r} {text or ''} -> {result}")
    if result.startswith("STOP"):
        break
print(env.observe().splitlines()[0])

# --- 按坐标点击：高斯指向误差 ------------------------------------------------
def p_hit(w, h, sigma):
    """若 x 与 y 方向的误差独立且服从 N(0, sigma^2)，返回 P(点击落在 w x h 的框内)。"""
    return math.erf(w / (2 * math.sqrt(2) * sigma)) * math.erf(h / (2 * math.sqrt(2) * sigma))
rng = random.Random(0)
for w, h, sigma in [(80, 30, 10), (80, 30, 20), (24, 24, 10)]:
    hits = sum(abs(rng.gauss(0, sigma)) <= w / 2 and abs(rng.gauss(0, sigma)) <= h / 2
               for _ in range(50000))
    print(f"box {w}x{h}, sigma {sigma}px: formula {p_hit(w, h, sigma):.4f}, simulated {hits/50000:.4f}")
```

```text
1 home     click [0] 'Search'  -> ok
2 search   type  [0] 'Query' kettle -> ok
3 search   click [1] 'Go'  -> ok
4 results  click [1] 'Kettle 1.0 L - 29.50'  -> ok
5 product  click [1] 'Add to basket'  -> ok
6 product  click [2] 'Basket'  -> ok
7 basket   click [1] 'Checkout'  -> STOP: checkout needs the user's confirmation
[0] text "1 item, total 29.50"
box 80x30, sigma 10px: formula 0.8663, simulated 0.8655
box 80x30, sigma 20px: formula 0.5219, simulated 0.5200
box 24x24, sigma 10px: formula 0.5927, simulated 0.5912
```

即便是这个玩具，也已经摆出了真实网页任务的形状：一个意图对应七个低层动作；必须从观察里读出来再比较的信息（两个价格）；以及环境在没有人确认时拒绝执行的收尾一步。真实页面还会添上玩具所没有的东西——盖住按钮的 cookie 横幅、把最便宜商品藏起来的「Next page」链接、选中某个规格后就会变的价格。

## 定位：从意图到像素 {#sec-grounding}

使用坐标动作时，一个已经决定按下某个按钮的智能体必须说出按钮在哪里。这一步输出里的错误，与决定**做哪个**动作的错误是两种不同的失败模式；一个简单模型能让这种错误随目标尺寸与屏幕分辨率的变化关系变得精确。

::: proposition 命中目标 {#prop-pointing}
设智能体瞄准一个宽 $w$ 像素、高 $h$ 像素的矩形目标的中心，其点击落在中心加上误差 $(\epsilon_x, \epsilon_y)$，其中 $\epsilon_x, \epsilon_y$ 相互独立且服从 $\Normal(0, \sigma^2)$。则点击落在目标内的概率为
$$
P(w, h, \sigma) = \operatorname{erf}\!\left(\frac{w}{2\sqrt2\,\sigma}\right)\operatorname{erf}\!\left(\frac{h}{2\sqrt2\,\sigma}\right).
$$ {#eq-pointing}
若截图在交给模型之前被缩小 $\kappa > 1$ 倍，而模型在以截图像素计的点上的误差为 $\sigma$，则概率为 $P(w/\kappa, h/\kappa, \sigma)$，其中 $w$ 与 $h$ 是目标在屏幕上的尺寸。
:::

::: proof
点击落在 $\lvert\epsilon_x\rvert\le w/2$ 且 $\lvert\epsilon_y\rvert\le h/2$ 之内才算命中，这是两个独立事件。对 $\epsilon\sim\Normal(0, \sigma^2)$，$\Prob(\lvert\epsilon\rvert\le a) = \Prob(\lvert Z\rvert\le a/\sigma)$，其中 $Z$ 为标准正态；由定义 $\operatorname{erf}(u) = \frac{2}{\sqrt\pi}\int_0^u e^{-t^2}dt$ 和换元 $t = z/\sqrt2$，它等于 $\operatorname{erf}(a/(\sigma\sqrt2))$。取 $a = w/2$ 与 $a = h/2$ 即得 [[#eq-pointing]]。缩小 $\kappa$ 倍把目标缩成 $w/\kappa\times h/\kappa$ 个截图像素，而模型的误差以它所见的像素来衡量，就是 $\sigma$；点击经乘以 $\kappa$ 映射回屏幕，误差与目标被同样放大，所以概率与对缩小后的目标而言相同。
:::

::: widget plot
f: erf(w/(2*sqrt(2)*x))*erf(h/(2*sqrt(2)*x)); erf(w/(4*sqrt(2)*x))*erf(h/(4*sqrt(2)*x))
x: 1, 40
y: 0, 1.02
sliders: w=80:10:200:1; h=30:10:100:1
labels: 全分辨率下的 $w\times h$ 目标; 同一目标，截图缩小 $2$ 倍
points: 10,0.8663; 20,0.5219
caption: 点击落在 $w\times h$ 像素目标上的概率随指向误差 $\sigma$ 的变化，$\sigma$ 以模型所见图像的像素计（[[#prop-pointing]]）。默认是一个 $80\times30$ 的按钮；标注的两点是清单里 $\sigma = 10$ 与 $20$ 的值。下面那条曲线是截图缩小 $2$ 倍后的同一个按钮：目标尺寸减半与误差加倍是等价的。窄的那条边占主导：一个 $30$ 像素高的按钮，命中远没有其 $80$ 像素宽度所暗示的那么可靠。
:::

::: example 缩小后的截图 {#ex-downscale}
一块 $2560\times1600$ 的屏幕被缩小到 $1280\times800$ 交给模型。一个「Save」图标在屏幕上是 $24\times24$ 像素，模型在它所见图像中的指向误差为 $\sigma = 5$ 像素。模型输出 $(600, 412)$。点击该送到屏幕上的哪里？命中的可能性有多大？
::: solution
两个方向上的缩放因子都是 $\kappa = 2$，所以点击送到屏幕上的 $(1200, 824)$。图标在截图里是 $12\times12$ 像素，故 $P = \operatorname{erf}(12/(2\sqrt2\cdot5))^2 = \operatorname{erf}(0.849)^2 = 0.770^2 = 0.593$——与清单最后一行 $\sigma = 10$ 时的 $24\times24$ 目标完全相同。往回映射时忘了因子 $\kappa$——脚手架中一个常见的 bug——会把所有点击都送到屏幕的左上四分之一处。智能体缓解小目标误差的办法有：放大（请求更高分辨率的裁块）、在有无障碍树可用时优先用元素动作、以及每次点击后检查一张新截图。
:::
:::

真实的指向误差并不服从高斯分布——模型会混淆相似的元素、点到复选框的标签上、或者瞄准按钮在页面移动之前的旧位置——但这个模型抓住了两个稳健的事实：小目标难得不成比例，而缩小丢掉的信息不可能靠更好的策略找回来。随着视觉-语言模型在大量「截图配元素位置」的数据上训练，定位在 2024–2025 年间大幅改进；专门的定位基准（例如 ScreenSpot；Cheng 等，2024）把它与任务成功率分开度量。

## 从 WebGPT 到计算机操作 {#sec-history}

浏览智能体比大语言模型出现得还早：MiniWoB（Shi 等，2017）提供了一小批合成的网页任务——点一个按钮、填一张表单——在其上训练过从像素和标记学习的强化学习智能体。语言模型改变了人们尝试做的事情。

**WebGPT**（Nakano 等，2021）微调 GPT-3，让它通过搜索、点击链接、页内查找、滚动、引用一段文字、后退等命令操作一个基于文本的浏览器，从而回答长问题。它先向人示范的浏览行为学习（行为克隆），随后针对一个在人比较数据上训练的奖励模型（[[post-training/reward-models]]）做 best-of-$n$ 采样加以改进。它的答案注明了所引用段落的出处；人类评审在 $56\%$ 的情况下更喜欢它的答案胜过示范者的答案，在 $69\%$ 的情况下更喜欢它的答案胜过某热门问答论坛的最高票答案。WebGPT 确立了带出处的浏览这一技术；而那个浏览器是**文本**的——页面被转换成简化的文本形式——这使浏览成了一项语言任务。

**真实网站上的基准**接踵而来。Mind2Web（Deng 等，2023）在一百多个真实网站上收集了两千多个任务及录制的人工动作序列，评测智能体是否选择了与人相同的下一个动作。离线比对动作既无法为另辟蹊径的成功记功，也测不出纠错恢复的能力，于是其后的基准让智能体在线运行。

::: definition WebArena 与 OSWorld {#def-webarena}
**WebArena**（Zhou 等，2024）是一个自托管环境，由若干功能完整的网站构成——一个网店、一个讨论论坛、一个软件协作平台、一个给网店用的内容管理系统、一个地图服务，外加配套工具——里面填着贴近真实的数据，共有 $812$ 个用自然语言给出的任务（「找出该类别里最便宜的商品……加进我的愿望清单」）。成败以**功能**方式核验：检查网站数据库的最终状态或最终答案，而不是比对动作序列。**OSWorld**（Xie 等，2024）把这一想法扩展到虚拟机里的完整桌面操作系统：Ubuntu 上 $369$ 个任务（另有一批在 Windows 上），涉及真实应用——办公套件、浏览器、图像编辑器、文件管理器、终端——每个任务都带一份初始状态配置和一个基于执行的评测脚本。
:::

两个基准登场时，人与智能体之间都隔着极大的差距。WebArena 的作者报告，他们最好的基于 GPT-4 的智能体成功率约 $14\%$，而人约 $78\%$；OSWorld 报告最好的模型约 $12\%$，而人约 $72\%$。人的数字与模型的数字同等要紧：它们说明多数任务写得清楚明白，同时其中约四分之一连人也奈何不得——或因含糊，或因对任何智能体都同样存在的真实难度。各变体陆续加入了视觉任务（VisualWebArena；Koh 等，2024）和其他操作系统；随着定位更好、模型在界面交互上得到训练、可靠的操作跨度更长，智能体的分数在 2024 与 2025 年迅速上升。

作为一种通用模型能力的**计算机操作**出现在 2024 年 10 月：Anthropic 发布了一个模型和一套接口，让模型根据屏幕截图、以鼠标和键盘动作操作桌面；2025 年，其他提供商类似的浏览器与计算机操作智能体相继出现，为界面控制训练的开放权重模型也是如此。截至 2026 年，它们已被用于浏览器和桌面应用里的日常任务——通常在隔离的虚拟机里——而在有 API 可用的场合，它们仍然明显比基于 API 的工具调用更慢、更不可靠。[[agents/function-calling]] 的一般教训依然成立：有结构化接口就用它；没有，再去操作屏幕。

::: example 屏幕还是 API？ {#ex-latency}
一个任务——把上个月的发票导出成电子表格——需要某个计算机操作智能体 $30$ 个动作。每个动作需要一张截图（$0.3$ s）、一次模型调用（读约 $1{,}300$ 个图像词元加历史，产出一个简短动作，$4$ s）、以及执行加等页面稳定（$1.5$ s）。同一件事走会计系统的 API 只需 $3$ 次工具调用，每次 $2.5$ s，含模型时间。比较墙钟时间与模型调用次数。
::: solution
屏幕：$30\cdot(0.3 + 4 + 1.5) = 30\cdot5.8 = 174$ s，将近三分钟，外加 $30$ 次模型调用，每次都是一次出错的机会。API：$3\cdot2.5 = 7.5$ s，$3$ 次模型调用。这个比例——时间上二十多倍，调用次数上十倍——很典型，也正是为什么计算机操作是没有 API 的接口面前的后备，而不是默认选择。在用得上它的场合，因为智能体是无人值守地干活，延迟往往可以接受；但出错敞口并不会因为有耐心而缩小。
:::
:::

### 网页任务为什么难

若干困难会相互叠加（[[agents/agent-loops#sec-compound]]）。任务很长：几十个动作，每个都是点错或看错的机会。页面是**非平稳**的：内容异步加载、布局移动、对话框冒出来，于是一个用半秒前的截图算出来的动作可能落在别的东西上。观察是**部分的**：要紧的东西可能在首屏以下、结果的下一页、或者某个菜单背后，而不滚动、不翻页的智能体会断定它不存在。许多动作**不可逆**或代价高——提交表单、发送消息、付款——而智能体并不总能分辨哪些是。而且每个页面都是**不可信内容**：页面上的文本会被模型读到，完全可以被设计得看起来像指令（[[agents/agent-security]]）。

::: widget graph
nodes: Home@0,1; Search@1,2; Results@2,2; Page2@3,2; Product@3,1; Basket@4,1; Checkout@5,1; Account@1,0; Orders@2,0
edges: Home>Search; Home>Account; Search>Results; Results>Page2; Results>Product; Page2>Product; Product>Basket; Basket>Checkout; Account>Orders; Orders>Product
algorithm: bfs
start: Home
caption: 一家小商店的导航图。从 Home 开始一步步执行广度优先搜索：商品页经搜索只需三次点击，或者经 Account、Orders 走一条补购的路。智能体就这样隐式地探索着这样的图；没见过 "Page2" 的智能体不可能知道最便宜的东西在那里——这正是部分可观测（而不只是点错）造成失败的原因。Checkout 是唯一一个进入前应当要求人确认的节点。
:::

::: example 网页上的步数与可靠性 {#ex-web-reliability}
一个网页任务需要 $25$ 个动作。每个动作以概率 $0.97$ 做出正确决策，且在决策正确的条件下以概率 $0.98$ 定位正确。每次动作之后的新截图能检出 $70\%$ 的失败，被检出的失败会重试，每个动作至多 $2$ 次尝试。完成任务的概率是多少？若智能体改用定位准确率 $0.999$ 的元素动作呢？
::: solution
单次尝试成功率 $p = 0.97\cdot0.98 = 0.9506$。由 [[agents/agent-loops#prop-retry]]，取 $d = 0.7$、$r = 2$：$S = 0.9506\,(1 + 0.0494\cdot0.7) = 0.9506\cdot1.03458 = 0.98347$，于是 $S^{25} = 0.659$。改用元素动作时，$p = 0.97\cdot0.999 = 0.96903$，$S = 0.96903\,(1 + 0.03097\cdot0.7) = 0.99004$，于是 $S^{25} = 0.779$。在这里，更好的定位值十二个百分点的任务成功率；更好的核验则更值钱（若 $d = 0.95$，第一种情形给出 $0.887$）。
:::
:::

::: warning 屏幕不是真相
截图显示的是页面*展示*的东西，而页面展示的正是它的作者想让人看到的。「Payment successful」的绿色横幅可能在服务器尚未确认任何事之前就已出现，价格可能不含之后才显示的税费，标着「Cancel」的元素可能干的是别的事。把显示文本照单全收的智能体，会继承页面上的一切错误与欺骗。结果要紧时，要通过页面控制不了的渠道核验它——账户历史里的订单、一封确认邮件、磁盘上的文件——并向用户报告核验了什么。
:::

## 负责任地设计计算机操作智能体 {#sec-design}

计算机操作智能体把最宽的动作空间与最不可信的输入结合在一起，因此 [[agents/agent-security]] 的防护措施要以最强形式生效：

- **隔离。** 在专用的虚拟机或浏览器配置里运行智能体，不要在一个人日常使用、所有会话都登录着的桌面上跑。只给它任务需要的账户，最好是有单独账户、权限有限。
- **有分量的动作先确认。** 购买、发送消息、提交表单、删除、改动账户设置，以及任何涉及付款或凭据的事，都应暂停下来等一个人明确批准，并向他展示恰切会发生什么。玩具商店的结账规则就是这一模式的样本。
- **许可名单。** 限定给定任务下智能体可以访问的网站和应用；订行程的任务不需要用户的邮箱。
- **把屏幕上的文本当数据。** 给智能体的指令来自用户和系统提示；页面上的文本是关于任务的信息，绝不是新指令，脚手架要把这一区分尽量摆到明面上。
- **可观察。** 让人能实时看到智能体的屏幕，随时暂停或接管，事后还能回看录像。

::: quiz
一个浏览智能体接到任务：「找一家 5 月 3–5 日每晚不超过 150 欧元的里斯本酒店，并订下来。」哪种设计最能兼顾有用与安全？
- [ ] 既然用户要的就是订房，就让智能体用他保存的卡完成预订。
- [x] 让智能体搜索、比较并填写预订表单，然后停下来，把酒店、日期、总价和取消条款展示给用户，经批准后再提交。
- [ ] 拒绝这个任务，因为浏览智能体在预订上不可信。
- [ ] 让智能体先订下，然后给用户发一封总结邮件。
::: solution
智能体做掉费力的部分——搜索、比较、填表——而由人在信息齐全之下做出不可逆的决定，这同时也能抓住误读，比如按人计价或日期看错。不经确认就预订、或事后才报告，等于把付款放到一条没人核验的「感知加点击」链条之后；而拒绝，则是放弃了一个有检查点就能做得很好的任务。
:::
:::

::: history
MiniWoB（Shi 等，2017）及其扩展 MiniWoB++（Liu 等，2018）是面向强化学习智能体的早期网页交互基准。Nakano 等（2021）训练 WebGPT 在文本化的网上带出处地浏览，Yao 等（2022）构建了用于评测 ReAct 的模拟网店 WebShop。Deng 等（2023）发布了基于真实网站的 Mind2Web；Zhou 等（WebArena，2023；ICLR 2024）与 Koh 等（VisualWebArena，2024）让在线运行、功能评分的网页环境成为标准；Xie 等（OSWorld，2024）为桌面操作系统做了同样的事。Yang 等（2023）提出用于视觉定位的 set-of-mark 提示，Zheng 等（2024）指出定位是视觉-语言网页智能体的瓶颈，Shaw 等（2023）与 Hong 等（CogAgent，2024）则训练从像素行动的策略。Anthropic 于 2024 年 10 月为其模型发布计算机操作能力；其他提供商在 2025 年发布了浏览器与计算机操作智能体，开放权重的界面控制模型随后跟进。
:::

::: summary
- 计算机操作智能体通过为人打造的接口行动：观察是标记、无障碍树或屏幕截图；动作是坐标、元素、导航与控制操作。
- 无障碍树紧凑且可操作，但依赖页面的标记；截图通用，但需要视觉定位；原始 HTML 通常太长。观察的大小决定了装得下多少历史。
- 定位是一种独立的失败模式：指向误差为高斯 $\sigma$ 时，命中 $w\times h$ 目标的概率是 $\operatorname{erf}(w/2\sqrt2\sigma)\operatorname{erf}(h/2\sqrt2\sigma)$；小目标与缩小后的截图难得不成比例。
- WebGPT（2021）在文本网上带出处地浏览；WebArena（自托管网站上的 $812$ 个任务）与 OSWorld（虚拟机里的 $369$ 个桌面任务）对在线运行的智能体做功能性评分，登场时人机差距巨大。
- 网页任务长、非平稳、观察不完全、常不可逆且满是不可信文本，因此误差会累积，经由独立渠道的核验十分重要。
- 计算机操作智能体要在隔离环境中运行，配许可名单、实时可见性，并在每个有分量的动作之前要求确认；把屏幕上的文本当数据，绝不当指令。
:::

## 习题

::: exercise 图像词元 {level=1 check="2048"}
某模型的图像编码器每 $28\times28$ 像素块产出一个词元。一张 $1792\times896$ 的截图产出多少个词元？
::: solution
$(1792/28)\cdot(896/28) = 64\cdot32 = 2{,}048$ 个词元。
:::
:::

::: exercise 把点击映射回去 {level=1}
一块 $3840\times2160$ 的屏幕以 $1280\times720$ 的截图展示给模型。模型点击在 $(512, 300)$。这个点击应送到屏幕上的哪里？
::: solution
两个方向上的缩放因子都是 $3$，故为 $(1536, 900)$。
:::
:::

::: exercise 命中按钮 {level=1 check="0.866"}
利用 [[#eq-pointing]]，指向误差 $\sigma = 10$ 像素时命中一个 $80\times30$ 像素按钮的概率是多少？保留三位小数。
::: solution
$\operatorname{erf}(80/28.28)\operatorname{erf}(30/28.28) = \operatorname{erf}(2.828)\operatorname{erf}(1.061) = 0.99994\cdot0.8664 = 0.866$。
:::
:::

::: exercise 所需的精度 {level=2 check="6.12"}
若只考虑水平方向，指向误差 $\sigma$（像素）为多大，才能以 $95\%$ 的概率命中一个宽 $24$ 像素的目标？用 $\Prob(\lvert Z\rvert\le1.96) = 0.95$，保留两位小数。
::: solution
点击落在中心 $12$ 像素之内、概率为 $0.95$，当 $12/\sigma = 1.96$，故 $\sigma = 12/1.96 = 6.12$ 像素。要两个方向一起以概率 $0.95$ 命中，需要每个方向达到 $\sqrt{0.95} = 0.9747$，即 $z = 2.236$、$\sigma = 5.36$ 像素。
:::
:::

::: exercise 网页上的可靠性 {level=2 check="0.659"}
复现 [[#ex-web-reliability]] 的第一个结果：$25$ 个动作，决策准确率 $0.97$，定位准确率 $0.98$，检出率 $d = 0.7$，$r = 2$。保留三位小数。
::: solution
$p = 0.9506$，$S = 0.9506\,(1 + 0.0494\cdot0.7) = 0.98347$，$S^{25} = e^{25\ln0.98347} = e^{25\cdot(-0.016668)} = e^{-0.41671} = 0.659$。
:::
:::

::: exercise 选择观察 {level=2}
为下列任务各选择一种观察类型（无障碍树、截图，或两者都用），并说明理由：(a) 在一个做得规范的政府网站上填一张长表单；(b) 在基于画布的绘图应用里编辑一幅示意图；(c) 检查一个网页的布局在手机大小的屏幕上是否显示正确；(d) 通过远程桌面连接操作一个老旧的桌面应用。
::: solution
(a) 无障碍树：无障碍做得好的站点上表单都有清楚的标注，元素动作可免掉定位误差，而且字段很多时树仍然紧凑。(b) 截图：画布内容不在树里。(c) 截图，加上用于定位元素的树：布局正确性在定义上就是视觉的。(d) 截图：远程桌面只传像素，没有树可用，坐标动作是唯一的选项——要多用放大和操作后的核验。
:::
:::

::: exercise 靠截图检出失败 {level=3}
在 [[#ex-web-reliability]] 中，求坐标动作智能体以概率 $0.9$ 完成这个 $25$ 步任务所需的检出率 $d$，取 $r = 2$。然后讨论：从截图检出失败为什么难？说一种能提高 $d$ 的技术。
::: solution
需要 $S^{25} = 0.9$，即 $S = 0.9^{1/25} = 0.995794$。取 $p = 0.9506$：$0.9506\,(1 + 0.0494d) = 0.995794$，于是 $1 + 0.0494d = 1.047543$，$d = 0.962$。检测之所以难，是因为许多失败在屏幕上看去和成功一样：落在空白的点击没有改变任何可见的东西，一个拒绝输入的表单字段可能要到提交时才显示错误，一个慢页面只是*暂时*还没变。提高 $d$ 的技术有：比较每次动作前后的截图，把「没有变化」当作大概率的失败；显式检查预期的效果（字段里现在有刚输入的文本、购物车计数增加了）——通过读无障碍树或页面状态；以及先等页面稳定（网络空闲）再观察。
:::
:::

::: exercise 分页隐藏的信息 {level=3}
一个智能体要在随机排序、每页显示 $10$ 件的 $N$ 件商品里找最便宜的一件。若只检查第一页，它找到真正最便宜商品的概率是多少？若每多读一页花一个动作、该动作以概率 $0.02$ 独立失败，且动作失败就以「目前见到的最好商品」结束搜索，那么当 $N = 50$ 时它应当计划读几页？成功概率是多少？
::: solution
只读第一页：最便宜商品在其上的概率是 $10/N$，$N = 50$ 时为 $0.2$。读全部 $5$ 页需要 $4$ 个翻页动作，全部成功概率为 $0.98^4 = 0.922$，此后智能体必然找到最便宜的商品。共读 $m$ 页时，只要商品在*实际到达*的某一页上就算成功。成功概率为 $\sum_{j=1}^{m}\frac{10}{50}\cdot0.98^{j-1}$：$m = 5$ 时，$0.2\,(1 + 0.98 + 0.9604 + 0.9412 + 0.9224) = 0.2\cdot4.804 = 0.961$。（即便某次翻页失败，商品也可能早已见过。）由于每多读一页概率都会增加，它应当读满五页；第 $j$ 页带来的增益是 $0.2\cdot0.98^{j-1}$，恒为正。这一课的启示是：提前停下的风险远大于多花动作的代价——任务要的是最值时，必须告诉智能体（或让它自己学会）把分页翻干净。
:::
:::
