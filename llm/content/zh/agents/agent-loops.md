一次工具调用只能回答一个问题。而多数值得托付的任务都需要许多次调用：找到文件、读它、发现数据在别处、再去读那里、计算、检查、作答。没有人——无论用户还是开发者——能事先写下调用的序列，因为每一步都取决于上一步揭示了什么。解决办法是把模型放进一个**循环**：把任务和迄今为止发生的一切展示给它，让它选择下一个动作，执行这个动作，把观察结果追加进去，如此重复，直到它认为完成为止。以这种方式运行的模型就是一个**智能体**（agent），而这个循环连同它的工具、提示和限制，被称为它的**脚手架**（scaffold）或**运行框架**（harness）。

本章把这一循环讲确切。先按经典意义定义智能体，再把大语言模型的智能体循环看作一个带有显式状态、策略与停止规则的控制器，并介绍多数智能体至今仍遵循的 ReAct 模式——把推理与行动交替进行（Yao 等，2023）。接着转向支配智能体工程的那个性质：误差会随步骤累积。两个小结果——完成一个 $k$ 步任务的概率，以及重试与检验如何改变它——既解释了智能体为何失败，也解释了为什么检查工作是让它们成功的最有效手段。本章以 Reflexion（Shinn 等，2023）以及智能体从自身失败尝试中学习的其他方法收尾，最后讨论循环的实际设计：预算、终止与执行轨迹。正文配有一个用普通 Python 实现、由脚本化模型驱动的智能体，以及一个可靠性模拟。

## 什么是智能体 {#sec-agent}

这个词来自经典人工智能，在那里它有一个刻意宽泛而精确的含义（CS 图谱中的[智能体](/learn/cs/lesson.php?c=artificial-intelligence&l=intelligent-agents)一课；Russell 与 Norvig，2020，第 2 章）。

::: definition 智能体 {#def-agent}
一个**智能体**在离散时间上与一个**环境**相互作用。在每一步 $t$，它收到一个**观察**（知觉）$o_t$，并从动作集 $\mathcal{A}$ 中选择一个**动作** $a_t$；环境随之改变并产生下一个观察。智能体的行为由一个**策略** $\pi$ 描述，它把**历史** $h_t = (o_1, a_1, \dots, a_{t-1}, o_t)$ 映射为一个动作（或动作上的分布）。其优劣由设计者选定的、定义在所得环境状态序列上的**性能度量**来衡量。
:::

这个定义既涵盖语言模型，也涵盖恒温器和国际象棋程序，而这正是它的用意：它把**智能体做什么**（把历史映射为动作）与**怎么做**（一张查找表、一个搜索过程、一个学来的网络）区分开来。强化学习（[[post-training/rl-for-language-models]]）使用的是同一套图景，只是以奖励信号作为性能度量。大语言模型智能体新在策略：一个预训练、指令微调过的模型，把历史当作文本读入、把下一个动作当作文本写出，完全不需要针对任务的训练。

::: definition 大语言模型的智能体循环 {#def-loop}
一个**大语言模型智能体**由以下部分构成：一个模型 $p_\theta$；一个工具集 $\mathcal{T}$（[[agents/function-calling#def-tool]]），它定义了动作集 $\mathcal{A} = \{\text{工具调用}\}\cup\{\textsf{finish}(y)\}$；一个**上下文** $c_t$（第 $t$ 步模型看到的文本）；以及一条**更新规则**。从 $c_1 = (\text{系统提示}, \text{工具定义}, \text{任务})$ 出发，第 $t$ 步是：

1. **思考并行动。**采样 $(z_t, a_t)\sim p_\theta(\cdot\mid c_t)$：一段可选的自由文本推理轨迹 $z_t$，后面跟着一个动作 $a_t\in\mathcal{A}$。
2. **停止？**若 $a_t = \textsf{finish}(y)$，或某个**停止条件**成立，则结束并返回 $y$（或失败）。
3. **执行。**在环境中运行 $a_t$，得到观察 $o_t$——工具结果、错误信息或屏幕截图。
4. **更新。**$c_{t+1} = U(c_t, z_t, a_t, o_t)$；最简单的情况下 $U$ 把三者全部追加，$c_{t+1} = c_t\oplus z_t\oplus a_t\oplus o_t$。
:::

定义中有三个成分是设计选择，而非给定事实。**动作集**决定智能体能做什么，从而决定可能出什么错（只读智能体删不掉任何东西）。**更新规则** $U$ 决定智能体记住什么：全部追加最简单，但上下文会无界增长，[[agents/memory-context]] 讲的正是如何用摘要与检索来应对这一点。**停止条件**决定当模型从不说自己完成时，循环何时结束。

::: definition 停止条件 {#def-stopping}
循环在首次满足下列条件之一的步骤处结束：
- **完成**：模型发出 $\textsf{finish}(y)$（可选地，仅当对 $y$ 的检验通过时才接受）；
- **步数预算**：$t = T_{\max}$；
- **资源预算**：已花的词元、金钱或墙钟时间超过限额；
- **停滞**：同一动作配同一参数已执行 $m$ 次，或连续 $m$ 步都产生错误；
- **上报**：下一步动作需要只有人才能给予的许可或确认（[[agents/agent-security]]）。

只有第一种返回结果；其余各条返回失败、部分结果或求助请求，并应说明是哪一种。
:::

### 工作流与智能体

并非每个多步系统都需要模型自己决定步骤。当步骤已知——先抽取字段、再校验、再摘要——用代码在每个阶段调用模型的固定流水线更便宜、更快、也更好测试。一份广为引用的实践指南（Schluntz 与 Zhang，2024）如此划界：在**工作流**中，模型和工具经由预先定义的代码路径编排（提示链、把输入路由给若干处理器之一、并行运行调用再汇总、或让一次调用评估并改进另一次调用的输出）；而在**智能体**中，模型动态地指挥自己的过程和工具调用。该指南的建议与普遍经验相符：使用能奏效的最简单模式，只在路径确实无法预先固定的地方才加入自主性。本章余下部分讲的就是无法固定的情形。

## ReAct：推理与行动 {#sec-react}

2022 年之前，把语言模型用于多步问题的两条工作线索各自为政。思维链提示（[[reasoning/chain-of-thought]]）让模型在作答前用文本推理，但推理接触不到世界，缺什么事实就编什么事实。生成动作的系统——例如 WebGPT 的浏览命令（Nakano 等，2021）或在文字游戏里输出动作的模型——在世界上行动，却不对所见内容做显式推理。Yao 等（2023）把两者合为一体。

::: definition ReAct {#def-react}
**ReAct** 智能体是一个智能体循环（[[#def-loop]]），通过提示（或微调）使其每一步先产出一段自由文本的**思考**，紧接着产出一个**动作**，并在下一次思考之前收到**观察**。一条轨迹具有如下形式
$$
\text{思考}_1,\ \text{行动}_1,\ \text{观察}_1,\ \text{思考}_2,\ \text{行动}_2,\ \text{观察}_2,\ \dots,\ \text{行动}_T = \textsf{finish}(y).
$$
思考不影响环境；它们负责分解目标、跟踪进展、解释观察，并决定下一步做什么。
:::

原论文里，问答任务上的动作是三个维基百科操作——`search[entity]`、`lookup[string]` 和 `finish[answer]`——提示中包含几条人工撰写的示例轨迹。一条该风格的缩短轨迹如下：

```text
Question: Which of the two rivers is longer, the one through Kraków or the one through Prague?
Thought 1: Kraków is on the Vistula; Prague is on the Vltava. I need both lengths.
Action 1:  search[Vistula]
Obs 1:     The Vistula is the longest river in Poland, at 1,047 km ...
Thought 2: Now the Vltava.
Action 2:  search[Vltava]
Obs 2:     The Vltava is the longest river within the Czech Republic, 430 km ...
Thought 3: 1,047 km > 430 km, so the Vistula is longer.
Action 3:  finish[the Vistula]
```

Yao 等在维基百科接口上评测了多跳问答（HotpotQA）与事实核查（FEVER）上的 ReAct，并在两个交互环境上评测：文字家庭任务模拟器 ALFWorld 和模拟网店 WebShop。他们报告：在交互任务上，只用一两个示例提示的 ReAct 超过了用多得多的示范训练的监督模仿和强化学习基线，成功率绝对领先分别达 $34$ 和 $10$ 个百分点，也超过了去掉思考的「只行动」消融。在知识任务上图景更微妙：ReAct 的答案比思维链的更有据、更少幻觉，但单看 HotpotQA 准确率并没有超过带自洽性的思维链；最好的结果来自在两种方法之间切换。错误也很有特点：一条没有信息量的搜索结果会让轨迹跑偏，模型有时还会陷入同一个思考与动作的循环。

思考为什么有用？动作必须从**当前**上下文中选出，而经过几次观察之后的上下文既长又乱。写进上下文的一段思考，是模型为将来的自己做的摘要——「第一条长度已经有了，现在需要第二条」——这让下一步成为一个容易得多的预测。用 [[#def-loop]] 的话说，思考是被更新规则携带下去的状态的一部分，一种廉价的工作记忆。被训练成在作答前长时间推理的模型（[[reasoning]]）在内部做的是同一件事；截至 2026 年，许多智能体脚手架已不再要求显式的「Thought:」行，因为模型自己的推理就承担了这一角色；观察–思考–行动的结构并没有变。

### 一个用普通 Python 写成的最小智能体循环

下面的清单实现了 [[#def-loop]]：在一个两文件的「文件系统」上提供三个工具、带步数预算、把错误作为观察返回，并为模型配一个确定性的替身。这个替身策略只看最后一条观察，真正的模型不会这么做；要点在于它外面的循环——无论接入什么模型，循环都是同一套。清单的后半部分模拟下一节的可靠性计算。

```python
import json, random

# --- 环境：一个供智能体查看的微型文件系统 ---------------------------------
FILES = {"notes.txt": "budget: see q3.csv", "q3.csv": "jul,410\naug,385\nsep,442"}
def ls():           return sorted(FILES)
def read(path):     return FILES[path]
def add(numbers):   return sum(numbers)
TOOLS = {"ls": ls, "read": read, "add": add}

# --- 模型的一个确定性替身 --------------------------------------------------
def mock_model(history):
    """看最后一条观察，选出下一步（思考，动作）。"""
    last = history[-1]
    if last["role"] == "user":
        return "I should see which files exist.", ("ls", {})
    obs = last["content"]
    if isinstance(obs, list):                       # ls 的结果
        return "notes.txt may say where the data is.", ("read", {"path": "notes.txt"})
    if isinstance(obs, str) and "see" in obs:
        f = obs.split("see ")[1]
        return f"The figures are in {f}.", ("read", {"path": f})
    if isinstance(obs, str) and "," in obs:
        nums = [int(line.split(",")[1]) for line in obs.splitlines()]
        return "Sum the three months.", ("add", {"numbers": nums})
    if isinstance(obs, (int, float)):
        return "I have the total.", ("final", {"answer": f"Q3 total: {obs}"})
    return "I am stuck.", ("final", {"answer": "unknown"})

def run_agent(task, model, max_steps=8):
    history = [{"role": "user", "content": task}]
    for step in range(1, max_steps + 1):
        thought, (name, args) = model(history)
        print(f"{step} thought: {thought}\n  action: {name} {json.dumps(args)}")
        if name == "final":                          # 停止条件 1
            return args["answer"], step
        try:
            obs = TOOLS[name](**args)
        except Exception as e:                       # 错误作为观察返回
            obs = f"error: {e}"
        print(f"  observation: {obs!r}")
        history += [{"role": "assistant", "content": [thought, name, args]},
                    {"role": "tool", "content": obs}]
    return None, max_steps                           # 停止条件 2：步数预算

print(run_agent("What was total spending in Q3?", mock_model))

# --- k 步上的可靠性：解析式 vs 模拟 ----------------------------------------
def episode(rng, p, k, r=1, d=1.0):
    """k 步；每次尝试以概率 p 成功；失败以概率 d 被发现，
    发现后重试，每步至多尝试 r 次。未被发现的失败 = 整局输掉。"""
    for _ in range(k):
        for attempt in range(r):
            if rng.random() < p: break               # 该步成功
            if attempt == r - 1 or rng.random() >= d:
                return False                         # 重试次数用尽，或没被发现
    return True

rng = random.Random(1)
N = 20000
for p, k, r, d in [(0.95, 20, 1, 1.0), (0.95, 20, 2, 1.0), (0.95, 20, 2, 0.8), (0.99, 50, 1, 1.0)]:
    sim = sum(episode(rng, p, k, r, d) for _ in range(N)) / N
    q = 1 - p
    step = p * (1 - (q * d) ** r) / (1 - q * d)      # 命题：单步成功率
    print(f"p={p} k={k} r={r} d={d}: analytic {step ** k:.4f}  simulated {sim:.4f}")
```

  action: ls {}
  observation: ['notes.txt', 'q3.csv']
2 thought: notes.txt may say where the data is.
  action: read {"path": "notes.txt"}
  observation: 'budget: see q3.csv'
3 thought: The figures are in q3.csv.
  action: read {"path": "q3.csv"}

智能体从读的第一个文件里发现了数据的位置——固定流水线不会拥有这条信息——并在五步内完成，第五步就是 $\textsf{finish}$ 动作。模拟得到的成功率与下一节导出的公式在 $20{,}000$ 局的抽样误差之内吻合（标准误约 $0.003$）。

## 误差累积 {#sec-compound}

智能体的每一步都是一次模型预测，都可能出错：选错工具、参数写错、看错观察、得出一个貌似合理却错误的结论。在一个长任务上，这些出错的机会会相乘。

::: proposition 在 $k$ 步上的成功率 {#prop-compound}
设一个任务需要 $k$ 步，每一步都必须成功，且第 $i$ 步以概率 $p$ 成功、与其他步相互独立。则任务以概率 $p^k$ 成功，而成功率降到一半所需的步数 $k_{1/2}$ 为
$$
k_{1/2} = \frac{\ln 2}{-\ln p}\approx\frac{0.693}{1 - p}\qquad(p\to1).
$$ {#eq-half-life}
:::

::: proof
独立性给出 $\Prob(\text{全部成功}) = \prod_{i=1}^{k}p = p^k$。解 $p^k = \frac12$ 得 $k = \ln 2/(-\ln p)$；而当 $p$ 接近 $1$ 时，$-\ln p = -\ln(1 - (1 - p)) = (1 - p) + \frac12(1 - p)^2 + \dots\approx 1 - p$。
:::

::: example 智能体的半衰期 {#ex-half-life}
某智能体每步有 $95\%$ 的概率做对。完成 $20$ 步的概率是多少？它的成功率减半之前最多能走多少步？要让 $100$ 步的任务 $90\%$ 的情况下成功，每步必须多可靠？
::: solution
$0.95^{20} = 0.358$，课程概览中引用的正是这个数。半衰期是 $\ln2/(-\ln0.95) = 0.693/0.0513 = 13.5$ 步（近似式给出 $0.693/0.05 = 13.9$）。要使 $p^{100} = 0.9$，需要 $p = 0.9^{1/100} = e^{\ln 0.9/100} = e^{-0.00105} = 0.99895$：每步错误率约千分之一。长任务所需的每步可靠性，远非单次模型调用的典型水平所能及。
:::
:::

独立性假设是一把双刃剑，值得细看。错误常常是**正**相关的——误解了任务的模型会连着错许多步——这使得失败集中于某些回合，而对其余回合来说 $p^k$ 偏于悲观。另一方面，并非每个错误都致命：读错文件的智能体可以察觉并去读对的。这后一点正是可靠智能体的关键。

### 恢复：重试与检验

设想每步之后都有什么东西检查结果——一个测试、一个模式（schema）、工具自身的报错、模型重读自己的输出——一旦检测到失败，这一步就重新尝试。

::: proposition 有检验与重试时的单步成功率 {#prop-retry}
每一步的每次尝试独立地以概率 $p$ 成功。失败之后，该失败以概率 $d$ 被检测到（成功绝不会被告警），被检测到的失败会重试，总共至多 $r$ 次尝试；未被检测到的失败，或最后一次尝试仍失败，都会让这一步失败。则这一步成功的概率为
$$
S(p, d, r) = p\sum_{j=0}^{r-1}\big((1 - p)\,d\big)^{j} = p\,\frac{1 - ((1 - p)d)^r}{1 - (1 - p)d},
$$ {#eq-step-success}
而由 $k$ 个这样的步骤组成的任务以概率 $S(p, d, r)^k$ 成功。在完美检测（$d = 1$）下，$S = 1 - (1 - p)^r$。
:::

::: proof
这一步恰在前 $j$ 次尝试全部失败且每次都被检测到（概率 $((1 - p)d)^j$）、且第 $j + 1$ 次尝试成功（概率 $p$）时，于第 $j + 1$ 次尝试处成功（$j = 0, \dots, r - 1$）。这些事件互斥，故 $S$ 是它们之和——一个公比 $(1 - p)d < 1$ 的有限等比级数。取 $d = 1$，$S = p\,(1 - (1 - p)^r)/p = 1 - (1 - p)^r$。各步独立，故任务以概率 $S^k$ 成功。
:::

::: example 一次重试换来什么 {#ex-retry}
设 $p = 0.95$、$k = 20$，分别计算完美检测下一次重试（$r = 2$）时的任务成功率，以及一次重试配上能捕获 $80\%$ 失败的检验器时的任务成功率。
::: solution
完美检测：$S = 1 - 0.05^2 = 0.9975$，$S^{20} = 0.951$，比 $0.358$ 高出一大截。$d = 0.8$ 时：$S = 0.95\,(1 + 0.05\cdot0.8) = 0.95\cdot1.04 = 0.988$，且 $0.988^{20} = 0.786$。清单中的模拟给出 $0.948$ 与 $0.786$。完美检测下的一次重试几乎消除了累积效应；不完美的检验器每步仍留下 $(1 - p)(1 - d) = 1\%$ 的残余失败率，而这仍会累积。稀缺的资源是检测，不是重试。
:::
:::

labels: 无恢复 $p^k$; 每步 $r$ 次尝试、检验完美; 每步 $r$ 次尝试、检验捕获比例为 $d$
points: 20,0.3585; 20,0.9512; 20,0.7855
caption: 任务成功率随步数 $k$ 的变化。没有恢复时，成功率按 $p^k$ 衰减（[[#prop-compound]]）。每步 $r$ 次尝试且检验完美时，按 $(1 - (1 - p)^r)^k$ 衰减，慢得多；检验只能捕获一个比例 $d$ 的失败时，未被发现的错误 $(1 - p)(1 - d)$ 决定了衰减速度（[[#prop-retry]]）。标注的点是 $k = 20$ 处 [[#ex-retry]] 的三个值。令 $d = 1$，可见第二条与第三条曲线重合。
:::

当 $r\to\infty$ 时，[[#eq-step-success]] 趋于 $p/(1 - (1 - p)d)$，只要 $d < 1$ 它就小于 $1$：无限制的重试补偿不了没人察觉的失败。这个简单事实组织起智能体设计的许多部分。代码智能体要跑测试，因为测试能检测失败（[[agents/code-agents]]）；工具返回精确的错误信息，因为那些错误就是检测；模式（schema）与校验器能抓住格式不良的调用；而最可靠的智能体，是那些工作在能便宜而如实地告诉它们哪里错了的环境里的智能体。没有这种信号的地方，模型必须检查自己的工作，而关于模型对自己错误的检测能力，证据是好坏参半的（见下文）。

### 把循环看作吸收马尔可夫链

另一种理想化描述的是开放式任务：步数不预先固定。每一步，智能体要么成功完成，要么不可挽回地失败（删掉了需要的数据、陷入无法脱身的状态），要么继续。

::: proposition 开放式循环的成功率与长度 {#prop-absorbing}
设每一步中，智能体独立于过去，以概率 $f$ 成功完成、以概率 $g$ 不可挽回地失败、以概率 $1 - f - g$ 继续，其中 $f + g > 0$。若没有步数预算，任务以概率 $f/(f + g)$ 成功，步数 $N$ 服从均值为 $1/(f + g)$ 的几何分布。预算为 $T$ 步时，成功概率为 $\dfrac{f}{f + g}\big(1 - (1 - f - g)^T\big)$。
:::

::: proof
循环恰在第 $n$ 步以成功结束的概率为 $(1 - f - g)^{n-1}f$。对 $n = 1, \dots, T$ 求和得 $f\,\frac{1 - (1 - f - g)^T}{f + g}$，再令 $T\to\infty$ 得 $f/(f + g)$。循环恰在第 $n$ 步（不论成败）结束的概率为 $(1 - f - g)^{n-1}(f + g)$，这是一个均值为 $1/(f + g)$ 的几何分布。
:::

::: widget markov
matrix: 0.9,0.07,0.03; 0,1,0; 0,0,1
states: Working; Done; Failed
start: 0
steps: 30
caption: 每步 $f = 0.07$、$g = 0.03$ 的智能体循环，视作吸收马尔可夫链。从 "Working" 出发，链条最终将以概率 $0.07/0.10 = 0.7$ 被 "Done" 吸收、以概率 $0.3$ 被 "Failed" 吸收，平均经过 $1/0.1 = 10$ 步（[[#prop-absorbing]]）。调大步数可观察分布收敛；若预算为 $T = 10$ 步，成功率只有 $0.7\,(1 - 0.9^{10}) = 0.46$，而非 $0.7$。
:::

这个公式解释了关于预算的一个常见观察。只有当 $(1 - f - g)^T$ 不可忽略时，提高 $T$ 才有用；超过平均长度 $1/(f + g)$ 的几倍之后，更多的步几乎买不来什么，而每一步都要花词元和时间。比值 $f/(f + g)$ 则指出两个杠杆：要么提高每步迈向成功的概率，要么降低不可挽回失败的概率——例如禁止破坏性操作、保留备份、或在任何不可逆操作之前先征询。

::: warning 「完成」是一个声明，不是一次检验
发出 $\textsf{finish}$ 的智能体相信——或至少预测——任务已经完成。模型会提前收场，对没做过的工作给出自信的总结；会宣布从未运行过的测试通过；会在读到与自己矛盾之前先作答。要把完成当作一个假设：尽可能先在代码中检验结果（跑测试、重读文件、确认记录存在）再接受它，并向用户报告哪些检验过、哪些没有。
:::

## 从失败的尝试中学习 {#sec-reflexion}

用同样的上下文重试同一步，往往重犯同样的错误。在整个任务上失败的智能体，如果知道自己**为什么**失败，下一次就能做得更好。Shinn 等（2023）把这变成了一种方法。

::: definition Reflexion {#def-reflexion}
**Reflexion** 让一个智能体对同一任务重复**尝试**。每次尝试之后，一个评估器给出一个信号——二元的成败、一个标量分数、测试结果、或一个模型的评判——若这次尝试失败，模型就写一段简短的自然语言**自我反思**，分析哪里出了错、下次该怎么做。反思存放在一个情景记忆缓冲区里（保留最近几条），并纳入下一次尝试的上下文。模型权重不变：所谓「学习」全部发生在尝试之间携带的文本里。
:::

作者称之为**语言化的强化学习**：反思扮演的角色，相当于普通强化学习中梯度更新扮演的角色——把稀疏奖励变成具体、可执行的纠正。他们报告了各方面的改进：ALFWorld 的决策任务（在反复尝试下，智能体完成了 $134$ 个任务中的 $130$ 个）、HotpotQA、以及代码生成——在 HumanEval（[[agents/code-agents]]）上，用 GPT-4 的 Reflexion 达到 $91\%$ 的 pass@1，而当时单独使用 GPT-4 报告的是 $80\%$。代码结果说明了此法最擅长的场景：评估器是模型自己编写并运行的一组单元测试——一种便宜且相当可靠的检测信号。

要公允地看待它，需要两点保留。第一，Reflexion 用的是**同一任务的多次尝试、每次之后都有反馈**，其数字不能与单次尝试的结果比较；它是测试时搜索的一种形式（[[reasoning/test-time-scaling]]）。第二，它的收益取决于反馈的质量。Huang 等（2024）发现，让模型在**没有**外部反馈的情况下批评并修改自己对推理题的答案，准确率常常不升反降，因为模型改对答案和改错答案一样随手。只有当模型之外的某种东西——一个测试、一个工具、环境——告诉它错了时，自我纠正才有效；[[#prop-retry]] 用公式说了同一件事，其中一切都系于 $d$。

::: example 第二次尝试何时划算？ {#ex-trials}
一个代码智能体第一次尝试解决某任务的概率为 $0.6$。一套测试能检测出每一次失败。带着写下的反思重试时成功率为 $0.5$；没有反思（一次全新的独立尝试）则为 $0.35$，因为容易的任务已经解决掉了。两种情形下，两次尝试之内成功的概率各是多少？尝试次数的期望是多少？
::: solution
有反思：$0.6 + 0.4\cdot0.5 = 0.80$；没有：$0.6 + 0.4\cdot0.35 = 0.74$。两种情形的期望尝试次数都是 $1 + 0.4 = 1.4$，因为恰好在第一次失败时才进行第二次尝试。反思的价值在于用同样的尝试成本换来六个百分点的提升（再加上反思本身花费的词元）。注意重试的成功率是以第一次失败为条件的：剩下的都是更难的任务，所以重试成功率低于首次成功率——这是对独立性的又一次背离。
:::
:::

其他设计追求同一目标。Self-refine（Madaan 等，2023）让模型迭代地批评并修改单个输出；LATS（Zhou 等，2024）这类树搜索方法探索智能体轨迹的若干分支，用价值估计和反思在分支之间选择；而下一章的规划方法则预先决定如何把任务拆成可检验的部件。

## 设计循环 {#sec-design}

一个可用的脚手架要做出许多定义留而未决的小决定。下面列出的是最影响可靠性与成本的那些。

- **系统提示**写明目标、约定（如何调用工具、如何结束、何时询问用户）、约束和可用的预算。每一步都会读它，因此它比任何其他提示都值得更多斟酌。
- **工具集**应当规模小、描述清楚且**正交**：用途重叠的工具会招来混乱（[[agents/function-calling#sec-selection]]）。为智能体设计的工具往往比为人类设计的界面返回得更少——给搜索结果的摘要而不是原始网页——因为每条观察都要占上下文。
- **观察**应当截断、分页或摘要到有界的大小；错误信息要说出该怎么办（「文件不存在；用 `ls` 查看现有文件」），而不是只说哪里错了。
- **预算**（步数、词元、时间、金钱）为失控循环的成本封顶。[[#prop-absorbing]] 建议把步数预算设为成功运行典型长度的几倍。
- **循环检测。**当智能体用同样参数重复同样动作时停下来或介入——这是自 ReAct 原论文起就很有代表性的一种失败。
- **与人的检查点。**对耗时或有分量的任务，循环可以在预先规定的节点暂停等待批准；对不可逆的操作则必须如此（[[agents/agent-security]]）。
- **执行轨迹。**记录每一次上下文、思考、动作与观察。智能体的失败方式难以预料，可一旦读过却容易看懂；执行轨迹既是调试工具、评测数据（[[agents/agent-security#sec-evaluation]]），也是审计记录。

::: example 长循环的成本 {#ex-loop-cost}
某智能体的上下文从 $6{,}000$ 个词元起，每步增长 $1{,}500$ 个词元（思考、动作和观察）。每一步的输入都是整个上下文。一次 $30$ 步的运行要消耗多少输入词元？按每百万输入词元 $\$3$ 计价，成本是多少？若对不变的前缀做缓存，图景又会如何变化？
::: solution
第 $t$ 步读入 $6{,}000 + 1{,}500(t - 1)$ 个词元。对 $t = 1, \dots, 30$ 求和：$30\cdot6{,}000 + 1{,}500\cdot\frac{29\cdot30}{2} = 180{,}000 + 652{,}500 = 832{,}500$ 个词元，约 $\$2.50$。总额随步数二次增长——把运行加倍到 $60$ 步，得 $360{,}000 + 1{,}500\cdot1{,}770 = 3{,}015{,}000$ 个词元，超过原来的三倍半。由于每一步的上下文都是上一步加上新词元，前缀缓存（[[inference/kv-cache]]）能避免重算其中的大部分；提供商通常按正常价格的一个折扣对缓存输入计费，这改变的是常数，而非上下文自身的增长；上下文增长的上限问题留给 [[agents/memory-context]]。
:::
:::

::: quiz
一个智能体在一批任务上失败 $40\%$。它的执行轨迹显示：多数失败发生在工具返回了一个被它误读的错误之后——此后它自信地沿着错误的路径继续。哪种改动最可能有帮助？
- [ ] 把步数预算从 $30$ 提到 $100$。
- [ ] 要求模型一步步思考。
- [x] 让工具错误明确且可据以行动，并在易出错的步骤后加一道检查，使失败能被检测到并重试。
- [ ] 把同一个智能体跑五遍，取最长的那个答案。
::: solution
轨迹显示的是未被发现的失败：用 [[#prop-retry]] 的话说，$d$ 太小。改进检测——清楚的错误信息、危险步骤之后的检查——正对着这一点下手。更大的预算只对最终会成功的智能体有帮助（[[#prop-absorbing]]）；而这里的智能体是沿着错误的路径继续走。要求推理提供不了缺失的信号，最长的答案也未必最可能正确。
:::
:::

::: history
智能体的抽象——知觉、动作、策略与性能度量——在 Russell 与 Norvig 的教科书（初版 1995；第四版 2020）以及 Wooldridge 关于多智能体系统的工作中为人工智能所确立。语言模型最初是在文字环境中被用作策略的，例如 Huang 等（2022）用提示让模型为家务任务产生一步步的计划，以及 WebGPT 的浏览（Nakano 等，2021）。Yao 等于 2022 年 10 月发布了 ReAct（发表于 ICLR 2023），把推理轨迹与动作、观察结合起来。2023 年春，AutoGPT、BabyAGI 等开源项目让模型在开放式循环中运行、自己生成任务清单，引来广泛关注，也在实践中演示了错误累积得有多快。Shinn 等（2023）提出 Reflexion；Madaan 等（2023）提出 self-refine；Wang 等（2023）提出 Voyager——一个在《我的世界》里把代码当作技能编写并复用的智能体；Huang 等（2024）则提醒：没有外部反馈的自我纠正不可靠。区分工作流与智能体的实践指南（Schluntz 与 Zhang，2024），以及用强化学习专为长程智能体任务训练的模型，到 2025 年已把本章的循环变成标准架构。
:::

::: summary
- 智能体把观察的历史映射为动作；大语言模型智能体以模型为策略、以工具为动作，并靠一个把每次思考、动作、观察追加到上下文里的循环运转。
- 循环由动作集、更新规则与停止条件定义：完成、步数与资源预算、停滞、上报给人。
- 步骤已知就用固定工作流；步骤需要探索才用智能体。
- ReAct 把自由文本的思考与动作、观察交替进行；思考充当工作记忆，观察让推理立足于事实。
- 误差累积：可靠性为 $p$ 的 $k$ 个独立步骤以概率 $p^k$ 成功，每 $\ln2/(-\ln p)\approx0.69/(1 - p)$ 步成功率减半。
- 检验加上每步 $r$ 次尝试可把单步成功率提到 $p\,(1 - ((1 - p)d)^r)/(1 - (1 - p)d)$；限制可靠性的是未被发现的失败，而不是重试。
- Reflexion 在尝试之间携带自然语言反思，在有可靠外部信号时效果最好；没有反馈的自我纠正不可靠。
- 用预算为循环封顶、检测重复、让错误可据以行动、对要紧的操作让人参与、记录完整的执行轨迹。
:::

## 习题

::: exercise 二十步 {level=1 check="0.358"}
某智能体的每一步独立地以概率 $0.95$ 成功。一个 $20$ 步的任务成功的概率是多少？保留三位小数。
::: solution
$0.95^{20} = 0.3585$，保留三位小数为 $0.358$（[[#prop-compound]]）。
:::
:::

::: exercise 半衰期 {level=1 check="68.97"}
每步可靠性 $p = 0.99$ 的智能体，其成功率降到一半需要多少步？保留两位小数。
::: solution
$k_{1/2} = \ln2/(-\ln0.99) = 0.693147/0.0100503 = 68.97$ 步；近似值 $0.693/0.01 = 69.3$ 与之相差不远。
:::
:::

::: exercise 一次重试，检验完美 {level=1 check="0.9975"}
$p = 0.95$、完美检测、共 $r = 2$ 次尝试时的单步成功率是多少？
::: solution
$1 - (1 - 0.95)^2 = 1 - 0.0025 = 0.9975$（[[#prop-retry]] 取 $d = 1$）。
:::
:::

::: exercise 所需的可靠性 {level=2 check="0.99895"}
没有恢复机制时，每步可靠性 $p$ 多大才能让一个 $100$ 步的任务以概率 $0.9$ 成功？保留五位小数。
::: solution
$p = 0.9^{1/100} = \exp(\ln0.9/100) = \exp(-0.0010536) = 0.99895$。
:::
:::

::: exercise 不完美的检验 {level=2 check="0.842"}
某步以概率 $0.9$ 成功。检验器能检测 $85\%$ 的失败，被检测到的失败会重试，总共至多 $3$ 次尝试。单步成功率是多少？一个 $10$ 步任务的成功率是多少？后者保留三位小数。
::: solution
$(1 - p)d = 0.1\cdot0.85 = 0.085$，由 [[#eq-step-success]] 得 $S = 0.9\,(1 + 0.085 + 0.085^2) = 0.9\cdot1.092225 = 0.98300$。于是 $S^{10} = 0.98300^{10} = 0.842$。没有检验器时，任务以概率 $0.9^{10} = 0.349$ 成功。
:::
:::

::: exercise 开放式任务的预算 {level=2 check="0.4559"}
在 [[#prop-absorbing]] 的设定下，$f = 0.07$、$g = 0.03$，预算为 $T = 10$ 步时的成功概率是多少？保留四位小数。预算多大才能拿到无预算时可达成功概率的 $95\%$？
::: solution
$\frac{0.07}{0.10}(1 - 0.9^{10}) = 0.7\,(1 - 0.348678) = 0.7\cdot0.651322 = 0.45593$，即 $0.4559$。要达 $95\%$ 需 $0.9^T\le0.05$，即 $T\ge\ln0.05/\ln0.9 = 28.4$，故 $T = 29$ 步——约为平均运行长度 $10$ 的三倍。
:::
:::

::: exercise 二次增长的成本 {level=2}
证明：若智能体的上下文从 $c_0$ 个词元起、每步增长 $\delta$ 个词元，则 $T$ 步内输入词元总数为 $Tc_0 + \delta\,T(T - 1)/2$。对 $c_0 = 6{,}000$、$\delta = 1{,}500$，求增长项首次超过固定项时的步数。
::: solution
第 $t$ 步读入 $c_0 + \delta(t - 1)$ 个词元，且 $\sum_{t=1}^{T}(t - 1) = T(T - 1)/2$。当 $\delta(T - 1)/2 > c_0$ 时增长项超过固定项，即 $T - 1 > 2c_0/\delta = 8$，故从 $T = 10$ 步起（$T = 9$ 时两者相等：$9\cdot6{,}000 = 54{,}000 = 1{,}500\cdot36$）。在此之后，智能体的成本主要花在重读自己的历史上。
:::
:::

::: exercise 无限重试 {level=3}
证明当 $r\to\infty$ 时 [[#prop-retry]] 的单步成功率趋于 $p/(1 - (1 - p)d)$，且每步尝试次数的期望为 $(1 - ((1 - p)d)^r)/(1 - (1 - p)d)$。解释 $d = 0.5$、$p = 0.8$ 时的极限。关于把算力花在更多重试还是更好的检测上，这说明了什么？
::: solution
[[#eq-step-success]] 中的等比求和收敛，因为 $(1 - p)d < 1$。恰当前 $j$ 次尝试全部失败且都被检测到（概率 $((1 - p)d)^j$）时才会进行第 $j + 1$ 次尝试，故尝试次数的期望为 $\sum_{j=0}^{r-1}((1 - p)d)^j = (1 - ((1 - p)d)^r)/(1 - (1 - p)d)$。取 $p = 0.8$、$d = 0.5$，极限为 $0.8/(1 - 0.1) = 0.889$：无论重试多少次，这一步都超不过 $89\%$，而第二次之后的每次重试增添甚少（$r = 2$ 已给出 $0.8\cdot1.1 = 0.88$）。把检测提到 $d = 0.9$，极限则为 $0.8/0.82 = 0.976$。超过一两次重试之后，算力更值得花在检测上——测试、校验器、独立检查——而不是更多尝试。
:::
:::

::: exercise 一个循环检测器 {level=3}
给清单中的 `run_agent` 加上 [[#def-stopping]] 的两个停止条件：同一个（工具，参数）对被选中三次，或连续三条观察都是错误时，带着失败信息停止。用一个总是对不存在的文件调用 `read` 的模型来测试它。
::: solution
```python
import json
FILES = {"notes.txt": "budget: see q3.csv"}
TOOLS = {"read": lambda path: FILES[path]}

def run_agent(task, model, max_steps=8, max_repeat=3, max_errors=3):
    history, seen, errors = [{"role": "user", "content": task}], {}, 0
    for step in range(1, max_steps + 1):
        thought, (name, args) = model(history)
        if name == "final":
            return args["answer"], step
        key = (name, json.dumps(args, sort_keys=True))
        seen[key] = seen.get(key, 0) + 1
        if seen[key] >= max_repeat:
            return f"stopped: repeated {name} {key[1]} {seen[key]} times", step
        try:
            obs, errors = TOOLS[name](**args), 0
        except Exception as e:
            obs, errors = f"error: {e!r}", errors + 1
            if errors >= max_errors:
                return f"stopped: {errors} consecutive errors", step
        history += [{"role": "assistant", "content": [thought, name, args]},
                    {"role": "tool", "content": obs}]
    return "stopped: step budget", max_steps

stubborn = lambda h: ("Read the data.", ("read", {"path": "q3.csv"}))
print(run_agent("Total for Q3?", stubborn))
```

```text
('stopped: repeated read {"path": "q3.csv"} 3 times', 3)
```

这里两个条件都会在第 $3$ 步触发；代码中重复检查在前。参数用排序后的键序列化，于是 `{"a":1,"b":2}` 与 `{"b":2,"a":1}` 算作同一次调用。真正的检测器还应抓住近似重复（换了几个字同义的搜索），这需要的是相似度度量而不是相等比较。
