智能体在任何给定时刻关于其任务所知的一切，都在它的上下文里：指令、工具定义、对话、到目前为止的每一段思考、每一次调用、每一条观察。上下文就是智能体的工作记忆，而和一切工作记忆一样，它很小。$128{,}000$ 词元的窗口听起来很慷慨——直到智能体读几个源文件、跑一个打印三千行输出的测试套件、再搜索两次网络。长任务会撑爆任何窗口；而在撑爆之前很久，一个杂乱的上下文就会让模型变慢、变贵、变笨。决定什么进上下文、什么被压缩、什么存在别处、什么再取回来——这一在 2025 年被称为**上下文工程**的实践——对智能体成败的重要性不亚于模型本身。

本章把记忆当作一种需要编预算的资源。先讲上下文预算的算术：词元花在何处、智能体消耗它们有多快、一次运行能持续多久。然后导出**压缩**（compaction）——历史过长时加以摘要——的经济学，包括在一个简单模型下使成本最小的阈值，并用一个用普通 Python 写成的预算模拟器检验结果。接下来是检索式记忆：过去的信息存在上下文之外，靠搜索取回，以 Park 等（2023）的 Generative Agents 的评分规则为例题算一遍。MemGPT（Packer 等，2023）展示了模型如何经由函数调用亲自管理这样一个层级；本章以所有记忆里最简单、也常常最有效的那种收尾：智能体写给未来自己的文件。

## 作为预算的上下文 {#sec-budget}

::: definition 上下文预算 {#def-budget}
在第 $t$ 步，智能体的上下文 $c_t$（[[agents/agent-loops#def-loop]]）占据
$$
\lvert c_t\rvert = \underbrace{F}_{\text{系统提示、工具定义}} + \underbrace{M_t}_{\text{已载入的记忆}} + \underbrace{H_t}_{\text{历史}} + \underbrace{o_t}_{\text{最新观察}}
$$
个词元，而窗口 $W$ 还必须容得下模型的输出，所以要始终空出一个**预留量** $R$（最大输出长度，含一切推理词元）：$\lvert c_t\rvert + R\le W$。**历史预算**是 $W - R - F - M_t$，即留给任务自身记录的空间。
:::

固定部分 $F$ 在每一步都要付费，历史里携带的一切也一样。几个关于长上下文的事实使得预算比窗口表面看起来更紧。对长上下文的注意力，其计算与显存开销随长度增长（[[inference/kv-cache]]、[[inference/long-context]]）。准确率也会退化：模型检索长上下文中部的事实不如在开头或末尾可靠（Liu 等，2024），而在比单事实检索更苛刻的任务上，长上下文使用的基准发现有效长度——性能仍与短上下文时相近的长度——常常远低于标称窗口（Hsieh 等，2024）。上下文是一种随使用退化的资源，不是一个可以填满的免费缓冲区。

::: example 词元花在哪里 {#ex-budget}
某智能体的窗口是 $128{,}000$ 个词元。它的系统提示占 $2{,}500$ 个词元，$22$ 个工具定义占 $6{,}500$ 个，任务占 $1{,}000$ 个，并为输出预留 $8{,}000$ 个词元。每一步大约追加 $300$ 个词元的思考与调用，以及平均 $1{,}972$ 个词元的观察。窗口装满之前能容纳多少步？
::: solution
固定负载 $F = 2{,}500 + 6{,}500 = 9{,}000$；加上任务与预留量，$9{,}000 + 1{,}000 + 8{,}000 = 18{,}000$ 个词元已被占用，历史还剩 $110{,}000$ 个。一步平均花 $2{,}272$ 个词元，所以大约装得下 $110{,}000/2{,}272 = 48$ 步。一个代码智能体在一处不起眼的改动上就可能用掉五十步；吃掉窗口的不是推理而是观察，所以观察是第一个要管理的东西。
:::
:::

### 增长、溢出与成本

若不加管理，历史线性增长，于是上下文在一个可预见的步数之后撞上窗口，而整个运行的总成本二次增长（[[agents/agent-loops#ex-loop-cost]]）。三类技术能把它约束住：

- **截断**丢弃最旧的轮次（滑动窗口）。它简单，但会丢掉任务的开头——那里往往放着最重要的信息：指令与早期发现。
- **观察清除**保留*做过什么*的记录，但把旧的工具输出换成一小段占位符（「`read config.yaml` 的输出，3,140 个词元，已移除」）。智能体几乎从不需要三十步之前读过的文件的全文；真需要时，重新读一遍就是。这是最便宜、常常也是最有效的技术。
- **压缩**（摘要）用一段模型撰写的、关于任务到目前为止的摘要替换历史——目标、决定、发现、未决问题、相关文件名——然后从摘要继续。

::: example 观察清除买来了什么 {#ex-clearing}
在 [[#ex-budget]] 的智能体中，观察一旦超过五步就被换成 $20$ 个词元的占位符。忽略最近五条观察，现在 $110{,}000$ 个词元的历史预算里装得下多少步？智能体失去了什么？
::: solution
每条旧步骤如今花掉 $300$ 个词元的思考与调用，加 $20$ 个词元的占位符，共 $320$ 个词元，而最近五条观察占去约 $5\cdot1{,}972\approx9{,}900$ 个词元。于是 $(110{,}000 - 9{,}900)/320\approx313$ 步装得下，比之前多了六倍还不止。智能体保住了它做了什么、为何而做的记录，失去的是它看到过的细节；由于观察来自工具，它通常能靠重新调用工具找回——这正是清除比摘要更安全、并且在工具便宜而确定时效果最好的原因。
:::
:::

::: definition 压缩 {#def-compaction}
一个阈值为 $C$、摘要长度为 $s$ 的**压缩策略**监控着 $\lvert c_t\rvert$。当上下文超过 $C$（要求 $C + R\le W$）时，一次摘要器调用读取上下文，写出一份至多 $s$ 个词元的摘要；历史被摘要取代，于是上下文降到 $B = F + M + s$ 个词元，循环继续。下一次压缩时，这份摘要本身可能再次被摘要（**递归摘要**）。
:::

::: proposition 压缩的成本 {#prop-compaction}
设每步追加 $\delta$ 个词元，压缩把上下文重置回 $B$，并在其达到 $C > B$ 时触发；一次运行的成本以输入词元计：每一步读取整个上下文，每次压缩读取一个大小为 $C$ 的上下文。那么在 $T$ 步之上、当 $T$ 远大于周期长度 $L = (C - B)/\delta$ 时，上下文平均为 $(B + C)/2$ 个词元，总输入成本近似为
$$
\text{成本}(C) \approx T\,\frac{B + C}{2} + \frac{T}{L}\,C = T\left(\frac{B + C}{2} + \frac{\delta\,C}{C - B}\right).
$$ {#eq-compaction-cost}
它在
$$
C^{*} = B + \sqrt{2\,\delta B}.
$$ {#eq-optimal-threshold}
处取到最小。
:::

::: proof
两次压缩之间，上下文以 $\delta$ 为步长从 $B$ 增长到 $C$，构成一个 $L$ 步的周期，周期内上下文平均为 $(B + C)/2$（除步长的离散性外是精确的）。周期约有 $T/L$ 个，每个周期以一次读取 $C$ 个词元的压缩收尾。代入 $L = (C - B)/\delta$ 即得 [[#eq-compaction-cost]]。令 $u = C - B > 0$。由于 $\frac{\delta C}{C - B} = \delta + \frac{\delta B}{u}$，每步成本为 $\frac{2B + u}{2} + \delta + \frac{\delta B}{u}$。它对 $u$ 的导数是 $\frac12 - \frac{\delta B}{u^2}$，在 $u = \sqrt{2\delta B}$ 处为零，而二阶导数 $2\delta B/u^3 > 0$ 确认这是极小值。于是 $C^{*} = B + \sqrt{2\delta B}$。
:::

这是一个库存论里经济订货批量那一类熟悉的平方根定律：压缩得太频繁，浪费摘要器的调用；压缩得太稀疏，每一步都要背着一个长上下文。它的实践含义是：成本最优的阈值远低于整个窗口——取 $B = 14{,}000$、$\delta = 2{,}272$，得 $C^{*}\approx B + 7{,}976 \approx 22{,}000$ 个词元。但模型只数词元。每次压缩还会*丢失信息*，并且有引入错误的风险，因为摘要是和其他文本一样的模型输出；这笔成本把阈值往上推。真实系统的压缩点远比 $C^{*}$ 靠后——常见的是在窗口的一大截分数处——并用几乎不丢什么的观察清除来减缓其间的增速 $\delta$。

### 一个上下文预算模拟器

下面的清单模拟 [[#ex-budget]] 的智能体跑 $150$ 步，观察大小由一个固定的、带种子的分布抽出，使每种策略看到的都是同样的步骤。它比较四种做法：不加管理、观察清除（最近五条观察保留全文，其余换成占位符）、在两个不同阈值处压缩、以及两者并用。

```python
import random

W        = 128_000   # 上下文窗口（词元）
FIXED    = 9_000     # 系统提示 + 工具定义
RESERVE  = 8_000     # 为模型的输出留空
TASK     = 1_000     # 用户的请求

def step_tokens(rng):
    """一步追加的词元数：思考 + 调用（约 300）加一条观察（大小不定）。"""
    return 300 + rng.choice([200, 400, 800, 1500, 3000, 6000])

def run(strategy, steps=150, seed=0, threshold=0.8, summary=4_000, keep_obs=5):
    rng = random.Random(seed)                    # 让每种策略看到同样的步骤
    history = []                                 # (调用词元, 观察词元) 的列表
    summ, total_read, compactions = 0, 0, 0
    for t in range(1, steps + 1):
        call = 300; obs = step_tokens(rng) - call
        history.append([call, obs])
        if strategy in ("clear", "both"):                  # 旧观察换成占位符
            for h in history[:-keep_obs]:
                h[1] = min(h[1], 20)
        used = FIXED + TASK + summ + sum(c + o for c, o in history)
        if strategy in ("compact", "both") and used > threshold * (W - RESERVE):
            summ, history, compactions = summary, [], compactions + 1
            used = FIXED + TASK + summ
        if used > W - RESERVE:
            return f"{strategy:8s} overflow at step {t:3d}, read {total_read/1e6:5.2f}M tokens"
        total_read += used                       # 每一步都重读整个上下文
    return (f"{strategy:8s} {steps} steps,          read {total_read/1e6:5.2f}M tokens,"
            f" final context {used:6d}, compactions {compactions}")

rng = random.Random(0)
mean = sum(step_tokens(rng) for _ in range(100000)) / 100000
print(f"mean tokens per step {mean:.0f}; budget for history "
      f"{W - RESERVE - FIXED - TASK} tokens -> about {(W - RESERVE - FIXED - TASK)/mean:.0f} steps")
for s, th in [("none", 0.8), ("clear", 0.8), ("compact", 0.8), ("compact", 0.4), ("both", 0.3)]:
    print(f"threshold {th}:", run(s, threshold=th))
```

```text
mean tokens per step 2272; budget for history 110000 tokens -> about 48 steps
threshold 0.8: none     overflow at step  50, read  2.94M tokens
threshold 0.8: clear    150 steps,          read  6.60M tokens, final context  66300, compactions 0
threshold 0.8: compact  150 steps,          read  8.01M tokens, final context  23900, compactions 4
threshold 0.4: compact  150 steps,          read  4.37M tokens, final context  24400, compactions 9
threshold 0.3: both     150 steps,          read  3.81M tokens, final context  28700, compactions 5
```

不加管理时，运行在第 $50$ 步死掉，与预算算术的预言一致。只靠观察清除就能跑满 $150$ 步，上下文只按每步 $320$ 个词元（调用加占位符）增长。在预算的 $80\%$ 处压缩同样能完成运行，但总共读取的词元比清除还多，因为它在每个周期的大部分时间里都背着接近装满的上下文——这正是 [[#eq-compaction-cost]] 的效应（模拟没有计摘要器的调用，若计入约再添 $4\times96{,}000$ 个词元）。把阈值调低，成本减半；清除加压缩的组合最便宜，需要的摘要还更少。这些数字完全忽略了质量的一面：九次摘要，就是九次弄丢关键细节的机会。

::: warning 摘要有损、会错，是模型输出
压缩用模型对事实的转述替换事实本身。摘要器认为不要紧的细节——一条精确的错误信息、一个文件路径、用户提过一次的一个约束——都没了，而智能体并不知道自己忘了什么。摘要还可能是错的：一个失败的测试被写成通过，一个智能体自己做的决定被安到用户头上。要按固定的模板写摘要（目标、约束、决定及其理由、当前状态、未决问题、完整细节存放处的指涉），在上下文之外保留原始历史以便检索，并且绝不让摘要成为用户指令的唯一记录。
:::

## 记忆的种类 {#sec-kinds}

心理学把工作记忆与长期记忆区分开，又把长期记忆分为情景记忆（事件）、语义记忆（事实）与程序性记忆（技能）。Sumers 等（2024）在他们的 CoALA 框架里把这些类别搬到了语言智能体上，是一套有用的词汇。

::: definition 语言智能体中的记忆 {#def-memory}
- **工作记忆**就是上下文本身：模型在这一步正注意着的东西。
- **情景记忆**保存过往经历的资料——这个任务早先的步骤、此前的会话、过去的轨迹及其结局（[[agents/agent-loops#def-reflexion]] 的反思就是情景记忆）。
- **语义记忆**保存关于世界或用户的事实：文档、知识库、用户的偏好。
- **程序性记忆**保存如何行动：模型的权重、系统提示，以及可复用的技能，比如代码片段或反复出现的任务的操作说明。

长期记忆存在于上下文之外，只有被**检索**时才进入上下文；写入它们是另一个独立的决定。
:::

于是设计问题就是：写什么、写到哪里、怎么读回来。什么都写，会得到一份大到检索不好的记忆；有选择地写，则需要一个通常由模型做出的判断——什么以后会用得上。读回来需要一个查询，以及一个足够好的检索方法：需要时找对那条记忆，同时不找错。

## 检索式记忆 {#sec-retrieval}

最常见的长期记忆是一个文本条目库——过往的消息、观察、笔记、文档块——为搜索建好索引，每一步或智能体开口索要时接受查询。[[prompting-rag/retrieval-augmented-generation]] 里的一切在此都适用：条目被嵌入（[[prompting-rag/text-embeddings]]），与查询最相似的被检索出来，智能体的上下文收到前 $k$ 条。智能体的记忆添上两样静态文档库没有的难处。记忆会累积、会变旧，所以*时近性*与相似度同样要紧；并非所有记忆都值得唤起同样的多次回忆，所以*重要性*也要紧。

::: definition 记忆的检索得分（Generative Agents） {#def-ga-score}
在 Park 等（2023）的 Generative Agents 里，带时间戳的**记忆流**中的每条记忆 $m$ 对时刻 $t$ 的查询 $q$ 有三个得分：**时近性** $\operatorname{rec}(m) = \lambda^{\,t - t_m}$，其中 $t_m$ 是 $m$ 最近被访问的时刻（他们取每模拟小时 $\lambda = 0.995$）；**重要性** $\operatorname{imp}(m)$，写入记忆时模型给出的 $1$ 到 $10$ 的评分；**相关性** $\operatorname{rel}(m, q)$，二者嵌入的余弦相似度。每个得分都在候选记忆之间做 min–max 归一化到 $[0, 1]$，检索得分为如下加权和：
$$
\operatorname{score}(m) = \alpha_{\text{rec}}\,\widehat{\operatorname{rec}}(m) + \alpha_{\text{imp}}\,\widehat{\operatorname{imp}}(m) + \alpha_{\text{rel}}\,\widehat{\operatorname{rel}}(m, q),
$$ {#eq-ga-score}
他们的实现里各权重都取 $1$。得分最高、且放得进预算的记忆被放进上下文。
:::

::: example 哪条记忆会被唤起？ {#ex-ga}
对查询「为聚会做计划」，三条记忆是候选。记忆 1 在一小时前被访问，重要性 $3$，相关性 $0.62$；记忆 2：三十小时前，重要性 $8$，相关性 $0.55$；记忆 3：两百小时前，重要性 $6$，相关性 $0.81$。取 $\lambda = 0.995$、权重全为 $1$，算一算 [[#eq-ga-score]]。
::: solution
时近性：$0.995^{1} = 0.995$、$0.995^{30} = 0.860$、$0.995^{200} = 0.367$；归一化到 $[0, 1]$ 得 $1$、$0.786$、$0$。重要性 $3, 8, 6$ 归一化为 $0$、$1$、$0.6$。相关性 $0.62, 0.55, 0.81$ 归一化为 $0.269$、$0$、$1$。得分：记忆 1，$1 + 0 + 0.269 = 1.269$；记忆 2，$0.786 + 1 + 0 = 1.786$；记忆 3，$0 + 0.6 + 1 = 1.600$。最先被唤起的是记忆 2，尽管它与查询的相似度*最低*。min–max 归一化会把候选之间的小差距拉伸到整个区间，于是权重的可读性没有看上去那么好：只有三个候选时，每个分量都必有一个 $0$ 和一个 $1$。
:::
:::

:::

Park 等还引入了记忆意义上的**反思**：定期地，智能体自问从近期的记忆里能得出什么高层结论，并把这些结论存成新的、更抽象的记忆，此后它们和其他记忆一样可检索。这类摘要把长长的经历记录变成语义记忆。他们的智能体——一座小镇里的二十五个模拟角色——在两天的模拟里记得事情、建立关系、协调起了聚会这样的事；消融实验报告说，去掉观察、规划或反思中的任何一样，人类评审都会觉得角色的行为更不可信。

检索式记忆的失败模式就是一般检索的失败模式，只是被累积雪上加霜：该检索到的记忆没检索到（查询与它不像）、检索到的是一条该被其更正版本顶掉的旧记忆、从不可信内容写下的记忆会留存并在后续会话里卷土重来。最后一条是安全问题——一条在记忆里幸存的植入指令，会影响之后每个检索到它的任务（[[agents/agent-security]]）——这也正是应当为每条记忆记录**来源**、并让用户能查看和删除智能体对他们记得什么的原因。

## 让模型自己管理记忆：MemGPT {#sec-memgpt}

在以上设计中，决定何时检索、何时压缩的是模型之外的代码。Packer 等（2023）提出把这些决定交给模型，类比是一个在快慢存储器之间换页的操作系统。

::: definition MemGPT {#def-memgpt}
**MemGPT** 把记忆分为**主上下文**——即模型的上下文窗口——和模型无法直接看到的**外部上下文**。主上下文里有系统指令、一份可编辑事实的**工作上下文**（例如关于用户与智能体人设的事实），以及一个先进先出的近期消息队列。外部上下文里有**回忆存储**（消息的完整历史，可搜索）与**归档存储**（一个开放式的文本库，按嵌入搜索）。模型通过函数调用在两者之间搬运信息——追加或编辑工作上下文、向归档存储写入、以分页的结果搜索回忆或归档存储。当队列逼近窗口上限时，系统插入一条「记忆压力」警告，让模型来得及保存要紧的东西；当队列装满时，较旧的消息被换出到回忆存储，并以一份递归摘要顶替。
:::

模型还必须能够在作答之前连续执行好几个记忆操作——搜索、读一页结果、再搜索——所以 MemGPT 允许一次函数调用请求把控制权立即交还给模型，而不是等下一条用户消息。作者在长得多会话对话（问题引用早先会话里早已离开窗口的信息）和需要在许多文档之间查证的文档分析任务上对它做了评测，报告它在两类任务上都胜过固定上下文的基线。这一教训可以推广到这个具体系统之外：记忆操作可以像其他操作一样是工具，而模型能够学会决定何时记住、何时去查。代价是记忆管理会与任务争夺模型的注意力和步数，而它的出错——没保存一条事实、保存了一条错的——与任何工具调用的出错同样可能发生。

::: example 一次记忆搜索的成本 {#ex-memgpt}
一个自己管理记忆的智能体要回答一个关于早先会话的问题。它发出一次回忆搜索（$80$ 个词元），收到一页 $5$ 条、每条约 $200$ 个词元的结果；又发出一次改进过的搜索（$80$ 个词元），再收到 $1{,}000$ 个词元；然后作答。它的主上下文在第一次搜索前是 $9{,}000$ 个词元。三次模型调用一共读入多少输入词元？与一种「每次调用模型之前总把前五条记忆检索进上下文」的设计相比如何？
::: solution
第 $1$ 次调用读 $9{,}000$；第 $2$ 次读 $9{,}000 + 80 + 1{,}000 = 10{,}080$；第 $3$ 次读 $10{,}080 + 80 + 1{,}000 = 11{,}160$。合计 $30{,}240$ 个输入词元、三次串行调用。自动检索进上下文的设计一次调用读 $9{,}000 + 1{,}000 = 10{,}000$ 个词元——成本与延迟都是三分之一——但它不管需不需要，每一轮都检索，而且用的查询（用户的消息）可能不如模型自己拟的好。模型主导的记忆用调用次数换灵活；自动检索用噪声付账。
:::
:::

## 草稿文件与结构化状态 {#sec-files}

有些最有效的智能体记忆一点都不巧妙。一个有文件系统的智能体可以写给未来自己的便条：一份勾着已完成条目的计划待办清单（[[agents/planning]]）、一份进展日志、一份决定及其理由的文件、一份行之有效的命令记录。这些文件能在压缩、重启或移交另一个智能体之后存活；它们很小；智能体恰在需要时用平常的工具读回它们；而且人能读、能改。许多代码智能体还会在每次会话开头读一份项目级指令文件——约定、构建与测试命令、坑——那就是人写、智能体编辑的程序性记忆。

草稿文件背后的原理，与本章每种技术背后的原理相同：在当前这一步需要的东西留在上下文里，其余一切放在找得到的地方，并让这条边界清清楚楚。**结构化状态**是最强的形式。若任务有一个天然的状态——改过的文件集合、失败的测试清单、表单已填的字段——把它保存在一个数据结构里，由运行时更新、每一步渲染进上下文，比指望模型从长长的历史里自己重建要可靠得多。

::: application 上下文工程的实践
截至 2026 年，实践者谈长程智能体时反复出现的一张检查清单：保持系统提示与工具定义稳定（这也让前缀缓存收益最大）；返回简明的工具结果、让智能体自己要求更多（分页，用 `head` 和 `grep`，而不是整个文件倒进上下文）；清除过时的观察；按模板压缩，而不是随手写散文；维护一份计划或待办文件，并在压缩后重读；把大量的探索性读取交给一个只汇报结论的子智能体（[[agents/multi-agent-systems]]）；在上下文之外记录完整历史，以便检索或审计。这些没有一样需要更长的窗口，而在有更长窗口可用时，它们照样管用。
:::

::: quiz
一个智能体已经干了三个小时。第三次压缩之后，它开始重做第一小时里已经完成的工作，还违背了一条用户在开头给过的约束。最稳妥的补救是什么？
- [ ] 换一个上下文窗口更大的模型，关掉压缩。
- [ ] 更频繁地压缩，让摘要更短。
- [x] 把用户的指令和进展文件保存在可压缩的历史之外——固定在上下文里，或在每次压缩后重读——并按一份记录了已完成工作的模板来压缩。
- [ ] 调高温度，让智能体探索新工作而不是重复旧工作。
::: solution
症状是教科书式的摘要丢失：指令和已完成工作的记录被压缩掉了。把绝不该丢的东西固定住，并把进展写进会被重读的文件，要紧的状态就不再看摘要器的脸色。更大的窗口只是推迟问题，还让每一步更贵；更频繁的压缩丢得更多；温度与此无关。
:::
:::

::: history
神经网络记忆的沿革本身源远流长：循环网络携带状态，LSTM（Hochreiter 与 Schmidhuber，1997）用门保护状态，记忆网络（Weston 等，2015）与神经图灵机（Graves 等，2014）则给了网络一个由注意力读取的外部存储器。检索增强的语言模型（Lewis 等，2020；Borgeaud 等，2022）让外部文本记忆成了常规配置。在智能体方面，Park 等（2023）带来了带时近性、重要性与相关性得分以及反思的记忆流；Packer 等（2023）提出 MemGPT 的操作系统类比、由模型管理的换页；Shinn 等（2023）让言语化的反思在多次尝试之间传递；Wang 等（2023）在 Voyager 里保存可复用的代码技能。Sumers 等（2024）用 CoALA 框架把这些设计梳理成一个体系。Liu 等（2024）记录了「迷失在中间」效应，Hsieh 等（2024）发现有效上下文长度低于标称窗口。2024–2025 年，托管助手加上了跨会话的用户记忆，代码智能体采纳了项目指令文件与自动压缩，实践者则开始把整门学问称为上下文工程。
:::

::: summary
- 上下文是一份预算：窗口 $=$ 固定指令与工具 $+$ 已载入的记忆 $+$ 历史 $+$ 最新观察 $+$ 输出预留。历史里通常以观察为主。
- 无人管理的历史线性增长，在可预见的步数后溢出，并使总成本变成二次；长上下文还在装满之前就拖累准确率。
- 截断、观察清除与压缩能给上下文封顶；清除丢得最少，压缩丢得最多。
- 从 $B$ 出发、阈值在 $C$ 的压缩，每步成本约为 $(B + C)/2 + \delta C/(C - B)$，在 $C^{*} = B + \sqrt{2\delta B}$ 处最小；信息丢失把真实阈值推得更高。
- 长期记忆分情景、语义或程序性，存在上下文之外、靠检索进入；智能体的记忆除相关性外还需要时近性与重要性，如 Generative Agents 的得分所示。
- MemGPT 让模型通过函数调用在上下文与外部存储之间搬运信息，用调用次数换灵活。
- 草稿文件、固定的指令与结构化状态是最简单可靠的记忆：它们熬得过压缩，人也读得到。
- 记忆同样会留存不可信内容；记录来源，并让用户能查看和删除记忆。
:::

## 习题

::: exercise 溢出前的步数 {level=1 check="40"}
某智能体的窗口为 $64{,}000$ 个词元，为输出预留 $4{,}000$ 个词元，系统提示、工具与任务共占 $12{,}000$ 个词元。每步追加 $1{,}200$ 个词元。能装下多少个完整的步？
::: solution
历史预算 $64{,}000 - 4{,}000 - 12{,}000 = 48{,}000$ 个词元；$48{,}000/1{,}200 = 40$ 步。
:::
:::

::: exercise 压缩下的平均上下文 {level=1 check="55000"}
压缩把上下文重置回 $B = 14{,}000$ 个词元，并在 $C = 96{,}000$ 处触发。长期运行下，每步的平均上下文有多大？
::: solution
$(B + C)/2 = (14{,}000 + 96{,}000)/2 = 55{,}000$ 个词元（[[#prop-compaction]]）。
:::
:::

::: exercise 时近性衰减 {level=1 check="138.3"}
按 [[#def-ga-score]] 中每小时的时近性因子 $\lambda = 0.995$，一条记忆的原始时近性经多少小时衰减到一半？保留一位小数。
::: solution
由 $0.995^h = 0.5$ 得 $h = \ln0.5/\ln0.995 = 0.693147/0.0050125 = 138.3$ 小时，将近六天。
:::
:::

::: exercise 最优阈值 {level=2 check="22000"}
取 $B = 14{,}000$、每步 $\delta = 2{,}272$ 个词元，用 [[#eq-optimal-threshold]] 计算 $C^{*}$，四舍五入到千位词元，并求以步为单位的周期长度 $L$。
::: solution
$\sqrt{2\cdot2{,}272\cdot14{,}000} = \sqrt{63{,}616{,}000} = 7{,}976$，故 $C^{*} = 21{,}976\approx22{,}000$ 个词元，而 $L = 7{,}976/2{,}272 = 3.5$ 步——每三四步就要压缩一次。这说明纯词元模型离实践有多远：信息丢失让如此频繁的摘要无法接受。
:::
:::

::: exercise 比较成本 {level=2 check="57.7"}
在 [[#eq-compaction-cost]] 中取 $B = 14{,}000$、$\delta = 2{,}272$，计算 $C = 96{,}000$ 时每步的成本，以千词元计、保留一位小数。再与 $C^{*}$ 处的每步成本比较。
::: solution
$C = 96{,}000$ 时：$(14{,}000 + 96{,}000)/2 + 2{,}272\cdot96{,}000/82{,}000 = 55{,}000 + 2{,}660 = 57{,}660$ 个词元，即 $57.7$ 千。$C^{*} = 21{,}976$ 时：$(14{,}000 + 21{,}976)/2 + 2{,}272\cdot21{,}976/7{,}976 = 17{,}988 + 6{,}260 = 24{,}248$，约 $24.2$ 千——不到一半。靠后的阈值是用词元买单的；它买到的是更少的有损摘要。
:::
:::

::: exercise 摘要里该放什么 {level=2}
为一个代码智能体设计一份压缩模板：列出各节，说明每节放什么，并逐节解释它各自防住哪种失败。
::: solution
(1) **任务与约束**，从用户处逐字照抄、绝不转述——防止对原始请求的走样。(2) **已做的决定，附理由**——防止反复争论已定之事、防止自相矛盾。(3) **当前状态**：改过的文件、通过和失败的测试、所在分支——防止重做或撤销已完成的工作。(4) **未决问题与下一步**——让计划穿过压缩这一边界存活。(5) **发现的事实**（某个 API 的怪癖、配置的位置），并指涉完整细节所在（文件路径、日志偏移）——让摘要保持短小的同时，智能体还能找回细节。(6) **核验过什么、如何核验**——防止摘要把声明变成事实。各节固定不变，遗漏才看得见；存在结构化状态时，摘要应当与它对照检查。
:::
:::

::: exercise 推导最优值 {level=3}
把 [[#prop-compaction]] 的推导在如下设定下重做一遍：每次压缩花费固定的 $\kappa$ 个词元（摘要器只读自上次压缩以来的历史，外加固定开销），而不是 $C$ 个。证明最优阈值为 $C^{*} = B + \sqrt{2\delta\kappa}$，并加以解释。
::: solution
每步的读取成本平均为 $(B + C)/2$；压缩每 $L = (C - B)/\delta$ 步发生一次、每次花 $\kappa$，故每步成本为 $\frac{B + C}{2} + \frac{\delta\kappa}{C - B}$。令 $u = C - B$：$\frac{2B + u}{2} + \frac{\delta\kappa}{u}$，其导数 $\frac12 - \frac{\delta\kappa}{u^2}$ 在 $u = \sqrt{2\delta\kappa}$ 处为零。这条平方根定律正是经济订货批量的定律：持有成本（每步）随 $u$ 线性增长，订货（压缩）成本（每步）按 $1/u$ 下降。摘要更便宜（$\kappa$ 小）就更有理由压缩得更勤；增长更快（$\delta$ 大）在词元上值得更长的周期，却也意味着按步数算压缩来得更勤。
:::
:::

::: exercise 归一化与无关候选 {level=3}
证明在 min–max 归一化下，[[#eq-ga-score]] 给出的排序会仅仅因为往候选集中加入一条既陈旧、又不重要、相关性也不高于其余的记忆而改变，尽管原来那些记忆的一切都没有变。取记忆 1 的（时近性、重要性、相关性）$= (0.9, 6, 0.6)$，记忆 2 的 $= (0.5, 5, 0.8)$，再加入记忆 3 $= (0, 1, 0.6)$。提出一种没有此毛病的评分规则。
::: solution
两个候选时：时近性归一化为 $1, 0$；重要性为 $1, 0$；相关性为 $0, 1$。得分：记忆 1 得 $2$；记忆 2 得 $1$。记忆 1 排第一。加入记忆 3 后：时近性 $0.9, 0.5, 0$ 归一化为 $1, 0.556, 0$；重要性 $6, 5, 1$ 为 $1, 0.8, 0$；相关性 $0.6, 0.8, 0.6$ 为 $0, 1, 0$。得分：记忆 1 得 $2$；记忆 2 得 $0.556 + 0.8 + 1 = 2.356$；记忆 3 得 $0$。记忆 2 现在排第一。新加的记忆得分为零、永远不会被唤起，但它靠拉伸时近性与重要性两把尺，缩小了记忆 1 在这些分量上的优势，而记忆 2 的相关性优势仍是满值 $1$。没有此毛病的规则使用固定的尺度：原始时近性 $\lambda^{t - t_m}\in(0, 1]$，重要性除以 $10$，余弦相似度从 $[-1, 1]$ 映射到 $[0, 1]$，然后加权求和。这样每个得分只取决于记忆与查询，加入候选不可能打乱其余的排序。
:::
:::
