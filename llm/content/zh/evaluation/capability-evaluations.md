前面各章的基准问的是：模型在一组固定任务、固定协议下做得多好。而对部署与安全决策而言，另一个问题同样要紧：**如果有人下功夫去促成，这个模型能做到什么？** 用普通提示做不成任务的模型，可能换一个更好的提示、配上工具、多试几次、或稍微微调一下就成功了；而一个本可以做到的模型，按理也可能在被测试时表现出低于其能力的水平。**能力评测**旨在估计模型在强**激发**（elicitation）下能做什么；**危险能力评测**则把这一思路用于可能造成严重伤害的能力，例如协助网络攻击或武器相关工作、或以规避人类控制的方式自主行动。

本章把这些评测当作一门测量学科来对待。它界定能力与典型表现的对立、**倾向**（propensity）与能力的对立；推导为什么激发出的能力是一个下界、重复尝试如何改变"失败"的含义；说明**藏拙**（sandbagging）之忧；并详解 METR 发表的智能体能力**任务时间跨度**度量（Kwa 等，2025），附一份纯 Python 的拟合。然后仅在公开文献的层面上，描述前沿开发者的安全框架与政府机构如何使用这类评测，以及作为一套流程的**红队测试**是什么。与图谱其余部分一致，本章不含任何危险内容：没有危险领域的示例题目，也不涉及模型可能如何提供提升的细节；方法一律用中性任务来说明。

## 能力、激发与倾向 {#sec-capability}

::: definition 能力、激发与倾向 {#def-capability}
对一个任务族 $\mathcal{T}$ 与模型 $M$，记 $s(M, e)$ 为在某种**激发**方法 $e$ 下于 $\mathcal{T}$ 上的成功率——$e$ 可以是一个提示、一个带工具的脚手架、一个尝试次数、一套微调流程——取自评测者可用的方法集合 $\mathcal{E}$。模型关于 $\mathcal{T}$ 相对于 $\mathcal{E}$ 的**能力**为

$$
\operatorname{cap}_{\mathcal{E}}(M) = \sup_{e\in\mathcal{E}}s(M, e).
$$

其**典型表现**是按默认使用方式 $e_0$ 时的 $s(M, e_0)$。**激发差距**为 $\operatorname{cap}_{\mathcal{E}}(M) - s(M, e_0)$。模型对某一行为的**倾向**，是不被专门激发时它表现出该行为的频率——在普通使用中，或在行为有可能发生但并未受要求的情形里。
:::

Shevlane 等（2023）针对风险把两个问题分开：**危险能力评测**问模型在被指挥或被滥用时*能否*造成伤害，**对齐评测**问它有没有*自发*这样做的倾向。有危险能力而无倾向的模型是滥用风险；两者兼有的模型更严重。两者需要不同的方法：能力靠拼命设法让模型成功来激发，倾向靠观察模型在无人推动时做什么来测量。

::: proposition 激发出的能力是下界 {#prop-lower-bound}
对任意激发方法集合 $\mathcal{E}\subseteq\mathcal{E}'$，$\operatorname{cap}_{\mathcal{E}}(M)\le\operatorname{cap}_{\mathcal{E}'}(M)$。特别地，任何测得的成功率 $s(M, e)$ 都是相对于每个包含 $e$ 的方法集合的能力的下界。若某方法对一个任务做 $k$ 次独立尝试、每次成功概率为 $p$、且配有可靠的成败检验，则其成功率为

$$
s_k = 1 - (1 - p)^k,
$$ {#eq-attempts}

只要 $p > 0$，它就随 $k\to\infty$ 增至 $1$。
:::

::: proof
更大集合上的上确界只大不小，且对 $e\in\mathcal{E}$ 有 $s(M, e)\le\sup_{e'\in\mathcal{E}}s(M, e')$。尝试相互独立时，$k$ 次全失败的概率为 $(1 - p)^k$，而检验能认出任何一次成功；对 $0 < p\le1$，$(1 - p)^k\to0$。
:::

这条命题简单，却塑造了整个领域。能力评测只能表明模型*能*做到某事；它永远无法证明模型*不能*，因为更好的激发方法可能存在。因此评测者在激发上投入重金——专家级提示、配备合适工具的智能体脚手架、大量尝试、在相关任务上微调——并报告他们试过什么。相关的集合 $\mathcal{E}$ 由威胁模型决定：一个现实的行动者会拥有哪些激发手段？只有聊天界面的人，方法比拿到权重、能够微调的人少。

[[#eq-attempts]] 也改变了"失败"的含义。一个在 $2\%$ 的尝试中能解出任务的模型，单次尝试看来是不行，但若成功可被识别，$50$ 次尝试的成功概率是 $1 - 0.98^{50} = 64\%$。这就是[[evaluation/benchmarks#sec-passk]]的 pass@$k$ 思想用到风险上；也正是测试时计算——更多样本、更长推理——属于激发一部分的原因（[[reasoning/test-time-scaling]]）。

::: example 测量激发差距 {#ex-gap}
在一套中性软件任务上，某模型用普通提示解出 $12\%$；在带代码解释器的智能体脚手架内，每次尝试解出 $31\%$，且脚手架能运行任务的测试来检验自己的解答。每个任务允许 $5$ 次尝试时，脚手架能达到多高的成功率？相对普通提示的激发差距是多大？哪个假设会让 $5$ 次尝试的数字偏高？
::: solution
由[[#eq-attempts]]，$1 - 0.69^5 = 0.844$，于是激发差距为 $0.844 - 0.12 = 0.72$：测得的能力大部分来自激发。该公式假设尝试相互独立、且每题的成功概率相同。实际上有些任务可解、有些不可解，失败在题内相关；真实的 $5$ 次尝试成功率介于 $0.31$（完全相关）与 $0.844$（独立）之间，必须测量而不能代公式。无论哪种情形，只报告 $12\%$ 这个数字都会严重低估模型能做到的事。
:::
:::

### 当模型从不成功 {#sec-zero}

危险能力评测常常报告模型在 $n$ 次尝试中没有一次成功。这排除了什么？

::: proposition 三分律 {#prop-rule-of-three}
若在成功概率为 $p$ 的 $n$ 次独立尝试中全部失败，则 $p$ 的精确单侧 $95\%$ 置信上界为

$$
p_{\text{up}} = 1 - 0.05^{1/n}\ \approx\ \frac{3}{n}.
$$

此时一个对同一任务做 $k$ 次尝试的行动者，至少成功一次的概率最高可达 $1 - (1 - p_{\text{up}})^k$；一旦 $k\ge n\ln2/\ln20\approx0.23n$，它就超过 $\frac12$。
:::

::: proof
该上界就是数据在 $5\%$ 水平下还不能拒绝的最大 $p$：$\Prob(\text{全部 } n\text{ 次失败}) = (1 - p)^n\ge0.05$，所以 $p\le1 - 0.05^{1/n}$。小 $p$ 时 $-\ln(1 - p)\approx p$，故 $(1 - p)^n = 0.05$ 给出 $np\approx-\ln0.05 = \ln20 = 2.996\approx3$。第二条：当 $k\ge n\ln2/\ln20 = 0.231n$ 时 $(1 - p_{\text{up}})^k = 0.05^{k/n}\le\frac12$。
:::

所以，"$50$ 次尝试 $0$ 成功"在 $95\%$ 置信水平下与每次最高 $5.8\%$ 的成功率相容——而一个尝试十二次的行动者在那种情形下能有一半概率成功。观察到零次成功，支持的论断是某项能力*"在所试激发下很低"*，而不是它不存在。因此，用评测来排除能力的框架会组合使用大量尝试、手头最强的激发手段、以及在阈值之下留出安全余量。

::: widget plot

x: 1, 200
y: 0, 1
sliders: n=50:10:500:10

:::

::: example 规划尝试次数 {#ex-attempts}
一位评测者想在观察到零成功后，能以 $95\%$ 的置信说某任务的单次成功率低于 $1\%$。需要多少次尝试？若模型实际的成功率为 $0.5\%$，这些尝试仍然全部失败的概率是多大？
::: solution
需要 $1 - 0.05^{1/n}\le0.01$，即 $n\ge\ln0.05/\ln0.99 = 298.1$，于是 $299$ 次（三分律给 $300$）。若 $p = 0.005$，$299$ 次全失败的概率为 $0.995^{299} = 0.223$：约四五次里就有一次，一个能力真实存在却很少露面的模型会干净地通过评测。这不是方法的错误——这样的模型*确实*低于 $1\%$ 阈值——但它说明"零"的分量多么依赖尝试次数。
:::
:::

## 藏拙与评测感知 {#sec-sandbagging}

下界的逻辑假设模型在尽力。对高能力模型的评测还面临一种可能：它并没有尽力。

::: definition 藏拙 {#def-sandbagging}
**藏拙**（sandbagging）指在评测中的策略性表现不佳：模型或开发者使被测出的能力低于模型的实际能力，例如为了不触发安全措施。**评测感知**（evaluation awareness）指模型辨认出自己正在被评测、而非在被部署的能力。
:::

两者都已在受控环境中得到演示。Van der Weij 等（2024）表明，可以对语言模型做提示或微调，使它在危险能力基准上选择性地表现不佳、同时在一般基准上保持水准，还表明模型可以被**密码锁定**（password-locked）——训练成只在某个特定字符串出现时才展示某项能力。Greenblatt 等（2024）把密码锁定的模型当作激发技术的试验台，发现用少量高质量示例做微调通常能恢复被隐藏的能力，而提示常常不能；当被锁定模型的输出足够好、可供学习时，强化学习也能恢复它。2025 年的工作报告，前沿模型往往能区分评测记录与真实部署记录，准确率远高于随机水平（例如 Needham 等，2025），这对倾向评测尤其要紧：在一个模型认出是测试的测试中所观察到的行为，未必是它部署时的行为。

这些都不能说明部署中的模型实际上在藏拙；它们说明的是评测方法必须对这种可能性保持稳健。文献与开发者框架中提到的缓解措施包括：**基于微调的激发**，它比提示更难抵挡；把结果与按缩放趋势、以及相关的、敏感度较低的任务作出的**预测**放在一起对照，使异常低的分数凸显出来；检查任务在改述与伪装版本之间的**一致性**；在有推理轨迹可查时加以检查（[[reasoning/faithfulness-limits]]）；以及让评测环境贴近真实。

## 智能体能力与任务时间跨度 {#sec-horizon}

许多令人担忧——也极有价值——的能力都涉及长行动序列：完成一个软件项目、运行一个实验、操作一台计算机。**智能体评测**在允许模型运行代码、浏览网页或使用工具的脚手架内（[[agents/agent-loops]]），给模型一个沙盒环境中的任务，并按它是否达成目标打分。SWE-bench 这类基准（[[evaluation/benchmarks#sec-code-benchmarks]]）对固定任务集计分；另一种做法则试图把所有任务放到同一把尺上。

::: definition 任务时间跨度 {#def-horizon}
对一套任务，给每题一个**人类完成时间** $t_i$（熟练人类所花的时间，通过实测得到），在 $x_i = \log_2t_i$ 上拟合智能体成功率的 logistic 模型：

$$
\Prob(\text{在任务 } i\text{ 上成功}) = \sigma(a + b\,x_i),\qquad b < 0.
$$

智能体的**$q$ 时间跨度**是拟合成功率等于 $q$ 处的人类任务时长 $h_q$；**$50\%$ 时间跨度**是最常被报告的。
:::

METR 的 Kwa 等（2025）构建了一套约 $170$ 项软件工程、机器学习与推理任务，人类完成时间从约一秒到许多小时不等，他们实测了人类专家用时，并评测了 2019 至 2025 年初发布的多个前沿模型。他们报告，在此期间最强模型的 $50\%$ 时间跨度大致呈指数增长，**约每七个月翻倍**，有迹象表明 2024–2025 年增长更快；而 $80\%$ 可靠性处的跨度比 $50\%$ 处短好几倍。作者明确列出了局限：任务几乎全是软件与研究任务、自足、成功标准明确，不如真实工作那样"乱"；人类时间取决于给谁计时；趋势外推有不确定性。这一度量的吸引力在于，它不像基准分数那样有上限：总能加入更难的任务。

::: proposition 由 logistic 拟合得到跨度 {#prop-horizon}
在[[#def-horizon]]下，

$$
h_q = 2^{(\operatorname{logit}q - a)/b},\qquad\text{于是}\quad h_{50} = 2^{-a/b},\qquad \frac{h_{50}}{h_q} = 2^{-\operatorname{logit}q/b}.
$$

若 $h_{50}$ 随日历时间指数增长、倍增时间为 $d$，则它增长 $F$ 倍所需的时间为 $d\log_2F$。
:::

::: proof
$\sigma(a + bx) = q$ 当且仅当 $a + bx = \operatorname{logit}q$，于是 $x = (\operatorname{logit}q - a)/b$ 且 $h_q = 2^x$。取 $q = \frac12$ 时 $\operatorname{logit}\frac12 = 0$。比值为 $2^{(0 - a)/b - (\operatorname{logit}q - a)/b} = 2^{-\operatorname{logit}q/b}$。若 $h_{50}(T) = h_{50}(T_0)\,2^{(T - T_0)/d}$，则当 $(T - T_0)/d = \log_2F$ 时它增长 $F$ 倍。
:::

比值 $h_{50}/h_{80} = 2^{-\operatorname{logit}0.8/b} = 2^{1.386/\lvert b\rvert}$ 只依赖斜率：一个成功率随任务长度下降得慢的智能体（$\lvert b\rvert$ 小），其 $80\%$ 跨度远短于 $50\%$ 跨度——它有时能做长任务，但不可靠。

清单对一个真实 $50\%$ 跨度为 $60$ 分钟的 **合成** $150$ 任务集，用牛顿法做 logistic 回归拟合该模型，并用重抽样任务得到 bootstrap 区间。

```python
import math, random

rng = random.Random(7)
sig = lambda z: 1 / (1 + math.exp(-z))

# 合成任务集：人类完成时间在 1 分钟到 16 小时上对数均匀；
# 智能体的真实成功概率是 sigma(beta * (log2 h50 - log2 t))，h50 = 60 分钟
H50, BETA = 60.0, 0.7
tasks = []
for _ in range(150):
    t = 2 ** rng.uniform(0, math.log2(960))                       # 分钟
    tasks.append((math.log2(t), rng.random() < sig(BETA * (math.log2(H50) - math.log2(t)))))

def fit(data, iters=25):
    """Logistic regression success ~ sigma(a + b * log2 t) by Newton's method."""
    a = b = 0.0
    for _ in range(iters):
        ga = gb = haa = hab = hbb = 0.0
        for x, y in data:
            p = sig(a + b * x)
            ga += y - p; gb += (y - p) * x                          # 梯度
            w = p * (1 - p)
            haa += w; hab += w * x; hbb += w * x * x                # 负 Hessian
        det = haa * hbb - hab * hab
        a += (hbb * ga - hab * gb) / det
        b += (haa * gb - hab * ga) / det
    return a, b

def horizon(a, b, q):
    """Human task time (minutes) at which the fitted success probability equals q."""
    return 2 ** ((math.log(q / (1 - q)) - a) / b)

a, b = fit(tasks)
print(f"fitted a = {a:.3f}, slope b = {b:.3f} per doubling of task length")
print(f"50% time horizon: {horizon(a, b, 0.5):.1f} min, 80% time horizon: {horizon(a, b, 0.8):.1f} min")
boot = sorted(horizon(*fit([tasks[rng.randrange(len(tasks))] for _ in tasks]), 0.5)
              for _ in range(500))
print(f"95% bootstrap interval for the 50% horizon: [{boot[12]:.1f}, {boot[487]:.1f}] min")
for lo, hi in [(1, 4), (4, 15), (15, 60), (60, 240), (240, 960)]:
    sub = [y for x, y in tasks if math.log2(lo) <= x < math.log2(hi)]
    print(f"tasks of {lo:3d}-{hi:3d} min: {len(sub):3d} tasks, success rate {sum(sub) / len(sub):.2f}")
```

```text
fitted a = 4.865, slope b = -0.872 per doubling of task length
50% time horizon: 47.8 min, 80% time horizon: 15.9 min
95% bootstrap interval for the 50% horizon: [33.2, 69.1] min
tasks of   1-  4 min:  39 tasks, success rate 1.00
tasks of   4- 15 min:  30 tasks, success rate 0.93
tasks of  15- 60 min:  31 tasks, success rate 0.52
tasks of  60-240 min:  20 tasks, success rate 0.25
tasks of 240-960 min:  30 tasks, success rate 0.10
```

点估计 $48$ 分钟与真实值 $60$ 之间的偏差来自抽样噪声，而 bootstrap 区间——从 $33$ 到 $69$ 分钟、相差一倍——包含了真值。有了 $150$ 个任务，跨度也只知道个大约 $1.5$ 倍范围内的数；若长任务更少，区间还会更宽，而长任务恰恰是最贵、计时也最费的部分。同样的不确定性会传播到趋势估计中：对少数几个各带这样区间的模型拟合倍增时间，其本身就很不确定，原研究的作者们对此也作了强调。

caption: [[#def-horizon]]的 logistic 任务时间跨度模型，$50\%$ 跨度为 $h$ 分钟、斜率为每任务时长翻倍 $c$。$50\%$ 与 $80\%$ 跨度是曲线与两条水平线相交处；斜率越平缓，两者分得越开，正如[[#prop-horizon]]所预言。

::: example 外推跨度 {#ex-extrapolate}
某智能体的 $50\%$ 跨度为 $1$ 小时，最强智能体的趋势倍增时间为 $7$ 个月。若趋势延续，跨度达到 $8$ 小时还要多久？倍增时间有 $\pm1$ 个月的不确定，对答案有何影响？
::: solution
由[[#prop-horizon]]，$7\log_28 = 21$ 个月。倍增时间为 $6$ 或 $8$ 个月时，$18$ 或 $24$ 个月。速率上的小不确定性会变成日期上的大不确定性；而且外推还假设趋势延续、假设任务集对相关工作具有代表性——两者都是未决问题。这类预测是情景，不是预言。
:::
:::

## 危险能力评测的实际运作 {#sec-frameworks}

自 2023 年起，多家前沿模型开发者公布了**安全框架**，把训练与部署决策同能力评测的结果绑定起来。例子包括 Anthropic 的**《负责任扩展政策》**（Responsible Scaling Policy，2023 年首次发表）、OpenAI 的**《防范框架》**（Preparedness Framework，2023 年，2025 年修订）与 Google DeepMind 的**《前沿安全框架》**（Frontier Safety Framework，2024 年，其后又有修订），其他开发者的框架随后跟进；2024 年 5 月的 AI 首尔峰会上，十六家公司承诺公布此类框架。它们的细节彼此不同、且经常修订；下面描述的是其发表文本中的共同结构，而非其当前内容。

::: definition 能力阈值与保障措施 {#def-thresholds}
**能力阈值**（也称能力等级、临界能力等级之类）是对某一风险领域中某个能力水平的书面刻画，开发者承诺达到该水平时采取额外**保障措施**——保护权重的安全措施、限制滥用的部署措施，或不部署的决定。**预警评测**或**初步评测**旨在提前发现模型可能正在逼近某个阈值，并留有裕度，以便在越过之前准备好更充分的评测与保障措施。
:::

各已发表框架点名的风险领域大体相似：化学与生物武器（有些框架还包括放射性与核）、网络进攻、自主性与自我复制，以及加速 AI 研发本身的能力；一些还包括说服与操纵。每个领域都用一组混合方法评测，框架与开发者的**系统卡**只作概略描述：

- 相关知识与技能的**自动基准**，通常由领域专家构建，题目保密；
- 沙盒环境中的**智能体任务**，例如评测网络能力的夺旗（capture-the-flag）演练，或按[[#sec-horizon]]方式计分的研究型 AI 任务；
- **专家红队测试**：领域专家在开发者处理敏感信息的保障措施之下，在一定时期内交互式地探查模型；
- **提升研究**（uplift studies）：随机实验，比较拿到模型与拿不到模型的参与者完成代理任务的最好水平，对照组则享有网络搜索等其他资源——它最直接地度量模型添加的边际风险，代价也最高。

::: example 提升研究的统计 {#ex-uplift}
一项提升研究用中性的代理任务（照文档完成一道技术流程），把 $50$ 名参与者分入有网络接入的对照条件，另 $50$ 名分入额外有一个模型的条件。对照条件有 $20$ 人完成任务，模型条件有 $28$ 人。这一差别显著吗？要在 $5\%$ 水平上以 $80\%$ 的功效检出这么大一个真实差别，每组需要多少参与者？
::: solution
完成率为 $0.40$ 与 $0.56$，差 $0.16$，标准误差 $\sqrt{0.4\cdot0.6/50 + 0.56\cdot0.44/50} = 0.099$，故 $z = 1.62$、$p\approx0.10$：不显著。要达到 $80\%$ 功效，标准正态近似需要每组 $n = (1.96 + 0.84)^2(0.24 + 0.2464)/0.16^2\approx149$ 人（[[evaluation/evaluation-statistics]]）。提升研究花费高昂，因为每位参与者要花上几小时，所以许多研究功效不足；一项小研究的不显著结果只是"无提升"的弱证据，应当连同其置信区间（此处为 $0.16\pm0.19$）报告，而不是当成零效应的发现。
:::
:::

系统卡以摘要形式报告结果——跑了哪些评测、用了什么激发、是否被认定达到阈值——而题目本身不予公布，因为公布既是污染风险、在某些领域本身也是危险。Phuong 等（2024）按这一描述层级发表了一个完整评测计划的例子，覆盖说服与欺骗、网络安全、自我扩散与自我推理，但不含危险细节。

### 政府机构与第三方 {#sec-institutes}

各国政府设立了机构以独立评测前沿模型。英国的 **AI 安全研究所**（AI Safety Institute，2023 年 11 月在布莱切利园峰会上宣布成立，2025 年更名为 **AI Security Institute**）与设在 NIST 的**美国 AI 安全研究所**（2023–2024 年成立，2025 年改组为 **AI 标准与创新中心**，Center for AI Standards and Innovation，CAISI），在与开发者的自愿协议下对若干前沿模型做了部署前测试，发表了联合评测报告，并发展了方法；英国研究所于 2024 年发布了运行评测的开源框架 **Inspect**。其他国家也建立了类似机构，而首份《国际人工智能安全报告》（Bengio 等，2025）面向政策制定者综述了能力与风险的证据。METR 与 Apollo Research 之类的独立组织替开发者在模型发布前做评测，并发表方法与发现，例如关于自主完成任务、以及模型在被设计的测试情境中追求隐藏目标的能力（Meinke 等，2024）。这套安排仍在演化，其 specifics——哪些模型被测试、由谁测、开放什么访问——应查阅当前的原始来源。

::: warning 通过评测不是安全保障
人们容易把"模型未达到阈值"读成"模型是安全的"。它的实际含义是：在所试的激发下、在所用的任务上，证据没有显示该能力。由[[#prop-lower-bound]]，更好的方法可能显示出更多；由[[#prop-rule-of-three]]，零成功仍容许不可忽略的成功率；任务是现实伤害的代理，部分因为代理能被安全地测试；而且能力可以在发布后通过微调、新工具或更好的脚手架增长。框架以安全裕度、重新评测与外部测试应对这些问题，其作者也把它们描述为演化中的文本。阅读评测论断时，要看它们的激发、样本量与代理。
:::

## 作为流程的红队测试 {#sec-red-teaming}

**红队测试**——赶在别人前面找出失败案例的对抗性测试——是一套流程而非一次评测，其价值取决于流程怎么运行。针对已部署系统的红队技术在[[safety-alignment/red-teaming]]中作概念性讨论；这里关心的是它作为评测的角色。

::: algorithm 一次红队测试行动 {#alg-red-team}
1. **范围与威胁模型**：哪些伤害、哪几类用户或对手、什么访问级别（聊天界面、API、工具、权重）、什么算作一次发现、以及发现的严重程度量表。
2. **招募**具备相关专长、背景多样的红队队员，并就是否保密与如何处理任何敏感输出达成协议。
3. **探查**：人工探索、结构化测试计划、以及测试输入的自动生成，包括用其他模型生成（Perez 等，2022）。
4. **记录**每次尝试与结果，连同严重程度与可复现性，使发现数得出来、而不只是轶事式地报告。
5. **分诊与缓解**：把发现送进训练数据、分类器、政策或部署限制。
6. **回归**：把发现变成在后续版本上重跑的测试用例，把一次性演练变成可重复的评测。
:::

Ganguli 等（2022）详细描述了一次大规模红队测试工作，发布了约 $39{,}000$ 条带有危害程度评分的红队尝试数据集，并发现用 RLHF 训练的模型规模越大越难被红队攻破，其他类型的模型则不然。红队结果很难化为比率：红队队员自适应地搜索，所以成功尝试的比例取决于他们的技巧与坚持，不只是模型。这些结果最好被读作存在性证明与测试用例的来源，量化论断则留给第 6 步的系统性重测。

::: quiz
一份评测报告写道："我们用一个标准智能体脚手架，在某风险领域的 $100$ 道专家编写任务上每题尝试 $5$ 次；模型解出 $0$ 道。我们结论它是缺乏这一能力。"哪些反对意见成立？
- [x] 其他激发（微调、更好的工具、更多尝试）可能成功
- [x] $500$ 次尝试全部失败时，约 $0.6\%$ 的单次成功率仍与数据相容
- [x] 在代理任务上成功，可能与现实风险两个方向都脱节
- [ ] 零成功证明模型在藏拙
::: solution
由[[#prop-lower-bound]]，这一结果是相对于所试方法的下界。由[[#prop-rule-of-three]]，$500$ 次中 $0$ 次给出的单次上界约为 $3/500 = 0.6\%$（若尝试相互独立；同一任务上相关的尝试会令有效样本更小、上界更大）。代理可能比真实情形更容易，也可能更难。零分本身并不表明故意表现不佳；只有当分数远低于相关任务的预测、或微调恢复出多得多的时候，才需要怀疑藏拙。
:::
:::

::: history
在部署前评测 AI 系统的危险能力，约在 2021–2022 年由对齐社区提出，并首次大规模实践于 2022 年 GPT-4 的发布前评测：其中后来成为 METR 的团体测试了自主复制，系统卡报告了外部专家的红队测试（OpenAI，2023）。Shevlane 等的《Model evaluation for extreme risks》（2023）系统陈述了危险能力评测与对齐评测作为部署决策输入的理由。开发者的安全框架自 2023 年 9 月起相继出现，英国与美国的政府机构自 2023 年 11 月起相继成立。对评测本身的研究记录了藏拙现象（van der Weij 等，2024）、用密码锁定的模型研究激发（Greenblatt 等，2024）、发表了完整的评测计划（Phuong 等，2024）、并提出任务时间跨度度量（Kwa 等，2025）。红队测试借鉴自军事与计算机安全实践，由 Ganguli 等（2022）引入语言模型工作，自动红队测试则始于 Perez 等（2022）。
:::

::: summary
- **能力**是允许的**激发**方法集合上的最佳成功率；**典型表现**用默认方法；**倾向**是模型无人激发的自发所为（[[#def-capability]]）。
- 激发出的能力是**下界**（[[#prop-lower-bound]]）；评测者必须竭尽全力（提示、脚手架、工具、大量尝试、微调）并报告所试。单次成功率为 $p$ 时，$k$ 次尝试至少成功一次的概率为 $1 - (1 - p)^k$。
- **$n$ 次零成功**把成功率约束到约 $3/n$（[[#prop-rule-of-three]]），但这仍容许一个尝试次数很多的行动者成功。
- **藏拙**与**评测感知**都已在受控环境中得到演示；基于微调的激发、趋势预测与一致性检查可作缓解。
- **任务时间跨度**度量把成功率对 $\log_2$ 人类时间拟合，报告 $h_{50} = 2^{-a/b}$（[[#prop-horizon]]）；METR 报告 2019 至 2025 年初 $h_{50}$ 约每七个月翻倍，不确定范围很宽，且作者列明了局限。
- 开发者的**安全框架**把能力**阈值**与保障措施绑定（[[#def-thresholds]]），使用基准、智能体任务、专家红队测试与提升研究；政府机构（英国 AISI、美国 CAISI）与第三方独立测试。危险领域的题目不予公布。
- **红队测试**是有范围、有记录、可迭代的过程，其发现变成回归测试（[[#alg-red-team]]）。
:::

## 习题

::: exercise 三分律 {level=1 check="0.0487"}
一个模型在某任务的 $60$ 次独立尝试中全部失败。给出其单次尝试成功率的精确 $95\%$ 置信上界（保留四位小数），以及三分律近似。
::: solution
$1 - 0.05^{1/60} = 1 - e^{\ln0.05/60} = 1 - e^{-0.04993} = 0.0487$。近似值为 $3/60 = 0.05$。
:::
:::

::: exercise 多次尝试 {level=1 check="0.636"}
一个模型在某任务的独立尝试中有 $2\%$ 成功，且成功能够被识别。$50$ 次尝试中至少成功一次的概率是多少（保留三位小数）？
::: solution
由[[#eq-attempts]]，$1 - 0.98^{50} = 1 - 0.3642 = 0.636$。
:::
:::

::: exercise 由拟合系数求跨度 {level=1 check="32"}
一次任务时间跨度拟合得到 $a = 3$、$b = -0.6$，任务时间以分钟计。$50\%$ 时间跨度是多少分钟？
::: solution
$h_{50} = 2^{-a/b} = 2^{3/0.6} = 2^5 = 32$ 分钟。
:::
:::

::: exercise $80\%$ 跨度 {level=2 check="6.45"}
对上一题的拟合，计算 $80\%$ 时间跨度（分钟，保留两位小数），以及比值 $h_{50}/h_{80}$。
::: solution
$\operatorname{logit}0.8 = \ln4 = 1.386$。$h_{80} = 2^{(1.386 - 3)/(-0.6)} = 2^{2.690} = 6.45$ 分钟。比值为 $32/6.45 = 4.96 = 2^{1.386/0.6}$，与[[#prop-horizon]]的预测一致。
:::
:::

::: exercise 外推趋势 {level=2 check="21"}
一个 $50\%$ 跨度以 $7$ 个月倍增时间增长的模型，要从 $15$ 分钟长到 $2$ 小时需要多少个月？
::: solution
倍数为 $8$，故 $7\log_28 = 21$ 个月。
:::
:::

::: exercise 最好的激发会有偏吗 {level=2}
一位评测者尝试 $10$ 种激发方法，并把最好的成功率报告为模型的能力。在[[evaluation/evaluation-principles#prop-winners-curse]]中，从多个带噪声的分数里选最好一个是偏差的一个来源。在这里这是问题吗？请区分该评测用于*确认*某项能力（"模型做得到"）与用于*排除*某项能力（"模型低于阈值"）两种情形。
::: solution
$10$ 个带噪声估计中的最好者会高估所选方法的成功率；若各方法本来同等好坏，约高 $1.54$ 个标准误。对**排除**一项能力而言，这一偏差是偏保守的：报告的能力至多是偏高，因此低于阈值的结果对它稳健。对**确认**而言——声称模型达到某个水平——它是偏乐观的，所选方法应当在新尝试或新任务上重跑一遍，以获得无偏估计，与前面那章的做法完全一样。由于能力定义为对方法取上确界，选最好者是正确的*估计目标*；需要修正的只是它的估计。
:::
:::

::: exercise 设计藏拙检测 {level=2}
你在一个敏感领域的一组私有任务上评测模型，同时在普通领域的一组对照任务上也评测——后者要求相似的技能（例如同类的软件推理）。描述两种能暴露选择性表现不佳的比较，并说明什么样的结果值得怀疑。
::: solution
(1) **跨领域一致性**：在一串一般能力递增的模型上，普通领域与敏感领域两组分数应当一起上升；若某个模型的敏感领域分数明显低于由其普通领域分数（及其前代模型）预测的趋势线，就值得怀疑。(2) **激发反应**：用敏感领域（或其某个留出部分）中少数已解出的任务对模型做少量微调；若极少训练后分数大幅跃升——远超同一流程在普通领域组上产生的跃升——则说明能力本已存在却未被表现，正如 Greenblatt 等（2024）那批被密码锁住的模型。把任务改述得不那么像评测、再比较表现，是第三种针对评测感知的检查。
:::
:::

::: exercise 不独立的尝试 {level=3}
[[#prop-rule-of-three]]假设尝试相互独立。现有一次评测在 $100$ 个任务上各跑 $5$ 次尝试，模型 $500$ 次全部失败，而同一任务上的成功在各次尝试间高度相关（对每个任务，模型要么几乎总能成功，要么几乎从不能）。(a) 若要给模型可解任务的比例设界，$100$ 与 $500$ 哪个是更好的有效样本量？(b) 给出相应的 $95\%$ 上界。(c) 对于一个将对某一个特定任务反复尝试的行动者，哪个上界才相关？
::: solution
(a) 若同一任务上的尝试几乎完全相关，五次尝试携带的信息不比一次多多少，有效样本约为 $100$ 个任务。(b) 可解任务比例的上界为 $1 - 0.05^{1/100} = 0.0295$，约 $3\%$，而非 $0.6\%$。(c) 对专注于某一个任务的行动者，要紧的是*那个任务*的单次尝试成功率，而数据对评测集之外的任务几乎一无所知；在评测集内部，每任务五次尝试只能很弱地约束每个任务的单次成功率（每任务 $1 - 0.05^{1/5} = 45\%$）。这就是[[evaluation/evaluation-statistics]]的聚类问题：独立证据的单位是任务，不是尝试。
:::
:::

::: exercise 手拟合一个跨度 {level=3}
证明：若一个评测套件中所有任务的人类时间相同，则[[#def-horizon]]中的斜率 $b$ 不可识别，并解释为什么用于跨度测量的任务套件必须覆盖很宽的时间范围。然后，利用[[#sec-horizon]]的清单，只用短于 $60$ 分钟的任务重新拟合，报告 $50\%$ 跨度的估计值及其区间发生了什么变化。
::: solution
当 $x$ 只有一个取值时，模型对每个任务预测相同的概率 $\sigma(a + bx)$；任何使 $a + bx$ 相同的 $(a, b)$ 都同样好地拟合，故 $b$ 不可识别——除该时间点外的任何跨度也就都不可识别。$x$ 的大跨度分布正是让拟合能把水平与斜率分开的原因，而任务范围之外的跨度都是外推。限制清单中的评测套件后：

```python
short = [(x, y) for x, y in tasks if x < math.log2(60)]
a2, b2 = fit(short)
boot2 = sorted(horizon(*fit([short[rng.randrange(len(short))] for _ in short]), 0.5)
               for _ in range(500))
print(f"{len(short)} tasks: 50% horizon {horizon(a2, b2, 0.5):.1f} min, "
      f"95% interval [{boot2[12]:.1f}, {boot2[487]:.1f}]")
```

```text
100 tasks: 50% horizon 36.4 min, 95% interval [23.9, 71.2]
```

点估计从 $48$ 分钟降到 $36$ 分钟，区间扩大到 $[24, 71]$ 分钟，相差三倍：没有长于一小时的任务时，接近一小时的跨度正处在数据的边缘，只靠少数紧挨着它的任务定住；而斜率是从智能体几乎总能解出的短任务估出来的。长任务是这类套件中最昂贵的部分，也是最不可少的部分。
:::
:::
