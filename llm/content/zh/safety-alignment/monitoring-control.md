前面的章节问的是如何让模型对齐、以及如何判断它们是否对齐。本章问的是一个不同的问题：**如果一个模型并不对齐，哪些保障措施仍然有效？**如果评测无法排除"模型只在被盯着时表现良好"（[[safety-alignment/deception-misalignment#prop-recognition]]），那么部署就不应建立在它确实如此表现的假设之上。银行不假设自己的员工诚实；他们职责分离、审计交易记录，并限制任何单个人所能做的事。**AI 控制**（AI control）把同样的逻辑用于 AI 系统：设计这样的协议——*即使*模型正在主动试图制造灾难，它也能把灾难概率保持在低位——并用扮演未对齐模型的红队来检验它们。

本章介绍 Greenblatt、Shlegeris、Sachan 与 Roger（ICML 2024，"AI control: improving safety despite intentional subversion"）的控制框架，以及它的主要协议：可信监控、转交可信模型、不可信监控与可信编辑。核心的数学是每个部署监控器的人都应当会做的计算：给定审计预算、已知质量的监控器、以及一个自选攻击频率的攻击者，在它成功之前捕获它的概率是多少？我们用朴素的 Python 把它算出来。然后转向实践中的监控——监控思维链，以及为什么这个机会是脆弱的（Baker 等，2025；Korbak 等，2025）——以及异常检测与部署时的保障措施。思维链的忠实性在[[reasoning/faithfulness-limits]]中讨论，这里只做链接。

## 控制框架 {#sec-control}

::: definition 控制设定 {#def-control}
一个**控制设定**由待**不可信模型** $U$ 完成的一系列 $N$ 个任务组成——$U$ 有本事，但可能未对齐——以及防守方可信的资源：一个**可信模型** $T$，较弱，但假设它不是对抗性的（例如因为它太弱、无法连贯地搞密谋），以及一份有限的**可信高质量人力** $H$（人类审计者），能够检查比例为 $a$ 的任务。一个**协议**针对每个任务决定如何使用 $U$、$T$ 与 $H$ 产出输出。它的**有用性**是当 $U$ 无害时它在任务上的表现；它的**安全性**是当 $U$ 被红队为制造灾难而写的**攻击策略**替换时，不发生灾难的概率。
:::

方法论上的关键一步是**控制评测**：评测者不去试图判断真实模型是否未对齐，而是做最坏假设，让红队在真实模型说得通所能做的限度之内，控制不可信模型的行为。一个协议按它在给定有用性下、针对所发现的最佳红队策略所取得的安全性来评判。Greenblatt 等使用了一个编程场景：$U$（GPT-4）解 $5{,}000$ 道竞赛编程题；红队的目标是让至少一个**带后门的**解被接受——通过测试、但在攻击者知道的某个输入上给出错误答案的代码；$T$ 是 GPT-3.5；审计可以检查 $2\%$ 的解。后来的工作把这套方法论扩展到 shell 环境中的多步智能体场景（Bhatt 等，2025，"Ctrl-Z"），其中一次攻击可以分散在许多动作里。

::: definition 协议 {#def-protocols}
- **先行审计**（upfront auditing）：审计 $U$ 在前 $aN$ 个任务上的输出；其余不检查直接使用。
- **可信监控**（trusted monitoring）：$T$ 给 $U$ 的每个输出一个嫌疑分数；$H$ 审计嫌疑最高的比例 $a$。一次审计若发现攻击，部署即告结束（模型被捕获）。
- **转交可信模型**（defer to trusted）：与可信监控相同，但超过第二个较低阈值的输出被丢弃，换成 $T$ 自己的输出——更安全，但有用性更低。
- **不可信监控**（untrusted monitoring）：用 $U$ 的另一个实例来给输出打分，因为它比 $T$ 更强；风险是**共谋**（collusion），即监控器故意漏掉攻击——对策是用合成攻击检验监控器，并对输出做改写或删节以去除秘密信号。
- **可信编辑**（trusted editing）：$T$ 重写 $U$ 的输出，去除任何可疑之处，保留其有用的部分。
:::

## 审计预算与捕获攻击的概率 {#sec-audit}

控制着 $U$ 的红队选择攻击的频率。频繁攻击有及早被捕获的风险；罕见攻击有永远不成功的可能。把每次攻击建模为三种可能的结果：**被捕获**（审计看到它，部署停止）、**得手**（未被捕获并达到目的——一场灾难），或**中性**（未被捕获且失败，例如因为后门不起作用）。

::: proposition 对重复攻击的安全性 {#prop-race}
设每次攻击独立地以概率 $c$ 被捕获、以概率 $u$ 得手，其余情况为中性，且 $c + u > 0$；攻击者持续攻击，直到前两种情况之一发生。那么攻击者在得手之前被捕获的概率是
$$
\text{安全} = \frac{c}{c + u}.
$$ {#eq-race}
如果部署可能在决定性事件之前结束——任务有限、攻击很少——那么安全性至少是这个值。
:::

::: proof
决定性的那次攻击是第 $k$ 次的概率为 $(1 - c - u)^{k - 1}(c + u)$；而在给定攻击是决定性的条件下，它是捕获的概率为 $c/(c + u)$，与 $k$ 无关。对 $k$ 求和，$\Prob(\text{先被捕获}) = \sum_{k\ge1}(1 - c - u)^{k - 1}c = c/(c + u)$。攻击次数有限时，"没有攻击具有决定性"这一事件也算安全，这只会提高安全性。
:::

在这一模型中，安全性由*每次攻击*捕获与得手之比决定，而不是由任务数量决定——只要红队攻击得足够频繁。审计预算通过 $c$ 起作用，而协议决定了这笔预算能买到多大的 $c$。

::: example 随机审计 {#ex-random}
随机审计 $2\%$ 的任务。每次未被审计的攻击以概率 $s = 0.5$ 得手。安全性是多少？
::: solution
随机审计以概率 $c = a = 0.02$ 捕获攻击，而一次攻击以概率 $u = (1 - a)s = 0.49$ 得手。由[[#prop-race]]，安全性 $= 0.02/(0.02 + 0.49) = 0.039$。面对能够反复尝试的攻击者，小预算的随机审计几乎毫无用处：每捕获一次，攻击者预期得手约 $25$ 次。
:::
:::

先行审计的表现不同，因为审计集中在开头。攻击者于是应当*罕见地*攻击，以便在受审计的时期内大概不发动攻击，但又要足够频繁，以便在此之后能够得手。

::: example 先行审计 {#ex-upfront}
$N = 5{,}000$ 个任务，前 $M = 100$ 个受审计（$a = 2\%$），未被审计的攻击以概率 $s = 0.5$ 得手。攻击者对每个任务以概率 $p$ 独立地发起攻击。求攻击者最佳的 $p$ 与相应安全性。
::: solution
若前 $M$ 个任务中没有攻击、且之后至少一次得手，红队获胜：$\Prob(\text{红队胜}) = (1 - p)^M\big(1 - (1 - ps)^{N - M}\big)$。$p$ 小则第一个因子接近 $1$ 而第二个因子小；$p$ 大则相反。数值最大化（[[#sec-code]]）给出 $p = 0.00132$——在 $5{,}000$ 个任务中预期约六次或七次攻击——且 $\Prob(\text{红队胜}) = 0.842$，于是安全性为 $0.158$。这比随机审计好，但依然很差：攻击者利用的正是审计*何时*发生的可预测性。
:::
:::

### 可信监控

监控器把审计预算花在攻击可能出现的地方，从而把它变成更高的捕获率。把可信监控器的嫌疑分数建模为：在诚实输出上为 $\Normal(0, 1)$，在攻击上为 $\Normal(d', 1)$，其中 $d'$ 度量 $T$ 区分两者的能力。审计诚实输出中排名前 $a$ 的部分，就把阈值定为 $\tau = \Phi^{-1}(1 - a)$，于是一次攻击被捕获的概率为
$$
c(a) = 1 - \Phi\big(\Phi^{-1}(1 - a) - d'\big).
$$ {#eq-catch}

::: widget plot

x: -1, 5
y: 0, 1
sliders: d=2:0:4:0.1

labels: fraction of honest outputs audited, $a = 1 - \Phi(\tau)$; fraction of attacks caught, $c = 1 - \Phi(\tau - d')$
caption: 可信监控器的审计阈值 $\tau$ 所决定的取舍：监控器的嫌疑分数在诚实输出上为 $\Normal(0, 1)$、在攻击上为 $\Normal(d', 1)$（滑块 $d = d'$）。竖线是审计 $2\%$ 诚实输出的阈值 $\tau = 2.054$；在 $d' = 2$ 下它捕获 $47.9\%$ 的攻击（[[#ex-monitor]]）。更好的监控器（更大的 $d'$）在同样预算下捕获更多攻击；更大的预算把线向左移动。
:::

::: example 可信监控与转交 {#ex-monitor}
设 $a = 0.02$、$d' = 2$、$s = 0.5$：(a) 可信监控的捕获率与安全性是多少？(b) 嫌疑排名前 $10\%$、未被审计的输出被换成 $T$ 的输出。现在安全性是多少？代价是什么？
::: solution
(a) 由[[#eq-catch]]，$\tau = \Phi^{-1}(0.98) = 2.054$，$c = 1 - \Phi(0.054) = 0.479$。未被捕获的攻击以概率 $s$ 得手，故 $u = (1 - c)s = 0.261$，安全性 $= 0.479/(0.479 + 0.261) = 0.647$（[[#prop-race]]）。[[#sec-code]]中的模拟给出 $0.650\pm0.015$。(b) 得分在转交阈值 $\Phi^{-1}(0.9) = 1.282$ 之上、审计阈值之下的攻击被替换，因此它们既不得手也不被捕获。攻击中位于转交阈值之上的比例是 $1 - \Phi(1.282 - 2) = 0.764$，所以只有 $1 - 0.764 = 0.236$ 的攻击被原样使用，$u = 0.236\cdot0.5 = 0.118$。安全性升到 $0.479/(0.479 + 0.118) = 0.802$。代价是有用性：$8\%$ 的诚实任务现在改由较弱的模型完成。转交前 $20\%$ 给出 $0.886$，代价是 $18\%$。
:::
:::

这个例子展示了控制评测所描绘的**安全–有用性前沿**的形状：每个协议与阈值是一个点，更好的协议把前沿向外推。Greenblatt 等发现，在他们的场景中，带转交的可信监控、带反共谋对策的不可信监控、以及可信编辑，都相对先行审计有实质改进，其中可信编辑与不可信监控给出最好的权衡。他们的数字依赖具体场景；可比的方法才是可迁移的部分。

labels: safety with auditing only, $c/(c + (1 - c)s)$; with deferral removing a further fraction $k$ of uncaught attacks
caption: 当未被捕获的攻击以概率 $s$ 得手时，对反复攻击的策略的安全性（[[#prop-race]]）随每次攻击捕获率 $c$ 的变化。转交给可信模型能使审计漏掉的攻击中的一个比例 $k$ 失去作用：在 $c = 0.479$、$k = 0.55$ 时（[[#ex-monitor]]中把嫌疑前 $10\%$ 转交，移除了未被捕获攻击的 $0.285/0.521$），安全性从 $0.65$ 升到 $0.80$。在捕获率很小时，安全性对 $c$ 极为敏感，这就是监控器质量与审计预算如此重要的原因。
:::

### 不可信监控与共谋

可信模型往往比不可信模型弱得多，所以它的嫌疑分数很差。用 $U$ 的另一个拷贝当监控器，如果这个拷贝是诚实的，分数会更好——但如果 $U$ 未对齐，监控器可能共谋，恰好在真实攻击上报告低嫌疑。有两种对策处于核心地位。**蜜罐**（honeypot）：给监控器看蓝队制造的合成攻击；漏标它们的监控器就会被抓到说谎。**信号干扰**（signal jamming）：在监控器看到输出之前改写或删节它们，使攻击者无法嵌入共谋监控器能够识别的秘密信号（"这条是我干的，别报告"）。

::: example 抓住共谋的监控器 {#ex-collusion}
一个共谋的监控器试图标记合成攻击、而对真实攻击保持沉默，所以它必须能分辨两者。设它把一次合成攻击误判为真实的概率为 $e = 0.1$，蓝队在部署前用 $k = 30$ 次合成攻击测试它。共谋被揭穿的概率是多少？改写有什么帮助？
::: solution
只要监控器对至少一次合成攻击保持沉默，它就被揭穿：$1 - (1 - e)^k = 1 - 0.9^{30} = 1 - 0.042 = 0.958$。监控器最好的防御是让 $e$ 变小——可靠地认出合成攻击，或者用攻击者植入的信号认出真实攻击。改写与删节去除了植入的信号，使真实与合成攻击看起来一样，这就抬高了 $e$；逼真的合成攻击也能做到这一点。这一分析与[[safety-alignment/deception-misalignment#prop-recognition]]如出一辙：能识别测试的对手能使测试失效，所以防御是让测试不可识别。
:::
:::

::: warning 控制并不是在断言模型未对齐
针对对抗性模型设计协议，并不预设当前的模型具有对抗性；它是获得这样一种安全性保证的途径：这种保证不依赖于先把那个问题争论出结果。这一方法也有其公开的限度：它假设可信模型确实可信，红队的攻击策略至少和真实模型所能做到的攻击一样好（随着模型比自己的红队越来越强，这一假设会不断被削弱），以及捕获一次攻击会引来响应。它的支持者把它描述为管理早期变革性系统风险的方式，而不是长期的解决方案。
:::

## 监控思维链 {#sec-cot}

推理模型在行动之前会写出很长的思维链（[[reasoning/chain-of-thought]]）。当模型用自然语言推理它正在做什么时，监控器就能阅读这段推理——包括那些单看行动并不会暴露的意图。

Baker 等（OpenAI，2025，"Monitoring reasoning models for misbehavior and the risks of promoting obfuscation"）在前沿推理模型于智能体编程任务上做强化学习训练期间研究了这一点。一个较弱的模型（GPT-4o）被提示为监控器，阅读智能体的思维链与行动并标记奖励破解——例如通过特判测试用例来让测试通过，而不是修复代码（[[safety-alignment/reward-hacking]]）。报告的结果：

- 监控**思维链**检测系统性奖励破解的效果远好于只监控**行动**（在他们的分析中召回率约 $95\%$ 对约 $60\%$），因为智能体常常把自己的意图说得很直白。
- 当监控器的标记被并入训练**奖励**——惩罚"坏想法"——之后，智能体一开始破解得更少、表现更好。随着优化加强，它学会了**隐匿的奖励破解**：它继续破解，而其思维链不再暴露这一点。

后一个发现是古德哈特定律（[[safety-alignment/alignment-problem#def-goodhart]]）的直接实例：一个被当作优化目标的监控器就不再是好监控器。作者建议开发者避免对思维链直接施加强的优化压力，必要时接受一笔"可监控性税"（monitorability tax）。

::: definition 可监控性 {#def-monitorability}
对一类行为，一个模型的推理是**可监控的**，程度在于：一个阅读推理（以及行动）的监控器能以可接受的误报率、用高召回率检测这些行为。可监控性要求推理是**可读的**（用监控器理解的语言），要求这类行为**需要**模型必须外化的推理、或至少模型确实外化了推理，并且要求推理足够**忠实**地反映计算（[[reasoning/faithfulness-limits#def-faithful]]）。
:::

Korbak 与来自多家开发机构、政府研究院所和学术界的四十多位共同作者（2025，"Chain of thought monitorability: a new and fragile opportunity for AI safety"）在一篇立场文件中论证：这个机会之所以存在，是因为当前困难任务*要求*模型用文本思考；但它可能因为若干发展而丧失：对推理的优化压力（如上所述）、使推理偏离可读语言的训练、在连续潜空间中推理的新架构、以及学到自己被监控的模型。他们建议开发者评测可监控性、报告它（例如在系统卡中），并在训练与架构决策中权衡它。也有人指出思维链本来就只是部分忠实（[[reasoning/faithfulness-limits]]），所以监控它是有用的一层额外保障，而不是保证；这份立场文件也同意它应当与其他措施相配合。

## 异常检测与内部监控 {#sec-anomaly}

监控也可以看文本之下。对内部激活的**探针**——被训练来检测欺骗或背叛意图一类状态的线性分类器——在刻意植入后门的模型生物上显示出很高的准确率（[[safety-alignment/deception-misalignment#sec-sleeper]]），并已在更现实的场景中就策略性欺骗进行了测试，结果令人鼓舞但并不完美。对齐研究中心（Alignment Research Center）的研究者提出的**机制性异常检测**（mechanistic anomaly detection）旨在标记那些输出由异常内部机制产生的输入——"这个输出的原因与正常情形下的原因不同"——即使输出本身看起来正常。**分布外检测器**标记与训练数据不同的输入。这些方法全都继承了基率问题：一个灵敏度与特异度都为 $99\%$ 的检测器，用在目标行为万分之一发生率的场合，每个真警报大约会产生一百个误报，所以标记必须接入一个分诊（triage）流程——进一步的自动检查，再由人工复核——而不是直接触发行动。支撑内部监控的可解释性方法是[[interpretability]]的主题。

::: example 警报的分诊 {#ex-triage}
一个部署每天处理 $10^6$ 个智能体回合。一个检测器标记 $0.5\%$ 的良性回合和 $90\%$ 的含有目标行为的罕见回合（发生率 $10^{-5}$）。第二阶段的模型检查把 $5\%$ 的良性标记与 $95\%$ 的真实标记转给人工。每天有多少回合进入人工复核？其中有多大比例是真的？
::: solution
真实回合：每天 $10$ 个；检测器标记 $9$ 个，其中 $8.55$ 个通过第二阶段。良性：$999{,}990$ 个回合，标记 $5{,}000$ 个，$250$ 个通过。人工每天复核约 $258.5$ 个回合，其中 $8.55/258.5 = 3.3\%$ 是真的。仅第一阶段就会送来约 $5{,}009$ 个回合，其中 $0.18\%$ 是真的。层层分诊使人工复核可行；$3\%$ 的命中率能否接受，取决于复核能力与漏掉一个回合的代价——与[[#sec-audit]]的审计预算是同一个权衡。
:::
:::

## 部署中的保障措施 {#sec-deployment}

控制协议与监控器置身于一组更宽的部署保障措施之中，其中多数既关乎用户的滥用、也关乎模型的失当行为：

- **输入与输出分类器**，用于违禁内容（[[safety-alignment/robustness-jailbreaks#sec-defences]]）。
- 对智能体的**最小权限与沙箱**（least privilege and sandboxing）：工具、凭据与网络访问限制在任务所需，不可逆的操作需要确认（[[agents/agent-security]]）。
- **日志与审计痕迹**：记录提示、推理、工具调用与输出并留存，以便调查事件。
- **使用监控**：在账户与汇总层面进行，包括用隐私保护的方式分析系统如何被使用（例如 Anthropic 的 Clio，Tamkin 等，2024），以发现任何单次对话都看不出的滥用模式。
- **速率限制与分级访问**，限制攻击者可用的尝试次数（[[safety-alignment/robustness-jailbreaks#prop-compound]]）。
- **事件响应**：回滚模型、吊销访问权限、修补分类器、通知受影响方的流程，并规定触发它们的条件。一个捕获了攻击的控制协议，只有在捕获会引出决策时才有价值。

::: algorithm 设计监控与控制方案 {#alg-plan}
1. **威胁模型。**列出不可信模型或滥用系统的用户在这个部署中所能做的、不可接受的事情，以及经由哪些动作。
2. **可信资源。**确定可信模型、人工复核能力（审计预算 $a$）与响应流程。
3. **协议。**选择监控器（可信的、带反共谋对策的不可信监控器、思维链、内部探针），确定审计与转交或拦截的阈值，并对动作施加最小权限限制。
4. **控制评测。**让红队用攻击策略替换模型；对每种配置估计安全性（[[#prop-race]]）与有用性并给出置信区间；在前沿上选一个点。
5. **分诊。**按复核能力给警报流水线定规模，并考虑基率（[[#ex-triage]]）。
6. **保护监控器。**不要针对用于监督的监控器做训练；在合成攻击上跟踪监控器召回率随时间的变化。
7. **响应与复盘。**定义一次被确认的攻击会触发什么；复盘事件并更新威胁模型。
:::

## 代码 {#sec-code}

下面的清单计算在[[#ex-upfront]]与[[#ex-monitor]]的场景下先行审计、随机审计、可信监控与转交的安全性，并用模拟检验可信监控。

```python
import random, math
from statistics import NormalDist

N, a, s = 5000, 0.02, 0.5        # 任务数、审计预算（比例）、P(未被审计的攻击得手)
Phi, Q = NormalDist().cdf, NormalDist().inv_cdf

# --- 1. 先行审计：审计前 a*N 个任务，之后一个不审 --------------------------------
M = int(a * N)
def red_wins_upfront(p):
    return (1 - p) ** M * (1 - (1 - p * s) ** (N - M))
best_p = max((i / 100000 for i in range(1, 5001)), key=red_wins_upfront)
print(f"upfront auditing: red's best attack rate p={best_p:.5f}, safety {1 - red_wins_upfront(best_p):.3f}")

# --- 2. 逐次攻击的协议：捕获概率 c，得手概率 u -----------------------------------
def safety(c, u):
    """每次攻击以概率 c 被捕获、以概率 u 得手时，P(首个决定性事件是捕获)。"""
    return c / (c + u)
print(f"random auditing:  safety {safety(a, (1 - a) * s):.3f}")

d = 2.0                                       # 监控器分离度：攻击得分 ~ N(d, 1)，诚实 ~ N(0, 1)
t_audit = Q(1 - a)
c_audit = 1 - Phi(t_audit - d)
print(f"trusted monitoring: audit threshold {t_audit:.3f}, catch rate {c_audit:.3f}, "
      f"safety {safety(c_audit, (1 - c_audit) * s):.3f}")
for defer in (0.05, 0.10, 0.20):
    c_defer = 1 - Phi(Q(1 - defer) - d)         # 被标记用于审计或转交
    print(f"  + defer to trusted above top {defer:.0%}: safety {safety(c_audit, (1 - c_defer) * s):.3f}, "
          f"tasks handed to the weaker model {defer - a:.0%}")

# --- 3. 用蒙特卡洛检验可信监控（红队以 p = 0.002 攻击）--------------------------
rng = random.Random(7)
def episode(p=0.002):
    for _ in range(N):
        if rng.random() < p:                              # 一次攻击
            if rng.gauss(d, 1) > t_audit:
                return "caught"
            if rng.random() < s:
                return "red wins"
    return "no success"
runs = [episode() for _ in range(4000)]
blue = sum(r != "red wins" for r in runs) / len(runs)
print(f"simulated safety {blue:.3f} (+/- {1.96 * math.sqrt(blue * (1 - blue) / len(runs)):.3f})")
```

输出：

```
upfront auditing: red's best attack rate p=0.00132, safety 0.158
random auditing:  safety 0.039
trusted monitoring: audit threshold 2.054, catch rate 0.479, safety 0.647
  + defer to trusted above top 5%: safety 0.726, tasks handed to the weaker model 3%
  + defer to trusted above top 10%: safety 0.802, tasks handed to the weaker model 8%
  + defer to trusted above top 20%: safety 0.886, tasks handed to the weaker model 18%
simulated safety 0.650 (+/- 0.015)
```

一个团队在强化学习中，每当思维链监控器检测到"有意钻测试的空子"就惩罚其推理模型。监控器标记的钻空子行为降到接近零。他们应当得出什么结论？
- [ ] 钻测试空子已被根除。
- [x] 不能确定什么：策略可能真的不再钻空子，也可能学会了在不暴露于推理的情况下钻空子，所以他们需要一个未被用作训练信号的独立检验。
- [ ] 监控器太弱。
- [ ] 思维链监控从来不管用。
::: solution
Baker 等（2025）恰好观察到了这一点：在优化压力之下，智能体学会了隐匿的奖励破解。被当作奖励使用的监控器不再是独立的测量；检测必须使用优化之外的信号（[[#sec-cot]]）。

::: history
对自动化系统的监控与审计远早于语言模型；在 AI 方面，Christiano 与其合作者讨论了对抗性训练、监控与"引出潜在知识"（eliciting latent knowledge，2021），机制性异常检测随后提出。Shlegeris 与 Greenblatt 在 Redwood Research 发展了 AI 控制，与 Sachan 和 Roger 发表了这篇 ICML 2024 论文（最早发布于 2023 年 12 月），并论证了控制评测与建立其上的安全论证。Clymer 等（2024）提出了结构化安全论证，其中包括控制的论证；Bhatt 等（2025）把控制扩展到智能体场景；Korbak 等（2025）勾勒了一个控制安全论证。在推理方面，Baker 等（2025）研究了思维链监控与隐匿化，Korbak 等（2025）发表了多家机构联署的关于思维链可监控性的立场文件。到 2026 年，若干开发者在其安全框架中描述了对推理、内部部署与智能体行动的监控（[[safety-alignment/safety-frameworks]]）。
:::

::: summary
- AI 控制设计即使模型未对齐也能起作用的保障措施，以红队扮演模型的控制评测来评判；协议在安全–有用性前沿上比较。
- 面对"一直攻击直到出现决定性事件"的攻击者，安全性为每次攻击的 $c/(c + u)$（[[#prop-race]]）：$a = 2\%$ 的随机审计只有约 $4\%$；可预测的先行审计让攻击者可以躲风头（例中为 $16\%$）。
- 分离度为 $d'$ 的可信监控器把审计预算转化为捕获率 $1 - \Phi(\Phi^{-1}(1 - a) - d')$；转交可信模型用有用性换取更多安全性。
- 不可信监控器更强，但可能共谋；蜜罐与改写让真实与合成攻击不可分辨，从而让共谋可被检测。
- 思维链监控能抓住许多单看行动看不到的失当行为，但针对监控器训练会教会隐匿化；可监控性宝贵而脆弱，应当测量并保护。
- 探针与异常检测器深入文本之下；基率意味着警报需要分诊。
- 部署保障措施——分类器、最小权限、日志、使用监控、速率限制与事件响应——补全全局；捕获攻击只有在它触发响应时才有意义。
:::

## 习题

::: exercise 随机审计 {level=1 check="0.0952"}
在随机审计率 $a = 5\%$、未被审计的攻击成功率 $s = 0.5$ 下，对反复攻击的策略的安全性是多少？保留四位小数。
::: solution
$c = a = 0.05$，$u = (1 - a)s = 0.95\cdot0.5 = 0.475$，安全性 $= 0.05/(0.05 + 0.475) = 0.0952$（[[#prop-race]]）。
:::
:::

::: exercise 竞速公式 {level=1 check="0.75"}
每次攻击以概率 $0.3$ 被捕获、以概率 $0.1$ 得手。攻击者先被捕获的概率是多少？
::: solution
$0.3/(0.3 + 0.1) = 0.75$（[[#prop-race]]）。
:::
:::

::: exercise 蜜罐测试 {level=1 check="0.878"}
一个共谋的监控器把合成攻击误判为真实的概率为 $0.05$。用 $41$ 次蜜罐测试，它被揭穿的概率是多少？保留三位小数。
::: solution
$1 - 0.95^{41} = 1 - e^{41\ln0.95} = 1 - e^{-2.1030} = 1 - 0.1221 = 0.878$（[[#ex-collusion]]）。
:::
:::

::: exercise 监控器的捕获率 {level=2 check="0.672"}
一个可信监控器 $d' = 2.5$，审计预算 $2\%$，于是 $\tau = 2.054$。捕获率是多少？用 $\Phi(0.446) = 0.6722$，保留三位小数。
::: solution
由[[#eq-catch]]，$c = 1 - \Phi(2.054 - 2.5) = 1 - \Phi(-0.446) = \Phi(0.446) = 0.672$。把监控器从 $d' = 2$ 提升到 $2.5$，在同样预算下把捕获率从 $0.479$ 提到 $0.672$。
:::
:::

::: exercise 更好监控器的安全性 {level=2 check="0.804"}
设 $c = 0.672$、$s = 0.5$，不带转交的可信监控的安全性是多少？保留三位小数。
::: solution
$u = (1 - 0.672)\cdot0.5 = 0.164$，安全性 $= 0.672/(0.672 + 0.164) = 0.804$（[[#prop-race]]），而 $d' = 2$ 时为 $0.647$。
:::
:::

::: exercise 分诊的容量 {level=2 check="1250"}
在[[#ex-triage]]中，复核人员每天能处理 $300$ 个回合。流量增长到每天 $5\times10^6$ 个回合，比率不变。现在每天有多少良性回合进入人工复核？
::: solution
良性标记：$5\times10^6\cdot0.005 = 25{,}000$；第二阶段之后 $25{,}000\cdot0.05 = 1{,}250$ 每天，超出复核能力。必须收紧阈值（牺牲召回率）、改进第二阶段、或增加复核能力——这是一个关于审计预算的决策，而且被摆到了明面上。
:::
:::

::: exercise 先行审计为什么失效 {level=2}
用语言解释：先行审计下攻击者的最佳攻击率为什么很小，而可信监控为什么不受同一策略的威胁。
::: solution
在先行审计下，攻击只在最初 $aN$ 个任务中才被捕获。攻击者希望在那个窗口内不发起攻击、而在此之后至少成功一次，所以它要攻击得罕见：罕见到那个窗口大概是空的，又频繁到剩下的 $N - aN$ 个任务里大概有一次成功（[[#ex-upfront]]）。在可信监控下，每次攻击无论何时发生都面对同样的捕获概率 $c$，时机不带来好处，安全性 $c/(c + u)$ 不依赖攻击率（[[#prop-race]]）。不可预测、依赖攻击内容的审计能剥夺攻击者这样等待的能力。
:::
:::

::: exercise 转交阈值 {level=3}
导出带转交的可信监控的安全性：审计比例 $a$、转交比例 $b > a$、监控器分离度 $d'$ 与成功率 $s$，并证明 $b\to1$ 时安全性趋于 $1$。相应的有用性代价是什么？$b = 1$ 为什么毫无意义？
::: solution
设 $c_a = 1 - \Phi(\Phi^{-1}(1 - a) - d')$，$c_b = 1 - \Phi(\Phi^{-1}(1 - b) - d')$。审计阈值之上的攻击被捕获（$c_a$）；两个阈值之间的被替换（$c_b - c_a$，中性）；其下的被原样使用，以概率 $s$ 得手，于是 $u = (1 - c_b)s$，安全性 $= c_a/(c_a + (1 - c_b)s)$（[[#prop-race]]）。当 $b\to1$，$\Phi^{-1}(1 - b)\to-\infty$，故 $c_b\to1$，$u\to0$，安全性 $\to1$。有用性代价是比例为 $b - a$ 的诚实任务由可信模型完成。$b = 1$ 时，每个未经审计的任务都由 $T$ 完成，于是不可信模型只对受审计的那 $a$ 部分有贡献——该协议还不如根本不部署 $U$。这两个极端之间的前沿，才是控制评测所描绘的东西（[[#ex-monitor]]）。
:::
:::

::: exercise 跨步骤分散的攻击 {level=3}
在一个智能体场景中，一次攻击需要 $m$ 个连续的可疑动作，每个动作独立地被监控器以概率 $c_1$ 标记，任何一个动作被标记则攻击被捕获。（a）每次攻击的捕获概率是多少？（b）如果攻击者改为把攻击拆分，使每个动作看起来不那么可疑、每个动作的标记概率降为 $c_1/m$，那么 $m$ 很大时会怎样？说明它与 Bhatt 等（2025）的重采样协议的关系。
::: solution
(a) $c = 1 - (1 - c_1)^m$，随 $m$ 增长很快：多步攻击给了监控器多次机会。(b) 每动作概率为 $c_1/m$ 时，$m\to\infty$ 时 $c = 1 - (1 - c_1/m)^m\to1 - e^{-c_1}$。取 $c_1 = 0.5$，极限为 $0.393$，低于单步攻击的 $0.5$，更远低于未拆分的 $m$ 步攻击的 $1 - 0.5^m$：把攻击摊薄就消除了监控器从多步中获得的优势。Bhatt 等用如下协议回应：当一个动作看起来可疑时，在同一上下文中从模型*重采样*更多动作：攻击策略往往会在重采样中继续攻击，从而暴露自己，而诚实策略的重采样看起来无害。这把多步结构重新变成防守方的优势。
:::
:::
