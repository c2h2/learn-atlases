语言模型从不直接看词，它看到的是一串整数，而这串整数是文本经过一连串容易被忽略的决定得到的：哪些字符存在、它们如何存成字节、两个看起来一模一样的字符串是否被当作同一个、一个词在哪里结束、下一个词从哪里开始。每一个决定都会改变模型能学到什么、运行它要花多少钱。一个分不清一把键盘上敲出的 *café* 与另一把键盘上敲出的 *café* 相等的模型，在读者看到一个词的地方看到了两个词；一个在字节上工作的分词器，处理一个汉字花掉的符号数是处理一个英语字母的三倍。

本章讲的是任何模型介入之前的文本。前半部分讲**字符**：Unicode 码位、把码位变成字节的 UTF-8 编码（逐比特算出来），以及决定两个字符串何时相等的规范化形式。后半部分讲**词**：词例与词形、语料库，以及在几乎每一种语言、每一个语料库中都成立的两条经验规律——**齐普夫定律**（Zipf's law），说的是少数词极频繁而大多数词极罕见；**赫普斯定律**（Heaps' law），说的是无论读了多少文本，新词总在出现。两条定律都在下文用一部真实的公版小说作拟合，而它们都解释了为什么下一章[[text-and-language/tokenisation]]要放弃把整词当作语言模型的单位。

## 字符与码位 {#sec-unicode}

计算机存储的是数，所以文本必须用数来表示。早期系统使用小表格：ASCII（1963）把 $0$ 到 $127$ 这些数分配给英语字母、数字、标点和控制码，几十个互不兼容的 8 位扩展又在上半区 $128$–$255$ 里塞进了带重音的字母、西里尔字母或希腊字母。不知道用的是哪张表，一个文件就什么也说明不了；而没有任何一张表装得下需要数万个字符的中、日、韩文。Unicode 用一张总表取代了所有这些表。

::: definition Unicode 码位 {#def-codepoint}
**Unicode 码位空间**是 $0$ 到 $\text{10FFFF}_{16} = 1{,}114{,}111$ 这些整数的集合，写成 U+0000 到 U+10FFFF。它被划分为 $17$ 个**平面**（plane），每个平面含 $2^{16} = 65{,}536$ 个码位；平面 $0$，即 U+0000–U+FFFF，是**基本多文种平面**。$2{,}048$ 个码位 U+D800–U+DFFF（**代理项**）为 UTF-16 编码保留，永不代表字符；其余的 $1{,}114{,}112 - 2{,}048 = 1{,}112{,}064$ 个是 **Unicode 标量值**。标准把一部分标量值分配给**抽象字符**，每个字符都有一个名字和一组性质（类别、大小写映射、分解）。一个 **Unicode 字符串**是标量值的一个有限序列。
:::

Unicode 16.0（2024 年 9 月；本章所用 Python 3.14 包含的就是这个版本）共分配了 $154{,}998$ 个字符；每个新版本都会新增几千个（历史文字、中日韩表意文字、表情符号），所以这个数最好记作"约 $155{,}000$ 个，且持续增长"（2026 年时）。码位空间的大部分是空的，而且会一直是空的。

一个码位并不等于读者感知为一个字符的东西。Unicode 区分三个层次：

- **码位**——标准的单位，也是 Python 的 `len` 所数的东西。
- **字素簇**——用户感知为一个字符的东西，可能由好几个码位组成。字母 *é* 既可以是单个码位 U+00E9，也可以是 U+0065（e）后接 U+0301（组合尖音符）这一对。法国国旗是两个码位：区域指示符 F 和 R。家庭表情符号 👨‍👩‍👧 是五个：男人、零宽连接符、女人、零宽连接符、女孩。
- **字形**——字体画出来的形状，它取决于字体，也取决于上下文（阿拉伯字母的形状随位置而变；*f* 和 *i* 可能被画成一个连字）。

语言模型处理的是码位，或者更常见的是编码码位的字节；除非训练数据教会它，字素这一层对它是不可见的。因此逐码位倒转一个字符串，可能把重音符与它的字母拆开、或者把一个表情符号劈成两半——这也是"简单"的字符操作对语言模型为何很难的几个原因之一，[[text-and-language/tokenisation]]对此有详细说明。

## 从码位到字节：UTF-8 {#sec-utf8}

文件和网络消息都是字节序列，即 $0$ 到 $255$ 的整数。**编码形式**把每个标量值映射为一个短的字节序列。Unicode 定义了三种：UTF-32 对一切用四个字节，UTF-16 用两个或四个，UTF-8 用一到四个。UTF-8 是绝大多数网页所用的编码，是多数编程语言和操作系统的默认编码，也是字节级分词器看到的字节流。

::: algorithm UTF-8 编码 {#alg-utf8}
把标量值 $c$ 写成二进制，按它的大小决定字节数：

| $c$ 的范围 | 位数 | 字节 1 | 字节 2 | 字节 3 | 字节 4 |
|---|---|---|---|---|---|
| U+0000 – U+007F | 7 | `0xxxxxxx` | | | |
| U+0080 – U+07FF | 11 | `110xxxxx` | `10xxxxxx` | | |
| U+0800 – U+FFFF | 16 | `1110xxxx` | `10xxxxxx` | `10xxxxxx` | |
| U+10000 – U+10FFFF | 21 | `11110xxx` | `10xxxxxx` | `10xxxxxx` | `10xxxxxx` |

把 `x` 位置填入 $c$ 的比特，最高位在前，位数不足时按第二列给出的位数在高位补零。代理项（U+D800–U+DFFF）不予编码。序列的第一个字节是**首字节**，其余所有形如 `10xxxxxx` 的字节是**续字节**。
:::

::: example 四个字符，逐字节 {#ex-utf8}
在 UTF-8 中编码 *é*（U+00E9）、*€*（U+20AC）、*中*（U+4E2D）和 😀（U+1F600）。
::: solution
**é**：$\text{E9}_{16} = 233$ 落在 U+0080–U+07FF，所以需要两个字节、11 个比特：`000 1110 1001` 重新分组为 `00011` 和 `101001`。两个字节是 `110 00011` $=$ C3 与 `10 101001` $=$ A9。

**€**：$\text{20AC}_{16}$ 需要三个字节、16 个比特：`0010 0000 1010 1100` 重新分组为 `0010 | 000010 | 101100`。三个字节是 `1110 0010` $=$ E2、`10 000010` $=$ 82 与 `10 101100` $=$ AC。

**中**：$\text{4E2D}_{16}$ = `0100 1110 0010 1101`，重新分组为 `0100 | 111000 | 101101`，得到 `1110 0100` $=$ E4、`10 111000` $=$ B8、`10 101101` $=$ AD。

**😀**：$\text{1F600}_{16}$ 超过 U+FFFF，所以用四个字节、21 个比特：`000 011111 011000 000000`。四个字节是 `11110 000` $=$ F0、`10 011111` $=$ 9F、`10 011000` $=$ 98 与 `10 000000` $=$ 80。

于是 *é* 占两个字节，*€* 和 *中* 三个，😀 四个。一个码位需要多少个字节只由它的大小决定，与这个文字的重要程度、说它的人数都无关。
:::
:::

同样的计算用 Python 写出，并与内置编解码器核对：

```python
import unicodedata

def utf8_encode(cp):
    """Encode one code point (an int) as UTF-8 by hand; returns a list of byte values."""
    if cp < 0x80:                      # 1 byte : 0xxxxxxx
        return [cp]
    if cp < 0x800:                     # 2 bytes: 110xxxxx 10xxxxxx
        return [0xC0 | cp >> 6, 0x80 | cp & 0x3F]
    if cp < 0x10000:                   # 3 bytes: 1110xxxx 10xxxxxx 10xxxxxx
        if 0xD800 <= cp <= 0xDFFF:
            raise ValueError("surrogates are not characters")
        return [0xE0 | cp >> 12, 0x80 | cp >> 6 & 0x3F, 0x80 | cp & 0x3F]
    if cp <= 0x10FFFF:                 # 4 bytes: 11110xxx 10xxxxxx 10xxxxxx 10xxxxxx
        return [0xF0 | cp >> 18, 0x80 | cp >> 12 & 0x3F, 0x80 | cp >> 6 & 0x3F, 0x80 | cp & 0x3F]
    raise ValueError("beyond U+10FFFF")

for ch in "Aé€中😀":
    mine = utf8_encode(ord(ch))
    assert bytes(mine) == ch.encode("utf-8")       # agrees with Python's codec
    print(f"U+{ord(ch):04X} {unicodedata.name(ch):<34} {' '.join(f'{b:02X}' for b in mine)}")

s = "naïve café"
print(len(s), "code points,", len(s.encode("utf-8")), "bytes")
```

```text
U+0041 LATIN CAPITAL LETTER A             41
U+00E9 LATIN SMALL LETTER E WITH ACUTE    C3 A9
U+20AC EURO SIGN                          E2 82 AC
U+4E2D CJK UNIFIED IDEOGRAPH-4E2D         E4 B8 AD
U+1F600 GRINNING FACE                      F0 9F 98 80
10 code points, 12 bytes
```

（在 Python 中，`>>` 和 `&` 比 `|` 结合得更紧，`>>` 又比 `&` 结合得更紧，所以 `0x80 | cp >> 6 & 0x3F` 的意思是 `0x80 | ((cp >> 6) & 0x3F)`。）UTF-8 的设计有四个性质，凡按字节处理文本时都用得上。

::: proposition UTF-8 的性质 {#prop-utf8}
1. **ASCII 兼容性。** $128$ 以下的字节在 UTF-8 字符串中只可能作为相应 ASCII 字符的编码出现。
2. **唯一解码与自同步。** 首字节决定其序列的长度，且首字节与续字节可以区分，所以一个字节串至多有一种解码；从字符串中间某处开始的解码器至多跳过三个字节，就能找到下一个字符边界。
3. **最短形式。** 每个标量值恰有一种编码；把小数值塞进较长模式的"过长"编码是非法的。
4. **次序。** 逐字节（按字典序）比较两个 UTF-8 字符串，得到的次序与比较它们的码位序列相同。
:::

::: proof
（1）多字节序列的每个字节最高位都是 $1$：首字节以 `110`、`1110` 或 `11110` 开头，续字节以 `10` 开头。所以一个 `0xxxxxxx` 字节只能是一个单字节序列，也就是那个 ASCII 字符。

（2）模式 `0`、`10`、`110`、`1110`、`11110` 是前缀无关的——没有哪个是另一个的开头——所以任意字节的前几位就能说明它是续字节还是首字节，而首字节说明后面跟着几个续字节。从头读起，每个序列由此被唯一确定，于是一个字节串至多有一种切成编码字符的方式。把解码器放在任意字节处，它会跳过续字节（`10xxxxxx`）直到遇到一个首字节；由于一个序列至多有三个续字节，它至多跳三个。

（3）编码规则按 $c$ 的范围决定字节数，而[[#alg-utf8]]中的范围互不相交，所以编码是一个函数。解码器必须拒绝（例如）C0 80（它本会用两个字节解码到 U+0000）；有了这条规则，解码就是编码的逆，每个标量值只有一种合法形式。

（4）设 $a$ 与 $b$ 是码位且 $a < b$。若它们所需字节数相同，它们的编码就是各自的比特串、补零到同一长度、切在相同定长前缀之后的相同字段里；逐字节比较就是从最高位端比较这些比特，也就是比较这两个数。若 $a$ 所需字节数比 $b$ 少，则 $a$ 的首字节更小：一、二、三、四字节的首字节分别落在 $[\text{00}, \text{7F}]$、$[\text{C2}, \text{DF}]$、$[\text{E0}, \text{EF}]$ 与 $[\text{F0}, \text{F4}]$，这些区间递增。由于编码是前缀无关的，逐字节比较两个字符串必然在第一个不同的码位内部到达第一个不同的字节，那里的次序就是码位的次序。
:::

两个推论在本课程中反复出现。其一，**字节数取决于文字**：ASCII 字母占一个字节；带变音符号的拉丁字母、希腊文、西里尔文、希伯来文、阿拉伯文占两个；基本多文种平面的多数其他字符——天城文、泰文、中文、日文、韩文——占三个；表情符号和罕见中日韩表意文字占四个。因此从字节出发的分词器，处理内容相同的印地语或中文文本时，起步序列就是英语的两三倍长；这一悬殊差别在[[text-and-language/tokenisation#sec-disparity]]中有度量。其二，**任何字节串都能切成词元，但并非任何字节串都是文本**：生成字节（或字节级词元）的模型可能产出非法的 UTF-8（有首字节而后续续字节缺失），解码器必须对此作出处理。

::: quiz
字符串 `naïve café`（十个码位，含一个空格，无组合字符）在 UTF-8 中占多少个字节？
- [ ] $10$
- [ ] $11$
- [x] $12$
- [ ] $20$
::: solution
十个码位里有八个是 ASCII（各占一个字节，含那个空格）；*ï*（U+00EF）和 *é*（U+00E9）落在 U+0080–U+07FF，各占两个字节。总计 $8 + 2\cdot2 = 12$，与清单打印的一致。
:::
:::

## 两个字符串何时相等？规范化 {#sec-normalisation}

"e 加组合尖音符"这一对与单个码位"é"是不同的码位序列，而每个读者都认为它们是同一段文本。Unicode 称它们**规范等价**。有一个更弱的关系——**兼容等价**——把那些对多数用途而言是同一种东西的变体等同起来，尽管它们看起来可能不同：连字 *ﬁ*（U+FB01）与两个字母 *fi*、东亚排版用的全角 *Ａ*（U+FF21）与普通 *A*、带圈数字 *①* 与数字 *1*、上标 *²* 与数字 *2*。

::: definition 规范化形式 {#def-normal-forms}
Unicode 标准附录 #15 定义了四个**规范化形式**，即字符串到字符串的函数：

- **NFD**（规范分解）：把每个字符递归地替换为它的规范分解，并把组合标记的序列排成标准顺序。
- **NFC**（规范组合）：先做 NFD，再在标准允许之处把基字与标记重新合成预组合字符。
- **NFKD** 与 **NFKC**：同上，但同时使用兼容分解与规范分解。

两个字符串规范等价，当且仅当它们有相同的 NFD（等价地，相同的 NFC）；兼容等价，当且仅当它们有相同的 NFKD（等价地 NFKC）。每个形式都是幂等的：规范化两次与规范化的结果相同。
:::

::: example 规范化实践 {#ex-normalise}
对 *e*+U+0301、*é*、*ﬁ*、*①*、*Ａ*、*x²* 与 *Å* 施加 NFC、NFD 与 NFKC。
::: solution
```python
import unicodedata
for t in ["é", "é", "ﬁ", "①", "Ａ", "x²", "Å"]:
    forms = {f: unicodedata.normalize(f, t) for f in ("NFC", "NFD", "NFKC")}
    print(repr(t), {f: [f"U+{ord(c):04X}" for c in v] for f, v in forms.items()})
```

```text
'é' {'NFC': ['U+00E9'], 'NFD': ['U+0065', 'U+0301'], 'NFKC': ['U+00E9']}
'é' {'NFC': ['U+00E9'], 'NFD': ['U+0065', 'U+0301'], 'NFKC': ['U+00E9']}
'ﬁ' {'NFC': ['U+FB01'], 'NFD': ['U+FB01'], 'NFKC': ['U+0066', 'U+0069']}
'①' {'NFC': ['U+2460'], 'NFD': ['U+2460'], 'NFKC': ['U+0031']}
'Ａ' {'NFC': ['U+FF21'], 'NFD': ['U+FF21'], 'NFKC': ['U+0041']}
'x²' {'NFC': ['U+0078', 'U+00B2'], 'NFD': ['U+0078', 'U+00B2'], 'NFKC': ['U+0078', 'U+0032']}
'Å' {'NFC': ['U+00C5'], 'NFD': ['U+0041', 'U+030A'], 'NFKC': ['U+00C5']}
```

两种写法的 *é* 打印出来完全相同，NFC 与 NFD 也分别相同，所以它们规范等价。NFC 与 NFD 对 *ﬁ*、*①*、*Ａ* 和 *²* 原样不动，因为它们只是兼容变体；NFKC 把它们变成 *fi*、*1*、*A* 和 *2*。（这里的 *Å* 是按 U+00C5 输入的；埃格斯特朗符号（Ångström）U+212B 在 NFC 下也规范化为 U+00C5。）
:::
:::

规范化是分词器设计者做出的选择。SentencePiece（[[text-and-language/tokenisation]]）默认施加基于 NFKC 的规则；GPT-2 一族的字节级分词器完全不做规范化，把"*é* 的两种写法意思相同"这件事留给模型去学。两个选择都有代价：不做规范化，同一个词就有多种编码，统计量被分到各处；做了 NFKC，有些区别就被抹掉了。

::: warning 规范化与大小写折叠会改变语义
NFKC 把用上标写成的 $x^2$ 变成 *x2*，把看起来像化学式的 *H₂O* 变成 *H2O*；它适合用于搜索与匹配，不适合必须逐字复现的文本。转小写不是一种规范化形式，而且依赖语言：在土耳其语中，*I* 的小写是无点的 *ı*，德语 *ß* 的大写是 *SS*，所以一来一回字符串的长度就变了。对训练文本做过什么，推理时就必须一模一样地做什么；一个在 NFKC 文本上训练、却被喂进未规范化文本的分词器，会看到它很少或从未见过的码位。
:::

## 词、词形与语料库 {#sec-words}

在字符之上，文本由词构成——至少看起来在英语里如此。数词首先要决定什么算一个词。

::: definition 词例、词形与语料库 {#def-types}
**语料库**是为研究而收集的大量文本。**词切分**（分词，经典意义上的 tokenisation）把语料库切成一串**词例**——连读的词——$w_1, w_2, \dots, w_N$；$N$ 就是语料库按词例计的大小。出现的不同取值是它的**词形**；词形的集合是**词表**，大小为 $V$。一个词形的**频率** $c(w)$ 是它的词例数，于是 $\sum_wc(w) = N$。$c(w) = 1$ 的词形叫 **hapax legomenon**（希腊语，"仅说过一次"）。
:::

句子 *the cat sat on the mat* 有 $N = 6$ 个词例、$V = 5$ 个词形，*the* 的频率为 $2$。即便对英语，切分也涉及种种选择——*don't* 算一个词例还是两个？*New York* 算一个吗？*Cat* 和 *cat* 是同一个词形吗？*run*、*runs* 和 *ran* 呢？——每个选择都会改变 $N$、$V$ 和计数。许多文字系统让这道选择题更难。中文、日文和泰文不用空格分词，切分本身就是一个预测问题，而且汉语语言学家连"什么是词"都还在争论（见中文图谱中关于[形态学](/learn/chinese/lesson.php?c=linguistics&l=morphology)与[数字时代的汉字](/learn/chinese/lesson.php?c=chinese-characters&l=characters-digital)的课）。土耳其语、芬兰语这类黏着语用许多语素构成长词，不同词形的数目因此极其庞大。[[text-and-language/linguistic-structure]]会回到形态学；这里我们刻意用最简单的一条规则——把文本转小写，取最长的连续字母段、允许词内有撇号——并研究它给出的计数。

用于语言建模的语料库规模已经增长了好几个数量级。布朗语料库（Brown Corpus，Francis 与 Kučera 编，1960 年代编制）收录约一百万词的美式英语，来自 $15$ 个文体的 $500$ 个样本，是早期频率研究的基础。Project Gutenberg 提供数万本公版书。大语言模型的预训练语料主要由过滤后的网络爬取汇编而成，以数万亿词元计（2026 年时；见[[pretraining/training-data]]）。下面的统计规律在所有这些尺度上成立。

## 齐普夫定律 {#sec-zipf}

把语料库的词形按频率排序，最频繁的排最前，记 $f(r)$ 为排名第 $r$ 的词形的频率。在任何自然语言的语料库中，$f(r)$ 都又陡又平滑地下降。

::: definition 齐普夫定律 {#def-zipf}
若对某个常数 $C$，排名第 $r$ 的词形的频率近似满足

$$
f(r)\approx\frac{C}{r^{s}},\qquad\text{等价地}\qquad\log f(r)\approx\log C - s\log r,
$$ {#eq-zipf}

其中 $s > 0$，则称该语料库服从指数为 $s$ 的**齐普夫定律**。对词频率，$s$ 接近 $1$。齐普夫定律是一条经验规律，不是定理：它在排名区间的中间部分描述得很好，对最靠前的几个词形和罕见词形的长尾则差一些。曼德尔布罗特（Mandelbrot）的推广 $f(r)\approx C/(r + b)^{s}$ 能更好地拟合头部。
:::

在双对数图上[[#eq-zipf]]是一条斜率为 $-s$ 的直线。下面把它拟合到梅尔维尔（Herman Melville）的《白鲸记》（*Moby-Dick*，1851；Project Gutenberg 电子书 #2701，2026-10-27 下载；文件包含古腾堡的页眉与许可证，已剪去）：

```python
import re, math, collections

raw = open("pg2701.txt", encoding="utf-8").read()     # Moby-Dick, Project Gutenberg #2701
start = raw.index("\n", raw.index("*** START OF")) + 1  # strip the Gutenberg header ...
end = raw.index("*** END OF")                           # ... and licence footer
words = re.findall(r"[a-z]+(?:['’][a-z]+)*", raw[start:end].lower())
counts = collections.Counter(words)
ranked = counts.most_common()                           # [(type, frequency)], by rank
N, V = len(words), len(counts)
print("tokens N =", N, " types V =", V)
print("hapax legomena:", sum(1 for w, c in ranked if c == 1))
for r in (1, 2, 3, 4, 5, 10, 100, 1000, 10000):
    w, c = ranked[r - 1]
    print(f"rank {r:>5}: {w!r:>12} {c:>6}  r*f = {r * c}")

def fit(xs, ys):                                        # least-squares line y = a + b x
    n = len(xs); mx = sum(xs) / n; my = sum(ys) / n
    b = sum((x - mx) * (y - my) for x, y in zip(xs, ys)) / sum((x - mx) ** 2 for x in xs)
    return my - b * mx, b

xs = [math.log10(r) for r in range(10, 1001)]           # ranks 10..1000
ys = [math.log10(ranked[r - 1][1]) for r in range(10, 1001)]
a, b = fit(xs, ys)
print(f"Zipf fit, ranks 10-1000: log10 f = {a:.3f} {b:+.3f} log10 r  (s = {-b:.3f})")
```

::: example 解读齐普夫拟合 {#ex-zipf-fit}
用拟合直线 $\log_{10}f = 4.575 - 1.083\log_{10}r$ 预测《白鲸记》中排名第 $100$ 的词形的频率，并与观测值 $281$ 比较。精确的定律 $f(r) = f(1)/r$ 又会预测多少？
::: solution
$\log_{10}f = 4.575 - 1.083\cdot2 = 2.409$，于是 $f\approx10^{2.409}\approx256$，比观测值 $281$ 低约 $9\%$。以最高频词锚定的精确 $s = 1$ 定律预测 $14{,}535/100\approx145$，低得太多，因为 *the* 比曲线其余部分所暗示的还要频繁——分布的头部正是齐普夫定律拟合最差的地方，这也是拟合排除 $10$ 以下排名的原因。
:::
:::

齐普夫定律给出两个对语言建模至关重要的定量预言：一小撮词形占了全部词例的很大份额，而绝大多数词形都很罕见。

::: proposition 齐普夫定律下的覆盖率 {#prop-coverage}
设词表有 $V$ 个词形、其频率恰好与 $1/r$ 成正比，则属于最频繁 $k$ 个词形的词例占全部词例的比例为

$$
\frac{H_k}{H_V}\approx\frac{\ln k + \gamma}{\ln V + \gamma},\qquad H_n = \sum_{r=1}^{n}\frac1r,
$$

其中 $\gamma = 0.5772\ldots$ 是欧拉–马斯凯罗尼常量。
:::

::: proof
在 $f(r) = C/r$ 下，最靠前 $k$ 个词形的词例数是 $C\sum_{r\le k}1/r = CH_k$，总数是 $CH_V$；常数 $C$ 相消。近似用的是经典渐近式 $H_n = \ln n + \gamma + O(1/n)$，它可由把和式与 $\int_1^n dx/x = \ln n$ 比较得出。
:::

对《白鲸记》，$V = 17{,}368$、$H_V = 10.34$，于是命题预测最靠前 $100$ 个词形覆盖 $H_{100}/H_V = 5.187/10.34 = 50.2\%$ 的文本；用同一份计数算出的实际覆盖率是 $50.6\%$。一百个词——其中几乎全是功能词——构成了小说的一半，而同一定律下要覆盖 $90\%$ 的词例约需 $6{,}000$ 个词形（习题 9）。预言的另一半关乎长尾。

::: proposition 绝大多数词形很罕见 {#prop-hapax}
设排名第 $r$ 的词形的频率为 $C/r$，并把排名当作连续量，于是频率至少为 $m$ 的词形数为 $C/m$。则频率恰为 $m$ 的词形数为

$$
V_m = \frac{C}{m} - \frac{C}{m + 1} = \frac{C}{m(m+1)},
$$

又最罕见的词形频率为 $1$，故 $V\approx C$。于是约 $\tfrac12$ 的词形只出现一次，$\tfrac16$ 出现两次，$\tfrac1{12}$ 出现三次；一般地，出现 $m$ 次的词形占比例 $1/\big(m(m+1)\big)$。
:::

::: proof
词形的频率至少为 $m$，恰好当 $C/r\ge m$，即 $r\le C/m$，这样的词形有 $C/m$ 个（忽略取整）。频率恰为 $m$ 的词形就是频率至少为 $m$ 但不至少为 $m + 1$ 的那些，即上式的差。排名最大 $V$ 的词形频率为 $C/V\approx1$，故 $V\approx C$；把 $V_m$ 除以 $V$ 就得到这些比例。它们加起来是一：$\sum_{m\ge1}\big(\tfrac1m - \tfrac1{m+1}\big) = 1$，一个裂项相消的级数。
:::

在《白鲸记》中，$17{,}368$ 个词形里有 $7{,}650$ 个只出现一次——占 $44\%$，而预测值是 $50\%$；恰出现两次的有 $2{,}899$ 个，占 $16.7\%$，与预测的 $\tfrac16 = 16.7\%$ 吻合。对统计模型而言，后果是严酷的：将近一半的词表只被见过一次，因此从这个语料库对它们什么都估计不可靠；而在同类的新文本里，相当一部分词例将是从未见过的词形。这就是[[text-and-language/ngram-models]]迎面碰上的**稀疏数据问题**，而且词对和词组的稀疏比单词严重得多。

::: intuition 齐普夫定律为何应当成立？
对它的成因并无公认的解释，而几种很不相同的机制都会产生这种形状的排名–频率曲线。齐普夫（Zipf，1949）诉诸说话人与听话人之间的"最小努力原理"。西蒙（Herbert Simon，1955）证明"富者愈富"的过程——每个新词以正比于过去频率的概率重复一个旧词、以很小的概率成为新词——会产生幂律。米勒（George Miller，1957）观察到，即使一只猴子随机敲字母键和空格键敲出的"词"，其排名–频率曲线也接近齐普夫型，所以定律本身并不能说明太多语言的事。定律可靠提供的是一个描述：一条任何语料库都穷尽不了的罕见事件的长尾。
:::

## 赫普斯定律：词表永不停止增长 {#sec-heaps}

从头读一部语料库，数一数读完前 $n$ 个词例后已经见过多少个不同词形。如果一种语言的词表是一张固定的、有限的清单，这个数会趋于平稳。它不会。

::: definition 赫普斯定律 {#def-heaps}
若其前 $n$ 个词例中不同词形的个数近似满足

$$
V(n)\approx Kn^{\beta},\qquad 0 < \beta < 1,
$$ {#eq-heaps}

对常数 $K$ 与 $\beta$ 成立，则称该语料库服从**赫普斯定律**（Heaps' law，又称 Herdan 定律）。对英语词形，$\beta$ 通常在约 $0.4$ 到 $0.7$ 之间，$K$ 在约 $5$ 到 $100$ 之间，取决于语料库和切分方式。与齐普夫定律一样，它是一条经验规律。
:::

接着上面的清单，在大约对数间隔的 $n$ 处记录 $V(n)$，再对 $\log V$ 关于 $\log n$ 拟合一条直线：

```python
seen, growth = set(), {}
checkpoints = {int(10 ** (k / 4)) for k in range(12, 22)} | {N}   # n = 1000, 1778, ..., N
for i, w in enumerate(words, 1):
    seen.add(w)
    if i in checkpoints:
        growth[i] = len(seen)
for n in sorted(growth):
    print(f"n = {n:>6}  V(n) = {growth[n]:>5}")
ks = sorted(growth)
a2, b2 = fit([math.log10(n) for n in ks], [math.log10(growth[n]) for n in ks])
print(f"Heaps fit: V = {10 ** a2:.2f} * n^{b2:.3f}")
```

::: example 外推词表 {#ex-heaps}
用拟合 $V(n) = 5.90\,n^{0.660}$，估计 (a) 语料库翻倍时词表增长多少，以及 (b) 若有一部十亿词元、文体如同《白鲸记》的语料库，它的词表有多大。
::: solution
(a) $V(2n)/V(n) = 2^{0.660} = 1.58$：文本翻倍，词形就多 $58\%$，与 $n$ 无关。(b) $5.90\cdot(10^{9})^{0.660} = 5.90\cdot10^{5.94}\approx5.1$ 百万个词形。第二个数不可当真到几倍以内：它从 $2\times10^{5}$ 个词例外推到 $10^{9}$，而十亿词元的真实文本会出自许多作者、涉及许多主题，带着这部小说没有的姓名、数字、拼错和外语词。定性结论仍然成立：词级词表会不断增长，大致是语料库大小的一个幂。
:::
:::

齐普夫定律和赫普斯定律是有关联的。如果词例是从一个固定分布独立抽取的，该分布在无界词表上取齐普夫型概率，那么词表就会以 $n$ 的幂增长，指数为 $1/s$。

::: proposition 由齐普夫推出赫普斯 {#prop-heaps-zipf}
设词例独立地抽自无穷多个词形上的分布，$p_r = r^{-s}/\zeta(s)$，$r = 1, 2, \dots$，某个 $s > 1$，其中 $\zeta(s) = \sum_rr^{-s}$。则 $n$ 次抽取中不同词形数的期望满足 $\mathbb{E}[V(n)]\sim c\,n^{1/s}$（$n\to\infty$），其中常数 $c > 0$ 依赖于 $s$。
:::

::: proof
词形 $r$ 出现在 $n$ 次抽取中的概率是 $1 - (1 - p_r)^n$，所以由期望的线性性 $\mathbb{E}[V(n)] = \sum_{r\ge1}\big(1 - (1 - p_r)^n\big)$。记 $a = 1/\zeta(s)$、$u = n^{-1/s}$。当 $n$ 大时，起作用的项 $p_r$ 很小，此时 $(1 - p_r)^n\approx e^{-np_r}$，而和式可用积分逼近：

$$
\sum_{r\ge1}\big(1 - e^{-anr^{-s}}\big)\approx\int_0^\infty\big(1 - e^{-anx^{-s}}\big)\,dx = n^{1/s}\int_0^\infty\big(1 - e^{-ay^{-s}}\big)\,dy,
$$

其中作了代换 $x = n^{1/s}y$。最后的积分是有限的：被积函数在 $0$ 附近不超过 $1$，在 $y$ 大时像 $ay^{-s}$，而后者在 $s > 1$ 时可积。于是 $\mathbb{E}[V(n)]\sim c\,n^{1/s}$，其中 $c = \int_0^\infty(1 - e^{-ay^{-s}})\,dy$。（把 $(1 - p)^n$ 换成 $e^{-np}$、把和换成积分所引入的误差是低阶的；Karlin（1967）对这类占位问题给出了严格的处理。）
:::

命题背后的模型——从一个固定分布独立抽取——并不是文本的生成方式：词是成簇出现的（*whale* 一旦出现就会再出现），话题会漂移，拟合出的齐普夫指数还随所用的排名范围而变。对《白鲸记》，齐普夫拟合给出 $1/s = 1/1.083 = 0.92$，而直接拟合的赫普斯指数是 $0.66$；这个理想化的关系预言的是定律的形状，不是它的指数。不过，两条定律对建模说的是同一件事：**词级词表不可能封闭**。任何固定的词的清单都会在新文本里遇到未收录的词，而清单里最罕见的词又例句太少、学不会。

::: application 对语言模型的后果
一个词的清单固定的模型，必须把清单外的每个词映射到单个"未知"符号，丢掉的恰恰是齐普夫定律所说构成词表大部分的那些罕见而有信息量的词（人名、术语）。子词分词器（[[text-and-language/tokenisation]]）避免这个问题：每个词都由一套封闭的片段清单拼出来——必要时一直降到 UTF-8 的 $256$ 个字节值——同时让高频词保持完整。这条长尾也解释了为什么语言模型的词表大小是一种折中，通常从几万到几十万个词元（2026 年时）：词表越大，序列越短，但多出来的每个词元都更罕见，它的嵌入能被训练的机会更少。
:::

::: history
国际电报字母表与后来的 ASCII（美国信息交换标准码，1963）为电传打字机和计算机标准化了小的字符集。Joe Becker、Lee Collins 与 Mark Davis 于 1987–88 年开始了最终促成 Unicode 的工作，Unicode 1.0 于 1991 年发布，不久后与 ISO/IEC 10646 标准协调一致。UTF-8 由 Ken Thompson 与 Rob Pike 于 1992 年 9 月为 Plan 9 操作系统设计，并作为互联网标准发表（现为 RFC 3629，2003，其中把它限定在 U+10FFFF 以内）。排名–频率规律先由法国速记员 Jean-Baptiste Estoup（1916）和物理学家 Edward Condon（1928）注意到，后经 George Kingsley Zipf 在《语言的心理生物学》（*The Psycho-Biology of Language*，1935）与《人类行为与最小努力原则》（*Human Behavior and the Principle of Least Effort*，1949）中发扬光大；曼德尔布罗特（Mandelbrot）在 1953 年提出了他的推广。Herdan（1960）与 Heaps（1978，在一部信息检索的书中）描述了词表的幂律增长。Henry Kučera 与 W. Nelson Francis 出版了《现代美式英语的计算分析》（*Computational Analysis of Present-Day American English*，1967），即布朗语料库的频率研究。
:::

::: summary
- Unicode 给出码位 U+0000–U+10FFFF；其中 $1{,}112{,}064$ 个是标量值（去掉代理项），约 $155{,}000$ 个是已分配字符（Unicode 16.0）。用户感知为一个字符的东西（字素簇）可能是好几个码位。
- UTF-8 用一个到四个字节编码一个码位，首字节前缀无关、续字节形如 `10xxxxxx`；它兼容 ASCII、唯一可解码、自同步、保序。字节数取决于文字：ASCII 一个，多数带变音符号的字母文字两个，中日韩与多数印度系文字三个，表情符号四个。
- 规范等价的字符串有相同的 NFC/NFD；NFKC 还会合并兼容变体（连字、全角形式、上标），可能改变语义。训练与推理文本务必一模一样地规范化。
- $N$ 个词例的语料库有 $V$ 个词形。齐普夫定律 $f(r)\approx C/r^{s}$（$s\approx1$）在经验上成立：在《白鲸记》中（$N = 216{,}625$、$V = 17{,}368$），最靠前 $100$ 个词形覆盖一半文本，而 $44\%$ 的词形只出现一次。
- 赫普斯定律 $V(n)\approx Kn^{\beta}$（《白鲸记》的拟合 $\beta = 0.66$）：新词层出不穷，词级词表无法封闭——这正是子词分词的动机。

## 习题

::: exercise 一个德语词的字节数 {level=1 check="7"}
*Größe* 在 UTF-8（NFC 形式）中占多少个字节？给出 *ß*（U+00DF）的字节。
::: solution
*G*、*r* 和 *e* 是 ASCII，各一个字节；*ö*（U+00F6）与 *ß*（U+00DF）在 U+0080–U+07FF，各两个字节。共 $3 + 4 = 7$ 个字节。*ß*：$\text{DF}_{16}$ = `000 1101 1111` 重新分组为 `00011` 与 `011111`，得 `110 00011` $=$ C3 与 `10 011111` $=$ 9F。
:::
:::

::: exercise 手工解码 {level=1 check="8364"}
解码 UTF-8 字节序列 E2 82 AC，给出码位的十进制值。
::: solution
E2 = `1110 0010` 是三字节首字节，贡献 `0010`；82 = `10 000010` 贡献 `000010`；AC = `10 101100` 贡献 `101100`。拼接得 `0010 000010 101100` = $\text{20AC}_{16} = 8364$，欧元符号——[[#ex-utf8]]的逆运算。
:::
:::

::: exercise 码位与字节 {level=1 check="9"}
字符串 *日本語*（日语的"日语"）由码位 U+65E5、U+672C、U+8A9E 组成。它有几个码位、几个 UTF-8 字节？它的英语译文 *Japanese* 要占几个字节？
::: solution
三个码位，每个都在 U+0800 到 U+FFFF 之间，所以各三个字节：$9$ 个字节。*Japanese* 是八个 ASCII 字母，$8$ 个字节。两个字符串的字节数几乎相同，尽管一个只有三个字符、另一个有八个；对日语的字节级模型来说，每个字符是三个符号。
:::
:::

::: exercise 一个齐普夫预测 {level=2 check="14535/50"}
假设有 $s = 1$ 的齐普夫定律从顶部起精确成立，$f(r) = f(1)/r$，取 $f(1) = 14{,}535$（即《白鲸记》中 *the* 的频数）。预测排名第 $50$ 的词形的频率。结合[[#ex-zipf-fit]]看，这个预测偏高还是偏低？
::: solution
$f(50) = 14{,}535/50 = 290.7$。由于 *the* 相对于曲线其余部分异常地频繁（头部高于拟合线），以排名 $1$ 为锚、斜率 $-1$ 会低估中间排名——在排名 $100$ 处它预测 $145$，而观测值是 $281$——所以这个预测大概偏低。（排名 $50$ 的实际频率，词形 *what*，其实是 $565$。）
:::
:::

::: exercise 频率为三的词形 {level=2 check="1/12"}
在[[#prop-hapax]]的假设下，恰好出现三次的词形占多少？出现超过三次的占多少？
::: solution
$V_3/V = 1/(3\cdot4) = 1/12\approx0.083$。频率至少为 $4$ 的词形有 $C/4$ 个，占 $\tfrac14$；等价地，$1 - \tfrac12 - \tfrac16 - \tfrac1{12} = \tfrac14$。
:::
:::

::: exercise 语料库翻倍 {level=2 check="2^0.66"}
赫普斯定律 $V(n) = Kn^{0.66}$ 下，语料库翻倍时词表增大为多少倍？要让词表翻倍，语料库要扩大为多少倍？
::: solution
$V(2n)/V(n) = 2^{0.66} = 1.580$。要让词表翻倍，$\lambda^{0.66} = 2$，故 $\lambda = 2^{1/0.66} = 2^{1.515} = 2.86$：词形翻倍需要差不多三倍于原来的文本量。
:::
:::

::: exercise 三字节的码位 {level=2 check="61440"}
有多少个 Unicode 标量值在 UTF-8 中恰用三个字节编码？四个字节呢？
::: solution
三个字节覆盖 U+0800–U+FFFF，即 $2^{16} - 2^{11} = 65{,}536 - 2{,}048 = 63{,}488$ 个码位，其中 $2{,}048$ 个代理项不是标量值：$61{,}440$。四个字节覆盖 U+10000–U+10FFFF，$16\cdot65{,}536 = 1{,}048{,}576$ 个标量值。校验：$128 + 1{,}920 + 61{,}440 + 1{,}048{,}576 = 1{,}112{,}064$，即[[#def-codepoint]]中标量值的总数。
:::
:::

::: exercise 覆盖 $90\%$ {level=3 check="6176"}
在 $V = 17{,}368$ 个词形下精确的 $s = 1$ 齐普夫定律下，求使最靠前 $k$ 个词形至少覆盖 $90\%$ 词例的最小 $k$。先用[[#prop-coverage]]的近似，再用精确的调和数校验。
::: solution
需要 $H_k\ge0.9H_V$。用 $H_n\approx\ln n + \gamma$：$\ln k + \gamma\ge0.9(\ln V + \gamma)$，于是 $k\ge\exp\big(0.9(\ln17{,}368 + 0.5772) - 0.5772\big) = \exp(8.731) = 6{,}176$。精确计算，

```python
V = 17368
HV = sum(1 / r for r in range(1, V + 1))     # 10.3396
k, h = 0, 0.0
while h < 0.9 * HV:
    k += 1; h += 1 / k
print(k)                                       # 6176
```

得到同一个 $k = 6{,}176$。覆盖一半词例要 $100$ 个词形；覆盖 $90\%$ 要超过三分之一的词表。文本的最后 $10\%$ 摊在 $11{,}000$ 多个词形上。
:::
:::

::: exercise 一个 UTF-8 解码器 {level=3}
写一个函数 `utf8_decode(bs)`，接受一个 `bytes` 对象，返回码位的列表，遇到非法输入抛出 `ValueError`：不该出现的续字节、被截断的序列、过长编码、代理项、或超过 U+10FFFF 的值。用 `utf8_encode` 的输出以及非法输入 `b"\xc0\x80"`、`b"\xe4\xb8"` 和 `b"\xed\xa0\x80"` 测试它。
::: solution
```python
def utf8_decode(bs):
    out, i = [], 0
    while i < len(bs):
        b = bs[i]
        if b < 0x80:   n, cp, lo = 0, b, 0
        elif b >> 5 == 0b110:   n, cp, lo = 1, b & 0x1F, 0x80
        elif b >> 4 == 0b1110:  n, cp, lo = 2, b & 0x0F, 0x800
        elif b >> 3 == 0b11110: n, cp, lo = 3, b & 0x07, 0x10000
        else:
            raise ValueError(f"unexpected byte {b:02X} at {i}")
        for j in range(1, n + 1):
            if i + j >= len(bs) or bs[i + j] >> 6 != 0b10:
                raise ValueError("truncated sequence")
            cp = cp << 6 | bs[i + j] & 0x3F
        if cp < lo: raise ValueError("overlong encoding")
        if 0xD800 <= cp <= 0xDFFF: raise ValueError("surrogate")
        if cp > 0x10FFFF: raise ValueError("beyond U+10FFFF")
        out.append(cp); i += n + 1
    return out

print([hex(c) for c in utf8_decode("Aé€中😀".encode("utf-8"))])
for bad in (b"\xc0\x80", b"\xe4\xb8", b"\xed\xa0\x80"):
    try: utf8_decode(bad)
    except ValueError as e: print(bad, "->", e)
```

```text
['0x41', '0xe9', '0x20ac', '0x4e2d', '0x1f600']
b'\xc0\x80' -> overlong encoding
b'\xe4\xb8' -> truncated sequence
b'\xed\xa0\x80' -> surrogate
```

首字节给出长度以及该长度所能编码的最小值（`lo`）；每个续字节必须以 `10` 开头，贡献六个比特。三个非法输入分别是：过长的 NUL 编码、被砍短的三字节序列、以及代理项 U+D800 的编码。
:::

::: exercise 规范化与计数 {level=3}
某语料库等量混用 *café* 的两种规范等价写法（一种用 U+00E9，一种用 e + U+0301），还含有全角字符串 *ｃａｆé*。(a) 一个不做任何规范化的词计数器会看到几个词形？(b) NFC 之后呢？(c) NFKC 之后呢？(d) 就"在训练通用语言模型的分词器之前先施加 NFKC"给出一条赞成理由和一条反对理由。
::: solution
(a) 三个词形：码位序列不同。(b) 两个：NFC 合并 *café* 的两种写法（它们有相同的规范分解），但全角字母只是兼容变体。(c) 一个：NFKC 把 U+FF43 等映射为 ASCII 的 *c*、*a*、*f*，并把重音符合成。(d) 赞成：同一个词的统计量不再被拆散到不同编码上，词表更小，在不同系统上敲出的输入一视同仁。反对：NFKC 有损——上标、连字、全角形式和某些数学字母承载着语义或格式，模型此后既读不出也复现不了；这对代码、数学式和忠实抄录文本很重要。
:::
