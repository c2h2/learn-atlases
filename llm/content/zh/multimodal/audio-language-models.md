最简单的语音助手是一个**级联**（cascade）：识别器把用户的语音转成文本（[[multimodal/speech]]），语言模型写出回答，再由语音合成系统读出来。级联是可行的，而且每个组件都能单独改进，但它有两个与生俱来的限制。它丢掉了语音中除词以外的一切——说话的语气、迟疑、笑声、是谁在说、背景声音——因为组件之间只传递转写文本。而且它慢：每一级都在等上一级，系统在没有判定用户已经说完之前不能开始回答。人对话时，话轮之间只留约 $200$ ms 的间隙，还会彼此抢话，在对方话音未落时用“嗯嗯”表示赞同；一个需要一秒以上才能回应、说起来就听不见的级联，用起来像对讲机。

另一条路是让语言模型直接读、写音频。这要求以很低的速率把音频变成**离散词元**，就像文本被变成子词词元那样，从而使 Transformer 能用下一个词元预测为它们建模。本章解释在用的两类音频词元——对自监督语音特征聚类得到的**语义词元**，以及带**残差向量量化**（RVQ）的**神经音频编解码器**产生的**声学词元**（SoundStream, 2021；EnCodec, 2022）——并算出它们的比特率。接着描述在这些词元上训练的语言模型，从 AudioLM 的层级结构到音频输入的语言模型，最后以**全双工口语对话**收尾：Moshi (2024) 这样边听边说的模型，以及决定语音接口是否自然的那些延迟预算。

## 两类音频词元 {#sec-tokens}

以 16 位采样的 $24$ kHz 音频流携带 $384{,}000$ 比特每秒。在单个采样上建语言模型，将面对每秒 $24{,}000$ 个词元的序列；WaveNet 确实以那个速率建模过音频（[[multimodal/speech#sec-tts]]），但一次只能持续几秒。音频词元把这个流压缩两到三个数量级，而两个词元家族为不同的目的而压缩。

**语义词元**捕捉*说了什么*。HuBERT 或 w2v-BERT（[[multimodal/speech#sec-asr]]）这样的自监督语音编码器每 $20$ ms 产生一个特征向量；对这些特征跑 $k$-means，并把每个向量替换成最近质心的索引，就得到离散**单元**的序列，簇数通常从几百到一千。这些单元与音素强相关，并且大体丢弃了说话人身份和录音条件。它们适合为语言建模，但由它们重新合成的音频听起来像另一个千篇一律的说话人。

**声学词元**捕捉*听起来如何*。神经编解码器是一个以重建波形为目标训练的自编码器，瓶颈处有一个量化器；它的词元把音色、韵律与声学细节保留得足够好，可以解码出高质量音频，但单个词元几乎不携带语言结构。

### 向量量化 {#sec-vq}

::: definition 向量量化 {#def-vq}
**码本**是 $K$ 个向量 $\mathbf{c}_1, \dots, \mathbf{c}_K\in\R^{D}$ 的集合。**向量量化**把向量 $\mathbf{z}$ 替换为离它最近的码向量，

$$
q(\mathbf{z}) = \mathbf{c}_{k^\star},\qquad k^\star = \arg\min_k\lVert\mathbf{z} - \mathbf{c}_k\rVert^2,
$$

并发送索引 $k^\star$，它占 $\log_2K$ 比特。在学习到的自编码器中，量化器位于编码器与解码器之间；由于 $\arg\min$ 没有可用的梯度，训练使用**直通估计器**——前向传播时解码器收到的是 $q(\mathbf{z})$，而关于 $q(\mathbf{z})$ 的梯度原样复制到 $\mathbf{z}$ 上——并配一个**承诺损失** $\beta\lVert\mathbf{z} - \operatorname{sg}[q(\mathbf{z})]\rVert^2$，使编码器输出贴近各自的码（$\operatorname{sg}$ 表示停梯度）。码本则由损失 $\lVert\operatorname{sg}[\mathbf{z}] - q(\mathbf{z})\rVert^2$ 或赋给每个码的编码器输出的指数滑动平均来更新（van den Oord 等人, 2017）。
:::

同样的机制在 [[multimodal/image-generation#sec-ar]] 中产生离散图像词元。单个码本有一个硬限制：以每秒 $75$ 帧表示 $6$ kbps 的音频，每帧需要 $80$ 比特，即一个 $2^{80}$ 项的码本——无法存储也无法搜索。残差量化把这笔账分解成逐级的小量化。

::: definition 残差向量量化（RVQ） {#def-rvq}
带 $Q$ 个大小皆为 $K$ 的码本 $\mathcal{C}_1, \dots, \mathcal{C}_Q$ 的**残差向量量化**分阶段量化 $\mathbf{z}$：令 $\mathbf{r}_0 = \mathbf{z}$，并对 $j = 1, \dots, Q$，取 $\hat{\mathbf{c}}_j$ 为 $\mathcal{C}_j$ 中与 $\mathbf{r}_{j-1}$ 最近的向量，令 $\mathbf{r}_j = \mathbf{r}_{j-1} - \hat{\mathbf{c}}_j$。$\mathbf{z}$ 的码就是这 $Q$ 个索引组成的元组，重构为 $\hat{\mathbf{z}} = \sum_{j=1}^{Q}\hat{\mathbf{c}}_j$。每一级量化的都是前面各级漏掉的部分。
:::

::: proposition RVQ 的性质 {#prop-rvq}
(a) 用 $Q$ 个大小为 $K$ 的码本的 RVQ 每个向量用 $Q\log_2K$ 比特，只存 $QK$ 个码向量，却能表示多达 $K^Q$ 种不同的重构。(b) 重构误差为 $\lVert\mathbf{z} - \hat{\mathbf{z}}\rVert = \lVert\mathbf{r}_Q\rVert$。(c) 若每个码本都包含零向量，则残差范数不增：$\lVert\mathbf{r}_j\rVert\le\lVert\mathbf{r}_{j-1}\rVert$，因此去掉末尾的码本时重构会平缓地退化。
:::

::: proof
(a) $Q$ 个索引各占 $\log_2K$ 比特，码本共存放 $QK$ 个向量，而 $K^Q$ 个索引元组各给出一个和式。(b) 归纳可得 $\mathbf{r}_j = \mathbf{z} - \sum_{i\le j}\hat{\mathbf{c}}_i$，于是 $\mathbf{r}_Q = \mathbf{z} - \hat{\mathbf{z}}$。(c) $\hat{\mathbf{c}}_j$ 在 $\mathcal{C}_j$ 上最小化 $\lVert\mathbf{r}_{j-1} - \mathbf{c}\rVert$，而 $\mathcal{C}_j$ 含有 $\mathbf{0}$，故 $\lVert\mathbf{r}_j\rVert = \lVert\mathbf{r}_{j-1} - \hat{\mathbf{c}}_j\rVert\le\lVert\mathbf{r}_{j-1} - \mathbf{0}\rVert$。
:::

实践中码本是学出来的、未必含零向量，但训练会使每一级在平均意义上减小误差。下面这段代码对合成 $4$ 维数据的残差逐级跑 $k$-means，学习四个 $K = 8$ 的码本。

```python
import math, random
random.seed(5)
D, K, STAGES, N = 4, 8, 4, 2000              # 向量维数、码本大小、级数、数据点数

# 编码器输出的替身：相关的 4 维向量
centres = [[random.gauss(0, 2) for _ in range(D)] for _ in range(5)]
data = [[c + random.gauss(0, 0.7) for c in random.choice(centres)] for _ in range(N)]

sq = lambda a, b: sum((x - y) ** 2 for x, y in zip(a, b))
def nearest(v, book):
    return min(range(len(book)), key=lambda k: sq(v, book[k]))

def kmeans(points, k, iters=20):
    book = [p[:] for p in random.sample(points, k)]
    for _ in range(iters):
        groups = [[] for _ in range(k)]
        for p in points: groups[nearest(p, book)].append(p)
        book = [[sum(col) / len(g) for col in zip(*g)] if g else book[j] for j, g in enumerate(groups)]
    return book

energy = sum(sq(v, [0] * D) for v in data) / N
residual = [v[:] for v in data]
books = []
print(f"mean energy per vector {energy:.3f}")
for s in range(STAGES):                       # 残差向量量化，逐级进行
    book = kmeans(residual, K)
    books.append(book)
    residual = [[r - c for r, c in zip(v, book[nearest(v, book)])] for v in residual]
    mse = sum(sq(v, [0] * D) for v in residual) / N
    print(f"stages {s + 1}: {3 * (s + 1):2d} bits/vector  error {mse:.4f}  ({mse / energy:.2%} of energy)")

v = data[0]; codes = []; recon = [0.0] * D; r = v[:]
for book in books:                            # 对一个向量编码，再解码
    k = nearest(r, book); codes.append(k)
    recon = [a + b for a, b in zip(recon, book[k])]; r = [a - b for a, b in zip(r, book[k])]
print("vector", [round(x, 2) for x in v], "codes", codes, "decoded", [round(x, 2) for x in recon])

# 编解码器的比特率：每秒帧数 x 码本数 x 每个码的比特数
for name, fps, q, size in [("SoundStream/EnCodec 6 kbps", 75, 8, 1024),
                           ("EnCodec 1.5 kbps", 75, 2, 1024), ("Mimi (Moshi)", 12.5, 8, 2048)]:
    print(f"{name}: {fps} x {q} x {math.log2(size):.0f} bits = {fps * q * math.log2(size):.0f} bit/s")
```

```text

stages 1:  3 bits/vector  error 1.7521  (8.09% of energy)
stages 2:  6 bits/vector  error 0.8037  (3.71% of energy)
stages 3:  9 bits/vector  error 0.3716  (1.71% of energy)
stages 4: 12 bits/vector  error 0.1754  (0.81% of energy)
vector [-0.8, 1.34, -1.89, 0.03] codes [2, 7, 7, 0] decoded [-0.53, 1.2, -2.08, 0.25]
SoundStream/EnCodec 6 kbps: 75 x 8 x 10 bits = 6000 bit/s
EnCodec 1.5 kbps: 75 x 2 x 10 bits = 1500 bit/s
Mimi (Moshi): 12.5 x 8 x 11 bits = 1100 bit/s
```

第一级捕捉了聚类结构，去掉了 $92\%$ 的能量；其后每一级用多出的 $3$ 比特把剩余误差大约减半。信息论给出一个基准：对高斯数据，当码率每 $D$ 维向量增加 $R$ 比特时，可达到的最小均方误差变为 $2^{-2R/D}$ 倍（率失真函数；[[math-for-ml/information-theory]]），在这里相当于每 $3$ 比特一级乘 $0.35$。学出的各级达到的比例约为 $0.46$——贪心的逐级量化器并不最优，但它简单、可扩展。

## 神经音频编解码器 {#sec-codecs}

::: definition 神经音频编解码器 {#def-codec}
**神经音频编解码器**由三部分构成：**编码器**（卷积网络，有时也含 Transformer）以总步幅 $H$ 把采样率 $f_s$ 的波形变成速率 $f_r = f_s/H$ 的潜在帧；对每帧施加的、含 $Q$ 个大小为 $K$ 的码本的**残差量化器**；以及把量化帧映回波形的**解码器**。它以端到端方式训练，损失包括时域与频域的重建损失、判别音频真假的判别器的对抗损失，以及量化器的承诺损失和码本损失。它的**比特率**是

$$
\text{比特率} = f_r\cdot Q\cdot\log_2K\quad\text{比特每秒}.
$$ {#eq-bitrate}
:::

**SoundStream**（Zeghidour 等人，2021）开创了这一设计。在 $24$ kHz 下、各级步幅连乘为 $320$ 时，它每秒产生 $75$ 帧；码本大小为 $1024$ 时，每个码本增加 $750$ 比特每秒。为了让一个模型服务于多个比特率，它使用了**量化器丢弃**（quantiser dropout）：训练时随机跳过末尾若干个码本，于是解码器学会从码的任意前缀重建——[[#prop-rvq]] 恰好说明了这样做为何自然。听音测试中，$3$ kbps 的 SoundStream 被认为优于 $12$ kbps 的 Opus 编解码器。**EnCodec**（Défossez 等人，2022）采用同样的结构，但换了判别器并加入损失均衡方案；其 $24$ kHz 模型提供 $1.5$、$3$、$6$、$12$ 和 $24$ kbps，分别对应 $2$、$4$、$8$、$16$ 和 $32$ 个码本；它的词元被 VALL-E（[[multimodal/speech#sec-codec-tts]]）与许多后续模型采用。

::: example 编解码器的算术题 {#ex-codec}
计算 EnCodec 在 $6$ kbps 时相对于 $24$ kHz 16 位音频的压缩比；若语言模型把所有码本建模成一条扁平序列，它每秒必须生成多少个词元？
::: solution
未压缩音频是 $24{,}000\cdot16 = 384{,}000$ bit/s，故压缩比为 $384{,}000/6000 = 64$。$6$ kbps 时有 $8$ 个码本、帧率 $75$ Hz：每秒 $600$ 个词元。一分钟语音就是 $36{,}000$ 个词元——大约是同一分钟语音所需文本词元数（约 $150$ 词、约 $200$ 个词元）的 $40$ 倍。因此，更低的帧率和更少的码本，或者让模型只自回归预测部分码本的层级结构，都是必不可少的。
:::
:::

:::

**一个编解码器兼有语义与声学词元。** 由于编解码词元建模的是声音而非语言，在其上训练的语言模型学会句法和语义会很慢。于是有几个编解码器把*第一个*码本做成语义的：SpeechTokenizer（Zhang 等人，2024）把 HuBERT 特征蒸馏进第一级 RVQ；而 **Mimi**——Moshi 的编解码器（Défossez 等人，2024）——把一个自监督语音模型（WavLM）的特征蒸馏进第一级，其余各级承载声学细节。Mimi 在 Moshi 中以 $24$ kHz 运行，帧长 $80$ ms（$12.5$ Hz），$8$ 个 $2048$ 项码本，$1.1$ kbps。

::: warning 词元率不是比特率，编解码质量也不是语言质量
两个量很容易混淆。**比特率**度量码携带多少信息、重建可以好到什么程度；**词元率**（每秒帧数乘以模型必须预测的码本数）决定在其上建语言模型的序列长度与成本。增大码本会提高比特率而不提高词元率，但让每次预测变成在更多类别上的分类。而重建音频很好的编解码器，给出的词元仍可能难以建模：感知质量与语言结构是不同的目标，语义蒸馏正因这一点而被引入。
:::

## 在音频词元上建语言模型 {#sec-audio-lm}

**无文本的口语语言建模。** Lakhotia 等人 (2021) 在数千小时有声书的 HuBERT 单元上训练语言模型，并用单元到语音的声码器重新合成其输出（GSLM）：不用任何文本，它就能生成合理、像语音的接续，但连贯性有限，音色也千篇一律。

**AudioLM**（Borsos 等人，2023）把两类词元组合进三个 Transformer 的层级结构，每一级都以前一级的输出为条件：

1. 一个**语义**模型，建模 w2v-BERT 的 $k$-means 词元（每秒 $25$ 个，$1024$ 个簇），承载长期结构——词、句法、旋律；
2. 一个**粗声学**模型，建模前 $4$ 个 SoundStream 码本（每秒 $50$ 帧），以语义词元为条件，提供说话人身份与录音条件；
3. 一个**细声学**模型，建模其余 $8$ 个码本，补上细节。

给定某个说话人的几秒钟语音，AudioLM 能以一致的音色、合理（却未必有意义）的内容续写这段语音；对钢琴录音，它能按风格续写——这一切只从音频学到。这种层级是一个反复出现的模式：用自回归预测粗粒度、低速率的语义流，再用更便宜的模型补上声学细节。

::: example AudioLM 的序列长度 {#ex-audiolm}
对 $10$ 秒音频，AudioLM 的每一级各建模多少个词元？
::: solution
语义级：$25\cdot10 = 250$ 个词元。粗声学级：$50\cdot10\cdot4 = 2000$ 个词元。细声学级：$50\cdot10\cdot8 = 4000$ 个词元。需要长程连贯性的模型工作在最短的序列上；更长的声学序列以它为条件，可以在较短的窗口上建模。
:::
:::

**音频输入的语言模型。** 若只求理解而非生成，[[multimodal/vision-language-models#sec-llava]] 的 VLM 配方可以直接照搬：一个预训练语音编码器——常用 Whisper 的——产生连续特征，一个适配器沿时间做池化（例如降到每秒 $25$ 帧或更少），再把它们投影进语言模型的嵌入空间，然后把合并后的模型在转写、翻译、关于语音、声音与音乐的问答以及语音指令等任务上做指令微调。已发表的例子有 Qwen-Audio（Chu 等人，2023）与 SALMONN（Tang 等人，2024）。这类模型能听到转写文本会丢掉的语气与非语音声音，但回答仍是文本；要开口说话还需要一条输出通路——一个 TTS 环节，或音频词元。

## 实时口语对话 {#sec-dialogue}

口语对话系统既要决定*说什么*，也要决定*何时说*。**半双工**系统轮流发言：用语音活动检测判断用户的话轮是否结束（常取几百毫秒的静音阈值），然后才回应；它们在说话时要么忽略用户的声音，要么被打断时停下（“打断”）。**全双工**系统像人一样边听边说：用户说话时它能发出**附和语**（backchannel），能在长停顿出现之前就开始回答，并把重叠与打断当作对话的一部分来处理。

::: definition 响应延迟 {#def-latency}
口语对话系统的**响应延迟**是从用户的话音结束到系统的回答出声之间的时间。对级联而言，它等于话轮结束检测的延迟、识别器的收尾时间、语言模型的首词元时间加上生成第一个口语短语所需文本的时间、合成器产出第一个音频块的时间、以及传输与缓冲延迟之和。
:::

会话分析给出了目标。Stivers 等人 (2009) 研究了十种语言，发现一人问完到另一人答话之间最常见的间隙约为 $0$–$200$ ms，各语言之间只有细微差别；听者在对方还没说完时就开始筹划自己的回答。

::: example 级联的延迟预算 {#ex-latency}
一个级联等 $500$ ms 静音才判定话轮结束，用 $100$ ms 收尾转写，语言模型的首词元时间为 $300$ ms、生成速度为每秒 $50$ 词元，第一个口语短语需要 $15$ 个词元，合成第一个音频块用 $150$ ms，另有 $100$ ms 的网络与缓冲延迟。计算总延迟，并指出流式设计能省去哪些部分。
::: solution
$500 + 100 + 300 + 15\cdot20 + 150 + 100 = 1450$ ms。最大的一项是话轮结束的等待，它存在是因为半双工系统必须确信用户说完了；一个从内容与韵律预测话轮结束的模型可以砍掉它，而全双工模型根本没有独立的话轮结束环节。流式 ASR、在部分转写上投机地开始生成、以及流式 TTS 能把它级联的各阶段重叠起来，但每一级仍会贡献自己的首个输出延迟。OpenAI 报告其较早的语音管线——一个级联——平均延迟为 $2.8$ s 与 $5.4$ s，取决于所用的语言模型。
:::
:::

### Moshi：一个全双工的语音-文本模型 {#sec-moshi}

**Moshi**（Défossez 等人，2024，来自 Kyutai 实验室）是一个公开发表、开放权重的全双工模型，能详细展示这套设计。

::: definition 多流语音-文本建模（Moshi） {#def-moshi}
在每个 $80$ ms 的帧 $t$，Moshi 建模一个词元向量：一个属于它自己话语的**文本**词元、**它自己的**音频的 $Q = 8$ 个 Mimi 词元，以及**用户的**音频的 $8$ 个 Mimi 词元。一个大型**时间 Transformer**（由 $70$ 亿参数的文本语言模型 Helium 初始化）在这些向量的历史上每帧运行一次；随后一个小型**深度 Transformer** 以时间 Transformer 的输出为条件，把帧内的词元逐个预测出来（即 RQ-Transformer 分解）。文本词元——与 Moshi 自己的语音在时间上对齐的“内心独白”——先于帧内的音频词元被预测，而声学码本相对语义码本延迟一两帧。推理时，用户的词元不是预测出来的，而是随其到达从麦克风填入。
:::

由于用户的那一路始终出现在输入里，Moshi 说话时仍能听到用户，静音不过是一段和别处无异的词元序列：模型在每一帧自己决定是说话、沉默，还是发出一句附和语。内心独白的文本为它的语音提供了语言的脚手架，Défossez 等人发现这能提高它所说内容的连贯性。每 $80$ ms 的代价是大模型一步加深度模型的几小步；他们报告的理论延迟是 $160$ ms（一帧加声学延迟），单块 GPU 上实测约 $200$ ms。Moshi 先在约七百万小时音频上预训练，再在分离好的双人对话（包括 $2000$ 小时的电话通话 Fisher 语料库）和合成对话上训练。更早的 dGSLM（Nguyen 等人，2023）已经表明，在 Fisher 上训练的双通道单元语言模型无需文本就能生成带自然话轮切换与重叠的对话。

::: example Moshi 的词元预算 {#ex-moshi}
Moshi 每秒处理多少个词元？一场 $5$ 分钟的对话占多少帧？
::: solution
每帧在 $12.5$ 帧每秒下含 $1 + 8 + 8 = 17$ 个词元：每秒 $212.5$ 个词元。但昂贵的部分——时间 Transformer——每帧只运行一次，而 $5$ 分钟的对话是 $300\cdot12.5 = 3750$ 帧（所有流合计 $63{,}750$ 个词元）。深度 Transformer 只处理每帧内部的 $17$ 个词元。把时间与深度这样拆开，使大模型的序列保持在帧率的长度，远短于一条扁平的词元序列。
:::
:::

**商用系统。** 2024 年 5 月，OpenAI 把 GPT-4o 描述为一个在文本、视觉与音频上端到端训练的单模型，对音频的响应最快 $232$ ms、平均 $320$ ms；架构与数据未公布。Google 与其他开发者也发布了口语对话产品，若干开放模型（截至 2026 年）要么沿用 Moshi 式多流方案，要么采用“思考者-说话者”式分工：语言模型产出文本与隐状态，再由一个语音解码器以流式方式把它们变成音频词元。已发表的细节差异很大；关于延迟与自然度的说法，都应连同测量条件一起看。

::: quiz
为什么 Moshi 在每一帧都把用户的音频词元喂给模型，即使 Moshi 自己正在说话？
- [ ] 为了训练编解码器重建用户的嗓音
- [x] 为了让模型能对用户任何时刻的举动——打断、附和、重叠——作出反应，而不是等一个话轮结束
- [ ] 因为深度 Transformer 每帧恰好需要 $17$ 个词元
- [ ] 为了计算用户语音的词错误率
::: solution
全双工行为要求模型的输入始终反映两位说话人的当前状态。用户那一路每一帧都在输入里，话轮切换便是从数据里学来的，而不是由某个语音活动检测器强加的。
:::
:::

## 评测口语模型 {#sec-evaluation}

语音生成要同时在多个维度上评测：

- **可懂度**：把强识别器跑在生成语音上得到的词错误率（[[multimodal/speech#def-wer]]）。
- **自然度与质量**：听者评分（平均意见分 MOS 或对比测试），或学出来的 MOS 预测器；对编解码器，则用 ViSQOL、原始信号与重建之间的 mel 距离等客观指标。
- **说话人相似度**：做语音克隆时，提示音频与输出音频的说话人验证嵌入之间的余弦。
- **内容与推理**：问答基准的口语版本，以及同一模型被口语提问与被文本提问时的准确率差——语音模型常常相对其文本基座损失准确率。
- **对话动态**：与人类对话相比的延迟分布，以及打断、重叠、附和语的频率。

安全评测再添音频特有的问题：语音克隆与冒充（见 [[multimodal/speech#sec-codec-tts]] 中的应用短记），藏在音频里、而倾听的模型可能照做的指令——这是 [[prompting-rag/prompt-design]] 讨论过的提示注入的一种形态——以及嗓音的隐私问题：在许多司法管辖区，嗓音属于生物特征数据（[[llm-society/privacy-memorisation]]）。

::: history
用向量量化做语音编码可追溯到 1980 年代（码激励线性预测，Schroeder 与 Atal，1985）；残差（多级）VQ 由 Juang 与 Gray (1982) 研究过。神经声码器（WaveNet，2016）与 VQ-VAE（van den Oord 等人，2017）已经用离散潜变量为语音建模，为此铺平了道路。SoundStream（Zeghidour 等人，2021）与 EnCodec（Défossez 等人，2022）确立了带 RVQ 的端到端神经编解码器。在 HuBERT 单元上的生成式口语语言建模（Lakhotia 等人，2021）、AudioLM（Borsos 等人，2022，期刊版 2023）、VALL-E (2023) 与 dGSLM (2023) 表明，音频词元上的语言模型能够续写、合成与对话。音频输入的 LLM（2023–2024）沿用了 VLM 配方。GPT-4o（2024 年 5 月）把端到端语音对话带进了商用助手，Moshi（2024 年 9 月）则发表了开放权重的全双工语音-文本模型。
:::

::: summary
- 级联（ASR → LLM → TTS）丢掉副语言信息，并在每一级都增加延迟；音频词元让语言模型能直接读写语音。
- 语义词元（对自监督特征做 $k$-means）捕捉内容；声学词元（神经编解码器）捕捉声音并可解码为音频。
- RVQ 逐级量化残差：每帧 $Q\log_2K$ 比特，存 $QK$ 个向量，至多 $K^Q$ 种重构，丢掉后面的码本时平缓退化。
- 编解码器比特率 $=$ 帧率 $\times$ 码本数 $\times\log_2K$：SoundStream/EnCodec 为 $75\cdot8\cdot10 = 6$ kbps；Mimi 为 $12.5\cdot8\cdot11 = 1.1$ kbps。决定语言模型成本的是词元率，而非比特率。
- AudioLM 以层级结构建模语义、粗声学与细声学词元；音频输入的 LLM 经适配器接上语音编码器。
- Moshi 这样的全双工模型以 $80$ ms 为帧，同时建模用户与自己两路音频流（外加对齐的文本），由一个时间 Transformer 与一个深度 Transformer 承担；延迟目标来自人类的对话轮转节奏（约 $200$ ms）。
:::

## 习题

::: exercise 24 kbps 需要多少码本 {level=1 check="32"}
一个 $75$ Hz 的编解码器要达到 $24$ kbps，需要多少个 $1024$ 项的码本？
::: solution
$24{,}000/(75\cdot10) = 32$ 个码本，即 EnCodec 的最高档。
:::
:::

::: exercise Mimi 的比特率 {level=1 check="1100"}
计算 Mimi 以每秒 $12.5$ 帧、$8$ 个 $2048$ 项码本运行时的比特率。
::: solution
$12.5\cdot8\cdot\log_22048 = 12.5\cdot8\cdot11 = 1100$ bit/s。
:::
:::

::: exercise 编解码器的压缩倍数 {level=1 check="64"}
一个 $6$ kbps 的编解码器流比 $24$ kHz 16 位单声道音频小多少倍？
::: solution
$384{,}000/6000 = 64$。
:::
:::

::: exercise Moshi 每秒词元数 {level=1 check="212.5"}
Moshi 的三条流合起来每秒建模多少个词元？
::: solution
在 $12.5$ Hz 下每帧 $17$ 个词元：每秒 $212.5$ 个词元（[[#ex-moshi]]）。
:::
:::

::: exercise 未用满的码与有效比特率 {level=2 check="4800"}
一个编解码器以 $75$ Hz 运行、有 $8$ 个 $1024$ 项的码本，但每个码本实际只用 $256$ 项，且各等频出现。其词元的信息速率是多少比特每秒？
::: solution
每个词元在所使 $256$ 项上均匀分布，故携带 $\log_2256 = 8$ 比特而非 $10$ 比特；速率为 $75\cdot8\cdot8 = 4800$ bit/s。**码本利用率**低会浪费比特率，是训练 VQ 模型的常见故障；码本重置、EMA 更新和熵罚都被用来对付它。
:::
:::

::: exercise 话轮检测更快的级联 {level=2 check="1150"}
在 [[#ex-latency]] 中，一个话轮结束模型把静音等待从 $500$ ms 降到 $200$ ms。新的延迟是多少毫秒？
::: solution
$1450 - 300 = 1150$ ms。即便话轮检测很快，剩下的各阶段仍使级联的延迟远高于人类话轮之间的 $200$ ms。
:::
:::

::: exercise 扁平码本的大小 {level=2}
(a) 单个码本要多少项，才能抵得上 $8$ 个大小为 $1024$ 的 RVQ 码本的比特数？(b) RVQ 存多少个码向量？(c) 即便一个巨大的码本存得下，为什么也学不出来？
::: solution
(a) $8\cdot10 = 80$ 比特，即 $2^{80}\approx1.2\times10^{24}$ 项。(b) $8\cdot1024 = 8192$ 个向量。(c) 码本中的项只从被指派给它的那些编码器输出中学习；$10^{24}$ 项中的绝大多数在训练中永远不会被指派到，而在其中做最近邻搜索也不可行。RVQ 共享结构：$K^Q$ 种重构中的每一种，都是由在许多数据上都得到训练的向量相加而成。
:::
:::

::: exercise 直通梯度 {level=2}
在 [[#def-vq]] 中，设编码器输出为 $\mathbf{z}$，解码器损失为 $\mathcal{L}_{\text{rec}}(q(\mathbf{z}))$。写出 $\tilde{\mathbf{z}} = \mathbf{z} + \operatorname{sg}[q(\mathbf{z}) - \mathbf{z}]$ 的前向取值及其对 $\mathbf{z}$ 的梯度，并解释为什么需要承诺损失。
::: solution
前向传播时 $\tilde{\mathbf{z}} = \mathbf{z} + q(\mathbf{z}) - \mathbf{z} = q(\mathbf{z})$，解码器看到的就是量化后的向量。反向传播时停梯度项是常数，故 $\partial\tilde{\mathbf{z}}/\partial\mathbf{z} = I$ 且 $\partial\mathcal{L}_{\text{rec}}/\partial\mathbf{z} = \partial\mathcal{L}_{\text{rec}}/\partial\tilde{\mathbf{z}}$：解码器的梯度被原样复制给编码器，仿佛量化就是恒等映射。这只在 $\mathbf{z}$ 离 $q(\mathbf{z})$ 很近时才准确。若没有承诺项，就没有任何东西把编码器输出拉在码本附近：它们可以不断漂移、变大，而码本跟在后面追不上，直通近似与量化本身都会越来越糟。项 $\beta\lVert\mathbf{z} - \operatorname{sg}[q(\mathbf{z})]\rVert^2$ 把每个输出拉向它的码。
:::
:::

::: exercise 量化器丢弃 {level=3}
SoundStream 训练时使用量化器丢弃：对每个样例，从 $\{1, \dots, Q\}$ 均匀抽取一个数 $n_q$，只用前 $n_q$ 个码本。(a) 解释为什么这让一个模型能用于 $Q$ 个比特率。(b) 为什么这会让前面的码本携带最重要的信息？(c) 对 AudioLM 或 VALL-E 这样先自回归预测前面码本、再并行预测其余码本的语言模型，这一排序有何助益？
::: solution
(a) 解码器被训练成能从码的每个前缀重建，因此推理时只需传输前 $n_q$ 个索引，用同一个模型就能在比特率 $f_r\,n_q\log_2K$ 上解码。

(b) 第一个码本在每个训练样例中都被使用，最后一个只在 $1/Q$ 的样例中被使用；要对 $n_q$ 取期望的损失最小，前面的码本就必须抓住最能减小误差的东西——粗略的频谱包络与基频——把细节留给后面的码本。这正是 RVQ 天生具有（[[#prop-rvq]]）、又被训练强化的由粗到细的排序。

(c) 自回归部分是昂贵且依赖上下文的，它负责预测决定内容、音色与韵律的那些码本；其余码本承载的细节在很大程度上由同一帧内前面的码本决定，因而可以用更少的上下文、以并行方式预测，质量的损失也不大。
:::
:::

::: exercise 双工序列设计 {level=3}
一个团队把 Moshi 的各条流拉平成单一词元序列来构建全双工模型：每帧内按文本、自己的音频、用户的音频排序，并在其上训练一个标准解码器。(a) 一场 $5$ 分钟的对话对应的序列有多长？(b) 将其每帧的注意力开销与 Moshi 的时间/深度 Transformer 拆分作比较。(c) 推理时，如果模型要产生自己第 $t$ 帧的音频时，用户第 $t$ 帧的词元尚未到达，会发生什么？
::: solution
(a) $3750$ 帧 $\times$ $17$ 词元 $= 63{,}750$ 个词元。

(b) 扁平模型中，每帧 $17$ 个词元中的每一个都要注意整个历史，于是历史长度为 $17t$ 个词元时，每帧的注意力开销按 $17\cdot17t$ 增长，比在 $t$ 个帧向量上建模的模型大约 $17^2 = 289$ 倍；而且大模型每帧还要运行 $17$ 次。Moshi 的时间 Transformer 在 $t$ 个向量的历史上每帧运行一次，深度 Transformer 只在 $17$ 个位置上运行。

(c) 模型自己第 $t$ 帧的音频将以它并不拥有的用户词元为条件，因此排序必须把用户第 $t$ 帧的词元放在模型自己的之后，或者让模型第 $t$ 帧只以截至 $t - 1$ 的用户词元为条件。Moshi 的排序与延迟正是为了让每个预测只依赖已经听到的东西；扁平序列也必须遵守同样的因果性，否则无法实时运行。
:::
:::
