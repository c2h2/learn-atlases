前几章的模型都是用零件拼起来的。视觉-语言模型通过一个小型连接器，把一个单独预训练好的图像编码器接到一个单独预训练好的语言模型上（[[multimodal/vision-language-models]]）；一个语音助手可能把语音识别器、语言模型和语音合成器拼在一起（[[multimodal/audio-language-models]]）；文本到图像系统则以一个冻结文本编码器的输出为条件来驱动一个扩散模型（[[multimodal/image-generation]]）。这种**晚期融合**的做法复用了强大的组件、搭起来便宜，但每个组件在大部分训练中都只见得到自己的模态，信息只能通过狭窄的接口在它们之间穿过，而且系统通常能*读*好几种模态，却只能*写*其中一种。

**原生多模态**模型从一开始就在一个网络里同时训练多种模态。最纯粹的形式是**早期融合**：每种模态都被转换成共享词表中的词元，文本、图像、音频交错的文档变成单条词元序列，一个 Transformer 用下一词元预测在这一切上训练，从而能以任意顺序读取和生成任何模态。本章给出这一区分的精确定义，以公开发表的 Chameleon (2024) 为例，算清一个早期融合模型的词元账并逐条分析它的训练难点；然后考察那些为图像保留连续表示（Transfusion）、或为理解与生成各用一套编码器的变体；最后讨论能生成逼真人像与嗓音的模型所带来的数据、评测与安全问题。

## 晚期融合与早期融合 {#sec-fusion}

::: definition 晚期融合与早期融合 {#def-fusion}
若一个多模态模型中每种非文本模态都由自己的预训练编码器处理（输出时则用自己的解码器或生成器），只有编码器的输出经由连接器或交叉注意力进入语言模型，它使用的是**晚期融合**。若所有模态在输入端都由简单的分词器映射成一条词元或向量的序列，并由一个从一开始就在所有模态上训练的 Transformer 来处理、预测这条序列，它使用的是**早期融合**。
:::

这两个词描述的是一段谱系，而不是两个格子。一个把图像编码器解冻、联合训练了几万亿词元的 VLM 在向早期融合靠拢；一个早期融合模型则仍然依赖单独训练好的图像分词器。有用的问题是：跨模态交互从哪里开始（第一层，还是只在某个模态编码器之后）？模型能生成每种模态，还是只能读？各个组件是联合训练的，还是由独立训练的部分拼起来的？

早期融合能带来三样东西。模型的每一层都能把词与图像区域或声音联系起来——基于投影层的 VLM 也做得到，池化的对比嵌入却做不到。任何模态的输出都出自那个理解上下文的同一网络，于是模型在一次生成里就能写说明、画示意图，再回头引用它。而且模型可以在**交错文档**——网页、幻灯片、说明书、带视频帧的文字稿——上按它们的自然顺序训练。它的代价同样明白：模型要从头训练，花的是一门大语言模型的本钱；图像词元既多又有损；而且在相互竞争的模态上训练更不稳定。

## 用离散词元做早期融合 {#sec-early}

### 一个词表 {#sec-vocab}

**Chameleon**（Chameleon Team，Meta，2024）是一个有 $70$ 亿和 $340$ 亿参数的早期融合模型家族。它的图像分词器是一个 VQ 自编码器，即 [[multimodal/image-generation#sec-ar]] 那一类，把一张 $512\times512$ 的图像编码成 $32\times32 = 1024$ 个取自 $8192$ 项码本的离散码。它的文本分词器是一个 $65{,}536$ 项的 BPE 词表，其中已把 $8192$ 个图像码包含为词元。文档中的一张图像成为夹在图像开始与结束标记之间的一段 $1024$ 个词元的跨度；模型是一个仅解码器 Transformer，在文本跨度与图像跨度任意混合的序列上用通常的下一词元损失训练。它在若干万亿词元的文本、图文对与交错文档上预训练，然后在混合模态指令数据上微调。

下面这段代码构造了这样一个序列，展示了图像跨度内部的采样如何加约束，并构造了下文将要讨论的混合模型的注意力掩码。

```python
import math, random
random.seed(7)

# 两个模态共用一个词表：先是文本 id，再是图像码，最后是标记
N_TEXT, N_IMAGE = 65536 - 8192 - 2, 8192
IMG_START, IMG_END = N_TEXT, N_TEXT + 1
IMG0 = N_TEXT + 2                              # 图像码 k 的 id 为 IMG0 + k
V = IMG0 + N_IMAGE
print("vocabulary", V, " image share %.3f" % (N_IMAGE / V))

def image_span(codes):                         # 一张量化后的图像成为一个词元跨度
    return [IMG_START] + [IMG0 + c for c in codes] + [IMG_END]

doc = [101, 2009, 318] + image_span([random.randrange(N_IMAGE) for _ in range(4)]) + [464, 5000]
kind = ["T" if t < N_TEXT else "<" if t == IMG_START else ">" if t == IMG_END else "I" for t in doc]
print("sequence", doc[:6], "...", " kinds", "".join(kind))

# 模态受限采样：图像跨度内部只能接图像码
def constrained(logits, allowed):
    m = max(logits[i] for i in allowed)
    z = sum(math.exp(logits[i] - m) for i in allowed)
    return {i: round(math.exp(logits[i] - m) / z, 3) for i in allowed}

# 7 项玩具词表：id 0-2 文本，3 = <img>，4 = </img>，5-6 图像码
toy = [2.0, 1.0, 0.5, -1.0, 0.0, 1.5, 0.3]
Z = sum(math.exp(y) for y in toy)
print("unconstrained", [round(math.exp(x) / Z, 3) for x in toy])
print("inside image ", constrained(toy, [5, 6]))
print("in text      ", constrained(toy, [0, 1, 2, 3]))

# Transfusion 式掩码：整体因果，每张图像内部双向
kinds = "TTT" + "IIII" + "TT"
img_id, cur = [], 0
for i, k in enumerate(kinds):
    if k == "I" and (i == 0 or kinds[i - 1] != "I"): cur += 1
    img_id.append(cur if k == "I" else 0)
mask = [[1 if j <= i or (img_id[i] and img_id[i] == img_id[j]) else 0 for j in range(len(kinds))]
        for i in range(len(kinds))]
for i, row in enumerate(mask):
    print(kinds[i], "".join("x" if a else "." for a in row))
print("allowed pairs", sum(map(sum, mask)), "of", len(kinds) ** 2)
```

unconstrained [0.39, 0.143, 0.087, 0.019, 0.053, 0.236, 0.071]

::: example 一份交错文档的词元预算 {#ex-budget}
一篇操作指南有 $600$ 个文本词元和三张图像，每张编码成 $1024$ 个码，外加开始与结束标记。序列有多长？文本占多大比例？与一个用投影层、每张图像读 $576$ 个视觉词元的 VLM 相比又如何？
::: solution
图像占 $3\cdot(1024 + 2) = 3078$ 个词元，序列共 $3678$ 个；文本占 $600/3678 = 16\%$。一个 $336$ 像素的投影层 VLM 会用 $3\cdot576 + 600 = 2328$ 个位置——但它只能读图像，不能生成图像。早期融合为对称性付出的代价是更长的序列：模型每读或写一张图像，就占去一篇短文章那么多的上下文。
:::
:::

### 在正确的模态里生成 {#sec-constrained}

对合并后的词表只做一个 softmax，意味着在图像开始标记之后，模型原则上可能在图像中间吐出一个文本词元，或在句子中间吐出一个图像码。训练好的模型在这些地方放的概率很小，但推理代码通常仍会强制执行这一结构。

::: proposition 模态受限解码 {#prop-constrained}
设 $p(\cdot\mid\mathbf{x}_{<t})$ 是模型在词表 $\mathcal{V}$ 上的下一词元分布，$\mathcal{A}\subset\mathcal{V}$ 是位置 $t$ 上允许的词元集合（例如图像跨度内的图像码）。在 softmax 之前把 $\mathcal{A}$ 之外词元的 logit 置为 $-\infty$，得到

$$
\tilde p(v\mid\mathbf{x}_{<t}) = \frac{p(v\mid\mathbf{x}_{<t})}{\sum_{u\in\mathcal{A}}p(u\mid\mathbf{x}_{<t})}\quad(v\in\mathcal{A}),
$$

这正是模型以“下一词元落在 $\mathcal{A}$ 中”为条件后的分布。
:::

::: proof
设 logit 为 $z_v$，则 $p(v) = e^{z_v}/\sum_{u\in\mathcal{V}}e^{z_u}$。加掩码后，对 $v\in\mathcal{A}$ 有 $\tilde p(v) = e^{z_v}/\sum_{u\in\mathcal{A}}e^{z_u}$；分子分母同除以 $\sum_{u\in\mathcal{V}}e^{z_u}$，得 $p(v)/\sum_{u\in\mathcal{A}}p(u) = p(v\mid v\in\mathcal{A})$，由条件概率的定义即得。
:::

::: example 在图像跨度内重新归一化 {#ex-constrained}
在上面代码的玩具词表中，两个图像码的无约束概率为 $0.236$ 与 $0.071$。若采样限制在图像码上，它们的概率是多少？模型把多少概率放在了非法词元上？
::: solution
$0.236/(0.236 + 0.071) = 0.769$ 与 $0.071/0.307 = 0.231$，与打印结果一致。在这个只有图像码合法的位置上，模型把 $1 - 0.307 = 0.693$ 的概率放在了文本词元与标记上——这是一个训练得很糟的玩具；在训练好的模型里这一泄漏很小，但绝不会恰好为零，而加约束能把泄漏去掉，又不改变合法词元之间的相对概率。
:::
:::

同一套结构也固定了图像跨度的长度：$1024$ 个码之后强制出现结束标记。引导（guidance，[[multimodal/image-generation#def-cfg]]）也能搬到词元模型上：把一次带提示的前向传播的 logit 与一次不带提示的合并起来，Chameleon 式及其他自回归图像生成器就用它来提高对提示词的遵循。

### 训练稳定性 {#sec-stability}

从头在混合模态上训练比只训练文本更难。Chameleon 报告描述了训练后期出现的损失发散，并将其归因于激活与 logit 的范数不断向上漂移，而一个 softmax 被熵差别极大的模态共用会雪上加霜：图像码远比文本词元难预测，模型可以靠把 logit 吹大来压低简单词元上的损失。报告给出的补救正是大规模训练的标准工具（[[pretraining/training-stability]]）：在注意力乘积之前对查询与键做归一化（**QK-norm**）、dropout、调整归一化层的位置，以及对 softmax 归一化因子施加的 **z 损失**。

::: definition z 损失 {#def-zloss}
对 logit $\mathbf{z}$ 及其归一化因子 $Z = \sum_ve^{z_v}$，**z 损失**在每个词元的损失上加上 $\lambda_z(\log Z)^2$，系数取小值（PaLM 用 $\lambda_z = 10^{-4}$）。
:::

::: proposition z 损失的梯度 {#prop-zloss}
$\dfrac{\partial}{\partial z_v}\lambda_z(\log Z)^2 = 2\lambda_z\log Z\cdot p_v$，其中 $p_v = e^{z_v}/Z$。当 $\log Z > 0$ 时，z 损失按其概率成比例地压低每一个 logit，把归一化因子拉向 $1$。
:::

::: proof
$\partial\log Z/\partial z_v = e^{z_v}/Z = p_v$，链式法则给出 $2\lambda_z\log Z\,p_v$。给所有 logit 同减一个常数不改变 softmax，只把 $\log Z$ 减小该常数；z 损失的梯度并不严格均匀（它按 $p_v$ 加权），但它的主要作用是把 $\log Z$ 驱向 $0$，从而防止 logit 漂移到幅度过大、低精度运算与 softmax 都不稳定的地方。
:::

::: example 一步 z 损失 {#ex-zloss}
logit $(2, 0, -1)$ 给出 $\log Z = 2.170$、概率 $(0.844, 0.114, 0.042)$。取 $\lambda_z = 10^{-4}$，计算 z 损失及其梯度。
::: solution
损失为 $10^{-4}\cdot2.170^2 = 4.71\times10^{-4}$。梯度为 $2\cdot10^{-4}\cdot2.170\cdot(0.844, 0.114, 0.042) = (3.66, 0.50, 0.18)\times10^{-4}$。与交叉熵梯度（量级为 $1$）相比它微乎其微，几乎不影响预测；但它每一步作用在每一个词元上，能在漫长的训练中看住归一化因子。
:::
:::

### 平衡各个模态 {#sec-balance}

损失按词元平均时，每个模态在训练中的权重就是它的词元占比。图像是贪吃词元的，所以一个按*文档*平衡的语料，按词元衡量可能被图像占据。

::: proposition 混合模态损失作为加权平均 {#prop-mix}
设一个批量含模态 $m$ 的 $n_m$ 个词元，其平均损失为 $\bar\ell_m$，$N = \sum_mn_m$。按词元平均的损失为 $\bar\ell = \sum_m\frac{n_m}{N}\bar\ell_m$，其梯度就是各模态平均梯度的相应混合。取选定权重 $\lambda_m$ 的损失 $\sum_m\lambda_m\bar\ell_m$，能让一个模态的影响力与它的词元数脱钩。
:::

::: proof
$\bar\ell = \frac1N\sum_{\text{tokens}}\ell = \frac1N\sum_mn_m\bar\ell_m$，而求导是线性的。
:::

::: example 谁占据了损失？ {#ex-mix}
一个批量含 [[#ex-budget]] 中的 $600$ 个文本词元与 $3072$ 个图像码（忽略标记）。平均损失为每个文本词元 $2.0$ nat、每个图像码 $5.0$ nat。计算按词元平均的损失，以及文本贡献的损失份额。
::: solution
$\bar\ell = (600\cdot2.0 + 3072\cdot5.0)/3672 = 16{,}560/3672 = 4.51$。文本贡献 $1200/16{,}560 = 7\%$。图像码既多又难预测，因此不加权的损失把大部分梯度花在了它们身上；按文档选择的数据混合会让模型的语言能力吃不饱。正因如此，数据配比（[[pretraining/data-mixtures]]）与各模态的权重都要调优。
:::
:::

::: widget plot
f: n/(n + x*k)
x: 0, 10
y: 0, 1
sliders: n=600:50:4000:50; k=1024:64:4096:64
labels: text share of the sequence
caption: 一份含 $n$ 个文本词元与 $x$ 张每张 $k$ 个词元的图像的文档里，文本词元占的比例。图像为 $1024$ 个词元时，一张图像就比得上一篇典型页面的文字。按词元平均的损失下，这个份额决定了各模态的权重（[[#prop-mix]]），序列长度则决定了算力；原生分辨率或高分辨率图像（$k$ 达数千）会让这两种效应都更强。
:::

Aghajanyan 等人 (2023) 对在模态对（文本、图像、语音、代码、分子等）上训练的生成模型拟合了缩放定律，既发现了**竞争**——小规模下加入第二个模态会损害第一个模态的表现——也发现了**协同**，它随模型变大而出现；转折点取决于模态对。这是一条经验规律，与其他缩放定律（[[scaling/scaling-laws]]）一样；它也说明了早期融合为何要到大规模才变得可行。

## 混合设计 {#sec-hybrid}

离散图像词元是一个瓶颈。$16\times$ 下采样的 VQ 分词器重建照片不错，却会丢精细的文字与细小的人脸——Chameleon 报告就提到对含大量文字的图像感到吃力——而对 $1024$ 个码做下一词元预测，与几十步扩散相比非常慢。已有几个公开发表的设计保留了单个 Transformer，但对图像与文本区别对待。

::: definition Transfusion {#def-transfusion}
**Transfusion** 模型（Zhou 等人, 2024）是这样的一个 Transformer：序列中的文本是离散词元，每张图像是一列连续潜图块（来自 VAE，[[multimodal/image-generation#def-ldm]]），训练时被加噪到随机的扩散步。它的损失是文本词元上的语言建模损失加上图像图块上加权的扩散损失，

$$
\mathcal{L} = \mathcal{L}_{\text{LM}} + \lambda\,\mathcal{L}_{\text{diffusion}},
$$

其注意力掩码**对整个序列因果、但在每张图像内部双向**，于是一张图像的每个图块都能注意同一张图像的每个图块，而文本仍保持自回归。推理时文本逐词元生成；模型一旦发出图像开始标记，就用同一个 Transformer 在图像的位置上运行扩散采样器生成图像，然后继续生成文本。
:::

上面的代码为三个文本词元、一张四图块图像、两个文本词元的序列打印了这样一个掩码：$45$ 个因果对加上图像内部的 $6$ 个额外对，共 $51$ 对、占 $81$ 对。Zhou 等人报告，在同等算力下，Transfusion 生成图像的质量明显好于使用离散图像词元的 Chameleon 式模型，文本表现则与之持平。相关设计有：文本自回归、图像用掩码离散扩散的 Show-o（Xie 等人, 2024）；把视觉通路分开的 Janus（Wu 等人, 2024）——读图用语义编码器（SigLIP 特征，利于理解），写图用 VQ 词元（利于生成），两者共享一个 Transformer。Emu3（Wang 等人, 2024）反其道而行，主张对离散图像与视频词元做朴素的下一词元预测在大规模下就够用。截至 2026 年，这些问题都还没有定论；图像表示的选择——离散还是连续、语义还是重构、一种表示还是两种——是统一模型分野的主轴。

::: example 视频即词元 {#ex-video}
一段一分钟的视频以每秒 $2$ 帧采样，每帧被编码成 $256$ 个词元。它一共有多少个词元？若一个分词器还能把时间上 $4$ 帧压成一个潜帧，又能省下什么？
::: solution
$60\cdot2\cdot256 = 30{,}720$ 个词元每分钟——以低帧率视频的一分钟而言，相当于中等长度的文本上下文。一个把 $4$ 帧映射成一帧 $256$ 词元潜帧的时空分词器得到 $7680$ 个词元，代价是快速运动变得模糊。视频生成与视频阅读模型都依赖这种时间压缩，而对长视频仍然靠抽帧处理。
:::
:::

## 任意到任意的模型 {#sec-any}

把早期融合推广到图像之外，无非再添几个分词器：语音用第一本码带语义的编解码器（[[multimodal/audio-language-models#sec-codecs]]），音乐用声学编解码器，视频用时空分词器，甚至把机器人动作或边界框当作离散化的数。公开发表的例子包括：Unified-IO 2（Lu 等人, 2024），在图像、文本、音频与动作上从头训练；AnyGPT（Zhan 等人, 2024），给语言模型加上语音、图像与音乐的分词器，在合成的多模态对话上训练；以及语音-文本模型 Moshi（[[multimodal/audio-language-models#sec-moshi]]），它在两个模态上就是原生多模态的。

若干商用系统被其开发者描述为原生多模态。Gemini 1.0 报告（2023 年 12 月）描述从一开始就在文本、图像、音频与视频上联合训练的模型，能接受交错的输入，并能通过离散图像词元生成图像。OpenAI 把 GPT-4o（2024 年 5 月）描述为一个在文本、视觉与音频上端到端训练的单模型，并于 2025 年引入了由同一模型生成图像。两份报告都几乎没有给出架构细节；关于这些系统如何工作，凡开发者未发表的说法都应谨慎对待。

::: warning “原生”不等于“没有组件”，也不等于“样样更好”
早期融合模型仍然依赖单独训练的分词器，而分词器的损失为下游一切的质量设了上限；产品说明里的“原生多模态”，可能指从共享词元上的单个 Transformer，到联合微调的编码器与解码器拼装，无所不包。早期融合也并非处处更优：固定算力下，复用强大的预训练语言模型与视觉编码器的晚期融合模型，在理解基准上可以追平甚至胜过早期融合模型；而模态竞争（[[#sec-balance]]）可能牺牲文本表现。请在同等的算力与数据下比较设计，并去读实际发表的内容。
:::

::: quiz
与 LLaVA 这样基于投影层的 VLM 相比，Chameleon 这样早期融合模型的区分性特征是？
- [ ] 只有早期融合模型使用 Transformer。
- [x] 早期融合模型把图像表示成与文本同一词表中的词元，并用同一个下一词元目标生成它们；VLM 能读图像但只输出文本。
- [ ] VLM 不能处理一张以上的图像。
- [ ] 早期融合模型不需要图像分词器。
::: solution
两者都用 Transformer，VLM 也能读多张图像。区别在于早期融合模型的图像是与文本同一个 softmax 预测出的离散词元，这才使图像生成与任意交错成为可能，代价是有损的分词器和很长的序列。
:::
:::

## 原生多模态的数据 {#sec-data}

早期融合模型需要各模态按自然顺序共同出现的数据。主要有三类：

- **成对数据**——图像-说明文字对（如 [[multimodal/contrastive-learning#sec-data]]）、语音-转写对、视频-描述对——教会模型对应关系，却几乎不含语言。
- **交错文档**——图像原位排布的网页。MMC4（Zhu 等人, 2023）通过把图像与句子对齐，把 $5.71$ 亿张图像插进 $1.01$ 亿篇文本文档；OBELICS（Laurençon 等人, 2023）抽取了 $1.41$ 亿个网页，含 $3.53$ 亿张图像与 $1150$ 亿文本词元，保持原始版式；MINT-1T（Awadalla 等人, 2024）达到一万亿文本词元与 $34$ 亿张图像，包括 PDF。交错数据教会模型把图像当作叙述的一部分，并在一个上下文里处理多张图像。
- **合成与指令数据**——生成的说明文字、渲染的文字与图表、混合模态对话——补上网络上很少显式出现的技能，也带来继承生成者错误的常见风险（[[multimodal/vision-language-models#sec-training]]）。

出处、同意与过滤的问题，与文本及图文数据面临的相同，还多出人脸、嗓音与儿童图像的问题；2023 年的 LAION 事件（[[multimodal/contrastive-learning#sec-data]]）表明，公开数据集里可能藏着过滤器漏掉的违法内容。

## 评测与安全 {#sec-safety}

评测一个能读写多种模态的模型，要把前几章的评测合在一起——理解的 VLM 基准，图像的 FID、提示对齐与人类偏好，语音的 WER、自然度与说话人相似度——再加上没有自动指标的混合模态任务，比如制作一份带插图的食谱。Chameleon 报告就依赖人工评审，把混合模态的回答与其他系统的对比；这类评测的结果高度依赖题目集与评审规程。截至 2026 年，混合模态生成还没有公认的基准。

安全问题随每一个输出模态增长：

- **合成媒体。** 逼真的图像、视频与克隆的嗓音使冒充、诈骗、未经同意的影像与伪造证据成为可能。对策包括：拒绝关于真实人物的提示、过滤输出、给生成内容打**水印**（例如 Google DeepMind 面向图像、音频与文本的 SynthID），并按 C2PA 标准附上签名的**出处元数据**。水印会被编辑削弱，元数据会被剥除；对未标记合成媒体的检测并不可靠。这些机制及其极限在 [[llm-society/copyright-provenance#sec-watermark]] 与 [[llm-society/copyright-provenance#sec-c2pa]] 中分析，社会影响见 [[llm-society/misinformation]]。
- **藏在其他模态里的指令。** 会读图中文字（[[multimodal/contrastive-learning#sec-limits]]）、听话音的模型，可能照第三方提供的图像、文档或音频片段里嵌入的指令行事——这是提示注入的多模态形态，对依据屏幕截图行动的智能体（[[agents]]）尤其要紧。
- **跨模态的安全训练。** 主要在文本上做的拒绝与偏好训练，未必能完全迁移到以图像或语音提出的同一请求；红队测试与安全数据必须覆盖每个输入与输出模态（[[safety-alignment]]）。
- **隐私。** 图像与嗓音能认出人；识别面孔或嗓音的模型、复述记忆中的训练图像的模型（[[multimodal/image-generation#warn-memorise]]），带来超出文本的隐私问题（[[llm-society/privacy-memorisation]]）。

::: application 选择架构
一个需要在有限预算下做文档与屏幕截图理解、输出文本的团队，通常会基于强大的开放语言模型与视觉编码器搭建一个晚期融合 VLM。一个需要交错生成——带插图的回答、对话中的图像编辑、实时语音——的团队，则需要一个能生成另一种模态的模型：大规模训练的早期融合或混合模型，或外挂一个生成器的晚期融合系统。这一取舍正是本课程一路跟到底的那条：复用强组件，与组件之间接缝的代价。
:::

::: history
早期的多模态 Transformer 是在文本词元与图像区域上编码的编码器（ViLBERT、LXMERT，2019）。CM3（Aghajanyan 等人, 2022）在带 VQ 图像词元的 HTML 文档上训练了因果掩码模型；CM3leon（Yu 等人, 2023）把它扩展到文本到图像与图像到文本生成，并加上指令微调。Aghajanyan 等人 (2023) 度量了模态之间的竞争与协同。Gemini 1.0 报告（2023 年 12 月）描述了一个联合训练的多模态模型家族；Unified-IO 2（2023 年底，CVPR 2024）、AnyGPT 与 Chameleon（均为 2024）发表了早期融合模型；GPT-4o（2024 年 5 月）把端到端语音对话带进了助手；Transfusion、Show-o、Janus 与 Emu3（均为 2024）探索了混合与纯自回归的统一模型；2025 年，若干助手加入了由对话的同一模型生成图像。
:::

::: summary
- 晚期融合把预训练的模态编码器（及生成器）接到语言模型上；早期融合把所有模态编成词元放进一条序列，从一开始就训练一个 Transformer 处理一切。真实系统介于两者之间。
- Chameleon 把一张 $512^2$ 的图像编码成 $1024$ 个码（取自 $8192$ 项码本），置于 $65{,}536$ 项的词表之内；图像使序列很长，并在按词元平均的损失中占大头（权重 $n_m/N$），因此必须选定模态权重与配比。
- 把 logit 掩码到允许的模态，就是以该事件为条件取模型的条件分布；图像跨度定长，引导可以搬到词元模型上。
- 混合模态训练更不稳定；常用手段有 QK-norm、dropout、调整归一化层的位置，以及 z 损失 $\lambda_z(\log Z)^2$（梯度 $2\lambda_z\log Z\,p_v$）。
- 混合设计或者让图像保持连续（Transfusion：语言建模损失加扩散损失，因果掩码、图像内部双向注意力），或者分开理解与生成的通路（Janus）。
- 交错的网页数据（MMC4、OBELICS、MINT-1T）教授混合模态上下文；混合模态生成的评测至今主要靠人工。
- 合成媒体、跨模态提示注入、安全训练的迁移与隐私是主要的安全问题；水印与 C2PA 出处标准能帮上忙，但单独都不够鲁棒。
:::

## 习题

::: exercise 图像词元数 {level=1 check="1024"}
一个分词器对一张 $512\times512$ 的图像在每个维度上 $16$ 倍下采样。这张图像变成多少个词元？
::: solution
$(512/16)^2 = 32^2 = 1024$。
:::
:::

::: exercise 一条交错序列 {level=1 check="5930"}
一份文档有 $800$ 个文本词元和 $5$ 张图像，每张 $1024$ 个码，另加一个开始与一个结束标记。这条序列有多少个词元？
::: solution
$5\cdot1026 + 800 = 5130 + 800 = 5930$。
:::
:::

::: exercise 词表中的图像码 {level=1 check="0.125"}
$8192$ 个图像码占 $65{,}536$ 项词表的多大比例？
::: solution
$8192/65{,}536 = 1/8 = 0.125$。
:::
:::

::: exercise 视频词元 {level=1 check="30720"}
一段 $60$ 秒的视频，每秒 $2$ 帧、每帧 $256$ 个词元，一共多少个词元？
::: solution
$60\cdot2\cdot256 = 30{,}720$（[[#ex-video]]）。
:::
:::

::: exercise 受限概率 {level=2 check="0.6"}
在图像跨度内的某个位置，模型给图像码 $a$ 概率 $0.3$、图像码 $b$ 概率 $0.2$、给文本词元共 $0.5$；没有其他概率非零的图像码。模态受限解码下 $a$ 的概率是多少？
::: solution
由 [[#prop-constrained]]，$0.3/(0.3 + 0.2) = 0.6$。
:::
:::

::: exercise 加权的混合模态损失 {level=2 check="3.5"}
对 [[#ex-mix]] 的批量（文本平均损失 $2.0$，图像平均损失 $5.0$），团队改用 $\mathcal{L} = \frac12\bar\ell_{\text{text}} + \frac12\bar\ell_{\text{image}}$。损失是多少（填入的答案）？其中文本贡献的份额现在是多少？
::: solution
$\frac12(2.0) + \frac12(5.0) = 3.5$；文本贡献 $1.0/3.5 = 29\%$ 而不是 $7\%$。文本词元上的梯度相对于按词元平均的情形也相应变大。
:::
:::

::: exercise 数一数混合掩码 {level=2 check="31"}
一个序列有 $2$ 个文本词元、一张 $3$ 图块的图像、再 $2$ 个文本词元。在 Transfusion 掩码（因果，加图像内部双向）下，允许多少个（查询、键）对？
::: solution
$7$ 个位置上的因果掩码允许 $7\cdot8/2 = 28$ 对。图像内部，每个图块还可以注意同一图像中位于它之后的图块：多出 $\binom32 = 3$ 对。共 $31$ 对。
:::
:::

::: exercise logit 漂移中的 z 损失 {level=2}
设训练中某个模型的所有 logit 都同向上漂同样的量 $c$。(a) 证明交叉熵损失不变。(b) 证明 z 损失增大，并求它对 $c$ 的导数。(c) 为什么即使预测不变，这样的漂移也可能有害？
::: solution
(a) 给每个 logit 加 $c$，softmax 的分子分母同乘 $e^c$，概率与交叉熵都不变。(b) $\log Z$ 变为 $\log Z + c$，z 损失为 $\lambda_z(\log Z + c)^2$，对 $c$ 的导数为 $2\lambda_z(\log Z + c)$，只要 $\log Z + c > 0$ 就为正：z 损失把漂移推回去。(c) 交叉熵对漂移视而不见，主损失里没有任何东西阻止它；大 logit 在 16 位运算中损失精度，让 softmax 饱和，使小的 logit 误差引起大的概率变化，而且与大规模训练中报告的发散相关联。
:::
:::

::: exercise 晚期还是早期融合？ {level=3}
就下列每条需求，论证带文本输出的晚期融合 VLM、带离散图像词元的早期融合模型、或 Transfusion 这样的混合模型哪个是更好的起点，并指出主要风险：(a) 回答扫描版发票上的问题；(b) 撰写一份带生成示意图的分步图文教程；(c) 按一条指令编辑用户的照片，同时保留照片中人物的脸。
::: solution
(a) 晚期融合：任务只需要高分辨率读取与文本输出，一个强大的预训练视觉编码器配上切块或原生分辨率就能读小字；而早期融合模型的 $16\times$ VQ 词元会丢掉精细文字。风险：文字低于词元分辨率时，出现被幻觉出来的数字（[[multimodal/vision-language-models#sec-hallucination]]）。

(b) 早期融合或混合：模型必须生成与文本互相指涉、彼此交错的图像，纯文本输出的 VLM 做不到；一个能看见自己先前文本与图像的单模型能保持一致性。风险：离散分词器把示意图内部的文字渲染得很糟；用连续潜向量的混合可能更好，代价是更复杂的训练目标。

(c) 混合模型或专门的图像编辑模型：保持身份需要高保真地重建输入，连续潜向量（扩散）胜过有损的离散分词器；编辑必须以指令为条件，统一模型天然如此。风险：脸部的细微改变（身份漂移），以及利用它操纵真人影像的滥用，这要求打出处标记（[[#sec-safety]]）。
:::
:::

::: exercise 模态之间的竞争 {level=3}
一个团队训练两个规模与算力相同的模型：一个只在文本上训练，一个在文本与图像码各占一半（按词元）的混合数据上训练。在一个文本基准上，混合模型更差。(a) 给出两个与 [[#prop-mix]] 及 Aghajanyan 等人发现相符的解释。(b) 提出两个能区分它们的实验。
::: solution
(a) 其一是**数据稀释**：混合模型看到的文本词元只有一半，它在文本上本来就训练得少——同等算力下，它的文本损失相当于一个只用一半数据训练的纯文本模型。其二是**容量竞争**：两种模态争用同一批参数，即使文本词元数相同，混合模型在这个规模上也会更差；Aghajanyan 等人发现某些模态对在小规模下竞争、大规模下协同。

(b) 先训练一个纯文本模型，只给它混合模型实际看到的那些文本词元（一半算力）：若它与混合模型在文本上打平，稀释即可解释差距。再在若干个规模上训练文本词元数相同的混合与纯文本模型：若差距随规模缩小或反转，解释就是容量竞争，且协同可能在更大规模出现。改变配比或各模态的损失权重，可以检验结果对平衡有多敏感。
:::
:::
