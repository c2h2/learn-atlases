Quantisation ([[inference/quantisation]]) keeps every weight and stores it in fewer bits. The other routes to a cheaper model change *which* computations happen. **Distillation** trains a smaller model to imitate a larger one. **Pruning** removes weights, neurons, heads or whole layers. **Early exit** stops the computation for a token as soon as an intermediate layer is confident enough. This chapter covers them from the inference side: what each saves in bytes and FLOPs on real hardware, which methods can be applied after training with only a little calibration data, and which need retraining.

The training side of distillation — the loss functions, what the student learns from the teacher's distribution, distilling reasoning traces — is the subject of [[post-training/distillation]]; here it appears mainly as the step that repairs a pruned model. Most of the chapter is about pruning, because it is where the gap between "fewer parameters" and "faster inference" is widest: a model with half its weights set to zero is, on a GPU, usually no faster at all, unless the zeros follow a pattern the hardware understands.

## Distillation in one paragraph {#sec-distil}

::: definition Knowledge distillation {#def-kd}
Given a trained **teacher** $p_T(\cdot\mid x_{<t})$ and a smaller **student** $p_\theta$, **distillation** trains the student to minimise, over a corpus of contexts, a divergence between the two next-token distributions, typically

$$
\mathcal{L}_{\text{KD}}(\theta) = \E_{x}\sum_t\operatorname{KL}\big(p_T(\cdot\mid x_{<t})\ \big\|\ p_\theta(\cdot\mid x_{<t})\big),
$$

possibly at a raised temperature and mixed with the ordinary next-token loss (Hinton, Vinyals and Dean, 2015). **Sequence-level** distillation instead trains the student on text generated by the teacher.
:::

For inference, distillation matters in three places. It produces small models that are served directly in place of large ones; it produces the **draft models** of speculative decoding, whose value depends on how closely they match the target ([[inference/speculative-decoding]]); and it **heals** pruned models, as below. Its cost is a training run — far smaller than pretraining, but not the minutes of calibration that post-training quantisation needs. Details, and the trade-offs between logit-level and sequence-level distillation, are in [[post-training/distillation]].

## Pruning: what can be removed {#sec-pruning}

::: definition Pruning and sparsity patterns {#def-pruning}
**Pruning** a weight matrix $W$ replaces it by $M\odot W$ for a binary **mask** $M$, possibly also adjusting the surviving weights. The **sparsity** is the fraction of zeros. By the pattern of the zeros:

- **Unstructured**: any individual weights may be zero.
- **Semi-structured ($N{:}M$)**: in every group of $M$ consecutive weights along a row, at most $N$ are non-zero; **2:4** sparsity (two of every four) is supported in hardware.
- **Structured**: whole rows or columns are removed — neurons of an MLP, attention heads, embedding channels, or entire layers — leaving a smaller dense model.
:::

The patterns trade accuracy against speed. Unstructured pruning has the most freedom and so loses least accuracy at a given sparsity, but it leaves a matrix of the same shape with scattered zeros, which dense matrix-multiply hardware cannot skip. Structured pruning produces a smaller dense model that runs faster on any hardware, but removes whole units at once and usually needs retraining to recover. Semi-structured sparsity sits between them.

### How big is a sparse matrix? {#sec-storage}

::: proposition Storage of sparse formats {#prop-storage}
A matrix with $m$ entries of $b$ bytes and density $\rho$ (fraction of non-zeros) needs

1. $mb$ bytes dense;
2. about $\rho m(b + c)$ bytes in a compressed-row format storing each non-zero with a $c$-byte column index (plus a negligible row-pointer array), which is smaller than dense only if $\rho < b/(b + c)$;
3. $\tfrac{N}{M}m\,b + \tfrac{N}{M}m\,\lceil\log_2M\rceil/8$ bytes in an $N{:}M$ format storing each kept value with its position within the group; for 2:4 with 16-bit values this is $\tfrac{2\cdot16 + 2\cdot2}{4\cdot16} = 0.5625$ of dense.
:::

::: proof
Dense storage is immediate. Compressed-row storage keeps $\rho m$ values and as many column indices, $\rho m(b + c)$ bytes, and one pointer per row; it is smaller than $mb$ when $\rho(b + c) < b$. In an $N{:}M$ format each group of $M$ weights keeps $N$ values and, for each, its index within the group, which needs $\lceil\log_2M\rceil$ bits: for 2:4, $2$ values and $2\times2$ bits per $4$ weights, i.e. $(2b\cdot8 + 4)$ bits against $4b\cdot8$, which is $36/64 = 0.5625$ for $b = 2$.
:::

With 16-bit values and 32-bit indices, a compressed-row matrix is smaller than dense only below a density of $1/3$; at $50\%$ sparsity it is $1.5$ times *larger*. Speed is worse still: sparse kernels access memory irregularly, and on GPUs they typically beat dense kernels only at very high sparsity. That is why unstructured pruning of large language models, however accurate, is mostly of research interest for GPU serving, and why the 2:4 pattern exists: NVIDIA introduced sparse tensor cores supporting it with the A100 generation in 2020 (Mishra et al., 2021), doubling the peak arithmetic rate for 2:4-sparse matrices and storing them at the $0.5625$ ratio above.

::: example What 2:4 sparsity buys {#ex-24}
A model with $8\times10^9$ parameters in bfloat16 is pruned to 2:4 sparsity in all its linear layers (assume they hold all the parameters). Estimate (a) the weight memory, (b) the best-case speed-up of a memory-bound decode step and (c) of a compute-bound prefill, and (d) what changes if the remaining weights are also quantised to 8 bits.
::: solution
(a) $16\text{ GB}\times0.5625 = 9$ GB. (b) A memory-bound step's time is proportional to the bytes read, so at best $1/0.5625 = 1.78\times$ faster (less, since the cache reads are unchanged, [[inference/batching-serving#prop-attn-intensity]]). (c) Sparse tensor cores double the peak rate, so at best $2\times$; measured end-to-end gains are smaller, because not every operation is a sparse matrix product. (d) With 8-bit values, $(2\cdot8 + 4)/(4\cdot16) = 0.3125$ of the bfloat16 dense size, $5$ GB — the two techniques compose, as SparseGPT demonstrated by combining them.
:::
:::

## Choosing what to prune {#sec-criteria}

Which weights matter least? The answer depends on what "matters" means, and the natural meaning after training is the same as in [[inference/quantisation#def-layerwise]]: the change in each layer's output on representative inputs. Pruning weight $w_{rj}$ is quantising it to zero, so the theory of that chapter applies directly, and three popular criteria turn out to be the same objective under three successively weaker assumptions.

::: proposition A hierarchy of pruning criteria {#prop-criteria}
Let a layer compute $\mathbf{y} = W\mathbf{x}$ with inputs of second-moment matrix $\Sigma = \E[\mathbf{x}\mathbf{x}^\top]$ (estimated by $H = XX^\top/n$ from calibration data). Removing a set $S_r$ of weights from row $r$ *without adjusting the others* increases the expected squared output error by $\mathbf{u}^\top\Sigma\mathbf{u}$, where $\mathbf{u}$ holds the removed weights. Hence:

1. if $\Sigma = \sigma^2I$ (isotropic inputs), the error is $\sigma^2\sum_{j\in S_r}w_{rj}^2$, and removing the smallest-magnitude weights is optimal (**magnitude pruning**);
2. if $\Sigma$ is diagonal with entries $\sigma_j^2$, the error is $\sum_{j\in S_r}w_{rj}^2\sigma_j^2$, and removing the weights with the smallest $\lvert w_{rj}\rvert\,\sigma_j$ is optimal — up to the factor $\sqrt n$, the score $\lvert w_{rj}\rvert\,\lVert X_{j,:}\rVert_2$ of **Wanda** (Sun et al., 2024);
3. if the other weights of the row may be adjusted, the least error for removing a single weight $j$ is $w_{rj}^2/[\Sigma^{-1}]_{jj}$ (the **optimal brain surgeon** saliency), achieved by the compensating update of [[inference/quantisation#prop-obs]] with $e_j = w_{rj}$.
:::

::: proof
The output error is $(W - \hat W)\mathbf{x}$, whose row $r$ is $\mathbf{u}^\top\mathbf{x}$ with $\mathbf{u}$ the vector of removed weights (zero elsewhere). Its expected square is $\E[(\mathbf{u}^\top\mathbf{x})^2] = \mathbf{u}^\top\Sigma\mathbf{u}$. (1) With $\Sigma = \sigma^2I$ this is $\sigma^2\lVert\mathbf{u}\rVert^2$, a sum of independent terms $\sigma^2w_{rj}^2$; to remove $k$ weights at least cost, remove the $k$ smallest. (2) With diagonal $\Sigma$ the cross terms vanish and the cost is $\sum_{j\in S_r}w_{rj}^2\sigma_j^2$; the same argument applies to the scores $\lvert w_{rj}\rvert\sigma_j$, and $\lVert X_{j,:}\rVert_2^2 = n\,H_{jj}$ estimates $n\sigma_j^2$. (3) Removing weight $j$ is quantising it to $0$, an error $e_j = w_{rj}$; [[inference/quantisation#prop-obs]] gives the minimum $e_j^2/[\Sigma^{-1}]_{jj}$ when the other weights are re-optimised.
:::

The hierarchy explains the empirical record. Magnitude pruning, used successfully on smaller networks for decades (Han et al., 2015), assumes all inputs equally large — badly wrong for large language models, whose activations have outlier features ([[inference/quantisation#sec-outliers]]): a small weight on a huge feature matters more than a large weight on a tiny one. Sun et al. found that magnitude pruning of LLaMA models to $50\%$ unstructured sparsity raised perplexity sharply, while their Wanda score — weight times input norm, compared within each output row, with no weight updates and a single forward pass of calibration data — came close to the far more expensive reconstruction methods.

### SparseGPT {#sec-sparsegpt}

**SparseGPT** (Frantar and Alistarh, 2023) applies the third level: it prunes with OBS saliencies and updates the remaining weights to compensate, using the same machinery as GPTQ — a fixed column order shared by all rows, so that the sequence of inverse Hessians is computed once per layer, lazy block updates and a Cholesky factorisation. The mask is chosen adaptively, block by block of columns, using saliencies computed with the current (already compensated) weights. Frantar and Alistarh pruned $175$-billion-parameter models (OPT-175B and BLOOM-176B) to $50\%$–$60\%$ unstructured sparsity in a few GPU hours with small increases in perplexity, and showed that the method extends to 2:4 and 4:8 patterns and combines with quantisation in a single pass. They also observed that larger models were easier to prune: the relative loss at a given sparsity shrank with scale.

::: algorithm OBS pruning with reconstruction (one row; simplified SparseGPT) {#alg-sparsegpt}
1. Compute $H^{-1}$ for $H = XX^\top + \lambda I$ (damped).
2. For each block of $B$ consecutive columns (for 2:4, $B = 4$): compute the saliency $w_j^2/[H^{-1}]_{jj}$ of each weight in the block with the current $\mathbf{w}$ and $H^{-1}$, and mark the lowest-saliency half for removal.
3. Within the block, for each column $j$ in order: if marked, set $e = w_j/[H^{-1}]_{jj}$, update $w_k\mathrel{-}= e\,[H^{-1}]_{jk}$ for the remaining columns $k > j$, and set $w_j = 0$; in either case remove $j$ from $H^{-1}$ by [[inference/quantisation#eq-schur]].
:::

::: example Magnitude against Wanda {#ex-wanda}
A row has weights $(1.0, 0.5)$; the corresponding input channels have norms $\lVert X_{1,:}\rVert = 1$ and $\lVert X_{2,:}\rVert = 4$ over the calibration set, and are uncorrelated. One weight is to be removed without updating the other. Which does each criterion remove, and what squared output error results (summed over the calibration tokens)?
::: solution
Magnitude removes $0.5$; the error is $0.5^2\cdot4^2 = 4$. Wanda scores $1.0\cdot1 = 1$ and $0.5\cdot4 = 2$ and removes the first weight, at error $1.0^2\cdot1^2 = 1$. Since the inputs are uncorrelated, $\Sigma$ is diagonal and Wanda's choice is optimal among removals without update ([[#prop-criteria]]): the smaller weight matters more because its input is four times larger.
:::
:::

## Implementing it {#sec-code}

The listing compares, on one $16\times32$ layer with correlated calibration inputs whose channel scales differ (three channels $8$ times larger than average, eight channels $0.3$ times), magnitude pruning, Wanda and OBS pruning with reconstruction, at $50\%$ unstructured and 2:4 sparsity, and evaluates the storage formula.

```python
import math, random
rng = random.Random(0)
d_in, d_out, n = 32, 16, 512
# calibration inputs: correlated features with very different scales (as in LLM activations)
scale = [8.0 if i < 3 else (0.3 if i >= 24 else 1.0) for i in range(d_in)]
A = [[rng.gauss(0, 1) for _ in range(d_in)] for _ in range(d_in)]
Z = [[rng.gauss(0, 1) for _ in range(n)] for _ in range(d_in)]
X = [[scale[i] * sum(A[i][k] * Z[k][c] for k in range(d_in)) / math.sqrt(d_in) for c in range(n)]
     for i in range(d_in)]                                            # (d_in, n)
W = [[rng.gauss(0, 1) for _ in range(d_in)] for _ in range(d_out)]    # (d_out, d_in)

def matmul(A, B): return [[sum(a * b for a, b in zip(r, c)) for c in zip(*B)] for r in A]
def inverse(M):
    m = len(M); A = [row[:] + [float(i == j) for j in range(m)] for i, row in enumerate(M)]
    for c in range(m):
        p = max(range(c, m), key=lambda r: abs(A[r][c])); A[c], A[p] = A[p], A[c]
        piv = A[c][c]; A[c] = [v / piv for v in A[c]]
        for r in range(m):
            if r != c and A[r][c] != 0:
                f = A[r][c]; A[r] = [a - f * b for a, b in zip(A[r], A[c])]
    return [row[m:] for row in A]
Y = matmul(W, X)
def out_err(Wp):
    Yp = matmul(Wp, X)
    return sum((a - b) ** 2 for r1, r2 in zip(Y, Yp) for a, b in zip(r1, r2)) / sum(a * a for r in Y for a in r)

xnorm = [math.sqrt(sum(v * v for v in X[i])) for i in range(d_in)]   # ||X_j||_2 per input channel
def prune_by_score(score, pattern):
    """pattern 'half': drop the 50% lowest scores in each row; '2:4': drop 2 of every 4."""
    Wp = []
    for r, row in enumerate(W):
        s = [score(r, j) for j in range(d_in)]
        if pattern == "half":
            drop = set(sorted(range(d_in), key=lambda j: s[j])[:d_in // 2])
        else:
            drop = {j for g in range(0, d_in, 4) for j in sorted(range(g, g + 4), key=lambda j: s[j])[:2]}
        Wp.append([0.0 if j in drop else w for j, w in enumerate(row)])
    return Wp

H = matmul(X, list(map(list, zip(*X))))
damp = 0.01 * sum(H[i][i] for i in range(d_in)) / d_in
Hinv0 = inverse([[H[i][j] + damp * (i == j) for j in range(d_in)] for i in range(d_in)])
def sparsegpt(pattern, block=4):
    """OBS pruning with reconstruction (simplified SparseGPT): columns left to right; in each block,
    choose the weights with the lowest saliency w^2 / [H^-1]_jj, zero them and update the rest."""
    Wp = []
    for row in W:
        w = row[:]; Hi = [r[:] for r in Hinv0]
        b = block if pattern == "2:4" else d_in
        drop = set()
        for j in range(d_in):
            if j % b == 0:                                           # choose this block's mask adaptively
                cols = range(j, j + b)
                sal = sorted(cols, key=lambda c: w[c] ** 2 / Hi[c - j][c - j])
                drop = set(sal[: b // 2])
            if j in drop:
                err = w[j] / Hi[0][0]
                for k in range(1, len(Hi)): w[j + k] -= err * Hi[0][k]
                w[j] = 0.0
            hj = Hi[0][:]                                            # remove the first remaining column
            Hi = [[Hi[a][c] - Hi[a][0] * hj[c] / hj[0] for c in range(1, len(Hi))] for a in range(1, len(Hi))]
        Wp.append(w)
    return Wp

for pattern in ("half", "2:4"):
    mag = out_err(prune_by_score(lambda r, j: abs(W[r][j]), pattern))
    wanda = out_err(prune_by_score(lambda r, j: abs(W[r][j]) * xnorm[j], pattern))
    sg = out_err(sparsegpt(pattern))
    print(f"50% sparsity ({pattern:4s}): relative output error  magnitude {mag:.3f}  Wanda {wanda:.3f}  "
          f"OBS+update {sg:.3f}")

# storage of sparse formats, relative to dense 16-bit
for name, ratio in [("2:4, 16-bit values + 2-bit indices", (2 * 16 + 2 * 2) / (4 * 16)),
                    ("CSR at 50% density, 16-bit values + 32-bit column ids", 0.5 * (2 + 4) / 2),
                    ("CSR at 10% density", 0.1 * (2 + 4) / 2)]:
    print(f"{name:55s}: {ratio:.4f} of dense")
```

Output:

```
50% sparsity (half): relative output error  magnitude 0.078  Wanda 0.006  OBS+update 0.006
50% sparsity (2:4 ): relative output error  magnitude 0.139  Wanda 0.080  OBS+update 0.029
2:4, 16-bit values + 2-bit indices                     : 0.5625 of dense
CSR at 50% density, 16-bit values + 32-bit column ids  : 1.5000 of dense
CSR at 10% density                                     : 0.3000 of dense
```

(In the reconstruction, the inverse Hessian shrinks by one row and column after each column is processed, so index $0$ always refers to the current column $j$.) With unequal input scales, magnitude pruning is thirteen times worse than Wanda at $50\%$ unstructured sparsity, and Wanda matches the reconstruction method: here the dominant effect is the scale of the inputs, which Wanda captures. The 2:4 pattern is harder for every method, since each group of four must lose two weights even when all four matter; there, compensating with the surviving weights pays, cutting Wanda's error by a factor of nearly three. These are single-layer errors on synthetic data; whole-model results depend on how errors propagate through layers, and are measured by perplexity and task accuracy.

::: quiz
A $50\%$ unstructured-sparse model, stored in a standard compressed sparse format with 32-bit indices, is served on a GPU with dense kernels. Compared with the dense model, what happens?
- [ ] It runs about twice as fast, since half the multiplications are skipped
- [x] It is no faster with dense kernels, and the sparse format would take more memory than dense
- [ ] It uses half the memory and runs at the same speed
- [ ] It becomes compute-bound
::: solution
Dense kernels multiply the zeros like any other number, so nothing is saved unless the matrix is converted to a sparse format; and at $50\%$ density, values plus 32-bit indices take $1.5$ times the dense size ([[#prop-storage]]), while sparse kernels are rarely faster at this density. Only the hardware-supported 2:4 pattern turns $50\%$ sparsity into real savings on GPUs.
:::
:::

## Structured pruning {#sec-structured}

To get a model that is faster everywhere, remove whole units. An MLP neuron is a column of the up-projection (and of the gate, in a gated MLP) together with the matching row of the down-projection; an attention head is a slice of the query, key, value and output projections; a layer is a whole block. Removing a unit deletes its parameters and their FLOPs exactly, leaving a smaller dense model.

::: definition Importance of a structure {#def-importance}
An **importance score** ranks prunable structures. Common choices are: the magnitude of the unit's activations on calibration data; the first-order **Taylor** estimate of the loss change $\big\lvert\sum_{w\in\text{unit}}w\,\partial\mathcal{L}/\partial w\big\rvert$ (Molchanov et al., 2017); and, for whole layers, how little the layer changes its input — for example $1 - \cos(\mathbf{h}_{\text{in}}, \mathbf{h}_{\text{out}})$ averaged over tokens.
:::

Structured pruning of language models nearly always needs a **healing** phase. Representative published approaches (each a research result evaluated on particular models) are LLM-Pruner (Ma et al., 2023), which pruned coupled groups of structures and recovered with brief low-rank fine-tuning; Sheared LLaMA (Xia et al., 2024), which pruned Llama 2 7B to target shapes of $1.3$ and $2.7$ billion parameters with learned masks and then continued pretraining; and the Minitron work (Muralidharan et al., 2024), which pruned width and depth of a $15$-billion-parameter model to $8$ and $4$ billion and retrained with distillation from the original, reporting comparable quality to models of the same size trained from scratch at a small fraction of the training tokens. Several studies (for example Gromov et al., 2024; Men et al., 2024) found that a substantial fraction of the deeper layers of some open models could be removed with modest losses on some benchmarks, especially after a little healing — an observation about redundancy in those models rather than a recipe that holds for every task.

::: example Removing MLP neurons {#ex-structured}
A model has $32$ layers of width $d = 4096$ with gated MLPs of inner width $d_{\text{ff}} = 14{,}336$ (three matrices per MLP: gate and up of shape $d\times d_{\text{ff}}$, down of shape $d_{\text{ff}}\times d$). Structured pruning removes $25\%$ of the MLP neurons in every layer. How many parameters are removed, and by what factor does the MLP's decode-step weight traffic fall?
::: solution
Each neuron accounts for $3d = 12{,}288$ parameters (a column of gate and up, a row of down). Removing $0.25\cdot14{,}336 = 3584$ neurons per layer removes $3584\cdot12{,}288 = 4.40\times10^7$ parameters per layer and $1.41\times10^9$ in all. The MLP weights fall from $3\cdot4096\cdot14{,}336\cdot32 = 5.64\times10^9$ to $4.23\times10^9$, so their traffic and FLOPs fall by exactly $25\%$ on any hardware — unlike unstructured sparsity, no special kernel is needed. Whether quality survives depends on the healing.
:::
:::

## The lottery ticket hypothesis {#sec-lottery}

Pruning a trained network shows that it did not need all its weights at the end. Could a sparse network have been trained from the start? Frankle and Carbin (2019) made an influential empirical observation on small vision networks: train a dense network, prune the smallest-magnitude weights, **rewind** the survivors to their *original initial values*, and retrain the sparse network; repeating this (iterative magnitude pruning) found subnetworks of $10$–$20\%$ of the original size that trained to the same accuracy as the full network, often faster. With fresh random initial values instead, the same sparse architectures trained worse. They called such subnetworks **winning tickets** and stated the **lottery ticket hypothesis**: dense, randomly initialised networks contain subnetworks that, trained in isolation, can match the full network.

This is a finding, not a theorem, and its scope is limited. For larger networks, rewinding to initialisation failed; Frankle et al. (2020) found that rewinding to an early point of training (a few percent in) worked instead, and linked success to the stability of training to the noise of the data order. Finding a ticket requires training the dense network first — repeatedly, for iterative pruning — so it does not reduce training cost; and the tickets are unstructured, so they do not speed up inference on dense hardware. The hypothesis matters for understanding why over-parameterised networks are easy to train and prune, and it motivated much work on sparse training, but it is not a compression method for large language models.

## Early exit {#sec-early-exit}

Pruning makes every token cheaper by the same amount. But tokens differ: after "The capital of France is", the next token is obvious after a few layers; elsewhere the full depth is needed. **Early exit** spends less computation on easy tokens.

::: definition Early-exit decoding {#def-early-exit}
An **early-exit** model attaches an output head to some intermediate layers $\ell_1 < \ell_2 < \dots < L$ (often sharing the final unembedding). For each token, after layer $\ell_i$ it computes a **confidence** — for example the top probability of the intermediate distribution, or the difference between the top two — and, if it exceeds a threshold $\lambda$, emits the token without running the remaining layers.
:::

::: proposition Expected cost of early exit {#prop-early-exit}
If a token exits after layer $\ell_i$ with probability $\pi_i$ ($\sum_i\pi_i = 1$, the last exit being $L$), and each exit check costs $c$ layer-equivalents, the expected cost per token is

$$
\E[\text{cost}] = \sum_i\pi_i\big(\ell_i + i\,c\big)\quad\text{layers},
$$

and the speed-up over the full model is $L/\E[\text{cost}]$.
:::

::: proof
A token exiting at the $i$th exit has run $\ell_i$ layers and $i$ confidence checks (one at each exit up to and including the $i$th). Taking expectations over the exit distribution gives the formula.
:::

::: example Early exit in a batch {#ex-exit-batch}
Exits sit after layers $8$, $16$ and $32$ of a $32$-layer model, and each token independently exits at them with probabilities $0.3$, $0.3$ and $0.4$. For a single stream, how many layers' weights does a decode step read on average? For a batch of $4$ and of $64$ streams decoding together?
::: solution
A single stream reads $0.3\cdot8 + 0.3\cdot16 + 0.4\cdot32 = 20$ layers on average. In a batch, layers $9$–$16$ must be read if *any* token continues past layer $8$, with probability $1 - 0.3^B$, and layers $17$–$32$ if any continues past $16$, probability $1 - 0.6^B$. For $B = 4$: $8 + 8(1 - 0.0081) + 16(1 - 0.1296) = 29.9$ layers. For $B = 64$ both probabilities are $1$ to many decimal places: all $32$ layers are read. Early exit saves arithmetic for the exited tokens, but a memory-bound batched step saves almost nothing, since some token always needs the deep layers.
:::
:::

Two complications make early exit harder for autoregressive models than for classifiers. First, **missing caches**: if token $t$ exits after layer $8$ of $32$, layers $9$–$32$ never computed its keys and values, yet later tokens that run those layers attend to it. CALM (Schuster et al., 2022) copied the exited hidden state upwards to fill the missing entries (approximating them), and calibrated the exit thresholds so that the output agrees with the full model's with a stated probability; other designs compute the missing caches later, in parallel. Second, **batching**: tokens in a batch exit at different layers, so the batch shrinks unevenly from layer to layer and the saved arithmetic is hard to turn into saved time in a memory-bound decode step, which must read each layer's weights for whoever is left. An alternative that sidesteps both is to use the early layers as a draft model for speculative decoding and verify with the full model, which LayerSkip (Elhoushi et al., 2024) did after training the model so that early exits are accurate ([[inference/speculative-decoding]]).

::: warning "Halving the parameters halves the cost"
Fewer non-zero parameters do not by themselves mean fewer bytes moved or fewer cycles. Unstructured zeros cost the same as any other number in a dense kernel; a sparse format can take more memory than the dense one; early exit saves arithmetic that a memory-bound step was not spending anyway. Before pruning, ask which resource limits the deployment — memory capacity, memory bandwidth or arithmetic — and whether the sparsity pattern reduces that resource on the target hardware.
:::

::: history
LeCun, Denker and Solla's "optimal brain damage" (1990) pruned weights by a diagonal second-order saliency, and Hassibi and Stork's "optimal brain surgeon" (1993) used the full inverse Hessian with compensating updates. Han, Pool, Tran and Dally (2015) and Han, Mao and Dally's Deep Compression (2016) made magnitude pruning with retraining standard for convolutional networks. Hinton, Vinyals and Dean (2015) named knowledge distillation, building on model compression by Buciluǎ, Caruana and Niculescu-Mizil (2006); Kim and Rush (2016) introduced sequence-level distillation. Frankle and Carbin proposed the lottery ticket hypothesis (ICLR 2019). NVIDIA's A100 (2020) introduced hardware support for 2:4 sparsity. For large language models, Frantar and Alistarh's SparseGPT (ICML 2023) and Sun, Liu, Bair and Kolter's Wanda (ICLR 2024) showed one-shot pruning at scale. Early exit goes back to BranchyNet (Teerapittayanon, McDanel and Kung, 2016) and was adapted to language generation by CALM (Schuster et al., NeurIPS 2022).
:::

::: summary
- **Distillation** trains a small student on a teacher's distributions; for inference it yields small models, draft models and the healing step after pruning ([[post-training/distillation]]).
- **Unstructured** sparsity loses least accuracy but rarely speeds up GPUs: general sparse formats are larger than dense above about $1/3$ density. **2:4** sparsity has hardware support: $0.5625$ of dense storage in 16 bits, up to $2\times$ arithmetic. **Structured** pruning yields smaller dense models but needs healing.
- Without weight updates, the output error of pruning is $\mathbf{u}^\top\Sigma\mathbf{u}$: **magnitude** pruning assumes isotropic inputs, **Wanda** ($\lvert w\rvert\lVert X_j\rVert$) diagonal inputs, and **OBS/SparseGPT** uses the full inverse Hessian and compensates with the remaining weights.
- The **lottery ticket hypothesis** is an empirical finding about trainable sparse subnetworks, not an inference technique.
- **Early exit** saves layers on easy tokens but must deal with missing caches and uneven batches; its expected cost is $\sum_i\pi_i(\ell_i + ic)$.
- Compress against the resource that limits the deployment, and measure on the target hardware and tasks.
:::

## Exercises

::: exercise 2:4 storage with 8-bit values {level=1 check="0.625"}
A matrix of 8-bit values is stored in 2:4 format with $2$-bit indices. What fraction of the dense 8-bit storage does it take?
::: solution
Per group of four: $2\cdot8 + 2\cdot2 = 20$ bits against $32$: $20/32 = 0.625$. Relative to dense 16 bits it is $0.3125$.
:::
:::

::: exercise Break-even density {level=1 check="0.5"}
A sparse format stores 16-bit values and 16-bit column indices. Below what density is it smaller than dense 16-bit storage?
::: solution
By [[#prop-storage]], $\rho < b/(b + c) = 2/(2 + 2) = 0.5$.
:::
:::

::: exercise Magnitude pruning by hand {level=1 check="0.0426"}
Prune $50\%$ of the row $(0.3, -0.05, 0.2, -0.6, 0.01, 0.4)$ by magnitude. Under isotropic unit-variance inputs, what is the expected squared output error?
::: solution
The three smallest magnitudes are $0.01$, $0.05$ and $0.2$; removing them costs $0.0001 + 0.0025 + 0.04 = 0.0426$ ([[#prop-criteria]], with $\sigma^2 = 1$). The kept row is $(0.3, 0, 0, -0.6, 0, 0.4)$.
:::
:::

::: exercise A 2:4 group {level=1}
Apply magnitude-based 2:4 pruning to the row $(0.1, -0.7, 0.3, 0.2,\ 0.5, 0.45, -0.05, 0.6)$. What is the cost under isotropic inputs, and how does it compare with $50\%$ unstructured magnitude pruning of the same row?
::: solution
Group 1 keeps $-0.7$ and $0.3$, dropping $0.1$ and $0.2$ (cost $0.01 + 0.04 = 0.05$). Group 2 keeps $0.6$ and $0.5$, dropping $0.45$ and $-0.05$ (cost $0.2025 + 0.0025 = 0.205$). Total $0.255$. Unstructured: the four smallest magnitudes are $0.05, 0.1, 0.2, 0.3$, cost $0.0025 + 0.01 + 0.04 + 0.09 = 0.1425$. The 2:4 constraint forced the removal of $0.45$ because the second group held three large weights.
:::
:::

::: exercise Expected layers with early exit {level=2 check="20"}
A $32$-layer model has exits after layers $8$, $16$ and $32$. A token exits at layer $8$ with probability $0.3$, at $16$ with probability $0.3$, and otherwise runs all $32$ layers. Ignoring the cost of the checks, how many layers run per token on average?
::: solution
$0.3\cdot8 + 0.3\cdot16 + 0.4\cdot32 = 2.4 + 4.8 + 12.8 = 20$ layers, a speed-up of $32/20 = 1.6$ in arithmetic. With a check cost of $c = 0.1$ layers per exit, add $0.3\cdot0.1 + 0.3\cdot0.2 + 0.4\cdot0.3 = 0.21$ ([[#prop-early-exit]]).
:::
:::

::: exercise The best case for 2:4 in decode {level=2 check="1.78"}
A decode step is entirely memory-bound and its time is proportional to the bytes of weights read (ignore the cache). By what factor, to two decimal places, can 2:4 sparsity with 16-bit values and 2-bit indices speed it up?
::: solution
The bytes fall to $0.5625$ of dense, so the step is at best $1/0.5625 = 1.78$ times faster — less than the $2\times$ arithmetic speed-up that matters for compute-bound prefill.
:::

::: exercise OBS saliency in two dimensions {level=2}
For a row $\mathbf{w} = (1.0, 0.5)$ with $H = \begin{pmatrix}1&0.9\\0.9&1\end{pmatrix}$ (strongly correlated inputs), compute the OBS saliency of each weight and the error of removing each *without* compensation. Which weight should be removed, and what does the compensation do?
::: solution
$H^{-1} = \frac{1}{0.19}\begin{pmatrix}1&-0.9\\-0.9&1\end{pmatrix}$, so $[H^{-1}]_{11} = [H^{-1}]_{22} = 5.263$. Saliencies: $1.0^2/5.263 = 0.19$ and $0.5^2/5.263 = 0.0475$; remove the second. Its compensation is $\delta_1 = -\frac{0.5}{5.263}\cdot(-4.737) = 0.45$, so the first weight becomes $1.45$: since the two inputs are nearly the same signal, the first weight takes over most of the second's contribution ($0.5\cdot0.9$). Without compensation, removing the second costs $0.5^2\cdot H_{22} = 0.25$, more than five times the compensated $0.0475$; removing the first costs $1.0$. With strongly correlated inputs, compensation is what makes pruning cheap.
:::
:::

::: exercise Designing a lottery-ticket experiment {level=3}
You want to test whether a winning ticket exists for a small Transformer language model at $80\%$ sparsity. Describe the procedure, the controls needed to support the claim, and what result would count against the hypothesis at this scale.
::: solution
Train the dense model to convergence from initialisation $\theta_0$, recording $\theta_k$ at an early step $k$ (say $1$–$5\%$ of training). Iterative magnitude pruning: prune $20\%$ of the remaining weights by magnitude (globally or per layer), rewind the survivors to $\theta_k$ (and to $\theta_0$ as a separate arm), retrain with the same schedule, and repeat until $80\%$ sparsity. Controls: (i) the same masks with fresh random initial values (tests whether the initial values, not only the architecture, matter); (ii) random masks of the same per-layer sparsity, rewound the same way; (iii) the dense model trained for the same number of steps; and several seeds for every arm, reporting validation loss with confidence intervals. The hypothesis is supported at this scale if the rewound ticket matches the dense model's loss within noise while controls (i) and (ii) are clearly worse. Evidence against: the ticket matching only with late rewinding (which weakens the claim to "a partly trained network contains a good sparse subnetwork"), or controls matching the ticket (sparsity alone, not the ticket, suffices).
:::
:::

::: exercise SparseGPT with quantisation {level=3}
Modify `sparsegpt` in the listing so that each weight that is *kept* is also quantised to $4$ bits (per-row absmax scale computed from the original row) at the moment its column is processed, with its quantisation error compensated in the same way as a pruning error. Explain why the two operations combine naturally in this algorithm.
::: solution
In the branch where column $j$ is not dropped, replace the original weight by its quantised value and propagate the error exactly as GPTQ does:

```python
s4 = max(abs(v) for v in row) / 7                    # before the column loop
...
target = 0.0 if j in drop else s4 * max(-8, min(7, round(w[j] / s4)))
err = (w[j] - target) / Hi[0][0]
for k in range(1, len(Hi)): w[j + k] -= err * Hi[0][k]
w[j] = target
```

Pruning is quantisation to the single value $0$, so both are "fix column $j$ to a value and compensate", with the same inverse-Hessian update ([[inference/quantisation#prop-obs]]) and the same removal of column $j$ from $H^{-1}$. Doing them together means the later columns compensate for both kinds of error at once, which Frantar and Alistarh found more accurate than pruning and then quantising separately. With the listing's seed, the relative output errors of the reconstruction method rise from $0.006$ to $0.012$ (unstructured) and from $0.029$ to $0.036$ (2:4) — larger than for pruning alone, while the storage falls to roughly $(2\cdot4 + 2\cdot2)/(4\cdot16)\approx0.19$ of dense for 2:4 with 4-bit values.
:::
