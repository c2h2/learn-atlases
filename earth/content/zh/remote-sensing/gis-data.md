一个分类的图在一个人能找到它、打开它、信任它、分析它之前不是信息。前面的章节生产着地图；本章关于着容器——数据的模型、格式、数据库、标准，它们把一个分类的栅格、一个数字化的野外的边界变成另一个国家的、另一个软件的、另一个十年的一个同事实际能使用的东西。GIS 的历史部分是一个格式的历史：coverage 与 shapefile，geodatabase 与 GeoPackage，Web 地图服务与云的原生的数组。每一代是一个关于谁将持有着数据、它将如何更新、"当前的版本"意味着什么的赌注。当前的赌注——云的对象存储，JSON 的元数据，分块的数组——是自 1990 年代以来最大的，本章给出着好好地下那个赌注、不是按着时髦的推理。

::: definition 矢量的数据的模型：几何，属性，拓扑 {#def-vector-model}
一个**矢量**的数据集把世界表示为离散的几何的对象：点（一个水位计），线（一条河，一条路），面（一个地块，一个洪水的范围）。每一个几何携带着**属性**——一个类型的字段的表的一行——这一对存储在两个哲学的一个里。**意大利面条的**模型独立地存储每一个面的坐标；层之间的叠加靠数字化的差异产生着小的碎片的片，"哪些面接触"要求着贵的坐标的比较。**拓扑的**模型显式地存储着节点、弧、面带着邻接的表——1982 的 ESRI 的 coverage、同一个时代的 TIN——共享的边界存储一次，缝隙与重叠靠构造不可能，网络的遍历（河流的选线，管线的追踪）是自然的；代价是一个更难的编辑的工作流。**简单的特征**（ISO 19125，OpenGIS 1999）为交换做了一个务实的妥协：作为坐标的序列的几何带着明确定义的谓词（相交，包含，在内部）被计算地评估着，拓扑在需要时断言着、不总是存储着。2020 年代的分析的堆栈加一个列的转折：**GeoParquet** 把简单的特征的几何保持在编码的列的形式，一个查询能读着一个一百万个面的边界盒的统计、不触碰着几何自己——空间的索引变成一个文件的格式的特征。几何的**有效性**是一个一等的问题：自相交的面，内部的孔洞，未闭合的环——有效性可逐几何判定着、可自动地修复着，但修复改变着坐标，规则是在导入时验证着、记录着修复了什么。 {#def-vector-model}

:::
::: definition 拓扑，有效性，空间的索引 {#def-topology-index}
三个属性决定着矢量的数据是否可用。**拓扑的一致性**：共享的边界存储一次，相邻的面之间没有缝隙与重叠，没有悬挂与双的节点的线——1980 年代以来的地籍的要求，测量的等级的数据集仍然作为拓扑的模型交付的理由。**几何的有效性**：环闭合、不自相交、包含着它们的孔的面；有效性逐几何可判定着、可自动地修复着，但修复改变着坐标，规则是在导入时验证着、记录着修复了什么。**空间的索引**：R 树与它的变体——PostGIS 的 GiST 与 GIN 的索引的种类，栅格目录的层次与四叉树的网格——按最小边界矩形组织着几何，"一千万个地块的哪些接触着这条线"花费着几百个矩形的检验、不是一千万个面的相交。索引回答着边界盒的问题；精确的谓词只在它返回着的少数候选上运行着。两个操作的规则随之：每一个空间的列得到一个索引，每一个按几何过滤的查询被写成索引可使用——先一个边界盒的谓词，第二贵的精确的检验。一个未索引的空间的连接在一个国家的地块层上是一个完成的查询、一个永不完成的查询之间的区别。 {#def-topology-index}

:::
::: definition 栅格的数据：堆栈，数组，分析就绪 的访问 {#def-raster-access}
栅格的数据的组织从单个的文件到服务运行着。GeoTIFF 的经典的**按像元的波段交错**对着**按行的波段交错**对着**顺序的波段**的选择决定着哪些读是快的：使用着一个场景的所有波段的分析要求着像元的交错；一个跨着场景的一个波段的时间序列要求着每一个场景的波段连续的、更好的、一个缝合着场景、选出着波段不复制着字节的**虚的栅格**（VRT）XML。**云优化的 GeoTIFF**（COG）标准化着内部的布局——8 位对齐的分块，作为内部的金字塔的概览，一个良好排序的标签的块——任何一个 HTTP 的客户端能请求着它需要的分块的确切的字节范围：一个 $100$ 亿字节的场景的一个 $30$ 米的窗口花费着一个短的请求、不下载着场景。**Zarr 与 netCDF** 服务着数组的世界：对象存储里的分块的 N 维的数组带着逐分块的压缩，气候的模型与数据立方体的平台的原生的形式，**xarray** 作为事实的客户端。**STAC**（时空的资产的目录）提供着缺失的目录卡片：描述着每一个场景的足迹、日期、仪器、链接的 JSON 的项，索引着"2024 年在这个流域之上低于 $20$ 个百分点的云的所有的 Sentinel-2 的场景"是一个查询、不是一个目录的行走。**分析就绪 的地球的观测**（ARD）关闭着环：预先校正到地表的反射率的、共同配准的、云的掩膜的产品，加上**无云的组合**（一个季节的中位数与百分位的镶嵌），分析读着观测、不是原生的轨道。2020 年代的平台的三位一体——发现的 STAC，访问的 COG 与 Zarr，服务端的计算（批的处理者，在数据处的用户定义的函数）——是 Landsat 与 Sentinel 的档案、行星的计算机的计划、商业的档案汇聚着的方式。 {#def-raster-access}

:::
::: example 选择一个格式：GeoPackage，GeoParquet，PostGIS {#ex-formats}
格式的决定归结为一个短的诚实的总结。**GeoPackage** 为桌面的编辑与离线野外工作：一个 SQLite 的文件，没有大小的上限，适当的类型与索引——当一个人在一个森林里的一个电话上编辑时务实的默认。**GeoParquet** 为分析：列的压缩与边界盒的统计，一个数据框读着不加载着几何——Python 的堆栈的 2021 起的默认。**PostGIS** 作为记录的制度：并发的编辑者，引用的完整性，事务的版本化的编辑，空间的 SQL——当几个人在今天下午更新着同一个层唯一正确的答案。**GeoJSON** 为网络的运输，带着它的精度与大小的警告，带着纬度与经度的列的普通的 CSV 作为点的数据的通用的捐献者。**Shapefile**——$63$ 个字符的字段名，一个 $2$ 十亿字节的天花板，Latin-1 的假设——只作为一个交换的格式存活着、像它自己的生态系统的维护者现在建议着的；2020 年代看着统计的机构与地籍的服务发表着正式的弃用的通知。决定的规则：按着工作流的瓶颈选择——编辑，分析，共享——从不按着习惯，总是记录着坐标的参考系统与有效性的状态在文件旁边。 {#ex-formats}

:::
::: example 碎片：当两个分类关于一个边界不一致时 {#ex-slivers}
同一个事件的两个洪水的范围的制图——一个雷达的派生的，一个野外测量的——沿着它们的边缘相差着米。不谨慎地合并它们，叠加产生着数百个碎片的片：薄的、拉长的碎片带着数十平方米的面积、数百米的周长。一个天真的面积摘要把合并报告为比任何一个输入大 $12$ 个百分点，一个改变的图把洪泛平原的 $12$ 个百分点报告为新洪水的。诊断是几何的：碎片有着极端的周长对面积的比，远在真实的面的形状统计之外。修复，按偏好的秩序：在叠加之前把输入吸附到一个共同的网格（一半的位置的不确定度的容差），使用着把碎片的片在一个阈值的面积之下坍缩着的拓扑意识的叠加，携带着两个边界作为一个模糊的区、从不强制着一个单的线。报告的规则：进入一个统计的工作流的任何一个面层先得到一个形状的审计——面积的分布，周长对面积的离群，重复与近重复的几何——因为一个摘要的表里的碎片的片是不可见的、恰恰以重要的方式错的。 {#ex-slivers}

:::
::: example 空间的 SQL：替换着脚本的查询 {#ex-sql}
问题：多少卫生的诊所在一个制图的百年一遇的洪水的范围的 $5$ 公里之内，按区？脚本的方法下载着两个层，在 Python 里循环着诊所，随着诊所的登记更新着每月重新运行着。数据库的方法保持着两个层在带着空间的索引的 PostGIS 里、问一次：在诊所的点与洪水的面之间的 ST_DWithin 的一个连接，按区分组着，在一个国家的登记之上在秒内执行着，因为 R 树修剪着到每一个诊所的少数候选。SQL 也说明着它自己的假设：距离是大地的（地理的转换，不是错的投影的平面的米，按着地图与投影的课），洪水的层是当前的版本，登记的时标记录在结果里。从三十年的 GIS 的脚本的一般课：在数据居住的地方运行的分析更快、更新鲜、可审计；空间数据据库不是一个花哨的文件柜、问题被问的地方。2020 年代的扩展是云里的同一个论证：对着对象存储评估着 STAC 的查询的服务端的函数，数据从不移动着。 {#ex-sql}

:::
::: example 为一个分析就绪 的档案做预算 {#ex-ard-budget}
一个国家的林业的服务计划着一个在 Sentinel-2 ARD 上的年度的监测系统：每年 $2500$ 个覆盖着领土的场景，每一个 $10980$ 乘 $10980$ 个像元在 $13$ 个波段在 $16$ 位，作为 COG 带着逐场景的云的掩膜保持着。原生的容量约每一个场景 $3$ 十亿字节——$1.2\times10^8$ 个像元乘 $13$ 个波段乘 $2$ 字节——约每年 $8$ 万亿字节未压缩的；云的优化的压缩（反射率的数据上的 deflate 与 Zstd）把它带到 $3$ 到 $4$ 万亿字节，一个热的加档案的分层在公共的云里负担得起——与 2010 年同一个计算暗示着的磁带库的采购相距甚远，当时这个容量要求着一个专门的存储的项目。重要的预算是访问的模式：一个省的每月的绿度组合的工作读着每一个场景的像元的约 $40$ 个百分点；靠 COG 的请求的范围在 HTTP 之上的同一个工作每次运行花费着几分钱，一个下载着整个的场景的设计每月为 $2500$ 个完全的传输付着、需要着像元、不需要着。架构的课一般化着：在数组的时代，成本的驱动是分块的布局、读的模式之间的不匹配——设计着分块匹配着你实际查询着的窗口，统治着 1975 的磁带分块的同一个规则，现在每一个请求定价着。 {#ex-ard-budget}

::: history 从核心的系统到开放的数据的立方体 {#history-gis-data}
第一的地理的信息的系统是 1960 年代的核心系统：从 1963 为加拿大的土地的资源调查建造的加拿大的地理的信息系统，罗杰·汤姆林森的核心系统的架构带着它的分层的主题与基于扫描的拓扑，哈佛的结构性的分析小组的发明着"制图的计算"的术语、生产着 SYMAP 与 POLYVRT 与奥德赛的原型的实验。1970 年代看着第一的商业的系统、第一的国家数字的地籍的努力；1980 年代带来着 ESRI 的 coverage 与 ARC/INFO，康奈尔的 LISC 与 GRID 的谱系，使"国家的空间数据"成为一个常设的政府的功能的美国地质调查局的数字的线状的图与数字的高的模型。1990 年代是标准与网络的十年：1994 成立的开放地理的空间的联盟，作为 ISO 19125 采纳的简单的特征，使空间的统计学形式化的 NCGIA 然后 UCSB 的空间的分析的研究中心，美国的联邦地理的数据的委员会与 1994 的国家的空间数据据的基础设施的框架，从 1995 的 MapServer、把地图放在浏览器上的 2000 的 WMS 的规范，shapefile——一个来自一个未发表的 ArcExport 的内部结构的 1998 的偶然的交换的格式——成为这个领域最使用、最批评的容器。2004 成立的 OpenStreetMap 证明了志愿的地理的信息；2001 第一次发布的 PostGIS 把同样的数据放进着空间的 SQL。2010 年代把堆栈搬到云上：从 2015 托管着 Landsat 的亚马逊的公共的数据集的计划，微软的行星的计算机与从 2018 的时空的资产的目录的规范，成为访问的默认的 COG 与 Zarr，使分析就绪 的数组成为编程的模型的 xarray 与开放的数据的立方体，从 2021 加入着分析的层的 GeoParquet。2020 年代的争论是治理塑造的：欧盟的它的地理的数据的立法的修订，OGC 的标准化着云的原生的堆栈的努力，消费着开放的地球的观测的档案的基础模型是否改变着持有着数据的机构、持有着计算的平台的之间的平衡的问题。 {#history-gis-data}

::: exercise {level=3 check="6.4"}
一个十年的档案持有着 $20000$ 个每一个 $800$ 兆字节的场景。档案的格式的压缩达到原生的大小的 $0.4$ 的因子。档案的容量多少万亿字节（$1\ \mathrm{TB} = 10^{12}$ 字节）？ {#ex-archive-tb}

::: solution
$20000$ 乘 $800\times10^6$ 字节 $= 1.6\times10^{13}$ 字节 $= 16\ \mathrm{TB}$ 原生的；乘 $0.4 = 6.4\ \mathrm{TB}$ 档案的。以 2020 年代的价格作为对象存储负担得起；同一个计算在 2010 证明着一个多年的基础设施的计划合理，是为什么开放的档案在它们的时候发生的经济的历史。 {#ex-archive-tb}
:::
:::

::: warning 四个数据的谬误 {#warning-gis-data}
**"我打开的文件是数据。"** 它是一个带着未说明的假设的容器：投影可能缺失、错的，编码可能损坏了地名，几何的有效性未知，版本是最后导出它的人。边车的文件与元数据存在携带着这些假设；一个不带它们的数据集是一个谣言。 **"一个索引使查询快。"** 一个索引使边界盒的过滤器快；一个在索引能接合之前应用着它的贵的谓词的查询、一个无论如何选择着表的多数的查询，仍然爬着——在优化之前计划着。 **"云的原生的意味着免费的。"** 对象存储使字节便宜地保持、贵地滥用着：流出的费用，请求的收费，天真的全场景的下载是新的磁带装载，一个工作流的请求的模式现在是它的设计的审查的一部分。 **"一个标准的格式保证着互操作性。"** 格式互操作；语义不。两个在一个相同的 GeoPackage 形式的数据集能在基准、在类的定义、在"洪水的范围"在边缘包括着什么上不一致——前面的课的不确定度与本体论的课作为模式的审查重新出现，最有价值的元数据的字段常常是类自己的定义。 {#warning-gis-data}
:::

::: summary {#summary-gis-data}
矢量的数据存储着带着几何与属性的对象；拓扑决定着共享的边界是否存储一次、碎片的片是否可能，有效性、空间的索引是可用的矢量的数据实践的价格。栅格的数据汇聚到云的原生的组织——字节范围的访问的 COG 与 Zarr，发现的 STAC，分析就绪 的内容的 ARD 与组合——带着分块的布局必须匹配着读的模式的同一个老的规则。格式是工作流的选择：编辑的 GeoPackage，分析的 GeoParquet，作为记录的制度的 PostGIS，交换要求的遗留的容器。空间的 SQL 把问题带到数据，更快、更新鲜、可审计。在它的下面的全部治理的问题——谁策划着，谁版本着，谁发表着，在什么许可下、带着什么类的定义——决定着一个空间数据据的基础设施服务着它的用户、装饰着它的服务器。 {#summary-gis-data}
:::
