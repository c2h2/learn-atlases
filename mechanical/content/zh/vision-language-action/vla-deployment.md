在实验室记录本里成功的策略还没有推动过一台机器人。在网络与电机之间，隔着有延迟的相机、内存与带宽都有限的 GPU、每毫秒都要一个新设定点的控制器，以及可能走进工作空间的人。部署就是这条路径上的工程：让策略足够快，把它缓慢而一阵一阵的输出平稳地交给一个快速的控制器，并且——最要紧的是——确保策略输出的任何东西都不能让机械臂做出危险的事。学得的策略是这样一种部件：它在未见过的输入上会如何表现，规格里并没有写；系统的其余部分必须假定它有时就是会输出胡话，并据此设计。

本章从延迟预算的最底层开始搭部署栈，一直搭到安全论证的最顶层。我们先算清从一个光子到达相机到一个关节动起来之间的每一毫秒，再看推理时间如何依赖硬件的内存与算术吞吐、以及量化。然后处理**异步执行**：在当前动作块执行的同时计算下一个动作块，把各块在时间上对齐，并把它们平滑地混合。接着是从策略频率到关节控制器频率的**插值**。最长的一节讲**策略之下的安全层**——对关节位置、速度、加速度与力的限制，工作空间边界、看门狗（watchdog）与急停——本章以监控与故障处理收尾。臂级的安全要求在 [[robot-arm-design/arm-safety]]，控制器结构在 [[robot-arm-design/software-stack]]；推理技术在 LLM Atlas 的[量化](/learn/llm/lesson.php?c=inference&l=quantisation)与[延迟、吞吐量与成本](/learn/llm/lesson.php?c=inference&l=latency-cost)里有深入讲解。

::: warning 安全不是策略的一种性质
本章的任何内容都不能替代由合格人员按适用标准对完整机器人工作单元做的风险评定（方法见 ISO 12100；工业机器人及其集成见 ISO 10218-1与 -2，2025年修订；协作运行见 ISO/TS 15066；安全相关控制功能见 ISO 13849-1或 IEC 62061）。学得的策略绝不能成为安全功能的一部分。本课教的是策略周围各软件层的原则；它不是一个可认证系统的设计。
:::

## 部署栈 {#sec-stack}

一个典型的安排，从上到下：

1. **传感器**：相机（每秒30–60帧）与机器人的关节状态（来自控制器，按控制器自己的频率）。
2. **策略服务器**：预处理图像（缩放、归一化），在 GPU 上跑 VLA，把输出反归一化，并带上时间戳发布动作块——通常每秒2–15块。
3. **动作缓冲与执行器**：存放当前块，把新块在时间上对齐、混合，并按策略的动作频率发出关节（或笛卡儿）目标，10–50 Hz。
4. **插值器**：把这些目标变成关节控制器频率下平滑的设定点，500 Hz–1 kHz。
5. **安全滤波器**：在设定点到达控制器之前检查并限制每一个设定点（位置、速度、加速度、工作空间、力）；在一个实时进程里按控制器频率运行。
6. **机器人控制器与安全控制器**：制造商的实时关节控制及其安全额定的功能（保护性停止、安全速度、安全转矩关断），独立于以上的一切。

只有第5、6层是硬实时的；第1–4层可以运行在时序上尽力而为的普通操作系统上，前提是第5层在它们迟到时的行为是安全的。

## 延迟预算 {#sec-latency}

::: definition 观测到动作的延迟 {#def-latency}
**观测到动作的延迟**$t_{\mathrm{lat}}$是从某个动作所依据的那次观测被采集起，到控制器开始执行该动作为止的时间。它是采集与传输时间、预处理、推理、后处理与通信之和。在动作频率$f$下，策略的动作到达时相对其所依据的观测已经晚了$\lceil t_{\mathrm{lat}}f\rceil$步。
:::

::: example 一份延迟预算 {#ex-latency}
一个 VLA 机械臂系统有：相机曝光与 USB 传输$25\,\mathrm{ms}$、图像预处理$5\,\mathrm{ms}$、推理（前缀加10个积分步）$90\,\mathrm{ms}$、反归一化与发布$2\,\mathrm{ms}$、到执行器的传输$1\,\mathrm{ms}$。动作频率为$50\,\mathrm{Hz}$，手的移动速度最高$0.3\,\mathrm{m/s}$。求$t_{\mathrm{lat}}$、它相当于多少个动作步，以及这段时间里手移动多远。
::: solution
$t_{\mathrm{lat}} = 25 + 5 + 90 + 2 + 1 = 123\,\mathrm{ms}$。在$50\,\mathrm{Hz}$（每步20 ms）下，$123/20 = 6.15$，所以块的首个动作到达时已经旧了$\lceil6.15\rceil = 7$步。这段时间里手移动$0.3\times0.123 = 0.037\,\mathrm m = 37\,\mathrm{mm}$。
推理占了预算的73%，所以它是值得优化的地方；但相机那25 ms 的延迟也不容忽略，而且很容易测错（[[vision-language-action/demonstration-data#ex-sync]]）。
检验：如果执行器每次新块都从它的首个动作开始执行，它就会命令机械臂回到7步之前的位置——每个块边界处都会有一次看得见的、向后的顿挫。这就是[[#sec-async]]的对齐问题。
:::
:::

### 推理硬件

推理时间要么受算术运算限制，要么受内存搬运限制（[[vision-language-action/vla-architectures#prop-flops]]）。处理观测前缀——一次成百个词元——是**算力受限**的：在达到的吞吐$F$下耗时$\approx 2P n_{\mathrm{tok}}/F$。生成少量词元，或在少量词元上跑一个小动作专家，是**内存受限**的：每趟耗时$\approx bP/W$，其中$b$为每个权重的字节数、$W$为内存带宽。一家公司会考虑的两种硬件，主要就在这两个数字与功耗上不同：

- 放在机器人旁边的**工作站或服务器 GPU**（截至2026年，例如一张24 GB 显存、带宽约$1\,\mathrm{TB/s}$的消费级卡），用以太网连接；
- 装在机器人本体或其控制柜内的**嵌入式模块**（例如 NVIDIA 的 Jetson AGX Orin 64 GB，内存带宽约$205\,\mathrm{GB/s}$，由 CPU 与 GPU 共享），功耗只有几十瓦。

::: example 一块嵌入式模块上的3B VLA {#ex-edge}
一个 π0大小的模型（3B 骨干、0.3B 动作专家）跑在一块带宽$205\,\mathrm{GB/s}$、前缀达到$2\times10^{13}$ FLOP/s 的嵌入式模块上（此吞吐为待实测的假设）。(a) 估计788个词元（三路相机）与532个词元（两路相机）的前缀耗时。(b) 估计专家以 bf16跑10个积分步的时间。(c) 把骨干权重做4比特量化有多大帮助？
::: solution
(a) 三路相机：$2\times3\times10^9\times788/2\times10^{13} = 0.236\,\mathrm s$。两路相机：$2\times3\times10^9\times532/2\times10^{13} = 0.160\,\mathrm s$。
(b) 每趟专家权重 $0.3\times10^9\times2 = 0.6\,\mathrm{GB}$，$0.6/205 = 2.9\,\mathrm{ms}$；十个步 $29\,\mathrm{ms}$。
(c) 骨干权重按4比特：$1.5\,\mathrm{GB}$ 而不是 $6\,\mathrm{GB}$，这腾出了内存、并加快内存受限的各趟——但前缀是算力受限的，所以只量化权重几乎不改变 (a)。只有当算术本身以更低精度运行（8比特整数或8比特浮点的矩阵单元）时，它才对计算有帮助。
两路相机的合计：每块约 $190\,\mathrm{ms}$——配上1 s 的块与异步执行可以用，但反应慢。办法：更少或更小的图像、更小的骨干、编译并融合的核函数，或换服务器 GPU——同一模型在那里大约要 $60$–$80\,\mathrm{ms}$。
检验：这块嵌入式模块的带宽约为服务器 GPU 的五分之一，前缀吞吐（按假设）也约为五分之一；五倍左右的变慢正是预期的量级。
:::
:::

**量化**把权重（可能还有激活）用更少的位数存放：8比特整数或浮点数，或带分组缩放因子的4比特格式。相对 bf16，权重内存缩小 $2\times$ 或 $4\times$，内存受限的各趟按比例提速，原先装不下的模型也许就装得下了。代价是每一层里的一个近似误差：它在8比特下对语言模型基准很小，4比特下往往也很小，但它对闭环策略的影响必须实测：动作里一个小小的系统性偏倚，可能比文本基准上一点小小的下降更要紧。OpenVLA 的作者们2024年报告，4比特推理在他们的任务上保住了成功率，而在他们的实现里8比特推理反而*更慢*，因为开销——这提醒我们：速度既取决于位数，也取决于核函数。任何量化的构建在交付之前，都要用 [[vision-language-action/policy-evaluation]] 的规程评测一遍。

其他标准优化：把模型编译（图捕获、融合的注意力核函数），所有东西都留在 GPU 上（不在主机侧拷贝图像），在各积分步之间缓存前缀的键与值，在 GPU 上做图像预处理，一台服务器驱动多条臂时跨臂做批。

## 异步执行 {#sec-async}

如果执行器等每一个新块到位才动，机器人就会在每个块边界处为$t_{\mathrm{lat}}$停顿一次。标准的修法是当前块还在执行时就开始下一个块的推理。

::: algorithm 异步的块执行 {#alg-async}
1. 在时刻$t_0$采集一次观测并开始推理；把得到的块$\mathbf A = (a_0, \dots, a_{H-1})$标上其观测的时间戳$t_0$。
2. 块在$t_0 + t_{\mathrm{lat}}$到达时，丢弃它的前$d = \lceil t_{\mathrm{lat}}f\rceil$个动作——它们对应已经过去的时间——并从$a_d$起继续执行。
3. 当前块已执行$h$个动作时启动下一次推理，$h$的选取要使$h/f\ge t_{\mathrm{lat}}$再加一个余量——下一个块必须赶在当前块用完之前到达（$d + h\le H$）。
4. 每次切换时，在几步之内把新旧块混合，或使用实时分块（见下），使指令的轨迹保持连续。
5. 当前块用完时若还没有新块到达，就以受控减速保持位置，绝不外推。
:::

::: example 对齐动作块 {#ex-align}
设$t_{\mathrm{lat}} = 123\,\mathrm{ms}$、$f = 50\,\mathrm{Hz}$、块长$H = 50$，求 (a) 每个新块要丢弃多少个动作；(b) 允许对延迟留50%余量时，保证新块在旧块用完之前到达的最短执行时域$h$；(c) GPU 的推理占空比。
::: solution
(a) $d = \lceil0.123\times50\rceil = 7$。
(b) 含余量的延迟 $1.5\times123 = 185\,\mathrm{ms}$，即 $9.2$，所以 $h\ge10$ 步（$200\,\mathrm{ms}$）。核对：$d + h = 17\le50$。
(c) $h = 10$ 时，推理每 $200\,\mathrm{ms}$ 启动一次、每次占 $90\,\mathrm{ms}$ 的 GPU 时间：45%。若 $h = 25$ 则是18%，但反应更慢。
检验：50个动作的块覆盖1 s，而其中只有第7到17步会在下一个块接管之前被执行；每个块的大部分从未被执行。这很正常：块的后半段充当一份计划，使运动保持一致，并在下一个块迟到时充当储备。
:::
:::

### 块与块之间的平滑切换

即使对齐了，相邻的块之间也不一致：新块是从更新的观测算出来的，而对生成式策略，还是从新的随机噪声算出来的——它甚至可能选了一个不同的模式（[[vision-language-action/action-representations]]）。突然切换会产生指令位置的跳变。常用的补救有三种：

- **交叉淡化**（cross-fading）：切换后的 $m$ 步内执行 $(1 - \lambda_i)\,a^{\mathrm{old}}_i + \lambda_i\,a^{\mathrm{new}}_i$，$\lambda_i$ 从0升到1。块彼此接近时简单有效，但它是在取平均，而两个不同模式的平均可能比其中任何一个都糟。
- 当推理便宜到每步都能跑一次时，用**时间维集成**（[[vision-language-action/action-representations#eq-ensemble]]）。
- 对流策略与扩散策略用**实时分块**（real-time chunking；Black、Galliker 与 Levine，Physical Intelligence，2025）。在当前块执行期间生成下一个块时，把推理延迟期间将要执行的那些动作*固定*为当前块中的值，并把重叠区域的其余部分朝当前块温和地引导——这是一个在流采样过程中用引导解决的“补全”（inpainting）问题，无需重训模型。于是新块与机器人正在做的事一致，从而延续同一个运动、同一个模式。作者们报告了更平滑、更快的执行，以及对大推理延迟的鲁棒性。

## 插值到控制器频率 {#sec-interp}

关节位置控制器每 $1\,\mathrm{ms}$（或 $2\,\mathrm{ms}$、$4\,\mathrm{ms}$）要一个设定点；策略每 $20$–$100\,\mathrm{ms}$ 才给一个。把每个策略目标作为阶跃发出，控制器就会看到一个突发的误差，而它的响应——一记转矩脉冲——会激起振动、磨损减速器。目标必须插值。

::: example 线性插值及其速度台阶 {#ex-interp}
某关节收到 $50\,\mathrm{Hz}$ 的策略目标：$t = 0$、$0.02$ 与 $0.04\,\mathrm s$ 时为 $0$、$0.010$ 和 $0.030\,\mathrm{rad}$，控制器以 $1\,\mathrm{kHz}$ 运行。(a) 用线性插值，每个区间内的指令速度是多少，$t = 0.02\,\mathrm s$ 时会发生什么？(b) 过这些目标作一条三次样条能换来什么？
::: solution
(a) 每个20 ms 的区间分成20个设定点。速度 $0.010/0.02 = 0.5\,\mathrm{rad/s}$，随后 $0.020/0.02 = 1.0\,\mathrm{rad/s}$。在 $t = 0.02\,\mathrm s$ 处，速度在一个1 ms 的控制器节拍内跳变 $0.5\,\mathrm{rad/s}$——相当于一个节拍的指令加速度 $0.5/0.001 = 500\,\mathrm{rad/s^2}$，即一记冲击。每秒这样重复50次，就是对机械臂的50 Hz 激励。
(b) 同样过这些目标的三次样条（[[robotics/trajectory-planning]]）在节点处速度与加速度连续，所以控制器看到的是一条平滑的参考；加速度由目标序列的弯曲程度而非节拍长度来限定。代价是延迟：过一点作样条需要下一个点，所以在*最后两个*已收到的目标之间插值会加上一整个策略周期（20 ms）的延迟。替代做法：对目标做低通滤波，或使用对每个新目标在线跟踪的加加速度受限的轨迹生成器。
:::
:::

::: widget interpolation
points: 0, 0; 1, 0.01; 2, 0.03; 3, 0.06; 4, 0.075; 5, 0.08
method: spline
x: 0, 5
y: -0.01, 0.1
caption: 策略以50 Hz 给出的关节目标（横轴一个单位 = 一个20 ms 的策略步；纵轴以 rad 计），以及过它们的自然三次样条——插值器以1 kHz 采样的就是这一类曲线。拖动一个点来模拟带噪声的策略输出，看样条如何平滑地弯曲；把方法切成线性的（在 Lab 里切换），看看那些变成速度台阶的拐角。
:::

## 安全层 {#sec-safety}

策略是一个不可信的指令来源。在它之下，一个确定性的、简单而可测试的层按控制器频率对每一条指令施加限制，无论策略做什么都照限不误。它不取代机器人的安全额定功能——那些功能必须始终与这整套软件相互独立——而是从一开始就不让策略的错误走到它们面前。

::: definition 安全滤波器 {#def-filter}
**安全滤波器**是在指令设定点送往机器人控制器之前对其施加的一个函数，它 (i) 把任何指令映射成一个满足已组态限制的指令——带余量的关节行程范围、关节速度、加速度与加加速度限制、笛卡儿工作空间边界与禁入区、工具速度限制、夹爪力限制——并且 (ii) 在某个限制无法通过修改指令满足时、在某个测量量（力、转矩、跟踪误差）超过其阈值时、或当指令流停止到达时，触发一次受控停止。
:::

::: algorithm 每节拍的安全滤波器 {#alg-filter}
每个控制器节拍，给定上一个安全的设定点$\mathbf q_{k-1}$与速度$\dot{\mathbf q}_{k-1}$、请求的设定点$\mathbf q^{\mathrm{req}}_k$与节拍$\Delta t$：
1. **看门狗**：若超过$T_{\mathrm{wd}}$（例如2–3个策略周期）没有有效指令到达，转入受控停止。
2. **有效性**：拒绝非有限值与超出关节范围（带余量）之外的指令；把其钳制回范围内。
3. **速度**：$\dot{\mathbf q}^{\mathrm{req}} = (\mathbf q^{\mathrm{req}}_k - \mathbf q_{k-1})/\Delta t$；把*整个向量*乘以 $s = \min\bigl(1, \min_i \dot q_{i,\max}/\lvert\dot q^{\mathrm{req}}_i\rvert\bigr)$ 进行缩放，使运动的方向保持不变。
4. **加速度**：以同样的方式限制每个节拍的速度变化。
5. **工作空间**：用正运动学算出工具位姿（以及连杆上的点）；若下一个设定点会离开允许区域或进入禁入区，就停止该方向的运动，或干脆停止。
6. **力与跟踪**：若测得的外力或外力矩、或跟踪误差超过其阈值，触发保护性停止。
7. 发出$\mathbf q_k$，并记录滤波器的任何一次干预。
:::

::: example 保持方向的速度限制 {#ex-vel}
一个策略对三个关节请求关节速度 $(1.2, 0.3, -2.0)\,\mathrm{rad/s}$，三个关节的限制为 $(1.0, 1.0, 1.5)\,\mathrm{rad/s}$。比较逐关节钳制与对整个向量缩放。
::: solution
钳制：$(1.0, 0.3, -1.5)$。关节之间的比例改变了（关节2现在相对更快了），所以工具将沿*不同的路径*运动，而不只是变慢。
缩放：$s = \min(1/1.2,\ 1/0.3,\ 1.5/2.0) = \min(0.833, 3.33, 0.75) = 0.75$，得 $(0.90, 0.225, -1.50)\,\mathrm{rad/s}$。每个关节按同一比例放慢，所以路径不变，只有速度下降。
检验：缩放之后，最受限的关节（关节3）恰好到达限制，其余关节都在各自限制之下。对一条直线的笛卡儿运动，缩放保持直线；钳制则会把它掰弯——可能掰向策略本来在避开的障碍物。
:::
:::

::: proposition 停止距离 {#prop-stop}
一个以速度$v$运动的工具，在反应时间$t_r$（检测、通信与控制器延迟）之后以恒定减速度$a$开始制动，将前行
$$
s_{\mathrm{stop}} = v\,t_r + \frac{v^2}{2a}
$$ {#eq-stop}
才停下。工作空间边界与禁入区至少要在物理边界之前$s_{\mathrm{stop}}$（再加上工具自身的尺寸与一个余量）处强制生效。
:::

::: proof
在$t_r$内速度为$v$，走过$v\,t_r$。在恒定减速度$a$下从$v$减到0：$v^2 = 2as$（由$v\,dv = -a\,ds$积分而得），所以制动距离为$v^2/(2a)$。两者相加即总距离。一个比$s_{\mathrm{stop}}$更贴近障碍物的边界，无论滤波器做什么都无法阻止以速度$v$发生接触。
:::

::: example 工作空间边界的余量 {#ex-stop}
某臂的工具在夹具附近最高可以$0.5\,\mathrm{m/s}$运动。滤波器的反应时间是$20\,\mathrm{ms}$，该臂在工具端能以$5\,\mathrm{m/s^2}$制动。(a) 求停止距离。(b) 在$1.0\,\mathrm{m/s}$下重做一遍。(c) 如果停止由策略服务器发现问题来触发、反应时间$100\,\mathrm{ms}$，结果如何？
::: solution
(a) $0.5\times0.02 + 0.5^2/(2\times5) = 0.010 + 0.025 = 0.035\,\mathrm m = 35\,\mathrm{mm}$。
(b) $1.0\times0.02 + 1.0/10 = 0.020 + 0.100 = 0.120\,\mathrm m$——速度翻倍，距离却是原来的三倍半，因为制动项按 $v^2$ 增长。
(c) 在$0.5\,\mathrm{m/s}$下：$0.05 + 0.025 = 0.075\,\mathrm m$。非实时进程里的反应时间使距离翻倍；这就是限制要在实时层里强制生效、而不是交给策略服务器的原因。
检验：这些数字是一只手的大小，这就是为什么在人附近允许的速度要由标准与风险评定限定，也为什么协作运行要依靠力与速度的限制（ISO/TS 15066）以及速度与间隔监控。
:::
:::

::: widget plot
f: x*t + x^2/(2*a)
x: 0, 2
y: 0, 0.6
sliders: t=0.005:0.005:0.2; a=1:0.5:15
labels: s_{\text{stop}}\ (\text{m})
caption: 停止距离随工具速度$v$（m/s）的变化，反应时间$t$（s）、减速度$a$（m/s²）。把$t = 0.02$、$a = 5$设好，在0.5 m/s 处读出35 mm；然后把$t$升到0.1 s——那相当于由非实时进程请求停止的情形——看着曲线变陡。高速时二次的制动项占主导；低速时反应时间占主导。
:::

滤波器之外还有：

- **急停**：一个硬接线、安全额定的功能（对 IEC 60204-1的0类或1类，要求见 ISO 13850与 ISO 10218），在所有计算机都失效时仍然工作。任何软件停止、更遑论策略的一个“停止”输出，都不是急停。
- 在机器人的安全控制器里做**安全额定的监控**：安全速度、安全区域、安全转矩关断、碰撞检测。为学习策略的运行把这些组态得保守一些，独立于滤波器的限制。
- **夹爪**：限制夹持力与闭合速度；检测被抓物体的意外丢失。
- **人附近的速度**：对协作应用，力、压力与速度的限制来自风险评定与 ISO/TS 15066；学得的策略不改变它们。

::: quiz
一个策略偶尔输出一个越过允许工作空间边界30 cm 的目标。哪种响应应当归安全滤波器来做？
- [ ] 重训策略直到它不再这样，然后取消工作空间检查。
- [x] 在工作空间边界处把运动钳制或停住（按至少一个停止距离的余量强制生效），记录该事件并上报分析。
- [ ] 把它交给控制器，反正机器人自己的关节限位会拦下它。
::: solution
无论策略越界多么罕见，滤波器都必须强制边界；重训可以降低频率，却永远证明不了它为零。关节限位保护不了关节范围之内的那些夹具和人。把事件记录下来，策略的失败才看得见。
:::
:::

## 监控与故障处理 {#sec-monitor}

一个部署了的策略会以评测没有展示过的方式失败。监控使失败可见，并使失败可以恢复。

**要记录什么**，每个回合都要：观测（以降低了的频率）、块与实际执行的动作、推理延迟、滤波器的干预、力的读数、操作员的干预、结果。这些日志就是下一轮的训练与评测数据（[[vision-language-action/imitation-learning#alg-dagger]]）。

值得盯住的**在线信号**：

- **延迟**与错过截止（GPU 因热降频、后台进程）；
- **滤波器活动**：一个经常被修剪的策略，正运行在它的训练分布之外；
- **样本之间的分歧**：从一个生成式策略抽出几个块并度量它们的散布，得到一个廉价的不确定性信号——在示范本应一致的地方散布很大，提示状态陌生；
- **进度**：好几秒里场景没有变化（策略卡死），或反复尝试同一个抓取；
- **分布外输入**：图像嵌入相对训练集的距离、光照或相机位姿的变化。

**故障处理**应当被设计成策略外围的一台小状态机：同一步重试有限的次数；退回到程序化的恢复动作（张开夹爪、收回到安全位姿）；向操作员求助并附上对状态的清楚描述；什么都不管用时就安全停机。让新的策略先跑**影子模式**（shadow mode）——与在役系统并行计算动作但不执行——以及在机群上逐步铺开，是降低更新风险的标准做法。

::: example 一份部署检查清单 {#ex-checklist}
你公司即将在客户的机械臂上运行一个微调后的 VLA，做有人监督的试运行。按层分组，列出在第一个自主回合之前要做的检查。
::: solution
**模型**：检查点、归一化统计量与具身形态名匹配；量化构建经过闭环评测；延迟在目标硬件上实测（中位数与99分位）。**执行器**：块的对齐使用观测时间戳；混合或实时分块已启用；块迟到时的行为是受控保持。**插值器**：在控制器频率下平滑（样条或加加速度受限）；通过记录设定点来验证。**安全滤波器**：带余量的关节范围、速度与加速度限制（向量缩放）、工作空间与禁入区至少设在内边界之内一个停止距离处、力阈值、看门狗；每条限制都靠注入违规指令来测试。**机器人安全**：急停已测；安全控制器的区域与速度已组态；该单元的风险评定已做。**运行**：操作员已培训，使能装置或急停触手可及；日志已开；故障状态机已测；可回滚到上一版本。
:::
:::

::: history
工业机器人控制器从来都把运动生成与安全监督分开的：关节限位、速度监控与急停早在学得的策略出现之前就是标准配置。“安全滤波器”的思想——对来自不可信控制器的指令做最小的修改——在2010年代通过控制屏障函数在控制理论中被形式化。学得的策略的部署遇上实时约束，是在大模型到来之时：RT-2（2023）在云端硬件上以几赫兹跑它最大的模型；OpenVLA（2024）研究了为单 GPU 推理做量化；π0（2024）用动作分块与一个小动作专家达到50 Hz 的动作频率；2025年则带来了异步与实时分块方法，以及一批设计为跑在机器人上的小型开放模型，例如 Hugging Face 的 SmolVLA。
:::

::: summary
- 栈：传感器 → 策略服务器 → 块执行器 → 插值器 → 实时安全滤波器 → 机器人控制器与相互独立的安全控制器。
- 延迟是采集、预处理、推理与通信之和；前缀算力受限，小趟内存受限；权重量化对内存受限的部分有帮助，且必须闭环验证。
- 异步执行：丢弃每个新块里 $\lceil t_{\mathrm{lat}}f\rceil$ 个过时的动作，足够早地启动下一次推理，并把各块混合（交叉淡化、时间维集成或实时分块）。
- 用平滑（样条或加加速度受限）的参考把策略目标插值到控制器频率；线性插值会产生速度台阶。
- 策略之下的安全滤波器强制关节、速度（向量缩放）、加速度、工作空间与力的限制，外加看门狗；边界至少设在 $s_{\mathrm{stop}} = vt_r + v^2/(2a)$ 之内。急停与安全额定的功能是独立的硬件。
- 监控延迟、滤波器活动、样本分歧与进度；用带上限的重试、程序化恢复、向操作员求助与安全停机来处理故障。
:::

## 习题

::: exercise 过时的步数 {#exr-stale level=1 check="5"}
设$t_{\mathrm{lat}} = 95\,\mathrm{ms}$、动作频率$50\,\mathrm{Hz}$，一个新块必须丢弃多少个动作？（填入数字。）
::: solution
$\lceil0.095\times50\rceil = \lceil4.75\rceil = 5$。
:::
:::

::: exercise 停止距离 {#exr-stop level=1 check="0.0405"}
一个工具以$0.3\,\mathrm{m/s}$运动；反应时间$15\,\mathrm{ms}$；减速度$1.25\,\mathrm{m/s^2}$。求停止距离。（以 m 计。）
::: solution
$0.3\times0.015 + 0.09/2.5 = 0.0045 + 0.036 = 0.0405\,\mathrm m$。
:::
:::

::: exercise 内存受限的一趟 {#exr-mem level=1 check="4"}
一个4亿参数、以 bf16运行的动作网络跑在带宽$200\,\mathrm{GB/s}$的器件上。每趟最短耗时是多少？（以 ms 计。）
::: solution
$0.4\times10^9\times2/(200\times10^9) = 0.004\,\mathrm s = 4\,\mathrm{ms}$。
:::
:::

::: exercise 速度缩放因子 {#exr-scale level=2 check="0.6"}
请求的关节速度为 $(0.5, -2.5, 1.0)\,\mathrm{rad/s}$，限制为 $(1.5, 1.5, 1.5)\,\mathrm{rad/s}$。求缩放因子$s$。（填入数值。）
::: solution
$s = \min(1, 1.5/0.5, 1.5/2.5, 1.5/1.0) = \min(1, 3, 0.6, 1.5) = 0.6$；缩放后的向量为 $(0.3, -1.5, 0.6)\,\mathrm{rad/s}$。
:::
:::

::: exercise 最短执行时域 {#exr-horizon level=2 check="6"}
一个 $30\,\mathrm{Hz}$ 的策略有 $160\,\mathrm{ms}$ 的观测到动作延迟。对延迟留20%的余量，最小的执行时域$h$（以步计）是多少，才能保证下一个块按时到达？（填入数字。）
::: solution
含余量的延迟 $1.2\times160 = 192\,\mathrm{ms}$；$h\ge0.192\times30 = 5.76$，所以 $h = 6$ 步（$200\,\mathrm{ms}$）。若不留余量，$h = 5$ 勉强够用（$167\,\mathrm{ms}$），但容不下任何一次慢推理。
:::
:::

::: exercise 占空比 {#exr-duty level=2 check="0.3"}
推理耗时 $60\,\mathrm{ms}$，每 $h = 10$ 步在 $50\,\mathrm{Hz}$ 下启动一次。GPU 有多大的时间份额忙于推理？（填入一个分数。）
::: solution
周期 $10/50 = 0.2\,\mathrm s$；$0.06/0.2 = 0.3$。
:::
:::

::: exercise 两个模式的交叉淡化 {#exr-fade level=3}
用一个数值例子说明，为什么在障碍物附近对一个扩散策略的两个相邻块做交叉淡化是危险的，并为执行器提出一条规则。
::: solution
设旧块在 $y = -0.10\,\mathrm m$ 处越过障碍物，新块从不同的噪声采样、在 $+0.10\,\mathrm m$ 处过（障碍物占 $\pm0.05\,\mathrm m$）。10步的线性交叉淡化会经过 $\lambda = 0.5$，指令 $y = 0$——正落在障碍物里面——恰是[[vision-language-action/imitation-learning#ex-obstacle]]里那种取平均的失败。规则：只有当两个块在重叠段上彼此一致到某个容差以内时才混合（否则继续执行旧块并重新规划）；更好的办法是生成新块时把正在执行的那些动作作为条件（实时分块），使它延续同一个模式；并让安全滤波器的禁入区兜住剩下的问题。
:::
:::

::: exercise 一次部署设计评审 {#exr-review level=3}
一个团队提议在客户的仓库里为一个机械臂机群在云上跑一个7B VLA，通过互联网发送图像、接收动作。评审这个提案：延迟及其波动、网络的故障模式、安全架构、隐私、成本，以及一个替代方案。
::: solution
延迟：互联网的往返会添上几十到几百毫秒，且带有沉重的长尾；决定执行时域的是99分位而非中位数，所以机器人反应会慢，并且必须能挺过很长的空档。故障模式：断网必须让本地执行器与滤波器转入受控保持或后撤，绝不能拿着过时的块继续运动；看门狗必不可少。安全：滤波器、工作空间边界与急停都留在本地，独立于云端。隐私：客户场所的相机图像离开现场——需要取得同意，并规定加密与留存。成本：每条臂的 GPU 时间与带宽（压缩后的图像每秒几帧）。替代方案：双系统的拆分，本地一个快策略、远端一个慢模型（[[vision-language-action/vla-architectures#def-dual]]），或者一个更小、经蒸馏或微调、能跑在本地部署的 GPU 上的模型，云端只用于日志、训练与偶尔的高层规划。
:::
