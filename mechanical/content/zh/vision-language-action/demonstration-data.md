行为克隆策略永远好不过它的数据。[[vision-language-action/imitation-learning]]讲清了数据必须包含什么——一致的动作、对机器人将要到达之状态足够的覆盖、从小误差中恢复——本章讲的是如何得到它。这部分工作不如设计网络光鲜，却是一个真实机器人学习项目里投入最多的地方：搭一套操作员能连续用几个小时的遥操作台、写清规程使示范彼此一致、以正确的时间戳记录相机与关节数据、存储数百小时的视频，并把一切整理成训练代码和别的团队都能读的格式。

我们先看人驾驶机械臂的几种方式——拖动示教、6自由度输入设备、虚拟现实与主从臂——并按速度、精度与所产数据的质量比较它们。然后定义一条示范回合必须记录什么，讨论数据质量与一个任务需要多少示范，并算一遍多相机系统的存储与带宽账。本章末尾介绍常见的数据集格式（RLDS、LeRobot 格式、HDF5），以及大多数通用策略在其上预训练的大规模共享数据集——Open X-Embodiment 与 DROID。

## 示范的方式 {#sec-teleop}

示范必须产生*机器人*动作：策略日后要输出的关节或末端执行器指令。人与机器人之间的接口决定了示范有多自然、有多快、以及记录的动作是否是机器人真能执行的那些。

::: definition 遥操作与拖动示教 {#def-teleop}
在**拖动示教**（kinesthetic teaching）中，操作员徒手移动机械臂，臂同时运行在柔顺、重力补偿的模式下，记录其关节轨迹。在**遥操作**（teleoperation）中，操作员移动一个输入设备，机器人跟随；设备可以指末端执行器的位姿或速度（空间鼠标、VR 控制器、手部跟踪），也可以直接指关节角（一对**主从**臂：操作员移动*领航*臂，*随动*机器人复制其关节角）。若信息只从操作员流向机器人，遥操作是**单向的**；若机器人处测得的力被反馈给操作员，则是**双向的**。
:::

**拖动示教**在带关节力矩传感或良好电流式重力补偿的机械臂上不需要任何额外硬件，对慢而精确的动作也很直观。但对基于视觉的学习，它的缺点相当严重：操作员的手和身体会出现在相机图像里（测试时策略永远见不到这样的图像）、能舒服地引导的只有单臂，而且臂的摩擦与惯性使快速或精细的动作很累人。它在示教路径点和低维技能上仍然好用。

**空间鼠标与游戏手柄**遥操作把一个6自由度旋钮的偏转映射成末端执行器速度旋量，再由笛卡尔控制器（或微分逆运动学回路，[[robotics/jacobians]]）换算为关节速度。硬件便宜、数据干净，但平移与旋转同时进行很难控制，操作员倾向于一次动一个轴，产出缓慢的“阶梯形”示范。空间鼠标数据是 robomimic（2021）等早期机器人学习基准的标准做法。

**虚拟现实**遥操作跟踪一个手持控制器（或手本身）的位姿，再经逆运动学映射为末端执行器位姿。它对伸手与粗大动作快速而自然；大规模数据集 DROID 就是用消费级 VR 控制器采集的。它的短处是没有力反馈、人臂运动学与机器人不匹配（控制器可以被移到机器人达不到的位姿，或穿过一个奇异位形），以及隔着头显或显示器看深度的困难。

**主从**式采集台用一条运动学相似的第二臂作输入设备。由于领航臂的关节与随动臂一一对应，没有逆运动学、没有奇异位形的意外，操作员还能直接感到臂的构型——包括冗余、肘的位置与关节限位。ALOHA（Zhao、Kumar、Levine 与 Finn，2023）用两对小而廉价的机械臂做穿扎带、装电池之类的双臂任务；GELLO（Wu 等，2023）用3D 打印的商品臂缩比复制品，配仅作关节编码器用的舵机，一套的零件成本几百美元（2023年时）。截至2026年，精细双臂任务的数据采集大多使用主从式采集台。一个相关的想法是通用操作界面（Universal Manipulation Interface，UMI，Chi 等，2024）：干脆去掉机器人——操作员手持一个装着广角相机的夹爪，其位姿由视觉 SLAM 跟踪，记录的轨迹之后再重定向到装有同款夹爪与相机的机器人上。

| 接口 | 硬件成本 | 速度 | 精度 | 双臂 | 主要数据问题 |
|---|---|---|---|---|---|
| 拖动示教 | 无需额外 | 慢 | 好 | 难 | 人出现在图像里 |
| 空间鼠标 | 极低 | 慢 | 好 | 难 | 一次只动一个轴 |
| VR 控制器/手部跟踪 | 低 | 快 | 中 | 可 | IK 失配、无力反馈 |
| 主从式 | 中等 | 快 | 好 | 可 | 每种臂都要一套领航臂 |
| 手持夹爪（UMI 式） | 低 | 快 | 好 | 可 | 重定向、机器人在回路之外 |

::: example 空间鼠标的速度标定 {#ex-spacemouse}
某空间鼠标逐轴报告$-350$到$350$之间的整数平移偏转量。遥操作软件把满偏转映射为$0.20\,\mathrm{m/s}$，设$\pm 20$个计数的死区，策略将以$10\,\mathrm{Hz}$在末端执行器增量上训练。求 (a) 速度分辨率，(b) 每个策略步的最大增量，(c) 最小非零速度，以及 (d) 满偏转下一次$0.30\,\mathrm m$的伸手需要多久。
::: solution
(a) $0.20\,\mathrm{m/s}/350 = 5.7\times10^{-4}\,\mathrm{m/s}$每计数。
(b) 在$10\,\mathrm{Hz}$下，$\Delta x_{\max} = 0.20 \times 0.1 = 0.020\,\mathrm m = 20\,\mathrm{mm}$每步——它为任何动作归一化或分箱定了范围（[[vision-language-action/action-representations]]）。
(c) 刚出死区处，$21 \times 5.7\times10^{-4} = 0.012\,\mathrm{m/s}$，即每步1.2 mm。比这更小的指令会被记录为精确的零，于是在慢而精细的阶段产生大量一模一样的零动作。
(d) $0.30/0.20 = 1.5\,\mathrm s$，但操作员很少保持满偏转；3–5 s 更典型。
检验：10 Hz 下每步20 mm 只是温和的$0.2\,\mathrm{m/s}$，远在与人协作的机械臂的速度限制之内。
:::
:::

### 领航关节到随动关节的映射

主从式采集台需要一个从领航臂编码器读数到随动臂关节角的标定：对每个关节$i$，$q^{\mathrm F}_i = s_i\,(q^{\mathrm L}_i - q^{\mathrm L}_{i,0}) + q^{\mathrm F}_{i,0}$，其中符号$s_i = \pm1$（编码器可能反向安装），偏移量则在双臂摆成同一参考位姿时测得。随动臂的关节位置控制器按自己的伺服频率跟踪$q^{\mathrm F}$。夹爪通常还需要一个独立的非线性映射，从领航臂的扳机或手柄映到随动臂的指宽。若领航臂是缩比复制品，关节*角度*仍一一对应（缩放长度不改变角度），但操作员的手速会按领航臂的尺度缩小。

::: warning 记录指令还是测量值
一份遥操作日志里有两处都可当“动作”的候选：发给随动机构的*指令*（来自领航臂或设备），以及片刻后随动机构的*实测*位置。二者相差随动控制器的跟踪误差与延迟——快速运动时可达数度。策略将要输出的是指令，所以动作标签通常应当是指令；实测位置属于观测。把两者混用，或把$t+1$的实测位置当作$t$的动作来用，会训练出一个输出滞后或欠程的策略。
:::

## 示范必须记录什么 {#sec-episode}

::: definition 回合记录 {#def-episode}
一条示范**回合**以带时间戳的**步**序列加上回合级**元数据**存储。每一步包含观测（相机图像、关节位置与速度、夹爪状态，以及可选的力-扭矩与触觉读数）、该步发出的动作指令、来自统一时钟的时间戳，以及标记第一步与最后一步、并指明最后一步是否真正是终止状态的标志位。元数据包括语言指令、成功标签、机器人与夹爪型号、控制与记录频率、相机的内参与外参标定、动作空间及其单位与坐标系、操作员与日期，以及软件版本。
:::

元数据是最常被省掉、也最常让人后悔的部分。没有动作坐标系（基坐标系还是末端执行器？米还是毫米？增量还是绝对？）的数据集无法与其他数据合并；没有相机外参的数据集无法用于任何三维推理方法。一年后，没有人记得哪些回合是在腕部相机被挪动之前录的。

### 时间与同步

相机、关节控制器与遥操作设备运行在不同的时钟上、不同的速率下——比如相机每秒30帧、关节状态500 Hz–1 kHz、策略10–50 Hz。记录器必须用统一时钟给每个样本打时间戳，然后把它们**对齐**：对每个策略步，取最新的图像、图像拍摄时刻的关节状态，以及该步发出的动作指令。相机帧因曝光、传输与解码而延迟——通常几十毫秒——所以拍摄时刻不是到达时刻。

$$
e_{\mathrm{sync}} \approx v\,\Delta t_{\mathrm{sync}}
$$ {#eq-sync}

图像所示与本体感知所述之间的几何失配，就是末端执行器速度乘以计时误差，[[#eq-sync]]。

::: example 一个要紧的相机延迟 {#ex-sync}
某腕部相机的帧在拍摄后$60\,\mathrm{ms}$才到达，而记录器按到达时刻打戳。示范期间夹爪的移动速度最高$0.30\,\mathrm{m/s}$。图像与关节状态之间的失配有多大？对容差为$\pm 3\,\mathrm{mm}$的抓取可以接受吗？
::: solution
$e = 0.30\,\mathrm{m/s}\times0.060\,\mathrm s = 0.018\,\mathrm m = 18\,\mathrm{mm}$——抓取容差的六倍。在缓慢的最后接近段，速度也许只有$0.03\,\mathrm{m/s}$，失配降到$1.8\,\mathrm{mm}$，所以损害主要在快速阶段；但策略在测试时也会看到这个失配，而不一致的延迟（$\pm 20\,\mathrm{ms}$的 USB 抖动）是学不掉的。解决办法：测量延迟（把快速闪烁的 LED 或转动的编码器码盘与关节数据一起拍下来），用拍摄时刻给每帧打戳，或使用硬件触发的相机。检验：30 fps 下一帧是$33\,\mathrm{ms}$，所以60 ms 的误差就是两帧——把图像与关节曲线并排回放时一目了然。
:::
:::

## 数据质量 {#sec-quality}

策略会照抄示范的一切，包括示范者无心展示的东西。来自大规模训练操作策略的团队的经验收敛到几条规则。

1. **策略的一致性。**对给定情形，除非想要多样性，示范者应当使用同一种策略。源自操作员个人习惯的多峰性（有人总是从左边抓）会消耗模型容量，并可能把较弱策略头搞糊涂。一份书面规程加上每个操作员的简短培训会有帮助；记录每个回合由谁采集、以便比较各操作员的数据同样有帮助。
2. **停顿与空转。**任务中途犹豫的操作员会教策略犹豫——而停住的机器人产生一成不变的图像，策略可能永远卡在那个状态（观测说“还没发生任何事”，标签说“什么都不做”）。剪掉每回合开头与结尾的空转帧；回合内部，要么滤掉动作接近零的长段落，要么只在它是任务一部分（等机器）时保留。
3. **速度。**策略会复制示范的速度。慢而小心的示范给出慢的策略；过快的则不一致。稳定适中的节奏最好，并在要紧之处安排缓慢精细的阶段。有些部署会以比录制更快的速度重放动作块，代价是准确率。
4. **初始条件的多样性。**物体位置、朝向、干扰物、光照、桌面纹理与相机摆放，都应在策略必须应付的范围内变化——并记录下来以便检查覆盖情况。已有研究发现，模仿学习的泛化更取决于不同环境与物体的数量，而非每个环境的示范条数（例如 Lin 等，2024，《Data scaling laws in imitation learning》）。
5. **成功、失败与标签。**保留失败的回合但要打上标签；它们作为 BC 目标毫无用处，但对评测、训练成功检测器以及某些强化学习方法很有价值。操作员认为糟糕的回合要标注出来。
6. **硬件稳定性。**相机要刚性固定并定期复查标定；被撞过的场景摄像头会悄无声息地改变观测分布。

::: example 数据集里的空转帧 {#ex-idle}
一个300条回合的数据集平均每条$25\,\mathrm s$、以10 Hz 记录。平均而言，每条回合开头有$2.5\,\mathrm s$操作员做准备，结尾有$1.5\,\mathrm s$松手后的静止。训练样本对中空转的占多大比例？修剪后还剩多少数据？
::: solution
每回合$250$步；空转步$(2.5 + 1.5)\times10 = 40$，即全部样本对的$40/250 = 16\%$。修剪后每回合$210$步，$300\times210 = 63\,000$对，而非$75\,000$对。
百分之十六听起来无害，但这些全都是近乎相同的起始场景图像配*同一个*标签（零动作）——恰是策略每次测试开头都会看到的状态。在其上训练的网络可以学会“在初始场景里什么都不做”，于是永远不开始。检验：修剪后的回合平均$21\,\mathrm s$，与旁观者估计的任务用时大致相符。
:::
:::

::: quiz
你的策略在约三分之一的测试回合开头僵住；用手碰一下之后，它就能把任务做完。最可能的数据病因是什么？
- [x] 示范开头未修剪的空转帧，带着零动作标签。
- [ ] 示范总数太少。
- [ ] 相机分辨率太低。
::: solution
僵在*初始*状态、并且一碰改变了图像之后就恢复，正是开头空转帧的特征：初始图像最常见的标签是“什么都不做”。修剪它们（或丢弃回合边界处动作接近零的步）并重新训练。
:::
:::

### 需要多少示范？

没有公式，但有一些参照点，而且全都带着时代烙印，因为方法在进步、预训练模型在变强：

- **单任务、单场景、从头学**（ACT 或 Diffusion Policy，2023）：几十条到几百条示范；ACT 论文的精细双臂任务每任务用了50条。
- **把预训练 VLA 微调到已知机械臂上的新任务**（2024–26年）：报告的跨度从简单任务的几十条示范，到叠衣服这类长灵巧任务的许多小时数据。
- **跨场景与物体泛化：**不同场景与物体的数量比重复更重要；比如在30种布置下各采10条，通常胜过在一种布置下采300条。

实用的办法是渐进的：采第一批、训练、评测、看失败样本，再针对失败所在补采数据（[[vision-language-action/imitation-learning#alg-dagger]]是这一流程的形式化版本）。

::: algorithm 一次数据采集行动 {#alg-campaign}
1. 写任务规程：起始条件及其范围、允许的策略、成功判据、复位流程。
2. 标定并固定相机；测量相机到关节的计时偏移；把标定写进元数据。
3. 按规程培训操作员；采10–20条试采回合并回放（视频加关节曲线），检查同步、坐标系、单位与空转时间。
4. 采第一批（例如50–100条回合），初始条件按时间表随机化而非凭兴致。
5. 训练一个策略、评测它，并给失败分类（感知、抓取、恢复、超时）。
6. 针对性补采数据：泛化失败处加多样性，执行失败处加干预与恢复。
7. 用校验和冻结数据集版本，使每个训出的模型都能追溯到它的数据。
:::

::: example 一次行动需要的操作员时间 {#ex-time}
一次行动需要一个30 s 任务的300条示范；场景每次复位要20 s，操作员每小时需要10分钟休息（即每小时工作50分钟）。需要多少操作员小时？一个每天有效工作6小时的操作员要工作几天？
::: solution
每条示范$30 + 20 = 50\,\mathrm s$；$300\times50 = 15\,000\,\mathrm s = 4.17\,\mathrm h$的有效工作。按每小时50个工作分钟计，$4.17\times60/50 = 5.0$操作员小时。再留出约15%的回合要作废（失败、失误），$5.0/0.85 = 5.9\,\mathrm h$——约一个操作员的一个工作日。
检验：*录下来*的数据只有$300\times30\,\mathrm s = 2.5\,\mathrm h$，可见复位与杂项开销几乎使成本翻倍。把复位自动化（一个会把零件倒回去的托盘、一条负责撒开物体的第二臂）往往是换取更多数据最便宜的办法。
:::
:::

## 存储与带宽 {#sec-storage}

相机流压倒一切。$n$路宽$W$、高$H$像素、每像素3个颜色字节、帧率为$f$的相机，其原始数据率为

$$
R_{\mathrm{raw}} = n\,W\,H \times 3\,\mathrm{B} \times f .
$$ {#eq-raw}

视频压缩（H.264、H.265、AV1）以几十到几百倍压低它而几乎无可见损失，但它是有损的，而且会引入策略可能学会依赖的伪影；数据集通常存压缩视频，训练时再解码。相比之下，本体感知与动作的数据量微乎其微。

::: example 一套三路相机的系统 {#ex-storage}
某系统有三路相机（两路场景、一路腕部），均为$640\times480$、30 fps、RGB，并以500 Hz、4字节浮点数记录7个关节加夹爪的关节位置、速度与力矩。(a) 求原始相机数据率与每小时存储量。(b) 若以每路$4\,\mathrm{Mbit/s}$的 H.264压缩，求压缩后数据率与1,000小时的存储量。(c) 单个 USB 3控制器（实际吞吐约$3\,\mathrm{Gbit/s}$）足以承载未压缩的流吗？
::: solution
(a) [[#eq-raw]]：$3\times640\times480\times3\times30 = 82.9\times10^6\,\mathrm{B/s} = 82.9\,\mathrm{MB/s}$；每小时$82.9\times3600 = 2.99\times10^{11}\,\mathrm B = 299\,\mathrm{GB}$。
本体感知：$(7\times3 + 1)\times4\,\mathrm B\times500\,\mathrm{Hz} = 44\,\mathrm{kB/s} = 0.16\,\mathrm{GB/h}$——原始视频的0.05%。
(b) 压缩后：$3\times4\,\mathrm{Mbit/s} = 12\,\mathrm{Mbit/s} = 1.5\,\mathrm{MB/s} = 5.4\,\mathrm{GB/h}$，比原始低55倍。1,000小时为$5.4\,\mathrm{TB}$视频加$0.16\,\mathrm{TB}$本体感知，约$5.6\,\mathrm{TB}$——一两块硬盘而已，而原始数据需要$299\,\mathrm{TB}$。
(c) 原始：$82.9\,\mathrm{MB/s}\times8 = 663\,\mathrm{Mbit/s}$，约为$3\,\mathrm{Gbit/s}$的22%——可行，但换成$1280\times720$，同样三路相机就要$1.99\,\mathrm{Gbit/s}$，四路就会把控制器打满。许多 USB 相机因此选择板载压缩（MJPEG）。
检验：策略通常看的是5–15 Hz 的$224\times224$图像；这样三路以10 Hz 记录原始也只有$4.5\,\mathrm{MB/s}$。以高于策略所用的分辨率与帧率记录仍是明智的，因为它为将来的模型留了余地。
:::
:::

## 数据集格式 {#sec-formats}

截至2026年，三类格式家族覆盖了大多数机器人学习数据。

- **每回合一个 HDF5文件。**每条回合一整个文件，每种观测与动作流各存一个数组。简单快捷；robomimic 与最初的 ALOHA 代码在用它。图像可存原始帧或逐帧 JPEG 压缩。元数据约定则各凭各家项目自定。
- **RLDS**（Reinforcement Learning Datasets，Ramos 等，2021），构建于 TensorFlow Datasets 之上。数据集是一批*回合*（episodes）的集合，每个回合是一串*步*（steps），带有 `observation`、`action`、`reward`、`discount` 字段与 `is_first`、`is_last`、`is_terminal` 标志。回合级元数据存放在步的旁边。RLDS 是 Open X-Embodiment 的格式，因而也是众多在其上预训练的模型的格式。
- **LeRobot 数据集**（Hugging Face，2024年起）。逐回合分步的表格数据（状态、动作、时间戳、回合与帧下标）存 Parquet 文件，相机流存 MP4视频文件，另有一个描述特征、帧率与回合边界的元数据文件；数据集在 Hugging Face Hub 上共享，用 `lerobot` 库加载，该库还提供若干策略的训练代码。格式经历过多次版本变更，所以要查清某个工具期望哪一版。

无论装在外壳里的是什么，内容都与[[#def-episode]]相同。格式之间互转是常规工作；丢失的元数据却找不回来。

::: definition 具身形态 {#def-embodiment}
数据集的**具身形态**（embodiment）是记录它时所用的机械臂（运动学、关节限位）、末端执行器、相机布置与动作空间的组合。只有当动作以可比较的单位与坐标系表达，或者模型带有按具身形态区分的输入或输出头时，不同具身形态的数据才能汇在一起训练（[[vision-language-action/vla-fine-tuning]]）。
:::

## 大规模共享数据集 {#sec-shared}

直到2022年，多数实验室都用自己的数据训练，一次几百条示范。两个进展改变了局面。

**Open X-Embodiment**（2023）是众多高校与企业实验室的合作，它们把约60个已有数据集转成 RLDS 并一起发布：来自22种机器人具身形态的超过一百万条轨迹，从单臂到双臂与移动操作平台应有尽有。这些数据集在各方面都不同——动作空间、控制频率、相机布置、质量——配套的 RT-1-X 与 RT-2-X 模型表明，在混合数据上训练相比只在每台机器人自己的数据上训练，能提升单台机器人上的表现。2024年的多数开放 VLA 模型（Octo、OpenVLA）都在其子集上预训练。

**DROID**（Distributed Robot Interaction Dataset，Khazatsky 等，2024）走了相反的路：一套标准化的硬件平台——一台 Franka Panda 机械臂，配两路外部立体相机与一路腕部相机，用 VR 控制器遥操作——在北美、欧洲与亚洲的多个站点复制，在数百个不同场景中采集了约76,000条轨迹（约350小时）。它的价值在于场景与物体的多样性，配上单一而一致的具身形态。

此后又有几家公司发布或描述了自己的大规模数据集，最大的私有数据集规模据报道达数万小时（截至2026年）。对自研机械臂的企业，教训是：共享数据集是预训练的起点，而决定产品任务表现的，是产品机械臂上的内部示范数据。

::: remark 许可与隐私
共享数据集带有许可证（多为宽松许可，有时禁止商用），它们同样约束在其上训练的模型；商用前务必核查。在住宅或工厂录制的视频可能拍到人物、文件与屏幕；匿名化与知情同意要在采集之前规划，而不是之后。
:::

::: history
用示范编程与工业机器人同龄：1970与1980年代喷涂机器人的示教器与“拖动引导”示教，记录一条人手引导的轨迹再重放。而从示范学出一个*策略*——一个能对所见做出反应的策略——需要传感器与大规模数据。Google 2016年的机械臂阵列（Levine 等）用14台机器人自主采集了约800,000次抓取尝试；RT-1（2022）历时17个月采集了约130,000条遥操作示范。廉价遥操作采集台（2023年的 ALOHA 与 GELLO、2024年的 UMI）与标准格式（2021年的 RLDS、2024年的 LeRobot）使小团队也能采集并共享高质量数据，随后 Open X-Embodiment（2023）与 DROID（2024）把数据跨实验室汇到了一起。
:::

::: summary
- 示范可由拖动示教、6自由度设备、VR、主从臂或手持夹爪采集；截至2026年，精细双臂工作以主从式采集台为主。
- 记录*指令的*动作作标签、*实测的*状态作观测；用统一时钟给每个样本打戳，并校正相机延迟（失配$\approx v\,\Delta t$）。
- 回合记录需要逐步的观测、动作、时间戳与标志位，以及回合元数据：指令、成功与否、具身形态、坐标系、单位、标定。
- 质量规则：策略一致、修剪空转、速度平稳、初始条件多样且记录在案、失败要有标签、相机稳定。
- 视频主导存储：原始数据率$nWH\cdot3f$字节每秒；压缩以几十到几百倍压低它。
- 常见格式是 RLDS、LeRobot 与 HDF5；主要的开放预训练数据集是 Open X-Embodiment 与 DROID。
:::

## 习题

::: exercise 一路腕部相机的原始数据率 {#exr-raw level=1 check="27.648"}
求一路 RGB 相机在$640\times480$、30 fps 下的原始数据率。（以 MB/s 填入，取1 MB = $10^6$字节。）
::: solution
$640\times480\times3\times30 = 27\,648\,000\,\mathrm{B/s} = 27.648\,\mathrm{MB/s}$。
:::
:::

::: exercise 一次同步误差 {#exr-sync level=1 check="4"}
机械臂以$0.08\,\mathrm{m/s}$运动，图像时间戳晚了$50\,\mathrm{ms}$。求图像与关节数据的失配。（以 mm 填入。）
::: solution
$0.08\times0.050 = 0.004\,\mathrm m = 4\,\mathrm{mm}$。
:::
:::

::: exercise 压缩后的存储 {#exr-comp level=1 check="1.8"}
两路相机以 H.265、各$2\,\mathrm{Mbit/s}$记录。一小时的录制需要多少存储？（以 GB 填入。）
::: solution
$4\,\mathrm{Mbit/s} = 0.5\,\mathrm{MB/s}$；$0.5\times3600 = 1800\,\mathrm{MB} = 1.8\,\mathrm{GB}$。
:::
:::

::: exercise 空转占比 {#exr-idle level=2 check="0.125"}
回合平均长32 s，其中开头与结尾合计4 s 为空转。记录器以15 Hz 运行。空转步占比是多少？（填入小数。）
::: solution
$4/32 = 0.125$；记录速率会约掉。
:::
:::

::: exercise 每天的示范数 {#exr-perday level=2 check="360"}
一位操作员每天工作6小时，每小时有50分钟是有效工作。每条示范含复位需45 s，另有10%要作废。他每天能产出多少条可用示范？（填入数字。）
::: solution
有效时间$6\times50 = 300\,\mathrm{min} = 18\,000\,\mathrm s$；$18\,000/45 = 400$条回合，其中90%可用：每天$360$条。
:::
:::

::: exercise 选哪种接口？ {#exr-interface level=2}
你的公司要为以下任务采集示范：(a) 双臂把线缆穿过卡扣的走线任务，(b) 给码垛单元示教20个路径点，(c) 在众多不同厨房里擦拭桌面上任意位置的泼洒物。为每个任务推荐一种示范接口并论证。
::: solution
(a) 主从臂：双臂、快，关节空间映射能精确控制两条臂和冗余的肘部；走线需要协调精细的动作。(b) 拖动示教（或示教器）：任务要的是位姿而不是反应式策略，手拖是设定路径点最快的办法；不训练视觉策略，相机被污染也无妨。(c) 带腕部相机的持握夹爪（UMI 式）或便携 VR 装置：厨房的多样性比精度要紧，手持设备可以带到许多住户家中而不用搬机器人；要事先规划重定向，并检查机器人能否到达记录的位姿。
:::
:::

::: exercise 一份存储预算 {#exr-budget level=3}
一个团队计划从10套相同装置采集2,000小时数据，每套四路相机$1280\times720$、30 fps，另有1 kHz 的关节数据。估计 (a) 原始与 (b) 每路$6\,\mathrm{Mbit/s}$压缩后的存储量，(c) 若全部装置把压缩数据实时上传所需的网络带宽，以及 (d) 一个每训练一轮读一遍全量数据集、限时24 h 的训练集群所需带宽。点评这一设计。
::: solution
(a) 每套装置原始：$4\times1280\times720\times3\times30 = 332\,\mathrm{MB/s}$；2,000 h $= 7.2\times10^6\,\mathrm s$，故$332\times10^6\times7.2\times10^6 = 2.4\times10^{15}\,\mathrm B = 2.4\,\mathrm{PB}$。(b) 压缩：每录制小时每装置$24\,\mathrm{Mbit/s} = 3\,\mathrm{MB/s}$；$3\times10^6\times7.2\times10^6 = 21.6\,\mathrm{TB}$，加上关节数据（$\sim 1000\times30\times4\,\mathrm B = 0.12\,\mathrm{MB/s}$，约$0.9\,\mathrm{TB}$）：约$22.5\,\mathrm{TB}$。(c) 十套实时：$10\times24 = 240\,\mathrm{Mbit/s}$——千兆链路毫无压力。(d) $22.5\,\mathrm{TB}$在$86\,400\,\mathrm s$读完即$260\,\mathrm{MB/s} \approx 2.1\,\mathrm{Gbit/s}$的持续带宽，此外还要以该速率解码视频——瓶颈往往是解码器而非磁盘，这正是许多流水线预先解码并降采样到训练分辨率（如$224\times224$）一次然后存下来的原因。存原始数据免谈；保留压缩原件，外加一份训练分辨率缓存。
:::
:::

::: exercise 一份数据集规格书 {#exr-spec level=3}
为你的公司将在自家6自由度机械臂（配平行夹爪、一路腕部相机与一路场景相机）上录制、用于微调 VLA 的示范数据集写一份规格书（字段、单位、坐标系、速率、元数据）。每项选择简要说明理由。
::: solution
好的回答应包含：逐步字段 `timestamp`（秒，统一时钟，图像用拍摄时刻）、`observation.images.wrist` 与 `.scene`（RGB，按原始分辨率与30 fps 存为视频，内外参写入元数据）、`observation.state`（6个关节角，rad；关节速度，rad/s；夹爪开度，m）、可选的基坐标系末端执行器位姿（位置 m，姿态四元数）、`action`（关节目标指令，rad，夹爪指令，m——用绝对值，以便日后换算成增量；若遥操作是笛卡尔式的，也记录指令末端执行器位姿）、标志 `is_first`、`is_last`、`is_terminal`，以及一个 `controller` 字段（human 或 policy）用于干预数据。回合元数据：指令文本、成功标签与判定人、操作员编号、机器人序列号与固件、夹爪型号、相机序列号与标定、控制频率与各记录频率、动作空间描述（坐标系、单位、绝对/增量）、软件与数据集版本、场景描述（光照、桌面、物体）。以标准格式存储（LeRobot 或 RLDS），使开放的训练代码可以直接读。
:::
