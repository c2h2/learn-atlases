前面几章的策略把一切都从某个单一任务的几百条示范中学来——杯子长什么样、“左”是什么意思、怎样合上夹爪扣住一个把手。**视觉-语言-动作模型**（vision-language-action model，VLA）则从另一个东西出发：一个**视觉-语言模型**（vision-language model，VLM），它已经在来自网络的数十亿图像与文本上预训练过，因此本来就能识别物体、读取标签、遵循指令，并对空间关系有一些概念。机器人示范要教的只是如何*行动*。这一希望——2023–2026年的模型已将其部分证实——就是得到这样的策略：听从从未训练过的指令、应对新物体，并且能用相对较少的数据适应新任务或新机械臂。

本章剖析动作输出如何接到 VLM 上。我们先描述骨干网络——视觉编码器、投影层与语言模型——并计算它的词元数与开销。然后按时间顺序讲述几条主要设计路线：**动作即词元**（RT-2，2023；OpenVLA，2024）、**从头训练的通用策略**（Octo，2024）、带流匹配的**动作专家**（π0，2024及其后续模型），以及让慢速推理模型与快速运动模型以不同频率运行的**双系统**设计（Helix、GR00T N1与 Gemini Robotics，2025）。这个领域进展很快：这里的名字会过时，但设计问题——如何从语言模型输出连续动作、如何让它足够快、如何保住它的网络知识——不会过时。凡描述某个模型之处，描述依照其公开论文、报告或博客，并附年份。

各组件的背景见 LLM Atlas：[视觉 Transformer](/learn/llm/lesson.php?c=multimodal&l=vision-transformers)、[图文对比学习](/learn/llm/lesson.php?c=multimodal&l=contrastive-learning)、[视觉-语言模型](/learn/llm/lesson.php?c=multimodal&l=vision-language-models)与 [Transformer 块](/learn/llm/lesson.php?c=transformers&l=transformer-block)。

## 视觉-语言骨干网络 {#sec-backbone}

::: definition 视觉-语言模型与 VLA {#def-vla}
**视觉-语言模型**由三部分组成：（i）一个**视觉编码器**，通常是视觉 Transformer，它把图像切成图块并为每个图块输出一个嵌入向量；（ii）一个**投影层**，一个小型网络（常常是两层 MLP），把这些嵌入映射到（iii）**语言模型**——一个仅解码器 Transformer——的输入空间，由它把图像词元与文本词元在一起处理。**视觉-语言-动作模型**是在网络规模的图文数据上预训练、进而被进一步训练以在相机图像、一条指令以及通常还包括机器人本体感知状态为条件的情况下输出机器人动作的 VLM。
:::

VLA 中反复出现两种视觉编码器。**SigLIP**（2023）及其同族以对比方式训练来匹配图像与图注，因此捕捉*语义*——图像里有什么。**DINOv2**（2023）仅用图像以自监督方式训练，捕捉*几何与精细空间细节*。OpenVLA 的骨干（Prismatic VLM）把两者的特征拼接起来，理由是操作任务两类信息都需要。

图块大小为$p$的 ViT 把一张$N\times N$的图像变成$(N/p)^2$个词元；SigLIP 与 DINOv2在$224\times224$、$p = 14$下每张图给出$16\times16 = 256$个词元。有几路相机加上一句指令时，语言模型的输入在产生任何动作词元之前已有数百词元之长。

::: proposition 每个词元的 Transformer 开销 {#prop-flops}
对于一个权重矩阵含$P$个参数的仅解码器 Transformer，一次前向传播每个词元约需$2P$次浮点运算（FLOP），此外注意力部分对$L$层、模型宽度$d$、$n$个词元的上下文，每个词元另有$4\,L\,n\,d$量级的运算。自回归地生成一个词元需要从内存读出全部$P$个权重，所以每个权重占$b$字节、内存带宽为$W$时，其耗时至少为$bP/W$。
:::

::: proof
几乎所有的参数都在把词元激活向量$\mathbf x\in\R^k$相乘的矩阵$\mathbf W\in\R^{m\times k}$里。乘积$\mathbf W\mathbf x$需要$mk$次乘法与大约$mk$次加法，共$2mk$次 FLOP，而$mk$正是$\mathbf W$中的参数量；对所有矩阵求和即得每个词元$2P$。注意力部分每层每个词元再加上：查询与$n$个键中每一个的点积（$2nd$次 FLOP）、$n$个值的加权和（$2nd$次 FLOP），合计$4nd$。至于时间下界：要产生一个新词元，整个网络要被完整求值一次，所以每个权重都至少要从内存搬运到运算单元一次；每个权重占$b$字节就是$bP$字节，至少需要$bP/W$秒。当成批的词元一起处理时（提示词，或一个批次），每次读出的权重被每个词元复用，计算转而受算术限制。
:::

::: example 一个70亿参数 VLA 的词元数与内存 {#ex-backbone}
一个语言模型有70亿参数的 VLA 接收一张$224\times224$图像（256个词元）与一条30词元的指令。(a) 求以16位（bf16）和4位格式存放权重所需的内存。(b) 估计处理提示所需的耗时（按达到的$10^{14}$ FLOP/s），以及 bf16下内存带宽为$1\,\mathrm{TB/s}$时每个生成词元的耗时。(c) 若每步7个动作词元，能达到怎样的控制频率？
::: solution
(a) bf16：$7\times10^9\times2\,\mathrm B = 14\,\mathrm{GB}$。4位：$3.5\,\mathrm{GB}$（另有存放缩放因子的少量额外开销）。
(b) 提示：$2\times7\times10^9\times286 = 4.0\times10^{12}\,\mathrm{FLOP}$，即$40\,\mathrm{ms}$。每个生成词元：读出权重至少需$14\times10^9/10^{12} = 14\,\mathrm{ms}$。
(c) 一个动作：$40 + 7\times14 = 138\,\mathrm{ms}$，最佳情形约$7\,\mathrm{Hz}$；实际实现还有额外开销。
检验：OpenVLA 的作者报告2024年在单张消费级 GPU 上控制频率为几 Hz，与此估计一致。瓶颈是动作词元的*串行*解码；若在一次前向中输出整个动作，可省下$6\times14 = 84\,\mathrm{ms}$。
:::
:::

## 动作即词元：RT-2与 OpenVLA {#sec-tokens}

**RT-2**（Google DeepMind，2023年7月）提出了视觉-语言-动作模型一词。其前提是：只要把动作写成文本，VLM 无需改动架构就能被微调来输出动作。每个动作维度被离散化为256个箱（[[vision-language-action/action-representations#def-binning]]），箱编号写成词元；模型在机器人轨迹与原始网络视觉-语言任务（视觉问答、图像描述）的混合数据上被**联合微调**（co-fine-tuned），以免忘记网络知识（[[vision-language-action/vla-fine-tuning]]）。RT-2构建在两个 VLM 之上：PaLI-X（50亿与550亿参数）和 PaLM-E（120亿），在 RT-1机器人数据上训练。它的招牌结果是*语义*泛化：听从涉及机器人数据中没有的物体与概念的指令（机器人数据本身教不会这些——比如“把香蕉搬到二加一之和的地方”，以及物件中放着一只玩具恐龙时的“捡起已灭绝的动物”）。最大的模型对机器人自己的电脑来说太大，运行在云端硬件上，控制频率很低（几 Hz）。

**OpenVLA**（Kim、Pertsch、Karamcheti 等，2024年6月）公开了这一配方。它的骨干是 Prismatic VLM：融合的 DINOv2与 SigLIP 特征、一个投影层、以及70亿参数的 Llama 2语言模型。动作每步七个词元（末端执行器位置增量、旋转增量与夹爪），每个词元是256个箱之一，箱的范围由训练动作的第1与第99百分位数确定，并映射到 Llama 分词器中使用最少的256个词元上。它在来自 Open X-Embodiment 数据集的约970,000条轨迹上训练，并连同权重与训练代码一起发布；论文还演示了 LoRA 微调与4比特量化推理（[[vision-language-action/vla-fine-tuning]]、[[vision-language-action/vla-deployment]]）。同一团队2025年的后续工作（OpenVLA-OFT）用对连续动作块的并行预测取代了逐词元解码，速度大幅提升，在其基准上的成功率也更高——这说明了在同一骨干下输出设计有多重要。

动作词元的吸引力在于简单：语言模型的训练代码不变，损失是交叉熵，而且按维度的类别输出天然可以是多峰的。其代价即[[vision-language-action/action-representations]]所讨论的那些：分辨率粗、串行解码，以及除非使用 FAST 这类压缩词元化，否则难以从高频动作块中学好。

## 从头训练的通用策略：Octo {#sec-octo}

并非每个通用策略都从 VLM 出发。**Octo**（Octo Model Team，2024）是一个从头训练的 Transformer，在 Open X-Embodiment 的约800,000条轨迹上训练，规模有两种：Small 版2700万参数，Base 版9300万参数。语言用预训练的 T5文本编码器嵌入，图像用一个小型卷积主干编码；来自任意路数的相机、本体感知、以及语言指令或目标图像之一的输入都变成词元序列，学习到的**读出词元**（readout tokens）对它们作注意力，并馈入一个输出动作块的**扩散动作头**。设计目标是可适应性：新的观测类型或动作空间可以在微调时通过增添词元化器或输出头来引入，无需从头重训。

Octo 与同类模型远比基于 VLM 的 VLA 小而快，但没有网络知识，其语言理解局限于机器人数据所含的内容。对企业来说它们是有用的基线：若任务不涉及开放式语言，小策略可能与大策略一样胜任，而推理成本只有后者的零头。

## 动作专家：π0 {#sec-pi0}

**π0**（Physical Intelligence，2024年10月；权重于2025年初发布）把 VLM 与[[vision-language-action/diffusion-flow-policies]]中的流匹配生成器结合在一个 Transformer 里。

- 骨干是 **PaliGemma**，一个30亿参数的 VLM（SigLIP 视觉编码器与 Gemma 2B 语言模型）。
- 第二套更小的 Transformer 权重——**动作专家**（action expert），约3亿参数——处理机器人状态与一个含$H = 50$个带噪动作的动作块。两套权重构成一个 Transformer，其中每个词元由自己类型的权重处理（图像与文本由 VLM 权重，状态与动作由专家权重），词元在每一层通过注意力相互作用——一种按词元类型而非按学习路由划分的“混合专家”。
- **分块因果注意力掩码**（block-causal attention mask）让图像-语言前缀只在其内部作注意力，于是它的键与值可以计算一次并缓存；状态与动作词元则注意前缀及彼此。
- 动作专家输出[[vision-language-action/diffusion-flow-policies#def-flow]]中的流匹配速度；推理时动作块以约十步欧拉积分生成，每一步都复用缓存的前缀。

论文报告了对多种机器人——单臂、双臂与移动操作平台——的控制，动作频率最高50 Hz，任务包括叠衣服、收拾餐盘与组装纸箱。预训练用了公司自采遥操作数据的大混合（若干种机器人构型，超过10,000小时）加上公开数据集，随后针对每个困难任务在高质量数据上微调。

::: example 动作专家型 VLA 的推理结构 {#ex-pi0}
一个 π0式模型有30亿参数的骨干与3亿参数的动作专家。三路相机各给出256个词元，指令20个词元；动作专家处理一个状态词元与50个动作词元。使用[[#prop-flops]]，取达到的$10^{14}$ FLOP/s并忽略注意力，估计 (a) 前缀开销，(b) 一个流步的开销，(c) 10步一块的耗时，以及 (d) 能够产出动作块的最高速率。
::: solution
(a) 前缀词元$3\times256 + 20 = 788$；FLOP 数$2\times3\times10^9\times788 = 4.7\times10^{12}$，即$47\,\mathrm{ms}$。
(b) 专家词元51；FLOP 数$2\times3\times10^8\times51 = 3.1\times10^{10}$，即$0.31\,\mathrm{ms}$的算术。由于只处理51个词元，这一步是内存受限的：以$1\,\mathrm{TB/s}$读出$0.6\,\mathrm{GB}$的 bf16专家权重需要$0.6\,\mathrm{ms}$，所以每步约$1\,\mathrm{ms}$是现实的底线。
(c) $47 + 10\times1 \approx 57\,\mathrm{ms}$——计入实际开销，在$60$–$100\,\mathrm{ms}$量级。
(d) 至多约每秒10–15块。一个含50个动作的块在50 Hz 下历时1 s，所以即使每块只执行一半（$h = 25$）也只需每秒2块——GPU 约有15%的时间在忙。
检验：对比[[#ex-backbone]]：自回归的7B 模型产生*一个*动作需要$138\,\mathrm{ms}$；动作专家用大约一半的时间产生50个动作。并行生成整个动作块、并为迭代部分配备小网络，正是50 Hz 频率得以实现的原因。
:::
:::

**π0-FAST**（2025年1月）是采用[[vision-language-action/action-representations#alg-fast]]的 FAST 词元化器的自回归变体；它训练得更快，并在许多任务上与 π0打成平手，但其逐词元解码在推理时更慢。**π0.5**（2025年4月）解决的是向全新环境的泛化——在训练中未见过的家庭住宅里清理厨房与卧室。它的主要配方是**在异构数据上联合训练**：来自多种机器人的示范、来自多户家庭移动操作平台的数据、用于图像描述与问答的网络数据、以及用语言标注高层步骤的样例。运行时模型先以文本预测一个高层子任务（“拿起盘子”），再为它生成低层动作块，两个层级共用一个网络。Physical Intelligence 后期的模型（2025年）加入了在机器人自身的、带有纠正与奖励信号的自主经验上训练。这些结果均由开发方报告，在可比硬件上的独立复现（截至2026年）还很有限。

## 双系统设计 {#sec-dual}

一个既大（为了理解）又快（为了控制）的网络难以建造。**双系统**架构以卡尼曼（Kahneman）的“系统1”（快速、自动）与“系统2”（缓慢、深思熟虑）思考作类比命名，把两者拆开。

::: definition 双系统 VLA {#def-dual}
**双系统 VLA**由一个大型视觉-语言模型（“系统2”）与一个较小的视觉运动策略（“系统1”）组成：前者以低频率运行，解读场景与指令并产生一个潜向量或简短计划；后者以高频率运行，接收最近的图像与本体感知以及最新的系统2输出，产生运动指令。两者联合训练或分阶段训练，并异步运行。
:::

2025年三个公开描述的例子说明了这一模式。

- **Helix**（Figure AI，2025年2月）控制一个人形机器人的上半身。按公司的描述，系统2是一个以7–9 Hz 运行的70亿参数 VLM，系统1是一个以200 Hz 运行的8000万参数视觉运动 Transformer，两者由一个潜向量相连，都运行在机器人上。
- **GR00T N1**（NVIDIA，2025年3月）是一个面向人形机器人的开放模型，把一个处理图像与语言的 VLM（系统2）与一个用流匹配训练的扩散 Transformer 动作模块（系统1）配对，后者以更高的频率生成运动动作块。它在真实机器人数据、人类视频与仿真生成的合成数据的混合上训练。
- **Gemini Robotics**（Google DeepMind，2025年3月）在 Gemini 2.0模型之上构建 VLA。其报告描述了一个运行在云端硬件上的骨干与一个运行在机器人自己电脑上的本地动作解码器，两者一起给出数百毫秒的端到端延迟，同时以高得多的有效控制频率产出动作块。配套的模型 Gemini Robotics-ER 专注于具身推理（指点、三维检测、抓取预测），并能驱动传统控制器。2025年后期的版本增加了端侧变体，以及一个在行动前先以文本推理的模型。

::: example 双系统控制器的滞后 {#ex-staleness}
系统2以8 Hz 更新它的潜向量；系统1以200 Hz 运行。末端执行器以$0.25\,\mathrm{m/s}$运动。(a) 有多少个系统1步使用同一个潜向量？(b) 两次潜向量更新之间手移动多远？(c) 为什么系统1需要自己的相机输入？
::: solution
(a) $200/8 = 25$步。
(b) 潜向量最多已陈旧$1/8 = 0.125\,\mathrm s$（再加上系统2自身的延迟）：$0.25\times0.125 = 0.031\,\mathrm m = 31\,\mathrm{mm}$。
(c) 31 mm 远大于抓取容差。潜向量可以携带做*什么*（“用把手抓住左边的杯子”），却不能携带手*此刻确切在哪里*；系统1必须以自己的频率在新鲜的图像与本体感知上闭环。检验：这与传统机器人软件中运动规划器和伺服回路之间的分工相同（[[robot-arm-design/software-stack]]），只是两级都换成了学习组件。
:::
:::

## 各设计的比较 {#sec-compare}

| 设计 | 例子（年份） | 动作输出 | 优点 | 缺点 |
|---|---|---|---|---|
| 动作即词元 | RT-2（2023）、OpenVLA（2024）、π0-FAST（2025） | 离散箱或压缩词元，自回归 | 语言模型训练代码不变、按词元多峰 | 解码慢、分辨率 |
| 从头训练的通用策略 | Octo（2024） | 读出词元上的扩散头 | 小、快、输入输出灵活 | 网络知识少 |
| 动作专家 | π0（2024）、π0.5（2025） | 在动作块上的流匹配、共享 Transformer | 平滑的高频动作块、保住 VLM | 比小策略大、训练中须保护 VLM 知识 |
| 双系统 | Helix、GR00T N1、Gemini Robotics（2025） | 快策略以慢 VLM 的潜向量为条件 | 大模型下的高控制频率 | 两套系统都要训练并同步 |

截至2026年，有几条趋势贯穿整个表格：用于控制的连续动作块输出（流匹配或扩散），有时在预训练期间与离散词元结合；动作之前显式的中间推理（子任务、点、边界框、文本计划）；在更多样的数据上训练，包括人类视频与仿真；以及运行在机器人上的更小模型。

::: quiz
某 VLA 的语言模型权重以 bf16存放占6 GB。机器人的 GPU 内存带宽为0.5 TB/s。对一个7维动作，哪种输出设计能给出更高的控制频率？
- [ ] 自回归动作词元、每维一个，因为每个词元很便宜。
- [x] 产生动作块的动作头，因为自回归解码每个动作至少需要7次对6 GB 权重的串行读出。
- [ ] 两者相同，因为它们用同一个骨干。
::: solution
每个自回归词元需要对权重做一次完整遍历：$6\,\mathrm{GB}/0.5\,\mathrm{TB/s} = 12\,\mathrm{ms}$，7个词元便是单个动作84 ms。动作块头每个动作块只需读骨干一次，就能产出几十个动作。
:::
:::

::: warning 不要用头条数字来比较模型
VLA 论文中的成功率是在作者自己的任务、机器人、初始条件与评测方案下测得的；一篇论文报告的90%与另一篇论文报告的70%不能据数字排座次。要在你自己的机械臂与任务上、以配平的初始条件和足够多次的试次来比较候选模型（[[vision-language-action/policy-evaluation]]）。
:::

::: example 产品该选哪种架构？ {#ex-choose}
你的公司销售一款带平行夹爪的6自由度机械臂，配一块16 GB 内存的机载 GPU。客户想要覆盖多种物体的“按语音指令抓取并放置”，外加一个精密插入任务。给出一个架构建议并论证它。
::: solution
跨多种物体的指令跟随要求 VLM 骨干（语义泛化）；插入任务要求平滑、高频的连续动作块。一个约3B 参数的动作专家设计（π0式，2025–26年有开放权重可用）合适：bf16下约7 GB，在16 GB 之内为激活与 KV 缓存留有余地，用8位权重则更少。其动作块输出支持30–50 Hz 控制。7B 的词元输出模型只有量化后才装得下，而且只能跑几 Hz。若云端骨干可以接受，双系统是一个选项，但会增加网络延迟与依赖。仅就插入任务而言，小型任务专用扩散或流策略可能表现得同样好，应作为基线来评测。内存检验：权重$3.3\times10^9\times2 = 6.6\,\mathrm{GB}$，明显低于16 GB。
:::
:::

::: history
让机器人策略以语言为条件的想法比 VLA 更古老——CLIPort（2021）与 BC-Z（2021）用了预训练的语言与图像编码器，SayCan（2022）用语言模型在学得的技能之间做选择。RT-1（2022年12月）展示了一个在130,000条示范上训练的 Transformer 策略；RT-2（2023年7月）微调了一个网络规模的 VLM 来输出动作词元，并创造了 VLA 一词。Open X-Embodiment 数据集的发布（2023年10月）催生了开放的通用模型：Octo（2024年5月）与 OpenVLA（2024年6月）。π0（2024年10月）把一个流匹配动作专家接到 VLM 上；π0.5、GR00T N1、Helix 与 Gemini Robotics（2025年）则向着开放世界泛化、人形机器人与双系统设计推进。
:::

::: summary
- VLA 是一个 VLM（视觉编码器加投影层加语言模型）经进一步训练以输出机器人动作；它继承了关于物体与语言的网络知识。
- Transformer 开销：每词元约$2P$ FLOP；自回归解码每个词元需要一次完整权重读出，所以按维度输出的动作词元很慢。
- RT-2与 OpenVLA 输出分箱的动作词元；Octo 是一个带扩散头的小型从头训练通用策略；π0给3B VLM 加了一个300M 的流匹配动作专家，用缓存前缀生成50步动作块。
- π0.5在异构数据上联合训练，行动前先预测语言子任务；双系统模型（Helix、GR00T N1、Gemini Robotics）让慢 VLM 与快运动策略并行运行。
- 依任务需求（语义通用性、精度、频率）与硬件的内存、带宽来做选择，并在你自己的机器人上比较候选。
:::

## 习题

::: exercise 图像词元 {#exr-imgtok level=1 check="1024"}
图块大小14的 ViT 处理一张$448\times448$的图像。它产生多少个图块词元？（填入数字。）
::: solution
$(448/14)^2 = 32^2 = 1024$个词元——是$224\times224$时的四倍，前缀开销也变为四倍。
:::
:::

::: exercise 权重内存 {#exr-mem level=1 check="6.6"}
33亿参数模型的权重在 bf16下占多少内存？（以 GB 填入，取1 GB = $10^9$字节。）
::: solution
$3.3\times10^9\times2\,\mathrm B = 6.6\,\mathrm{GB}$。
:::
:::

::: exercise 解码底线 {#exr-decode level=1 check="28"}
一个70亿参数模型以8位权重存放在带宽为$2\,\mathrm{TB/s}$的 GPU 上。解码8个词元最少需要多长时间？（以 ms 填入。）
::: solution
每词元$7\times10^9/(2\times10^{12}) = 3.5\,\mathrm{ms}$；8个词元$28\,\mathrm{ms}$。
:::
:::

::: exercise 三路相机的前缀开销 {#exr-prefix level=2 check="96"}
一个30亿参数的骨干处理三张$224\times224$图像（图块大小14）与一条32词元的指令，达到$5\times10^{13}$ FLOP/s。用每词元$2P$ FLOP 估计前缀时间。（以 ms 填入，四舍五入到毫秒。）
::: solution
词元$3\times256 + 32 = 800$；FLOP 数$2\times3\times10^9\times800 = 4.8\times10^{12}$；时间$4.8\times10^{12}/5\times10^{13} = 0.096\,\mathrm s = 96\,\mathrm{ms}$。
:::
:::

::: exercise 每个潜向量的步数 {#exr-latent level=2 check="20"}
双系统模型中系统2以10 Hz 运行、系统1以200 Hz 运行。每个系统2的输出被多少个系统1步使用？（填入数字。）
::: solution
$200/10 = 20$。
:::
:::

::: exercise 分块因果掩码 {#exr-mask level=2}
π0式模型中，图像-语言前缀不得注意状态与动作词元，而动作词元注意前缀。解释这一掩码为何 (i) 允许缓存，以及 (ii) 对动作预测的表达力毫无损失。
::: solution
(i) 若前缀词元从不注意动作词元，则前缀的键与值就不依赖带噪动作——后者每个流步都在变；它们可以每次观测计算一次，供全部十步复用。(ii) 要预测的量是*动作*词元的速度；它们在每一层仍然注意整个前缀，所以图像与文本中的全部信息都会到达它们。所失去的只是图像词元被当前带噪动作猜测所修正的能力，而这不含有关于观测的任何信息。
:::
:::

::: exercise 并行解码的加速 {#exr-parallel level=3}
对[[#ex-backbone]]中的模型，比较产出一个含8个7维动作的动作块的耗时：(a) 自回归解码56个词元；(b) 用一次前向并行输出全部56个值（如同 OpenVLA-OFT 的并行解码，把56个输出位置当作额外的输入词元）。陈述你的假设。
::: solution
(a) 提示$40\,\mathrm{ms}$加上56步内存受限的解码、每步$14\,\mathrm{ms}$：$40 + 784 = 824\,\mathrm{ms}$。(b) 一次覆盖$286 + 56 = 342$个词元的前向，算术受限：$2\times7\times10^9\times342/10^{14} = 48\,\mathrm{ms}$。加速约17倍，而且一个动作块覆盖8个控制步，于是有效动作频率从约$10\,\mathrm{Hz}$升到远高于$100\,\mathrm{Hz}$。假设：bf16权重、$1\,\mathrm{TB/s}$带宽、成批词元下达到$10^{14}$ FLOP/s、注意力可忽略。并行输出头需要为此专门训练（输出不再以彼此为条件），而且发表的后续工作用的是连续回归输出而非箱。
:::
:::

::: exercise 一份架构评审 {#exr-review level=3}
为你的团队写一页架构评审，比较7B 词元输出 VLA、3B 动作专家 VLA 与100M 任务专用扩散策略，用于一个有300个 SKU、偶尔有语音指令的料箱拣选产品。涵盖泛化、精度、频率、硬件、数据需求与风险。
::: solution
一份好的评审应包含的要点。泛化：300个外观各异的 SKU 有利于预训练视觉（两种 VLA 都行，或带预训练图像编码器的扩散策略）；语音指令有利于语言骨干。精度与频率：几 Hz 的词元输出对精密抓取与运动偏弱；动作专家与扩散策略给出20–50 Hz 的连续动作块。硬件：7B 在16 GB GPU 上需要量化且慢；3B 在 bf16下装得下；100M 在普通硬件上就能运行。数据：VLA 因预训练而需要的任务数据较少，但微调需要更多算力；小策略需要更多任务数据，但数小时就能训完。风险：依赖第三方权重与许可证、评测成本、微调时对语言能力的灾难性遗忘、延迟尖峰。建议：并行做出3B 动作专家 VLA 与小型扩散策略的原型，在相同的初始条件上评测两者，按实测成功率、节拍时间与成本定夺。
:::
:::
