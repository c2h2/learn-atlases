制造机械臂的公司很少会从零训练一个视觉-动作模型。经济账指向相反的方向：一个视觉-语言模型的预训练要花数百万 GPU 小时，而一个在来自许多机器人的几十万条示范上训练出来的通用机器人模型，已有多个团队提供开放权重（截至2026年）。实际的问题是：如何拿这样一个模型，让它擅长*你的*任务、跑在*你的*机械臂上——用你的运动学、相机、夹爪与控制频率——只用几百或几千条示范，又不破坏这个预训练模型值得你从它出发的那些东西。

本章由外向内跟着一条 VLA 的训练流水线走。我们描述各个阶段（VLM 预训练、机器人预训练、后训练），说明由许多数据集构成的**预训练混合**如何加权，机器人训练为什么与网络数据**联合训练**，以及来自不同机器人的数据如何靠**跨具身归一化**变得兼容。然后转向一个团队真正要做的决定：**全量微调**还是 LoRA 这样的**参数高效**方法，把内存与算力算清楚，最后谈数据量、超参数，以及微调后的策略过拟合或遗忘的信号。架构见 [[vision-language-action/vla-architectures]]；数据见 [[vision-language-action/demonstration-data]]。微调大模型的一般机制见 LLM Atlas 的[指令微调](/learn/llm/lesson.php?c=post-training&l=instruction-tuning)、[参数高效微调](/learn/llm/lesson.php?c=post-training&l=parameter-efficient-tuning)与[数据混合](/learn/llm/lesson.php?c=pretraining&l=data-mixtures)。

## 训练流水线 {#sec-pipeline}

一个 VLA 至多分三个阶段训练，每一阶段都从上一阶段的权重出发。

1. **VLM 预训练。** 视觉编码器与语言模型先分别在网络数据上预训练，再在图文对、图注与视觉问答上拼合成一个视觉-语言模型。机器人团队通常把这一阶段当作现成的（PaliGemma、基于 Llama 的 Prismatic、Gemini、Eagle 等）。
2. **机器人预训练。** 在一个来自许多具身形态与任务的大规模机器人示范混合上训练这个 VLM——Open X-Embodiment、DROID 等公开数据集，加上私有数据——常常还与网络数据一起。产出的是“基座”或“通才”机器人模型。
3. **后训练或微调。** 用面向目标机器人、任务或任务族的一小批高质量示范继续训练基座模型。π0的作者把这个分工比作语言模型的预训练与对齐：预训练用宽、杂、不完美的数据；后训练用精选、一致的数据。

一家公司通常从第3阶段切入，有时也在自己的多任务数据上跑一个轻量版的第2阶段。

## 预训练混合 {#sec-mixtures}

为机器人预训练汇集的数据集，规模可以相差几个数量级。按数据集大小成比例地抽取训练样本会让最大的数据集独大；对数据集均匀抽取则把最小的过度重复。

::: definition 混合权重与温度采样 {#def-mixture}
一个**数据混合**以概率$w_i$从数据集$i$抽取每个训练样本，$\sum_i w_i = 1$。在**温度采样**下，权重为
$$
w_i = \frac{n_i^{\alpha}}{\sum_j n_j^{\alpha}},\qquad 0\le\alpha\le1,
$$ {#eq-temperature}
其中$n_i$是数据集$i$的规模（按回合数、步数或小时数计）：$\alpha = 1$是按比例采样，$\alpha = 0$是对数据集均匀采样。抽取$S$个样本后，数据集$i$的**有效轮次**为$S w_i/n_i$。
:::

实践中，随 Octo 与 OpenVLA（2024）发布的机器人学习混合是手工整理的：先按质量与相关性过滤数据集（单臂操作、第三视角相机、可用的动作），再手工加权，有些数据集因多样性低而被降权。在没有更好的信息时，按比例或温度加权是合理的起点。

::: example 三个数据集的加权 {#ex-mixture}
一个预训练混合含一个$10^6$步的公开数据集、一个$10^5$步的数据集和公司的$2\times10^3$步自有数据。(a) 求$\alpha = 1$、$0.5$与$0.3$时的权重。(b) 当$\alpha = 0.5$、抽取$S = 10^6$步时，各数据集相当于多少轮？
::: solution
(a) $\alpha = 1$：权重$\propto 10^6 : 10^5 : 2000$，即$0.907, 0.091, 0.002$。$\alpha = 0.5$：$\propto 1000 : 316.2 : 44.7$，即$0.735, 0.232, 0.033$。$\alpha = 0.3$：$\propto 63.1 : 31.6 : 9.8$，即$0.604, 0.303, 0.094$。
(b) 轮次$= S w_i/n_i$：$10^6\times0.735/10^6 = 0.73$；$10^6\times0.232/10^5 = 2.3$；$10^6\times0.033/2000 = 16$。
检验：$\alpha$变小，小数据集的权重上升、被重复得更多；对2,000条步数跑16轮，已经足以冒把它记住的风险。相对于其余数据这么小的数据集，通常做法不是在预训练中抬升它的权重，而是留到之后做微调。
:::
:::

### 与网络数据联合训练

只用机器人动作训练 VLM，会以损害其语言与视觉能力的方式改变权重——**灾难性遗忘**（catastrophic forgetting）。机器人数据里词很少（每条回合一句短指令）、图像范围狭窄（同一张实验台），于是模型广博的知识——当初使用 VLM 的根本理由——被侵蚀。RT-2（2023）用**联合微调**（co-fine-tuning）应对这一点：每个批次把机器人轨迹与 VLM 原本的网络任务混在一起；其作者发现，与只在机器人数据上微调相比，这改善了向新物体与新指令的泛化。π0.5（2025）把来自许多具身形态的机器人数据与图注生成、视觉问答、目标检测、高层子任务预测联合训练，并报告去掉网络数据对未见物体的泛化伤害最大。

遗忘的第二种机制是动作专家模型特有的：刚刚初始化的动作专家的梯度流入预训练骨干，在训练早期就可能把它扰乱。Physical Intelligence 在2025年报告，阻断这些梯度（“知识绝缘”）——让骨干在离散动作词元与网络数据上训练、让动作专家在连续动作上训练且不把梯度传回骨干——训练更快，语言遵循也保持得更好。一般性的教训是：*保护好骨干*——掺入它原本的数据、给它更低的学习率、冻结它的部分、或限制哪些梯度能到达它。

## 跨具身训练 {#sec-embodiment}

来自不同机器人的数据在动作维度（6、7或14个关节，带不带移动底盘）、动作空间（关节或末端执行器、绝对或增量）、单位与坐标系、控制频率（Open X-Embodiment 里从3到50 Hz）以及相机布置上都不一样。只有当这些差异要么被抹掉、要么对模型可见，模型才能同时从所有数据中学习。

::: definition 逐数据集动作归一化 {#def-normalisation}
对每个数据集（或具身形态）$e$和动作维度$j$，统计训练动作的量——均值$\mu^e_j$与标准差$\sigma^e_j$，或第1与第99百分位$q^e_{01,j}, q^e_{99,j}$——并用归一化后的动作训练
$$
\bar a_j = \frac{a_j - \mu^e_j}{\sigma^e_j}\qquad\text{or}\qquad \bar a_j = 2\,\frac{a_j - q^e_{01,j}}{q^e_{99,j} - q^e_{01,j}} - 1 ,
$$ {#eq-normalise}
第二种情形把结果裁剪到固定范围。部署时，用模型所跑具身形态的统计量对输出做反归一化。
:::

归一化把每个机器人的动作放到可比的尺度上，免得一个机器人的小增量被另一个的大增量淹没。但它并不能让动作*含义*相同：归一化后的0.8，在关节空间数据集的第一个维度上和在末端执行器数据集上指挥的是不同的运动。模型的应对办法有：

- **填充与掩码**：所有动作向量用零填充到混合中最大的维度，损失对填充项做掩码（π0填充到其机器人里最大的动作维度）；
- **具身形态专属的头或编码器**：每个具身形态各配一小套输入输出层，如 Octo 面向新动作空间的设计与 GR00T N1的具身形态专属模块，中间是共享的 Transformer；
- **条件化**：把具身形态标识、机器人状态或动作空间的描述作为输入给出；
- **统一时间基准**：对分块重新采样，使一个分块代表固定时长（比如1 s），无论控制频率是多少。

::: example 一次归一化错配 {#ex-norm}
机器人 A 以5 Hz 记录末端执行器$x$增量，第1与第99百分位为$\mp0.020\,\mathrm m$；机器人 B 以20 Hz 记录，为$\mp0.005\,\mathrm m$。(a) 分别用 B 的统计量和 A 的统计量归一化 B 的一个$0.004\,\mathrm m$增量。(b) 为机器人 B 微调出的策略输出$\bar a = 0.8$；若部署代码误用 A 的统计量反归一化，会得到什么运动？(c) 为什么两个机器人的范围差了四倍？
::: solution
(a) 用 B 的统计量：$2(0.004 + 0.005)/0.010 - 1 = 0.80$。用 A 的：$2(0.004 + 0.020)/0.040 - 1 = 0.20$。
(b) 用 A 的统计量反解 [[#eq-normalise]]：$a = q_{01} + (\bar a + 1)(q_{99} - q_{01})/2 = -0.020 + 1.8\times0.020 = 0.016\,\mathrm m$——每步是预期的$0.004\,\mathrm m$的四倍；在20 Hz 下相当于$0.32\,\mathrm{m/s}$的速度而不是$0.08\,\mathrm{m/s}$。
(c) 控制频率相差四倍：同样的手部速度在20 Hz 下给出的增量小四倍。检验：$0.020\times5 = 0.005\times20 = 0.10\,\mathrm{m/s}$——两个数据集的典型速度相同。归一化统计量要*连同模型检查点与具身形态名一起*保存，并让部署代码在它们缺失时拒绝运行。
:::
:::

::: warning 归一化统计量是模型的一部分
缺少训练时所用动作统计量的微调检查点是不完整的。用另一个数据集（哪怕是同一数据集的新版本）重新计算这些统计量，或在一条新机械臂上微调之后继续沿用基座模型的统计量，都会让每个动作的幅度整体走样——而且这个错误在离线时看不见，因为训练与验证用的统计量是对的。给统计量做版本管理、随权重一起发布，并在部署检查里核对具身形态名一致。
:::

## 全量微调与 LoRA {#sec-lora}

**全量微调**更新每一个参数。它给模型最大的适应自由，也是已发表 VLA 的后训练在有算力时大多采用的做法。它的内存开销由优化器主导。

::: proposition 用 Adam 全量微调的内存 {#prop-memory}
以混合精度训练一个$P$参数的模型（bf16权重与梯度用于计算，fp32主权重与两个 fp32矩估计）大约需要
$$
M \approx (2 + 2 + 4 + 4 + 4)\,P = 16P\ \text{字节}
$$ {#eq-memory}
用于权重、梯度与优化器状态，还要加上激活，后者随批量大小与序列长度增长。
:::

::: proof
逐参数数字节：前向与反向所用的 bf16权重副本，2；bf16梯度，2；供优化器更新的 fp32主副本（免得小更新被 bf16舍入吞掉），4；Adam 的一阶矩估计$m$，4；二阶矩估计$v$，4。总计16。变体会改变计数——fp32梯度加2，8位优化器状态约省6，在$G$块 GPU 间分片把状态除以$G$——但数量级不变。激活不与$P$成正比，单独计算。
:::

对一个70亿参数的模型，[[#eq-memory]] 给出不含激活的112 GB——超过一块80 GB 加速器的容量，所以状态必须分片到几块卡上。**低秩适配**（Low-Rank Adaptation，LoRA；Hu 等，2021）通过冻结预训练权重、只学习一个小修正来避开这一点。

::: definition 低秩适配（LoRA） {#def-lora}
对冻结的预训练权重矩阵$\mathbf W_0\in\R^{m\times k}$，LoRA 学习矩阵$\mathbf B\in\R^{m\times r}$与$\mathbf A\in\R^{r\times k}$，秩$r\ll\min(m,k)$，并使用
$$
\mathbf W = \mathbf W_0 + \frac{\alpha_{\mathrm L}}{r}\,\mathbf B\mathbf A ,
$$ {#eq-lora}
其中$\alpha_{\mathrm L}$是固定的缩放常数。$\mathbf B$初始化为零，因此训练从预训练模型出发。只有$\mathbf A$与$\mathbf B$参与训练。
:::

::: proposition LoRA 的参数数量与合并 {#prop-lora}
施加在$m\times k$矩阵上的秩$r$ LoRA 适配器有$r(m+k)$个可训练参数，占该矩阵的$r(m+k)/(mk)$。训练之后适配器可以合并进$\mathbf W = \mathbf W_0 + (\alpha_{\mathrm L}/r)\mathbf B\mathbf A$，得到一个原本形状的矩阵，因此推理开销与原模型完全相同。
:::

::: proof
$\mathbf B$有$mr$个条目、$\mathbf A$有$rk$个，合计$r(m+k)$；除以$mk$即得占比。乘积$\mathbf B\mathbf A$是一个$m\times k$矩阵（秩至多$r$），所以$\mathbf W_0 + (\alpha_{\mathrm L}/r)\mathbf B\mathbf A$是一个普通的$m\times k$矩阵；该层的输出$\mathbf W\mathbf x = \mathbf W_0\mathbf x + (\alpha_{\mathrm L}/r)\mathbf B(\mathbf A\mathbf x)$，无论用合并后的矩阵还是用分开的因子计算都相同。
:::

::: example 70亿参数骨干上的 LoRA {#ex-lora}
一个 Llama-2-7B 型语言模型有32层，宽度$d = 4096$、MLP 宽度$11\,008$；每层有四个$4096\times4096$注意力投影、两个$4096\times11\,008$ MLP 输入投影与一个$11\,008\times4096$输出投影。秩$r = 32$的 LoRA 加在每层的全部七个矩阵上。(a) 数一数可训练参数。(b) 与全量微调比较内存（每个可训练参数16字节，每个冻结参数 bf16占2字节）。(c) 冻结权重改用4位存储能省多少？
::: solution
(a) 每层：注意力$4\times32\times(4096 + 4096) = 1\,048\,576$；MLP 输入$2\times32\times(4096 + 11\,008) = 966\,656$；MLP 输出$32\times(11\,008 + 4096) = 483\,328$；合计$2\,498\,560$。32层共$79.95\times10^6$，约8000万——模型67亿参数的1.2%。
(b) 全量微调：$16\times6.7\times10^9 = 108\,\mathrm{GB}$（凑整70亿则为112 GB）。LoRA：冻结权重$2\times6.7\times10^9 = 13.5\,\mathrm{GB}$，加上适配器及其优化器状态的$16\times80\times10^6 = 1.3\,\mathrm{GB}$：约$15\,\mathrm{GB}$外加激活——单张24–48 GB 的 GPU 即可容纳。
(c) 冻结权重用4位只需$3.4\,\mathrm{GB}$而不是$13.5\,\mathrm{GB}$（QLoRA 的做法），代价是速度以及可能的精度；总计约$5\,\mathrm{GB}$外加激活。
检验：适配器数量与$r$成正比；秩8得0.2亿，秩64得1.6亿。实践中往往是激活（连带批量大小与图像数量）决定了选哪块 GPU。
:::
:::

x: 0.5, 15

怎么选？OpenVLA 的作者们在2024年报告，LoRA 微调在他们的适配任务上以一小部分算力追平了全量微调。一般而言，截至2026年：当目标数据量大且与预训练分布差别大（新的具身形态、高频灵巧控制）且算力充足时，优先全量微调；当数据量中等、需要为一个基座模型保留许多任务专用变体（每个适配器都很小）、或内存是瓶颈时，用 LoRA。中间方案很常见：冻结视觉编码器（它已经看得很好）只调其余部分；或只训练动作头与最后几层。

::: quiz
一个团队用秩16的 LoRA 在150条示范上为某个新任务微调一个30亿参数的 VLA。成功率40%，而同样数据做全量微调得75%。哪种解释最可信？
- [ ] LoRA 根本无法改变模型的行为。
- [x] 新任务需要的改动超出了所选层上秩16适配器所能表达的范围（比如动作头或新的动作空间）；试更高的秩、给更多层加适配器，或完整训练动作头。
- [ ] 全量微调一定会记住数据，所以75%必是评测错误。
::: solution
LoRA 把每个权重更新限制在所选矩阵的低秩范围内。若动作头是刚初始化的，或动作空间与预训练不同，所需的改动可能不是低秩的，或落在没有适配器的层上。完整训练动作头、给所有线性层都加上适配器、或调大$r$，通常能补上大部分差距；另外要检查学习率是否为 LoRA 设定过（通常应高于全量微调）。
:::
:::

## 数据、算力与超参数 {#sec-hyper}

**多少数据。** 已报告的 VLA 微调集规模，从熟悉的机械臂上做简单抓取-放置的几十条示范，到长灵巧任务的几十或几百小时（2024–26年的报告）。一个新的具身形态——基座模型从未见过的——比在熟悉的机械臂上做一个新任务需要更多数据，因为模型必须学习从意图到关节运动的新映射。多样性（场景、物体、初始条件）比重复更值钱（[[vision-language-action/demonstration-data]]）。

**算力。** Transformer 的训练开销约为被训练部分每词元$6P$ FLOP（前向$2P$、反向$4P$）；冻结基座加 LoRA 时，反向仍要穿过冻结层传播，所以算力的节省小于内存的节省。

::: example 一次微调的 GPU 小时 {#ex-compute}
一个30亿参数的 VLA 以批量大小32全量微调30,000步，每个样本约850个词元。(a) 估算 FLOP，并在每 GPU 实际达到$4\times10^{14}$ FLOP/s 下估算 GPU 小时。(b) 数据集有200条示范、每条300步；这是多少轮？
::: solution
(a) $6\times3\times10^9\times850\times32\times30\,000 = 1.47\times10^{19}$ FLOP；$1.47\times10^{19}/4\times10^{14} = 36\,700\,\mathrm s = 10.2$ GPU 小时——八卡节点上跑几个小时。
(b) 样本数$200\times300 = 60\,000$；采样数$30\,000\times32 = 960\,000$；16轮。
检验：微调的开销相对预训练（数千 GPU 天）微不足道，但相对在真实机器人上*评测*每个检查点的开销（操作员小时）却很大；先规划评测预算（[[vision-language-action/policy-evaluation]]）。
:::
:::

典型选择如下——须按模型与数据调整，不可照抄：

- **优化器与学习率**：AdamW，短预热加余弦或常数衰减；大骨干全量微调的学习率在$10^{-5}$量级，LoRA 适配器或刚初始化的头更高（$10^{-4}$量级）；视觉编码器有时用更低的速率。
- **批量大小与步数**：内存允许下尽量大的批量（必要时梯度累积）；数万步；定期保存检查点，因为最好的闭环检查点往往不是最后一个。
- **数据增强**：随机裁剪与轻微颜色抖动可对抗对具体场景的过拟合；会改变图像与动作对应关系的几何增强（翻转）必须同样施加到动作上，否则干脆不用。
- 权重的**指数滑动平均**（EMA），Diffusion Policy 等在用，能得到更平滑、通常更好的检查点。
- **归一化统计量**针对目标具身形态在微调数据上重新计算（[[#def-normalisation]]）。

## 过拟合与遗忘 {#sec-overfit}

小数据集上的模仿学习很容易过拟合，而常规信号——训练损失下降时验证损失上升——只是弱指南，因为行为克隆策略的验证损失与闭环成功只有松松的相关（[[vision-language-action/imitation-learning]]）。尤其是扩散策略，常常在验证损失已经开始上升之后，在机器人上仍在继续变好。更好的信号来自机器人：

- **记住的轨迹**：不管物体在哪，机械臂都重放示范里的动作；把物体挪到示范位置之外即可检验。
- **无视指令**：不管听到什么，策略都只做最常见的那个任务；在同一场景里给出其他任务的指令即可检验。这也是骨干的语言接地被**遗忘**的特征。
- **对干扰物与光照变化脆弱**：这些微调数据里没有，基座模型却能处理。
- 训练后期出现**卡顿或迟疑的动作**，说明模型在拟合示范里的噪声。

补救都是老办法——更多样的数据、增强、更少的步数、更低的学习率、LoRA 或部分冻结、掺入一些预训练数据联合训练——而检验补救的办法永远是受控的闭环评测。

::: algorithm 一套微调流程 {#alg-finetune}
1. 选基座模型：让它的预训练动作空间、相机与控制频率尽量与你的机器人匹配；读它的许可证。
2. 把你的示范转成基座模型的格式；设定动作空间；在你的数据上计算归一化统计量。
3. 先在几条回合计上做一次短的健全性训练（几百步），确认模型能把它们过拟合——这能抓住格式与归一化的错误。
4. 微调（全量或 LoRA），间隔保存检查点；可选地掺入一部分预训练或网络数据。
5. 在固定的初始条件集合上闭环评测多个检查点，包括分布外的物体位置与其他任务的指令。
6. 选定检查点；把基座模型、数据版本、统计量、超参数与评测结果记录在一起。
:::

::: history
在预训练网络上为新任务微调，是现代深度学习的开创性实践：2014年起，ImageNet 预训练的卷积网络被微调去做检测与分割；预训练语言模型（BERT 与 GPT，2018）则被微调去做下游语言任务。LoRA（Hu 等，2021）与 QLoRA（Dettmers 等，2023）让十亿参数模型的适配负担得起。在机器人领域，RT-2的联合微调（2023）证明了把网络数据留在混合里的价值；Octo 与 OpenVLA（2024）发布的基座模型明确供他人微调（包括用 LoRA）；π0（2024）则把面向机器人数据的宽预训练与精选后训练的分工明确摆了出来。
:::

::: summary
- VLA 的训练：VLM 预训练、在多个具身形态加权混合数据上的机器人预训练、然后在精选目标数据上后训练。
- 混合权重$w_i\propto n_i^\alpha$在按比例与均匀采样之间插值；盯紧小数据集的轮数。
- 与网络数据联合训练、给骨干更低的学习率、冻结与梯度绝缘，保护 VLM 的知识不被遗忘。
- 逐具身形态归一化（均值/标准差或分位数）、填充与掩码、具身形态专属的头与统一时间基准，让一个模型能从许多机器人身上学习。归一化统计量要随检查点一起发布。
- 带 Adam 的全量微调约需$16P$字节；LoRA 每个矩阵训练$r(m+k)$个参数（70亿模型在秩32时约1%），且合并后推理零额外开销。
- 过拟合与遗忘要在机器人上判断：记住的轨迹、无视指令、脆弱。
:::

## 习题

::: exercise 单个矩阵上的 LoRA {#exr-lora1 level=1 check="65536"}
秩8的 LoRA 适配器加在一个$4096\times4096$矩阵上，有多少可训练参数？（输入数字。）
::: solution
$r(m+k) = 8\times8192 = 65\,536$，即该矩阵 $16.8$ 百万个条目的0.39%。
:::
:::

::: exercise 全量微调的内存 {#exr-full level=1 check="52.8"}
按每参数16字节计算，一个33亿参数模型的权重、梯度与 Adam 状态需要多少内存？（以 GB 输入。）
::: solution
$16\times3.3\times10^9 = 52.8\,\mathrm{GB}$，外加激活。
:::
:::

::: exercise 按比例权重 {#exr-prop level=1 check="0.25"}
两个分别含300与100条回合的数据集以$\alpha = 1$混合。较小数据集的权重是多少？（以小数输入。）
::: solution
$100/400 = 0.25$。
:::
:::

::: exercise 平方根加权 {#exr-sqrt level=2 check="0.366"}
同样两个数据集以$\alpha = 0.5$混合，求较小数据集的权重。（保留三位小数。）
::: solution
$\sqrt{100}/(\sqrt{300} + \sqrt{100}) = 10/(17.32 + 10) = 0.366$。
:::
:::

::: exercise 反归一化 {#exr-unnorm level=2 check="0.008"}
夹爪旋转维度的第1与第99百分位是$-0.04$与$0.08\,\mathrm{rad}$。模型输出$\bar a = -0.2$。求动作。（以 rad 输入。）
::: solution
$a = q_{01} + (\bar a + 1)(q_{99} - q_{01})/2 = -0.04 + 0.8\times0.12/2 = -0.04 + 0.048 = 0.008\,\mathrm{rad}$。注意$\bar a = 0$映射到百分位区间的中点$0.02\,\mathrm{rad}$，而不是零动作：统计量不对称时，“中性”输出仍会让关节动起来。
:::
:::

::: exercise 小数据集的轮数 {#exr-epochs level=2 check="40"}
一次微调跑20,000步、批量大小64，数据集有32,000个样本。这是多少轮？（输入数字。）
::: solution
$20\,000\times64/32\,000 = 40$轮——对32,000个高度相关的数据帧来说是很多次；小心出现记住轨迹。
:::
:::

::: exercise 为什么 LoRA 省算力不如省内存 {#exr-compute level=3}
解释为什么对7B 模型做 LoRA 微调能把内存大约省到七分之一（[[#ex-lora]]），而训练 FLOP 省得少得多。估计 LoRA 训练相对全量微调的每词元 FLOP。
::: solution
内存降得多，是因为梯度与优化器状态只为适配器保留。算力降得少：前向穿过冻结权重仍要花每词元$2P$；反向为了够到下方的适配器，仍要把激活梯度穿过每个冻结层传播（约$2P$），只是跳过了冻结矩阵的权重梯度计算（另外那$2P$）。因此 LoRA 训练约为每词元$4P$对$6P$——大约三分之二——再加上适配器自身的一点开销。
:::
:::

::: exercise 一条新机械臂的微调方案 {#exr-plan level=3}
贵公司的新7自由度机械臂以关节空间控制、500 Hz 运行，配两个腕部相机和一个场景相机。你要微调一个开源的 π0风格基座模型（主要在别的机械臂上预训练过），做五个装配任务。写一份方案，覆盖动作空间、归一化、数据、全量与 LoRA 微调、联合训练与评测。
::: solution
一份好方案：(1) 动作空间——绝对关节目标（7 + 夹爪），策略频率50 Hz、每块50步，插值到500 Hz；同时记录末端执行器位姿。若基座模型的混合里有7自由度关节空间机械臂，匹配它的约定（顺序、单位）。(2) 在你的数据上逐维计算归一化统计量；填充到模型的动作维度并做掩码。(3) 相机映射到模型的相机槽位（场景与腕部），位置保持一致。(4) 数据——每个任务几百条多样化示范，附恢复示范，五个任务再共享一个数据池；留出初始条件用于评测。(5) 具身形态是新的，若算力允许优先全量微调（或高秩 LoRA 加上完整训练的动作专家）；训一个多任务模型，而不是五个。(6) 掺入一部分基座模型的预训练数据或网络数据以保护语言遵循，并用错误任务的指令做测试。(7) 在初始条件匹配、带置信区间的情况下闭环评测各检查点；把权重、统计量与评测一起交付。
:::
:::
