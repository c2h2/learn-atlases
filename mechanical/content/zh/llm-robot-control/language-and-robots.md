操作员走到一个机器人单元前说道：“把工作台清干净，但扭矩扳手留在原处。”这句话的每个词对人来说都轻而易举。“清干净”意味着把散落的零件拾起并放到合适的地方；“工作台”是机械臂面前的台面，而不是身后的架子；“扭矩扳手留在原处”意味着别碰某一个特定的物体，而它首先得被找到。常规机器人程序根本无法接受这句话。它需要零件编号、抓取位姿、放置位姿和动作顺序，由系统集成商提前写好。大语言模型（LLM）能读懂这句话，但它看不见工作台，不知道机械臂能伸多远，也从未感受过零件从夹爪中滑脱。本课程要讲的就是把两者结合：保留你已经拥有的、经过验证的机器人栈——运动规划器、关节控制器，以及[[robot-arm-design/software-stack]]里的抓取检测器——再把语言模型放到它上面，作为理解请求并决定做什么的那个部件。

这第一章说明语言模型能贡献什么、缺少什么；解释为什么通顺的计划往往是不可行的计划（**接地问题**）；用一个简单的概率模型说明误差为何在多步任务上复合放大；比较把语言与运动连接起来的四种主要架构；并给出决定哪种架构适合某个单元的延迟与成本数字（截至2026年）。语言模型的背景知识——Transformer、提示、工具使用——在LLM图谱中讲授，例如[提示设计](/learn/llm/lesson.php?c=prompting-rag&l=prompt-design)和[函数调用与工具](/learn/llm/lesson.php?c=agents&l=function-calling)；这里我们视其为已知，专注于机器人。

## 语言模型带来什么 {#sec-knows}

语言模型以预测文本为目标训练，而互联网、手册与书籍中的文本包含着关于物体与任务的海量日常知识。没有人把它写成数据库，但它隐含在其中：杯子装有液体时要竖直搬运，刀具要刀柄朝前递给别人，螺丝刀与螺丝成对，从罐子里倒出东西之前要先取下盖子，易碎品要放在箱子上面而不是底部。对机器人程序员来说，这正是手工编码既枯燥、又会在每次产品组合变化时失效的那类知识。

::: definition 可供性 {#def-affordance}
一个物体的**可供性**（affordance）是该物体为某个智能体使可能的动作：把手可供握持，抽屉可供拉开，平整稳定的台面可供放置。这个术语来自心理学家吉布森（James J. Gibson，1977）。在机器人学里它有两种用法，本课程加以区分：**语义可供性**，即知道某类物体适合某个动作（“马克杯可以握住把手拿起”）；以及**物理可供性**，即*这台*机器人*此刻*确实能对*这个*物体执行该动作（马克杯在可达范围内，把手没有被遮挡，夹爪张得足够开）。
:::

语言模型擅长语义可供性，以及与之相关的三件事：

- **任务分解。**“为下一班次清理工作台”变成一张子任务清单——清走废料、把工具放回工具形迹板、擦净夹具——因为类似的分解出现在无数成文的规程里。
- **解析模糊指称。**“我用来拧M8螺栓的那个东西”可以根据上下文解析为“扭矩扳手”或“8 mm内六角扳手”；解析不了时，模型还能提出澄清问题。
- **把意图翻译成约束。**“别把任何东西放到量规上面”和“先做重零件”变成规划器能够执行的排序与放置约束。

模型还能可靠地写代码、填写结构化表单，这对下面的架构至关重要：一个能针对有文档的API产出正确JSON对象或简短Python函数的模型，就能驱动机器人，而从不亲手发出电机指令。

## 语言模型不知道什么 {#sec-doesnt}

它缺少什么，这份清单同样重要，这正是本课程余下部分存在的理由。

1. **度量几何。**文本模型对距离、角度、间隙没有可靠的感觉。它也许“知道”马克杯大约10 cm高，但它算不出一个12 cm的夹爪能否放进相距11 cm的两个盒子之间。视觉-语言模型（[[llm-robot-control/vision-language-perception]]章）能缩小这个缺口却填不上它；度量答案必须来自深度感知与几何。
2. **机器人的本体。**模型不知道臂展、负载、关节限位、夹爪行程或装着哪个工具——除非你告诉它——而即使告诉了，它也是把这些数字当作文本而不是运动学来推理。
3. **当前的场景。**它没看过工作台。它说的任何关于物体位置的话，要么是你放进它上下文的内容，要么是猜测。
4. **机器人的技能。**它不知道你的单元里有一个验证过的`pick_from_tray`技能却没有`pour`技能，也不知道吸盘夹爪抓不了带孔的薄板。
5. **动力学与接触。**摩擦、滑移、柔顺、插入连接器所需的力：这些都无法从文本可靠地学到。

缺了其中任何一样，模型也不会沉默。它会产出一个“读起来”很好的计划。这个失效模式有个名字。

::: definition 幻觉可行性 {#def-hallucinated-feasibility}
当一个计划的每一步在语义上都讲得通、计划整体也通顺，但至少有一步对实际场景中的实际机器人来说物理上不可能或不安全时，这个计划就表现出**幻觉可行性**——够不到的物体、不在场的物体、机器人没有的技能、超出额定值的负载，或者会发生碰撞的放置。
:::

::: example 一个读起来漂亮却跑不起来的计划 {#ex-shelf}
一台臂展$0.85\,\mathrm m$（从肩部轴线到法兰）的六轴机械臂安装在桌子上，肩部高于地面$0.75\,\mathrm m$。操作员让它“把备用滤芯放到顶层架子上”。只看到这条请求的LLM给出一个整齐的四步计划：找到滤芯、逐个拿起、移到顶层架子、放下。顶层架子高于地面$1.90\,\mathrm m$，其前沿与肩部轴线水平相距$0.40\,\mathrm m$。这个计划可行吗？
::: solution
目标点比肩部高$1.90 - 0.75 = 1.15\,\mathrm m$、在其前方$0.40\,\mathrm m$，到肩部的距离
$$
d = \sqrt{0.40^2 + 1.15^2}\,\mathrm m = 1.218\,\mathrm m
$$
超过了$0.85\,\mathrm m$的臂展$0.37\,\mathrm m$——这还没算夹爪长度和滤芯——所以没有任何关节位形能够到架子。LLM计划的每一个词都讲得通；第3步却不可能。一个在执行前用逆运动学检查每个目标位姿的系统会在几毫秒内拒绝这个计划；一个轻信文本的系统则会把机械臂推向完全伸直的奇异位形然后失败，或者更糟：尝试最接近的可达位姿，把滤芯掉下。合理性检查：$1.2\,\mathrm m$对比$0.85\,\mathrm m$，差了43%——不是标定误差能解释的临界情况。
:::
:::

::: warning 通顺不等于可行
第一次把LLM接到机器人上时最常见的错误，就是把写得漂亮的计划当作计划能奏效的证据。语言模型被训练去产出貌似合理的文本；貌似合理与物理可行互不相干。模型的自信程度、解释的质量、答案里有没有数字（“向左移动0.3 m”），都不能告诉你这个运动是否可达、是否无碰撞。模型提出的每个动作，都必须由了解机器人与场景的部件来检查。
:::

### 接地问题 {#sec-grounding}

远在LLM出现之前，哲学家与认知科学家就在追问语言的符号如何获得意义；哈纳德（Stevan Harnad）把这一问题称为**符号接地问题**（1990）。对机器人来说，这个问题很具体。

::: definition 接地 {#def-grounding}
对语言模型的输出做**接地**，就是把它里面的每个符号接到机器人能够测量或能够做到的东西上：物体名接到机器人基坐标系中带位姿的检测物体，动词接到机器人技能库中前置条件可检查的技能，空间词（“左边”“上面”“附近”）接到在当前场景上求值的几何谓词。当输出的每一个指称都解析到这样一个实体时，称该输出**已接地**，否则**未接地**。
:::

对LLM做接地有三种互补的途径，本课程后面三种都会用到：

- **给输入接地。**把机器人的技能、限位和当前场景的描述放进模型的上下文，让它针对真实情况推理（[[llm-robot-control/grounded-task-planning]]章和[[llm-robot-control/vision-language-perception]]章）。
- **给输出接地。**把模型能说的话限制在机器人能做的事上：固定的技能清单、带类型的工具调用，或者一个小API，使得不存在倒水技能时连“pour”都无法表达（[[llm-robot-control/code-as-policies]]章和[[llm-robot-control/robot-tool-calling]]章）。
- **通过反馈接地。**执行、观测，并把发生了什么告诉模型，让它修正自己对世界的图景（[[llm-robot-control/closed-loop-recovery]]章）。

单靠哪一种都不能让模型的输出可信。接地能减少模型出错的频率；模型*之下*的检查与限值（[[llm-robot-control/llm-guardrails]]章）才决定出错时会发生什么。

::: quiz
已知机器人的技能列表，以及一条写着“red bin at (0.42, −0.10, 0.05) m”的场景描述，一个LLM规划出“pick the blue bin”。哪种接地能阻止这个计划到达运动规划器？
- [ ] 给输入接地：更长的场景描述
- [x] 给输出接地：要求物体参数必须是当前场景列表中的标识符，并拒绝一切不合规的引用
- [ ] 都不行——这是幻觉，无法预防
- [ ] 更大的语言模型
::: solution
输入其实已经接地——场景列表就在上下文里——模型仍然引用了一个不存在的物体。输出接地会机械地拦住它：如果`pick`只接受取自当前检测列表的`object_id`（工具schema里的枚举，或一个会抛出错误的查找），那么对不存在的蓝色箱子的引用在任何运动被规划之前就会被拒绝，错误还可以反馈给模型。更大的模型会让这类错误更少，但不会绝迹；机械的检查才是可靠的修复。
:::
:::

## 误差为何复合放大 {#sec-compound}

用语言下达的机器人任务通常有好几步，而每一步都可能失败：计划可能是错的，物体可能被误检，抓取可能滑脱。一个简单的模型说明了为什么长任务需要在每一步而不是只在最后做检查。

::: proposition 多步任务的成功概率 {#prop-compound}
设一个任务由$n$步组成，并设在前面的所有步骤都成功的条件下，第$i$步以概率$p_i$成功；任务只有当每一步都成功时才成功。则任务成功概率为
$$
P_{\text{task}} = \prod_{i=1}^{n} p_i ,
$$ {#eq-compound}
当各步可靠性相等时即为$p^n$。此外，若失败的一步以概率$d$被检出，且被检出的失败会以同样的成功概率$p$重试一次，则每步成功概率为
$$
p' = p + (1 - p)\,d\,p ,
$$ {#eq-retry-once}
任务成功概率为$(p')^n$。
:::

::: proof
设$S_i$为第$i$步成功的事件。由条件概率的乘法公式（[条件概率](/learn/maths/lesson.php?c=probability&l=conditional-probability)），$\Prob(S_1\cap\dots\cap S_n) = \Prob(S_1)\,\Prob(S_2\mid S_1)\cdots\Prob(S_n\mid S_1\cap\dots\cap S_{n-1}) = \prod p_i$，任务恰好在这个交事件上成功。除了把$p_i$定义为条件概率之外，不需要任何独立性假设。至于重试：一步要么第一次尝试就成功（概率$p$），要么失败（$1 - p$）、失败被检出（$d$）且重试成功（$p$）；这两种情形互斥，所以$p' = p + (1 - p)dp$。未被检出的失败，概率$(1 - p)(1 - d)$，使任务以失败告终。我们假设重试的成功概率等于$p$，即失败的尝试没有让情况变得更糟——真实系统必须通过恢复到已知状态来兑现这一假设。
:::

乘积下降得很快。八步、每步95%，得到$0.95^8 = 0.663$：每步“几乎总是”成功，任务却大约每三次就失败一次。第二个公式指出了杠杆所在：在良好的故障检测（$d = 0.9$）与单次重试下，每步成功率升到$0.95 + 0.05\times0.9\times0.95 = 0.9928$，八步任务升到$0.9928^8 = 0.943$。故障检测比更好的规划器更值钱：它是[[llm-robot-control/closed-loop-recovery]]的主题。

caption: 任务成功概率随步数$n$（把横轴读作$n$）的变化。下面的曲线是开环乘积$p^n$；上面的曲线加入了概率为$d$的故障检测与一次重试。从$p = 0.95$开始：开环成功率仅两步之后就跌到90%以下。把$d$提高到1，看90%这条线向右移多远；再把$d = 0$，两条曲线重合——故障不被察觉时，重试一文不值。
:::

::: example 每一步必须多可靠？ {#ex-step-reliability}
客户要求十二步配料任务在90%的情况下不经操作员干预即可完成。不用重试时这需要每步多高的可靠性？在$d = 0.95$且重试一次时，首次尝试的可靠性至少要多少才够？
::: solution
不用重试时，$p^{12} \ge 0.90$给出$p \ge 0.90^{1/12} = 0.99126$：每一步必须有99.1%的成功率——对杂乱环境中的抓取已是苛求，更不必说语言部分。有了检测与一次重试，我们需要$p' = p + (1 - p)(0.95)p \ge 0.99126$。这是一个二次不等式$-0.95p^2 + 1.95p - 0.99126 \ge 0$；相关的根为
$$
p = \frac{1.95 - \sqrt{1.95^2 - 4(0.95)(0.99126)}}{2(0.95)} = 0.9285 .
$$
所以只要失败能被发现并重试，约93%的首次成功率就够了。检验：$0.9285 + 0.0715\times0.95\times0.9285 = 0.9916$ ✓。对系统设计的启示是：每步93%与99%之间6个百分点的差距，用检测来买远比用更强的模型来买便宜。
:::
:::

## 四种架构 {#sec-architectures}

把语言模型接到机械臂上有四种成熟的路线。它们的区别在于模型输出什么，因而其下的各层必须检查什么也不同。

::: definition LLM作为规划器 {#def-planner}
模型接收指令、机器人技能列表和场景描述，输出一个**固定词表上的技能调用序列**，例如`[pick(cartridge_3), place(cartridge_3, shelf_2)]`。传统的执行器逐个验证并运行每个技能。SayCan（2022）是经典例子；[[llm-robot-control/grounded-task-planning]]对此详细展开。
:::

::: definition LLM作为程序员 {#def-programmer}
模型针对有文档的机器人API写一个**短程序**——通常是Python——该API带有感知查询（`detect`、`get_pose`）和动作（`move_to`、`grasp`、`place`）。程序可以包含循环、条件判断和算术，所以一次生成就能表达“把每个红色零件拣起来，排成一排放下，间隔5 cm”。程序运行在沙箱里，沙箱检查每一次API调用。Code as Policies（2022）是经典例子；见[[llm-robot-control/code-as-policies]]。
:::

::: definition LLM作为工具调用器 {#def-toolcaller}
机器人的能力被暴露为**带JSON schema的带类型工具**，模型在智能体循环中一次调用一个或几个，在决定下一次调用之前先读取每个工具的结果。这就是到2024年所有主流LLM API都提供的函数调用接口，也是模型上下文协议（MCP）所标准化的接口；见[[llm-robot-control/robot-tool-calling]]。
:::

::: definition 端到端视觉-语言-动作模型 {#def-vla}
**视觉-语言-动作（VLA）模型**是单个网络，以控制频率（通常5–50 Hz）把相机图像与指令直接映射为低层动作（末端执行器或关节目标）。它用机器人示范数据训练，而不是靠提示工作；VLA课程的[[vision-language-action/vla-architectures]]章对它作了描述。VLA可以作为LLM规划器之下的一个技能——即[[llm-robot-control/closed-loop-recovery]]的分层布置。
:::

前三种把模型放在经过验证的栈*之上*，区别只在粒度。规划器从菜单里点菜；程序员写菜谱；工具调用器与机器人一次一句地对话。第四种则把学习到的行为放进栈*里面*。

| | 规划器 | 程序员 | 工具调用器 | 端到端VLA |
|---|---|---|---|---|
| 模型输出 | 技能序列 | Python程序 | JSON工具调用 | 5–50 Hz的动作 |
| 每任务模型调用数 | 1（外加重新规划） | 1（外加修复） | 3–20 | 连续 |
| 检查内容 | 技能名、前置条件 | 代码（静态检查）、每次API调用 | schema、每次调用 | 输出限值、安全层 |
| 处理循环/算术 | 差 | 好 | 中等 | 不适用 |
| 对新观测的响应 | 步与步之间 | 仅当程序主动轮询时 | 每次调用之后 | 每个控制周期 |
| 需要机器人训练数据 | 不需要（技能已存在） | 不需要 | 不需要 | 需要，且量大 |
| 典型失败 | 技能顺序错误 | 微妙的逻辑错误 | 循环又长又慢 | 不可预测的分布外运动 |

如何选择？决定因素与其说是模型，不如说是单元。

::: algorithm 架构选型 {#alg-choose}
1. **列出单元已有的技能**及其验证方式。如果任务就是现有可靠技能的组合（pick、place、open fixture、scan），从规划器或工具调用器开始：LLM只需要选择和排序。
2. **检查任务是否需要算术、循环或空间模式**（“每隔一个槽位”“30 mm间距的4 × 5网格”）。需要的话，就在该层加入代码生成，或者提供把模式作为参数的技能。
3. **检查场景在任务执行中变化多大。**如果后面的步骤取决于前面步骤揭示的内容（打开箱子看看里面有什么），优先选择每次调用后都有观测的工具调用循环。
4. **检查所需运动究竟能不能编出来。**柔性物体、线缆布线、擦拭，以及其他难以经典编程的富接触技能，是学习策略（VLA或更小的学习技能）的用武之地，把它们放在语言层*之下*。
5. **对照下一节的数字检查延迟预算。**每次调用1–3 s的延迟对一条配料命令是可以接受的；在控制回路里则不可接受。
6. **无论选哪种，都在其下设置同样的硬限值**——工作空间、速度、力、碰撞检查——并把每次模型输出连同它通过的检查一起记入日志。
:::

2026年的多数生产系统是混合体：一个工具调用智能体，它的工具里包含一个处理多步序列的规划器、一个处理模式的沙箱代码工具，以及一两个用于富接触步骤的学习技能。

::: quiz
一条食品包装线接到这样的订单：“把托盘每种口味各装三个，交替摆放，四角放巧克力。”pick-and-place技能很可靠；装箱图案每单都在变。哪种架构能最自然地处理这种图案？
- [ ] 端到端VLA，因为任务是视觉的
- [ ] 在固定槽位名的`pick`与`place`之间做选择的规划器
- [x] 代码生成：写一个短程序计算槽位序列并调用现有技能
- [ ] 都不行：LLM帮不了装箱图案
::: solution
难点是组合与算术（交替、四角约束、计数），一个短程序几行就能表达，而且能在任何东西动起来之前检查——例如模拟出装箱后的托盘布局。规划器可以逐个列出3 × $k$个放置动作，但长长的平铺列表正是LLM数错的地方。VLA则需要每种模式的示范。在所有方案里，pick-and-place运动本身仍然是被验证过的技能。
:::
:::

## 延迟与成本 {#sec-latency}

一个每次移动前先停顿十秒的机器人让人觉得它出了故障，而每个控制周期调用一次模型是不可能的。这些数字决定了语言模型可以坐在栈的哪一层。它们变化很快；下面的数值是截至2026年托管前沿模型的典型值，你应当为自己的部署重新测量。

一次模型调用的时间由两项主导：**首词元时间**$t_{\text{ft}}$（网络往返、排队与输入处理，随输入长度增长），以及以速率$r$生成$N_{\text{out}}$个输出词元：
$$
T_{\text{call}} \approx t_{\text{ft}} + \frac{N_{\text{out}}}{r} .
$$ {#eq-call-latency}
这是一个模型，不是定律：它忽略了网络抖动和$r$随服务器负载的变化；“先思考再作答”的模型还会往$N_{\text{out}}$里加上隐藏的思考词元。截至2026年，托管中型前沿模型的典型值为$t_{\text{ft}} \approx 0.3$–$1.5\,\mathrm s$、$r \approx 50$–$200$词元/秒；部署在本地GPU上的小模型能力较低，但可以达到$t_{\text{ft}} < 0.1\,\mathrm s$。一个词元大约相当于四分之三个英文单词，一个带位姿的JSON工具调用约50–150个词元。托管模型按每百万词元计价；截至2026年末，某主要厂商的一档中档模型大约每百万输入词元\$2、每百万输出词元\$10，小模型便宜一到两个数量级。重复的前缀（系统提示、工具定义）可以被多数提供商**缓存**，只按输入价格的一小部分收费。

::: example 一次工具调用命令的延迟与成本 {#ex-latency}
一个工具调用智能体处理“把三个螺栓放进左边的托盘”。它需要五轮模型调用（检测，然后pick/place调用，最后汇报）。每轮生成约150个词元；输入是一个6,000词元的前缀（系统提示、工具schema、场景），并随着工具结果被追加而每轮增加约300词元。取$t_{\text{ft}} = 0.8\,\mathrm s$、$r = 80$词元/秒、每百万输入词元\$2、每百万输出词元\$10，不使用缓存。估算每条命令的模型时间与成本，以及每天1,000条命令的成本。
::: solution
由[[#eq-call-latency]]，每轮$T = 0.8 + 150/80 = 2.675\,\mathrm s$；五轮共$13.4\,\mathrm s$模型时间，*此外*还有运动时间（三个pick-and-place周期大约$15$–$20\,\mathrm s$）。五轮的输入词元：$6000 + 6300 + 6600 + 6900 + 7200 = 33{,}000$，花费$33{,}000\times\$2\times10^{-6} = \$0.066$；输出$750$词元花费$\$0.0075$。每条命令合计约$\$0.074$，按每天1,000条算是$\$74$。两点观察：成本由输入主导（每轮重发前缀），这正是前缀缓存划算的原因；模型时间与运动时间相当，这正是场景可预测时规划器与代码架构（每任务一次模型调用）有吸引力的原因。一次生成400词元的代码调用花费$0.8 + 400/80 = 5.8\,\mathrm s$。
:::
:::

三个结论塑造了后面各章的架构。**绝不要把托管模型放进控制回路**：每次调用1–3 s，它能选下一个子任务，选不了下一个关节目标；关节控制留在控制器里以1 kHz运行，轨迹下发以100–500 Hz运行。**让每次调用做足量的工作**：一个`pick_and_place(object, target)`工具胜过`move_to`、`open_gripper`、`move_to`、`close_gripper`一连串调用。**为断网做好准备**：模型不回应时，机械臂必须保持安全静止，或者能够完成当前技能。

::: example 对比：一个VLA的延迟预算 {#ex-vla-rate}
一个在本地GPU上运行的VLA用$80\,\mathrm{ms}$的推理，为接下来的$0.8\,\mathrm s$生成一个含16个末端执行器目标的“动作块”。它每秒能产出多少个块？若每$0.4\,\mathrm s$重规划一次（每块执行一半），推理占用多大比例的时间？
::: solution
每次推理$80\,\mathrm{ms}$，它每秒可以产出$12.5$个块。每$0.4\,\mathrm s$重规划一次占用GPU时间的$0.08/0.4 = 20\%$，各目标相隔$0.8/16 = 50\,\mathrm{ms}$（20 Hz），由更低层的控制器插补。对比$1$–$3\,\mathrm s$一次的托管LLM调用：比一个VLA动作块慢10–40倍。两者属于分层的不同层级——VLA把“拿起线缆”变成运动，LLM决定接下来该去拿线缆。
:::
:::

## 语言模型在栈中的位置 {#sec-stack}

把这些部件拼起来，一条语言控制的机械臂有五层，每层以自己的速率运行，而且每层都能拒绝上一层的请求：

1. **交互**（秒级）：语音或文本输入，确认与提问输出。
2. **语言模型**（每次调用秒级）：规划、写代码或调用工具；看到的是技能、限值、场景摘要与执行结果。
3. **技能与感知**（几十毫秒到秒级）：开放词汇检测、抓取规划、pick、place、insert；每个技能检查自己的前置条件。
4. **运动规划与轨迹生成**（毫秒到秒级）：无碰撞路径与时间标定轨迹，如[[robotics/motion-planning-perception]]与[[robotics/trajectory-planning]]所述。
5. **控制与安全**（1 kHz及更快）：关节伺服回路，以及带有速度、力和区域限值的安全额定控制器（[[robot-arm-design/arm-safety]]）。

命令向下流动并在每一层被检查；观测向上流动并在每一层被摘要。语言模型永远看不到原始关节力矩，也永远不发送它们。这条分界线是本课程最重要的设计决策：它意味着模型给出错误答案时，最坏也只是得到一个被拒绝的请求，或者一个做了合理却非所求之事的技能——而不是失控运动。

::: history
Terry Winograd的SHRDLU（MIT，1968–1970）在一个彩色积木的模拟世界里回答问题、服从英语命令，用手写语法把句子解析成过程；它惊艳了所有人，出了那个世界却什么都不会泛化。Shakey（SRI，1966–1972）是第一个对自身行动进行推理的移动机器人，使用Richard Fikes和Nils Nilsson（1971）的STRIPS规划器。在整个1990年代和2000年代，机器人的“自然语言接口”指的是把受限英语映射为逻辑式的语义解析器（例如Tellex等，2011的概率接地图）。大规模预训练语言模型的到来改变了局面：2022年，Google的SayCan把一个5400亿参数的语言模型与移动操作机器人上学到的技能价值函数结合起来；Code as Policies让模型编写机器人程序；Inner Monologue把观测反馈给模型。2023年，RT-2与PaLM-E把视觉与语言带进一个直接产出动作的单一模型，开启了端到端VLA这条路线。到2025–2026年，函数调用API与模型上下文协议已让“LLM作为工具调用者”成为默认的工业接口。
:::

::: summary
- LLM懂得语义可供性、任务结构与日常物体知识；不懂得度量几何、机器人的本体、当前场景、可用技能与接触动力学。
- 通顺却在物理上不可能的计划是**幻觉可行性**（[[#def-hallucinated-feasibility]]）；每个被提出的动作都必须由了解机器人的部件检查。
- **接地**（[[#def-grounding]]）把词绑定到检测结果、技能与几何谓词——途径是输入、允许的输出与反馈。
- 多步成功是一个乘积，$P = \prod p_i$（[[#prop-compound]]）；带重试的故障检测把每步可靠性提高到$p + (1 - p)dp$，比换更好的模型便宜。
- 四种架构：规划器（技能序列）、程序员（对API写代码）、工具调用器（循环中的带类型调用）、端到端VLA（控制频率的动作）；生产系统把它们混合使用。
- 截至2026年，一次托管模型调用约为$0.3$–$1.5\,\mathrm s$加上$N_{\text{out}}/r$，其中$r \approx 50$–$200$词元/秒；别让模型进控制回路，让每次调用做足量的工作。
- 模型位于技能、规划与安全额定控制器之上；它从不发送电机指令。
:::

## 习题

::: exercise 十步任务 {level=1 check="0.737"}
一个任务有十步，每步成功概率为$0.97$，没有重试。任务成功的概率是多少？（概率保留三位小数。）
::: solution
由[[#prop-compound]]，$P = 0.97^{10} = 0.737$。每步97%的时间里都工作，任务却有超过四分之一会失败。
:::
:::

::: exercise 够得着吗？ {level=1 check="0.778"}
一台臂展（从肩部算起）为$0.90\,\mathrm m$的机械臂，肩部高于地面$0.80\,\mathrm m$。一个料箱放在高于地面$0.25\,\mathrm m$处，与肩部轴线水平相距$0.55\,\mathrm m$。从肩部到料箱的距离是多少，料箱在不在可达范围内？（距离以m计，保留三位小数。）
::: solution
料箱比肩部低$0.80 - 0.25 = 0.55\,\mathrm m$、在其前方$0.55\,\mathrm m$，所以$d = \sqrt{0.55^2 + 0.55^2} = \sqrt{0.605} = 0.778\,\mathrm m < 0.90\,\mathrm m$。法兰能够到这个点，但$0.12\,\mathrm m$的余量还得容下夹爪长度和接近方向，所以可行性检查必须针对完整抓取位姿用逆运动学来做，而不能只看距离。
:::
:::

::: exercise 一次调用的延迟 {level=1 check="2.5"}
一个模型的首词元时间为$0.5\,\mathrm s$，生成速度为$100$词元/秒。一次产出200词元工具调用的调用需要多长时间？（时间以s计。）
::: solution
由[[#eq-call-latency]]，$T = 0.5 + 200/100 = 2.5\,\mathrm s$。
:::

::: exercise 所需的步骤成功率 {level=2 check="0.99126"}
一个十二步任务要在不用重试的情况下有90%的成功率，每一步需要多大的成功概率？（概率保留五位小数。）
::: solution
$p = 0.90^{1/12} = 0.99126$，同[[#ex-step-reliability]]。
:::

::: exercise 使用缓存的成本 {level=2 check="0.0303"}
重做[[#ex-latency]]的成本估算，假设提供商缓存了那个6,000词元的前缀：第2–5轮中，这6,000词元按每百万\$0.20而不是每百万\$2计费，而第一轮以及前缀之后新增的词元仍按全价计费；输出不变。每条命令的成本是多少？（成本以美元计，保留四位小数。）
::: solution
第一轮：$6000$词元全价，$\$0.012$。第2–5轮：缓存的前缀$4\times6000 = 24{,}000$词元按$\$0.20$每百万，$\$0.0048$；未缓存的增量$300 + 600 + 900 + 1200 = 3000$词元按$\$2$每百万，$\$0.006$。输出$750$词元，$\$0.0075$。合计$0.012 + 0.0048 + 0.006 + 0.0075 = \$0.0303$，约为未缓存时$\$0.0735$的41%。输出如今占账单的四分之一，所以简短的工具调用对成本和对延迟同样重要。
:::
:::

::: exercise 模型不知道的东西 {level=2}
对“把抽屉里的10 mm套筒递给我”这条命令，列出机器人系统必须知道、而只拿到这句话的语言模型无从知道的一切，并为每一项指出应当提供它的部件。
::: solution
(1) 是哪个抽屉、它在哪里：场景地图或一次感知查询。(2) 抽屉是否开着、机械臂有没有开抽屉的技能：带前置条件的技能库，加上抽屉状态的感知。(3) 在众多相似的套筒里哪个是10 mm套筒：开放词汇检测，最好再加上基准标记或已知的存放布局，因为“10 mm”字样印得很小，VLM很容易读错。(4) 套筒是否可达、可抓：在其实测位姿上做逆运动学与抓取规划。(5)“我”在哪里、如何安全交接：人体检测、一个降低速度与力限值的交接技能，以及安全控制器的协作运行限值。(6) 工作空间里是否还有别人：这是安全系统的事，不是模型的事。模型贡献的是任务分解——开抽屉、找套筒、拿起、递交——以及把“10 mm套筒”落实到物体类别。
:::
:::

::: exercise 检测对比首次成功率 {level=2}
一个团队要么(a)换用更大的模型，把步骤的首次成功率从$0.92$提高到$0.96$，要么(b)保持$p = 0.92$，加一个$d = 0.85$的成功检测器和一次重试。十步任务哪个成功率更高？
::: solution
(a) $0.96^{10} = 0.665$。(b) $p' = 0.92 + 0.08\times0.85\times0.92 = 0.9826$，且$0.9826^{10} = 0.839$。加检测与重试明显胜出。两者结合：$p' = 0.96 + 0.04\times0.85\times0.96 = 0.9926$，且$0.9926^{10} = 0.928$。
:::
:::

::: exercise 不止重试一次 {level=3}
把[[#eq-retry-once]]推广到最多$k$次重试：每次失败都独立地以概率$d$被检出，每次尝试以概率$p$成功。证明该步的成功概率为
$$
p'_k = p\sum_{j=0}^{k}\bigl((1-p)d\bigr)^j = p\,\frac{1 - ((1 - p)d)^{k+1}}{1 - (1 - p)d},
$$
并求$k\to\infty$时的极限。当$d < 1$时，这个极限对“更多重试”的价值说明了什么？
::: solution
第$j + 1$次尝试（$j = 0, \dots, k$）成功，当且仅当前$j$次尝试都失败且每次都被检出——概率$((1 - p)d)^j$——且第$j + 1$次成功，概率$p$。不同$j$的事件互斥，所以$p'_k$就是这些项之和，一个公比为$q = (1 - p)d < 1$的等比级数，由此得到闭式。当$k\to\infty$时，$p'_\infty = p/(1 - (1 - p)d)$。对$p = 0.95$、$d = 0.9$：$p'_1 = 0.99275$，$p'_\infty = 0.95/0.955 = 0.99476$。上限由未被检出的失败决定：最终发生未检出失败的概率是$1 - p'_\infty = (1 - p)(1 - d)/(1 - (1 - p)d)$。超过一两次重试之后，改进$d$是唯一的杠杆——而且实际上重试还消耗时间，并可能让场景变得更糟。
:::
:::

你公司销售一款负载7 kg的机床上下料机械臂。客户想说“从左边托盘装入接下来五个毛坯，带划痕的跳过”“这批之后换长夹爪”这类话。用[[#alg-choose]]提出一个架构，说明哪些部件已经存在、哪些必须新建，并指出你会最先测试的两个失效模式。
::: solution
一个合理的回答：在现有的机床上下料技能之上放一个工具调用智能体。已有：已知托盘几何的托盘拣取、机床门/卡盘接口、换刀装置、安全控制器。需要暴露的工具：`list_pallet_slots`、`inspect_blank(slot)`（用VLM或经典视觉检查划痕，返回一个分数和一张供记录用的图像裁剪）、`load_blank(slot)`、`change_gripper(name)`、`get_cell_state`。跳过与计数（“接下来五个”“跳过划痕的”）是智能体能通过多次调用处理的简单逻辑；模式变复杂时可加一个小的沙箱代码工具。不需要VLA：运动是结构化的，而且已经编好。硬限值留在控制器与技能里（机床门联锁、换夹爪时的负载检查）。首先测试的失效模式：(1)划痕检测——错误的接收会把坏件送进机床，所以要记录每个决定，并在留出的零件上度量精确率与召回率；(2)计数中的状态混乱——智能体装了六个或四个毛坯，或在一次重试的抓取之后数错了数；用“抓取在序列中途失败”的脚本场景来测试，并把最终计数与单元自己的计数器核对，后者才应是事实来源，而不是模型的记忆。
