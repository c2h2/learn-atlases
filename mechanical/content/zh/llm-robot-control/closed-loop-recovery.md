一个经过验证的计划、一个通过了检查的程序、一次参数完美的工具调用，在与世界相遇时都可能失败。螺栓从指间滑脱；盒盖弹回；检测器发现的那个零件其实是个反光。在[[llm-robot-control/language-and-robots#prop-compound]]里我们见过那道算术：每步95%的可靠性，八步任务平均每三次就有一次失败，而检测失败并重试能把任务成功率抬到约94%。本章讲如何让这成为现实。内容包括**成功检测**——系统如何知道一步是否成了：凭夹爪与力信号、凭重跑感知、凭询问一个视觉-语言模型；**状态反馈**——每步之后该告诉语言模型什么、不该告诉什么；**恢复与重规划**——一个由局部重试、重新观察、重规划与上报组成的分层策略，重试预算用一条简单的期望代价规则选取；以及到2025–2026年已成为把语言模型与学得的机器人策略相结合的主要方式的**分层**系统，其中LLM或VLM选择语言子任务，由[[vision-language-action/vla-architectures]]所述的那种视觉-语言-动作（VLA）模型执行它们。

## 成功了吗？成功检测 {#sec-success}

::: definition 成功检测器 {#def-success-detector}
一个技能的**成功检测器**是在技能运行之后，把可得的观测——本体感知、力与力矩、图像、其他传感器——映射为一个关于技能是否达成其预期效果的“成功”或“失败”决定（在可得之处附上置信度）的函数。它的质量由一个代表性测试集上的两个错误率描述：**误接受率**$\alpha$，即技能失败却报告成功的概率，与**漏报率**（误拒绝率）$\beta$，即技能成功却报告失败的概率。
:::

这两种错误代价悬殊。一次误拒绝导致一次不必要的重试——损失几秒，偶尔还有一次反而有害的重试（多抓了一个零件）。一次误接受则让计划在错误的世界图景上继续——下一步什么也没放下，或者配料套件缺件出厂——而它即便最终被发现，也已经很晚。因此多数单元把检测器调到低的误接受率，容忍更多的误拒绝。

成功信号分三档，从最快最便宜到最慢最通用：

| 档位 | 信号 | 例检查 | 延迟 | 局限 |
|---|---|---|---|---|
| 本体感知 | 夹爪指位与电流；关节力矩；力-力矩传感器 | 手指停在与物体宽度相符的开口处；提起后的负载估计；压入力曲线达到到位力 | ms | 说不出夹的是*哪个*物体、放在了*哪里* |
| 感知 | 重跑检测与位姿估计 | 物体从源处消失、在容差内出现在目标处 | 0.1–0.5 s | 被夹爪遮挡；检测器错误 |
| 语义 | 就图像向VLM问一个是非问题 | “M6螺栓在左托盘里吗？”；“盖子完全关严了吗？” | 0.5–2 s | 较慢；可能自信地答错；必须在你的单元上标定 |
| 工艺 | 单元传感器 | 秤、夹具到位传感器、螺丝刀的扭矩-角度曲线 | ms | 只限于装了的场合 |

最好的检测器组合多个档位。一次拾取由手指开口*加上*物体从源处消失来确认；一次放置由手指在正确高度的张开*加上*目标处的检测来确认；一颗螺钉由起子的扭矩-角度曲线来确认。

::: proposition 组合独立的检测器 {#prop-combine}
设两个成功检测器的误接受率为$\alpha_1, \alpha_2$、漏报率为$\beta_1, \beta_2$，并假设给定真实结果时它们的错误独立。只有当**两者**都报成功时（AND规则）才宣布成功，得到
$$
\alpha_{\wedge} = \alpha_1\alpha_2,\qquad \beta_{\wedge} = 1 - (1 - \beta_1)(1 - \beta_2);
$$ {#eq-and-rule}
**任一**报成功（OR规则）就宣布成功，则$\alpha_{\vee} = 1 - (1 - \alpha_1)(1 - \alpha_2)$且$\beta_{\vee} = \beta_1\beta_2$。
:::

::: proof
以技能失败为条件。AND规则下的误接受要求两个检测器都接受；由条件独立性，概率为$\alpha_1\alpha_2$。以技能成功为条件：AND规则只有在两个检测器都不漏报时才报成功，概率$(1 - \beta_1)(1 - \beta_2)$，于是漏报率是1减它。OR规则是它的镜像：除非两个检测器都正确拒绝，否则就发生误接受，$1 - (1 - \alpha_1)(1 - \alpha_2)$；而漏报要求两者都漏，$\beta_1\beta_2$。独立性是关键假设，而且常常部分地不成立：若一颗螺栓藏在手指之下，相机*和*看着同一幅图像的VLM会以同样的方式失败，所以*不同物理信号*的组合比看着同一张图的两个模型的组合更接近独立。
:::

::: example 夹爪加VLM {#ex-combine}
一个“夹着螺栓吗？”的夹爪宽度检查有$\alpha_1 = 0.04$（它在手指停在托盘边缘上时接受）与$\beta_1 = 0.01$。一个在腕部相机图像上被问“夹爪指间有螺栓吗？”的VLM有$\alpha_2 = 0.06$与$\beta_2 = 0.05$，在500次记录的抓取上测得。比较AND规则与OR规则。在一个10%的抓取会失败的单元里，两种规则下每1,000次抓取各发生多少次误接受与误拒绝？
::: solution
AND：$\alpha = 0.04\times0.06 = 0.0024$，$\beta = 1 - 0.99\times0.95 = 0.0595$。OR：$\alpha = 1 - 0.96\times0.94 = 0.0976$，$\beta = 0.01\times0.05 = 0.0005$。每1,000次抓取里有100次失败与900次成功。AND：误接受$100\times0.0024 = 0.24$次，误拒绝$900\times0.0595 = 53.6$次。OR：误接受$9.8$次，误拒绝$0.45$次。AND规则以每1,000次抓取约54次不必要的检查或重试为代价，几乎消除了那个昂贵的错误；若重试是“重新抓取”，那可能害多于利，所以对AND规则的拒绝，更好的响应是先“再看一眼”（把夹爪移开、重跑感知）再重试。合理性检查：0.24%的误接受率仍不是零——下游检查（配料的重量、终检）仍然值得做。
:::
:::

### 问VLM成没成

一次语义成功检查是一个单一、窄措辞的问题，配一个结构化回答。问“机器人完成任务了吗？”招来的是含糊的回答；问一个可观察的事实、把图像裁剪到相关区域，效果要好得多。

```python
SUCCESS_SCHEMA = {
    "type": "object",
    "properties": {
        "answer": {"type": "string", "enum": ["yes", "no", "cannot_tell"]},
        "evidence": {"type": "string", "maxLength": 200}
    },
    "required": ["answer", "evidence"],
    "additionalProperties": False,
}

def vlm_check(image_crop, question: str) -> str:
    """Ask one yes/no question about a cropped image; 'cannot_tell' counts as failure."""
    reply = vlm.ask(image=image_crop,
                    prompt=f"Answer only about what is visible. {question}",
                    schema=SUCCESS_SCHEMA)          # structured output, see robot-tool-calling
    log_success_check(question, reply)
    return reply["answer"]
```

允许`cannot_tell`很要紧：在被遮挡的图像上强要一个是或非的答案只会产出猜测。问题模板每个技能固定（“Is the {object} inside the {target}?”），由计划填充，并在记录的图像上评估，直到它的错误率为人所知——VLM的成功检查是一个传感器，必须像传感器一样表征它。

::: warning 成功检测器会漂移
一月份在500次抓取上表征过的检测器，到六月可能就错了：新的零件颜色、不同的托盘、变了的照明、提供商的一次模型更新。持续记录检测器的输入与决定，手工（或对照一个更慢的真值，比如称一称配料的重量）审计随机样本，并在单元、模型版本或提示词的每次改动之后重新测量$\alpha$与$\beta$。一个版本会不打招呼就改变的主机托管VLM，是一个标定可能不打招呼就改变的传感器；在提供商允许的范围内钉住模型版本。
:::

## 该告诉模型什么 {#sec-feedback}

每步之后，语言模型需要足够的信息来决定下一步——也仅此而已，因为每一点反馈都花延迟和钱，并稀释模型的注意力。一条好的结果消息，无论是[[llm-robot-control/robot-tool-calling]]的工具结果，还是Inner Monologue记录里的一行（[[llm-robot-control/grounded-task-planning#sec-monologue]]），都有四个部分：

1. **结果**：`succeeded`、`failed`或`uncertain`，出自成功检测器，附上检测器的名字。
2. 失败时的**原因**，用技能的词汇：`grasp_empty`（手指完全闭合）、`object_moved`（目标不在原来的位置了）、`ik_failed`、`collision_predicted`、`timeout`、`force_limit`。
3. 场景中对计划要紧的**变化**：物体的新位姿；一个新可见的物体；所持物体。
4. **机器人状态**：夹爪里有什么，机械臂是否在安全位姿，当前错误。

两条规则让反馈可信。**单元是它可测状态的真值来源**：套件里零件的计数来自单元自己对已确认放置的记录，而不是模型对对话的记忆。而**历史记录随增长被摘要**：二十步之后，模型需要的是当前状态加一份简短的“做了什么、失败了什么”清单，而不是二十份完整的场景转储。

::: example 上下文的增长 {#ex-context}
一个长配料任务的每一步追加一次约80个词元的工具调用与一条约350个词元的结果（一份十个物体的场景摘要）。固定前缀是6,000个词元。40步之后上下文有多大？把完整场景摘要换成约120个词元的“变化”结果、再加一个400词元的当前状态块，能省下什么？
::: solution
完整结果：$6000 + 40\times(80 + 350) = 6000 + 17{,}200 = 23{,}200$个词元，而整个任务计费的输入是逐步之和，约$\sum_{k=1}^{40}(6000 + 430k) = 240{,}000 + 430\times820 = 592{,}600$个词元。用“变化”结果：结束时$6000 + 400 + 40\times(80 + 120) = 14{,}400$个词元，总计约$\sum_{k=1}^{40}(6400 + 200k) = 256{,}000 + 164{,}000 = 420{,}000$个词元——少29%，而且每次调用更快，因为首词元时间随输入长度增长。更大的收益是准确性：上下文里堆着十份几乎相同的场景转储，模型读到过期位姿的可能性更大。
:::
:::

## 恢复与重规划 {#sec-recovery}

一步失败时，最便宜的有效响应取决于它*为什么*失败。分层的恢复策略先试便宜的响应，逐级升级。

::: algorithm 分层恢复策略 {#alg-recovery}
输入：失败的一步及其失败原因；计划；每步的重试预算$k_{\max}$；操作员接口。
1. **确保安全。**把机械臂带到一个已知状态：停止，按技能规定张开或保持夹爪，退到安全位姿。读取机器人状态。
2. **重新观察。**对受影响的区域跑感知并更新场景。许多“失败”在这里化解：物体其实已被抓走了，或它现在出现在一个新位置、能被看见。
3. **局部重试**（不涉及语言模型）：若原因是技能知道如何应对的那类（物体仍在时的`grasp_empty`、只移动了一小段的`object_moved`），用更新后的参数重试同一技能，总共至多$k_{\max}$次尝试，尝试次数记在单元上，而不是记在模型的记忆里。
4. **重规划**（语言模型或规划器）：若局部重试用尽，或原因不属于局部（`ik_failed`、`object_missing`、有意外物体挡路），把失败、更新后的场景与剩余目标发给规划器，请求一个新计划；照[[llm-robot-control/grounded-task-planning#alg-validate]]那样验证它。
5. **上报。**若重规划失败、或同一失败再次出现、或失败原因与安全有关（`force_limit`、近人时的`collision_predicted`、`protective_stop`），停下并求助操作员，说明尝试过什么、已知什么。
:::

第1步值得强调。在*任何*重试之前，系统必须知道机器人与物体的状态：从未知状态发起的重试，正是一次可恢复的滑脱变成碰撞的途径。

### 重试几次？

重试不是免费的，而且它们并不相互独立：若一次抓取失败是因为零件卡住了，第二次尝试的成功可能性比第一次还低。一个简单的代价模型能把这道权衡摆到明面上。

::: proposition 再多一次重试何时划算 {#prop-retry-rule}
设对某一步的第$m$次尝试（$m = 0, 1, 2, \dots$），在之前所有尝试都失败的条件下以概率$p_m$成功；每次尝试花时间$t_a$；最后一次尝试失败后上报操作员花时间$t_e$。设$F_m = \prod_{j<m}(1 - p_j)$为前$m$次尝试全部失败的概率（$F_0 = 1$）。在$M$次尝试的预算下，这步的期望时间为
$$
E_M = t_a\sum_{m=0}^{M-1}F_m + F_M\,t_e ,
$$ {#eq-retry-time}
而增加第$M$次尝试使它改变
$$
E_{M+1} - E_M = F_M\,\bigl(t_a - p_M\,t_e\bigr).
$$ {#eq-retry-delta}
因此第$M$次尝试减少期望时间当且仅当$p_M\,t_e > t_a$。若诸$p_m$不增，最优预算就是：只要$p_m > t_a/t_e$就继续尝试，在第一个$p_m\le t_a/t_e$的$m$处上报。
:::

::: proof
第$m$次尝试只在尝试$0, \dots, m - 1$都失败时才被做出，其概率为$F_m$，花费$t_a$；上报只在全部$M$次尝试都失败时才发生，概率$F_M$。把期望代价相加即得[[#eq-retry-time]]。从$M$次到$M + 1$次尝试，增加了第$M$次尝试的代价$F_Mt_a$，并把上报项$F_Mt_e$替换为$F_{M+1}t_e = F_M(1 - p_M)t_e$；两者之差是$F_M\bigl(t_a + (1 - p_M)t_e - t_e\bigr) = F_M(t_a - p_Mt_e)$。因为$F_M > 0$，其符号即$t_a - p_Mt_e$的符号。若诸$p_m$不增，符号至多改变一次，从负变正，于是$E_M$在$p_m > t_a/t_e$时递减、此后递增；最小值在不等式首次不成立的那个$m$处。这个模型略去了重试可能把事情弄得更糟（把零件打落到桌下）的可能；那会给每次尝试加上一项代价，并把阈值压得更低。
:::

::: example 选一个重试预算 {#ex-retry-budget}
一次抓取尝试花$t_a = 6\,\mathrm s$，一次操作员干预花$t_e = 120\,\mathrm s$。第一次尝试以$p_0 = 0.7$成功；记录数据表明，在之前尝试都失败的条件下，其后每次尝试的成功可能性都是前一次的一半：$p_m = 0.7\times0.5^m$。什么重试预算使期望时间最小？那个时间是多少？与（错误的）“每次尝试都以$0.7$成功”假设下的答案比较。
::: solution
阈值是$t_a/t_e = 0.05$。各次尝试的成功概率是$0.7, 0.35, 0.175, 0.0875, 0.0438, \dots$；第一个低于$0.05$的是$p_4 = 0.0438$。所以做尝试$0$–$3$——共四次尝试、三次重试——在第四次失败后上报。由[[#eq-retry-time]]求期望时间：$F_0 = 1$，$F_1 = 0.3$，$F_2 = 0.195$，$F_3 = 0.1609$，$F_4 = 0.1468$，于是$E_4 = 6(1 + 0.3 + 0.195 + 0.1609) + 0.1468\times120 = 9.94 + 17.62 = 27.6\,\mathrm s$。再多一次尝试给$27.7\,\mathrm s$，少一次给$28.3\,\mathrm s$——一个平缓的最优。在尝试独立的假设下，每次重试都显得划算（$0.7\times120 = 84 > 6$），而五次尝试会预测期望时间低于$9\,\mathrm s$——过度乐观得厉害，因为现实中一个连拒三次抓取的零件通常是被卡住或被误检测了。合理性检查：仍有15%的步骤走到操作员那里，这正是[[#alg-recovery]]的第2步（重新观察）加上换一个策略重规划，比第四次一模一样的抓取更值钱的原因。
:::
:::

f: ta*(1 - (1 - p)^(x + 1))/p + (1 - p)^(x + 1)*te
x: 0, 8
y: 0, 60
sliders: p=0.7:0.05:0.95:0.01; ta=6:1:30:0.5; te=120:20:600:10

caption: 某步的期望时间对重试次数$k$（横轴；$k + 1$次尝试），每次尝试有恒定的成功概率$p$、尝试时间$t_a$、上报时间$t_e$。当$p\,t_e > t_a$时曲线随每次重试下降，在$t_a/p$处趋平；把$t_e$往$t_a/p$拖，曲线就变平，低于它重试只会加时间。记住真实的重试是相关的：恒定$p$的曲线是乐观界，而递减$p_m$下的[[#prop-retry-rule]]给出的是现实的预算。
:::

::: quiz
一个螺钉压入技能以原因`force_limit`（实测压入力超过其限值）失败。[[#alg-recovery]]规定作何响应？
- [ ] 用更高的力压入限值立即重试
- [ ] 请语言模型换一颗螺钉重规划
- [x] 确保安全、重新观察，若原因不明明是良性的就上报操作员——力限值与安全有关
- [ ] 当作成功，因为螺钉多半进去了
::: solution
达到力限值，要么是零件出了问题（乱扣、进错孔、毛刺），要么是有意外之物在接触——在协作单元里可能是人的手。在软件里抬高限值以“闯过去”，违背了限值的目的，而绝不能给LLM改变它们的能力。安全的默认做法是停下、退开、查看，并请操作员介入；在分析过记录的案例之后，可以针对某些良性的具体原因（一个已知的错位）设置局部恢复。
:::
:::

## 分层：给学得的技能派语言子任务 {#sec-hierarchy}

到目前为止本课程里的技能是程序化的：拾取、放置、压入，各由集成商调校。有些任务抗拒编程——理线束、折袋子、擦曲面、抓取纠缠成堆的零件——而学到的**视觉-语言-动作**策略恰在这些任务上最强。然而VLA不擅长长任务：它一次只按一条短指令执行几秒，而它的训练数据里很少有几分钟的流程。两者的结合很自然。

::: definition 分层语言条件控制 {#def-hierarchy}
在**分层语言条件控制**中，一个**高层**模型——LLM或VLM——以低频率（通常每几秒一次，或在子任务边界处）观察场景与任务，并发出一个**语言子任务**（“拿起左连接器附近的黑色线缆”，“把插头推入3号端口”），从低层策略训练时所用的指令中选出、或与其很接近。一个**低层**策略——一个VLA，或一组学得的或程序化的技能——以控制频率（5–50 Hz的动作块）执行子任务，条件是指令与相机图像。一个**子任务监视器**决定子任务何时完成、停滞或失败，并把控制权交还高层。
:::

到2025年，已有若干团队发表了这种形状的系统。Physical Intelligence的Hi Robot（2025）用一个VLM把开放式指令和用户中途的纠正（“不是那个，另一个三明治”）拆解成给其π0 VLA的短指令。Google DeepMind把VLA模型Gemini Robotics与具身推理模型Gemini Robotics-ER配对，后者负责规划并把VLA当作工具调用（2025）。Figure称其Helix模型是一个慢速的“System 2”视觉-语言模型引导一个快速的“System 1”视觉运动策略（2025）。更早的RT-H（Google DeepMind，2024）表明，一层居间的“语言动作”（“把机械臂往前移”“合上夹爪”）能让低层策略更容易被语言纠正。

层间的接口，就是本课程的全部教训再应用一次：**把高层的输出接地在低层能做的事上。**对一个以“带一点晃动地插入插头”为条件的VLA，如果它在训练里从没见过这个短语，它可能做出难以预料的事。实用的系统会把低层策略在其上训练并评测过的指令模板清单连同实测成功率一起交给高层模型，完全像一份技能库（[[llm-robot-control/grounded-task-planning#def-skill]]），并把每条指令当作一个带前置条件和成功检查的技能。

::: example 让两层流水线起来 {#ex-pipeline}
一个线束任务有六个子任务。高层VLM选每个子任务要$1.5\,\mathrm s$；VLA执行每个约$5\,\mathrm s$；每个末尾的VLM成功检查花$0.8\,\mathrm s$。比较两层严格串行时的总时间，与高层在当前子任务执行期间选*下一个*子任务（假设成功，检查失败则丢弃所选）时的时间。
::: solution
串行：$6\times(1.5 + 5 + 0.8) = 43.8\,\mathrm s$。流水线：第一次选择花$1.5\,\mathrm s$；此后每个子任务的选择都在前一个子任务$5\,\mathrm s$的执行期间完成，不再添加时间；总$1.5 + 6\times(5 + 0.8) = 36.3\,\mathrm s$，省17%。若下一个子任务不依赖成功检查的结果，检查也可以与它的开头重叠，但通常是依赖的。当检查失败时，投机做出的选择被丢弃，高层从观察到的状态重新规划，花掉那$1.5\,\mathrm s$——流水线本来把它藏了起来。合理性检查：节省量以高层每子任务时间×子任务数$6\times1.5 = 9\,\mathrm s$减去第一次选择为上界——$7.5\,\mathrm s$ ✓。
:::
:::

::: remark 监视一个学得的技能
程序化的技能知道自己何时完成；VLA除非被训练成发出“完成”信号，否则自己不会停。所以子任务监视器综合使用一个**超时**（子任务典型时长的一个倍数）、**进度信号**（末端执行器一秒没动；目标物体没有移动）、**力与接触异常**，以及周期性地向VLM提出的一个**成功问题**。一个停滞或来回振荡的VLA，是学得的技能版的抓取失败：确保安全、重新观察、换个说法重试一次或移交程序化恢复，然后上报。
:::

::: history
在感知与动作之间闭合回路是机器人学里最古老的思想——反馈控制——但在*计划*的层级上闭合它是后来的事。Shakey的PLANEX执行程序（1972）用记录每步所需条件的“三角表”监视STRIPS计划的执行，使机器人能在意外变化之后从正确的点重新进入计划。执行监视与重规划在1980–1990年代成为规划体系结构的标准部分（例如Gat等人的三层架构：审议式规划器、执行程序与反应式技能）。学成的成功检测器随2010年代的深度学习而出现。2022年，Inner Monologue（Huang等）把成功检测与场景描述作为文本反馈给LLM规划器；2023年，多项工作把VLM用作成功检测器与奖励模型（例如Du等的《Vision-Language Models as Success Detectors》）。从2024年起，推理模型与VLA的分层结合成为主流架构，发表的例子包括RT-H（2024）、Hi Robot、Helix与Gemini Robotics（2025）。
:::

::: summary
- 一个**成功检测器**（[[#def-success-detector]]）有误接受率$\alpha$与漏报率$\beta$；误接受的代价通常高得多，所以调向低$\alpha$。
- 组合物理机理不同的信号（夹爪、力、视觉、工艺传感器、对VLM的提问）；错误独立时，AND规则给出$\alpha_1\alpha_2$，OR规则给出$\beta_1\beta_2$（[[#prop-combine]]）。
- 向VLM问一个窄的、模板化的问题，配一个允许`cannot_tell`的结构化回答；像表征任何传感器一样表征它，并在改动后重新测量。
- 反馈结果、原因、变化与机器人状态；以单元为真值来源，并把历史摘要化。
- **恢复**（[[#alg-recovery]]）：确保安全、重新观察、局部重试、重规划、上报；与安全有关的失败交给操作员。
- 再一次尝试划算当且仅当$p_m t_e > t_a$（[[#prop-retry-rule]]）；因为重试相关，预算都很短。
- **分层**（[[#def-hierarchy]]）：LLM/VLM从低层策略训练过的指令库中选择语言子任务；VLA执行；一个带超时、进度、力与成功检查的监视器负责交还控制权。
:::

## 习题

::: exercise AND规则 {level=1 check="0.0015"}
两个独立的成功检测器的误接受率是$0.03$与$0.05$。AND规则的误接受率是多少？（以比例填入。）
::: solution
$\alpha_\wedge = 0.03\times0.05 = 0.0015$。
:::
:::

::: exercise OR规则的漏报率 {level=1 check="0.0006"}
两个独立检测器的漏报率是$0.02$与$0.03$。OR规则的漏报率是多少？（以比例填入。）
::: solution
$\beta_\vee = 0.02\times0.03 = 0.0006$。
:::
:::

::: exercise 重试阈值 {level=1 check="0.04"}
一次尝试花$8\,\mathrm s$，一次操作员干预花$200\,\mathrm s$。成功概率低于多少时，再一次尝试就不值得做了？（填入概率。）
::: solution
由[[#prop-retry-rule]]，一次尝试划算当且仅当$p\,t_e > t_a$，即$p > 8/200 = 0.04$。
:::
:::

::: exercise 两次尝试的期望时间 {level=2 check="21.6"}
$t_a = 6\,\mathrm s$、$t_e = 120\,\mathrm s$、$p_0 = 0.8$、$p_1 = 0.4$，两次尝试预算下一步的期望时间是多少？（时间以s计。）
::: solution
$F_1 = 0.2$且$F_2 = 0.2\times0.6 = 0.12$，由[[#eq-retry-time]]，$E_2 = 6(1 + 0.2) + 0.12\times120 = 7.2 + 14.4 = 21.6\,\mathrm s$。对照：一次尝试给$E_1 = 6 + 0.2\times120 = 30\,\mathrm s$；第二次尝试划算，因为$p_1t_e = 48 > 6$。
:::
:::

::: exercise 每班的误接受 {level=2 check="0.6"}
一个单元每班执行2,500次抓取；8%失败。成功检测器（夹爪宽度与重检测的AND）的误接受率为$0.003$。每班有多少次失败的抓取被当作成功接受？
::: solution
失败：$2500\times0.08 = 200$次；误接受$200\times0.003 = 0.6$次每班——大约每两个班一次，每一次都是一个缺件的配料套件，除非后续检查（称重）抓住它。
:::
:::

::: exercise 一条好的结果消息 {level=2}
写一个系统应在一次`place(bolt_m6_2, left_tray)`调用后返回给语言模型的工具结果（JSON格式）：这次调用中夹爪在正确高度张开了，但重检测发现螺栓在托盘边缘上，距目标位置$3\,\mathrm{cm}$，歪斜着。包含模型需要的一切，不包含它不需要的一切。
::: solution
```json
{"outcome": "failed", "detector": "redetect_at_target",
 "reason": "object_misplaced",
 "details": "bolt_m6_2 detected on the rim of left_tray, 0.03 m from target, tilted",
 "changed": {"bolt_m6_2": {"position": [0.512, 0.188, 0.034], "pose_note": "tilted, unstable"}},
 "robot": {"holding": null, "at_safe_pose": true, "errors": []},
 "suggestion_allowed": ["grasp", "ask_operator"]}
```
它用技能的词汇给出结果与原因、新位姿（模型因此不必再调一次`get_scene`）、机器人状态，以及可选的当前适用的技能。它不包含完整场景、图像、无关物体的原始检测分数，也不写叙事。
:::
:::

::: exercise 相关的重试 {level=3}
证明：若每次尝试都以相同的概率$p$独立成功且$p\,t_e > t_a$，则期望时间[[#eq-retry-time]]随每次额外尝试递减，并趋于$t_a/p$。解释为什么这个模型对设定重试预算是危险的，并给出$p_m$随$m$递减的两个物理原因。
::: solution
$p$恒定时，$F_m = (1 - p)^m$且$E_{M+1} - E_M = (1 - p)^M(t_a - pt_e) < 0$对每个$M$成立，所以更多尝试永远有帮助。当$M\to\infty$，$F_M t_e\to0$而$t_a\sum_{m\ge0}(1 - p)^m = t_a/p$。这个模型的危险在于它推荐不设上限的重试。物理上，失败的原因是持续的：零件被卡住或缠住，检测器一贯地误定位它（反光、标定错误），夹爪指垫被污染，物体在学习所得抓取模型的训练分布之外。每次失败的尝试都是一个证据，表明这样持久的原因存在，于是下一次一模一样尝试的条件成功概率下降。此外，尝试还可能把场景变得更糟（把零件推到角落里）。预算必须由记录在案的条件成功率得出，而重试应当改变策略（重新观察、换一种抓取），而不是重复它。
:::
:::

::: exercise 配料单元的检测器设计 {level=3}
为一个把六种不同零件放进带凹槽泡沫内衬的单元设计成功检测，可用信号：夹爪位置与电流、腕部相机、顶部相机、套件下方的秤、一个VLM。对每个技能（拾取、放置、套件终检），说明你组合哪些信号、按什么规则，以及如何测量$\alpha$与$\beta$。
::: solution
拾取：（手指开口在该零件宽度带内，且电流卡停）与（顶部图像中该零件从其来源处消失）的AND；两个信号的失效原因不同，故α低。放置：（在预期高度的张开）与（秤的增量在该零件质量的±10%以内）与（顶部相机检测到零件在正确的凹槽里）的AND；秤使检查几乎独立于视觉。套件终检：秤的总重在容差内等于物料清单质量，且对每个凹槽做一次VLM或经典检查（“D零件的凹槽填了吗？”）AND——凹槽里放错零件这件事，若质量相近，单靠质量可能漏掉，VLM在这里就有用。测量：记录每个决定及其输入；通过有意制造失败（空抓、放错位置的零件、对调的零件）与成功来构造测试集；按技能计算α与β并带置信区间（要断定α接近0.003，你需要数千个失败案例，或者从各组件的独立率做一个统计学论证）；每次改动后重跑。把“不完整套件的下游比率”作为端到端指标报告。
:::
:::

::: exercise 设计一个分层接口 {level=3}
一个VLA在40条线缆操作指令模板上做了微调，实测成功率介于55%与95%之间。描述你如何把它们呈现给高层模型；对成功率为55%的模板，高层应当怎么做；对匹配不上任何模板的操作员请求，你如何处理。
::: solution
把模板当作技能库呈现：名字、带槽位的指令模板（“拿起{connector}附近的{colour}线缆”）、前置条件（线缆可见、夹爪为空）、监视器使用的成功检查、实测成功率与典型时长。高层随后像SayCan那样带着可行性推理：对一条55%的模板，若另一条成功率更高的模板能达到同样效果，它应当优先选后者；按[[#prop-retry-rule]]规划一次重新观察与重试预算；也许还请操作员把线缆摆得更合适。对匹配不上任何模板的请求，高层绝不能凭空编一条自由格式的指令然后指望VLA照办；它应当尽量把请求分解成模板，或者告诉操作员系统还做不到（并把请求记录下来——这类记录是下一步该采集哪些示范的最好指南）。这让语言层的输出始终接地在低层实际被证明能做的事情上。
:::
:::
