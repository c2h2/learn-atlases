一个研讨会只有一个报告厅，收到了十一份报告申请，每份都有固定的起止时间；至多能不冲突地安排多少份报告？一家有线电视公司要沿现有的道路铺设光缆连接一批城镇，使总造价最低。一个压缩程序要用尽可能少的比特对文本编码。每个问题的候选解都多得不计其数——报告的子集、道路的集合、编码方案——然而每一个都能由这样一个算法解决：它一次一块地构造解，每次选*眼下*看起来最好的一块，而且从不反悔：最早结束的报告、不构成回路的最便宜的边、两个出现最少的字符合并成一个。

这样的算法称为**贪心**的。它们简单而快，但大多数贪心算法是错的：局部最优的选择可能导致全局很差的解。因此贪心算法真正有趣的部分是它的**证明**。本章讲授两种标准证明技术——*贪心领先*（greedy stays ahead），把贪心解与最优解一步步比较；以及**交换论证**，把最优解在不使之变差的前提下改造成贪心解——并把它们用于区间调度、带截止时间的调度、哈夫曼编码与最小生成树。讲到生成树时我们还会遇到**并查集**数据结构，对它的分析是本学科的一桩瑰宝。迪杰斯特拉算法（[[algorithms/shortest-paths#thm-dijkstra]]）本来就是一个贪心算法；它的证明就是一次领先论证。

## 区间调度：贪心领先

**区间调度。**给定 $n$ 个请求，请求 $i$ 占用半开区间 $[s_i, f_i)$，求两两**相容**（互不重叠）的请求的最大集合。

有好几条贪心规则都会浮现在脑海：取*开始*最早的请求，或*最短*的请求，或与最少其他请求*冲突*的请求。三条都会失败（[[#ex-greedy-rules]]）。奏效的规则是：**取最早结束的请求**，丢弃一切与它重叠的请求，然后重复。

::: algorithm 最早结束时间优先 {#alg-eft}
把请求按结束时间排序，$f_1 \le f_2 \le \dots \le f_n$。令 $A = \emptyset$，$\ell = -\infty$。对 $i = 1, \dots, n$：若 $s_i \ge \ell$，把 $i$ 加入 $A$ 并置 $\ell \gets f_i$。返回 $A$。
:::

检验 $s_i \ge \ell$ 检查的是与 $A$ 中*所有*请求的相容性：每个已选请求都至多在 $\ell$ 结束。运行时间为排序的 $O(n\log n)$ 加扫描的 $O(n)$。

::: theorem 最早结束时间优先最优 {#thm-eft}
[[#alg-eft]] 返回一个规模最大的相容请求集合。
:::

::: proof
设 $A = \{i_1, \dots, i_k\}$ 为贪心解（按选取次序），$O = \{j_1, \dots, j_m\}$ 为某个最优集合，按结束时间排序（由于其中区间互不重叠，它也按开始时间排序）。由构造法，$A$ 是相容的；须证 $k \ge m$。

*贪心领先：*对每个 $r \le k$，$f_{i_r} \le f_{j_r}$。$r = 1$ 时成立，因为 $i_1$ 在所有请求中结束时间最小。设对 $r - 1$ 成立且 $r \le m$。于是 $j_r$ 在 $j_{r-1}$ 结束之后开始，故 $s_{j_r} \ge f_{j_{r-1}} \ge f_{i_{r-1}}$：请求 $j_r$ 与 $i_1, \dots, i_{r-1}$ 相容，在贪心作第 $r$ 次选取时它是可用的。贪心选取的是可用请求中结束时间最小的，故 $f_{i_r} \le f_{j_r}$。

现在反设 $m > k$。由断言在 $r = k$ 的结论，$f_{i_k} \le f_{j_k} \le s_{j_{k+1}}$，于是请求 $j_{k+1}$ 与 $A$ 全体相容；但贪心只有当没有剩余请求与 $A$ 相容时才停止——矛盾。故 $k = m$。
:::

```python
def max_compatible(intervals):
    """Greedy by earliest finish time; intervals are (start, finish) pairs."""
    chosen, last_finish = [], float('-inf')
    for s, f in sorted(intervals, key=lambda iv: iv[1]):
        if s >= last_finish:             # 与所有已选请求相容
            chosen.append((s, f))
            last_finish = f
    return chosen

talks = [(1, 4), (3, 5), (0, 6), (5, 7), (3, 9), (5, 9), (6, 10),
         (8, 11), (8, 12), (2, 14), (12, 16)]
print(max_compatible(talks))
```

```console
$ python3 intervals.py

```

::: solution
按结束时间排序，报告依次为 $[1,4), [3,5), [0,6), [5,7), [3,9), [5,9), [6,10), [8,11), [8,12), [2,14), [12,16)$。贪心取 $[1,4)$；跳过 $[3,5)$、$[0,6)$（它们在 $4$ 之前开始）；取 $[5,7)$；跳过 $[3,9)$、$[5,9)$、$[6,10)$；取 $[8,11)$；跳过 $[8,12)$、$[2,14)$；取 $[12,16)$：四份报告。由 [[#thm-eft]]，四份就是最大数目。要直接看出这一点，注意四个时刻 $3.5$、$6.5$、$10.5$ 和 $15$ “刺穿”了每一份报告：$[1,4)$、$[3,5)$、$[0,6)$、$[3,9)$ 和 $[2,14)$ 包含 $3.5$；$[5,7)$、$[5,9)$ 和 $[6,10)$ 包含 $6.5$；$[8,11)$ 和 $[8,12)$ 包含 $10.5$；$[12,16)$ 包含 $15$。两份相容的报告不能包含同一时刻，所以相容集合在每个刺点上至多有一份报告：至多四份。
:::

例中点集的存在并非巧合：贪心所选报告的结束时间（稍微提前一点）总是构成这样一组“刺点”，这两个数目相等正是 [[algorithms/network-flow]] 所发展的对偶性的一个小例子。

## 交换论证：带截止时间的调度

**最小化最大晚度。**一台机器要一次一个地加工 $n$ 个作业。作业 $j$ 需要加工时间 $t_j > 0$，有截止时间 $d_j$。从时刻 $0$ 开始、没有空闲时间的调度给出作业 $j$ 的完工时间 $f_j$ 和**晚度** $L_j = \max(0, f_j - d_j)$。目标是使最大晚度 $L = \max_j L_j$ 最小。

最短作业优先的贪心会失败（加工时间长而截止时间早的作业被排到最后），“最小松弛量 $d_j - t_j$ 优先”也会失败。奏效的规则完全不管加工时间：**最早截止时间优先**（EDF）。

::: theorem 最早截止时间优先最优 {#thm-edf}
在没有空闲时间的条件下，按截止时间非降次序安排各作业使最大晚度最小。
:::

::: proof
调度的一个**逆序**是指一对作业 $i, j$ 满足 $d_i < d_j$ 而 $j$ 排在 $i$ 之前。EDF 调度没有逆序；而一切没有逆序、没有空闲时间的调度都有相同的最大晚度：它们只在截止时间*相等*的作业的内部次序上有差别，而这样一组作业在每个调度中占据同一段时间区间，其最后一个作业在相同时刻完工，且是组内最晚的。

取一个没有空闲时间的最优调度 $O$（空闲时间从不有利）。若 $O$ 有逆序，它就有*相邻*逆序：沿 $O$ 走过，截止时间不可能一路不降，故某处作业 $j$ 后面紧跟着一个满足 $d_i < d_j$ 的作业 $i$。把两者**交换**。只有 $i$ 和 $j$ 的晚度会改变。$i$ 现在完工更早，其晚度不增。$j$ 现在在 $i$ 原先完工的时刻 $f$ 完工，其新晚度为 $\max(0, f - d_j) \le \max(0, f - d_i)$，而后者正是 $i$ 原来的晚度。于是最大晚度不增，且逆序数减少一个。至多重复 $\binom n2$ 次，就把 $O$ 变成一个没有逆序、仍是最优的调度；由第一段，它的最大晚度等于 EDF 的最大晚度，故 EDF 最优。
:::

这就是**交换论证**的套路：（1）定义一个衡量解离贪心解有多远的量（这里是逆序数）；（2）证明任何不同于贪心解的最优解都可以经过一次局部交换使这个量减小而解不变差；（3）断言贪心解最优。

::: example 最早截止时间优先 {#ex-edf}
作业：$A$（$t = 3$，$d = 6$）、$B$（$t = 2$，$d = 8$）、$C$（$t = 1$，$d = 9$）、$D$（$t = 4$，$d = 9$）、$E$（$t = 3$，$d = 14$）、$F$（$t = 2$，$d = 15$）。按 EDF 调度并计算最大晚度。与最短作业优先比较。
::: solution
EDF 次序 $A, B, C, D, E, F$ 给出完工时间 $3, 5, 6, 10, 13, 15$ 和晚度 $0, 0, 0, 1, 0, 0$：最大晚度 $1$。（没有调度能更好：$A$、$B$、$C$、$D$ 的截止时间都不超过 $9$ 而加工时间合计 $10$，所以其中必有一个在 $10$ 或更晚完工，晚度 $\ge 1$。）最短作业优先次序 $C, B, F, A, E, D$（平局按字母序打破），$D$ 在 $15$ 完工，晚度 $15 - 9 = 6$。
:::
:::

## 哈夫曼编码

**二进制编码**给字母表 $C$ 的每个字符指派一个比特串。若没有一个码字是另一个码字的前缀，就称其为**前缀码**，于是码字的连接串可以从左到右解码而无需分隔符。前缀码等同于以字符为叶子的二叉树：一个字符的码字就是自根而下的路径，左转记 $0$、右转记 $1$。给定每个字符 $c$ 的频率 $f(c)$，用编码树 $T$ 编码一篇文本的代价为

$$
B(T) = \sum_{c \in C} f(c)\, d_T(c),
$$

其中 $d_T(c)$ 是 $c$ 的叶子深度，即其码字的长。我们要求最小代价的树。最优树必然是**满**的——每个内部结点都有两个孩子——因为单孩子的结点可以用它的孩子取代，从而缩短某些码字。

::: algorithm 哈夫曼算法 {#alg-huffman}
让每个字符成为一棵权为 $f(c)$ 的单结点树。当剩下的树多于一棵时，删去权最小的两棵树 $x$ 和 $y$，并新建一棵树：以 $x$ 和 $y$ 为子，根的权为 $f(x) + f(y)$。返回最后剩下的树。借助最小堆（[[data-structures/heaps]]），$n$ 个字符耗时 $O(n\log n)$。
:::

```python
import heapq
from itertools import count

def huffman(freq):
    """Return an optimal prefix code {symbol: bit string} for the frequencies."""
    tick = count()                       # 平局决断因子，避免树之间被比较
    heap = [(f, next(tick), sym) for sym, f in freq.items()]
    heapq.heapify(heap)
    while len(heap) > 1:
        f1, _, a = heapq.heappop(heap)   # 频率最小的两棵树
        f2, _, b = heapq.heappop(heap)
        heapq.heappush(heap, (f1 + f2, next(tick), (a, b)))
    code = {}
    def walk(tree, prefix):
        if isinstance(tree, tuple):      # 内部结点：0 = 左，1 = 右
            walk(tree[0], prefix + '0')
            walk(tree[1], prefix + '1')
        else:
            code[tree] = prefix or '0'
    walk(heap[0][2], '')
    return code

freq = {'a': 45, 'b': 13, 'c': 12, 'd': 16, 'e': 9, 'f': 5}
code = huffman(freq)
print(code)
print(sum(freq[s] * len(code[s]) for s in freq))
```

```console
$ python3 huffman.py
{'a': '0', 'c': '100', 'b': '101', 'f': '1100', 'e': '1101', 'd': '111'}
224
```

::: example 构造哈夫曼树 {#ex-huffman}
一个 $100\,000$ 个字符的文件使用六个字符，频率（以千计）为 $a{:}\,45$、$b{:}\,13$、$c{:}\,12$、$d{:}\,16$、$e{:}\,9$、$f{:}\,5$。构造哈夫曼树，并把它的代价与定长编码比较。
::: solution
各次合并，每次都是最轻的两棵树：

1. $f$ (5) + $e$ (9) $\to$ 14；
2. $c$ (12) + $b$ (13) $\to$ 25；
3. $\{f, e\}$ (14) + $d$ (16) $\to$ 30；
4. $\{c, b\}$ (25) + $\{f, e, d\}$ (30) $\to$ 55；
5. $a$ (45) + 55 $\to$ 100。

深度：$a$ 为 $1$；$b, c, d$ 为 $3$；$e, f$ 为 $4$。代价 $45 \cdot 1 + (13 + 12 + 16)\cdot 3 + (9 + 5) \cdot 4 = 45 + 123 + 56 = 224$ 千比特，与程序输出一致。定长编码对六个字符需要每字符 $3$ 比特，即 $300$ 千比特：哈夫曼编码节省约 $25\%$。
:::
:::

两条引理证明哈夫曼算法最优：一个交换论证表明第一次合并是安全的，剩下的交给归纳。

::: lemma 两个最稀字符可以互为兄弟 {#lem-huffman-swap}
设 $x$ 和 $y$ 是频率最小的两个字符。则存在某个最优编码树，使 $x$ 和 $y$ 是最大深度上的一对兄弟叶子。
:::

::: proof
设 $T$ 为最优树；它是满的，所以最深的叶子 $a$ 必有兄弟，且这个兄弟是一片叶子 $b$（它下面若还有东西就更深了）。不妨设 $f(a) \le f(b)$、$f(x) \le f(y)$，于是 $f(x) \le f(a)$、$f(y) \le f(b)$，且 $d_T(a) = d_T(b) \ge d_T(x), d_T(y)$。把 $x$ 与 $a$ 交换：代价改变
$$
f(x)d_T(a) + f(a)d_T(x) - f(x)d_T(x) - f(a)d_T(a) = -\big(f(a) - f(x)\big)\big(d_T(a) - d_T(x)\big) \le 0.
$$
再把 $y$ 与 $b$ 交换，由同样的计算知它也不增大代价。所得仍是最优树，且 $x$ 和 $y$ 成为最大深度上的兄弟叶子。（若 $x = b$ 或 $y = a$，就少交换一些叶子；计算相同。）
:::

::: theorem 哈夫曼编码最优 {#thm-huffman}
[[#alg-huffman]] 产生最优前缀码。
:::

::: proof
对 $n = \lvert C\rvert$ 归纳。$n = 2$ 时，两片叶子的树是最优的（每个码字至少需要一个比特）。设 $n > 2$，$x, y$ 为算法最先合并的两个字符，$C'$ 是把 $C$ 中 $x$ 和 $y$ 换成一个新字符 $z$、其频率为 $f(z) = f(x) + f(y)$ 得到的字母表。算法的剩余部分就是 $C'$ 上的哈夫曼算法，故由归纳假设它为 $C'$ 造出最优树 $T'$，最终树 $T$ 就是给 $T'$ 的叶子 $z$ 安上两个孩子 $x$ 和 $y$。由于 $x$ 和 $y$ 比原先的 $z$ 深一层，
$$
B(T) = B(T') + f(x) + f(y).
$$
这个关系对 $C'$ 的*任何*树、以及由它把 $z$ 拆成 $x$ 和 $y$ 所得的 $C$ 的树都成立。现在设 $S$ 是 $C$ 的一个最优树，其中 $x$ 和 $y$ 互为兄弟（[[#lem-huffman-swap]]）。把它们合并成一片叶子 $z$，得 $C'$ 的树 $S'$，满足 $B(S) = B(S') + f(x) + f(y)$。于是 $B(T) = B(T') + f(x) + f(y) \le B(S') + f(x) + f(y) = B(S)$，因为 $T'$ 对 $C'$ 最优。故 $T$ 最优。
:::

::: quiz
对频率 $a{:}\,1$、$b{:}\,1$、$c{:}\,2$、$d{:}\,4$、$e{:}\,8$，哈夫曼编码的各码字长是什么？

- [ ] 除两个 $2$ 比特外都是 $3$ 比特
- [x] $4, 4, 3, 2, 1$
- [ ] $3, 3, 2, 2, 2$
- [ ] $5, 4, 3, 2, 1$
::: solution
合并 $a + b \to 2$；再把这棵树与 $c$ 合并（$2 + 2 \to 4$）；再与 $d$ 合并（$4 + 4 \to 8$）；最后与 $e$ 合并（$8 + 8 \to 16$）。这棵树是一条“毛毛虫”：$e$ 在深度 $1$，$d$ 在 $2$，$c$ 在 $3$，$a$ 和 $b$ 在 $4$。代价 $8 + 8 + 6 + 4 + 4 = 30$，而定长 $3$ 比特编码要 $3 \cdot 16 = 48$。五个码字长为 $5, 4, 3, 2, 1$ 对满树是不可能的：最深的叶子必须有一个同深度的兄弟叶子。
:::
:::

## 最小生成树

设 $G = (V, E)$ 是带边权 $w(u, v)$ 的连通无向图。**生成树**是一个边集 $T \subseteq E$，构成一棵含每个顶点的树；它恰有 $n - 1$ 条边。**最小生成树**（MST）是总权 $w(T) = \sum_{e\in T}w(e)$ 最小的生成树。光缆、管道或道路网络是显然的应用；生成树也用于聚类，并作为近似算法的构件。

两个经典 MST 算法都维护一个边集 $A$，它始终是某个 MST 的子集，每次加入一条**安全**边。哪些边是安全的，由割来判定。

::: definition 割 {#def-cut}
**割** $(S, V \setminus S)$ 是把 $V$ 划分为两个非空集合。一条边**横越**这个割，指它的两端各在一个集合中。若 $A$ 中没有边横越该割，则称该割**尊重**边集 $A$。**轻边**是横越某割的边中权最小者。
:::

::: theorem 割性质 {#thm-cut}
设 $A$ 是某个最小生成树的子集，$(S, V\setminus S)$ 是一个尊重 $A$ 的割，$e = \{u, v\}$ 是横越它的一条轻边。则 $A \cup \{e\}$ 是某个最小生成树的子集。
:::

::: proof
设 $T$ 为含 $A$ 的一个 MST。若 $e \in T$ 则已得证。否则把 $e$ 加入 $T$ 恰产生一个圈，由 $e$ 和 $T$ 中从 $u$ 到 $v$ 的路径组成。由于 $u$ 和 $v$ 在割的两侧，该路径至少横越这个割一次，沿某条边 $e' \in T$。由于割尊重 $A$，$e'$ 不属于 $A$。**交换**：$T' = T \setminus \{e'\} \cup \{e\}$ 是连通的（任何用过 $e'$ 的路径可以改走圈的另一侧）且有 $n - 1$ 条边，故它是一棵生成树；又因 $e$ 是轻边，$w(T') = w(T) - w(e') + w(e) \le w(T)$。于是 $T'$ 是 MST，且包含 $A \cup \{e\}$。
:::

### 克鲁斯卡尔算法

::: algorithm 克鲁斯卡尔算法 {#alg-kruskal}
把边按权排序。从 $A = \emptyset$ 开始，此时每个顶点自成连通分量。对每条边 $\{u, v\}$ 按权递增依次处理：若 $u$ 和 $v$ 在 $(V, A)$ 的不同连通分量中，就把这条边加入 $A$（合并两个连通分量）；否则跳过。返回 $A$。
:::

克鲁斯卡尔算法的正确性由割性质保证：它加入 $\{u, v\}$ 时，设 $S$ 为 $u$ 所在的连通分量。割 $(S, V \setminus S)$ 尊重 $A$，而 $\{u, v\}$ 是横越它的轻边，因为每条更轻的边都已考察过，且要么已被加入（那它就不横越该割，因为 $S$ 是连通分量），要么被跳过（那它的两端已在同一连通分量，也不横越该割）。被跳过的边会构成圈，故 $A$ 始终是一片森林；结束时它是连通的——因为 $G$ 连通——所以是生成树；再与 [[#thm-cut]] 归纳，它还是最小的。

功夫下在快速检验“是否在同一连通分量”。这正是**并查集**（不相交集合）结构的职责：它维护顶点的划分，支持操作 `find(x)`（$x$ 所在集合的代表元）和 `union(x, y)`（合并两个集合）。把每个集合表示为有根树，每个元素指向其父结点，根即代表元。

- **按秩合并**：给每个根一个*秩*，初始为 $0$；合并时让秩较小的根成为另一个根的孩子，两秩相等时让新根的秩加一。
- **路径压缩**：`find(x)` 过程中，让 $x$ 到根路径上的每个结点都直接指向根。

::: lemma 按秩合并使树保持浅 {#lem-rank}
按秩合并时（无论是否有路径压缩），秩为 $r$ 的根的树中至少有 $2^r$ 个元素，故每个秩都不超过 $\lfloor\log n\rfloor$。没有路径压缩时，一棵树的高度不超过其根的秩，故 `find` 耗时 $O(\log n)$。
:::

::: proof
对合并次数归纳。新元素是秩 $0$、含 $2^0 = 1$ 个元素的根。把秩较小的根链接到秩为 $r$ 的根之下，秩 $r$ 不变、只增加元素。两个秩同为 $r$ 的根合并，产生秩为 $r + 1$、至少含 $2^r + 2^r = 2^{r+1}$ 个元素的根。路径压缩不改变任何秩、也不改变集合大小。由于一棵树至多含 $n$ 个元素，$2^r \le n$。没有压缩时，树高只在两棵等秩的树链接时增加，每次恰加一——正是秩增加之时；故高度 $\le$ 秩。
:::

两种启发式并用时，塔扬（Tarjan，1975）证明：$n$ 个元素上任何 $m$ 次操作的序列耗时 $O(m\,\alpha(n))$，其中 $\alpha$ 是阿克曼（Ackermann）函数的反函数——对任何实际可能出现的 $n$ 都不超过 $4$。我们对此只陈述不证明（见 CLRS 第 19 章，第 4 版）。

::: theorem 克鲁斯卡尔算法的运行时间 {#thm-kruskal-time}
克鲁斯卡尔算法运行 $O(m\log n)$ 时间。
:::

::: proof
对边排序耗时 $O(m\log m)$，而 $\log m \le \log n^2 = 2\log n$。有 $2m$ 次 `find` 和 $n - 1$ 次 union，由 [[#lem-rank]] 耗时 $O(m\log n)$（用路径压缩则是 $O(m\,\alpha(n))$）。总计 $O(m\log n)$，由排序支配。
:::

```python
class UnionFind:
    """Disjoint sets with union by rank and path compression."""
    def __init__(self, items):
        self.parent = {x: x for x in items}
        self.rank = {x: 0 for x in items}

    def find(self, x):
        root = x
        while self.parent[root] != root:
            root = self.parent[root]
        while self.parent[x] != root:    # 路径压缩
            self.parent[x], x = root, self.parent[x]
        return root

    def union(self, x, y):
        rx, ry = self.find(x), self.find(y)
        if rx == ry:
            return False                 # 已在同一集合
        if self.rank[rx] < self.rank[ry]:
            rx, ry = ry, rx
        self.parent[ry] = rx             # 挂上较矮的树
        if self.rank[rx] == self.rank[ry]:
            self.rank[rx] += 1
        return True

def kruskal(vertices, edges):
    uf, tree = UnionFind(vertices), []
    for w, u, v in sorted(edges):        # 最轻的边优先
        if uf.union(u, v):               # 跳过同一连通分量内部的边
            tree.append((u, v, w))
    return tree

V = 'abcdefghi'
E = [(4, 'a', 'b'), (8, 'a', 'h'), (8, 'b', 'c'), (11, 'b', 'h'),
     (7, 'c', 'd'), (4, 'c', 'f'), (2, 'c', 'i'), (9, 'd', 'e'),
     (14, 'd', 'f'), (10, 'e', 'f'), (2, 'f', 'g'), (1, 'g', 'h'),
     (6, 'g', 'i'), (7, 'h', 'i')]
T = kruskal(V, E)
print(T)
print(sum(w for _, _, w in T))
```

### 普里姆算法

普里姆算法从根 $r$ 生长出一棵单独的树：每步加入离开这棵树的最轻的边。这条边对割（树，其余部分）是轻边，而该割尊重树的边，故由 [[#thm-cut]]，每次加入的边都是安全的。实现上，它就是换了键的迪杰斯特拉算法：树外的顶点以其*连向树的*最轻边的权作键，而不是以到源的距离作键。

```python
import heapq

def prim(adj, r):
    """Minimum spanning tree of a connected undirected graph, grown from r."""
    in_tree, tree = {r}, []
    heap = [(w, r, v) for v, w in adj[r]]
    heapq.heapify(heap)
    while heap:
        w, u, v = heapq.heappop(heap)    # 离开树的最轻边？
        if v in in_tree:
            continue                     # 两端都在树内：跳过
        in_tree.add(v)
        tree.append((u, v, w))
        for x, wx in adj[v]:
            if x not in in_tree:
                heapq.heappush(heap, (wx, v, x))
    return tree

E = [(4, 'a', 'b'), (8, 'a', 'h'), (8, 'b', 'c'), (11, 'b', 'h'),
     (7, 'c', 'd'), (4, 'c', 'f'), (2, 'c', 'i'), (9, 'd', 'e'),
     (14, 'd', 'f'), (10, 'e', 'f'), (2, 'f', 'g'), (1, 'g', 'h'),
     (6, 'g', 'i'), (7, 'h', 'i')]
adj = {v: [] for v in 'abcdefghi'}
for w, u, v in E:
    adj[u].append((v, w)); adj[v].append((u, w))
T = prim(adj, 'a')
print(T)
print(sum(w for _, _, w in T))
```

```console
37
```

用二叉堆时，普里姆算法运行 $O(m\log n)$ 时间（每条边至多引起一次压入，每次压入或弹出耗时 $O(\log m) = O(\log n)$）；用斐波那契堆并配合 decrease-key 则为 $O(m + n\log n)$，对稠密图更好。

::: example 从 a 出发的普里姆算法 {#ex-prim}
解释列表中普里姆算法加入各边的次序，并说明它为什么取 $a$–$h$（权 $8$），而克鲁斯卡尔算法到很晚才取它。
::: solution
从 $a$ 出发，候选边是 $a$–$b$（$4$）和 $a$–$h$（$8$）：取 $a$–$b$。此时离开 $\{a, b\}$ 的边有 $a$–$h$（$8$）、$b$–$c$（$8$）、$b$–$h$（$11$）；最轻的权是 $8$，平局由堆中元组的序打破，$(8, a, h) < (8, b, c)$，于是取 $a$–$h$。从 $h$ 出发，边 $h$–$g$（$1$）现在可用，立即被取，随后是 $g$–$f$（$2$）、$f$–$c$（$4$）、$c$–$i$（$2$）、$c$–$d$（$7$）和 $d$–$e$（$9$）。$a$–$h$ 和 $b$–$c$ 都是割 $(\{a, b\}, \text{rest})$ 的轻边，所以取哪条都安全；此图有两棵权为 $37$ 的 MST（一棵含 $a$–$h$，一棵含 $b$–$c$），两个算法恰好找到了同一棵。克鲁斯卡尔直到所有更轻的边处理完才轮到 $a$–$h$，但那时 $a$ 和 $h$ 仍在不同连通分量。
:::
:::

::: warning 贪心并不总是对
只有证明背书时贪心算法才正确。用面值为 $1$、$3$、$4$ 便士的硬币“最大面值优先”找零，会把 $6$p 找成 $4 + 1 + 1$（三枚）而不是 $3 + 3$（两枚）。对容量 $50$ 的背包装入（重量, 价值）为 $(10, 60)$、$(20, 100)$、$(30, 120)$ 的物品，按单位重量价值最优先取前两件（价值 $160$），第三件便装不下了，而最优解取后两件（价值 $220$）。而贪心的迪杰斯特拉算法遇到负权边就会失效。一条貌似合理的贪心规则，在依赖它之前需要领先论证或交换论证；当这样的证明不存在时，[[algorithms/dynamic-programming]] 通常能正确解决——背包问题就在其中解决。
:::

::: quiz
连通图的所有边权互不相同。哪些陈述为真？

- [x] 最小生成树唯一。
- [x] 图中最轻的边在这棵 MST 中。
- [ ] 图中最重的边绝不会在这棵 MST 中。
- [x] 对每个顶点，它关联的最轻的边在这棵 MST 中。
::: solution
顶点 $v$ 处最轻的边是割 $(\{v\}, V \setminus \{v\})$ 的唯一轻边，而全图最轻的边是其每个端点处最轻的边。若某个割的唯一轻边 $e$ 不在某棵 MST $T$ 中，则 [[#thm-cut]] 证明中的交换会用 $e$ 替换 $T$ 的一条更重的横边 $e'$，得到*更轻*的树——不可能；所以每棵 MST 都含有它。唯一性随之而来：若存在两棵 MST $T \ne T'$，取恰在其中之一而不在另一棵中的最轻边 $e$，设 $e \in T \setminus T'$；把 $e$ 加入 $T'$ 会与某条 $e' \in T' \setminus T$ 闭合成圈，且 $w(e') > w(e)$（由 $e$ 的选取和权互异），于是 $T' \cup \{e\} \setminus \{e'\}$ 将比 $T'$ 更轻。最重的边*可以*在 MST 中：若它是桥（连接图的两部分的唯一一条边），每棵生成树都含它。
:::
:::

::: history
奥塔卡·博鲁夫卡（Otakar Borůvka）于 1926 年发现了第一个 MST 算法，用于规划南摩拉维亚经济供电网。沃伊捷赫·亚尔尼克（Vojtěch Jarník）于 1930 年描述了如今称为普里姆算法的算法；罗伯特·普里姆（Robert Prim）于 1957 年在贝尔实验室重新发现了它（“Shortest connection networks and some generalizations”），迪杰斯特拉于 1959 年也独立发现。约瑟夫·克鲁斯卡尔（Joseph Kruskal）于 1956 年在《美国数学会会刊》（*Proceedings of the American Mathematical Society*）的一篇短文中发表了他的算法。戴维·霍夫曼（David Huffman）于 1951 年在罗伯特·法诺（Robert Fano）于 MIT 的信息论课上以期末论文的形式提出了霍夫曼编码，击败了老师本人和克劳德·香农（Claude Shannon）的方法；论文 “A method for the construction of minimum-redundancy codes” 发表于 1952 年。按秩合并的并查集结构可上溯到伯纳德·加勒（Bernard Galler）与迈克尔·费希尔（Michael Fischer）（1964）；罗伯特·塔扬于 1975 年证明了阿克曼反函数界。贪心算法何时可行的理论——**拟阵**——由哈斯勒·惠特尼（Hassler Whitney）于 1935 年奠基，杰克·埃德蒙兹（Jack Edmonds）于 1971 年把它与贪心算法联系起来。

## 后续内容

交换论证在算法设计中处处重现；当贪心选择无法得到论证时，[[algorithms/dynamic-programming]] 便考虑一切选择。哈夫曼编码是实用压缩器的一部分（gzip 和 PNG 使用的 DEFLATE 把它与 LZ77 匹配结合）。并查集在 [[algorithms/randomised-algorithms]] 中重现：Karger 最小割算法就是以随机边权运行的克鲁斯卡尔算法。许多 $\mathsf{NP}$-难问题（[[complexity]]）都有贪心*近似*算法——例如，对度量旅行商问题，最小生成树给出一条长不超最优值两倍的巡游。

::: summary
- **贪心算法**每次作局部最优选择且从不反悔；它需要一个证明，通常是**贪心领先**或**交换论证**。
- **区间调度**：最早结束时间优先最优（[[#thm-eft]]），证明是对任何最优方案步步领先。
- **最大晚度**：最早截止时间优先最优（[[#thm-edf]]），证明是交换相邻逆序。
- **哈夫曼算法**反复合并两个最稀的字符；两个最稀的字符总可以互为兄弟（[[#lem-huffman-swap]]），归纳给出最优性（[[#thm-huffman]]）。
- **割性质**：横越尊重 $A$ 的割的轻边是安全的（[[#thm-cut]]）。克鲁斯卡尔加入连接两个连通分量的最轻边；普里姆加入离开其树的最轻边。两者都运行 $O(m\log n)$。
- **并查集**配合按秩合并保持高度 $O(\log n)$ 的树（[[#lem-rank]]）；加上路径压缩，摊还代价为 $O(\alpha(n))$。
:::

::: exercise 失败的贪心规则 {#ex-greedy-rules level=1}
对区间调度，给出小的反例说明：(a) 最早开始时间优先、(b) 最短区间优先、(c) 冲突最少优先都不是最优的。
::: solution
(a) $[0, 10)$、$[1, 2)$、$[3, 4)$：最早开始只取 $[0, 10)$；最优解为 $2$。(b) $[0, 5)$、$[4, 6)$、$[5, 10)$：最短优先取 $[4, 6)$，它与其他两个都冲突；最优解取 $[0, 5)$ 和 $[5, 10)$。(c) 一个标准例子：上面一行 $[0,2), [2,4), [4,6), [6,8)$ 是最优的（$4$ 个区间）。加入 $[1, 3)$ 的三个副本和 $[5, 7)$ 的三个副本（它们与外圈区间重叠），以及一个区间 $[3, 5)$（它只与 $[2, 4)$ 和 $[4, 6)$ 重叠）。于是 $[3, 5)$ 有 $2$ 个冲突——少于上面一行任何区间（$[0,2)$ 有 $3$ 个，$[2,4)$ 有 $4$ 个）——所以最先被选，此后至多再放下 $3$ 个区间：冲突最少得到 $3 < 4$。
:::

::: exercise 哈夫曼代价 {level=1 check="33"}
计算频率 $1, 2, 3, 4, 5$ 的哈夫曼编码的代价 $B(T)$。（输入代价。）
::: solution
合并：$1 + 2 = 3$；再把合并出的 $3$ 与叶 $3$ 合并，得 $6$；然后 $4 + 5 = 9$；最后 $6 + 9 = 15$。代价是各次合并权之和，$3 + 6 + 9 + 15 = 33$（见最后一题：每个字符按其每个祖先贡献一次自己的频率）。用深度验证：$4$ 和 $5$ 的深度为 $2$，权为 $6$ 的子树在深度 $1$，其叶 $3$ 在深度 $2$，$1$、$2$ 在深度 $3$：$2\cdot(4 + 5) + 2\cdot3 + 3\cdot(1 + 2) = 18 + 6 + 9 = 33$。故 $B(T) = 33$。
:::

::: exercise 一条唯一的轻边 {level=2}
证明*圈性质*：若 $e$ 是 $G$ 的某个圈上唯一的权最大的边，则 $e$ 不在任何最小生成树中。
::: solution
设 $T$ 是一棵含 $e = \{u, v\}$ 的生成树。删去 $e$ 把 $T$ 分成两个连通分量，一个含 $u$、另一个含 $v$，它们确定一个割。经过 $e$ 的那个圈含一条避开 $e$ 的从 $u$ 到 $v$ 的路径，它必沿某条边 $e' \ne e$ 横越此割，且由假设 $w(e') < w(e)$。于是 $T \setminus \{e\} \cup \{e'\}$ 是重新连通两个分量的生成树，且权更小，故 $T$ 不是最小的。
:::
:::

::: exercise 手算并查集 {level=2 check="3"}
从单点集 $1, \dots, 8$ 出发，执行按秩合并（无路径压缩，平局时第一个参数的根获胜）：$\mathrm{union}(1, 2)$、$\mathrm{union}(3, 4)$、$\mathrm{union}(1, 3)$、$\mathrm{union}(5, 6)$、$\mathrm{union}(7, 8)$、$\mathrm{union}(5, 7)$、$\mathrm{union}(1, 5)$。最终根的秩是多少，最终树的高度是多少？（输入高度。）
::: solution
$\mathrm{union}(1, 2)$：$2$ 挂到 $1$ 下，rank$(1) = 1$。$\mathrm{union}(3, 4)$：rank$(3) = 1$。$\mathrm{union}(1, 3)$：两秩相等，$3$ 挂到 $1$ 下，rank$(1) = 2$。同理 $5$ 成为 $\{5, 6, 7, 8\}$ 上秩为 $2$ 的根。$\mathrm{union}(1, 5)$：两秩同为 $2$，$5$ 挂到 $1$ 下，rank$(1) = 3$。这棵树有 $8 = 2^3$ 个元素，是 [[#lem-rank]] 对秩 $3$ 允许的最小值，高度为 $3$（例如 $1 \to 5 \to 7 \to 8$）——恰等于秩，正如该引理在无压缩时预言的那样。
:::

::: exercise 最大生成树与最宽路径 {level=3}
(a) 说明为什么把边按权*递减*次序处理的克鲁斯卡尔算法能找到权最大的生成树。(b) 一条路径的**宽度**是其上边的最小权（可想象带宽或桥梁限重）。证明：对每对顶点 $u, v$，它们在最大生成树 $T$ 之间的路径是 $G$ 中从 $u$ 到 $v$ 的所有路径中宽度最大的。
::: solution
(a) $w$ 的最大生成树就是 $-w$ 的最小生成树，而本章一切证明都未用到权的符号。按递增次序对 $-w$ 运行克鲁斯卡尔，就是对 $w$ 按递减次序运行。

(b) 设 $P$ 为 $u$ 到 $v$ 的树路径，$e$ 为 $P$ 上权最小的边，于是 $P$ 的宽度为 $w(e)$。反设有条从 $u$ 到 $v$ 的路径 $Q$ 更宽：$Q$ 的每条边的权都大于 $w(e)$。从 $T$ 中删去 $e$ 把它分成两个连通分量，$u$、$v$ 分处两侧（因为 $e$ 在二者唯一的树路径上）。路径 $Q$ 从一侧走到另一侧，所以它有一条横越此割的边 $f$，满足 $w(f) > w(e)$，且 $f \notin T$（横越此割的树边只有 $e$）。于是 $T \setminus \{e\} \cup \{f\}$ 是比 $T$ 更重的生成树，与极大性矛盾。所以没有路径比 $P$ 更宽。
:::
:::

::: exercise 实现博鲁夫卡算法 {level=3}
博鲁夫卡算法分轮进行：每轮中，当前森林的每个连通分量选出自己最轻的外向边，然后把所有选中的边加入。设边权互异，证明每条被选中的边都属于 MST、每轮至少使连通分量数减半，且算法运行 $O(m\log n)$。用上面的 `UnionFind` 类实现它，并在列表的图上检验（其权并非互异——按 $(w, u, v)$ 元组打破平局）。
::: solution
*安全性：*离开连通分量 $C$ 的最轻边是割 $(C, V \setminus C)$ 的轻边，而该割尊重当前的森林；边权互异时它是唯一轻边，每棵 MST 都含它（交换论证同 [[#thm-cut]]）。于是所有选中的边都在唯一的 MST 中，一起加入也不可能构成圈。*减半：*每个分量都选中一条通向另一分量的边，故每个新分量至少合并两个旧分量。*时间：*至多 $\log n$ 轮，每轮以 $O(m\,\alpha(n))$ 扫描所有边。

```python
# appended to kruskal.py: uses UnionFind, V and E from that listing
def boruvka(vertices, edges):
    uf, tree = UnionFind(vertices), set()
    edges = [(w, min(u, v), max(u, v)) for w, u, v in edges]
    while len(tree) < len(vertices) - 1:
        best = {}                                  # 分量根 -> 边
        for e in edges:
            w, u, v = e
            ru, rv = uf.find(u), uf.find(v)
            if ru != rv:
                for r in (ru, rv):
                    if r not in best or e < best[r]:
                        best[r] = e
        for w, u, v in best.values():
            if uf.union(u, v):
                tree.add((u, v, w))
    return sorted(tree, key=lambda e: (e[2], e[0], e[1]))

T = boruvka(V, E)
print(T, sum(w for _, _, w in T))
```


按整个元组打破平局使序成为全序，于是“边权互异”的论证适用于打破平局后的权；结果的权为 $37$，与克鲁斯卡尔相同。
:::

::: exercise 哈夫曼算法的合并次数 {level=2}
证明哈夫曼树的代价等于所有由合并产生的树的权之和，并由此给出一个 $O(n)$ 的算法，在频率已经排好序时构造哈夫曼编码。
::: solution
每个字符 $c$ 恰位于 $d_T(c)$ 个内部结点之下，而每个内部结点的权是其下各字符频率之和；故内部结点权之和为 $\sum_c f(c)d_T(c) = B(T)$。至于 $O(n)$ 算法，用两个队列：$Q_1$ 存放排好序的叶子，$Q_2$ 存放合并出的树——它们的生成次序按权非降（每次合并的都是当前可用的两个最小权，而它单调不减）。两棵最小的树总在 $Q_1$ 和 $Q_2$ 的队首之中，$O(1)$ 即可找到；$n - 1$ 次合并每次耗时常数。
:::
:::
