归并排序对 $n$ 个元素排序大约作 $n\log n$ 次比较，随机化快速排序平均约作 $1.39\,n\log n$ 次。几十年的努力产生了更聪明的排序算法，却没有一个能在 $o(n\log n)$ 时间内按比较排序。这不是因为没人尝试：这是一条定理。任何只通过成对比较来获取输入信息的算法，最坏情况下都至少要作 $\log_2(n!) \approx n\log n - 1.44n$ 次比较。然而邮局按邮政编码给数以百万计的信件分拣却只用线性时间，计算机给整数排序也能如此：靠的是*看透*关键字内部，而不是比较它们——计数排序与基数排序因此逃出了下界。

本章分三个部分。先用决策树证明**比较下界**——这是计算机科学中为数不多的、能说明一个问题被*任何*算法求解都无法更快之处。然后研究**非比较排序**——计数排序与基数排序，看看它们究竟打破了下界的哪一条假设。最后转向**选择**：找第 $k$ 小的元素，例如中位数——这可以用线性时间完成：一个简单随机化算法在期望意义下做到，巧妙的"中位数的中位数"则确定性地做到。我们会用到 [[algorithms/divide-and-conquer#lem-partition]] 的划分和 [[algorithms/correctness-recurrences]] 的递归式。

## 比较模型与决策树

::: definition 比较排序 {#def-comparison-sort}
**比较排序**是这样一种排序算法：它只通过成对比较关键字来获取关于它们的信息——检验 $a_i \le a_j$（或 $<$、$=$、$\ge$、$>$），检验的结果决定它接下来做什么。它可以随意搬动关键字，但不能查看它们的值——它们的位数、比特，或把它们用作数组下标。
:::

插入排序、归并排序、快速排序与堆排序都是比较排序；它们对任何全序类型都原封不动地适用，从整数到字符串到日期。要对一切比较排序同时推理，我们把一个排序建模为一棵树。

::: definition 决策树 {#def-decision-tree}
固定 $n$。一个比较排序在规模 $n$ 的输入上的**决策树**是一棵二叉树：每个内部结点标注一个比较 $i:j$（意思是"$a_i \le a_j$ 吗？"），答案为是走左子树、为非走右子树；每个叶标注 $\{1, \dots, n\}$ 的一个排列 $\pi$，表示算法输出 $\langle a_{\pi(1)}, \dots, a_{\pi(n)}\rangle$。在一个输入上的一次执行是从根到某个叶的一条路径；它作的比较次数就是路径长。
:::

这棵树存在，是因为比较排序是确定性的：在规模 $n$ 的输入上，它的第一次比较永远是同一个，第二次只依赖第一个答案，依此类推。别的工作——搬元素、更新下标——在树中是隐形的；我们只数比较，而它是运行时间的下界。

## 下界

::: lemma 叶与高度 {#lem-leaves}
高为 $h$（最长根到叶路径上的边数）的二叉树至多有 $2^h$ 个叶。
:::

::: proof
对 $h$ 归纳。高度为 $0$ 的树是单个叶。高度为 $h \ge 1$ 的树有一个根，其子树至多两棵、各自高度至多 $h - 1$，由假设每棵至多有 $2^{h-1}$ 个叶，于是全树至多有 $2 \cdot 2^{h-1} = 2^h$ 个。
:::

::: theorem 比较下界 {#thm-sort-lower}
每个比较排序在规模 $n$ 的输入上最坏情况至少作 $\lceil\log_2(n!)\rceil$ 次比较，且 $\log_2(n!) = n\log n - n\log e + O(\log n) = \Theta(n\log n)$。因此每个比较排序的最坏情况运行时间都是 $\Omega(n\log n)$。
:::

::: proof
考虑 $\langle 1, 2, \dots, n\rangle$ 的 $n!$ 个排列构成的输入。正确的算法必须为它们中的每一个产生不同的输出排列 $\pi$（能排好一个输入的 $\pi$ 排不好其他任何输入，因为关键字互异）。所以决策树至少有 $n!$ 个*可达*的叶。若树高为 $h$，由 [[#lem-leaves]] 有 $n! \le 2^h$，故 $h \ge \log_2(n!)$，又 $h$ 是整数，$h \ge \lceil\log_2(n!)\rceil$。树高就是最坏情况的比较次数。

关于 $\log_2(n!)$ 的大小：上界 $n! \le n^n$ 给出 $\log_2(n!) \le n\log n$。下界方面，$n!$ 中最大的 $n/2$ 个因子每个都至少是 $n/2$，所以 $n! \ge (n/2)^{n/2}$，$\log_2(n!) \ge \frac n2\log\frac n2 = \frac12 n\log n - \frac n2$，这是 $\Omega(n\log n)$。更精确的形式可由 Stirling 公式 $n! = \sqrt{2\pi n}\,(n/e)^n(1 + O(1/n))$ 得到。
:::

::: widget plot
f: log(gamma(x + 1))/log(2); x*log(x)/log(2); x*log(x)/log(2) - 1.4427*x
x: 1, 64
labels: \log_2 n!; n\log_2 n; n\log_2 n - n\log_2 e

:::

这一论证数的是*信息*：每次比较有两个结果，因而至多把与算法所见一致、仍可能的次序集合缩小一半；从 $n!$ 种可能出发，要缩到只剩一种，至少需要 $\log_2(n!)$ 次"折半"。归并排序的最坏情况——$n\lceil\log n\rceil - 2^{\lceil\log n\rceil} + 1$ 次比较——对每个 $n$ 都只超出这个界不到 $0.53\,n$，所以归并排序在比较排序中是**渐近最优**的——堆排序亦然。

::: example 小 n 的下界 {#ex-small-n}
计算 $n = 3, 4, 5, 10, 12$ 时的下界 $\lceil\log_2 n!\rceil$，并与归并排序的最坏情况比较。
::: solution
```python
import math
for n in [3, 4, 5, 10, 12]:
    bound = math.ceil(math.log2(math.factorial(n)))
    k = math.ceil(math.log2(n))
    print(n, bound, n * k - 2**k + 1)     # 下界，归并排序最坏情况
```

```console
$ python3 lower.py

4 5 5

```

$n = 3$ 与 $4$ 时归并排序达到下界。$n = 5$ 时 $\lceil\log_2 120\rceil = 7$，而归并排序最坏需要 $8$ 次；更巧妙的方法——*归并插入*（Ford 与 Johnson，1959）——用 $7$ 次比较排好 $5$ 个元素，且对所有 $n \le 11$ 达到下界。$n = 12$ 时下界是 $29$，但一次穷尽式计算机搜索（Wells，1965）表明需要 $30$ 次比较：信息论下界并非总能达到。
:::
:::

同样的计数给出*平均*情形的下界。$n!$ 个输入等概率时，平均比较次数就是 $n!$ 个叶的平均深度，而含 $N$ 个叶的二叉树的平均叶深至少 $\log_2 N$（平衡树使总深度最小；见 [[#ex-average-lower]]）。所以即使在平均情形，比较排序也需要 $\log_2(n!)$ 次比较，随机化算法同样破不了这个界：随机化算法是决策树上的一个概率分布，而每棵树的平均深度都至少 $\log_2(n!)$。

::: warning 下界没有说的是什么
这个界是关于**比较模型**的。它并不是说排序总要 $\Omega(n\log n)$ 时间：已知范围内的整数可以线性时间排序，下一节就会看到，因为可以把值用作数组下标。它也没有说每个比较排序都是 $\Theta(n\log n)$（插入排序就不是），也没有说比较排序不能在*特定*输入上更快（插入排序在有序输入上是线性的）。而且它约束的是比较，不是移动、缓存缺失等其他代价。声称"比 $n\log n$ 更快的排序"，通常要么是非比较排序，要么是最坏情况之外的陈述。
:::

决策树方法还能给出别的下界。在有序数组中查找 $n$ 个关键字之一有 $n + 1$ 种可能结果（$n$ 个位置之一，或"不存在"），所以需要 $\lceil\log_2(n+1)\rceil$ 次比较：二分搜索是最优的。归并两个长度为 $n$ 的有序表有 $\binom{2n}{n}$ 种可能的交错方式，而 $\log_2\binom{2n}{n} = 2n - O(\log n)$。但就*求最大值*而言，树给出的界 $\log_2 n$ 太弱了；一个**对手论证**（[[#ex-max-lower]]）给出正确的 $n - 1$。

::: quiz
一种排序算法声称：对大的 $n$，它只用比较、至多 $n\log_2 n - 2n$ 次比较就能对任意 $n$ 个互异数排序。这可能吗？

- [x] 不可能：$\log_2(n!) \approx n\log_2 n - 1.44n$ 超过 $n\log_2 n - 2n$。
- [ ] 可能：下界只是 $\Omega(n\log n)$，而这是 $\Theta(n\log n)$。
- [ ] 只要算法是随机化的就可能。
- [ ] 仅当这些数是整数时才可能。
::: solution
这个界不只是渐近式的：每个比较排序在最坏情况下至少需要 $\log_2(n!) = n\log_2 n - n\log_2 e + O(\log n)$ 次比较，而 $\log_2 e \approx 1.443 < 2$。$n$ 大时 $n\log_2 n - 2n$ 更小，所以没有比较排序能做到它——无论随机化与否，也无论关键字是什么，只要它只作比较。
:::
:::

## 线性时间排序

若关键字是小范围内的整数，我们可以根本不比。

### 计数排序

::: algorithm 计数排序 {#alg-counting-sort}
输入：含 $n$ 个条目的表 $A$，其关键字是 $\{0, 1, \dots, k-1\}$ 中的整数。

1. 令 $C[0..k-1]$ 全为零，对每个条目把 $C[\mathrm{key}]$ 加一：此时 $C[v]$ 是关键字为 $v$ 的条目数。
2. 把 $C$ 替换为它的**严格前缀和**：$C[v] \gets \sum_{u<v}(\text{关键字为 } u \text{ 的条目数})$，即关键字 $v$ 的第一个输出位置的下标。
3. 对 $A$ 的每个条目 $x$，*从左到右*：把 $x$ 放入 $B[C[\mathrm{key}(x)]]$，并把 $C[\mathrm{key}(x)]$ 加一。
4. 返回 $B$。
:::

```python
def counting_sort(a, k, key=lambda x: x):
    """Stable sort of a by integer keys in range(k)."""
    count = [0] * k
    for x in a:                        # 统计每个键
        count[key(x)] += 1
    total = 0
    for v in range(k):                 # count[v] = 键 v 的第一个输出槽位
        count[v], total = total, total + count[v]
    out = [None] * len(a)
    for x in a:                        # 从左到右，相等关键字便保持原有次序
        out[count[key(x)]] = x
        count[key(x)] += 1
    return out

def radix_sort(a, digits, base=10):
    """LSD radix sort of non-negative integers with at most `digits` digits."""
    for d in range(digits):
        a = counting_sort(a, base, key=lambda x: (x // base**d) % base)
        print(d, a)
    return a

print(counting_sort([2, 5, 3, 0, 2, 3, 0, 3], 6))
radix_sort([329, 457, 657, 839, 436, 720, 355], 3)
```

```console
$ python3 count.py

1 [720, 329, 436, 839, 355, 457, 657]

```

::: definition 稳定排序 {#def-stable}
一个排序算法称为**稳定的**，如果关键字相等的条目在输出中保持它们在输入中的相对次序。
:::

::: theorem 计数排序 {#thm-counting-sort}
[[#alg-counting-sort]] 是稳定排序，运行时间与空间均为 $\Theta(n + k)$。
:::

::: proof
第 2 步之后，位置 $C[v], C[v] + 1, \dots, C[v] + c_v - 1$（其中 $c_v$ 是关键字为 $v$ 的条目数）构成一个区块，各区块按 $v$ 递增排列，且它们恰好铺满 $0..n-1$。第 3 步中，遇到的关键字为 $v$ 的第 $j$ 个条目（从左数，$j = 0, 1, \dots$）被放到其区块的位置 $C[v] + j$，因为此前每个关键字为 $v$ 的更早条目都使 $C[v]$ 加过一次。于是输出把所有关键字按递增列出（有序），同一关键字内部按输入次序列出（稳定）。第 1、3 步各耗 $\Theta(n)$ 时间，第 2 步 $\Theta(k)$，数组用 $\Theta(n + k)$ 空间。
:::

$k = O(n)$ 时计数排序是线性的。它之所以打破下界，是因为第 3 步把关键字用作*数组下标*：这一个操作实际上是在 $k$ 种结果中做选择，而不是两种。

### 基数排序

对 64 位关键字（$k = 2^{64}$），单靠计数排序毫无用处。**基数排序**一次按一位数字排序，每一位用一个稳定排序——而且它从*最低*位排起，这正是违反直觉之处。

::: algorithm LSD 基数排序 {#alg-radix}
对 $n$ 个 $d$ 位、基数为 $r$ 的整数排序：对 $i = 0, 1, \dots, d - 1$（最低位数字先），按第 $i$ 位对表作稳定排序，使用 $k = r$ 的计数排序。
:::

::: theorem 基数排序 {#thm-radix}
LSD 基数排序正确地对 $n$ 个至多 $d$ 位（基数 $r$）的非负整数排序，时间 $\Theta(d(n + r))$。
:::

::: proof
*不变式：*第 $i$ 位那一趟之后，表按第 $0..i$ 位组成的数有序（即按模 $r^{i+1}$ 的余数有序）。第 $0$ 趟后按第 $0$ 位有序。设此前表按第 $0..i-1$ 位有序，现在按第 $i$ 位作稳定排序。取两个条目 $x, y$，$x \bmod r^{i+1} < y \bmod r^{i+1}$。若它们的第 $i$ 位不同，第 $i$ 位的排序把 $x$ 排前。若第 $i$ 位相同，则 $x \bmod r^{i} < y \bmod r^{i}$，所以本趟之前 $x$ 就在 $y$ 前面，稳定性让它留在那里。于是本趟后表按第 $0..i$ 位有序。最后一趟后按全部 $d$ 位有序，也就是按值有序。每趟是 $k = r$ 的计数排序，耗 $\Theta(n + r)$。
:::

若没有稳定性，论证就在"稳定性让它留在那里"处断裂，各趟就会互相拆台。

::: example 跟踪基数排序 {#ex-radix-trace}
在基数 $10$ 下跟踪 LSD 基数排序处理 $\langle 329, 457, 657, 839, 436, 720, 355\rangle$（上面第二个程序），并检查每趟之后的不变式。
::: solution
| 第几趟之后 | 表 | 按什么有序 |
|---|---|---|
| 第 0 位（个位） | 720, 355, 436, 457, 657, 329, 839 | 末位数字：0, 5, 6, 7, 7, 9, 9 |
| 第 1 位（十位） | 720, 329, 436, 839, 355, 457, 657 | 末两位：20, 29, 36, 39, 55, 57, 57 |
| 第 2 位（百位） | 329, 355, 436, 457, 657, 720, 839 | 全部三位 |

看 $457$ 与 $657$：第 $0$ 趟后它们仍是输入次序（都以 $7$ 结尾）。第 $1$ 趟保持这个次序，因为二者十位都是 $5$ 而计数排序是稳定的。第 $2$ 趟中它们的百位不同（$4 < 6$），所以单靠这一趟就决定了它们的次序。第 $1$ 趟中，$329$ 跳到 $436$ 之前，因为 $2 < 3$，尽管它在前一次的次序中排在 $436$ 之后——之前的次序只在相等时才起作用。

::: example 选取基数 {#ex-radix}
用基数排序对 $n = 10^6$ 个 32 位无符号整数排序该怎么做？与 $n\log_2 n$ 次比较相比如何？
::: solution
设每个数字占 $b$ 位，则 $r = 2^b$、$d = \lceil 32/b\rceil$，代价约为 $d(n + r)$ 个基本步：

| $b$ | $r$ | 趟数 $d$ | $d(n + r)$ |
|---|---|---|---|
| 1 | 2 | 32 | $3.2 \times 10^7$ |
| 8 | 256 | 4 | $4.0 \times 10^6$ |
| 16 | 65 536 | 2 | $2.13 \times 10^6$ |
| 32 | $4.3 \times 10^9$ | 1 | $4.3 \times 10^9$ |

一般地，$b \approx \log_2 n$ 使 $\lceil 32/b\rceil(n + 2^b)$ 最小，得 $\Theta(32n/\log n)$；在这个计数下 $b = 16$（两趟）最好，而 $b = 8$（四趟，扫一张放得进高速缓存的 $256$ 个计数器的表）是常见的实用选择。比较排序需要约 $n\log_2 n \approx 2 \times 10^7$ 次比较——步数是它的五到十倍，不过基数排序的每一趟也要搬动全部数据，所以实测加速比更小，且依赖于机器。
:::
:::

**桶排序**是第三种线性时间方法，适用于关键字在某个区间上均匀散布的情形：把区间分成 $n$ 个等大的桶，把每个关键字丢进它的桶，每个桶内用插入排序，最后串接。若关键字独立且均匀，期望代价是 $\Theta(n)$（各桶大小平方之和的期望是 $2n - 1$；见 [[algorithms/randomised-algorithms]]），但全部落入一个桶的恶意输入要 $\Theta(n^2)$。

## 选择

**选择问题**：给定 $n$ 个关键字和整数 $1 \le k \le n$，找出第 $k$ 小的，即**秩**为 $k$ 的关键字。最小元秩为 $1$，最大元秩为 $n$，**中位数**秩为 $\lceil n/2\rceil$（下中位数）。排序能以 $O(n\log n)$ 解决选择，但排序做的远比需要的多。我们能线性时间选择吗？

### 随机化选择

像快速排序那样围绕随机主元划分，但只递归进*一侧*：包含秩 $k$ 的那一侧。

::: algorithm 快速选择 {#alg-quickselect}
在表 $A$ 中找秩为 $k$ 的元素：

1. 在 $A$ 中均匀随机选取主元 $x$。
2. 把 $A$ 分成 $S = \{a < x\}$、$E = \{a = x\}$ 与 $G = \{a > x\}$。
3. 若 $k \le \lvert S\rvert$，返回 $S$ 中秩为 $k$ 的元素；若 $k \le \lvert S\rvert + \lvert E\rvert$，返回 $x$；否则返回 $G$ 中秩为 $k - \lvert S\rvert - \lvert E\rvert$ 的元素。
:::

正确性由对 $n$ 的强归纳：$S$ 的每个元素都小于 $E$ 的每个元素，$E$ 的每个元素又小于 $G$ 的每个元素，所以秩 $1..\lvert S\rvert$ 在 $S$ 中，接着的 $\lvert E\rvert$ 个秩都是 $x$，其余在 $G$ 中、秩相应平移；递归调用在严格更短的表上进行，因为 $x \in E$。

::: theorem 快速选择的期望线性时间 {#thm-quickselect}
在 $n$ 个关键字的任意输入和任意 $k$ 上，快速选择的期望比较次数至多 $8n$（每次调用把每个元素与主元比较一次记为一次；更精细的分析给出 $4n$）；其期望运行时间为 $O(n)$。
:::

::: proof
称一个主元对 $m$ 个元素的表是**好的**，如果表中至少 $m/4$ 个元素 $\le$ 它且至少 $m/4$ 个元素 $\ge$ 它；有序表的中间一半（至少一半元素）都是好的，所以随机主元是好的概率至少 $1/2$。好主元之后，递归调用——进 $S$ 或进 $G$——至多在 $3m/4$ 个元素上进行。

称算法处于**阶段** $j$，若当前表的规模 $m$ 满足 $(3/4)^{j+1}n < m \le (3/4)^jn$。阶段 $j$ 中一次调用至多作 $(3/4)^jn$ 次比较，而一个好主元会终结该阶段。每次调用有好主元的概率至少 $1/2$，与过去独立，所以阶段 $j$ 中的调用次数 $N_j$ 满足 $\Prob(N_j \ge t) \le (1/2)^{t-1}$，从而 $\E[N_j] \le \sum_{t\ge1}(1/2)^{t-1} = 2$。于是期望比较次数至多为
$$
\sum_{j\ge0}\E[N_j]\Big(\frac34\Big)^jn \le 2n\sum_{j \ge 0}\Big(\frac34\Big)^j = 2n \cdot 4 = 8n.
$$
这就是常数为 $8$ 的期望 $O(n)$ 界。更精细的界 $4n$ 来自直接分析递归式：由 $\E[C(m)] \le m + \frac1m\sum_{i=1}^m\E[C(\max(i - 1, m - i))]$（对每个主元秩 $i$ 都取最坏一侧），用 $\E[C(m)] \le 4m$ 代入可通，因为 $\frac1m\sum_{i}\max(i-1, m-i) \le \frac{3m}{4}$，给出 $m + 4 \cdot \frac{3m}4 = 4m$。
:::

阶段论证给出的常数 $8$ 比较松，但论证稳健、可复用；代入法给出 $4n$，而对中位数的精确期望约为 $3.39n$（高德纳（Knuth））。与快速排序一样，快速选择有一个 $\Theta(n^2)$ 的最坏情况，只是 $n$ 大时其概率微乎其微。

### 确定性选择：中位数的中位数

不用随机性能保证好主元吗？Blum、弗洛伊德（Floyd）、Pratt、Rivest 与 Tarjan（1973）给出了办法：取*"小组中位数的中位数"*作主元，而这个主元本身由递归找出。

::: algorithm 中位数的中位数选择 {#alg-mom}
在 $n$ 个元素的表 $A$ 中找秩为 $k$ 的元素：

1. 若 $n \le 5$，排序 $A$ 并返回其第 $k$ 个元素。
2. 把 $A$ 分成 $\lceil n/5\rceil$ 个每组 $5$ 个的组（最后一组可能小些），每组排序求中位数。
3. 递归地求这 $\lceil n/5\rceil$ 个组中位数的中位数 $x$。
4. 像 [[#alg-quickselect]] 那样围绕 $x$ 把 $A$ 划分成 $S$、$E$、$G$，只在包含秩 $k$ 的那一部分继续递归。
:::

::: lemma 主元是好的 {#lem-mom-pivot}
在 [[#alg-mom]] 中，$A$ 里至少有 $\frac{3n}{10} - 6$ 个元素 $\ge x$，也至少有 $\frac{3n}{10} - 6$ 个元素 $\le x$。于是第 4 步的递归调用至多在 $\frac{7n}{10} + 6$ 个元素上进行。
:::

::: proof
$g = \lceil n/5\rceil$ 个组中位数中至少一半 $\ge x$（因为 $x$ 是它们的中位数）：至少有 $\lceil g/2\rceil$ 个组的中位数 $\ge x$。除最后一组（可能短）和 $x$ 自己所在的组外，每个这样的组都含有至少 $3$ 个 $\ge x$ 的元素：它的中位数和两个比它大的元素。所以至少有
$$
3\Big(\Big\lceil\frac g2\Big\rceil - 2\Big) \ge \frac{3n}{10} - 6
$$
个元素 $\ge x$。$\le x$ 同理。部分 $S$ 由小于 $x$ 的元素组成，因此排除了那至少 $\frac{3n}{10} - 6$ 个 $\ge x$ 的元素：$\lvert S\rvert \le \frac{7n}{10} + 6$，$G$ 同理。
:::

::: theorem 线性时间选择 {#thm-mom}
[[#alg-mom]] 最坏情况运行时间为 $O(n)$。
:::

::: proof
第 1、2 步和第 4 步的划分都耗 $O(n)$ 时间：至多某个常数 $an$（排一个 $5$ 元组耗常时间）。第 3 步在 $\lceil n/5\rceil$ 个元素上递归，第 4 步至多在 $7n/10 + 6$ 个元素上。于是对超过某个阈值的 $n$，
$$
T(n) \le T(\lceil n/5\rceil) + T(7n/10 + 6) + an,
$$
且 $T$ 单调不减。用代入法证明 $T(n) \le cn$。对 $n \ge 140$，用 $\lceil n/5\rceil \le n/5 + 1$，
$$
T(n) \le c\Big(\frac n5 + 1\Big) + c\Big(\frac{7n}{10} + 6\Big) + an = cn + \Big(-\frac{cn}{10} + 7c + an\Big),
$$
当 $c(n/10 - 7) \ge an$ 时括号 $\le 0$。$n \ge 140$ 时 $n/10 - 7 \ge n/20$，所以 $c \ge 20a$ 就够；再把 $c$ 取到同时对一切 $n < 140$ 有 $T(n) \le cn$。归纳之所以合法，是因为 $n \ge 140$ 时两个递归自变量都小于 $n$。
:::

关键在于两个子问题的规模之和小于 $n$：$\frac15 + \frac7{10} = \frac9{10} < 1$，于是递归树各层代价几何收缩。若用 $3$ 个一组，两个分数之和是 $\frac13 + \frac23 = 1$，得到 $\Theta(n\log n)$；用 $7$ 个一组，算法同样是线性的。这个算法的常数很大（比较次数多达约 $24n$），所以实践中用快速选择，或 **introselect**（进展太慢就退回中位数的中位数的快速选择）。C++ 的 `std::nth_element` 通常就实现为 introselect。

```python
import random

def quickselect(a, k):
    """Return the k-th smallest element of a (k = 1 is the minimum)."""
    pivot = random.choice(a)
    smaller = [x for x in a if x < pivot]
    equal = [x for x in a if x == pivot]
    if k <= len(smaller):
        return quickselect(smaller, k)
    if k <= len(smaller) + len(equal):
        return pivot
    larger = [x for x in a if x > pivot]
    return quickselect(larger, k - len(smaller) - len(equal))

def mom_select(a, k):
    """Deterministic selection by the median of medians (Blum et al.)."""
    if len(a) <= 5:
        return sorted(a)[k - 1]
    groups = [sorted(a[i:i + 5]) for i in range(0, len(a), 5)]
    medians = [g[(len(g) - 1) // 2] for g in groups]
    pivot = mom_select(medians, (len(medians) + 1) // 2)
    smaller = [x for x in a if x < pivot]
    equal = [x for x in a if x == pivot]
    if k <= len(smaller):
        return mom_select(smaller, k)
    if k <= len(smaller) + len(equal):
        return pivot
    larger = [x for x in a if x > pivot]
    return mom_select(larger, k - len(smaller) - len(equal))

random.seed(5)
data = [random.randint(0, 999) for _ in range(1001)]
print(quickselect(data, 501), mom_select(data, 501), sorted(data)[500])
```

```console
$ python3 select.py
488 488 488
```

两个函数都用三路划分，所以在有重复关键字时也正确；$1001$ 个随机整数的中位数与排序结果一致。

::: example 手工执行中位数的中位数 {#ex-mom}
求 [[#alg-mom]] 在 $15$ 个数 $\langle 12, 3, 17, 8, 34, 25, 1, 9, 30, 22, 5, 14, 19, 27, 2\rangle$ 上选出的主元，并问保证能排除掉多少个元素。
::: solution
各组及其有序形式为 $\langle 3, 8, \mathbf{12}, 17, 34\rangle$、$\langle 1, 9, \mathbf{22}, 25, 30\rangle$、$\langle 2, 5, \mathbf{14}, 19, 27\rangle$，中位数是 $12$、$22$、$14$。它们的中位数是 $x = 14$。$\ge 14$ 的元素包括 $14, 19, 27$（它自己的组）、$22, 25, 30$（中位数 $22 \ge 14$ 的那组）以及 $17, 34$：确实是 $17, 19, 22, 25, 27, 30, 34$ 加上 $14$，共八个。$\le 14$ 的：$1, 2, 3, 5, 8, 9, 12, 14$，也是八个。按有序次序 $14$ 的秩是 $8$——这里它恰好就是精确中位数。引证的保证 $3n/10 - 6 = -1.5$ 对这么小的 $n$ 毫无用处；它是一个渐近陈述，而对小表算法直接排序。
:::
:::

::: quiz
[[#alg-mom]] 为什么用 $5$ 个一组而不是 $3$ 个一组？

- [ ] $3$ 个一组的组没有中位数。
- [x] $3$ 个一组时，两个递归调用的规模约为 $n/3$ 与 $2n/3$，两者之和为 $n$，递归代价 $\Theta(n\log n)$。
- [ ] $3$ 个一组会让主元比随机的还差。
- [ ] 给 $3$ 个一组的组排序，每个元素摊到的比较更多。
::: solution
$3$ 个一组时，两侧各至少保证约 $2 \cdot \frac12 \cdot \frac n3 = \frac n3$ 个元素，于是递归选择至多在 $\frac{2n}3$ 个元素上进行，而求中位数的中位数要在 $\frac n3$ 个元素上递归。递归式 $T(n) = T(n/3) + T(2n/3) + \Theta(n)$ 的递归树每层都代价 $\Theta(n)$，解为 $\Theta(n\log n)$（如 [[algorithms/correctness-recurrences]] 中所述）。$5$ 个一组让两个分数之和为 $9/10$。
:::
:::

::: history
排序的决策树下界是 1950 年代的坊间常识（folklore）；Lester Ford 与 Selmer Johnson 1959 年关于归并插入的论文已经讨论了信息论界 $\lceil\log_2 n!\rceil$，高德纳（Knuth）的《计算机程序设计艺术》（The Art of Computer Programming）第 3 卷《排序与查找》（Sorting and Searching，1973）则把最少比较排序的理论整理成体系。基数排序比计算机还老：Herman Hollerith 为 1890 年美国人口普查制造的制表机就是一列一列地给穿孔卡片排序，而卡片分类机正是按最低位优先操作的，与 [[#alg-radix]] 如出一辙；Harold Seward 在 1954 年的 MIT 论文中为电子计算机描述了计数排序与基数排序。霍尔（Hoare）1961 年的 *FIND*（《ACM 通讯》算法 65）就是快速选择。线性时间确定性选择由 Manuel Blum、Robert Floyd（弗洛伊德）、Vaughan Pratt、Ronald Rivest 与 Robert Tarjan 发表于 "Time bounds for selection"（1973）——五人中有四人在此后荣获图灵奖。
:::

## 后续内容

下界论证在 [[algorithms/randomised-algorithms]] 中重现，而 [[complexity]] 整门课程正是下界之学，追问哪些问题需要指数时间。基数式的技巧是哈希（[[algorithms/randomised-algorithms]]）与整数数据结构的基础。选择是一块积木：以中位数为主元的快速排序有可保证的 $O(n\log n)$ 最坏情况，许多几何与统计算法需要中位数或分位数。堆——堆排序以及 [[algorithms/shortest-paths]]、[[algorithms/greedy-algorithms]] 中优先队列的来源——是一种受同一比较下界约束的比较结构：优先队列若能让插入与取出最小元都只花 $o(\log n)$ 次比较，就能以快于 $n\log n$ 的速度排序。

::: summary
- 在**比较模型**中，算法是一棵**决策树**；要排序就需要至少 $n!$ 个叶，所以树高——最坏情况比较次数——至少 $\lceil\log_2(n!)\rceil = n\log n - 1.44n + O(\log n)$（[[#thm-sort-lower]]）。归并排序与堆排序渐近最优。
- 这个界在平均情形下、对随机化比较排序同样成立，但在比较模型之外不成立。
- **计数排序**以 $\Theta(n + k)$ 稳定地对 $\{0, \dots, k-1\}$ 中的整数关键字排序（[[#thm-counting-sort]]）；**基数排序**按位使用稳定排序、从最低位排起，代价 $\Theta(d(n + r))$（[[#thm-radix]]）。
- **快速选择**以期望 $O(n)$ 时间找第 $k$ 小的元素（[[#thm-quickselect]]）。
- **中位数的中位数**保证主元两侧各有 $\ge 3n/10 - 6$ 个元素（[[#lem-mom-pivot]]），由于 $\frac15 + \frac7{10} < 1$，得到最坏情况线性时间的选择（[[#thm-mom]]）。
:::

::: exercise 六个关键字的下界 {level=1 check="10"}
给 $n = 6$ 个关键字排序，最坏情况比较次数的下界 $\lceil\log_2 n!\rceil$ 是多少？（输入该数。）
::: solution
$6! = 720$，而 $2^9 = 512 < 720 \le 1024 = 2^{10}$，所以 $\lceil\log_2 720\rceil = 10$。归并插入用 $10$ 次比较排好 $6$ 个关键字，所以下界可以达到；归并排序需要 $6 \cdot 3 - 8 + 1 = 11$。
:::

::: exercise 手工执行计数排序 {level=1}
用计数排序处理关键字 $\langle 1, 0, 3, 1, 3, 1\rangle$，$k = 4$，给出第 1、2 步之后的 $C$ 与最终输出。把三个 $1$ 标记为 $1_a, 1_b, 1_c$，检验稳定性。
::: solution
第 1 步后 $C = [1, 3, 0, 2]$。第 2 步（严格前缀和）后 $C = [0, 1, 4, 4]$。第 3 步：$1_a \to B[1]$（$C[1] = 2$），$0 \to B[0]$，$3 \to B[4]$，$1_b \to B[2]$，$3 \to B[5]$，$1_c \to B[3]$。输出：$\langle 0, 1_a, 1_b, 1_c, 3, 3\rangle$——三个 $1$ 保持输入次序，排序是稳定的。
:::
:::

::: exercise 稳定吗？ {level=1}
插入排序、归并排序（归并用 `<=`）、Lomuto 快速排序与选择排序（把未排部分的最小元换到位上）中，哪些是稳定的？给每个不稳定的算法举一个两三个元素的反例。
::: solution
插入排序稳定：元素只越过*严格*更大的元素。归并排序稳定，因为相等时从左边取。Lomuto 快速排序不稳定：在 $\langle 2_a, 2_b, 1\rangle$ 上，主元 $1$ 与 $2_a$ 交换，第一次划分后成为 $\langle 1, 2_b, 2_a\rangle$，而对 $\langle 2_b, 2_a\rangle$ 的递归调用保持这一次序（每个元素与自己交换，然后主元与自己交换）。选择排序不稳定：在 $\langle 2_a, 2_b, 1\rangle$ 上，第一步把 $2_a$ 与 $1$ 交换，得到 $\langle 1, 2_b, 2_a\rangle$。
:::
:::

::: exercise 求最大值 {#ex-max-lower level=2 check="99"}
证明每个基于比较、在 $n$ 个互异关键字中求最大值的算法最坏情况至少要作 $n - 1$ 次比较，而 $n - 1$ 次也够用。$n = 100$ 时需要多少次？（输入该数。）
::: solution
*充分性：*扫一遍表，记住目前最大者——除第一个元素外每个元素一次比较。*必要性：*每次比较产生一个败者（较小的关键字）。假设定某算法在不足 $n - 1$ 次比较后停下并宣布 $m$。那么存在某个键 $y \ne m$ 从未输过任何比较。改变输入，把 $y$ 变得比其他所有键都大，而保持其他键两两之间的相对次序不变；凡涉及 $y$ 的比较原本就是 $y$ 赢、现在仍然 $y$ 赢，其余比较一切如故，于是算法的行为完全相同、照样宣布 $m$——可现在 $y$ 才是最大值。所以除最大值外每个键都至少输过一次：至少 $n - 1$ 次比较，$n = 100$ 时为 $99$ 次。
:::
:::

::: exercise 同时求最小与最大 {level=2 check="148"}
说明如何用 $\lceil 3n/2\rceil - 2$ 次比较同时找出 $n$ 个关键字的最小元与最大元，并对 $n = 100$ 算出该数。（输入该数。）
::: solution
成对处理关键字：先把一对中的两个互相比较（$1$ 次），再让较小者与当前最小元比、较大者与当前最大元比（又 $2$ 次）。$n$ 为偶数时，第一对同时初始化两者（$1$ 次比较），其余 $n/2 - 1$ 对每对 $3$ 次：$1 + 3(n/2 - 1) = 3n/2 - 2$。$n$ 为奇数时，第一个元素同时初始化两者，$(n-1)/2$ 对每对 $3$ 次：$3(n-1)/2 = \lceil 3n/2\rceil - 2$。$n = 100$：$150 - 2 = 148$，而分两趟各扫一遍要 $2(n - 1) = 198$ 次。（对手论证表明 $\lceil 3n/2\rceil - 2$ 已是最优。）
:::
:::

::: exercise 平均情形下界 {#ex-average-lower level=2}
证明：每个有 $N \ge 1$ 个叶、且每个内部结点都有两个孩子的二叉树，叶深总和至少 $N\log_2 N$。由此推出：在 $n!$ 种互异关键字的次序上取平均，每个比较排序平均至少作 $\log_2(n!)$ 次比较。
::: solution
对 $N$ 强归纳。$N = 1$ 时总和为 $0 = 1 \cdot \log_2 1$。$N \ge 2$ 时根的两棵子树分别有 $i$ 与 $N - i$ 个叶，$1 \le i \le N - 1$，且每个叶比在子树中深一格，所以总深度 $D(N) \ge i\log_2 i + (N-i)\log_2(N-i) + N$。函数 $g(t) = t\log_2 t$ 是凸的，故 $g(i) + g(N - i) \ge 2g(N/2) = N\log_2 N - N$；于是 $D(N) \ge N\log_2 N$。排序的决策树可以假定每个内部结点都有两个可达的孩子（答案被迫定的比较可以删去，那只会降低深度），且至少有 $n!$ 个叶；限制在输入实际到达的 $n!$ 个叶上（并剪枝），得到一棵有 $N = n!$ 个叶的满二叉树，其平均深度至少 $\log_2(n!)$。
:::
:::

::: exercise 用基数排序给字符串排序 {level=2}
说明如何以 $\Theta(\ell(n + 26))$ 时间对 $n$ 个各恰含 $\ell$ 个小写字母的字符串排序。再解释为什么 LSD 基数排序对长度*不同*的字符串很别扭，以及补白如何解决。
::: solution
把每个字符串看作一个基数 $26$ 的 $\ell$ 位数，第一个字母是最高位，然后施以 LSD 基数排序：$\ell$ 趟 $k = 26$ 的稳定计数排序，从最后一个位置排到第一个。由 [[#thm-radix]]，结果按字典序排好，耗时 $\Theta(\ell(n + 26))$。长度不同时，"从末尾数第 $i$ 位"在各串之间对不齐。给每个串右端补上一个排在*所有*字母之前（计数排序取 $k = 27$）的特殊符号，补到最大长度 $L$；于是补白后串的字典序与原串一致（真前缀在前），代价为 $\Theta(L(n + 27))$——若某个串远比其余的长就会浪费。MSD（最高位优先）基数排序递归地排每个桶，可免补白。
:::
:::

::: exercise 更紧的快速选择界 {level=3}
证明 [[#thm-quickselect]] 之后勾勒的快速选择界 $\E[C(n)] \le 4n$：设 $\E[C(m)] \le 4m$ 对 $m < n$ 成立，证明 $\E[C(n)] \le (n - 1) + \frac4n\sum_{i=1}^n\max(i - 1, n - i) \le 4n$。
::: solution
对 $n$ 个元素划分作 $n - 1$ 次比较。若主元的秩为 $i$（互异关键字下概率 $1/n$），递归在 $i - 1$ 或 $n - i$ 个元素上进行，至多 $\max(i - 1, n - i)$，而 $\E[C]$ 随规模单调不减。所以 $\E[C(n)] \le (n - 1) + \frac1n\sum_{i=1}^n 4\max(i-1, n-i)$。$i = 1..n$ 时 $\max(i - 1, n - i)$ 的取值把 $n-1, n-2, \dots, \lceil n/2\rceil$ 各取到两次（从两端各来一次；$n$ 为奇数时中间值 $(n-1)/2$ 只出现一次），故 $\sum_i \max(i-1, n-i) \le 2\sum_{j=\lfloor n/2\rfloor}^{n-1} j \le \frac{3n^2}{4}$：$n$ 为偶数时和为 $2\big(\binom n2 - \binom{n/2}{2}\big) = \frac{3n^2}{4} - \frac n2$，$n$ 为奇数时为 $\frac{3n^2 - 2n - 1}{4}$。因此 $\E[C(n)] \le n - 1 + \frac4n\cdot\frac{3n^2}4 = n - 1 + 3n < 4n$。
:::
:::

::: exercise 7 个一组 {level=3}
分析取 $7$ 个一组的 [[#alg-mom]]：主元两侧各保证多少个元素？得到什么递归式？是线性的吗？
::: solution
$g = \lceil n/7\rceil$ 个组中至少 $\lceil g/2\rceil$ 个的中位数 $\ge x$，除主元自己的组和可能短的最后一组外，每个这样的组至少有 $4$ 个元素 $\ge x$（它的中位数和三个更大的）。所以至少有 $4(\lceil g/2\rceil - 2) \ge \frac{2n}{7} - 8$ 个元素 $\ge x$，$\le x$ 同理；递归调用至多在 $\frac{5n}7 + 8$ 个元素上进行。递归式为 $T(n) \le T(\lceil n/7\rceil) + T(5n/7 + 8) + an$，而 $\frac17 + \frac57 = \frac67 < 1$，所以对大的 $n$ 用 $T(n) \le cn$ 代入可行：$c(n/7 + 1) + c(5n/7 + 8) + an = cn - c(n/7 - 9) + an \le cn$，只要 $n \ge 126$ 且 $c \ge 14a$（此时 $n/7 - 9 \ge n/14$）。它是线性的。
:::
:::

::: exercise 螺母与螺栓 {level=3}
你有 $n$ 个螺母和 $n$ 个螺栓，尺寸互不相同，每个螺母恰好配一个螺栓。你只能拿一个螺母和一个螺栓比较（太大、太小、恰好），不能比较两个螺母或两个螺栓。给出一个随机化算法，以期望 $O(n\log n)$ 次比较把全部配上对，并证明最坏情况需要 $\Omega(n\log n)$ 次比较。
::: solution
*算法：*随机挑一个螺栓；把它与每个螺母比较，把螺母分成较小、较大与配上的那一个；再把这个螺母与每个螺栓比较，把螺栓同样三分。于是小螺母配小螺栓、大螺母配大螺栓；对两对各自递归。这就是把主元用了两次的快速排序，所以 [[algorithms/divide-and-conquer#thm-quicksort]] 的分析适用：期望约 $2 \times 2n\ln n$ 次比较。*下界：*算法必须确定螺母与螺栓之间的 $n!$ 个双射中哪一个是真正的配对。每次比较有 $3$ 个结果，所以一棵有 $n!$ 个叶、三分叉的决策树高度至少 $\log_3(n!) = \Omega(n\log n)$。
:::
:::
