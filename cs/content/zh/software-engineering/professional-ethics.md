2015 年 9 月，美国环境保护署宣布，大众汽车出售的柴油车中藏有软件，能检测到汽车正在接受排放测试——依据是实验室测试典型的时速、转向及其他输入的模式——只有那时才让发动机以达标的模式运转。在真实道路上，这些车的氮氧化物排放超出允许水平许多倍。大众称全世界约一千一百万辆车受影响；公司支付了数十亿的罚款与和解金，2017 年一名参与该软件的工程师在美国被判处 40 个月监禁。这段代码，在一个狭窄的意义上，设计得很精巧：它精确地做了它被设计来做的事。

前面每一章都在问如何把软件造对。这一章问的是造*对的*软件意味着什么，以及工程师欠其系统所影响的人们什么。我们考察职业**道德守则**及其用法、管辖代码的**知识产权**规则与**许可证**、**隐私**与数据保护、**无障碍**，以及自动化系统的**问责**——包括一个限定「公平」能意味着什么的定理。凡涉及法律之处，我们按 2026 年的状况作提纲式描述；法律因国家而异、且会变化，本文任何内容都不是法律意见。

## 职业责任

在大多数国家，软件工程不像医学或（在许多地方的）土木工程那样是需要执照的职业：谁都可以编写软件，即使是要害系统，也几乎没有哪个法域要求建造者具备资格。但它具有职业的其他标志——公众无力审查的专业知识，以及一旦失败就会伤害无从置喙之人的工作——而专业协会有行为规范，说明随之而来的责任。

::: definition 道德守则 {#def-codes}
**《ACM 计算机职业道德与专业行为守则》**（Association for Computing Machinery，2018 年修订）陈述了普遍的伦理原则——为社会和人类的福祉做贡献；避免伤害；诚实可信；公正，并行动以不歧视；尊重产生新思想与新成果所需的劳动；尊重隐私；信守保密——随后是职业责任（如高质量的工作、胜任、了解相关法律、接受并给予评审、彻底评估风险、建造在健全且可用的意义上安全的系统）以及领导者的义务。**《软件工程职业道德与专业实践守则》**（ACM 与 IEEE 计算机学会，1999 年）把其条款组织在八项原则之下：**公众**、**客户与雇主**、**产品**、**判断**、**管理**、**职业**、**同事**与**自身**，第一项是软件工程师应始终以符合公众利益的方式行事。
:::

守则并不能机械地裁决疑难案件；它们提供思考这些案件的结构，以及可以诉诸的共享标准。两份守则都把公众利益置于雇主与客户利益之上（当二者冲突时），都期望看到伤害风险的工程师把话说出来。ACM 守则关于避免伤害的原则补充说：计算机专业人员有义务报告可能导致伤害的系统风险迹象，并承认吹哨是有代价的、应当谨慎行事，在组织内部尝试解决问题之后才为之。

面对工作中一个伦理问题的实用方法：

1. **陈述事实**并识别受影响者——不只是客户和用户，还有第三方，以及那些永不使用系统却受其评判的人。
2. **识别适用的义务**：法律、合同、守则、组织自身的政策，以及普通的道德责任（诚实、避免伤害、公正、尊重自主）。
3. **生成选项**，不止服从/拒绝两种：提问、提出更安全的设计、把你的关切记录下来、逐级上报、寻求法务或合规人员，只在万不得已时拒绝或对外报告。
4. 就其对受影响者的后果、以及你能否公开为之——「头版测试」——逐项**评估**。
5. **行动并记录**你做了什么、为什么。

::: example 来自经理的要求 {#ex-ethics-case}
你在一个订阅制服务上工作。你的经理要求把退订变得更难：「取消」链接要挪到某个设置页的底部，退订必须在工作时间打电话办理，而注册在网上只需一次点击。用上面的方法分析这一要求。
::: solution
*事实与利害关系人。*想要退订的顾客，包括残障人士或在办公时间上班的人；收入依赖留存率的公司；将来要接这些电话的客服人员；被要求实现它的你。

*义务。*诚实与避免伤害（ACM 1.2、1.3）：一种以让顾客在有权做某事上故意失败为目的的设计是**黑暗模式**（dark pattern），是蓄意的欺骗或阻碍。公正（1.4）：只留电话一条退订途径，除非另有替代，就会把失聪或有语言障碍的人排斥在外。法律：截至 2026 年，许多法域对此已有规制——欧盟与英国的消费者保护规则要求许多合同的退订能与注册同样容易，美国联邦贸易委员会已着手追究「自动续订选项」（negative option）做法——所以这一要求还可能不合法；应当询问公司的律师。

*选项。*(a) 照做。(b) 直接拒绝。(c) 先问经理想解决什么问题——也许顾客离开的原因是可以修复的——并提出替代方案：一个在线退订流程加一个（诚实的、可跳过的）挽留报价和一个离网调查，既达成业务目标又不设置阻碍。(d) 若经理坚持，把你的关切书面化，咨询法务或合规，再决定是否愿意实现它。

*评估。*(c) 同时服务于公司的正当地利益与顾客的利益；(a) 通不过头版测试；(b) 站得住脚，但放弃了修复问题的机会。工作中大多数真实的伦理问题都是这样：不是英雄式的拒绝，而是坚持不懈地提供更好的替代方案，并留下这样做了的记录。
:::
:::

戴维·帕尔纳斯（David Parnas）1985 年给出了一个著名的职业判断范例：当年他从美国一个负责战略防御倡议软件的顾问委员会辞职，并在一系列论文（"Software aspects of strategic defense systems"，*Communications of the ACM*，1985）中说明：所需的那类软件无法在真实条件下测试，因而永远无法被信任能在第一次需要它时正常工作——正是 [[software-engineering/verification#prop-test-infeasible]] 的论证被用于一个政策问题。

## 知识产权与许可证

代码受几种**知识产权**法的保护。**版权**自动保护程序的表达——其源代码与目标代码——自写就之时起、无须注册，在《伯尔尼公约》缔约国如此；它不保护背后的思想或算法。**专利**在授予软件专利的地方（美国与欧洲的规则差异很大）保护发明，包括某些算法与技术，为期约二十年，且必须申请。**商业秘密**保护公司保守的秘密信息。**商标**保护名称与标志。对雇员，雇主通常拥有作为本职工作一部分所写代码的版权；对承包商，归属取决于合同。

因为版权自动产生，互联网上找到的代码*不是*可以随意使用的，除非其所有者给予许可。这种许可就是**许可证**。

::: definition 自由软件与开源许可证 {#def-licences}
**自由软件**或**开源**许可证向所有人授予使用、研究、修改和再分发软件的权利。**宽松型**（permissive）许可证（MIT、BSD、Apache 2.0）附加的条件很少——通常是保留版权声明，Apache 2.0 还要求注明修改并遵守其专利条款——并允许把代码纳入专有软件。**著佐权**（copyleft）许可证（GNU 通用公共许可证 GPL；LGPL；AGPL）要求再分发的修改版本，以及就 GPL 而言以该代码为基础的大型作品，以相同条款许可并提供源代码；AGPL 把这一要求扩展到通过网络向用户提供的软件。若两种许可证下的代码可以合成为一个同时满足两者的作品，则两种许可证**兼容**。
:::

自由软件基金会的自由软件定义（始于 20 世纪 80 年代；里奇·斯托尔曼（Richard Stallman）于 1983 年宣布 GNU 项目）与开源促进会的开源定义（1998 年）从不同的哲学出发点描述了几乎同一组许可证——前者视用户自由为道德问题，后者视之为一种有实际优点的开发方法。来自 **SPDX** 项目的标准短标识符（`MIT`、`Apache-2.0`、`GPL-3.0-only`、`GPL-2.0-or-later`）让工具能可靠地读取许可证信息。

::: example 检查依赖的许可证 {#ex-licences}
一个项目依赖四个（虚构的）库。用一张基于自由软件基金会公开立场的简化兼容性表，检查在项目以 GPL-3.0 或以 Apache-2.0 分发时，每个库能否用于该项目。
::: solution
```python
# 一张刻意简化的兼容性表：行许可证下的代码，能否合入以列许可证分发的程序？
#（基于自由软件基金会的公开立场；非法律意见。）
OK = {
    ("MIT", "MIT"), ("MIT", "Apache-2.0"), ("MIT", "GPL-2.0-only"), ("MIT", "GPL-3.0-only"),
    ("BSD-3-Clause", "Apache-2.0"), ("BSD-3-Clause", "GPL-2.0-only"),
    ("BSD-3-Clause", "GPL-3.0-only"),
    ("Apache-2.0", "Apache-2.0"), ("Apache-2.0", "GPL-3.0-only"),
    ("GPL-2.0-only", "GPL-2.0-only"), ("GPL-3.0-only", "GPL-3.0-only"),
}

def check(project_licence, dependencies):
    for name, lic in dependencies.items():
        verdict = "ok" if (lic, project_licence) in OK else "CONFLICT - ask"
        print(f"  {name:10} {lic:14} {verdict}")

deps = {"httpkit": "Apache-2.0", "tinyparse": "MIT",
        "oldcrypto": "GPL-2.0-only", "plotlib": "BSD-3-Clause"}
for project in ("GPL-3.0-only", "Apache-2.0"):
    print("project under", project)
    check(project, deps)
```

```console
$ python3 licences.py
project under GPL-3.0-only
  httpkit    Apache-2.0     ok
  tinyparse  MIT            ok
  oldcrypto  GPL-2.0-only   CONFLICT - ask
  plotlib    BSD-3-Clause   ok
project under Apache-2.0
  httpkit    Apache-2.0     ok
  tinyparse  MIT            ok
  oldcrypto  GPL-2.0-only   CONFLICT - ask
  plotlib    BSD-3-Clause   ok
```

宽松型库在两种项目许可下都没问题。`oldcrypto` 与两者都冲突。在 Apache-2.0 下，原因是著佐权：把它分发在项目内部，会要求整个组合作品采用 GPL-2.0。在 GPL-3.0 下，原因更微妙：「GPL-2.0-only」禁止按后续版本重新许可，而 GPL-2.0 与 GPL-3.0 附加的条件不同，所以自由软件基金会认为两者不兼容；若那个库是「GPL-2.0-or-later」，它就能在 GPL-3.0 下使用。Apache-2.0 的代码与 GPL-3.0 兼容，但在基金会的看法下与 GPL-2.0 不兼容，原因是 Apache 的专利条款。真实的兼容性取决于代码如何组合与分发（链接、独立程序、仅在服务器上使用），到那一步就需要法律意见；这个程序的价值在于自动把这些问题标出来，在发布之前、在持续集成里（[[software-engineering/version-control]]）。
:::
:::

还有两项义务容易被遗忘。按许可证条款分发软件通常要求把其声明传递下去——所以一个打包了数百个开源组件的产品必须随附数百份声明。而由在公共代码上训练的机器学习助手生成的代码的地位——归谁所有、是否会逐字复现受许可的代码——截至 2026 年仍在诉讼与不尽一致的官方指引之中；各组织日益为其使用制定政策，并像对待任何其他贡献一样扫描它的输出。

## 隐私

多数软件都在处理个人数据，而其开发者往往在未曾察觉之间决定了收集什么、保存多久、谁能看到。数据保护法使其中一些决定成为强制。影响最大的是欧盟的**《通用数据保护条例》**（GDPR，Regulation (EU) 2016/679），自 2018 年 5 月 25 日起适用于对欧盟境内人们之个人数据的处理，无论处理者身在何处；英国在脱欧后将其保留在本国法律中，许多其他国家也以它为蓝本立法。

::: definition 数据保护原则 {#def-gdpr}
依 GDPR 第 5 条，个人数据——与已识别或可识别的在世个人的信息——的处理必须**合法、公正、透明**；为指定的、明确的、合法的目的收集，且不得以与这些目的不相容的方式使用（**目的限制**）；充分、相关且限于必要（**数据最小化**）；**准确**；以可识别形式保存不超过必要之期限（**存储限制**）；处理须安全（**完整性与机密性**）。控制者必须能够证明合规（**问责**）。第 25 条要求**经设计的和默认的数据保护**：自始内置于系统的适当措施，以及默认只处理每个目的所必需之数据的设置。
:::

该条例还赋予个人一系列权利——访问、更正、删除、可携带，以及不受某些仅基于自动化处理之决定的约束——并要求将严重的个人数据泄露通报监管机构，可行时在 72 小时内。罚款可达 2,000 万欧元或全球年营业额的 4%。对开发者而言，这些原则化为具体需求（[[software-engineering/requirements]]）：不要「万一有用」就收集一个字段；给每类记录定保留期限并按时删除；设计注册路径的同时设计删除路径；记录对敏感数据的访问；在传输和静态存储中都加密（[[security/privacy]]）。

### 可识别性

去掉名字并不能使数据匿名。拉坦尼娅·斯威尼（Latanya Sweeney）根据 1990 年美国人口普查数据估计，87% 的美国人口可以被五位邮政编码、性别与完整出生日期这三项的组合唯一识别（"Simple demographics often identify people uniquely"，2000）；菲利普·戈勒（Philippe Golle）用 2000 年普查数据重复该分析（WPES 2006），得到约 63%——更低，但仍是多数。「匿名化」掉了名字的数据集曾被通过与其他数据关联而重新识别：斯威尼在 1990 年代从一份发布的医院数据集中指认出了马萨诸塞州州长的医疗记录，纳拉亚南（Narayanan）与什马蒂科夫（Shmatikov）（IEEE Symposium on Security and Privacy，2008）通过与公开评论比对重新识别了 Netflix 大奖赛的评分用户。GDPR 据此区分**假名化**的数据——标识符被替换，但借助附加信息可以重新识别——它仍是个人数据，与真正**匿名**的数据相区别，后者不是。

::: definition $k$-匿名性 {#def-k-anonymity}
在一张表中，**准标识符**（quasi-identifiers）是单独不具识别性、但组合起来或与其他数据关联后可能具有识别性的属性（邮编、出生日期、性别）。若表中出现的每个准标识符取值组合至少在 $k$ 行中出现，则表是 **$k$-匿名**的，于是每个人至少与另外 $k - 1$ 个人不可区分。
:::

::: example 度量并改进 $k$ {#ex-k-anonymity}
一个虚构的数据集记录了八个人的邮编、出生年份、性别与诊断。计算 $k$；然后把邮编泛化到片区、把出生年份泛化为五年段，再算一次。
::: solution
```python
from collections import Counter

# 一个虚构的数据集：准标识符（邮编、出生年份、性别）与诊断。
rows = [
    ("LS6 1AB", 1990, "F", "asthma"),   ("LS6 2CD", 1991, "F", "flu"),
    ("LS6 1AB", 1990, "M", "diabetes"), ("LS6 3EF", 1993, "M", "asthma"),
    ("LS2 9JT", 1975, "F", "migraine"), ("LS2 7HY", 1978, "F", "flu"),
    ("LS2 9JT", 1976, "M", "asthma"),   ("LS2 8QQ", 1979, "M", "flu"),
]

def k_anonymity(records, generalise):
    """记录按泛化后的准标识符分组时，最小分组的大小。"""
    groups = Counter(generalise(r) for r in records)
    return min(groups.values()), groups

exact = lambda r: r[:3]
coarse = lambda r: (r[0].split()[0], r[1] // 5 * 5, r[2])  # 片区、五年段、性别

if __name__ == "__main__":
    for name, g in (("exact", exact), ("generalised", coarse)):
        print(f"{name}: k = {k_anonymity(rows, g)[0]}")
    for key, n in sorted(k_anonymity(rows, coarse)[1].items()):
        print("  ", key, n)
```

```console
$ python3 kanon.py
exact: k = 1
generalised: k = 2
   ('LS2', 1975, 'F') 2
   ('LS2', 1975, 'M') 2
   ('LS6', 1990, 'F') 2
   ('LS6', 1990, 'M') 2
```

用精确值时每个人都是唯一的（$k = 1$）：任何知道某邻居的邮编、出生年份与性别的人，就能知道其诊断。泛化之后，$k = 2$。这仍然很弱，且 $k$-匿名性有一个已知的缺口：若一个组里两人的诊断相同，该组照样会把它暴露出来（**同质性**攻击），由此产生了 $\ell$-多样性（Machanavajjhala 等人，2006）这样的改进。最强的现代方法是**差分隐私**（Dwork、McSherry、Nissim 与 Smith，2006）：为聚合统计量加入经校准的随机噪声，并带有「任何个体之在场都不会使输出分布改变多少」的数学保证（[[security/privacy]]）。
:::
:::

一个相关的错误是用哈希来「匿名化」标识符。若标识符来自一个小空间——六位工号、电话号码、车牌号——任何人都可以把每个可能的值都哈希一遍再查表。在读者的机器上，对一个小数据集：

```python
import hashlib, hmac, secrets

def naive_pseudonym(staff_id):            # 无密钥哈希：谁都能重新算出来
    return hashlib.sha256(staff_id.encode()).hexdigest()[:16]

KEY = secrets.token_bytes(32)             # 与数据集分开保管

def keyed_pseudonym(staff_id):            # HMAC：需要密钥才能重新算出来
    return hmac.new(KEY, staff_id.encode(), hashlib.sha256).hexdigest()[:16]

published = naive_pseudonym("482913")     # 出现在一份「假名化」的导出文件中
# 工号是六位数字，所以外人可以直接试遍全部 10**6 个：
recovered = next(f"{n:06d}" for n in range(10**6) if naive_pseudonym(f"{n:06d}") == published)
print("naive pseudonym", published, "-> staff ID", recovered)
print("keyed pseudonym", len(keyed_pseudonym("482913")), "hex digits; without KEY,",
      "enumerating IDs does not help")
```

```console
$ time python3 pseudonym.py
naive pseudonym 4a8eec4925826f4b -> staff ID 482913
keyed pseudonym 16 hex digits; without KEY, enumerating IDs does not help

real	0m0.727s
```

不到一秒就还原了。用带密钥的哈希（HMAC），密钥与数据分开保存，外人就无法重新计算，这是相当合理的假名化技术——但结果仍是假名化的，不是匿名的，因为持有密钥的人能够重新识别。（使用经过审验的库提供的 HMAC，如这里这样，绝不要自己构造；[[cryptography]]。）

## 无障碍

按世界卫生组织 2023 年的估计，约每六人中就有一人带着显著的残障生活，而每个人都会在某些时刻处于暂时性失能——摔伤的手臂、屏幕上刺眼的阳光、嘈杂的列车。无法配合屏幕阅读器、纯键盘、放大或字幕使用的软件，会把这些人排斥在日益只有线上渠道的服务之外。**无障碍**（accessibility）是设计让能力范围最广的人都能够使用的系统。

标准参考是 W3C 的**《Web 内容无障碍指南》**（WCAG 2.0，2008 年；2.1，2018 年；2.2，2023 年 10 月），其成功标准组织在四项原则之下——内容必须是**可感知的**、**可操作的**、**可理解的**与**健壮的**——并分为 A、AA、AAA 三级。AA 级通常是法律与合同上的目标：在欧盟，《欧洲无障碍法案》自 2025 年 6 月 28 日起适用于许多产品与服务，许多国家的公共部门网站必须满足 WCAG AA。典型要求：每张图像有文本替代；一切都能用键盘操作，且有可见的焦点；表单有标签和清楚的错误消息；视频有字幕；文本与其背景有足够的**对比度**。

::: definition 对比度比值 {#def-contrast}
对各分量为 8 位的 sRGB 颜色 $R, G, B$，对每个分量 $v \in \set{R, G, B}$ 令 $c = v/255$ 线性化为 $c_{\text{lin}} = c/12.92$（当 $c \le 0.04045$）或 $\bigl((c + 0.055)/1.055\bigr)^{2.4}$（否则）。**相对亮度**为 $L = 0.2126\,R_{\text{lin}} + 0.7152\,G_{\text{lin}} + 0.0722\,B_{\text{lin}}$，从 $0$（黑）到 $1$（白）。亮度为 $L_1 \ge L_2$ 的两个颜色的**对比度比值**为
$$
\frac{L_1 + 0.05}{L_2 + 0.05},
$$
从 $1$ 到 $21$。WCAG 2.2 成功标准 1.4.3（AA 级）要求普通文本至少 $4.5$、大文本至少 $3$；标准 1.4.6（AAA 级）要求 $7$ 和 $4.5$。
:::

（较早的 WCAG 版本把线性化阈值写作 $0.03928$，这一差异对 8 位颜色没有影响。）

::: example 检查颜色对比度 {#ex-contrast}
实现 [[#def-contrast]] 并对六组颜色分类，其中包含只差一个色阶的两个灰色。
::: solution
```python
def luminance(hex_colour):
    """sRGB 颜色（如 '#767676'）的相对亮度（WCAG 2.x）。"""
    def linear(c):
        c /= 255
        return c / 12.92 if c <= 0.04045 else ((c + 0.055) / 1.055) ** 2.4
    r, g, b = (int(hex_colour[i:i + 2], 16) for i in (1, 3, 5))
    return 0.2126 * linear(r) + 0.7152 * linear(g) + 0.0722 * linear(b)

def contrast(fg, bg):
    hi, lo = sorted((luminance(fg), luminance(bg)), reverse=True)
    return (hi + 0.05) / (lo + 0.05)

for fg, bg in [("#000000", "#FFFFFF"), ("#767676", "#FFFFFF"), ("#777777", "#FFFFFF"),
               ("#FF0000", "#FFFFFF"), ("#0000EE", "#FFFFFF"), ("#AAAAAA", "#000000")]:
    r = contrast(fg, bg)
    verdict = "AAA" if r >= 7 else "AA" if r >= 4.5 else "AA large text only" if r >= 3 else "fails"
    print(f"{fg} on {bg}: {r:5.2f}:1  {verdict}")
```

```console
$ python3 contrast.py
#000000 on #FFFFFF: 21.00:1  AAA
#767676 on #FFFFFF:  4.54:1  AA
#777777 on #FFFFFF:  4.48:1  AA large text only
#FF0000 on #FFFFFF:  4.00:1  AA large text only
#0000EE on #FFFFFF:  9.40:1  AAA
#AAAAAA on #000000:  9.04:1  AAA
```

`#767676` 是在白色背景上通过 AA 的最浅灰色；再浅一个色阶就不合格。纯红配白对普通文本不合格。
:::
:::

这样的自动检查在持续集成中很有价值，但它们只能抓住问题的一部分：WebAIM 自 2019 年开始的年度自动调查，对头部一百万个网站的主页检测可发现的 WCAG 违规——最常见的是低对比度文本——每年都在 90% 以上，而自动工具无法判断替代文本是否有意义、一个流程用屏幕阅读器是否可用。用辅助技术与残障用户一起测试（[[hci/accessibility-ethics]]）是其余的部分。

## 自动化决定的问责

当软件做出或辅助做出关于人的决定——信贷、招聘、警务、福利、医疗分诊——它的错误落在通常看不见代码的个人头上，而它的错误模式可能系统性地使某些群体处于不利。公正与评估风险的职业责任在此有特殊的分量，法律也日益认同：GDPR 限制仅基于自动化处理做出的决定，欧盟《人工智能法案》（Regulation (EU) 2024/1689）对「高风险」系统施加义务，2025 至 2027 年间分阶段生效。

一个塑造了这场讨论的案例：2016 年，ProPublica 的新闻工作者分析了 COMPAS——一个为被告再犯风险打分的商业工具——并报告：在没有再犯的被告中，黑人被告被判为高风险的比率约为白人被告的两倍。供应商回应说分数对两个群体同样准确：高风险标签意味着相同的再犯概率，无论被告的种族。两个说法对同一份数据都为真。下面这个归功于亚历山德拉·丘尔杰霍娃（Alexandra Chouldechova，"Fair prediction with disparate impact"，2017；克莱因伯格（Kleinberg）、穆拉纳坦（Mullainathan）与拉加万（Raghavan），2016，有紧密相关的结果）的结果解释了原因。

::: proposition 公平性标准互相冲突 {#prop-fairness}
对一个用于某群体的二分类器，设该群体中实际为正的比例为 $p$（**基础比率**，$0 < p < 1$），$\mathrm{PPV}$ 为其查准率（被预测为正者中真正为正的比例，假设 $> 0$），$\mathrm{FNR}$ 为其假阴性率，$\mathrm{FPR}$ 为其假阳性率。则
$$
\mathrm{FPR} = \frac{p}{1 - p} \cdot \frac{1 - \mathrm{PPV}}{\mathrm{PPV}} \cdot (1 - \mathrm{FNR}).
$$ {#eq-chouldechova}
因此，若两个群体基础比率不同，一个在两个群体中具有相同 $\mathrm{PPV}$ 与相同 $\mathrm{FNR}$ 的分类器必须有不同的假阳性率——除非它是完美的。
:::

::: proof
设群体有 $N$ 名成员，于是 $pN$ 为正、$(1-p)N$ 为负，并设 $\mathit{TP}$ 与 $\mathit{FP}$ 为真阳性与假阳性的人数。由定义 $\mathrm{FNR} = 1 - \mathit{TP}/(pN)$，故 $\mathit{TP} = (1 - \mathrm{FNR})\,pN$。又有 $\mathrm{PPV} = \mathit{TP}/(\mathit{TP} + \mathit{FP})$，故 $\mathit{FP} = \mathit{TP}\,(1 - \mathrm{PPV})/\mathrm{PPV}$。于是
$$
\mathrm{FPR} = \frac{\mathit{FP}}{(1-p)N} = \frac{(1-\mathrm{FNR})\,pN\,(1-\mathrm{PPV})}{\mathrm{PPV}\,(1-p)N},
$$
即 [[#eq-chouldechova]]。若 $\mathrm{PPV}$ 与 $\mathrm{FNR}$ 固定且 $\mathrm{PPV} < 1$、$\mathrm{FNR} < 1$，则 $\mathrm{FPR}$ 是 $p/(1-p)$ 的严格增函数，从而也是 $p$ 的严格增函数；不同的基础比率给出不同的假阳性率。仅有的出路是 $\mathrm{PPV} = 1$（完全没有假阳性）或 $\mathrm{FNR} = 1$（完全没有真阳性）。
:::

基础比率为 $0.5$ 与 $0.2$ 时，一个在两个群体中 $\mathrm{PPV} = 0.6$、$\mathrm{FNR} = 0.3$ 的分类器，假阳性率为 $1 \cdot \tfrac{0.4}{0.6} \cdot 0.7 \approx 0.47$ 与 $0.25 \cdot \tfrac{0.4}{0.6} \cdot 0.7 \approx 0.12$：第一个群体中本不会再犯的人被错误标记的可能性是第二个群体的四倍。数学没有说哪个标准是对的；它说的是必须做出选择，这是一个对真实的人有后果的价值判断，而且应当由对此负责的人明确做出，而不是隐含在工程师对损失函数的选择里。

caption: 以自然频率呈现的贝叶斯定理，用于筛查试验或分类器：基础比率（流行率）$0.2$，真阳性率 $1 - \mathrm{FNR} = 0.7$，真阴性率 $1 - \mathrm{FPR} = 0.9$。从图中读出查准率。现在把流行率降到 $0.05$，保持错误率不变：大多数阳性变成假阳性。同一个分类器用于基础比率不同的两个群体，不可能既有相等的查准率*又*有相等的错误率——这正是 [[#prop-fairness]] 的内容。

问责还意味着不过度信任软件。1999 至 2015 年间，英国邮政总局凭借 Horizon 记账系统报告的亏空，以盗窃和虚假记账罪起诉了数百名副邮政局长；许多人被定罪、监禁或破产。在 *Bates v Post Office*（2019）中，高等法院认定 Horizon 中存在能够造成此类亏空的缺陷、错误与故障；自 2021 年起法院开始撤销定罪，2024 年议会立法予以撤销。一条「计算机证据除非被证伪即推定可靠」的法律推定，把负担压在了无法接触系统内部的被告身上。工程上的教训正是本课程的那些：系统有缺陷（[[software-engineering/testing]]），其记录需要可以被独立核查的审计痕迹，而知道缺陷存在的人有义务披露。

::: warning 「我只是写代码」
人们很容易相信伦理责任在决定*造什么*的人身上——经理、客户、监管者——而实现一份规格说明在道德上是中立的。守则拒绝这种看法，法院也是：大众那位工程师并不是发明排放作弊装置的人，但他明知其用途仍然实现了它。工程师常常是第一个知道系统不安全、有欺骗性、有歧视性或违法的人，因为他们知道它实际做什么。「我是奉命行事」是一个解释，不是抗辩。相反的错误是把每一次分歧都当作伦理紧急状态：多数决定是负责任的当事人有权做出的正当权衡，工程师的职责是把后果说清楚，而不是用自己的偏好取而代之。
:::

::: quiz
一家公司发布了一份用户活动数据集，其中每个用户的电子邮件地址被替换为其 SHA-256 哈希。按 GDPR，这份数据集是什么？
- [ ] 匿名数据，因为哈希不可逆。
- [x] 假名化的个人数据，仍受该条例约束。
- [ ] 不是个人数据，因为不含姓名。
- [ ] 加密数据，可以自由发布。
::: solution
任何拥有电子邮件地址列表的人都能把它们哈希后比对结果，而活动模式本身就能识别个人，所以这些数据关系到可识别的人：它们是个人数据，把标识符换成哈希充其量是假名化（GDPR 序言第 26 条）。哈希不是加密，当输入可以被猜到时，「不可逆」并不意味「不可关联」。
:::
:::

::: history
诺伯特·维纳（Norbert Wiener）的《人有人的用处》（*The Human Use of Human Beings*，1950）在这个领域起步之时就提出了计算的社会后果。ACM 于 1972 年通过第一份职业行为守则，1992 年与 2018 年两次修订；ACM/IEEE-CS 合编的《软件工程守则》于 1999 年跟进。里奇·斯托尔曼于 1983 年宣布 GNU，第一份 GNU 通用公共许可证出现于 1989 年（第二版 1991 年，第三版 2007 年）；开源促进会成立于 1998 年。Therac-25 事故（1985–87）与戴维·帕尔纳斯 1985 年的 SDI 论文使软件安全成为公共关切。W3C 于 1999 年发布 WCAG 1.0，2008 年发布 2.0。GDPR 于 2016 年通过、2018 年起适用——同年修订后的 ACM 守则问世；关于算法公平的讨论围绕 2016–17 年的 COMPAS 分析成形。
:::

::: summary
- 软件工程师的工作一旦失败，会伤害从未选择卷入的人；**ACM 守则**与**软件工程守则**（[[#def-codes]]）把公众利益放在首位，并期望工程师提出风险。分析疑难案件：事实、义务、选项、评估、记录。
- 代码自动受**版权**保护；使用他人的代码需要**许可证**（[[#def-licences]]）。宽松许可证允许专有使用；著佐权要求共享衍生作品；组合之前检查兼容性。
- **数据保护**（GDPR）要求合法、限定目的、最小化、准确、限期、安全的处理，且须经设计与默认（[[#def-gdpr]]）。
- 去掉名字并不匿名：准标识符会重新识别人。度量 **$k$-匿名性**（[[#def-k-anonymity]]），优先使用泛化或差分隐私，绝不要把小标识符空间的无密钥哈希当作匿名。
- **无障碍**遵循 WCAG 的四项原则；对比度比值 $(L_1 + 0.05)/(L_2 + 0.05)$ 在 AA 级对普通文本至少为 4.5（[[#def-contrast]]）。自动检查只能发现问题的一部分。
- 基础比率不同时，相等的查准率与相等的错误率不可能同时成立（[[#prop-fairness]]）；公平性标准是必须明确地、可问责地做出的价值选择。
- 问责意味着披露已知的缺陷与风险；「我只是写代码」不是抗辩。
:::

## 习题

::: exercise 一次对比度检查 {level=1 check="5.13"}
用 [[#def-contrast]]（或上面的程序），计算绿色 `#2E7D32` 上的白色文本的对比度比值，精确到小数点后两位。它对普通文本达到 AA 吗？（填入比值。）
::: solution
`contrast("#FFFFFF", "#2E7D32")` 给出 $5.127\ldots \approx 5.13$，对普通文本达到 AA（$\ge 4.5$），但未达到 AAA（$\ge 7$）。
:::

::: exercise 哪一条原则？ {level=1}
说出 [[#def-gdpr]] 中最直接相关的 GDPR 原则：(a) 一款健身应用无限期保存用户的位置历史，「为了将来的功能」；(b) 一个新闻通讯注册表要求填写出生日期；(c) 为配送收集的客户数据被卖给广告公司；(d) 一个患者记录数据库无需密码即可访问。
::: solution
(a) 存储限制（以及目的限制：「将来的功能」不是指定的目的）。(b) 数据最小化：发送新闻通讯不需要出生日期。(c) 目的限制；除非顾客被告知并给出有效同意，还有合法性与透明性。(d) 完整性与机密性（安全），以及一件必须通报的个人数据泄露。
:::
:::

::: exercise 我能用这段代码吗？ {level=1}
对每种情形，说明你能否做所述之事，以及你必须做什么：(a) 把一篇未声明许可证的博客文章中的一个函数复制进你公司的产品；(b) 在一个专有移动应用中使用一个 MIT 许可证的库；(c) 修改一个 GPL-3.0 命令行工具并把修改后的二进制分发给客户；(d) 在自己的服务器上为公众用户运行一个修改过的 AGPL-3.0 Web 应用。
::: solution
(a) 不安全：版权自动产生，没有许可证你就没有许可（有限的例外如合理使用除外，但不要指望它们）。询问作者或自己写。(b) 可以；保留版权与许可声明，通常放在应用的「开源许可证」页面。(c) 可以，但你必须以 GPL-3.0 许可修改后的程序，并向这些客户提供相应的源代码。(d) 可以，但 AGPL 要求你向通过网络与其交互的用户提供你修改版本的源代码。
:::

::: exercise 枚举重新识别 {level=2 check="10"}
英国手机号码形如 07 后接九位数字。一个数据集把每个号码换成其无密钥 SHA-256 哈希。若攻击者每秒能计算 $10^8$ 个哈希，把每个可能的号码都哈希一遍从而还原整个数据集至多需要多少秒？（填入秒数。）
::: solution
可能的号码有 $10^9$ 个，$10^9 / 10^8 = 10$ 秒——加上查表会稍多一些。商用图形处理器每秒计算数十亿个 SHA-256 哈希，所以实际数字还要小得多。慢速的口令哈希函数会提高代价，但改变不了这么小空间下的结论；需要带密钥的 HMAC（密钥保密），或者根本不发布标识符。
:::
:::

::: exercise 假阳性率 {level=2 check="0.114"}
在一个基础比率 $p = 0.3$ 的群体中，某分类器的 $\mathrm{PPV} = 0.75$、$\mathrm{FNR} = 0.2$。用 [[#eq-chouldechova]] 计算它在该群体中的假阳性率，精确到小数点后三位。（填入比率。）
::: solution
$\mathrm{FPR} = \tfrac{0.3}{0.7} \cdot \tfrac{0.25}{0.75} \cdot 0.8 = 0.42857 \times 0.33333 \times 0.8 \approx 0.114$。用计数验证：1000 人中 300 人为正，其中 240 人被标记（$\mathrm{FNR} = 0.2$）；由 $\mathrm{PPV} = 0.75$，240 个真阳性占全部被标记者的四分之三，所以 700 名阴性中有 80 人被标记：$80/700 \approx 0.114$。
:::
:::

::: exercise 一个安全隐忧 {level=2}
你是一台输液泵控制器的开发者。发布前一周，你发现在罕见的按键顺序下，显示的剂量可能与实际输注的剂量不同。你的经理说发布日期已定，这一情景「不现实」。用 [[#def-codes]] 与本章的方法，决定该怎么做。
::: solution
*事实：*一个可能对患者造成严重伤害的缺陷，而患者是在决定中没有发言权的第三方；「罕见」的顺序在每天数千台设备的使用中会发生，显示与输出不符是用药错误的经典原因。*义务：*两份守则都把公众置于进度压力之上（公众、产品原则；ACM 1.2）；医疗器械法规（如 IEC 62304 过程）要求这类异常被记录并评估；你能够判断技术事实，但不能替患者接受风险。*选项：*在缺陷跟踪系统中精确记录该缺陷，附复现方法与严重性评估；正式提请经理以及负责风险接受的安全或质量部门注意；提出缓解措施（小则修复，或带着受影响功能禁用发布，或推迟）；不要不经评审悄悄修复，也不要沉默。*评估：*只有对安全负责的人才能决定带着已知危险发布，而且必须是在知情之下、留档在案地做出。若组织仍然压制这一问题，守则支持在内部途径穷尽之后升级上报，直至监管机构——对你的代价是真实的，这正是内部步骤与记录重要的原因。

::: exercise 精确地陈述不可能性 {level=3}
由 [[#eq-chouldechova]] 证明：若两个群体的基础比率 $p_1 \ne p_2$，则一个分类器不可能在两个群体中同时有相等的 $\mathrm{PPV}$、相等的 $\mathrm{FNR}$ 与相等的 $\mathrm{FPR}$，除非两者中 $\mathrm{PPV} = 1$ 或 $\mathrm{FNR} = 1$。然后举例说明基础比率不同时*可以*做到相等的 $\mathrm{FPR}$ 与相等的 $\mathrm{FNR}$，并计算查准率会发生什么。
::: solution
设两个群体中 $\mathrm{PPV}$、$\mathrm{FNR}$、$\mathrm{FPR}$ 相等，公共值为 $v$、$f$、$r$。由 [[#eq-chouldechova]]，对 $i = 1, 2$ 有 $r = \tfrac{p_i}{1-p_i} \cdot \tfrac{1-v}{v} \cdot (1-f)$。若 $v < 1$ 且 $f < 1$，因子 $\tfrac{1-v}{v}(1-f)$ 为正，于是 $\tfrac{p_1}{1-p_1} = \tfrac{p_2}{1-p_2}$；由于 $x \mapsto x/(1-x)$ 在 $(0, 1)$ 上是单射，得 $p_1 = p_2$，矛盾。所以 $v = 1$ 或 $f = 1$。

*相等的错误率是可以做到的。*取两个群体中 $\mathrm{FNR} = 0.2$、$\mathrm{FPR} = 0.1$，基础比率分别为 $0.5$ 与 $0.2$。群体 1 有 1000 人：阳性 500 人，被标记 400 人；阴性 500 人，被标记 50 人；$\mathrm{PPV}_1 = 400/450 \approx 0.89$。群体 2：阳性 200 人，被标记 160 人；阴性 800 人，被标记 80 人；$\mathrm{PPV}_2 = 160/240 \approx 0.67$。相等的错误率迫使查准率不相等：一个标记在一个群体中意味着 89% 的可能性为正，在另一个群体中只有 67%。这能否接受——或者，一个标记是否应当对每个人都意味着同一件事，代价是错误率不相等——不是数学问题。
:::
:::

::: exercise 达到目标 $k$ {level=3}
扩展 [[#ex-k-anonymity]]：写一个函数，尝试粗糙度递增的泛化——邮编先泛化到片区、再只留地区字母；出生年份泛化为 5 年、10 年、20 年段；性别保留或抑制——返回达到目标 $k$ 的最不粗糙的组合，其中粗糙度以各维度档位之和度量。在虚构数据集上分别对 $k = 2$ 与 $k = 4$ 运行。为什么说「最不粗糙」是一个合理但不完美的目标？
::: solution
```python
from collections import Counter
from itertools import product
from kanon import rows

POSTCODE = [lambda p: p, lambda p: p.split()[0], lambda p: p[:2]]   # 完整、片区、地区
YEAR = [lambda y: y, lambda y: y // 5 * 5, lambda y: y // 10 * 10, lambda y: y // 20 * 20]
SEX = [lambda s: s, lambda s: "*"]

def k_of(levels):
    pc, yr, sx = POSTCODE[levels[0]], YEAR[levels[1]], SEX[levels[2]]
    return min(Counter((pc(p), yr(y), sx(s)) for p, y, s, _ in rows).values())

def least_coarse(k):
    options = sorted(product(range(3), range(4), range(2)), key=lambda l: (sum(l), l))
    return next(l for l in options if k_of(l) >= k)

for k in (2, 4):
    levels = least_coarse(k)
    print(f"k >= {k}: postcode level {levels[0]}, year level {levels[1]}, "
          f"sex level {levels[2]} (actual k = {k_of(levels)})")
```

```console
$ python3 generalise.py
k >= 2: postcode level 1, year level 1, sex level 0 (actual k = 2)
k >= 4: postcode level 1, year level 1, sex level 1 (actual k = 4)
```

对 $k \ge 2$，搜索重新发现了 [[#ex-k-anonymity]] 的泛化——片区加五年段、性别保留——因为总档位不超过 2 且保留完整邮编的选项中没有一个可行：有几个完整邮编只出现一次。对 $k \ge 4$，它把性别也抑制了。「档位之和」把任何属性上的每一步视为同等代价，这是任意的：研究性别差异的研究者宁可进一步泛化邮编，也不愿完全失去性别。更好的目标会按属性对既定分析的价值加权——而无论目标是什么，$k$-匿名性都不能防范同质性或与外部数据的关联，所以泛化后的表仍应被当作个人数据，除非有更强的保证适用。
