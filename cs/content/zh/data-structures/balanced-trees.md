[[data-structures/binary-search-trees]] 中的二叉搜索树有一个严重缺陷：它们的高度，从而每个操作的代价，取决于键到来的次序。按递增次序插入十万个客户编号，这棵“树”就是一条十万个结点长的路径；每次查找平均要走五万步。随机次序本会给出几十的高度——但一个程序库不能假定用户按随机次序插入。

**平衡搜索树**消除了这种依赖。它们通过在每次更新之后检查一个局部平衡条件、并用少数几个被称为**旋转**的廉价重构步骤加以修复，对*每一个*插入与删除序列都把高度保持在 $O(\log n)$。本章介绍三种经典设计。**AVL树**使每个结点的两棵子树的高度至多相差一。**红黑树**给结点染色，并使每条根到叶路径的长度至多与其他每条路径相差两倍；它们是多数标准库中有序映射的实现。**B树**则彻底放弃二叉结点，让每个结点存放许多键，于是十亿个键的树只有三四层深——当每访问一个结点都要付出一次磁盘访问的代价时，这正是恰当的形状。对每一种树，我们都证明高度上界——保证正来源于此——并说明更新如何维持这个界。

## 旋转

所有平衡二叉树都用同一种原语做重构。旋转改变树的一小部分的形状，同时保持中序序列不变——因而由 [[data-structures/binary-search-trees#thm-inorder-sorted]]，也保持搜索树性质。

::: definition 旋转 {#def-rotation}
设 $y$ 是一个拥有左孩子 $x$ 的结点，$A$ 和 $B$ 是 $x$ 的左右子树，$C$ 是 $y$ 的右子树。对 $y$ 的一次**右旋**使 $x$ 成为这一部分树的根，$y$ 作为它的右孩子，$A$ 作为 $x$ 的左子树，$B$ 和 $C$ 分别作为 $y$ 的左右子树。对 $x$ 的一次**左旋**是相反的运算。

```text
          y                           x
         / \     rotate right at y   / \
        x   C   ---------------->   A   y
       / \      <----------------      / \
      A   B      rotate left at x     B   C
```
:::

::: lemma 旋转保持搜索树性质 {#lem-rotation}
一次旋转改变 $O(1)$ 个引用，耗时 $O(1)$，并且不改变树的中序序列。
:::

::: proof
两种形状的中序序列都是 $A, x, B, y, C$：在左边的形状中，$y$ 的左子树（列在 $y$ 之前）是 $A, x, B$；在右边的形状中，$x$ 的右子树（列在 $x$ 之后）是 $B, y, C$。树的其余部分只看到这一部分的根换了，仍接在同一根父链上。发生改变的链恰有三条：父结点的链（指向 $x$ 而不是 $y$）、$x$ 的右链（指向 $y$）以及 $y$ 的左链（指向 $B$）。
:::

旋转（就右旋而言）把 $A$ 上移一层、把 $C$ 下移一层，而 $B$ 的深度不变。这就是平衡树所扳动的杠杆：若 $A$ 太深，对 $y$ 右旋就能把它抬高。

## AVL树

::: definition AVL树 {#def-avl}
一个结点的**平衡因子**是其左子树的高度减去右子树的高度（空子树的高度取 $-1$）。**AVL树**是每个结点的平衡因子都为 $-1$、$0$ 或 $+1$ 的二叉搜索树。
:::

每个结点存放自己的高度（或者只存平衡因子，需要两个比特）。这个条件是局部的，但它在全局上约束了树的形状。

::: theorem AVL树的高度是对数的 {#thm-avl-height}
含 $n$ 个结点的 AVL树的高度满足 $h \le \log_\phi(n + 1) - 1 < 1.4405\log_2(n+1)$，其中 $\phi = (1 + \sqrt5)/2$。更精确地，$n \ge F_{h+3} - 1$，其中 $F_k$ 是第 $k$ 个斐波那契数（$F_1 = F_2 = 1$）。
:::

::: proof
设 $N(h)$ 为高度为 $h$ 的 AVL树的最少结点数。则 $N(0) = 1$，$N(1) = 2$。对 $h \ge 2$，高度为 $h$ 的极小树有一个根、一棵高度为 $h-1$ 的子树，并且由于平衡因子的绝对值至多为 $1$，另一棵子树的高度至少为 $h - 2$；极小树把这棵子树的高度恰好取为 $h - 2$，并且各子树处处极小，于是

$$
N(h) = 1 + N(h-1) + N(h-2).
$$

令 $M(h) = N(h) + 1$：则 $M(h) = M(h-1) + M(h-2)$，且 $M(0) = 2 = F_3$，$M(1) = 3 = F_4$，所以 $M(h) = F_{h+3}$，$N(h) = F_{h+3} - 1$。每棵高度为 $h$ 的 AVL树都有 $n \ge N(h)$ 个结点。

斐波那契数对 $k \ge 1$ 满足 $F_k \ge \phi^{k-2}$（归纳可知，因为 $\phi^2 = \phi + 1$：$F_{k} = F_{k-1} + F_{k-2} \ge \phi^{k-3} + \phi^{k-4} = \phi^{k-4}(\phi + 1) = \phi^{k-2}$，且 $F_1 = 1 \ge \phi^{-1}$，$F_2 = 1 = \phi^0$）。于是 $n + 1 \ge F_{h+3} \ge \phi^{h+1}$，得到 $h \le \log_\phi(n+1) - 1 < \log_\phi(n+1)$。最后 $\log_\phi x = \log_2 x / \log_2\phi$，而 $1/\log_2\phi \approx 1.4404$。
:::

所以 AVL树的高度至多比一棵完美平衡的树高出约 $44\%$。证明中那类极小的 AVL树称为**斐波那契树**；它们歪斜到了条件所允许的程度。

### 插入

像普通 BST 那样插入；新叶可能使它的那些祖先变高，从而把其中一些（多出恰好一个）压出平衡。沿插入路径往回走，我们更新高度，并在第一个平衡因子变成 $\pm 2$ 的结点处，执行一次旋转或一对旋转。

::: algorithm AVL的重平衡 {#alg-avl}
在返回根的路径上的结点 $z$ 处，更新它的高度之后：

1. 若 $z$ 的平衡因子为 $+2$（左子树过高），令 $x$ 为它的左孩子。
   - **左–左情形**（$x$ 的左子树不比它的右子树矮）：对 $z$ 右旋。
   - **左–右情形**（$x$ 的右子树更高）：对 $x$ 左旋，再对 $z$ 右旋（一次**双旋转**）。
2. 若 $z$ 的平衡因子为 $-2$，做镜像操作：右–右情形下对 $z$ 左旋；右–左情形下对 $z$ 的右孩子右旋、再对 $z$ 左旋。
:::

::: theorem 插入后一次重平衡即足够 {#thm-avl-insert}
在 AVL树上做一次 BST 插入后，设 $z$ 为新叶的平衡因子为 $\pm2$ 的最低祖先。在 $z$ 处执行 [[#alg-avl]] 的重平衡，使该处为根的子树成为一棵 AVL树，其高度等于插入*之前*的高度。于是其上的任何结点都无需改动，插入耗时 $O(\log n)$，旋转至多两次。
:::

::: proof
设 $z$ 的平衡因子为 $+2$（另一侧对称）。令 $x = z.\mathit{left}$，设 $h$ 为 $z$ 的右子树的高度，于是 $x$ 现在的高度是 $h + 2$。由于插入只增加了一个叶，它把 $x$ 的高度恰好抬高了一，从 $h + 1$ 抬来：$z$ 此前是平衡的，高度为 $h + 2$。新叶在 $x$ 的某棵子树中，该子树的高度变成了 $h + 1$，而 $x$ 的另一棵子树高度为 $h$——若它是 $h + 1$，$x$ 在插入之前就已经高度为 $h + 2$ 了。（$x$ 自身是平衡的，因为 $z$ 是*最低*的不平衡结点。）

*左–左情形*：$x.\mathit{left}$ 的高度为 $h + 1$，$x.\mathit{right}$ 的高度为 $h$。对 $z$ 右旋后，结点 $z$ 的两棵子树是 $x.\mathit{right}$ 和原来的右子树，高度都是 $h$，所以 $z$ 的高度为 $h+1$、平衡因子为 $0$；结点 $x$ 的两棵子树高度为 $h + 1$ 和 $h + 1$，平衡因子为 $0$，高度为 $h + 2$。

*左–右情形*：$x.\mathit{left}$ 的高度为 $h$，$y = x.\mathit{right}$ 的高度为 $h + 1$，它的子树 $B$ 与 $C$ 的高度为 $h$ 和 $h-1$（次序不定；或者 $y$ 就是新叶本身，此时 $h = -1$）。双旋转使 $y$ 成为根，其孩子为 $x$（子树为高度 $h$ 的 $x.\mathit{left}$ 与高度 $\le h$ 的 $B$）和 $z$（子树为高度 $\le h$ 的 $C$ 与高度 $h$ 的 $z$ 的右子树）。$x$ 与 $z$ 的高度都是 $h + 1$、平衡因子为 $0$ 或 $\pm1$，$y$ 的高度为 $h + 2$、平衡因子为 $0$。

两种情形下子树都是平衡的，且其高度 $h + 2$ 就是插入前的高度，于是所有祖先的高度与平衡因子都和从前一样。工作量为长 $O(\log n)$ 的路径（由 [[#thm-avl-height]]）上每个结点 $O(1)$，加上至多两次旋转。
:::

删除类似但没那么干净：删去一个结点可能*减小*某个高度，而修复某个结点的旋转可能减小它所在子树的高度，进而使某个祖先失去平衡。因此删除耗时 $O(\log n)$，但可能需要多达 $O(\log n)$ 次旋转，每层一次。

下面是 Python 中的 AVL 插入。每个结点存放自己的高度；递归回溯时在插入路径的每个结点上调用 `rebalance`——这比在第一个不平衡结点处停下更简单，每层只多花 $O(1)$。

```python
class Node:
    def __init__(self, key):
        self.key, self.left, self.right, self.height = key, None, None, 0

def h(t):
    return -1 if t is None else t.height

def update(t):
    t.height = 1 + max(h(t.left), h(t.right))

def rotate_right(y):              # y 的左孩子 x 成为该子树的根
    x = y.left
    y.left, x.right = x.right, y
    update(y); update(x)
    return x

def rotate_left(x):               # 镜像操作
    y = x.right
    x.right, y.left = y.left, x
    update(x); update(y)
    return y

def rebalance(t):
    update(t)
    bf = h(t.left) - h(t.right)   # 平衡因子
    if bf > 1:                    # 左重
        if h(t.left.left) < h(t.left.right):
            t.left = rotate_left(t.left)        # 左-右情形：双旋转
        return rotate_right(t)
    if bf < -1:                   # 右重
        if h(t.right.right) < h(t.right.left):
            t.right = rotate_right(t.right)     # 右-左情形：双旋转
        return rotate_left(t)
    return t

def insert(t, key):
    if t is None:
        return Node(key)
    if key < t.key:
        t.left = insert(t.left, key)
    elif key > t.key:
        t.right = insert(t.right, key)
    return rebalance(t)           # 回溯途中修正高度与平衡
```

::: example 向 AVL树按有序插入 {#ex-avl-sorted}
按递增次序向一棵空 AVL树插入 $1, 2, \dots, 7$，用 root(left, right) 记号写出每次插入后的树。再按次序插入 $1, \dots, 100\,000$，报告高度。
::: solution
```python
def shape(t):                     # root(left, right) 记号
    if t is None:
        return "-"
    if t.left is None and t.right is None:
        return str(t.key)
    return f"{t.key}({shape(t.left)}, {shape(t.right)})"

root = None
for k in range(1, 8):
    root = insert(root, k)
    print(k, shape(root))

root = None
for k in range(1, 100_001):       # 有序输入：普通 BST 的最坏情形
    root = insert(root, k)
print("height after 100000 sorted insertions:", root.height)
```

```console
$ python3 avl.py
1 1
2 1(-, 2)
3 2(1, 3)
4 2(1, 3(-, 4))
5 2(1, 4(3, 5))
6 4(2(1, 3), 5(-, 6))
7 4(2(1, 3), 6(5, 7))
height after 100000 sorted insertions: 16
```

插入 $3$ 使根 $1$ 右重（平衡因子 $-2$），且其右孩子 $2$ 同样右重：右–右情形，对 $1$ 左旋修复。插入 $5$ 使 $3$（最低的不平衡结点）失去平衡，在此左旋修复，于是 $4$ 成为 $2$ 的右孩子。插入 $6$ 使根 $2$ 失去平衡：对 $2$ 左旋使 $4$ 成为根。插入 $7$ 使 $5$ 失去平衡。$7$ 次插入之后树是完美的，高度为 $2$。

$100\,000$ 个有序键的高度是 $16 = \lfloor\log_2 100\,000\rfloor$，即可能的最小值——普通 BST 在这里高度将是 $99\,999$。（有序输入对 AVL树恰好是好的情形；[[#thm-avl-height]] 对任意次序保证至多 $1.44\log_2(n+1) \approx 23.9$。）
:::
:::

::: example 一次双旋转 {#ex-avl-double}
向一棵空 AVL树依次插入 $40, 20, 60, 10, 30$，然后插入 $25$。最后一次插入发生的是哪种情形？所得的树是什么？
::: solution
前五个键得到 $40(20(10, 30), 60)$，一棵根的平衡因子为 $+1$ 的 AVL树。键 $25$ 落在 $30$ 的左边。此时 $30$ 的高度为 $1$，$20$ 的高度为 $2$，而根 $40$ 的左子树高度为 $2$、右子树（$60$）高度为 $0$：平衡因子 $+2$。最低的不平衡结点是 $40$（$20$ 的两棵子树高度为 $0$ 和 $1$，平衡因子 $-1$）。它的左孩子 $20$ 是*右*重的，所以这是**左–右情形**：对 $20$ 左旋（使 $30$ 成为 $20$ 的父结点），再对 $40$ 右旋。结果是

```text
        30
       /  \
     20    40
    /  \     \
  10    25    60
```

也就是 $30(20(10, 25), 40(-, 60))$，上面的程序也会给出它。只对 $40$ 做一次右旋是不行的：那会使 $20$ 成为根，其右子树为 $40(30(25, -), 60)$，这个根的平衡因子为 $+1$，但 $20$ 自身的平衡因子将是 $0 - 2 = -2$。中间那个键 $30$ 必须上移两层，这需要两次旋转。
:::
:::

## 红黑树

AVL树平衡得很紧，但要在删除中维持这种紧度可能需要许多次旋转。**红黑树**把平衡条件放宽到两倍，换来的是只需常数次旋转的更新。

::: definition 红黑树 {#def-rb}
**红黑树**是每个结点各被染成红色或黑色的二叉搜索树，其中空子树被看作黑色的 **nil** 叶，并满足：

1. 根是黑的；
2. 红结点没有红孩子（等价地说：红结点的两个孩子都是黑的）；
3. 对每个结点 $x$，从 $x$ 向下到 nil 叶的每条路径含有同样多个黑结点（不计 $x$ 本身）。这个数目称为**黑高** $\mathit{bh}(x)$。
:::

::: theorem 红黑树的高度是对数的 {#thm-rb-height}
含 $n$ 个（非 nil）结点的红黑树的高度至多为 $2\log_2(n+1)$。
:::

::: proof
**断言。** 以任一结点 $x$ 为根的子树至少包含 $2^{\mathit{bh}(x)} - 1$ 个非 nil 结点。对 $x$ 的高度归纳。若 $x$ 是 nil 叶，则 $\mathit{bh}(x) = 0$，子树有 $0 = 2^0 - 1$ 个结点。否则 $x$ 的每个孩子 $c$ 的黑高为 $\mathit{bh}(x)$（若 $c$ 为红）或 $\mathit{bh}(x) - 1$（若 $c$ 为黑），从而至少 $\mathit{bh}(x) - 1$；由归纳假设，每个孩子的子树至少有 $2^{\mathit{bh}(x) - 1} - 1$ 个结点，于是 $x$ 的子树至少有 $2(2^{\mathit{bh}(x)-1} - 1) + 1 = 2^{\mathit{bh}(x)} - 1$ 个结点。

现在设 $h$ 为树的高度。在一条最长的根到叶路径上，没有两个红结点相邻（性质 2），且根是黑的，所以这条路径上根以下的结点至少一半——即至少 $h/2$ 个——是黑的。于是 $\mathit{bh}(\mathit{root}) \ge h/2$，由断言得 $n \ge 2^{h/2} - 1$。整理得 $h \le 2\log_2(n + 1)$。
:::

这个界弱于 AVL 的界（$2$ 对 $1.44$），所以红黑树可能略高一些，查找也略慢一些。作为回报，更新做更少的重构。

### 插入

新键按 BST 的方式插为一个叶并染成**红色**，这保持性质 3（它不给任何路径增加黑结点）。可能不成立的只有性质 2——当新结点的父结点为红时——或性质 1——当新结点就是根时。**修复**（fix-up）把问题向树的上部移动。设 $z$ 是父结点 $p$ 为红的那个红结点；于是 $p$ 不是根（根是黑的），从而 $z$ 有一个祖父 $g$，它是黑的。设 $u$ 为 $z$ 的**叔结点**，即 $g$ 的另一个孩子。

::: algorithm 红黑树的插入修复 {#alg-rb-insert}
当 $z$ 的父结点 $p$ 为红时（祖父为 $g$，叔结点为 $u$）：

1. **情形 1——叔结点为红。** 重新染色：$p$ 与 $u$ 变黑，$g$ 变红。令 $z \gets g$，上移两层继续。
2. **情形 2——叔结点为黑且 $z$ 是“内侧”孙结点**（$z$ 是左孩子 $p$ 的右孩子，或是右孩子的左孩子）。对 $p$ 旋转，使 $p$ 成为 $z$ 的孩子；改名使 $z$ 又成为两个红结点中较低的那个（此时它是“外侧”孙结点），转入情形 3。
3. **情形 3——叔结点为黑且 $z$ 是“外侧”孙结点。** 对 $g$ 旋转（$p$ 是左孩子则右旋，否则左旋），然后把 $p$ 染黑、$g$ 染红。循环结束。

最后把根染黑。
:::

情形 1 只改变颜色，可能沿树向上重复 $O(\log n)$ 次。情形 2 与 3 至多发生一次，在结尾。每一步保持性质 3 并对性质 2 取得进展的证明是细致的分情形检查；见 Cormen、Leiserson、Rivest 与 Stein（第 4 版，2022），§13.3。结果是：

::: theorem 红黑树的更新 {#thm-rb-updates}
向红黑树插入耗时 $O(\log n)$，旋转至多两次；删除耗时 $O(\log n)$，旋转至多三次。
:::

::: solution

| 15 | 叔结点 30 为红：情形 1，重新染色；根重新染黑 | 20B(10B(-, 15R), 30B) |
| 25 | 父结点为黑：无事 | 20B(10B(-, 15R), 30B(25R, -)) |
| 5 | 父结点为黑：无事 | 20B(10B(5R, 15R), 30B(25R, -)) |
| 1 | 叔结点 15 为红：在 5 处情形 1，随后 10 的父结点 20 为黑，停止 | 20B(10R(5B(1R, -), 15B), 30B(25R, -)) |
| 28 | 叔结点（nil，30 的右边）为黑，$28$ 在内侧：情形 2 对 25 左旋，再情形 3 对 30 右旋 | 20B(10R(5B(1R, -), 15B), 28B(25R, 30R)) |

检查最后的树。根是黑的，没有红结点带有红孩子。从根向下到每个 nil 叶的每条路径在根以下恰遇到两个黑结点（计入 nil 叶）：$20 \to 10 \to 5 \to 1 \to \text{nil}$ 遇到 $5$B 和 nil；$20 \to 10 \to 15 \to \text{nil}$ 遇到 $15$B 和 nil；$20 \to 28 \to 30 \to \text{nil}$ 遇到 $28$B 和 nil。所以根的黑高是 $2$。树的高度为 $3$，落在 [[#thm-rb-height]] 的界 $2\log_2 9 \approx 6.3$ 之内。
:::
:::

::: intuition 红黑树是乔装的 2-3-4树
把每个红结点并入它的黑父结点。每个黑结点连同它的红孩子一起成为一个“胖”结点，存放 $1$、$2$ 或 $3$ 个键，拥有 $2$、$3$ 或 $4$ 个孩子；而性质 3 说胖树的所有叶子处在同一深度。这棵胖树是一棵 **2-3-4树**，即下一节中最小度为 $2$ 的 B树；红黑树的运算用重新染色和旋转模拟它的结点分裂：[[#alg-rb-insert]] 的情形 1 就是一个满 4-结点的分裂，其中间键（此时为红）升入父结点。塞奇威克（Sedgewick）的**左倾红黑树**（2008）以同样方式对应 2-3树，而且代码特别简短。
:::

::: quiz
关于一棵含 $n$ 个结点的红黑树，哪些命题为真？（选出所有符合的。）
- [x] 最长的根到叶路径至多是最短路径的两倍长。
- [x] 它的高度是 $O(\log n)$。
- [ ] 每个结点的平衡因子都属于 $\set{-1, 0, 1}$。
- [ ] 插入可能需要 $\Theta(\log n)$ 次旋转。
::: solution
每条根到 nil 的路径都有同样多个黑结点，而最长的那条至多能在每个黑结点之后插进一个红结点，所以它至多是最短那条（全黑）的两倍长。高度至多 $2\log_2(n+1)$（[[#thm-rb-height]]）。红黑树未必是 AVL 平衡的：一个结点的两棵子树的高度之差可以超过一。插入至多需要两次旋转（[[#thm-rb-updates]]），尽管重新染色可能沿 $\Theta(\log n)$ 层向上传播。
:::
:::

## B树

当结点住在磁盘或 SSD 上时，二叉树的形状就错了。从存储器读一个块远比检查块中的键慢——以 2026 年计，从硬盘随机读一次约为 $10$ ms，从 SSD 读约为 $0.1$ ms，而内存中一次比较只要几纳秒。十亿个键的平衡二叉树高度约 $30$，于是一次查找要读 $30$ 个块。若改为每个结点存放数百个键、拥有数百个孩子，恰好占满一个块，高度便降到三四。

::: definition B树 {#def-btree}
**最小度**为 $t \ge 2$ 的 **B树**是一棵有根树，其中：

1. 每个结点 $x$ 按递增次序存放 $k_x$ 个键 $\mathit{key}_1 < \dots < \mathit{key}_{k_x}$，若它是内部结点，则还有 $k_x + 1$ 个孩子 $c_0, \dots, c_{k_x}$，使得 $c_i$ 的子树中的每个键都介于 $\mathit{key}_i$ 与 $\mathit{key}_{i+1}$ 之间（其中 $\mathit{key}_0 = -\infty$，$\mathit{key}_{k_x + 1} = +\infty$）；
2. 所有叶子同深；
3. 除根以外的每个结点至少有 $t - 1$ 个键，每个结点至多有 $2t - 1$ 个键，非空树的根至少有 $1$ 个键。

含 $2t-1$ 个键的结点是**满**的。$t = 2$ 时，结点有 $2$、$3$ 或 $4$ 个孩子：**2-3-4树**。
:::

::: theorem B树的高度 {#thm-btree-height}
含 $n \ge 1$ 个键、最小度为 $t$ 的 B树的高度满足 $h \le \log_t\dfrac{n+1}{2}$。
:::

::: proof
根至少有一个键，因而至少有两个孩子（若 $h \ge 1$）；其余每个内部结点至少有 $t$ 个孩子。所以深度 $1$ 处至少有 $2$ 个结点，深度 $2$ 处至少 $2t$ 个，深度 $d$ 处至少 $2t^{d-1}$ 个（对 $1 \le d \le h$），每个存放至少 $t - 1$ 个键。对键计数，

$$
n \ge 1 + (t - 1)\sum_{d=1}^{h} 2t^{d-1} = 1 + 2(t-1)\frac{t^h - 1}{t - 1} = 2t^h - 1,
$$

于是 $t^h \le (n+1)/2$，$h \le \log_t\frac{n+1}{2}$。
:::

取 $t = 500$（每结点至多 $999$ 个键）、$n = 10^9$ 个键，则 $h \le \log_{500}(5\times10^8) \approx 3.2$，故 $h \le 3$：任何一个键至多读 $4$ 个结点即可找到，而根——很可能连同第二层——会留在缓存中。

**查找**是 BST 查找的推广：在结点 $x$ 中找第一个 $\ge k$ 的键（在结点内部用顺序查找或二分查找）；若它等于 $k$，完成；否则下降到相邻两键之间的那个孩子。它读 $O(h) = O(\log_t n)$ 个结点，每个做 $O(t)$ 次工作（二分查找则为 $O(\log t)$），CPU 时间共 $O(t\log_t n)$。

**插入**总是把键加到一个叶上，但满的叶装不下另一个键。补救办法是把一个满结点**分裂**：它的中间键升入父结点，两侧各 $t - 1$ 个键形成两个结点。为确保父结点有位置，标准算法在*下行的途中*把遇到的每个满结点都分裂掉，这样它永远不必再回头上来。

::: algorithm B树的插入（单趟，沿路分裂） {#alg-btree-insert}
1. 若根是满的，新建一个根，把旧根作为它唯一的孩子，然后分裂那个孩子；树增高一层。（这是 B树高度增长的唯一途径——发生在顶部，这正是所有叶子保持同深的原因。）
2. 从根向下朝着 $k$ 应落入的叶下降。每当要移向一个满的孩子之前，先分裂它：它的中间键升入当前结点（由上一步，它不满），那个孩子变成各含 $t - 1$ 个键的两个结点。继续下降到包含 $k$ 的位置的那一半。
3. 把 $k$ 插入那个不满的叶，放在它按有序应处的位置。
:::

```python
class BNode:
    def __init__(self, leaf=True):
        self.keys, self.children, self.leaf = [], [], leaf

class BTree:
    """B-tree of minimum degree t: every node except the root holds t-1 to 2t-1 keys."""
    def __init__(self, t):
        self.t, self.root = t, BNode()

    def search(self, x, k):
        i = 0
        while i < len(x.keys) and k > x.keys[i]:
            i += 1                                   # 第一个 >= k 的键
        if i < len(x.keys) and k == x.keys[i]:
            return x, i
        return None if x.leaf else self.search(x.children[i], k)

    def _split_child(self, x, i):                    # x.children[i] 是满的
        t, y = self.t, x.children[i]
        z = BNode(y.leaf)
        x.keys.insert(i, y.keys[t - 1])              # 中间键升入
        x.children.insert(i + 1, z)
        z.keys, y.keys = y.keys[t:], y.keys[:t - 1]  # 两侧各 t-1 个键
        if not y.leaf:
            z.children, y.children = y.children[t:], y.children[:t]

    def insert(self, k):
        r = self.root
        if len(r.keys) == 2 * self.t - 1:            # 满根：树增高
            self.root = BNode(leaf=False)
            self.root.children.append(r)
            self._split_child(self.root, 0)
        x = self.root
        while not x.leaf:                            # 下降，先分裂满结点
            i = sum(1 for key in x.keys if key < k)
            if len(x.children[i].keys) == 2 * self.t - 1:
                self._split_child(x, i)
                if k > x.keys[i]:
                    i += 1
            x = x.children[i]
        x.keys.insert(sum(1 for key in x.keys if key < k), k)
```

::: example 让一棵 2-3-4树生长 {#ex-btree}
向一棵 $t = 2$ 的空 B树（每结点至多 $3$ 个键）插入 $10, 20, \dots, 90$，写出每次插入后的树。孩子写在其父结点之后的大括号中。
::: solution
```python
def show(x):
    if x.leaf:
        return str(x.keys)
    return str(x.keys) + "{" + " ".join(show(c) for c in x.children) + "}"

B = BTree(t=2)                                       # 一棵 2-3-4 树
for k in [10, 20, 30, 40, 50, 60, 70, 80, 90]:
    B.insert(k)
    print(k, show(B.root))
print(B.search(B.root, 70)[0].keys, B.search(B.root, 75))
```

B树的删除是镜像操作：在下行的途中，保证每个被进入的结点至少有 $t$ 个键——必要时从兄弟借一个键（经由父结点），或在双方都处于最少状态时与兄弟**合并**。它同样只需一趟，访问 $O(\log_t n)$ 个结点。

实践中，数据库与文件系统使用 **B+树**：一种变体，其中所有键和记录都住在叶中，内部结点只存放键的副本用于路由（于是每个块装得下更多键，扇出更大），叶子按次序链接，使一次范围扫描能够顺次读连续的叶而不必回到根。它们是 [[databases]] 中索引结构的主题。

::: warning 平衡树并非没有代价
平衡树在最坏情况下保证 $O(\log n)$，但它们的常数比普通 BST 或哈希表的大：每次更新都要维护高度或颜色，并可能旋转；每个结点还多带若干字段。当键不需要有序时，哈希表通常更快（[[data-structures/hash-tables]]）。当键以随机次序到来且很少删除时，普通 BST 在实践中可能同样好——但只有平衡树才能对有序或恶意的输入保证安全。另外，“$O(\log n)$”数的是比较：比较长的字符串键比比较整数贵，而在现代硬件上占主导的是高速缓存缺失——每层一次——这也是每结点存许多键的类 B树布局即使在内存中也快的原因。
:::

## 实践中

截至 2026 年，红黑树实现了主流 C++ 标准库中的 `std::map` 与 `std::set`、Java 中的 `TreeMap` 与 `TreeSet`，以及 Linux 内核中的许多有序容器（`lib/rbtree.c`），例如其 CPU 调度器的运行队列。AVL树平衡得更紧，适合以下查为主的工作负载。Python 的标准库中没有平衡树：`dict` 是哈希表，需要有序的代码通常用 `bisect` 模块维护一个有序列表（得益于内存的连续性，在中等规模上很快），或使用第三方包。B树——大多以 B+树的形式——是 PostgreSQL、MySQL 的 InnoDB 与 SQLite 等关系数据库的默认索引结构，并组织 NTFS、Btrfs 与苹果的 APFS 等文件系统的元数据。其他平衡结构也扮演同样的角色：跳表（Pugh，1990）靠掷硬币来平衡，例如用于 Redis 的有序集合；treap；以及伸展树——它是摊还平衡而非最坏情况平衡。

::: history
阿德尔松-韦利斯基（Georgy Adelson-Velsky）与兰迪斯（Evgenii Landis）在《信息组织的一种算法》（"An algorithm for the organization of information"，《苏联科学院报告》（*Doklady Akademii Nauk SSSR*），1962）中发表了第一棵平衡搜索树，即 AVL树。拜耳（Rudolf Bayer）与麦克赖特（Edward McCreight）在波音科学研究实验室发明了 B树，1970 年提出，1972 年在 *Acta Informatica* 上发表《大型有序索引的组织与维护》（"Organization and maintenance of large ordered indexes"）；“B”的所指从未被官方解释过。同年拜耳引入了“对称二叉 B树”，即 2-3-4树的二叉表示；圭巴斯（Leonidas Guibas）与塞奇威克（Robert Sedgewick）在《平衡树的一种二色框架》（"A dichromatic framework for balanced trees"，1978）中把它们用红黑两色重新表述，这便是红黑树名称的由来。科默（Douglas Comer）的综述《无处不在的 B树》（"The ubiquitous B-tree"，《ACM 计算综述》（*ACM Computing Surveys*），1979）记录了 B树多么快地在数据库中变得无处不在。休（William Pugh）的跳表（1990）与塞奇威克的左倾红黑树（2008）是同一思想的后续简化。
:::

## 后续内容

有了平衡树，有序映射的每个操作——查找、插入、删除、最小元、后继、秩与区间查询（用 [[data-structures/binary-search-trees]] 的增广方法）——都在最坏情况 $O(\log n)$ 时间内完成。增广平衡树（区间树、顺序统计树）以及摊还或随机的替代结构（伸展树、treap、跳表）在 [[algorithms]] 中展开。堆（[[data-structures/heaps]]）通过放弃完全有序，用更简单、更快的办法解决一个更窄的问题——反复取出最小元。B+树作为 [[databases]] 的索引结构再次登场，在那里它的代价按读入的磁盘块数来计；而平衡树是 [[parallel-computing]] 与 [[distributed-systems]] 中许多并发与持久数据结构的构件。

::: summary
- **旋转**（[[#def-rotation]]）在 $O(1)$ 时间内重构三条链，并保持中序序列不变（[[#lem-rotation]]）；平衡树用旋转在更新之后恢复平衡。
- **AVL树**（[[#def-avl]]）把每个平衡因子保持在 $\set{-1,0,1}$ 内；它的高度小于 $1.4405\log_2(n+1)$，因为高度 $h$ 的树至少有 $F_{h+3} - 1$ 个结点（[[#thm-avl-height]]）。一次单旋或双旋即可修复一次插入（[[#thm-avl-insert]]）；删除可能需要 $O(\log n)$ 次。
- **红黑树**（[[#def-rb]]）的根为黑、没有红结点带红孩子、且黑高相等；其高度至多 $2\log_2(n+1)$（[[#thm-rb-height]]）。更新需要 $O(\log n)$ 次重新染色，但旋转至多 $2$ 次（插入）或 $3$ 次（删除）。
- 红黑树对应于 2-3-4树，即最小度为 $2$ 的 B树。
- 最小度为 $t$ 的 **B树**（[[#def-btree]]）每结点保持 $t-1$ 到 $2t-1$ 个键，所有叶子同深；其高度至多 $\log_t\frac{n+1}{2}$（[[#thm-btree-height]]），这使它成为存储场合——每个结点是一个块——的首选结构。
- B树的插入沿路分裂满结点；树只在根处长高。
:::

向一棵空 AVL树插入 $3, 2, 1, 4, 5, 6, 7, 16, 15, 14$。指出每次重平衡发生的情形与所做的旋转，并给出最后的树。
::: solution
$3, 2, 1$：在 $3$ 处左–左情形，右旋：$2(1, 3)$。$4$：不需重平衡。$5$：在 $3$ 处右–右情形，左旋：$2(1, 4(3, 5))$。$6$：在 $2$ 处右–右情形，左旋：$4(2(1, 3), 5(-, 6))$。$7$：在 $5$ 处右–右情形：$4(2(1,3), 6(5, 7))$。$16$：不需重平衡。$15$：插在 $16$ 的左边，使 $7$ 失去平衡（平衡因子 $-2$），其右孩子 $16$ 左重：右–左情形，对 $16$ 右旋、再对 $7$ 左旋：$6$ 的右子树变成 $15(7, 16)$。$14$：插在 $7$ 的右边（$15$ 之下），使 $6$ 失去平衡（左高 $0$，右高 $2$），其右孩子 $15$ 左重：右–左情形，对 $15$ 右旋、再对 $6$ 左旋，使 $7$ 成为那棵子树的根：$7(6(5, -), 15(14, 16))$。最后的树：$4(2(1, 3), 7(6(5, -), 15(14, 16)))$，高度 $3$。运行 `insert` 函数可予证实。
:::

::: exercise 红黑树的性质 {level=2}
(a) 每个结点都是黑的树是合法的红黑树吗？哪些形状是可能的？(b) 证明：若一棵红黑树的根的黑高为 $b$（计入 nil 叶，如 [[#def-rb]]），则它至多有 $4^b - 1$ 个结点。(c) 给出一棵含键 $1, \dots, 7$ 的合法红黑树，使根的左右子树的高度分别为 $0$ 与 $2$——这是 AVL树不允许的。
::: solution
(a) 是，只要性质 3 成立：没有红结点时，所有根到 nil 的路径有同样多个结点，于是每个 nil 叶同深，树必是完美的。

(b) 考虑从根到某个 nil 叶的任意一条路径。根以下它恰含 $b$ 个黑结点，最后一个是 nil 叶。路上每个红结点后面都跟着一个黑结点（性质 2），所以它至多含 $b$ 个红结点。于是这条路径在根以下至多有 $2b$ 个结点，其中至多 $2b - 1$ 个非 nil：每个非 nil 结点的深度至多 $2b - 1$。高度至多 $2b - 1$ 的二叉树至多有 $2^{2b} - 1 = 4^b - 1$ 个结点（[[data-structures/trees#thm-height-size]]）。

(c) 取 $2$B$(1$B$,\ 4$R$(3$B$,\ 6$B$(5$R$, 7$R$)))$。它是 BST（中序为 $1, \dots, 7$）。根是黑的；红结点 $4$ 的孩子是黑的，$5$、$7$ 的孩子是 nil。每条路径上根以下的黑结点（计入 nil）：$2 \to 1 \to$ nil：$1$，nil；$2 \to 4 \to 3 \to$ nil：$3$，nil；$2 \to 4 \to 6 \to 5 \to$ nil：$6$，nil。全都等于 $2$。根的左子树高度 $0$、右子树高度 $2$，所以根的平衡因子为 $-2$。
:::

::: exercise 分裂的代价 {level=2 check="1"}
在 [[#ex-btree]] 中接着插入 $100$。这次插入做了几次结点分裂？（填入次数。）
::: solution
树是 $[40]\{[20]\{[10]\ [30]\}\ [60]\{[50]\ [70, 80, 90]\}\}$。根有一个键：不满。下降到 $[60]$：不满。下降到叶 $[70, 80, 90]$：满，于是分裂：$80$ 升上来，得到 $[60, 80]$，孩子为 $[50]$、$[70]$、$[90]$；随后 $100$ 加入 $[90]$。恰好 $1$ 次分裂，结果为 $[40]\{[20]\{[10]\ [30]\}\ [60, 80]\{[50]\ [70]\ [90, 100]\}\}$，程序可以证实。分裂是罕见的：大多数插入只是把一个键加进有空位的叶。
:::

::: exercise AVL树的删除可能连锁 {level=3}
证明：从 AVL树删去一个键可能需要 $\Theta(\log n)$ 次旋转。使用**斐波那契树**：$T_0$ 是单个结点，$T_1$ 是一个带左孩子的根，$T_h$ 是一个左子树为 $T_{h-1}$、右子树为 $T_{h-2}$ 的根。
::: hint
归纳证明：对每个 $h \ge 0$，$T_h$ 中都有一个键，删去它并沿途重平衡后，得到一棵高度 $h - 1$ 的 AVL树，且执行了至少 $\lfloor h/2 \rfloor$ 次旋转。
:::
::: solution
$T_h$ 是一棵高度 $h$ 的 AVL树，每个内部结点的平衡因子都是 $+1$，有 $F_{h+3} - 1$ 个结点（它是最小的，如 [[#thm-avl-height]]），所以 $h = \Theta(\log n)$。

**断言：** 对每个 $h \ge 0$，都可删去 $T_h$ 的某个键，使结果是一棵高度 $h - 1$ 的 AVL树，且用到至少 $\lfloor h/2\rfloor$ 次旋转。

$h = 0$ 时删去唯一的结点（高度 $-1$，无旋转）；$h = 1$ 时删去那个叶（高度 $0$，无旋转）。$h \ge 2$ 时，把断言用于右子树 $T_{h-2}$：它在至少 $\lfloor (h-2)/2\rfloor$ 次旋转后成为高度 $h - 3$ 的 AVL树。此时根 $z$ 有左子树 $x = T_{h-1}$（高度 $h - 1$）和高度 $h - 3$ 的右子树：平衡因子 $+2$。由于 $x$ 的平衡因子为 $+1$（它的左子树 $T_{h-2}$ 高 $h-2$，右子树 $T_{h-3}$ 高 $h - 3$），这是左–左情形：对 $z$ 右旋。于是 $z$ 得到高度 $h - 3$ 与 $h - 3$ 的两棵子树，高度为 $h - 2$；$x$ 得到高度 $h - 2$ 与 $h - 2$ 的两棵子树，高度为 $h - 1$。结果是一棵高度 $h - 1$ 的 AVL树，共用去 $\lfloor (h-2)/2\rfloor + 1 = \lfloor h/2 \rfloor$ 次旋转。

关键是旋转*减小*了该子树的高度（从 $h$ 到 $h - 1$），于是不平衡向上传到父结点——而插入之后旋转恢复原有高度（[[#thm-avl-insert]]），修复就此停止。
:::
:::

::: exercise $t = 3$ 的 B树 {level=3}
用 $t = 3$ 的 `BTree` 类（每结点至多 $5$ 个键）按递增次序插入键 $1, 2, \dots, 20$。先手工预测最后的树，再运行代码。树有多少个结点？键位（每结点 $5$ 个）用了多大比例？解释为什么有序插入会让大多数结点只装到最少 $t - 1$ 个键，以及为什么有些数据库会对 B+树最右端的追加做专门处理。
::: solution
第一次分裂发生在 $6$ 到达满根 $[1, 2, 3, 4, 5]$ 之时：中间键 $3$ 升入一个新根，留下 $[1, 2]$ 与 $[4, 5]$，$6$ 加入右叶。此后每个键都走到最右的叶；每当它满了——$[a, \dots, a+4]$——就被分裂，中间键 $a + 2$ 升上去，$[a, a+1]$ 留在原地，此后再也不会被碰到。当根本身满了（$[3, 6, 9, 12, 15]$），就在下一次能到达它的插入时分裂。程序打印

```console
[9]{[3, 6]{[1, 2] [4, 5] [7, 8]} [12, 15]{[10, 11] [13, 14] [16, 17, 18, 19, 20]}}
```

共有 $9$ 个结点（一个根、$2$ 个内部结点和 $6$ 片叶），在 $45$ 个键位中存放 $20$ 个键，约 $44\%$；最右一路以外的每个结点都恰存放最少的 $t - 1 = 2$ 个键。顺序键——时间戳、自增标识符——极为常见，因此有些 B+树实现当新键最大时把满的最右叶不对称地分裂：旧叶保持满，另起一个几乎空的新叶；于是只追加的工作负载几乎能把结点装满。
:::
