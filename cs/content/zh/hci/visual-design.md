一台服务器仪表盘把每台机器显示为一个彩色圆点：绿色代表健康，红色代表故障。在设计评审中它看起来干净利落。可在运维室里，每十二名工程师中就有一人看到的这两种颜色几乎是一片浑浊的橄榄色，它们旁边的浅灰色标签在房间另一头的墙面大屏上根本看不清，而响应时间的图表使用一条彩虹色标，在数据平滑变化的地方制造出突兀的视觉分界。这些都不是品味问题。红–绿色觉缺陷者眼中显得相同的颜色是可以计算出来的，白底灰字的可读性是可以计算出来的，而彩虹色标引入的失真可以从视觉的工作原理加以解释。

界面中的**视觉设计**（visual design）是屏幕上各元素的排布——它们的分组、对齐、大小、字体与颜色——使人们能看见要紧的东西、读到需要的内容、理解自己能做什么。**信息设计**（information design）与**可视化**（visualisation）把它扩展到数据的呈现，使比较足够精确。本章建立在 [[hci/human-factors]] 所讲的视觉与注意之上：我们涵盖视觉层次与格式塔分组、字体排印与屏幕上物体的大小、颜色——sRGB 编码、相对亮度与 WCAG 2.2 精确的对比度公式——色觉缺陷及其模拟，以及好图表的知觉基础。

## 分组与层次

在屏幕上读出任何东西之前，视觉系统已经把它分成了区域与物体。1920 年代的**格式塔**（Gestalt）心理学家——马克斯·韦特海默（Max Wertheimer）、沃尔夫冈·科勒（Wolfgang Köhler）与库尔特·科夫卡（Kurt Koffka）——描述了这种分组的规律，它们至今仍是版式设计最有用的词汇表。

::: definition 格式塔的分组原则 {#def-gestalt}
当元素满足下列条件时，它们往往被知觉为同属一组：

- 彼此**靠近**（*proximity*，邻近性）；
- 在颜色、形状、大小或朝向上**相似**（*similarity*，相似性）；
- 位于同一个有边界的区域之内（*common region*，公共区域，由 Stephen Palmer 于 1992 年补充）；
- 位于同一条平滑的直线或曲线之上（*continuity*，连续性）；
- 一起运动（*common fate*，共同命运）；
- 而不完整的形状往往被看作完整（*closure*，闭合性），同时每个场景都被分为处在前景的**图形**（figure）与其下的**背景**（ground）（*figure–ground*，图形–背景）。
:::

这些原则会相互作用，而邻近性与公共区域通常最强。版式问题往往是分组问题：一个与两个输入框等距的标签，会被读成属于其中任意一个；一个 "Delete" 按钮若放得离它并不影响的列表比离它要删除的条目还近，就诱发了错误的解读。

::: example 按邻近性给表单分组 {#ex-proximity}
一个收货表单的标签与输入框处处用相等的 16 像素间隔排布：

```text
Name
[                    ]
Street
[                    ]
City
[                    ]
Card number
[                    ]
Expiry
[                    ]
```

页面滚动之后，用户有时会把城市名输进卡号栏。重新设计间距。
::: solution
间隔相等时，每个标签离它*上方*的输入框与离下方的同样近，地址与支付两个部分成了一列无差别的内容。在两个层次上运用邻近性：让每个标签贴近它自己的输入框（4 px）而远离上一个输入框（16 px）；再用一个大得多的间隔（40 px）加一个标题把两个部分分开——公共区域、一圈浅色边框或背景能进一步强化分组：

```text
Delivery address
  Name         [                    ]
  Street       [                    ]
  City         [                    ]

Payment
  Card number  [                    ]
  Expiry       [     ]
```

输入框的宽度现在也在暗示预期的长度（有效期很短），这是 [[hci/user-centred-design#def-norman]] 意义上的一个指示物。标签放在输入框上方还是旁边，远不如"每个标签都明确地只与一个输入框归为一组"重要；在窄窄的手机屏幕上，标签放在输入框上方效果更好。
:::
:::

**视觉层次**（visual hierarchy）是元素按吸引注意力的强弱排出的次序：大小、字重、对比、颜色、位置与周围的空间。好的层次让页面上重要性的次序与用户需要的次序一致：页面标题，然后主操作，然后内容，然后次要操作。[[hci/human-factors#def-preattentive]] 的前注意特征就是工具，而规则是节俭：每屏一个主操作，用别的元素都不用的那一种特征来突出。向少数几条公共边线**对齐**（一个**网格**，grid）减少了眼睛必须追踪的不同位置的数目，使分组与层次一目了然；**留白**不是浪费的空间，而是邻近性赖以构成的材料。

## 屏幕上的文字

### 易认性与易读性

**易认性**（legibility）指单个字符彼此区分的容易程度（I、l 与 1；rn 与 m）；**易读性**（readability）指连续文本阅读的容易程度。两者都取决于大小、对比、字母形状、间距与行长。字体排印对单栏连续文本的传统建议是行长约 45 到 75 个字符，66 左右最佳（Robert Bringhurst，*The Elements of Typographic Style*），行距约为字号的 1.2 到 1.5 倍；行太长，眼睛难以找到下一行的开头；太短则把短语切断。这些是工艺惯例，只有参差的实验文献支持，而不是精确的最优值：Mary Dyson 的综述发现，屏幕上的阅读*速度*有时在长行下反而更高，而读者*偏好*适中的行长。无障碍指南把其中最重要的部分写成了标准，例如允许用户调整间距而不丢失内容（WCAG 2.2 成功标准 1.4.12）。

### 一个像素有多大？

屏幕的像素密度差别极大，所以 CSS 用视角而不是物理像素来定义其长度单位。

::: definition CSS 参考像素 {#def-css-px}
**CSS 参考像素**是像素密度为 96 dpi 的设备在一臂之长（取 28 英寸）处观看时一个像素所张的视角。由 [[hci/human-factors#eq-visual-angle]] 它是

$$
\theta_{\text{px}} = 2 \arctan\frac{1/96}{2 \times 28} \approx 0.0213°.
$$

CSS 像素（`px`）在任何设备上都大致对应这一角度：手机因为拿得更近，其 CSS 像素在物理上比桌面显示器上的更小。在印刷品和大多数桌面浏览器上，$1\,\text{in} = 96\,\text{px}$ 恰好成立。
:::

::: example 手机与显示器上的字号 {#ex-text-size}
正文设为 16 CSS px。在 96 CSS px 每英寸、于 70 厘米处观看的桌面显示器上，以及在把 16 CSS px 映射为 2.6 毫米、于 30 厘米处观看的手机上，字号各张多大的视角？
::: solution
在显示器上，16 px 是 $16/96 = 1/6$ 英寸 $\approx 4.23$ 毫米，故 $\theta \approx 4.23/700$ 弧度 $\approx 0.346°$。在手机上，$\theta \approx 2.6/300$ 弧度 $\approx 0.497°$。手机上的文字物理上更小，却因为拿得更近而张出*更大*的角度；CSS 像素如 [[#def-css-px]] 所设想的那样是一个近似的角度单位，尽管真实设备只是近似满足它。（字号是字体正文（body）的高度；大写字母通常约占它的 70%。）
:::
:::

## 颜色

### 屏幕上颜色的编码

人的色觉是**三色觉**（trichromatic）：视网膜的三种视锥细胞分别对长（L）、中（M）、短（S）波长敏感，把任意光谱压缩为三个数，这就是显示设备只需三个原色的原因。Web 上的屏幕使用 **sRGB** 色彩空间（IEC 61966-2-1，1999）：一个颜色是三个 8 位值 $R, G, B \in \set{0, \dots, 255}$，但它们是 **gamma 编码**的——与发出的光不成正比——好让 256 个级别大致均匀地分布在*知觉*亮度上。要计算任何物理量（如亮度），必须先解码。[[graphics/images-colour]] 完整地发展了色度学；这里我们只需要亮度。

::: definition 相对亮度（WCAG 2.2） {#def-luminance}
对通道为 8 位的 sRGB 颜色，对每个通道令 $c_{\text{sRGB}} = c_8/255$ 并线性化：

$$
c = \begin{cases} c_{\text{sRGB}} / 12.92 & \text{若 } c_{\text{sRGB}} \le 0.04045,\\ \bigl((c_{\text{sRGB}} + 0.055)/1.055\bigr)^{2.4} & \text{否则。}\end{cases}
$$

**相对亮度**为

$$
L = 0.2126\,R + 0.7152\,G + 0.0722\,B,
$$ {#eq-luminance}

其中 $R, G, B$ 是线性化后的通道；黑色时 $L = 0$，白色时 $L = 1$。
:::

这些权重反映了眼睛对绿光远比对蓝光敏感。2021 年 5 月之前的 WCAG 版本把阈值印作 0.03928（出自 sRGB 标准的早期草稿）；现行的 WCAG 2.2 使用 0.04045，并注明这一改动没有实际影响。事实上，对 8 位值它什么都没改变：$10/255 \approx 0.0392$ 低于两个阈值，$11/255 \approx 0.0431$ 高于两个阈值。

::: definition 对比度 {#def-contrast}
相对亮度为 $L_1 \ge L_2$ 的两个颜色的**对比度**为

$$
CR = \frac{L_1 + 0.05}{L_2 + 0.05}.
$$ {#eq-contrast}

WCAG 2.2 在 AA 级（成功标准 1.4.3）要求正文 $CR \ge 4.5$、**大尺寸文本**（至少 18 磅，或 14 磅粗体）$CR \ge 3$，在 AAA 级（1.4.6）则分别要求 $7$ 与 $4.5$。用户界面组件与有意义的图形相对相邻颜色需要 $CR \ge 3$（1.4.11，AA 级）。比较比值时不做四舍五入：$4.499{:}1$ 不合格。
:::

$0.05$ 两项模拟屏幕反射的光与环境眩光，它们使真正的纯黑不存在，也使比值保持有限。它们同时给出了界限：

::: proposition 对比度的取值范围 {#prop-contrast-range}
(a) $1 \le CR \le 21$，且仅当白底黑字时 $CR = 21$。(b) 对任何颜色，它相对黑色与相对白色的对比度中较大者至少为 $\sqrt{21} \approx 4.58$，等号恰当 $L = \sqrt{0.0525} - 0.05 \approx 0.1791$ 时成立。因此不存在相对*黑色和白色*的对比度都超过 $\sqrt{21}$ 的颜色。
:::

::: proof
(a) 由 $0 \le L_2 \le L_1 \le 1$，$CR = (L_1 + 0.05)/(L_2 + 0.05) \ge 1$，且 $CR \le (1 + 0.05)/(0 + 0.05) = 21$，等号成立当且仅当 $L_1 = 1$ 且 $L_2 = 0$。(b) 亮度为 $L$ 的颜色相对白色的比为 $w(L) = 1.05/(L + 0.05)$，相对黑色的比为 $k(L) = (L + 0.05)/0.05$。对每个 $L$ 二者之积都是 $w(L)\,k(L) = 1.05/0.05 = 21$。若两者都小于 $\sqrt{21}$，乘积就会小于 21，矛盾；故 $\max(w, k) \ge \sqrt{21}$，同理 $\min(w, k) \le \sqrt{21}$。等式 $w = k = \sqrt{21}$ 成立当且仅当 $(L + 0.05)^2 = 1.05 \times 0.05 = 0.0525$，即 $L = \sqrt{0.0525} - 0.05 \approx 0.1791$。
:::

这条命题说明：任何背景上总*有一种*文字颜色——黑或白——能达到 AA（$\sqrt{21} > 4.5$），这对自动选取文字颜色很有用：若 $L < 0.1791$ 选白色，否则选黑色。它还说明：$L \approx 0.18$ 附近的中灰对两种颜色的文字都是糟糕的背景：8 位灰度中只有 `#757575` 与 `#767676` 两个能相对黑白者都达到 4.5。

::: example 精确计算对比度 {#ex-contrast}
计算几对颜色的对比度，并对照 WCAG AA 阈值分类。
::: solution
```python
def channel(c8):
    """8-bit sRGB channel -> linear value, as in the WCAG 2.2 definition."""
    c = c8 / 255
    return c / 12.92 if c <= 0.04045 else ((c + 0.055) / 1.055) ** 2.4

def luminance(hex_colour):
    r, g, b = (int(hex_colour[i:i + 2], 16) for i in (1, 3, 5))
    return 0.2126 * channel(r) + 0.7152 * channel(g) + 0.0722 * channel(b)

def contrast(c1, c2):
    l1, l2 = sorted((luminance(c1), luminance(c2)), reverse=True)
    return (l1 + 0.05) / (l2 + 0.05)

for fg, bg in [("#767676", "#FFFFFF"), ("#777777", "#FFFFFF"), ("#959595", "#FFFFFF"),
               ("#949494", "#FFFFFF"), ("#FFFFFF", "#0066CC"), ("#D62728", "#2CA02C"),
               ("#000000", "#FFFFFF")]:
    r = contrast(fg, bg)
    verdict = "AA" if r >= 4.5 else "AA large only" if r >= 3 else "fails"
    print(f"{fg} on {bg}: L = {luminance(fg):.4f} / {luminance(bg):.4f}, ratio {r:.3f}:1 ({verdict})")
```

```console
#777777 on #FFFFFF: L = 0.1845 / 1.0000, ratio 4.478:1 (AA large only)
#959595 on #FFFFFF: L = 0.3005 / 1.0000, ratio 2.995:1 (fails)
#949494 on #FFFFFF: L = 0.2961 / 1.0000, ratio 3.033:1 (AA large only)
#FFFFFF on #0066CC: L = 1.0000 / 0.1386, ratio 5.567:1 (AA)
#D62728 on #2CA02C: L = 0.1590 / 0.2586, ratio 1.476:1 (fails)
#000000 on #FFFFFF: L = 0.0000 / 1.0000, ratio 21.000:1 (AA)
```

先手算第一组：$0x76 = 118$，$118/255 \approx 0.4627 > 0.04045$，故 $c = ((0.4627 + 0.055)/1.055)^{2.4} \approx 0.1812$；灰色的 $R = G = B$，而权重之和为 1，所以 $L = c$。于是 $CR = 1.05/(0.1812 + 0.05) \approx 4.54$。浅一档的 `#777777` 达不到正文 AA：`#767676` 是在白底上通过的最浅的灰。红–绿那一对比值只有 1.48：这两个颜色的差别几乎全在色相上而不在亮度上——这是色觉缺陷的第一个警示信号。
:::
:::

::: warning "对比度达标，文字就好读"
WCAG 对比度是一个简单、可检验的代理指标，弱点也为人所知。除了大字号门槛之外，它无视字重与字号，所以一款极细的字体可以达标却仍然难读；它不是感知均匀的，倾向于高估深色背景上的浅色文字相对于浅色背景上的深色文字的对比；它对眩光、屏幕质量或环境光也只字不提。诸如 APCA 之类的较新模型（被提议用于未来的 WCAG 3）试图解决这些问题，但截至 2026 年，标准与法律引用的仍是 WCAG 2.2 的比值。把达标的比值当作最低要求，并在真实条件下与用户一起测试。
:::

### 色觉缺陷

约 8% 的北欧裔男性和 0.4% 的女性有红–绿**色觉缺陷**（colour-vision deficiency，CVD），大多数其他人群中的比例更低（Jennifer Birch，"Worldwide prevalence of red–green color deficiency"，*Journal of the Optical Society of America A*，2012）。色觉缺陷是遗传的，多半只影响一种视锥细胞：

| 类型 | 受影响的视锥 | 效应 |
|---|---|---|
| 红色盲（protanopia）/ 红色弱（protanomaly） | L（长波）缺失 / 偏移 | 红绿相混；红色显得暗 |
| 绿色盲（deuteranopia）/ 绿色弱（deuteranomaly） | M（中波）缺失 / 偏移 | 红绿相混（绿色弱是最常见的形式） |
| 蓝色盲（tritanopia）/ 蓝色弱（tritanomaly） | S（短波）缺失 / 偏移 | 蓝黄相混（罕见） |
| 全色盲（achromatopsia） | 视锥均无功能 | 无色觉；通常视力差且畏光（极罕见） |

"-opia"（盲）形式是**二色觉**（dichromacy，两种视锥工作），"-anomaly"（弱）形式是**异常三色觉**（anomalous trichromacy，三种都工作，一种偏移）。二色觉者的颜色知觉可以近似为把颜色投影到他们所能区分的二维颜色集合上。Gustavo Machado、Manuel Oliveira 与 Leandro Fernandes（*IEEE Transactions on Visualization and Computer Graphics*，2009）给出了在线性 RGB 下按严重程度参数化的 $3 \times 3$ 矩阵。

::: example 二色觉者在仪表盘上看到什么 {#ex-cvd}
对绿色盲与红色盲，模拟仪表盘的红色（`#D62728`）与绿色（`#2CA02C`），并连同蓝色与橙色一起模拟。
::: solution
```python
# Simulating dichromacy with the matrices of Machado, Oliveira & Fernandes (2009),
# severity 1.0, applied to linear RGB.
DEUTAN = [[0.367322, 0.860646, -0.227968],
          [0.280085, 0.672501, 0.047413],
          [-0.011820, 0.042940, 0.968881]]
PROTAN = [[0.152286, 1.052583, -0.204868],
          [0.114503, 0.786281, 0.099216],
          [-0.003882, -0.048116, 1.051998]]

def to_linear(c8):
    c = c8 / 255
    return c / 12.92 if c <= 0.04045 else ((c + 0.055) / 1.055) ** 2.4

def to_srgb8(c):
    c = min(max(c, 0.0), 1.0)
    c = 12.92 * c if c <= 0.0031308 else 1.055 * c ** (1 / 2.4) - 0.055
    return round(255 * c)

def simulate(hex_colour, m):
    rgb = [to_linear(int(hex_colour[i:i + 2], 16)) for i in (1, 3, 5)]
    out = [sum(m[r][k] * rgb[k] for k in range(3)) for r in range(3)]
    return "#" + "".join(f"{to_srgb8(c):02X}" for c in out)

for colour in ["#D62728", "#2CA02C", "#1F77B4", "#FF7F0E"]:
    print(colour, "deutan ->", simulate(colour, DEUTAN), " protan ->", simulate(colour, PROTAN))
```

```console
$ python3 cvd.py
#D62728 deutan -> #8B7C1F  protan -> #615725
#2CA02C deutan -> #968838  protan -> #A39119
#1F77B4 deutan -> #456CB3  protan -> #5A79B7
#FF7F0E deutan -> #C4AE05  protan -> #A59100
```

对绿色盲者，红色变成 `#8B7C1F`，绿色变成 `#968838`：两个极其相近的橄榄色，这就是开头那个故障。对红色盲者红色还会变暗（`#615725`），而绿色相对保持明亮，所以仅凭亮度就能略加分开它们。蓝色在两种情况下都保持得很好，橙色变成与蓝色明显可分的黄色。矩阵每行之和为 1，所以灰色不变。三条补救措施：绝不把颜色作为传达信息的*唯一*手段（WCAG 2.2 成功标准 1.4.1）——加上形状、位置或标签（失败用叉号，成功用对勾）；若必须由颜色承担区分，选择在亮度上和蓝–黄轴上都有差别的配对（蓝与橙是常用的安全配对）；并用模拟工具检查设计。模拟只是对平均二色觉者的近似；异常三色觉者之间差异很大。
:::
:::

## 呈现数据

### 视觉编码的准确度

图表把数字编码为视觉属性——位置、长度、角度、面积、颜色——而读者再把它们解码出来。William Cleveland 与 Robert McGill（"Graphical perception"，*Journal of the American Statistical Association*，1984）测量了人们在不同编码下判断两个数值之比的准确程度，并提出**基本知觉任务**的一个排序，从最准确到最不准确：

1. 沿共同刻度的位置；
2. 沿不对齐刻度的位置；
3. 长度、方向、角度；
4. 面积；
5. 体积、曲率；
6. 明暗、色彩饱和度。

Jeffrey Heer 与 Michael Bostock 用众包参与者复现了核心结果（CHI 2010）。这个排序解释了常见的建议：条形图与点图（共同刻度上的位置）比饼图（角度与面积）支持更精确的比较，而堆叠条形图除最底下一段外每一段都更难比较（位置不对齐）。面积特别容易误导，因为感知的面积增长比实际面积慢——S. S. Stevens 的心理物理测量给出表观面积的指数约为 0.7——所以除非读者去读数字，气泡图和按比例缩放的图标都会低估大的差别。

Jock Mackinlay 的自动呈现系统（1986）把选择编码的两条准则形式化：**表达性**（expressiveness）——编码显示数据中的全部事实且*只*显示这些事实（颜色渐变暗示次序，所以不应用于无序类别）——以及**有效性**（effectiveness）——在表达性编码之中，最重要的变量应当使用人们解码最准确的那种编码。

### 诚实的刻度

::: definition 谎言因子 {#def-lie-factor}
Edward Tufte（*The Visual Display of Quantitative Information*，1983）把一幅图形的**谎言因子**（lie factor）定义为

$$
\text{谎言因子} = \frac{\text{图形中所显示的效应幅度}}{\text{数据中的效应幅度}},
$$

其中两个值 $v_1, v_2$ 之间效应的幅度是相对变化 $\lvert v_2 - v_1\rvert / v_1$——分别在图形的视觉维度上与数据中测量。一幅诚实的图形，其谎言因子接近 1。
:::

::: example 按两个维度缩放的图标 {#ex-lie}
一张信息图用两个手机图标表示某公司用户从 200 万翻倍到 400 万，第二个图标画得既高一倍又宽一倍。若读者按面积判断图标，谎言因子是多少？若同一数据的条形图把坐标轴起点设在 150 万呢？
::: solution
数据中的效应是 $(4 - 2)/2 = 1$（增长 100%）。第二个图标的面积是 $2 \times 2 = 4$ 倍，图形上的效应是 $(4 - 1)/1 = 3$。谎言因子是 $3/1 = 3$。（由于感知的面积增长比面积慢，读者感知到的也许不到四倍——但图形仍在失真。）对于截断的条形图，长度正比于 $v - 1.5$ 的条形长为 $0.5$ 与 $2.5$，效应为 $(2.5 - 0.5)/0.5 = 4$，所以谎言因子是 4。条形长度必须从零开始；折线图编码的是位置而不是长度，当要紧的是*变化*时可以采用非零基线，前提是坐标轴有清楚的标注。
:::
:::

### 色标

色标把数字映射为颜色，应当与数据的结构匹配：**顺序**（sequential）色标（单一或少数几种色相上由浅到深）用于有次序的量值；**发散**（diverging）色标（两种色相在中性中点处相接）用于有有意义中心的数，例如相对基线的变化；**分类**（categorical）色板（亮度相近、彼此相异的色相）用于无序类别——类别至多只能有几个，因为人无法可靠地区分许多种色相。

**彩虹**（rainbow）色标长期是科学软件的默认，作为顺序色标很差。它的亮度沿色标先升后降（黄色远比蓝色或红色亮），于是在数据平滑变化之处——在窄窄的黄色与青色带上——制造出表观的分界，又在宽阔的绿色区域里掩盖真实的差别；它对许多读者没有自然的次序；对红–绿色觉缺陷也不适用。David Borland 与 Russell Taylor 在 "Rainbow color map (still) considered harmful"（*IEEE Computer Graphics and Applications*，2007）中总结了证据。**感知均匀**（perceptually uniform）的色标使数据中的相等步长对应感知色差的相等步长、且亮度单调递增，从而避免了这些问题；*viridis* 由 Stéfan van der Walt 与 Nathaniel Smith 为 matplotlib 于 2015 年设计，是被广泛使用的例子，在色觉模拟下和灰度上也保持有序。

::: quiz
一张图表要显示 30 条产品线月销售额的百分比变化，从 −40% 到 +60%，让经理们能看出哪些产品线增长了、哪些萎缩了。哪种编码最好？
- [ ] 按产品线显示销售额的饼图，按变化上色。
- [ ] 条形按 −40%（蓝）到 +60%（红）的彩虹色标上色。
- [x] 水平条形置于共同坐标轴上并标出零点，按变化排序，用零点为中心的发散色标上色。
- [ ] 气泡面积正比于变化量的气泡图。
::: solution
这项任务是比较带符号的量值，所以沿共同刻度的位置或长度是最准确的编码（Cleveland 与 McGill）。标出零点并按变化排序，使增长与萎缩一目了然；以 0% 为中心的发散色标表达了数据有意义的中点，且与位置冗余，不添乱。饼图用弱通道（角度）编码了错误的量（销售额的份额）；彩虹色标没有感知中点且对色觉缺陷失效；面积甚至无法表示负值，而且解码不准确。
:::
:::

::: history
格式塔原则由韦特海默（Wertheimer）于 1923 年提出。Jacques Bertin 的 *Sémiologie graphique*（1967）给出了第一个关于视觉变量——位置、大小、明度、纹理、颜色、朝向与形状——的系统理论；爱德华·塔夫特（Edward Tufte）的 *The Visual Display of Quantitative Information*（1983）让数据墨水、图表垃圾与谎言因子广为人知。Cleveland 与 McGill 的图形知觉实验随后于 1984 年发表，Mackinlay 的自动呈现于 1986 年。颜色方面，CIE 1931 标准观察者使颜色可以测量，sRGB 标准（IEC 61966-2-1，1999）固定了 Web 的色彩空间，WCAG 2.0（2008）引入了至今仍在 WCAG 2.2（2023）中使用的对比度。Viénot、Brettel 与 Mollon 1999 年的算法以及 Machado、Oliveira 与 Fernandes 2009 年的模型使色觉模拟成为常规操作，而 viridis（2015）把感知均匀的色标带进了科学软件的默认设置。
:::

## 后续内容

对比度、颜色与文字缩放是法律要求，与 WCAG 2.2 的其余部分一起在 [[hci/accessibility-ethics]] 中讨论。一个版式或一张图表是否真的对读者有效，要由 [[hci/usability-evaluation]] 与 [[hci/experiments]] 来定夺——Cleveland 与 McGill 的排序本身就出自一项受控实验。sRGB、gamma 与色彩空间背后的物理学与色度学在 [[graphics/images-colour]] 中展开。

::: summary
- 版式靠**格式塔分组**起作用（[[#def-gestalt]]）：邻近性与公共区域让结构可见；层次用大小、字重、对比与空间，每屏只有一处主要强调。
- 连续文本适中的行长（约 45–75 个字符）与宽松的间距是工艺惯例；要让用户能缩放与调整文字间距。
- **CSS 像素**是一个近似的角度单位（[[#def-css-px]]），所以以 `px` 标注的大小在各自通常观看距离下的不同设备之间可以比较。
- **相对亮度**（[[#def-luminance]]）解码 gamma 编码的 sRGB，且绿色权重最大；WCAG **对比度** $(L_1 + 0.05)/(L_2 + 0.05)$（[[#def-contrast]]）对 AA 级文本至少要是 4.5；它的取值范围是 1 到 21，而黑或白总能达到 $\sqrt{21}$（[[#prop-contrast-range]]）。
- 约 8% 的北欧裔男性有红–绿**色觉缺陷**（CVD）；要模拟它（[[#ex-cvd]]），并且绝不单靠颜色承载含义。
- 用**共同刻度上的位置**编码最重要的量；避开面积、角度与截断的条形（[[#def-lie-factor]]）；用顺序、发散或分类色标匹配数据，并用感知均匀的色标取代彩虹。
:::

## 习题

::: exercise 白底黑字的对比度 {level=1 check="21"}
白底上黑色文字的对比度是多少？（把比值以数字输入。）
::: solution
$L_1 = 1$，$L_2 = 0$：$CR = 1.05/0.05 = 21$（[[#prop-contrast-range]]）。
:::
:::

::: exercise 灰色的亮度
为什么灰度 `#808080`（级别 128，0–255 区间的一半）的相对亮度只有约 0.216 而不是 0.5？算出来。
::: solution
8 位值是 gamma 编码的。线性化后，$128/255 \approx 0.50196$，而 $((0.50196 + 0.055)/1.055)^{2.4} \approx 0.2159$，对灰色 $L$ 就等于这个值，因为 [[#eq-luminance]] 中的权重之和为 1。编码把 256 级中更多的份额分给暗调——视觉在那里对差别更敏感——所以正中间的码值远暗于白色光强的一半。
:::
:::

::: exercise 谎言因子 {level=1 check="20"}
一张图用起点设在 950 万英镑坐标轴上的条形显示收入从 1000 万英镑升到 1200 万英镑。它的谎言因子是多少？（输入数字。）
::: solution
数据效应：$(12 - 10)/10 = 0.2$。条形长度：$10 - 9.5 = 0.5$ 与 $12 - 9.5 = 2.5$，效应 $(2.5 - 0.5)/0.5 = 4$。谎言因子是 $4/0.2 = 20$（[[#def-lie-factor]]）：20% 的增长被画成了五倍。
:::
:::

::: exercise 通过的最浅灰色 {level=2 check="118"}
用 [[#def-contrast]]，找出相对白色对比度至少为 4.5 的最大 8 位灰度级 $g$（即颜色为 `#gggggg`）。（把 $g$ 以十进制数输入。）
::: solution
需要 $1.05/(L + 0.05) \ge 4.5$，即 $L \le 1.05/4.5 - 0.05 \approx 0.18333$。反解线性化，$c_{\text{sRGB}} = 1.055\,L^{1/2.4} - 0.055 \approx 1.055 \times 0.4935 - 0.055 \approx 0.4657$，故 $g \le 0.4657 \times 255 \approx 118.7$。最大整数是 $g = 118$（`#767676`，比值 4.542）；$g = 119$ 时为 4.478，如 [[#ex-contrast]] 中所计算。
:::
:::

::: exercise 自动选取文字颜色
一个打标签的应用让用户为标签任选背景颜色，并必须自动在黑或白的文字中作出选择。写出这条规则，证明它总能给出至少 $\sqrt{21} \approx 4.58$ 的对比度，并把它用于 `#0066CC` 与 `#FFB000`。
::: solution
规则：计算背景的 $L$；若 $L < 0.1791$（更准确地说，若 $1.05/(L + 0.05) \ge (L + 0.05)/0.05$）就用白色文字，否则用黑色。由 [[#prop-contrast-range]]，两个候选比值之积为 21，故较大者至少为 $\sqrt{21}$，而规则恰取较大者。对 `#0066CC`，$L \approx 0.1386 < 0.1791$：白色文字，比值 $\approx 5.57$（[[#ex-contrast]]）。对 `#FFB000`：各通道为 $1$、$\approx 0.4342$（对应 $176/255$）、$0$，故 $L \approx 0.2126 + 0.7152 \times 0.4342 \approx 0.523$；黑色文字，比值 $(0.523 + 0.05)/0.05 \approx 11.5$。凭肉眼判断"颜色亮不亮"、或用 $R, G, B$ 的无权平均的规则会算错，例如遇到饱和的蓝色或黄色时。
:::
:::

::: exercise 选择图表编码
对每项任务，选择一种编码，并用 Cleveland 与 McGill 的排序或 Mackinlay 的准则说明理由：(a) 精确比较三家公司的市场份额；(b) 在世界地图上显示 200 个国家的人口；(c) 显示 1880 年以来每年的气温距平（相对 1951–1980 平均值的差）；(d) 显示 50 个项目各属于六个部门中的哪一个。
::: solution
(a) 共同刻度上的条形图或点图——位置最准确；饼图只在回答"份额大约多少"、且扇区极少时才可接受。(b) 分级统计地图（choropleth）给*区域*上色，面积大而人口稀的国家会在视觉上占据主导；比例符号地图（在国家上画圆）或变形地图（cartogram）更忠实地编码人口，地图旁配一张排序条形图可支持精确比较。(c) 从零距平出发的折线图或条形图，配上以零为中心的**发散**色标（下方蓝、上方红）——数据有有意义的中点。(d) 六种亮度相近的分类色相，配上图例并优先直接标注；颜色渐变会虚假地暗示次序（Mackinlay 的表达性），而冗余的形状或位置能帮助色觉缺陷的读者。
:::
:::

::: exercise 亮度单调
顺序色标的亮度应当单调递增（或递减）。写一个函数，接受一组十六进制颜色并报告它们的相对亮度是否单调，并把它用于七步彩虹 `#FF0000, #FF7F00, #FFFF00, #00FF00, #0000FF, #4B0082, #8F00FF` 与七步蓝色标 `#F7FBFF, #DEEBF7, #C6DBEF, #9ECAE1, #6BAED6, #3182BD, #08519C`。
::: solution
```python
def channel(c8):
    c = c8 / 255
    return c / 12.92 if c <= 0.04045 else ((c + 0.055) / 1.055) ** 2.4

def luminance(h):
    r, g, b = (int(h[i:i + 2], 16) for i in (1, 3, 5))
    return 0.2126 * channel(r) + 0.7152 * channel(g) + 0.0722 * channel(b)

def monotone(colours):
    ls = [luminance(c) for c in colours]
    up = all(a <= b for a, b in zip(ls, ls[1:]))
    down = all(a >= b for a, b in zip(ls, ls[1:]))
    return [round(l, 3) for l in ls], up or down

rainbow = ["#FF0000", "#FF7F00", "#FFFF00", "#00FF00", "#0000FF", "#4B0082", "#8F00FF"]
blues = ["#F7FBFF", "#DEEBF7", "#C6DBEF", "#9ECAE1", "#6BAED6", "#3182BD", "#08519C"]
print(monotone(rainbow))
print(monotone(blues))
```

```console
$ python3 monotone.py
([0.213, 0.364, 0.928, 0.715, 0.072, 0.031, 0.131], False)
([0.96, 0.817, 0.689, 0.549, 0.383, 0.203, 0.083], True)
```

彩虹的亮度从 0.36（橙）跳到 0.93（黄），跌到 0.07（蓝），在紫端又升起来：读者会把黄色与绿色处的亮带看成数据的特征。蓝色标的亮度稳定递减，所以越浅就总是越小。亮度单调是感知均匀的必要条件而非充分条件——相等的步长还应当*看起来*相等，这需要一个感知色彩空间，如设计 viridis 时所用的 CIELAB 或 CAM02-UCS。
:::
:::

::: exercise 证明 CVD 矩阵保持灰色
证明：线性 RGB 上的线性映射 $x \mapsto Mx$ 使每个灰色 $(t, t, t)$ 保持不变，当且仅当 $M$ 的每一行之和为 1，并对 [[#ex-cvd]] 的绿色盲矩阵作检验。为什么这对色觉模拟是合理的性质？它是否意味着模拟后的颜色与原色有相同的相对亮度？
::: solution
$M(t, t, t)\T = t\,(r_1, r_2, r_3)\T$，其中 $r_i$ 是第 $i$ 行之和。它对一切 $t$ 等于 $(t, t, t)\T$ 当且仅当 $r_1 = r_2 = r_3 = 1$。对绿色盲矩阵：$0.367322 + 0.860646 - 0.227968 = 1.000000$，$0.280085 + 0.672501 + 0.047413 = 0.999999$，$-0.011820 + 0.042940 + 0.968881 = 1.000001$——在发表时的舍入误差内等于 1。它之所以合理，是因为二色觉者对消色轴的知觉是正常的：白、灰、黑都不变，这也正是模拟图像能与原图比较的原因。它并*不*意味着其他颜色的亮度被保持：$L(Mx) = w\T M x$，其中 $w = (0.2126, 0.7152, 0.0722)$，它对所有 $x$ 等于 $w\T x$ 仅当 $w\T M = w\T$——这是一个关于*列*而非行的条件。例如，[[#ex-cvd]] 中的模拟会让红色对红色盲变暗（`#D62728` → `#615725`），而红色盲者事实上正是把红色知觉得更暗。
:::
:::
