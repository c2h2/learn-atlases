海湾战争期间的 1991 年 2 月 25 日，驻达兰（Dhahran）的一处爱国者（Patriot）导弹阵地未能拦截一枚来袭的飞毛腿（Scud）导弹，后者击中一栋营房，造成 28 名士兵死亡。美国审计总署（General Accounting Office）把这次失效归结为算术问题。该系统以十分之一秒为单位计时，再把计数乘以 $0.1$ 换算成秒，而这个 $0.1$ 保存在一个 24 位定点寄存器中。但 $0.1$ 没有有限的二进制展开，寄存器里的值因此约偏小 $9.5 \times 10^{-8}$。该阵地开机运行约 100 小时——$3.6$ 百万个十分之一秒——之后，累积误差约达 $0.34$ 秒，足以让一个以超过 1,600 m/s 运动的目标的预测位置偏差半公里以上。

用固定数目的位表示实数必然带来近似，而近似会产生程序员必须能够预见的后果。[[programming-1/values-types]] 见过症状：`0.1 + 0.2` 不等于 `0.3`。本章解释病因。我们逐位定义 IEEE 754 浮点格式，包括特殊值（零、无穷、NaN）与非规格化数的渐进下溢；陈述并证明正确舍入算术的基本误差界；再用它来理解种种陷阱——不满足结合律、消除、误差积累、类型转换——以及如何避开它们。

除非另有说明，C 代码均在 x86-64 Linux 上用 GCC 15.2 以 `gcc -std=c17 -Wall -Wextra`（用到 `<math.h>` 处再加 `-lm`）在不优化的情况下编译；在 x86-64 上，`float` 与 `double` 算术由 SSE 单元严格按照 IEEE 单精度与双精度格式执行。数值都用 Python 3.14 核验过。

## 二进制小数与定点

进位记数制可以延伸到二进制点的右边。二进制数 $b_m \ldots b_1 b_0 . b_{-1} b_{-2} \ldots b_{-n}$ 表示

$$
\sum_{i=-n}^{m} b_i \, 2^{i},
$$

所以 $101.11_2 = 4 + 1 + \tfrac12 + \tfrac14 = 5.75$，而 $0.0011_2 = \tfrac{3}{16}$。二进制点左移一位相当于除以二，正如小数点左移相当于除以十。有限的二进制小数总等于 $m/2^k$，其中 $m$ 与 $k$ 为整数；正如 [[programming-1/values-types]] 证明过的，$\tfrac{1}{10}$ 这样的数不属于这种形式，它的二进制展开 $0.000110011001100\ldots_2$ 永远循环下去。

**定点**表示把二进制小数的小数点两边各存固定数目的位——实际上就是一个按常数 $2^{-k}$ 缩放的整数。定点很简单，对求和还是精确的，至今仍在信号处理与货币计算（以整数分计）中使用，但它覆盖的范围很窄：32 位、16 个小数位时，大于 $32768$ 的数和 $0$ 与 $2^{-16}$ 之间的数都表示不了。科学计算却需要在同一个程序里表示从原子到星系那样跨度极大的数。解决办法，就像科学计数法 $6.022 \times 10^{23}$ 那样，让小数点*浮动*：把有效数字和指数分开存储。

## IEEE 754 格式

::: definition IEEE 754 二进制格式 {#def-ieee}
一个有 $k$ 个指数位和 $f$ 个尾数位的二进制浮点格式，用 $1 + k + f$ 个位、按三个字段存储一个数：**符号**位 $s$、**指数域** $E$（按 $k$ 位无符号整数读）和**尾数域** $M = 0.m_1m_2\ldots m_f$（按二进制小数读）。设**偏移量**为 $B = 2^{k-1} - 1$。其值为

- **规格化数**，当 $0 < E < 2^k - 1$：$\;(-1)^s \times 1.m_1\ldots m_f \times 2^{E - B}$；
- **非规格化数**（亦称 denormalised，非正规数）：当 $E = 0$：$\;(-1)^s \times 0.m_1\ldots m_f \times 2^{1 - B}$；
- **特殊值**，当 $E = 2^k - 1$（全 $1$）：若 $M = 0$ 则为 $(-1)^s \infty$，否则为 **NaN**（"not a number"，非数）。

把隐含的前导位计算在内，有效位的个数称为**精度** $p = f + 1$。
:::

定义中的每一部分都有道理。规格化数在二进制点前有一个前导 $1$，而它永远是 $1$，所以不必存储——**隐含前导位**白赚了一个有效位。指数按偏移量而不是补码存储，是为了（我们下面将证明）正浮点数的位模式比较顺序与数值本身的大小顺序一致。非规格化数填补零与最小规格化数之间的空隙，特殊值则让每个运算都能返回*某个东西*：$1/0$ 是 $+\infty$ 而不是崩溃，$0/0$ 是一个 NaN，它会在后续运算中一路传播。

C 的 `float` 与 `double` 使用的两种格式是：

| 格式 | C 类型 | 位数 | $k$ | $f$ | $p$ | 偏移量 | 最大有限值 | 最小规格化数 | 最小非规格化数 | $\varepsilon = 2^{1-p}$ |
|---|---|---|---|---|---|---|---|---|---|---|
| binary32（单精度） | `float` | 32 | 8 | 23 | 24 | 127 | $\approx 3.40 \times 10^{38}$ | $2^{-126} \approx 1.18 \times 10^{-38}$ | $2^{-149} \approx 1.40 \times 10^{-45}$ | $2^{-23} \approx 1.19 \times 10^{-7}$ |
| binary64（双精度） | `double` | 64 | 11 | 52 | 53 | 1023 | $\approx 1.80 \times 10^{308}$ | $2^{-1022} \approx 2.23 \times 10^{-308}$ | $2^{-1074} \approx 4.94 \times 10^{-324}$ | $2^{-52} \approx 2.22 \times 10^{-16}$ |

这里的 $\varepsilon$ 是**机器 epsilon**，即从 $1$ 到下一个更大的可表示数的距离。标准的 2008 年修订版还定义了 binary16（"半精度"，5 个指数位、10 个尾数位）与 binary128，以及十进制格式；截至 2026 年，机器学习硬件还广泛使用非 IEEE 的 bfloat16（8 个指数位、7 个尾数位）。

把 `float` 的位复制进一个 `uint32_t`，就能检查它的各个字段（用 `memcpy` 复制是良定义的做法；通过 `int *` 读取 `float` 违反 C 的别名规则）：

```c
#include <stdio.h>
#include <stdint.h>
#include <string.h>

/* 打印一个 float 的符号、指数与尾数字段。 */
static void fields(float f) {
    uint32_t u;
    memcpy(&u, &f, sizeof u);           /* 复制位：没有未定义行为 */
    unsigned sign = u >> 31;
    unsigned exp  = (u >> 23) & 0xff;
    unsigned frac = u & 0x7fffff;
    printf("%-14g 0x%08x  s=%u e=%3u f=0x%06x\n", f, u, sign, exp, frac);
}

int main(void) {
    fields(1.0f);
    fields(-0.75f);
    fields(0.1f);
    fields(3.0e38f * 10.0f);            /* 溢出为 +infinity */
    fields(1.0e-45f);                   /* 最小的正非规格化数 */
    fields(0.0f / 0.0f);                /* 不是数 */
    return 0;
}
```

```console
$ gcc -std=c17 -Wall -Wextra -o fbits fbits.c && ./fbits

-0.75          0xbf400000  s=1 e=126 f=0x400000
0.1            0x3dcccccd  s=0 e=123 f=0x4ccccd
inf            0x7f800000  s=0 e=255 f=0x000000
1.4013e-45     0x00000001  s=0 e=  0 f=0x000001
-nan           0xffc00000  s=1 e=255 f=0x400000
```

把各行对照 [[#def-ieee]] 来读。$1.0 = 1.0 \times 2^0$，所以 $E = 0 + 127 = 127$，尾数为零。$-0.75 = -1.1_2 \times 2^{-1}$：符号 $1$，$E = 126$，尾数 $.1_2$，其最高位是 $2^{22}$ 位，即 `0x400000`。$0.1$ 的位模式有 $E = 123$，所以 $0.1 \approx 1.6 \times 2^{-4}$；尾数 `0x4ccccd` 是循环模式 $1100\,1100\ldots$ 被截断后最后一位向*上*舍入的结果（是 `d` 而不是 `c`），所以存下来的 `float` 比 $0.1$ 略大；它恰好等于 $13421773/2^{27} = 0.100000001490116\ldots$。SSE 单元为 $0/0$ 产生的安静 NaN 置了符号位，这就是它打印成 `-nan` 的原因；NaN 的符号不携带任何含义。

求 $-6.25$ 的 `float` 位模式，用十六进制表示。
::: solution
$6.25 = 110.01_2 = 1.1001_2 \times 2^2$。于是 $s = 1$，指数为 $2$，存成 $E = 2 + 127 = 129 = 1000\,0001_2$，尾数域是 $1001$ 后跟十九个 $0$。把符号、指数、尾数拼接起来：

$$
1 \;|\; 1000\,0001 \;|\; 1001\,0000\,0000\,0000\,0000\,000 ,
$$

再从左侧起每 4 位一组重新分组：$1100\,0000\,1100\,1000\,0000\ldots = $ `0xc0c80000`。Python 证实：`struct.pack('>f', -6.25).hex()` 是 `'c0c80000'`。
:::
:::

### 一个玩具格式

真实格式的取值太多，无法一一列出。要看清全部结构，可取一个 8 位格式，$k = 4$ 个指数位、$f = 3$ 个尾数位（精度 $p = 4$，偏移量 $7$）。于是：

| 描述 | 位 $s\,E\,M$ | $E$ | 值 |
|---|---|---|---|
| 零 | 0 0000 000 | 0 | $0$ |
| 最小非规格化数 | 0 0000 001 | 0 | $\tfrac18 \times 2^{-6} = \tfrac{1}{512}$ |
| 最大非规格化数 | 0 0000 111 | 0 | $\tfrac78 \times 2^{-6} = \tfrac{7}{512}$ |
| 最小规格化数 | 0 0001 000 | 1 | $1 \times 2^{-6} = \tfrac{1}{64} = \tfrac{8}{512}$ |
| 一 | 0 0111 000 | 7 | $1$ |
| 一之后的数 | 0 0111 001 | 7 | $\tfrac98$ |
| 最大规格化数 | 0 1110 111 | 14 | $\tfrac{15}{8} \times 2^{7} = 240$ |
| 无穷 | 0 1111 000 | 15 | $+\infty$ |
| NaN | 0 1111 $\ne 000$ | 15 | NaN |

注意底端过渡是平滑的：最大非规格化数是 $7/512$，最小规格化数是 $8/512$，恰好在下一步。这就是非规格化数使用指数 $1 - B$ 而不是 $0 - B$ 的原因。若非如此，从 $0$ 到 $1/64$ 之间就会出现一个空隙，其宽度是紧邻其上方间隔的六十四倍，而且不同的 $x$ 与 $y$ 可能有 $x - y$ 为零；有了非规格化数，$x - y = 0$ 就意味着 $x = y$。这个性质称为**渐进下溢**。

::: widget floatline
p: 4
emin: -6
emax: 7
value: 19
caption: 8 位玩具格式（$p = 4$，指数 $-6$ 到 $7$）的全部非负取值。打开对数刻度，可以看到全部十四个二进位区间（binade）：每个 2 的幂区间内八个取值等距排列，而从一个区间到下一个区间间隔加倍。非规格化数（开关它试试）以与第一个二进位区间相同的间隔，填满紧邻零的区域。数值 $19$ 恰在 $18$ 与 $20$ 的正中间；看它舍入到 $20$，其有效数字 $1.010_2$ 以 $0$ 结尾。$248$ 及以上的数（比最大有限值 $240$ 高出半个间隔）溢出为 $\infty$。
:::

## 顺序、间隔与舍入

由格式的排布可推出两条有用的性质。

::: theorem 位模式与数值同序 {#thm-order}
对 IEEE 二进制格式中的非负浮点数 $x$ 与 $y$（包括 $+0$ 与 $+\infty$，不包括 NaN），$x < y$ 当且仅当把 $x$ 的位模式按无符号整数读小于 $y$ 的位模式。
:::

::: proof
非负数的符号位为 $0$，所以位模式的无符号值为 $U = E \cdot 2^f + m$，其中 $m = 2^f M$ 是把尾数域按整数来读的结果，$0 \le m < 2^f$。比较字段为 $(E, m)$ 与 $(E', m')$ 的两个数。若 $E = E'$，两个数都等于 $c\cdot(\text{前导位} + m/2^f)$，其中 $c$ 是同一个正常数，所以 $m$ 大的数更大，它的 $U$ 也大。若 $E < E'$，则由 $m < 2^f \le 2^f(E' - E)$ 得 $U < U'$。还须说明这个数确实也更小。指数域为 $E$ 的每个数都小于 $2^{E - B + 1}$（有效数字小于 $2$；当 $E = 0$ 时小于 $1 \times 2^{1-B}$），而指数域为 $E' \ge 1$ 的每个数都至少是 $2^{E' - B} \ge 2^{E - B + 1}$。无穷有最大的指数域和为零的尾数域，大于一切有限数。所以两种顺序一致。
:::

这正是指数要加偏移量的原因：比较、排序、查找非负浮点数都可以用整数指令完成。（负数按相反顺序排列，因为这种表示是原码带符号位的；一个标准技巧是先把它们的位取反。）

在相邻的 2 的幂之间，间隔是均匀的。在**二进位区间**（binade）$[2^e, 2^{e+1})$ 内，可表示的数是 $(1 + j\,2^{-f}) \times 2^e$，其中 $j = 0, 1, \ldots, 2^f - 1$，所以相邻两数的间隔——**末位单位**（unit in the last place，$\operatorname{ulp}$）——为 $2^{e - f} = 2^{e - p + 1}$。间隔与数的大小成正比：浮点数大致保持恒定的*相对*精度。单精度下，直到 $2^{24} = 16\,777\,216$ 的整数都能精确表示，但在二进位区间 $[2^{24}, 2^{25})$ 中间隔为 $2$，所以 $16\,777\,217$ 不是一个 `float`。

### 舍入

绝大多数实数位于两个可表示数之间，标准规定了该选哪一个。默认的**舍入模式**是**就近舍入，平局取偶**（round to nearest, ties to even）：除非程序另行要求，一律使用这一模式——选取最近的可表示数；若实数恰在正中间，就选有效数字最后一位为 $0$ 的那一个。标准还提供向 $+\infty$、向 $-\infty$ 和向零舍入，用于区间算术和转换为整数时。

为什么是平局取偶，而不是像小学里那样"半值上入"？若中间情形总向上舍入，这样一批数连加之后平均会向上漂移。向偶数舍入一半时候上、一半时候下，偏走在总体上相互抵消。

::: example 在玩具格式中舍入 {#ex-round}
把 $5.5$、$0.3$、$19$ 与 $100$ 舍入到 8 位玩具格式，并给出各自的相对误差。
::: solution
**$5.5$** $= 101.1_2 = 1.011_2 \times 2^2$ 只用四个有效位，可以精确表示：$E = 2 + 7 = 9 = 1001_2$，尾数 $011$，位模式 $0\,1001\,011$ = `0x4b`。误差 $0$。

**$0.3$** $= 1.0011\,0011\ldots_2 \times 2^{-2}$。在二进位区间 $[\tfrac14, \tfrac12)$ 内间隔为 $2^{-2-3} = \tfrac{1}{32}$，所以候选者是 $\tfrac{9}{32} = 0.28125$ 与 $\tfrac{10}{32} = 0.3125$。由于 $0.3 \times 32 = 9.6$，较近的是 $\tfrac{10}{32}$。相对误差 $\abs{0.3125 - 0.3}/0.3 \approx 0.0417$。

**$19$** $= 10011_2 = 1.0011_2 \times 2^4$ 有五个有效位。在 $[16, 32)$ 内间隔为 $2^{4-3} = 2$；邻居是 $18 = 1.001_2 \times 2^4$ 与 $20 = 1.010_2 \times 2^4$，而 $19$ 恰在正中间。平局归有效数字为偶的那个，即 $1.010_2$，所以 $19 \mapsto 20$。相对误差 $1/19 \approx 0.0526$。

**$100$** $= 1.1001_2 \times 2^6$。在 $[64, 128)$ 内间隔为 $8$，邻居是 $96 = 1.100_2 \times 2^6$ 与 $104 = 1.101_2 \times 2^6$。又是一个平局；偶者是 $96$。相对误差 $0.04$。

三个相对误差都低于 $2^{-p} = \tfrac{1}{16} = 0.0625$，正如下一条定理所保证的。
:::
:::

::: theorem 舍入的相对误差 {#thm-rel-error}
记 $\operatorname{fl}(x)$ 为 $x$ 在精度为 $p$ 的二进制格式下的就近舍入结果，并设实数 $x$ 的绝对值落在规格化范围内（介于最小规格化数与最大有限数之间）。则

$$
\operatorname{fl}(x) = x(1 + \delta) \quad\text{其中}\quad \abs{\delta} \le u = 2^{-p} = \tfrac{\varepsilon}{2} .
$$ {#eq-fl}

这个 $u$ 称为**单位舍入误差**：`float` 为 $2^{-24} \approx 5.96 \times 10^{-8}$，`double` 为 $2^{-53} \approx 1.11 \times 10^{-16}$。
:::

::: proof
不妨设 $x > 0$。取 $e$ 使 $2^e \le x < 2^{e+1}$。这个二进位区间内的可表示数间隔为 $2^{e-p+1}$，且 $2^{e+1}$ 本身可表示（或者，在范围的最高端，由假设 $x$ 距最大有限数不超过半个间隔），于是 $x$ 位于距离为 $2^{e-p+1}$ 的两个可表示邻居之间。其中较近者距 $x$ 不超过半个间隔：$\abs{\operatorname{fl}(x) - x} \le 2^{e-p}$。两边除以 $x \ge 2^e$，得 $\abs{\delta} = \abs{\operatorname{fl}(x) - x}/x \le 2^{e-p}/2^e = 2^{-p}$。
:::

在非规格化范围内，*绝对*误差仍不超过非规格化间隔的一半，但相对误差可能很大：靠近范围底部的非规格化数只有一两个有效位。

## 浮点算术

IEEE 754 的核心是一条规则。

::: definition 正确舍入的运算 {#def-correct-rounding}
IEEE 754 要求加、减、乘、除、开平方与融合乘加都是**正确舍入**的：$x \circledast y$ 的结果必须是精确数学结果按当前舍入模式舍入的值，$x \circledast y = \operatorname{fl}(x \ast y)$。溢出产生 $\pm\infty$（在就近舍入下），而 $0/0$、$\infty - \infty$、$\sqrt{-1}$ 一类的非法运算产生 NaN。
:::

结合 [[#thm-rel-error]]，每个单独的运算的相对误差至多为 $u$（当结果落在规格化范围内时）：$x \oplus y = (x + y)(1 + \delta)$，其中 $\abs{\delta} \le u$。这已经是可能的最好保证——但这也正是浮点算术与实数算术*不同*的原因。每个运算都精确，可熟悉的代数律失效了：

- 加法与乘法满足交换律（$x \oplus y = y \oplus x$），因为精确结果相等。
- 它们**不满足结合律**。设 `double a = 1e16, b = -1e16, c = 1.0`，则 `(a + b) + c` 是 $1$，而 `a + (b + c)` 是 $0$：$b + c = -10^{16} + 1$ 舍入后又回到 $-10^{16}$，因为 $10^{16}$ 附近 `double` 的间隔是 $2$。
- 乘法对加法不满足分配律，$x \otimes (1/x)$ 也未必恰好是 $1$。
- 对 NaN 而言 $x = x$ 不成立：除 `!=`（恒为真）之外，一切涉及 NaN 的比较都为假。（`x != x` 是检测 NaN 的经典写法；`isnan(x)` 说得更清楚。）

```c
double nan = 0.0 / 0.0;
printf("nan == nan: %d, nan != nan: %d\n", nan == nan, nan != nan);   /* 0, 1 */
printf("%.17g\n", 0.1 + 0.2);                                         /* 0.30000000000000004 */
```

不满足结合律有一个直接的实践后果：编译器不得重排浮点运算，所以除非你允许（`-ffast-math` 或 `-fassociative-math`），C 编译器不能把 `for (...) s += a[i];` 这样的求和向量化为同时维护四个部分和。这些开关允许*改变数值*的优化，而 `-ffast-math` 还额外假定 NaN 与无穷绝不会出现；只有在确认结果仍然可以接受的地方才应使用它们。

- [x] 若 `x - y == 0` 则 `x == y`
::: solution
交换律成立，因为两边都是同一个实数 $x + y$ 的正确舍入值。乘 $1$ 是精确的。结合律不成立（那个 $10^{16}$ 的例子）；除以 $10$ 再乘 $10$ 要舍入两次——对某些小整数碰巧能还原，但 `0.11 / 10.0 * 10.0` 是 `0.10999999999999999`。最后一条成立恰恰是*因为有非规格化数*（渐进下溢）：两个不同 `double` 的精确差是最小非规格化数的整数倍，因此或者可表示，或者至少与该非规格化数一样大，绝不会舍入为零。若非如此，这条就可能失效。
:::
:::

### 消除与误差积累

[[#thm-rel-error]] 给出的是一次运算的误差相对于*其自身结果*的界。当结果被组合起来时，麻烦就开始了。两个相近的数相减是精确的——这是一条定理：

::: lemma 斯特本茨（Sterbenz） {#lem-sterbenz}
若 $x$ 与 $y$ 是同一二进制格式中的浮点数且 $y/2 \le x \le 2y$，则 $x - y$ 可精确表示，于是 $x \ominus y = x - y$。
:::

::: proof
不妨设 $0 < y \le x \le 2y$（$x < y$ 的情形对称，且由假设 $x, y$ 同号）。设 $2^e$ 为 $y$ 的间隔（$\operatorname{ulp}$）；那么 $x$ 的指数不小于 $y$ 的指数，因而 $x$ 也是 $2^e$ 的整数倍，$x - y$ 亦然。由于 $0 \le x - y \le y$，这个差是不超过 $y$ 的 $2^e$ 的倍数。$[0, y]$ 内 $2^e$ 的每个倍数都可表示：把它写成 $j\,2^e$，其中 $0 \le j \le y/2^e < 2^p$，这是一个至多 $p$ 位的整数乘以 2 的幂，而该幂至少不低于最小非规格化数的指数。于是 $x - y$ 可表示，正确舍入的结果就是精确的。
:::

所以减法本身不引入误差——但它会把 $x$ 与 $y$ 中*早已存在*的误差暴露出来。若 $x$ 与 $y$ 各带有 $10^{-16}$ 的相对误差、前十二位数字都相同，它们的差就只剩四位可靠数字。这就是**灾难性消除**。

::: example $1 - \cos x$ 中的消除 {#ex-cancel}
在双精度下计算 $f(x) = (1 - \cos x)/x^2$ 在 $x = 10^{-8}$ 处的值。真值非常接近 $\tfrac12$（因为 $1 - \cos x \approx x^2/2$）。解释哪里出了问题，并加改正。
::: solution
```c
#include <stdio.h>
#include <math.h>

int main(void) {
    double x = 1e-8;
    double naive  = (1.0 - cos(x)) / (x * x);
    double s      = sin(x / 2);
    double stable = 2.0 * s * s / (x * x);   /* 1 - cos x = 2 sin^2(x/2) */
    printf("naive  = %.17g\n", naive);
    printf("stable = %.17g\n", stable);
    return 0;
}
```

```console
$ gcc -std=c17 -Wall -Wextra -o cancel cancel.c -lm && ./cancel
naive  = 0
stable = 0.5
```

$\cos(10^{-8}) = 1 - 5 \times 10^{-17} + \cdots$。$1$ 之下紧邻的 `double` 间隔为 $2^{-53} \approx 1.1 \times 10^{-16}$，所以正确舍入的余弦值恰好是 $1.0$，于是相减（由 [[#lem-sterbenz]] 是精确的）得 $0$。一切信息都丢失在 $\cos x$ 的舍入中，*在减法之前*。恒等式 $1 - \cos x = 2\sin^2(x/2)$ 计算同一个量而不必相减两个相近数；其中每个运算的相对误差都很小，结果具有满精度。改写公式以避免消除，是数值上谨慎的代码的主要工具；`<math.h>` 中另两个标准例子是求 $\ln(1 + x)$ 的 `log1p(x)` 与求 $e^x - 1$ 的 `expm1(x)`。
:::
:::

误差在长计算中也会积累。把 $n$ 个数从左到右相加，误差可能按 $nu$ 乘以各数绝对值之和的比例增长；把小数字加到一个已经很大的累计和上，一旦它们小于总和半个 ulp，就会被完全丢掉。

::: example 两种顺序求级数之和 {#ex-harmonic}
用 `float` 分别按正向与反向求 $\sum_{k=1}^{10^7} 1/k$，并与 `double` 求和的结果比较。
::: solution
```c
#include <stdio.h>

int main(void) {
    const int n = 10000000;
    float up = 0.0f, down = 0.0f;
    for (int k = 1; k <= n; k++) up += 1.0f / k;      /* 先加最大的项 */
    for (int k = n; k >= 1; k--) down += 1.0f / k;    /* 先加最小的项 */
    double exact = 0.0;
    for (int k = n; k >= 1; k--) exact += 1.0 / k;
    printf("float, forwards : %.7f\n", up);
    printf("float, backwards: %.7f\n", down);
    printf("double          : %.7f\n", exact);
    return 0;
}
```

```console
$ gcc -std=c17 -Wall -Wextra -o harmonic harmonic.c && ./harmonic
float, forwards : 15.4036827
float, backwards: 16.6860313
double          : 16.6953114
```

真值是 $16.695311\ldots$（`double` 求和与 Python 精确舍入的 `math.fsum` 在所显示的全部位数上一致）。正向相加时，`float` 的总和远未到终点就停止增长：一旦达到约 $15.4$，其 ulp 就是 $2^{3-23} \approx 9.5 \times 10^{-7}$，其后每个项 $1/k < 4.8 \times 10^{-7}$ 都不足半个 ulp，于是 `up + 1.0f/k` 又舍入回 `up`。数以百万计的项就这样被白白丢弃。反向相加时，小的项先彼此相加，此时总和还小、ulp 还很细；结果的第五位有效数字上误差约在三个单位以内。更好的做法是**补偿求和**（卡汉（Kahan）算法，[[#ex-kahan]]）、配对求和（NumPy 采用），或使用更宽的累加器。
:::
:::

::: warning 用 `==` 比较浮点数
因为几乎每个结果都经过舍入，对计算得到的浮点数做精确相等判断几乎总是缺陷：`0.1 + 0.2 == 0.3` 为假。应当用与该计算相称的容差来比较，通常取相对容差：`fabs(a - b) <= 1e-12 * fmax(fabs(a), fabs(b))`。但也不要矫枉过正：不存在万能的"epsilon"，$10^{-9}$ 的容差对量级为 $10^{-12}$ 的量毫无意义；而当已知取值精确时（小整数、2 的幂、一个数与它自身的副本比较），精确比较才是正确的。
:::

## C 中的浮点数

在所有主流平台上，C 的 `float` 与 `double` 就是 IEEE binary32 与 binary64（标准的附录 F 描述了与 IEEE 的绑定；x86-64 上的 GCC 是符合的）。`long double` 在 x86-64 Linux 上是 x87 的 80 位扩展格式（$p = 64$），在某些其他平台上则只是一个 `double`；不要依赖它。

转换遵循 [[#def-ieee]] 与舍入的规则：

| 转换 | 行为 |
|---|---|
| `int` → `double` | 精确（每个 32 位整数至多有 32 个有效位 $\le 53$） |
| `int` → `float` | 舍入：`(float) 16777217` 是 `16777216.0f` |
| `long` → `double` | 绝对值超过 $2^{53}$ 时舍入 |
| `float` → `double` | 精确 |
| `double` → `float` | 舍入；可能溢出为 $\pm\infty$，或下溢为非规格化数或零 |
| `double` → `int` | **向零截断**：`(int) 3.9` 是 `3`，`(int) -3.9` 是 `-3`；若结果装不下则为*未定义行为*（x86-64 的 `cvttsd2si` 此时返回 `0x80000000`，但不要依赖这一点） |

最后一行正是阿丽亚娜 5 号出事之处：把一个放不进 16 位整数的值转换为 16 位整数。当你想要的不是截断时，请使用 `<math.h>` 中的 `round`、`floor`、`ceil` 或 `lrint`，并在转换之前检查取值范围。

`<math.h>` 与 `<fenv.h>` 还给出了访问 IEEE 特性的途径：`isnan`、`isinf`、`isfinite`、`nextafter`（相邻的浮点数）、`fma`（融合乘加：只做一次舍入的 $\operatorname{fl}(xy + z)$），以及用于有向舍入的 `fesetround`。融合乘加在 IEEE 754-2008 中标准化，现代 x86-64 与 ARM 处理器已用硬件实现。

::: application 精确地打印与读入浮点数
`printf("%g")` 只显示六位有效数字，会掩盖大部分舍入：`0.1 + 0.2` 打印成 `0.3`。要让打印出的 `double` 读回来恰好是同一个值，请用 `%.17g`（17 位有效数字对 binary64 永远够用；binary32 是 9 位），或者用精确的十六进制格式 `%a`——它把 `0.1` 打印成 `0x1.999999999999ap-4`。自 C99 起，`strtod` 与像 `0x1.8p1`（即 $3.0$）这样的十六进制浮点字面量能把它们精确读回。以文本承载浮点数的数据文件与网络协议应采用这些形式之一。
:::

::: history
康拉德·楚泽（Konrad Zuse）的 Z3（1941）已经使用二进制浮点数。整个 1960 与 1970 年代，每家厂商都有自己的格式和自己的舍入行为——IBM 的 System/360 用十六进制作基数，有些机器甚至会算出 $x \ne y$ 却 $x - y = 0$——所以数值软件不得不为每台机器重写。1976 年，英特尔（Intel）聘请威廉·卡汉（William Kahan）为其 8087 协处理器（1980 年出货）设计算术单元；卡汉、Jerome Coonen 与 Harold Stone 写出的提案成为了 **IEEE 754-1985**。它强制要求正确舍入、渐进下溢、无穷量与 NaN。卡汉获得了 1989 年的图灵奖。标准在 2008 年（加入融合乘加、binary16、binary128 与十进制格式）和 2019 年（澄清与新推荐的运算）两度修订。David Goldberg 的综述 *What Every Computer Scientist Should Know About Floating-Point Arithmetic*（1991）至今仍是经典的入门文献。
:::

## 后续内容

搬运与运算浮点数的指令（`movsd`、`addsd`、`cvttsd2si`）和存放它们的寄存器（`%xmm0`–`%xmm15`）出现在 [[computer-systems/machine-code]] 中。对误差在整个算法中传播的分析——条件数、后向稳定性，以及为什么有些算法可靠而另一些不可靠——属于数值分析（[Maths Atlas：浮点算术](/learn/maths/lesson.php?c=numerical-analysis&l=floating-point)）。浮点数还是 [[graphics]] 的基础，那里的误差积累表现为三角形之间的裂缝；训练语言模型所用的低精度格式亦然（[LLM Atlas](/learn/llm/)）。

::: summary
- 二进制浮点数存符号、加偏移量的指数和尾数：规格化值 $(-1)^s \times 1.M \times 2^{E-B}$ 带隐含的前导 $1$；非规格化数 $0.M \times 2^{1-B}$ 带来**渐进下溢**；全 $1$ 的指数编码 $\pm\infty$ 与 NaN（[[#def-ieee]]）。
- `float` 是 binary32（$p = 24$，$\varepsilon = 2^{-23}$），`double` 是 binary64（$p = 53$，$\varepsilon = 2^{-52}$）。间隔在每个二进位区间内均匀，每到 2 的幂翻一倍；非负浮点数的大小顺序与位模式的顺序一致（[[#thm-order]]）。
- 默认舍入是就近舍入、平局取偶；在规格化范围内 $\operatorname{fl}(x) = x(1+\delta)$，$\abs{\delta} \le 2^{-p}$（[[#thm-rel-error]]），且每个基本运算都正确舍入。
- 浮点加法满足交换律但不满足结合律；NaN 不等于自身；不被告知允许，编译器不会重排浮点算术。
- 相近数相减是精确的（[[#lem-sterbenz]]），但会暴露早先的误差（**消除**）；改写公式、先加小项，或使用补偿求和。
- 绝不用 `==` 比较计算得到的浮点数；绝不用浮点数存钱；把浮点数转换为整数之前要检查范围（截断，溢出时未定义）。
:::

## 习题

::: exercise 解码一个 float {level=1 check="12.375"}
`float` 位模式 `0x41460000` 是哪个数？（输入该值。）
::: solution
写成二进制，`0x41460000` 是 $0100\,0001\,0100\,0110\,0000\ldots$。符号为 $0$；接下来八位是 $1000\,0010 = 130$，所以指数是 $130 - 127 = 3$；尾数域是 $1000\,1100\ldots_2$，所以有效数字为 $1.100011_2 = 1 + \tfrac12 + \tfrac1{32} + \tfrac1{64} = 1.546875$。该值为 $1.546875 \times 8 = 12.375$。
:::
:::

::: exercise 玩具格式计数 {level=1 check="119"}
本章的 8 位玩具格式（$k = 4$、$f = 3$）有多少个正的有限值？（输入数目。）
::: solution
正的有限数符号为 $0$，指数域 $E \in \set{0, \ldots, 14}$，尾数任意，只是 $E = 0$ 且尾数 $000$ 时为要排除的零。共 $15 \times 8 - 1 = 119$ 个值：$7$ 个非规格化数与 $14 \times 8 = 112$ 个规格化数。等价地，它们就是位模式 `0x01` 到 `0x77`，而 $0x77 = 119$。
:::
:::

::: exercise float 之间的间隔 {level=1 check="2^(-13)"}
区间 $[1024, 2048)$ 内相邻 `float` 值的间隔是多少？（输入该间隔。）
::: solution
$1024 = 2^{10}$，所以二进位区间为 $e = 10$，间隔为 $2^{e - p + 1} = 2^{10 - 24 + 1} = 2^{-13} \approx 1.22 \times 10^{-4}$。因此 $1500$ 附近的 `float` 只能分辨约四位小数。这就是在几公里范围内以微米为单位测量坐标时，单精度很危险的原因。
:::
:::

::: exercise 就近向偶数舍入 {level=2 check="10.25"}
用就近舍入平局取偶把下列每个二进制数舍入到二进制点后两位：$10.01011_2$、$10.01100_2$、$10.10100_2$、$10.11101_2$。结果用十进制给出。（输入四个结果之和。）
::: solution
点后两位意味着间隔为 $\tfrac14$；由小数点后第二位之后的数字决定取舍。$10.01|011$：余下的 $0.011_2$ 个间隔小于一半（$0.1_2$），舍入到 $10.01_2 = 2.25$。$10.01|100$：恰好一半；候选是 $10.01$ 与 $10.10$，偶者（末位为 $0$）是 $10.10_2 = 2.5$。$10.10|100$：恰在 $10.10$ 与 $10.11$ 的正中；偶者是 $10.10_2 = 2.5$。$10.11|101$：超过一半，进位到 $11.00_2 = 3$。总和：$2.25 + 2.5 + 2.5 + 3 = 10.25$。
:::
:::

::: exercise 最大奇整数 {level=2 check="2^24 - 1"}
能作为 `float` 精确表示的最大奇整数是多少？给出理由。（输入该值。）
::: solution
满足 $2^{24} \le n < 2^{25}$ 的整数 $n$ 落在间隔为 $2^{24 - 24 + 1} = 2$ 的二进位区间内，所以那里只有偶整数可表示；而更高的二进位区间间隔更大，且至少是 $2$ 的幂。在 $2^{24}$ 以下，每个整数至多有 24 个有效位，都可表示。所以可表示的最大奇整数是 $2^{24} - 1 = 16\,777\,215$，位模式 `0x4b7fffff`。
:::
:::

::: exercise 无消除的二次公式 {level=2}
$x^2 + bx + c = 0$ 的根是 $(-b \pm \sqrt{b^2 - 4c})/2$。当 $b = 10^8$、$c = 1$ 时，小根约为 $-10^{-8}$。解释为什么通常的公式在双精度下把小根算得很糟，并给出一个能把两个根都算准的公式。
::: solution
$b = 10^8$ 时，$b^2 - 4c = 10^{16} - 4$ 是精确算出的，但它的平方根 $10^8\sqrt{1 - 4 \times 10^{-16}} \approx 10^8 - 2 \times 10^{-8}$ 必须舍入为 `double`，而 $10^8$ 附近 `double` 的间隔是 $2^{26-52} \approx 1.49 \times 10^{-8}$：算出的根是 `99999999.999999985`。于是 $-b + \sqrt{\cdots}$ 相减两个相近数，平方根的舍入误差——相对大小 $10^{-16}$——在差中变成约 $25\%$ 的相对误差：在 GCC 15.2 下，该公式给出 $-7.45 \times 10^{-9}$ 而不是 $-1.00 \times 10^{-8}$。补救办法用韦达（Viète）关系 $x_1 x_2 = c$：先无消除地算出大根 $x_1 = (-b - \operatorname{sgn}(b)\sqrt{b^2 - 4c})/2$（其中两项同号），再取 $x_2 = c / x_1$。此处 $x_1 = -10^8$，而 $x_2 = c/x_1$ 打印为 `-1e-08`，具有满精度。
:::
:::

::: exercise 卡汉求和 {#ex-kahan level=3}
在 C 中为一个 `float` 数组实现补偿求和：维护一个累计和 $s$ 与一个修正量 $c$，对每个 $x$ 计算 `y = x - c; t = s + y; c = (t - s) - y; s = t;`。解释 $c$ 保存的是什么，并用 [[#ex-harmonic]] 的正向调和求和来测试它。为什么它不能用 `-ffast-math` 编译？
::: solution
```c
#include <stdio.h>

int main(void) {
    const int n = 10000000;
    float s = 0.0f, c = 0.0f;           /* 和与累计补偿量 */
    for (int k = 1; k <= n; k++) {
        float y = 1.0f / k - c;         /* 用上一轮的误差修正本项 */
        float t = s + y;                /* y 的低位在这里丢失……        */
        c = (t - s) - y;                /* ……又在这里找回（带相反符号）*/
        s = t;
    }
    printf("Kahan, forwards: %.7f\n", s);
    return 0;
}
```

```console
$ gcc -std=c17 -Wall -Wextra -o kahan kahan.c && ./kahan
Kahan, forwards: 16.6953106
```

当 $s$ 大而 $y$ 小时，`t = s + y` 只保留 $y$ 的高位部分。此时 `t - s` 是精确的（由 [[#lem-sterbenz]]，因为 $t$ 与 $s$ 很接近），恰好等于 $y$ 中真正加上的部分；再减去 $y$，就把丢失部分的相反数留在 $c$ 里，反馈进下一项。结果 $16.6953106$ 是最接近真和 $16.6953114\ldots$ 的 `float`（相邻的两个 `float` 是 $16.6953106$ 与 $16.6953125$）——远好于朴素求和的 $15.40$。在 `-ffast-math` 下，编译器可能把 `(t - s) - y` 代数化简成 `((s + y) - s) - y = 0`，把修正删掉：这是对实数成立、对浮点数不成立的优化。用 GCC 15.2，`gcc -O2 -ffast-math` 确实把打印结果改成了 `16.4196701`。
:::
:::

::: exercise 给负的浮点数排序 {level=3}
[[#thm-order]] 只覆盖非负浮点数。定义函数 `uint32_t key(float x)`，使得对所有非 NaN 的 `float`：$x < y$ 蕴含 `key(x) < key(y)`，并且 $x = y$ 的相容处理（把 $-0$ 与 $+0$ 视为相等，或视为 $-0 < +0$，任君选择）也保持一致。证明它是对的。
::: solution
```c
#include <stdint.h>
#include <string.h>

uint32_t key(float x) {
    uint32_t u;
    memcpy(&u, &x, sizeof u);
    return (u & 0x80000000u) ? ~u : (u | 0x80000000u);
}
```

对 $x \ge +0$（符号位 $0$），键是把最高位置 $1$ 的位模式：$2^{31} + U(x)$，由 [[#thm-order]] 它随 $x$ 增大，且落在 $[2^{31}, 2^{32})$ 内。对 $x \le -0$（符号位 $1$），位模式是 $2^{31} + U(\abs{x})$，其按位取反为 $2^{32} - 1 - 2^{31} - U(\abs{x}) = 2^{31} - 1 - U(\abs{x})$，落在 $[0, 2^{31})$ 内，并且*随 $\abs{x}$ 增大而减小*，即随 $x$ 增大而增大。每个负数的键都低于每个非负数的键。所以键的顺序与数值的顺序完全一致；$-0$ 得到键 $2^{31} - 1$，$+0$ 得到 $2^{31}$，因此这个写法令 $-0 < +0$。对浮点数据做基数排序用的正是这个变换。
:::
:::
