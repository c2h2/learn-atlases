两个循环对同一个 $4096 \times 4096$ 数组的一千六百万个整数求和。它们唯一的区别是循环的先后次序：

```c
#define _POSIX_C_SOURCE 199309L   /* 在 -std=c17 下为 clock_gettime 所需 */
#include <stdio.h>
#include <time.h>

#define N 4096
static int a[N][N];                    /* 64 MiB，远大于任何高速缓存 */

static double now(void) {
    struct timespec t;
    clock_gettime(CLOCK_MONOTONIC, &t);
    return t.tv_sec + t.tv_nsec * 1e-9;
}

int main(void) {
    for (int i = 0; i < N; i++)
        for (int j = 0; j < N; j++)
            a[i][j] = i + j;
    long s = 0;
    double t0 = now();
    for (int i = 0; i < N; i++)        /* 逐行：步长 1 */
        for (int j = 0; j < N; j++)
            s += a[i][j];
    double t1 = now();
    for (int j = 0; j < N; j++)        /* 逐列：步长 N */
        for (int i = 0; i < N; i++)
            s += a[i][j];
    double t2 = now();
    printf("sum %ld\nrow-major    %.3f s\ncolumn-major %.3f s\n", s, t1 - t0, t2 - t1);
    return 0;
}
```

```console
$ gcc -std=c17 -Wall -Wextra -O2 -o rowcol rowcol.c && ./rowcol
sum 137405399040
row-major    0.009 s
column-major 0.049 s
```

逐列的循环慢了五倍多（用 `-O1` 编译时，差距是 $0.011$ 秒对 $0.155$ 秒，达十四倍）。它执行的加法次数相同；[[algorithms]] 的渐近分析把两个循环都记作 $\Theta(n^2)$。差别完全出在*访问内存的次序*上，其来源是**存储器层次结构**：计算机的内存并不是 [[computer-systems/machine-code]] 假装的那种单一的均匀数组，而是一叠容量递增、速度递减的存储设备，靠近处理器的小而快的**高速缓存**（cache）中保存着最近使用数据的副本。

本章解释高速缓存如何工作，以及如何编写善用它们的程序。我们从使高速缓存成为必要的速度差距、以及使它们卓有成效的程序特性——**局部性**——讲起。然后精确定义高速缓存的组织——组、行、块、标签——手工跟踪高速缓存的状态，推出平均访问时间，并用数缺失的方法分析循环嵌套。同样的思想再往下一个层次，就是虚拟内存。

本章所有计时都是在一台机器上的**观测**——一颗 Intel Xeon E5-2696 v3（Haswell，2014），带 32 KiB 8 路 L1 数据高速缓存、256 KiB 的 L2 高速缓存、共享的 45 MiB L3 和 64 字节的行，运行 Linux——用 GCC 15.2 编译得到。其他机器数字不同，道理相同。

## 内存差距

处理器每个纳秒能启动好几条指令，但从主存取一个值却要花一百纳秒左右。这个差距是物理规律和经济规律共同造成的。快的内存（**SRAM**，静态随机存取存储器，每位六个晶体管）每位成本高，而且必须物理上紧邻处理器才快；容量大的内存（**DRAM**，动态随机存取存储器，每位一个晶体管加一个电容）便宜但慢，住在独立的芯片上。持久存储（**SSD** 中的闪存、磁盘）又便宜一个量级，也慢若干数量级。自 1980 年代以来，处理器速度提高得比 DRAM 时延快得多，于是差距不断拉大——"内存墙"。

2026 年前后，桌面或服务器处理器的典型数字（只看数量级；不同机器之间相差两倍或更多）：

| 层次 | 典型容量 | 典型时延 | 按约 3 GHz 折合周期数 |
|---|---|---|---|
| 寄存器 | 约 1 KiB | < 0.3 ns | 0 |
| L1 高速缓存（SRAM，每核心） | 32–64 KiB | 约 1 ns | 约 4–5 |
| L2 高速缓存（SRAM，每核心） | 0.25–2 MiB | 约 4 ns | 约 12–15 |
| L3 高速缓存（SRAM，共享） | 8–100+ MiB | 约 10–20 ns | 约 40–70 |
| 主存（DRAM） | 8 GiB – 1 TiB | 约 80–100 ns | 约 250–300 |
| SSD（闪存） | 0.5–8 TB | 约 10–100 µs | 约 $10^5$ |
| 硬盘 | 1–30 TB | 约 5–10 ms | 约 $10^7$ |

每一层都比上一层大约十倍、慢好几倍。只要程序在大多数时候所需的数据都能在小而快的层里找到，这个层次结构就能奏效。

## 局部性

程序访问内存不是随机的。

::: definition 局部性 {#def-locality}
若一个程序引用过的存储位置很可能很快再次被引用，就称该程序有良好的**时间局部性**；若引用某位置之后很可能很快引用邻近的位置，就称它有**良好的空间局部性**。依次访问数组中相邻元素的访问模式**步长为 1**；每隔 $k$ 个元素访问一次的模式**步长为 $k$**。
:::

逐行求和有极好的空间局部性：它依次访问 `a[i][0]`、`a[i][1]`、…，而由于 C 按行优先顺序存储数组（[[computer-systems/machine-code#eq-rowmajor]]），这些元素在内存中彼此相邻。变量 `s` 有极好的时间局部性——每次迭代都用到它（而且它住在寄存器里）。逐列求和触及的是 `a[0][j]`、`a[1][j]`、…，它们相隔 $4 \times 4096 = 16\,384$ 字节：步长 $4096$，几乎没有空间局部性。指令同样有局部性：循环体被一遍又一遍地执行（时间局部性），其中的指令又是连续的（空间局部性）。

::: quiz
对 `double v[n]` 和链表，下面哪些循环有良好的*空间*局部性？
- [x] `for (i = 0; i < n; i++) s += v[i];`
- [x] `for (i = n - 1; i >= 0; i--) s += v[i];`
- [ ] $n$ 很大时的 `for (i = 0; i < n; i++) s += v[(i * 4099) % n];`
- [ ] 沿着结点散落在各处地址上的链表追踪 `next` 指针
::: solution
步长 1 无论哪个方向都好：相邻元素共享高速缓存块，与你沿哪个方向走无关。把下标乘一个大常数再对 $n$ 取模会在数组里四处乱跳；结点地址散落的链表每一步都访问毫不相干的内存（这就是实践中链表常常比数组慢的原因，即使渐近代价一致——见 [[data-structures]]）。
:::
:::

### 作为一般原理的缓存

::: definition 高速缓存、命中与缺失 {#def-cache}
**高速缓存**是一个更小、更快的存储设备，保存着一个更大、更慢设备的部分数据的副本。数据在上下两层之间以固定大小的单位移动，这种单位称为**块**（在 CPU 高速缓存中也称**行**；在虚拟内存中称**页**）。程序请求数据时，若包含它的块在高速缓存中，这次访问就**命中**（hit）；否则**缺失**（miss，未命中），块从下一层取来，可能**逐出**（替换）另一个块。**缺失率**是缺失访问所占的比例，**命中率**是 $1 -$ 缺失率。
:::

缺失分三种，即"三个 C"。**强制性**（cold，冷启动）缺失是对一个块的首次引用，任何高速缓存都不可避免。**容量**缺失是因为程序的**工作集**——它正在积极使用的块——比高速缓存大。**冲突**缺失是高速缓存虽有空间，但放置规则把两个都在使用的块逼进同一个位置，于是它们互相逐个没完。

块正是空间局部性奏效的原因：对一个字节的缺失会把整块取进来，随后对同一块的访问就命中了。这个层次结构在每一层都应用同一原理：L1 缓存 L2，L2 缓存 L3，L3 缓存 DRAM，DRAM 缓存磁盘（虚拟内存），磁盘缓存远程服务器（web 缓存、内容分发网络）。

## 高速缓存的组织

CPU 高速缓存必须在大致一个纳秒内回答"包含地址 $A$ 的块在不在这里，在哪个位置？"它不可能搜索整个高速缓存。取而代之的是，每个块只能放进由地址某些位决定的受限位置集合。

::: definition 高速缓存参数 {#def-cache-org}
设地址有 $m$ 位。高速缓存组织成含 $S = 2^s$ 个**组**的数组，每组含 $E$ 个**行**；每行存放一个 $B = 2^b$ 字节的**块**，外加一个**有效位**和一个 $t = m - s - b$ 位的**标签**。**容量**为 $C = S \times E \times B$ 字节（不计标签和有效位）。地址 $A$ 从最高位起划分为
$$
A = \underbrace{t \text{ 标签位}}_{\text{哪个块}} \;\Big|\; \underbrace{s \text{ 组索引位}}_{\text{哪个组}} \;\Big|\; \underbrace{b \text{ 块内偏移位}}_{\text{哪个字节}} 。
$$

$E = 1$ 的高速缓存称为**直接映射**；$1 < E < C/B$ 的称为 **$E$ 路组相联**；只有一个组（$S = 1$，$E = C/B$）的称为**全相联**。
:::

::: algorithm 高速缓存查找 {#alg-lookup}
读地址 $A$ 处的字节：

1. **选组。** 取出组索引 $i$（$A$ 的第 $b$ 到 $b + s - 1$ 位），选中第 $i$ 组。
2. **匹配行。** 把 $A$ 的标签与该组中每个有效行的标签比较（在硬件中，$E$ 次比较全部并行完成）。
3. **命中。** 若某个有效行的标签匹配，返回其块内偏移为（$A$ 的低 $b$ 位）的那个字节。
4. **缺失。** 否则从下一层取回包含 $A$ 的块——把 $A$ 的低 $b$ 位清零后起的 $B$ 个字节。若该组有无效行就用它；否则按**替换策略**（通常是最近最少使用，**LRU**，或其近似）逐出一个行。存入该块，设置有效位与标签，返回所请求的字节。
:::

::: proposition 地址到行的映射是唯一的 {#prop-unique}
对固定的 $s$ 和 $b$，两个地址落在同一个块中当且仅当它们的标签位和组索引位相同；而在其组内，块由标签唯一标识。因此，若一次查找在选中的组里找到了标签匹配的有效行，它找到的就是正确的块。
:::

::: proof
包含 $A$ 的块是 $\lfloor A / 2^b \rfloor$，它的二进制表示恰为 $A$ 的高 $t + s$ 位（标签位接组索引位）。所以两个地址同块当且仅当这些位相同。所有放入第 $i$ 组的块都有相同的组索引位 $i$，因而在它们中间，块号完全由标签位决定。所以第 $i$ 组中标签为 $T$ 的有效行，存放的恰是块号 $T \cdot 2^s + i$，即 $A$ 所在的块。
:::

组索引取*中间*的位是刻意为之。若用高位选组，连续的块就全落进同一组，扫描数组的程序只会用到高速缓存的一个组。用中间的位，连续的块进入连续的组，一段 $C$ 字节的连续区域恰好能完整放进高速缓存。

::: example 一个真实的 L1 高速缓存 {#ex-l1}
测试机的 L1 数据高速缓存 $C = 32$ KiB、$E = 8$、$B = 64$ 字节。它有多少个组？地址 `0x7ffc3a5e` 如何划分？（地址按 48 位宽处理。）
::: solution
$S = C/(E \cdot B) = 32768 / (8 \cdot 64) = 64$ 个组，故 $s = 6$；$B = 64$ 给出 $b = 6$；标签为 $t = 48 - 6 - 6 = 36$ 位。块内偏移是 `0x7ffc3a5e` 的低六位：`0x5e & 0x3f` $= 30$。组索引是再往上的六位：$(\text{0x7ffc3a5e} \gg 6) \mathbin{\&} 63 = 41$。标签是第 12 位以上的一切：`0x7ffc3`。所以这个字节若被缓存，就住在第 $41$ 组八个行中某行的第 $30$ 个偏移处，该行的标签是 `0x7ffc3`。因为 $s + b = 12$，组索引完全来自地址的低 12 位——即 4 KiB 页内的偏移——这让硬件能在地址转换（见下文）完成之前就开始查找。
:::
:::

::: example 直接映射与二路组相联 {#ex-trace}
一个 $C = 32$ 字节、$B = 8$ 字节的微缩高速缓存依次收到字节读 `0, 4, 8, 36, 0, 40, 8, 68, 4`（地址为十进制）。分别把它当作直接映射（$S = 4$，$E = 1$）和二路组相联、LRU 替换（$S = 2$，$E = 2$）来跟踪。
::: solution
地址 $A$ 的块号为 $\lfloor A/8 \rfloor$。直接映射：组 $= $ 块号模 $4$，标签 $= \lfloor \text{块号}/4 \rfloor$。

| 地址 | 块 | 组 | 标签 | 结果 |
|---|---|---|---|---|
| 0 | 0 | 0 | 0 | 缺失（强制性） |
| 4 | 0 | 0 | 0 | 命中 |
| 8 | 1 | 1 | 0 | 缺失（强制性） |
| 36 | 4 | 0 | 1 | 缺失，逐出块 0 |
| 0 | 0 | 0 | 0 | 缺失（冲突），逐出块 4 |
| 40 | 5 | 1 | 1 | 缺失，逐出块 1 |
| 8 | 1 | 1 | 0 | 缺失（冲突），逐出块 5 |
| 68 | 8 | 0 | 2 | 缺失，逐出块 0 |
| 4 | 0 | 0 | 0 | 缺失（冲突），逐出块 8 |

一次命中，八次缺失。块 $0$、$4$、$8$ 全映射到第 $0$ 组，块 $1$ 和 $5$ 映射到第 $1$ 组，于是它们互相逐个没完，尽管高速缓存有四个行、实际只用到五个不同的块。

二路组相联：组 $= $ 块号模 $2$，标签 $= \lfloor \text{块号}/2 \rfloor$；每组放两个块，满组缺失时逐出最近最久未使用的一个。

| 地址 | 块 | 组 | 标签 | 结果 | 访问后组内内容（LRU 在前） |
|---|---|---|---|---|---|
| 0 | 0 | 0 | 0 | 缺失 | {0} |
| 4 | 0 | 0 | 0 | 命中 | {0} |
| 8 | 1 | 1 | 0 | 缺失 | {1} |
| 36 | 4 | 0 | 2 | 缺失 | {0, 4} |
| 0 | 0 | 0 | 0 | 命中 | {4, 0} |
| 40 | 5 | 1 | 2 | 缺失 | {1, 5} |
| 8 | 1 | 1 | 0 | 命中 | {5, 1} |
| 68 | 8 | 0 | 4 | 缺失，逐出块 4（LRU） | {0, 8} |
| 4 | 0 | 0 | 0 | 命中 | {8, 0} |

四次命中，五次缺失。容量不变，相联度消去了大部分冲突缺失。（为这个例子写的一个 Python 模拟给出相同的计数。）真实的 L1 高速缓存通常是 8 到 12 路：相联度足以让冲突罕见，同时让并行的标签比较保持快速。
:::
:::

### 写操作

读很简单，因为缓存副本与下一层一致。写则带来选择。**写直达**（write-through）高速缓存把每次存储立即写到下一层；**写回**（write-back）高速缓存只更新缓存中的块，把它标为**脏**，等它被逐出时才写回，块被反复写时可节省流量。写缺失时，**写分配**（write-allocate）高速缓存先取回该块再写入（利用后续写的空间局部性）；**非写分配**（no-write-allocate）高速缓存直接写下一层。现代 CPU 高速缓存在每一层通常都是写回、写分配的。多核各有私有高速缓存时，**一致性协议**（如 MESI）让同一块的各副本保持一致；那以及它的性能后果（如伪共享）属于 [[parallel-computing]]。

## 度量高速缓存的性能

内存访问的代价用一个数字概括。

::: theorem 平均访问时间 {#thm-amat}
设高速缓存的命中时间为 $T_h$（判定命中并交付数据的时间），缺失率为 $r$，缺失损失为 $P$（从下一层取得块所*额外*花的时间）。则平均每次访问的时间为
$$
\text{AMAT} = T_h + r \cdot P .
$$ {#eq-amat}

对多级层次结构，上一层的缺失损失就是下一层的 AMAT：两级时 $\text{AMAT} = T_{h,1} + r_1 \,(T_{h,2} + r_2 P_2)$，其中 $r_2$ 是 L2 的**局部**缺失率（*到达* L2 的访问中在 L2 缺失的比例）。
:::

::: proof
每次访问都花 $T_h$ 在高速缓存中。比例为 $r$ 的访问还要再付 $P$。对访问取平均，$\text{AMAT} = (1 - r) T_h + r(T_h + P) = T_h + rP$。对两级结构，从 L1 的角度看，一次 L1 缺失相当于一次对 L2 子系统的访问，按同一公式其平均代价为 $T_{h,2} + r_2 P_2$；把它代回 $P$ 即得第二个公式。（这是在"每次访问独立地命中或缺失"的模型下的平均值；真实处理器会让缺失与其他工作重叠，所以该公式是代价模型，不是运行时间的精确预言。）
:::

::: widget plot
f: h + (1 - x)*p
x: 0.8, 1
y: 0, 60
sliders: h=4:1:10:1; p=200:50:400:10
labels: \text{AMAT（周期数）}
caption: 单个高速缓存的平均访问时间随命中率 $x$ 的变化，命中时间 $h$ 与缺失损失 $p$ 以周期计。注意这条线有多陡：缺失损失为 $200$ 周期时，命中率从 $97\%$ 提到 $99\%$，平均时间就从 $10$ 周期降到 $6$ 周期。缺失率的微小变化主导着内存性能，这就是本章余下部分一直在数缺失的原因。
:::

::: example 一个两级层次结构 {#ex-amat}
L1 命中时间 4 周期，缺失率 5%。L2 命中时间 12 周期，局部缺失率 20%。主存代价 200 周期。AMAT 是多少？若一处程序改动使 L1 缺失率减半呢？
::: solution
由 [[#thm-amat]]，$\text{AMAT} = 4 + 0.05 \times (12 + 0.2 \times 200) = 4 + 0.05 \times 52 = 6.6$ 周期。L1 缺失率为 $2.5\%$ 时：$4 + 0.025 \times 52 = 5.3$ 周期。程序的内存访问平均快约 $20\%$，尽管 L1 命中一点都没有变快。L2 的**全局**缺失率——流向主存的访问占全部访问的比例——第一种情形下是 $0.05 \times 0.2 = 1\%$。
:::
:::

## 编写对高速缓存友好的代码

由这个模型可以得出两条经验法则：让常见情形——内层循环——命中高速缓存，并用步长 1 访问（空间局部性）和重复使用已载入的数据（时间局部性）把其中的缺失降到最低。第一条可以量化。

::: proposition 跨步扫描的缺失率 {#prop-stride}
一个循环从冷高速缓存出发，对 $w$ 字节元素的数组以步长 $k$ 各读一次共 $n$ 个元素，数组按块边界对齐，且 $kw$ 要么整除 $B$、要么是 $B$ 的倍数。若一个块在使用期间不会被逐出，则缺失率为
$$
r = \min\!\left(1, \frac{kw}{B}\right)
$$

（数组尽头的取整误差除外）。
:::

::: proof
相邻两次访问相距 $kw$ 字节。若 $kw \ge B$（且 $kw$ 是 $B$ 的倍数），每次访问都落在不同的、此前从未被碰过的块里，于是每次访问都是强制性缺失：$r = 1$。若 $kw < B$ 且 $kw$ 整除 $B$，由于块边界是 $B$ 的倍数从而也是 $kw$ 的倍数，每个块恰好接收 $B/(kw)$ 次连续访问。每个块的首次访问缺失，而块在使用期间不被逐出，其余 $B/(kw) - 1$ 次命中。所以缺失率为 $1 / (B/(kw)) = kw/B$。
:::

对 `int`（$w = 4$）和 64 字节的行，逐行求和的缺失率为 $4/64 = 1/16$：每十六个元素一次缺失。逐列求和的步长为 $4096$ 个元素、$16\,384$ 字节，于是每次访问都缺失——更糟的是，同一列的各元素都相距 $16\,384$ 字节，是 L1 的 64 个组所占 $64 \times 64 = 4096$ 字节的倍数，所以它们全部映射到*同一个* L1 组里相互冲突。这就解释了观测到的倍数（硬件**预取器**在实践中缓解了它，预取器能识别规则的步长并提前取块）。

### 冲突与填充

::: example 点积中的颠簸 {#ex-thrash}
一个直接映射高速缓存有 16 个组、16 字节的块（共 256 字节）。某个函数对两个含 16 个 `double` 的数组计算 $\sum_i x_i y_i$，`x` 在地址 $0$，`y` 在地址 $256$，按 `x[0], y[0], x[1], y[1], …` 的顺序读。数一数缺失次数。然后把 `y` 移到地址 $272$。
::: solution
`x[i]` 在 $8i$，块 $\lfloor i/2 \rfloor$，组 $\lfloor i/2 \rfloor$。`y[i]` 在 $256 + 8i$，块 $16 + \lfloor i/2 \rfloor$，组 $(16 + \lfloor i/2 \rfloor) \bmod 16 = \lfloor i/2 \rfloor$——同一个组。于是读 `x[0]` 把块 0 载入第 0 组，读 `y[0]` 把它逐出，读 `x[1]`（与 `x[0]` 同块）又缺失并把 `y` 的块逐出，如此下去：**32 次访问全部缺失**。称高速缓存**颠簸**（thrash），尽管两个数组合起来恰好占满其容量。

`y` 在 $272$ 时，`y[i]` 在块 $17 + \lfloor i/2 \rfloor$，组 $(1 + \lfloor i/2 \rfloor) \bmod 16$：永远是 `x[i]` 所用组的*下一个*组。现在每个块只载入一次，它的两个元素都在被逐出之前用完了：16 次缺失、16 次命中，缺失率 $8/16 = 1/2$，即 [[#prop-stride]] 的值。模拟证实了这两个计数。插入**填充**让两个数组彼此错开是标准的补救办法，避免把数组维数取成很大的 2 的幂也一样。
:::
:::

### 矩阵乘法中的循环次序

考虑 $n \times n$ 的 `double` 矩阵的 $C \mathrel{+}= AB$，对 $i$、$j$、$k$ 的三重循环计算 `C[i][j] += A[i][k] * B[k][j]`。三个循环的全部六种次序都用 $n^3$ 次乘加算出相同的结果，但访问内存的方式不同。用 [[#prop-stride]] 分析**内层循环**，设 $n$ 很大（一行放不进高速缓存），块 64 字节、可放 8 个 double：

| 次序 | 内层循环变化的下标 | `A` 的访问 | `B` 的访问 | `C` 的访问 | 内层每次迭代的缺失 |
|---|---|---|---|---|---|
| `ijk`（以及 `jik`） | $k$ | 行，步长 1：$1/8$ | 列：$1$ | 固定：$0$ | $1.125$ |
| `jki`（以及 `kji`） | $i$ | 列：$1$ | 固定：$0$ | 列：$1$ | $2$ |
| `kij`（以及 `ikj`） | $j$ | 固定：$0$ | 行，步长 1：$1/8$ | 行，步长 1：$1/8$ | $0.25$ |

预测是 `kij` 最快、`jki` 最慢。实测，$n = 1024$、`gcc -O2`：

```console
$ ./mm
check -3.58373e+08 -3.58373e+08 -3.58373e+08
ijk 4.30 s   jki 18.27 s   kij 0.57 s
```

次序与分析吻合；差距的大小（两端相差 $32$ 倍，超过缺失比 $8$）显示出两个进一步的效应：$n = 1024$ 时列元素相距 $8192$ 字节，在同一批组中冲突；而 `kij` 步长 1 的内层循环还能被编译器**向量化**成一条指令同时处理多个 double 的 SIMD 指令。（完整程序 41 行，初始化 `A[i][j] = i - j`、`B[i][j] = i + j`，把三个版本先后各运行一遍；`check` 行确认它们算出同一个 $C_{7,9}$。）

::: warning 数操作不等于数时间
"两个循环都是 $\Theta(n^3)$，所以时间相同"在这里错了 30 倍。渐近分析在"每次内存访问代价相同"的模型里数操作；真实内存不是这样的。在乎性能时，还要数*缺失*——[[algorithms]] 的**外存模型**与**缓存无关**（cache-oblivious）模型正式地做这件事——并且动手测量。反过来，也不要不测量就为高速缓存"优化"：现代预取器和乱序执行能掩盖简单访问模式中的许多缺失。
:::

工作集超过高速缓存时，**分块**（blocking，tiling）能进一步改善时间局部性：把矩阵切成足够小的 $b \times b$ 子矩阵，让三个这样的块能同时放进高速缓存，然后逐块相乘。每次分块乘法中每个块只载入一次，随后从高速缓存中被重复使用 $b$ 次，从而把缺失次数除以大约与 $b$ 成正比的倍数。优化过的库（BLAS 实现）把针对每一级高速缓存的分块与向量化结合起来，比最好的朴素循环快几十倍。

## 虚拟内存：DRAM 是磁盘的高速缓存

再往下一个层次，同样的组织以截然不同的数字重现。每个进程看到一个私有的**虚拟地址空间**（[[computer-systems/c-programming#sec-regions]]）；硬件的**内存管理单元**（MMU）借助操作系统维护的**页表**，把每个虚拟地址翻译成 DRAM 中的**物理地址**。内存被划分为**页**，x86-64 默认 4 KiB（$2^{12}$ 字节，另有可选的 2 MiB 和 1 GiB "大页"）。虚拟地址划分为**虚拟页号**和 12 位**页内偏移**；翻译把页号换成物理页号，偏移保持不变。

从高速缓存的角度看，DRAM 存放着虚拟地址空间的页；引用不在 DRAM 中的页就是**缺页**，由操作系统处理（[[computer-systems/exceptions-processes]]），操作系统把该页从磁盘读入。缺失损失大得惊人——硬盘是毫秒级，SSD 是几十微秒，合几百万或几十万个周期——所以虚拟内存是全相联的（任何页可放入任何物理页框），在软件中采用精巧的替换策略，并且永远是写回的。

在 x86-64 上，48 位虚拟地址经四级页表翻译：$48 = 12 + 4 \times 9$，每级由 9 位索引，含 $2^9 = 512$ 个八字节的表项，恰好一个 4 KiB 页。（支持五级分页的处理器把它扩展到 57 位。）每次访问都走四级页表代价无法承受，于是 MMU 用**快表**（TLB，转换后备缓冲器）缓存最近的翻译——它是一个很小、相联度很高的页表项高速缓存。一个有 64 个 4 KiB 页表项表目的快表覆盖 $64 \times 4 = 256$ KiB 内存——它的**覆盖范围**（reach）——这就是大型而分散的工作集能从大页受益的原因。页替换算法、页表结构及其管理在 [[operating-systems]] 中讲授。

::: history
莫里斯·威尔克斯（Maurice Wilkes）在 1965 年描述了用一个小的快速的"从属存储器"保存更大主存中部分字副本的思想；IBM System/360 Model 85（1968）是第一台带高速缓存的商品化计算机，IBM 称之为 buffer。虚拟内存更早：曼彻斯特大学的 Atlas 计算机（1962 年投入运行，汤姆·基尔本（Tom Kilburn）的小组设计）采用了"单级存储"，页在磁芯存储器与磁鼓之间自动移动。彼得·登宁（Peter Denning）的工作集模型（1968）给局部性以精确的表述。Wm. A. Wulf 与 Sally McKee 在 1995 年把不断扩大的处理器—内存差距命名为"内存墙"。Bryant 与 O'Hallaron 的《深入理解计算机系统》（Computer Systems: A Programmer's Perspective，第 3 版，2016）让"内存山"流行起来——它以工作集大小和步长为轴画出的读吞吐量曲线，能在任何机器上让层次结构现形。
:::

本章数缺失的论证会在 [[databases]] 的 B树分析中重现——B树结点的大小正是为了匹配磁盘或 SSD 的块——也会在 [[algorithms]] 的缓存高效算法中重现。[[computer-systems/dynamic-memory]] 讨论分配器的放置决策如何影响局部性。核心之间共享的高速缓存、一致性与伪共享属于 [[parallel-computing]]；虚拟内存、页替换与快表管理在 [[operating-systems]] 中展开。SRAM 与 DRAM 的电路以及高速缓存控制器的设计属于计算机体系结构，见[电气电子工程图谱](/learn/ee/)。高速缓存还会通过计时泄露信息，这是 Spectre 等侧信道攻击及其缓解措施的基础（[[security]]）。

::: summary
- 存储构成一个层次——寄存器、L1、L2、L3、DRAM、SSD、磁盘——每层比上一层大约十倍、慢好几倍；处理器与内存的差距约为 100 纳秒，即几百个周期。
- 高速缓存能奏效是因为程序有**时间**与**空间**局部性；数据以块为单位移动（当前 CPU 是 64 字节的行）。
- 高速缓存有 $S = 2^s$ 个组、每组 $E$ 行、每行 $B = 2^b$ 字节；地址划分为标签、组索引与块内偏移（[[#def-cache-org]]）；直接映射、组相联与全相联高速缓存用查找代价换冲突缺失。
- 缺失分为强制性、容量与冲突；写策略通常是写回、写分配。
- $\text{AMAT} = T_h + rP$，逐层套用（[[#thm-amat]]）：缺失率的微小变化占主导。
- 对 $w$ 字节元素做步长 $k$ 的扫描，缺失率为 $\min(1, kw/B)$（[[#prop-stride]]）。优先选择步长 1 的内层循环，趁数据还在缓存时重复使用，靠数内层缺失决定循环次序，对大型计算分块，用填充错开数组以避免冲突。
- 虚拟内存以 4 KiB 的页、多级页表和快表，把同样的思想用在 DRAM 与磁盘之间。
:::

## 习题

::: exercise 高速缓存的几何参数 {level=1 check="1024"}
一个 1 MiB 的 L2 高速缓存是 16 路组相联、行长 64 字节。它有多少个组？组索引和块内偏移各占几位？（输入组的个数。）
::: solution
$S = C/(E B) = 2^{20} / (2^4 \cdot 2^6) = 2^{10} = 1024$。所以 $s = 10$、$b = 6$；地址 48 位时标签为 $48 - 10 - 6 = 32$ 位。容量不变而把相联度加倍到 32 路，组的个数减半为 $512$。
:::
:::

::: exercise 划分地址 {level=1 check="25"}
对 [[#ex-l1]] 的 L1 高速缓存（64 组、块 64 字节），地址 `0x12345678` 映射到哪个组？再给出块内偏移。（输入组索引。）
::: solution
偏移是低六位：`0x78 & 0x3f` $= 0x38 = 56$。组索引是第 6–11 位：$(\text{0x12345678} \gg 6) \mathbin{\&} 63$。右移六位得 `0x48d159`，`0x59 & 0x3f` $= 0x19 = 25$。所以组 $25$，偏移 $56$，标签 `0x12345`。
:::
:::

::: exercise 平均访问时间 {level=1 check="4"}
某高速缓存命中时间 1 ns，缺失率 3%，缺失损失 100 ns。AMAT 是多少纳秒？（输入该值。）
::: solution
由 [[#eq-amat]]，$1 + 0.03 \times 100 = 4$ ns。3% 的访问贡献的时间是所有命中加起来总时间的三倍。
:::
:::

::: exercise 跨步读取 {level=2 check="0.25"}
一个循环对一个大型 `double` 数组每隔一个元素读一次（步长 2），每个元素读一次，块 64 字节，冷高速缓存。缺失率是多少？（以分数或小数输入。）
::: solution
由 [[#prop-stride]]，$k = 2$、$w = 8$、$B = 64$：$kw/B = 16/64 = 1/4$。每个 64 字节的块含 8 个 double，循环读其中 4 个；每个块的首次读缺失，其后三次命中。
:::
:::

::: exercise 跟踪直接映射高速缓存 {level=2 check="6"}
一个直接映射高速缓存有 4 个组、块 16 字节。跟踪字节读 `0x00, 0x08, 0x40, 0x48, 0x00, 0x80, 0x08, 0x40` 并数缺失次数。（输入缺失次数。）
::: solution
块号 $\lfloor A/16 \rfloor$，组为块号模 4。各块：`0x00` → 0，`0x08` → 0，`0x40` → 4，`0x48` → 4，`0x80` → 8。三个块全映射到第 $0$ 组。序列：块 0 缺失；块 0 命中；块 4 缺失（逐出 0）；块 4 命中；块 0 缺失（逐出 4）；块 8 缺失（逐出 0）；块 0 缺失（逐出 8）；块 4 缺失（逐出 0）。共 $6$ 次缺失、$2$ 次命中，尽管高速缓存有四个组、只用到三个不同的块。一个二路 LRU、2 组的高速缓存（容量相同）同样把三个块全映射到第 0 组（块号模 $2 = 0$），但同时装得下其中两个：它在块 0、4、8 以及最后又一个 4 上缺失，$4$ 次缺失、$4$ 次命中。
:::
:::

::: exercise 其余的循环次序 {level=2}
对 `jik` 与 `ikj` 两种次序补全矩阵乘法的分析：写出各自的循环嵌套，说明内层循环的每个数组引用沿哪个矩阵、以什么步长前进，并按正文表格中的假设给出内层每次迭代的缺失数。
::: solution
`jik`：`for j, for i { s = C[i][j]; for k: s += A[i][k] * B[k][j]; C[i][j] = s; }`。内层循环变化 $k$：`A[i][k]` 以步长 1 沿第 $i$ 行走（每次迭代缺失 $1/8$），`B[k][j]` 以步长 $n$ 沿第 $j$ 列走（每次迭代一次缺失），`C[i][j]` 固定在寄存器中。合计 $1.125$，与 `ijk` 相同。

`ikj`：`for i, for k { r = A[i][k]; for j: C[i][j] += r * B[k][j]; }`。内层循环变化 $j$：`B[k][j]` 沿第 $k$ 行、`C[i][j]` 沿第 $i$ 行，都是步长 1（各 $1/8$），`A[i][k]` 固定。合计 $0.25$，与 `kij` 相同。规律：最优的次序让最内层循环恰好索引它触及的每个数组的*最后*一个下标。
:::
:::

::: exercise LRU 与循环访问 {level=3}
一个全相联高速缓存装 $E$ 个块，使用 LRU 替换。一个程序反复循环访问 $E + 1$ 个不同的块 $b_0, b_1, \ldots, b_E, b_0, b_1, \ldots$。证明每次访问都缺失。最优替换策略能做到什么？
::: solution
断言：每次访问 $b_j$ 之前（最初 $E + 1$ 次访问之后），高速缓存中恰是最近被访问的 $E$ 个块，即*除* $b_j$ *外*的 $E$ 个块。LRU 保留最近使用的 $E$ 个块，因为缺失会逐出最近最久未使用的那个。在 $E + 1$ 个块的循环序列中，最近 $E + 1$ 次访问里最近最久未使用的块正是 $b_j$ 自己，也就是即将被访问的那个块：前面 $E$ 次访问发生在其余 $E$ 个块上。所以 $b_j$ 不在缓存中，这次访问缺失。最初的 $E + 1$ 次访问是强制性缺失。于是每次访问都缺失：缺失率为 $1$。

最优策略（贝拉迪（Belady）策略：逐出下次使用在将来最远的块）在稳态下大约每 $E$ 次访问只缺失一次：缺失时逐出最晚才被再次需要的块，在循环序列中就是最近刚用过的那个，此后 $E - 1$ 次访问都命中。这个"LRU 悬崖"——工作集超出高速缓存一个块，性能就崩塌——正是一些高速缓存采用其他策略、以及扫描比高速缓存大的数据集时从中得不到好处的原因。（一个 $E = 4$、对 5 个块做 20 次访问的模拟给出 20 次缺失。）
:::
:::

::: exercise 分块转置 {level=3}
写一个 C 函数，以 $b \times b$ 的块转置一个 $n \times n$ 的 `double` 矩阵（`dst[j][i] = src[i][j]`），并用 [[#prop-stride]] 解释：设块 64 字节、高速缓存装得下两个 $8 \times 8$ 的小块（tile）、数组按块对齐，为什么朴素版本在 $n$ 很大时约缺失 $n^2 (1/8 + 1)$ 次，而 $b = 8$ 的分块版本约缺失 $n^2/4$ 次。
::: solution
```c
#include <stddef.h>

void transpose_blocked(size_t n, double dst[n][n], const double src[n][n], size_t b) {
    for (size_t ii = 0; ii < n; ii += b)
        for (size_t jj = 0; jj < n; jj += b)
            for (size_t i = ii; i < ii + b && i < n; i++)      /* 一个 b×b 的小块 */
                for (size_t j = jj; j < jj + b && j < n; j++)
                    dst[j][i] = src[i][j];
}
```

（参数使用变长数组类型，C99 起成为标准，这样 `src[i][j]` 才能对 $n \times n$ 的数组寻址。）在先 $i$ 后 $j$ 的朴素双重循环中，`src` 沿行读，步长 1，缺失率 $1/8$；`dst` 沿列写，步长 $n$，$n$ 很大时每次写都触及一个新块，而该块所属块的下一个元素轮到被写时它早已被逐出，所以每次写都缺失：合计约 $n^2(1/8 + 1)$ 次缺失。

$b = 8$ 的分块版本中，`src` 的一个小块是 8 行各 8 个 double，即 8 个高速缓存块，`dst` 相应的小块也是 8 块。若两个小块在处理期间都留在高速缓存中，每个块只载入一次：每 $64$ 个元素的小块 $8 + 8 = 16$ 次缺失，于是合计 $16 \cdot n^2 / 64 = n^2/4$ 次缺失——约是朴素计数的五分之一。（真实高速缓存配合 2 的幂的 $n$ 时，一个小块的八行可能在同一组中冲突；把行长填充一下即可避免。）
:::
:::
