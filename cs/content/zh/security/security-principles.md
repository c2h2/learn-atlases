一所大学运行着一个在线系统：教师录入成绩，学生查看成绩。它工作得很完美：每个页面都能打开，每个成绩都被存储，每份报表都算得对。它*安全*吗？这个问题现在还没有答案，因为我们尚未说明系统要保护什么、防住谁、以及允许它依赖哪些假设。一个篡改成绩的学生、一个账号仍然有效的离职员工、一个阅读自己不教的课程成绩的教师、出分日前夜汹涌而来的请求、一盘落在火车上的备份磁带——每一个都是不同的失效，要靠不同的机制来阻止，而且彼此的重要程度相去甚远。安全工程的第一步，就是把这些提问变精确。

本章为整个课程建立词汇。我们定义**安全目标**（机密性、完整性、可用性及其近亲），把**策略**——允许做什么——与执行它的**机制**分开，并学会写出**威胁模型**：对手是谁，他们能做什么。随后我们认识三件系统性地思考威胁的工具——攻击树、STRIDE 与风险估计——以及 Saltzer 和 Schroeder（1975）的设计原则，它们至今仍描述着良好安全设计的大部分内容。本课程后面的一切——认证、访问控制、内存安全、web 与网络防御——都是这些思想的实例。我们所依赖的密码学构件在 [[cryptography]] 中展开；这里我们把它们当作保证已经声明的工具来使用。

## 安全目标

安全要讲的是：在*有人蓄意让系统失效*的情况下，仍使系统按预期工作。可靠性工程问的是部件随机失效时会发生什么；安全问的是智能对手*挑选*失效时会发生什么。这就改变了一切：随机故障下概率为 $10^{-9}$ 的事件，若攻击者能够安排，就可能每次都会发生。

经典的目标有三个。

::: definition 机密性、完整性与可用性 {#def-cia}
对系统中的信息或资源：

- **机密性**：只向有权获知它的人泄露。
- **完整性**：只由有权者以授权的方式修改（创建、更改、删除）；对一个系统而言，其行为符合规范。
- **可用性**：有权使用它的人在需要时能够使用。

这三者合称 **CIA 三元组**。
:::

若干进一步的目标是对它们的细化或组合。**真实性**是来源的完整性：一条消息确实出自它所声称的来源。**可追责性**指行为可以被追踪到负责的一方，这需要先认证、再有防篡改的日志。**不可否认性**是其中的强形式：责任方无法向第三方作看似合理的否认（数字签名提供它，共享密钥的 MAC 不提供：[[cryptography/signatures]]）。**隐私**关乎个人信息及其所描述的当事人，而非系统的所有者，其内容是 [[security/privacy]]。

这些目标彼此牵制。把一切都加密有利于机密性，可一把丢失的密钥就摧毁了可用性。要求两人批准每一项更改保护了完整性，却拖慢了正常工作。保留详细日志有助于可追责性，却可能损害隐私。安全设计是一门选择契合系统的权衡的艺术，而选择取决于系统：对银行的账簿，完整性居首；对医疗记录，机密性与可用性都重要（急诊时医生被锁在门外同样是失效）；对一个公开网站，可用性与内容完整性比机密性重要得多。

### 策略与机制

**安全策略**规定什么允许、什么不允许；**机制**是执行策略某部分的办法、工具或规程。"只有课程的主讲教师可以改该课成绩"是策略；口令、应用中的一道访问控制检查、一项数据库权限是机制。把两者分开是安全工程师的第一个习惯：在"谁可以改成绩"都未商定之前去争论口令的优劣，就是在错的事情上争论。

为了精确地推理策略，沿用 Bishop 的做法，我们采用状态机视角。

::: definition 安全策略与安全系统 {#def-policy}
把一个系统建模为一个状态集 $P$ 及其上的转移。**安全策略**是把 $P$ 划分为**授权**（安全）状态 $Q$ 与**非授权**状态 $P \setminus Q$ 的一个划分。若系统从 $Q$ 中的状态出发，且任何转移序列都不能把它带到 $Q$ 之外，则称系统关于该策略是**安全的**。
:::

::: definition 安全的与精确的机制 {#def-mechanism}
一个**安全机制**把系统限制在一个可达状态集 $R \subseteq P$ 上。若 $R \subseteq Q$，机制是**安全的**；若 $R = Q$，是**精确的**；若存在状态 $r \in R$ 满足 $r \notin Q$，是**宽松的**。
:::

一个安全的机制可能禁止某些授权状态——一个拒绝一切请求的系统既绝对安全又绝对无用——而缺口 $Q \setminus R$ 度量了机制牺牲了多少合法行为。宽松的机制有一个漏洞。多数真实机制既不精确*又*略为宽松，工程上的问题是漏洞是否要紧。

::: proposition 机制的组合 {#prop-combine}
设机制 $M_1$ 和 $M_2$ 分别把系统限制到 $R_1$ 和 $R_2$，并假设同时运行二者把系统限制到 $R_1 \cap R_2$。若其中任一机制关于策略 $Q$ 是安全的，则组合也是安全的。组合是精确的仅当 $Q \subseteq R_1 \cap R_2$，即使两个机制各自对不同策略都精确，这也可能不成立。
:::

::: proof
若 $R_1 \subseteq Q$，则 $R_1 \cap R_2 \subseteq R_1 \subseteq Q$，对 $R_2$ 同理；故组合是安全的。精确性要求 $R_1 \cap R_2 = Q$；由于安全性已给出 $R_1 \cap R_2 \subseteq Q$，精确性等价于 $Q \subseteq R_1 \cap R_2$，即两个机制都不禁止任何授权状态。若 $M_1$ 对另一策略 $Q_1$ 精确而 $Q \not\subseteq Q_1$，则 $Q$ 的某个授权状态位于 $R_1 = Q_1$ 之外，组合将其禁止。
:::

关键在"同时运行两者得到 $R_1 \cap R_2$"这一假设。当每个机制只*阻断*转移时它成立——一个自带检查的应用前面的防火墙。当一个机制能够改变另一个机制的行为时它就失效了：一个会解析攻击者可控输入的日志组件本身可能成为一条入口，使可达集扩大而非缩小。2021 年 12 月的 Log4Shell 漏洞（CVE-2021-44228）是经典案例：一个被广泛使用的 Java 日志库把被记录数据中的特殊字符串解释为获取并运行代码的指令（[[security/web-security]]）。增加组件就是增加代码，而代码就是攻击面。

::: quiz
某文件服务器的策略规定只有 `staff` 组成员可以读 `/payroll`。管理员把操作系统配置成*无人*能读 `/payroll`，工资相关员工改用打印件代替。用 [[#def-mechanism]] 的术语说，这个机制是：

- [x] 安全但不精确
- [ ] 精确
- [ ] 宽松
- [ ] 既不安全也不宽松
::: solution
没有可达状态存在未授权的读者，故 $R \subseteq Q$：安全。但"staff 成员读取该文件"的状态是授权的却不可达，故 $R \ne Q$：不精确。（打印件是否安全是关于另一个系统的问题——纸也有访问控制问题。）
:::
:::

## 威胁模型

策略说明什么不该发生。**威胁模型**说明对手能做什么使它发生。没有威胁模型，安全声明就毫无意义：一把挡得住路人的锁挡不住拿撬棍的人，却没人因此说这把锁坏了。

::: definition 威胁模型 {#def-threat-model}
一个系统的**威胁模型**陈述

1. 要保护的**资产**以及每个资产的安全目标；
2. **对手**：他们是谁、想要什么，以及他们的**能力**——能观察什么、能发送或修改什么、知道什么、拥有多少计算力、资金和时间，以及他们控制或能腐化系统的哪些部分；
3. **信任假设**：被假定为正确运行的组件（**可信计算基**，TCB），以及关于环境的假设。

**漏洞**是让模型内的对手得以违反某个目标的弱点；**威胁**是潜在的违反；**攻击**是利用漏洞的企图；**控制措施**或**对策**削减某个漏洞或其后果。
:::

**可信计算基**值得特别注意：它是一切其失效可能破坏策略的东西。对成绩系统而言，它包括 web 应用、数据库、它们底下的操作系统、管理员，以及产出这套软件的构建系统。这里的"可信"指*被依赖*，而非*值得信赖*。把 TCB 做小是设计者能做的最有效的事情之一，因为 TCB 之外的一切即便失效也无害。

对手的能力是思考最集中之处。几个标准模型在整个课程中反复出现：

- **网络攻击者**（1983 年的 Dolev–Yao 模型）：能读取、删除、修改、重放网络上的任意消息并注入消息，但攻不破密码学。密码协议就是针对这种对手设计的（[[cryptography/protocols]]）；一个能注入却不能读取的**离路**（off-path）对手更弱，TCP 序号防的就是他（[[networks/tcp-congestion]]）。
- **恶意用户**：拥有账号、试图超出自己权限的合法用户——想改成绩的学生。访问控制（[[security/access-control]]）就是针对这种对手设计的。
- **恶意输入**：任何能向系统发送待解析数据的人——一个 web 表单、一个上传的文件、一封邮件。内存安全与注入漏洞（[[security/memory-safety]]、[[security/web-security]]）就是这样被利用的。
- **内部人员**：拥有合法权限的管理员或雇员。主要防御是职责分离与审计日志。
- **物理攻击者**：偷走笔记本电脑或接上一个设备。对策是磁盘加密与防篡改。

**攻击面**是对手能够提供输入或观察行为的所有点的集合：每个网络端口、每种被解析的文件格式、每个系统调用、每个用户界面字段。缩减它——关闭端口、删减功能、不去解析不需要解析的东西——往往比为它加上保护更省钱。

::: warning 没有威胁模型的"我们的系统是安全的"
"某系统是安全的"是关于一族对手的声明。"用了 AES-256 加密"对一个能从配置文件里读出密钥、给服务台打电话、或利用持有解密数据的 web 服务器中漏洞的对手什么也没说。每当看到一条安全声明，要问：对谁安全、防什么行为、假设了什么？反过来说，不要因为一个威胁模型排除了某个对手就摒弃它——一切有用的模型都排除了一些东西——但要检查排除是否已写明、能否接受。
:::

### 攻击树

**攻击树**（Schneier，1999）把对手通向目标的诸途径组织起来。

::: definition 攻击树 {#def-attack-tree}
**攻击树**是一棵有根树：根是对手的目标，内部结点是两类子目标——**OR 结点**只要*任一*子结点达成即达成，**AND 结点**须*全部*子结点达成才达成。叶是基本攻击步骤，各标注若干属性，如对对手的代价 $c(\ell)$ 或成功概率。结点 $v$ 的**代价**递归定义如下：
$$
c(v) = \begin{cases} c(\ell) & \text{若 } v = \ell \text{ 为叶，} \\ \min_{u \text{ 取遍 } v \text{ 的子结点}} c(u) & \text{若 } v \text{ 为 OR 结点，} \\ \sum_{u \text{ 取遍 } v \text{ 的子结点}} c(u) & \text{若 } v \text{ 为 AND 结点。} \end{cases}
$$ {#eq-tree-cost}
:::

::: proposition 最廉价的攻击 {#prop-cheapest}
假设对手执行一组叶的代价是它们代价之和，且不同子树中的叶互不相同。则 $c(\text{根})$ 是达成根的叶集的最小总代价，而自底向上求值 [[#eq-tree-cost]] 的时间与树的大小成线性。
:::

::: proof
对树作结构归纳，证明 $c(v)$ 是达成 $v$ 的叶集的最小代价。对叶，这就是它自身的代价。对 OR 结点 $v$，一个集合达成 $v$ 当且仅当它达成某个子结点 $u$，故 $v$ 的最廉价集合就是各子结点最廉价集合中最廉价的那个：由归纳假设，即 $\min_u c(u)$。对 AND 结点，一个集合达成 $v$ 当且仅当它达成每个子结点。由于各子结点的子树叶子互不相同，达成所有子结点的集合是一些集合 $S_u$ 的不交并（$S_u$ 达成子结点 $u$），其代价为 $\sum_u \text{代价}(S_u)$，逐项分别取最小即整体最小：$\sum_u c(u)$。每个结点恰访问一次，所做工作与其子结点数成正比，故总时间为线性。
:::

当同一个叶出现在多个子树中（在下面的例子里，"工作时间后进入办公室"服务于两个分支），递归可能把它算两次而高估代价；此时精确的最小值是一个更难的优化问题。实践中树是一件思考工具、数字只是粗略估计，所以这没有看上去那么要紧——但值得知道一次计算作了哪个假设。

::: example 试卷的攻击树 {#ex-attack-tree}
对手想在考前读到一份试卷。试卷已打印，锁在教师办公室的柜子里；文件在教师的账号里，该账号需要口令与第二因子。对手可以（代价为粗略估计，单位任意）：工作时间后进入办公室（$100$）；撬开柜锁（$300$）或在桌子里找到钥匙（$50$）；得知教师的口令（$400$）并破解第二因子（$1000$）；或发现办公室的 PC 处于登录状态（$150$，须先进入办公室）；或贿赂打印室的员工（$500$）。求最廉价的攻击，并观察两项对策的效果。
::: solution
OR 根下有三个分支：*偷打印件* = AND(进办公室, OR(撬锁, 找钥匙))；*读文件* = OR(AND(口令, 第二因子), AND(进办公室, PC 未锁))；*贿赂*。自底向上：OR(撬锁, 钥匙) $= \min(300, 50) = 50$，故打印件的代价是 $100 + 50 = 150$。远程登录要 $400 + 1000 = 1400$，无人看管的 PC 要 $100 + 150 = 250$，故读文件的代价是 $250$。根的代价是 $\min(150, 250, 500) = 150$。一个小程序可以代劳：

```python
# 攻击树：("leaf", 名称, 代价) | ("and", 名称, [子结点]) | ("or", 名称, [子结点])
def cheapest(node):
    """返回达成 node 的最廉价途径的 (代价, 叶列表)。"""
    kind, name, x = node
    if kind == "leaf":
        return x, [name]
    results = [cheapest(child) for child in x]
    if kind == "or":                      # 攻击者挑最便宜的子结点
        return min(results)
    cost = sum(c for c, _ in results)     # "and"：每个子结点都少不了
    return cost, [leaf for _, leaves in results for leaf in leaves]

enter = ("leaf", "enter office after hours", 100)
tree = ("or", "read exam paper", [
    ("and", "steal printed copy", [
        enter,
        ("or", "open cabinet", [("leaf", "pick lock", 300),
                                ("leaf", "find key in desk", 50)])]),
    ("or", "read the file", [
        ("and", "log in remotely", [("leaf", "learn password", 400),
                                    ("leaf", "defeat second factor", 1000)]),
        ("and", "use unattended PC", [enter,
                                      ("leaf", "PC left unlocked", 150)])]),
    ("leaf", "bribe print-room staff", 500)])
print(cheapest(tree))
```

```console
$ python3 tree.py
(150, ['enter office after hours', 'find key in desk'])
```

若教师把钥匙随身带着（删去 $50$ 那个叶），打印件的代价变为 $100 + 300 = 400$，最廉价的攻击成了无人看管的 PC 的 $250$。若 PC 也自动锁屏，最廉价的现在是 $\min(400, 1400, 500) = 400$。两项廉价的规程控制把对手的代价从 $150$ 抬到 $400$；昂贵的那项技术控制——第二因子——对最廉价的攻击毫无作用，因为它保护的那条分支从来不是最弱的。对手总走最廉价的路，花在非最弱分支之外的力气都是浪费。
:::
:::

### STRIDE

攻击树从目标出发。**STRIDE** 由洛伦·科恩费尔德（Loren Kohnfelder）与普拉里特·加尔格（Praerit Garg）1999 年在微软提出，从系统出发：画出外部实体、进程、数据存储以及其间数据流的**数据流图**，标出数据跨越的**信任边界**，再对每个元素询问六类威胁，每一类是某个性质的违反。

| 威胁 | 被违反的性质 | 成绩系统中的例子 | 典型控制措施 |
|---|---|---|---|
| **S** 假冒 | 真实性 | 冒充教师登录 | 认证（[[security/authentication]]） |
| **T** 篡改 | 完整性 | 在传输中或数据库中改动成绩 | MAC、签名、访问控制 |
| **R** 抵赖 | 不可否认性 | 教师否认改过成绩 | 审计日志、签名 |
| **I** 信息泄露 | 机密性 | 偷读其他学生的成绩 | 加密、访问控制 |
| **D** 拒绝服务 | 可用性 | 出分日灌爆服务器 | 限流、容量、过滤 |
| **E** 权限提升 | 授权 | 学生获得教师权限 | 最小特权、输入校验、隔离 |

并非每个威胁适用于每个元素。在微软的"STRIDE per element"表中：外部实体对应 S 与 R；进程对应全部六种；数据存储对应 T、I、D（当存储是日志时还有 R）；数据流对应 T、I、D。

::: example 成绩系统的 STRIDE {#ex-stride}
图中有一个外部实体（学生的浏览器）、一个进程（web 应用）、一个数据存储（成绩数据库）和两条数据流（浏览器到应用、应用到数据库），浏览器与应用之间有一条信任边界。逐元素列出 STRIDE 产生的威胁，并挑三个来讨论。
::: solution
浏览器贡献 S 与 R（$2$ 个威胁），应用全部六种（$6$），数据库 T、I、D（$3$），每条数据流 T、I、D（$3 \times 2 = 6$）：共 $17$ 个威胁。举三个例子：*假冒浏览器*——有人用偷来的学生口令登录，对策是良好的认证与多因子登录；*浏览器–应用数据流上的信息泄露*——成绩在网络线路上被读到，对策是 TLS；*应用中的权限提升*——学生改一个隐藏表单字段后发出改成绩的请求，对策是对每个请求都在服务器上检查授权，绝不信任客户端。最后一条是开发中最容易漏掉的，也是"访问控制失效"自 2021 年起高居 OWASP web 风险 Top 10 榜首的原因（[[security/web-security]]）。STRIDE 不给威胁排序；那是风险估计的工作。
:::
:::

## 风险

安全预算有限，威胁必须分先后。经典的定量方法对每个威胁估计**单次损失期望值**（single loss expectancy，SLE，一次事故的成本）与**年化发生率**（annualised rate of occurrence，ARO），再把两者相乘得到**年度损失期望值**
$$
\text{ALE} = \text{SLE} \times \text{ARO}.
$$ {#eq-ale}
按这种观点，一项控制措施若带来的 ALE 降幅超过其年成本，就值得买。

::: example 这项控制值得买吗？ {#ex-ale}
一次客户数据库泄露估计耗资 $£200{,}000$（通知、罚款、流失业务），约每十年发生一次。一套改进的监控与打补丁服务每年 $£8{,}000$，估计能把发生率降到每五十年一次。值得买吗？
::: solution
之前：$\text{ALE} = 200{,}000 \times 0.1 = £20{,}000$。之后：$200{,}000 \times 0.02 = £4{,}000$。该控制以每年 $£8{,}000$ 的成本把预期损失每年减少 $£16{,}000$，净收益每年 $£8{,}000$。注意这有多敏感：若之前的真实发生率是每四十年一次（$\text{ARO} = 0.025$），降幅就只有 $£1{,}000$，这项控制就赔本——而没人能把发生率估计到四倍以内。
:::
:::

这样的数字不过是穿上算术外衣的猜测；有经验的人主要用它来逼出关于可能性与影响的明确推理，往往采用粗粒度等级（低/中/高）排成**风险矩阵**。响应的几个类别比数字更可靠：一个风险可以被**缓解**（增加控制措施）、**转移**（保险、合同）、**规避**（不提供该功能、不收集该数据）或**接受**（记录在案，继续前进）。规避被低估了：从未收集的数据不会泄露。

**经济学**也塑造风险。罗斯·安德森（Ross Anderson）2001 年的文章《为什么信息安全难以做好——一个经济学的视角》（"Why information security is hard — an economic perspective"）指出，许多失效是激励的失效：能修好问题的一方往往不是受害的一方（软件厂商不承担客户的泄露成本）；买家难以度量安全，因而无从奖赏它；网络效应奖赏先出货、后补安全。单靠优秀的工程修不好坏的激励，这正是监管与责任属于安全一部分的原因之一。

## 设计原则

1975 年，杰罗姆·萨尔策（Jerome Saltzer）和迈克尔·施罗德（Michael Schroeder）在论述 Multics 系统时列出了保护机制的八条设计原则。半个世纪过去，它们仍是安全设计最好的简明指南。

::: definition 萨尔策–施罗德原则 {#def-saltzer-schroeder}
1. **机制的经济性**：让设计尽可能简单、尽可能小，以便检查它并找出其错误。
2. **故障安全的默认**：把访问决定建立在许可而非排除之上；默认是没有访问权，出错时应拒绝而非放行。
3. **完全仲裁**：对每个对象的每次访问都检查权限，而不只查第一次；缓存的决定不可盲用，要考虑它们何时失效。
4. **开放设计**：设计本身不应是秘密；安全应依赖于密钥或口令，而非攻击者的无知。
5. **特权分离**：在可行之处，要求两个独立条件（两把钥匙、两个人）才授予访问。
6. **最小特权**：每个程序和每个用户都应以完成任务所需的最小特权集运行。
7. **最少的公共机制**：尽量减少多个用户共享的机制，因为每个共享机制都是用户之间一条潜在的通道。
8. **心理可接受性**：人机界面必须易用，用户才会常规地、正确地使用这些保护。

他们还提到两条自认对计算机适用性不完整的原理：**工作因子**（比较绕过一个机制的成本与攻击者的资源）和**失陷记录**（即便无法防止失陷，也要记录下失陷已经发生）。
:::

每条原则都点名的确是一整族后来的技术。**机制的经济性**是 TCB 应当做小的原因，也是微内核或虚拟机监控器比宏内核更容易信任的原因（[[operating-systems/os-structure]]）。**故障安全的默认**是防火墙的"默认拒绝"规则（[[security/network-security]]），也是输入白名单比危险输入黑名单更安全的原因。**完全仲裁**就是 [[security/access-control]] 中的引用监视器，而它的违反就是检查时刻到使用时刻的漏洞。**开放设计**即柯克霍夫（Kerckhoffs）1883 年在密码学中提出的原则。**特权分离**是多因子认证与双人授权。**最小特权**解释了 web 服务器为何在绑定 443 端口后放弃 root，以及浏览器为何把每个网站跑在一个沙箱化的进程里。**最少的公共机制**说明了共享缓存为何危险：2018 年的 Spectre 与 Meltdown 攻击经由处理器高速缓存与推测执行——本来是给从不打算相互通信的程序共享的机制——泄露了秘密。**心理可接受性**开创了可用安全领域：阿尔玛·惠滕（Alma Whitten）与道格·泰加尔（Doug Tygar）1999 年的研究《为什么强尼不会加密》（"Why Johnny can't encrypt"）发现，多数参加者没能在 90 分钟内正确使用一个设计良好的邮件加密程序。

::: example 把原则用于一个备份脚本 {#ex-principles}
一个脚本每晚由 `cron` 以 `root` 身份运行，把成绩数据库复制到一台远程服务器。它用写在脚本里的口令登录远程服务器；若 `/tmp` 里存在一个配置文件，它就拿来用。指出被违反的原则并改正。
::: solution
**最小特权**：脚本只需要读一个数据库文件、发起一个网络连接；以 `root` 运行却把整台机器交给了它。应让它在专门的非特权账号下运行，该账号只能读数据库转储。**故障安全的默认**与**完全仲裁**：从人人可写的 `/tmp` 读配置文件，等于任何本地用户都能改变备份的去向；配置只能从仅备份账号可写的目录读取，且其权限有误时拒绝运行。**开放设计**并不反对公开脚本，但把口令存在脚本里，意味着任何读到脚本的人都能登录；应使用一把在远端只授权做这一件事的密钥（对 SSH 来说，是限定于单条命令的密钥），使这个秘密授予的不超过任务所需——这又是最小特权。**失陷记录**：为每次运行记录日志，备份失败或目标改变时发出告警。注意这一个弱点（`/tmp` 文件）本可让任何本地用户得到 `root`，因为脚本把不可信输入与过大特权结合在了一起——这正是多数权限提升漏洞背后的模式。
:::
:::

### 纵深防御

没有哪个机制是完美的，于是系统把它们分层：先是防火墙，再是认证，再是授权，再是存储数据加密，最后是监控。这个思想叫**纵深防御**，在一个理想化假设下其收益可以被量化。

::: proposition 分层防御 {#prop-layers}
假设一次攻击必须突破 $k$ 层防御，第 $i$ 层被突破的概率为 $p_i$，且各层相互独立。则攻击成功的概率为 $\prod_{i=1}^k p_i$。又设以概率 $c$ 发生一次**共因**失效，一次性突破所有层（否则各层独立失效），则攻击成功的概率为 $c + (1 - c)\prod_{i=1}^k p_i \ge c$。
:::

::: proof
攻击成功当且仅当每一层都被突破。由独立性，$k$ 个事件全发生的概率是其概率之积。在第二个模型中，按共因事件是否发生作条件：若发生（概率 $c$）攻击成功；若不发生（概率 $1 - c$）则按第一部分以概率 $\prod p_i$ 成功。全概率公式给出这个和；因第二项非负，它不小于 $c$。
:::

三层各以十分之一的概率被突破时，独立假设下得 $10^{-3}$。但若一百分之一的情形下存在一个原因同时突破所有层——同一个被盗的管理员密码能打开防火墙、服务器和数据库；三者跑着同一个有漏洞的库——概率就是 $0.01 + 0.99 \times 0.001 \approx 0.011$，差了十一倍，而且再加多少层也压不到 $0.01$ 以下。只有各层*相异*时分米才有用：不同的机制、不同的代码、不同的凭据、不同的管理员。

caption: 一次攻击突破 $k$ 层防御的概率（[[#prop-layers]]），横轴是层数 $k$。各层独立时（第一条曲线），每多一层就把概率乘以 $p$。把共因概率 $c$ 调大，第二条曲线便逐渐压平到直线 $y = c$ 上：一旦各层共享弱点，再加更多同类的层几乎毫无价值。令 $c = 0$ 可见两条曲线重合。
:::

::: quiz
下列哪项是*最少的公共机制*的最好例子？

- [ ] 登录既要求口令又要求硬件密钥。
- [x] 云服务给每位客户一台独立虚拟机，而不是在共享的一台服务器上开各自账号。
- [ ] 公开一个加密程序的源代码。
- [ ] 拒绝一切未被明确允许的网络连接。
::: solution
最少的公共机制要求把用户共享的东西最小化。独立的虚拟机只共享虚拟机监控器和硬件，而一台服务器上的各账号共享内核、文件系统、临时目录和每一个守护进程（[[operating-systems/virtualisation]]）。其余三个选项分别体现的是特权分离、开放设计与故障安全的默认。
:::
:::

### 以隐蔽求安全

开放设计原则常被误读。它不是说秘密不好：密钥和口令就是秘密。它说的是*设计本身*不能是秘密，理由有三：设计会泄露（通过逆向工程、离职员工或被盗文档），而泄露之后又改不起；秘密的设计无法交由能够发现其缺陷的人来评审；防御者也无从知道这个秘密是否仍是秘密。密钥则相反：短小、随机、可更换。隐藏细节——不登软件版本、不公布网络拓扑——也许能抬高一点对手的工作因子，但只能作为一个即使被完全了解仍然安全的设计之上的一层。安全完全建立在秘密算法之上的系统记录很差：DVD 的专有加密（CSS）在 1999 年被逆向工程后数周内即遭破解，GSM 移动通信系统的秘密密码被重建后也被发现脆弱。

### 人与流程

系统由人运维，而最廉价的攻击往往在人身上。钓鱼、向服务台冒充身份、写在显示器上的口令——这些不是用户的失败，而是设计的失败：它们要求人做人力所不能可靠做到的事——记住几十个随机串、逐字符检查 URL，或在看惯了上百个假警报之后分辨出真正的警告。好的设计让安全的操作成为容易的操作：口令管理器，以及替用户核对网站身份的硬件密钥（[[security/authentication]]）；无需配置的安全默认；少到人们还愿意当真的警告。组织还需要*流程*：打补丁、备份、密钥管理、事件响应（[[security/malware]]），以及从失败中学习而不责怪个人的习惯。

::: history
现代领域始于美国国防部关于在不同保密等级用户之间共享计算机的报告。威利斯·韦尔（Willis Ware）为国防科学委员会任务组撰写的《计算机系统安全控制》（*Security Controls for Computer Systems*，1970）分析了这一问题；詹姆斯·安德森（James P. Anderson）的《计算机安全技术规划研究》（*Computer Security Technology Planning Study*，1972）提出了引用监视器。巴特勒·兰普森（Butler Lampson）的《保护》（"Protection"，1971）定义了访问控制矩阵，大卫·贝尔（David Bell）和伦纳德·拉帕杜拉（Leonard LaPadula）的模型（1973）把军事机密性形式化。杰罗姆·萨尔策（Jerome Saltzer）和迈克尔·施罗德（Michael Schroeder）的《计算机系统中信息的保护》（"The protection of information in computer systems"，*Proceedings of the IEEE*，1975）给出了本章的设计原则。美国《可信计算机系统评价准则》（"橙皮书"，1983 年发布，1985 年成为标准）按系统提供的保证为系统定级，国际上由通用准则（Common Criteria，ISO/IEC 15408，1999）接替。作为工程实践的威胁建模始于 STRIDE（微软的科恩费尔德（Kohnfelder）和加尔格（Garg），1999）与布鲁斯·施奈尔（Bruce Schneier）的攻击树（1999）。罗斯·安德森（Ross Anderson）的《安全工程》（*Security Engineering*，第一版 2001，第三版 2020）和他 2001 年关于经济学的文章，把主题从机制扩展到系统、人和激励。
:::

## 后续内容

课程的其余部分逐层应用这些思想。[[security/authentication]] 确立来者是谁——STRIDE 的 S。[[security/access-control]] 决定其可以做什么，其中引用监视器是完全仲裁的化身，机密性与完整性策略则有形式模型。[[security/memory-safety]] 与 [[security/web-security]] 研究恶意输入变成权限提升所凭借的漏洞及其缓解措施。[[security/network-security]] 把纵深防御用于网络，[[security/malware]] 研究防御失效后会发生什么以及如何响应，[[security/privacy]] 转向数据被系统保管的人们，[[security/secure-development]] 把威胁建模与测试纳入软件的制造方式。贯穿始终的密码学在 [[cryptography]]；安全工作的伦理——披露、只测试你获准测试的系统——在 [[software-engineering/professional-ethics]]。

::: summary
- 安全意味着在智能对手面前维护 **机密性、完整性与可用性**（[[#def-cia]]）以及相关目标（真实性、可追责性、不可否认性）。目标之间互相冲突，正确的平衡取决于系统。
- 把**策略**（哪些状态是授权的）与执行它的**机制**分开；机制若不进入任何非授权状态则是安全的，若允许每一个授权状态则是精确的（[[#def-mechanism]]）。
- 每个安全声明都是相对于一个**威胁模型**而言的：资产、对手及其能力、**可信计算基**（[[#def-threat-model]]）。把 TCB 和攻击面做小。
- **攻击树**找出对手最廉价的途径（[[#prop-cheapest]]）；花在并非最弱的分支上的力气是浪费的。**STRIDE** 沿数据流图逐元素询问假冒、篡改、抵赖、信息泄露、拒绝服务与权限提升。
- **风险**综合可能性与影响（ALE $=$ SLE $\times$ ARO）；数字虽然粗略，但缓解、转移、规避、接受是一套有用的规程。
- **萨尔策–施罗德原则**——机制的经济性、故障安全的默认、完全仲裁、开放设计、特权分离、最小特权、最少的公共机制、心理可接受性——至今仍在指导设计。
- **纵深防御**只有在各层独立失效时才成倍增加攻击者的困难；共因失效给被攻破的概率设了下限（[[#prop-layers]]）。
:::

## 习题

::: exercise 判断目标 {level=1}
为每个事件指出主要被违反的安全目标（机密性、完整性或可用性）：(a) 勒索软件加密了一家医院的病历；(b) 一台磁盘未加密、存有工资数据的笔记本被盗；(c) 攻击者改掉了供应商发票上的银行账号；(d) 僵尸网络在开票期间灌爆一个售票网站。
::: solution
(a) 可用性——病历还在、内容未变，只是谁也用不了（如今的勒索团伙常常先偷数据，于是又添上机密性）。(b) 机密性。(c) 完整性（具体说是付款信息的真实性）。(d) 可用性。
:::
:::

::: exercise 数 STRIDE 威胁 {level=1 check="31"}
一个数据流图有两个外部实体、两个进程、一个数据存储和四条数据流。按 STRIDE per element——实体用 S、R；进程用全部六种；存储与数据流用 T、I、D——列出多少个威胁？（填入数字。）
::: solution
实体给出 $2 \times 2 = 4$，进程 $2 \times 6 = 12$，存储 $3$，数据流 $4 \times 3 = 12$，合计 $4 + 12 + 3 + 12 = 31$。威胁数随图增长极快，这就是团队优先处理跨越信任边界的元素的原因。
:::
:::

::: exercise 年度损失期望 {level=1 check="12400"}
一家公司全境每年被盗 $0.6$ 台存有客户数据的笔记本；磁盘未加密时，每次失窃的通知与罚款为 $£25{,}000$，加密时为 $£1{,}000$（硬件本身）。磁盘加密每年管理成本 $£2{,}000$。加密使年度损失期望扣除成本后净减少多少？（以英镑填入数额。）
::: solution
未加密时 $\text{ALE} = 0.6 \times 25{,}000 = £15{,}000$。加密时 $\text{ALE} = 0.6 \times 1{,}000 = £600$。降幅为 $£14{,}000$，扣除 $£2{,}000$ 成本后每年净收益 $£12{,}400$。
:::
:::

::: exercise 是哪条原则？ {level=2}
为每条说明最能体现或被违反的萨尔策–施罗德原则，并指出是遵循还是违反：(a) 一个 web 应用在页面加载时检查用户角色，但提交页面上的表单时不检查；(b) 发射导弹需要两名军官同时转动钥匙；(c) 手机操作系统只允许每个应用访问它申请过、用户批准过的文件和传感器；(d) 一台路由器出厂自带管理员口令 `admin`；(e) 一个系统在每次登录时打印一条安全警告，用户不读就点掉。
::: solution
(a) 完全仲裁，被违反：提交也是一次访问，攻击者可以不加载页面直接提交表单。(b) 特权分离，遵循。(c) 最小特权，遵循。(d) 故障安全的默认，被违反——默认配置向任何知道公开口令的人敞开；安全的产品出厂带每台设备唯一的口令，或强制首次使用时修改。(e) 心理可接受性，被违反：每次都显示的警告只会训练用户无视它。
:::
:::

::: exercise 攻击树中共享的叶 {level=2 check="300"}
在 [[#ex-attack-tree]] 中，"工作时间后进入办公室"出现在两个分支里。假设对手想*同时*读到文件并偷到打印件（这两个分支之上是一个 AND 结点），且进办公室两个目标共用一次。真正的最小代价是多少？若共享的叶被计两次，[[#eq-tree-cost]] 给出什么？（填入真正的最小值。）
::: solution
打印件：进入（$100$）+ 钥匙（$50$）。文件：远程登录（$1400$）或无人看管的 PC（进入 $100$ + $150$）。共享进入后，组合"进入、钥匙、PC 未锁"的代价是 $100 + 50 + 150 = 300$。递推式算出 $c(\text{打印件}) + c(\text{文件}) = 150 + 250 = 400$，把进入算了两次。故真正的最小值是 $300$；递推式高估了 $100$，恰是共享叶重复计算一次的代价。
:::

::: exercise 带相关性的纵深防御 {level=2 check="0.01099"}
三层各以概率 $0.1$ 被突破；以概率 $0.01$ 一个共因突破全部三层。用 [[#prop-layers]] 计算攻击成功的概率。（填入精确值。）
::: solution
$c + (1 - c)p^3 = 0.01 + 0.99 \times 0.001 = 0.01 + 0.00099 = 0.01099$，约为各层独立时值 $0.001$ 的十一倍。
:::

::: exercise 机制组合失去精确性时 {level=3}
[[#prop-combine]] 假设同时运行两个机制把系统限制到 $R_1 \cap R_2$。(a) 证明在两个机制下都可到达的状态集总是 $R_1 \cap R_2$ 的子集，并给出一个小状态机，即使 $M_1$ 对 $Q_1$ 精确、$M_2$ 对 $Q_2$ 精确，它也是真子集。(b) 解释为什么真实的组合甚至比其中任一部分更不安全。
::: solution
(a) 把每个机制建模为一组它阻断的转移，并设组合阻断其并集。任何被组合允许的运行时都被单个机制各自允许，所以它到达的每个状态都既在 $R_1$ 中也在 $R_2$ 中。要构造真子集，取状态 $s_0$（起点）、$t$、$t'$、$s$，转移为 $s_0 \to t \to s$ 和 $s_0 \to t' \to s$。设 $M_1$ 阻断 $s_0 \to t'$，$M_2$ 阻断 $s_0 \to t$。则 $R_1 = \{s_0, t, s\} = Q_1$，$R_2 = \{s_0, t', s\} = Q_2$，各自对自己的策略精确，而 $R_1 \cap R_2 = \{s_0, s\}$。但两者合起来阻断了 $s_0$ 的两个出边，于是只有 $\{s_0\}$ 可达：授权状态 $s \in Q_1 \cap Q_2$ 丢了。可达性是路径的性质而非状态的性质，所以对各机制的可达集求交会高估组合允许的行为。（一个现实例子：一条规则只允许已验证账户转账，另一条只允许处于首周试用期的账户转账；分开看，新客户最终都能转账，合起来则永远不能。）

(b) 该命题假设每个机制只阻断转移。真实的安全组件还会增加代码——它解析输入、持有凭据、以特权运行——而它的漏洞会加入*新的*转移。一个解析每个分组的入侵检测系统、一个解释日志字符串的日志库（Log4Shell）、一个运行在内核里的终端代理，都可能成为入口，于是组合的可达集会包含原先两个系统都到不了的状态。每个机制都要同时作为攻击面来评判。
:::

::: exercise 带概率的攻击树 {level=3}
不给叶标注代价，而是给每个叶 $\ell$ 标注对手在该步成功的概率 $q(\ell)$，各步相互独立，并设对手尝试每一个叶。给出 OR 结点与 AND 结点被达成概率的递归公式，在子树叶子集互不相交的假设下证明它们，并对 [[#ex-attack-tree]] 的根求值——把两个"进入办公室"的叶当作独立的尝试，概率为：进入 $0.5$，撬锁 $0.2$，找到钥匙 $0.3$，口令 $0.1$，破解第二因子 $0.05$，PC 未锁 $0.4$，贿赂 $0.1$。
::: solution
对 AND 结点，所有子结点都必须成功；由于叶子集不相交，各子结点的成功事件依赖互不相交的独立叶子集，因而相互独立，故 $q(v) = \prod_u q(u)$。对 OR 结点，结点失败当且仅当每个子结点都失败，故 $q(v) = 1 - \prod_u (1 - q(u))$。两者都可仿照 [[#prop-cheapest]] 以结构归纳证明，只须把代价的可加性换成子结点的独立性。

求值：打开柜子 $= 1 - 0.8 \times 0.7 = 0.44$；偷打印件 $= 0.5 \times 0.44 = 0.22$。远程登录 $= 0.1 \times 0.05 = 0.005$；无人看管的 PC $= 0.5 \times 0.4 = 0.2$；文件 $= 1 - 0.995 \times 0.8 = 0.204$。根 $= 1 - (1 - 0.22)(1 - 0.204)(1 - 0.1) = 1 - 0.78 \times 0.796 \times 0.9 = 1 - 0.558792 = 0.441208 \approx 0.44$。"对手尝试一切（且第一次失手被抓不会使其却步）"的假设使这是一个上界估计；若共享的进入叶真实存在，事件便相关，公式只是近似。
:::
