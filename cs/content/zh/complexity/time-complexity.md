假设为使任何学生都不会在同一时刻有两场考试，你必须为 60 场大学考试排出时间表，并决定把考试分配到 10 个时段的每一种安排都试一遍。这样的安排共有 $10^{60}$ 种。一台每秒检验十亿种的计算机大约需要 $3 \times 10^{43}$ 年，远超宇宙的年龄。再假设你要做的只是给 60 个考试代码排序：任何排序算法都只要几微秒就完成了。这两个问题都是*可判定的*，所以 [[theory-of-computation]] 对它们之间的差别无话可说；然而一个很容易，另一个——据任何人所知——在规模面前毫无出路。

**计算复杂性**研究的正是这种差别。它不问一个问题*能否*由算法求解，而问它的一切算法各*需要多少*时间、内存、随机性或其他资源。其核心组织性概念是**复杂性类**：能在给定资源界内求解的一切问题的集合。本章作为开篇，先定下度量标尺。我们在图灵机上度量时间，考察这一度量如何依赖——以及更重要的是，如何*不*依赖——模型的细节，并定义可按多项式时间求解的问题类 $\mathsf{P}$；复杂性理论把它当作"可有效求解"的形式化对应物。本课程其余部分大体上研究的正是那些看来落在它之外的问题。

## 度量运行时间

与 [[theory-of-computation/turing-machines#def-recognisable]] 中一样，我们使用判定器：一个问题是一门语言 $L \subseteq \Sigma^*$，它的算法是一台在每个输入上都停机、且恰好接受 $L$ 的各串的图灵机。时间就是移动步数。

::: definition 运行时间 {#def-running-time}
设 $M$ 是一台在每个输入上都停机的确定图灵机。$M$ 的**运行时间**（或**时间复杂度**）是函数 $t\colon \N \to \N$，其中 $t(n)$ 是 $M$ 在长度为 $n$ 的任一输入上所作移动步数的*最大值*。我们称 $M$ **运行时间为** $t(n)$，并称 $M$ 是一台 $t(n)$-**时间**机。
:::

这一定义内含三个选择。第一，它是**最坏情况**的：一个长度为 $n$ 的坏输入就足以使 $t(n)$ 很大。平均情况复杂度确实存在，但它需要输入上的一个概率分布，而让我们能够安全地组合算法的正是最坏情况保证。第二，时间是**输入长度** $n$ 的函数，而不是输入"值"的函数；我们在 [[#sec-encoding]] 回到这一点。第三，我们通常只关心 $t$ 的**增长率**，用 [[data-structures/asymptotic-analysis#def-asymptotic]] 的渐近记号书写：作 $3n^2 + 7n + 4$ 次移动的机器运行时间为 $O(n^2)$。

::: definition 时间复杂度类 {#def-time}
对函数 $t\colon \N \to \R^+$，**时间复杂度类** $\mathsf{TIME}(t(n))$ 是由某台 $O(t(n))$ 时间的确定多带图灵机判定的语言之集合。
:::

定义里的 $O(\cdot)$ 很要紧：借助"线性加速"论证（扩大带符号集，使一个格子容纳原来的几个格子），常数因子总可以去掉，因此区分 $\mathsf{TIME}(n^2)$ 与 $\mathsf{TIME}(5n^2)$ 意义不大。定义中我们还使用**多带**机。马上会看到，带的数目确实会改变运行时间，但改变至多多项式倍。

### 一个问题，三种运行时间

考虑 $A = \{0^k 1^k : k \ge 0\}$。在单带机上，显然的做法是把符号成对匹配。

::: algorithm 之字形匹配 {#alg-zigzag}
在输入 $w$ 上：

1. 扫描磁带；若有 $0$ 出现在 $1$ 的右边则**拒绝**。
2. 只要 $0$ 与 $1$ 都还有未划去者：划去最左边的未划去 $0$，右行到最左边的未划去 $1$ 并将其划去，然后返回最左端。
3. 若无未划去的符号则**接受**；否则**拒绝**。
:::

第 1 阶段耗 $O(n)$ 步。第 2 阶段的每次迭代划去两个符号并沿磁带往返一次，至多 $2n$ 步，而迭代至多 $n/2$ 次：合计 $O(n^2)$。于是 $A \in \mathsf{TIME}(n^2)$。若每扫一遍就划去剩下符号的一半，还能做得更好。

::: algorithm 折半法 {#alg-halving}
在输入 $w$ 上：

1. 扫描磁带；若有 $0$ 出现在 $1$ 的右边则**拒绝**。
2. 只要 $0$ 与 $1$ 都还有未划去者：
   1. 扫描磁带；若未划去符号的总数为奇数，则**拒绝**；
   2. 再扫描一遍，从第一个开始每隔一个划去一个未划去的 $0$，同样从第一个开始每隔一个划去一个未划去的 $1$。
3. 若无未划去的符号则**接受**；否则**拒绝**。
:::

::: theorem 折半法以 $O(n \log n)$ 时间判定 $A$ {#thm-halving}
[[#alg-halving]] 在一台单带图灵机上以 $O(n \log n)$ 时间判定 $A = \{0^k1^k\}$。
:::

::: proof
*时间。* 第 2 阶段的每一遍耗 $O(n)$ 步。若在第 2b 步之前还有 $z \ge 1$ 个 $0$ 未划去，则此后剩 $\lfloor z/2\rfloor$ 个，于是每次迭代未划去的 $0$ 的个数至少减半，对 $1$ 亦然。两个计数之一达到 $0$ 时循环停止，故循环至多运行 $1 + \log_2 n$ 次。总计 $O(n) + O(n)\cdot O(\log n) = O(n \log n)$。

*正确性。* 若第 1 阶段拒绝，则 $w \notin A$。否则 $w = 0^z1^o$；把 $z$ 与 $o$ 写成二进制。从第一个开始每隔一个划去一个符号，就是把计数 $c$ 换成 $\lfloor c/2\rfloor$，即删去 $c$ 的最低位。第 2a 步检验 $z + o$ 是否为奇数，亦即 $z$ 与 $o$ 当前的最低位是否不同。于是第 $i$ 次迭代把 $z$ 的第 $i$ 位与 $o$ 的第 $i$ 位相比较，不同则拒绝。若 $z = o$，则所有比较都通过，两个计数在同一次迭代达到 $0$，第 3 阶段接受。若 $z \ne o$，则它们在某一位上不同。或者循环在两个计数仍非零时到达该位并在该处拒绝，或者某一个计数先变为 $0$——此时另一个仍非零（所有更低位都相同，故两计数在某个更高位上不同），第 3 阶段拒绝。
:::

::: example 折半法在 $0^6 1^6$ 与 $0^{12} 1^4$ 上的运行 {#ex-halving}
对输入 $0^61^6$ 与 $0^{12}1^4$，追踪 [[#alg-halving]] 执行过程中未划去符号的计数。
::: solution
对 $0^61^6$：第一次迭代前 $(z, o) = (6, 6)$，总数 $12$ 为偶数，每隔一个划去后剩 $(3, 3)$；总数 $6$ 为偶数，剩 $(1, 1)$；总数 $2$ 为偶数，剩 $(0, 0)$。循环停止，第 3 阶段接受。三次迭代中 $z$ 的奇偶性依次为 $0, 1, 1$：正是 $6 = 110_2$ 的二进制位，从最低位开始。

对 $0^{12}1^4$：$(12, 4)$，总数为偶数，剩 $(6, 2)$；总数为偶数，剩 $(3, 1)$；总数 $4$ 为偶数，剩 $(1, 0)$。$1$ 已无剩余，循环停止；还剩下一个未划去的 $0$，第 3 阶段拒绝。这里 $12 = 1100_2$ 与 $4 = 0100_2$ 的三个最低位相同而第四位不同，两个计数恰恰在此分道扬镳。
:::
:::

有了**第二条磁带**，问题便成为线性的：把各 $0$ 抄到磁带 2 上，再让磁带 1 上的各 $1$ 与之匹配，两个读头同步移动。这是 $O(n)$ 步，故对双带机有 $A \in \mathsf{TIME}(n)$。单带上不可能好于 $O(n \log n)$：一个"穿越序列"论证（特拉赫滕布罗特（Trakhtenbrot）1964、亨尼（Hennie）1965、哈特马尼斯（Hartmanis）1968）表明，凡能由单带机以 $o(n\log n)$ 时间判定的语言都是正则的，而 $A$ 不是正则的（[[theory-of-computation/non-regular-languages]]）。

于是问题的*确切*运行时间取决于模型：同一语言分别有 $n$、$n\log n$ 与 $n^2$。不怎么变的，是运行时间是否为多项式。

### 模型到底有多要紧

::: theorem 多带与单带的时间 {#thm-multitape-time}
设 $t(n) \ge n$。每台 $t(n)$ 时间的多带图灵机都有一台与之等价、运行时间为 $O(t(n)^2)$ 的单带图灵机。
:::

::: proof
这正是 [[theory-of-computation/turing-machines#thm-multitape]] 中的时间界：单带并排放置 $k$ 条磁带的内容并标出各读头位置；每次被模拟的移动要对已用到的 $O(t(n))$ 个格子扫两遍，外加至多 $k$ 次长度 $O(t(n))$ 的平移，而移动共有 $t(n)$ 次。
:::

非确定性则是另一回事。若非确定图灵机 $N$ 的计算在每个输入上的每条分支都停机，则称 $N$ 是一台**判定器**；其运行时间 $t(n)$ 是长度 $n$ 的一切输入上*任一*分支的移动步数的最大值。

::: theorem 非确定时间的确定模拟 {#thm-ntm-time}
设 $t(n) \ge n$。每台 $t(n)$ 时间的非确定单带判定器 $N$ 都有一台与之等价、运行时间为 $2^{O(t(n))}$ 的确定单带判定器。
:::

::: proof
设 $b$ 为 $N$ 的任何转移中可选走法的最大数目。在长度为 $n$ 的输入上，每条分支长至多 $t(n)$，故计算树至多有 $b^{t(n)}$ 片叶子、至多 $\sum_{i=0}^{t(n)} b^i \le 2b^{t(n)}$ 个结点。[[theory-of-computation/turing-machines#thm-ntm]] 的三带模拟通过从根重放路径来访问每个结点，每个结点耗 $O(t(n))$ 步，此外把地址按短字典序推进还要 $O(t(n))$ 步。某条分支一接受它就接受；长度 $t(n)$ 的地址全部试完则拒绝——它能算出何时该停，因为树的深度至多 $t(n)$，且所有分支都停机。总时间为 $O(t(n)\, b^{t(n)}) = 2^{O(t(n))}$。把三条带合并成一条使其平方：$(2^{O(t(n))})^2 = 2^{O(t(n))}$。
:::

可见确定模型之间只差一个多项式，而我们所知的对非确定性的唯一一般模拟要付出指数代价。这个指数能否避免，正是 [[complexity/np]] 的主题。

## 编码与输入规模 {#sec-encoding}

运行时间是相对输入的*编码*长度来度量的，因此必须说明输入如何编码。图写成邻接矩阵或边表，公式写成符号串，数则**以二进制**（或任何 $\ge 2$ 的基数）写出。对有 $n$ 个顶点、$m$ 条边的图，邻接矩阵有 $n^2$ 位，边表有 $O((n + m)\log n)$ 位。这些长度彼此之间、以及与 $n + m$ 之间都是多项式相关的，所以对一种编码的多项式时间算法对另一种编码也是多项式时间的。凡与这些标准编码多项式相关的编码，我们都称为**合理的**；对象 $x$ 的编码记作 $\langle x\rangle$。

数恰恰是需要小心的地方。一个 $b$ 位的数 $N$ 的值可达 $2^b$。因此一个耗 $N$ 步的算法，在其输入长度上是指数级的。

::: example 试除法是指数的 {#ex-trial-division}
试除法逐一尝试满足 $2 \le d \le \sqrt{N}$ 的除数 $d$，以检验 $N$ 是否为素数。它在一个 $b$ 位的数上耗时多久？这对一个 2048 位的 RSA 模数意味着什么？
::: solution
候选除数约有 $\sqrt{N} \approx 2^{b/2}$ 个，而用学校里的竖式算术，一次 $b$ 位数的除法耗 $O(b^2)$ 次位运算。所以最坏情况下（$N$ 为素数时）运行时间是 $\Theta(2^{b/2})$ 次除法，对输入长度 $b$ 是指数级的——尽管 $\sqrt N$ 看起来像是"近乎线性"。对 $b = 2048$，除法次数为 $2^{1024} \approx 1.8 \times 10^{308}$：远非任何计算机所能胜任。（素性*可以*用多项式时间检验——见 [[#sec-practice]]——但不是靠试除法。）
:::
:::

倘若同一个数改用**一进制**写出，即写成 $1^N$，输入长度就是 $N$，试除法将耗多项式时间。问题并未变容易，只是输入变得指数级地长。这正是我们固定采用二进制编码的原因，也是为什么一个运行时间对输入的*数值*为多项式的算法——例如背包问题的 $O(nW)$ 动态规划（[[algorithms/dynamic-programming#thm-knapsack]]）——被称为**伪多项式**而非多项式。

## 类 P

::: definition 类 P {#def-p}
$$
\mathsf{P} = \bigcup_{k \ge 0} \mathsf{TIME}(n^k).
$$ {#eq-p}
$\mathsf{P}$ 是可由确定（单带或多带）图灵机以**多项式时间**判定的语言之类。
:::

由 [[#thm-multitape-time]]，此定义用单带还是多带无关紧要：运行时间为 $O(n^k)$ 的多带机可由单带机以 $O(n^{2k})$ 时间模拟，仍是多项式。对一切合理的确定模型同样成立。

::: theorem 类 P 的稳健性 {#thm-p-robust}
1. 多项式对加法、乘法与复合封闭。因此，一个调用多项式时间子程序多项式多次、且每次调用的输入长度都是多项式的算法，运行时间是多项式的。
2. 无论用单带图灵机、多带图灵机，还是寄存器只容纳 $O(\log n)$ 位字的随机存取机（或容纳任意整数、但每条指令按其触及的位数计费）来定义，$\mathsf{P}$ 都是同一个类。
3. $\mathsf{P}$ 不依赖于在输入的各合理编码之间所作的选择。
:::

::: proof
(1) 若 $p$ 与 $q$ 是次数分别为 $d$ 与 $e$ 的多项式，则 $p + q$、$pq$ 与 $p(q(n))$ 都是多项式，次数分别至多为 $\max(d, e)$、$d + e$ 与 $de$。设立一算法自身运行 $p(n)$ 步，且至多调用子程序 $p(n)$ 次。它能写出的每个中间结果长度至多 $n + p(n)$，于是每次调用的输入长度至多 $n + p(n)$，至多耗 $q(n + p(n))$。总计 $p(n) + p(n)\,q(n + p(n))$，是一个多项式。

(2) 单带与多带即 [[#thm-multitape-time]]。对随机存取机，两个方向都概述如下。随机存取机把每条磁带存成一个数组，即以每次移动常数开销模拟多带图灵机。反之，一台多带图灵机可以把 RAM 的内存作为磁带上（地址，值）对的表来保存，从而模拟一台运行 $t$ 步的对数代价 RAM。$t$ 步之后至多写了 $t$ 个寄存器，且每个地址与值的位数关于 $t$ 与 $n$ 是多项式的。于是一次 RAM 步骤——扫描表找到寄存器、对两个数做算术、更新表——耗费的图灵机移动步数是多项式的，$t$ 步的代价是关于 $t$ 与 $n$ 的多项式。

(3) 合理编码之间的转换耗多项式时间，且由定义各编码的长度多项式相关；套用 (1)。
:::

(2) 中的附带条件不可或缺。一台能以单位代价乘任意大整数的 RAM 与图灵机*并非*多项式等价：从 $2$ 出发平方 $k$ 次，仅 $k$ "步"就得到 $2^{2^k}$，一个 $2^k + 1$ 位的数（[[#ex-squaring]]）。关于 $\mathsf{P}$ 的一切结论都假设一次操作的代价反映其操作数的长度。

"$\mathsf{P}$ 恰好刻画了实践中可有效求解的问题"这一论断称为**科班–埃德蒙兹（Cobham–Edmonds）论题**。它与丘奇–图灵论题一样不是定理，而且是一种弱得多的断言。其长处在于稳健（该类不依赖模型）、封闭（多项式时间子程序可以复合）与经验：先被证明属于 $\mathsf{P}$ 的问题，随后往往能遇上次数很小的算法，往往是 $1$、$2$ 或 $3$ 次。

::: warning 多项式并不意味着快，指数并不意味着慢
一个 $O(n^{100})$ 算法属于 $\mathsf{P}$ 却毫无用处；一个最坏情况为指数的算法在实践中却可能非常出色。线性规划的单纯形法在 Klee–Minty 算例（1972）上耗指数时间，但在人们实际求解的问题上很快；现代 SAT 求解器也能轻松处理含数百万变量的工业公式（见 [[complexity/coping-with-hardness]]）。属于 $\mathsf{P}$ 是一种数学分类，不是性能保证。它的价值在于其稳健，以及*不*属于 $\mathsf{P}$（若能证明）所道出的持久事实：再先进的未来硬件、再巧妙的编码，也无法把一个指数时间问题拉进多项式的射程。
:::

另一个警示涉及**强（或扩展）丘奇–图灵论题**，它断言每一台物理上可实现的计算机都可由图灵机以至多多项式的减速模拟。量子计算机是对它的主要挑战：肖尔（Shor）算法（1994）在量子计算机上以多项式时间分解整数，而经典的多项式时间分解算法一无所知。大规模量子计算机能否建成是一个工程问题；分解问题在经典意义下是否困难则悬而未决；[[quantum-computing]] 将回到类 $\mathsf{BQP}$。

::: example 更快的计算机换来什么 {#ex-speedup}
三个算法分别耗 $n^2$、$n^3$ 与 $2^n$ 步，在今天的机器上各用一小时解得动规模 $n_0$ 的输入。现在买了一台快 $10$ 倍的机器，一小时里它们各能处理多大的输入？
::: solution
一小时内新机器可作 $10$ 倍的步数。对 $n^2$：由 $n^2 = 10\,n_0^2$ 得 $n = \sqrt{10}\,n_0 \approx 3.16\,n_0$。对 $n^3$：$n = 10^{1/3} n_0 \approx 2.15\,n_0$。对 $2^n$：由 $2^n = 10 \cdot 2^{n_0}$ 得 $n = n_0 + \log_2 10 \approx n_0 + 3.3$。若 $n_0 = 1000$，平方算法现在能达到约 $3162$，立方算法约 $2154$；而指数算法——本来就到不了 $1000$——不过从 $n_0$ 挪到 $n_0 + 3$。多项式算法随硬件*成倍*扩展，指数算法只能*加性*扩展。
:::
:::

## 属于 P 的问题

要证明一个问题属于 $\mathsf{P}$，我们像 [[theory-of-computation]] 其余部分那样分阶段描述一个算法，并论证两件事：每个阶段都可在合理的确定模型上用多项式时间实现，且阶段的数目是多项式的。由 [[#thm-p-robust]]，此后我们就可以就普通伪代码进行推理了。

### 可达性

$$
\mathit{PATH} = \{\langle G, s, t\rangle : G \text{ 是有从 } s \text{ 到 } t \text{ 的有向路径的有向图}\}.
$$

::: theorem PATH 属于 P {#thm-path}
$\mathit{PATH} \in \mathsf{P}$。
:::

::: proof
从 $s$ 出发运行广度优先搜索（[[algorithms/graph-search#alg-bfs]]），当且仅当 $t$ 被标记时接受。BFS 恰好标记从 $s$ 可达的各顶点（[[algorithms/graph-search#thm-bfs]]）。用 $n^2$ 位的邻接矩阵时，每个顶点出队一次、其所在行扫描一次，共 $O(n^2)$ 次 RAM 步骤；每步只操作 $O(\log n)$ 位的顶点名。由 [[#thm-p-robust]]，这在图灵机上是多项式时间。
:::

对比穷举法：从 $s$ 到 $t$ 不重复顶点的路径至多有 $n - 1$ 条边，于是可以枚举互异顶点的一切序列——多达 $(n-2)!$ 个。BFS 避开了这一点，因为它从不枚举路径，只枚举顶点，并记住哪些已经见过。靠重复利用部分信息来避免穷举搜索，是多项式时间算法的共同主题。

### 互素的数

$$
\mathit{RELPRIME} = \{\langle x, y\rangle : x, y \ge 1 \text{ 且 } \gcd(x, y) = 1\}.
$$

搜寻公因数会耗去关于位数的指数时间，如 [[#ex-trial-division]]。欧几里得算法快上指数倍。

::: algorithm 欧几里得算法 {#alg-euclid}
在满足 $x \ge y \ge 1$ 的输入 $\langle x, y\rangle$ 上：只要 $y \ne 0$，就把 $(x, y)$ 替换为 $(y, x \bmod y)$。输出 $x$。（判定 $\mathit{RELPRIME}$：当且仅当输出为 $1$ 时接受。）
:::

::: lemma 欧几里得算法的余数收缩很快 {#lem-euclid-halving}
若 $x \ge y \ge 1$，则 $x \bmod y < x/2$。
:::

::: proof
若 $y \le x/2$，则 $x \bmod y < y \le x/2$。若 $y > x/2$，则 $x \bmod y = x - y < x - x/2 = x/2$。
:::

::: theorem RELPRIME 属于 P {#thm-relprime}
欧几里得算法至多用 $2\lceil\log_2 x\rceil + 2$ 次迭代算出 $\gcd(x, y)$；故 $\mathit{RELPRIME} \in \mathsf{P}$。
:::

::: proof
*正确性。* $\gcd(x, y) = \gcd(y, x \bmod y)$，因为对某个整数 $q$ 有 $x \bmod y = x - qy$，故 $(x, y)$ 与 $(y, x \bmod y)$ 的公因数相同。数对在减小，故循环在 $y = 0$ 处结束，而 $\gcd(x, 0) = x$。

*时间。* 考察相邻两次迭代：$(x, y) \to (y, r) \to (r, s)$，其中 $r = x \bmod y$。由 [[#lem-euclid-halving]]，$r < x/2$，于是每两次迭代第一个分量就降到其值的一半以下。从 $x$ 出发，$2j$ 次迭代后它小于 $x/2^j$，而循环运行时它是正整数，故循环在 $2\lceil\log_2 x\rceil + 2$ 次迭代内结束。每次迭代对至多 $b$ 位的数做除法，$O(b^2)$ 次位运算，这里 $b$ 是输入长度。总计 $O(b^3)$：多项式。
:::

::: example 欧几里得算法遇斐波那契数 {#ex-euclid}
对 $(89, 55)$ 与 $(1071, 462)$ 追踪 [[#alg-euclid]] 的执行，并把迭代次数与 [[#thm-relprime]] 的界作比较。
::: solution
对 $(89, 55)$，数对依次为

$$
(89, 55) \to (55, 34) \to (34, 21) \to (21, 13) \to (13, 8) \to (8, 5) \to (5, 3) \to (3, 2) \to (2, 1) \to (1, 0),
$$

共九次迭代（除最后一个商为 $2$ 外，每个商都是 $1$），$\gcd = 1$，故 $\langle 89, 55\rangle \in \mathit{RELPRIME}$。界为 $2\lceil\log_2 89\rceil + 2 = 2 \cdot 7 + 2 = 16$。相邻的斐波那契数其实是欧几里得算法的最坏情形（拉梅（Lamé）定理，1844），因为每个商都尽可能小。

对 $(1071, 462)$：$1071 = 2 \cdot 462 + 147$，$462 = 3 \cdot 147 + 21$，$147 = 7 \cdot 21 + 0$。三次迭代，$\gcd = 21$，故该数对不属于 $\mathit{RELPRIME}$。大的商使余数比最坏情形收缩得快得多。
:::
:::

### 上下文无关语言

::: theorem 每个上下文无关语言都属于 P {#thm-cfl-p}
若 $L$ 是上下文无关的，则 $L \in \mathsf{TIME}(n^3)$。
:::

::: proof
取定 $L$ 的一个乔姆斯基范式文法 $G$（[[theory-of-computation/context-free-grammars#thm-cnf]]）；它是算法的一部分，而非输入的一部分。CYK 算法（[[theory-of-computation/context-free-grammars#alg-cyk]]）填一张表，其条目 $(i, j)$ 是推导出子串 $w_i \cdots w_j$ 的各变元的集合。条目有 $O(n^2)$ 个，每个都要尝试 $O(n)$ 个分裂点与 $G$ 的常数目产生式，合计 $O(n^3)$ 步（[[theory-of-computation/context-free-grammars#thm-cyk]]）；$w \in L$ 当且仅当开始变元属于条目 $(1, n)$。表有 $O(n^2)$ 个常数大小的条目，故多带机执行这些步骤只需多项式开销；更精细的实现直接达到 $O(n^3)$。
:::

注意与朴素算法的对比：长度 $n$ 的串的 CNF 推导有 $2n - 1$ 步，而尝试该长度的一切推导要耗指数时间。CYK 是动态规划：对"哪些变元推导出这个子串"这 $O(n^2)$ 个子问题，它把答案共享给一切需要它们的推导。

::: quiz
输入以二进制编码时，下列问题中哪些已知属于 $\mathsf{P}$？
- [x] 给定有向图和两个顶点，它们之间是否有路径？
- [x] 给定整数 $x$ 与 $y$，$\gcd(x, y) = 1$ 是否成立？
- [ ] 给定 $n$ 个取整数重量与价值的物品、容量 $W$ 与目标价值 $V$，是否存在重量不超过 $W$ 而价值至少 $V$ 的子集？（$O(nW)$ 动态规划判定它。）
- [x] 给定串 $w$，$w$ 是否属于固定文法 $S \to aSb \mid SS \mid \varepsilon$ 的语言？
::: solution
可达性（BFS）、互素性（欧几里得算法）与固定上下文无关语言的从属问题（CYK）都属于 $\mathsf{P}$。背包动态规划耗 $O(nW)$ 步，但 $W$ 约用 $\log_2 W$ 位写出，故 $nW$ 可能是输入长度的指数：该算法只是伪多项式的。背包问题其实是 $\mathsf{NP}$ 完全的（[[complexity/np-complete-problems]]），因此没有人知道它有多项式时间算法。
:::
:::

## 实践中 {#sec-practice}

一些标志性问题花了很长时间才被归入 $\mathsf{P}$：

- **线性规划**由列昂尼德·哈奇扬（Leonid Khachiyan）的椭球算法（1979）被证明属于 $\mathsf{P}$，纳伦德拉·卡尔马卡尔（Narendra Karmarkar）的内点法（1984）使多项式时间算法变得实用。年代久得多的单纯形法最坏情况是指数级的，却至今仍被广泛使用。
- **素性。** 在马尼德拉·阿格拉瓦尔（Manindra Agrawal）、尼尔拉杰·卡亚尔（Neeraj Kayal）与尼廷·萨克塞纳（Nitin Saxena）于 2002 年证明 $\mathit{PRIMES} \in \mathsf{P}$（AKS 算法，2004 年发表）之前，随机化多项式时间检验（Solovay–Strassen 1977、Miller–Rabin 1976/1980）已经使用了几十年。实践中人们仍用 Miller–Rabin，因为它快得多；确定性算法敲定的是一个理论问题。
- **最大匹配**：一般图中的最大匹配由杰克·埃德蒙兹（Jack Edmonds）的开花算法（1965）归入 $\mathsf{P}$；正是在这篇论文里，他论证了多项式时间是"好"算法的正确概念。

截至 2026 年，**整数分解**、**图同构**与**离散对数**是众所周知的、既不知属于 $\mathsf{P}$、也不被认为属于 [[complexity/np]] 最难问题之列的问题。拉斯洛·巴拜（László Babai）的算法（2015 年宣布）以拟多项式时间 $2^{O((\log n)^c)}$ 求解图同构，它介于多项式与指数之间。

::: history
以资源度量计算的难度始于 1960 年代初，有米哈伊尔·拉宾（Michael Rabin）1960 年关于"难度"的工作，以及尤里斯·哈特马尼斯（Juris Hartmanis）与理查德·斯特恩斯（Richard Stearns）的工作——他们的论文 "On the computational complexity of algorithms"（*Transactions of the AMS*，1965）为多带图灵机定义了时间复杂度类，证明了加速定理与层次定理，并为这一领域命名。同年，艾伦·科班（Alan Cobham，"The intrinsic computational difficulty of functions"，1965）与杰克·埃德蒙兹（Jack Edmonds，"Paths, trees, and flowers"，1965）各自独立地提出以多项式时间作为可行计算的数学概念。弗雷德里克·亨尼（Frederick Hennie，1965）证明了单带机的穿越序列下界。哈特马尼斯与斯特恩斯因开创计算复杂性而获 1993 年图灵奖。
:::

## 后续内容

$\mathsf{P}$ 是全课程赖以对照的基准。[[complexity/np]] 加上非确定性——等价地说，加上*检验*一个候选解的能力——并问这是否让多项式时间变得更强大；[[complexity/np-completeness]] 指出那个更大类中最难的问题。[[complexity/space-complexity]] 度量的是内存而非时间；[[complexity/hierarchies]] 则证明更多的时间确实允许解更多的题，例如 $\mathsf{P}$ 真小于指数时间。

::: summary
- 判定器的运行时间是移动步数关于输入长度 $n$ 的最坏情况函数（[[#def-running-time]]）；$\mathsf{TIME}(t(n))$ 是可用 $O(t(n))$ 时间判定的语言之类（[[#def-time]]）。
- 确切运行时间依赖模型（$\{0^k1^k\}$ 单带需 $\Theta(n \log n)$，双带需 $O(n)$），但确定模型之间多项式相关（[[#thm-multitape-time]]）；已知的非确定性模拟要付出指数代价（[[#thm-ntm-time]]）。
- 输入长度是合理编码的长度；数写成二进制，故对数的值为多项式的运行时间只是伪多项式。
- $\mathsf{P} = \bigcup_k \mathsf{TIME}(n^k)$（[[#def-p]]）是稳健的：对复合封闭，与合理的模型和编码无关（[[#thm-p-robust]]）——前提是操作按其操作数的长度计费。
- $\mathit{PATH}$、$\mathit{RELPRIME}$ 与每个上下文无关语言都属于 $\mathsf{P}$（[[#thm-path]]、[[#thm-relprime]]、[[#thm-cfl-p]]）；每一例中算法都靠共享工作量来避免穷举搜索。
- "多项式"是一个分类，不是速度保证；但多项式算法随更快的硬件成倍扩展，指数算法只是加性扩展。
:::

## 习题

::: exercise 数中有几个位 {level=1 check="20"}
$N = 10^6$ 的二进制表示有多少位？一个算法在输入 $N$ 上循环 $N$ 次；它是多项式时间的吗？（输入位数。）
::: solution
$2^{19} = 524\,288 \le 10^6 < 2^{20} = 1\,048\,576$，故 $10^6$ 有 $20$ 位。一般地，$N$ 有 $\lfloor\log_2 N\rfloor + 1$ 位。运行 $N$ 次的循环在 $b$ 位的输入上约运行 $2^{b}$ 次，对输入长度是指数级的：该算法不是多项式时间的（它是伪多项式的）。
:::
:::

::: exercise 是不是多项式？ {level=1}
下列运行时间哪些关于 $n$ 是多项式的：(a) $n^3 \log n$；(b) $n^{\log n}$；(c) $2^{\sqrt{\log n}}$；(d) $(\log n)^{100}$；(e) $1.0001^n$；(f) $n^{100}$？
::: solution
若一个函数对某个常数 $k$ 是 $O(n^k)$，就称它多项式有界。(a) 是：$O(n^4)$。(b) 否：$n^{\log n} = 2^{(\log n)^2}$，比每个 $n^k = 2^{k\log n}$ 增长都多——它是**拟多项式**的。(c) 是：$\sqrt{\log n} \le \log n$，故 $2^{\sqrt{\log n}} \le n$；它比 $n$ 的任何正次幂增长都慢，却比 $\log n$ 的任何次幂都快。(d) 是：$(\log n)^{100} = O(n)$（多对数的）。(e) 否：指数级，尽管它要到极大的 $n$ 才超过 $n^{100}$——在 $n = 10^7$ 处约为 $e^{1000}$。(f) 按定义是，尽管毫无实用价值。
:::
:::

::: exercise 欧几里得算法的迭代次数 {level=1 check="9"}
$\gcd(89, 55)$ 要把 [[#alg-euclid]] 的循环执行多少次迭代——也就是说，在第二个分量变为 $0$ 之前作了多少次带余除法？（输入该数。）
::: solution
由 [[#ex-euclid]]：$89 = 1\cdot 55 + 34$，$55 = 1 \cdot 34 + 21$，$34 = 1 \cdot 21 + 13$，$21 = 1 \cdot 13 + 8$，$13 = 1 \cdot 8 + 5$，$8 = 1 \cdot 5 + 3$，$5 = 1 \cdot 3 + 2$，$3 = 1 \cdot 2 + 1$，$2 = 2 \cdot 1 + 0$。共 $9$ 次除法。
:::
:::

::: exercise 类 P 的封闭性 {level=2}
证明 $\mathsf{P}$ 对并、交、补与连接封闭。
::: solution
设 $M_1$ 与 $M_2$ 分别以 $O(n^a)$ 与 $O(n^b)$ 时间判定 $L_1$ 与 $L_2$。*补：*交换 $M_1$ 的接受与拒绝状态；运行时间不变。*并与交：*在输入 $w$ 上，先在 $w$ 上运行 $M_1$，再在 $w$ 上运行 $M_2$（用第二条磁带，或恢复输入之后再运行），若其中一个（两个）接受则接受；时间 $O(n^a + n^b)$。*连接：*在输入 $w = w_1 \cdots w_n$ 上，对每个分裂 $i = 0, \dots, n$，在 $w_1 \cdots w_i$ 上运行 $M_1$、在 $w_{i+1} \cdots w_n$ 上运行 $M_2$，若某个 $i$ 使二者都接受则接受。分裂有 $n + 1$ 处，每处耗 $O(n^a + n^b)$ 外加复制的 $O(n)$，故时间为 $O(n^{\max(a, b) + 1})$：多项式。
:::
:::

::: exercise 伪多项式的子集和 {level=2}
$\mathit{SUBSET\text{-}SUM} = \{\langle a_1, \dots, a_k, T\rangle : \text{某个 } a_i \text{ 的子集之和为 } T\}$（正整数，二进制）。(a) 给出一个耗 $O(kT)$ 次算术步骤的算法。(b) 它是多项式时间的吗？(c) 证明所有数都以**一进制**写出的版本属于 $\mathsf{P}$。
::: solution
(a) 维护一个布尔数组 $R[0..T]$，$R[s]$ 为真当且仅当已处理的数中某个子集之和为 $s$。初始只有 $R[0]$ 为真。对每个 $a_i$，令 $s$ 从 $T$ 递减到 $a_i$，置 $R[s] \gets R[s] \lor R[s - a_i]$（逆序进行保证每个 $a_i$ 至多用一次）。当且仅当 $R[T]$ 时接受。共 $O(kT)$ 步，每步的下标是 $O(\log T)$ 位的。
(b) 否：输入约含 $\sum_i \log_2 a_i + \log_2 T$ 位，而 $T$ 可以是这个量的指数级，例如 $T \approx 2^{n/2}$。（事实上 $\mathit{SUBSET\text{-}SUM}$ 是 $\mathsf{NP}$ 完全的：[[complexity/np-complete-problems]]。）
(c) 一进制下输入长度 $n$ 至少为 $T$、至少为 $k$，故共 $O(kT) = O(n^2)$ 步，每步代价为多项式：多项式时间。问题本身毫无变化，只是为工作量付账的输入变多了。
:::
:::

::: exercise 三带机并入单带 {level=2 check="4"}
一台三带图灵机以 $O(n^2)$ 时间判定 $L$。利用 [[#thm-multitape-time]]，你能保证以 $O(n^k)$ 时间判定 $L$ 的单带机的哪个指数 $k$？无论如何 $L \in \mathsf{P}$ 吗？（输入 $k$。）
::: solution
模拟使运行时间平方：$O((n^2)^2) = O(n^4)$，故 $k = 4$。无论如何 $L \in \mathsf{P}$，因为 $\mathsf{P}$ 的定义允许任意条数的磁带，而多项式次数只不过翻了一倍。
:::
:::

::: exercise 反复平方与代价模型 {#ex-squaring level=3 check="1025"}
一个程序从 $x = 2$ 出发，执行十次 `x = x * x`。(a) $x$ 的最终值有多少位？(b) 解释为什么对每次乘法——不论操作数多大——都只收一个单位代价的机器模型，会使 $\mathsf{P}$ 比它的图灵机定义更大（至少，它能算出多项式时间图灵机连写都写不出的数）。(c) 为什么只含加法与减法的单位代价 RAM 没有这个问题？（输入 (a) 的位数。）
::: solution
(a) 平方 $j$ 次后 $x = 2^{2^j}$。$j = 10$ 时 $x = 2^{1024}$，有 $1024 + 1 = 1025$ 位。
(b) 有了 $k$ 次单位代价的平方，一个 $k + 1$ 步的程序就产出 $2^{2^k}$，一个 $2^k + 1$ 位的数，于是它能在时间 $n$ 内算出长度关于 $n$ 呈指数的数。图灵机要写下这么多位至少需要 $2^k$ 步。更糟的是，对这样的数做算术（例如用除法取出各个位）能让带乘法的单位代价机器解开一些被认为不属于 $\mathsf{P}$ 的问题（哈特马尼斯与西蒙（Hartmanis and Simon），1974：带乘法与按位布尔运算的单位代价 RAM 能在多项式时间内判定的恰是 $\mathsf{PSPACE}$ 中的问题——见 [[complexity/space-complexity]]）。
(c) 两数相加，结果的位数至比比长的那个操作数多 $1$，故 $t$ 步之后每个寄存器至多有 $\max(\text{输入长度}, \text{常数}) + t$ 位。于是每一步都可在关于 $t$ 与 $n$ 的多项式时间内模拟，如 [[#thm-p-robust]] 的证明。
:::
:::

::: exercise 语言的 Kleene 星属于 P {level=3}
证明：若 $L \in \mathsf{P}$，则 $L^* \in \mathsf{P}$；并对以成员函数给出的语言，用 Python 实现你的算法。（把 $w$ 分成若干段的所有分法都试一遍要耗指数时间，所以要用动态规划。）
::: solution
设 $w = w_1 \cdots w_n$。定义 $S[i]$ 为真当且仅当前缀 $w_1 \cdots w_i$ 属于 $L^*$。则 $S[0]$ 为真（空串属于 $L^*$），且对 $i \ge 1$，$S[i]$ 为真当且仅当存在 $j < i$ 使 $S[j]$ 为真且 $w_{j+1} \cdots w_i \in L$：非空前缀的任何一个由 $L$ 中各段构成的分解都有最后一段，而它之前的部分是 $L^*$ 中更短的前缀。当且仅当 $S[n]$ 时接受。表有 $n + 1$ 个条目，每个条目由至多 $n$ 次对长度至多 $n$ 的子串所作的成员检验算出，故若 $L$ 的判定器运行时间为 $O(n^k)$，总计为 $O(n^2 \cdot n^k) = O(n^{k+2})$：多项式。

```python
def in_star(w, in_L):
    """用 O(len(w)^2) 次调用判定器 in_L，判定 w 是否属于 L*。"""
    n = len(w)
    S = [True] + [False] * n          # S[i]：前缀 w[:i] 属于 L*
    for i in range(1, n + 1):
        S[i] = any(S[j] and in_L(w[j:i]) for j in range(i))
    return S[n]

is_square = lambda s: s != "" and s.isdigit() and int(s) ** 0.5 == int(int(s) ** 0.5)
print(in_star("14916", is_square), in_star("1492", is_square))
```
