前面的各章构造了安全的原语——认证加密、Diffie–Hellman、签名——每一样都有精确的定义和一个证明。真正的安全需要把它们组合成一个**协议**：参与者之间的一系列消息，要达到诸如"Alice 和 Bob 最终共享一把新鲜密钥，各自知道对方是谁，而其他任何人对密钥都一无所知"的目标。密码学的失败大多发生在协议层面，因为安全的部件可能不安全地组合起来：一条消息可能在另一个会话中被重放、被反射回它的发送者，或者被当作来自某个从未发送过它的人。经典例子是 1978 年发表的一个三条消息的协议，其中的缺陷十七年无人察觉。

本章研究三类协议。**认证密钥交换**是安全通信的基础，我们从一个被攻破的教科书协议讲到 TLS 1.3——HTTPS 背后的协议——的设计原则，包括它的密钥派生函数 HKDF。**秘密分享**把一个秘密拆开，使得 $n$ 个参与者中的任何 $t$ 个都能恢复它，而更少的份额什么也学不到，其完美安全性的证明沿袭 [[cryptography/perfect-secrecy]] 的风格。**零知识证明**使验证者相信一个命题为真，同时不泄露任何别的信息。TLS 的网络层面——往返次数、HTTP/3 以及 TLS 隐藏不了的东西——在 [[networks/application-layer]] 中，此处不重复。

## 认证密钥交换

Diffie–Hellman 单用只防得住窃听者（[[cryptography/public-key#thm-dh]]），防不住中间人。一个**认证密钥交换**（AKE）协议应对每一个完成的会话提供：

- **密钥机密性**：会话密钥对一个控制网络的攻击者来说与随机不可区分——这个攻击者能延迟、丢弃、修改、重放和注入消息，还能自己发起会话——而且它还可能学到*其他*会话的密钥；
- **认证**：若 Alice 认为自己与 Bob 完成了一个会话，那么 Bob 确实与 Alice 一起参加了那个会话，且两人持有同一把密钥（实体认证与**密钥确认**）；
- **前向安全性**：即使双方的长期私钥在会话结束*之后*被盗，会话密钥仍然保密。

把这些要求精确化的形式模型——对手调度许多并发会话，可以腐蚀参与者、揭示会话密钥——由 Bellare 与 Rogaway（1993）以及 Canetti 与 Krawczyk（2001）提出。我们采用这些非形式目标，考察协议如何达到或错过它们。

### 一个协议缺陷

Needham–Schroeder 公钥协议（1978）让已知彼此公钥加密密钥的 $A$ 与 $B$，用新鲜的随机 **nonce** $N_A$、$N_B$ 为对方作认证；我们用 $\{X\}_B$ 表示 $X$ 在 $B$ 的公钥下加密。

1. $A \to B$: $\{N_A, A\}_B$
2. $B \to A$: $\{N_A, N_B\}_A$
3. $A \to B$: $\{N_B\}_B$

每一方都发出了一个只有预期接收者才能解密的新鲜 nonce，又看到它被送回，于是双方看起来都在与对方交谈。1995 年 Gavin Lowe 用模型检查器发现这是错的。设 $A$ 与不诚实的一方 $M$ 开始会话。$M$ 解密消息 1，把 $\{N_A, A\}$ 在 $B$ 的密钥下重新加密后发给 $B$。$B$ 用 $\{N_A, N_B\}_A$ 回复，收件人是 $A$；$M$ 读不懂它，却把它当作自己的回复转发给 $A$。$A$ 以为自己在和 $M$ 说话，于是解密并发送 $\{N_B\}_M$；$M$ 解密这条消息，再把 $\{N_B\}_B$ 发给 $B$。现在 $B$ 以为自己认证了 $A$——可 $A$ 是在跟 $M$ 说话，而 $M$ 知道两个 nonce。每个原语都工作正常；失败的是协议，因为消息 2 没有说*谁*发的。Lowe 的补救是把应答者的身份写进去：$\{N_A, N_B, B\}_A$。于是 $A$ 期待的是 $M$，看到 $B$ 的名字便中止。

这一教训可以推广为一条设计准则：**把每条消息绑定到它的上下文**——双方的身份、会话、以及到目前为止说过的一切。标准做法是对整个**会话记录**（transcript）的哈希做认证。

### 带签名的 Diffie–Hellman 与 SIGMA

对付中间人攻击的一个自然补救，是各方对自己的 Diffie–Hellman 份额签名。但只签 $g^y$ 还不够：攻击者可以重放一个旧的已签名份额，身份也可能被错误绑定（攻击者中继某方的已签名份额，却声称那是它自己的份额）。**SIGMA** 设计（"SIGn-and-MAc"，Krawczyk 2003）——TLS 1.3 与 IKEv2 的基础——要求各方

1. 发送一个临时份额 $g^x$ 或 $g^y$；
2. 用长期密钥对到目前为止的会话记录——两个份额以及交换过的其他一切——签名；并且
3. 发送一个 MAC，其密钥由 $g^{xy}$ 导出，内容是它自己的身份和会话记录，以证明它持有会话密钥并把身份与之绑定。

签名证明谁在*这个*会话之中（会话记录含有新鲜份额，旧签名对不上），MAC 证明持有密钥、并把身份绑上去，从而防止错误绑定。由于份额是**临时的**——每个会话都用新的指数，事后销毁——日后偷到长期签名密钥的攻击者只能在未来会话中冒充该方，却算不出以往会话的密钥：前向安全性。对照 **RSA 密钥传递**——TLS 直到 1.2 版都在使用——客户端把一个随机秘密在服务器的长期 RSA 密钥下加密：录下流量、日后拿到那把密钥的攻击者能解密录下的每一个会话。

::: definition 密钥派生函数 HKDF {#def-hkdf}
HKDF（Krawczyk 2010；RFC 5869）用 HMAC（[[cryptography/hash-mac#def-hmac]]）从秘密导出密钥，分两步：

- **提取（Extract）**：$\mathit{PRK} = \mathrm{HMAC}(\mathit{salt}, \mathit{IKM})$ 把保密但不均匀的输入密钥材料 $\mathit{IKM}$（例如一个 Diffie–Hellman 群元素）变成一把伪随机密钥；
- **扩展（Expand）**：$\mathit{OKM} = T(1) \,\|\, T(2) \,\|\, \dots$ 截断到 $L$ 字节，其中 $T(0)$ 为空，$T(i) = \mathrm{HMAC}(\mathit{PRK},\ T(i-1) \,\|\, \mathit{info} \,\|\, i)$，$i$ 是一个单字节。
:::

$\mathit{info}$ 串为每把导出的密钥标注用途（比如"客户端握手流量密钥"），使不同用途的密钥相互独立：泄露一把不透露其他任何一把。这正是对 [[cryptography/hash-mac#thm-etm]] 密钥分离要求的系统性回答。

::: example HKDF 与一个测试向量 {#ex-hkdf}
计算 HKDF-SHA256，其中 $\mathit{IKM}$ 为 22 个字节 `0x0b`，$\mathit{salt}$ 为字节 `00` 到 `0c`，$\mathit{info}$ 为字节 `f0` 到 `f9`，$L = 42$，并与 RFC 5869 的第一个测试用例比对。
::: solution
```python
import hashlib, hmac

def hkdf_extract(salt, ikm):
    return hmac.new(salt, ikm, hashlib.sha256).digest()

def hkdf_expand(prk, info, L):
    out, t, i = b"", b"", 1
    while len(out) < L:
        t = hmac.new(prk, t + info + bytes([i]), hashlib.sha256).digest()
        out, i = out + t, i + 1
    return out[:L]

prk = hkdf_extract(bytes(range(13)), b"\x0b" * 22)
print(prk.hex())
print(hkdf_expand(prk, bytes(range(0xF0, 0xFA)), 42).hex())
```

```console
$ python3 hkdf.py
077709362c2e32df0ddc3f0dc47bba6390b6c73bb50f9c3122ec844ad7c2b3e5
3cb25f25faacd57a90434f64d0362f2a2d2d0a90cf1a5a4c5db02d56ecc4c5bf34007208d5b887185865
```

两行结果与 RFC 5869 测试用例 1 的 PRK 和 OKM 完全一致。由于 SHA-256 输出 32 字节，$L = 42$ 在扩展步骤中需要 $\lceil 42/32\rceil = 2$ 个 HMAC 块，其中第二个截断到 10 字节。生产环境请使用库提供的 HKDF（Python 的 `cryptography` 包就提供一个），而不要用这份代码——不过这里情况特殊：这份代码短到可以对照标准逐一检查。
:::
:::

## TLS 1.3

TLS 1.3（RFC 8446，2018）的设计过程开放得不同寻常：对草案的学术分析——包括握手在符号模型下的机器验证证明——反哺设计本身。它删除了早期版本中一切引发过攻击的东西：RSA 密钥传递（无前向安全性、Bleichenbacher 预言机）、静态 Diffie–Hellman、CBC 模式与先加密后加 MAC（填充预言机）、压缩（通过密文长度泄露秘密）、重新协商、以及自定义群。剩下的东西，在有服务器认证的完整握手里，就是一个 SIGMA 风格的协议。花括号 $\{\dots\}$ 标出在握手密钥下加密的消息。

1. **客户端 → 服务器：`ClientHello`**——一个随机 nonce、支持的密码套件（如 `TLS_AES_128_GCM_SHA256` 与 `TLS_CHACHA20_POLY1305_SHA256`——只有 AEAD 和哈希），以及一个 `key_share`，含有一个或多个临时公钥，例如一个 X25519 份额 $g^x$，或者——自 2026 年起日益普遍的——把 X25519 与后量子 ML-KEM（[[cryptography/post-quantum]]）组合起来的混合份额。
2. **服务器 → 客户端：`ServerHello`**——它自己的 nonce、选定的套件以及它的 `key_share` $g^y$。双方现在都能计算 $g^{xy}$ 并导出握手密钥。
3. **服务器 → 客户端：`{EncryptedExtensions}`、`{Certificate}`、`{CertificateVerify}`、`{Finished}`**——服务器的证书链（[[cryptography/signatures]]）、用证书密钥对到此为止的会话记录哈希所作的签名，以及用握手秘密导出的密钥对会话记录做的 MAC（HMAC）。
4. **客户端 → 服务器：`{Finished}`**——客户端对会话记录的 MAC。（若服务器要求客户端认证，客户端的 `Certificate` 与 `CertificateVerify` 先于此发出。）随后应用数据在应用流量密钥下流动。

**密钥表**（key schedule）把一系列 HKDF 调用串联起来。*早期秘密*从预共享密钥（或全零）中提取；*握手秘密*以 Diffie–Hellman 值为输入密钥材料、以上一个秘密（经一次扩展步骤得到）为盐提取；随后是*主秘密*。从每个秘密出发，带标签的扩展步骤把到该点为止会话记录的哈希包括进去，导出客户端与服务器的流量密钥、`Finished` 密钥以及用于会话恢复的秘密。于是每把密钥都既依赖新鲜的 Diffie–Hellman 值，*又*依赖确切交换过的消息：任何一处的修改都会产生不同的密钥，导致 `Finished` 检验失败。

::: example 追踪 TLS 1.3 中的认证 {#ex-tls}
链路上的攻击者把服务器的 `key_share` $g^y$ 换成它自己的 $g^{y'}$，想坐到中间。握手在哪一步失败？为什么？若攻击者改为从 `ClientHello` 中删去客户端最强的密码套件、强迫改用较弱的套件，又会怎样？
::: solution
客户端用 $g^{xy'}$ 计算密钥；攻击者只有在反方向也替换了客户端的份额时才能解密服务器的加密消息——这就是经典的中间人。但它产生不了有效的 `CertificateVerify`：服务器的签名覆盖的是*服务器*看到的会话记录的哈希，其中含 $g^{y}$，而客户端的会话记录含 $g^{y'}$，所以签名对客户端验证不过；而没有证书的私钥，攻击者也签不出一份新的会话记录。握手在客户端检查 `CertificateVerify` 时中止。

删去一个密码套件改变了 `ClientHello`，而 `ClientHello` 是签过名、做过 MAC 的会话记录的一部分，于是在服务器视角下算出的服务器签名和 `Finished` MAC 与客户端的不再匹配。降级到*更旧的协议版本*要作特殊处理，因为旧版本不会以同样的方式认证会话记录：一个协商成 TLS 1.2 的 TLS 1.3 服务器会在它签名的随机 nonce 的最后几个字节写入一个固定标记，供 TLS 1.3 客户端检查。
:::
:::

**会话恢复与 0-RTT。**握手之后，服务器可以发放一张对应预共享密钥的票据，让客户端以后用简化握手恢复会话（可选地仍做一次新鲜的 Diffie–Hellman 交换以保持前向安全性）。采用 **0-RTT** 时，客户端在第一个飞行包里就发送应用数据，用只由预共享密钥导出的密钥加密。这些数据对该密钥没有前向安全性，而且可能被攻击者**重放**，因为服务器尚未贡献任何新鲜随机性；TLS 1.3 把它留给应用：只对重复执行无害的请求使用 0-RTT（省下的往返次数见 [[networks/application-layer]]）。

::: warning 不要设计你自己的协议
Needham–Schroeder 的缺陷在专家的目光下存活了十七年；1.3 版之前的 TLS 在单个部件都成立的组合上积累了一长串攻击，而形式化工具至今仍在发现新的协议缺陷。设计认证或密钥交换协议是一项研究工作，不是工程任务。请经由一个维护良好的库使用 TLS 1.3；或者在定制场合，使用发表过分析的框架——如 Noise 协议框架——或有形式证明的消息协议，并按其推荐默认值配置。"把套接字用 AES 加密"不是协议。
:::

::: quiz
一台服务器使用带 RSA 密钥传递的 TLS 1.2。多年后它的 RSA 私钥被盗。攻击者此前录下了许多过往会话。它能做什么？

- [ ] 什么也做不了：会话密钥是随机的，每个会话一结束就被删除了。
- [x] 解密每一个录下的会话，因为每个会话的预主密钥都是在被盗密钥下加密的。
- [ ] 只能在未来的会话中冒充服务器。
- [ ] 只能解密使用了 0-RTT 的会话。
::: solution
在 RSA 密钥传递下，客户端把会话的预主密钥在服务器的长期密钥下加密，于是那把密钥能解密录下的握手，进而解密会话：没有前向安全性。若是临时 Diffie–Hellman（TLS 1.3 完整握手强制使用），被盗密钥只能支持将来的冒充，解密不了过去。同样的"现在录下、以后解密"之忧，也推动了向后量子密钥交换的迁移。
:::
:::

## 秘密分享

一家公司的签名密钥太宝贵，不能只交给一名员工；也太宝贵，不能因为一名员工离职而丢失。**门限秘密分享**把它拆成 $n$ 份份额，使得其中任何 $t$ 份都能重构它，而任何 $t - 1$ 份都完全不泄露它。

::: definition Shamir 秘密分享 {#def-shamir}
设 $p > n$ 为素数，秘密 $S \in \Z_p$。分发者从 $\Z_p$ 中均匀选取 $a_1, \dots, a_{t-1}$，构成多项式
$$
f(x) = S + a_1x + a_2x^2 + \dots + a_{t-1}x^{t-1} \pmod p,
$$
并把份额 $(i, f(i))$ 交给参与者 $i$，$i = 1, \dots, n$。
:::

::: theorem Shamir 方案正确且完美隐私 {#thm-shamir}
(a) 任何 $t$ 份份额决定 $S$，可用拉格朗日（Lagrange）插值计算：对互不相同的 $x_1, \dots, x_t$，
$$
S = f(0) = \sum_{j=1}^t f(x_j)\,\lambda_j, \qquad \lambda_j = \prod_{m \ne j}\frac{-x_m}{x_j - x_m} \pmod p .
$$
(b) 任何 $t - 1$ 份份额均匀分布且与 $S$ 独立：按完美保密的意义，它们不提供关于 $S$ 的任何信息。
:::

::: proof
两部分都依赖于这样一个事实：在域 $\Z_p$ 上，对互不相同的点 $x_1, \dots, x_t$ 和任意取值 $y_1, \dots, y_t$，**恰有唯一一个**次数至多 $t - 1$、对所有 $j$ 满足 $f(x_j) = y_j$ 的多项式。存在性：拉格朗日多项式 $L(x) = \sum_j y_j\prod_{m\ne j}(x - x_m)/(x_j - x_m)$ 的次数至多 $t-1$，且在 $x_j$ 处取值 $y_j$（乘积在 $x_j$ 处为 $1$、在其余各点为 $0$）；分母非零因而可逆，因为 $x_j$ 互异且 $p$ 是素数。唯一性：两个这样的多项式之差次数至多 $t - 1$ 而有 $t$ 个根，而域上的非零多项式根数不超过次数，所以差为零。

(a) $f$ 本身就是经过这 $t$ 份份额的、次数至多 $t - 1$ 的多项式，故它等于 $L$，而 $S = f(0) = L(0)$，即所给的公式。

(b) 固定任意 $t - 1$ 个互异的非零点 $x_1, \dots, x_{t-1}$。对每个候选秘密 $S'$ 和每组取值 $(y_1, \dots, y_{t-1})$，经过 $t$ 个点 $(0, S'), (x_1, y_1), \dots, (x_{t-1}, y_{t-1})$ 的次数至多 $t-1$ 的多项式恰有一个，也就是说系数 $(a_1, \dots, a_{t-1})$ 的取法恰有一种。系数在 $\Z_p^{t-1}$ 上均匀，所以每个 $S'$ 之下，$p^{t-1}$ 种可能的份额取值序列每一种都恰以概率 $p^{-(t-1)}$ 出现。于是 $t - 1$ 份份额的分布是均匀的、不依赖秘密——正是 [[cryptography/perfect-secrecy#lem-perfect-equiv]] 的条件。
:::

::: example 分享并恢复一个秘密 {#ex-shamir}
设 $p = 97$、$t = 3$、秘密 $S = 13$，分发者取 $a_1 = 5$、$a_2 = 2$。计算参与者 $1$ 到 $6$ 的份额，从参与者 $1$、$3$、$5$ 的份额恢复 $S$，并说明仅有参与者 $1$ 和 $3$ 的份额时，与每一个秘密都相容。
::: solution
$f(x) = 13 + 5x + 2x^2 \bmod 97$ 给出 $f(1) = 20$、$f(2) = 31$、$f(3) = 46$、$f(4) = 65$、$f(5) = 88$、$f(6) = 115 \bmod 97 = 18$。

由 $x = 1, 3, 5$，在 $0$ 处的拉格朗日系数为
$$
\lambda_1 = \frac{(-3)(-5)}{(1-3)(1-5)} = \frac{15}{8}, \quad \lambda_3 = \frac{(-1)(-5)}{(3-1)(3-5)} = -\frac54, \quad \lambda_5 = \frac{(-1)(-3)}{(5-1)(5-3)} = \frac38 .
$$
在有理数上，$\tfrac{15}{8}\cdot 20 - \tfrac54 \cdot 46 + \tfrac38 \cdot 88 = 37.5 - 57.5 + 33 = 13$。模 $97$ 下系数为 $15 \cdot 8^{-1} \equiv 14$、$-5\cdot 4^{-1} \equiv 23$、$3 \cdot 8^{-1} \equiv 61$，而 $14 \cdot 20 + 23 \cdot 46 + 61 \cdot 88 = 280 + 1058 + 5368 = 6706 = 69 \cdot 97 + 13$，所以仍有 $S = 13$。参与者 $2, 4, 6$ 的份额（含绕回的取值 $18$）也给出 $13$。

只有 $(1, 20)$ 和 $(3, 46)$ 时，*每一个*秘密都有可能：$S' = 0$ 时多项式 $87x + 30x^2$ 吻合；$S' = 1$ 时是 $1 + 21x + 95x^2$；$S' = 2$ 时是 $2 + 52x + 63x^2$；如此下去——$97$ 个秘密各对应一个多项式，正如 [[#thm-shamir]] 的 (b) 所说。

```python
P = 97
def recover(shares):
    """在 Z_P 上对 0 作拉格朗日插值（玩具秘密分享）。"""
    S = 0
    for j, (xj, yj) in enumerate(shares):
        num = den = 1
        for m, (xm, _) in enumerate(shares):
            if m != j:
                num, den = num * -xm % P, den * (xj - xm) % P
        S = (S + yj * num * pow(den, -1, P)) % P
    return S

print(recover([(1, 20), (3, 46), (5, 88)]), recover([(2, 31), (4, 65), (6, 18)]))
```


秘密分享是**门限密码学**的基础——$n$ 方中的 $t$ 方共同解密或签名，而不把密钥在任何一地重构；也是**安全多方计算**的基础——各方在各自的私密输入上计算一个函数，只学到输出（Ben-Or、Goldwasser 与 Wigderson，1988）。Shamir 方案本身信任分发者、也信任参与者提交的份额正确；*可验证*秘密分享加上承诺，使作弊能够被发现。

## 零知识证明

Schnorr 的识别协议（[[cryptography/signatures#alg-schnorr-id]]）能使验证者相信证明者知道某个离散对数，同时不泄露关于它的任何信息。一般的概念由 Goldwasser、Micali 与 Rackoff（1985）提出。

::: definition 交互式证明与零知识 {#def-zk}
语言 $L$ 的一个**交互式证明**是证明者 $P$ 与 PPT 验证者 $V$ 在公共输入 $w$ 上进行的协议，满足

- **完备性**：若 $w \in L$，诚实证明者使 $V$ 以概率 $1$（或接近 $1$）接受；
- **可靠性**：若 $w \notin L$，则任何证明者策略都不能使 $V$ 以超过某个 $\varepsilon < 1$ 的概率接受，而重复能把这个概率压低。

若存在一个 PPT **模拟器**，只凭 $w \in L$ 就能输出与 $P$ 同诚实 $V$ 的真实执行分布完全相同的会话记录，则称该证明是（完美、诚实验证者）**零知识**的。
:::

模拟器刻画了"什么也没学到"：验证者能从会话记录算出的任何东西，都能从一个模拟会话记录算出来——而后者它可以不经证明者自己产生。最强的概念要求对*每个*高效验证者都存在模拟器，包括作弊的验证者；下面的协议也做到了这一点，其模拟器猜测验证者的挑战、猜错就重新开始。

### 图同构

顶点集 $\{1, \dots, n\}$ 上的两个图 $G_0, G_1$ 是**同构的**，如果某个顶点置换 $\pi$ 把 $G_0$ 的边恰好映为 $G_1$ 的边；记作 $G_1 = \pi(G_0)$。判定图同构的多项式时间算法无人知晓（Babai 2015 年的算法是拟多项式的）。证明者知道 $\pi$。

::: algorithm 图同构的零知识证明 {#alg-gi-zk}
重复 $k$ 轮：

1. 证明者选取均匀的置换 $\sigma$ 并发送 $H = \sigma(G_1)$。
2. 验证者发送均匀的比特 $b$。
3. 若 $b = 1$，证明者发送 $\tau = \sigma$；若 $b = 0$，它发送 $\tau = \sigma \circ \pi$。
4. 验证者检验 $H = \tau(G_b)$。

每一轮都通过就接受。
:::

::: theorem 该协议是一个完美零知识证明 {#thm-gi-zk}
协议是完备的；若 $G_0$ 与 $G_1$ 不同构，作弊证明者每轮通过的概率至多 $1/2$，于是全部 $k$ 轮通过的概率至多 $2^{-k}$；并且它是完美诚实验证者零知识的。
:::

::: proof
**完备性。**若 $b = 1$，$\tau(G_1) = \sigma(G_1) = H$。若 $b = 0$，$\tau(G_0) = \sigma(\pi(G_0)) = \sigma(G_1) = H$。

**可靠性。**设 $G_0 \not\cong G_1$。无论作弊证明者发来什么图 $H$，它至多与 $G_0$、$G_1$ 之一同构（同构是等价关系，若它与两者都同构，两者便彼此同构）。对另一个 $b$ 值，没有任何 $\tau$ 能通过检验。由于 $b$ 均匀且在 $H$ 之后选定，证明者每轮独立地至少以 $1/2$ 的概率失败。

**零知识。**模拟器每轮选取均匀的比特 $b$ 与均匀的置换 $\tau$，输出满足 $H = \tau(G_b)$ 的 $(H, b, \tau)$。真实的一轮中，$b$ 是均匀的；给定 $b$，$\tau$ 是 $\sigma$ 或 $\sigma\circ\pi$ 而 $\sigma$ 均匀，所以两种情形下 $\tau$ 都均匀（与固定置换复合是置换集合上的双射）；而 $H = \tau(G_b)$ 由 $b$ 与 $\tau$ 决定。于是真实三元组与模拟三元组分布相同。
:::

::: example 协议的一轮 {#ex-gi-round}
设 $G_0$ 是边为 $\{1,2\}, \{2,3\}, \{3,4\}$ 的路径，$\pi$ 把 $1 \mapsto 3$、$2 \mapsto 1$、$3 \mapsto 4$、$4 \mapsto 2$。计算 $G_1 = \pi(G_0)$，然后取 $\sigma\colon 1 \mapsto 4, 2 \mapsto 3, 3 \mapsto 1, 4 \mapsto 2$、挑战 $b = 0$，跑一轮。
::: solution
$G_1 = \pi(G_0)$ 的边为 $\{\pi(1), \pi(2)\} = \{3, 1\}$、$\{\pi(2), \pi(3)\} = \{1, 4\}$、$\{\pi(3), \pi(4)\} = \{4, 2\}$：即路径 $3 - 1 - 4 - 2$。证明者发送 $H = \sigma(G_1)$，其边为 $\{\sigma(3), \sigma(1)\} = \{1, 4\}$、$\{\sigma(1), \sigma(4)\} = \{4, 2\}$、$\{\sigma(4), \sigma(2)\} = \{2, 3\}$：即路径 $1 - 4 - 2 - 3$。对 $b = 0$ 它交出 $\tau = \sigma\circ\pi$：$1 \mapsto \sigma(3) = 1$、$2 \mapsto \sigma(1) = 4$、$3 \mapsto \sigma(4) = 2$、$4 \mapsto \sigma(2) = 3$。验证者检验 $\tau(G_0)$：边为 $\{1, 4\}, \{4, 2\}, \{2, 3\}$，与 $H$ 相同。验证者得到的是 $G_0$ 的一个等于 $H$ 的随机重贴标签——这是它本来就能自己产生的东西——而关于 $\pi$ 一无所知：$\pi$ 被均匀的 $\sigma$ 藏了起来。
:::
:::

::: widget permutation
perm: 3 1 4 2
second: 4 3 1 2
caption: [[#ex-gi-round]] 的秘密同构 $\pi$（一行记法：$1 \mapsto 3$、$2 \mapsto 1$、$3 \mapsto 4$、$4 \mapsto 2$）以及证明者的随机重贴标签 $\sigma$。它们的复合 $\sigma\circ\pi$ 就是挑战为 $b = 0$ 时交出的置换。由于 $\sigma$ 均匀，$\sigma\circ\pi$ 也均匀，所以看到它对 $\pi$ 毫无泄露；只有能对同一个 $H$ 回答*两个*挑战的人，才必须知道 $\pi$。
:::

Goldreich、Micali 与 Wigderson（1986）证明：假设单向函数存在，$\mathsf{NP}$ 中的*每个*语言都有（计算）零知识证明——他们用承诺给出了图三着色的一个证明。现代的**简洁**非交互式论证（zk-SNARK 与 zk-STARK）借由 [[cryptography/signatures]] 的 Fiat–Shamir 变换变为非交互式，让证明者能用几百字节的证明使任何人相信一次运算是正确执行的，已被用于隐私保护与区块链系统。

::: quiz
在图同构协议中，验证者希望被作弊证明者骗过的概率至多为 $10^{-6}$。需要多少轮？

- [ ] $6$
- [ ] $10$
- [x] $20$
- [ ] $10^6$
::: solution
每轮让作弊者通过的概率至多 $1/2$，于是 $k$ 轮至多 $2^{-k}$。需要 $2^{-k} \le 10^{-6}$，即 $k \ge 6\log_2 10 \approx 19.93$，所以 $k = 20$。零知识性在序贯重复下保持。
:::

## 后续内容

TLS 1.3 的密钥交换正通过把 X25519 与 ML-KEM 组合的混合份额升级到能抵抗量子计算机的水平，它的证书最终也将搭载后量子签名：[[cryptography/post-quantum]]。许多参与方（其中一些有故障或恶意）之间达成一致的分布式协议，是 [[distributed-systems]] 的主题。协议在实践中如何部署、配置与被攻击——证书验证错误、降级攻击、侧信道、协议模糊测试——属于 [[security]]，而零知识与交互式证明的思想在 [[complexity]] 中有深远的推论（$\mathsf{IP} = \mathsf{PSPACE}$、PCP 定理）。

::: summary
- 即使每个原语都安全，协议仍会在组合处失败；Needham–Schroeder 公钥协议被一个中继攻击攻破，补救是给应答者点名。**把每条消息绑定到身份与会话记录。**
- **认证密钥交换**追求对主动攻击者的密钥机密性、带密钥确认的双向认证、以及**前向安全性**——临时 Diffie–Hellman 能提供前向安全性，RSA 密钥传递不能。
- **SIGMA**（对会话记录签名、对身份做 MAC）是 **TLS 1.3** 的基础：份额在首个飞行包中，会话记录经签名与 MAC，密码套件只含 AEAD，密钥表用 **HKDF**（[[#def-hkdf]]）。0-RTT 数据可能被重放。
- **Shamir 秘密分享**把秘密藏进一个随机 $t - 1$ 次多项式的 $f(0)$；任何 $t$ 份份额经拉格朗日插值重构它，任何 $t - 1$ 份与它均匀独立（[[#thm-shamir]]）。
- **零知识证明**是完备的、可靠的、可模拟的（[[#def-zk]]）；图同构协议的可靠性误差为 $2^{-k}$，且具有完美零知识性（[[#thm-gi-zk]]）。假设单向函数存在，每个 $\mathsf{NP}$ 语言都有零知识证明。
- 请使用经过标准制定与分析的协议（TLS 1.3、Noise），经由经过评审的库使用；不要设计自己的协议。
:::

::: exercise 前向安全性需要什么 {level=2}
一台 TLS 1.3 服务器为节省计算量，一整天内对所有连接复用同一个临时 X25519 密钥份额。哪项安全性质被削弱了？它在什么时候要紧？
::: solution
前向安全性依赖会话结束后销毁临时私指数。若服务器的指数 $y$ 被保留一天，在这一天入侵服务器（或拿到留存的 $y$）的攻击者就能为当天录下的每个会话计算 $g^{xy}$，因为客户端的份额 $g^x$ 就在会话记录里。其他日子的会话仍然受保护。暴露窗口从一个会话扩大到了一天；认证、以及对外部窃听者（他们从不攻破服务器）的机密性不受影响。

::: exercise Lowe 攻击的细节 {level=2}
在 Needham–Schroeder 攻击中，列出六条消息及其发送方、接收方与内容，并确切说明 Lowe 的补救使哪项检验失败。
::: solution
(1) $A \to M$: $\{N_A, A\}_M$。(2) $M(A) \to B$: $\{N_A, A\}_B$，由 $M$ 假扮 $A$ 发出。(3) $B \to M(A)$: $\{N_A, N_B\}_A$，发给 $A$。(4) $M \to A$: 同样的 $\{N_A, N_B\}_A$，作为 $M$ 的回复。(5) $A \to M$: $\{N_B\}_M$。(6) $M(A) \to B$: $\{N_B\}_B$。$B$ 此刻以为自己与 $A$ 共享 $N_A, N_B$。采用补救后，消息 3 是 $\{N_A, N_B, B\}_A$；$M$ 改不了它（没有 $A$ 的密钥，它无法有意义地解密再加密），于是在消息 4 处 $A$ 在它期待 $M$ 的地方看到名字 $B$，遂中止。
:::

::: exercise 两份份额的隐私性，靠计数 {level=2 check="97"}
在 $p = 97$、$t = 3$ 的 Shamir 方案中，固定两份份额 $(1, 20)$ 和 $(3, 46)$。有多少组系数 $(a_1, a_2)$ 同时与这两份份额*和*给定的秘密 $S'$ 相容？总共有多少个秘密与它们相容？（填入相容秘密的个数。）
::: solution
对每个 $S'$，条件 $S' + a_1 + a_2 = 20$ 与 $S' + 3a_1 + 9a_2 = 46$ 是关于 $(a_1, a_2)$ 的两个线性方程，行列式 $9 - 3 = 6 \ne 0 \pmod{97}$，所以恰有一组解。于是 $97$ 个秘密中每个都恰与一个多项式相容，而全部 $97$ 个秘密都可能——且每个概率相同，因为每个多项式本来就等可能。这就是 [[#thm-shamir]] 的 (b) 的微型版本。
:::

::: exercise Schnorr 协议的模拟器不是伪造者 {level=3}
图同构的模拟器（以及 [[cryptography/signatures#lem-hvzk]] 中 Schnorr 协议的模拟器）不用秘密就能产生会被接受的会话记录。仔细解释为什么这与可靠性不矛盾，以及为什么由 Fiat–Shamir 变换产生的*非交互式*会话记录令人信服，而模拟的交互式会话记录不令人信服。
::: solution
可靠性谈论的是这样的一种交互：验证者在证明者对 $H$（或 $R$）作出承诺*之后*才均匀选取 $b$（或 $e$）。模拟器把次序颠倒过来：先挑挑战，再构造一个恰好契合的承诺。因此一份会话记录对第三方什么也证明不了——它可能是模拟出来的——但能说服*在场的*验证者，因为它知道自己在承诺之后才选的挑战。在 Fiat–Shamir 中，挑战是 $H(\text{承诺} \,\|\, m)$；要模拟，就得找出一个哈希值恰等于预先选定的挑战的承诺，而对随机预言机来说这是不可行的。于是哈希强制了次序，会话记录也就成了可传递的证据，即签名。在随机预言机的证明中，*归约*可以编程预言机使模拟奏效，而这恰恰是真实攻击者不具备的能力。
:::
:::

::: exercise 实现 Shamir 分享 {level=3}
编写 `share(S, t, n, p)`：用取自 `secrets.randbelow(p)` 的系数返回 $n$ 份份额；并以 $p = 2^{127} - 1$（一个梅森素数）测试：$t$ 份份额的随机子集用 [[#ex-shamir]] 的 `recover`（改造为带参数 $p$）都能恢复 $S$，而 $t - 1$ 份给出的值基本上是随机的。真实系统还会加上什么？
::: solution
```python
import secrets, random

def share(S, t, n, p):
    coeffs = [S] + [secrets.randbelow(p) for _ in range(t - 1)]
    f = lambda x: sum(c * pow(x, k, p) for k, c in enumerate(coeffs)) % p
    return [(i, f(i)) for i in range(1, n + 1)]

def recover(shares, p):
    S = 0
    for j, (xj, yj) in enumerate(shares):
        num = den = 1
        for m, (xm, _) in enumerate(shares):
            if m != j:
                num, den = num * -xm % p, den * (xj - xm) % p
        S = (S + yj * num * pow(den, -1, p)) % p
    return S

p, S = 2**127 - 1, 123456789
sh = share(S, 3, 5, p)
print(all(recover(random.sample(sh, 3), p) == S for _ in range(20)))
print(recover(sh[:2], p) == S)
```

```console
$ python3 shamir_test.py

```

每个 3 元子集都能恢复秘密；只插值 2 份份额得到的是经过它们的直线在 $0$ 处的值，它均匀分布，仅以概率 $1/p$ 等于 $S$。真实系统会增加：传输份额用的认证信道；可验证秘密分享，使坏的份额能被发现；对分发者多项式的安全销毁；以及通常还有直接利用份额、绝不重构密钥的门限协议——一律取自经过评审的库。
:::
