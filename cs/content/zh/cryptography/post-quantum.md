[[cryptography/public-key]] 与 [[cryptography/signatures]] 中的每一个公钥方案都建立在两个问题之一上：分解大整数，或在 $\Z_p^*$ 与椭圆曲线上计算离散对数。1994 年，Peter Shor 证明量子计算机能在多项式时间内解决两者。迄今建成的量子计算机都远达不到所需的规模，而截至 2026 年，没有人能有把握地说它何时——乃至是否——会来。但两个事实已使这一威胁迫在眉睫。今天用 RSA 或椭圆曲线 Diffie–Hellman 加密的数据，可以今天录下来、等一台大型量子计算机出现时再解密——**现在收集、以后解密**——因此必须保存十年的秘密如今就需要保护。而替换掉全球每一个协议、每一台设备、每一张证书里的公钥密码学要花很多年：从 SHA-1 迁到 SHA-2 这样简单得多的改变都花了十年以上。

**后量子密码**指跑在普通计算机上的经典算法，其安全性建立在量子计算机已知不能高效解决的问题上。2024 年 8 月，NIST 发布了头三个标准：**ML-KEM**（FIPS 203），基于模格的密钥封装机制（KEM）；**ML-DSA**（FIPS 204），基于格的签名方案；以及**SLH-DSA**（FIPS 205），只基于哈希函数的签名方案。本章解释量子计算机威胁什么、不威胁什么，**带错学习**问题与建在其上的玩具格加密方案，从 Lamport 一次性方案到默克尔树的基于哈希的签名，以及截至 2026 年迁移的现状。量子计算本身是 [[quantum-computing]] 的主题；这里我们把量子算法当作具有已知开销的黑箱。

## 量子计算机会打破什么

### 肖尔（Shor）算法

肖尔算法解决**求阶**问题——给定 $N$ 与 $a \in \Z_N^*$，求最小的 $r > 0$ 使 $a^r \equiv 1 \pmod N$——用时关于 $\log N$ 为多项式，用量子傅里叶变换探测 $x \mapsto a^x \bmod N$ 的周期。仅凭经典数论，分解就能归约到求阶。

::: proposition 由阶分解 {#prop-order-factor}
设 $N$ 为奇合数，$a \in \Z_N^*$，$r$ 为 $a$ 模 $N$ 的阶。若 $r$ 为偶数且 $a^{r/2} \not\equiv -1 \pmod N$，则 $\gcd(a^{r/2} - 1, N)$ 是 $N$ 的一个非平凡因子。
:::

::: proof
令 $x = a^{r/2} \bmod N$。则 $x^2 = a^r \equiv 1$，故 $N$ 整除 $x^2 - 1 = (x - 1)(x + 1)$。由于 $r/2 < r$ 而 $r$ 是阶，$x \not\equiv 1$，故 $N \nmid x - 1$；由假设 $x \not\equiv -1$，故 $N \nmid x + 1$。若 $\gcd(x - 1, N)$ 为 $1$，则（因 $N \mid (x-1)(x+1)$）$N$ 将整除 $x + 1$；若它为 $N$，则 $N$ 将整除 $x - 1$。两者都不成立，故该最大公因数严格介于 $1$ 与 $N$ 之间。
:::

利用中国剩余定理可以证明：若 $N$ 至少有两个不同的奇素因子，则均匀随机的 $a \in \Z_N^*$ 至少以概率 $1/2$ 满足假设条件，于是随机选取 $a$ 几次就够。同样的求周期思想能在任何群运算可高效计算的群中计算离散对数——包括椭圆曲线群。因此肖尔算法一并打破 RSA、有限域 Diffie–Hellman、ElGamal、DSA、ECDH、ECDSA 与 EdDSA，在任何密钥长度上都是如此：更大的密钥只是让量子计算机稍微大一点。

::: example 由阶分解 15 与 21 {#ex-shor-classical}
用 [[#prop-order-factor]] 以 $a = 7$ 分解 $N = 15$、以 $a = 2$ 分解 $N = 21$，阶由手算求得（这一步在大 $N$ 时由量子计算机完成）。
::: solution
$N = 15$、$a = 7$：$7$ 模 $15$ 的幂为 $1, 7, 4, 13, 1$，故 $r = 4$，是偶数，且 $7^2 = 49 \equiv 4 \not\equiv -1$。于是 $\gcd(4 - 1, 15) = 3$、$\gcd(4 + 1, 15) = 5$：$15 = 3 \cdot 5$。

$N = 21$、$a = 2$：$2$ 模 $21$ 的幂为 $1, 2, 4, 8, 16, 11, 1$，故 $r = 6$，且 $2^3 = 8 \not\equiv -1 \equiv 20$。于是 $\gcd(8 - 1, 21) = 7$、$\gcd(8 + 1, 21) = 3$：$21 = 3 \cdot 7$。

经典部分是平凡的；全部难度在于求 $r$，而 $r$ 的大小与 $N$ 相当。迄今为止在量子硬件上演示肖尔算法的实验只分解过这么小的数，其中一些还使用了事先预设答案的简化。
:::
:::

需要多大的机器？随着算法和纠错技术的改进，资源估计一直在下降：Craig Gidney 在 2025 年的一份估计把分解 2048 位 RSA 模数压到不足一百万个带噪声的物理量子比特、运行不到一周，而 2026 年最大的机器约有上千个物理量子比特，其错误率还支撑不了这样的计算。这类估计是关于当前工程的观察，不是定理，而且会变化；审慎的应对是在问题变得紧迫之前完成迁移。

### 格罗弗（Grover）算法

对称密码受到的影响小得多。**格罗弗算法**（1996）用约 $\tfrac\pi4\sqrt N$ 次函数求值就能在 $N$ 个对象中找到被标记的那一个，而这对无结构搜索是最优的（Bennett、Bernstein、Brassard 与 Vazirani，1997）。用到穷尽密钥搜索上，它把 $2^k$ 次尝试变成约 $2^{k/2}$ 次对密码的量子求值。即便如此，这仍然夸大了威胁：格罗弗迭代天生是串行的，每一次都是在纠错量子计算机内部对 AES 做一次完整的可逆求值，而把搜索摊到 $P$ 台机器上也只把时间缩短 $\sqrt P$。NIST 的后量子安全等级其实就是按对 AES-128（等级 1）、AES-192（等级 3）、AES-256（等级 5）做密钥搜索的开销定义的。截至 2026 年的通常建议是：对多数用途 AES-128 仍然够用，AES-256 留有从容的裕量；SHA-256 与 SHA-3 依然安全（最好的已知量子碰撞算法把内存开销计入后，相对经典算法没有实际优势）。

## 格与带错学习

**格（lattice）**是线性无关向量 $\mathbf b_1, \dots, \mathbf b_n \in \R^n$ 的全体整系数组合 $\set{z_1\mathbf b_1 + \dots + z_n\mathbf b_n : z_i \in \Z}$——一张规则的点阵，可能歪斜得很厉害。格上有两个问题历经数十年，经典与量子攻击都攻不动：**最短向量问题**（找一个最短的非零格点）与**最近向量问题**（找离给定目标最近的格点），以及多项式近似因子下的近似版本。最好的算法——格筛分法或枚举——用时关于维数 $n$ 指数增长；量子算法只把指数改进一点。密码学使用的，是这些问题的一种平均情形形式。

::: definition 带错学习（learning with errors） {#def-lwe}
设 $n, q$ 为整数，$\chi$ 是在小整数上的一个分布（例如在 $\{-1, 0, 1\}$ 上均匀，或小宽度的离散高斯）。对秘密 $\mathbf s \in \Z_q^n$，一个 **LWE 样本**是 $(\mathbf a, b)$，其中 $\mathbf a$ 在 $\Z_q^n$ 上均匀，$b = \langle\mathbf a, \mathbf s\rangle + e \bmod q$，$e \gets \chi$。**判定 LWE 问题**是：以不可忽略的优势，把 $m$ 个 LWE 样本——写成矩阵即 $(A, A\mathbf s + \mathbf e)$，$A \in \Z_q^{m\times n}$——与 $(A, \mathbf u)$（$\mathbf u$ 在 $\Z_q^m$ 上均匀）区分开。
:::

没有误差时，$A\mathbf s = \mathbf b$ 是一个高斯消元法能在多项式时间内解出的线性方程组。小小的误差却让问题看起来难：消元会把误差不断放大，直到淹没答案。Regev（2005）证明：对合适的参数，平均情形解 LWE 至少和用量子算法解*任意* $n$ 维格上的近似最短向量问题一样难——这是分解与离散对数所不享有的那种从最坏情形到平均情形的归约——而 Peikert（2009）等人对某些参数给出了经典版本。

### Regev 加密体制

::: definition Regev 加密（一位） {#def-regev}
参数 $n, m, q$ 与误差分布 $\chi$。密钥生成在 $\Z_q^n$ 中均匀选取 $\mathbf s$，在 $\Z_q^{m \times n}$ 中均匀选取 $A$，并取 $\mathbf e \gets \chi^m$；公钥是 $(A, \mathbf b = A\mathbf s + \mathbf e)$，私钥是 $\mathbf s$。加密比特 $\mu$ 时，选取均匀的 $\mathbf r \in \{0, 1\}^m$（即行的随机子集），输出
$$
\mathbf u = \mathbf r^{\mathsf T}A \in \Z_q^n, \qquad v = \mathbf r^{\mathsf T}\mathbf b + \mu\lfloor q/2\rfloor \in \Z_q .
$$
解密时计算 $d = v - \langle\mathbf u, \mathbf s\rangle \bmod q$；若 $d$（模 $q$ 意义下）离 $0$ 比离 $\lfloor q/2\rfloor$ 近则输出 $0$，否则输出 $1$。
:::

::: theorem Regev 加密的正确性与安全性 {#thm-regev}
(a) 只要 $\lvert\mathbf r^{\mathsf T}\mathbf e\rvert < q/4$，解密就正确；特别地，若每个误差的绝对值至多为 $B$ 且 $mB < q/4$，则永远正确。(b) 若判定 LWE 困难且 $m \ge (n + 1)\log_2 q + \omega(\log n)$，则方案是 CPA-安全的。
:::

::: proof
(a) $d = \mathbf r^{\mathsf T}(A\mathbf s + \mathbf e) + \mu\lfloor q/2\rfloor - \mathbf r^{\mathsf T}A\mathbf s = \mu\lfloor q/2\rfloor + \mathbf r^{\mathsf T}\mathbf e$。项 $\mathbf r^{\mathsf T}\mathbf e$ 是至多 $m$ 个误差之和，故 $\lvert\mathbf r^{\mathsf T}\mathbf e\rvert \le mB$。只要它绝对值小于 $q/4$，$d$ 就落在 $\mu\lfloor q/2\rfloor$ 的 $q/4$ 范围之内，解密返回 $\mu$。

(b) 考虑一个混合实验：公钥 $(A, \mathbf b)$ 换成 $(A, \mathbf u')$，$\mathbf u'$ 均匀。若某个 CPA 对手在真实方案与这个混合之间的成功率有显著差别，就能据以把 LWE 样本与均匀分布区分开——用通常的归约（区分器用挑战构造公钥、执行加密，并转述对手的猜测）。在混合实验中，矩阵 $[A \mid \mathbf u']$ 是均匀的，而**残留哈希引理**——这里不证直接用——说：当 $m \ge (n+1)\log_2 q + \omega(\log n)$ 时，对均匀的 $\mathbf r \in \{0,1\}^m$，对子 $([A \mid \mathbf u'],\ \mathbf r^{\mathsf T}[A \mid \mathbf u'])$ 在统计上接近均匀。于是 $(\mathbf u, \mathbf r^{\mathsf T}\mathbf u')$ 接近均匀，像一次一密一样遮蔽 $\mu\lfloor q/2\rfloor$，所以对手在混合实验中的优势可忽略。
:::

::: example 玩具数字上的 Regev 加密 {#ex-regev}
取 $n = 4$、$m = 8$、$q = 97$，误差在 $\{-1, 0, 1\}$ 上均匀。生成密钥，加密比特 $0, 1, 1, 0$ 并解密，每次展示 $d$ 的值。
::: solution
这里 $mB = 8 < q/4 = 24.25$，故由 [[#thm-regev]] 解密永不失败。

```python
import random
random.seed(2026)
n, m, q = 4, 8, 97                        # 玩具参数：完全不安全
s = [random.randrange(q) for _ in range(n)]                    # 秘密密钥
A = [[random.randrange(q) for _ in range(n)] for _ in range(m)]
e = [random.choice([-1, 0, 1]) for _ in range(m)]              # 小误差
b = [(sum(a * x for a, x in zip(row, s)) + err) % q for row, err in zip(A, e)]

def encrypt(bit):
    S = [i for i in range(m) if random.random() < 0.5]         # 行的随机子集
    u = [sum(A[i][j] for i in S) % q for j in range(n)]
    v = (sum(b[i] for i in S) + bit * (q // 2)) % q
    return u, v, S

def decrypt(u, v):
    d = (v - sum(x * y for x, y in zip(u, s))) % q             # = bit*48 + 误差之和
    return 0 if min(d, q - d) < q // 4 else 1, d

print("s =", s, "e =", e)
for bit in (0, 1, 1, 0):
    u, v, S = encrypt(bit)
    print(bit, S, u, v, decrypt(u, v))
```

第一个密文取子集为行 $\{1, 2, 6\}$，其误差之和为 $1 + 1 + 0 = 2$，事实上 $d = 2$，接近 $0$。第二个取行 $\{0, 1, 2, 4, 5\}$，误差之和为 $0 + 1 + 1 - 1 + 1 = 2$，而 $d = 48 + 2 = 50$，接近 $\lfloor 97/2\rfloor = 48$。每个 $d$ 都是"被小噪声扰动过的消息"。真实参数用几百维的 $n$ 和大得多的 $m$；这个玩具密钥可以把 $97^4 \approx 8.9 \times 10^7$ 个秘密全部试一遍找回来。

### 从 Regev 到 ML-KEM

Regev 方案的公钥是 $m \times n$ 个数，而且一次只加密一个比特。**环 LWE** 与**模 LWE** 用例如 $R_q = \Z_q[X]/(X^{256} + 1)$ 这样环上的多项式代替整数，于是一个环元素携带 256 个系数，而乘法——用数论变换快速计算，它是 FFT 的模运算类比——把它们全部混合起来。**ML-KEM**（模格 KEM，FIPS 203，2024 年 8 月）源自 CRYSTALS-Kyber 提交方案，在 $q = 3329$ 时处理 $R_q$ 上的 $k \times k$ 矩阵，参数集 ML-KEM-512、ML-KEM-768、ML-KEM-1024（NIST 安全等级 1、3、5）分别取 $k = 2, 3, 4$。秘密与误差取自中心化二项分布；密文通过丢弃低序比特来压缩（这又加进一点噪声）；而**Fujisaki–Okamoto 变换**的一个变体把 CPA-安全的加密变成 CCA-安全的 KEM：解封装方把解出的消息重新加密，若结果与收到的密文不符，它返回一个由秘密值导出的伪随机密钥而不是报错（**隐式拒绝**），使攻击者从畸形密文什么都学不到。解密可能失败，ML-KEM-768 的失败概率低于 $2^{-164}$——远低于任何其他风险。

**ML-DSA**（FIPS 204）源自 CRYSTALS-Dilithium，是模格上精神同于 Schnorr（[[cryptography/signatures#def-schnorr]]）的 Fiat–Shamir 签名：签名者对一个掩蔽后的值作出承诺，经哈希导出挑战，然后应答；由于格的应答可能通过其分布泄露秘密，签名者检查应答是否落在安全范围内，否则**中止并带着新随机量重来**（"带中止的 Fiat–Shamir"，Lyubashevsky 2009），从而发表的应答与密钥无关。

## 基于哈希的签名

签名可以只凭哈希函数构造，安全性除哈希的单向性或抗碰撞性外不依赖任何东西——而对这两个性质，量子计算机只提供有限的加速。这使它们成为最保守的后量子选择。

::: definition Lamport 一次性签名 {#def-lamport}
设 $H$ 是输出 $n$ 比特的哈希函数，并对 $\ell$ 比特的消息签名（实际签的是消息的 $\ell$ 比特哈希）。私钥是 $2\ell$ 个均匀的 $n$ 比特串 $x_{i,b}$，$i = 1, \dots, \ell$、$b \in \{0, 1\}$；公钥是 $y_{i,b} = H(x_{i,b})$。对 $m = m_1\dots m_\ell$ 签名时，揭示 $\sigma = (x_{1,m_1}, \dots, x_{\ell,m_\ell})$。验证时对每个 $i$ 检查 $H(\sigma_i) = y_{i,m_i}$。
:::

每对密钥只能签**一**条消息：签两条在第 $i$ 位不同的消息，就把 $x_{i,0}$ 和 $x_{i,1}$ 一起泄露了；签名够多时，攻击者能把原像拼来拼去，给新消息签名。

::: theorem Lamport 签名是一次安全的 {#thm-lamport}
若 $H$ 是单向的，则 Lamport 方案在对手至多对自己选定的一条消息取得签名的情形下存在不可伪造：任何 PPT 伪造者成功的概率可忽略。
:::

::: proof
设 $\mathcal A$ 以概率 $\varepsilon$ 伪造。构造求逆器 $\mathcal I$，它拿到均匀 $x^*$ 的 $y^* = H(x^*)$，必须找出一个原像。$\mathcal I$ 均匀选取 $i^* \in \{1, \dots, \ell\}$ 与 $b^* \in \{0, 1\}$，自己生成所有其他 $x_{i,b}$，并令 $y_{i^*, b^*} = y^*$。这个公钥的分布与真实公钥完全相同，且不提供关于 $(i^*, b^*)$ 的任何信息。当 $\mathcal A$ 请求对 $m$ 签名：若 $m_{i^*} = b^*$，$\mathcal I$ 无法回答，中止；否则它用自己知道的原像作答。当 $\mathcal A$ 输出伪造 $(m', \sigma')$ 且 $m' \ne m$ 时，若 $m'_{i^*} = b^*$，则 $\sigma'_{i^*}$ 就是 $y^*$ 的一个原像，$\mathcal I$ 输出它。

$\mathcal I$ 在"$\mathcal A$ 伪造成功、$m_{i^*} \ne b^*$ 且 $m'_{i^*} = b^*$"时得手。由 $m' \ne m$，存在位置 $j$ 使 $m'_j \ne m_j$；事件"$i^* = j$ 且 $b^* = m'_j$"的概率是 $\tfrac1\ell\cdot\tfrac12$，与 $\mathcal A$ 的行为无关（后者不依赖 $(i^*, b^*)$），并且它蕴含上述两个条件。于是 $\mathcal I$ 至少以概率 $\varepsilon/(2\ell)$ 逆转 $H$；若 $H$ 单向，则 $\varepsilon$ 可忽略。（若 $\mathcal A$ 一个签名都不请求，同样的论证去掉中止条件即适用。）
:::

::: example 玩具 Lamport 签名 {#ex-lamport}
用一把对 8 比特摘要签名（取 SHA-256 哈希的首字节）的 Lamport 密钥为消息 `release v2.1` 签名，并检查该签名对 `release v6.6` 验证不过。
::: solution
```python
import hashlib, secrets

def H(x: bytes) -> bytes:
    return hashlib.sha256(x).digest()

ELL = 8                                              # 对 8 比特摘要签名（玩具）
sk = [[secrets.token_bytes(32) for b in range(2)] for i in range(ELL)]
pk = [[H(sk[i][b]) for b in range(2)] for i in range(ELL)]

def bits(m: bytes):                                   # H(m) 的前 ELL 位
    d = H(m)[0]
    return [(d >> (ELL - 1 - i)) & 1 for i in range(ELL)]

def sign(m):
    return [sk[i][bit] for i, bit in enumerate(bits(m))]

def verify(m, sig):
    return all(H(s) == pk[i][bit] for i, (s, bit) in enumerate(zip(sig, bits(m))))

sig = sign(b"release v2.1")
print(bits(b"release v2.1"), verify(b"release v2.1", sig), verify(b"release v6.6", sig))
```

```console
$ python3 lamport.py
[0, 0, 0, 0, 0, 1, 1, 1] True False
```

`release v2.1` 的摘要比特是 `00000111`，所以签名揭示了 $x_{1,0}, \dots, x_{5,0}, x_{6,1}, x_{7,1}, x_{8,1}$。`release v6.6` 的摘要比特是 `10100100`，在五个位置上不同，所以验证失败：伪造者需要（例如）从未被揭示的 $x_{1,1}$。当然，摘要只有 8 位时，伪造者尽可另找一条摘要为 `00000111` 的消息（每 256 次尝试就有一次成功）；真实方案签完整的 256 位哈希，代价是公钥 $2 \cdot 256 \cdot 32 = 16$ KiB、签名 $8$ KiB——这就是实用方案改用 Winternitz 链这类更紧凑的一次性签名的原因。
:::
:::

**从一到多次签名。**Merkle（1979）注意到，$2^h$ 个一次性公钥可以用一棵哈希二叉树来承诺——一棵**默克尔树**——其根就是唯一的公钥。一次签名由下一个未用一次性密钥的签名、那个一次性公钥、以及沿路径到根的 $h$ 个兄弟哈希（**认证路径**）组成，验证者据此重算出根。安全性归约到一次性方案与树的哈希的抗碰撞性。但签名者必须记住自己用过哪些叶——这是一个**有状态**方案——而在恢复备份或克隆虚拟机之后重用一片叶，安全就破了。有状态方案 XMSS（RFC 8391）与 LMS（RFC 8554）已在状态能被小心管理的场合标准化，例如固件签名（NIST SP 800-208）。

**SLH-DSA**（FIPS 205）源自 SPHINCS+，去掉了状态。它搭成一棵默克尔树的*超树*，上层的叶为下层树的根签名，最底层是一个**少次**签名方案（FORS），并且最底层的叶由消息伪随机地选定，于是即便签上 $2^{64}$ 次，同一片叶被用到成事的次数也几乎不可能。代价是大小与速度：签名约 8 到 50 KB，签名时间比 ML-DSA 慢几个数量级。回报是其安全性只依赖 SHA-2 或 SHAKE 的标准性质（[[cryptography/hash-mac]]）——这些假设被研究的时间远比格长久。

::: warning 新假设需要时间——新标准也需要经过评审的实现
进入 NIST 流程最后两轮的方案中有两个在 2022 年被经典方式攻破：多变量签名方案 Rainbow（被 Ward Beullens 攻破）与基于同源密钥交换 SIKE（被 Wouter Castryck 与 Thomas Decru 攻破，主参数集在一台笔记本电脑上大约花了一小时）。它们的数学是可靠的，但它们具体的困难假设被研究的时间太短。这正是过渡期的部署采用**混合**构造的原因——把一个经典方案（X25519、ECDSA）与一个后量子方案组合，使二者*任一*安全则整体安全；这也是只依赖最古老假设的哈希方案 SLH-DSA 与格方案一同被标准化的原因。ML-KEM 与 ML-DSA 在实现上也是新的：其安全性依赖常数时间的采样、解码与拒绝，而早期实现有过计时泄露。请使用维护中、经过评审的库里的实现，绝不用自己的实现，并把本章的玩具代码就当作玩具。
:::

## 截至 2026 年的迁移

NIST 的流程始于 2016 年的方案征集，收到 69 份完整提交，经过三轮公开分析，于 2022 年 7 月选定 CRYSTALS-Kyber、CRYSTALS-Dilithium、SPHINCS+ 与 Falcon。前三个于 2024 年 8 月 13 日成为 FIPS 203、204、205；一个基于 Falcon 的标准（FN-DSA，签名更短，但需要微妙的浮点高斯采样）将作为 FIPS 206 随后发布。2025 年 3 月，NIST 还选定了 **HQC**——一个基于纠错码的 KEM——作为依托不同假设的 ML-KEM 后备。NIST 的过渡计划（NIST IR 8547 草案，2024 年）提议在 2030 年后淘汰 112 位安全级别上易受量子攻击的公钥算法，2035 年后禁止使用；其他国家的政府也公布了类似的时间表。

密钥交换最先行动，因为"现在收集、以后解密"。混合密钥份额 **X25519MLKEM768** 把 X25519 与 ML-KEM-768 两个共享秘密一起送进 TLS 1.3 密钥表（[[cryptography/protocols]]），自 2024–2025 年起已在主流浏览器和大型内容分发网络中默认启用，因此到 2026 年，很大一部分网络流量已经受到对未来量子解密的保护；SSH 与消息协议（如 Signal 的 PQXDH，2023 年）也加入了可比的混合方案。签名与证书移动得慢一些：未来发生的签名伪造不会危害过去的流量，而更大的尺寸影响每一条证书链，所以万维网公钥基础设施迁往 ML-DSA（或迁往减少所发签名数量的新证书设计）预计要用去本余下的十年。长寿命签名——固件信任根、代码签名——是例外，基于哈希的方案已在那些地方使用。

::: quiz
某机构加密的医疗记录必须保密 25 年，并且它为软件更新签名，签名密钥每两年轮换一次。它应当先把什么迁到后量子密码？

- [x] 保护医疗记录的密钥交换与加密，因为被录下的密文日后可能被解密。
- [ ] 软件更新的签名，因为签名更容易被伪造。
- [ ] 都不迁，因为 2026 年不存在大型量子计算机。
- [ ] 记录的 AES-256 加密，用 ML-KEM 取代它。
::: solution
机密性是受追溯性威胁的：对手可以现在录下密钥交换，并在量子计算机一旦出现时——很可能就在 25 年窗口之内——把它破解。签名只须在人们信任它的期间抵抗伪造，因此短期签名密钥可以稍后再迁（长寿命信任根是另一回事）。AES-256 本身不需要替换；ML-KEM 取代的是建立 AES 密钥的那个**公钥**步骤。
:::
:::

::: history
Ralph Merkle 的博士论文（1979）引入了哈希树，以及从 Lamport 1979 年一次性方案构造的多次签名；McEliece 于 1978 年提出基于编码的加密。Peter Shor 于 1994 年发表了他的分解与离散对数量子算法（期刊版 1997 年），Lov Grover 于 1996 年发表了他的搜索算法。Miklós Ajtai 于 1996 年证明格问题存在从最坏情形到平均情形的归约；Jeffrey Hoffstein、Jill Pipher 与 Joseph Silverman 于 1996 年提出 NTRU 密码体制（1998 年发表）；Oded Regev 于 2005 年引入带错学习（期刊版 2009 年），这项工作为他赢得了 2018 年哥德尔奖。Vadim Lyubashevsky、Chris Peikert 与 Regev 于 2010 年引入环 LWE。NIST 于 2016 年宣布后量子标准化流程，2022 年 7 月选定首批算法，并于 2024 年 8 月 13 日发布 FIPS 203、204、205；同样在 2022 年夏天，Rainbow 与 SIKE 被攻破。
:::

## 后续内容

量子算法本身——量子傅里叶变换、周期寻找、幅度放大，以及一台对密码学有威胁的机器所需的纠错——在 [[quantum-computing]] 中展开。复杂性类 $\mathsf{BQP}$ 以及它不包含 $\mathsf{NP}$ 的证据——这正是格问题被认为对量子计算机仍保持困难的原因——在 [[complexity]]。把新方案部署进协议——混合密钥交换、更大的证书链、软件中的密码敏捷性（crypto-agility）——是 [[security]] 的一部分；而量子密钥分发用量子物理而非计算困难性来分发一次一密的密钥（[[cryptography/perfect-secrecy]]），是对同一威胁的另一种回应，其部署约束则截然不同。

::: summary
- **肖尔算法**在量子计算机上以多项式时间求阶与离散对数，在任何密钥长度上打破 RSA、有限域与椭圆曲线 Diffie–Hellman、DSA、ECDSA 与 EdDSA；分解可用经典方式归约到求阶（[[#prop-order-factor]]）。
- **格罗弗算法**对密钥搜索只有平方根加速，且天生串行；AES-128 对多数用途仍然够用，AES-256 留有裕量，SHA-2/SHA-3 保持安全。
- **带错学习**（[[#def-lwe]]）——带噪声的线性方程组——和最坏情形格问题一样难；**Regev 加密**在累积误差低于 $q/4$ 时正确解密，并在 LWE 假设下 CPA-安全（[[#thm-regev]]）。**ML-KEM**（FIPS 203）与 **ML-DSA**（FIPS 204）是模格方案，密钥与密文约一千字节或更大。
- **基于哈希的签名**只需要哈希函数：**Lamport** 一次性签名在 $H$ 单向时安全（[[#thm-lamport]]）；默克尔树给出多次签名的有状态方案（XMSS、LMS），**SLH-DSA**（FIPS 205）无状态，代价是巨大的签名。
- 截至 2026 年，混合密钥交换（**X25519MLKEM768**）已在 TLS 中广泛部署，签名迁移较慢，新假设则被谨慎对待——两个入围方案在 2022 年被经典方式攻破。请使用经过评审的实现。
:::

## 习题

::: exercise 用一个阶做分解 {level=1 check="5"}
$a = 2$ 模 $N = 15$ 的阶是 $r = 4$。用 [[#prop-order-factor]] 求 $15$ 的两个素因子中较大的那个。（填入它。）
::: solution
$2^{r/2} = 2^2 = 4 \not\equiv -1 \pmod{15}$。于是 $\gcd(4 - 1, 15) = 3$、$\gcd(4 + 1, 15) = 5$。较大的因子是 $5$。
:::
:::

::: exercise 格罗弗对 AES-128 {level=1 check="2^64"}
格罗弗算法找一把 128 位密钥大约需要对 AES 作多少次串行求值？取最近的 2 的幂。（以 2 的幂填入。）
::: solution
约 $\tfrac\pi4\sqrt{2^{128}} = \tfrac\pi4 \cdot 2^{64} \approx 0.79 \cdot 2^{64}$，取最近的 2 的幂是 $2^{64}$——每一次都是容错量子计算机上一次完整的可逆 AES 运算，只能一次接一次地跑。摊到 $2^{20}$ 台机器上也只把每台的时间降到 $2^{54}$ 次求值。
:::
:::

::: exercise 手算一次 Regev 解密 {level=1}
设 $q = 97$，某条密文给出 $d = v - \langle\mathbf u, \mathbf s\rangle \bmod q = 45$。它解密成哪个比特？若解密正确，累积误差是多少？对 $d = 95$ 再做一遍。
::: solution
$\lfloor 97/2\rfloor = 48$。$d = 45$ 离 $48$ 的距离是 $3$、离 $0$ 的距离是 $45$，所以比特是 $1$，误差为 $45 - 48 = -3$。$d = 95$ 离 $0$ 的距离是 $2$（因为 $97 - 95 = 2$）、离 $48$ 的距离是 $47$，所以比特是 $0$，误差为 $-2$。
:::
:::

::: exercise 解密何时会失败 {level=2 check="24"}
在 Regev 方案中，误差以 $B = 1$ 为界、$q = 97$，[[#thm-regev]](a) 要对每种子集选取都保证解密正确，$m$ 最大能取多少？（填入 $m$。）
::: solution
需要 $mB < q/4 = 24.25$，故 $m \le 24$。$m$ 更大时解密以高概率仍正确，因为随机符号之和在一个随机子集上通常大小约为 $\sqrt m$ 而非 $m$——真实方案正是据此选参数，接受一个微小、计算精确的失败概率。
:::
:::

::: exercise 混合密钥份额 {level=2 check="2336"}
一次使用 X25519MLKEM768 的 TLS 1.3 握手中，客户端与服务器加起来一共发送多少字节的密钥份额数据？与单用 X25519 相比如何？（填入混合方案的总数。）
::: solution
客户端：$32 + 1184 = 1216$ 字节；服务器：$32 + 1088 = 1120$ 字节；总计 $2336$ 字节，而单用 X25519 是 $64$ 字节——每次完整握手约多 $2.2$ KiB，通常仍装得进最初几个数据包。
:::
:::

::: exercise 两个 Lamport 签名 {level=2}
一把对 4 比特摘要签名的 Lamport 密钥签了摘要 `0110` 与 `1100`。哪些私钥值已被揭示？攻击者现在还能为哪些摘要签名？
::: solution
`0110` 揭示 $x_{1,0}, x_{2,1}, x_{3,1}, x_{4,0}$；`1100` 揭示 $x_{1,1}, x_{2,1}, x_{3,0}, x_{4,0}$。于是位置 $1$ 与位置 $3$ 的两个值都已揭示，位置 $2$ 与位置 $4$ 只揭示了 $x_{2,1}$ 与 $x_{4,0}$。所以攻击者能为形如 $b_1\,1\,b_3\,0$ 的任何摘要签名：`0100`、`0110`、`1100`、`1110`——其中两个是新的。签名多了，几乎每个位置的两个值都会被暴露，这就是每对密钥只能签一次的原因。
:::
:::

::: exercise 一棵默克尔树 {level=3}
说明一棵高 $h = 3$、架在八个 Lamport 公钥之上的默克尔树如何得到一个能为八条消息签名的签名方案。一次签名包含什么？验证者为重算根要做多少次哈希计算（验证 Lamport 签名之外）？签名者忘记自己用过哪些叶会出什么事？
::: solution
叶是八个一次性公钥的 $L_j = H(\mathit{pk}_j)$；每个内部节点是其两个孩子之哈希；根就是公钥。为第 $j$ 条消息签名时，签名者用 $\mathit{sk}_j$ 产生一个 Lamport 签名，附上 $j$、$\mathit{pk}_j$ 以及从叶 $j$ 到根路径上的三个兄弟哈希。验证者用 $\mathit{pk}_j$ 检验 Lamport 签名，计算 $L_j = H(\mathit{pk}_j)$，然后向上做三次哈希，按 $j$ 的各个比特给出的顺序与兄弟合并——共四次哈希计算，一般情形是 $h + 1$ 次——再与根比较。伪造者要么伪造一个一次性签名，要么找出另一个向上哈希到同一根的 $\mathit{pk}$，而这需要一个碰撞。签名者若重用一片叶，就是拿一把 Lamport 密钥签两条消息，上一题已说明这是不安全的：这就是状态的由来，也是 SLH-DSA 用伪随机选叶来避免它的理由。
:::
:::

::: exercise 为什么要混合 {level=3}
一个混合 KEM 把会话密钥取为 $k = \mathrm{KDF}(k_1 \,\|\, k_2 \,\|\, \mathit{transcript})$，由 X25519 共享秘密 $k_1$ 与 ML-KEM 共享秘密 $k_2$ 导出。把 KDF 建模为随机预言机，非形式地论证：只要 $k_1$ 与 $k_2$ 中*有一个*与随机不可区分，$k$ 就与随机不可区分。为什么要带上会话记录（密文与公钥）？
::: solution
设 $k_2$ 即便在对手看到的一切之下也与均匀串不可区分（因为 ML-KEM 安全），而 $k_1$ 可能被完全知晓（因为 X25519 已被破解）。在随机预言机模型中，除非对手恰好对 $k_1 \| k_2 \| \mathit{transcript}$ 查询过预言机，$k$ 就是一个全新的随机值，而要做到这一点必须猜中 $k_2$；这只有可忽略的成功概率，否则对手就把 $k_2$ 与随机区分开了。论证对 $k_1$ 与 $k_2$ 对称。带上会话记录把密钥绑定到确切使用的那些公钥与密文上，使攻击者不能把不同会话的组件拼在一起、也不能替换其中一个组件，并且对那些共享秘密本身不依赖密文的 KEM 的弱点也构成了防护。TLS 的混合把拼接后的秘密喂给 [[cryptography/protocols]] 中与会话记录绑定的密钥表。
:::
:::
