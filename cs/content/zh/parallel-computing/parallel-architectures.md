下面是同一个 C 程序在一台机器上分别用 $1, 2, 4, \dots, 32$ 个线程运行的结果。第一个实验中，每个线程对保存在自己寄存器里的数做算术运算；第二个实验中，每个线程把自己那一份共 $3.2$ GB 的 `double` 数组各自求和。总工作量固定，且在线程之间均分。

```console
$ nproc
36
$ for p in 1 2 4 8 16 32; do ./scale 0 $p 1600000000; done     # 计算受限
p= 1  1.644 s  (sum 1.6e+09)
p= 2  0.822 s  (sum 1.6e+09)
p= 4  0.419 s  (sum 1.6e+09)
p= 8  0.213 s  (sum 1.6e+09)
p=16  0.111 s  (sum 1.6e+09)
p=32  0.057 s  (sum 1.6e+09)
$ for p in 1 2 4 8 16 32; do ./scale 1 $p 400000000; done      # 访存受限
p= 1  0.538 s  (sum 4e+08)
p= 2  0.307 s  (sum 4e+08)
p= 4  0.152 s  (sum 4e+08)
p= 8  0.088 s  (sum 4e+08)
p=16  0.062 s  (sum 4e+08)
p=32  0.061 s  (sum 4e+08)
```

算术运算版在 $32$ 个线程上快了 $1.644 / 0.057 \approx 29$ 倍。数组求和版在 $4$ 个线程之前几乎完美加速，随后便停滞了：$16$ 和 $32$ 个线程耗时相同，约为单线程的 $8.8$ 倍。两个程序每个线程执行的循环迭代次数相同；不同的是它们用到机器的哪一部分。每个线程都有自己的核心，但所有线程共享通往内存的通路，而第二个程序把这些通路占满了。

以上是在一台机器上的观测——一台装有两只 $18$ 核 Intel Xeon E5-2696 v3 处理器的服务器（Haswell 微架构，2014 年），GCC 15、Linux，与其他用户共享，记录于 2026 年——你的数字会有所不同。但它们所讲的道理不会变：**并行计算机是一组资源的集合，有些资源是复制的，有些是共享的；并行程序的速度由它最先耗尽的那种共享资源决定。**本章概览这些资源。我们先讲处理器为何走上并行之路，用 Flynn 分类法对并行机分类，然后逐层考察：多核处理器及其存储系统、SIMD 向量单元、GPU，以及由网络相连、其拓扑可以精确分析的集群。本课程其余部分讲如何给这些机器编程；本章讲的是弄清你在给什么编程。

## 为什么每个处理器都是并行的

从 20 世纪 70 年代到 21 世纪初，单线程性能大约每两年翻一番，多数程序员可以等着更快的硬件，而不必重写代码。两股趋势推动了这一点。**摩尔定律**（Moore's law，戈登·穆尔（Gordon Moore），1965，1975 年修订）观察到芯片上晶体管的数量大约每两年翻一番。**登纳德缩放**（Dennard scaling，罗伯特·登纳德（Robert Dennard）等人，1974）解释了这为何不是功耗问题：若晶体管的每个线性尺寸缩小 $k$ 倍、电压也随之缩小，则每个晶体管的开关速度快 $k$ 倍而功耗只有 $1/k^2$，于是单位面积的功耗保持不变。

芯片因开关动作耗散的功率称为**动态功耗**

$$
P_{\text{dyn}} = a\, C\, V^2 f,
$$ {#eq-power}

其中 $a$ 是每个周期内处于开关状态的晶体管比例（活动因子），$C$ 是被开关的电容，$V$ 是电源电压，$f$ 是时钟频率。在同一设计中，更高的频率需要大致成比例更高的电压才能让晶体管及时翻转，所以 $P_{\text{dyn}}$ 大约按 $f^3$ 增长。

2005 年前后，登纳德缩放走到尽头。电压低于约 $1$ V 之后，就无法再逐代随之下降，因为晶体管在该关断的时候会漏电，而阈值电压一降低，漏电流便急剧增长。$V$ 卡住之后，再提高 $f$ 只会让功耗与热量的上升快过芯片的散热能力。Intel 于 2004 年取消了计划中主频 4 GHz 以上的 Pentium 4 后继产品，并于 2005 年出货双核处理器；IBM 的 POWER4 早在 2001 年就已把两个核心放进一颗芯片。晶体管数量仍在增长——摩尔定律又延续了二十年，尽管在放缓——只是它们被用到了*更多*的核心、更宽的向量单元和更大的高速缓存上，而不是更快的时钟上。

::: example 两个较慢的核心对一个较快的核心 {#ex-two-cores}
在 $P \propto f^3$ 模型下（电压与频率成正比），比较一个频率为 $f$ 的核心与两个频率各为 $0.8f$ 的相同核心。假设工作可以在两者之间完美划分。
::: solution
单核功耗为 $P_1 = c f^3$，吞吐量为 $1$（以频率 $f$ 下单位时间完成的工作量计）。每个慢核心功耗 $c(0.8f)^3 = 0.512\,cf^3$，所以一对核心功耗 $1.024\,P_1$——大致相同的功耗。它们的吞吐量为 $2 \times 0.8 = 1.6$。用基本相同的功耗多完成 $60\%$ 的工作，*前提是*程序能用上两个核心。这个前提正是本课程的主题。实际上电压不能一路按频率成比例下降，静态（漏电）功耗根本不降，而且第二个核心要占用芯片面积；但这一权衡的方向，正是处理器设计者转向多核的原因。
:::
:::

::: widget plot
f: 1; n*(1/n)^(1/3)
x: 0, 1
y: 0, 4
sliders: n=2:1:16:1
labels: \text{满速运行的单核心}; \text{同等总功耗下 } n \text{ 个核心的吞吐量}
caption: 在 $P \propto f^3$ 模型下，$n$ 个核心分摊一个核心的功耗预算，每个都能以 $f/n^{1/3}$ 运行，总吞吐量为单核的 $n^{2/3}$ 倍（横轴在此无关紧要；两条线都是常数）。把 $n$ 从 $2$ 拖到 $16$：频率减半的八个核心带来四倍的吞吐量。注意这一收益只属于能让全部 $n$ 个核心都忙碌的程序——顺序程序在多核芯片上反而*慢* $n^{1/3}$ 倍。
:::

这一后果有时被称为"免费午餐"的终结（赫布·萨瑟（Herb Sutter）语，2005）：软件只有并行起来，才能在新硬件上变快。今天一台笔记本有 $4$ 到 $16$ 个核心，每个核心配有一个能同时对 $4$ 到 $16$ 个数进行运算的向量单元；一部手机有八个核心和一块 GPU；一台大型服务器有一百多个核心（均为 2026 年的情形）。最快的超级计算机把数万个这样的节点组合在一起。

## Flynn 分类法

迈克尔·弗林（Michael Flynn，1966，1972 年扩充）按计算机同时处理多少条指令流和多少条数据流为其分类。这一分类很粗糙，但其术语世界通用。

::: definition Flynn 分类法 {#def-flynn}
**指令流**是一个控制单元执行的指令序列；**数据流**是它所操作的操作数序列。

- **SISD**（single instruction, single data，单指令单数据）：经典的顺序处理器。
- **SIMD**（single instruction, multiple data，单指令多数据）：一条指令流驱动许多处理单元，每个单元以锁步方式对自己的数据施加同一操作。向量处理器、现代 CPU 的向量指令（SSE、AVX、NEON、SVE），以及——在较宽泛的意义上——GPU。
- **MISD**（multiple instruction, single data，多指令单数据）：多条指令流作用于一条数据流。罕见；通常的例子是对同一数据流做不同操作的流水线，以及互相校验的多余度飞行计算机。
- **MIMD**（multiple instruction, multiple data，多指令多数据）：彼此独立的处理器，各自有自己的指令流和数据流。多核处理器、共享内存多处理器与集群。
:::

MIMD 的两个细化贯穿本课程。为 MIMD 硬件写的程序通常是 **SPMD**（single program, multiple data，单程序多数据）：每个处理器都运行同一个程序，但数据不同、所走分支也可能不同——它是哪个处理器，即它的**编号**（rank）或线程号，决定它承担哪一份工作。开头两个实验都是 SPMD。GPU 则被 NVIDIA 描述为 **SIMT**（single instruction, multiple threads，单指令多线程）：程序员像 SPMD 那样为单个线程写标量程序，硬件则把线程组成 $32$ 个一组按 SIMD 锁步执行（[[parallel-computing/gpu-programming]]）。

实践中更重要的区分不是 Flynn 的分类，而是内存如何组织。

::: definition 共享内存与分布式内存 {#def-memory-org}
**共享内存**机器中，所有处理器都能对同一地址空间的任何位置做读写；它们通过读写内存通信。若每个处理器访问每个位置的速度相同，则为 **UMA**（uniform memory access，一致内存访问）；若内存划分给各个节点、处理器访问本节点的内存比访问别处的更快，则为 **NUMA**（non-uniform memory access，非一致内存访问）。

**分布式内存**机器中，每个处理器有私有的地址空间；处理器之间只能通过网络互发消息通信。
:::

开头实验那台机器就是一台双节点 NUMA 机器：每个处理器插槽有自己的内存控制器和内存，两个插槽之间由一条点到点链路相连（这一代 Intel 的 QPI）。任一插槽上的线程都能访问全部 $161$ GiB 内存，但远端访存代价更高。集群是分布式内存机器，其节点本身又是共享内存机器，所以今天大多数大型程序是**混合**的：节点内用线程，节点间用消息。

::: example 读懂这台机器 {#ex-lscpu}
找出开头实验那台机器的处理器数、核心数、每核心线程数、高速缓存大小和 NUMA 节点数。
::: solution
`nproc` 报告本进程可在其上运行的处理器数；`lscpu` 给出机器结构（输出有删节）：

```console
$ lscpu
Model name:            Intel(R) Xeon(R) CPU E5-2696 v3 @ 2.30GHz
CPU(s):                72
On-line CPU(s) list:   0-35
Off-line CPU(s) list:  36-71
Thread(s) per core:    2
Core(s) per socket:    18
Socket(s):             2
L1d cache:             1.1 MiB (36 instances)
L2 cache:              9 MiB (36 instances)
L3 cache:              90 MiB (2 instances)
NUMA node(s):          2
NUMA node0 CPU(s):     0-17,36-53
NUMA node1 CPU(s):     18-35,54-71
```

机器有 $2$ 个插槽，每个 $18$ 核。每个核心支持两个硬件线程（**同时多线程**（simultaneous multithreading），即 Intel 的超线程 Hyper-Threading），本应给出 $72$ 个逻辑 CPU，但每个核心的第二个线程已被关闭：CPU $36$–$71$ 离线，在线的 CPU $0$–$17$（节点 $0$）与 $18$–$35$（节点 $1$）是 $36$ 个互不相同的物理核心。每个核心有私有的 $32$ KiB L1 数据高速缓存和 $256$ KiB L2 高速缓存；一个插槽的 $18$ 个核心共享 $45$ MiB 的 L3 高速缓存。多数机器都启用 SMT，此时 `nproc` 统计的是逻辑 CPU 数，为核心数的两倍。
:::
:::

## 多核处理器内部

现代核心即便只跑一个线程，其自身也高度并行。它是**流水线的**（多条指令同时处于不同流水段）、**超标量的**（每周期发射多条指令）且**乱序的**（操作数就绪就立即执行，而不按程序顺序）。这种**指令级并行**由硬件从顺序代码中挖掘，除性能外对程序员不可见；其工作原理属于计算机体系结构，在[电气工程图谱](/learn/ee/)中讲授。本课程讲的是必须由程序员表达的并行：跨核心的**线程级并行**，以及核心内向量单元上的**数据级并行**。

每个核心有私有的 L1、L2 高速缓存；一颗芯片上的核心共享末级高速缓存、内存控制器以及通往其他插槽的链路（[[computer-systems/memory-hierarchy]] 讲过单个核心的高速缓存）。高速缓存里放的是内存的*副本*，因此当两个核心缓存同一条缓存行、其中一个写入时，另一个的副本必须被更新或作废。硬件通过**缓存一致性协议**自动完成这一点，它让高速缓存对正确性透明——但对性能并不透明，因为一条缓存行每秒可能在核心之间来回迁移数千次。[[parallel-computing/memory-consistency]] 研究一致性问题，以及更微妙的*顺序*问题：一个核心的写以什么顺序对另一个核心可见。

**同时多线程**（SMT）让一个核心同时保存两个（有时四个或八个）线程的状态，并在同一周期从所有线程发射指令。当单个线程会让核心的功能单元闲置——例如在等待高速缓存缺失——时它很有用；而当线程本已让它们忙碌时用处很小。一个核心上的两个硬件线程共享它的缓存与功能单元，所以它们不是两个核心。

::: warning 逻辑 CPU 不是核心
`nproc`、`os.cpu_count()` 和 `omp_get_num_procs()` 报告的是*逻辑* CPU 数。启用 SMT 时这通常是物理核心数的两倍，而计算受限程序从第二个硬件线程一般只多得 $0\%$ 到 $30\%$ 的吞吐，绝不是 $100\%$。测量加速比之前，先弄清这个数字在你的机器上意味着什么（`lscpu`，如 [[#ex-lscpu]]），并在每份测量报告里注明核心数与 SMT 设置。本课程的这台机器禁用了 SMT，所以它的 $36$ 个逻辑 CPU 就是 $36$ 个核心。
:::

开头实验现在就说得通了。计算受限的循环把每个线程都留在自己的核心里，只用寄存器：核心是复制的资源，所以时间几乎按 $1/p$ 下降。（降得略少一些：处理器为了不超过功耗预算，会随活跃核心增多而降低睿频频率——还是 [[#eq-power]] 的道理——而且机器上当时还跑着其他用户的作业。）访存受限的循环每次加法大约要从内存取 $8$ 字节。单个核心单独读出的速度约为 $3.2 \text{ GB} / 0.538 \text{ s} \approx 6$ GB/s，受限于它能同时挂起多少个高速缓存缺失；$16$ 个核心合计达到约 $52$ GB/s，此后存储系统就饱和了。更多的线程只是在同一组导线上排队。[[parallel-computing/performance-laws]] 把这一观测变成**屋顶线模型**（roofline model），而 [[parallel-computing/performance-engineering]] 表明在这台机器上数组在内存中的摆放也有影响：主线程初始化了整个数组，所以它的页全部分配在一个 NUMA 节点上。

## SIMD 与向量单元

**向量指令**把一个操作作用于宽寄存器中存放的一个短操作数向量。上面那颗处理器的 AVX2 指令使用 $256$ 位寄存器，可放 $4$ 个 `double` 或 $8$ 个 `float`；一条 `vfmadd231pd` 指令一次算出 $4$ 个 $i$ 值的 $c_i \gets c_i + a_i b_i$——这是一条**融合乘加**指令，每个元素记作两次浮点运算。AVX-512 把宽度翻倍；ARM 的 SVE 允许硬件在 $128$ 到 $2048$ 位之间选择宽度，程序在运行时适应它。

::: definition 峰值浮点速度 {#def-peak}
处理器的**峰值**浮点速度为

$$
F_{\text{峰值}} = (\text{核心数}) \times (\text{时钟频率}) \times (\text{每周期向量指令数}) \times (\text{每向量通道数}) \times (\text{每通道运算数}).
$$ {#eq-peak}

它是一个上界，真实的程序只有在让每个向量单元都忙于融合乘加、且从不等待内存时才能接近它。
:::

::: example Haswell 服务器的峰值 {#ex-peak}
每颗 Haswell 核心每周期能发射两条 AVX2 融合乘加。计算 $36$ 核机器在其 $2.3$ GHz 基准频率下的双精度峰值，并与约 $2 \times 68$ GB/s 的峰值内存带宽（每插槽四个 DDR4-2133 通道）比较。
::: solution
每周期每核心做 $2 \times 4 \times 2 = 16$ 次双精度运算（$2$ 条指令、$4$ 个通道、每条融合乘加 $2$ 次运算）；单精度、$8$ 个通道时为 $32$ 次。于是

$$
F_{\text{峰值}} = 36 \times 2.3 \times 10^9 \times 16 \approx 1.32 \times 10^{12}\ \text{flop/s} = 1.32\ \text{Tflop/s}.
$$

内存最多输送约 $136$ GB/s，即每秒 $17 \times 10^9$ 个 `double`。因此，程序若要跑到峰值，每从内存载入一个 `double` 大约必须做 $1325 / 17 \approx 78$ 次浮点运算——约每字节 $10$ 次。很少有程序做得到：数组求和每 $8$ 字节只做一次。这个比值，即机器的**平衡度**（balance），是 [[parallel-computing/performance-laws]] 屋顶线模型的核心。
:::
:::

向量单元有两种用法。编译器会对简单循环**自动向量化**——`gcc -O3` 在能证明这样做安全时，把 `for (i…) c[i] = a[i] + b[i];` 变成向量指令——编译器做不到时，程序员使用**内在函数**（intrinsics，如 `_mm256_fmadd_pd`）或可移植的 SIMD 库。阻碍向量化的是迭代之间的依赖、数组之间可能的别名、分支，以及存储不连续的数据；[[parallel-computing/performance-engineering]] 对每一项都有实测。

## GPU

**图形处理器**（GPU）把 [[#ex-two-cores]] 的权衡推到极端。GPU 没有少数几个大型乱序核心，而是有几十个**流多处理器**（SM，NVIDIA 的叫法；AMD 的对应部件叫*计算单元*），每个带有许多简单算术通道、一个大型寄存器堆和一小块片上暂存存储器。它几乎不做分支预测，也不乱序执行；它靠让成千上万个线程常驻、每周期在它们的小组之间切换来隐藏访存时延。GPU 上的程序是一个**核函数**（kernel），由成千上万乃至上百万线程组成的网格来执行的函数，每个线程计算结果的一小块。

这种设计对拥有大量规则数据并行的程序回报丰厚——稠密线性代数、图像处理、网格模拟，以及神经网络的训练与推理——在这些负载上 GPU 每瓦提供的算术能力和内存带宽比 CPU 高一个数量级。对并行度少、分支不规则或需要指针追踪的程序，回报就很差。独立 GPU 还有自己的内存：数据必须先经 PCIe 或 NVLink 总线拷贝过去核函数才能使用，在小问题上这笔开销足以吞掉加速比。[[parallel-computing/gpu-programming]] 详细研究这一模型。

## 集群与互连网络

超出单机之后，并行机就是**集群**：一个个节点，每个是一台共享内存计算机，由网络连接。网络可以是通用的以太网，也可以是时延更低、支持远程内存访问的专用高性能互连（InfiniBand、HPE Slingshot 等，2026 年）。程序通过消息传递通信，通常经由 MPI（[[parallel-computing/message-passing]]）。

网络的*拓扑*——哪些节点或交换机连到哪些——决定消息要走多远、网络能承载多少流量。我们把它建模成图：处理器或交换机是顶点，链路是边（[数学图谱：图](/learn/maths/lesson.php?c=discrete&l=graphs)）。

::: definition 拓扑度量 {#def-topology}
对建模成连通图 $G = (V, E)$、含 $p = \lvert V \rvert$ 个节点的互连网络：

- **度**是每个节点上链路数的最大值——一个节点或交换机需要的端口数；
- **直径**是全体节点对之间最短路长度的最大值——最坏情况的跳数；
- **对分宽度**是把 $V$ 切成大小分别为 $\lfloor p/2 \rfloor$ 和 $\lceil p/2 \rceil$ 的两半所需删去边数的最小值——衡量一次能有多少流量横穿机器中部的指标。
:::

直径约束时延；对分宽度约束"机器这一半与另一半通信"这类模式的吞吐量，例如排序或转置。网络的**代价**大致就是链路数。经典拓扑有：

- $p$ 个节点的**环**：度 $2$，直径 $\lfloor p/2 \rfloor$，对分宽度 $2$。
- **二维网格** $k \times k$（$p = k^2$）：度 $4$，直径 $2(k - 1)$，对分宽度 $k$（$k$ 为偶数）。
- **二维环面** $k \times k$，带回绕链路的网格：度 $4$，直径 $2\lfloor k/2 \rfloor$，对分宽度 $2k$（$k$ 为偶数）。
- 维数为 $d$ 的**超立方体**（$p = 2^d$）：节点是 $d$ 位串，恰差一位者相连；度 $d$，直径 $d$，对分宽度 $2^{d-1} = p/2$。
- 处理器挂在叶子的交换机**树**：直径 $2\log p$，但对分宽度 $1$——根是瓶颈。**胖树**（Charles Leiserson，1985）让越靠近根的链路容量成比例地更大，使对分宽度增至 $p/2$；用相同交换机构造的折叠 Clos 网络实现了它，今天多数数据中心与超算网络都属于这一族。
- **交叉开关**：每个处理器经交换矩阵连到每个内存或其他处理器；直径 $1$、对分满配，但要 $p^2$ 个开关，所以只适合小 $p$。

::: theorem 超立方体的直径与对分宽度 {#thm-hypercube}
$d$ 维超立方体 $Q_d$ 有 $p = 2^d$ 个节点，直径为 $d$，对分宽度为 $2^{d-1}$。
:::

::: proof
**直径。** 沿一条边走一步恰改变一位，所以从 $u$ 到 $v$ 的路至少需要 $u$ 与 $v$ 相差的位数那么多步，即它们的**汉明距离** $h(u, v)$；而 $h(u, v)$ 步也够用：逐次翻转有差异的位即可。于是距离就是 $h(u, v) \le d$，互补串取等。

**对分宽度上界。** 设 $S$ 为首位在 $0$ 的节点集，$T$ 为首位在 $1$ 的节点集；两半各有 $2^{d-1}$ 个节点。它们之间的边恰是第 $1$ 维的那些边，$S$ 中每个节点一条：共 $2^{d-1}$ 条。

**对分宽度下界。** 让每个节点 $s$ 到每个 $t \ne s$ 的消息都沿**逐位修正路径**走：按从第 $1$ 位到第 $d$ 位的顺序修正有差异的位。考虑一条从 $u$ 到 $u \oplus e_i$（翻转第 $i$ 位）的有向边。$s$ 到 $t$ 的路恰在它修正第 $i$ 位时位于 $u$ 才使用这条边，这意味着 $t_1 \dots t_{i-1} = u_1 \dots u_{i-1}$、$s_i \dots s_d = u_i \dots u_d$ 且 $t_i \ne u_i$。自由的位是 $s_1 \dots s_{i-1}$ 和 $t_{i+1} \dots t_d$，所以恰有 $2^{i-1} \cdot 2^{d-i} = 2^{d-1}$ 个有序对使用每条有向边。现在任取一种把节点分成各含 $p/2$ 个节点的 $S$、$T$ 两半、切掉 $c$ 条边的对分。每个满足 $s \in S$、$t \in T$ 的有序对 $(s, t)$——共 $(p/2)^2$ 个——其路径至少沿一条由 $S$ 指向 $T$ 的割边离开 $S$，而这样一条有向边承载 $2^{d-1} = p/2$ 条路径。故 $c \cdot p/2 \ge (p/2)^2$，即 $c \ge p/2 = 2^{d-1}$。
:::

::: example 64 节点的拓扑对比 {#ex-topologies}
在 $p = 64$ 个节点上比较环、$8 \times 8$ 环面和 $6$ 维超立方体：链路数、度、直径和对分宽度。用广度优先搜索验证直径。
::: solution
| 拓扑 | 链路数 | 度 | 直径 | 对分宽度 |
|---|---|---|---|---|
| 环 | $64$ | $2$ | $32$ | $2$ |
| $8 \times 8$ 环面 | $128$ | $4$ | $8$ | $16$ |
| 超立方体 $Q_6$ | $192$ | $6$ | $6$ | $32$ |

链路：环有 $p$ 条；环面 $2p$ 条（每个节点四条链路，每条由两个节点共享）；超立方体 $dp/2 = 6 \cdot 64 / 2$ 条。一个简短的 Python 程序算出直径：

```python
from collections import deque

def diameter(nodes, nbrs):
    def ecc(s):                          # s 的离心率，用 BFS 计算
        dist, q = {s: 0}, deque([s])
        while q:
            u = q.popleft()
            for v in nbrs(u):
                if v not in dist:
                    dist[v] = dist[u] + 1
                    q.append(v)
        return max(dist.values())
    return max(ecc(s) for s in nodes)

p, k, d = 64, 8, 6
print(diameter(range(p), lambda u: [(u + 1) % p, (u - 1) % p]))
print(diameter([(i, j) for i in range(k) for j in range(k)],
               lambda u: [((u[0] + a) % k, (u[1] + b) % k)
                          for a, b in ((1, 0), (-1, 0), (0, 1), (0, -1))]))
print(diameter(range(2 ** d), lambda u: [u ^ (1 << i) for i in range(d)]))
```

```console
$ python3 topo.py
32
8
6
```

超立方体在直径和对分宽度上取胜，代价是度随 $\log p$ 增长；$p = 2^{20}$ 个节点时每个节点需要 $20$ 个端口。环面对任意规模都把度保持为 $4$，并天然对应模拟物理网格的程序，这就是若干台超级计算机（Cray 的 T3D 与 T3E、IBM 的 Blue Gene、富士通的 K 计算机与 Fugaku）采用三维到六维环面的原因。胖树把复杂性放进交换机而非节点，从而绕开了这一权衡。
:::

::: quiz
关于本章的机器，哪些说法正确？
- [x] 多核节点组成的集群是 MIMD，为其编写的程序通常是 SPMD。
- [ ] 双插槽 NUMA 服务器是分布式内存机器，因为每个插槽有自己的内存。
- [x] AVX2 中一次对四对 `double` 求和的指令是 SIMD 的一个例子。
- [ ] $p$ 个节点的环和 $p$ 个节点的超立方体对分宽度相同，因为两者都是连通的。
::: solution
集群的节点在各自的数据上执行彼此独立的指令流（MIMD），而标准的编程方式是在每个节点上运行同一个程序、以编号区分（SPMD）。NUMA 服务器仍是*共享*内存机器：每个核心都能对任何地址读写，只是快慢不同（[[#def-memory-org]]）。向量加法是一条指令作用于多个数据元素：SIMD。环的对分宽度不管多大都是 $2$，而超立方体的是 $p/2$（[[#thm-hypercube]]）。
:::
:::

::: history
最早的并行机是向量机与阵列处理机。ILLIAC IV 由伊利诺伊大学的丹尼尔·斯洛特尼克（Daniel Slotnick）主持设计，20 世纪 70 年代中期起在 NASA 艾姆斯研究中心运行，有 $64$ 个处理单元由一个控制单元驱动——弗林（Flynn）意义上的 SIMD。迈克尔·弗林（Michael Flynn）在 "Very high-speed computing systems"（*Proceedings of the IEEE*，1966）中提出他的分类法，并于 1972 年作了扩充。西摩·克雷（Seymour Cray）的 Cray-1（1976）让向量处理在此后二十年里成为超级计算机的主导设计。1980 年代出现了大规模并行机：加州理工的 Cosmic Cube（查尔斯·塞茨（Charles Seitz）与杰弗里·福克斯（Geoffrey Fox），1983），一台 $64$ 个微处理器的超立方体，开创了消息传递；丹尼·希利斯（Danny Hillis）的 Connection Machine（1985），有 $65{,}536$ 个 1 位处理器。托马斯·斯特林（Thomas Sterling）与唐纳德·贝克尔（Donald Becker）在 NASA 戈达德航天中心做出的 Beowulf 集群（1994）证明商用 PC 加以太网也能干同样的活，此后集群一直统治着超级计算机 TOP500 榜单（始于 1993）。罗伯特·登纳德（Robert Dennard）的缩放定律（1974）在 2000 年代中期走到尽头；IBM 的 POWER4（2001）是第一颗商用多核处理器，双核桌面处理器于 2005 年接踵而至。NVIDIA 的 CUDA（2006 年宣布，2007 年发布）把图形处理器变成了通用并行机。
:::

## 后续内容

下一章 [[parallel-computing/performance-laws]] 问并行程序究竟能快多少：阿姆达尔定律与古斯塔夫森定律、工作量-跨度模型，以及把本章平衡度计算精确化的屋顶线模型。之后课程沿本章的层次展开。共享内存机器用线程与 OpenMP 编程（[[parallel-computing/shared-memory]]）；它们的高速缓存要保持一致、访存要有次序（[[parallel-computing/memory-consistency]]）；共享数据结构需要新的设计（[[parallel-computing/concurrent-data-structures]]）。[[parallel-computing/parallel-algorithms]] 设计与机器无关的算法；[[parallel-computing/gpu-programming]] 与 [[parallel-computing/message-passing]] 把它们映射到 GPU 和集群上；[[parallel-computing/performance-engineering]] 则在真实代码上把这一切合起来。分布式系统——许多台独立失效、没有共享时钟的机器——是 [[distributed-systems]] 的主题。

::: summary
- 登纳德缩放在 2005 年前后终结，处理器于是走向并行：动态功耗 $aCV^2f$ 约按 $f^3$ 增长，所以几个较慢的核心比一个快的核心每瓦吞吐更高（[[#ex-two-cores]]）——但只对并行程序如此。
- **Flynn 分类法**（[[#def-flynn]]）区分 SISD、SIMD、MISD 与 MIMD；多数并行程序是 **SPMD**，GPU 是 **SIMT**。内存组织——**共享**（UMA 或 NUMA）还是**分布式**（[[#def-memory-org]]）——在实践中更重要。
- 多核芯片复制核心与私有高速缓存，却共享末级缓存、内存控制器与内存带宽：在我们机器的 $32$ 个核心上，计算受限循环加速 $29$ 倍，访存受限的只有 $8.8$ 倍。
- 向量单元成倍提高算术速度：**峰值** = 核心数 × 时钟频率 × 每周期向量指令数 × 每向量通道数 × 每通道运算数（[[#eq-peak]]）；我们的 $36$ 颗 Haswell 核心为 $1.32$ Tflop/s，而内存带宽约 $136$ GB/s。
- GPU 以单线程速度换取海量简单通道与线程，靠在其间切换来隐藏时延；它在规则的数据并行负载上出类拔萃。
- 互连网络按度、**直径**和**对分宽度**比较（[[#def-topology]]）；超立方体直径 $\log p$、对分宽度 $p/2$（[[#thm-hypercube]]），环是 $p/2$ 和 $2$，胖树用固定度数的交换机做到满对分。
- SMT 线程不是核心：务必弄清 `nproc` 数的是什么。
:::

## 习题

::: exercise 笔记本的峰值速度 {level=1 check="384"}
一台笔记本处理器有 $8$ 个 $3$ GHz 的核心，每个核心每周期能发射两条 $256$ 位融合乘加。其双精度峰值是多少 Gflop/s？（填入 Gflop/s 数。）
::: solution
由 [[#eq-peak]]：$8 \times 3 \times 10^9 \times 2 \times 4 \times 2 = 384 \times 10^9$ flop/s，即 $384$ Gflop/s。（单精度、$8$ 个通道时是 $768$ Gflop/s。）持续负载下时钟常低于标称值，所以这个峰值偏乐观。
:::
:::

::: exercise 超立方体的直径 {level=1 check="10"}
一个超立方体网络有 $1024$ 个节点。它的直径是多少？（填入跳数。）
::: solution
$1024 = 2^{10}$，所以它是 $Q_{10}$，由 [[#thm-hypercube]] 直径为 $10$——一个节点到其互补串的距离。每个节点需要 $10$ 个端口，共有 $10 \cdot 1024 / 2 = 5120$ 条链路。
:::
:::

::: exercise 环面的对分宽度 {level=1 check="16"}
$8 \times 8$ 二维环面的对分宽度是多少？（填入链路数。）解释为什么从中间切一刀就跨过这么多条链路。
::: solution
$16$。在第 $4$、$5$ 列之间切开环面：$8$ 行中的每一行都是 $8$ 个节点的环，一条竖直切线两次穿过每行——一次在中间、一次在回绕链路——共 $2 \times 8 = 16$ 条链路。（按行切同理。）要证明没有哪个对分用的链路更少，需要类似 [[#thm-hypercube]] 下界的论证；偶数 $k \times k$ 环面结果为 $2k$ 是标准结论。不带回绕链路的网格对分宽度为 $8$。
:::
:::

::: exercise Flynn 分类 {level=1}
把下列各项按 Flynn 分类法分类，并说明其内存是共享还是分布式：(a) 单核执行一个标量循环；(b) 同一核心执行一个 AVX2 循环；(c) 双插槽服务器运行一个 OpenMP 程序；(d) $100$ 个集群节点运行一个 MPI 程序；(e) 三台飞行计算机计算同一控制律并对结果表决。
::: solution
(a) SISD（忽略指令级并行，它不改变指令流）。(b) SIMD：一条指令流，每条指令作用于四个或八个数据元素。(c) 共享内存（NUMA）的 MIMD：每个核心有自己的指令流；全部共享一个地址空间。(d) 分布式内存的 MIMD，按 SPMD 编程。(e) 通常被当作 MISD 式的冗余，尽管严格地说每台计算机都有自己的数据流副本；它恰好说明 MISD 多么不适配真实机器。
:::
:::

::: exercise 慢核心的功率 {level=2 check="1.024"}
在 [[#ex-two-cores]] 的 $P \propto f^3$ 模型下，两个以单核频率 $80\%$ 运行的核心，总功耗是该单核功耗的多少倍？（填入倍数。）多少颗以 $50\%$ 频率运行的核心能装进一颗满速核心的功耗预算，其总吞吐是多少？
::: solution
$2 \times 0.8^3 = 1.024$。半频时每个核心功耗为 $0.5^3 = 1/8$，所以预算装得下 $8$ 个核心，吞吐 $8 \times 0.5 = 4$ 倍于单核——即图中 $n = 8$ 时的 $n^{2/3}$。真实芯片的电压降不到某个下限之下，所以三次方律在低频处变平；漏电功耗无论频率如何都要按核心支付；实际收益更小。
:::
:::

::: exercise 带宽耗尽之时 {level=2 check="8"}
一个处理器的单核从内存读数据的速度为 $6$ GB/s，而存储系统给所有核心合计至多 $48$ GB/s。一个只在数组上流水读数的程序（如开头实验）从任意多核心所能获得的最大加速比是多少？（填入加速比。）在多少个核心上达到？
::: solution
时间是字节数除以达到的带宽，即 $p$ 核时 $\min(6p, 48)$ GB/s。对单核的加速比是 $\min(6p, 48)/6 = \min(p, 8)$，至多 $8$，在 $p = 8$ 个核心达到。再多核心只能等待。开头实验每核约 $6$ GB/s、总计 $52$ GB/s，表现一样（加速比 $8.8$）。在 [[parallel-computing/performance-laws]] 中这就是屋顶线的带宽顶。
:::
:::

::: exercise 解释计算受限的结果 {level=2}
开头的计算受限实验中，$32$ 个线程只比单线程快 $28.8$ 倍而不是 $32$ 倍。列出至少三个可能的原因，并设计实验区分其中两个。
::: solution
(1) **频率**：受功耗预算所限，Intel 处理器只有单核活跃时睿频更高（本机可达 $3.8$ GHz），所以单线程基线跑在更高的时钟上。(2) **干扰**：其他用户的作业占用了部分核心（load average 约 $7$），有些线程与别的进程共享一个核心。(3) **线程的创建与汇合**每个线程要几十微秒——对 $57$ ms 虽小，但并非为零。(4) **不均衡**：程序要等最慢的线程；某个线程被中断或繁忙邻居拖慢，所有人都得等。要区分 (1) 与 (2)，可以锁定频率后重复测量（有权限的话用 `cpupower frequency-set`），或在运行期间从 `/proc/cpuinfo` 读取实际频率；也可以在空闲机器上重做，或对每个配置重复多次取最小值——这能滤掉干扰，滤不掉频率效应。
:::
:::

::: exercise 超立方体的边 {level=2}
证明 $Q_d$ 有 $d\,2^{d-1}$ 条边，且是**二部图**（节点可染成两种颜色，使每条边两端异色）。由此推出 $Q_d$ 没有奇长度环。
::: solution
$2^d$ 个节点中每个恰有 $d$ 个邻居（翻转 $d$ 位中的一位），每条边被两端各计一次，所以有 $d\,2^d / 2 = d\,2^{d-1}$ 条边。按节点所含 $1$ 位的奇偶染色。翻转一位使该位数增减一，所以每条边连接偶节点与奇节点：图是二部的。任一圈上颜色交替，回到起点时颜色复原，故边数为偶。
:::

::: exercise 嵌进超立方体的环 {level=3}
一个为 $p = 2^d$ 个处理器的环写的程序（每个与两个邻居通信）要放到超立方体 $Q_d$ 上运行。说明如何把环位 $0, \dots, p - 1$ 分配给超立方体节点，使环上相邻者在超立方体中亦相邻（一个**膨胀**（dilation）为 $1$ 的嵌入）。证明你的构造可行，并给出 $d = 3$ 时的分配。
::: solution
用**二进制反射格雷码**（Gray code）：$G_1 = (0, 1)$；$G_{d+1}$ 是把 $G_d$ 的每个字冠以 $0$，再接上*倒序*的 $G_d$ 且每个字冠以 $1$。把环位 $i$ 分配给 $G_d$ 的第 $i$ 个字。

对 $d$ 归纳证明：$G_d$ 恰一次列出全体 $2^d$ 个 $d$ 位字，且相邻两字——包括末字与首字——恰差一位。$d = 1$ 时，$0$ 与 $1$ 差一位。设结论对 $G_d$ 成立。$G_{d+1}$ 的字是 $2^d$ 个 $0w$ 与 $2^d$ 个 $1w$，互不相同。同一半内相邻的字差一位，因为 $G_d$（或其倒序）的相邻字如此。接缝处，前半的末字是 $0w_{\text{last}}$，后半的首字是 $1w_{\text{last}}$（倒序从末字开始）：只差首位。回绕处，$G_{d+1}$ 的末字是 $1w_{\text{first}}$，首字是 $0w_{\text{first}}$：同样只差一位。

$d = 3$ 时：$000, 001, 011, 010, 110, 111, 101, 100$。写进代码，第 $i$ 个字是 `i ^ (i >> 1)`。同样的想法给每个坐标用一个格雷码，可把 $2^a \times 2^b$ 环面嵌入 $Q_{a+b}$，这就是超立方体机器能高效运行网格程序的原因。
:::

::: exercise 用程序算直径 {level=3}
把 [[#ex-topologies]] 的程序扩展到 $k \times k$ 网格（无回绕），以及 $p$ 个处理器挂在叶子的满二叉交换机树（只数叶子之间的跳数）。对 $p = 16, 64, 256$ 列出直径，并与公式 $2(k - 1)$、$2\log p$ 核对。
::: solution
对网格，$(i, j)$ 的邻居是落在网格内的至多四个位置 $(i \pm 1, j)$、$(i, j \pm 1)$。对树，按二叉堆的方式编号——节点 $v$ 的孩子是 $2v$ 与 $2v + 1$、父亲是 $\lfloor v/2 \rfloor$，节点 $1, \dots, p - 1$ 是交换机，$p, \dots, 2p - 1$ 是叶子——并且只对叶子取最大离心率：

```python
def mesh(k):
    nodes = [(i, j) for i in range(k) for j in range(k)]
    def nbrs(u):
        cand = [(u[0] + 1, u[1]), (u[0] - 1, u[1]), (u[0], u[1] + 1), (u[0], u[1] - 1)]
        return [v for v in cand if 0 <= v[0] < k and 0 <= v[1] < k]
    return nodes, nbrs

def tree(p):                                  # p 个叶子，堆编号
    def nbrs(v):
        out = [v // 2] if v > 1 else []
        return out + ([2 * v, 2 * v + 1] if v < p else [])
    return range(p, 2 * p), nbrs              # 只算叶子的离心率

for k, p in ((4, 16), (8, 64), (16, 256)):
    print(p, diameter(*mesh(k)), diameter(*tree(p)))
```

由于 `ecc` 从每个起点探索全图，而 `diameter` 只从交给它的节点出发，传入叶子度量的就是最大的叶-叶距离（离叶子最远的节点还是叶子）。输出为

```console
16 6 8
64 14 12
256 30 16
```

与 $2(k - 1) = 6, 14, 30$ 和 $2\log p = 8, 12, 16$ 吻合。树的直径只按对数增长，但对分宽度是 $1$；网格的直径按 $\sqrt{p}$ 增长，对分宽度也按 $\sqrt{p}$ 增长。
:::
