下面这个 OpenMP 程序有两个阶段。第一阶段用一个伪随机发生器填充一个含两千万个数的数组，每个值都由前一个算出，所以这一阶段无法在线程之间划分。第二阶段对每个元素独立地施加四十步逻辑斯谛映射，再把结果加起来——这一阶段可以完美划分。

```c
#include <omp.h>
#include <stdio.h>

enum { N = 20000000 };
static double x[N];

int main(void) {
    double t0 = omp_get_wtime();
    unsigned long s = 1;                     /* 串行阶段：线性同余发生器， */
    for (long i = 0; i < N; i++) {           /* 每个值都由上一个算出 */
        s = s * 6364136223846793005UL + 1442695040888963407UL;
        x[i] = (double)(s >> 11) / 9007199254740992.0;   /* 位于 [0, 1) 内 */
    }
    double t1 = omp_get_wtime();
    double sum = 0;                          /* 并行阶段：相互独立的工作 */
    #pragma omp parallel for reduction(+ : sum)
    for (long i = 0; i < N; i++) {
        double y = x[i];
        for (int k = 0; k < 40; k++) y = y * (1.0 - y) * 3.9;   /* 逻辑斯谛映射 */
        sum += y;
    }
    double t2 = omp_get_wtime();
    printf("p=%2d  serial %.3f s  parallel %.3f s  total %.3f s  (sum %.6f)\n",
           omp_get_max_threads(), t1 - t0, t2 - t1, t2 - t0, sum / N);
    return 0;
}
```

本章给出回答这类问题的定量工具。我们定义加速比与效率，证明**阿姆达尔定律**与**古斯塔夫森定律**并看清它们为何并不矛盾，学会从测量估计程序的串行比例。然后，我们把"串行"与"并行"两部分的粗糙划分换成把并行计算看作任务图的精确模型——**工作量-跨度模型**——并证明**布伦特定理**，它说明任何这样的计算在 $p$ 个处理器上最快能被调度到多快。最后，**屋顶线模型**从另一侧为性能定界，其依据正是 [[parallel-computing/parallel-architectures]] 发现的那许多程序的瓶颈——内存带宽。

## 加速比与效率

::: definition 加速比与效率 {#def-speedup}
设 $T_1$ 为程序在一个处理器上的运行时间，$T_p$ 为其在 $p$ 个处理器上的运行时间。**加速比**与**效率**为

$$
S(p) = \frac{T_1}{T_p}, \qquad E(p) = \frac{S(p)}{p} = \frac{T_1}{p\,T_p}.
$$ {#eq-speedup}

若 $T_1$ 是该并行程序在一个处理器上的时间，$S$ 称为**相对加速比**；若它是该问题最优顺序程序的时间，$S$ 称为**绝对加速比**。加速比为 $p$（效率 $1$）称为**线性**；超过 $p$ 的加速比称为**超线性**。
:::

相对加速比更容易测量，却可能自我美化：一个做了最优顺序程序两倍工作的并行算法，可能显示出完美的相对加速比，而实际只比你原本要跑的程序快 $p/2$ 倍。尽量报告绝对加速比，并说清你报告的是哪一种。

超线性加速比看似不可能——$p$ 个处理器把一件活干得比 $p$ 倍还快——在工作量-跨度模型中它确实不可能（见 [[#thm-laws]]）。实践中它发生在划分数据之后、每个处理器的那份装进了它的高速缓存时：$p$ 个处理器带来 $p$ 倍的高速缓存，于是并行程序的慢速访存总次数更少。这是缓存效应，不是多出来的算力；当顺序程序也为缓存做了分块时，它便消失了（[[parallel-computing/performance-engineering]]）。

度量可扩展性的两种方式回答不同的问题：

- **强扩展**（strong scaling）：固定问题规模，增大 $p$，画出 $T_p$ 或 $S(p)$。它回答"这个问题能再快多少？"
- **弱扩展**（weak scaling）：让问题随 $p$ 增长、保持每个处理器的工作量不变，画出 $T_p$（理想情形下是常数）或缩放加速比。它回答"同样的时间我能解多大的问题？"

## 阿姆达尔定律

吉恩·阿姆达尔（Gene Amdahl）1967 年在为快速单处理器对抗当时提出的并行机而辩护时观察到：程序的顺序部分限制着任意多个处理器所能达到的一切。

::: theorem 阿姆达尔定律 {#thm-amdahl}
假设程序在单个处理器上运行时间的比例 $f$（$0 \le f \le 1$）必须顺序执行，而剩下的比例 $1 - f$ 可以在任意多个处理器之间完美划分。则在 $p$ 个处理器上

$$
S(p) = \frac{1}{f + \dfrac{1 - f}{p}}, \qquad\text{且}\qquad S(p) < \frac{1}{f} \text{（若 } f > 0\text{，对一切 } p\text{）}.
$$ {#eq-amdahl}
:::

::: proof
在一个处理器上，顺序部分耗时 $fT_1$，并行部分 $(1 - f)T_1$。在 $p$ 个处理器上，顺序部分仍耗时 $fT_1$，而完美划分的并行部分耗时 $(1 - f)T_1/p$。于是 $T_p = fT_1 + (1 - f)T_1/p$，$S(p) = T_1/T_p = 1/(f + (1 - f)/p)$。只要 $f < 1$ 就有 $(1 - f)/p > 0$，故分母大于 $f$，从而 $S(p) < 1/f$；若 $f = 1$，则 $S(p) = 1 = 1/f$ 从不被超出。当 $p \to \infty$ 时，$S(p) \to 1/f$。
:::

::: example 把阿姆达尔定律用于开头的程序 {#ex-amdahl}
开头那次运行中，串行阶段在 $1.295$ s 里占了 $0.131$ s。预测 $2, 4, \dots, 32$ 个线程下的加速比并与实测比较。任意多个线程的上限是多少？
::: solution
串行比例为 $f = 0.131/1.295 \approx 0.101$。[[#eq-amdahl]] 给出预测；实测加速比是表中数据的 $T_1/T_p$，效率为 $S/p$：

| $p$ | $1$ | $2$ | $4$ | $8$ | $16$ | $32$ |
|---|---|---|---|---|---|---|
| 阿姆达尔 $S(p)$ | $1.00$ | $1.82$ | $3.07$ | $4.69$ | $6.36$ | $7.75$ |
| 实测 $S(p)$ | $1.00$ | $1.82$ | $3.03$ | $4.78$ | $6.35$ | $6.82$ |
| 实测 $E(p)$ | $1.00$ | $0.91$ | $0.76$ | $0.60$ | $0.40$ | $0.21$ |

$16$ 个线程以内，定律对实测的预测误差在 $3\%$ 以内。到 $32$ 时程序达不到，原因是阿姆达尔模型没有考虑的：并行阶段自己就用了 $0.067$ s 而不是 $1.164/32 = 0.036$ s，因为要付出启动与同步 $32$ 个线程的代价、内存受到争用、睿频频率更低，还有其他用户的作业。上限是 $1/f \approx 9.9$：多少个处理器也无法让这个程序快上十倍。要更好，就去并行化发生器——例如给每个线程一个自己的发生器，或在序列中向前跳跃，线性同余发生器是允许这样做的（[[#ex-lcg-jump]]）。
:::
:::

阿姆达尔定律以一种确切的方式悲观：它把*问题*固定住。$1\%$ 的串行比例把加速比封顶在 $100$，这在 1967 年让大规模并行机显得毫无意义。然而如今拥有数百万个核心的机器正高效地运行着真实应用。化解来自二十年后。

## 古斯塔夫森定律

1988 年，桑迪亚国家实验室的约翰·古斯塔夫森（John Gustafson）报告了在一台 $1024$ 处理器的超立方体上，三个科学应用取得了超过 $1000$ 的加速比，而按阿姆达尔的标准，它们的串行比例本应把加速比封顶在低得多的地方。他的解释是：用户不是在大机器上跑同一个问题，而是在同样的时间里跑更大的问题。串行部分——读输入、做准备工作——通常保持不变，而并行部分随机器增长。

::: theorem 古斯塔夫森定律 {#thm-gustafson}
假设某程序在 $p$ 个处理器上运行 $T_p$ 时间，其中比例 $s$ 花在顺序代码上，$1 - s$ 花在让全部 $p$ 个处理器忙于独立工作的代码上。则同样的工作在一个处理器上要花 $T_1 = sT_p + p(1 - s)T_p$，**缩放加速比**为

$$
S(p) = \frac{T_1}{T_p} = s + p(1 - s) = p - s(p - 1).
$$ {#eq-gustafson}
:::

::: proof
顺序部分在任何处理器数目下都花 $sT_p$。并行部分占据 $p$ 个处理器 $(1 - s)T_p$ 时间，所以其中包含 $p(1 - s)T_p$ 处理器秒的工作，一个处理器执行这些工作需要 $p(1 - s)T_p$。相加得 $T_1$，再除以 $T_p$ 即得 [[#eq-gustafson]]。
:::

两条定律是同样的代数，只是固定的东西不同。阿姆达尔固定问题，在*一个*处理器上测串行比例 $f$；古斯塔夫森固定运行时间，在 *$p$* 个处理器上测串行比例 $s$。对固定的问题，两个比例满足 $f = s/(s + p(1 - s))$，把它代入阿姆达尔公式即得古斯塔夫森公式。两条定律都无所谓"对"：强扩展受阿姆达尔支配，弱扩展受古斯塔夫森支配。拿到更大机器的气候学家会细化网格；银行有一项固定要跑一整夜的批处理任务，只想让它早点完事。

::: example 大机器上的天气模型 {#ex-gustafson}
一个模拟在 $1024$ 个处理器上运行，把运行时间的 $2\%$ 花在顺序的准备与输出上。它的缩放加速比是多少？若同一个问题在一个处理器上运行，阿姆达尔定律会看到多大的串行比例？它会预测 $1024$ 个处理器的加速比是多少？
::: solution
由 [[#eq-gustafson]]，$S = 1024 - 0.02 \times 1023 = 1003.5$。按阿姆达尔的视角，归一化 $T_{1024} = 1$：顺序部分占 $0.02$，并行部分占 $0.98$，在一个处理器上就是 $0.98 \times 1024 = 1003.52$。所以 $T_1 = 1003.54$，$f = 0.02/1003.54 \approx 2.0 \times 10^{-5}$。用这个 $f$ 的阿姆达尔定律给出 $1/(f + (1 - f)/1024) \approx 1003.5$——同一个数，本来就该如此。大问题之所以串行*比例*极小，是因为它的串行部分没有随它一起增长。若在原来那个串行比例更大的小问题上，阿姆达尔上限会低得多。
:::
:::

### 串行比例的测量

真实程序很少自报串行比例，而且随 $p$ 增长的开销（通信、同步、不均衡）表现得像额外的串行工作。艾伦·卡普（Alan Karp）与霍勒斯·弗拉特（Horace Flatt）（1990）提出反解阿姆达尔定律：给定实测加速比，从 [[#eq-amdahl]] 解出 $f$。

::: definition 卡普-弗拉特度量 {#def-karp-flatt}
实测加速比 $S$ 在 $p > 1$ 个处理器上的**实验测定串行比例**为

$$
e = \frac{1/S - 1/p}{1 - 1/p}.
$$ {#eq-karp-flatt}

若 $p$ 增大而 $e$ 保持不变，加速比的限制来自串行代码；若 $e$ 随 $p$ 增长，则来自并行开销。
:::

对开头那个程序，实测加速比给出 $p = 2, 4, 8, 16$ 时 $e = 0.097, 0.106, 0.096, 0.101$——恒定，且等于实测的串行比例——而 $p = 32$ 时 $e = 0.119$，是开销出现的最初征兆。

## 工作量-跨度模型

阿姆达尔模型把程序分成完全串行与完全并行的两部分。真实的并行程序更微妙：并行归并排序在每一层都是并行的，但每一层都必须等待它下面一层。工作量-跨度模型精确刻画了这种结构。它是 Cilk 这类任务并行语言、OpenMP 任务与 Intel Threading Building Blocks 所采用的模型，也是科曼（Cormen）、莱瑟森（Leiserson）、里弗斯特（Rivest）与斯坦（Stein）的教材对并行算法进行分析所用的模型。

::: definition 计算 DAG、工作量与跨度 {#def-work-span}
并行计算用一个**计算 DAG**（有向无环图）$G$ 建模，其顶点是单位时间的**任务**（顺序指令的串），边 $u \to v$ 表示 $v$ 不能在 $u$ 完成之前开始。于是：

- **工作量** $T_1$ 是顶点数：在一个处理器上执行该计算的时间；
- **跨度** $T_\infty$（也称*深度*或*关键路径长度*）是最长路径上的顶点数：在无穷多个处理器上的时间；
- **并行度**是比值 $T_1 / T_\infty$。

$T_p$ 表示某个给定调度下 $p$ 个处理器上的时间；调度把每个任务指派给一个处理器和一个时间步，每个处理器每步至多一个任务，且遵守所有的边。
:::

长度不等的任务可以用单位任务的链来建模。DAG 是*算法*及其输入的性质，与任何机器无关；机器在调度处登场。派生（spawn）一个任务并等待它（一次 **fork** 与一次 **join**）构成 DAG 的边：被派生的任务有一条自派生点指向它的边，而会合点有来自两个分支的边。

::: theorem 工作量定律与跨度定律 {#thm-laws}
对每个计算 DAG 和 $p$ 个处理器上的每个调度，

$$
T_p \ge \frac{T_1}{p} \quad\text{（工作量定律）}, \qquad T_p \ge T_\infty \quad\text{（跨度定律）}.
$$

由此 $S(p) \le p$ 且 $S(p) \le T_1/T_\infty$：加速比至多是处理器数，也至多是并行度。
:::

::: proof
每一步至多执行 $p$ 个任务，而全部 $T_1$ 个任务都必须执行，所以至少需要 $T_1/p$ 步。最长路径上的任务必须先后相继地运行，因为每个都依赖前一个，所以至少需要 $T_\infty$ 步。把 $T_1$ 除以每个界，即得 $S(p) = T_1/T_p$ 的界。
:::

::: example 一个小 DAG 的工作量与跨度 {#ex-dag}
下面的 DAG 有九个单位任务：$A$ 先于 $B$、$C$、$D$；$B$ 与 $C$ 先于 $E$；$D$ 先于 $F$ 与 $G$；$E$、$F$、$G$ 先于 $H$；$H$ 先于 $I$。求 $T_1$、$T_\infty$ 与并行度，并求 $2$ 和 $3$ 个处理器上的最优调度。
::: solution
$T_1 = 9$。最长路径有 $5$ 个顶点——例如 $A, B, E, H, I$ 或 $A, D, F, H, I$——所以 $T_\infty = 5$，并行度为 $9/5 = 1.8$。由 [[#thm-laws]]，多少个处理器也给不出超过 $1.8$ 的加速比。

$3$ 个处理器上：第 $1$ 步：$A$；第 $2$ 步：$B, C, D$；第 $3$ 步：$E, F, G$；第 $4$ 步：$H$；第 $5$ 步：$I$。即 $T_3 = 5 = T_\infty$，最优。

$2$ 个处理器上，[[#thm-laws]] 的下界是 $\max(9/2, 5) = 5$，但 $5$ 步做不到。要在 $5$ 步内完成，$I$ 必须在第 $5$ 步运行、$H$ 在第 $4$ 步运行，于是 $E$、$F$、$G$ 都要在第 $3$ 步完成，从而 $B$、$C$（为 $E$ 所需）和 $D$（为 $F$、$G$ 所需）全都挤在第 $2$ 步——两个处理器的一步里挤三个任务。存在 $6$ 步的调度：$A$；$B, C$；$D, E$；$F, G$；$H$；$I$。所以 $T_2 = 6$：工作量定律与跨度定律是下界，未必总能达到。
:::
:::

:::

### 贪心调度与布伦特定理

求最优调度很难：对带先后约束的单位任务，当 $p$ 是输入的一部分时，判定 $p$ 个处理器能否在给定的步数内完成是 NP 完全的（杰弗里·乌尔曼（Jeffrey Ullman），1975；见 [[complexity]]）。引人注目的是，一种非常简单的策略从不比最优差出两倍。

::: definition 贪心调度 {#def-greedy}
若一个调度在每一步都尽可能多地执行就绪任务——就绪数不超过 $p$ 时全部执行，否则任取其中 $p$ 个——则称它是**贪心**的。执行了 $p$ 个任务的步称为**完整步**，否则称为**非完整步**。
:::

::: theorem 布伦特定理（贪心调度界） {#thm-brent}
工作量 $T_1$、跨度 $T_\infty$ 的计算 DAG 在 $p$ 个处理器上的任何贪心调度耗时

$$
T_p \le \frac{T_1}{p} + T_\infty
$$ {#eq-brent}

步。由此 $T_p$ 至多是最优 $p$ 处理器时间的两倍。
:::

::: proof
分别统计完整步与非完整步。

*完整步。* 每步执行 $p$ 个任务，而任务总共只有 $T_1$ 个，所以完整步至多 $T_1/p$ 个。

*非完整步。* 设 $G_k$ 为第 $k$ 步之前尚未执行的任务构成的子 DAG，$L_k$ 为 $G_k$ 中最长路径上的顶点数；初始 $L_1 = T_\infty$，且 $L$ 从不增大，因为 $G_{k+1} \subseteq G_k$。一个任务在第 $k$ 步就绪，当且仅当它在 $G_k$ 中没有前驱。在非完整步中，贪心调度执行*每一个*就绪任务。假设这样一步之后 $G_{k+1}$ 中仍有一条含 $L_k$ 个顶点的路径。它也是 $G_k$ 的路径，而且是最长的，所以它的第一个顶点 $v$ 在 $G_k$ 中没有前驱——否则路径可以向前延伸——于是 $v$ 在第 $k$ 步就绪。那么 $v$ 就在第 $k$ 步被执行了，与 $v \in G_{k+1}$ 矛盾。因此每个非完整步之后 $L_{k+1} \le L_k - 1$，而 $L$ 从 $T_\infty$ 出发、不可能低于 $0$，所以非完整步至多 $T_\infty$ 个。

相加即得 $T_p \le T_1/p + T_\infty$。至于因子二：任何调度，无论最优与否，由 [[#thm-laws]] 都满足 $T_p^* \ge \max(T_1/p, T_\infty)$，而 $T_1/p + T_\infty \le 2 \max(T_1/p, T_\infty) \le 2T_p^*$。
:::

里查德·布伦特（Richard Brent，1974）对**逐层**调度证明了密切相关的界：把任务按深度分层（第 $i$ 层含那些"从源出发的最长路径有 $i$ 个顶点"的 $w_i$ 个任务），每层用 $\lceil w_i / p \rceil$ 步执行。由于 $\sum_i w_i = T_1$ 且共有 $T_\infty$ 层，

$$
T_p \le \sum_{i=1}^{T_\infty} \left\lceil \frac{w_i}{p} \right\rceil \le \sum_{i=1}^{T_\infty} \left( \frac{w_i}{p} + 1 \right) = \frac{T_1}{p} + T_\infty.
$$

逐层形式是把布伦特定理用于 PRAM 算法（[[parallel-computing/parallel-algorithms]]）的常用方式：先用大量处理器和小深度设计算法，再用较少的处理器模拟它，代价是 $T_1/p$ 那一项。贪心形式——实质上源自罗纳德·格雷厄姆（Ronald Graham）对表调度的分析（1966、1969）——正是动态任务调度器所能达到的。

[[#thm-brent]] 有明确的实践含义。若并行度 $T_1/T_\infty$ 远大于 $p$——例如十倍——则 $T_\infty$ 项相比 $T_1/p$ 很小，于是 $T_p \approx T_1/p$：**线性加速比**。所以程序员的职责是把并行度暴露到远超处理器数的程度（这称为**并行富余**（parallel slackness）），调度器的职责则是廉价地做到贪心、或近乎贪心。Cilk、TBB、Java 的 fork/join 池与 Rust 的 Rayon 的工作窃取调度器在没有任何中央队列的情况下达到期望的 $T_1/p + O(T_\infty)$（[[parallel-computing/shared-memory]]）。

::: example 用模拟检验布伦特界 {#ex-greedy-sim}
随机生成 $2000$ 个至多含 $60$ 个单位任务的 DAG，在 $p = 1, 2, 3, 4, 8$ 个处理器上对每个都做贪心调度，同时检验 [[#thm-laws]] 与 [[#thm-brent]]。
::: solution
把任务编号为 $0, \dots, n - 1$，且只加满足 $u < v$ 的边 $u \to v$；于是编号本身就是拓扑序，图无环。

```python
import random

def greedy(succ, n, p):
    """Unit-time tasks 0..n-1 with edges u -> v in succ; greedy p-processor schedule."""
    indeg = [0] * n
    for u in range(n):
        for v in succ[u]:
            indeg[v] += 1
    ready = [u for u in range(n) if indeg[u] == 0]
    steps = 0
    while ready:
        run, ready = ready[:p], ready[p:]     # 运行任意 p 个就绪任务（不足则全运行）
        steps += 1
        for u in run:
            for v in succ[u]:
                indeg[v] -= 1
                if indeg[v] == 0:
                    ready.append(v)
    return steps

def span(succ, n):                            # 最长路径，按顶点数计
    depth = [1] * n                           # 顶点按拓扑序编号
    for u in range(n):
        for v in succ[u]:
            depth[v] = max(depth[v], depth[u] + 1)
    return max(depth)

rng = random.Random(1)
worst = 0
for trial in range(2000):
    n = rng.randint(1, 60)
    succ = [[v for v in range(u + 1, n) if rng.random() < 0.08] for u in range(n)]
    T1, Tinf = n, span(succ, n)
    for p in (1, 2, 3, 4, 8):
        Tp = greedy(succ, n, p)
        assert max(T1 / p, Tinf) <= Tp <= T1 / p + Tinf
        worst = max(worst, Tp / max(T1 / p, Tinf))
print("all bounds hold; worst ratio to the lower bound:", round(worst, 3))
```

```console
$ python3 greedy.py
all bounds hold; worst ratio to the lower bound: 1.6
```

在一步之中变为就绪的任务被追加到表尾，只能在下一步运行，正如模型所要求。没有一个断言失败，而且所有这些 DAG 上，贪心调度从不超过下界 $\max(T_1/p, T_\infty)$ 的 $1.6$ 倍，落在定理保证的因子 $2$ 之内。模拟只是证据，不是证明；证明是 [[#thm-brent]]。
:::
:::

::: example 并行递归斐波那契 {#ex-fib}
任务并行的教科书示例通过派生两次递归来计算斐波那契数：`fib(n) = spawn fib(n-1); fib(n-2); sync; add`。求工作量与跨度，以及 $n = 30$ 时的并行度。
::: solution
把每个调用自身的常数工作量记作 $\Theta(1)$，工作量满足 $T_1(n) = T_1(n - 1) + T_1(n - 2) + \Theta(1)$，恰是斐波那契数本身的递归式，所以 $T_1(n) = \Theta(\varphi^n)$，其中 $\varphi = (1 + \sqrt{5})/2$。两个调用并行运行，所以跨度是两者中较长者加一个常数：$T_\infty(n) = \max(T_\infty(n - 1), T_\infty(n - 2)) + \Theta(1) = T_\infty(n - 1) + \Theta(1) = \Theta(n)$。并行度为 $\Theta(\varphi^n / n)$，大得惊人：每次调用记单位代价时，$T_1(30) = 2\,\mathrm{fib}(31) - 1 = 2{,}692{,}537$ 次调用而 $T_\infty(30) = 30$ 层，并行度约 $90{,}000$。布伦特定理于是保证在任何现实机器上都能线性加速。但每个任务几乎无事可做，所以实践中派生的开销占了上风；真实程序在**截断阈值**之下就不再派生而顺序递归，[[parallel-computing/shared-memory]] 对此有实测。
:::
:::

### 开销与等效率

工作量-跨度模型只数有用的操作。真实的并行程序还要花时间通信、同步和等待，这些开销通常随 $p$ 增长。格拉马（Grama）、古普塔（Gupta）与库马尔（Kumar）（1993）把这一点精确化。

::: definition 开销与等效率 {#def-isoefficiency}
并行程序的**总开销**是 $T_o = p\,T_p - T_1$，即花在顺序算法的工作之外的处理器时间。其效率于是为

$$
E = \frac{T_1}{p\,T_p} = \frac{1}{1 + T_o/T_1}.
$$ {#eq-efficiency}

当且仅当 $T_1$ 与 $T_o$ 成比例增长时，效率在 $p$ 增大时保持不变。并行系统的**等效率函数**是保持 $E$ 不变时问题规模必须随 $p$ 增长的速度；它增长得越慢，系统就越可扩展。
:::

例如，用 $p$ 个处理器给 $n$ 个数求和：先在本地加 $n/p$ 个，再把部分和按 $\log p$ 轮在树上合并，每轮一次加法加一条消息（代价 $c$），耗时 $T_p \approx n/p + c\log p$，所以 $T_o \approx c\,p\log p$。要保持 $E$ 不变需要 $n = \Theta(p \log p)$：处理器翻倍，数据就要增加略多于两倍。若某算法的 $T_o = \Theta(p^2)$，数据就得按平方增长——它的扩展性差得多。

::: quiz
某程序工作量 $T_1 = 10^9$ 次操作、跨度 $T_\infty = 10^6$。哪些说法是有保证的？
- [x] 无论在多少个处理器上用任何调度，都完不成于少于 $10^6$ 步。
- [x] $100$ 个处理器上的贪心调度在 $1.1 \times 10^7$ 步内完成，因此加速比至少约为 $91$。
- [ ] $10^4$ 个处理器上的贪心调度达到 $10^4$ 的加速比。
- [ ] 只要调度器足够聪明，$2000$ 个处理器上的加速比就能达到 $2000$。
::: solution
跨度定律给出任何机器上 $T_p \ge 10^6$。布伦特定理给出 $T_{100} \le 10^9/100 + 10^6 = 1.1 \times 10^7$，加速比至少 $10^9/(1.1 \times 10^7) \approx 91$。$10^4$ 个处理器上它给出 $T_p \le 10^5 + 10^6$，加速比至少约 $909$；而跨度定律把任何加速比封顶在并行度 $T_1/T_\infty = 1000$，所以 $10^4$ 和 $2000$ 哪个调度器都达不到。
:::
:::

## 屋顶线模型

工作量-跨度模型把每个操作都记作一个单位时间。而在真实机器上，正如 [[parallel-computing/parallel-architectures]] 所示，许多程序的限制不在处理器算得多快，而在内存供数多快。塞缪尔·威廉姆斯（Samuel Williams）、安德鲁·沃特曼（Andrew Waterman）与戴维·帕特森（David Patterson）（2009）把两种限制画进了同一张图。

::: definition 算术强度与屋顶线 {#def-roofline}
一个计算的**算术强度** $I$ 是它每在处理器与内存之间搬运一字节所做的浮点运算数（除指明其他层次外，内存指 DRAM）。对峰值浮点速度为 $\pi$（flop/s）、峰值内存带宽为 $\beta$（字节/秒）的机器，可达性能的**屋顶线**界为

$$
P(I) = \min(\pi,\ I \beta).
$$ {#eq-roofline}

**屋脊点** $I^* = \pi/\beta$ 把**访存受限**的计算（$I < I^*$）与**计算受限**的计算（$I > I^*$）分开。
:::

::: proposition 屋顶线是上界 {#prop-roofline}
在一个处理器至多执行 $\pi$ flop/s、内存至多传输 $\beta$ 字节/秒的机器上，做 $W$ 次浮点运算、与内存之间搬运 $Q$ 字节的计算耗时 $T \ge \max(W/\pi,\ Q/\beta)$，因此至多达到 $W/T \le \min(\pi, I\beta)$，其中 $I = W/Q$。
:::

::: proof
仅算术就至少需要 $W/\pi$ 秒，仅数据搬运至少需要 $Q/\beta$ 秒，无论两者是否重叠都如此，所以 $T$ 至少是二者中的较大者。于是 $W/T \le W/(W/\pi) = \pi$，且 $W/T \le W/(Q/\beta) = (W/Q)\beta = I\beta$。
:::

在双对数坐标上，$P(I)$ 形如屋顶：一条斜线 $I\beta$（带宽顶）与一条水平线 $\pi$（计算顶）相交于屋脊。把一个核函数在其算术强度处的实测性能画在图上，一眼就能看出是哪个顶限制着它、离顶还差多少——从而是该优化访存流量还是算术。附加的顶（无向量化、无融合乘加、来自 L2 或 L3 高速缓存而非 DRAM）可使图形更精细；[[parallel-computing/performance-engineering]] 有实测。

::: example 36 核机器上的三个核函数 {#ex-roofline}
取 $\pi = 1325$ Gflop/s（[[parallel-computing/parallel-architectures#ex-peak]] 算出的双精度峰值）与 $\beta = 52$ GB/s（那章开头实验测得的带宽）。定出屋脊点，并为下列性能定界：(a) 点积 $\sum_i x_i y_i$；(b) "三元组"（triad）$a_i \gets b_i + s c_i$；(c) $n = 2000$ 的两个 $n \times n$ 矩阵相乘，假设每个矩阵恰被从内存读或写一次。
::: solution
屋脊在 $I^* = 1325/52 \approx 25$ flop/字节。

(a) 每一项花费两次运算（一次乘一次加）和 $16$ 字节（两个 `double`）：$I = 1/8$。于是 $P \le 52/8 = 6.5$ Gflop/s——不到峰值的 $0.5\%$。访存受限。

(b) 每个元素两次运算；读 $b_i$ 与 $c_i$、写 $a_i$，共 $24$ 字节，外加 $8$ 字节，因为写分配的高速缓存会先读入即将被覆写的 $a$ 所在的那条缓存行（[[computer-systems/memory-hierarchy]]）：$I = 2/32 = 1/16$，$P \le 3.25$ Gflop/s。访存受限。

(c) $W = 2n^3 = 1.6 \times 10^{10}$ 次运算；$Q = 3 \times 8n^2 = 9.6 \times 10^7$ 字节；$I = n/12 \approx 167$。由于 $I > I^*$，$P \le \pi = 1325$ Gflop/s。计算受限——但前提是算法真的实现了这种复用，而这需要对高速缓存做**分块**（blocking）；朴素的三重循环会把 $B$ 一遍又一遍地从内存读进来，其有效强度低得多（[[parallel-computing/performance-engineering]]）。
:::
:::

::: warning 加速比不是性能
加速比完美的程序仍然可以很慢，加速比差的程序却可以很快。得到线性加速比最容易的办法是从一个低效的顺序程序出发：若每个线程都在同样的开销上浪费时间，这份浪费并行起来漂漂亮亮。一定要与一个好的顺序基线比较（绝对加速比，[[#def-speedup]]），并在加速比之外报告绝对性能——时间，或对照屋顶线的 flop/s。反过来说，一个访存受限的核函数在 $8$ 个核心上停止扩展时，可能已经跑在带宽顶上了，那里任何并行巧思都无济于事；只有减少访存流量才管用。
:::

::: history
阿姆达尔（Amdahl）的论证发表于 "Validity of the single processor approach to achieving large scale computing capabilities"，1967 年 AFIPS Spring Joint Computer Conference 会刊上一篇四页纸的文章；通常归于他的公式是后人重构的，因为原文中没有公式。约翰·古斯塔夫森（John Gustafson）的 "Reevaluating Amdahl's law"（*Communications of the ACM*，1988）报告了桑迪亚国家实验室一台 $1024$ 处理器 nCUBE 超立方体上超过 $1000$ 的缩放加速比，荣获首届戈登·贝尔奖（Gordon Bell Prize）；缩放加速比公式记在埃德温·巴尔西斯（Edwin Barsis）名下。罗纳德·格雷厄姆（Ronald Graham）在 1966 与 1969 年分析了表调度这一贪心策略，里查德·布伦特（Richard Brent）在 "The parallel evaluation of general arithmetic expressions"（*Journal of the ACM*，1974）中证明了他关于用较少处理器模拟并行求值的界。工作量-跨度术语由 MIT 的 Cilk 项目（罗伯特·布卢莫夫（Robert Blumofe）、查尔斯·莱瑟森（Charles Leiserson）等，1995 年起）推广开来，其工作窃取调度器可证明地达到期望时间 $T_1/p + O(T_\infty)$（布卢莫夫与莱瑟森，1999）。艾伦·卡普（Alan Karp）与霍勒斯·弗拉特（Horace Flatt）于 1990 年发表了他们的度量，阿南特·格拉马（Ananth Grama）、安舒尔·古普塔（Anshul Gupta）与维平·库马尔（Vipin Kumar）于 1993 年提出等效率函数。塞缪尔·威廉姆斯（Samuel Williams）、安德鲁·沃特曼（Andrew Waterman）与戴维·帕特森（David Patterson）于 2009 年在 *Communications of the ACM* 上引入屋顶线模型。

## 后续内容

本章的定律在之后的每一章都要用到。[[parallel-computing/shared-memory]] 编写 OpenMP 与任务并行程序，测量它们离布伦特界有多近，并解释达到该界的工作窃取调度器。[[parallel-computing/parallel-algorithms]] 为求和、前缀和、排序与图设计跨度小、工作量最优的算法，使它们的并行度足够大。[[parallel-computing/message-passing]] 用 α–β 模型把通信代价加进模型，[[parallel-computing/performance-engineering]] 则测量真实的屋顶线并据以决定该优化什么。

::: summary
- **加速比** $T_1/T_p$ 与**效率** $S/p$（[[#def-speedup]]）；对照最优顺序程序报告绝对加速比，并区分**强扩展**（固定问题）与**弱扩展**（固定每处理器的工作量）。
- **阿姆达尔定律**：串行比例 $f$ 把加速比封顶在 $1/f$（[[#thm-amdahl]]）；它在 $16$ 个线程以内把我们的实测预测到 $3\%$ 以内（[[#ex-amdahl]]）。**古斯塔夫森定律**：问题随机器增长时，缩放加速比为 $p - s(p-1)$（[[#thm-gustafson]]）。两者只差在固定了什么。
- **卡普-弗拉特度量**从测量中恢复串行比例；若它随 $p$ 增长，限制扩展性的就是开销而非串行代码（[[#def-karp-flatt]]）。
- 在**工作量-跨度模型**（[[#def-work-span]]）中，任何调度都有 $T_p \ge \max(T_1/p, T_\infty)$（[[#thm-laws]]），而任何贪心调度都达到 $T_p \le T_1/p + T_\infty$（**布伦特定理**，[[#thm-brent]]），距最优不超过因子 $2$。当并行度 $T_1/T_\infty$ 远超 $p$ 时，线性加速比随之而来。
- 开销 $T_o = pT_p - T_1$ 决定效率；**等效率函数**说明要保持效率不变，问题必须以多快的速度增长（[[#def-isoefficiency]]）。
- **屋顶线** $\min(\pi, I\beta)$ 用峰值算术能力与内存带宽为性能定界（[[#prop-roofline]]）；算术强度低于屋脊 $\pi/\beta$ 的核函数是访存受限的——在我们的机器上，约 $25$ flop/字节以下。
:::


## 习题

::: exercise 阿姆达尔上限 {level=1 check="20"}
某程序顺序运行时间的 $5\%$ 花在无法并行的代码上。任意多个处理器上它能达到的最大加速比是多少？（填入加速比。）$36$ 个处理器上是多少？
::: solution
由 [[#thm-amdahl]]，上限为 $1/f = 1/0.05 = 20$。$36$ 个处理器上，$S = 1/(0.05 + 0.95/36) = 1/0.07639 \approx 13.1$，效率只有 $36\%$。
:::
:::

::: exercise 古斯塔夫森缩放加速比 {level=1 check="62.488"}
某程序在 $64$ 个处理器上运行，其运行时间的 $2.4\%$ 花在顺序代码上，其余时间让所有处理器保持忙碌。它的缩放加速比是多少？（填入数值。）
::: solution
由 [[#eq-gustafson]]，$S = s + p(1 - s) = 0.024 + 64 \times 0.976 = 0.024 + 62.464 = 62.488$，效率 $97.6\%$。同一个程序若跑在一个小到单处理器能在同样时间内完成的问题上，显示的加速比会低得多。
:::
:::

::: exercise 卡普-弗拉特度量 {level=1 check="1/28"}
某程序在 $8$ 个处理器上达到 $6.4$ 的加速比。计算其实验测定的串行比例 $e$。（以分数或小数填入 $e$。）若 $16$ 个处理器上的加速比是 $9.0$，串行比例还一样吗？
::: solution
由 [[#eq-karp-flatt]]，$e = (1/6.4 - 1/8)/(1 - 1/8) = (0.15625 - 0.125)/0.875 = 0.03125/0.875 = 1/28 \approx 0.0357$。$16$ 个处理器上，$e = (1/9 - 1/16)/(15/16) = 0.04861/0.9375 \approx 0.0519$。度量变大了，所以效率的损失无法用固定的串行部分解释：某种开销随 $p$ 增长（通信、同步、负载不均衡）。
:::
:::

::: exercise 工作量定律还是跨度定律？ {level=1 check="3"}
某计算 DAG 工作量 $T_1 = 12$、跨度 $T_\infty = 4$。要使跨度定律的下界至少达到工作量定律的下界，最小的处理器数 $p$ 是多少？（填入 $p$。）布伦特定理对 $T_3$ 给出什么上界？
::: solution
工作量定律给出 $T_p \ge 12/p$，跨度定律给出 $T_p \ge 4$；$4 \ge 12/p$ 恰在 $p \ge 3$ 时成立，故 $p = 3$。布伦特定理给出 $T_3 \le 12/3 + 4 = 8$，所以三个处理器上的贪心调度耗时介于 $4$ 与 $8$ 步之间。超过 $3$ 再加处理器也不会把下界拉到 $4$ 以下，因为并行度只有 $T_1/T_\infty = 3$。
:::
:::

::: exercise 程序能有多串行？ {level=2 check="1/175"}
你要在 $36$ 个处理器上得到 $30$ 的加速比。阿姆达尔定律允许的最大串行比例 $f$ 是多少？（填入 $f$。）
::: solution
解 $1/(f + (1 - f)/36) = 30$：$f + (1 - f)/36 = 1/30$。乘以 $36$：$36f + 1 - f = 1.2$，故 $35f = 0.2$，$f = 0.2/35 = 1/175 \approx 0.0057$。顺序运行时间中至多 $0.6\%$ 可以是串行的——这就是扩展到众多处理器时，程序的每个阶段、包括输入、输出与初始化都必须并行的原因。
:::
:::

::: exercise 树形求和的并行度 {level=2 check="(2^20 - 1)/20"}
$n = 2^{20}$ 个数的和由一棵平衡的加法二叉树计算：先 $n/2$ 次把输入两两相加，再 $n/4$ 次把所得结果两两相加，如此下去。每次加法记一个单位任务。并行度 $T_1/T_\infty$ 是多少？（填入。）利用布伦特定理，至多多少个处理器能保证效率至少为 $1/2$？
::: solution
共有 $n/2 + n/4 + \dots + 1 = n - 1$ 次加法，所以 $T_1 = 2^{20} - 1$；树有 $\log n = 20$ 层，层层依赖前一层，所以 $T_\infty = 20$。并行度为 $(2^{20} - 1)/20 \approx 52{,}429$。由 [[#thm-brent]]，$T_p \le T_1/p + T_\infty$，于是效率 $T_1/(pT_p) \ge T_1/(T_1 + pT_\infty)$，当 $pT_\infty \le T_1$、即 $p \le T_1/T_\infty \approx 52{,}429$ 时它至少为 $1/2$。效率 $1/2$ 一路有保证，直到并行度本身；要效率 $0.9$ 则需要 $p \le T_1/(9T_\infty)$，约 $5800$。
:::
:::

::: exercise 屋顶线上的稀疏矩阵-向量乘法 {level=2 check="25/6"}
一台机器峰值 $\pi = 200$ Gflop/s、内存带宽 $\beta = 25$ GB/s。压缩稀疏行格式的稀疏矩阵-向量乘法对每个非零元做一次乘法和一次加法，读入一个 $8$ 字节的值和一个 $4$ 字节的列下标；忽略其他所有流量。屋顶线界是多少 Gflop/s？（填入。）该核函数是计算受限还是访存受限？
::: solution
$I = 2/12 = 1/6$ flop/字节，远低于屋脊 $\pi/\beta = 8$。由 [[#eq-roofline]]，$P \le \min(200, 25/6) = 25/6 \approx 4.17$ Gflop/s：访存受限，约为峰值的 $2\%$。我们忽略的流量（输入向量、行指针、输出）只会进一步压低 $I$。要提速，应当减少每个非零元的字节数——$32$ 位值、压缩下标、一个下标合并多个非零元——而不是减少算术。
:::
:::

::: exercise 阿姆达尔与古斯塔夫森是同一定律 {level=3}
某程序在 $p$ 个处理器上运行时间 $T_p$，其中比例 $s$ 是串行的，其余完美并行。设 $f$ 是*同一*份工作在一个处理器上执行时的串行比例。证明 $f = s/(s + p(1 - s))$，并证明把这个 $f$ 代入阿姆达尔公式 [[#eq-amdahl]] 即得古斯塔夫森公式 [[#eq-gustafson]]。
::: solution
归一化 $T_p = 1$。顺序部分在两种机器上都花 $s$；并行部分代表 $p(1 - s)$ 个处理器时间单位，一个处理器需要 $p(1 - s)$ 去执行。所以 $T_1 = s + p(1 - s)$，$T_1$ 中顺序部分的比例是 $f = s/(s + p(1 - s))$。于是 $1 - f = p(1 - s)/(s + p(1 - s))$，且

$$
f + \frac{1 - f}{p} = \frac{s + (1 - s)}{s + p(1 - s)} = \frac{1}{s + p(1 - s)},
$$

所以阿姆达尔的 $S(p) = 1/(f + (1 - f)/p) = s + p(1 - s)$，正是古斯塔夫森公式。两条定律计算的是同一个比值 $T_1/T_p$；只有当 $f$ 与 $s$ 之一被错误地假设在 $p$ 变化时保持不变时，两者才显出分歧。弱扩展下 $s$ 大致不变而 $f$ 随 $p$ 下降；强扩展下 $f$ 不变而 $s$ 上升。
:::
:::

::: exercise 并行化发生器 {#ex-lcg-jump level=3}
开头程序的串行阶段计算 $s_{i+1} = (a s_i + c) \bmod 2^{64}$。证明 $s_{i+k} = (A_k s_i + C_k) \bmod 2^{64}$，其中 $A_k = a^k$、$C_k = c(a^{k-1} + \dots + a + 1)$，并且 $(A_k, C_k)$ 可以用 $O(\log k)$ 次乘法算出。利用这一点用 OpenMP 并行化发生器，使每个线程恰好以顺序循环本应产生的值填入自己那一段数组。加以实测。
::: solution
对 $k$ 归纳：$s_{i+1} = a s_i + c$ 给出 $k = 1$；若 $s_{i+k} = a^k s_i + c\sum_{j<k} a^j$，则 $s_{i+k+1} = a^{k+1} s_i + c\sum_{j<k} a^{j+1} + c = a^{k+1}s_i + c\sum_{j<k+1} a^j$。所有算术都在环 $\Z/2^{64}\Z$ 中进行，C 的无符号算术自动如此。映射 $\phi(s) = as + c$ 与自身复合是 $\phi^2(s) = a^2 s + c(a + 1)$，所以 $2^j$ 步的映射对 $(a, c)$ 可以平方出 $2^{j+1}$ 步的映射对；按 $k$ 的二进制位把映射对合并起来（如快速幂那样），就在 $O(\log k)$ 步内得到 $(A_k, C_k)$。（这些映射全都可交换，因为它们都是 $\phi$ 的幂，所以合并次序无关紧要。）

```c
/* 从 s 出发 k 步之后的状态：s_k = a^k s + c (a^(k-1) + ... + 1)，全部模 2^64。
   反复平方在 O(log k) 步内把映射 s -> a s + c 与自身复合。 */
static unsigned long jump(unsigned long s, unsigned long k) {
    unsigned long a = A, c = C, ra = 1, rc = 0;   /* (ra, rc)：至今复合出的映射 */
    while (k) {
        if (k & 1) { ra = ra * a; rc = rc * a + c; }   /* 追加映射 (a, c) */
        c = c * (a + 1); a = a * a;                    /* (a, c) 与自身复合 */
        k >>= 1;
    }
    return ra * s + rc;
}
...
    #pragma omp parallel
    {
        int t = omp_get_thread_num(), p = omp_get_num_threads();
        long lo = N * (long)t / p, hi = N * (long)(t + 1) / p;
        unsigned long s = jump(1, lo);           /* 元素 lo 之前的状态 */
        for (long i = lo; i < hi; i++) {
            s = s * A + C;
            x[i] = (double)(s >> 11) / 9007199254740992.0;
        }
    }
```

这里 `A` 与 `C` 是开头程序中的常数。在本章的机器上（观测值，2026 年）：

::: exercise 贪心可以几乎差最优两倍 {level=3}
证明 [[#thm-brent]] 中的因子 $2$ 几乎无法改进：对每个 $p \ge 2$ 和每个能被 $p$ 整除的 $L$，构造一个 DAG 和 $p$ 个处理器上的一个贪心调度，耗时 $(2 - 1/p)L$ 步，而最优调度只需 $L$ 步。
::: solution
取一条由 $L$ 个单位任务构成的链 $c_1 \to c_2 \to \dots \to c_L$，外加 $(p - 1)L$ 个独立的单位任务。则 $T_1 = pL$，$T_\infty = L$。

*最优调度：*在每一步 $i = 1, \dots, L$，运行 $c_i$ 和 $p - 1$ 个独立任务。耗时 $L$ 步，恰等于两个下界 $T_1/p$ 与 $T_\infty$。

*糟糕的贪心调度：*只要还剩至少 $p$ 个独立任务，就运行其中 $p$ 个而让 $c_1$ 等待——这是贪心的，因为这样的每一步都运行了 $p$ 个任务。$(p - 1)L$ 个独立任务耗时 $(p - 1)L/p$ 步（因 $p$ 整除 $L$ 而为整数）。之后只剩链，还需要 $L$ 步、每步一个任务（这些步是非完整的，但仍是贪心的：只有一个任务就绪）。合计 $(p - 1)L/p + L = (2 - 1/p)L$ 步，与最优之比为 $2 - 1/p$。布伦特界 $T_1/p + T_\infty = 2L$ 因而与最坏的贪心表现只相差 $L/p$。当 DAG 预先已知时——而它很少预先已知——实用的调度器会优先选择长路径上的任务（关键路径调度）来降低这种风险。
:::
