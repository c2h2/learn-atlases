坐在一台 Wi-Fi 接入点旁边，一次下载可能跑满几百兆比特每秒；走到建筑的另一头、隔过两堵混凝土墙，它就慢成了涓涓细流——尽管接入点以外的网络没有任何变化。走出门外，你的手机切换到移动网络；你正在进行的视频通话继续进行，也许会先停顿一下——尽管你的设备此时换了另一个 IP 地址，经由另一家运营商的设备接入。而在一条拥塞的无线链路上，一条 TCP 连接即使在链路还有富余容量时也可能步履蹒跚，因为 TCP 把每一个损坏的帧都误认为拥塞的迹象。

无线与移动网络和前几章的有线网络有两处彼此独立的差异。**无线**是链路的属性：信号随距离衰减、被墙壁反射、彼此干扰、而且并非每个台站都能听到彼此，于是误码率高且起伏不定，多路访问问题也比在电缆上更难。**移动**是用户的属性：设备从一个接入点移动到另一个接入点、甚至跨越网络，而网络必须继续把它的分组送到。本章研究这两点：无线链路及其容量的香农极限；Wi-Fi 的 CSMA/CA 协议与帧格式；蜂窝网络的体系结构；从移动 IP 到蜂窝切换的移动性处理；最后是无线链路对 TCP 做了什么、协议如何补救。多路访问借用 [[networks/link-layer]]，拥塞控制借用 [[networks/tcp-congestion]]。

## 无线链路

无线信号在传播中向外扩散，功率随距离下降——自由空间中与距离的平方成反比，在室内、穿越障碍物时下降得快得多。以分贝计的**自由空间路径损耗**为

$$
\text{FSPL} = 20 \log_{10} d + 20 \log_{10} f - 147.55\ \text{dB}
$$ {#eq-fspl}

其中距离 $d$ 以米计、频率 $f$ 以赫兹计：在 2.4 GHz 下，信号传播 10 m 后减弱约 $60$ dB（一百万倍），距离每增加十倍就再多损失 $20$ dB。频率越高损耗越大、穿墙能力越差，这正是近期 Wi-Fi 的 6 GHz 频段比 2.4 GHz 覆盖距离更短的原因。信号还会被表面反射、经由多条长度不同的路径到达，相互叠加时相长或相消——**多径衰落**——于是设备移动几厘米，接收功率就可能变化好几个数量级。同一频段内的其他发射机——别的网络、蓝牙设备、2.4 GHz 的微波炉——又添上**干扰**。

::: definition 信噪比 {#def-snr}
接收机处的**信噪比**（SNR）是接收信号功率与同频带内噪声（在 **SINR** 中还含干扰）功率之比，通常以分贝给出：$\text{SNR}_\text{dB} = 10 \log_{10}(P_\text{signal}/P_\text{noise})$。**调制**方案把比特映射成信号；在给定 SNR 下，往每个码元里塞更多比特的方案（如 256-QAM，每码元 8 比特）比稳健的方案（如 BPSK，每码元 1 比特）有更高的**误码率**（BER）。
:::

在给定的 SNR 下，一个信道究竟能多快地传送数据？香农（Shannon）在 1948 年作出了回答，他的定理划下了一条任何工程都无法突破的绝对界限。

::: theorem 香农-哈特利容量 {#thm-shannon}
带宽 $B$ 赫兹、带加性高斯白噪声、信噪比（功率比）为 $\text{SNR}$ 的信道，其容量为

$$
C = B \log_2 (1 + \text{SNR})\ \text{比特每秒}:
$$ {#eq-shannon}

低于 $C$ 的任一速率都存在能以任意小的错误概率传输的编码，而高于 $C$ 的任一速率下，错误概率离零有正的距离。
:::

我们不加证明地陈述这一结果；它属于信息论，其证明——为可达性随机编码的论证，加上由法诺（Fano）不等式导出的逆定理——可参见科弗（Cover）与托马斯（Thomas）合著的《信息论要素》（*Elements of Information Theory*）。这里要紧的有两个推论。容量随带宽线性增长，这正是每一代 Wi-Fi 都使用更宽信道的动力（20、40、80、160，到 Wi-Fi 7 是 320 MHz）。而在高 SNR 下它只随 SNR 对数增长，所以发射功率翻倍只增加 $B$ 比特每秒（[[#exr-shannon-regimes]]）。

::: example 一个 Wi-Fi 信道的容量 {#ex-shannon}
一个 20 MHz 的信道 SNR 为 25 dB。它的香农容量是多少？若设备走远、SNR 落到 5 dB 呢？
::: solution
25 dB 是功率比 $10^{2.5} \approx 316$。由 [[#eq-shannon]]，$C = 20 \times 10^6 \times \log_2 317 \approx 20 \times 10^6 \times 8.31 \approx 166$ Mb/s。在 5 dB（比值 $10^{0.5} \approx 3.16$）下，$C = 20 \times 10^6 \times \log_2 4.16 \approx 41$ Mb/s。真实系统借助现代编码能达到容量的一大截，所以 Wi-Fi 会自适应：**速率自适应**算法逐帧选择在当前 SNR 下可用的调制与编码方案，信号变弱时回退到更慢、更稳健的方案。这就是建筑另一头那个慢下载的全部原因。
:::
:::

::: widget plot
f: B*log2(1 + 10^(x/10))
x: -10, 40
y: 0, 1000
sliders: B=20:20:320:20
labels: C\ \text{(Mb/s)}
caption: $B$ MHz 信道的香农容量（Mb/s）随 SNR $x$（分贝）的变化（[[#thm-shannon]]）。注意在高 SNR 处曲线在以分贝为刻度时几乎是直线——每多 3 dB（功率翻倍）只增加 $B$ Mb/s——而加宽信道会把整条曲线成倍抬起。试试 30 dB 下取 $B = 320$（一个 Wi-Fi 7 信道），再在同一 SNR 下取 $B = 20$。在 0 dB 以下容量虽小却非零：即使噪声强于信号也能传送数据，只是速率很低，深空探测器和某些蜂窝模式正是这样工作的。
:::

无线电的另外两个性质让多路访问难上加难。一个台站自己在发送时听不见其他发送——在它自己的天线上，自己的信号比任何到达的信号强几百万倍——所以**碰撞检测是不可能的**。而且并非每个台站都能听到每个台站：在**隐藏终端**问题中，台站 A 和 C 都在接入点 B 的覆盖范围内，却都在彼此的覆盖范围之外（隔得太远，或有障碍物阻挡），于是谁也听不到谁在发送，可能同时发射，在 B 处发生碰撞。

## Wi-Fi

Wi-Fi 是 IEEE 802.11 系列无线局域网标准。台站（主机）与一个**接入点**（AP）关联，AP 连同它的各个台站构成一个**基本服务集**（BSS），以 **SSID** 命名；AP 通常经以太网交换机接入有线网络。台站也可以在没有 AP 的情况下组成**自组织**（ad hoc）网络。台站加入网络靠**扫描**——监听 AP 大约每秒广播十次的**信标**帧，或发送探测请求——然后与选定的 AP **关联**，在有安全防护的网络上再完成认证。

| 标准（市场名称） | 年份 | 频段 | 标称最高速率 |
|---|---|---|---|
| 802.11b | 1999 | 2.4 GHz | 11 Mb/s |
| 802.11a / 802.11g | 1999 / 2003 | 5 / 2.4 GHz | 54 Mb/s |
| 802.11n（Wi-Fi 4） | 2009 | 2.4, 5 GHz | 600 Mb/s |
| 802.11ac（Wi-Fi 5） | 2013 | 5 GHz | 约 6.9 Gb/s |
| 802.11ax（Wi-Fi 6, 6E） | 2021 | 2.4, 5, 6 GHz | 约 9.6 Gb/s |
| 802.11be（Wi-Fi 7） | 自 2024 年起认证 | 2.4, 5, 6 GHz | 约 46 Gb/s |

标称速率假设了最宽的信道、多条空间流（多副天线，**MIMO**）和理想条件；截至 2026 年，典型设备只能达到其中一小部分。它们全部使用同一套基本的媒体接入协议，只是随时间加入了调度接入（802.11ax 用 OFDMA 在不同子载波上同时调度多个台站）。

### CSMA/CA

因为碰撞无法被检测，802.11 转而尽力**避免**碰撞，并用显式确认来证实发送成功。

::: algorithm 802.11 CSMA/CA（分布协调功能） {#alg-csmaca}
常量：一个时槽时间、SIFS（短帧间间隔）和 DIFS（分布式帧间间隔，$= \text{SIFS} + 2$ 个时槽）；竞争窗口的上下界 $\text{CW}_\text{min}$ 与 $\text{CW}_\text{max}$。

**发送方**，有一个帧要发送：

1. 置 $\text{CW} \gets \text{CW}_\text{min}$。
2. 若信道已空闲了 DIFS，且这是空闲期后的一次新帧发送，立即发送。否则，从 $\set{0, 1, \dots, \text{CW}}$ 中均匀选取一个**退避计数器**。
3. 计数器为正期间：信道每持续空闲一个时槽（须已空闲 DIFS），计数器减一；信道忙时，计数器冻结。
4. 计数器到达 $0$ 时，发送整个帧（没有碰撞检测）。
5. 若在某个超时之内收到 ACK，帧发送成功。否则置 $\text{CW} \gets \min(2\,\text{CW} + 1, \text{CW}_\text{max})$ 并回到步骤 2，重试次数达上限后放弃。

**接收方**：收到 CRC 正确的帧后，等待 SIFS，发送一个 ACK。
:::

每一个设计选择都对应无线电的一个性质。需要 ACK，是因为发送方听不到碰撞；ACK 紧跟在短暂的 SIFS 之后，比 DIFS 短，所以别的台站无法在中间抢走信道。退避计数器是在发送*之前*、而不只是在碰撞之后选定的，因为多个等待同一段忙期的台站否则会在忙期结束的一刹那一齐发射。信道忙时冻结计数器，让等待最久的台站下次有更大的机会。而竞争窗口在每次失败后加倍，与以太网的退避相同（[[networks/link-layer#alg-csmacd]]）。

针对隐藏终端问题，802.11 提供了一个可选的预约。发送长帧之前，发送方先发一个短的**请求发送**（RTS）帧，内含整个交换过程的持续时间；AP 用一个**允许发送**（CTS）帧应答，凡是能听到 AP 的台站——包括隐藏的那些——都能听到它，并各自设定一个**网络分配向量**（NAV），在这段时间内把信道视为忙。这样碰撞就只可能发生在短小的 RTS 帧之间。因为 RTS/CTS 有开销，通常只对超过阈值的长帧启用它。

::: example 54 Mb/s 的链路有多快？ {#ex-wifi-throughput}
估算单个 802.11a 台站以 54 Mb/s 发送 1500 字节 IP 数据报的吞吐量，没有其他流量、没有碰撞，按标准的定时参数：时槽 9 µs，SIFS 16 µs，DIFS 34 µs，每帧前有 20 µs 前导，OFDM 码元长 4 µs，$\text{CW}_\text{min} = 15$，ACK 以 24 Mb/s 发送。
::: solution
```python
# wifi.py：802.11a（5 GHz OFDM）下无碰撞发送一个 1500 字节数据报所需的时间
import math

SLOT, SIFS = 9, 16                       # 微秒（IEEE 802.11a 定时）
DIFS = SIFS + 2 * SLOT                   # 34 us
PREAMBLE = 20                            # PLCP 前导与首部，us
CW_MIN = 15                              # 退避取自 0..15 个时槽

def airtime(nbytes, rate_mbps):
    bits = 16 + 8 * nbytes + 6           # SERVICE 域 + 数据 + 尾部比特
    per_symbol = rate_mbps * 4           # 一个 OFDM 码元长 4 us
    return PREAMBLE + 4 * math.ceil(bits / per_symbol)

def exchange(rate, ack_rate, payload=1500):
    data = airtime(payload + 8 + 28, rate)   # LLC/SNAP 8 + MAC 首部 24 + FCS 4
    ack = airtime(14, ack_rate)
    return DIFS + SLOT * CW_MIN / 2 + data + SIFS + ack, data, ack

for rate, ack_rate in ((54, 24), (6, 6)):
    total, data, ack = exchange(rate, ack_rate)
    print(f"{rate:2} Mb/s: data {data} us, ACK {ack} us, cycle {total} us, "
          f"throughput {1500 * 8 / total:.1f} Mb/s")
```

```console
$ python3 wifi.py
54 Mb/s: data 248 us, ACK 28 us, cycle 393.5 us, throughput 30.5 Mb/s
 6 Mb/s: data 2072 us, ACK 44 us, cycle 2233.5 us, throughput 5.4 Mb/s
```

每个数据报成为一个 1536 字节的帧（8 字节 LLC/SNAP 封装、24 字节 MAC 首部和 4 字节 CRC），在 54 Mb/s 下（每码元 216 比特）需要 57 个码元、228 µs，加上前导：共 248 µs。一个来回还要加上 DIFS（34 µs）、平均 $7.5$ 个时槽的退避（$67.5$ µs）、SIFS（16 µs）和 ACK（28 µs）：每个数据报 $393.5$ µs，于是吞吐量为 $12000/393.5 \approx 30.5$ Mb/s——标称速率的 56%，而且旁边没有任何别的台站。这些开销以固定时间计，所以速率越高占比越大，这正是新标准把许多数据报**聚合**成一个帧、用一个块确认（block ACK）统一确认的原因。在 6 Mb/s 下，同样的数据报需要 $2233.5$ µs，吞吐量为 $5.4$ Mb/s。
:::
:::

### 802.11 帧

一个 802.11 数据帧有一个 2 字节的帧控制字段（类型，以及包含 *to DS*、*from DS* 在内的标志位，指明帧是去往还是来自有线的“分配系统”）、2 字节的**持续时间**（用来设定其他台站的 NAV）、至多四个 48 位地址、一个序列控制字段（使接收方能在 ACK 丢失、帧被重传时丢弃重复帧），其后是载荷和 CRC-32。

::: definition 802.11 帧中的地址 {#def-80211-addresses}
在台站与接入点之间的帧里，**地址 1** 是无线上接收方的 MAC 地址（应当接收并确认这个帧的那个台站或 AP），**地址 2** 是无线发送方的，**地址 3** 是有线一侧设备的——对于去往分配系统的帧是最终目的站，对于来自分配系统的帧是原始源站。地址 4 仅当 AP 之间以无线方式中继帧（网格或网桥）时使用。
:::

::: example 一个帧穿过接入点 {#ex-80211-frame}
主机 H 关联在接入点 AP 上，向自己所在子网的默认网关、位于 AP 背后以太网上的路由器 R 发送一个 IP 数据报。H 发出的 802.11 帧里出现了哪些 MAC 地址？AP 发给 R 的以太网帧里呢？
::: solution
H 的帧置了 *to DS*：地址 1 = AP（无线接收方，它将发回 ACK），地址 2 = H（发送方），地址 3 = R（有线侧的目的站）。AP 确认收讫，把它转换成以太网帧（[[networks/link-layer#def-ethernet]]），目的站是 R、源站是 H——不是 AP 自己的地址：AP 是链路层网桥，所以 R 看到的帧就如同 H 直接发来的，并学到 H 的 MAC 地址，恰如交换机所做的那样。回程时，R 向 H 发送以太网帧；AP 的 802.11 帧置了 *from DS*，地址 1 = H，地址 2 = AP，地址 3 = R。
:::
:::

无线帧能被任何在范围内的设备收到，所以 Wi-Fi 安全至关重要。**WPA2**（基于 IEEE 802.11i，2004 年）和 **WPA3**（2018 年）认证台站——用共享口令短语，或在企业网络中经 802.1X 使用每用户凭据——并为每个会话派生新鲜的密钥，用 AES 对每个帧加密并做完整性保护。WPA3 的 **SAE** 握手使窃听者即使录下一次登录也无法离线猜测口令短语，这正是 WPA2 预共享密钥模式的一个弱点。相形之下，开放网络什么都不保护，攻击者还能架起一个同名 SSID 的假接入点（“邪恶双胞胎”）；防御之道是信赖端到端加密（TLS，并核验证书）而不是信赖网络本身，而在必须信任网络本身的场合，用带服务器证书的 WPA3-Enterprise。

::: quiz
为什么 802.11 用确认和碰撞避免，而不是以太网的碰撞检测？
- [x] 发送中的台站无法在自己的信号之上听到其他台站的信号。
- [x] 两个台站可能都在 AP 的范围内、却不在彼此的范围内。
- [ ] 无线电波比铜缆里的信号传播得慢，碰撞要过太久才能检测到。
- [ ] Wi-Fi 帧太短，做不了碰撞检测。
::: solution
前两项就是原因：台站自己的发送会淹没自己的接收机，而隐藏终端听不到彼此的载波，所以 AP 处的碰撞对两个发送方都可能不可见。无线电波的传播速度约 $3 \times 10^8$ m/s，比电缆里的信号还快；而 Wi-Fi 帧常常很长。既然碰撞检测不了，成功的唯一凭据就是显式的 ACK，碰撞只能靠每次发送前的随机退避、以及可选的 RTS/CTS 来变得更少见。
:::
:::

## 蜂窝网络

蜂窝网络在许可频谱上提供广域网无线接入。它的体系结构与 Wi-Fi 大不相同，因为运营商必须认证并计费用户、覆盖整个国家，并在高速公路速度下维持连接。

在 **4G LTE**（3GPP Release 8，2008 年）中，手机——**用户设备**（UE）——经无线接入服务于一个或多个小区的**基站**（eNodeB）。基站连接到运营商的**核心网**（演进分组核心网）：**移动性管理实体**（MME）负责认证并跟踪每个设备的位置；**归属用户服务器**（HSS）保存用户数据和密钥；**服务网关**和**分组数据网络网关**（S-GW、P-GW）用**隧道**把用户数据从基站承载到运营商网络的边缘，P-GW 在那里给设备分配 IP 地址并接入互联网。**5G**（Release 15，2018 年）换了名字保留这一结构——基站叫 gNB，核心网的功能（负责接入与移动性的 AMF、负责会话的 SMF、承载用户数据的 UPF）是软件服务——并加入更宽的信道、更高的频段和低得多的无线时延。截至 2026 年，5G 网络已广泛部署，4G 仍承载世界上很大一部分移动流量。

无线接入是**调度**式的，不是随机式的：基站按其需求和信道质量，至多每毫秒为各设备分配其 OFDMA 信道的时频块，两个方向都是。这避免了 CSMA 的碰撞与争用开销，但需要一个中央调度器——基站——蜂窝网络有它，而各自为政的 Wi-Fi 台站网络没有。设备用存储在 SIM 卡中的密钥认证，采用在设备与其归属网络之间运行、并能派生加密无线链路密钥的**挑战-应答**协议（**认证与密钥协商**，AKA）。

## 移动性

设备移动时，会发生两种不同的情况。若它在一个网络内部移动——同一子网上的几个 Wi-Fi 接入点之间，或一个运营商的几个小区之间——它能保住 IP 地址，网络只需改变送帧或送隧道到的位置。若它移动到一个不同的网络，它就从那个网络获得一个新的 IP 地址（[[networks/network-layer]]），而所有以旧地址为标识的连接——每条 TCP 连接，由它的四个值决定（[[networks/sockets#def-socket]]）——都会中断，除非有什么东西把这次变化藏起来。

::: definition 归属网络与拜访网络 {#def-mobility}
移动设备有一个永久的**归属网络**，它在其中拥有永久的**归属地址**，以及一个**归属代理**——那里一台负责跟踪它所在位置的路由器或网关。当它身处另一个**拜访**（外地）网络时，在那里取得一个**转交地址**，并向归属代理登记。**通信对应方**是与移动设备通信的任何主机。
:::

把分组送给不在家的移动设备有两条途径。**间接路由**中，通信对应方照旧发往归属地址；归属网络的路由把分组带到归属代理，代理把它们**隧道**转发——把每个数据报再封装进一个以转交地址为目的的封装里——送进拜访网络，在那里拆封交付。移动设备的应答可以直接回给通信对应方。这对通信对应方是透明的，设备在拜访网络之间迁移只需在归属代理处更新一次，但每个分组都要绕行归属网络，这就是**三角路由**问题。**直接路由**中，通信对应方从归属代理学到转交地址并直接隧道到那里，省下了绕行，代价是通信对应方必须感知移动性，迁移也更麻烦。

**移动 IP**（IPv4 见 RFC 5944；Mobile IPv6 见 RFC 6275）把间接路由连同可选的直接模式标准化了，但在公共互联网上部署寥寥。蜂窝网络以自己的方式使用同一体系结构：漫游手机的数据常常从拜访网络的网关隧道回归属网络的 P-GW（“归属路由”），于是手机保有着归属运营商的地址，从归属国的位置出现在互联网上，代价是三角绕行。在一个运营商的网络内部，**切换**把设备从一个基站移到另一个基站，而它在网关处的隧道端点保持不动：新旧基站直接协调（经由 X2 或 Xn 接口），旧基站把在途分组转发给新基站，核心网随后切换隧道的末端——通常在几十毫秒内完成，TCP 毫无察觉。

::: example 三角路由的代价 {#ex-triangle}
一位旅行者的手机归属网络在巴黎，他正在东京拜访，并与东京的一位朋友通话。在归属路由下，通话的分组要从朋友处先发到巴黎的归属网关、再回到东京。若东京与巴黎之间的单向时延是 110 ms、东京市内是 3 ms，那么归属路由和本地路由下的单向时延各是多少？
::: solution
归属路由：朋友的分组走东京 → 巴黎（110 ms）→ 东京（110 ms），约 220 ms，再加上两座城市内部各几毫秒：单向大约 $223$ ms，往返 $446$ ms。本地路由：大约 $3$ ms。单向超过约 150 ms 后通话就让人难受了，所以交互式流量对此很敏感；对网页浏览，它给每一次交换再加上两个跨洲往返的时延（[[networks/application-layer#prop-http-time]]）。这正是漫游协议越来越多地允许拜访网络为部分流量提供本地互联网出口的原因。
:::
:::

另一种思路不是让地址保持不变，而是允许地址改变、让*传输层*活下来。QUIC 用连接标识符而不是地址来标识连接，于是从 Wi-Fi 移到蜂窝网络的客户端只需做一次“确实拥有这个地址”的快速检查，就可以径直从新地址继续通信（**连接迁移**，RFC 9000 §9）；多路径 TCP（Multipath TCP，RFC 8684）甚至能让一条连接同时在多个地址上传输。把问题交还给端主机——这又一次是端到端论据在发挥作用。

## 无线链路与传输协议

TCP 的拥塞控制把丢失当作拥塞（[[networks/tcp-congestion#alg-reno]]）。在无线链路上，帧会因为噪声、衰落和碰撞而丢失，根本没有拥塞，而每一次这样的丢失都会使 TCP 的窗口减半。按平方根公式（[[networks/tcp-congestion#prop-mathis]]），在 RTT 为 50 ms 的路径上，1% 的残余丢失率就把一条使用 1460 字节报文段的 TCP 流限制在约 $\sqrt{1.5}\cdot 1460 \cdot 8/(0.05 \sqrt{0.01}) \approx 2.9$ Mb/s——无线电速率再高也没用。移动性又添上切换，其间分组成串地被延迟或丢失；而无线路段的 RTT 会随调度和重传的起落变化一个数量级，把 TCP 的重传超时不断拉长（[[networks/tcp-congestion#alg-rto]]）。

人们使用三类补救办法。

1. **本地恢复**：在无线链路本身重传丢失的帧——那里往返很短——让传输协议几乎看不到丢失。Wi-Fi 靠它的 ACK 和重试上限做到这一点，蜂窝网络靠快速混合自动重传请求（HARQ）和可靠的链路层协议做到。代价是额外且不定的时延。
2. **让发送方了解无线链路**：最初的连接分割方案把 TCP 终结在基站，在无线跳上另跑一条独立连接（违反端到端语义，而且在传输层加密时根本行不通——QUIC 总是加密的）；也提出过显式丢失通告，但用得很少。
3. **不把丢失等同于拥塞的拥塞控制**，例如 BBR（[[networks/tcp-congestion]]），它主要响应实测的带宽和 RTT。

本地恢复是重中之重，其效果容易量化。

::: proposition 链路层重传 {#prop-arq}
设一个帧在一条链路上的每次传输都独立地以概率 $q$ 丢失，链路层把丢失的帧最多重传 $k$ 次。则该帧彻底丢失的概率为 $q^{k+1}$，而每个帧的期望传输次数为 $(1 - q^{k+1})/(1 - q)$。
:::

::: proof
帧彻底丢失，当且仅当全部 $k + 1$ 次尝试都失败，由独立性其概率为 $q^{k+1}$。第 $j$ 次尝试（$j = 1, \dots, k + 1$）发生，当且仅当先前 $j - 1$ 次都失败，概率为 $q^{j-1}$。于是尝试次数的期望为 $\sum_{j=1}^{k+1} q^{j-1} = (1 - q^{k+1})/(1 - q)$，一个几何级数之和。
:::

::: example Wi-Fi 重传与 TCP {#ex-retries}
一条 Wi-Fi 链路独立地丢失 10% 的帧传输。比较没有重传、以及重试上限为 3 时 TCP 看到的丢失率，以及它们对一条 RTT 50 ms、报文段 1460 字节的 TCP 流的影响。
::: solution
没有重传时 TCP 看到 $p = 0.1$，由 [[networks/tcp-congestion#eq-mathis]] 得到约 $\sqrt{15} \times 1460 \times 8/0.05 \approx 0.90$ Mb/s。有至多 $3$ 次重试时，由 [[#prop-arq]] 残余丢失为 $0.1^4 = 10^{-4}$，公式给出约 $\sqrt{15000} \times 233.6\ \text{kb/s} \approx 28.6$ Mb/s——多了三十倍，这条流如今受制于无线电速率，而非 TCP 对丢失的反应。代价是每帧 $(1 - 0.1^4)/0.9 \approx 1.11$ 次传输，以及偶尔每重传一次多出几百微秒的延迟。独立很重要：若丢失成串而来（有人从天线前走过），连续的重传会一起失败，残余丢失远高于 $q^{k+1}$。
:::
:::

::: warning 无线链路不是“慢一点的以太网”
人们很容易把 Wi-Fi 或蜂窝链路建模成一条速率低一些的有线链路。但它们的差异是性质上的：速率随无线条件和竞争台站数目瞬息万变；丢失有相当一部分是随机的，而非拥塞所致；时延随调度和重传而波动；共享链路的台站还会以出人意料的方式互相拖慢——一个远离接入点、以低速率发送的台站，每个帧占用信道那么久，以至于其他每个台站的吞吐量都跌到和它差不多的水平（[[#exr-anomaly]]）。为固定、可靠、有线链路设计的协议和应用在这种链路上表现糟糕；那些边测量边适应的（速率自适应、BBR、自适应视频码率）才如鱼得水。
:::

::: history
马可尼（Guglielmo Marconi）的无线电报问世于二十世纪初，但无线*分组*网络始于阿布拉姆森（Norman Abramson）在夏威夷大学（1971 年）主持的 ALOHAnet，它的随机接入协议塑造了以太网（[[networks/link-layer]]）。香农（Claude Shannon）的《通信的数学理论》（*“A mathematical theory of communication”*，1948 年）定下了其后一切无线电系统工作的界限。第一个 IEEE 802.11 标准于 1997 年问世，速率 2 Mb/s；Wi-Fi 联盟于 1999 年成立，负责互操作性认证。珀金斯（Charles Perkins）主持设计了移动 IP，1996 年发表为 RFC 2002。巴拉克里希南（Hari Balakrishnan）、帕德马纳班（Venkata Padmanabhan）、塞尚（Srinivasan Seshan）与卡茨（Randy Katz）比较了改进无线链路上 TCP 的途径（SIGCOMM 1996），论证了感知 TCP 的链路层恢复的价值。休斯（Martin Heusse）等人 2003 年描述了 802.11 的“性能异常”。蜂窝数据从 GSM 上的 GPRS（约 2000 年）走到 LTE（3GPP Release 8，2008 年）和 5G（Release 15，2018 年）。
:::

## 后续内容

本章到此完成了对协议层次的巡礼。无线与移动网络的安全——WPA3、蜂窝认证、跟踪与位置隐私——在 [[security]] 中展开，其背后的密码学在 [[cryptography]]。必须随设备移动、断线与重连而持续运转的服务——复制数据、同步、一致性——是 [[distributed-systems]] 的主题。天线、调制与编码的物理属于 [Electrical Engineering Atlas](/learn/ee/)，香农理论则是信息论课程的内容。

::: summary
- 无线信号遭受**路径损耗**（[[#eq-fspl]]）、多径**衰落**和**干扰**；**SNR**（[[#def-snr]]）决定每种调制的误码率，**速率自适应**逐帧选择方案。
- **香农容量** $B \log_2(1 + \text{SNR})$（[[#thm-shannon]]）随带宽线性增长、随 SNR 对数增长。
- 无线台站检测不了碰撞、彼此还可能**隐藏**，所以 **802.11** 使用 **CSMA/CA**：发送前随机退避、链路层 ACK、指数退避和可选的 RTS/CTS（[[#alg-csmaca]]）。固定的开销使吞吐量远低于标称速率（[[#ex-wifi-throughput]]）。
- 802.11 帧最多携带四个地址（[[#def-80211-addresses]]）；接入点在 Wi-Fi 与以太网之间网桥。WPA2/WPA3 提供加密与认证。
- **蜂窝**网络集中调度无线资源，用户数据经核心网隧道送到网关；切换让设备在基站之间移动而不改变地址。
- 跨网络的**移动性**用归属代理和转交地址（[[#def-mobility]]）；**间接路由**透明，但带来三角路由（[[#ex-triangle]]）。QUIC 的连接迁移端到端地应对地址变化。
- TCP 把无线丢失误读为拥塞；**链路层重传**把残余丢失降到 $q^{k+1}$（[[#prop-arq]]），以不定时延为代价恢复 TCP 吞吐量。
:::

## 习题

::: exercise 分贝 {level=1 check="1000"}
接收信号比噪声高 30 dB。信号功率与噪声功率之比是多少？若随后把信号功率减半，SNR 以分贝计是多少？（输入 30 dB 对应的功率比。）
::: solution
$10^{30/10} = 10^3 = 1000$。功率减半要减去 $10 \log_{10} 2 \approx 3.01$ dB，约得 $27$ dB。分贝把乘法变成加法，这正是链路预算——发射功率、天线增益、路径损耗、噪声——都用 dB 累加的原因。
:::
:::

::: exercise 香农容量 {level=1 check="166"}
一个 20 MHz 信道在 SNR 为 25 dB 时的香农容量是多少（取整到 Mb/s）？（容量以 Mb/s 输入。）
::: solution
同 [[#ex-shannon]]：$20 \times \log_2(1 + 10^{2.5}) = 20 \times \log_2(317.2) \approx 20 \times 8.309 \approx 166$ Mb/s。
:::
:::

::: exercise 路径损耗 {level=1 check="60"}
用 [[#eq-fspl]]，2.4 GHz 信号传播 10 m 的自由空间路径损耗是多少（取整到分贝）？100 m 时多多少？5 GHz、10 m 时呢？（输入 2.4 GHz、10 m 时的损耗。）
::: solution
$20 \log_{10} 10 + 20 \log_{10}(2.4 \times 10^9) - 147.55 = 20 + 187.60 - 147.55 \approx 60$ dB。100 m 时多 $20$ dB（$80$ dB）。5 GHz、10 m 时多 $20 \log_{10}(5/2.4) \approx 6.4$ dB，约 $66$ dB——这还没算墙体，它对更高频率衰减得更多。
:::
:::

::: exercise 残余丢失 {level=2 check="0.0016"}
一条链路独立地丢失 20% 的帧传输，每个帧至多重传 3 次。彻底丢失的帧占多大比例？每帧的期望传输次数是多少？（输入丢失比例。）
::: solution
由 [[#prop-arq]]，$q = 0.2$、$k = 3$：彻底丢失的概率为 $0.2^4 = 0.0016$；期望传输次数 $(1 - 0.0016)/0.8 = 1.248$。
:::
:::

::: exercise 隐藏终端 {level=2}
台站 A 和 C 都关联在接入点 B 上；A 和 C 彼此听不见。A 正向 B 发送一个长帧；发送尚未结束，C 的退避计数器归零。(a) 没有 RTS/CTS 时会发生什么？(b) 描述带 RTS/CTS 的交换过程，解释 C 为什么保持沉默。(c) 为什么不给每个帧都用 RTS/CTS？
::: solution
(a) C 听到的是空闲信道（它听不到 A），于是发送；两个帧在 B 处碰撞，B 哪个都没能正确收到，不发 ACK。两个发送方都超时，把竞争窗口加倍后重试——而且可能再次碰撞。(b) A 向 B 发送 RTS，内含整个交换过程的持续时间；B 用携带剩余时间的 CTS 应答，C 能听到它；C 据此设定 NAV，推迟到整个交换——数据和 ACK——结束。此后只有短小的 RTS 帧才可能碰撞。(c) 每次交换都要多出两个帧（RTS 和 CTS），各带自己的前导和 SIFS：在存在隐藏台站的网络里、发送长帧之前值得花这个开销，但对短帧纯属浪费——重传短帧花不了比一个 RTS 多多少。因此设置一个可配置的长度阈值。
:::
:::

::: exercise 三角路由 {level=2 check="223"}
在 [[#ex-triangle]] 中，从朋友到旅行者、经归属路由的分组的单向时延是多少？直接路由每次往返能省下多少？（单向时延以毫秒输入。）
::: solution
两座城市之间约 $220$ ms（东京到巴黎再回来），加上东京市内约 $3$ ms 的本地投递：$\approx 223$ ms。直接、本地路由单向约 $3$ ms，于是每次往返省下约 $2 \times (223 - 3) = 440$ ms。
:::
:::

::: exercise 性能异常 {#exr-anomaly level=3 check="4.57"}
两个台站共享一个 802.11a 接入点；两者总有 1500 字节的数据报要发。台站 F 以 54 Mb/s 发送，远处台站 S 以 6 Mb/s 发送（ACK 也按 6 Mb/s）。假设 CSMA/CA 在长期中给每个台站同样多次的发送机会，忽略碰撞。用 `wifi.py` 的周期时间求每台站的吞吐量，并与 F 单独在场时的吞吐量比较。（每台站的吞吐量以 Mb/s 输入，保留两位小数。）
::: solution
`wifi.py` 给出 54 Mb/s 下每个数据报的周期为 $393.5$ µs，6 Mb/s 下为 $2233.5$ µs。机会均等时，两台站交替发送：在 $393.5 + 2233.5 = 2627$ µs 里各发出一个 $12000$ 比特的数据报。所以各得 $12000/2627\ \text{µs} \approx 4.57$ Mb/s，合计 $9.14$ Mb/s。F 单独在场本可得到 $30.5$ Mb/s，如今被拖到不足 S 单独在场所能的 $5.4$ Mb/s。CSMA/CA 在*帧*的意义上公平、在*时间*上不公平，所以慢台站占去了大部分信道时间。补救办法包括接入点里的信道时间公平（按均等时间而非均等帧调度）、把客户端导向更好的接入点，以及禁用最低的几档速率。
:::
:::

::: exercise 容量的两种机制 {#exr-shannon-regimes level=3}
由 [[#eq-shannon]] 证明：(a) 在高 SNR 下，信号功率翻倍使容量增加约 $B$ 比特每秒；(b) 在低 SNR 下，容量约为 $B \cdot \text{SNR}/\ln 2$，与功率成正比；(c) 对固定的总功率 $P$ 和噪声功率谱密度 $N_0$（于是 $\text{SNR} = P/(N_0 B)$），容量随带宽增大，但当 $B \to \infty$ 时趋于有限极限 $P/(N_0 \ln 2)$。
::: solution
(a) 对大的 SNR，$\log_2(1 + 2\,\text{SNR}) - \log_2(1 + \text{SNR}) = \log_2\frac{1 + 2\,\text{SNR}}{1 + \text{SNR}} \to \log_2 2 = 1$，所以容量增加约 $B \times 1$ 比特每秒。(b) 对小的 $x$，$\ln(1 + x) = x - x^2/2 + \dots \approx x$，于是 $C = B \ln(1 + \text{SNR})/\ln 2 \approx B\,\text{SNR}/\ln 2$。(c) $C(B) = B \log_2(1 + P/(N_0 B))$。令 $u = P/(N_0 B)$，则 $C = \frac{P}{N_0} \cdot \frac{\log_2(1 + u)}{u}$，而 $\log_2(1 + u)/u$ 在 $u > 0$ 上递减（因为 $\ln(1 + u)/u$ 递减：其导数为 $(u/(1+u) - \ln(1 + u))/u^2 < 0$），所以当 $B$ 增大（$u$ 减小）时 $C$ 增大。当 $B \to \infty$ 时，$u \to 0$ 且 $\log_2(1 + u)/u \to 1/\ln 2$，故 $C \to P/(N_0 \ln 2)$。加宽带宽有用，但在信号被摊薄到低于噪声之后，收益越来越小；而在 (a) 的高 SNR 机制下，划算的是带宽。
