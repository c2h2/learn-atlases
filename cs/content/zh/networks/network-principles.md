假设你把一张 1 兆字节的照片从伦敦上传到悉尼的一台服务器。光在海底光纤中要走过大约 17,000 km，而玻璃中的光速约为 $2 \times 10^8$ m/s，只有真空中光速的三分之二。无论你的连接有多快，第一个比特的到达都不可能早于

$$
\frac{1.7 \times 10^7\ \text{m}}{2 \times 10^8\ \text{m/s}} = 85\ \text{ms}.
$$

把照片的 $8 \times 10^6$ 比特推上 1 Gb/s 的链路还要花 $8$ ms。把链路升级到 100 Gb/s，第二个数字缩小为 $0.08$ ms，第一个却毫不改变。两个不同的量——比特以多*快*的速度被送上导线，以及每个比特穿过导线要花多*久*——支配着一切网络，而混淆它们正是推理网络性能时最常见的错误。

本章建立本课程其余部分所用的词汇与模型。我们从互联网的中央设计决策——**分组交换**——出发，看看它为什么胜过为每一次对话预留一条电路。然后我们从时间上拆解一个分组——时延的四个组成部分、排队与丢失、吞吐量与带宽时延乘积——并给出能让你在信封背面就估算出网络性能的公式。最后我们考察互联网的协议如何组织成**层次**，这种组织为什么历经五十年而不衰，以及网络的整体面貌：主机、接入网络、互联网服务提供商，以及把它们联结在一起的标准。

## 电路交换与分组交换

网络连接**主机**（**端系统**）：笔记本电脑、手机、服务器、传感器。主机由**链路**——铜缆、光纤、无线电——以及把数据从一条链路传到另一条链路的**交换机**和**路由器**连接起来。问题在于：链路容量如何在所有想要通信的主机之间共享。

::: definition 电路交换与分组交换 {#def-switching}
在**电路交换**中，两台主机通信之前，网络为它们之间一条路径上每条链路的容量预留一个固定份额——一条**电路**——持续整个对话期间，无论是否在发送数据。这个份额通常是重复帧中的一个时隙（**时分复用**，TDM）或一个频段（**频分复用**，FDM）。

在**分组交换**中，数据被划分成**分组**，每个分组携带一个含有目的地址的**首部**。来自许多对话的分组按需共享链路：交换机收到一个分组，查看它的首部，一旦某条输出链路空闲就把它发送出去，其间把它存放在**队列**（缓冲区）中。不预留任何容量。
:::

电话网络建立在电路之上：一次通话端到端地预留一条 64 kb/s 的信道，这适合产生稳定语音抽样流的对话。计算机流量则不同。一个浏览网页的人几秒钟什么都不发送，接着请求一个页面，页面以几百千字节的一阵突发到达，然后又归于沉默。按突发定容量的电路几乎全程空闲；按平均流量定容量的电路又让突发慢得令人难以忍受。分组交换能让一个用户的空闲容量去服务另一个用户的突发。

### 存储转发

大多数分组交换机是**存储转发**式的：交换机必须收到*整个*分组之后才能开始转发它，因为它需要检查分组是否有错并读取它的首部。一个 $L$ 比特的分组在速率为 $R$ 比特/秒的链路上传输需要 $L/R$ 秒，所以一个跨越多条链路的分组要在每条链路上付出这个代价。

::: proposition 存储转发时延 {#prop-saf}
一个源把 $P$ 个各长 $L$ 比特的分组背靠背地发送出去，经过 $N$ 条速率都为 $R$ 的链路和 $N-1$ 台存储转发交换机。忽略传播、处理和其他流量。则最后一个分组在时刻

$$
d = (N + P - 1)\,\frac{L}{R}.
$$ {#eq-saf}

到达目的主机。
:::

::: proof
记 $\tau = L/R$ 为一个分组在一条链路上传输的时间。我们断言：分组 $k$（$k = 1, \dots, P$）在时刻 $(k + j - 1)\tau$ 完成穿越链路 $j$（$j = 1, \dots, N$），并对 $k + j$ 归纳证明。分组 $1$ 在 $[0, \tau]$ 期间穿越链路 $1$。一般地，分组 $k$ 能在链路 $j$ 上开始发送只有当两个条件都满足：它已经通过链路 $j - 1$ 完全到达（按归纳假设为时刻 $(k + j - 2)\tau$；当 $j = 1$ 时为 $(k-1)\tau$，因为源是背靠背发送的），并且链路 $j$ 已经发送完分组 $k - 1$（按归纳假设为时刻 $(k - 1 + j - 1)\tau = (k + j - 2)\tau$；当 $k = 1$ 时链路从未繁忙）。两个条件都在时刻 $(k + j - 2)\tau$ 成立，所以分组 $k$ 于该时刻在链路 $j$ 上开始发送，并在 $\tau$ 之后、即 $(k + j - 1)\tau$ 完成。最后一个分组 $k = P$ 在时刻 $(P + N - 1)\tau$ 完成最后一条链路 $j = N$ 的传输。
:::

这个公式有一个简单的解读：第一个分组需要 $N\tau$ 才能通过整条路径，此后每隔 $\tau$ 就有一个分组出来——这条路径是一条**流水线**。

::: example 为什么消息要切分成分组 {#ex-segmentation}
一台主机把一条 $M = 8 \times 10^6$ 比特（1 MB）的消息，经过两台存储转发路由器发往另一台主机，路径共 $N = 3$ 条速率为 $R = 10$ Mb/s 的链路。忽略首部和传播，问：(a) 若消息作为一个巨大的分组整体发送，传输要花多长时间？(b) 若把它切成 $10^4$ 比特的分组呢？
::: solution
(a) $P = 1$、$L = M$，由 [[#eq-saf]] 得 $d = 3 \cdot M/R = 3 \times 0.8\ \text{s} = 2.4$ s。每台路由器都要等整个兆字节到齐才开始转发，所以三条链路是先后串行使用的。

(b) 现在 $P = 800$ 且 $L/R = 10^4 / 10^7 = 1$ ms，于是 $d = (3 + 800 - 1) \times 1\ \text{ms} = 0.802$ s。当路由器 1 转发分组 $k$ 时，源已经在发送分组 $k+1$：三条链路并行工作。把消息切成分组让传输快了 3 倍。若考虑真正的首部，分组并非越小越好——每个分组都要携带一个固定长度的首部，而 [[#exr-optimal-packet]] 会求出最佳分组长度。
:::
:::

::: widget plot

sliders: N=3:2:10:1; h=320:0:2000:40; M=8000000:1000000:16000000:1000000; R=10000000:1000000:100000000:1000000
labels: \text{传输时间（s）}
caption: 一条 $M$ 比特的消息切成若干分组、每个分组携带 $x$ 比特数据加 $h$ 比特首部，经过 $N$ 条速率为 $R$ 的链路时的存储转发总时间（即带首部的 [[#ex-segmentation]] 模型）。先把 $h = 0$ 试试：曲线随 $x$ 变小而一直下降，看起来分组越小越好。再把 $h$ 调大：非常小的分组把时间浪费在首部上，非常大的分组又失去流水线的好处，于是出现一个最小值——位置在 $x = \sqrt{hM/(N-1)}$ 附近，[[#exr-optimal-packet]] 将证明这一点。增大 $N$，看最佳分组长度如何变小。
:::

### 统计复用

支持分组的第二个理由关乎一条链路能支持多少用户。分组交换**统计地**共享容量：它赌的是并非所有用户同时活动。

::: example 电路与分组 {#ex-statmux}
一条 10 Mb/s 的链路由若干用户共享，每个用户活动时的发送速率为 1 Mb/s，且各自独立地有 10% 的时间处于活动状态。(a) 电路交换能支持多少用户？(b) 若用分组交换且有 30 个用户，同一时刻活动用户超过 10 个（从而它们的总需求超过链路容量）的概率是多少？
::: solution
(a) 每条电路预留 1 Mb/s，所以链路支持 $10$ 个用户——不论他们是否活动。

(b) 活动用户数 $X$ 服从 $n = 30$、$p = 0.1$ 的二项分布。当 $X \ge 11$ 时需求超过容量：

$$
\Prob(X \ge 11) = \sum_{k=11}^{30} \binom{30}{k} (0.1)^k (0.9)^{30-k} \approx 8.9 \times 10^{-5}.
$$

（在 Python 中用 `math.comb` 算得。）于是分组交换支持三倍于电路交换的用户数，而他们遇到链路超载的时刻不足万分之一；在这些时刻，分组只是短暂排队，而不像电路那样被拒绝。40 个用户时该概率升到大致 $1.5 \times 10^{-3}$，50 个用户时升到约 $0.0094$。
:::
:::

::: widget distribution
dist: binomial
params: n=30, p=0.1
a: 11
b: 30
caption: [[#ex-statmux]] 中同时活动的用户数。阴影尾部 $X \ge 11$ 是需求超过 10 Mb/s 链路容量的概率。增大 $n$（更多用户），看尾部如何先缓慢后迅速地增长：统计复用之所以可行，是因为二项分布集中在均值 $np$ 附近，标准差只有 $\sqrt{np(1-p)}$。试试 $p = 0.5$——突发性流量才是共享的红利所在；恒定的流量几乎占不到便宜。
:::

分组交换的代价是不可预测。一阵突发到来时，分组在队列中等待，时延随之波动；突发太长时，队列溢出，分组丢失。电路提供有保证的恒定时的延，却浪费容量。互联网选择了分组，并把自己的大量协议机制——重传、拥塞控制、应用层缓冲——用在应付这些后果上。

## 时延、丢失与吞吐量

跟踪一个离开路由器的分组。它在这个**节点**的总时延有四部分。

::: definition 节点时延的组成 {#def-delay}
一个 $L$ 比特的分组经过某节点、进入一条速率 $R$ 比特/秒、长 $d$ 米、信号以速度 $s$ 传播的链路：

- **处理时延** $d_\text{proc}$：检查首部、核查比特差错、决定输出链路所需的时间（路由器中通常为微秒级或更短）；
- **排队时延** $d_\text{queue}$：等待输出链路空闲所花的时间（从 0 到几毫秒不等，取决于流量）；
- **发送时延** $d_\text{trans} = L/R$：把这 $L$ 比特全部推上链路所需的时间；
- **传播时延** $d_\text{prop} = d/s$：一个比特走完链路全长所需的时间；光纤和铜线中 $s \approx 2 \times 10^8$ m/s，空气中约 $3 \times 10^8$ m/s。

**节点时延**为 $d_\text{nodal} = d_\text{proc} + d_\text{queue} + d_\text{trans} + d_\text{prop}$，端到端时延则是路径上各节点时延之和。
:::

发送时延与传播时延常被混淆，两者却毫不相干。发送时延取决于分组长度和链路速率，与距离无关；传播时延取决于距离和媒体，与分组和速率无关。一个有用的意象：汽车（比特）每隔几秒驶离一个收费站（发送），然后以恒定速度驶上高速公路（传播）。一个 1500 字节的分组在 10 Gb/s 链路上只占用 $1.2$ µs 的发送时间，其间它的第一个比特已在光纤中走过 $240$ m；在 1 Mb/s 链路上，发送要花 $12$ ms，分组被摊开在 $2400$ km 长的光纤上。

::: example 两条链路上的时延 {#ex-two-links}
主机 A 经过一台路由器向主机 B 发送一个 1500 字节的分组。A 到路由器的链路长 1000 km、速率 100 Mb/s；路由器到 B 的链路长 10 km、速率 10 Mb/s。信号传播速度为 $2 \times 10^8$ m/s，处理时间可忽略，且没有其他流量。端到端时延是多少？
::: solution
分组长度 $L = 1500 \times 8 = 12000$ 比特。

| 链路 | $d_\text{trans} = L/R$ | $d_\text{prop} = d/s$ |
|---|---|---|
| A → 路由器 | $12000 / 10^8 = 120$ µs | $10^6 / (2 \times 10^8) = 5$ ms |
| 路由器 → B | $12000 / 10^7 = 1.2$ ms | $10^4 / (2 \times 10^8) = 50$ µs |

路由器必须先收全整个分组才能转发，所以时延直接相加：$0.12 + 5 + 1.2 + 0.05 = 6.37$ ms。长链路上以传播为主，慢链路上以发送为主。把长链路的速率翻倍只能省下 $60$ µs。
:::
:::

### 排队与丢失

排队时延是最值得关注的分量，因为它取决于网络中发生的一切其他事情。设 $L$ 比特的分组以平均每秒 $a$ 个的速率到达一个队列，将在一条 $R$ 比特/秒的链路上传送。

::: definition 流量强度 {#def-intensity}
链路的**流量强度**（**利用率**）为 $\rho = La/R$，即比特到达的平均速率与链路发送它们所能达到的速率之比。
:::

若 $\rho > 1$，比特到达比离开更快，队列将无界增长——或者，由于真实缓冲区有限，分组被丢弃。因此网络设计的第一条法则是**永远不要让流量强度长时间超过 1**。不那么显然的是，早在 $\rho = 1$ 之前队列就已经很长了。若分组完全等间隔地到达，间隔不小于 $L/R$ 秒，那么没有分组需要等待。真实的到达是突发的，而突发会堆起队列。经典模型由爱尔朗（Erlang）建立、并由克莱因罗克（Kleinrock）针对分组网络加以发展，把这件事精确化了。

::: theorem M/M/1 队列的平均时延 {#thm-mm1}
设分组按速率为 $\lambda$ 的泊松过程到达（到达间隔相互独立且服从指数分布，均值为 $1/\lambda$），传输时间相互独立且服从指数分布、均值为 $1/\mu$，只有一条链路和无限大的缓冲区，且 $\rho = \lambda/\mu < 1$。则稳态下系统中（排队中或正在发送的）分组数为 $n$ 的概率为 $\pi_n = (1 - \rho)\rho^n$，平均分组数为 $\bar N = \rho/(1 - \rho)$，而一个分组在系统中停留的平均时间为

$$
T = \frac{1}{\mu - \lambda} = \frac{1/\mu}{1 - \rho}.
$$ {#eq-mm1}
:::

::: proof
在这些假设下，系统中的分组数是状态空间 $\set{0, 1, 2, \dots}$ 上的一个连续时间马尔可夫链，以速率 $\lambda$ 从 $n$ 转移到 $n+1$（一个到达），在 $n \ge 1$ 时以速率 $\mu$ 从 $n$ 转移到 $n - 1$（一个离开）。稳态下，沿状态 $n$ 与 $n+1$ 之间这个“切口”的长期转移速率在两个方向上必须相同，因为该链长期而言向上越过某切口的次数不可能多于向下越过的次数：$\lambda \pi_n = \mu \pi_{n+1}$。于是 $\pi_{n+1} = \rho\, \pi_n$，$\pi_n = \rho^n \pi_0$。概率之和为 $1$，且由于 $\rho < 1$，几何级数收敛：$\pi_0 \sum_{n \ge 0} \rho^n = \pi_0/(1-\rho) = 1$，故 $\pi_0 = 1 - \rho$。平均数为

$$
\bar N = \sum_{n \ge 0} n (1-\rho)\rho^n = (1 - \rho) \cdot \frac{\rho}{(1-\rho)^2} = \frac{\rho}{1-\rho},
$$

其中用到 $\sum_{n\ge0} n\rho^n = \rho/(1-\rho)^2$。最后，由**利特尔法则（Little's law）**——任何稳态系统中，平均顾客数等于到达速率乘以每位顾客平均停留时间，$\bar N = \lambda T$——得 $T = \bar N/\lambda = \rho / (\lambda(1 - \rho)) = 1/(\mu - \lambda)$。
:::

这些假设是理想化的——互联网的流量比泊松到达更突发，分组长度也远不是指数分布——所以把 [[#eq-mm1]] 当作一个模型而非定律。但它的形状是对的，而重要的恰恰是形状：以服务时间 $1/\mu$ 为单位度量的时延是 $1/(1 - \rho)$。利用率 $50\%$ 时，一个分组平均要在系统中待上其发送时间的两倍；$90\%$ 时是十倍；$99\%$ 时是一百倍。

::: widget plot
f: s/(1 - x)
x: 0, 0.98
y: 0, 50
sliders: s=1:0.5:5:0.5
labels: \text{平均时延 } T
caption: M/M/1 队列的平均停留时间随利用率 $\rho = x$ 的变化，以服务时间 $s = 1/\mu$ 为单位（[[#thm-mm1]]）。注意曲线在大约 $\rho = 0.5$ 以下多么平坦，而在超过 $0.8$ 之后上升多么陡峭：一条 95% 负载的链路的时延是 50% 负载链路的十倍，尽管它承载的流量还不到后者的两倍。这就是运营商会远早于链路“装满”就升级链路的原因，也是一点额外容量——或少一点流量——就能消去大部分排队时延的原因。
:::

真实的路由器只有有限的缓冲区。分组到达一个已满的缓冲区时就被**丢弃**（丢失），丢失的比例随流量强度上升。丢失不是网络的故障，而是其设计的一部分：在互联网中，网络层不承诺交付，从丢失中恢复交给主机去做（[[networks/reliable-transport]]）。我们将在 [[networks/tcp-congestion]] 看到，TCP 甚至把丢失用作网络发生拥塞的信号。

::: quiz
一台路由器的输出链路以 1 Gb/s 运行，平均承载 900 Mb/s 的流量。运营者在流量不变的情况下把链路速率翻倍到 2 Gb/s。按 M/M/1 模型，分组在这台路由器停留的平均时间降为原来的几分之一？
- [ ] 二分之一，因为链路快了一倍。
- [x] 十一分之一。
- [ ] 二十分之一。
- [ ] 不变，因为流量相同。
::: solution
设原来的服务速率为每秒 $\mu$ 个分组，则到达率为 $\lambda = 0.9\mu$。升级前，由 [[#eq-mm1]] 得 $T = 1/(\mu - 0.9\mu) = 10/\mu$。升级后服务速率为 $2\mu$，$T = 1/(2\mu - 0.9\mu) = 1/(1.1\mu)$。两者之比为 $10 \times 1.1 = 11$。收益的一半来自每个分组的发送时间减半；剩下的——$5.5$ 倍——来自利用率从 $0.9$ 降到 $0.45$，使队列几乎被清空。
:::
:::

## 吞吐量与带宽时延乘积

时延告诉我们一个比特要花多久到达；**吞吐量**告诉我们一段时间内平均每秒有多少比特到达。对一次文件传输来说，决定下载耗时的是吞吐量而不是时延。

::: definition 吞吐量 {#def-throughput}
从主机 A 到主机 B 的一次传输的**瞬时吞吐量**是某一时刻 B 接收数据的速率，以比特/秒计。若一个 $F$ 比特的文件花了 $T$ 秒到达，**平均吞吐量**为 $F/T$。
:::

::: proposition 瓶颈吞吐量 {#prop-bottleneck}
考虑一次长传输，路径由速率 $R_1, R_2, \dots, R_N$ 的各条链路组成，其中传输独占链路 $i$ 或固定分得其 $R_i$。则该传输的长期吞吐量至多为 $R_\text{min} = \min_i R_i$；而一个恰好以 $R_\text{min}$ 发送的发送方能在队列有界的情况下达到这个吞吐量。
:::

::: proof
设 $B_i(t)$ 为到时刻 $t$ 已穿过链路 $i$ 的比特数。一个比特只有先穿过链路 $i - 1$ 之后才能穿过链路 $i$，所以 $B_i(t) \le B_{i-1}(t)$；而链路 $i$ 每秒至多发送 $R_i$ 比特，所以 $B_i(t) \le R_i t$。于是已交付的比特对一切 $t$ 满足 $B_N(t) \le \min_i B_i(t) \le R_\text{min}\, t$，长期吞吐量 $\lim B_N(t)/t$ 至多为 $R_\text{min}$。反过来，若源以速率 $R_\text{min}$ 发送，则每条链路接收比特的速度都不快于它能发送的速度（$R_\text{min} \le R_i$），于是没有队列会长过正在接收的那个分组，比特以速率 $R_\text{min}$ 离开最后一条链路。
:::

最慢的链路是**瓶颈**。在当今的互联网中，核心链路又快又轻载，所以瓶颈通常在一端的接入链路（家庭宽带、移动无线链路）——或者一条被许多条流共享的链路。

::: example 一条共享的核心链路 {#ex-shared}
一个客户端的接入链路是 50 Mb/s，它从一个接入链路为 100 Mb/s 的服务器下载。路径中途经过某 ISP 网络中一条 1 Gb/s 的链路，该链路被 25 路这样的传输平均共享。这次下载的吞吐量是多少？
::: solution
该下载在共享链路上分到 $1000/25 = 40$ Mb/s。吞吐量为 $\min(100, 40, 50) = 40$ Mb/s，瓶颈是这条共享的核心链路，而不是任何一条接入链路。若其他传输中有十路完成，份额升为 $1000/15 \approx 67$ Mb/s，此时该客户端自己的 50 Mb/s 接入链路成为瓶颈。（25 条流各得均等份额是由谁决定的、它们又如何在没有中央权威的情况下发现这个份额，是 [[networks/tcp-congestion]] 中拥塞控制的主题。）
:::
:::

时延与速率在一个数中相遇，而我们在几乎每一章里都要用到它。

::: definition 带宽时延乘积 {#def-bdp}
一条路径的**带宽时延乘积**是 $R \times \text{RTT}$，即瓶颈速率乘以**往返时间**（一个比特从发送方到达接收方、再由一个应答返回所需的时间）。当发送方以速率 $R$ 连续发送、并等待每个比特的确认时，它就是“在途”（in flight）的比特数。
:::

带宽时延乘积是管道的容量。一个想要达到满速率 $R$ 的发送方必须有 $R \times \text{RTT}$ 个已发送而尚未确认的比特；若它自我限制在更少——因为某个协议限制了未确认数据的“窗口”——那么无论链路速率多高，它的吞吐量至多为 窗口/RTT。

::: example 长肥网络 {#ex-lfn}
一条路径的瓶颈速率为 10 Gb/s，往返时间为 100 ms。(a) 它的带宽时延乘积是多少？(b) 原始 TCP 首部用一个 16 位字段表示接收方愿意接收的未确认数据量，所以在途数据至多 65,535 字节。这样的连接在这条路径上能达到的吞吐量是多少？
::: solution
(a) $R \times \text{RTT} = 10^{10} \times 0.1 = 10^9$ 比特 $= 125$ MB。这条管道能装下 125 兆字节。

(b) 发送方可以发送 65,535 字节，然后必须等待确认，而确认在数据发出后一个 RTT 才到达。于是它每 $0.1$ s 至多发送 $65535 \times 8$ 比特，即 $\approx 5.24$ Mb/s——约为链路容量的 $0.05\%$。这就是 TCP 后来加入**窗口缩放**选项的原因（1992 年的 RFC 1323，现为 RFC 7323），它把这个 16 位字段最多放大 $2^{14}$ 倍。
:::
:::

::: warning 带宽不是速度
“更快的连接”通常意味着更高的链路速率，它只能减小发送时延 $L/R$。它对传播时延毫无办法——那由距离和光速决定；对那些短小的网页传输为建立连接所花的许多个往返也毫无办法（[[networks/application-layer]]）。从地球另一端获取一个小网页时，往返时间占绝对主导，把链路速率翻倍几乎无济于事；把内容搬得更近——内容分发网络背后的思想——才有效果。反过来，对长路径上的一次批量传输，限制吞吐量的往往是带宽时延乘积而不是链路速率。
:::

## 协议层次

只有当由不同的人制造、运行着不同软件的主机，对到底发送什么、其含义如何达成完全的一致时，网络才有用。这种一致就是协议。

::: definition 协议 {#def-protocol}
**协议**定义了通信双方（或多方）之间交换的消息的**格式**、发送的**顺序**，以及在发送或接收某个消息或其他事件（例如定时器到期）时采取的**动作**。
:::

把数据从一台主机上的程序搬到另一台主机上的程序，这项工作对单个协议而言太过复杂：它必须应付导线上的信号、差错与丢失的分组、在成千上万个网络之间寻找路由、把数据交给正确的程序，以及数据的含义。互联网把工作划分为**层次**。每一层向上一层提供一项**服务**，只依赖下一层的服务加上自己的动作；而每台主机上的每一层都通过自己的协议与另一台主机上的同一层对话。

::: definition 互联网协议栈 {#def-stack}
互联网的体系结构从上到下有五个层次：

| 层次 | 服务 | 数据单元 | 例子 |
|---|---|---|---|
| 应用层 | 网络应用程序本身 | 报文 | HTTP、DNS、SMTP、TLS |
| 传输层 | 在两台主机的*进程*之间交付 | 报文段（TCP）或数据报（UDP） | TCP、UDP、QUIC |
| 网络层 | 通过路由选择在许多网络之中的*主机*之间交付 | 数据报（分组） | IP、ICMP、路由协议 |
| 数据链路层 | 在一条链路的*相邻*节点之间交付 | 帧 | 以太网、Wi-Fi、5G 无线电 |
| 物理层 | 在媒体上移动单个比特 | 比特 | 双绞线、光纤、无线电 |

七层的 **OSI 参考模型**（ISO 7498，1984）在应用层与传输层之间增加了**表示层**（数据表示、加密）和**会话层**（对话控制）。在互联网中，这些功能在需要时内建在应用程序里。
:::

在发送方主机上，每一层取上一层交给它的数据——它的**有效载荷**——并加上自己的**首部**（有时还有尾部），其中携带它的对等层所需的信息。这就是**封装**：一条 HTTP 报文成为一个 TCP 报文段的有效载荷，该报文段成为一个 IP 数据报的有效载荷，该数据报又成为一个以太网帧的有效载荷。路径上的每台路由器都剥掉数据链路层的帧，检查 IP 首部，再把数据报重新封装进面向下一链路的新帧；它从来看不到 TCP 首部或 HTTP 报文。数据链路层的交换机只看帧。接收方主机按相反的顺序剥去各层首部。

::: example 封装的代价 {#ex-overhead}
一条 TCP 连接在以太网之上发送满尺寸的报文段，以太网的最大载荷（**MTU**，最大传输单元）是 1500 字节。IP 和 TCP 首部各为 20 字节（不含选项）。在线路上，每个以太网帧还要加上 14 字节帧首部和 4 字节帧检验序列，前面有 8 字节前导码，后面跟至少 12 字节的静默间隔。一条 1 Gb/s 以太网链路的容量有多大比例用于承载应用数据？
::: solution
每个报文段承载 $1500 - 20 - 20 = 1460$ 字节的应用数据。它在线路上占用 $1500 + 14 + 4 + 8 + 12 = 1538$ 个字节时间。效率为 $1460 / 1538 \approx 94.9\%$，所以在 1 Gb/s 以太网上传送应用数据的最好吞吐量约为 $949$ Mb/s。实践中 TCP 还给大多数报文段加上 12 字节的时间戳选项（RFC 7323），只剩 1448 字节数据，效率 $94.1\%$。对小消息来说开销要大得多：一次语音呼叫用 RTP（12 字节）、UDP（8 字节）和 IP（20 字节）首部发送 160 字节的语音抽样，每个 IP 分组有五分之一是首部——这还没算数据链路层自己的开销。
:::
:::

### 分层为何有效

分层是**模块化**的一种形式：只要每层提供的服务不变，它自己就可以更换而其余各层毫无察觉。以太网从同轴电缆上的 10 Mb/s（1980 年代）走到了光纤上的 400 Gb/s，IP 和 TCP 却无须任何改动；从电子邮件到视频通话的应用都建立在同样的传输协议之上。代价是一些重复（差错检测在多个层次都在做）和一些丢失的信息（一层看不到下层行为背后的原因——这个问题在 [[networks/wireless-mobile]] 中重新出现，那里 TCP 分不清无线差错和拥塞）。

互联网的层次有一个独特的形状，常被画成**沙漏**。窄腰处只有一个网络层协议 IP，每台主机和路由器都必须会讲它。它下面是许多链路技术，上面是许多传输协议和成千上万种应用。IP 对链路几乎没有要求（链路只需运载分组，允许不可靠），对上层也几乎不承诺什么（它**尽力而为**地交付分组，不保证交付、顺序或时间）。正因为腰身如此之细，任何新链路只要能承载 IP 就能接入互联网，任何新应用无需知道链路的存在就能使用它。

可靠性之类的功能应该放在哪一层？一个著名的答案来自萨尔策（Saltzer）、里德（Reed）与克拉克（Clark）。

::: proposition 端到端论据 {#prop-e2e}
只有在端点处应用的了解与帮助下才能完备且正确地实现的功能，就应当在端点处实现。在网络中也提供它，只能作为性能上的改进才有意义，永远不能取而代之。
:::

这是一条设计原则而非定理，但它的根据是一个实实在在的论证。拿可靠文件传输来说。即使每条链路都完美地重传受损的帧，一个文件仍然可能被有故障的路由器内存、有缺陷的操作系统或接收方坏掉的磁盘弄坏。要确信文件完好地到达，唯一的办法是让接收方的应用去校验它——比如用发送方算好的检验和——必要时重新请求。既然端点反正要这样做，链路层的可靠性就不能取而代之；它只能让端到端的校验更少失败。这就是互联网的网络层不可靠、可靠性住在主机上的 TCP 里、而某些链路（尤其 Wi-Fi）仍然在本地重传的原因：端到端论据允许它作为一种性能措施，因为否则的话一条高差错的无线链路会引起整条路径上的端到端重传。

::: intuition 装在信封里又装进另一个信封的一封信
一家公司的收发室就像分层。一位经理写了一封信（应用数据）交给助手，助手把它装进一个写明另一间办公室某位同事收的信封（传输层：哪个人）。收发室把这个信封放进发往正确城市的邮袋（网络层：哪栋楼），快递员再把邮袋装上开往下一个中转站的货车（数据链路层：哪一跳）。每个中转站只打开货车，看邮袋上的标签，把它装上另一辆货车。除了那位同事，没人拆信封；而经理根本不在乎货车烧柴油还是用电。
:::

## 互联网的体系结构

互联网是一个网络互联的网络，由数万个独立组织运营。

- **主机**经由**接入网络**接入：家庭的电缆、DSL 或光纤接入，移动网络，公司或大学的以太网和 Wi-Fi。
- 接入网络属于**互联网服务提供商**（ISP），或向其购买服务。小型的、地区性的 ISP 向更大的 ISP 购买**转接**（transit），大 ISP 又向少数几十家**一级**（tier-1）全球 ISP 购买，后者无需向任何人付费就能到达所有目的地。规模相当的 ISP 常常**对等互联**（peering）——在各自客户之间互通流量而不收费——或直接对接，或是在**互联网交换点**（IXP）——许多网络接进一台共享交换机的机房——进行。
- 大型内容提供商运营自己的全球网络与数据中心，并直接连接许多接入 ISP，其大部分流量因此绕开了上层运营商。

每个独立管理的网络都是一个拥有自己路由策略的**自治系统**；流量如何在数万个自治系统之间穿行是 [[networks/routing]] 的主题。协议本身是标准。互联网的标准由互联网工程任务组（IETF）编写，以编号的 **Requests for Comments**（RFC）发表：IP 是 RFC 791（1981），UDP 是 RFC 768（1980），TCP 是 RFC 9293（2022，取代 1981 年的 RFC 793）。以太网（IEEE 802.3）和 Wi-Fi（IEEE 802.11）等数据链路层标准来自 IEEE，蜂窝标准来自 3GPP。本书通篇引用 RFC 编号，以便你阅读权威原文：它们免费可得，其中最好的那些也非常好读。

### 一个并非为对手设计的网络

互联网的早期设计者假设用户彼此信任，而它的许多协议不携带任何认证。从体系结构直接引出三类攻击，每类都有一族标准防御手段。

- **窃听。** 一个分组途经许多网络，它们的运营者——或任何能搭线或接入共享 Wi-Fi 信道的人——都能读到它。防御手段是在传输层或应用层做端到端加密——TLS（[[networks/application-layer]]）和 QUIC——它能隐藏内容（但本身不隐藏谁在和谁通话）。
- **欺骗。** IP 中没有任何东西阻止一个主机在分组里写入任何源地址。防御手段包括在网络边缘过滤——ISP 丢弃其用户发出的、源地址不属于他们的分组（RFC 2827，即“BCP 38”）——以及用密码学而不是地址来认证对等方的协议。
- **拒绝服务。** 由于分组交换按需共享容量，来自许多失陷机器的一阵流量洪峰可能耗尽一条链路或一台服务器。防御手段包括超额配置容量、在靠近源头处过滤与限速，以及把服务分散在许多地点，使任何单条链路都不成为目标。

相关协议出现时我们会回到每一种攻击。对攻击与防御的详细研究是 [[security]] 的主题。

::: quiz
下面关于互联网各层次的说法哪些正确？
- [x] 路由器处理每个分组的网络层首部，但不处理传输层首部。
- [ ] TCP 之所以保证交付，是因为 IP 会在每条链路上重传丢失的分组。
- [x] 新的链路技术无须改动 TCP 或 HTTP 就能承载互联网流量。
- [ ] 路径上的每台路由器都要在每个分组上添加每一层的首部。
::: solution
路由器只实现物理层、数据链路层和网络层：它们读取 IP 首部来转发数据报，从不需要 TCP 首部（分层模型之外的某些功能——如防火墙和 NAT——除外，见 [[networks/network-layer]]）。IP 是尽力而为的，不重传；可靠性由端主机上的 TCP 提供，这正是端到端论据的体现。因为 IP 是窄腰，新的链路只需承载 IP 数据报即可。路由器只剥掉并重新加上数据链路层的帧；IP、TCP 和应用层首部由发送方一次性加上。
:::
:::

::: history
分组交换被发明了两次。兰德公司（RAND Corporation）的保罗·巴兰（Paul Baran）在 1964 年的系列著作《论分布式通信》（*On Distributed Communications*）中提出：用大量冗余链路组成网络，“报文块”在其上逐台中继，使通信系统能在失去许多节点的条件下继续工作。几乎同时，英国国家物理实验室的唐纳德·戴维斯（Donald Davies）在 1965–66 年提出建一个全国性的计算机网络，并发明了 *packet*（分组）一词。伦纳德·克莱因罗克（Leonard Kleinrock）关于报文交换网络的排队论（他 1962 年的博士论文，1964 年结集出版）提供了数学工具。这些思想汇合于 ARPANET，其第一条链路于 1969 年 10 月 29 日从 UCLA 向 SRI 传送了第一条报文。为了把 ARPANET 与无线、卫星分组网络互联，温顿·瑟夫（Vint Cerf）和鲍勃·卡恩（Bob Kahn）于 1974 年 5 月发表了《一种分组网络互通信协议》（*“A Protocol for Packet Network Intercommunication”*）：这就是后来 TCP 与 IP 的设计，1978 年拆分为两个协议。ARPANET 于 1983 年 1 月 1 日切换到 TCP/IP，这个日期常被视为互联网的诞生日。杰罗姆·萨尔策（Jerome Saltzer）、戴维·里德（David Reed）与戴维·克拉克（David Clark）的《系统设计中的端到端论据》（*“End-to-end arguments in system design”*，《ACM Transactions on Computer Systems》，1984）为这套体系结构提供了被引用最多的原则，而克拉克的《DARPA 互联网协议的设计哲学》（*“The design philosophy of the DARPA internet protocols”*，SIGCOMM 1988）阐明了其背后的优先次序——生存性第一，计费最后。
:::

- **分组交换**按需共享链路容量；与**电路交换**相比，它能支持多得多的突发用户（[[#ex-statmux]]），代价是波动的时延和偶尔的丢失。
- $P$ 个分组经过 $N$ 条链路的存储转发需要 $(N + P - 1)L/R$（[[#prop-saf]]）：把消息切成分组让路径形成流水线。
- 节点时延 = 处理 + 排队 + **发送**（$L/R$）+ **传播**（$d/s$）（[[#def-delay]]）；发送取决于分组长度和速率，传播取决于距离。
- 排队时延随利用率 $\rho$ 按 $1/(1 - \rho)$ 增长（[[#thm-mm1]]）；队列远早于链路装满就变得很长，而有限缓冲区下会造成丢失。
- 吞吐量受**瓶颈**链路限制（[[#prop-bottleneck]]）；填满一条路径需要在途有相当于**带宽时延乘积** $R \times \text{RTT}$ 的数据。
- 互联网有五个**层次**——应用层、传输层、网络层、数据链路层、物理层——每一层把上一层的消息**封装**在自己的消息之下，IP 是沙漏的窄腰。
- **端到端论据**把可靠性之类的功能放在端主机上；网络本身是尽力而为的。
:::

## 习题

::: exercise 发送时延 {level=1 check="120"}
把一个 1500 字节的分组发送上 100 Mb/s 的链路需要多长时间？（答案以微秒为单位。）
::: solution
$L = 1500 \times 8 = 12000$ 比特，故 $d_\text{trans} = L/R = 12000 / 10^8\ \text{s} = 1.2 \times 10^{-4}$ s $= 120$ µs。链路的长度无关紧要。
:::
:::

::: exercise 传播时延 {level=1 check="10"}
一条光纤链路长 2000 km，信号以 $2 \times 10^8$ m/s 传播。它的传播时延是多少？它依赖链路速率吗？（时延以毫秒为单位。）
::: solution
$d_\text{prop} = d/s = 2 \times 10^6 / (2 \times 10^8) = 10^{-2}$ s $= 10$ ms。它与链路速率和分组长度都无关：同样长度的 1 Mb/s 链路和 100 Gb/s 链路有相同的传播时延。
:::
:::

::: exercise 以字节计的带宽时延乘积 {level=1 check="10"}
一条路径的瓶颈速率为 1 Gb/s，往返时间为 80 ms。发送方要让路径保持充满需要在途多少字节？那是多少个 1500 字节的分组？（以兆字节为单位输入，$1\ \text{MB} = 10^6$ 字节。）
::: solution
$R \times \text{RTT} = 10^9 \times 0.08 = 8 \times 10^7$ 比特 $= 10^7$ 字节 $= 10$ MB，即 $10^7 / 1500 \approx 6667$ 个满尺寸分组。在途数据更少的发送方用不满整个千兆比特（[[#def-bdp]]）。
:::
:::

::: exercise 繁忙路由器上的队列 {level=2 check="5"}
分组按泊松过程到达某路由器的输出链路，到达率为每秒 800 个分组；链路平均每秒能发送 1000 个分组，传输时间服从指数分布。用 M/M/1 模型求链路上的平均分组数和一个分组在链路停留的平均时间。（平均时间以毫秒为单位。）
::: solution
$\rho = 800/1000 = 0.8$。由 [[#thm-mm1]]，$\bar N = \rho/(1 - \rho) = 0.8/0.2 = 4$ 个分组，而 $T = 1/(\mu - \lambda) = 1/(1000 - 800) = 0.005$ s $= 5$ ms。用利特尔法则验证：$\lambda T = 800 \times 0.005 = 4 = \bar N$。一个自身发送平均只要 1 ms 的分组，在链路上却平均要停留五倍于此的时间。
:::
:::

::: exercise 排队何时占主导？{level=2 check="0.9"}
在 M/M/1 模型中，利用率 $\rho$ 为多少时，系统中的平均时间恰为平均发送时间 $1/\mu$ 的十倍？（输入 $\rho$。）
::: solution
由 [[#eq-mm1]]，$T \mu = 1/(1 - \rho)$。令 $1/(1-\rho) = 10$ 得 $1 - \rho = 0.1$，故 $\rho = 0.9$。90% 负载下，一个分组在自己发送之前平均要等待九个发送时间的长度。
:::
:::

::: exercise 哪一层？{level=2}
对下列每项任务，说出互联网协议栈中执行它的层次，并说明路径上的一台路由器是否参与：(a) 选择哪条输出链路朝向目的主机；(b) 把字节交付给目的主机上正确的程序；(c) 检测出一个帧在单个 Wi-Fi 跳上损坏了；(d) 按名字请求一个网页；(e) 把比特变成光纤中的光脉冲。
::: solution
(a) 网络层（IP 转发，路由由路由协议算出）；路由器做这件事——这是它的主要工作。(b) 传输层（TCP 或 UDP 中的端口号）；只有主机。(c) 数据链路层（802.11 的帧检验序列）；由该跳两端的两个节点完成，它们可能是一台主机和一个接入点，或者是路由器的一个接口。(d) 应用层（HTTP）；只有主机。(e) 物理层；光纤上发送的每个节点，包括路由器。
:::
:::

::: exercise 更多用户的统计复用 {level=2 check="0.0015"}
在 [[#ex-statmux]] 的设定下（一条 10 Mb/s 的链路；用户活动时以 1 Mb/s 发送，且各自独立地以 $0.1$ 的概率活动），40 个用户中同时活动者超过 10 个的概率是多少（保留两位有效数字）？（输入概率。）
::: solution
$X \sim \Bin(40, 0.1)$，

$$
\Prob(X \ge 11) = 1 - \sum_{k=0}^{10} \binom{40}{k} (0.1)^k (0.9)^{40-k} \approx 0.00147,
$$

保留两位有效数字为 $0.0015$（Python：`sum(comb(40,k)*0.1**k*0.9**(40-k) for k in range(11,41))` 给出 `0.0014697…`）。平均活动用户数为 $4$，标准差 $\sqrt{40 \times 0.1 \times 0.9} \approx 1.9$，所以 11 个活动用户比均值高出三个半标准差还多。
:::
:::

::: exercise 最佳分组长度 {#exr-optimal-packet level=3 check="sqrt(1280000000)"}
一条 $M$ 比特的消息经 $N \ge 2$ 条速率 $R$ 的存储转发链路发送。它被切成每个携带 $p$ 比特数据的分组（假设 $p$ 整除 $M$），每个分组还携带一个 $h$ 比特的首部。忽略传播与处理，(a) 证明传输时间为 $T(p) = (N - 1 + M/p)(p + h)/R$；(b) 把 $p$ 当作连续变量，证明 $T$ 在 $p^* = \sqrt{hM/(N - 1)}$ 处最小；(c) 对 $M = 8 \times 10^6$、$N = 3$、$h = 320$（40 字节首部）计算 $p^*$。（$p^*$ 以比特为单位。）
::: solution
(a) 共有 $P = M/p$ 个分组，每个长 $L = p + h$ 比特，由 [[#prop-saf]] 得 $T = (N + M/p - 1)(p + h)/R$。

(b) 展开：$R\,T(p) = (N-1)p + (N-1)h + M + Mh/p$。求导得 $R\,T'(p) = (N - 1) - Mh/p^2$，它在 $p < p^*$ 时为负、$p > p^*$ 时为正，其中 $p^* = \sqrt{Mh/(N-1)}$，所以 $p^*$ 是 $p > 0$ 上的全局最小值（等价地，$R\,T''(p) = 2Mh/p^3 > 0$，故 $T$ 是凸的）。小分组付了过多的首部（$Mh/p$）；大分组失去了流水线（$(N-1)p$）；最优点让两项平衡，而它们在 $p^*$ 处恰好相等。

(c) $p^* = \sqrt{320 \times 8 \times 10^6 / 2} = \sqrt{1.28 \times 10^9} \approx 35777$ 比特，约 4.5 kB，在 $R = 10$ Mb/s 下给出 $T \approx 0.814$ s，而 $10^4$ 比特分组为 $0.828$ s。这个最小值很平缓——上面图中的曲线在 $p^*$ 附近很平——这是真实网络能对一切流量固定单一最大分组长度的原因之一。
:::
:::

::: exercise 带传播的流水线 {level=3}
把 [[#prop-saf]] 一般化：设 $N$ 条链路每条还有传播时延 $d_\text{prop}$，每台交换机每个分组还有处理时延 $d_\text{proc}$（在分组完全到达之后、发送之前执行，且可与后续分组的接收重叠）。证明 $P$ 个背靠背分组中最后一个在 $(N + P - 1)L/R + N d_\text{prop} + (N - 1) d_\text{proc}$ 时刻到达；并对 $P = 800$ 个 $10^4$ 比特的分组、$N = 3$ 条 10 Mb/s 且各长 1000 km 的链路（$s = 2 \times 10^8$ m/s）、$d_\text{proc} = 10$ µs 求值。
::: solution
记 $\tau = L/R$，$\delta_j = (j - 1)(d_\text{prop} + d_\text{proc})$，即前 $j - 1$ 条链路与交换机在链路 $j$ 之前加入的固定迟延。我们断言分组 $k$ 在时刻 $(k + j - 1)\tau + \delta_j$ 完成向链路 $j$ 的*发送*。$j = 1$ 时这就是背靠背的源：$k\tau$。$j > 1$ 时，分组 $k$ 在时刻 $(k + j - 2)\tau + \delta_{j-1} + d_\text{prop}$ 被交换机 $j - 1$ 完全收到，$d_\text{proc}$ 之后、即 $(k + j - 2)\tau + \delta_j$ 就绪；链路 $j$ 按归纳假设在 $(k + j - 2)\tau + \delta_j$ 发完分组 $k - 1$（$k = 1$ 时则一直空闲）。两个条件在同一时刻成立，所以分组 $k$ 在 $(k + j - 1)\tau + \delta_j$ 完成于链路 $j$。之后最后一位在链路 $N$ 上传播，在 $(P + N - 1)\tau + (N-1)(d_\text{prop} + d_\text{proc}) + d_\text{prop} = (N + P - 1)\tau + N d_\text{prop} + (N-1) d_\text{proc}$ 到达。

代入数值：$\tau = 1$ ms，$d_\text{prop} = 10^6/(2 \times 10^8) = 5$ ms，于是总时间为 $802 + 15 + 0.02 = 817.02$ ms。传播与处理只加一个固定量，按链路付费而不是按分组付费——这又是流水线取胜的又一个理由。
:::
:::
