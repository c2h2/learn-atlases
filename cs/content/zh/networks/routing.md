[[networks/network-layer]] 中的转发表告诉每台路由器每个分组该发往何处，但总得有人把这些表项填进去。在一个小网络里，管理员可以手工键入表项；然而互联网上有数万个独立运营的网络、数百万台路由器和大约一百万个 IPv4 前缀，每分钟都在某处有链路失效又恢复，而且没有人统管全局。这些表必须由路由器自己计算出来——通过与邻居交换报文——并且一旦哪里出了故障，它们必须在几秒之内完成调整。

这就是**路由选择**问题，互联网在两个层次上解决它。在一个网络内部——一所大学、一家公司、一个 ISP——路由器用迪杰斯特拉（Dijkstra）算法或贝尔曼-福特（Bellman-Ford）算法之类的路由算法寻找最小代价路径，并把它们作为分布式协议运行：**链路状态**路由，每台路由器获知整张地图并自己计算路径；或者**距离向量**路由，路由器之间只交换各自的当前距离。在网络之间，每个网络都有自己的商业利益、不愿向他人透露内部地图，路由遵循**策略**，其协议是 BGP。本章研究这两个层次：算法正确性的证明、距离向量路由中称为计数到无穷的著名故障，以及 BGP 出错的方式与防护手段。最短路径算法本身在 [[algorithms/shortest-paths]] 中展开；这里我们关注如何在网络中运行它们。

## 路由问题

::: definition 作为图问题的路由选择 {#def-routing}
把网络建模为一个图 $G = (V, E)$，其中顶点是路由器，边是链路，每条链路带有管理员设定的正**代价** $c(x, y)$——通常与链路速率成反比，或反映其距离或价格。一条路径的代价是其各链路代价之和。**路由选择**为每台路由器 $x$ 和每个目的地 $y$ 计算一条从 $x$ 到 $y$ 的**最小代价路径**；$x$ 的转发表随即记下这条路径的第一条链路，即**下一跳**。若每台路由器都依据完整的网络地图自己计算路径，则路由算法是**集中式**（全局）的；若路由器根据与邻居交换的信息迭代地计算路径，则是**分布式**的。
:::

关于最小代价路径的两个事实是一切路由算法的基础。第一，最小代价路径的子路径也是最小代价路径：如果从 $x$ 到 $y$ 的最佳路径经过 $v$，那么其中从 $v$ 到 $y$ 的部分就是从 $v$ 到 $y$ 的最佳路径。因此下一跳表项是一致的——若 $x$ 把一个分组交给 $v$，$v$ 自己的表会让它沿着 $x$ 的最佳路径的剩余部分继续走下去，而 IP 的逐跳转发会把分组沿一条最小代价路径送达。第二，最小代价 $D_x(y)$ 满足**贝尔曼-福特方程（Bellman-Ford equation）**

$$
D_x(y) = \min_{v \text{ 为 } x \text{ 的邻居}} \bigl( c(x, v) + D_v(y) \bigr), \qquad D_y(y) = 0,
$$ {#eq-bellman-ford}

因为从 $x$ 出发的路径必定以一条通向某个邻居 $v$ 的链路开头，然后再从 $v$ 尽可能廉价地走下去。

## 链路状态路由选择

在**链路状态**协议中，每台路由器把自己的链路告诉所有其他路由器，于是每台路由器都拼出同一张完整的地图，并各自计算最小代价路径。

1. 每台路由器发现它的邻居以及各链路的代价（通过在每条链路上交换 *hello* 报文）。
2. 它把这些信息打包成一个**链路状态通告**（LSA）——“我是 $x$，我的链路通往 $v_1$，代价 $c_1$，……”——并带上一个随每个新版本递增的序号。
3. 它把这个 LSA **泛洪**出去：它在自己的所有链路上发送它；任何收到比手中更新的 LSA 的路由器都把它存下，并在其余所有链路上转发。较旧或重复的 LSA 被丢弃，于是泛洪停止。
4. 任何东西发生变化时，该路由器就泛洪一个新的 LSA。每当地图变化，每台路由器就在自己的地图上运行迪杰斯特拉算法。

::: algorithm 迪杰斯特拉算法 {#alg-dijkstra}
输入：一个带正链路代价的图和一个源 $s$。输出：$D(v)$，从 $s$ 到每个 $v$ 的最小代价；$p(v)$，$v$ 在一条最小代价路径上的前驱。

1. $N \gets \set{}$；$D(s) \gets 0$；对每个 $v \ne s$ 置 $D(v) \gets \infty$。
2. 只要还有顶点不在 $N$ 中：
   1. 选取 $N$ 之外 $D(u)$ 最小的 $u$，把 $u$ 加入 $N$（**确定** $u$）。
   2. 对 $u$ 的每个不在 $N$ 中的邻居 $v$：若 $D(u) + c(u, v) < D(v)$，则置 $D(v) \gets D(u) + c(u, v)$，且 $p(v) \gets u$。
:::

::: theorem 迪杰斯特拉算法的正确性 {#thm-dijkstra}
在链路代价为正的条件下，一个顶点 $u$ 被确定时，$D(u)$ 等于从 $s$ 到 $u$ 的最小代价，并且从 $u$ 出发沿前驱回溯即得一条最小代价路径。
:::

::: proof
对已确定顶点的个数归纳证明：每个已确定的顶点都有 $D$ 等于其最小代价 $\delta$，并且对每个未确定的顶点 $v$，$D(v)$ 是从 $s$ 到 $v$ 的、除 $v$ 外所有顶点均已确定的路径的最小代价。$s$ 被确定后两者都成立。设两者成立且 $u$ 是下一个被确定的顶点。取任意一条从 $s$ 到 $u$ 的路径 $P$，设 $y$ 是 $P$ 上第一个不属于 $N$ 的顶点（它存在，因为 $u \notin N$）。$P$ 到 $y$ 为止的部分在 $y$ 之前只经过已确定的顶点，由第二个归纳假设其代价至少为 $D(y)$，而 $P$ 的其余部分代价至少为 $0$；于是 $\text{代价}(P) \ge D(y) \ge D(u)$，因为 $u$ 是在 $D$ 最小时被选中的。所以没有任何路径能胜过 $D(u)$，而 $D(u)$ 本身就是一条（经过已确定顶点的）路径的代价，故 $D(u) = \delta(u)$。确定 $u$ 之后，步骤 2.2 考察的恰是以 $u$ 为最后一个已确定顶点的那些新路径，于是第二个归纳假设得以恢复。前驱记录了达到每个 $D$ 值的路径。
:::

::: example 小网络上的迪杰斯特拉算法 {#ex-dijkstra}

::: solution

| 已确定 $N$ | B | C | D | E | F |

用带优先队列（标准实现，$n$ 台路由器、$m$ 条链路时复杂度为 $O((n + m)\log n)$）的 Python 做同样的计算：

```python
# dijkstra.py：链路状态协议计算的、从一台路由器出发的最小代价路径
import heapq

def dijkstra(graph, source):
    dist, prev = {source: 0}, {source: None}
    done, heap = set(), [(0, source)]
    while heap:
        d, u = heapq.heappop(heap)
        if u in done:
            continue                             # 过期表项：u 早已被确定
        done.add(u)
        print(f"settle {u} at distance {d}")
        for v, w in graph[u].items():
            if v not in done and d + w < dist.get(v, float("inf")):
                dist[v], prev[v] = d + w, u
                heapq.heappush(heap, (d + w, v))
    return dist, prev

def first_hop(prev, source, dest):               # dest 对应的转发表项
    while prev[dest] != source:
        dest = prev[dest]
    return dest

edges = {("A", "B"): 4, ("A", "C"): 1, ("B", "C"): 2, ("B", "D"): 5, ("C", "D"): 8,
         ("C", "E"): 10, ("D", "E"): 2, ("D", "F"): 6, ("E", "F"): 3}
graph = {}
for (u, v), w in edges.items():                  # 链路是双向的
    graph.setdefault(u, {})[v] = w
    graph.setdefault(v, {})[u] = w
dist, prev = dijkstra(graph, "A")
for d in sorted(dist):
    if d != "A":
        print(f"{d}: cost {dist[d]}, next hop {first_hop(prev, 'A', d)}")
```


注意 A 到直接邻居 B 的最佳路径要经过 C（$1 + 2 = 3 < 4$），而且每个目的地都经由 C 到达，所以 A 的转发表只有一个下一跳。其余每台路由器都在同一张地图上算出自己的表。

:::

泛洪要消耗报文：每个 LSA 大致在每条链路上、每个方向各穿过一次，所以一次变更花费 $O(m)$ 个报文，而每台路由器的计算代价为 $O((n + m) \log n)$。作为交换，收敛很快——新的 LSA 一到某台路由器，它的路径就正确了——而且每台路由器都能核查自己的地图。有一个陷阱：若链路代价依赖于负载，路由可能**振荡**——流量移到便宜的路径，那条路径随之变贵，流量又移了回来——这就是实践中代价保持静态、由管理员设定的原因。

## 距离向量路由选择

在**距离向量**协议中，路由器永远学不到整张地图。每台路由器 $x$ 只保存自己的**距离向量** $D_x = (D_x(y) : y \in V)$——它对自己到每个目的地最小代价的当前估计——以及最近从邻居收到的向量，并在本地应用 [[#eq-bellman-ford]]。

::: algorithm 距离向量路由选择 {#alg-dv}
在每台路由器 $x$ 上：

1. 初始时，$D_x(x) = 0$，对邻居 $y$ 有 $D_x(y) = c(x, y)$，对其余一切 $y$ 为 $\infty$；把 $D_x$ 发给每个邻居。
2. 每当链路代价 $c(x, v)$ 改变，或从邻居 $v$ 收到一个新的向量 $D_v$：
   1. 对每个目的地 $y$：$D_x(y) \gets \min_v \bigl(c(x, v) + D_v(y)\bigr)$，并把取到最小值的 $v$ 记为 $y$ 的下一跳。
   2. 若 $D_x$ 发生了变化，把它发给每个邻居。
:::

这个算法是**迭代**的（不断进行直到没有向量改变）、**异步**的（路由器无须步调一致地动作）并且是**分布式**的（每台路由器只使用邻居的信息）。基本的正确性结论最容易用同步轮次来陈述。

::: theorem 同步距离向量路由选择的收敛 {#thm-dv}
假设所有路由器都以 $x = y$ 时 $D_x(y) = 0$、否则为 $\infty$ 开始，且每一轮中每台路由器都用邻居们上一轮的向量替换自己的向量。则第 $k$ 轮之后，$D_x(y)$ 是从 $x$ 到 $y$、至多含 $k$ 条链路的路径的最小代价。于是至多 $n - 1$ 轮后所有向量都等于真正的最小代价，此后再不改变。
:::

::: proof
对 $k$ 归纳。$k = 0$ 时，不含链路的路径只有从 $y$ 到自身的空路径，代价 $0$，与初始向量吻合。设断言在第 $k$ 轮后成立。一条从 $x \ne y$ 到 $y$、至多含 $k + 1$ 条链路的路径由第一条链路 $(x, v)$ 加上一条从 $v$ 出发、至多含 $k$ 条链路的路径构成；其中最廉价的一条代价为 $\min_v (c(x, v) + D^{(k)}_v(y))$，按归纳假设这正是第 $k + 1$ 轮所计算的值。（对 $x = y$，由于代价为正，该值保持 $0$。）因为链路代价为正，最小代价路径绝不重复经过顶点，所以它至多有 $n - 1$ 条链路；第 $n - 1$ 轮之后每个 $D_x(y)$ 都是真正的最小代价，再往后的轮次算出的还是同样的值。
:::

::: example 距离向量的收敛 {#ex-dv}
三台路由器 X、Y、Z 由代价为 3 的链路 X–Y、代价为 1 的链路 Y–Z 和代价为 6 的链路 X–Z 连接。从只了解直连链路的向量出发（[[#alg-dv]] 的步骤 1），计算每个同步轮次之后的各向量。
::: solution
把每个向量写成（到 X、到 Y、到 Z 的距离）。

| 轮次 | $D_X$ | $D_Y$ | $D_Z$ |
|---|---|---|---|
| 初始 | $(0, 3, 6)$ | $(3, 0, 1)$ | $(6, 1, 0)$ |
| 1 | $(0, 3, 4)$ | $(3, 0, 1)$ | $(4, 1, 0)$ |
| 2 | $(0, 3, 4)$ | $(3, 0, 1)$ | $(4, 1, 0)$ |

第 1 轮中，X 算得 $D_X(Z) = \min(c(X, Y) + D_Y(Z),\ c(X, Z) + D_Z(Z)) = \min(3 + 1, 6 + 0) = 4$，经由 Y；Z 对称地发现 $D_Z(X) = 4$，经由 Y；Y 的向量已经正确。第 2 轮没有任何变化，于是没有路由器发送新向量，协议归于沉寂。（从直连链路向量出发，比 [[#thm-dv]] 的全 $\infty$ 起点领先一轮。）链路 X–Z 始终不被使用，因为经过 Y 的两跳路径更便宜。
:::
:::

只要更新持续进行、代价为正且固定（伯特卡斯（Bertsekas）与加拉格（Gallager）给出了证明），异步版本也从任何初始状态收敛到正确的代价。但“任何初始状态”包括错得离谱的状态，从这些状态出发的收敛可能非常慢。

### 好消息传得快，坏消息传得慢

链路代价*减小*时，新信息像 [[#thm-dv]] 那样每次交换传播一跳。链路*失效*或代价增大时，会发生更糟的事情。

::: example 计数到无穷 {#ex-count-to-infinity}
三台路由器排成一条线 A — B — C，链路代价均为 1。收敛状态下 $D_A(C) = 2$（经由 B），$D_B(C) = 1$。随后链路 B–C 失效。采用同步更新，并以 $16$ 代表无穷（如同 RIP），追踪 $D_A(C)$ 与 $D_B(C)$。
::: solution
B 不再有到 C 的链路，但它手里还有 A 的最后一个向量，上面写着 $D_A(C) = 2$。B 并不知道 A 到 C 的路由其实经过 B 自己，于是它断定自己可以经由 A、以代价 $1 + 2 = 3$ 到达 C。接着 A 听到 $D_B(C) = 3$，把 $D_A(C)$ 设为 $1 + 3 = 4$；B 听到 4 又设成 5；如此每两轮各上涨两级：

```python
# dv.py：到目的地 C 的距离向量路由选择，链路 B-C 失效前后
INF = 16                                         # RIP 的“无穷大”

def run(cost, dist, via, rounds, poison=False):
    """除 C 外每个结点上贝尔曼-福特更新的同步轮次。"""
    history = [dict(dist)]
    for _ in range(rounds):
        # 每个结点向每个邻居通告的内容（毒性反转：向自己
        # 经由其转发的那个邻居通告 INF）
        adv = {(u, v): (INF if poison and via.get(u) == v else dist[u])
               for (u, v) in cost}
        new, newvia = dict(dist), dict(via)
        for x in dist:
            if x == "C":
                continue
            options = [(min(INF, c + adv[(v, x)]), v) for (u, v), c in cost.items() if u == x]
            new[x], newvia[x] = min(options) if options else (INF, None)
        if new == dist:
            break
        dist, via = new, newvia
        history.append(dict(dist))
    return history

def links(pairs):                                # 把无向链路表示为有向对
    return {**{(u, v): c for (u, v), c in pairs.items()}, **{(v, u): c for (u, v), c in pairs.items()}}

after = links({("A", "B"): 1})                   # B-C 已失效
start = {"A": 2, "B": 1, "C": 0}
for poison in (False, True):
    h = run(after, start, {"A": "B", "B": "C"}, rounds=30, poison=poison)
    print("poisoned reverse" if poison else "plain", "-> rounds:", len(h) - 1)
    print("  A:", [d["A"] for d in h])
    print("  B:", [d["B"] for d in h])
```

```console
$ python3 dv.py
plain -> rounds: 15
  A: [2, 2, 4, 4, 6, 6, 8, 8, 10, 10, 12, 12, 14, 14, 16, 16]
  B: [1, 3, 3, 5, 5, 7, 7, 9, 9, 11, 11, 13, 13, 15, 15, 16]
poisoned reverse -> rounds: 2
  A: [2, 2, 16]

```

若没有上限，这些代价将永远上升下去；在 RIP 的无穷大 16 之下，两台路由器花了 15 轮就 C 不可达达成一致，在此期间发往 C 的分组在 A 与 B 之间来回弹跳，直到 TTL 耗尽。采用**毒性反转**（poisoned reverse）——A 到 C 的路由经由 B，就告诉 B 自己到 C 的距离是无穷大——B 立刻知道自己没有路由，两台路由器两轮之内达成一致。
:::

:::

背后的问题是，距离向量只说明*多远*而不说明*经由哪条路*，所以路由器看不出邻居的路由其实绕回了自己。**水平分割**（split horizon，不把一条路由通告回它学自的那个邻居）和**毒性反转**（把它以无穷大通告回去）能修复两台路由器之间的环，却修不了更长的环：三台路由器连成三角形时，每台仍可能从另一台学到一条出自第三台的过时路由（[[#exr-triangle]]）。下文的路径向量协议通过通告整条路径来彻底解决这个问题。

| | 链路状态 | 距离向量 |
|---|---|---|
| 交换的信息 | 每台路由器的链路，泛洪给所有路由器 | 距离向量，只发给邻居 |
| 计算 | 每台路由器在完整地图上运行迪杰斯特拉算法 | 贝尔曼-福特更新，分布式 |
| 每次变更的报文数 | $O(m)$（一次泛洪） | 不定；可能很多轮 |
| 收敛 | 快 | 可能很慢；计数到无穷 |
| 鲁棒性 | 一台路由器只会算错自己的表 | 一个错误的向量会传播给所有路由器 |

::: quiz
路由器 X 与邻居 Y（代价 2）、Z（代价 7）相连。Y 报告到目的地 W 的距离为 5，Z 报告 1。按贝尔曼-福特方程，X 把自己到 W 的距离设成什么？下一跳是谁？
- [ ] 1，经由 Z
- [x] 7，经由 Y
- [ ] 8，经由 Z
- [ ] 5，经由 Y
::: solution
$D_X(W) = \min(c(X, Y) + D_Y(W),\ c(X, Z) + D_Z(W)) = \min(2 + 5, 7 + 1) = \min(7, 8) = 7$，经由 Y。通告距离较小的邻居未必是更好的下一跳：通往它的链路代价也要计入。
:::
:::

## 网络内部的路由选择：OSPF 与 IS-IS

互联网是一个由**自治系统**（AS）构成的网络之网络：自治系统是单一机构管理下的网络，每个都用一个自治系统号标识。在一个自治系统内部，**域内**路由选择协议（**内部网关协议**，IGP）计算最小代价路径。早期的 ARPANET 使用距离向量路由选择，RIP（路由信息协议，RFC 2453）就是一种至今仍见于小型网络的距离向量协议。较大的网络使用链路状态协议：**OSPF**（Open Shortest Path First；用于 IPv4 的 OSPFv2 见 RFC 2328，用于 IPv6 的 OSPFv3 见 RFC 5340）或 **IS-IS**（源自 OSI 套件，如今被运营商广泛采用）。

OSPF 路由器可靠地泛洪链路状态通告（带确认和周期性刷新），并运行迪杰斯特拉算法。管理员设定链路代价（“权重”），以此工程化地安排流量的走向。有几个特性在大规模下举足轻重：当若干条路径代价相等时，流量可以在它们之间分担（**等价多路径**）；报文可以被**认证**，使链路上的攻击者无法注入虚假通告；一个大的自治系统可以划分成若干**区域**，每个区域泛洪自己的详细地图，由**区域边界路由器**把各区域的前缀汇总到一个**骨干**区域，于是任何路由器都不需要整个自治系统的地图。

## 网络之间的路由选择：BGP

自治系统之间，最小代价不是目标，共享地图也不可能。每个自治系统都有自己的利益——它为自己的付费客户承载流量、避免替别人免费承载流量、偏好更便宜的链路——而且不会向竞争对手暴露内部结构。**边界网关协议**（BGP-4，RFC 4271）是互联网唯一的域间路由选择协议，每个连接到一个以上其他自治系统的自治系统都要运行它。

::: definition BGP 路由与路径向量 {#def-bgp}
相邻的自治系统用建立在 TCP 之上（端口 179）的 **BGP 会话**连接各自的**边界路由器**：自治系统之间用**外部 BGP**（eBGP），自治系统内部为了把学到的信息分发给自己的路由器而用**内部 BGP**（iBGP）。一条 BGP **路由**是对一个前缀的通告，连同若干**属性**，其中包括：

- **AS-PATH**：该通告穿过的自治系统序列，最近的在前；
- **NEXT-HOP**：发往该前缀的流量应当送往的边界路由器的地址；
- **LOCAL-PREF**：一个自治系统按自身策略在本系统内部设定的偏好值。

一个自治系统向邻居**通告**一个前缀，就是提出为该前缀承载流量。收到一条 AS-PATH 中已经含有自己自治系统号的路由的路由器会拒绝它。由于路由携带整条路径而不只是一个距离，BGP 是一个**路径向量**协议。
:::

::: proposition AS 路径中无环 {#prop-no-loops}
若每个自治系统都拒绝 AS-PATH 中含有自己编号的通告，并且在转发一个通告时把自己的编号添加在前面，那么每个自治系统所接受的每条 AS-PATH 都由互不相同的自治系统组成。在稳定状态——每个自治系统都在使用一条路由，而该路径上下一个自治系统自己也正在使用并通告对应的路由——下发往该前缀的流量沿路由的 AS-PATH 行进，因而不会第二次经过任何自治系统。
:::

::: proof
一个通告从起源自治系统 $o$ 出发，AS-PATH 为 $(o)$。接受一个通告的自治系统 $X$ 已检查过 $X$ 不在其中，并在继续通告它时把 $X$ 加在最前面；对跳数归纳可知，每条被接受的路径都由互不相同的自治系统组成。在稳定状态下，若 $X$ 使用从 $Y$ 学到的路由 $(Y, Z, \dots, o)$，则 $Y$ 使用它自己所通告的路由 $(Z, \dots, o)$，$Z$ 使用 $(\dots, o)$，依此类推。于是从 $X$ 出发逐自治系统转发的流量按顺序经过 $Y, Z, \dots, o$：恰是该 AS-PATH，其中没有重复。（在收敛期间，通告与撤销仍在途中时，瞬时的环是可能的；随着状态稳定它们随即消失。）
:::

当一台路由器拥有到达同一前缀的多条路由时，它按一系列打破平局的规则选择其一（RFC 4271 §9.1，加上常见的厂商实践）：LOCAL-PREF 最高者优先，其次 AS-PATH 最短，其次起源类型（origin）与多出口判别值（multi-exit discriminator）最低，其次经 eBGP 而非 iBGP 学到的路由，其次按 IGP 度量 NEXT-HOP 最近的路由——即**热土豆路由**（hot-potato routing），尽早把流量交给另一个自治系统——最后是路由器标识符最小的。起决定作用的第一条规则是策略，由本自治系统的运营者设定；路径长度只用来打破平局。

### 策略：谁为谁承载流量

自治系统之间的关系大体分两种。在**客户-提供商**关系中，客户付钱给提供商，请它把自己的流量送往互联网的其他部分、并把其他部分的流量送回来。在**对等互联**关系中，两个自治系统在各自的客户之间交换流量而不付费。这些关系决定了 BGP 策略。

::: definition Gao-Rexford 策略 {#def-gao-rexford}
遵循 **Gao-Rexford** 准则的自治系统：

1. 更**偏好**从客户学到的路由，其次是从对等方学到的，最次是从提供商学到的（客户付钱；提供商必须拿到钱）。
2. 把自己学到的（从客户学到的和自己的前缀）**导出**给所有邻居；但从对等方或提供商学到的路由只导出给自己的客户。
:::

规则 2 意味着一个自治系统绝不会在自己的两个对等方或两个提供商之间免费承载流量：它只向为之付费者提供**转接**。由此得到的 AS 路径是**无谷**（valley-free）的：它们从客户上升到提供商，至多穿过一条对等链路，然后下降到客户。Gao 与 Rexford 证明了（2001 年）：若每个自治系统都遵守这些规则，且客户-提供商关系中没有环，BGP 必定收敛到一组稳定的路由；没有这些限制，各自治系统的策略可能相互作用，使 BGP 永远振荡——路由的稳定性取决于经济关系。

::: example 导出一条路由 {#ex-export}
AS 64500 是客户 AS 64510 和 AS 64511 的提供商，并与另一个提供商 AS 64501 对等互联；AS 64496 是 64500 和 64501 共同的提供商。客户 64510 通告前缀 `192.0.2.0/24`。64500 会把这个前缀告诉它的哪些邻居？64501 的网络经由什么路径到达该前缀？（这些自治系统号取自为文档保留的号段，RFC 5398。）
::: solution
该路由来自一个客户，所以 64500 把它导出给所有人：它的另一个客户 64511、它的对等方 64501 和它的提供商 64496，每份都带 AS-PATH $(64500, 64510)$。AS 64501 从对等方 64500（路径 $(64500, 64510)$）和提供商 64496（路径 $(64496, 64500, 64510)$）两处都学到了这个前缀。按规则 1 它偏好来自对等方的路由——免费，而且更短——于是 64501 的客户发出的流量跨过对等链路到达 64500，再下行到 64510。再设 64500 还从对等方 64501 学到一条到 64501 某个客户的路由。规则 2 禁止 64500 把它导出给提供商 64496 或其他对等方：那样等于邀请 64496 把流量经 64500 送往 64501，而 64500 要为自己的提供商对这份分文不赚的流量付费。
:::
:::

### BGP 出错的时候

BGP 信任它的邻居：一个自治系统接受邻居通告的前缀，而默认情况下没有任何机制检查通告方是否有权通告它们。最长前缀匹配（[[networks/network-layer#def-forwarding]]）随后会使被错误通告的*更具体*的前缀把所有听到它的网络发出的流量都吸引过来。2008 年 2 月，一家 ISP 试图通过在内部通告该网站地址的更具体前缀、在本国境内屏蔽一个视频网站，结果这个通告泄露给了它的提供商，并由此传遍整个互联网；大约两个小时里，全世界通往该网站的大部分流量都被送到了错误的网络。这样的**前缀劫持**既有失手所为，也有蓄意为之；**路由泄露**——一个自治系统违反 Gao-Rexford 导出规则重新通告路由（常见的是一个客户把一家提供商的路由传给另一家）——可能把大量流量引进无力承载它们的网络。

防御手段分层而来。提供商依据登记机构记录“哪个客户持有哪些前缀”，对客户可通告的内容进行**过滤**。**资源公钥基础设施**（RPKI，RFC 6480）让一个地址块的持有者发布签名的**路由源授权**（ROA），声明哪个自治系统可以起源它；执行**路由源验证**（RFC 6811）的路由器会拒绝起源自治系统与之矛盾的通告。起源验证挡不住伪造一条*终于*正确自治系统的路径的攻击者；**BGPsec**（RFC 8205）为路径上的每一跳签名，但部署寥寥；对路径合理性的更轻量检查正在标准化之中。运营这些防御手段——而不是发明新攻击——才是网络运营者的日常：路由系统的安全是一项集体事业。

::: warning 最短路径不一定是 BGP 路径
人们很自然地假设互联网流量走最短或最快的路由。但在自治系统之间，流量走的是*策略*：LOCAL-PREF 压倒路径长度，一个自治系统可以拒绝承载转接流量，而热土豆路由在最近的出口处把流量交出去、而不是最好的出口处。路径常常是不对称的——从 A 到 B 的路由不同于回程的路由——而一条按 AS 跳数最短的路径在公里数上可能长得多。只有在一个自治系统内部——运行 IGP 的地方——分组才沿最小代价路径行进，而且即便如此，代价也不过是管理员所选的数值。
:::

::: application 任播
由于 BGP 允许多个自治系统或多个站点通告同一个前缀，一个服务可以用同一个地址部署在许多地点：每个客户端的流量都会去往其所在网络的 BGP 选择认为最佳的那个地点，通常是邻近的一个。这种**任播**（anycast）技术正是 DNS 根服务器（[[networks/application-layer#def-dns]]）和许多内容分发网络能够以少数几个地址、数百个站点服务全世界的方式，也是针对它们的拒绝服务洪泛会被摊散到所有站点的原因。
:::

::: history
迪杰斯特拉（Dijkstra）于 1959 年发表了最短路径算法，贝尔曼-福特递推式则来自贝尔曼（Richard Bellman，1958）与小福特（Lester Ford Jr.，1956）。ARPANET 的第一个路由算法（1969 年）是一个分布式的贝尔曼-福特算法，每三分之二秒交换一次距离向量；其收敛缓慢与路由环促使麦克奎兰（John McQuillan）、里希尔（Ira Richer）与罗森（Eric Rosen）在 1979–80 年用一个链路状态算法取而代之：泛洪实测的时延，并在每个结点运行迪杰斯特拉算法——它就是 OSPF 的前身（RFC 1131，1989 年；OSPFv2 见 RFC 2328，由莫伊（John Moy）完成，1998 年）。1984 年的外部网关协议假设互联网呈树形；当这一点不再成立时，卢希德（Kirk Lougheed）与雷克特（Yakov Rekhter）在 1989 年的一次 IETF 会议上著名地（据称是在餐巾纸上）勾勒出了 BGP，并于同年发表为 RFC 1105。支持 CIDR 的 BGP-4 于 1995 年跟进（RFC 1771，2006 年修订为 RFC 4271）。高立新（Lixin Gao）与雷克斯福德（Jennifer Rexford）关于策略与稳定性的分析发表于 2001 年。
:::

## 后续内容

一般意义下的最短路径算法及其完整证明——负代价、全源算法、优先队列——都在 [[algorithms/shortest-paths]]。下一章 [[networks/link-layer]] 下降到路由之下，研究各条链路和交换式局域网，在那里由另一种协议（生成树协议）来防止环路。共识以及“尽管有故障仍要对状态达成一致”的问题（路由收敛是它的表亲）属于 [[distributed-systems]]；路由安全在 [[security]] 中进一步研究。

::: summary
- 路由选择在路由器与链路构成的图上计算最小代价路径；转发表记录下一跳。最小代价满足**贝尔曼-福特方程** [[#eq-bellman-ford]]。
- **链路状态**协议把每台路由器的链路泛洪给所有路由器，并在每台路由器中运行**迪杰斯特拉算法**（[[#alg-dijkstra]]，由 [[#thm-dijkstra]] 证明正确）：收敛快，每次变更 $O(m)$ 个报文。
- **距离向量**协议只与邻居交换距离向量（[[#alg-dv]]）；同步轮次在第 $k$ 轮后算得至多 $k$ 条链路的路径的最小代价（[[#thm-dv]]）。
- 故障之后，距离向量可能**计数到无穷**（[[#ex-count-to-infinity]]）；毒性反转只能修好两台路由器之间的环。
- 自治系统内部使用 **OSPF** 或 IS-IS（链路状态），以区域应对规模。自治系统之间，**BGP** 是一个**路径向量**协议，其 AS-PATH 可防止环路（[[#prop-no-loops]]），选路以**策略**优先。
- **Gao-Rexford** 策略——偏好客户、对等方、提供商这一顺序的路由；对等方和提供商的路由只导出给客户——产生无谷路径并保证稳定（[[#def-gao-rexford]]）。
- BGP 信任通告；前缀劫持与路由泄露以过滤、RPKI 和路由源验证来对抗。
:::

::: exercise 一次贝尔曼-福特更新 {level=1 check="6"}
路由器 X 的邻居 P、Q、R 的链路代价为 $c(X, P) = 1$、$c(X, Q) = 4$、$c(X, R) = 2$。它们最新的向量给出到目的地 Z 的距离 $D_P(Z) = 7$、$D_Q(Z) = 2$、$D_R(Z) = 5$。$D_X(Z)$ 是多少？哪个邻居是下一跳？（输入 $D_X(Z)$。）
::: solution
$\min(1 + 7, 4 + 2, 2 + 5) = \min(8, 6, 7) = 6$，经由 Q。

::: exercise BGP 选路 {level=1}
一台边界路由器有三条到达 `198.51.100.0/24` 的路由：路由 1，LOCAL-PREF 100，AS-PATH (64510, 64520)；路由 2，LOCAL-PREF 200，AS-PATH (64511, 64530, 64540, 64520)；路由 3，LOCAL-PREF 200，AS-PATH (64512, 64520)。它选择哪一条？该自治系统的运营者为什么会这样设置偏好值？
::: solution
LOCAL-PREF 最高者最先胜出，于是尽管路径很短，路由 1 仍被淘汰。在路由 2 和 3 之间（都是 200），AS-PATH 较短者胜出：路由 3，含两个自治系统。路由 1 多半是从提供商（要花钱）学来的，而路由 2 和 3 是从客户或对等方学来的，这正是 Gao-Rexford 策略所偏好的；该自治系统用 LOCAL-PREF 来表达这一点。
:::
:::

把 [[#ex-count-to-infinity]] 中的“无穷大”从 16 改为 32 重做一遍（在 `dv.py` 中修改 `INF`，并把 `rounds=30` 提高到 50）。多少轮后两台路由器都报告 C 不可达？解释这个规律。（输入轮数。）
::: solution
估计值每两轮上涨 2，在 A 与 B 之间交替：第 $r$ 轮后 $D_B(C) = 2\lfloor (r+1)/2 \rfloor + 1$，$D_A(C) = 2\lfloor r/2 \rfloor + 2$（图中的两条台阶曲线），并以无穷大取顶。无穷大为 $32$ 时，$D_A$ 在第 $30$ 轮达到 $32$，$D_B$ 在第 $29$、$30$ 轮后为 $31$、在第 $31$ 轮达到 $32$；把 `INF = 32` 和更高的轮数上限代入运行 `dv.py`，报告 `rounds: 31`。一般地，无穷大为 $I$ 时朴素协议在这里需要 $I - 1$ 轮：收敛时间随所选无穷大值线性增长，这就是 RIP 选一个小数值、并被限制在至多 15 跳的网络中使用的原因。
:::
:::

::: exercise 泛洪的代价 {level=2 check="13"}
一个网络有 $n = 6$ 台路由器和 $m = 9$ 条链路（[[#ex-dijkstra]] 的网络）。一台路由器泛洪一个新的 LSA。每台路由器第一次收到这个 LSA 时，就在除它到达所用链路之外的所有链路上转发它，之后收到的副本一律丢弃；源发者在自己的所有链路上发送它。一共发生多少次 LSA 传输？（输入数目。）
::: solution
每台路由器恰好在自己的每条链路上传输这个 LSA 一次，只是除源发者外每台路由器都跳过 LSA 最初到达的那条链路。对所有路由器求和，总数为 $\sum_x \deg(x) - (n - 1) = 2m - (n - 1) = 18 - 5 = 13$，与发送时序无关（若两个副本在某条链路上交错穿过，对各自的发送方仍各计一次）。因此一次泛洪花费 $\Theta(m)$ 次传输，而每台路由器会在自己的每条链路上收到一个副本，OSPF 的可靠泛洪正把它用作隐式确认。
:::
:::

::: exercise 无谷路径 {level=2}
四个自治系统：P1 与 P2 对等互联；C1 是 P1 的客户；C2 是 P2 的客户；C3 同时是 P1 和 P2 的客户。在 Gao-Rexford 策略下，(a) C1 经由什么路径到达 C2？(b) P1 会承载从 P2 的网络发往 C3 的流量吗？(c) 从 C1 出发的流量会经过 C3 到达 C2 吗（C1 → P1 → C3 → P2 → C2）？为什么？
::: solution
(a) C2 把自己的前缀通告给提供商 P2，P2 把这条客户路由导出给所有人，包括它的对等方 P1；P1 再把它导出给自己的客户，包括 C1。路径：C1 → P1 → P2 → C2（上行，跨过对等链路，下行）。(b) 会：C3 是 P1 的客户，所以 P1 把 C3 的路由导出给对等方 P2，并承载从 P2 到 C3 的流量——C3 为此付钱给 P1。（P2 自己也有到 C3 的直接客户路由，它会更偏好那条。）(c) 不会。C3 就得把它从提供商 P2 学到的、到 C2 的路由导出给另一个提供商 P1，而规则 2 禁止这样做：客户不在自己的两个提供商之间提供转接，那样它得向两边付钱。这样的路径会包含一个“谷”（下行到 C3，再上行）。
:::
:::

::: exercise 三角形中的毒性反转 {#exr-triangle level=3}
路由器 A、B、C 连成一个三角形（三条链路代价均为 1），C 另有一条代价为 1 的链路连到 D。收敛状态下 $D_A(D) = D_B(D) = 2$（都经由 C），$D_C(D) = 1$。链路 C–D 失效。在毒性反转和同步轮次下（无穷大 16），追踪三台路由器到 D 的距离，并解释为什么毒性反转在这里不能阻止计数到无穷。
::: solution
改造 `dv.py`（目的地改为 D，链路为 A–B、A–C、B–C）运行，逐轮得到 $(D_A, D_B, D_C)$：

```text
(2, 2, 1) → (2, 2, 16) → (3, 3, 16) → (16, 16, 4) → (16, 5, 16) → (6, 16, 16) → (16, 16, 7) → … → (16, 16, 16)
```

15 轮后全部变成无穷大。第 1 轮中，C 从 A 和 B 听到被毒性反转的距离（两者都经由 C 路由），正确地设为 $16$。但 A 同时听到 B 的距离 $2$——B 经由 C 而不是经由 A 路由，所以 B 不会对自己发往 A 的通告施毒——于是第 2 轮 A 经由 B 设成 $1 + 2 = 3$，B 也对称地经由 A 设成 $3$。它们的路由从此指向对方，于是第 3 轮他们彼此施毒；但 C 已听到他们第 2 轮的 $3$，这些值对 C 并未施毒（两者都不再经由 C 路由），C 于是设成 $1 + 3 = 4$。过时的信息绕着三角形逐台路由器循环，每过一步增加 1。毒性反转只能阻止一台路由器相信一条径直绕回自己的路由；它看不见三个以上路由器的环，因为距离向量不暴露路径。像 BGP 这样通告整条路径的路径向量协议则能直接发现这类环（[[#prop-no-loops]]）。
:::
:::

::: exercise 带负代价的贝尔曼-福特 {level=3}
[[#thm-dv]] 假设链路代价为正。(a) 证明在哪里用到了为正？(b) 证明若某条有向链路的代价为负、但不存在总代价为负的环，同步算法仍在 $n - 1$ 轮后算得最小代价。(c) 若存在负代价环会发生什么？为什么路由协议绝不允许它？
::: solution
(a) 两处：对 $x = y$，要保持 $D_y(y) = 0$，需要每条经过 $y$ 的环代价非负；而 $n - 1$ 条链路上界的证明用到最小代价路径绝不重复经过顶点这一事实。(b) 没有负环时，从一条行走中删去一个环绝不会增大其代价，所以最小代价行走可取为简单路径，至多含 $n - 1$ 条链路；且 $D_y(y) = 0$ 仍然正确（每个环的代价至少为 $0$）。[[#thm-dv]] 的归纳——第 $k$ 轮后，$D_x(y)$ 是至多 $k$ 条链路的行走中的最小代价——根本不曾用到为正的条件，所以 $n - 1$ 轮后这些值就是最小代价。(c) 若存在一条从 $x$ 可达、又能到达 $y$ 的负环，绕着它走的越绕越便宜，最小代价不存在，估计值将永远下降（第 $n$ 轮仍有变化，这正是贝尔曼-福特算法检测这类环的办法：[[algorithms/shortest-paths]]）。在网络中负代价没有物理意义，而允许它的路由协议会让分组绕着这个环打转；协议要求代价为正，这同时还保证了每个目的地的下一跳图是一棵树。
:::
