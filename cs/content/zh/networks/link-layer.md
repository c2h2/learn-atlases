当你的笔记本电脑向一台 Web 服务器发送分组时，IP 决定这个分组必须先发往你网络边缘的那台路由器。但路由器并不是靠 IP 地址到达的——分组必须被装进一个以路由器的网络接口卡为目的地址的**帧**里，用的是一种完全不同种类的首部地址，在别的设备也在发送的共享无线信道或以太网电缆上传输，并配上足够强的编码，以防媒体偶尔引入的比特差错，再经过一台或几台从未被告知任何人在哪里的**交换机**。这些任务中的每一件都属于**数据链路层**，即把数据报送过一条链路的层。

一个数据报从源到目的要穿过许多条链路——先是 Wi-Fi，然后以太网，再是路由器之间的光纤，在数据中心里又是以太网——而每一条都可能使用不同的链路层协议。本章研究它们共同的问题。我们先看**差错检测**：奇偶校验、决定任何编码能力的汉明距离（Hamming distance），以及以太网和 Wi-Fi 使用的循环冗余检验。然后是**多路访问**：多个发送方如何共享一个信道，从时隙到 ALOHA（以其著名的 $1/e$ 效率）再到以太网的 CSMA/CD。接着是**以太网**及其 48 位地址、把 IP 地址映射到它们的 **ARP**、会自己学习主机位置的**交换机**、使交换式网络无环的生成树协议，以及虚拟局域网。拥有自己接入协议的无线链路在 [[networks/wireless-mobile]] 中讲述。

## 数据链路层的服务

链路层协议主要实现在**网络接口**——网络适配器，或称“网卡”——的硬件和固件里，其余部分在操作系统的驱动程序里。它的服务有：

- **成帧**：把每个数据报封装进带首部（地址、指明载荷属于哪个网络层协议的类型字段）和尾部（差错检测码）的**帧**中，并标示帧的起止位置。
- **链路接入**：**媒体接入控制**（MAC）协议决定一个结点何时可以发送，这在多个结点共享一个广播信道时至关重要。
- **差错检测**，在某些链路上还有通过重传实现的**纠错**或**可靠交付**——无线链路因为误码率高而在本地重传（[[networks/network-principles#prop-e2e]] 说明了为什么这是一种性能措施，而不是端到端校验的替代品）。
- 相邻结点之间的**流量控制**，某些链路上才有。

链路要么是**点对点**的——两端各只有一个发送方，如两台路由器之间的光纤、或主机与交换机之间的电缆——要么是**广播**式的，许多结点共享一个信道、每个结点都能听到每次发送，如 Wi-Fi、电缆调制解调器网络或最初的以太网。广播链路需要多路访问协议。

## 差错检测与纠错

噪声、干扰和衰减会在传输途中翻转比特。发送方在数据 $D$ 上添加**差错检测与纠错**位（EDC）；接收方把 $D'$ 和 $\text{EDC}'$——两者都可能已被改动——相互核对。没有哪种编码能抓住一切差错；目标是让未检测出的差错在低成本下稀到几乎不可能发生。

最简单的编码是一个**奇偶校验位**：追加一个比特，使 1 的个数为偶数。任意奇数个比特差错都能检测出来，任意偶数个则被漏掉——而差错通常以**突发**的形式到来，这笔押注很不划算。**二维奇偶校验**把数据排成网格，给每一行每一列都加上一个校验位；于是一个被翻转的比特恰好在一行和一列中显现，从而被定位，可以**纠正**而无需重传。

::: definition 汉明距离 {#def-hamming}
两个等长比特串之间的**汉明距离** $d(u, v)$ 是它们取值不同的位置数。一个码（一组合法码字）的**最小距离**是两个不同码字之间汉明距离的最小值。
:::

::: theorem 检测与纠错的能力 {#thm-hamming}
最小距离为 $d$ 的码能检测出至多 $d - 1$ 个比特的一切差错模式，并能通过把接收字译成最近的码字来纠正至多 $\lfloor (d-1)/2 \rfloor$ 个比特的一切差错模式。最小距离为 $d$ 的任何码在最坏情况下都做不到更好。
:::

::: proof
*检测。* 一个 $t \le d - 1$ 比特的差错把码字 $c$ 变成距 $c$ 为 $t$ 的一个字，$1 \le t < d$，它不可能是另一个码字；于是接收方看到的是一个非法字。*纠错。* 设 $t \le \lfloor (d-1)/2 \rfloor$，故 $2t < d$，并设发送的是 $c$、接收的是 $r$ 且 $d(c, r) = t$。对任何别的码字 $c'$，三角不等式给出 $d(c', r) \ge d(c', c) - d(c, r) \ge d - t > t$。所以 $c$ 是距 $r$ 最近的唯一码字。*最优性。* 取距离为 $d$ 的码字 $c, c'$。翻转两者不同的那 $d$ 个位置就把 $c$ 变成了 $c'$，这是一个 $d$ 比特、无法检测的差错。而且存在一个字 $r$，使 $d(c, r) = \lceil d/2 \rceil$ 且 $d(c', r) = \lfloor d/2 \rfloor$（翻转那些位置的一半）；$c$ 上一个 $\lceil d/2 \rceil$ 比特的差错产生 $r$，而 $r$ 距 $c'$ 至少和距 $c$ 一样近，因此无法可靠纠正。
:::

单个奇偶校验位给出最小距离 2（检测一个差错，纠正不了任何差错）。二维奇偶校验的最小距离为 4（改动一个数据位会同时改变它所在行的校验位、列的校验位和角落里的校验位，而没有更小的改动能让所有行列保持偶性）。最小距离大的纠错码用于重传代价高昂之处——深空链路、存储介质，以及 Wi-Fi 和蜂窝无线电的物理层——而大多数链路只检测差错并丢弃坏帧。

### 循环冗余检验

以太网、Wi-Fi 和大多数其他链路的差错检测码是**循环冗余检验**（CRC）。它把比特串当作系数在 $\set{0, 1}$ 中的多项式，按模 2 加减——也就是异或、不进位。

::: definition 循环冗余检验 {#def-crc}
发送方和接收方约定一个最高次项和常数项都为 1、次数为 $r$ 的**生成**多项式 $G(x)$。对读作多项式 $D(x)$ 的数据比特 $D$，发送方计算余式

$$
R(x) = x^r D(x) \bmod G(x)
$$

（次数小于 $r$，故为 $r$ 比特），然后先发送 $D$、再发送 $R$，其整体作为多项式是 $T(x) = x^r D(x) + R(x)$。因为模 2 下减法即加法，$T(x)$ 能被 $G(x)$ 整除。接收方把收到的东西除以 $G(x)$，余式为零就接受。
:::

::: example 手工计算一次 CRC {#ex-crc}
对 $D = 110101$ 用生成多项式 $G = 1011$（即 $x^3 + x + 1$，故 $r = 3$）计算 CRC，并检验一个单比特差错能被检测出来。
::: solution
追加 $r = 3$ 个零，用异或除以 $1011$，依次把生成多项式对齐到每个最高位的 1 之下：

| 步骤 | 在最高位 1 下与 $G$ 异或后的比特 |
|---|---|
| 开始 | `110101000` |
| 1 | `011001000` |
| 2 | `001111000` |
| 3 | `000100000` |
| 4 | `000001100` |
| 5 | `000000111` |

余式是最后的 3 个比特，$R = 111$，帧携带 $110101\,111$。接收方把 $110101111$ 除以 $1011$，得到余式 $000$。若翻转最后一个比特、变成 $110101110$，余式就成了 $001$：差错被抓住了。（用 Python 做同样长除法的函数给出这些余式；真正的 CRC 实现中，硬件用一个移位寄存器和几个异或门以线速完成。）
:::
:::

::: proposition CRC 能检测什么 {#prop-crc}
设 $G(x)$ 的次数为 $r$、常数项非零。差错模式 $E(x)$（被翻转比特的位置）检测不出来，当且仅当 $G(x)$ 整除 $E(x)$。于是以 $G$ 为生成多项式的 CRC：

1. 能检测一切**突发**差错——所有被翻转的比特位于连续 $r$ 位的窗口之内；
2. 若 $x + 1$ 整除 $G(x)$，能检测一切翻转奇数个比特的差错；
3. 能检测一切单比特差错（情形 1 的特例）。
:::

::: proof
接收方收到 $T(x) + E(x)$，因为 $G \mid T$，其余式为 $(T(x) + E(x)) \bmod G = E(x) \bmod G$。所以差错被漏过当且仅当 $G \mid E$。

(1) 局限于连续 $r$ 个位置之内的突发满足 $E(x) = x^i B(x)$，其中 $B(x)$ 非零、次数至多 $r - 1$ 且 $B(0) = 1$（突发的最低位被翻转）。$G$ 不能整除次数更小的 $B$。又因为 $G$ 的常数项是 1，$x$ 不整除 $G$，所以 $G$ 与 $x^i$ 没有公因子；而二元域上的多项式唯一分解，故 $G \mid x^i B$ 会推出 $G \mid B$。所以 $G \nmid E$。

(2) 若 $x + 1$ 整除 $G$ 且 $G$ 整除 $E$，则 $x + 1$ 整除 $E$，于是 $E(1) = 0$。但 $E(1)$ 就是被翻转比特的个数模 2，所以个数是偶数。因此任何奇数个比特的差错都能被检测。
:::

以太网的 CRC-32 使用 $G(x) = x^{32} + x^{26} + x^{23} + x^{22} + x^{16} + x^{12} + x^{11} + x^{10} + x^8 + x^7 + x^5 + x^4 + x^2 + x + 1$（写作 `0x04C11DB7`）。在以太网尺寸下的帧中，它能检测一切长度不超过 32 比特的突发和一切至多 3 个比特的差错，而一个随机差错模式漏检的概率约为 $2^{-32}$。实现中有两个变通：寄存器从全 1 开始（这样前导的零不至于隐形）、结果最后取反，并且按最低位先行的顺序处理比特，与以太网发送它们的顺序一致：

```python
# crc32.py：以太网与 zlib 使用的 CRC-32，逐位计算，并与 zlib 校验一致
import zlib

POLY = 0xEDB88320          # x^32 + x^26 + ... + 1（0x04C11DB7）的位序反转

def crc32(data: bytes) -> int:
    crc = 0xFFFFFFFF                         # 初始值：全 1
    for byte in data:
        crc ^= byte                          # 比特按最低位先行的顺序处理
        for _ in range(8):
            if crc & 1:
                crc = (crc >> 1) ^ POLY      # “减去”（异或）生成多项式
            else:
                crc >>= 1
    return crc ^ 0xFFFFFFFF                  # 最后取反

msg = b"The quick brown fox jumps over the lazy dog"
print(f"{crc32(msg):#010x} {zlib.crc32(msg):#010x}")
print(f"{crc32(b'123456789'):#010x}")        # 标准校验值
bad = bytearray(msg); bad[10] ^= 0b00011100  # 一个 3 比特的突发差错
print(f"{crc32(bytes(bad)):#010x}  (changed: {crc32(bytes(bad)) != crc32(msg)})")
```

```console
$ python3 crc32.py
0x414fa339 0x414fa339
0xcbf43926
0x2fab629e  (changed: True)
```

这个函数与 `zlib` 中的 C 实现一致，而 `0xcbf43926` 正是 CRC-32 对字符串 `123456789` 的标准校验值。

::: warning CRC 不是密码学哈希
CRC 是线性的：$D_1 \oplus D_2$ 的 CRC 由 $D_1$ 和 $D_2$ 的 CRC 决定，任何人都能算出任何东西的 CRC。对付随机差错它非常出色，对付对手则一无是处——对手可以改动一个帧，再用几个异或把它的 CRC 修好。有线等效保密（WEP）是第一个 Wi-Fi 安全协议（1997 年），它在加密内部用 CRC-32 做完整性校验；因为 CRC 和流密码都是线性的，攻击者可以翻转加密帧中选定的比特、并在不知道密钥的情况下改正加密后的 CRC——这是 WEP 最终被废弃的若干缺陷之一。防攻击者的完整性需要带密钥的消息认证码（[[cryptography]]）。
:::

## 多路访问协议

在 $N$ 个结点共享、速率 $R$ 的广播信道上，时间上重叠的两次发送会**碰撞**，两者都告丢失。**多路访问协议**告诉结点何时发送。理想情况：只有一个活动结点时它得到速率 $R$；$M$ 个活动结点时每个大约得到 $R/M$；协议是分布式的；而且简单。协议有三族。

**信道划分**把信道切开：**TDMA** 给每个结点一个周期重复帧中的时隙，**FDMA** 给一个频段（而用于 3G 蜂窝网络的 **CDMA** 给一个码）。它们公平、无碰撞，但即使某个结点是唯一有数据的结点，它也至多得到 $R/N$——这正是电路交换的短处（[[networks/network-principles#def-switching]]）。

**轮流**协议把发送权依次传递：主控站逐个**轮询**每个结点（蓝牙就是这么工作的），或者一个**令牌**在各结点之间环转。它们让活动结点得到多于 $R/N$，但主控站或令牌是单点故障，而且传递它要花时间。

**随机接入**协议允许结点随时以全速率 $R$ 发送，检测碰撞，并在随机延迟后重传。它们是分布式而简单的，以太网和 Wi-Fi 用的就是它们。问题在于有多少容量损失在碰撞上。

### ALOHA

::: algorithm 分槽 ALOHA {#alg-slotted-aloha}
时间被划分为长度为一个帧时间 $L/R$ 的时隙，各结点与时隙同步。

1. 有新生成的帧的结点在下一个时隙开始时发送它。
2. 若该时隙内没有其他结点发送，帧发送成功。
3. 若发生了碰撞（在时隙结束时检测到），结点在此后的每个时隙中以概率 $p$、相互独立地重传这个帧，直到成功。
:::

::: theorem 分槽 ALOHA 的效率 {#thm-aloha}
设 $N$ 个结点总有帧要发送，各结点在每个时隙中以概率 $p$ 独立发送。一个时隙成功携带一次发送的概率是 $N p (1 - p)^{N - 1}$。它在 $p = 1/N$ 处最大，最大值为 $(1 - 1/N)^{N-1}$，当 $N \to \infty$ 时递减趋于 $1/e \approx 0.368$。
:::

::: proof
一个时隙成功，当恰好一个结点发送：可以是 $N$ 个结点中的任意一个（概率 $p$），而其余 $N - 1$ 个都不发送（每个概率 $1 - p$）。于是 $f(p) = N p (1 - p)^{N-1}$。求导，

$$
f'(p) = N (1 - p)^{N-2} \bigl( (1 - p) - (N - 1)p \bigr) = N (1 - p)^{N-2} (1 - N p),
$$

在 $p < 1/N$ 时为正、$p > 1/N$ 时为负（当 $0 < p < 1$），所以最大值在 $p = 1/N$ 处，为 $f(1/N) = (1 - 1/N)^{N-1}$。把 $(1 - 1/N)^{N-1}$ 写成 $(1 - 1/N)^N / (1 - 1/N)$，并用 $(1 - 1/N)^N \to 1/e$，即得极限 $1/e$。该序列递减，因为它的对数 $(N-1)\ln(1 - 1/N)$ 关于 $N$ 递减（一道微积分习题）。
:::

所以最好情况下也只有约 37% 的时隙携带数据，37% 空着，26% 发生碰撞。**纯 ALOHA**——诺曼·阿布拉姆森（Norman Abramson）在夏威夷的 ALOHAnet 无线电网络（1971 年）的原始协议——没有时隙，表现更差：在时刻 $t_0$ 发出的帧会与任何在 $(t_0 - L/R, t_0 + L/R)$ 内开始的帧碰撞，脆弱期长一倍，最大效率减半为 $1/(2e) \approx 0.18$（[[#exr-pure-aloha]]）。

### CSMA/CD 与以太网的退避

两个简单的改进能消除大部分碰撞。**载波监听**（CSMA）：发送前先听，信道忙就等待。碰撞仍可能发生，因为信号传播需要时间：一个开始发送的结点，在 $d_\text{prop}$ 之后才能被远处的结点听到，而那个结点可能在此期间也开始发送。**碰撞检测**（CD）：一边发送一边继续监听，一旦检测到碰撞立即停发，不再浪费余下的帧时间。

::: algorithm 以太网 CSMA/CD（经典共享式以太网） {#alg-csmacd}
1. 帧就绪时，监听信道；信道忙则等待，空闲后发送。
2. 发送过程中持续监视信道。若整个帧发送完毕而未检测到别的信号，即告完成。
3. 若检测到碰撞，立即停发，并发送一个简短的**干扰**（jam）信号，让每个结点都检测到这次碰撞。
4. **二进制指数后退**：此帧第 $n$ 次连续碰撞后，从 $\set{0, 1, \dots, 2^{\min(n, 10)} - 1}$ 中均匀随机地选取 $K$，等待 $K \cdot 512$ 比特时间，然后回到步骤 1。尝试 16 次之后放弃。
:::

这种退避无须知道活动结点的数目就自动适应它：一次碰撞之后，两个碰撞结点从 $\set{0, 1}$ 中选取，以 $1/2$ 的概率再次碰撞；第 $n$ 次碰撞后，范围已扩大到 $2^n$ 个取值，少数几个碰撞结点选中同一个的概率已经很小。实际上等于把 [[#thm-aloha]] 的发送概率 $p$ 调向 $1/(\text{活动结点数目})$。

要让碰撞检测起作用，发送方在碰撞的证据传回它时自己必须仍在发送。最坏情形是与电缆最远端的一个结点相撞，那个结点恰好在第一个信号到达之前开始发送；它的信号还要再花一个 $d_\text{prop}$ 才传回来。因此**最小帧**的持续时间必须至少等于往返传播时间 $2 d_\text{prop}$。经典的 10 Mb/s 以太网把**时槽**（slot time）定为 512 比特时间，即 51.2 µs，这（算上中继器的延迟）把网络的直径限制在约 2.5 km，并给出了 64 字节的最小帧长——这个数值以太网沿用至今。

梅特卡夫（Metcalfe）与博格斯（Boggs）的一个近似分析给出：许多结点都繁忙时 CSMA/CD 的效率约为

$$
E \approx \frac{1}{1 + 5\, d_\text{prop}/d_\text{trans}},
$$

其中 $d_\text{trans}$ 是发送一个最大尺寸帧的时间。当传播时间比起帧短得多时它趋于 1，这就是 CSMA/CD 在局域网上比 ALOHA 好得多的原因：碰撞被迅速检测到，代价只是一帧中的一小部分。

::: example 经典以太网的效率 {#ex-csmacd}
一条 10 Mb/s 的共享式以太网横跨 2.5 km，传播速度 $2 \times 10^8$ m/s，承载 1500 字节的帧。估算它的效率；若同样的电缆跑 1 Gb/s，效率又是多少？
::: solution
$d_\text{prop} = 2500/(2 \times 10^8) = 12.5$ µs，$d_\text{trans} = 12000/10^7 = 1.2$ ms，于是 $d_\text{prop}/d_\text{trans} \approx 0.0104$，$E \approx 1/(1 + 0.052) \approx 0.95$。在 1 Gb/s 下，$d_\text{trans} = 12$ µs，比值约为 $1.04$，$E \approx 1/(1 + 5.2) \approx 0.16$——比 ALOHA 好不了多少。更糟的是，64 字节的帧在 1 Gb/s 下只持续 $0.512$ µs，期间信号只传出约 100 m，所以稍长一点的电缆上碰撞检测都会失效。这正是快速以太网放弃共享电缆、转向交换式全双工链路的原因之一——在这种链路上根本没有碰撞。
:::
:::

## 以太网、地址与 ARP

以太网于 1973 年在施乐帕洛阿尔托研究中心（Xerox PARC）发明，被标准化为 IEEE 802.3，速率从 10 Mb/s 一直做到 800 Gb/s（截至 2026 年），是有线局域网的主导技术。早期版本在共享同轴电缆上用 CSMA/CD；自 1990 年代末以来，几乎所有以太网都是**交换式**的：每台主机都有一条自己的全双工电缆连到交换机的一个端口，于是没有共享媒体、也没有碰撞，[[#alg-csmacd]] 的 MAC 协议只残留在标准文本里。完整保留下来的是帧格式。

::: definition MAC 地址与以太网帧 {#def-ethernet}
**MAC 地址**（链路层地址）长 48 位，写作六个十六进制字节，如 `00:1b:21:3a:4f:5c`。厂商从以头三个字节（**OUI**）标识自己的地址块中分配它们；首字节的次低位标记**本地管理**地址（出于隐私，如今许多设备在 Wi-Fi 上使用随机本地地址），最低位标记**组**（多播）地址。`ff:ff:ff:ff:ff:ff` 是**广播**地址，局域网上每个接口都会接收。

一个以太网帧由以下字段构成：

| 字段 | 字节数 | 用途 |
|---|---|---|
| 前导码与帧开始界定符 | 7 + 1 | 交替的比特，用于同步接收方的时钟；`10101011` |
| 目的地址 | 6 | |
| 源地址 | 6 | |
| 类型（EtherType） | 2 | 载荷协议：`0x0800` IPv4，`0x86DD` IPv6，`0x0806` ARP |
| 载荷 | 46–1500 | 不足 46 字节则填充 |
| 帧检验序列 | 4 | 地址、类型与载荷的 CRC-32 |
:::

网卡接收目的地址是自身地址、广播地址、或它已加入的某个多播组的帧，其余丢弃。以太网不提供确认：CRC 校验错的帧直接被丢弃，恢复（如果需要）留给更高的层。46 字节的最小载荷使从目的地址到 CRC 的最小帧为 64 字节，即时槽所要求的最小值。

既然主机有 IP 地址，为什么还要链路层地址？因为各层彼此独立：网卡的 MAC 地址出厂即定，在任何局域网都能用，不管用哪种网络层协议；而 IP 地址取决于主机接入网络的位置，由网络分配（[[networks/network-layer#def-cidr]]）。两者之间必须有东西负责翻译。

::: definition 地址解析协议 {#def-arp}
主机要给自己子网上的地址 $a$ 发送 IPv4 数据报，就需要 $a$ 的 MAC 地址。**地址解析协议**（ARP，RFC 826）维护一张由（IP 地址，MAC 地址，到期时刻）表项构成的 **ARP 表**。若表中没有 $a$，主机就向 `ff:ff:ff:ff:ff:ff` 广播一个 **ARP 请求**——“谁是 $a$？请告诉我（我的 IP 地址，我的 MAC 地址）”。地址为 $a$ 的接口以单播帧直接应答它的 MAC 地址；双方都记下这一映射，过时（几分钟）即失效，除非再次刷新。IPv6 使用等价的**邻居发现**协议（RFC 4861），把 ICMPv6 报文发到多播地址而不是广播。
:::

::: example 向另一个子网发送 {#ex-arp}
主机 A（`192.0.2.10/24`，MAC `02:00:00:00:00:0a`）向另一个子网上的服务器 S（`198.51.100.7`）发送一个数据报。A 的默认网关是路由器 R，它在 A 的子网上的接口是 `192.0.2.1`，MAC 为 `02:00:00:00:00:01`。A 的 ARP 表为空。列出 A 发出的各个帧及其中的地址。
::: solution
1. A 把 `198.51.100.7` 与自己的前缀 `192.0.2.0/24` 比较：不是本地地址，所以下一跳是网关 `192.0.2.1`（[[networks/network-layer#def-cidr]]）。
2. A 没有 `192.0.2.1` 的 MAC 地址，于是广播一个 ARP 请求：目的 MAC `ff:ff:ff:ff:ff:ff`，源 `02:00:00:00:00:0a`，EtherType `0x0806`，询问谁是 `192.0.2.1`。
3. R 用发往 `02:00:00:00:00:0a` 的单播 ARP 应答回复：`192.0.2.1` 在 `02:00:00:00:00:01`。A 将其缓存。
4. A 把数据报装进一个帧发送：目的 MAC `02:00:00:00:00:01`（R 的），源 `02:00:00:00:00:0a`，EtherType `0x0800`；帧里面，IP 首部的目的地址是 `198.51.100.7`（S 的），源地址是 `192.0.2.10`。

IP 目的地址自始至终是 S，但 MAC 目的地址是*下一跳* R。R 剥去帧头，在转发表中查询 S，再把同一个数据报装进面向下一链路的新帧——配上新的 MAC 地址。A 从未、也无须知道 S 的 MAC 地址。
:::
:::

ARP 没有认证：局域网上的任何主机都可以发送 ARP 应答、声称自己拥有任何 IP 地址，别的机器就会更新自己的表。攻击者由此可以把受害发往网关的流量改道到自己身上——**ARP 欺骗**——进而读取或篡改它。防御手段包括管理型交换机上的**动态 ARP 检测**（丢弃与交换机所见 DHCP 分配地址不符的 ARP 应答）；为关键主机配置静态 ARP 表项；以及最根本的，端到端加密（TLS），它使被截获的流量毫无价值。还是从前那个教训：为彼此协作的网络设计的协议需要分层地补上防御，而两端的加密能防范其间任何地方的弱点。

## 交换机

**交换机**连接许多条以太网链路，只在链路层查看帧头并在它们之间转发帧。它是**透明**的：主机把帧的地址写给彼此、而不是写给交换机，也感觉不到它的存在。它还是**自学习**的：无须配置就能建起自己的转发表。

::: algorithm 自学习交换机 {#alg-switch}
交换机的表有（MAC 地址，端口，时间）表项。当一个帧从端口 $i$ 到达，源为 $s$、目的为 $t$ 时：

1. **学习**：记录（或刷新）表项（$s$，$i$，当前时刻）。
2. **转发**：若 $t$ 在表中、位于端口 $j$：若 $j = i$，丢弃该帧（**过滤**：源和目的在同一网段上）；否则只在端口 $j$ 上发送它。若 $t$ 不在表中，或是广播地址，就把帧发送到除 $i$ 以外的所有端口（**泛洪**）。
3. 删除比**老化时间**（通常 300 s）更旧的表项，使表能跟着主机迁移。
:::

::: example 交换机在学习 {#ex-switch}
一台交换机有端口 1–4，主机 A 在端口 1，B 在端口 2，C 在端口 3，D 在端口 4，表为空。帧按以下顺序发送：A → D、D → A、B → A、C → B、A → C。对每个帧，说出交换机把它发到哪些端口、学到了什么。
::: solution
| 帧 | 学到 | 查表结果 | 发往端口 |
|---|---|---|---|
| A → D | A 在端口 1 | D 未知 | 2, 3, 4（泛洪） |
| D → A | D 在端口 4 | A 在端口 1 | 1 |
| B → A | B 在端口 2 | A 在端口 1 | 1 |
| C → B | C 在端口 3 | B 在端口 2 | 2 |
| A → C | （A 被刷新） | C 在端口 3 | 3 |

只有第一个帧被泛洪；每台主机发过一个帧之后，交换机就知道它在哪里了。B 和 C 都收到了那个发给 D 的第一个帧的副本，并在各自的网卡处把它丢弃了。
:::
:::

交换机自身也有软肋：它的表有限。攻击者用几百万个凭空捏造的源地址产生的帧冲击交换机，就能填满表；此后凡是目的未知——也就是被赶出表的——的帧都被泛洪到所有端口，攻击者在这些端口上就能看到它们。**端口安全**特性限制每个端口可学习的地址数目，从而防住这种攻击。

### 环路与生成树

为了可靠性，局域网常常在交换机之间布上冗余链路。但环路对自学习交换机是灾难性的：一个广播帧会绕着环路永远泛洪下去——以太网没有 TTL——并且环路里每个多于两个端口的交换机都会使它倍增，直到链路饱和（**广播风暴**）。

**生成树协议**（STP，IEEE 802.1D；今天通常用其收敛更快的后继 RSTP，802.1w）禁用足够多的端口，使活动的拓扑成为一棵树。交换机交换称为**网桥协议数据单元**的消息，并且（1）选举标识符最小（一个可配置的优先级加上其 MAC 地址）的交换机为**根**；（2）其余每台交换机计算自己到根的最小代价路径——一次类似距离向量路由的分布式最短路径计算（[[networks/routing#alg-dv]]）——并把该路径上的端口保留为**根端口**；（3）在每个局域网段上，由到根路径最便宜的交换机为该网段转发（其**指定端口**）；其余每个端口对数据帧**阻塞**。活动链路构成一棵覆盖所有交换机的树，于是每个帧恰好有一条路径；若某条链路失效，交换机重新计算树并按需解除阻塞。1985 年在数字设备公司设计了该算法的珀尔曼（Perlman）用一首诗《Algorhyme》总结过它：“我想我永远也不会看见 / 一幅比树更可爱的图。”

### 交换机、路由器与虚拟局域网

交换机和路由器都转发分组，只是层不同。交换机即插即用、速度快，但每台主机都要学习其他所有主机的 MAC 地址，广播流量（ARP、DHCP）会到达每台主机，所以单个交换式局域网扩展到几千台主机就到头了；而且生成树只用到链路中的一棵树。路由器需要配置（地址、路由协议），但它们把广播限制在本地，通过路由用满所有链路，并能扩展到整个互联网。因此大型网络把两者结合：中等规模的交换式局域网，用路由器互连。

在交换式网络内部，**虚拟局域网**（VLAN，IEEE 802.1Q）把一个物理网络分成若干逻辑网络：每个交换机端口被划入一个 VLAN，帧只在本 VLAN 内泛洪，VLAN 之间的流量必须经过路由器，就好像它们是彼此独立的局域网。交换机之间的链路（**干道**，trunk）承载多个 VLAN 的帧，每个帧带上一个 4 字节的 **802.1Q 标记**，其中含 12 位的 VLAN 标识符（因此至多 4,094 个 VLAN；0 和 4095 为保留值）和一个 3 位的优先级。VLAN 让一个组织无须重新布线就能隔开部门、访客与设备，并把广播域保持在较小的规模。

数据中心把这一切推向极致：数万台服务器经由多层交换机和路由器按 **Clos** 拓扑连接——一棵多根树，任意两个机架之间有许多条等价代价的路径——用路由选择（数据中心内部常用 BGP）和等价多路径取代生成树，于是每条链路都在承载流量。

::: quiz
关于交换机的下列说法哪些正确？
- [x] 目的 MAC 地址不在表中的帧，交换机会泛洪它。
- [ ] 交换机在转发一个帧之前，会把它的源 MAC 地址替换成自己的。
- [x] 没有生成树协议，一个交换机环路会让广播帧无限循环。
- [ ] 主机必须配置它所连接的交换机的地址。
::: solution
交换机会泛洪未知目的地（[[#alg-switch]]），并且原样转发帧——它是透明的，这也正是主机无须为它作任何配置的原因。（*路由器*倒是会重写链路层地址：[[#ex-arp]]。）以太网帧没有跳数限制，所以没有生成树的环路会把广播反复转发下去，直到网络饱和。
:::
:::

::: history
梅特卡夫（Robert Metcalfe）与博格斯（David Boggs）1973 年在施乐帕洛阿尔托研究中心建成了第一个以太网，在一条同轴电缆上以 2.94 Mb/s 运行，其灵感来自阿布拉姆森（Norman Abramson）的 ALOHAnet——一个自 1971 年起把夏威夷大学的各个岛屿连起来的分组无线电网络——并在《以太网：用于局域计算机网络的分布式分组交换》（*“Ethernet: distributed packet switching for local computer networks”*，《ACM 通讯》，1976 年）中作了阐述。数字、英特尔与施乐 1980 年发表了 10 Mb/s 规范，1983 年成为 IEEE 802.3。罗伯茨（Lawrence Roberts）1972 年提出了分槽 ALOHA，使 ALOHA 的效率翻倍。彼得森（W. Wesley Peterson）1961 年提出了用于差错检测的循环码；汉明（Richard Hamming）早在 1950 年就发表了他的距离和第一批单纠错码。珀尔曼（Radia Perlman）1985 年设计了生成树算法，而交换式以太网在 1990 年代取代了共享电缆。
:::

## 后续内容

无线链路继承本章的许多思想——随机接入、链路层重传、MAC 地址——但用碰撞避免取代碰撞检测，理由在 [[networks/wireless-mobile]] 中说明。纠错码在编码理论中展开，其代数基础见 [Maths Atlas](/learn/maths/)；网络适配器的硬件和移位寄存器 CRC 属于 [Electrical Engineering Atlas](/learn/ee/)。链路层的网络安全——802.1X 端口认证、Wi-Fi 加密——是 [[security]] 的一部分。

::: summary
- 数据链路层把帧送过一条链路：成帧、媒体接入、差错检测，有时还有可靠交付；它主要实现在网卡里。
- 最小**汉明距离**为 $d$ 的码能检测 $d - 1$ 个差错、纠正 $\lfloor (d-1)/2 \rfloor$ 个（[[#thm-hamming]]）。**CRC** 按生成多项式模 2 做除法（[[#def-crc]]），能抓住一切至多 $r$ 位的突发，若 $x + 1 \mid G$ 还能抓住一切奇数个比特的差错（[[#prop-crc]]）；它们防不住攻击者。
- 多路访问：信道划分、轮流，或**随机接入**。分槽 ALOHA 的效率至多 $(1 - 1/N)^{N-1} \to 1/e$（[[#thm-aloha]]）；纯 ALOHA 为 $1/(2e)$。
- 带**二进制指数后退**的 **CSMA/CD**（[[#alg-csmacd]]）在传播时间比起帧短得多时使共享式以太网高效；64 字节的最小帧长来自碰撞检测时槽。
- **以太网**帧携带 48 位 MAC 地址、一个类型字段和一个 CRC-32（[[#def-ethernet]]）；**ARP** 在子网上把 IP 地址映射到 MAC 地址（[[#def-arp]]），需要防范欺骗。
- **自学习交换机**用源地址建表，对未知目的地泛洪（[[#alg-switch]]）；**生成树协议**消除环路；**VLAN** 把一个交换式网络划分为若干广播域。
:::

## 习题

::: exercise 一个码的能力 {level=1 check="3"}
一个码的最小汉明距离为 4。它能总是检测出多少个比特差错？能总是纠正多少个？（输入它能检测的数目。）
::: solution
由 [[#thm-hamming]]，它能检测至多 $d - 1 = 3$ 个差错，纠正至多 $\lfloor 3/2 \rfloor = 1$ 个。因此它可以用来纠正单个差错，同时仍能检测（但纠不了）两个差错——即“SECDED”，ECC 内存采用的方案。
:::
:::

::: exercise 一个 CRC 余式 {level=1 check="3"}
对数据 $D = 101110$、生成多项式 $G = 1001$ 计算 CRC 余式 $R$。（$R$ 以十进制数输入。）
::: solution
追加三个零：$101110000$。在每个最高位的 1 之下异或 $1001$：$101110000 \to 001010000 \to 000011000 \to 000001010 \to 000000011$。所以 $R = 011$，即 $3$。发送的比特是 $101110\,011$，把它除以 $1001$ 余式为 $0$。
:::
:::

::: exercise 以太网的最小帧 {level=1 check="64"}
经典的 10 Mb/s 以太网要求每个帧至少持续 512 比特时间。那是多少个字节？一个最小帧持续多少微秒？（输入字节数。）
::: solution
$512/8 = 64$ 字节，持续 $512/10^7$ s $= 51.2$ µs。若帧更短，在 2.5 km 网络最远端结点的碰撞消息传回之前它就可能已经发完，发送方会误以为自己成功了。
:::
:::

::: exercise 十个结点的分槽 ALOHA {level=2 check="0.9^9"}
十个结点总有帧要经由分槽 ALOHA 信道发送。多大的发送概率使效率最大？最大效率是多少？（输入效率。）
::: solution
由 [[#thm-aloha]]，$p = 1/N = 0.1$，效率为 $(1 - 1/10)^{9} = 0.9^9 \approx 0.387$——略高于极限值 $1/e \approx 0.368$。
:::
:::

::: exercise 碰撞之后等待多久 {level=2 check="179.2"}
在 10 Mb/s 以太网上，一个帧刚刚经历了第三次碰撞。结点再次监听信道之前的期望退避时间是多少？（时间以微秒输入。）
::: solution
第三次碰撞后 $K$ 均匀取自 $\set{0, \dots, 2^3 - 1} = \set{0, \dots, 7}$，均值为 $3.5$。每个单位是 $512$ 比特时间 $= 51.2$ µs，所以期望等待为 $3.5 \times 51.2 = 179.2$ µs。第十次碰撞后，范围不再增长，停在 $\set{0, \dots, 1023}$，平均等待约 $26$ ms。
:::

::: exercise 交换机接一个集线器 {level=2}
在 [[#ex-switch]] 的情形中，假设主机 A 和 E 都经由一个老式集线器（它把收到的每个帧转发到自己的所有端口）接在端口 1 上。从空表出发，帧依次发送：A → E、E → A、A → B。对每个帧，说出交换机会怎么做，以及为什么丢弃那个帧是正确的。
::: solution
A → E：交换机在端口 1 学到 A；E 未知，于是在端口 2–4 上泛洪。（E 也已经通过集线器直接收到了这个帧。）E → A：它在端口 1 学到 E；A 在端口 1，正是这个帧到达的端口，于是交换机**过滤**（丢弃）它——A 已经通过集线器收到了，再往别处发送只是浪费带宽。A → B：A 在端口 1 被刷新；B 未知，泛洪到 2–4。过滤规则正是让交换机既能连接共享网段、又不必转发网段内部流量的机制。
:::

::: exercise 纯 ALOHA {#exr-pure-aloha level=3}
在纯（不分槽的）ALOHA 中，$N$ 个结点各有帧待发，且每个结点在任意一个帧时间长度的区间内以概率 $p$ 相互独立地开始一次发送（一种离散近似）。(a) 论证：在 $t_0$ 开始的帧，当且仅当没有其他结点在 $(t_0 - L/R, t_0 + L/R)$ 内开始时成功，且效率为 $N p (1 - p)^{2(N-1)}$。(b) 证明它在 $p = 1/(2N - 1)$ 处最大，且最大值趋于 $1/(2e)$。(c) 对 $N = 10$ 求值。
::: solution
(a) 一个帧占据 $[t_0, t_0 + L/R]$。另一个帧若在 $(t_0 - L/R, t_0 + L/R)$ 内开始就会与它重叠：在 $t_0$ 之前开始的，若到 $t_0$ 还没发完；在 $t_0$ 之后开始的，若在我们帧结束之前开始。那个窗口有两个帧时间长，所以每个其他结点在其中保持静默的概率是 $(1-p)^2$，于是效率为 $Np(1-p)^{2(N-1)}$。

(b) 设 $f(p) = Np(1-p)^{2N-2}$。则 $f'(p) = N(1-p)^{2N-3}\bigl((1-p) - (2N-2)p\bigr) = N(1-p)^{2N-3}(1 - (2N-1)p)$，在 $p^* = 1/(2N-1)$ 以下为正、以上为负，所以 $p^*$ 是最大值点。在该点，$f(p^*) = \tfrac{N}{2N-1}\left(1 - \tfrac{1}{2N-1}\right)^{2N-2}$。当 $N \to \infty$ 时，$\tfrac{N}{2N-1} \to \tfrac12$ 且 $\left(1 - \tfrac{1}{2N-1}\right)^{2N-2} \to e^{-1}$，所以最大值趋于 $1/(2e) \approx 0.184$。

(c) $N = 10$：$p^* = 1/19$，$f(p^*) = \tfrac{10}{19}\left(\tfrac{18}{19}\right)^{18} \approx 0.199$——大约是同样 $N$ 下分槽 ALOHA 的值 $0.387$ 的一半，如上图所示。
:::

::: exercise 查表法 CRC-32 {level=3}
上面的逐位 `crc32` 每字节要做八步。真正的软件预先算出一张 256 项的表，使每字节只需一次查表。(a) 解释为什么处理一个字节的效果只依赖于寄存器低 8 位与该字节异或的结果，再加上对其余位的移位。(b) 实现查表版本，在随机输入上与 `zlib.crc32` 核对一致，并比较运行时间。
::: solution
(a) 在逐位循环中，`crc ^= byte` 之后的八步中，每一步右移一位，是否异或 `POLY` 只取决于当前最低位。八步下来，决定这些异或的正是 `crc ^ byte` 的低八位（每次异或 `POLY` 都可能改变稍后要检测的位，但改变只是这同八个位的函数）。高 24 位只是右移 8 位，再与一个由低八位决定的 `POLY` 移位组合相异或。所以八步算出的就是 `(crc >> 8) ^ TABLE[(crc ^ byte) & 0xFF]`，其中 `TABLE[i]` 是对 `i` 单独做这八步的结果（异或的线性性）。

(b)
```python
import os, time, zlib

POLY = 0xEDB88320

def make_table():
    table = []
    for i in range(256):
        c = i
        for _ in range(8):
            c = (c >> 1) ^ POLY if c & 1 else c >> 1
        table.append(c)
    return table

TABLE = make_table()

def crc32_table(data):
    crc = 0xFFFFFFFF
    for byte in data:
        crc = (crc >> 8) ^ TABLE[(crc ^ byte) & 0xFF]
    return crc ^ 0xFFFFFFFF

def crc32_bitwise(data):
    crc = 0xFFFFFFFF
    for byte in data:
        crc ^= byte
        for _ in range(8):
            crc = (crc >> 1) ^ POLY if crc & 1 else crc >> 1
    return crc ^ 0xFFFFFFFF

for n in (0, 1, 7, 1000):
    d = os.urandom(n)
    assert crc32_table(d) == crc32_bitwise(d) == zlib.crc32(d)
data = os.urandom(200_000)
for f in (crc32_bitwise, crc32_table, zlib.crc32):
    t = time.perf_counter(); f(data); print(f.__name__, f"{time.perf_counter() - t:.4f} s")
```

```console
$ python3 crctable.py
crc32_bitwise 0.1780 s
crc32_table 0.0253 s
crc32 0.0001 s
```

三者的结果全部一致。在测试机上，查表版比逐位版快约七倍，而 `zlib` 的 C 实现（使用更宽的表，并在可用时借助处理器的无进位乘法指令）又快出数百倍：实际生产中，请使用库。
