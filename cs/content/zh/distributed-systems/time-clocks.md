一位用户报告说她的账户里的钱不翼而飞。工程师收集了牵涉其中的两台服务器的日志，并按时间戳把条目排序。服务器 A 在 12:00:00.120 记下“借记 $£50$，向 B 发送转账”。服务器 B 在 12:00:00.095 记下“收到来自 A 的转账，贷记 $£50$”——比它被发送还*早*二十五毫秒。转账本身没有问题；只是 B 的时钟比 A 的慢了三十毫秒。按时间戳排序得到的是一段不可能发生过的事件史，任何据此推理的人——正在调试的工程师，或是在两个更新之间判断谁更新的程序——都会得出错误的结论。

每台计算机都有时钟，但没有两台时钟能完全一致，而在异步系统中，再多的消息交换也无法让它们完全一致。本章要问的是：在分布式系统中，关于时间与次序我们*能够*知道什么。我们先来看物理时钟如何漂移，以及 NTP 这样的协议如何同步它们并给出可证明的误差界限。然后我们放弃物理时间，追随兰波特（Lamport）的洞见：通常重要的不是事件*何时*发生，而是哪些事件可能**影响**过哪些事件——即**先行发生**（happened-before）关系。我们构造尊重这一关系的**兰波特时钟**，以及精确刻画它的**向量时钟**，并证明这两个结论。最后，我们用这些思想以 Chandy–Lamport 算法记录运行中系统的一份**一致快照**，并看看 Google 的 TrueTime 如何带着显式的不确定度把物理时间带回来。模型沿用 [[distributed-systems/system-models]]：进程交换消息，没有共享内存，没有全局时钟。

## 物理时钟

计算机的时钟是由石英晶体振荡器驱动的计数器，由操作系统读取并换算成一天中的时刻。晶体便宜而稳定，却不精确：其频率取决于制造公差和温度，所以时钟以大约几 ppm 到几十 **ppm**（parts per million，百万分之一）的速率变快或变慢。$20$ ppm 就是一天 $1.7$ 秒。

::: definition 时钟、偏移与漂移 {#def-clock}
设 $t$ 表示真实时间。进程 $p$ 的**时钟**是函数 $C_p(t)$，即真实时间 $t$ 时 $p$ 的时钟读数。$p$ 的时钟的**偏移**（offset）是 $C_p(t) - t$，两个时钟之间的**偏斜**（skew）是 $\abs{C_p(t) - C_q(t)}$。若对所有 $t < t'$ 都有
$$
(1 - \rho)(t' - t) \;\le\; C_p(t') - C_p(t) \;\le\; (1 + \rho)(t' - t),
$$ {#eq-drift}
则称该时钟具有**漂移界限** $\rho$。
:::

两个自由运行的时钟会相互漂开，所以必须周期性地**重新同步**。多久一次？

::: proposition 重新同步之间的偏斜 {#prop-resync}
设两个时钟的漂移界限都是 $\rho$，且每过真实时间 $R$ 秒，就把两者调整到相差不超过 $\varepsilon$。那么它们的偏斜绝不超过 $\varepsilon + 2\rho R$。
:::

::: proof
考虑真实时刻 $t_0$ 的一次重新同步，其后 $\abs{C_p(t_0) - C_q(t_0)} \le \varepsilon$，再取 $t \in [t_0, t_0 + R]$。由 [[#eq-drift]]，每个时钟走过的量都在 $[(1-\rho)(t - t_0), (1+\rho)(t - t_0)]$ 内，所以两者走过之量至多相差 $2\rho(t - t_0) \le 2\rho R$。于是
$$
\abs{C_p(t) - C_q(t)} \le \abs{C_p(t_0) - C_q(t_0)} + 2\rho (t - t_0) \le \varepsilon + 2\rho R.
$$
:::

:::

### 通过网络同步

给时钟对表的显然办法，是去问一台时钟更好的服务器（追根究底是 GPS 接收机或原子钟）。困难在于答复到达需要时间，而客户端不知道需要多久。

::: theorem Cristian 界限 {#thm-cristian}
客户端在自己时钟的 $T_0$ 时刻发出请求，收到一条带着服务器时钟读数 $S$ 的答复，此时自己时钟的读数为 $T_1$。假设客户端的时钟在这段交换期间不漂移，服务器在收到请求之后、发送答复之前的某个时刻读了自己的时钟，且消息延迟非负。那么答复到达的时刻，服务器的时钟读数在 $[S, S + (T_1 - T_0)]$ 内；把客户端的时钟设为 $S + (T_1 - T_0)/2$，其误差就至多为 $(T_1 - T_0)/2$。
:::

::: proof
设 $D = T_1 - T_0$ 为客户端测得的往返时间。服务器是在请求发出之后、答复到达之前读的 $S$，所以从服务器读表到答复到达之间经过的真实时间在 $0$ 到 $D$ 之间。在这段很短的时间里，服务器时钟基本以真实时间的速率前进，所以答复到达时它的读数在 $S$ 到 $S + D$ 之间。这个区间的中点 $S + D/2$ 与区间内任一点的距离至多为 $D/2$。
:::

若单向延迟存在已知下界 $\mathit{min}$，区间就缩小为 $[S + \mathit{min}, S + D - \mathit{min}]$，误差界缩小为 $D/2 - \mathit{min}$。无论哪种情形，误差都由往返时间支配，这就是客户端要做多次测量、只信往返时间最小的那一次的原因。Flaviu Cristian 于 1989 年提出了这一概率性同步。

**网络时间协议**（Network Time Protocol，NTP，David Mills 设计，始于 1985 年；第 4 版是 RFC 5905，2010 年）用四个时间戳改进了这一思想，这四个时间戳还消去了服务器的处理时间。

::: theorem NTP 的偏移与延迟 {#thm-ntp}
客户端在 $t_1$（客户端时钟）发出请求；服务器在 $t_2$ 收到并在 $t_3$ 答复（服务器时钟）；客户端在 $t_4$（客户端时钟）收到答复。定义
$$
\theta = \frac{(t_2 - t_1) + (t_3 - t_4)}{2}, \qquad \delta = (t_4 - t_1) - (t_3 - t_2).
$$ {#eq-ntp}
假设这段交换期间两个时钟都不漂移，并设 $\theta^*$ 是服务器时钟相对客户端时钟的真实偏移（每一时刻服务器读数 $=$ 客户端读数 $+ \theta^*$）。那么 $\delta \ge 0$ 是网络总延迟，且 $\theta - \delta/2 \le \theta^* \le \theta + \delta/2$。若两个单向延迟相等，则 $\theta = \theta^*$。
:::

::: proof
设 $d_1, d_2 \ge 0$ 为请求与答复真实的单向延迟。把服务器的时间戳减去 $\theta^*$ 换算到客户端的时钟上，
$$
t_2 - \theta^* = t_1 + d_1, \qquad t_4 = t_3 - \theta^* + d_2 .
$$
于是 $\theta^* = (t_2 - t_1) - d_1$ 且 $\theta^* = (t_3 - t_4) + d_2$。把两式相加取半得 $\theta^* = \theta + (d_2 - d_1)/2$。减去 $t_4 - t_1$ 的第一个表达式：$t_4 - t_1 = d_1 + (t_3 - t_2) + d_2$，所以 $\delta = d_1 + d_2 \ge 0$。由 $d_1, d_2 \ge 0$ 且 $d_1 + d_2 = \delta$，差 $d_2 - d_1$ 落在 $[-\delta, \delta]$ 内，这就给出了界限；而 $d_1 = d_2$ 时 $\theta^* = \theta$。
:::

::: example 一次 NTP 交换 {#ex-ntp}
某客户端在自己时钟的 $t_1 = 10{:}00{:}00.000$ 发出请求。服务器在自己时钟的 $t_2 = 10{:}00{:}00.130$ 收到请求，在 $t_3 = 10{:}00{:}00.131$ 作出答复。答复在客户端时钟的 $t_4 = 10{:}00{:}00.042$ 到达。估计偏移并界定误差。
::: solution
以 $10{:}00{:}00$ 之后的毫秒计，$t_2 - t_1 = 130$，$t_3 - t_4 = 131 - 42 = 89$，所以 $\theta = (130 + 89)/2 = 109.5$ ms。延迟为 $\delta = (42 - 0) - (131 - 130) = 41$ ms。由 [[#thm-ntp]]，服务器的时钟比客户端的快 $109.5 - 20.5 = 89$ 到 $109.5 + 20.5 = 130$ ms 之间。客户端把时钟校正约 $109.5$ ms；若两个方向的延迟事实上相等（各 $20.5$ ms），这个校正就是精确的。注意答复到达时客户端时钟读数是 $42$ ms，而服务器是在 $131$ ms 时发出的：原始时间戳仿佛在说答复在发出之前就到达了——本章开头的那个悖论——由偏移化解。
:::
:::

真实的 NTP 保留近期样本中延迟最小的那些往返，用时钟选择算法合并多台服务器的信息并剔除离群值，并**微调**（slew）时钟（让它稍微跑快或跑慢）而不是跳变，大误差除外。服务器组成**层次**（stratum）结构：第 $0$ 层是基准时钟（GPS、原子钟），第 $1$ 层服务器直连一个基准，第 $2$ 层服务器与第 $1$ 层同步，依此类推。在因特网上 NTP 通常能达到几毫秒到几十毫秒的准确度；在数据中心内约一毫秒甚至更好；而在网卡和交换机里做硬件打时间戳的**精确时间协议**（Precision Time Protocol，PTP，IEEE 1588）能达到微秒乃至更低。**伯克利算法**（Gusella 和 Zatti，1989）解决的是另一个问题：没有权威源时，一台主机轮询各机器，把它们时钟的平均值（剔除离群值）算出来，再告诉每台如何调整，使它们彼此一致，而不必与真实时间一致。

::: warning 当日时间钟会跳变——绝不要用它测量时长
当日时间钟（`time.time()` in Python，POSIX 的 `CLOCK_REALTIME`）可能被 NTP 或管理员向前或向后拨，而闰秒前后它还可能重复或抹平一秒。两个读数之差算出的时长因此可能是负数或错得离谱，基于它的租约或超时会提前到期或永不到期。测量时长和超时要用**单调时钟**（`time.monotonic()`，`CLOCK_MONOTONIC`）：它绝不倒退，尽管它在跨机器或跨重启时没有意义。也绝不要假设来自两台机器的时间戳能在（未知的、无界的）偏斜之外相互比较——按墙上时钟时间戳“最后写入者胜出”，会悄悄丢弃自己时钟慢了的那台机器的写入。
:::

## 先行发生关系

时钟同步能缩小不确定度却无法消除它，而在异步系统中根本不存在任何界限。兰波特（Lamport）1978 年的论文《时间、时钟以及分布式系统中事件的次序》改变了问题本身。不要问事件何时发生，要问哪些事件*可能影响过*它。一个事件只有当信息能从它流向另一个事件——沿着某进程自己的步骤序列，或经由一条消息——才能影响另一个事件。

::: definition 先行发生 {#def-hb}
执行的事件上的**先行发生**（happened-before）关系 $\to$ 是满足下列条件的最小关系：
1. 若 $a$ 和 $b$ 是同一进程的事件且 $a$ 发生在 $b$ 之前，则 $a \to b$；
2. 若 $a$ 是某消息的发送而 $b$ 是它的接收，则 $a \to b$；
3. 若 $a \to b$ 且 $b \to c$，则 $a \to c$（传递性）。

若 $a \to b$ 与 $b \to a$ 都不成立，则事件 $a$ 和 $b$ 是**并发的**，记作 $a \parallel b$。
:::

先行发生是一个严格偏序：按定义它是传递的；而由于链条 $a \to \dots \to b$ 的每一步都沿真实时间严格向前（进程的后一步发生得更晚，消息在发送之后才被接收），没有链条能回到起点，所以它是反自交的。它是*潜在的*因果性：$a \to b$ 意味着 $a$ 可能影响过 $b$，而非确实影响了。而 $a \parallel b$ 意味着这两个事件在因果上互不相干——算法的任何一次执行都不曾让其中一个知道另一个——即便按墙上时钟，一个比另一个早发生了一个小时。

我们把执行画成**时空图**：每个进程一条水平线，时间向右流动，事件是点，消息是点与点之间的箭头。于是从 $a$ 沿进程线和消息箭头向右能走到 $b$ 时，恰好有 $a \to b$。

::: example 一次三进程的执行 {#ex-execution}
进程 $P_1, P_2, P_3$ 执行下列事件（各进程内部按列出的先后顺序）：
- $P_1$：$a$（内部），$b$（向 $P_2$ 发送 $m_1$），$c$（接收 $m_3$）；
- $P_2$：$d$（接收 $m_1$），$e$（向 $P_3$ 发送 $m_2$），$f$（内部）；
- $P_3$：$g$（内部），$h$（接收 $m_2$），$i$（向 $P_1$ 发送 $m_3$）。

$(a, h)$、$(g, b)$、$(f, c)$、$(g, c)$ 中哪些对由 $\to$ 相关？
::: solution
$a \to h$：$a \to b$（同进程），$b \to d$（$m_1$），$d \to e$，$e \to h$（$m_2$）。$g$ 与 $b$ 并发：$i$ 之前 $P_3$ 没有任何消息发出，而 $b$ 没有通往 $g$ 的路径，$g$ 是 $P_3$ 的第一个事件。$f \parallel c$：$b$ 之后进入 $P_1$ 的唯一消息是 $i$ 发的 $m_3$；$f$ 没有发出的消息，$c$ 处也没有任何东西能到达 $f$。$g \to c$：$g \to h \to i \to c$。所以 $\to$ 只通过消息链把不同进程上的事件联系起来。
:::
:::

## 兰波特时钟

我们想给每个事件配一个数，使这些数尊重因果性。兰波特的逻辑时钟用每个进程一个计数器加一条消息规则做到了这一点。

::: algorithm 兰波特时钟 {#alg-lamport}
每个进程 $p$ 维护一个整数 $L_p$，初始为 $0$。
1. 在 $p$ 的每个事件（内部、发送或接收）之前，置 $L_p \gets L_p + 1$；该事件的时间戳就是新值。
2. 发送消息时，附上发送事件的时间戳。
3. 收到带时间戳 $t$ 的消息时：置 $L_p \gets \max(L_p, t)$，然后执行规则 1，于是接收事件的时间戳为 $\max(L_p, t) + 1$。
:::

::: theorem 时钟条件 {#thm-clock-condition}
对一切事件 $a$ 和 $b$，若 $a \to b$，则 $L(a) < L(b)$。
:::

::: proof
只需对 [[#def-hb]] 的两个生成情形证明结论即可，因为 $<$ 是传递的，而每个满足 $a \to b$ 的对都由有限多条这样的步骤连起来。若 $a$ 在同一进程上先于 $b$，计数器只增不减且在 $b$ 之前加过一，所以 $L(b) \ge L(a) + 1$。若 $a$ 发送的消息在事件 $b$ 处被接收，消息带着 $t = L(a)$，而 $L(b) = \max(L_p, t) + 1 \ge L(a) + 1$。
:::

反过来不成立：$L(a) < L(b)$ 推不出 $a \to b$。在 [[#ex-execution]] 中，兰波特时间戳是 $P_1$ 上 $a = 1, b = 2, c = 7$；$P_2$ 上 $d = 3, e = 4, f = 5$；$P_3$ 上 $g = 1, h = 5, i = 6$。于是尽管 $g \parallel b$，却有 $L(g) = 1 < L(b) = 2$；尽管 $f \parallel c$，却有 $L(f) = 5 < L(c) = 7$。时钟条件能给的（取其逆否命题）是：若 $L(a) \ge L(b)$，则 $a \not\to b$——一个事件不可能受一个时间戳与它相等或更大的事件的影响。

### 一个全序

时间戳可能打平（上面有 $L(f) = L(h) = 5$）。用进程标识符打破平局便得到一个全序：当 $L(a) < L(b)$，或 $L(a) = L(b)$ 且 $p_a < p_b$ 时，$(L(a), p_a) < (L(b), p_b)$。由 [[#thm-clock-condition]]，这个全序**扩张**了先行发生——它从不与因果性矛盾——而且每个进程都能只凭时间戳在本地把它算出来。兰波特用它解决了没有中央协调者的**互斥**问题：想要资源的进程广播一个带时间戳的请求；每个进程把请求按 $(L, p)$ 排进队列并逐一确认；当一个进程的请求位于自己队列的队首、并且已从其他每个进程收到过带更大时间戳的消息时（假设 FIFO 信道，这就保证不会有更早的请求还滞留在途），它进入临界区；离开时广播一个释放消息。每次进入花费 $3(n-1)$ 条消息。而更重要的是，同一个思想——每个进程按同一个全序应用同一批命令——就是**状态机复制**，即 [[distributed-systems/consensus]] 和 [[distributed-systems/fault-tolerance]] 的主题。（兰波特的算法假定没有故障；容忍故障正是共识所添加的内容。）

::: quiz
事件 $x$ 和 $y$ 的兰波特时间戳为 $L(x) = 3$、$L(y) = 8$。你能得出什么结论？
- [ ] $x \to y$
- [x] $y \not\to x$（并非 $y$ 先于 $x$ 发生）
- [ ] $x \parallel y$
- [ ] $x$ 在真实时间中比 $y$ 发生得早
::: solution
由时钟条件，$y \to x$ 会迫使 $L(y) < L(x)$，而它不成立；所以 $y \not\to x$。$x \to y$ 与 $x \parallel y$ 都有可能——时间戳分不出是哪一种。它们对真实时间也一无所告：并发事件以任何一种先后次序发生都是可能的。
:::
:::

## 向量时钟

要判定两个事件是因果相关还是并发——这恰恰是复制的数据库区分“一个更新覆盖另一个”与“两者冲突”所需要的（[[distributed-systems/replication-consistency]]）——我们需要一个精确刻画 $\to$ 的时间戳。单个整数做不到（习题 8）。$n$ 个整数组成的向量可以做到。

::: algorithm 向量时钟 {#alg-vector}
每个进程 $p_i$ 维护一个向量 $V_i \in \N^n$，初始全为零。
1. 在 $p_i$ 的每个事件之前，置 $V_i[i] \gets V_i[i] + 1$；事件的时间戳 $V(e)$ 就是这个新向量。
2. 发送消息时，附上发送事件的时间戳。
3. 收到带时间戳 $W$ 的消息时：对每个 $j$ 置 $V_i[j] \gets \max(V_i[j], W[j])$，然后执行规则 1。

向量的比较按分量进行：若对所有 $j$ 有 $V[j] \le W[j]$，则 $V \le W$；若 $V \le W$ 且 $V \ne W$，则 $V < W$。
:::

各个分量的含义是一切的关键。对事件 $e$，称 $\mathord{\downarrow} e = \set{x : x \to e \text{ 或 } x = e}$ 为它的**因果过去**。

::: lemma 向量分量统计因果过去 {#lem-vector-entries}
对每个事件 $e$ 和进程 $p_j$，$V(e)[j]$ 等于 $\mathord{\downarrow} e$ 中 $p_j$ 的事件个数。而且，这些事件恰是 $p_j$ 的前 $V(e)[j]$ 个事件。
:::

::: proof
首先，$\mathord{\downarrow} e$ 中 $p_j$ 的事件构成 $p_j$ 事件序列的一个前缀：若 $x$ 是 $\mathord{\downarrow} e$ 中 $p_j$ 的一个事件，而 $x'$ 在 $p_j$ 上位于 $x$ 之前，则 $x' \to x$，于是 $x' \in \mathord{\downarrow} e$。所以只需证明 $V(e)[j]$ 是这一前缀的长度，即 $\mathord{\downarrow} e$ 中 $p_j$ 的最后一个事件的位置（从 $1$ 起计），若无则为 $0$。

我们对事件按其发生的次序归纳。设 $e$ 是 $p_i$ 的第 $k$ 个事件，$e^-$ 是 $p_i$ 的前一个事件（若存在）。

*若 $e$ 不是接收*，则 $\mathord{\downarrow} e = \mathord{\downarrow} e^- \cup \set{e}$，因为进入 $e$ 的生成边只有来自 $e^-$ 的那一条。算法在除 $V(e)[i] = V(e^-)[i] + 1 = (k - 1) + 1 = k$ 之外令 $V(e) = V(e^-)$，这里对 $e^-$ 用了归纳假设（它自身的位置是 $k - 1$；若 $e$ 是第一个事件，则各分量原先都是 $0$）。对 $j \ne i$，$\mathord{\downarrow} e$ 中 $p_j$ 的前缀就是 $\mathord{\downarrow} e^-$ 中的那一个，与 $V(e^-)[j]$ 相符；对 $j = i$，$\mathord{\downarrow} e$ 中 $p_i$ 的最后一个事件就是 $e$ 本身，位于位置 $k$。

*若 $e$ 接收了在事件 $s$ 发出的消息*，则 $\mathord{\downarrow} e = \mathord{\downarrow} e^- \cup \mathord{\downarrow} s \cup \set{e}$。对每个 $j \ne i$，这个并集中 $p_j$ 的事件构成两个前缀中较长者，由对 $e^-$ 和 $s$ 的归纳假设（两者都发生在 $e$ 之前），其长度为 $\max(V(e^-)[j], V(s)[j])$，正是算法所算的值。对 $j = i$：$e^-$ 之后的 $p_i$ 的事件没有一个能在 $\mathord{\downarrow} s$ 中，因为 $s$ 发生在 $e$ 之前，而那样的事件将是 $e$ 或更晚；所以并集中 $p_i$ 的前缀长度为 $k$（含 $e$），算法给出 $\max(k - 1, V(s)[i]) + 1 = k$，因为 $V(s)[i] \le k - 1$。
:::

::: theorem 向量时钟精确刻画先行发生 {#thm-vector}
对一切事件 $a$ 和 $b$：$a \to b$ 当且仅当 $V(a) < V(b)$。于是 $a \parallel b$ 当且仅当 $V(a)$ 与 $V(b)$ 不可比。
:::

::: proof
*若 $a \to b$ 则 $V(a) < V(b)$。* 由传递性，$\mathord{\downarrow} a \subseteq \mathord{\downarrow} b$，所以对每个 $j$，$\mathord{\downarrow} a$ 中 $p_j$ 的事件都包含在 $\mathord{\downarrow} b$ 的事件之中，由 [[#lem-vector-entries]] 得 $V(a) \le V(b)$。设 $p_j$ 是 $b$ 所在的进程。则 $b \in \mathord{\downarrow} b$；但 $b \notin \mathord{\downarrow} a$，因为若 $b \to a$ 再配上 $a \to b$ 便得 $a \to a$，而若 $b = a$ 也得 $a \to a$，两者都与反自交性矛盾。$\mathord{\downarrow} a$ 中 $p_j$ 的事件构成一个不含 $b$ 的前缀，所以它们都在 $b$ 之前，于是 $V(a)[j] < b\text{的位置} \le V(b)[j]$。故 $V(a) \ne V(b)$ 且 $V(a) < V(b)$。

*若 $V(a) < V(b)$ 则 $a \to b$。* 设 $a$ 是进程 $p_i$ 的第 $k$ 个事件。由引理，$V(a)[i] = k$，因为 $a$ 本身就是 $\mathord{\downarrow} a$ 中 $p_i$ 的最后一个事件。由 $V(b)[i] \ge V(a)[i] = k$，引理说 $\mathord{\downarrow} b$ 包含 $p_i$ 的前 $k$ 个事件，其中有 $a$。于是 $a \to b$ 或 $a = b$；而 $a = b$ 不可能，因为 $V(a) \ne V(b)$。

*并发。* 不同的事件绝不会有相等的向量：若 $V(a) = V(b)$ 且 $a$ 是 $p_i$ 的第 $k$ 个事件，则 $V(b)[i] = k$，于是由引理 $a \in \mathord{\downarrow} b$，从而 $a \to b$，第一部分又给出 $V(a) < V(b)$，矛盾。所以对不同的 $a, b$，“$a \to b$ 与 $b \to a$ 均不成立”等价于“$V(a) < V(b)$ 与 $V(b) < V(a)$ 均不成立”，而由于两个向量不同，这正是它们不可比。
:::

这个证明还给出一个更省判别法：若 $a$ 是 $p_i$ 的事件，则 $a \to b$ 当且仅当 $V(a)[i] \le V(b)[i]$ 且 $a \neq b$。一旦知道 $a$ 发生在哪个进程上，一个分量就够了。

::: example 向量时间戳 {#ex-vectors}
计算 [[#ex-execution]] 中各事件的向量时间戳，并用它们判定 $f$ 与 $c$、$f$ 与 $h$ 的关系。
::: solution
$P_1$：$a = (1,0,0)$，$b = (2,0,0)$。$P_2$：$d = \max((0,0,0), (2,0,0))$ 后打表：$(2,1,0)$；$e = (2,2,0)$；$f = (2,3,0)$。$P_3$：$g = (0,0,1)$；$h = \max((0,0,1),(2,2,0))$ 后打表：$(2,2,2)$；$i = (2,2,3)$。回到 $P_1$：$c = \max((2,0,0),(2,2,3))$ 后打表：$(3,2,3)$。

$f = (2,3,0)$ 与 $c = (3,2,3)$：$f$ 在第二个分量上更大，$c$ 在第一和第三个分量上更大——不可比，所以 $f \parallel c$，尽管兰波特时间戳是 $5 < 7$。$f = (2,3,0)$ 与 $h = (2,2,2)$：不可比，$f \parallel h$。相比之下 $e = (2,2,0) < c = (3,2,3)$，所以 $e \to c$（经由 $m_2$ 和 $m_3$）。单分量判别法结论一致：$e$ 在 $P_2$ 上，$V(e)[2] = 2 \le V(c)[2] = 2$。
:::

我们可以在随机执行上检验 [[#thm-vector]] 和时钟条件，把时间戳与先行发生边的传递闭包比较：

```python
import random
from itertools import product

def run(n, steps, seed):
    """n 个进程的随机执行；返回以 (pid, lamport, vector) 表示的事件以及发送->接收配对。"""
    rng = random.Random(seed)
    L, V = [0] * n, [[0] * n for _ in range(n)]
    events, msgs, in_flight = [], [], []
    for _ in range(steps):
        p = rng.randrange(n)
        L[p] += 1; V[p][p] += 1                       # 每个事件都给本地时钟打一格
        if in_flight and rng.random() < 0.8:          # 接收一条发给 p 的随机消息
            mine = [m for m in in_flight if m[1] == p]
            if mine:
                src_event, _, lt, vt = m = rng.choice(mine)
                in_flight.remove(m)
                L[p] = max(L[p], lt + 1)
                V[p] = [max(a, b) for a, b in zip(V[p], vt)]
                msgs.append((src_event, len(events)))
        events.append((p, L[p], tuple(V[p])))
        if rng.random() < 0.4:                        # 这个事件还发出一条消息
            in_flight.append((len(events) - 1, rng.randrange(n), L[p], tuple(V[p])))
    return events, msgs
```

函数 `happened_before`（未列出；它把进程内次序边和消息边加进去，再像 [[algorithms/shortest-paths]] 那样以 Floyd–Warshall 风格求传递闭包）给出真实关系，检验程序比较两者：

```console
$ python3 vc.py
events: 60  messages: 19
vector clocks characterise ->: True
Lamport clock condition holds: True
concurrent pairs: 791  of which Lamport orders: 727
```

$791$ 对并发事件中，兰波特时间戳给 $727$ 对赋了不同的值，使它们*看上去*有了先后；向量时钟则把每一对都识别为并发。（代码里，接收时的打表被并进 `max`，写作 $\max(L_p + 1, t + 1)$，它等于 $\max(L_p, t) + 1$。）

向量时钟的代价是每条消息、每个存储的时间戳都要 $n$ 个整数，而 Bernadette Charron-Bost 在 1991 年证明：一般说来，用少于 $n$ 个实数组成的向量刻画先行发生是不可能的。实践中，复制存储使用**版本向量**（version vector）：每个*副本*一个分量而非每个客户端一个，附在每个存储的值上，并且剪掉已经离开的副本的分量；Amazon 的 Dynamo 是经典的例子（[[distributed-systems/distributed-storage]]）。

## 一致快照

有些问题关乎系统的*全局*状态：计算死锁了吗？它终止了吗？银行里一共有多少钱？故障之后应当从哪里重启？没有全局时钟，我们就无法要求每个进程“在正午”记下自己的状态。Chandy 和兰波特（Lamport）的洞见是：我们并不需要同一时刻的状态，只需要一个*可能*出现过的状态。

::: definition 割与一致割 {#def-cut}
一次执行的**割**（cut）$C$ 是一个事件集合，它对每个进程都包含其事件的一个前缀（“割线之前”的事件）。若割每当包含一条消息的接收时就也包含该消息的发送，则称它是**一致的**。割的**全局状态**由每个进程在其割内最后一个事件之后的状态、以及每条信道上“在割内发送但未在割内接收”的消息构成。
:::

::: proposition 一致割对因果封闭 {#prop-cut-closed}
割 $C$ 是一致的，当且仅当对每个 $e \in C$ 和每个满足 $e' \to e$ 的事件 $e'$，都有 $e' \in C$。
:::

::: proof
*充分性。* 接收事件 $b \in C$ 的发送事件满足 $a \to b$，所以 $a \in C$。
*必要性。* 设 $C$ 一致且 $e \in C$，$e' \to e$。取一条链 $e' = x_0, x_1, \dots, x_k = e$，其中每一步或是进程内的步骤，或是一条消息。我们从 $x_k$ 向后归纳证明每个 $x_i \in C$。若 $x_{i+1} \in C$ 且 $x_i$ 在同一进程上位于它之前，则 $x_i \in C$，因为 $C$ 包含每个进程的一个前缀。若 $x_i$ 是一条消息的发送、而该消息在 $x_{i+1} \in C$ 处被接收，则 $x_i \in C$，由一致性。
:::

于是不一致的割记录了结果却没有记录其原因——一条被接收却从未发送的消息——这正是本章开头那段不可能的历史。一致割的全局状态是系统本可能经过的状态：把 $C$ 中的事件按 $\to$ 的任一线性化跑一遍，它们构成一次执行的一个合法前缀。

::: algorithm Chandy–Lamport 快照 {#alg-chandy-lamport}
假设 FIFO、可靠的信道和强连通的网络。任何进程都可发起。
1. **发起者**：记录自己的状态；然后在每条出站信道上、先于任何其他消息，发送一个特殊的**标记**（marker）消息；开始记录每条入站信道。
2. **在信道 $c$ 上收到标记时**：
   - 若该进程尚未记录自己的状态：记录自己的状态；把 $c$ 的状态记为空；在每条出站信道上先于任何其他消息发送标记；开始记录其余每条入站信道；
   - 否则：停止记录 $c$；$c$ 的状态是自开始记录以来在 $c$ 上收到的消息序列。
3. 当进程在每条入站信道上都收到标记时，它便完成。快照就是所记录的进程状态与信道状态的集合。
:::

::: theorem Chandy–Lamport 快照是一致的 {#thm-chandy-lamport}
设 $C$ 是每个进程中发生在它记录自己状态之前的那些事件的集合。那么 $C$ 是一个一致割，且每条信道被记录的状态恰好是那些在发送方的割之前发送、在接收方的割之后接收的消息——即 [[#def-cut]] 中的信道状态。
:::

::: proof
*终止性。* 发起者在所有出站信道上发送标记；每个收到标记的进程记录自己的状态，并在其所有出站信道上发送标记。由于网络强连通且信道可靠，每个进程都会收到标记、记录自己的状态，并最终在每条入站信道上收到标记。

*一致性。* 设消息 $m$ 经信道 $c$ 从 $p$ 发往 $q$，且它的接收属于 $C$，即 $q$ 在记录自己的状态之前收到了 $m$。反设 $m$ 的发送不属于 $C$：$p$ 发送 $m$ 时已经记录了自己的状态。那么 $p$ 早已在 $c$ 上、*先于* $m$ 发送过标记（它一记录状态就立即在所有出站信道上发标记）。由 FIFO，$q$ 在 $m$ 之前收到标记，而收到标记会促使尚未记录状态的 $q$ 记录状态——于是 $q$ 在收到 $m$ 之前就记录了自己的状态，与“$m$ 的接收属于 $C$”的假设矛盾。

*信道状态。* $q$ 记录的是在记录自己的状态之后、在 $c$ 上收到标记之前到达 $c$ 的消息（若 $c$ 上的标记正是促使它记录状态的那个，则一条也没有）。由 FIFO，在标记之前到达 $c$ 的消息恰好是 $p$ 在自己的标记之前发送的那些，也就是在 $p$ 记录状态之前发送的那些——属于 $C$ 的发送。在 $q$ 记录状态之后到达的那些，则是不属于 $C$ 的接收。所以 $q$ 记录的恰好是在割内发送、在割外接收的消息。
:::

::: example 一次银行快照 {#ex-bank-snapshot}
两个分行 $P$（余额 $£100$）与 $Q$（余额 $£50$）相互转账。当 $P$ 在向 $Q$ 汇出 $£10$ 之后发起算法，而 $Q$ 同时向 $P$ 汇出 $£20$ 时，跟踪算法的执行，并验证快照守恒金额。
::: solution
1. $P$ 向 $Q$ 汇出 $£10$；$P = 90$。
2. $P$ 发起：记录 $P = 90$，向 $Q$ 发送标记，开始记录信道 $Q \to P$。
3. $Q$ 向 $P$ 汇出 $£20$；$Q = 30$。
4. $Q$ 收到那笔 $£10$（它在 FIFO 信道 $P \to Q$ 上抢在标记之前到达）；$Q = 40$。
5. $Q$ 收到标记：记录 $Q = 40$，信道 $P \to Q$ 为空，向 $P$ 发送标记。
6. $P$ 收到那笔 $£20$，它先于 $Q$ 的标记发出；$P = 110$。$P$ 正在记录 $Q \to P$，于是记下这笔 $£20$。
7. $P$ 收到 $Q$ 的标记：信道 $Q \to P$ 被记录为 $\set{£20}$。

快照：$P = 90$，$Q = 40$，$P \to Q$ 为空，$Q \to P$ 上有 $£20$。总额为 $90 + 40 + 20 = 150，分毫不差。在真实的某个时刻，余额并不曾同时是 $90$ 和 $40$、*而且*有一笔 $£20$ 在途*并且*那笔 $£10$ 已经收到——按真实时间，$£20$ 是在 $£10$ 到达之前发出的——但这个状态是一致的：它可能出现在一次具有相同因果次序的另一执行中。若没有信道状态，快照将显示 $£130$，钱凭空少了；若没有 FIFO，那笔 $£10$ 就可能超过标记，被重复计数或干脆漏掉（习题 9）。
:::
:::

快照是检测**稳定性质**的良好基础——一旦为真便保持为真的性质，例如“计算已经终止”“这些进程死锁了”“这个对象是垃圾”。Chandy 和兰波特（Lamport）证明：被记录的状态既可从快照开始时的状态到达，也可到达快照结束时的状态，所以若某稳定性质在快照中成立，它在快照完成时也成立。同一算法用于数据流图，正是 Apache Flink 这类流处理器做一致性检查点的方式（[[distributed-systems/data-processing]]）。

## 物理时间归来：混合时钟与 TrueTime

逻辑时钟抓住了因果性却丢掉了真实时间：兰波特时间戳对事件何时发生一无所告，而经由系统看不见的通道的因果——一位用户在一个网站上读了确认、随后在另一个网站上采取行动——对它们是不可见的。两种现代设计把两种时间结合了起来。

**混合逻辑时钟**（Kulkarni、Demirbas 及合作者，2014）在每个进程上维护一个时间戳，取物理时钟与所见最大时间戳两者的最大值，再配一个小逻辑计数器来打破平局。它们满足 [[#thm-clock-condition]] 的时钟条件，并保持在物理时间的时钟同步误差之内，因此既能用于因果定序，也能用于“截至某个墙上时钟时刻”的查询。

**TrueTime**，见 Corbett 及合作者 2012 年关于 Google Spanner 数据库的论文，把时钟的不确定度摆到明面上。`TT.now()` 返回一个区间 $[\mathit{earliest}, \mathit{latest}]$，并且保证（凭每个数据中心的 GPS 接收机和原子钟，以及对漂移的保守假设）真实时间落在其中。论文报告的半宽度 $\varepsilon$ 在约 $1$ 到 $7$ ms 之间呈锯齿形变化，形状正像 [[#prop-resync]]。若事务 $T_1$ 被赋予时间戳 $s_1 = \mathit{latest}$，并等到 `TT.now().earliest` $> s_1$ 才让自己的效果可见——这段**提交等待**约为 $2\varepsilon$——那么任何在 $T_1$ 可见之后才开始的事务 $T_2$ 都会拿到更大的时间戳。于是真实时间次序与时间戳次序一致，这个性质称为**外部一致性**，其证明见 [[distributed-systems/distributed-transactions]]。不确定度没有被消除；它被界定下来，然后被等待掉。

兰波特（Lamport）的《时间、时钟以及分布式系统中事件的次序》（"Time, clocks, and the ordering of events in a distributed system"，《Communications of the ACM》，1978）定义了先行发生、逻辑时钟、全序和互斥算法，并指出了它与狭义相对论的联系——在那里，一个事件的因果未来就是它的光锥。David Mills 的网络时间协议最早在 RFC 958（1985）中被标准化；NTPv4 是 RFC 5905（2010）。Flaviu Cristian 于 1989 年发表了概率性时钟同步，Riccardo Gusella 和 Stefano Zatti 同年发表了伯克利 TEMPO 算法。向量时钟由 Colin Fidge（1988）和 Friedemann Mattern（1989）各自独立提出；用于复制文件的版本向量出现得更早，在 D. Stott Parker 及合作者 1983 年关于检测相互不一致的论文中。K. Mani Chandy 和兰波特（Lamport）的《分布式快照：确定分布式系统的全局状态》（"Distributed snapshots: determining global states of distributed systems"）发表于《ACM Transactions on Computer Systems》，1985 年。IEEE 1588 精确时间协议于 2002 年首次标准化，Spanner 的 TrueTime 由 James Corbett 及合作者发表于 OSDI 2012，Sandeep Kulkarni 及合作者于 2014 年提出了混合逻辑时钟。
:::

## 后续内容

先行发生是各一致性模型的标尺：[[distributed-systems/replication-consistency]] 中的**因果一致性**要求每个进程都按因果次序看到因果相关的写入，而 Dynamo 风格的存储用版本向量检测相互冲突的并发写入（[[distributed-systems/distributed-storage]]）。兰波特时间戳的全序是通向复制状态机的第一步，而复制状态机需要对次序达成*容错的*一致——共识（[[distributed-systems/consensus]]）。一致快照支撑着流处理器的检查点（[[distributed-systems/data-processing]]），而 TrueTime 的提交等待赋予 Spanner 全局一致的事务（[[distributed-systems/distributed-transactions]]）。多处理器中的内存一致性——同一台机器内部的同样问题——在 [[parallel-computing/memory-consistency]]。

::: summary
- 物理时钟会**漂移**（ppm），必须重新同步；偏斜保持在 $\varepsilon + 2\rho R$ 之下（[[#prop-resync]]）。
- Cristian 的方法和 **NTP** 用往返估计偏移；NTP 的误差不超过往返延迟的一半（[[#thm-ntp]]）。测量时长要用**单调**时钟。
- **先行发生**（$\to$）是潜在的因果性：进程内次序加上消息，并对传递性封闭；互不相关的事件是**并发的**。
- **兰波特时钟**满足 $a \to b \Rightarrow L(a) < L(b)$（[[#thm-clock-condition]]），并给出一个扩张 $\to$ 的全序，但检测不出并发。
- **向量时钟**精确刻画因果性：$a \to b \iff V(a) < V(b)$（[[#thm-vector]]），代价是 $n$ 个分量。
- **一致割**对 $\to$ 封闭；**Chandy–Lamport** 算法用标记消息在 FIFO 信道上记录下一个这样的割，连同信道状态（[[#thm-chandy-lamport]]）。
- **TrueTime** 把时钟不确定度作为区间暴露出来并等待其过去；混合逻辑时钟把物理时间与逻辑时间结合起来。
:::

## 习题

::: exercise 每天的漂移 {level=1 check="4.32"}
某时钟的漂移率为 $50$ ppm。一天之中它可能变快或变慢多少秒？（填入秒数。）
::: solution
$50 \times 10^{-6} \times 86{,}400 = 4.32$ s。
:::
:::

::: exercise 兰波特时间戳 {level=1 check="6"}
进程 $P$ 执行：向 $Q$ 发送 $m$，一个内部事件，从 $Q$ 接收 $n$。进程 $Q$ 执行：内部事件，内部事件，内部事件，接收 $m$，向 $P$ 发送 $n$。所有时钟都从 $0$ 开始。$P$ 接收 $n$ 的兰波特时间戳是多少？（填入时间戳。）
::: solution
$P$：发送 $m$ 时 $L = 1$；内部事件 $L = 2$。$Q$：三个内部事件 $1, 2, 3$；接收 $m$：$\max(3, 1) + 1 = 4$；发送 $n$：$5$。$P$ 以时间戳 $5$ 接收 $n$：$\max(2, 5) + 1 = 6$。
:::
:::

::: exercise 比较向量 {level=1}
把每一对归为 $a \to b$、$b \to a$ 或并发：(a) $V(a) = (2,1,0)$，$V(b) = (3,1,2)$；(b) $V(a) = (1,4,0)$，$V(b) = (2,3,1)$；(c) $V(a) = (0,2,5)$，$V(b) = (0,1,5)$。
::: solution
由 [[#thm-vector]]：(a) $(2,1,0) < (3,1,2)$，所以 $a \to b$。(b) 不可比（$4 > 3$ 但 $1 < 2$）：并发。(c) $(0,1,5) < (0,2,5)$，所以 $b \to a$。
:::
:::

::: exercise 一次 NTP 计算 {level=2 check="50"}
设 $t_1 = 100$，$t_2 = 160$，$t_3 = 161$，$t_4 = 121$（毫秒，$t_1, t_4$ 在客户端时钟上，$t_2, t_3$ 在服务器时钟上），计算 NTP 的偏移估计 $\theta$、延迟 $\delta$，以及必含真实偏移的那个区间。（以毫秒填入 $\theta$。）
::: solution
$\theta = ((160 - 100) + (161 - 121))/2 = (60 + 40)/2 = 50$ ms。$\delta = (121 - 100) - (161 - 160) = 21 - 1 = 20$ ms。由 [[#thm-ntp]]，真实偏移落在 $[40, 60]$ ms 内。
:::
:::

::: exercise 重新同步间隔 {level=2 check="75"}
漂移界限为 $10$ ppm 的时钟可以被同步到彼此相差 $0.5$ ms 以内。为了把偏斜保持在 $2$ ms 以下，必须多久（以秒计）重新同步一次？（填入最大的间隔 $R$，以秒计。）
::: solution
由 [[#prop-resync]]，需要 $0.5 + 2 \times 10 \times 10^{-6} \times R \times 1000 \le 2$ ms，即 $0.02 R \le 1.5$，所以 $R \le 75$ s。
:::
:::

::: exercise 哪些割是一致的？ {level=2}
在 [[#ex-execution]] 中，下列哪些割是一致的？(a) $\set{a, b, d, g}$；(b) $\set{a, d, e, g}$；(c) $\set{a, b, c, d, e, g, h}$；(d) $\set{a, b, d, e, g, h, i}$。
::: solution
检查割内的每个接收。(a) $d$ 接收 $m_1$，其发送 $b \in$ 割：一致。(b) $d$ 在割内而 $b$ 不在：不一致——每个进程都出了一个前缀（$P_1$ 出的是 $\set{a}$），但 $m_1$ 的接收被记录了而其发送没有。(c) $c$ 接收 $m_3$，其发送 $i$ 不在割内：不一致。(d) 接收有 $d$（在 $b$ 发送 ✓）和 $h$（在 $e$ 发送 ✓）：一致；$m_3$ 正在途中，所以在这个全局状态中信道 $P_3 \to P_1$ 上载着 $m_3$。
:::
:::

::: exercise 互斥的消息数 {level=2 check="12"}
在 $5$ 个进程的兰波特互斥算法中，进入一次临界区花费多少条消息？（填入该数。）
::: solution
向其他 $n - 1$ 个进程各发一个请求、$n - 1$ 条确认和 $n - 1$ 条释放：$n = 5$ 时为 $3(n-1) = 12$。
:::
:::

::: exercise 标量时钟无法刻画因果性 {level=3}
证明：不存在从事件到某个全序集的函数 $L$，使得对两个进程的每次执行都有 $a \to b \iff L(a) < L(b)$。（这正是需要向量的原因。）
::: solution
考虑这样一次执行：$P_1$ 执行一个内部事件 $a$，$P_2$ 依次执行两个内部事件 $b$ 和 $c$，期间没有消息。于是 $b \to c$，$a \parallel b$ 且 $a \parallel c$。反设 $L$ 刻画 $\to$。由 $a \parallel b$：$L(a) < L(b)$ 与 $L(b) < L(a)$ 都不成立；在全序中这迫使 $L(a) = L(b)$。同理 $a \parallel c$ 迫使 $L(a) = L(c)$。于是 $L(b) = L(c)$，但 $b \to c$ 要求 $L(b) < L(c)$——矛盾。同样的论证说明并发不具有传递性（$b \parallel a \parallel c$ 而 $b \to c$），而任何全序中的相等具有传递性：任何全序都无法编码这样一个关系——它的“不可比”部分不是一个等价关系。
:::
:::

::: exercise 快照需要 FIFO {level=3}
给出一个信道非 FIFO 的执行，其中 Chandy–Lamport 算法记录了一个不一致的割。然后解释当信道不是 FIFO 时算法可以如何改造。
::: solution
取两个进程 $P$ 和 $Q$ 以及 [[#ex-bank-snapshot]] 中的那家银行。$P$ 记录自己的状态（$£100$），向 $Q$ 发送标记，然后向 $Q$ 汇出 $£10$（于是 $P$ 的发送在其割*之后*）。在一条非 FIFO 的信道上，那笔 $£10$ 超过了标记：$Q$ 先收到 $£10$（余额 $60$），再收到标记，并记下 $£60$。这个割含有 $Q$ 的接收却不含 $P$ 的发送——不一致——而快照显示 $£100 + £60 = £160$：钱被凭空造了出来。

改造方案（Lai 和 Yang，1987）：不再让标记对信道*定序*，而是让每条消息捎带一个标志，说明发送方是否已经记录了自己的状态（一种“颜色”：记录前为白，记录后为红）。进程必须在它收到的第一条红色消息被处理*之前*记录自己的状态，于是任何割后的发送都不可能在割内被接收。信道状态由记录之后收到的白色消息算出，这要求每个进程知道每条信道上有多少条白色消息曾被发给自己（例如让发送方上报计数），以判断信道状态何时完整。
:::
