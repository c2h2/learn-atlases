让 Python 计算十分之一加两个十分之一，它不带一丝尴尬地回答：

```console
>>> 0.1 + 0.2
0.30000000000000004
```

再问它这个和是否等于三个十分之一，它说 `False`。让它把 `"20"` 和 `1` 相加，它回一个 `TypeError` 加以拒绝；然而它却乐于把 `"20"` 乘以 `3` 得到 `'202020'`。而 `-7 // 2` 是 `-4`，不是 C 程序员预期的 `-3`。这些都不是 Python 的缺陷。每个答案都来自一条精确的规则：当前操作的是哪一种**值**，以及每个**运算符**对那种类型的值意味着什么。懂得这些规则的程序员觉得这些结果毫不奇怪；不懂的人迟早会交出一个数错钱、或一遇意外输入就崩溃的程序。

本章给出 Python 基本值——整数、浮点数、字符串、布尔值与 `None`——以及组合它们的表达式（运算符、优先级与求值顺序）的规则。最后讲变量与赋值，把它们精确地陈述为与值绑定的名称。本课程之后的一切都建立在这些部件之上。

## 值与类型

Python 程序操作的每一份数据都是一个**值**：数 `42`、文本 `"hello"`、真值 `True`。每个值恰属于一个**类型**，类型决定这个值能表示什么、哪些运算适用于它。

::: definition 类型 {#def-type}
**类型**是一个值的集合，连同定义在其上的运算。Python 用内置函数 `type` 报告一个值的类型。基本类型有：

| 类型 | 值 | 字面量（书写方式） |
|---|---|---|
| `int` | 整数，位数不限 | `0`、`42`、`-7`、`10_000`、`0xff` |
| `float` | 实数的浮点近似 | `3.0`、`0.1`、`-2.5e-3`、`1e308` |
| `str` | 字符串：字符的有限序列 | `"hi"`、`"it's"`、`"line\n"`、`""` |
| `bool` | 两个真值 | `True`、`False` |
| `NoneType` | 唯一的值 `None`，表示“无值” | `None` |
:::

**字面量**是一个值在源代码中的直接写法。同一个数学上的数可以有多个字面量（`10000`、`10_000` 和 `0x2710` 都是整数一万），而长相一样的数可以代表两个不同的值：`3` 是 `int`，`3.0` 是 `float`。Python 的整数精确且无上界——`2 ** 100` 被精确计算——而浮点数大小固定，是近似值，我们马上就会看到。

```python
print(type(42), type(3.0), type("hi"), type(True), type(None))
```

```console
$ python3 types.py
<class 'int'> <class 'float'> <class 'str'> <class 'bool'> <class 'NoneType'>
```

类型之所以重要，是因为同一个运算符对不同类型意义不同。`+` 把两个数相加，却把两个字符串**拼接**（接在一起）；`*` 对数是相乘，对字符串是重复；而对操作数类型说不通的运算则会被拒绝：

```python
age = "20"          # 一个字符串，也许来自用户键入
print(age + 1)
```

```console
$ python3 concat.py
Traceback (most recent call last):
  File ".../concat.py", line 2, in <module>
    print(age + 1)
          ~~~~^~~
TypeError: can only concatenate str (not "int") to str
```

Python 在程序运行时检查类型（它是**动态类型**的），并且不会在互不相关的类型之间悄悄转换（它是**强类型**的）：它不会去猜 `"20" + 1` 应当是 `21` 还是 `"201"`。要做转换，就得你自己开口说——把类型名当函数用：

| 表达式 | 值 | 说明 |
|---|---|---|
| `int("42")` | `42` | 解析数字串 |
| `float("3.5")` | `3.5` | |
| `str(3) + "4"` | `'34'` | 数变文本 |
| `int(3.9)` | `3` | 向零截断 |
| `int(-3.9)` | `-3` | 仍然向零 |
| `int("3.5")` | `ValueError` | 该串不是整数字面量 |

Python 唯一会做的隐式转换发生在数之间：`2 + 0.5` 里整数被转换成浮点数，结果 `2.5` 是浮点数。布尔值也当数用（`True + True` 是 `2`）——这是历史的权宜，最好别依赖它。

## 表达式及其求值

**表达式**是一段有值的代码：字面量、名称、函数调用，或作用于较小表达式的运算符。**求值**就是算出表达式的值。求值是递归定义的：要求值 `a + b`，先求值 `a`，再求值 `b`（就按这个顺序——Python 的操作数从左到右求值），然后把 `+` 用于两个结果。

当表达式中含有多个运算符时，由**优先级**决定哪个先作用，正如代数中 $2 + 3 \times 4 = 14$，因为乘法比加法结合得更紧。Python 的算术与逻辑运算符按优先级从高到低排列如下：

| 优先级 | 运算符 | 含义 |
|---|---|---|
| 最高 | `**` | 幂运算（*从右*结合） |
| | `+x`、`-x` | 一元正号、负号 |
| | `*`、`/`、`//`、`%` | 乘、真除法、向下取整除法、余数 |
| | `+`、`-` | 加、减 |
| | `<`、`<=`、`>`、`>=`、`==`、`!=`、`in`、`is` | 比较 |
| | `not` | 逻辑非 |
| | `and` | 逻辑与 |
| 最低 | `or` | 逻辑或 |

同级的运算符从左到右结合（`10 - 3 - 2` 是 `(10 - 3) - 2 = 5`），例外是 `**`，它从右结合：`2 ** 3 ** 2` 是 `2 ** 9 = 512`，与数学约定 $2^{3^2} = 2^9$ 一致。因为 `**` 比一元负号结合得更紧，`-2 ** 2` 是 `-(2 ** 2) = -4`。拿不准就加括号：括号不花一分钱，还能把你的意图摆到下一位读者眼前。

::: example 一步步求值 {#ex-precedence}
求值 `17 // 5 * 2 + 3 ** 2 % 4`，逐步展示。
::: solution
优先级最高的是 `**`，先算 $3^2 = 9$：

`17 // 5 * 2 + 9 % 4`

接下来是 `//`、`*` 和 `%`：同一级，从左到右结合。从左读起：`17 // 5` 是 `3`；再 `3 * 2` 是 `6`；在低一级的 `+` 的另一侧，`9 % 4` 是 `1`：

`6 + 1`

最后 `+` 给出 `7`。加上全部括号，表达式是 `((17 // 5) * 2) + ((3 ** 2) % 4)`。Python 的看法相同：`17 // 5 * 2 + 3 ** 2 % 4` 求值为 `7`。
:::
:::

### 整数除法与余数

两个整数相除有两个自然的结果：商与余数。Python 的 `/` 永远做**真除法**，即使整除也得到浮点数（`10 / 5` 是 `2.0`）。运算符 `//` 和 `%` 给出整数商与余数；它们对负数的定义值得精确掌握。

::: definition 向下取整除法与余数 {#def-floordiv}
对整数 $a$ 与 $b \neq 0$，Python 定义

$$
a \mathbin{/\!/} b = \left\lfloor \frac{a}{b} \right\rfloor, \qquad a \mathbin{\%} b = a - b\,(a \mathbin{/\!/} b),
$$

其中 $\lfloor x\rfloor$ 是 $x$ 的**向下取整**（floor），即不超过 $x$ 的最大整数。除以零抛出 `ZeroDivisionError`。
:::

::: theorem 除法恒等式 {#thm-division}
对整数 $a$ 与 $b > 0$，Python 的运算符满足

$$
a = b\,(a \mathbin{/\!/} b) + a \mathbin{\%} b \quad\text{且}\quad 0 \le a \mathbin{\%} b < b.
$$
:::

::: proof
第一个等式就是 `%` 的定义移项而得。至于不等式，令 $q = \lfloor a/b \rfloor$。由向下取整的定义，$q \le a/b < q + 1$。各乘 $b > 0$ 保持不等号：$qb \le a < qb + b$。各减 $qb$ 得 $0 \le a - qb < b$，而 $a - qb = a \mathbin{\%} b$。
:::

所以只要除数为正，余数就永远介于 $0$ 与 $b - 1$ 之间，*无论 $a$ 的符号如何*。这正是数学中的约定（也是 [数学图谱：同余](/learn/maths/lesson.php?c=number-theory&l=congruences) 中 `mod` 的约定），也正是它让 `%` 在“绕回”时有用武之地：即使 `day + 3` 是负数，`(day + 3) % 7` 也给出 $0$ 到 $6$ 之间的一天。（当 $b < 0$ 时，余数落在 $b < r \le 0$ 内；同一个论证，把所有不等号反向即可。）

::: example 负操作数 {#ex-negative}
计算 `-7 // 2`、`-7 % 2`、`-17 // 5` 与 `-17 % 5`，并验证除法恒等式。
::: solution
$-7/2 = -3.5$，而 $\lfloor -3.5\rfloor = -4$（floor 向 $-\infty$ 方向*舍下*），所以 `-7 // 2` 是 `-4`，`-7 % 2` 是 $-7 - 2\cdot(-4) = 1$。验证：$2 \cdot (-4) + 1 = -7$，且 $0 \le 1 < 2$。

$-17/5 = -3.4$，其 floor 是 $-4$，所以 `-17 // 5` 是 `-4`，`-17 % 5` 是 $-17 - 5\cdot(-4) = 3$。验证：$5 \cdot (-4) + 3 = -17$。
:::
:::

::: warning 各语言对负数除法的约定不同
并非每种语言都用 floor。C、C++、Java 与 JavaScript 对整数除法**向零截断**，其余数取被除数的符号。用 `gcc -std=c17` 编译下面这个 C 程序

```c
#include <stdio.h>

int main(void) {
    printf("%d %d\n", -7 / 2, -7 % 2);   /* C 向零截断 */
    printf("%d %d\n", 7 / 2, 7 % 2);
    return 0;
}
```

先打印 `-3 -1` 再打印 `3 1`；而 Python 的 `-7 // 2, -7 % 2` 给出 `-4 1`。两种约定都满足 $a = bq + r$，区别只在所选的 $q$ 不同。对非负操作数两者一致。在不同语言之间移植代码时，凡是可能碰到负数的除法都要检查一遍。
:::

`//` 与 `%` 这一对是把一个量按单位拆分的标准工具，而 Python 内置的 `divmod(a, b)` 会把两者作为数对 `(a // b, a % b)` 一次性返回。

::: example 把秒数换算成时、分、秒 {#ex-hms}
写一个程序，把 `10_000` 秒换算成时、分、秒，并以 `h:mm:ss` 的形式打印。
::: solution
```python
seconds = 10_000
hours = seconds // 3600
minutes = seconds % 3600 // 60
secs = seconds % 60
print(hours, minutes, secs)
print(f"{hours}:{minutes:02d}:{secs:02d}")
```

```console
$ python3 hms.py
2 46 40
2:46:40
```

一小时有 $3600$ 秒，所以 `seconds // 3600` 就是小时的整数部分，$2$。剩下的 `seconds % 3600` 是 $2800$ 秒，`2800 // 60` 是 $46$ 个整分钟。秒的部分是 `seconds % 60` $= 40$（直接对总数取模 $60$ 之所以可行，是因为 $3600$ 是 $60$ 的倍数）。验证：$2\cdot3600 + 46\cdot 60 + 40 = 10000$。

字符串 `f"{hours}:{minutes:02d}:{secs:02d}"` 是一个 **f-字符串**（格式化字符串字面量）：每个 `{…}` 被其中表达式的值替换，`:02d` 表示把整数格式化为至少两位数字，不足处补零。
:::
:::

## 浮点数

整数是精确的，但大多数实数无法精确地存放在有限大小的内存里。Python 的 `float` 采用 IEEE 754 标准定义的**双精度**格式（也称 binary64），如今几乎每一台在用的处理器都在硬件中实现了这一标准。

::: definition 二进制浮点数 {#def-float}
精度为 $p$ 的**二进制浮点数**形如

$$
\pm\, (1.b_1 b_2 \ldots b_{p-1})_2 \times 2^{e},
$$

即带 $p$ 个有效二进制位的二进制**尾数**，再乘以一个 2 的幂，其**指数** $e$ 落在一个固定范围内。IEEE 754 双精度取 $p = 53$、$-1022 \le e \le 1023$，存于 64 位之中（1 位符号、11 位指数、52 位小数；最高位的 $1$ 隐含存储），外加一些特殊值：$\pm 0$、$\pm\infty$（`inf`）、“非数”（`nan`）以及极小的**非规格化**数。
:::

因为尾数有 53 位，双精度数大约携带 15 到 17 位有效十进制数字。最大的双精度数约为 $1.8 \times 10^{308}$（Python 的 `1e308 * 10` 给出 `inf`）；$1$ 与下一个双精度数之间的间隔是 $2^{-52} \approx 2.22 \times 10^{-16}$，称为**机器 epsilon**。该标准还规定了算术的行为：每次 `+`、`-`、`*`、`/` 与开方的结果，都是把精确的数学结果**舍入到最近**的可表示双精度数（遇到正中间时舍向末位为偶数的那个）。因此每个单独的运算都是尽可能准确的；误差的来源在于*输入*可能已经被舍入过，以及舍入误差在大量运算中不断累积。

著名的 `0.1 + 0.2` 之弊正出在输入上。像 $0.1$ 这样的十进制小数通常根本无法表示。

::: proposition 十分之一不是二进制小数 {#prop-tenth}
不存在整数 $m$ 与 $k \ge 0$ 使得 $\dfrac{1}{10} = \dfrac{m}{2^k}$。因此 $0.1$ 没有有限的二进制展开，字面量 `0.1` 表示的是一个接近 $1/10$ 但不等于它的双精度数。
:::

::: proof
有限二进制展开 $0.b_1b_2\ldots b_k$ 等于 $m/2^k$，其中 $m = (b_1 b_2 \ldots b_k)_2$ 是整数，所以只需排除 $1/10 = m/2^k$。若该式成立，则 $2^k = 10m = 2 \cdot 5 \cdot m$，于是 $5$ 整除 $2^k$。但 $2^k$ 唯一的素因子是 $2$，而素因数分解是唯一的；矛盾。
:::

同一个论证表明：一个最简分数有有限二进制展开，当且仅当其分母是 2 的幂：$0.5$、$0.25$ 与 $0.375 = 3/8$ 是精确的；$0.1$、$0.2$ 与 $1/3$ 不是。Python 打印的是能舍入回所存双精度数的*最短*十进制串，这就是为什么 `0.1` 显示为 `0.1`，尽管实际存储的值是

$$
0.1000000000000000055511151231257827021181583404541015625,
$$

正如 `decimal.Decimal(0.1)` 所揭示的那样。最接近 $0.1$ 和 $0.2$ 的两个双精度数都略为偏大；它们之和的精确值舍入成双精度数后，恰落在最接近 $0.3$ 的双精度数之上*紧邻*的那一个，而标识这个双精度数的最短字符串就是 `0.30000000000000004`。

::: widget floatline
p: 4
emin: -1
emax: 2
value: 1.1
caption: 一个玩具二进制浮点系统，只有 $p = 4$ 个有效位、指数从 $-1$ 到 $2$，画在数轴上。注意可表示的数在相邻的 2 的幂之间均匀分布，而间隔在每过一个 2 的幂就加倍：浮点数在零附近稠密，远离零就稀疏。给 $x$ 输入别的值，看它贴靠到最近的可表示数；在正常范围内，相对舍入误差不超过机器 epsilon 的一半。双精度就是同一幅图，只是 $p = 53$。
:::

::: example 误差的累积 {#ex-accumulate}
下面的程序打印什么？为什么？

```python
total = 0.0
count = 0
while count < 10:
    total = total + 0.1
    count = count + 1
print(total)
print(total == 1.0)
```
::: solution
```console
$ python3 tenth.py
0.9999999999999999
False
```

十次加法每次都把结果舍入到最近的双精度数，而存储的 `0.1` 本身就不完全对。误差不可能恰好抵消，十次相加之后的总和是 $1$ 之下紧邻的双精度数。因此一个坐等 `total == 1.0` 的循环永远不会停。补救之道是：永远不要对浮点数做精确的相等测试——要么带容差比较，如 `abs(total - 1.0) < 1e-9` 或标准库的 `math.isclose(total, 1.0)`；要么干脆避开浮点数，用整数来计数（十个十分之一最好写成 `count / 10`）。
:::
:::

::: warning 浮点数不能用来存钱
由于十进制小数一般无法精确表示，钱数不应当存成浮点数：`round(2.675, 2)` 给出 `2.67` 而不是 `2.68`，因为最接近 $2.675$ 的双精度数略*低于*它。钱应当存成最小货币单位（便士、分）的整数，或者使用标准模块 `decimal`，它做精确的十进制算术。另外注意 `round` 会把恰好位于正中间的数舍向偶数邻居——`round(2.5)` 是 `2`，`round(3.5)` 是 `4`——这正是 IEEE 754 默认模式要求的“银行家舍入”。
:::

::: quiz
在 Python 中，下列哪些比较的求值结果是 `True`？
- [x] `0.5 + 0.25 == 0.75`
- [ ] `0.1 + 0.2 == 0.3`
- [x] `abs((0.1 + 0.2) - 0.3) < 1e-9`
- [x] `2 ** 53 + 1 == 9007199254740993`
::: solution
$0.5$、$0.25$ 与 $0.75$ 的分母都是 2 的幂，所以三者都是精确的双精度数，求和也被精确计算。`0.1 + 0.2` 是 `0.30000000000000004`，不是最接近 $0.3$ 的双精度数，但二者之差（$5.55\times10^{-17}$）远小于 $10^{-9}$。最后一行是整数运算，任意位数都精确；只有*浮点*字面量 `9007199254740993.0` 会被舍入（舍成 `9007199254740992.0`）。
:::
:::

## 字符串、布尔值与 None

**字符串**（`str`）是字符的序列，写在一对匹配的单引号或双引号之间。在字面量内部，反斜杠引入**转义序列**：`"\n"` 是换行，`"\t"` 是制表符，`"\""` 是双引号，`"\\"` 是反斜杠。字符串支持拼接（`"Ada" + " " + "Lovelace"`）、重复（`"ab" * 3` 是 `'ababab'`）、长度函数（`len("hello")` 是 `5`），以及许多**方法**——方法附属于值、用点号调用，例如 `"snake_case".upper()` 给出 `'SNAKE_CASE'`。字符串将在[[programming-1/sequences]]中正式研究。

类型 `bool` 有两个值，`True` 与 `False`。比较产生布尔值：`3 < 5` 是 `True`，`"apple" == "Apple"` 是 `False`（比较区分大小写），`!=` 表示“不等于”。Python 允许像数学中那样**连续比较**：`1 < x < 10` 的意思是 `1 < x and x < 10`。相等性测试是 `==`；单个 `=` 是赋值，该写哪一个却写了另一个，是一个经典错误，Python 通常会以语法错误拒绝它。

逻辑运算符 `not`、`and` 与 `or` 组合布尔值。它们的优先级（`not` 先于 `and`，`and` 先于 `or`）与算术优先级同样重要。

::: widget truthtable
formula: p | (q & r)
compare: (p | q) & r
caption: Python 如何解读 `p or q and r`。因为 `and` 比 `or` 结合得更紧，它的意思是 `p or (q and r)`——第一个公式——而不是 `(p or q) and r`。真值表显示它们在两行上取值不同（试试 $p$ 为真而 $r$ 为假）。把第二个公式改成 `p | q & r`，确认它与第一个完全一致。
:::

Python 的 `and` 与 `or` 还有两个被反复使用的性质。

::: definition 短路求值与真值性 {#def-short-circuit}
每个值都有一个**真值**：`False`、`None`、零（`0`、`0.0`）以及空容器（`""`、`[]`、`{}`）为**假**；其余一切值为**真**。于是

- `x and y` 先求值 `x`；若 `x` 为假，结果就是 `x`，且 `y` **不被求值**；否则结果是 `y`；
- `x or y` 先求值 `x`；若 `x` 为真，结果就是 `x`，且 `y` 不被求值；否则结果是 `y`；
- `not x` 在 `x` 为假时给出 `True`，否则给出 `False`。
:::

对布尔操作数，这些规则复现了通常的逻辑。短路——第一个操作数已能决定结果时就不求第二个——让第一个操作数可以为第二个保驾护航：`count != 0 and total / count > 10` 永远不会除以零，因为 `count` 为 `0` 时那次除法根本不会执行。真值性规则让 `name or "anonymous"` 成为常见惯用法：当 `name` 可能是空串时，用它给出默认值。

::: example 短路的实例 {#ex-short-circuit}
给出下列每个表达式的值：`0 or "default"`、`5 and 0`、`"" or "default"`、`not 3 or 0`，以及 `False and 1 / 0`。
::: solution
- `0 or "default"`：`0` 为假，所以结果是第二个操作数 `'default'`。
- `5 and 0`：`5` 为真，所以结果是第二个操作数 `0`。
- `"" or "default"`：空串为假，所以是 `'default'`。
- `not 3 or 0`：`not` 结合更紧，所以这是 `(not 3) or 0`；`not 3` 是 `False`，为假，所以结果是 `0`。
- `False and 1 / 0`：`False` 为假，所以结果是 `False`，`1 / 0` 根本不被求值——不会抛 `ZeroDivisionError`。

注意 `and` 与 `or` 返回的是它的某个*操作数*，未必是 `True` 或 `False`。
:::
:::

最后，`None` 是类型 `NoneType` 的唯一值，用来表示“这里什么都没有”：没有显式返回值的函数返回 `None`；变量也可以置为 `None`，表示“尚未确定”。对它测试要用 `x is None` 而不是 `x == None`；运算符 `is` 询问两个名称是否指到*同一个对象*，而 `None` 只有一个。

## 变量与赋值

从第一章起我们就在非正式地使用变量。现在可以精确地说清它们是什么了。

::: definition 变量与赋值 {#def-variable}
**变量**是一个指向（与某个值**绑定的**）名称。**赋值语句** `name = expression` 先求值表达式，再把名称绑定到所得的值上，取代任何此前的绑定。从未绑定过的名称不能使用；对它求值会抛出 `NameError`。
:::

一个有用的图景是：变量是一枚拴在值上的**名字标签**，而不是装值的盒子。运行

```python
a = 10
b = a
a = a + 1
print(a, b)
```

之后程序打印 `11 10`。第二行把标签 `b` 拴到 `a` 当前拴着的那个值上，即 `10`。第三行算出一个*新*值 `11`，把标签 `a` 挪到它上面；`b` 不受影响。对数和字符串而言，盒子图景和标签图景预测的行为相同，因为这类值不能在原地修改。对列表则不然，而这一分歧——称为**别名**——是[[programming-1/sequences]]的核心主题之一。

因为名称是绑定到值上而不是带类型声明的，同一个名称这一刻可以指向一个 `int`，下一刻就指向一个 `str`。这种灵活很方便，但代价是：拼错的名称或意外的类型要等那一行运行时才暴露。

**名称**由字母、数字和下划线组成，不能以数字开头，且区分大小写（`total` 与 `Total` 是两个名称）。Python 3.14 的 35 个**关键字**——如 `if`、`while`、`def`、`True` 与 `None`——不能用作名称。按惯例，变量名用小写字母加下划线（`interest_rate`）；一个好名称说的是这个值*意味着*什么，而不是它是什么类型：`seconds_remaining` 胜过 `n` 或 `int_value`。

**增强赋值**是“用变量的旧值算出新值”这一常见模式的缩写：`x += 3` 意思是 `x = x + 3`，`-=`、`*=`、`/=`、`//=`、`%=` 与 `**=` 同理。`x = 5` 之后依次执行 `x += 3`、`x *= 2`，`x` 的值是 $16$。

### 读取输入

当程序处理运行时提供的数据时，它才真正有用。内置的 `input(prompt)` 打印提示，等待用户键入一行，然后把那一行**作为字符串**返回——永远是字符串，哪怕用户键入的是数字。转换它是程序员的职责：

```python
celsius = float(input("Temperature in Celsius: "))
print(f"{celsius} °C is {celsius * 9 / 5 + 32} °F")
```

```console
$ python3 convert.py
Temperature in Celsius: 21.5
21.5 °C is 70.7 °F
```

若用户键入的不是数，`float` 会抛出 `ValueError`，程序停止；[[programming-1/files-exceptions]]将演示如何优雅地处理这种情况。

::: history
数据类型这一思想有两个源头。伯特兰·罗素（Bertrand Russell）等数学家在二十世纪初把类型引入逻辑，以规避悖论；阿隆佐·丘奇（Alonzo Church）的简单类型λ演算（1940）让每个项都带一个类型。在编程中，FORTRAN（1957）区分了整型与实型（浮点型）变量，ALGOL 60（1960）则把类型声明与精确语法置于语言设计的核心。直到 1985 年的 IEEE 754 标准之前，几乎每家厂商都用自己的方式实现浮点算术；该标准由一个委员会制定，威廉·卡汉（William Kahan）是其中的核心人物，他因数值计算方面的这一贡献获得了 1989 年的图灵奖。该标准在 2008 年和 2019 年两次修订。
:::

## 后续内容

值、运算符与变量已在手中，下一步是让程序会判定、会重复：[[programming-1/control-flow]]引入 `if`、`while` 与 `for`，它们全都由本章的布尔表达式驱动。字符串将在[[programming-1/sequences]]中充分展开。整数与浮点数在内存中作为位模式的表示——补码、定宽整数的溢出、双精度数的精确布局——属于[[computer-systems]]；长串计算中舍入误差的分析则属于数值分析（[数学图谱：浮点数运算](/learn/maths/lesson.php?c=numerical-analysis&l=floating-point)）。

::: summary
- 每个值都有一个**类型**，它规定值代表什么、运算符对它意味着什么；基本类型是 `int`、`float`、`str`、`bool` 与 `NoneType`。Python 是动态类型且强类型的：用 `int()`、`float()` 与 `str()` 显式转换。
- 表达式递归求值，操作数从左到右；**优先级**决定结合方式；`**` 从右结合，且比一元负号结合更紧。拿不准就用括号。
- `/` 是真除法（永远是浮点数）；`//` 是向下取整除法，`%` 是与它配对的余数，$b > 0$ 时满足 $0 \le a \mathbin{\%} b < b$（[[#thm-division]]）。C 与 Java 则向零截断。
- 浮点数是 IEEE 754 双精度：53 位尾数、约 16 位十进制数字、每次运算正确舍入。包括 $0.1$ 在内的大多数十进制小数都无法精确表示（[[#prop-tenth]]），因此绝不对浮点数判等，也绝不用浮点数存钱。
- `and` 与 `or` **短路**，并返回它们的一个操作数；每个值非真即假。
- **变量**是与值绑定的名称；赋值先求值右端，再重新绑定名称。`input()` 永远返回字符串。
:::

## 习题

::: exercise 优先级 {level=1 check="12"}
求值 `2 + 3 * 4 // 5 % 3 + 2 ** 3`，逐步展示。（输入结果值。）
::: solution
先算优先级最高的 `**`：`2 ** 3` 是 `8`，得到 `2 + 3 * 4 // 5 % 3 + 8`。再算 `*`、`//` 与 `%`：同一级，从左到右结合：`3 * 4` 是 `12`，接着 `12 // 5` 是 `2`，再 `2 % 3` 是 `2`，得到 `2 + 2 + 8`。最后从左到右做加法：`12`。加上全部括号，表达式是 `(2 + (((3 * 4) // 5) % 3)) + (2 ** 3)`。
:::
:::

::: exercise 负数的余数 {level=1 check="3"}
在 Python 中计算 `-17 // 5` 与 `-17 % 5`，并验证除法恒等式。（输入 `-17 % 5` 的值。）
::: solution
$-17/5 = -3.4$，$-3.4$ 的 floor 是 $-4$，所以 `-17 // 5` 是 `-4`。于是 `-17 % 5` $= -17 - 5\cdot(-4) = 3$。验证：$5 \cdot (-4) + 3 = -17$ 且 $0 \le 3 < 5$，正如[[#thm-division]]所保证。（在 C 中，`-17 / 5` 是 `-3`，`-17 % 5` 是 `-2`。）
:::
:::

::: exercise 结果的类型 {level=1}
给出下列每个表达式的值与类型：`10 / 5`、`10 // 5`、`"1" + "2"`、`3 * "ab"`、`2 ** -1`、`7 > 3 > 1`、`int(-2.7)`。
::: solution
`10 / 5` 是 `2.0`（`float`：`/` 永远给出浮点数）。`10 // 5` 是 `2`（`int`）。`"1" + "2"` 是 `'12'`（`str`，拼接）。`3 * "ab"` 是 `'ababab'`（`str`）。`2 ** -1` 是 `0.5`（`float`：负的整数指数给出浮点数）。`7 > 3 > 1` 是 `True`（`bool`；它的意思是 `7 > 3 and 3 > 1`）。`int(-2.7)` 是 `-2`（`int`；类型转换向零截断，这一点不同于向小方向取整的 `//`）。
:::
:::

::: exercise 拆分时间长度 {level=2 check="3"}
用 `//` 与 `%` 把 $100{,}000$ 秒换算成天、时、分、秒。（输入小时数。）
::: solution
一天有 $86400$ 秒：`100000 // 86400` 是 $1$ 天，余下 `100000 % 86400` $= 13600$ 秒。接着 `13600 // 3600` 是 $3$ 小时，余下 $13600 - 10800 = 2800$ 秒，即 $46$ 分钟（$2760$ 秒）零 $40$ 秒。所以 $100{,}000$ 秒是 1 天 3 小时 46 分钟 40 秒。用 Python 写：`100000 // 86400`、`100000 % 86400 // 3600`、`100000 % 3600 // 60`、`100000 % 60` 给出 `1 3 46 40`。
:::
:::

::: exercise 短路值 {level=2}
给出下列每个表达式的值，并说明哪些操作数没有被求值：`0 or [] or "x"`、`3 and 4`、`None or 0`、`len("") == 0 or 1 / 0`。
::: solution
- `0 or [] or "x"` 结合为 `(0 or []) or "x"`。`0` 为假，所以 `0 or []` 是 `[]`；`[]` 为假，所以结果是 `'x'`。三个操作数都被求值了。
- `3 and 4`：`3` 为真，所以结果是 `4`。
- `None or 0`：`None` 为假，所以结果是 `0`——它也是假值，但 `or` 原样返回最后一个操作数，并不做转换。
- `len("") == 0 or 1 / 0`：比较的结果是 `True`，所以结果是 `True`，`1 / 0` 根本不被求值。
:::
:::

::: exercise 余数与和 {level=2}
证明：对一切整数 $a$、$b$ 与 $m > 0$，Python 满足 `(a + b) % m == (a % m + b % m) % m`。
::: hint
由[[#thm-division]]，$a = mq_1 + r_1$ 且 $b = mq_2 + r_2$。证明：两个整数除以 $m$ 余数相同，当且仅当它们相差 $m$ 的倍数。
:::
::: solution
先证一条引理：对整数 $x, y$ 与 $m > 0$，$x \mathbin{\%} m = y \mathbin{\%} m$ 当且仅当 $m$ 整除 $x - y$。事实上，设 $x = mq + r$、$y = mq' + r'$，其中 $0 \le r, r' < m$。若 $r = r'$，则 $x - y = m(q - q')$。反之，若 $m \mid x - y$，则 $m$ 整除 $(x - y) - m(q - q') = r - r'$；但 $-m < r - r' < m$，而该范围内 $m$ 的倍数只有 $0$，所以 $r = r'$。

现在令 $r_1 = a \mathbin{\%} m$、$r_2 = b \mathbin{\%} m$，于是 $a = mq_1 + r_1$、$b = mq_2 + r_2$。那么 $(a + b) - (r_1 + r_2) = m(q_1 + q_2)$ 是 $m$ 的倍数，由引理 $(a+b) \mathbin{\%} m = (r_1 + r_2)\mathbin{\%} m$，此即所求。同样的论证对乘积也成立。这就是为什么“模 $m$”工作的程序（钟表算术、哈希函数、校验和）可以在每一步都把中间结果缩小、让数字保持很小。
:::
:::

::: exercise 二进制小数的精确表示 {level=2 check="4"}
十进制数 $0.5$、$0.25$、$0.1$、$0.75$、$0.2$ 与 $0.375$ 中，哪些能被 Python 的浮点数精确表示？（输入其个数。）
::: solution
一个最简分数是有限二进制小数，当且仅当其分母是 2 的幂（[[#prop-tenth]]的论证给出了“仅当”；“当”则因为 $m/2^k$ 可以写成 $k$ 位二进制小数）。$0.5 = 1/2$、$0.25 = 1/4$、$0.75 = 3/4$ 与 $0.375 = 3/8$ 符合条件，而且全都轻松放进 53 位；$0.1 = 1/10$ 与 $0.2 = 1/5$ 不符合。所以四个是精确的。你可以用 `(0.375).as_integer_ratio()` 验证，它给出 `(3, 8)`；而 `(0.1).as_integer_ratio()` 给出 `(3602879701896397, 36028797018963968)`——一个分母为 $2^{55}$、接近却不等于 $1/10$ 的分数。
:::
:::

::: exercise 最大安全整数 {level=3 check="2^53"}
证明每个满足 $0 \le n \le 2^{53}$ 的整数 $n$ 都能精确表示为 IEEE 754 双精度数，而 $2^{53} + 1$ 不能。（输入 $2^{53}$，即使得 $0, 1, \dots, N$ 全体可表示的最大 $N$。）
::: solution
零是一个特殊值。正整数 $n < 2^{53}$ 至多有 53 个二进制位，$n = (1 b_1 \ldots b_{k})_2$，$k \le 52$，于是 $n = (1.b_1\ldots b_k)_2 \times 2^{k}$：尾数至多 53 位，指数 $k \le 52$，远在范围之内，所以可表示。$2^{53} = 1.0 \times 2^{53}$ 也可表示。但 $2^{53} + 1 = (1\underbrace{0\cdots0}_{52}1)_2$ 有 54 个有效位，首位与末位都是 $1$；53 位的尾数装不下它。在指数 $53$ 处，相邻双精度数的间隔是 $2^{53-52} = 2$，所以 $2^{53}+1$ 恰好在 $2^{53}$ 与 $2^{53}+2$ 的正中间，（按向偶数舍入）舍成 $2^{53}$。在 Python 中，`float(2**53 + 1)` 是 `9007199254740992.0`。JavaScript 唯一的数值类型就是双精度数，它把 $2^{53} - 1$ 叫做 `Number.MAX_SAFE_INTEGER`。
:::
:::

::: exercise 正确地格式化金额 {level=3}
一个程序把金额存成以整便士计的整数。写一个函数 `show_pounds(pence)`，使它例如对 `1234` 返回 `'£12.34'`，对 `5` 返回 `'£0.05'`，对 `-150` 返回 `'-£1.50'`。并解释为什么那个看起来最自然的 `f"£{pence // 100}.{pence % 100:02d}"` 对负金额是错的。
::: solution
```python
def show_pounds(pence):
    """Format a whole number of pence as pounds, e.g. -150 -> '-£1.50'."""
    sign = "-" if pence < 0 else ""
    pounds, rest = divmod(abs(pence), 100)   # 先按绝对值拆分，最后补回符号
    return f"{sign}£{pounds}.{rest:02d}"

print(show_pounds(1234))
print(show_pounds(5))
print(show_pounds(-150))
print(-150 // 100, -150 % 100)   # 天真写法为什么出错
```

```console
$ python3 pence.py
£12.34
£0.05
-£1.50
-2 50
```

按向下取整除法，$-150$ 便士拆成 $-2$ 镑加 $50$ 便士（$-200 + 50 = -150$），这在数学上没错，但会被打印成 `£-2.50`——一个不同的金额。先取绝对值、再拆分、最后补回符号，就避开了这个问题。（表达式 `"-" if pence < 0 else ""` 是一个**条件表达式**，将在[[programming-1/control-flow]]中引入。）
:::
:::
