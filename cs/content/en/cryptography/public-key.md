A company with $1000$ employees who all need to talk privately in pairs would, with symmetric cryptography alone, need $\binom{1000}{2} = 499\,500$ shared keys, each delivered securely in advance — and a website that wants to talk privately with every browser in the world could not do it at all. Public-key cryptography removes the need for a pre-shared secret. In **key exchange**, two parties who share nothing agree on a secret key while an eavesdropper watches every message. In **public-key encryption**, each party publishes a **public key** with which anyone can encrypt, and keeps a **private key** with which only they can decrypt.

This chapter develops both, using the number theory of [[cryptography/number-theory]]. We prove Diffie–Hellman key exchange secure against eavesdroppers under the DDH assumption, define security for public-key encryption, prove ElGamal encryption CPA-secure, and study RSA — first in the "textbook" form that is fast, simple, and insecure, then with the OAEP padding that makes it CCA-secure. We then meet elliptic curves, computing the group law on a toy curve by hand, and finish with hybrid encryption, which is how public-key encryption is actually used. Every number in this chapter is tiny so that you can check it by hand; it is a teaching toy, and real code must use a vetted library.

## Diffie–Hellman key exchange

Let $G$ be a cyclic group of prime order $q$ with generator $g$, all public — in practice an elliptic-curve group, or the subgroup of squares modulo a safe prime.

::: algorithm Diffie–Hellman key exchange {#alg-dh}
1. Alice chooses a uniform $x \in \Z_q$ and sends $h_A = g^x$.
2. Bob chooses a uniform $y \in \Z_q$ and sends $h_B = g^y$.
3. Alice computes $k = h_B^{\,x}$; Bob computes $k = h_A^{\,y}$. Both obtain $k = g^{xy}$.
:::

Correctness is $(g^y)^x = g^{xy} = (g^x)^y$. An eavesdropper sees $g$, $g^x$ and $g^y$; computing $g^{xy}$ from them is exactly the CDH problem ([[cryptography/number-theory#def-dlog]]). For a key to be *used*, though, we want more than "hard to compute": the key should be indistinguishable from random, so that using it in, say, AES-GCM is as good as using a uniform key.

::: definition Key-exchange security against eavesdroppers {#def-ke-eav}
In the experiment $\mathsf{KE}^{\mathsf{eav}}_{\mathcal A, \Pi}(n)$, the parties run protocol $\Pi$ on security parameter $n$, producing a transcript $\mathit{trans}$ and a key $k$. A uniform bit $b$ is chosen; if $b = 0$ let $\hat k = k$, and if $b = 1$ let $\hat k$ be uniform in the key space. $\mathcal A$ is given $(\mathit{trans}, \hat k)$ and outputs $b'$. $\Pi$ is **secure in the presence of an eavesdropper** if every PPT $\mathcal A$ guesses $b$ with probability at most $\tfrac12 + \mathsf{negl}(n)$.
:::

::: theorem Diffie–Hellman is secure against eavesdroppers {#thm-dh}
If DDH is hard relative to the group generator $\mathcal G$, then Diffie–Hellman key exchange (with keys in $G$) is secure in the presence of an eavesdropper.
:::

::: proof
Let $\mathcal A$ be an adversary. Build a DDH distinguisher $D$ that, given $(G, q, g, h_1, h_2, h_3)$, runs $\mathcal A$ on the transcript $(G, q, g, h_1, h_2)$ and key $\hat k = h_3$, and outputs $1$ if $\mathcal A$ says "real" ($b' = 0$). If $(h_1, h_2, h_3) = (g^x, g^y, g^{xy})$, $\mathcal A$ sees exactly the case $b = 0$; if $h_3 = g^z$ is uniform, it sees exactly the case $b = 1$. Hence
$$
\Prob[\mathcal A \text{ succeeds}] = \tfrac12\Prob[b' = 0 \mid b = 0] + \tfrac12\Prob[b' = 1 \mid b = 1] = \tfrac12 + \tfrac12\Big(\Prob[D(\text{real}) = 1] - \Prob[D(\text{random}) = 1]\Big),
$$
which is at most $\tfrac12 + \tfrac12\mathsf{negl}(n)$.
:::

In practice the group element $g^{xy}$ is fed through a key-derivation function (HKDF, [[cryptography/protocols]]) to produce bit-string keys; that step is also what lets protocols use groups in which only CDH, not DDH, is believed hard.

::: example Diffie–Hellman with toy numbers {#ex-dh}
Use $p = 23$ and $g = 5$ (a generator of $\Z_{23}^*$), with Alice's secret $x = 6$ and Bob's secret $y = 15$. What do they send, and what key do they agree on?
::: solution
Alice sends $h_A = 5^6 \bmod 23$: $5^2 = 25 \equiv 2$, $5^4 \equiv 4$, $5^6 \equiv 4 \cdot 2 = 8$. Bob sends $h_B = 5^{15} \bmod 23 = 19$. Alice computes $19^6 \bmod 23 = 2$ and Bob computes $8^{15} \bmod 23 = 2$. The shared key is $2$.

```python
p, g = 23, 5                       # toy parameters: utterly insecure
x, y = 6, 15
hA, hB = pow(g, x, p), pow(g, y, p)
print(hA, hB, pow(hB, x, p), pow(hA, y, p))
```

```console
$ python3 dh.py

```

Eve sees $8$ and $19$ and could find $x$ by trying all $22$ exponents. Note also that $\Z_{23}^*$ has even order $22$, so DDH fails in it ([[cryptography/number-theory#ex-ddh-zp]]); a careful toy would use the subgroup of order $11$ generated by $4$. Real deployments use groups of order about $2^{256}$, such as the elliptic curve X25519.

### Man in the middle

[[#thm-dh]] is about *eavesdroppers*. An active attacker Mallory who can intercept and replace messages runs one exchange with Alice (posing as Bob) and another with Bob (posing as Alice), ending up with a key shared with each, and relays — and reads — everything. Nothing in the bare protocol lets Alice tell Bob's $g^y$ from Mallory's $g^{y'}$. The defence is **authentication**: Bob signs his share with a long-term key whose public half Alice already trusts, through a certificate. Signatures are the subject of [[cryptography/signatures]], and authenticated key exchange as in TLS 1.3 of [[cryptography/protocols]].

## Public-key encryption

::: definition Public-key encryption {#def-pke}
A **public-key encryption scheme** consists of PPT algorithms $\mathsf{Gen}$, $\mathsf{Enc}$, $\mathsf{Dec}$: $\mathsf{Gen}(1^n)$ outputs a key pair $(pk, sk)$; $\mathsf{Enc}_{pk}(m)$ outputs a ciphertext; $\mathsf{Dec}_{sk}(c)$ outputs a message or $\bot$. Correctness: $\mathsf{Dec}_{sk}(\mathsf{Enc}_{pk}(m)) = m$ except with negligible probability over $\mathsf{Gen}$.

In the experiment $\mathsf{PubK}^{\mathsf{cpa}}_{\mathcal A, \Pi}(n)$, $(pk, sk) \gets \mathsf{Gen}(1^n)$; $\mathcal A$ is given $pk$ and outputs equal-length $m_0, m_1$; it receives $c \gets \mathsf{Enc}_{pk}(m_b)$ and outputs $b'$. $\Pi$ is **CPA-secure** if every PPT $\mathcal A$ succeeds with probability at most $\tfrac12 + \mathsf{negl}(n)$. In $\mathsf{PubK}^{\mathsf{cca}}$ the adversary also has an oracle for $\mathsf{Dec}_{sk}(\cdot)$, which it may not query on $c$; this defines **CCA-security**.
:::

No encryption oracle appears: the adversary has $pk$ and can encrypt anything itself, so in the public-key world eavesdropper security and CPA-security coincide. It follows, as in [[cryptography/block-ciphers#prop-det-cpa]], that **deterministic public-key encryption is never CPA-secure** — an adversary encrypts $m_0$ itself and compares — and this holds even for a single message. Another standard result, proved by a hybrid argument, is that CPA-security for one message implies CPA-security for many.

### ElGamal encryption

ElGamal (1985) turns Diffie–Hellman into encryption: the recipient's public key is a fixed half $h = g^x$ of an exchange, and each encryption performs the other half with fresh randomness and uses the resulting $h^y$ as a one-time pad in the group.

::: definition ElGamal encryption {#def-elgamal}
$\mathsf{Gen}$ obtains $(G, q, g)$, chooses a uniform $x \in \Z_q$, and outputs $pk = (G, q, g, h)$ with $h = g^x$ and $sk = x$. For a message $m \in G$, $\mathsf{Enc}_{pk}(m)$ chooses a uniform $y \in \Z_q$ and outputs $\langle c_1, c_2\rangle = \langle g^y,\ h^y\cdot m\rangle$. $\mathsf{Dec}_{sk}(\langle c_1, c_2\rangle) = c_2 \cdot (c_1^{\,x})^{-1}$.
:::

Correctness: $c_2/c_1^{\,x} = g^{xy}m/g^{xy} = m$.

::: theorem ElGamal is CPA-secure {#thm-elgamal}
If DDH is hard relative to $\mathcal G$, ElGamal encryption is CPA-secure.
:::

::: proof
First consider a modified scheme $\tilde\Pi$ in which $c_2 = g^z\cdot m$ for a uniform $z$ independent of everything else. Since $g^z$ is uniform in $G$ and multiplication by $m$ is a bijection of $G$, $c_2$ is uniform whatever $m$ is, and $c_1 = g^y$ is independent of $m$. So the ciphertext carries no information about $b$, and any adversary succeeds with probability exactly $\tfrac12$ against $\tilde\Pi$ — it is a one-time pad in the group.

Now let $\mathcal A$ attack ElGamal. The DDH distinguisher $D(G, q, g, h_1, h_2, h_3)$ sets $pk = (G, q, g, h_1)$, runs $\mathcal A(pk)$ to obtain $m_0, m_1$, chooses $b$, gives $\mathcal A$ the ciphertext $\langle h_2, h_3\cdot m_b\rangle$, and outputs $1$ iff $\mathcal A$ outputs $b$. On a real triple $(g^x, g^y, g^{xy})$ the ciphertext is a genuine ElGamal encryption under $pk$ with randomness $y$; on a random triple it is an encryption under $\tilde\Pi$. Hence
$$
\Prob[\mathsf{PubK}^{\mathsf{cpa}}_{\mathcal A, \mathrm{ElGamal}}(n) = 1] - \tfrac12 = \Prob[D(\text{real}) = 1] - \Prob[D(\text{random}) = 1] \le \mathsf{negl}(n). 
$$
:::

ElGamal ciphertexts are twice as long as messages, and messages must be group elements. It is also **malleable**: from $\langle c_1, c_2\rangle$ anyone can form $\langle c_1, c_2\cdot g\rangle$, an encryption of $m\cdot g$, so it is not CCA-secure ([[#ex-elgamal-cca]]). Malleability is occasionally a feature — it makes ElGamal **homomorphic**, useful in electronic voting — but for general encryption we need CCA-security.

::: example ElGamal in a group of order 11 {#ex-elgamal}
Work in the subgroup of order $q = 11$ of $\Z_{23}^*$ generated by $g = 4$. Bob's private key is $x = 7$. Compute his public key, encrypt $m = 9$ (an element of the subgroup) with randomness $y = 3$, and decrypt.
::: solution
$h = 4^7 \bmod 23 = 8$ (the powers of $4$ are $1, 4, 16, 18, 3, 12, 2, 8, \dots$). Encryption: $c_1 = 4^3 = 64 \equiv 18$; $h^y = 8^3 = 512 \equiv 6$, so $c_2 = 6\cdot 9 = 54 \equiv 8$. The ciphertext is $\langle 18, 8\rangle$. Decryption: $c_1^{\,x} = 18^7 \bmod 23 = 6$, whose inverse is $4$ (as $6 \cdot 4 = 24 \equiv 1$), and $c_2\cdot 6^{-1} = 8 \cdot 4 = 32 \equiv 9 = m$. Alternatively, since $c_1$ has order dividing $11$, $c_1^{-x} = c_1^{\,q - x} = 18^4$, avoiding the inversion. A second encryption of the same $m$ with $y = 5$ would give a completely different ciphertext — randomised encryption, as CPA-security requires.

```python
p, q, g, x = 23, 11, 4, 7          # toy parameters only
h = pow(g, x, p)
y, m = 3, 9
c1, c2 = pow(g, y, p), m * pow(h, y, p) % p
print(h, c1, c2, c2 * pow(c1, q - x, p) % p)
```

```console
$ python3 elgamal.py

```

## RSA

RSA (Rivest, Shamir and Adleman, 1977; published 1978) uses the group $\Z_N^*$ for $N = pq$, whose order $\phi(N) = (p-1)(q-1)$ is known to whoever chose $p$ and $q$.

::: definition RSA key generation and the RSA problem {#def-rsa}
$\mathsf{GenRSA}(1^n)$ chooses distinct uniform $n$-bit primes $p, q$, sets $N = pq$ and $\phi(N) = (p-1)(q-1)$, chooses $e > 1$ with $\gcd(e, \phi(N)) = 1$, computes $d = e^{-1} \bmod \phi(N)$, and outputs $(N, e, d)$. The **RSA problem** is hard if for every PPT $\mathcal A$,
$$
\Prob\big[\mathcal A(N, e, y) = x \text{ with } x^e \equiv y \pmod N\big] \le \mathsf{negl}(n),
$$
where $(N, e, d) \gets \mathsf{GenRSA}(1^n)$ and $y$ is uniform in $\Z_N^*$.
:::

By [[cryptography/number-theory#cor-eth-root]], $x \mapsto x^e$ is a permutation of $\Z_N^*$ with inverse $y \mapsto y^d$: easy to compute in both directions with $d$, and — under the RSA assumption — hard to invert without it. It is a **trapdoor permutation**. Knowing $d$ is as good as knowing the factors (there is an efficient randomised algorithm that factors $N$ given $e$ and $d$), so the RSA assumption implies the factoring assumption; whether the converse holds is open.

::: definition Textbook RSA {#def-textbook-rsa}
The public key is $(N, e)$ and the private key is $d$. Encrypt $m \in \Z_N$ as $c = m^e \bmod N$, and decrypt as $m = c^d \bmod N$.
:::

::: proposition Textbook RSA decrypts correctly {#prop-rsa-correct}
For every $m \in \Z_N$ (not only $m \in \Z_N^*$), $(m^e)^d \equiv m \pmod N$.
:::

::: proof
Write $ed = 1 + k(p-1)(q-1)$ with $k \ge 0$. Modulo $p$: if $p \mid m$, both sides are $0$; otherwise Fermat gives $m^{ed} = m\cdot(m^{p-1})^{k(q-1)} \equiv m$. Likewise modulo $q$. Since $m^{ed} \equiv m$ modulo both $p$ and $q$, the Chinese remainder theorem ([[cryptography/number-theory#thm-crt]]) gives $m^{ed} \equiv m \pmod N$.
:::

::: example RSA with toy numbers {#ex-rsa}
Let $p = 61$, $q = 53$ and $e = 17$. Compute $N$, $\phi(N)$ and $d$; encrypt $m = 65$; decrypt, both directly and with the CRT.
::: solution
$N = 3233$, $\phi(N) = 60 \cdot 52 = 3120$, and $d = 17^{-1} \bmod 3120 = 2753$ ([[cryptography/number-theory#ex-egcd]]). Encryption: $c = 65^{17} \bmod 3233 = 2790$. Decryption: $2790^{2753} \bmod 3233 = 65$.

With the CRT the private-key holder works modulo the primes, with exponents reduced modulo $p - 1$ and $q - 1$: $d_p = d \bmod 60 = 53$ and $d_q = d \bmod 52 = 49$. Then $m_p = 2790^{53} \bmod 61 = 4$ and $m_q = 2790^{49} \bmod 53 = 12$. Recombine with $q^{-1} \bmod p = 38$: $h = 38(m_p - m_q) \bmod 61 = 38\cdot(-8) \bmod 61 = 1$, and $m = m_q + hq = 12 + 53 = 65$.

```python
p, q, e = 61, 53, 17                  # textbook toy key: insecure
N, phi = p * q, (p - 1) * (q - 1)
d = pow(e, -1, phi)
c = pow(65, e, N)
mp, mq = pow(c, d % (p - 1), p), pow(c, d % (q - 1), q)
h = pow(q, -1, p) * (mp - mq) % p
print(N, phi, d, c, pow(c, d, N), mq + h * q)
```

```console
$ python3 rsa_toy.py

```

Exponentiations modulo $p$ and $q$ use numbers half as long and exponents half as long, so with schoolbook arithmetic each costs about one eighth of an exponentiation modulo $N$; two of them make CRT decryption about four times faster. Every RSA library uses it.

### Why textbook RSA is insecure

Textbook RSA is a trapdoor permutation, not an encryption scheme, and using it directly fails in several ways:

1. **It is deterministic**, so it is not CPA-secure. If the message is known to be "yes" or "no", or a 4-digit PIN, an eavesdropper encrypts each candidate under the public key and compares.
2. **It is malleable**: $(m_1m_2)^e = m_1^e m_2^e$, so from $c = m^e$ anyone can make $c\cdot 2^e$, an encryption of $2m$. With the toy key, $2790\cdot 2^{17} \bmod 3233 = 3017$ decrypts to $130$. An attacker with any decryption oracle — even a partial one — can exploit this.
3. **Small messages leak.** With $e = 3$ and $m < N^{1/3}$, no reduction modulo $N$ takes place, and $m$ is simply the integer cube root of $c$. The same message sent to three recipients with $e = 3$ can be recovered by the CRT (Håstad's broadcast attack).
4. **The RSA assumption is about random $y$.** It promises nothing for structured messages — small ones, or ones sharing known bits — and also says nothing about partial information such as the parity of $m$.

The cure is to **pad** the message with randomness and redundancy before applying the permutation. The older PKCS#1 v1.5 padding (random non-zero bytes after a fixed header) is randomised, but in 1998 Daniel Bleichenbacher showed that a server revealing whether a decrypted value has the correct header format is a padding oracle that lets an attacker decrypt any ciphertext with on the order of a million queries — the public-key analogue of [[cryptography/block-ciphers]]' padding oracles. Variants of the attack have recurred in deployed systems for two decades. TLS 1.3 removed RSA encryption for key transport entirely.

### RSA-OAEP

::: definition RSA-OAEP {#def-oaep}
Let $G$ and $H$ be hash functions (in practice built from SHA-256 by the mask-generation function of PKCS#1). To encrypt $m$, choose a uniform $k_0$-bit string $r$ and compute
$$
s = (m \,\|\, 0^{k_1}) \oplus G(r), \qquad t = r \oplus H(s), \qquad c = (s \,\|\, t)^e \bmod N .
$$
To decrypt, compute $s \,\|\, t = c^d \bmod N$, then $r = t \oplus H(s)$ and $m \,\|\, z = s \oplus G(r)$; output $m$ if $z = 0^{k_1}$, and $\bot$ otherwise.
:::

OAEP (**optimal asymmetric encryption padding**; Bellare and Rogaway, 1994) is a two-round Feistel network keyed by hash functions. The random $r$ makes encryption randomised; the redundancy $0^{k_1}$ means that a ciphertext not produced by the encryption algorithm almost certainly decrypts to $\bot$, so a decryption oracle reveals nothing useful. Fujisaki, Okamoto, Pointcheval and Stern (2001) proved RSA-OAEP CCA-secure under the RSA assumption **in the random-oracle model**, in which $G$ and $H$ are modelled as truly random functions (Bellare and Rogaway's original argument had a gap, found by Shoup in 2001). It is standardised in PKCS#1 v2.2 (RFC 8017). Even so, implementations must make all decryption failures indistinguishable, in content and timing — Manger (2001) described an oracle attack on OAEP implementations that leaked *which* check failed.

::: warning Never use textbook RSA, and never roll your own padding
Every weakness listed above has broken real systems: unpadded or ad hoc padded RSA, $e = 3$ with short messages, distinguishable padding errors, and keys generated with poor randomness (in 2012 two research groups independently found that a fraction of a percent of RSA keys on the public internet shared a prime factor with another key, so that both could be factored with a gcd). The safe pattern is to use a vetted library's RSA-OAEP or, better for most purposes, its hybrid encryption based on elliptic-curve Diffie–Hellman. The toy code in this chapter is for checking calculations only.
:::

::: quiz
Alice encrypts her vote, `YES` or `NO`, with textbook RSA under the election authority's public key and posts the ciphertext publicly. What can an observer learn?

- [ ] Nothing without factoring $N$.
- [x] Her vote: the observer encrypts both possible votes itself and compares.
- [ ] Only the length of her vote.
- [ ] Her vote, but only if $e = 3$.
::: solution
Textbook RSA is deterministic, and the public key lets anyone encrypt. With only two possible plaintexts, the observer computes `YES`$^e$ and `NO`$^e$ modulo $N$ and sees which matches; no factoring is needed and the size of $e$ is irrelevant. Randomised padding such as OAEP prevents this.

## Elliptic curves

The groups $\Z_p^*$ admit index-calculus attacks, so their elements must be thousands of bits long. Elliptic-curve groups, proposed for cryptography independently by Neal Koblitz and Victor Miller in 1985, have no known attack better than the generic $\sqrt q$ methods (for well-chosen curves), so elements of about $256$ bits give 128-bit security.

::: definition Elliptic curve over a prime field {#def-ec}
Let $p > 3$ be prime and $a, b \in \Z_p$ with $4a^3 + 27b^2 \not\equiv 0 \pmod p$. The **elliptic curve** $E(\Z_p)$ is the set of solutions $(x, y) \in \Z_p^2$ of $y^2 = x^3 + ax + b$, together with a **point at infinity** $\mathcal O$. The group law, written additively, has identity $\mathcal O$ and $-(x, y) = (x, -y)$. For points $P_1 = (x_1, y_1)$, $P_2 = (x_2, y_2)$ with $P_2 \ne -P_1$, let
$$
\lambda = \begin{cases} \dfrac{y_2 - y_1}{x_2 - x_1} & P_1 \ne P_2,\\[2mm] \dfrac{3x_1^2 + a}{2y_1} & P_1 = P_2, \end{cases}
$$
and set $P_1 + P_2 = (x_3, y_3)$ with $x_3 = \lambda^2 - x_1 - x_2$ and $y_3 = \lambda(x_1 - x_3) - y_1$; and $P + (-P) = \mathcal O$.
:::

Over the real numbers the formulas have a geometric meaning: the line through $P_1$ and $P_2$ (the tangent if they are equal) meets the curve in a third point, and $P_1 + P_2$ is that point reflected in the $x$-axis. The condition on $a$ and $b$ excludes singular curves. That this operation is associative — and so makes $E(\Z_p)$ an abelian group — is a classical theorem whose proof is long (by computation, or through algebraic geometry); we use it without proof. By **Hasse's theorem** the number of points satisfies $\lvert\#E(\Z_p) - (p + 1)\rvert \le 2\sqrt p$.

Cryptography uses the same formulas over $\Z_p$, where the "curve" is a scattered set of points.

::: example Arithmetic on a toy curve {#ex-ec}
On $E\colon y^2 = x^3 + 2x + 2$ over $\Z_{17}$, let $G = (5, 1)$. Check that $G$ is on the curve, compute $2G$ and $3G$, and find the order of $G$.
::: solution
$G$ is on the curve: $1^2 = 1$ and $5^3 + 2\cdot 5 + 2 = 137 = 8 \cdot 17 + 1 \equiv 1$.

$2G$: $\lambda = (3\cdot 5^2 + 2)/(2\cdot 1) = 77/2$. Modulo $17$, $77 \equiv 9$ and $2^{-1} \equiv 9$, so $\lambda = 81 \equiv 13$. Then $x_3 = 13^2 - 5 - 5 = 159 \equiv 6$ and $y_3 = 13(5 - 6) - 1 = -14 \equiv 3$. So $2G = (6, 3)$.

$3G = 2G + G$: $\lambda = (1 - 3)/(5 - 6) = (-2)/(-1) = 2$; $x_3 = 4 - 6 - 5 = -7 \equiv 10$; $y_3 = 2(6 - 10) - 3 = -11 \equiv 6$. So $3G = (10, 6)$.

A program continues the sequence:

```python
P_MOD, A = 17, 2                     # toy curve y^2 = x^3 + 2x + 2 over Z_17

def ec_add(P, Q):
    """Add points on the toy curve; None is the point at infinity."""
    if P is None: return Q
    if Q is None: return P
    (x1, y1), (x2, y2) = P, Q
    if x1 == x2 and (y1 + y2) % P_MOD == 0:
        return None                                   # P + (-P) = O
    if P == Q:
        lam = (3 * x1 * x1 + A) * pow(2 * y1, -1, P_MOD) % P_MOD
    else:
        lam = (y2 - y1) * pow(x2 - x1, -1, P_MOD) % P_MOD
    x3 = (lam * lam - x1 - x2) % P_MOD
    return (x3, (lam * (x1 - x3) - y1) % P_MOD)

R, G = None, (5, 1)
for k in range(1, 20):
    R = ec_add(R, G)
    print(k, R)
```

Scalar multiplication $kP$ uses **double-and-add**, the additive form of square-and-multiply, in $O(\log k)$ group operations; the **elliptic-curve discrete-logarithm problem** is to recover $k$ from $P$ and $kP$. Elliptic-curve Diffie–Hellman (ECDH) is [[#alg-dh]] in this group: on the toy curve, Alice with secret $3$ sends $3G = (10, 6)$, Bob with secret $7$ sends $7G = (0, 6)$, and both compute $21G = 2G = (6, 3)$. Widely used curves as of 2026 are NIST P-256 (FIPS 186) and Curve25519 (Bernstein, 2006), whose Diffie–Hellman function X25519 is specified in RFC 7748; both have groups of prime order about $2^{252}$–$2^{256}$. Curve25519 was designed so that simple implementations are naturally constant-time and every 32-byte string is a valid public key, avoiding a class of attacks in which a peer sends a point that is not on the intended curve. With other curves, implementations must check that received points lie on the curve.

::: quiz
On the toy curve of [[#ex-ec]], Bob's public key is $Q = 5G = (9, 16)$. Which statement is true?

- [ ] Bob's private key could be any of $5, 24, 43, \dots$, and these give different decryptions.
- [x] Finding Bob's private key means solving a discrete logarithm in a group of order $19$, which here takes at most $19$ trials.
- [ ] Because the curve is over $\Z_{17}$, there are $17$ possible private keys.
- [ ] $-Q = (9, -16)$ is not on the curve, so Bob's key is invalid.
::: solution
The group has prime order $19$, so private keys live in $\Z_{19}$; $5, 24, 43, \dots$ all give the same point and behave identically. Recovering $5$ from $(9, 16)$ is the ECDLP, trivial for a group of $19$ elements and infeasible for one of $2^{256}$. The field size $17$ is not the group order, and $-Q = (9, -16) = (9, 1)$ is on the curve (it is $14G$).
:::
:::

### Parameter sizes

The generic and special-purpose attacks of [[cryptography/number-theory]] determine how large keys must be for a given security level, and the result is very different for the three families. The table follows NIST SP 800-57 Part 1 (as of 2026), which matches other national recommendations closely:

| security level | symmetric key | RSA modulus / finite-field $p$ | elliptic-curve group order |
|---|---|---|---|
| 112 bits | 112 | 2048 | 224 |
| 128 bits | 128 | 3072 | 256 |
| 192 bits | 192 | 7680 | 384 |
| 256 bits | 256 | 15 360 | 512 |

The elliptic-curve column grows linearly (twice the security level, because of the $\sqrt q$ generic attacks), while the RSA column grows much faster, because the number field sieve is subexponential.

::: example What the sizes cost {#ex-sizes}
At the 128-bit level, compare the size in bytes of (a) an RSA-3072 public modulus and an RSA-OAEP ciphertext, (b) an ElGamal ciphertext in a 3072-bit finite-field group, and (c) an X25519 public key and the encapsulation sent by an elliptic-curve KEM.
::: solution
(a) The modulus has $3072$ bits $= 384$ bytes, and every RSA ciphertext is an element of $\Z_N$, also $384$ bytes, however short the message. (b) An ElGamal ciphertext is two group elements, $2 \times 384 = 768$ bytes. (c) An X25519 public key is $32$ bytes, and an ECDH-based KEM sends one point, $32$ bytes. Elliptic-curve operations at this level are also much faster than RSA decryption with a 3072-bit modulus (which costs roughly $(3072/2)^3$-proportional work per CRT half), though RSA *encryption* with $e = 65537$ is cheap: $17$ modular multiplications. These are the reasons that, as of 2026, elliptic-curve Diffie–Hellman is the default key exchange in TLS and SSH, with RSA mainly surviving in signatures and certificates.
:::
:::

## Hybrid encryption

Public-key operations are thousands of times slower than AES, and their messages are short and structured. Real systems therefore use **hybrid encryption**: a public-key **key-encapsulation mechanism** (KEM) produces a fresh symmetric key $k$ together with an encapsulation of it, and a symmetric authenticated-encryption scheme (the **data-encapsulation mechanism**) encrypts the actual data under $k$. With an elliptic-curve KEM the recipient's public key is $Q = xG$; the sender chooses $y$, sends $yG$, and derives $k$ by hashing the shared point $yQ = xyG$. If the KEM is CCA-secure and the symmetric scheme is an authenticated encryption scheme, the combination is CCA-secure (Cramer and Shoup, 2003). This is the structure of ECIES, of HPKE (RFC 9180, 2022), and — in interactive form — of the TLS 1.3 handshake. The post-quantum KEM ML-KEM ([[cryptography/post-quantum]]) slots into the same structure.

::: history
In 1976 Whitfield Diffie and Martin Hellman published "New directions in cryptography" (*IEEE Transactions on Information Theory*), introducing public-key cryptography and their key-exchange protocol; Ralph Merkle had independently devised a public-key scheme ("Merkle's puzzles") as a student. Ron Rivest, Adi Shamir and Leonard Adleman found RSA in 1977 (*Communications of the ACM*, 1978). At the British GCHQ, James Ellis (1970), Clifford Cocks (1973) and Malcolm Williamson (1974) had found equivalent ideas in secret, revealed only in 1997. Michael Rabin (1979) gave a scheme provably as hard as factoring; Shafi Goldwasser and Silvio Micali (1984) gave the first provably CPA-secure public-key encryption; Taher ElGamal published his scheme in 1985; and Neal Koblitz and Victor Miller independently proposed elliptic-curve cryptography the same year. Mihir Bellare and Phillip Rogaway introduced OAEP and the random-oracle methodology in 1993–1994, and Ronald Cramer and Victor Shoup gave the first practical CCA-secure scheme without random oracles in 1998.
:::

## Where this leads

Public-key encryption gives confidentiality without a shared secret, but not authenticity: anyone can encrypt to Bob, and nothing yet stops Mallory from replacing Bob's public key with her own. [[cryptography/signatures]] supplies digital signatures (RSA with hash-and-sign, Schnorr, ECDSA) and the certificates that bind public keys to names. [[cryptography/protocols]] combines Diffie–Hellman, signatures and AEAD into the authenticated key exchange of TLS 1.3. And [[cryptography/post-quantum]] explains why Shor's algorithm breaks everything in this chapter — factoring, finite-field and elliptic-curve discrete logarithms — and what replaces it.

::: summary
- **Diffie–Hellman** key exchange sends $g^x$ and $g^y$ and agrees on $g^{xy}$ ([[#alg-dh]]); it is secure against eavesdroppers under DDH ([[#thm-dh]]), but not against a man in the middle without authentication.
- **Public-key encryption** is CPA-secure if no adversary holding $pk$ can distinguish encryptions ([[#def-pke]]); deterministic schemes never are. CCA-security adds a decryption oracle.
- **ElGamal** encrypts $m$ as $\langle g^y, h^y m\rangle$ and is CPA-secure under DDH ([[#thm-elgamal]]), but malleable.
- **RSA**: $N = pq$, $ed \equiv 1 \pmod{\phi(N)}$, and $m \mapsto m^e$ is a trapdoor permutation ([[#def-rsa]], [[#prop-rsa-correct]]). **Textbook RSA is insecure** — deterministic, malleable, leaky for small messages. **RSA-OAEP** ([[#def-oaep]]) is CCA-secure in the random-oracle model; PKCS#1 v1.5 encryption invites padding oracles.
- **Elliptic curves** give groups with only generic $\sqrt q$ attacks ([[#def-ec]]); on $y^2 = x^3 + 2x + 2$ over $\Z_{17}$, $G = (5, 1)$ has order $19$. 256-bit curves give 128-bit security.
- In practice, public-key cryptography encapsulates a symmetric key (**hybrid encryption**, KEM/DEM), and real code uses vetted libraries.
:::

## Exercises

::: exercise Keys for a company {level=1 check="499500"}
How many symmetric keys are needed for every pair among $1000$ employees to have its own key, and how many key pairs are needed with public-key encryption? (Enter the number of symmetric keys.)
::: solution
$\binom{1000}{2} = 1000 \cdot 999/2 = 499\,500$ symmetric keys, each needing secure delivery to two people. With public-key encryption, $1000$ key pairs suffice, and the public halves can be published — though they must be *authenticated*, which is the job of certificates ([[cryptography/signatures]]).
:::
:::

::: exercise A Diffie–Hellman exchange {level=1 check="18"}
With $p = 23$, $g = 5$, Alice's secret $x = 4$ and Bob's secret $y = 3$, compute the two public values and the shared key. (Enter the key.)
::: solution
$h_A = 5^4 = 625 = 27 \cdot 23 + 4$, so $h_A = 4$; $h_B = 5^3 = 125 = 5\cdot 23 + 10$, so $h_B = 10$. Bob computes $h_A^{\,y} = 4^3 = 64 \equiv 18$. Alice computes $h_B^{\,x} = 10^4$: $10^2 = 100 \equiv 8$ and $8^2 = 64 \equiv 18$. Both obtain $18 = 5^{12} \bmod 23$.
:::
:::

::: exercise RSA by hand {level=1 check="1752"}
With the toy key $N = 3233$, $e = 17$, $d = 2753$, encrypt $m = 2$. What does the ciphertext $c = 1$ decrypt to? (Enter the ciphertext of $m = 2$.)
::: solution
$2^{17} = 131\,072 = 40 \cdot 3233 + 1752$, so $c = 1752$, and `pow(1752, 2753, 3233)` gives back $2$. The ciphertext $c = 1$ decrypts to $1^d = 1$: textbook RSA maps $0$, $1$ and $N - 1$ to themselves, one more reason messages must be padded before encryption.
:::
:::

::: exercise Malleability of textbook RSA {level=2 check="130"}
Given the toy ciphertext $c = 2790$ (an encryption of $65$ under $N = 3233$, $e = 17$), compute without $d$ a ciphertext of $2m$, and say what it decrypts to. (Enter the decryption.)
::: solution
$c' = c \cdot 2^{17} \bmod 3233 = 2790 \cdot 1752 \bmod 3233 = 3017$. Since $(2m)^e = 2^em^e$, it decrypts to $2 \cdot 65 = 130$, which `pow(3017, 2753, 3233)` confirms. An attacker who can get "harmless-looking" ciphertexts decrypted can thus learn about $m$ by blinding: decrypt $c\cdot r^e$ and divide the answer by $r$.
:::
:::

::: exercise ElGamal is not CCA-secure {#ex-elgamal-cca level=2}
Give an adversary that wins $\mathsf{PubK}^{\mathsf{cca}}$ against ElGamal with probability $1$.
::: solution
Choose any distinct $m_0, m_1 \in G$. On receiving the challenge $\langle c_1, c_2\rangle$, query the decryption oracle on $\langle c_1, c_2\cdot g\rangle$, which differs from the challenge and so is allowed. The answer is $m_b\cdot g$; multiply by $g^{-1}$ and compare with $m_0$. CCA-secure variants of DH-based encryption (Cramer–Shoup, or DHIES/ECIES with an authenticated symmetric part) prevent such modifications.
:::
:::

::: exercise Elliptic-curve addition {level=2 check="13"}
On the toy curve $y^2 = x^3 + 2x + 2$ over $\Z_{17}$, compute $4G + 4G = 8G$ from $4G = (3, 1)$ by the doubling formula. (Enter the $x$-coordinate of $8G$.)
::: solution
$\lambda = (3\cdot 3^2 + 2)/(2 \cdot 1) = 29/2$. Modulo $17$: $29 \equiv 12$, and $12 \cdot 2^{-1} = 12 \cdot 9 = 108 \equiv 6$. Then $x_3 = 36 - 3 - 3 = 30 \equiv 13$ and $y_3 = 6(3 - 13) - 1 = -61 \equiv 7$. So $8G = (13, 7)$, in agreement with the table in [[#ex-ec]].
:::
:::

::: exercise Cube roots with small exponent {level=2}
Explain why textbook RSA with $e = 3$ leaks $m$ completely when $m < N^{1/3}$, even though $N$ is a 2048-bit modulus, and why OAEP prevents it.
::: solution
If $m < N^{1/3}$ then $m^3 < N$, so $c = m^3 \bmod N$ equals the integer $m^3$; reduction modulo $N$, which is what makes $e$-th roots hard, never happened. Taking an integer cube root (by Newton's method or binary search, in polynomial time) recovers $m$. A 2048-bit modulus allows messages of up to about $682$ bits to leak this way — for example a 256-bit AES key. OAEP fills the whole block with pseudorandom-looking bits derived from $r$, so $s \,\|\, t$ is about as large as $N$ and the reduction always happens.
:::
:::

::: exercise $\phi(N)$ reveals the factors {level=3}
Prove that given $N = pq$ (distinct primes) and $\phi(N)$, one can compute $p$ and $q$ in polynomial time. Apply it to $N = 3233$, $\phi(N) = 3120$.
::: solution
$\phi(N) = (p-1)(q-1) = N - (p + q) + 1$, so $p + q = N - \phi(N) + 1$. Then $p$ and $q$ are the roots of $X^2 - (p+q)X + N = 0$, namely $\tfrac12\big((p+q) \pm \sqrt{(p+q)^2 - 4N}\big)$, computable with an integer square root in polynomial time. For $N = 3233$: $p + q = 3233 - 3120 + 1 = 114$, discriminant $114^2 - 4\cdot 3233 = 12996 - 12932 = 64$, so $p, q = (114 \pm 8)/2 = 61, 53$. Hence computing $\phi(N)$ is as hard as factoring, and RSA key generation must keep $\phi(N)$ secret along with $d$.
:::
:::

::: exercise Implement toy ECDH and check the group order {level=3}
Using `ec_add` from [[#ex-ec]], implement double-and-add scalar multiplication `ec_mul(k, P)`, and use it to (a) verify that $19G = \mathcal O$, (b) carry out ECDH between secrets $3$ and $7$, and (c) count the points on the curve by brute force. Why would this code be unacceptable for real keys even on a real curve?
::: solution
```python
def ec_mul(k, P):
    """Double-and-add: k*P on the toy curve (NOT constant-time)."""
    R = None
    for bit in bin(k)[2:]:
        R = ec_add(R, R)
        if bit == "1":
            R = ec_add(R, P)
    return R

G = (5, 1)
print(ec_mul(19, G))                                     # None: the point at infinity
A, B = ec_mul(3, G), ec_mul(7, G)
print(A, B, ec_mul(3, B), ec_mul(7, A))
pts = [(x, y) for x in range(17) for y in range(17) if (y * y - x**3 - 2 * x - 2) % 17 == 0]
print(len(pts) + 1)
```

```console
$ python3 ecdh_toy.py
None
(10, 6) (0, 6) (6, 3) (6, 3)
19
```

Both parties obtain $(6, 3) = 21G = 2G$, and the group has $19$ elements. For real keys this code is unacceptable: its branches and Python's big-integer arithmetic make running time depend on the secret scalar (a timing side channel), it does not validate received points, the special cases of the addition formula are handled with data-dependent branches, and a 17-element field is of course trivially breakable. Libraries implement X25519 or P-256 with constant-time field arithmetic and complete formulas.
:::
:::
